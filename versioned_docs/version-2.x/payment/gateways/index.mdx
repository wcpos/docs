A payment gateway adds a way to pay at the till: a card terminal on the counter, a payment from the customer's phone, or an invoice they pay later. Each one is a WordPress plugin from WCPOS that you add to your store.

:::info Pro Feature
Gateways need [WCPOS Pro](../../getting-started/pro-license.mdx). Without it, the till takes **Cash** and **Card** only.
:::

## Where a gateway shows at checkout {#at-the-till}

Press **Checkout** and the tender pane opens on **Payments**. A gateway marked **Tile** in the [list below](#gateways) gets its own tile there, next to **Cash** and **Card**.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[28, 42], [0, 0], [0, 0], [29, 42]]} alt="The tender pane on the Payments tab: the Payments and Legacy tabs, the Cash and Card tiles, the amount to pay and the Take button" />

<div className="pinned-legend">

1. **Payments** — the tender pane. Every payment method with a tile is here. See [The Tender Pane](../../pos/checkout/tender-pane.mdx).
2. **Cash** — counts the change for you. Comes with every store.
3. **Card** — for a card machine that isn't connected to the POS: take the card on the machine, then record it here. Comes with every store.
4. **Legacy** — gateways that run on their own payment page. See [The Legacy Tab](../../pos/checkout/legacy-tab.mdx).

</div>

Gateway tiles sit in the order set in [Checkout Settings](../../settings/wp-admin/checkout.mdx#reordering-gateways). A tile the till can't use right now folds into a line under the tiles: **Stripe Terminal is not available right now**, or **2 not available right now** for more than one. Tap the line to see why.

Any other gateway is on the **Legacy** tab, which opens the gateway's own payment page inside the POS. A Legacy gateway takes the whole order, so it can't be one part of a [split payment](../../pos/checkout/split-payments.mdx).

## Choose a gateway {#gateways}

### Card terminals {#hardware-terminal-gateways}

The customer taps, inserts or swipes a card on a terminal from your payment provider. The till sends the amount to the terminal and records the payment when the provider confirms it.

| Gateway | At checkout |
|---|---|
| [Stripe Terminal](./stripe-terminal.mdx) | Tile from version 2.0 |
| [SumUp Terminal](./sumup-terminal.mdx) | Tile from version 2.0 |
| [Mollie Terminal](./mollie-terminal.mdx) | Tile from version 2.0 |
| [Square Terminal](./square-terminal.mdx) | Tile from version 1.0 |
| [Mercado Pago Terminal](./mercadopago-terminal.mdx) | Tile from version 1.0 |
| [Windcave Terminal](./windcave-terminal.mdx) | Tile from version 1.0 |
| [PayArc Terminal](./payarc-terminal.mdx) | Tile from version 1.0 |
| [PayPal Reader (Zettle)](./paypal-reader.mdx) | Legacy tab |

An earlier version is on the **Legacy** tab. Which readers work on which device is on [Card reader compatibility](../../hardware/index.mdx#card-reader-compatibility).

### Phone payments {#mobile-payment-gateways}

- **[Vipps MobilePay](./vipps-mobilepay.mdx)** — the customer scans a QR code on screen, or confirms a request on their phone, in the Vipps or MobilePay app. On the **Legacy** tab.

### Pay later {#digital-payment-gateways}

The order is saved unpaid, and the customer pays it online afterwards.

- **[Email Invoice](./email-invoice.mdx)** — the customer gets an email with a link to pay the order. Has a tile.
- **[Web Checkout](./web-checkout.mdx)** — the customer pays on your web store's checkout. On the **Legacy** tab.

## Add a gateway to your store {#install}

You do this once, in WordPress, as the store owner: install the gateway, connect your account, turn it on for the POS, then reload the POS. Each gateway's page has its own settings.

<details>
<summary>Store owner: install and enable a gateway</summary>

1. **Install it.** In `WP Admin > POS > Settings > Extensions`, find the gateway, press **Install**, then **Activate**. Or download the plugin zip from the gateway's GitHub releases page and upload it in `Plugins > Add New > Upload Plugin`. Web Checkout isn't in the Extensions list, so it's always a zip. See [Extensions](../../extensions/index.mdx#installing-an-extension).
2. **Connect your account.** Open the gateway in `WP Admin > WooCommerce > Settings > Payments` and enter the keys from your payment provider. If the gateway has a test mode, take a test payment before going live.
3. **Turn it on for the POS.** In `WP Admin > POS > Settings > Checkout`, switch on **Enabled** for the gateway, and drag it to where you want its tile. It doesn't have to be switched on for your web store. See [Checkout Settings](../../settings/wp-admin/checkout.mdx#enabling-a-gateway).
4. **Reload the POS.** The till reads your payment methods each time it starts.

</details>

## If something goes wrong {#goes-wrong}

**The gateway isn't at checkout.** Look on the **Legacy** tab first. If it isn't there either, check that **Enabled** is on in Checkout Settings, then reload the POS.

**Install is greyed out, with Requires Pro to install.** Installing from **Extensions** needs WCPOS Pro.

**The Enabled switch is greyed out.** Every gateway but Cash and Card needs WCPOS Pro, activated with your licence key. See [Pro License](../../getting-started/pro-license.mdx).

**It's on the Legacy tab, not a tile.** That's where PayPal Reader, Vipps MobilePay and Web Checkout always go. For a gateway the [list above](#gateways) gives a tile, the installed version is too old. Update it: its card in **Extensions** shows **Update available** when there's a newer one.

**The tile is under "not available right now".** Tap the line: each gateway shows why, such as **Needs a connection** while you're offline. Finish the sale with another method meanwhile. See [PAYMENT301](../../error-codes/PAYMENT301.mdx).

**A payment fails on the terminal or the provider's side.** The gateway's own page has its error messages and fixes. To report a fault, see [Support](../../support/index.mdx).
