# WCPOS Polylang

[Polylang](https://wordpress.org/plugins/polylang/) keeps a copy of each product for every language on your site. Without help, the POS downloads all of them, so a cashier searching for a hoodie finds it once in English, once in French and once in German. WCPOS Polylang sends the POS one language only: each product shows once in search and in the product grid, with its name in that language.

## What the cashier sees {#what-it-does}

- **One copy of each product.** Search, the product grid and variations all come from one language.
- **The store's language.** On WCPOS Pro, each store can have its own language. Without Pro, the POS uses Polylang's default language.
- **Your POS Only settings still apply.** A product set to **Online Only** stays out of the POS. See [POS Only Products](../products/pos-only-products.mdx).

A product with no translation in the store's language doesn't show in that store. Add the translation in Polylang to sell it there.

## Set it up {#installation}

1. **Set up Polylang.** Install and activate [Polylang](https://wordpress.org/plugins/polylang/), add your languages and choose the default one. WordPress won't activate WCPOS Polylang until Polylang is active.
2. **Install WCPOS Polylang.**

   **With WCPOS Pro:** open **POS → Settings → Extensions**, find **WCPOS Polylang**, then **Install** and **Activate**. See [Installing an Extension](./index.mdx#installing-an-extension).

   **Without WCPOS Pro:** download `wcpos-polylang.zip` from the [latest release](https://github.com/wcpos/wcpos-polylang/releases/latest) and upload it in **Plugins → Add New Plugin → Upload Plugin**. Click **Install Now**, then **Activate Plugin**.

3. **With WCPOS Pro, choose each store's language** if a store shouldn't use Polylang's default. See [Choose a language for each store](#per-store-language-pro).
4. **Download the products again on each till.** See [Download the products again](#redownload).

## Choose a language for each store {#per-store-language-pro}

:::info With WCPOS Pro
Each store can have its own Polylang language. Without Pro, every till uses Polylang's default language.
:::

1. In WP Admin, open **POS → Stores** and click the store.
2. In the store's menu, under **Extensions**, click **Language**.
3. Under **Store language**, pick a language. Polylang lists them by code, such as `en` or `fr`. The first choice, **Default language** with your default's code beside it, follows Polylang's default.

The page saves as you go. Then [download the products again](#redownload) on that store's tills, as below.

The **Language** page shows only when WCPOS Pro, Polylang (with at least one language) and WCPOS Polylang are all active.

### Two settings called Language {#two-languages}

A store has two **Language** settings, and they can be different.

| In the store's menu | What it changes |
| --- | --- |
| **Extensions → Language** | Which products the store's tills get: one Polylang language. |
| **Currency & language → Language** | The language of the POS screen and receipts. See [Fill in the store's pages](../stores/setup.mdx#store-pages). |

## Download the products again {#redownload}

So that each till holds one language only, fetch its products again. Do this on each till while it's online:

1. Open the navigation drawer and tap **Store health** (the heartbeat icon). It opens on the **Database** tab.
2. On the **Products** row, open the **More actions** menu and choose **Clear & re-download…**, then confirm.
3. Do the same on the **Variations** row.

Nothing on the server changes. The first products come back right away, and the rest as you browse, search and sell. The **Products** row shows how many are back. See [Checking download progress](../products/sync.mdx#checking-progress).

## If something goes wrong {#compatibility-notes}

**Every product shows more than once.** Check that Polylang and WCPOS Polylang are both active in **Plugins**. When Polylang is off, WCPOS Polylang does nothing and the POS gets every language. Then [download the products again](#redownload) on each till.

**A store shows products in the wrong language.** Its **Extensions → Language** page is on **Default language**, or on another language. Pick the store's language, then [download the products again](#redownload) on its tills.

**A product is missing in one store.** Check that it has a translation in that store's language, and add one in Polylang if not. If it has, see [When you can't find it](../pos/product-panel/index.mdx#goes-wrong).

**There's no Language page under Extensions.** It needs WCPOS Pro, Polylang with at least one language, and WCPOS Polylang, all active.

## For developers {#developer-hooks}

<details>
<summary>How the filtering works, and its filters</summary>

- WCPOS Polylang adds Polylang's `lang` query to the product and variation REST queries that WCPOS makes, on both the `/wcpos/v1/…` routes and requests marked as WCPOS by the free plugin's `wcpos_request()`.
- It answers WCPOS's ID-only product and variation lists (`posts_per_page=-1` with `fields=id` or `fields=id,date_modified_gmt` on `/wcpos/v1/products` and its variation routes) itself, filtered to the language, leaving out **Online Only** IDs when POS Only products is on.
- With WCPOS Pro, a request with a `store_id` the user may use gets that store's language. A store's language is saved in the `_wcpos_polylang_language` post meta and returned as `language` by `/wcpos/v1/stores`.

| Filter | Purpose |
| --- | --- |
| `wcpos_polylang_resolved_language` | Change the language for a request. Receives the language slug and the `WP_REST_Request`. |
| `wcpos_polylang_default_language` | Change the fallback language when a store has none set. |
| `wcpos_polylang_is_supported` | Turn the integration on or off, whatever Polylang detection says. |
| `wcpos_polylang_minimum_version` | Require a minimum Polylang version. Empty by default: no version check. |

Source: [github.com/wcpos/wcpos-polylang](https://github.com/wcpos/wcpos-polylang).

</details>
