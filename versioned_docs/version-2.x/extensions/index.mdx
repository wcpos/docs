An extension is a WordPress plugin built for WCPOS: a card terminal, a multilingual catalog, store credit, stock by location. You find them all in one directory in WordPress, at **WP Admin > POS > Settings > Extensions**, and with WCPOS Pro you install them from there with one button.

## What's in the directory {#available-extensions}

Each card below links to that extension's own page: what it does, what it needs and how to set it up.

## Install an extension {#installing-an-extension}

:::note Before you start
Installing from the directory needs **WCPOS Pro** and a WordPress administrator: Shop Managers can't install plugins (see [Access](../settings/wp-admin/access.mdx)). On the free version, see [Without Pro](#install-by-hand).
:::

1. In WordPress, go to **WP Admin > POS > Settings** and choose **Extensions**.
2. Find the extension. Type in **Search extensions...**, or pick a tab: **All**, **Catalog**, **Coupons**, **Inventory**, **Payments**.
3. Press **Install** on its card. WCPOS downloads it, installs it and activates it in one go, and turns on **Auto-update**. The card now says **Active**.
4. Set it up. For a payment extension, open **⋮** (**More actions**) on the card and choose **Settings**: it takes you to the extension's page in WooCommerce's payment settings. Each extension's own page above says what to fill in.

### What a card shows {#browsing-extensions}

- **Status** — **Active**, **Inactive**, or **Update available**. No status means it isn't installed.
- **Version** — the installed version, or the latest one if it isn't installed. With an update waiting it reads **v0.5.9 → v0.5.10**. Each version links to its release on GitHub.
- **Category** — the tab it sits under.
- **Auto-update** — on or off for this extension. Installed extensions only.
- **The button** — **Install**, **Activate** or **Update**, whichever comes next. **Deactivate** sits beside it while the extension is running.
- **⋮ More actions** — **Settings** (installed extensions that have a settings page) and **View on GitHub**.

A number next to **Extensions** in the settings menu counts the updates waiting.

### Without Pro {#install-by-hand}

The free version lists every extension, but **Install** is greyed out with **Requires Pro to install**. The three multilingual extensions run without Pro, so you can install those by hand:

1. On the extension's card, open **⋮** (**More actions**) and choose **View on GitHub**.
2. Download the `.zip` attached to the latest release.
3. In **WP Admin > Plugins > Add New Plugin**, press **Upload Plugin**, choose the zip and activate it.

The directory then shows it as **Active**, and as **Update available** when a new release is out. Without Pro there's no **Update** button: upload the new release's zip the same way, and WordPress offers to replace the installed version.

## Update, turn off or turn on {#activating-and-deactivating}

With WCPOS Pro, the buttons on an installed extension's card do this:

- **Update** — installs the new version. An extension that was running keeps running.
- **Deactivate** — stops the extension without removing it. Its settings and files stay, and **Activate** brings it back. **Activate** turns **Auto-update** on again.
- To remove an extension for good, deactivate it here, then delete it from **WP Admin > Plugins** like any other plugin.

### Updates {#updating-extensions}

When a new version is out, the card says **Update available**. With WCPOS Pro it also shows the **Update** button, and WordPress lists the same update on its **Plugins** screen, so you can update from either place. On the free version, update by hand: see [Without Pro](#install-by-hand).

The directory checks for new versions once an hour. Press **Refresh** next to the search box to check now.

### Auto-updates {#auto-updates}

**Auto-update** is on for every extension you install or activate from the directory. With it on, WordPress installs new versions in the background, the same way it does for any plugin with auto-updates on. Turn it off on the card if you'd rather update by hand, for example to test a new version first.

A new version that needs a newer WCPOS than your site runs isn't offered at all, by the card or by auto-update. Update WCPOS Pro first, and the extension's update appears.

## If something goes wrong {#troubleshooting}

**Install is greyed out and says "Requires Pro to install".** You're on the free version: installing from the directory needs [WCPOS Pro](../getting-started/pro-license.mdx). The multilingual extensions can be [installed by hand](#install-by-hand).

**"You do not have permission to manage plugins."** Your WordPress user can't install plugins. Ask an administrator.

**"… needs WCPOS 2.1 or later; this site runs WCPOS 2.0. Update WCPOS Pro first."** The version on offer is newer than your WCPOS supports. Update WCPOS Pro, then try again.

**"Could not refresh extensions. Please try again." or "No extensions found." with nothing searched.** Your site couldn't fetch the list of extensions. The list comes from GitHub, and some hosts stop websites from connecting out. Try again later, or ask your host to allow connections to GitHub.

**The install fails with an error on the card.** WordPress couldn't download or unpack the plugin, and the message on the card names the cause. Ask your host to check that WordPress can save files in its plugins folder (`wp-content/plugins`) and can connect to GitHub.

**A new version isn't showing.** The directory keeps its list for an hour. Press **Refresh**.

:::info With WCPOS Pro
The free version shows the whole directory, but the **Install**, **Activate**, **Update**, **Deactivate** and **Auto-update** controls come with Pro. See [Free vs Pro](../getting-started/free-vs-pro.mdx).
:::

## For developers {#for-developers}

For building an extension or listing your own. Nothing below is needed to run a store.

### Creating a POS extension {#creating-a-pos-extension}

A WCPOS extension is an ordinary WordPress plugin that uses WCPOS hooks and APIs. For a payment extension, start from the [Gateway Template](../reference/gateway-template.mdx).

<details>
<summary>So that the directory recognises your plugin once it's installed</summary>

- **Folder name** — the plugin's folder must be the catalog `slug`, e.g. `my-extension/my-extension.php`. The directory finds installed extensions by that folder, and installs into it.
- **Text Domain or Plugin URI** — one of them must match the `slug` or the GitHub repository's name. Without a match, auto-updates and the WordPress **Plugins** screen don't offer your releases. The check stops a fork that reuses your folder name from receiving them.

</details>

### Hook naming {#hook-naming}

From WCPOS 2.0 every hook WCPOS fires is named `wcpos_*` (WCPOS Pro: `wcpos_pro_*`). The old `woocommerce_pos_*` hook names are deprecated aliases: they still fire, log a deprecation notice under `WP_DEBUG` when something is attached, and are removed in 2.2 at the earliest. Only hooks change: options, meta keys and capabilities keep their names.

Four hooks are fired by your code and heard by WCPOS: `woocommerce_pos_invalidate` (extensions), `woocommerce_pos_receipt_head` (saved PHP receipt templates), and `woocommerce_pos_head` / `woocommerce_pos_footer` (a theme's `pos.php` override). WCPOS keeps listening on those names until 2.2; switch to `wcpos_invalidate`, `wcpos_receipt_head`, `wcpos_head` and `wcpos_footer`.

Extensions: switch to the `wcpos_` names in your first release after 2.0 and require WCPOS 2.0 or later. Never attach to both names; on 2.0 and 2.1 your callback would run twice. See [ADR 0041](https://github.com/wcpos/woocommerce-pos/blob/main/docs/adr/0041-wcpos-is-the-hook-prefix.md).

### Submitting to the directory {#submitting-to-the-directory}

The directory reads `catalog.json` in the [`wcpos/extensions`](https://github.com/wcpos/extensions) repository on GitHub. To list your extension, open a pull request there that adds an entry to `catalog.json`, and an icon under `icons/` if you have one. Once it merges, WCPOS sites see it within about an hour.

<details>
<summary>Every field in a catalog entry</summary>

| Field | What it holds |
|---|---|
| `slug` | The plugin's folder name. |
| `name`, `description`, `author` | What the card shows. |
| `category` | The tab it sits under: `payments`, `catalog`, `coupons`, `inventory`, or a new one. |
| `tags` | Extra words the search matches. |
| `homepage` | The GitHub repository, `https://github.com/owner/repo`. Releases are read from here. |
| `icon` | URL of a square icon, usually the file you added under `icons/`. Without one the card shows a puzzle piece. |
| `requires_wp`, `requires_wc`, `requires_wcpos` | The lowest WordPress, WooCommerce and WCPOS versions it runs on. Sites below `requires_wcpos` are never offered the release. |
| `requires_pro` | Whether it needs WCPOS Pro to run. |
| `settings_url` | Its settings page, relative to `wp-admin/`, e.g. `admin.php?page=wc-settings&tab=checkout&section=my_gateway`. Fills **Settings** in the card's menu. |

Leave `version`, `latest_version`, `download_url` and `released_at` to the catalog: they're filled in from your releases.

</details>

### GitHub release conventions {#github-release-conventions}

Every hour the catalog reads the latest release of each listed repository and updates its entry. For a release to reach WCPOS sites:

- **Tag it** with the version, `v1.2.3`. The leading `v` is dropped for the version number, which must match the plugin header's `Version`.
- **Attach the plugin zip** named after the slug, `my-extension.zip`. Without that name, the first `.zip` on the release is used. WCPOS installs it into the `slug` folder whatever the folder inside the zip is called.
- **Publish it as a full release.** Drafts and pre-releases are skipped, so a pre-release is a safe way to share a test build.
- **Raise `requires_wcpos`** in `catalog.json` when a release needs a newer WCPOS, so older sites aren't sent a version that won't start.

Sites see the new version once their list is refreshed: within the hour, or straight away with **Refresh**. Sites with **Auto-update** on install it in the background.

To test a catalog of your own before submitting, point a site at it with the `wcpos_extensions_catalog_url` filter.
