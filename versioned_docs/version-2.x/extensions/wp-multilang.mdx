[WP Multilang](https://wordpress.org/plugins/wp-multilang/) keeps every translation of a product inside that one product, and lets you limit a product to some of your languages. The free **WCPOS WP Multilang** extension gives the POS one language to work in, so a product you limited to other languages stays out of it.

Cashiers have nothing to set up: the first section shows what changes for them. The rest of the page is for the store's administrator.

## What the cashier sees {#what-the-cashier-sees}

Product search, the product grid and a variable product's options show the products sold in the store's language:

- A product with **no language limit** shows in every store.
- A product **limited to some languages** shows only where the store's language is one of them.

Nothing changes in how a cashier sells: add to cart, take the payment, print the receipt as usual. See [Checkout](../pos/checkout/index.mdx).

## Install the extension {#install}

:::note Before you start
You need [WooCommerce](https://woocommerce.com/) and [WP Multilang](https://wordpress.org/plugins/wp-multilang/) active, with your languages set up in WP Multilang, and an administrator login to **WP Admin**. WordPress won't activate the extension until both are active.
:::

An administrator installs it once, in **WP Admin**. The POS uses WP Multilang's **default language** unless you [choose a language for the store](#store-language). After activating the extension, follow [Check it works](#check) below.

### With WCPOS Pro {#install-pro}

1. Go to **POS → Settings → Extensions**.
2. Find **WCPOS WP Multilang** and press **Install**.
3. Press **Activate**.

See [Install an extension](./index.mdx#installing-an-extension) for updates and auto-updates.

### With the free plugin {#install-free}

The Extensions screen lists the extension, but its **Install** button needs Pro. Instead:

1. Download `wcpos-wp-multilang.zip` from the extension's [latest release](https://github.com/wcpos/wcpos-wp-multilang/releases/latest).
2. Go to **Plugins → Add New Plugin** and press **Upload Plugin**.
3. Choose the file you downloaded and press **Install Now**.
4. Press **Activate Plugin**.

### Check it works {#check}

The POS keeps a copy of your products on each device, so clear it once to pick up the change.

Pick two in-stock products with language limits: one that includes the store's language, and one that doesn't. You set a product's languages in [WP Multilang](https://wordpress.org/plugins/wp-multilang/), not in the POS. Then, on each device that uses the POS:

1. Press and hold the sync button (4) and choose **Clear and Refresh** (5). Wait for the products to download again.
2. Turn off any filter lit in the bar other than **In Stock**. In **Search products** (1), type the name of the product that includes the store's language. It shows (2).
3. Search for the other product. It doesn't show.

## Choose a store's language {#store-language}

With WCPOS Pro, each [store](../stores/index.mdx) can work in its own language: a French shop and an English shop on the same site each see the products sold in their language.

:::note The Language page needs three things
WCPOS Pro, the **WCPOS WP Multilang** extension active, and WP Multilang active with at least one language. Without them, the store's menu has no **Language** page.
:::

1. In **WP Admin**, go to **POS → Stores** and click the store's name.
2. In the store's menu, under **Extensions**, open **Language**. Not **Currency & language → Language**, which changes the words on the screen and receipts; see [below](#product-and-screen-language).
3. Under **Store language**, pick a language. The list shows every language set up in WP Multilang. **Default language** follows WP Multilang's default. The choice saves by itself.
4. Open the POS for this store and [check it works](#check).

Other stores keep their own language.

### Product language and screen language {#product-and-screen-language}

A store has two settings called **Language**, in two places in the store's menu:

- **Extensions → Language → Store language** chooses which products the POS shows.
- **Currency & language → Language** chooses the words on the POS screen and on receipts. See [Fill in the store's pages](../stores/setup.mdx#store-pages).

:::tip
For a French shop, set both to French.
:::

## If something goes wrong {#goes-wrong}

**A product limited to another language still shows.** Check that **WCPOS WP Multilang** is active in **Plugins**, then press and hold the sync button and choose **Clear and Refresh** on that device.

**A product is missing in one store.** Check in WP Multilang whether the product's languages include this store's language. If they don't, add it, then refresh the POS. If they do, see [When you can't find it](../pos/product-panel/index.mdx#goes-wrong).

**WordPress won't activate the extension.** Activate WooCommerce and WP Multilang first.

**There is no Language page under Extensions in the store's menu.** The page needs WCPOS Pro, the extension active, and WP Multilang active with at least one language.

:::info With WCPOS Pro
Every store chooses its own language. Without Pro there is one store, and it uses WP Multilang's default language.
:::

<details>
<summary>For developers: filters and stored data</summary>

The extension works only on the product and variation requests the POS makes: it adds WP Multilang's `lang` query var and a `_languages` meta query to their product query. A product matches when it has no `_languages` meta, or when its `_languages` contains the language. Other REST clients are not affected. The language comes from the store the request names (`store_id`), then from WP Multilang's default.

- A store's choice is saved in the store's `_wcpos_wp_multilang_language` meta, and the stores API returns it as `language`. An empty value means WP Multilang's default language.
- `wcpos_wp_multilang_resolved_language` changes the language used for one request.
- `wcpos_wp_multilang_default_language` changes the default language.
- `wcpos_wp_multilang_is_supported` switches the extension on or off.
- `wcpos_wp_multilang_minimum_version` sets the lowest WP Multilang version it runs with. There is none by default.
- For the 1.x app, the extension also answers its ID-list requests on `/wcpos/v1/products` and the variation routes (`posts_per_page=-1` with `fields=id`) with the same language filter. The 2.x app does not send them.

Source: [github.com/wcpos/wcpos-wp-multilang](https://github.com/wcpos/wcpos-wp-multilang).

</details>
