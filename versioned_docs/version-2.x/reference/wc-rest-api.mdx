The **WooCommerce REST API** is the way other apps talk to your store. Instead of running inside your WordPress site, an app sends requests over the internet to fixed addresses, one for each kind of store data: products, orders, customers, coupons and so on. Your store answers in **JSON**, a plain-text format that lists every field by name.

WCPOS is one of those apps. The POS on your till asks your store for products and customers, and sends each sale back as a WooCommerce order.

## What the POS gets from your store {#what-the-pos-gets}

- **The API must be there.** When you connect a store, the POS checks that your site offers the WooCommerce REST API. If it doesn't, connecting stops with [AUTH321: WooCommerce missing](../error-codes/AUTH321.mdx).
- **A copy on the device.** The POS downloads products and variations, categories, tags and brands, customers, tax rates, coupons and orders, and keeps a copy on the device. Searching and selling read that copy, so the till stays fast and keeps working when the internet drops.
- **WooCommerce's own data.** The WCPOS plugin adds its own `wcpos/v2` routes to your store. They pass each request on to WooCommerce's `wc/v3` API and return WooCommerce's answer, so the POS gets the same fields any WooCommerce app gets.
- **Sales go back as orders.** A sale, a new customer or a product edit made at the till goes to your store the same way, and WooCommerce saves it. Each sale becomes a normal WooCommerce order you can open in **WooCommerce > Orders**.
- **Changes come in the background.** The POS checks your store for changes while it runs, so an edit made in WP Admin reaches the till without a restart. [How the Sync Engine Works](./sync-engine.mdx) explains how.

## See the data the POS holds {#viewing-the-json-data-in-the-pos}

Every panel that shows one record has a **JSON** tab beside **Form**: a product, a variation, a customer, a coupon, an order, **Order details** in the cart, and a cart line's **Edit** dialog. It shows that record as this device holds it, in WooCommerce's own JSON. You won't need it to sell. It answers the question "what did the POS actually get?" when a price, a stock count or a custom field looks wrong at the till.

To open it for a product:

1. Open **Products** from the menu and search for the product.
2. Tap the open arrow (›) at the end of its row. The panel opens on the **Form** tab.
3. Tap **JSON**, beside **Form**.

Every field your store sent for the product is listed by name, with the count of fields at the top. Fields that hold more fields, such as `categories` or `meta_data`, start folded: tap one to open it. Scroll to see the rest.

If a value here doesn't match WP Admin, the change hasn't reached this device yet. Tap **Form**, then **Sync**, to fetch the product again.

To see the order you're building, tap **⋮** beside **Checkout** to open **Order details**, then **JSON**. Each cart line has its own **JSON** tab too, in the line's **Edit** dialog (see [Edit or remove a line](../pos/cart/line-items.mdx#remove-item)).

<details>
<summary>Watch the requests in the browser</summary>

In the web app you can watch the POS talk to your store with your browser's developer tools:

1. Open the POS in Chrome, Edge or Firefox.
2. Press **F12** (on a Mac, **Option + Command + I**) and choose the **Network** tab.
3. Type `wcpos` or `wc/v3` in the filter box.
4. Use the POS: search, add a product, check out. Each request your store answers appears in the list. Select one and choose **Response** to read the JSON.

</details>

## Why some plugins don't change the POS {#why-dont-some-plugins-work-in-the-pos}

The POS works from its copy of your store's data. A plugin that only changes what a web page shows, or works something out while a shopper browses your website, never reaches that copy. The POS sees what the REST API sends, nothing more.

| Plugin type | What happens at the till | What to do |
|---|---|---|
| Dynamic pricing (prices per customer, per role or per quantity) | The POS shows the product's normal price. The plugin works its price out on the website, so the API never sends it. | Use [discounts at the till](../pos/cart/discounts.mdx), or a coupon. |
| Product add-ons (gift wrap, engraving, extra options) | The options don't appear on the product. The plugin builds them on the product page, and they aren't part of the product the API sends. | Add a [fee](../pos/cart/index.mdx#fees) for the extra cost, and a [custom field](../pos/cart/line-items.mdx#meta-data) for the detail. |
| Plugins that change the API itself | The POS can break. wePOS changes how your store sends variable products, so WCPOS turns itself off while wePOS is active. | See [wePOS](../integrations/index.mdx#wepos). |

A plugin that saves its data on the product, the customer or the order (as custom fields) usually does reach the POS. Open the **JSON** tab and look in `meta_data` to check.

## If something goes wrong {#goes-wrong}

- **Connecting fails with AUTH321** — your site isn't offering the WooCommerce REST API. See [AUTH321: WooCommerce missing](../error-codes/AUTH321.mdx).
- **A price or field at the till doesn't match WP Admin** — open the product's **JSON** tab. If the value there is the old one, tap **Sync** on the **Form** tab. If the value is already wrong there, your store is sending it that way: check the product in WP Admin.
- **A plugin's change never shows in the POS** — see [Why some plugins don't change the POS](#why-dont-some-plugins-work-in-the-pos).
- **Something stopped working after you installed a plugin** — see [Plugin Conflicts](../support/troubleshooting/plugin-conflicts.mdx).
