A thermal template is a small XML file. The same file gives you two things: the preview you see on screen, and the commands sent to a receipt printer (ESC/POS, StarPRNT or Star Line Mode). It fills in data with the same `{{placeholders}}` as [HTML templates](./html-templates.mdx). Every field is listed in [Receipt Data](./receipt-data.mdx).

Use a thermal template for any receipt printer you set up in [Printer Setup](../hardware/printers/index.mdx). You edit templates in WP Admin under **POS → Templates** ([Customise a Receipt](./customise.mdx)). The easiest start is a gallery template with the format **ESC/POS (thermal printer)**.

## The template and the printer {#the-template-and-the-printer}

Some things are set on the printer, not in the template. These settings are in **Settings → Printing**: press **Edit** on the printer's row.

| Printer setting | What it does to a thermal template |
|---|---|
| **Paper width** (32, 42, 48 or 64) | The number of characters per line on paper. It **replaces** the template's `paper-width` when you print. See [Receipt Width](../hardware/printers/receipt-width.mdx). |
| **Printer Language** | **ESC/POS**, **StarPRNT** or **Star Line Mode**. The same template prints on all three. |
| **Receipt language** (ESC/POS only) | The character table the text is written with. |
| **Auto-open cash drawer** | Opens the drawer after the receipt, unless the template has its own `<drawer />`. |
| **Cash drawer connector** | **Pin 2 / Drawer 1** or **Pin 5 / Drawer 2**. Used by `<drawer />` when it doesn't name a connector. |
| **Print receipts as an image** | Prints the whole receipt as a picture. For scripts the printer can't print as text, such as Arabic, Hebrew and Thai. Slower than text. |

So `paper-width` only sets the width of the **preview**. On paper, the printer's **Paper width** wins. Build rows with `width="*"` columns and one template fits every printer ([Star-Width Columns](#star-width-columns)).

## XML Elements {#xml-elements}

Every element at a glance. Attributes are optional unless marked.

| Element | Attributes (default) | What it prints |
|---|---|---|
| `<receipt>` | `paper-width` (`48`) | Required root. Holds everything else. |
| `<text>` | | One line of text. |
| `<bold>`, `<underline>`, `<invert>` | | Styled text. `<invert>` is white on black. |
| `<size>` | `width` (`1`), `height` (same as `width`) | Bigger text, 1–8 times. |
| `<align>` | `mode`: `left`, `center`, `right` (`left`) | Aligns what is inside. |
| `<row>` + `<col>` | `width`: a number or `*` (`12`); `align`: `left`, `right` (`left`) | Columns side by side. |
| `<line />` | `style`: `single`, `double`, `dashed`, `dotted` (`single`) | A separator across the paper. |
| `<feed />` | `lines` (`1`) | Blank lines. |
| `<barcode>` | `type` (`code128`), `height` (`40`) | A barcode of the text inside. |
| `<qrcode>` | `size` (`4`) | A QR code of the text inside. |
| `<image />` | `src` (required), `width` in dots (`200`) | A logo or picture. |
| `<cut />` | `type`: `full`, `partial` (`partial`) | Cuts the paper. |
| `<drawer />` | `connector`: `pin2`, `pin5` (the printer's setting) | Opens the cash drawer. |

Number attributes take whole numbers above zero. Anything else, such as `width="1.5"` or `lines="0"`, falls back to the default. A tag that isn't in this table is ignored, but the text inside it still prints.

### Root Element {#root-element}

Every thermal template starts with a `<receipt>` root:

```xml
<receipt paper-width="48">
  <!-- 48 characters = 80 mm paper on most Epson and Star printers -->
  <!-- 32 characters = 58 mm paper -->
</receipt>
```

`paper-width` sets the preview width in characters. On paper the printer's **Paper width** replaces it ([The template and the printer](#the-template-and-the-printer)).

### Text and Formatting {#text-and-formatting}

```xml
<text>Plain text</text>
<bold><text>Bold text</text></bold>
<underline><text>Underlined text</text></underline>
<invert><text>Inverted (white on black)</text></invert>
```

A styled element on its own doesn't end the line, so put a `<text>` inside it ([Wrap styled headings](#wrap-styled-headings-in-text-for-a-line-break)).

### Alignment {#alignment}

```xml
<align mode="left"><text>Left aligned</text></align>
<align mode="center"><text>Centered</text></align>
<align mode="right"><text>Right aligned</text></align>
```

Any other `mode` falls back to `left`.

### Text Size {#text-size}

Scale text width and height independently:

```xml
<size width="2" height="2"><text>Double-size text</text></size>
<size width="2" height="1"><text>Wide text</text></size>
<size width="1" height="2"><text>Tall text</text></size>
```

If you leave out `height`, it matches `width`. ESC/POS printers go up to 8 times; Star printers stop at 6.

### Tabular Layout {#tabular-layout}

Use `<row>` and `<col>` for aligned columns:

```xml
<row>
  <col width="24">Item name</col>
  <col width="8" align="right">Qty</col>
  <col width="16" align="right">Price</col>
</row>
```

Column widths are in characters. Use `width="*"` for a flex column that takes the space left over. Then the row fits any paper width without changes:

```xml
<row>
  <col width="*">{{name}}</col>
  <col width="12" align="right">{{line_total_display}}</col>
</row>
```

- A `<col>` aligns `left` or `right`. There is no `center` for a column.
- A `<col>` outside a `<row>` is ignored.
- A column prints its **text only**. Styling inside a `<col>` (`<bold>`, `<size>` and the rest) shows in the preview but not on paper. To print a whole row in bold, put the `<bold>` around the `<row>`:

```xml
<!-- Prints bold on paper -->
<bold>
  <row>
    <col width="*">{{i18n.total}}</col>
    <col width="16" align="right">{{totals.total_display}}</col>
  </row>
</bold>
```

### Separators and Spacing {#separators-and-spacing}

```xml
<line />                       <!-- Single rule -->
<line style="double" />        <!-- Double rule -->
<line style="dashed" />        <!-- Dashed rule -->
<line style="dotted" />        <!-- Dotted rule -->
<feed lines="2" />             <!-- Blank lines -->
```

The preview draws each style differently. On paper:

- `single` and `dashed` both print a row of `-` characters across the width.
- `dotted` prints `. . . .` across the width.
- `double` uses the printer's own double rule.

### Printer Commands {#printer-commands}

```xml
<cut />                <!-- Partial cut (leaves a small tab) -->
<cut type="full" />    <!-- Full cut -->
<drawer />             <!-- Open the cash drawer -->
<drawer connector="pin5" /> <!-- Open the drawer on pin 5 -->
```

- `<cut />` feeds the paper up to the cutter first. The preview shows the cut as a dashed line with ✂.
- `<drawer />` opens the drawer whatever **Auto-open cash drawer** says. When the template has its own `<drawer />`, the app doesn't add a second one. The preview shows nothing for it. See [Cash Drawer](../hardware/printers/cash-drawer.mdx).

### Barcodes and QR Codes {#barcodes-and-qr-codes}

```xml
<barcode type="code128" height="40">{{order.number}}</barcode>
<qrcode size="4">{{fiscal.qr_payload}}</qrcode>
```

- `height` is the barcode height in dots.
- `size` is the size of each QR square, from small to large.
- `<barcode type="qrcode">` (or `type="qr"`) also makes a QR code. Its size comes from `height`: `height` ÷ 10, kept between 2 and 10.

The preview draws barcodes and QR codes as images. The printer gets native barcode commands, or a printed image when the app has prepared one.

## Example: Simple 80mm Receipt {#example-simple-80mm-receipt}

```xml
<receipt paper-width="48">
  <align mode="center">
    <bold><size height="2"><text>{{store.name}}</text></size></bold>
    {{#store.address_lines}}<text>{{.}}</text>{{/store.address_lines}}
    {{#store.phone}}<text>{{store.phone}}</text>{{/store.phone}}
  </align>
  <line />

  <text>Order: #{{order.number}}</text>
  <text>Date: {{order.created.datetime}}</text>
  {{#cashier.name}}<text>Cashier: {{cashier.name}}</text>{{/cashier.name}}
  <line />

  <!-- Column headers, bold on paper -->
  <bold>
    <row>
      <col width="*">Item</col>
      <col width="4" align="right">Qty</col>
      <col width="12" align="right">Total</col>
    </row>
  </bold>
  <line />

  <!-- Line items -->
  {{#lines}}
  <row>
    <col width="*">{{name}}</col>
    <col width="4" align="right">{{qty}}</col>
    <col width="12" align="right">{{line_total_display}}</col>
  </row>
  {{/lines}}

  <line />

  <!-- Totals -->
  <row>
    <col width="*">Subtotal</col>
    <col width="16" align="right">{{totals.subtotal_display}}</col>
  </row>
  {{#totals.tax_total}}
  <row>
    <col width="*">Tax</col>
    <col width="16" align="right">{{totals.tax_total_display}}</col>
  </row>
  {{/totals.tax_total}}
  <bold>
    <row>
      <col width="*">TOTAL</col>
      <col width="16" align="right">{{totals.total_display}}</col>
    </row>
  </bold>

  <line />

  {{#payments}}
  <row>
    <col width="*">{{method_title}}</col>
    <col width="16" align="right">{{amount_display}}</col>
  </row>
  {{#tendered}}
  <row>
    <col width="*">Tendered</col>
    <col width="16" align="right">{{tendered_display}}</col>
  </row>
  <row>
    <col width="*">Change</col>
    <col width="16" align="right">{{change_display}}</col>
  </row>
  {{/tendered}}
  {{/payments}}

  <feed lines="2" />
  <align mode="center">
    <text>Thank you for your purchase!</text>
  </align>
  <feed lines="3" />
  <cut />
</receipt>
```

The labels here are plain English. The gallery templates use `{{i18n.*}}` labels instead, so the receipt follows the store's language ([i18n fields](./receipt-data.mdx#i18n)).

## Star-Width Columns {#star-width-columns}

The `width="*"` column makes a template fit any paper width. Instead of fixing every column for one paper size, use `*` for the column that should stretch:

```xml
<!-- Works on 58 mm (32 characters) AND 80 mm (48 characters) printers -->
<row>
  <col width="*">{{name}}</col>
  <col width="10" align="right">{{line_total_display}}</col>
</row>
```

On a 48-character printer the item name gets 38 characters. On a 32-character printer it gets 22. Fixed columns stay the same size on both.

With more than one `*` column, the space left over is shared equally. The last `*` column takes any odd character. A `*` column is never narrower than 1 character.

## Template preview {#template-preview}

The template editor in WP Admin shows a **live thermal preview** as you type. It updates 300 ms after you stop typing. The receipt window in the POS shows the same kind of preview before you print. Both draw your XML as monospace text, as wide as `paper-width`.

The same template makes the preview and the printer output. There is no separate print template. The preview is close to the paper, but not exact:

| In the preview | On paper |
|---|---|
| The width is `paper-width` | The width is the printer's **Paper width** |
| `<bold>`, `<size>` inside a `<col>` show | The column prints plain text |
| `<size>` grows with `width` only, so a tall-only size looks normal | Width and height both apply |
| Single and dashed lines look different | Both print `-` characters |
| `<cut />` is a dashed line with ✂; `<drawer />` shows nothing | The paper cuts; the drawer opens |
| Every script shows | Only what the printer's character table holds prints, unless **Print receipts as an image** is on |

## Authoring tips and pitfalls {#authoring-tips-and-pitfalls}

Thermal printing has a few traps that don't exist in HTML. These are the ones authors hit most often.

### Wrap styled headings in `<text>` for a line break {#wrap-styled-headings-in-text-for-a-line-break}

Styled containers — `<bold>`, `<size>`, `<underline>`, `<invert>`, `<align>` — **don't end the line by themselves**. Only `<text>` and block elements (`<line />`, `<row>`, `<feed />`) do.

```xml
<!-- ❌ Bug: the heading runs together with whatever follows -->
<bold>{{i18n.bill_to}}</bold>
{{customer.name}}

<!-- ✅ Fix: wrap the inner content in <text> -->
<bold><text>{{i18n.bill_to}}</text></bold>
<text>{{customer.name}}</text>
```

The bundled 80 mm gallery templates use this pattern for every heading.

### Avoid `<size width="2">` inside narrow rows {#avoid-size-width2-inside-narrow-rows}

Double-width text **doubles the space each character takes**. A headline that fits on a 48-character printer can overflow on a 42-character one, and on 58 mm paper it only leaves 16 characters.

Size inside a `<col>` doesn't print anyway. For a big value (a large total, a kitchen order number), print it on its own scaled line instead:

```xml
<!-- For store names, prefer normal-width, double-height -->
<bold><size height="2"><text>{{store.name}}</text></size></bold>

<!-- For a big total, put it on its own line above the row -->
<align mode="right">
  <bold><size height="2"><text>{{totals.total_display}}</text></size></bold>
</align>
```

### Use `width="*"` for paper-width-agnostic layouts {#use-width-for-paper-width-agnostic-layouts}

A `width="*"` column takes the width left after the fixed columns. The same template then fits 32-, 42-, 48- and 64-character printers without changes ([Star-Width Columns](#star-width-columns)).

If you do use fixed numeric widths, **budget them to 42**, not 48. Many 80 mm printers print 42 characters a line, and a row that adds up to 48 wraps on them. Check your printer's number in [Receipt Width](../hardware/printers/receipt-width.mdx).

### Centred styled headings inside `<align>` blocks {#centred-styled-headings-inside-align-blocks}

Inside `<align mode="center">` (or `right`), a styled heading placed straight inside the `<align>` — `<bold>`, `<size>`, `<underline>` or `<invert>` — ends its own line when another line follows. A centred, scaled store name above a centred address prints cleanly even without the `<text>` wrap.

Outside an alignment block, keep the `<text>` wrap.

### ESC/POS punctuation normalisation {#escpos-punctuation-normalisation}

When **Printer Language** is **ESC/POS**, typographic punctuation is changed to plain ASCII before printing:

- Hyphen and dash variants (en dash, em dash, figure dash, minus sign) → `-`
- Curly quotes → straight quotes

So `Mon–Sat 9:00–18:00` and `“open”` print correctly even on printers without a Unicode font. Star printers (**StarPRNT** and **Star Line Mode**) keep the original dashes and quotes, so write with characters the printer's font holds.

On every printer, special spaces (non-breaking, narrow and thin spaces) print as a regular space.

### Non-Latin and right-to-left scripts {#non-latin-and-rtl-scripts}

A thermal printer prints text with its own built-in font and character table. Arabic, Hebrew, Persian, Urdu, Thai and other non-Latin scripts print correctly only when the table matches. Otherwise you get blanks or the wrong characters.

The reliable fix is **Print receipts as an image** on the printer. It draws the whole receipt as a picture, so it prints as designed whatever fonts the printer has. Cuts, feeds and the drawer still work. For the other fixes, see [Non-Latin Receipts](../hardware/printers/non-latin-receipts.mdx).

:::note Thermal hardware needs a thermal template
A thermal printer can't print a full-page **HTML** template. The job has to become ESC/POS or Star commands, which HTML can't express. Use a thermal template for thermal hardware. For full-page A4/Letter HTML, print to a system or PDF printer, or through [PrintNode](./cloud-printing.mdx#setup-printnode).
:::

### Logos and images {#logos-and-images}

Use `<image />` to add a logo. The store logo is in `{{store.logo}}`:

```xml
<align mode="center">
  <image src="{{store.logo}}" width="200" />
</align>
```

The app turns the image into printer dots on the device: it fills see-through parts with white, scales it down, and turns it into black and white (dithered, so logos keep their shading). Then it sends it to the printer as an image.

- **Width**: `width` is in printer dots (default 200). The image never prints wider than the paper: 384 dots on 58 mm paper (32 characters or fewer), 576 dots on 80 mm.
- **Accepted sources**: `data:image/png` and `data:image/jpeg` data URLs, `http(s)` URLs, and paths on your own site that start with `/`. Addresses starting with `//`, and paths with backslashes or `..`, are refused.
- **Recommended format**: a high-contrast PNG on a transparent or white background. JPEG works, but its blur can print as noise.
- **SVG is not supported yet** on thermal printers.

### Tips {#tips}

- **Start from a gallery template.** The thermal templates in the gallery use all the patterns above. There are 58 mm, 80 mm and right-to-left receipts, a kitchen ticket, and register closure, count slip and report versions.
- **Test both paper sizes** if your stores use different printers, or stick to `width="*"` columns.
- **Use `_display` fields** for money. They are already formatted for the store's currency ([Currency fields](./receipt-data.mdx#currency-fields)).
- **Keep it simple.** Thermal has fewer formatting tools than HTML on purpose. Lean on `<row>` and `<col width="*">` and let the printer do its thing.

## If something goes wrong {#if-something-goes-wrong}

**The editor preview says "Thermal template rendering error. Check your XML syntax."**
The template can't be read. Two causes:

- The XML isn't well-formed: a tag isn't closed, or a bare `&` or `<` is in the text. Close every tag (`<line />`, not `<line>`) and write `&amp;` for a literal `&`.
- The outermost tag isn't `<receipt>`. Wrap the whole template in `<receipt>…</receipt>`.

**A heading runs into the next line.**
A styled element on its own doesn't end the line. Put a `<text>` inside it ([Wrap styled headings](#wrap-styled-headings-in-text-for-a-line-break)).

**A row wraps onto two lines on paper.**
The fixed widths add up to more than the printer's **Paper width**. Make one column `width="*"`, or budget fixed widths to 42 ([Use `width="*"`](#use-width-for-paper-width-agnostic-layouts)).

**The total is bold in the preview but plain on paper.**
Styling inside a `<col>` doesn't print. Put the `<bold>` around the whole `<row>` ([Tabular Layout](#tabular-layout)).

**The preview is narrower or wider than the paper.**
The paper follows the printer's **Paper width**, not `paper-width`. Set `paper-width` to the same number to preview what prints.

**The cut leaves a tab.**
`<cut />` is a partial cut. Use `<cut type="full" />` for a full cut.

**The logo doesn't print.**
Check the `src` is one of the [accepted sources](#logos-and-images) and isn't an SVG. In the browser, see [Logo Missing in the Browser](../hardware/printers/logo-missing-browser.mdx).

**Question marks, blanks or wrong letters.**
The printer's character table doesn't hold the script. Turn on **Print receipts as an image** ([Non-Latin scripts](#non-latin-and-rtl-scripts)).

**The cash drawer opens twice, or on every receipt.**
**Auto-open cash drawer** opens it after each receipt. A template `<drawer />` opens it whatever that setting says. Use one or the other.

**A template from the old StarPRNT fixed-layout adapter prints nothing useful.**
That adapter was removed in version 1.10. Rebuild the layout with `<row>`, `<col>` and `width="*"`, or start again from a gallery template.
