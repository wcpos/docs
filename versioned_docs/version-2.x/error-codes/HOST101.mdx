**Symptom:** in the web app, red text under **Connect** reads "This store's hosting setup is blocking the app — the details page names the exact cause and fix.", with a **Learn more** link to this page.

**Do this now:** sell from the WCPOS desktop or mobile app for now, and tell whoever looks after your website.

## Fix it at the till {#at-the-till}

1. Send whoever looks after your website a link to this page.
2. Meanwhile, use the desktop or mobile app. They don't need this check.
3. Once it's fixed, reload the web app, enter **Your store's address** and press **Connect**.
4. **If it connects:** carry on selling in the browser.
5. **If the red text shows again:** the block is still there. Tell them again.

## Is anything lost? {#your-data}

No. Nothing on this device or on your store changed. The browser stopped before anything was sent.

## If it keeps happening {#keeps-happening}

Something in front of your store, such as a firewall or a security plugin, blocks the check. Only whoever looks after your website can change that.

<details>
<summary>For whoever looks after your website</summary>

Browsers send an OPTIONS request before each call to the store's REST API. Something in front of the store blocks it, so the real request never goes out.

1. Check the firewall (WAF) for a rule blocking the OPTIONS method, and allow it on the `/wcpos/` REST routes.
2. Check security plugins for a "block uncommon request methods" setting. OPTIONS must stay allowed.
3. Test: an OPTIONS request to the store's REST API must not return 403.

</details>

## Still stuck? {#still-stuck}

If your host says nothing is blocked, tell support the code and when it happened.

<SupportContact />

<details>
<summary>Code details for support</summary>

<ErrorMeta code="HOST101" />

The OPTIONS preflight failed at network level while a simple request got through. Logged as "Store host blocked authorization probes".

</details>
