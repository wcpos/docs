## What this means {#what-this-means}

Your store's server is blocking the web version of WCPOS, so it cannot reach your store.

Something in front of this store — usually a firewall rule — is blocking that check, so the web app's real request is never sent. The desktop and mobile apps are unaffected; the fix is on the server.

## Your data {#your-data}

No order or product data is affected.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

Use the desktop or mobile app while this is being fixed, and tell your site administrator the code, HOST101.

### Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row. The picture shows an example entry, AUTH201; on your till the entry shows this page's code.

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support. The rows beside and under it (event code, record, operation, request, details) are for support too; you don't need to read them.

</JourneyShot>

### On the store {#on-the-store}

For the site administrator.

1. Check the firewall (WAF) for a rule blocking the OPTIONS method and allow it on /wcpos/ REST routes.
2. Some security plugins have a 'block uncommon request methods' toggle — OPTIONS must stay allowed.
3. Test: an OPTIONS request to the store's REST API should not return 403.

<details>
<summary>Technical detail</summary>

The server is blocking the browser's permission check (CORS preflight), so the web app cannot reach it.

Browsers send an OPTIONS request before any cross-origin API call that carries custom headers. Something in front of this store — usually a firewall rule — is blocking OPTIONS, so the browser never sends the real request. Native apps are unaffected; the fix is server-side. The desktop and mobile apps do not use CORS.

</details>
