**Symptom:** after a scan, a pop-up reads **Barcode not found** with the code, and the code stays in **Search products**. On the **Products** screen, it reads "No products matched the current search and filters." with **Help**.

**Do this now:** search for the product by name and add it to the cart by hand.

## Fix it at the till {#at-the-till}

1. Check the code in **Search products** against the label. If the scanner misread it, clear it with the cross at the end of the field and scan again.
2. Search for the product by name and add it to the cart.
3. **If the product is listed:** its barcode in your store is missing or different. Tell a manager the code and the product's name.
4. **On the Products screen:** clear the filters first, because a category or stock filter narrows every search. If you typed the search, check spelling and stray spaces.
5. **On the Products screen, for a product added today:** in **Store health → Database**, press **⋮** on **Products**, then **Check for changes now**, and scan again.

## Is anything lost? {#your-data}

No. The scan added nothing to the cart, and no product or order changed.

## If it keeps happening {#keeps-happening}

If every scan misses, your store is looking for barcodes in the wrong place. Tell whoever looks after your website.

<details>
<summary>For whoever looks after your website</summary>

Scans match the field set in **WP Admin > POS > Settings > General > Barcode Field**.

1. Add the scanned value to the product in that field, such as `_global_unique_id` (GTIN), `_sku` or `_barcode`.
2. For a product with variations, put it on the variation itself, not the parent.
3. If every scan misses, set **Barcode Field** to the field your products keep barcodes in.

</details>

## Still stuck? {#still-stuck}

[Send the log to support](../support/logs.mdx#for-support) with the code you scanned and the product's name.
