**Symptom:** a till on WCPOS 1.10 or 1.11 logs CLIENT144, sometimes with a pop-up starting "A search index rebuild failed" and "Try another search; reload if results still look wrong." WCPOS 2 doesn't log this code.

{/* source: v1.11.9 core.json:1635, :1728; v1.11.9 packages/database/src/plugins/search.ts:613-621, :896-902 (showToast true); v1.11.9 packages/core/src/contexts/merchant-toast.ts:68-73 (summary as title, action as description);
    error-registry.json:2221 (introduced 1.10.6); not raised at 6b2a2cb4f: packages/query/src/search-blob.ts:12-24, no call site outside generated files and tests */}

**Do this now:** run another search on the same list; WCPOS tries to start its search index again.

{/* source: core.json:2655; v1.11.9 packages/query/src/engine-query.ts:283-288 (the next keystroke retries); error-registry.json:2214 */}

## Fix it at the till {#at-the-till}

1. Find the entry in **Logs**. If its error mentions storage, free up space on the device; on the web, don't use a private window.
2. Run another search on the list that went wrong.
3. **If results look right:** there's nothing more to do.
4. **If results are still missing or out of order:** close WCPOS completely and open it again, or reload the tab on the web.
5. **If the code returns after that:** use **Copy debug info** and contact support.

{/* source: step 1 error-registry.json:2213, v1.11.9 search-readiness.ts:334-337 and search.ts:613-621 (the context carries the error); step 2 engine-query.ts:283-288;
    step 4 core.json:2655, error-registry.json:2215; step 5 error-registry.json:2215 */}

## Is anything lost? {#your-data}

No. Search keeps answering, from the index with wrong results hidden or from a direct look through this device's data. Nothing on your store changed.

{/* source: error-registry.json:2208, :2211; v1.11.9 engine-query.ts:326-328, :340-345 (filtered results), :255-269, :347-356 (scan) */}

## If it keeps happening {#keeps-happening}

WCPOS 2 no longer uses this search index, so it can't log this code. See [Upgrade to 2.0](../getting-started/upgrading-to-2.mdx) for whether your store can move.

{/* source: search-blob.ts:12-24 (6b2a2cb4f); no raise site at v2.0.0 or 6b2a2cb4f */}

## Still stuck? {#still-stuck}

Contact support with the debug info and the till's WCPOS version.

{/* source: error-registry.json:2215 */}
