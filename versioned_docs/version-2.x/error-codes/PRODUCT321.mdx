**Symptom:** after a scan, a pop-up reads **Several matches**, and the code stays in **Search products**. On the **Products** screen, it reads "More than one product matches this barcode." with **Help**.

**Do this now:** pick the right product from the list under **Search products** and add it to the cart by hand.

## Fix it at the till {#at-the-till}

1. Clear any category or stock filter: it can hide some of the matches.
2. Add the right product to the cart from the list, and finish the sale.
3. Tell a manager the code and the name of every product listed, so each gets its own barcode.
4. Once that's done, in **Store health → Database**, press **⋮** on **Products**, then **Check for changes now**. Do the same on **Variations** if a match was one. Scan again.

## Is anything lost? {#your-data}

No. The scan added nothing, because the till won't guess between products. No product or order changed.

## If it keeps happening {#keeps-happening}

If many barcodes clash, ask a manager to check how barcodes are set on your store.

<details>
<summary>For whoever looks after your website</summary>

1. In WP Admin, open each product the cashier listed and give each its own barcode.
2. Check the field set in **WP Admin > POS > Settings > General > Barcode Field**, by default the product's GTIN (`_global_unique_id`).
3. A duplicate in the SKU or another barcode field matches too, so check those as well.

</details>

## Still stuck? {#still-stuck}

[Send the log to support](../support/logs.mdx#for-support) with the code you scanned.

<SupportContact />

<details>
<summary>Code details for support</summary>

<ErrorMeta code="PRODUCT321" />

The entry is at warn level: press **All** in **Logs** and search for PRODUCT321. It carries the scanned code and, from the **Products** screen, the number of matches.

</details>
