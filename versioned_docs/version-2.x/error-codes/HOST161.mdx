**Symptom:** while you sell, a pop-up reads "The host is rate-limiting this store's tills." and "Ask your host to raise or exempt the API rate limit.", with a **Help** button.

**Do this now:** keep selling: syncing carries on by itself, more slowly, while you tell whoever looks after your website.

## Fix it at the till {#at-the-till}

1. Keep selling. Other tills' sales and store changes reach this till later.
2. Open **Store health**, then **Performance**. The pace line shows **Easing off** or **Paused until …** while your host refuses.
3. Send whoever looks after your website a link to this page.
4. To see when it started, open **Logs**, press **All**, type HOST161 in **Search Logs** and [open the entry](../support/logs.mdx#open).

### Check it worked {#check}

In **Store health → Performance**, the pace line goes back to **Normal pace**. The till recovers by itself.

## Is anything lost? {#your-data}

No. No order or product data is affected. Syncing carries on, but lags until the limit is raised.

## If it keeps happening {#keeps-happening}

Your host limits how many requests one address can make, and several tills on one internet connection share one address. Only whoever looks after your website can raise the limit.

<details>
<summary>For whoever looks after your website</summary>

The host keeps answering 429 (too many requests) even though the app backs off and honours Retry-After delays.

1. Ask the host to raise or exempt the REST API rate limit for the store's own traffic. Name the shop's static IP if it has one.
2. Check whether a security service counts repeated 429s toward a block (for example Sucuri's IDS). If so, exclude the store's API from that counter.
3. If several tills share one connection, tell the host: one IP here is a whole shop, not one user.

</details>

## Still stuck? {#still-stuck}

If your host says the limit is raised, [send the log to support](../support/logs.mdx#for-support).
