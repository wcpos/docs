## What this means {#what-this-means}

The host is rate-limiting this store's tills.

The server keeps answering "too many requests" even though the app is already slowing down and waiting as the server asks. Several tills on one internet connection share one address, so the host treats them as a single very busy client. Syncing continues automatically but will lag until the limit is raised.

## Your data {#your-data}

No order or product data is affected.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

Tell your site administrator the code, HOST161, and what you were doing when it appeared.

### On the store {#on-the-store}

For the site administrator.

1. Ask the host to raise or exempt the REST API rate limit for the store's own traffic — name the shop's static IP if it has one.
2. Security services that count repeated error responses (429s) toward a block (for example Sucuri's IDS) may need the store's API excluded from that counter.
3. If several tills share one connection, mention that to the host: one IP here is a whole shop, not one user.

<details>
<summary>Technical detail</summary>

The server keeps answering 429 (too many requests) even though the app is already backing off and honoring the server's Retry-After delays. Per-source rate limits treat several tills on one internet connection as a single very busy client.

</details>

## Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row.

<JourneyShot manifest={logs} device="tablet" step={3} offsets={[[50, 0], [64, -10], [-54, -97], [131, 0], [101, 0], [-33, 0]]} alt="An error entry opened under its row in Store health → Logs: what the server said, what to do, Open record, the Help link, the event code with Copy, and the record, operation and request">

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support.

</JourneyShot>
