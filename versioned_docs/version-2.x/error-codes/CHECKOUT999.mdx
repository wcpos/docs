**Symptom:** checkout stops with an error that has no code of its own. Its entry in **Store health → Logs** shows CHECKOUT999, and any pop-up has no **Help** button.

{/* source: core.json:2494; packages/utils/src/logger/index.ts:398-436 (an error row with no code in a wcpos.pos.checkout or wcpos.checkout category gets CHECKOUT999, codeFallback), :873-881 (Help);
    every coded checkout error at 6b2a2cb4f names its own code (scripts/errors-in.sh); extension route: packages/core/src/extensions/actions/types.ts:262-272. See CHECK.md */}

**Do this now:** check whether the order was created and paid before you charge again.

{/* source: core.json:2610; error-registry.json:1244 */}

:::warning

Don't charge the customer again until you know whether this sale was paid.

:::

{/* source: dataSafety outcome-unknown, error-registry.json:1239; core.json:2610 */}

## Fix it at the till {#at-the-till}

1. Check the payment: the card terminal or provider's screen, or for cash, the drawer.
2. **With WCPOS Pro:** in **Store health → Database**, press **⋮** on **Orders**, then **Check for changes now**, and open the order in **Orders**.
3. **Without Pro:** ask a manager to find the order in **WooCommerce → Orders** by its total and the time.
4. **If the order is paid, or the customer paid:** don't charge again.
5. **If there's no order and no charge:** try checkout once more.

{/* source: step 1 dataSafety outcome-unknown, as CHECKOUT201; step 2 packages/core/src/screens/main/health/database.tsx:347-362, core.json:1910, :731, versioned_docs/version-2.x/orders/index.mdx:18; step 3 core.json:2610, error-registry.json:1244, current/CHECKOUT999.mdx At the till step 1;
    steps 4-5 core.json:2610 ("Do not re-charge"), current/CHECKOUT999.mdx What this means */}

## Is anything lost? {#your-data}

Whether the order was created or paid isn't known. Go by the order's status and the payment, not by the error.

{/* source: dataSafety outcome-unknown, error-registry.json:1239; current/CHECKOUT999.mdx Your data */}

## If it keeps happening {#keeps-happening}

If it happens again, press **Copy debug info** in **Store health → Logs** and contact support.

{/* source: escalation support-with-export, error-registry.json:1240, :1246; current/CHECKOUT999.mdx At the till step 3; core.json:2124 */}

<details>
<summary>For whoever looks after your website</summary>

This code means the failure has no dedicated code yet, so the entry's message is the failing step's own words.

1. In WP Admin, check **WooCommerce → Orders** for the order.
2. On the till, open **Store health → Logs**, press **Errors** and open the entry. Note its message, the event code and any serverCode.
3. Send support the till's **Copy debug info** report with that note and the time.

{/* source: error-registry.json:1244-1246; current/CHECKOUT999.mdx At the till step 2, Technical detail, On the store step 1; logger/index.ts:433-436; core.json:2133, :2124 */}

</details>
