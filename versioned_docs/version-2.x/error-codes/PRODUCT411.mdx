## What this means {#what-this-means}

Barcode scanning settings could not be loaded, so scans may not match products.

The POS keeps trying to load these settings in the background. If scanning stays unreliable, reload the app once.

## Your data {#your-data}

No order or product data is affected.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

1. Keep working — the POS retries loading the barcode settings in the background.
2. If scans keep matching nothing, reload the app once.
3. If it persists after a reload, the settings request itself is failing — check the connection to the store, and look for matching errors in [**Store health → Logs**](#log-entry) (ask whoever manages the store if you need help).

## Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row.

<JourneyShot manifest={logs} device="tablet" step={3} offsets={[[50, 0], [64, -10], [-54, -97], [131, 0], [101, 0], [-33, 0]]} alt="An error entry opened under its row in Store health → Logs: what the server said, what to do, Open record, the Help link, the event code with Copy, and the record, operation and request">

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support.
