# Error Codes

When WCPOS encounters an issue, it displays an error code that helps identify the problem. From **v1.10.0**, codes follow the format **domain + three digits** — for example `SYNC131` or `AUTH311`. The domain names the area of the POS; the number identifies the specific condition. Every code has its own page with what it means, what to do, and what it means for your data.

In the POS, error codes appear in **Store health → Logs**: expand a row and use the **Help** link to jump straight to the code's page here.

## Error Domains (v1.10.0+) {#error-domains}

| Domain | Area |
|--------|------|
| [`AUTH`](#auth) | Login, sessions, and tokens |
| [`CHECKOUT`](#checkout) | Completing orders at the till |
| [`CLIENT`](#client) | The POS app itself and local storage |
| [`DISPLAY`](#display) | The customer-facing display |
| [`HOST`](#host) | Hosting and firewall rules that block the POS |
| [`LICENSE`](#license) | Pro licence activation and validation |
| [`PAYMENT`](#payment) | Payment gateways and terminals |
| [`PRINT`](#print) | Receipt printing |
| [`PRODUCT`](#product) | Product data and catalogue operations |
| [`REGISTER`](#register) | Cash drawer, register sessions, and counts |
| [`SYNC`](#sync) | Synchronisation between the POS and your store |

Find your code below, or search for it.

Codes ending in `999` are the domain's catch-all for conditions that don't yet have a specific code.

## Codes from before v1.10.0 {#legacy-codes}

Codes such as `API04001` come from versions before v1.10.0; this version never produces them. You may still see one in a log entry kept from before you upgraded, or in an old support thread. Switch the version menu to **1.x** to look them up.
