## What this means {#what-this-means}

A change on this device met a newer edit in your store. Nothing is lost.

If **Store health → Database** lists a held change for this record, tap **Send again** to keep this device's version, or **Use server version** to keep the store's. Otherwise, nothing to do — it has already been settled.

## Your data {#your-data}

Nothing is lost. When a change is held, your store keeps its version and this device keeps its change until you choose which to keep; further edits to that record wait on this device until then. Don't clear this device's data while a change is held — clearing deletes the held change.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

1. Open **Store health → Database**. A held change is listed in a panel beginning **"1 change was held"** (or **"… changes were held"**), with the record it belongs to.
2. If nothing is held for this record any more, it has already been settled — here or in another tab — and there is nothing to do.
   - An order clash that WCPOS settles by itself, by sending this device's version again, is logged as [SYNC222](/error-codes/SYNC222) instead.
3. If a change is held, press **Open record** (where shown) to see this device's version, and compare it with the store's version (your site administrator may need to do this; see [On the store](#on-the-store)).
4. To keep this device's version, tap **Send again** — the change is sent again and replaces the store's values for the fields this device changed.
   - To keep the store's version, tap **Use server version** (some rows say **Discard device change**) and confirm — this device's change is dropped.
   - Further edits to that record wait until you choose.
5. Frequent conflicts on the same records usually mean two people edit the same data in parallel (see [On the store](#on-the-store)). Agree on where each kind of edit happens.

### On the store {#on-the-store}

For the site administrator.

1. When a change is held, compare this device's version with the same record in WP Admin.
2. If conflicts on the same records are frequent, check where the same data is edited in parallel — for example stock on the till and in WP Admin.

## Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row. The picture shows an example entry, AUTH201; on your till the entry shows this page's code.

<JourneyShot manifest={logs} device="tablet" step={3} offsets={[[17, 28], [549, -9], [-54, -97], [131, 0], [101, 0], [-33, 0]]} alt="An error entry opened under its row in Store health → Logs: what the server said, what to do, Open record, the Help link, the event code with Copy, and the record, operation and request">

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support. The rows under it are for support; you don't need to read them.

</JourneyShot>
