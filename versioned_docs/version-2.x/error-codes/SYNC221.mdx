## What this means {#what-this-means}

A change on this device clashed with an edit made in your store.

Open the record and check which version is correct. The POS keeps both sides safe until the clash is settled — nothing is lost.

## Your data {#your-data}

The record itself is safe and unchanged — the POS keeps both the till's and the store's versions until the clash is settled.

## Troubleshoot {#troubleshoot}

1. Open **Store health → Database**. If a panel beginning **"1 change was held"** (or **"… changes were held"**) names the record, continue below. If no such panel is showing, the clash was settled automatically — orders are resent on top of the store's version by themselves — and nothing needs doing.
2. Press **Open record** (where shown) to see this device's version, and compare it with the same record in WP Admin (a site admin may need to do this).
3. If this device's version is right, press **Send again** — the change is sent again, replacing the store's values for the fields this device changed. If the store's version is right, press **Use server version** (some rows say **Discard device change**) and confirm; this device's change is dropped.
4. Frequent conflicts on the same records usually mean two people edit the same data in parallel — for example stock on the till and in WP Admin. Agree on where each kind of edit happens.
