## What this means {#what-this-means}

Your store's server is set up wrongly for the web version of WCPOS, so the browser refuses its answers.

The store answers, but the browser then hides the real answer from the web app, which also masks every other error behind a generic network failure. The fix is on the server.

## Your data {#your-data}

No order or product data is affected.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

Use the desktop or mobile app while this is being fixed, and tell your site administrator the code, HOST111.

### On the store {#on-the-store}

For the site administrator.

1. Look for a second CORS layer (a plugin AND the server config both adding headers) and remove one — duplicated Access-Control-Allow-Origin is a fatal browser error.
2. On nginx, add_header lines skip error responses unless they end with 'always' — CORS headers must be on 4xx/5xx too.
3. If a CDN or proxy adds CORS headers, make sure it does not conflict with WordPress's own.

<details>
<summary>Technical detail</summary>

The server's cross-origin (CORS) configuration is broken, so the browser refuses its responses.

The store's CORS response headers are wrong — duplicated, set to the wrong origin, or missing on error responses. The fix is server-side: exactly one Access-Control-Allow-Origin, present on every status code. The desktop and mobile apps do not use CORS.

</details>

## Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row. The picture shows an example entry, AUTH201; on your till the entry shows this page's code.

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support.
