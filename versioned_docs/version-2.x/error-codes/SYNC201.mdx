## What this means {#what-this-means}

This record was rejected by your store and is saved only on this device.

Correct the reason shown for the named record, then retry it. Export diagnostics if it remains rejected.

## Your data {#your-data}

The change is saved on this device but has not reached your store — unless it was an edit to a product, variation, customer or coupon, which is undone automatically so the device matches your store again. If this persists, export diagnostics and contact WCPOS support.

## Troubleshoot {#troubleshoot}

1. If a toast said **"Change rejected by your store — reverted"** (edits to products, variations, customers and coupons), the till has already put the store's version back and there is nothing to resend. Read the reason, correct it, and save the edit again only if you still need it.
2. Otherwise — an order, or a record created on this device — open **Store health → Database**. The refused change is listed under **"… changes never reached your server"** with your store's reason on its row. Fix what the reason names on the record itself, for example a field on the order, while the change stays listed.
3. Back in **Store health → Database**, press **Send again** on that row. It rebuilds the change from what is now on this device and sends it.
4. If the change is no longer wanted, press **Discard** instead: the store's version is kept. Read the confirmation first — for a record the store never saved, discarding deletes it from this device.
5. **Site admin:** if the reason says the user is not allowed to make the change, their role lacks that task — see [AUTH201](/error-codes/AUTH201). If the reason mentions a field the POS does not show, open the same record in WP Admin — another plugin may add validation the POS cannot see. If it is still refused, use **Copy debug info** on the **Logs** tab and contact support.
