**Symptom:** a till on WCPOS 1.10 or 1.11 logs CLIENT142: "The search index did not answer in time, so WCPOS searched the catalogue directly instead." WCPOS 2 doesn't log this code.

**Do this now:** nothing; search keeps answering, and the index takes over again once it responds.

## Fix it at the till {#at-the-till}

1. Keep searching. Results come from the products on this device and can be a little slower.
2. On the web, keep the POS in its own window rather than a background tab.
3. Searches stay slow? Reload: close WCPOS completely and open it again, or reload the tab on the web.
4. **If the code returns after that:** use **Copy debug info** and contact support.

## Is anything lost? {#your-data}

No. Your search was still answered, by a direct look through this device's products. Nothing on your store or on the till changed.

## If it keeps happening {#keeps-happening}

WCPOS 2 no longer uses this search index, so it can't log this code. See [Upgrade to 2.0](../getting-started/upgrading-to-2.mdx) for whether your store can move.

## Still stuck? {#still-stuck}

Contact support with the debug info and the till's WCPOS version.
