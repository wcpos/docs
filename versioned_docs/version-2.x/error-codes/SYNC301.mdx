## What this means {#what-this-means}

Some older store changes were skipped and must be downloaded again.

Run a targeted download for the affected data and export diagnostics if the gap remains.

## Your data {#your-data}

Some store changes have not yet reached this device, so local data may be out of date until the download completes. No local changes are at risk. If this persists, export diagnostics and contact WCPOS support.

## Troubleshoot {#troubleshoot}

1. Keep selling — nothing on this device is lost. The log entry may say how many store changes were skipped; they can be any kind of data.
2. Open **Store health → Database**. Before re-downloading anything, wait until **changes waiting to send** is 0 and check that no **"… changes never reached your server"** or **"… changes were held"** panel is showing.
3. Spot-check a few prices or stock levels you know were changed recently (whoever manages the store can compare against WP Admin). For any data that looks out of date, open the **⋮** menu on its row and choose **Clear & re-download…**. That clears the collection so every record is fetched fresh from your store, including the skipped changes — some straight away, the rest as they are needed. Start with **Products** if you are unsure.
4. If the code keeps reappearing, use **Copy debug info** on the **Logs** tab and contact support rather than clearing more data.
