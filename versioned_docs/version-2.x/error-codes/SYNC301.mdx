## What this means {#what-this-means}

Some older store changes were skipped and must be downloaded again.

Run a targeted download for the affected data and export diagnostics if the gap remains.

## Your data {#your-data}

Some store changes have not yet reached this device, so local data may be out of date until the download completes. No local changes are at risk. If this persists, export diagnostics and contact WCPOS support.

## Troubleshoot {#troubleshoot}

1. Keep selling — nothing on this device is lost. The log entry may say how many store changes were skipped; they can be any kind of data.
2. Open **Store health → Database**. Before re-downloading anything, wait until **changes waiting to send** is 0 and check that no **"… changes never reached your server"** or **"… changes were held"** panel is showing.
3. The skipped changes can be in any collection, and the log does not say which. To be sure nothing stays stale, re-download every row at a quiet moment: take no sales and make no edits on this device until you have finished. Immediately before each row, repeat the checks from step 2; then open that row's **⋮** menu and choose **Clear & re-download…**, waiting for it to finish before the next. Before clearing **Orders**, also save every open cart on this device with **Save to Server** (or finish it) — a cart never saved to your store exists only on this device and is not counted in any of the checks above, so clearing **Orders** deletes it. If a cart cannot be saved, skip the **Orders** row and contact support. Start with **Products**, **Variations** and **Tax rates**, which affect prices at the till. Each re-download fetches that collection fresh from your store — some records straight away, the rest as they are needed.
4. If the code keeps reappearing, use **Copy debug info** on the **Logs** tab and contact support rather than clearing more data.
