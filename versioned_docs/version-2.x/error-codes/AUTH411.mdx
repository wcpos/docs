## What this means {#what-this-means}

The store address is missing or not a valid URL.

Either the address field was empty, or your store answered but its WCPOS sign-in address is invalid — which is fixed on the store, not at the till.

## Your data {#your-data}

No order or product data is affected.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

1. Type the store's address into **Enter the URL of your WooCommerce store** — for example `shop.example.com` — and press **Connect**. A field holding only spaces counts as empty.
2. If the address is filled in and the message reads **"WCPOS login URL is invalid. Please ensure WCPOS plugin is properly configured"**, the problem is on the store. Tell your site administrator.
3. Once your site administrator has updated WCPOS (see On the store), press **Connect** again.

### On the store {#on-the-store}

For the site administrator.

1. Update WCPOS to the latest version in **WP Admin → Plugins**. Do not deactivate and reactivate it to fix this — reactivating resets every role's POS permissions to the defaults.
2. If that does not clear it, open the store's full address followed by `/wp-json/` in a browser — for example `https://your-store.com/wp-json/`, or `https://example.com/shop/wp-json/` when WordPress lives in `/shop`.
   - If that returns a 404 (for example on plain permalinks), use the same address followed by `/?rest_route=/` instead.
3. Under `authentication` → `wcpos` → `endpoints`, `authorization` should be a plain web address. If it is a list, an object or a number instead, a security, caching or REST-customising plugin is changing that response — disable those one at a time on a staging copy to find it.

## Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row. The picture shows an example entry, AUTH201; on your till the entry shows this page's code.

<JourneyShot manifest={logs} device="tablet" step={3} offsets={[[17, 28], [549, -9], [-54, -97], [131, 0], [101, 0], [-33, 0]]} alt="An error entry opened under its row in Store health → Logs: what the server said, what to do, Open record, the Help link, the event code with Copy, and the record, operation and request">

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support. The rows beside and under it (event code, record, operation, request, details) are for support too; you don't need to read them.
