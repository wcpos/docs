## What this means {#what-this-means}

This store now requires a newer version of the POS app.

Your store's WCPOS plugin has moved to a newer sync protocol than this version of the app speaks, and the store deliberately pauses syncing until the app is updated. This is a protection, not a fault: it stops an out-of-date app from reading or writing store data incorrectly. Update WCPOS (on the web, reload the page), then reopen. Unsent sales stay on this device and send after the update.

## Your data {#your-data}

Nothing on the till is lost. Sales and edits waiting to be sent stay safely on the device and sync once an updated app connects to the store. If no newer app exists yet (see the last two steps below), they stay queued until one does.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

1. On the web app, reload the browser tab — the web app picks up the new version on reload. If the screen comes back, use a hard reload (hold **Shift** while reloading).
2. On desktop, install the pending update and reopen the app — the check runs when the app reconnects. If no update is offered, download the latest build from the [Installation](/getting-started/installation) page.
3. On iPhone, iPad or Android, update WCPOS through the channel you installed it from — TestFlight on iOS, the Play testing programme on Android; both are linked from the [Installation](/getting-started/installation) page — then reopen the app.

### On the store {#on-the-store}

For the site administrator.

1. If no newer app is available yet, the store's WCPOS plugin was updated ahead of the matching app release. Restoring the previous WCPOS plugin version on the store resumes syncing until the newer app ships.
2. If neither an app update nor a plugin rollback is available to you, contact WCPOS support.

## Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row. The picture shows an example entry, AUTH201; on your till the entry shows this page's code.

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support. The rows under it are for support; you don't need to read them.
