## What this means {#what-this-means}

The store returned no checkout result, so the order status is unknown.

Open the order and check its status before retrying. If it's paid or completed, don't charge again. An empty response often means the order was created but the confirmation never arrived.

## Your data {#your-data}

The result couldn't be confirmed — check before trying again. If this keeps happening, use **Copy debug info** on the **Logs** tab and contact WCPOS support.

## Troubleshoot {#troubleshoot}

**At the till:**

1. Do not press **Process Payment** (on the checkout's **Legacy** tab) again and do not charge the customer again until you know the order's status.
2. Open the order and check its status. On WCPOS Pro, refresh the till's orders first — **Store health → Database**, the **⋮** menu on the **Orders** row, **Check for changes now** — then open the order in **Orders**. Without Pro, ask someone to open it in **WooCommerce → Orders** in WP Admin, searching by the total and the last few minutes.
3. Finding the order is not enough — an order can exist without being paid. If its status is **Processing** or **Completed**, the sale went through: don't charge again.
4. If the order is still unpaid, or you can't find it, check whether the customer paid — for a card, the payment provider's own screen, receipt or dashboard; for cash, the drawer and the amount tendered. If they paid, don't charge again. If you found the order, reload the app and check its status again (on start, the till finishes any sale whose payment it recorded); if you can't find it, or it still isn't paid, go to the last step.
5. If the order is not paid and the provider shows no charge, retry checkout once.
6. If it is still unclear, use **Copy debug info** on the **Logs** tab and contact support before another attempt.

**On the store** — for the site administrator:

1. Check WooCommerce → Status → Logs for a fatal error during checkout — a PHP crash after the order is created produces exactly this.
2. If WooCommerce's log shows nothing, ask the hosting provider for the server's PHP error log — some fatal errors are captured only there.

**For a developer:** in the browser's developer tools — or the desktop app's **Advanced → Toggle Developer Tools** — the checkout request on the Network tab with a success status but an empty or truncated body points at a plugin or server buffer cutting the response short.
