## What this means {#what-this-means}

The host's security filter is blocking product searches.

Product names with accents, and searches containing words like 'select' or 'union', will fail even though they are ordinary catalogue searches. The till works otherwise; searches will be unreliable until the rule is relaxed.

## Your data {#your-data}

No order or product data is affected.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

Tell your site administrator the code, HOST141, and what you were doing when it appeared.

### On the store {#on-the-store}

For the site administrator.

1. Ask the host to allow-list the store's own REST search parameters (/wcpos/ and /wc/ routes) in the query-string firewall rules.
2. On OWASP CRS-based firewalls, the SQL-injection rules on the 's' and 'search' arguments are the usual culprits — exclude those arguments for REST API routes.
3. Security plugins with a 'filter suspicious query strings' toggle need an exception for the REST API, not a global off switch.

<details>
<summary>Technical detail</summary>

A firewall rule on this host rejects REST requests whose query string contains non-ASCII characters or SQL-looking words. Those searches fail with a 403.

</details>

## Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row.

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support.

</JourneyShot>
