**Symptom:** while you connect to your store, a pop-up reads "The host's security filter is blocking product searches." and "Ask your host to allow product-search requests.", with a **Help** button.

**Do this now:** carry on connecting and selling, and send whoever looks after your website a link to this page.

## Fix it at the till {#at-the-till}

1. Carry on. The pop-up doesn't stop the connection, and the till works otherwise.
2. Send whoever looks after your website a link to this page.
3. Until it's fixed, searches with accents or words like "select" or "union" can fail. If a product doesn't turn up, try part of its name or its SKU.

## Is anything lost? {#your-data}

No. No order or product data is affected. Only some product searches are refused.

## If it keeps happening {#keeps-happening}

A firewall rule on your host treats ordinary search words as an attack. Only whoever looks after your website can relax it.

<details>
<summary>For whoever looks after your website</summary>

The rule rejects REST requests whose query string holds non-ASCII characters or SQL-looking words, with a 403.

1. Allow-list the store's own REST search parameters on the `/wcpos/` and `/wc/` routes in the query-string firewall rules.
2. On OWASP CRS-based firewalls, the SQL-injection rules on the `s` and `search` arguments are the common cause: exclude those arguments for REST API routes.
3. Security plugins with a "filter suspicious query strings" toggle need an exception for the REST API, not a global off switch.

</details>

## Still stuck? {#still-stuck}

If your host says nothing is blocked, tell support the code and when the pop-up showed.
