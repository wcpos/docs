**Symptom:** a log from WCPOS 1.10 names CLIENT121: the browser let only one tab send changes. WCPOS 2 doesn't log this code. A second tab shows **The POS is open in another tab** instead.

{/* source: core.json:2509; error-registry.json:1561, :1576 (retired on 2.0, kept for 1.10.x logs); raised at v1.10.9 apps/main/lib/sync-log-observer.ts:649-654 (engine.write-leader.degraded), not raised at v1.11.9 or 6b2a2cb4f (only generated files and error-registry.test.ts:93);
    apps/main/components/parked-tab.tsx:11 */}

**Do this now:** nothing to fix; keep the POS in one browser tab.

{/* source: core.json:2625 (nothing to do); apps/main/components/live-tab-gate.web.tsx:108-110 (only the live tab renders the app) */}

## Fix it at the till {#at-the-till}

1. Use the POS in one browser tab. A second tab reads **The POS is open in another tab** and **Only one tab can run the register.**
2. Go back to the first tab, or press **Take over here** to carry on in this one.
3. **If it reads The other tab isn't answering:** close or reload the other tab, then carry on here.
4. **If it reads Local database unavailable:** press **Reload the app**.

{/* source: step 1 parked-tab.tsx:11; live-tab-gate.web.tsx:110; step 2 parked-tab.tsx:17, :54-60, packages/database/src/live-tab/live-tab.web.ts:12-16 (waits for a payment or a save to finish), parked-tab.tsx:12-14;
    step 3 parked-tab.tsx:15, live-tab.web.ts:11 (3 s); step 4 parked-tab.tsx:16, :18, :52-53 */}

## Is anything lost? {#your-data}

No. A waiting tab never opens the till's data, so nothing in the first tab is disturbed. No order or product data is affected.

{/* source: parked-tab.tsx:8-9 (a parked tab never opens the user database); reference/sync-engine.mdx#multi-tab; dataSafety no-impact, error-registry.json:1561 */}

## If it keeps happening {#keeps-happening}

The desktop and mobile apps have no tabs to manage. A browser that can't coordinate tabs runs every tab without this check.

{/* source: apps/main/components/live-tab-gate.tsx and live-tab-gate.electron.tsx (render children, no gate); live-tab-gate.web.tsx:37, :89 (no Web Locks: every tab is live) */}

## Still stuck? {#still-stuck}

If a tab stays on **Taking over…**, contact support and say which browser you use.

{/* source: parked-tab.tsx:12-14 */}
