## What this means {#what-this-means}

Search showed some results that don't match your products, so WCPOS hid them.

Nothing to do unless search still looks wrong — then reload WCPOS.

To answer searches instantly, WCPOS keeps a local search index of the lists it searches — products, customers, orders and similar. A self-check found entries in that index that do not actually match what was typed. The mismatched results were hidden straight away. The app may also rebuild the index by itself, but only once per list per session, so a rebuild isn't guaranteed.

## Your data {#your-data}

No store data was changed. This concerns only the local search index, which is derived from the data already on this device — hiding a mismatched result changes what search shows, never the underlying record.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

1. Nothing to do unless search still looks wrong — sales can continue normally.
   - If you want to check, re-run the search named in [the log entry](#log-entry) (its context records the search term) and confirm the results now match what was typed, with nothing you expected missing.
2. If search still shows wrong results, or misses a product, customer or order you know exists, reload the app — on web, reload the browser tab; on desktop and mobile, close and reopen the app. That lets it attempt a fresh index rebuild the next time the problem is detected.
3. If the code returns after a reload, use **Copy debug info** in [**Store health → Logs**](#log-entry) and contact support — the entry's context names the list that was affected and the search that triggered it.

## Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row. The picture shows an example entry, AUTH201; on your till the entry shows this page's code.

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support. The rows under it are for support; you don't need to read them.
