**Symptom:** a till on WCPOS 1.10 or 1.11 logs CLIENT143: "Search was missing a product it should have found." Searches could have shown fewer results than the device holds. WCPOS 2 doesn't log this code.

**Do this now:** keep selling; reload only if a product you can see still won't come up in search.

## Fix it at the till {#at-the-till}

1. Keep selling. WCPOS rebuilds the index once per list in each session, so a repeat of this code needs the next step.
2. Search still misses something you can see, such as a product, customer or order? Close WCPOS completely and open it again, or reload the tab on the web.
3. **If search finds it now:** there's nothing more to do.
4. **If the code returns after a reload:** use **Copy debug info** and contact support.

## Is anything lost? {#your-data}

No. The search index is built from the data already on this device, so nothing is lost when it's rebuilt. Nothing on your store changed.

## If it keeps happening {#keeps-happening}

WCPOS 2 no longer uses this search index, so it can't log this code. See [Upgrade to 2.0](../getting-started/upgrading-to-2.mdx) for whether your store can move.

## Still stuck? {#still-stuck}

Contact support with the debug info, the record search missed and the till's WCPOS version.
