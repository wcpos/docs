## What this means {#what-this-means}

Search was missing a product it should have found.

Nothing to do unless a product you can see still won't come up in search — then reload WCPOS.

A periodic self-check asked the local search index for a record by that record's own words, and the index did not return it. That means searches may have been showing fewer results than this device really holds. The app may rebuild the index by itself, but only once per list per session, so a rebuild isn't guaranteed.

## Your data {#your-data}

No store data was changed. This concerns only the local search index, which is derived from the data already on this device — nothing is lost when it is rebuilt.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

1. Nothing to do unless a product you can see still won't come up in search — sales can continue normally.
   - The app may rebuild the index by itself, but only once per list per session, so if this code repeats, continue to the next step.
2. If search still misses records you can see in the app — a product, customer, order or other list — reload the app: on web, reload the browser tab; on desktop and mobile, close and reopen the app. That lets it attempt a fresh rebuild the next time the problem is detected.
3. If the code returns after a reload, use **Copy debug info** in **Store health → Logs** and contact support — [the log entry](#log-entry) includes the details support needs to identify the affected list and the record the index missed.

## Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row. The picture shows an example entry, AUTH201; on your till the entry shows this page's code.

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support. The rows beside and under it (event code, record, operation, request, details) are for support too; you don't need to read them.
