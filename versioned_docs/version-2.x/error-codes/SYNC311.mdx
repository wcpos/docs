## What this means {#what-this-means}

Data on this device was saved by a different WCPOS version and can't be opened yet.

Update WCPOS to the latest version and reopen. If it still won't open, tap **Copy debug info** and contact support. This usually follows an app update or downgrade on this device.

:::warning Don't clear this device's data
This device may hold sales that haven't reached your store — for example sales taken while offline. While the data can't be opened, they can't be sent, so clearing the local database, signing out or reinstalling would delete them permanently. Contact support before clearing anything.
:::

## Your data {#your-data}

Don't clear this device's data — it may hold sales that haven't reached your store. Your store's own data is safe and unaffected.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

1. Update WCPOS to the latest version on this device, then reopen it:
   - **Web:** reload the browser tab. If the old version comes back, hold **Shift** while reloading. If reloading doesn't help, ask your site administrator to update the store (see [On the store](#on-the-store)).
   - **Desktop:** install the pending update and reopen the app. If no update is offered, download the latest build from the [Installation](/getting-started/installation) page.
   - **iPhone, iPad or Android:** update WCPOS through the channel you installed it from — TestFlight on iOS, the Play testing programme on Android; both are linked from the [Installation](/getting-started/installation) page.
2. If it still won't open, tap **Copy debug info** in [**Store health → Logs**](#log-entry) and contact support. Say whether this device may hold sales that haven't reached your store.
3. Don't clear local data, sign out or reinstall while you wait — support will tell you whether anything on this device needs recovering first.

### On the store {#on-the-store}

For the site administrator.

1. The store's WCPOS plugin decides which web version loads, so if reloading the web app doesn't help, update the WCPOS plugin.

## Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row. The picture shows an example entry, AUTH201; on your till the entry shows this page's code.

<JourneyShot manifest={logs} device="tablet" step={3} offsets={[[17, 28], [549, -9], [-54, -97], [131, 0], [101, 0], [-33, 0]]} alt="An error entry opened under its row in Store health → Logs: what the server said, what to do, Open record, the Help link, the event code with Copy, and the record, operation and request">

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support. The rows under it are for support; you don't need to read them.
