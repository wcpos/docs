## What this means {#what-this-means}

Something in front of your store is rejecting the store's answers.

A cache or proxy layer in front of the store has a size limit. The store's small checks fit, but full answers go over the limit and are rejected by that layer, not by WordPress. The limit must be raised on that layer.

## Your data {#your-data}

No order or product data is affected.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

Tell your site administrator the code, HOST131, and what you were doing when it appeared.

### On the store {#on-the-store}

For the site administrator.

1. On Varnish, raise http_max_hdr (header count) and http_resp_hdr_len / http_resp_size (sizes).
2. Ask the host which proxy layer returns the 503 — the WordPress error log will show nothing because the request never fails there.
3. A quick check: the store's /wcpos/v2/ping answers fine while data endpoints 503.

<details>
<summary>Technical detail</summary>

A proxy in front of the store rejects the server's responses for having too many headers.

A cache or proxy layer (commonly Varnish) enforces a limit on response header count or size. The store's lightweight endpoints fit, but full API responses exceed the limit and come back as 503s from the proxy, not from WordPress.

</details>

## Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row. The picture shows an example entry, AUTH201; on your till the entry shows this page's code.

<JourneyShot manifest={logs} device="tablet" step={3} offsets={[[17, 28], [549, -9], [-54, -97], [131, 0], [101, 0], [-33, 0]]} alt="An error entry opened under its row in Store health → Logs: what the server said, what to do, Open record, the Help link, the event code with Copy, and the record, operation and request">

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support. The rows beside and under it (event code, record, operation, request, details) are for support too; you don't need to read them.
