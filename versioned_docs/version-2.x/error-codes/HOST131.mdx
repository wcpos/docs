**Symptom:** when you connect, red text under **Connect** reads "This store's hosting setup is blocking the app — the details page names the exact cause and fix.", with a **Learn more** link to this page.

**Do this now:** send whoever looks after your website a link to this page: the limit sits in front of your store.

## Fix it at the till {#at-the-till}

1. Send whoever looks after your website a link to this page.
2. Ask them to raise the limit on the cache or proxy in front of your store.
3. Once it's fixed, enter **Your store's address** and press **Connect** again.
4. **If it connects:** carry on selling.
5. **If the red text shows again:** the limit is still too low. Tell them again.

## Is anything lost? {#your-data}

No. No order or product data is affected, and nothing on your store changed.

## If it keeps happening {#keeps-happening}

A cache or proxy in front of your store has a size limit. Small checks fit, but full answers go over it and are rejected there, not by your store.

<details>
<summary>For whoever looks after your website</summary>

A cache or proxy layer (commonly Varnish) limits response header count or size. Lightweight requests fit, but full API responses go over and come back as 503s from the proxy, not from WordPress. Raise the limit on that layer.

1. On Varnish, raise `http_max_hdr` (header count) and `http_resp_hdr_len` / `http_resp_size` (sizes).
2. Ask the host which proxy layer returns the 503. The WordPress error log shows nothing, because the request never fails there.
3. Quick check: the store's `/wcpos/v2/ping` answers while data requests return 503.

</details>

## Still stuck? {#still-stuck}

If your host says no limit is reached, tell support the code and when it happened.
