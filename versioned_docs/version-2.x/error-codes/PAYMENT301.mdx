## What this means {#what-this-means}

The selected payment gateway is unavailable for this store.

Ask your site administrator to verify that the gateway is supported, enabled, and correctly configured.

## Your data {#your-data}

No order or product data is affected. If this persists, ask your site administrator.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

1. Tell your site administrator the code, PAYMENT301, and ask them to verify that the gateway is supported, enabled, and correctly configured.
2. Complete the sale meanwhile with another method, such as cash.
3. If the method is greyed out under **… not available right now** in the payment pane, that is a problem on this till, not this error — the reason shown (for example **Needs a connection** or **Turn on Bluetooth to use the reader**) tells you what to fix.
4. Once your site administrator has fixed the gateway (see On the store), reload the app on the till so it picks up the gateway again.

### Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row. The picture shows an example entry, AUTH201; on your till the entry shows this page's code.

<JourneyShot manifest={logs} device="tablet" step={3} offsets={[[17, 28], [549, -9], [-54, -97], [131, 0], [101, 0], [-33, 0]]} alt="An error entry opened under its row in Store health → Logs: what the server said, what to do, Open record, the Help link, the event code with Copy, and the record, operation and request">

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support. The rows beside and under it (event code, record, operation, request, details) are for support too; you don't need to read them.

### On the store {#on-the-store}

For the site administrator.

1. Go to **WP Admin > POS > Settings > Checkout**. Under **Gateways**, the gateway must be listed and its **Enabled** switch on.
   - If it is not listed, check that its plugin is installed and active.
   - It doesn't have to be switched on in **WP Admin > WooCommerce > Settings > Payments**: the POS lists every gateway an active plugin registers.
   - On WCPOS Free only the built-in cash and card methods can be enabled; other WooCommerce gateways need WCPOS Pro.
2. If the gateway worked yesterday, check whether it or WooCommerce updated — **WooCommerce → Status → Logs** may record gateway start-up errors.
