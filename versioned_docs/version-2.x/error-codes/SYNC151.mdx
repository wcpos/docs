## What this means {#what-this-means}

Your store's reply had stray text in it, which WCPOS tried to clean up.

Check the action you were doing finished — the clean-up does not always work. The stray text usually comes from a plugin or a PHP notice printing extra output into store responses. If this appears often, ask your site admin to check the site's PHP error log for warnings.

## Your data {#your-data}

If the action you were doing didn't finish (see Troubleshoot step 1), follow that request's guidance; otherwise no order or product data is affected. If this appears often, ask the person who manages your WordPress site.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

1. Check the action you were doing finished — for example that the sale or change now shows. If it did, nothing more is needed.
   - If it didn't, try it again; if that fails, follow the error it shows or contact support.
2. The cause is on the site. Ask your site administrator to check the site's logs for PHP notices at the failure time.

### On the store {#on-the-store}

For the site administrator.

1. A plugin or theme is printing warnings or stray output into REST responses. Check the site's logs for PHP notices at the failure time.
2. The clean-up is best-effort — if this appears often, fix the offending plugin rather than relying on it.

<details>
<summary>Technical detail</summary>

The browser's developer tools (Network tab) — or **Advanced → Toggle Developer Tools** in the desktop app — show the raw response body; the stray output is visible immediately before or after the JSON.

</details>

## Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row.

<JourneyShot manifest={logs} device="tablet" step={3} offsets={[[50, 0], [64, -10], [-54, -97], [131, 0], [101, 0], [-33, 0]]} alt="An error entry opened under its row in Store health → Logs: what the server said, what to do, Open record, the Help link, the event code with Copy, and the record, operation and request">

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support.

</JourneyShot>
