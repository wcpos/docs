## What this means {#what-this-means}

Your store's reply had stray text in it, which WCPOS tried to clean up.

The stray text usually comes from a plugin printing extra output into store responses. The cause is on the site, so your site administrator fixes it (see On the store).

## Your data {#your-data}

If the action you were doing didn't finish (see Troubleshoot step 1), follow that request's guidance; otherwise no order or product data is affected. If this appears often, ask your site administrator.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

1. Check the action you were doing finished — the clean-up does not always work. For example, check that the sale or change now shows. If it did, nothing more is needed.
   - If it didn't, try it again; if that fails, follow the error it shows or contact support.
2. The cause is on the site. Ask your site administrator to check the site's logs at the failure time (see On the store).

### Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row. The picture shows an example entry, AUTH201; on your till the entry shows this page's code.

<JourneyShot manifest={logs} device="tablet" step={3} offsets={[[17, 28], [549, -9], [-54, -97], [131, 0], [101, 0], [-33, 0]]} alt="An error entry opened under its row in Store health → Logs: what the server said, what to do, Open record, the Help link, the event code with Copy, and the record, operation and request">

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support. The rows beside and under it (event code, record, operation, request, details) are for support too; you don't need to read them.

</JourneyShot>

### On the store {#on-the-store}

For the site administrator.

1. A plugin or theme is printing warnings or stray output into REST responses. Check the site's logs for PHP notices at the failure time. If this appears often, check the site's PHP error log for warnings.
2. The clean-up is best-effort — if this appears often, fix the offending plugin rather than relying on it.

<details>
<summary>Technical detail</summary>

The stray text usually comes from a plugin or a PHP notice printing extra output into store responses.

The browser's developer tools (Network tab) — or **Advanced → Toggle Developer Tools** in the desktop app — show the raw response body; the stray output is visible immediately before or after the JSON.

</details>
