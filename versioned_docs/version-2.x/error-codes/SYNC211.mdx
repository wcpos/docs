## What this means {#what-this-means}

Your store refused a value it was sent.

The store's reason names the value. Correct it where you entered it, then save again. Usually the value belongs to a record — a product, customer or order — but this code can also come from a settings or sign-in request the store refused; then correct it on that screen.

## Your data {#your-data}

Don't clear this device's data — it may hold changes your store doesn't have yet. A refused edit to an existing product, variation, customer or coupon is usually undone automatically and logged as [SYNC202](/error-codes/SYNC202) instead. If it shows as this code and the change is listed in **Store health → Database**, the automatic undo didn't happen — treat it like any other listed change. A settings or sign-in request leaves nothing to save.

## Troubleshoot {#troubleshoot}

1. Expand the log entry and read the store's reason and the endpoint: the reason names the value, and the endpoint shows whether it came from a record or from a settings or sign-in request.
2. Correct the value where you entered it — common causes are a value out of range, a rejected format or a required option left empty — then save again. If the change is not listed in **Store health → Database**, the store's version was restored, so make the change again with the corrected value. If it is still listed under **"… changes never reached your server"** in **Store health → Database** after you correct it, tap **Send again** on its row.
3. If the record is instead listed under **"… changes were held"** with *"Your store required a current version"*, no value is at fault — decide between **Send again** and **Discard device change** as described in [SYNC221](/error-codes/SYNC221).
4. If it was a settings or sign-in request, correct the value on the screen where you entered it and save again. **Site admin:** the browser's developer tools (Network tab) — or **Advanced → Toggle Developer Tools** in the desktop app — show the store's response when the details are not in the POS log.
5. **Site admin:** if a named value looks correct in the POS, compare it with the same record in WP Admin — plugin-added validation on the store can reject values the POS considers fine.
