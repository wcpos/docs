## What this means {#what-this-means}

The store had already closed this order, so it refused a change to its lines.

This device sent a change to an order's lines (items, fees, shipping or coupons) after the store had already closed that order: it was paid or completed, cancelled or refunded. The store does not change the lines of a closed order, so it refused the change and kept its own copy as it was.

## Your data {#your-data}

The store's copy of the order is unchanged. The refused change stays on this device, listed in **Store health → Database**, until you settle it. To make the change land, the order has to be reopened on the store first; otherwise discard the change.

## Troubleshoot {#troubleshoot}

### At the till {#at-the-till}

1. Expand [the log entry](#log-entry): it names the order the store refused and the store's reason.
2. If the store's copy is already right, nothing was lost: press **Discard** on the change's row in **Store health → Database**.
3. If the change is still needed, your site administrator has to reopen the order first (see [On the store](#on-the-store)). Then press **Send again** on the row.
4. If the same order keeps being refused while it is still open on this device, another device or the site administrator is closing it. Agree who finishes the sale before changing it here.

### On the store {#on-the-store}

For the site administrator.

1. Open the same order in **WooCommerce → Orders** in WP Admin and check its status and lines. If the change is still needed, reopen the order there.
2. If the log entry also shows a rounding fee amount, the refused change carried a cash rounding line.

## Find the entry in the log {#log-entry}

Every code is logged in **Store health → Logs**. Press **Errors**, then tap the entry with this code to open it under its row. The picture shows an example entry, AUTH201; on your till the entry shows this page's code.

<JourneyShot manifest={logs} device="tablet" step={3} offsets={[[17, 28], [549, -9], [-54, -97], [131, 0], [101, 0], [-33, 0]]} alt="An error entry opened under its row in Store health → Logs: what the server said, what to do, Open record, the Help link, the event code with Copy, and the record, operation and request">

1. **Errors** — the filter that's on.
2. **The entry** — the code in **Status** is its error code.
3. **What happened and what to do** — what your store said, when it said something, then one line on what to do. When it matters, a warning comes first, such as **Payment has been taken — don't charge again.** or **Don't clear this device's data**.
4. **Help** — opens the code's page in these docs.
5. **Open record** — opens the order, product or customer the entry is about, when this till has it, your store has WCPOS Pro, and you're allowed to edit it.
6. **Copy** — copies the whole entry for support. The rows under it are for support; you don't need to read them.
