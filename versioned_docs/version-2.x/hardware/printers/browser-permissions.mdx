In a browser, the POS prints to Epson and Star printers through the printer's own web server, over HTTPS or plain HTTP. Three things can stop the browser reaching it: the browser's permission to reach your local network, a printer on plain HTTP when your store's address starts with `https://`, and a printer certificate the browser doesn't trust. The desktop app isn't affected by any of them.

## What you'll see {#symptom}

In **Settings → Printing → Add printer**, the scan finds nothing (**No printer found**), or you enter the printer's address and its card says **No connection**, though the printer is on and on the same network. Or the same printer prints from the desktop app and not from the browser tab.

After a failed test page, the app may say **The app was not allowed to reach the printer. Allow it in your system settings, then try again.** In a browser this means the browser couldn't reach the printer. Check that the printer is on and its address is right, then work through the fixes below. Both screens are [labelled further down](#on-screen).

## Fix it in this order {#fix-in-order}

In Safari or Firefox, start with [what works there](#safari-and-firefox). In Chrome or Edge:

1. [Allow local network access](#allow-local-network-access), then check the address again.
2. If the card still says **No connection** and the printer has HTTPS on, [trust its certificate](#the-printers-certificate), then check again.
3. If the printer only has plain HTTP, see [When the printer uses HTTP](#mixed-content).
4. Still **No connection**? See [Still stuck?](#still-stuck)

Not sure which one the POS is using? The **Port** beside the printer's address decides it. [HTTPS or HTTP](#https-or-http) has the ports for Epson and Star, and screens that show where to look.

To check the address again, press **Enter an IP address**, then **Check this address**. When the card shows **Ready**, the browser can reach the printer: go on to [Print a test page](./setup-wizard.mdx#test-page).

## Allow local network access {#allow-local-network-access}

Chrome and Edge ask before a website may reach a device on your local network. The prompt asks to **Access other devices on your local network**. Allow it.

If someone chose **Never allow**, or closed the prompt:

1. Click the icon at the left of the address bar, then **Site settings**.
2. Set **Local network** to **Allow**.
3. Reload the POS and check the address again.

## The printer's certificate {#the-printers-certificate}

Over HTTPS the printer shows its own certificate. If this browser doesn't trust it, the connection fails before anything is sent. These steps let this browser connect.

1. Make sure the printer has a certificate. If its status sheet shows none, create a self-signed certificate in the printer's web configuration. On an Epson, log in the way [Epson Secure Printing](./secure-printing.mdx#turn-it-off) describes.
2. In the same browser, open the printer's address over HTTPS, using your printer's own IP address:
   - **Epson:** try `https://192.168.1.200:8043` first. If that doesn't open, try `https://192.168.1.200`, which is port 443.
   - **Star:** `https://192.168.1.200`, which is port 443.
3. Accept the certificate warning:
   - **Chrome:** on **Your connection is not private**, press **Advanced**, then **Proceed to 192.168.1.200 (unsafe)**.
   - **Edge:** press **Advanced**, then **Continue to 192.168.1.200 (unsafe)**.
   - **Safari:** on **This Connection Is Not Private**, press **Show Details**, then the **visit this website** link, then **Visit Website**.
   - **Firefox:** use the warning's own option to continue to the site.
4. Go back to the POS and check the address again.

Do this in every browser on every computer that prints.

The desktop app accepts the printer's certificate itself. That's why the same printer can work there and not in the tab.

## When the printer uses HTTP {#mixed-content}

If your store's address starts with `https://` and the printer only has plain HTTP, print from Chrome or Edge 142 or newer and [allow local network access](#allow-local-network-access).

Other browsers block it: a secure page may not send to an insecure address, which browsers call mixed content. If you can't use Chrome or Edge, switch the printer to HTTPS with a [certificate](#the-printers-certificate), or use the desktop app.

## Safari and Firefox {#safari-and-firefox}

- **Over Wi-Fi:** the printer has to match the store. From an `https://` store only HTTPS works, once you've [accepted the certificate](#the-printers-certificate); plain HTTP is blocked. From an `http://` store, plain HTTP works.
- **USB and Bluetooth:** **Find a USB printer** and **Find a Bluetooth printer** appear only in browsers that can reach those devices, Chrome and Edge.

For anything else, use Chrome or Edge, or the desktop app.

## HTTPS or HTTP {#https-or-http}

The browser reaches the printer's web server on one of these ports. The port decides between HTTPS and plain HTTP.

| Printer | HTTPS port | HTTP port |
|---|---|---|
| Epson | **8043** or **443** | **8008** or **80** |
| Star | **443** | **80** |

- **HTTPS** needs a certificate on the printer that this browser trusts. See [the printer's certificate](#the-printers-certificate).
- **HTTP** from an HTTPS store needs Chrome or Edge 142 or newer and the [local network permission](#allow-local-network-access). See [When the printer uses HTTP](#mixed-content).

For a saved printer, **Edit printer** shows which one it uses under **Web print endpoint**:

<JourneyShot manifest={manifest} device="tablet" step={13} offsets={[[290, 0], [0, 30], [572, -2], [700, 0]]} alt="Edit printer for an Epson at 192.168.1.128 on port 8008, Detected: Epson, and the Web print endpoint http://192.168.1.128:8008/cgi-bin/epos/service.cgi, Using Epson ePOS over HTTP. Chrome or Edge may ask for permission to access your local network">

1. **IP Address** — the printer's address.
2. **Port** — 8008 here, Epson's plain HTTP port. On an HTTPS store a new Epson starts at **8043**, which uses HTTPS.
3. **Web print endpoint** — the address the browser sends the receipt to. It starts with `http://` for plain HTTP and `https://` for HTTPS.
4. **The line under the endpoint** — the vendor and HTTPS or HTTP in words. Over HTTP it adds that Chrome or Edge may ask for the [local network permission](#allow-local-network-access); over HTTPS, that the printer needs a certificate this browser trusts ([the printer's certificate](#the-printers-certificate)).

## Still stuck? {#still-stuck}

Use **Copy setup report** and paste it into your message. It's on the **Nothing printed** screen after a failed test page, and in the menu of a saved printer. It records the address, the port and what was tried. On the **Nothing printed** screen, **Support details** also shows which browser you used.
