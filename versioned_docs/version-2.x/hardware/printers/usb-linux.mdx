On Linux, the desktop app talks to a USB receipt printer directly, over the cable. Linux keeps USB devices for its administrator account (`root`) unless a rule says otherwise, so the app, running as you, is not allowed to open the printer. You fix it once, with a short rule file.

This page is for you if, in the desktop app on Linux:

- After **Print a test page**, the panel says **Nothing printed** and **The app was not allowed to reach the printer. Allow it in your system settings, then try again.** Linux has no settings screen for this: the rule below is the setting.
- **Support details**, under that message, shows `LIBUSB_ERROR_ACCESS`.
- In the search, your printer's card is named **USB printer** and a row of numbers, not the printer's own name. That usually means the app could not open the printer to read its name.

## Give the app the printer {#do-this}

You need a terminal and the computer's administrator password. When a command asks for the password, type it and press Enter: nothing shows on screen as you type. If you don't have the password, send this page to whoever set up the till.

1. Plug the printer in and switch it on.
2. Find the printer's two ids. In a terminal, run:

   ```bash
   lsusb
   ```

   Each line is one USB device. Find your printer's line, for example:

   ```text
   Bus 001 Device 007: ID 04b8:0e28 Seiko Epson Corp.
   ```

   | In the line | What it is | You use it in |
   |---|---|---|
   | `04b8` | The maker's id, the first code after `ID` | The rule, step 4 |
   | `0e28` | The model's id, the second code after `ID` | The rule, step 4 |
   | `Bus 001`, `Device 007` | Where the printer is plugged in right now | The check under [If something goes wrong](#goes-wrong) |

   If you can't tell which line is the printer, unplug it, run `lsusb` again, and see which line is gone.

3. Open a new rule file in the nano text editor:

   ```bash
   sudo nano /etc/udev/rules.d/99-receipt-printer.rules
   ```

4. Copy this line with the copy button in the corner of the box. It is one long line, ending `MODE="0666"`:

   ```text
   SUBSYSTEM=="usb", ATTRS{idVendor}=="04b8", ATTRS{idProduct}=="0e28", MODE="0666"
   ```

   Paste it into nano with **Ctrl+Shift+V**. Move along the line with the arrow keys and change `04b8` and `0e28` to your printer's two ids, typed exactly as `lsusb` shows them. Save with **Ctrl+O** and **Enter**, then leave nano with **Ctrl+X**.

   `MODE="0666"` lets every account on this computer use the printer, which is what a till needs.

5. Load the rule:

   ```bash
   sudo udevadm control --reload-rules && sudo udevadm trigger
   ```

6. Unplug the printer and plug it back in.
7. If you saved this printer earlier with **Save without testing**, delete it first: in **Settings → Printing**, open its **More actions** menu and choose **Delete**.
8. In the desktop app, go to **Settings → Printing** and press **Add Printer**. Pick your printer's card, marked **USB**. Now that the app can open the printer, the card shows the name the printer gives itself.
9. Press **Print a test page**, then answer **Did the test page print?** See [Print a test page](./setup-wizard.mdx#test-page).

:::tip Start the app as yourself
Open the desktop app the usual way, never with `sudo`. The rule is what lets the app use the printer as you.
:::

## Why the app needs this {#why-it-happens}

Most programs print through Linux's own print system. A receipt printer needs commands sent straight to it (cut the paper, open the drawer), so the desktop app opens the printer itself.

Linux also has its own driver for USB printers, which takes hold of the printer when you plug it in. The app releases it from that driver by itself before each print, so you don't need to remove or block it. But releasing it needs the same permission as printing, which is why one rule fixes both.

## If something goes wrong {#goes-wrong}

**Still not allowed, after the rule.** Check, in order:

- The two ids in the rule match `lsusb` exactly, lower case included.
- The rule file holds your line. Show it with `cat /etc/udev/rules.d/99-receipt-printer.rules`.
- You unplugged the printer and plugged it back in after step 5.

Then look at the printer's device file. Run `lsusb` again, because the `Device` number changes each time the printer is plugged in. Take the `Bus` and `Device` numbers from its line, for example `ls -l /dev/bus/usb/001/007`. The line should start `crw-rw-rw-`. If it starts `crw-rw-r--` or `crw-------`, the rule did not match.

**`lsusb: command not found`.** Install the `usbutils` package: `sudo apt install usbutils` on Ubuntu or Debian, `sudo dnf install usbutils` on Fedora.

**The card is named `ttyUSB0`, `ttyACM0` or `rfcomm0`.** That printer connects through a serial port, not as a USB printer, and Linux gives serial ports to the `dialout` group. Add yourself to it, then log out and back in:

```bash
sudo usermod -aG dialout $USER
```

On Arch Linux the group is `uucp`.

**No printer found.** The app lists only USB devices that say they are printers. Check the cable and that the printer is on, then press **Scan again**. See [No printer found](./setup-wizard.mdx#not-found).

**The test page prints, then later receipts don't.** That is not a permission problem. Start from [Still not printing?](./setup-wizard.mdx#troubleshoot)

## Still stuck? {#still-stuck}

Press **Copy setup report** on the **Nothing printed** panel, or in the printer's **More actions** menu in **Settings → Printing**. Paste it into your message, with your printer's `lsusb` line and the `ls -l` line from above.
