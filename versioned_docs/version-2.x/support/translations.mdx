WCPOS is translated by AI, and a person checks every batch before it ships. People who use WCPOS in their own language catch what the machine misses. If a word in the POS, the plugin or these docs reads wrong, you can fix it: you change one line on GitHub and open a pull request. You don't need to be a developer.

Jump to: [Fix the POS or the plugin](#apps-and-plugin) · [Fix these docs](#docs) · [Add a language](#add-a-language)

## See it in your language {#see-it}

Find the word on the screen where it's used before you change it. The POS opens in your store's language, the Site Language set in WordPress. To try another language on one device, open **Settings** from the menu, then **General**.

## Fix a word in the POS or the plugin {#apps-and-plugin}

Every app and plugin translation lives in [wcpos/translations](https://github.com/wcpos/translations).

1. **Find the file** for your language and the part of WCPOS you're fixing. For German, the POS text is in [German POS: `core.json`](https://github.com/wcpos/translations/blob/main/translations/js/de_DE/monorepo/core.json) and the plugin's PHP text is in [German plugin: `woocommerce-pos-de_DE.po`](https://github.com/wcpos/translations/blob/main/translations/php/de_DE/woocommerce-pos-de_DE.po). **Which file holds what**, below, lists every folder.
2. **Change the translated text only.** Leave the key, the `msgid` and every placeholder such as `{name}`, `%s`, `%d` or `<strong>` exactly as they are.

   In a JSON file, each line is a key, a colon, then the translation:

   ```json
   "common.added_to_cart": "{name} zum Warenkorb hinzugefügt",
   ```

   Change only the German words after the colon. Leave `common.added_to_cart` and `{name}` as they are.

   In a PO file, `msgid` is the English and `msgstr` is your language:

   ```text
   msgid "Copy of %s"
   msgstr "Kopie von %s"
   ```

   Change only the words in the `msgstr` line. Leave the `msgid` line and `%s` as they are.

3. **Send it as a pull request.** See [Send your fix on GitHub](#send).

<details>
<summary>Which file holds what</summary>

| Folder | What it holds |
|---|---|
| `source/` | The English text, collected automatically. Don't edit it. |
| `translations/js/<locale>/monorepo/` | The POS the cashier uses: buttons, cart, checkout, dialogs, errors. |
| `translations/js/<locale>/electron/` | The desktop app's own window and menus, for Windows and macOS. |
| `translations/js/<locale>/woocommerce-pos/` | The free plugin's WP Admin screens, such as Settings and Templates, one file per screen. |
| `translations/js/<locale>/woocommerce-pos-pro/` | The Pro plugin's WP Admin screens, such as the Stores editor and Pro settings. |
| `translations/php/<locale>/` | The plugin's PHP text. Edit the `.po` file. The `.l10n.php` file beside it is made from the `.po`, and the `.mo` file is no longer used, so leave both alone. |

Many languages have a base folder and regional ones, such as `de` and `de_DE`, `de_AT`. The POS reads the regional folder its language points to: German (Deutsch) reads `de_DE`.

</details>

If your language isn't there, see [Add a language](#add-a-language).

## Fix a page of these docs {#docs}

These docs use Docusaurus. The English pages live in `versioned_docs/` of [wcpos/docs](https://github.com/wcpos/docs). Each language has its own copy under `i18n/<locale>/docusaurus-plugin-content-docs/`, in a folder for the version, with the same path as the English page.

1. **Find the file.** **Edit this page** at the bottom of a page opens the English file. Open the same path in your language's folder instead. For French that's the [French folder](https://github.com/wcpos/docs/tree/main/i18n/fr/docusaurus-plugin-content-docs), `i18n/fr/docusaurus-plugin-content-docs/`, so the French copy of this page is `i18n/fr/docusaurus-plugin-content-docs/version-2.x/support/translations.mdx`.
2. **Change the words.** Keep Markdown and MDX syntax, links, code and the frontmatter keys as they are. Translate the text, the headings and the labels a reader sees.
3. **Send it as a pull request.** Change only the file under `i18n/<locale>/`, never the English page. See [Send your fix on GitHub](#send).

For anything bigger, a whole section or a new language, open an issue first so we can plan it together.

## Send your fix on GitHub {#send}

You need a free GitHub account. You don't need to install anything: it all happens in your browser.

1. **Sign in to GitHub** and open the file you want to fix.
2. **Press the pencil**, **Edit this file**, at the top right of the file. The first time, GitHub asks you to fork the repository: press **Fork this repository**. That gives you your own copy to change.
3. **Make your change** in the editor.
4. **Press Commit changes…** above the editor. A box opens.
5. **Say what you fixed** in one line in the box's message field, then press **Propose changes**.
6. **Press Create pull request** on the next page, then **Create pull request** again to send it.

A reviewer checks your change and merges it, or asks you about it on the pull request.

## How a fix reaches people {#how-it-works}

A person reviews every change before it ships. A fix to these docs is published with the site after it's merged. A fix to the POS, the desktop app or the plugin reaches people with their next update.

<details>
<summary>The whole path, step by step</summary>

1. **The English text is collected.** When the apps or the plugin change, their English strings go to the [wcpos/translations](https://github.com/wcpos/translations) repository. These docs keep theirs in [wcpos/docs](https://github.com/wcpos/docs).
2. **AI fills in what's missing**, in every language. It follows a rule set and a glossary for each language. A translation that breaks a placeholder, markup or a product name is rejected and tried again later.
3. **A person reviews the batch** as a pull request and merges it.
4. **The fix ships.** For these docs, the site is rebuilt from the merged pages and published. For the apps and the plugin, a merge makes a new translations release. The POS, the desktop app and the plugin each use a fixed release, so a fix reaches them in their next update.

For the apps and the plugin, a daily check also opens an issue on [wcpos/translations](https://github.com/wcpos/translations/issues) if anything is still missing.

</details>

So your part is rarely a blank file. It's a translation that's already there and reads wrong: a stiff phrase, a term that doesn't match what WooCommerce uses in your language, a label that doesn't fit its button.

:::note Not on translate.wordpress.org
WCPOS no longer takes translations through translate.wordpress.org. The plugin downloads its own translations from wcpos/translations. If you translated WCPOS there before, thank you: fixes now go to the places on this page.
:::

## Add a language {#add-a-language}

The apps and the plugin cover more than 50 languages and regional variants, listed in [`locales.json`](https://github.com/wcpos/translations/blob/main/locales.json). These docs cover fewer, listed below. If yours is missing, open an issue on the repository you need, and we'll add it. The AI fills a new language in quickly. From there, people who speak it make it read well.

### Language codes {#locale-codes}

These docs are published in:

| Code | Language |
|---|---|
| `ar` | Arabic *(right to left)* |
| `de` | German |
| `es` | Spanish |
| `fr` | French |
| `hi-IN` | Hindi (India) |
| `it` | Italian |
| `ja` | Japanese |
| `ko` | Korean |
| `nl` | Dutch |
| `pt-BR` | Portuguese (Brazil) |
| `zh-CN` | Chinese (Simplified) |

The two repositories write codes differently. wcpos/translations uses an underscore, `de_DE`, `pt_BR`, `zh_CN`, and has base languages (`de`, `fr`, `es`) as well as regional ones (`de_AT`, `fr_CA`, `es_MX`). These docs use a hyphen, `pt-BR`, `hi-IN`, `zh-CN`. Use the form of the repository you're editing.

## What a reviewer looks for {#translator-tips}

These are the rules the AI works to, so a reviewer checks your change against them too.

- **Placeholders stay exactly as they are.** `{name}`, `%s`, `%d` and tags such as `<strong>` are filled in or drawn by WCPOS. Translate around them.
- **Product names stay in English.** `WCPOS`, `WCPOS Pro`, `WooCommerce` and `WordPress` are never translated. Write **WCPOS** in text people read. The old long name belongs only in slugs, file names and web addresses.
- **WooCommerce's words win.** Store owners see WCPOS next to WooCommerce, so a word WooCommerce also uses, such as coupon, refund, tax or payment method, matches WooCommerce's own translation for your language. Where WooCommerce has no word, such as cashier, till or cash drawer, use the word in your language's glossary, `scripts/translation-glossary.json`.
- **Keep it about as long as the English.** A one-word button stays one or two words. POS screens have little room.
- **Formal or informal follows your language's notes.** Many languages have their own notes in `scripts/locale-context/` in wcpos/translations, with the register, the decimal separator and common traps. German uses **Sie**, for example.
- **Code stays as it is.** Coupon codes, gateway IDs, language codes, file paths and shortcodes are never translated. If you're not sure, leave it in English.
- **Check it on the screen.** A phrase that fits one screen can wrap on another. See [See it in your language](#see-it).

For a right-to-left language, such as Arabic, Hebrew, Persian or Urdu, receipts need a right-to-left template too. The gallery has them: see [Customise your receipt](../receipts/customise.mdx#the-bundled-templates) and [Non-Latin receipts](../hardware/printers/non-latin-receipts.mdx).
