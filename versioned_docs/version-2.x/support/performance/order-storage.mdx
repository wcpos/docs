**The symptom:** checkout in WCPOS takes several seconds, and it has been getting slower over time.

One common cause is the way WooCommerce stores your orders. Check which kind of storage your store uses, and if it is the old one, move to the faster one with WooCommerce's own tool. Whoever runs the store does this once, in WordPress admin, not at the till.

## Check which storage your store uses {#check-which-storage-your-store-uses}

1. In WordPress admin, go to **WooCommerce → Settings → Advanced → Features**.
2. Find **Order data storage**:
   - **High-performance order storage (recommended)** selected: you already use HPOS, so this is not the cause. See [Other causes of slow checkout](#other-causes-of-slow-checkout).
   - **WordPress posts storage (legacy)** selected: switch to HPOS below. It speeds up a slow step in every checkout ([why](#why-legacy-order-storage-slows-checkout)), and the larger your store, the more it helps.

New WooCommerce stores have used HPOS since 2023, so an older store is the one most likely to still be on legacy storage.

:::tip WCPOS tells you too
On a store with legacy storage, a warning sits at the top of **POS → Settings → [Checkout](../../settings/wp-admin/checkout.mdx)**. Its **Open WooCommerce's order storage setting** link takes you straight to the Features page, and **How to switch** brings you back here.
:::

## Switch to HPOS {#switch-to-hpos}

WooCommerce moves your orders for you. First it copies them across (the sync), then you switch. WooCommerce will not let you switch until the copy is complete.

:::warning Back up first
Make a full backup of your site and database before you start, and check that you can restore it. If you have a [staging site](../troubleshooting/plugin-conflicts.mdx#before-you-start-use-a-staging-site), try the switch there first.
:::

1. Go to **WooCommerce → Settings → Advanced → Features**.
2. Tick **Enable compatibility mode** and click **Save changes**. WooCommerce starts copying your orders in the background. On a large store this can take a while; the progress shows under the checkbox as **Currently syncing orders...** with the number still pending.
3. When the copy has finished, select **High-performance order storage (recommended)** and click **Save changes**. If the option is still greyed out, see [If something goes wrong](#goes-wrong).
4. Leave **Enable compatibility mode** ticked while you check that everything still works:
   - Take a test sale in WCPOS and check that it completes.
   - Find that sale in **WooCommerce → Orders**.
   - Check that the plugins that work with your orders, such as accounting, shipping or email plugins, still see new orders.

   While compatibility mode is on, both copies of your orders stay in step, so you can [switch back](#goes-wrong) straight away.
5. When those checks pass, untick **Enable compatibility mode** and click **Save changes**.

For the full details, see WooCommerce's guide: [High-Performance Order Storage](https://woocommerce.com/document/high-performance-order-storage/#how-to-enable-high-performance-order-storage).

## If something goes wrong {#goes-wrong}

**Both storage options are greyed out, and it says "There are currently orders out of sync."**
The copy has not finished, or it has stopped. Click **Sync orders now** under the checkbox, wait until the copy has finished, then switch.

**Only High-performance order storage is greyed out.**
WooCommerce blocks the switch while an active plugin is marked as incompatible with HPOS. A warning on the Features page names those plugins, with a **View and manage** link. Update them, or ask their developers about HPOS support, before you switch.

**Something stopped working after the switch.**
While **Enable compatibility mode** is still ticked, select **WordPress posts storage (legacy)** and click **Save changes**. Your store is back on legacy storage, with every order in place. Then find the plugin that broke before you try again.

**Checkout is still slow after switching.**
Order storage was not the only cause. See [Other causes of slow checkout](#other-causes-of-slow-checkout) below.

## Why legacy storage slows checkout {#why-legacy-order-storage-slows-checkout}

Every time WCPOS saves an order, it first looks the order up by the ID WCPOS gave it. With legacy storage that lookup has to go through your store's records one by one, so it gets slower as your store grows. With HPOS the same lookup is close to instant.

<details>
<summary>How much faster, and why</summary>

With legacy storage, WooCommerce keeps orders alongside your WordPress posts, in tables with no quick way to find an order by WCPOS's ID. HPOS keeps orders in their own tables, where this kind of lookup is fast.

On one store we measured (about 30,000 products and variations, legacy storage), each lookup took about 0.46 seconds and a checkout made about two of them. With HPOS the same lookup took about 1 millisecond. Your store will differ, but the larger it is, the more you gain.

</details>

## What WCPOS supports {#what-wcpos-supports}

- **HPOS is fully supported, and it is what we recommend.**
- **Legacy storage still works.** Nothing breaks; checkout is only slower on large stores.

## Other causes of slow checkout {#other-causes-of-slow-checkout}

Order storage is not the only thing that slows checkout. If you already use HPOS, or checkout is still slow after switching, look at:

- **Your hosting.** A busy or underpowered server slows every step. See [Server Performance](./server.mdx).
- **Other plugins that run when an order is saved**, such as accounting, email marketing or inventory plugins. See [Plugin Conflicts](../troubleshooting/plugin-conflicts.mdx) and [Checkout Performance](./checkout.mdx#2-plugin-interference-during-order-creation).
