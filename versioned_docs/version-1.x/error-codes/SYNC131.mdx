## What this means {#what-this-means}

Your store had an error and didn't finish this request.

The store was reached, but its server failed to handle the request — a problem on the website rather than the POS. Try the action again. If it keeps happening, ask your site admin to check **WooCommerce → Status → Logs**. Nothing was lost on this device.

## Your data {#your-data}

Don't clear this device's data — it may hold changes your store doesn't have yet. A change that was being sent may not have reached your store. If this keeps happening, use **Copy debug info** on the **Logs** tab and contact WCPOS support.

## Troubleshoot {#troubleshoot}

**On the POS (cashier):** expand the log entry and note the status, endpoint and serverCode — they say what the server was doing when it failed.

**On the website (site admin / host):**

1. Open WooCommerce → Status → Logs on the site and check the newest fatal-errors log around the failure time; a 500-class response almost always leaves a PHP error there.
2. If the failure started after a plugin, theme or PHP update on the site, suspect that change first and roll it back or disable it.
3. If WooCommerce's logs show nothing, ask the hosting provider for the server's PHP error log for the same time window.

**Then, back on the POS:** try the action again.
