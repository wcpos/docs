## What this means {#what-this-means}

This device saved its version over a newer edit made in your store.

Check the fields the log entry lists in WP Admin. If the store's edit was the right one, make it again there.

This happens with orders. The order was changed in your store after this device last downloaded it — by someone in WP Admin, or automatically by a plugin or a payment notification. When this device then saved its own change to the order, the store reported the clash. So that the till's sale is not held back, WCPOS sent this device's version again over the store's, and the store accepted it. The log entry lists every field where this device's value replaced a different value in the store. Some may be this device's own changes — a line added or a status set at the till — rather than edits made in the store.

If the same clash happens twice in a row, WCPOS holds the change instead and asks you to choose — see [SYNC221](/error-codes/SYNC221).

## Your data {#your-data}

The order is saved in your store with this device's version, and nothing on the till was lost. What may need redoing is the store's newer edit, in the listed fields. The log lists which fields were replaced, not their old values. If the entry says it is showing only some of the fields, more were replaced than are listed — check the whole order.

## Troubleshoot {#troubleshoot}

1. Expand the log entry: it names the order and lists the fields where this device's value replaced the store's.
2. Open the order in **WooCommerce → Orders** in WP Admin and check those fields. The order's notes may show who or what made the store's edit.
3. If the fields are right as they are — for example because they are the change made at the till — there is nothing to do.
4. If the store's edit was the right one, make it again in WP Admin. The till picks up the change on its next sync.
5. If this keeps happening, two places are changing the same orders at once — for example a status set in WP Admin while the sale is still open at the till, or a plugin that updates orders after they are created. Agree on where each kind of order edit happens; a site admin can check which plugin edits orders.
