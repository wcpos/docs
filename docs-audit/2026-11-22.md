### How users get each app version ("Released in")

- **Tags.** v2.0.0 = `5ac185b0e` (11-09), v2.0.1 = `fc7fada39` (11-21), v2.0.2 = `6f93e665b` (11-22), v2.0.3 = `ce6721010` (11-22). A row's version is the first tag whose history contains the commit (`git merge-base --is-ancestor`).
- **Browser (plugin).** `woocommerce-pos` `includes/Templates/Frontend.php` and `Web_Bundle_Loader_Config.php` load the app from the signed manifest at `cdn.wcpos.com/manifest`. The fallback is jsDelivr `wcpos/web-bundle@<plugin major.minor>`. So every 2.0.x plugin runs the newest web-bundle tag on the `2.0` lane, and the plugin's patch version doesn't decide which app build runs.
  - Web-bundle tags are cut from `main` by `scripts/release/tag-web-bundle.sh`. Their numbering is separate from the app version.
  - There is no local web-bundle clone, so I could not check which lane tag carries which app version (open question 1).
- **Desktop (electron).** `.monorepo-ref` pins the app build:
  - electron v2.0.0–v2.0.3 → monorepo v2.0.0
  - **electron v2.0.4 (11-14) → `489d5e0b9`**, a commit between v2.0.0 and v2.0.1. The electron CHANGELOG 2.0.4 entry confirms this pin.
  - electron v2.0.5 (11-21) → v2.0.1
  - electron v2.0.6 (11-22) → v2.0.2
  - No desktop release carries app 2.0.3 yet.
  - So the first 37 first-parent commits of 2.0.1 reached desktop users in 2.0.4, a week before the web app was tagged 2.0.1.
- **Plugin-side needs.** Two features also need plugin **woocommerce-pos 2.0.5** (11-21):
  - preselecting the default gateway (plugin `9339bcd2` #2681 adds `default_method`);
  - cashier/store reassignment (`reassign_woocommerce_pos_sales` is used by `Order_Writer.php` and `Status_Controller.php` only from v2.0.5).
- **Changelog.** Monorepo `CHANGELOG.md` isn't maintained for 2.0 (its last entry is 1.9.1). Release commits only bump `apps/main/package.json`.

Short forms used below:
- **2.0.0** = app 2.0.0 (web 2.0 lane; desktop 2.0.0)
- **2.0.1/d4** = app 2.0.1 (web 2.0 lane; desktop 2.0.4)
- **2.0.1/d5** = app 2.0.1 (web 2.0 lane; desktop 2.0.5)
- **2.0.2** = app 2.0.2 (web 2.0 lane; desktop 2.0.6)
- **2.0.3** = app 2.0.3 (web 2.0 lane; no desktop release yet)
