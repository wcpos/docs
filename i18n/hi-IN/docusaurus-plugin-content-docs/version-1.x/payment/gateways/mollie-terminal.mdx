# Mollie टर्मिनल गेटवे {#mollie-terminal-gateway}

Mollie टर्मिनल गेटवे आपको [Mollie Terminal](https://www.mollie.com/products/point-of-sale) हार्डवेयर पर सीधे WCPOS से व्यक्तिगत भुगतान स्वीकार करने देता है। भुगतान WooCommerce से शुरू होता है और टर्मिनल पर पूरा होता है, तथा Mollie की पुष्टि वापस ऑर्डर में लिख दी जाती है।

## यह कैसे काम करता है {#how-it-works}

Mollie टर्मिनल, Mollie के **सर्वर-साइड `pointofsale` भुगतानों** का उपयोग करता है। जब आप कोई भुगतान शुरू करते हैं, तो WooCommerce उस ऑर्डर के लिए एक Mollie भुगतान बनाता है और Mollie उसे चुने गए टर्मिनल पर भेज देता है। ग्राहक डिवाइस पर भुगतान करता है, और भुगतान तथा रिफ़ंड की स्थिति के लिए **Mollie ही सत्य का स्रोत** है — स्थानीय WooCommerce ऑर्डर मेटा केवल एक कैश है।

**भुगतान की पुष्टि कैसे होती है।** भुगतान चलते रहने के दौरान POS, Mollie को पोल करता है (डिफ़ॉल्ट रूप से हर 2 सेकंड में) और टर्मिनल की पुष्टि मिलते ही सीधे धन्यवाद पेज पर भेज देता है। इसे तेज़ करने के लिए Mollie वेबहुक का भी उपयोग होता है — और वेबहुक URL हर भुगतान पर अपने-आप सेट हो जाता है, इसलिए **Mollie डैशबोर्ड में कुछ भी कॉन्फ़िगर करने की ज़रूरत नहीं**।

टर्मिनल का उसी Mollie खाते पर पंजीकृत और सक्रिय होना ज़रूरी है जिस पर प्लगइन है।

## सेटअप {#setup}

<Steps>
  <StepCard number="1" title="WooCommerce के लिए Mollie Terminal इंस्टॉल करें">

`WP Admin > POS > Settings > Extensions` से इंस्टॉल करें, या [GitHub रिलीज़ पेज](https://github.com/wcpos/mollie-terminal-for-woocommerce/releases) से नवीनतम **प्लगइन ज़िप एसेट** (GitHub सोर्स-कोड ज़िप या टारबॉल नहीं) डाउनलोड करें और उसे `Plugins > Add New > Upload Plugin` के ज़रिए अपलोड करें।

  </StepCard>
  <StepCard number="2" title="अपने Mollie क्रेडेंशियल कॉन्फ़िगर करें">

1. `WP Admin > WooCommerce > Settings > Payments` पर जाएँ और **Mollie Terminal** खोलें
2. **Mode** को `Live` पर सेट करें — टर्मिनल भुगतानों के लिए लाइव खाता आवश्यक है ([दायरा और सीमाएँ](#scope-and-limitations) देखें)
3. **API key source** को इस तरह सेट करें कि वह आधिकारिक Mollie Payments for WooCommerce प्लगइन की कुंजी दोबारा उपयोग करे, या इसी स्क्रीन पर दर्ज की गई कुंजी का उपयोग करे
4. यदि आप कुंजी यहीं दर्ज करते हैं, तो अपनी Mollie **लाइव API कुंजी** को **Mollie API Key** में चिपकाएँ
5. सहेजें

:::warning Live मोड का उपयोग करें
Mollie टर्मिनल केवल **लाइव** खातों पर मौजूद होते हैं, इसलिए टेस्ट API कुंजी किसी टर्मिनल को नहीं चला सकती। Test मोड चुने जाने पर सेटिंग्स स्क्रीन आपको चेतावनी देती है — भुगतान लेने के लिए अपनी लाइव API कुंजी के साथ `Live` पर स्विच करें। देखें [दायरा और सीमाएँ](#scope-and-limitations)।
:::

:::note किसी Profile ID की ज़रूरत नहीं
`pointofsale` भुगतानों के लिए Mollie **Profile ID** आवश्यक नहीं है, और टर्मिनल पूरे खाते में से सूचीबद्ध किए जाते हैं, इसलिए और कुछ चिपकाने की ज़रूरत नहीं।
:::

  </StepCard>
  <StepCard number="3" title="अपने टर्मिनल चुनें">

1. ड्रॉपडाउन से एक **Default terminal** चुनें। यह सूची चुने गए Mollie परिवेश से लाई जाती है — निष्क्रिय टर्मिनल छिपे रहते हैं, क्योंकि Mollie उन्हें दोबारा सक्रिय नहीं कर सकता।
2. *(वैकल्पिक)* **Enabled terminals** को केवल उन डिवाइसों तक सीमित करें जो वास्तव में उपयोग में हैं। सहेजा गया डिफ़ॉल्ट तब भी उपलब्ध रहता है जब वह यहाँ चुना न गया हो; सभी सक्रिय टर्मिनलों की अनुमति देने के लिए इस सेटिंग को खाली छोड़ दें। किसी टर्मिनल को हटाने के लिए **Default terminal** को भी बदलें या खाली करें।
3. *(वैकल्पिक)* **Lock terminal selection** सक्षम करें ताकि कैशियर चेकआउट पर टर्मिनल न बदल सकें — हमेशा डिफ़ॉल्ट टर्मिनल ही उपयोग होता है, और यह सर्वर पर भी लागू किया जाता है।
4. सहेजें

  </StepCard>
  <StepCard number="4" title="WCPOS में सक्षम करें" isLast>

1. `WP Admin > POS > Settings > Checkout` पर जाएँ
2. **Mollie Terminal** गेटवे ढूँढें और उसे POS के लिए सक्षम करें
3. अपनी सेटिंग्स सहेजें

:::note
WooCommerce सेटिंग्स स्क्रीन पर मौजूद **Enable/Disable** चेकबॉक्स केवल *ऑनलाइन स्टोर* चेकआउट को नियंत्रित करता है। यह गेटवे एक बार कॉन्फ़िगर हो जाने पर WCPOS उसका उपयोग करता है, चाहे वह बॉक्स चुना गया हो या नहीं।
:::

  </StepCard>
</Steps>

## सेटिंग्स संदर्भ {#settings}

| सेटिंग | यह क्या करती है |
|---|---|
| **Enable/Disable** | ऑनलाइन स्टोर चेकआउट के लिए गेटवे सक्षम करता है (POS के लिए आवश्यक नहीं) |
| **Title** / **Description** | चेकआउट पर ग्राहक को दिखाई देने वाला लेबल और टेक्स्ट |
| **Mode** | `Test` या `Live`। टर्मिनल भुगतानों के लिए **Live** आवश्यक है — टेस्ट API कुंजी किसी टर्मिनल को नहीं चला सकती |
| **API key source** | नीचे दर्ज की गई कुंजी का उपयोग करता है, या आधिकारिक Mollie Payments for WooCommerce प्लगइन से मेल खाती टेस्ट/लाइव कुंजी दोबारा उपयोग करता है। यदि साझा कुंजी उपलब्ध न हो, तो प्लगइन नीचे दी गई कुंजी पर लौट आता है |
| **Mollie API Key** | चुने गए मोड के लिए टेस्ट या लाइव API कुंजी। तब उपयोग होती है जब **API key source** यहाँ दर्ज कुंजी पर सेट हो, और अनुपलब्ध साझा कुंजी के विकल्प के रूप में भी |
| **Default terminal** | चेकआउट पर डिफ़ॉल्ट रूप से उपयोग होने वाला टर्मिनल, जिसे चुने गए Mollie परिवेश के सक्रिय टर्मिनलों के ड्रॉपडाउन से चुना जाता है |
| **Enabled terminals** | चेकआउट सूची को चुने गए टर्मिनलों तक सीमित करता है। खाली = सभी सक्रिय टर्मिनल। सहेजा गया डिफ़ॉल्ट हमेशा उपलब्ध रहता है, इसलिए किसी टर्मिनल को हटाते समय उसे भी बदलें या खाली करें |
| **Lock terminal selection** | चेकआउट पर डिफ़ॉल्ट टर्मिनल को बाध्य करता है ताकि कैशियर उसे बदल न सकें (इसके लिए एक डिफ़ॉल्ट टर्मिनल आवश्यक है) |
| **Checkout debug logs** | चेकआउट भुगतान पैनल पर **Show logs**, **Copy**, और **Clear** टूल दिखाता है। सपोर्ट के लिए लॉग इकट्ठा करने के अलावा इसे बंद ही रहने दें; भुगतान गतिविधि हमेशा `WooCommerce > Status > Logs` के अंतर्गत दर्ज होती है |

वेबहुक URL हर भुगतान पर अपने-आप लागू हो जाता है, इसलिए भरने के लिए कोई वेबहुक फ़ील्ड नहीं है और Mollie डैशबोर्ड में किसी कॉन्फ़िगरेशन की ज़रूरत नहीं।

## उपयोग {#usage}

### भुगतान प्रक्रिया {#processing-payments}

1. **आइटम जोड़ें**: POS में अपने कार्ट में उत्पाद जोड़ें
2. **गेटवे चुनें**: भुगतान विधि के रूप में "Mollie Terminal" चुनें
3. **टर्मिनल चुनें**: ड्रॉपडाउन से एक टर्मिनल चुनें (डिफ़ॉल्ट रूप से कॉन्फ़िगर किया गया टर्मिनल; टर्मिनल चयन लॉक होने पर यह छिपा रहता है)
4. **भुगतान शुरू करें**: **Start Terminal Payment** पर क्लिक करें — Mollie भुगतान को डिवाइस तक भेज देता है
5. **ग्राहक भुगतान**: ग्राहक टर्मिनल पर अपना कार्ड टैप करता है, डालता है या स्वाइप करता है। स्थिति सजीव रूप से अपडेट होती है — `Sending to terminal…` → `Waiting for terminal…`
6. **स्वचालित पूर्णता**: टर्मिनल की पुष्टि मिलते ही ऑर्डर भुगतान-प्राप्त के रूप में चिह्नित होता है और POS अपने-आप रसीद पर पहुँचा देता है

### भुगतान नियंत्रण {#payment-controls}

- **Start Terminal Payment**: चुने गए टर्मिनल पर एक नया भुगतान अनुरोध भेजें
- **Cancel Payment**: ऐसे भुगतान को रद्द करें जो अब भी खुला है। भुगतान के टर्मिनल तक पहुँच जाने के बाद Mollie उसे रद्द न किए जा सकने योग्य बताता है, और कैशियर उसे डिवाइस पर ही रद्द करता है

### ऑर्डर प्रबंधन {#order-management}

- **सत्यापित पूर्णता**: हर वेबहुक, पोल, रद्दीकरण और पुनःप्रयास किसी ऑर्डर को बदलने से पहले आधिकारिक Mollie स्थिति लाता है, इसलिए ऑर्डर केवल पुष्ट Mollie स्थिति पर ही भुगतान-प्राप्त चिह्नित होते हैं
- **भुगतान ट्रैकिंग**: भुगतान प्रयास ऑर्डर पर केवल-जोड़ने योग्य इतिहास के रूप में दर्ज होते हैं
- **रसीद निर्माण**: सफल भुगतानों के बाद मानक POS रसीदें बनाई जाती हैं

## रिफ़ंड {#refunds}

रिफ़ंड समर्थित हैं। सामान्य WooCommerce ऑर्डर स्क्रीन से ऑर्डर का रिफ़ंड करें और रिफ़ंड Mollie को भेज दिया जाता है। चूँकि Mollie ही सत्य का स्रोत है, रिफ़ंड के पुनःप्रयास दूसरा रिफ़ंड बनाने से **पहले** Mollie की रिफ़ंड ID और मेटाडेटा से मिलान करते हैं, इसलिए कोई रिफ़ंड गलती से दो बार जारी नहीं होता।

## बासी भुगतानों की सफ़ाई {#stale-payment-cleanup}

चेकआउट अधूरा छोड़ दिए जाने पर Mollie का कोई `pointofsale` भुगतान Mollie की ओर "खुला" रह सकता है। प्लगइन ऐसे खुले भुगतानों को इन स्थितियों में अपने-आप रद्द कर देता है:

- ऑटो-पोल का समय समाप्त हो जाए (डिफ़ॉल्ट रूप से 5 मिनट) — भुगतान को पीछे छोड़ने के बजाय रद्दीकरण भेजा जाता है
- ऑर्डर किसी **अलग** भुगतान विधि से पूरा किया जाए (उदाहरण के लिए ग्राहक नकद भुगतान कर दे), या ऑर्डर WooCommerce में रद्द कर दिया जाए
- भुगतान के बीच में ही चेकआउट पेज बंद कर दिया जाए — टैब बंद होते समय यथासंभव प्रयास वाला रद्दीकरण भेजा जाता है
- हर 10 मिनट में एक WP-Cron स्वीप चलती है और बासी सीमा (डिफ़ॉल्ट रूप से 10 मिनट) के बाद खुले रह गए भुगतानों को रद्द या हल करती है, उन स्थितियों सहित जब बाकी सफ़ाई रास्ते चलने से पहले ही ब्राउज़र बंद हो जाए या नेटवर्क टूट जाए

यदि भुगतान पहले ही टर्मिनल तक पहुँच चुका हो, तो Mollie उसे रद्द न किए जा सकने योग्य बताता है और कैशियर उसे डिवाइस पर ही रद्द करता है — ऐसी स्थिति में ये सफ़ाइयाँ सुरक्षित रूप से कुछ नहीं करतीं।

## दायरा और सीमाएँ {#scope-and-limitations}

:::important Test मोड की सीमा
Mollie टर्मिनल केवल **लाइव** खातों पर मौजूद होते हैं। Mollie की **टेस्ट** API कुंजी किसी भौतिक (या iOS/Android) टर्मिनल को नहीं चला सकती, इसलिए टेस्ट मोड में टर्मिनल भुगतानों को एंड-टू-एंड आज़माया नहीं जा सकता। यह Mollie प्लेटफ़ॉर्म की सीमा है, प्लगइन की पाबंदी नहीं — Test मोड चुने जाने पर सेटिंग्स स्क्रीन एक चेतावनी दिखाती है। टर्मिनल भुगतान लेने के लिए अपनी लाइव API कुंजी के साथ **Live** मोड का उपयोग करें।
:::

:::note मुद्रा
जब तक Mollie Terminal के लिए व्यापक मुद्रा समर्थन की पुष्टि नहीं हो जाती, POS टर्मिनल भुगतान **EUR** तक सीमित हैं।
:::

## समस्या निवारण {#troubleshooting}

### सामान्य समस्याएँ {#common-issues}

<Accordion>
  <AccordionItem question="ड्रॉपडाउन में कोई टर्मिनल नहीं दिखता">

  - पुष्टि करें कि **Mode** `Live` पर सेट है और प्रभावी API कुंजी एक लाइव कुंजी है — टेस्ट खातों पर टर्मिनल मौजूद ही नहीं होते
  - जाँचें कि टर्मिनल आपके Mollie खाते पर पंजीकृत और **सक्रिय** है; निष्क्रिय टर्मिनल छिपे रहते हैं क्योंकि Mollie उन्हें दोबारा सक्रिय नहीं कर सकता
  - सुनिश्चित करें कि आपकी साइट Mollie तक पहुँच सकती है — यह सूची API के ज़रिए सजीव रूप से लाई जाती है

  </AccordionItem>

  <AccordionItem question="भुगतान शुरू ही नहीं होता">

  - पुष्टि करें कि कोई टर्मिनल चुना गया है (या चयन लॉक होने पर एक **Default terminal** सेट है)
  - जाँचें कि टर्मिनल चालू है, ऑनलाइन है, और उसी Mollie खाते पर सक्रिय है
  - सत्यापित करें कि ऑर्डर की मुद्रा **EUR** है

  </AccordionItem>

  <AccordionItem question="टर्मिनल का समय समाप्त हो गया या भुगतान खुला ही रह गया">

  - समय समाप्त होने पर (डिफ़ॉल्ट रूप से 5 मिनट) प्लगइन खुले भुगतानों को अपने-आप रद्द करने का प्रयास करता है
  - यदि भुगतान पहले ही टर्मिनल तक पहुँच चुका है और अपने-आप रद्द नहीं हो सकता, तो उसे डिवाइस पर ही रद्द करें
  - इसके बाद आप नया भुगतान शुरू कर सकते हैं या किसी अन्य तरीके से भुगतान ले सकते हैं

  </AccordionItem>

  <AccordionItem question="टर्मिनल पर ऑर्डर पूरा हो गया पर अपडेट होने में देर लग रही है">

  - POS हर 2 सेकंड में Mollie को पोल करता है और भुगतान की पुष्टि होते ही आगे भेज देता है; आमतौर पर वेबहुक इससे पहले ही पुष्टि कर देता है
  - चूँकि Mollie ही सत्य का स्रोत है, ऑर्डर का मिलान आधिकारिक Mollie स्थिति से किया जाता है — वह खोता नहीं है
  - किसी भी Mollie API संदेश के लिए `WooCommerce > Status > Logs` देखें

  </AccordionItem>
</Accordion>
