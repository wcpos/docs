## इसका क्या अर्थ है {#what-this-means}

स्टोर के REST API ने इस ऐप द्वारा उपयोग किए जा सकने वाले किसी भी पते के रूप में उत्तर नहीं दिया।

ऐप ने स्टोर के REST API को उसके सामान्य पते (/wp-json/...) और WordPress के अंतर्निहित वैकल्पिक पते (/?rest_route=...) पर आज़माया, लेकिन किसी ने भी उत्तर नहीं दिया। स्टोर की वेबसाइट स्वयं चालू हो सकती है — समस्या विशेष रूप से REST API तक पहुँच न होने की है, जो आमतौर पर किसी सुरक्षा प्लगइन द्वारा उसे छिपाने या फ़ायरवॉल नियम द्वारा उसे अवरुद्ध करने के कारण होती है।

## क्या करें {#what-to-do}

निदान जानकारी निर्यात करें और सहायता टीम से संपर्क करें। ऊपर दिया गया बदलाव करने के बाद पुनः प्रयास करें; उसके बिना पुनः प्रयास करने पर वही विफलता होगी।

## आपका डेटा {#your-data}

कोई भी ऑर्डर या उत्पाद डेटा प्रभावित नहीं है।

## समस्या निवारण {#troubleshoot}

1. यदि कोई सुरक्षा प्लगइन /wp-json/ को छिपाता है या उसका नाम बदलता है (उदाहरण के लिए WP Hide), तो WordPress के अंतर्निहित /?rest_route= रूप को भी अनुमति दें — ऐप स्वचालित रूप से इस पर फ़ॉलबैक करता है।
2. wp-json या rest_route से मेल खाने वाले किसी भी नियम के लिए फ़ायरवॉल (WAF) नियमों की जाँच करें और स्टोर के अपने REST API को अनुमति दें।
3. ब्राउज़र से जाँच करें: https://your-store.com/?rest_route=/ को JSON लौटाना चाहिए, न कि 403 पेज या साइट का होमपेज।
4. यदि सर्वर मेंटेनेंस पेज या बॉट चुनौती के पीछे है, तो REST अनुरोधों का उत्तर HTML पेज से दिया जा सकता है — REST API के लिए चुनौती को अक्षम करें।

## कहाँ देखें {#where-to-look}

जब WCPOS इस त्रुटि को सहेज सकता है, तो यह उसे उस डिवाइस पर रिकॉर्ड करता है जिसने त्रुटि उत्पन्न की थी। **स्टोर स्वास्थ्य → लॉग** खोलें (नेविगेशन ड्रॉअर के निचले भाग में हृदय-धड़कन आइकन), इस कोड से चिह्नित प्रविष्टि ढूँढें और उसे विस्तृत करें: विस्तृत पंक्ति में सरल भाषा में कारण और विफलता के समय कैप्चर किया गया संदर्भ दिखता है। किसी स्टोर अनुरोध के लिए, उस संदर्भ में सर्वर का अपना त्रुटि कोड (`serverCode`), HTTP `status` या `endpoint` शामिल हो सकता है; दिखाए जाने वाले फ़ील्ड इस पर निर्भर करते हैं कि विफलता कहाँ हुई थी। किसी समस्या की रिपोर्ट करते समय, स्क्रीनशॉट के बजाय लॉग स्क्रीन के शीर्ष पर **डीबग जानकारी कॉपी करें** का उपयोग करें (फ़ोन और टैबलेट पर **डीबग जानकारी साझा करें**): इसमें ऐप संस्करण, कनेक्शन स्थिति और सबसे हाल की त्रुटियाँ शामिल होती हैं। लॉग अधिकतम 30 दिनों तक रखे जाते हैं, इसलिए समस्या नई होने पर ही उन्हें एकत्र करें। साथ ही, POS द्वारा अपनी लॉग प्रविष्टि लिख पाने से पहले दिखाई देने वाली किसी भी ब्राउज़र-कंसोल त्रुटि को भी कॉपी करें।
