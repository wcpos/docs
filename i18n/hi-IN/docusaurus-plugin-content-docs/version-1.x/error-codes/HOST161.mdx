## इसका क्या अर्थ है {#what-this-means}

होस्ट इस स्टोर के काउंटरों को दर-सीमित कर रहा है।

सर्वर 429 (बहुत अधिक अनुरोध) उत्तर देता रहता है, भले ही ऐप पहले से ही पीछे हट रहा है और सर्वर की Retry-After देरी का सम्मान कर रहा है। एक ही इंटरनेट कनेक्शन पर कई काउंटर एक पते को साझा करते हैं, इसलिए प्रति-स्रोत दर सीमाएँ उन्हें एक ही बहुत व्यस्त क्लाइंट के रूप में मानती हैं। सिंकिंग स्वचालित रूप से जारी रहती है लेकिन जब तक सीमा नहीं बढ़ाई जाती, तब तक धीमी रहेगी।

## आपका डेटा {#your-data}

किसी ऑर्डर या उत्पाद डेटा पर कोई असर नहीं पड़ता।

## समस्या निवारण {#troubleshoot}

1. होस्ट से स्टोर के अपने ट्रैफ़िक के लिए REST API दर सीमा बढ़ाने या छूट देने के लिए कहें — यदि दुकान के पास स्थिर IP है तो उसका नाम बताएँ।
2. जो सुरक्षा सेवाएँ दोहराई गई एरर प्रतिक्रियाओं (429) को ब्लॉक की ओर गिनती हैं (उदाहरण के लिए Sucuri का IDS) उन्हें उस काउंटर से स्टोर के API को बाहर रखने की आवश्यकता हो सकती है।
3. यदि कई काउंटर एक कनेक्शन साझा करते हैं, तो होस्ट को यह बताएँ: यहाँ एक IP पूरी दुकान है, न कि एक उपयोगकर्ता।
