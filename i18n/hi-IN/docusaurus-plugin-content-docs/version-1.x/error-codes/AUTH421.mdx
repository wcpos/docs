## इसका क्या अर्थ है {#what-this-means}

स्टोर का सर्वर इस ऐप द्वारा उपयोग किए जा सकने वाले हर चैनल पर लॉगिन टोकन को अवरुद्ध कर रहा है।

ऐप ने पुष्टि की कि स्टोर तक पहुँचा जा सकता है, लेकिन सर्वर (या उसके सामने मौजूद कोई फ़ायरवॉल, प्रॉक्सी, या सुरक्षा प्लगइन) Authorization हेडर को हटा देता है और तब भी टोकन को अवरुद्ध करता है जब उसे URL पैरामीटर के रूप में भेजा जाता है। लॉगिन टोकन पहुँचाने का कोई तीसरा तरीका नहीं है, इसलिए इसे सर्वर पर ठीक किया जाना चाहिए।

## आपका डेटा {#your-data}

किसी ऑर्डर या उत्पाद डेटा पर कोई असर नहीं पड़ता।

## समस्या निवारण {#troubleshoot}

**आपके होस्ट / सर्वर के लिए** — जब तक सर्वर उसे पास नहीं होने देता, लॉगिन टोकन के पास कोई डिलीवरी चैनल नहीं है:

1. Authorization हेडर को WordPress तक पहुँचने दें — Apache पर यह आमतौर पर एक लाइन है: `SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1`।
2. यदि साइट `.htaccess` रीराइट का उपयोग करती है, तो WordPress की जनरेट की गई उस RewriteRule लाइन को बनाए रखें जो `HTTP_AUTHORIZATION` को पास करती है — सुरक्षा प्लगइन कभी-कभी इसे हटा देते हैं।
3. किसी प्रॉक्सी या CDN के पीछे, उसकी हेडर अनुमति-सूची की जाँच करें: Authorization अनुरोध हेडर को ओरिजिन तक अग्रेषित किया जाना चाहिए।
4. यदि कोई वेब एप्लिकेशन फ़ायरवॉल (WAF) URL पैरामीटर फ़िल्टर कर रहा है, तो `/wcpos/` REST मार्गों पर authorization पैरामीटर की अनुमति दें।
