## इसका क्या अर्थ है {#what-this-means}

स्टोर के सामने मौजूद एक कैश एक व्यक्ति की API प्रतिक्रियाओं को सभी को दोबारा दिखा रहा है।

एक कैशिंग परत यह जाँचे बिना कि कौन पूछ रहा है, संग्रहीत REST API प्रतिक्रियाएँ परोस रही है: ऐप ने दो अलग-अलग तरह से प्रमाणित जाँचें भेजीं और दोनों बार पहली जाँच का ही उत्तर प्राप्त हुआ। किसी लाइव स्टोर पर इसका अर्थ है कि एक कैशियर दूसरे का डेटा देख सकता है, इसलिए जब तक कैश स्टोर के API को बाहर नहीं रखता, कनेक्ट करना अवरुद्ध है। यह एक होस्टिंग-परत की समस्या है — WordPress स्वयं हमेशा प्रति-उपयोगकर्ता उत्तर देता है।

## आपका डेटा {#your-data}

इस डिवाइस पर डेटा जोखिम में हो सकता है — स्थानीय डेटा साफ़ न करें। यदि यह बना रहता है, तो डायग्नोस्टिक्स निर्यात करें और WCPOS सपोर्ट से संपर्क करें।

## समस्या निवारण {#troubleshoot}

1. स्टोर के REST API पथों (/wp-json/ और /?rest_route=) को पेज कैशिंग से बाहर रखें — LiteSpeed पर REST कैशिंग अक्षम करें या नो-कैश नियम जोड़ें; WP Engine पर WooCommerce अपवाद को /wp-json/wcpos तक बढ़ाएँ; Sucuri पर कैशिंग स्तर को Cache-Control का सम्मान करने के लिए सेट करें।
2. स्टोर का API पहले से ही Cache-Control: no-store और Vary: Authorization भेजता है — कैश परत उन्हें अनदेखा कर रही है; होस्ट को उन हेडरों की ओर इंगित करें।
3. कैश सेटिंग्स बदलने के बाद, दोबारा कनेक्ट करने से पहले कैश को purge करें।
