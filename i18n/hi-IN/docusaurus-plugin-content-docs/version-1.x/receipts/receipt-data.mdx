WCPOS लॉजिकलेस HTML टेम्पलेट और थर्मल XML टेम्पलेट एक ही कैनोनिकल रसीद पेलोड से रेंडर होते हैं। Mustache डॉट पाथ जैसे `{{order.number}}`, `{{store.name}}`, और `{{totals.total_display}}` का उपयोग करें। ऐरे को सेक्शन के साथ रेंडर किया जाता है:

```mustache
{{#lines}}
  {{name}} x {{qty}} — {{line_total_display}}
{{/lines}}
```

कैनोनिकल कॉन्ट्रैक्ट सर्वर पर WCPOS रसीद डेटा बिल्डर द्वारा तैयार किया जाता है और ऐप में ऑफ़लाइन रसीद रेंडरर द्वारा मिरर किया जाता है। रसीदें स्थानीय डेटा से तुरंत खुलती हैं, फिर सर्वर प्रतिक्रिया उपलब्ध होने पर उसमें अपग्रेड हो जाती हैं, इसलिए कस्टम टेम्पलेट को PHP ऑर्डर मेथड के बजाय नीचे दिए गए फ़ील्ड का उपयोग करना चाहिए।

रसीद डेटा v1.1 प्रत्येक उत्पाद लाइन के लिए रिकॉर्ड किए गए नियमित मूल्य, कूपन-पूर्व विक्रय मूल्य, और बचत फ़ील्ड जोड़ता है। यह ऑर्डर-स्तर की बचत कुल भी उपलब्ध कराता है, जिसमें एक **कुल बचत** मान शामिल है जो नियमित-मूल्य की बचत को WooCommerce छूटों के साथ जोड़ता है, बिना ऑर्डर कुल या रिपोर्ट बदले।

## रेंडरिंग नियम {#rendering-rules}

### मुद्रा फ़ील्ड {#currency-fields}

संख्यात्मक मुद्रा फ़ील्ड संख्याओं के रूप में संरक्षित रहते हैं और रेंडरर टेम्पलेट आउटपुट के लिए लोकेल-अवेयर `_display` फ़ील्ड जोड़ता है:

| संख्यात्मक फ़ील्ड | प्रदर्शन फ़ील्ड |
|---------------|---------------|
| `totals.total` | `totals.total_display` |
| `lines[].line_total` | `lines[].line_total_display` |
| `payments[].amount` | `payments[].amount_display` |
| `tax_summary[].tax_amount` | `tax_summary[].tax_amount_display` |

रसीद प्रिंट करते समय `_display` फ़ील्ड को प्राथमिकता दें। संख्यात्मक फ़ील्ड का उपयोग केवल सशर्त अनुभागों या मशीन-पठनीय आउटपुट के लिए करें।

### कर प्रदर्शन-सचेत फ़ील्ड {#tax-display-aware-fields}

कई फ़ील्ड के समावेशी और अनन्य वैरिएंट तथा एक प्रदर्शन-पक्ष सुविधा मान होता है। सुविधा मान स्टोर की कार्ट कर प्रदर्शन सेटिंग का अनुसरण करता है।

| सुविधा फ़ील्ड | समावेशी फ़ील्ड | अनन्य फ़ील्ड |
|-------------------|-----------------|-----------------|
| `lines[].regular_price` | `lines[].regular_price_incl` | `lines[].regular_price_excl` |
| `lines[].selling_price` | `lines[].selling_price_incl` | `lines[].selling_price_excl` |
| `lines[].unit_savings` | `lines[].unit_savings_incl` | `lines[].unit_savings_excl` |
| `lines[].line_regular_total` | `lines[].line_regular_total_incl` | `lines[].line_regular_total_excl` |
| `lines[].line_selling_total` | `lines[].line_selling_total_incl` | `lines[].line_selling_total_excl` |
| `lines[].line_savings` | `lines[].line_savings_incl` | `lines[].line_savings_excl` |
| `lines[].unit_price` | `lines[].unit_price_incl` | `lines[].unit_price_excl` |
| `lines[].unit_subtotal` | `lines[].unit_subtotal_incl` | `lines[].unit_subtotal_excl` |
| `lines[].line_subtotal` | `lines[].line_subtotal_incl` | `lines[].line_subtotal_excl` |
| `lines[].discounts` | `lines[].discounts_incl` | `lines[].discounts_excl` |
| `lines[].line_total` | `lines[].line_total_incl` | `lines[].line_total_excl` |
| `fees[].total` | `fees[].total_incl` | `fees[].total_excl` |
| `shipping[].total` | `shipping[].total_incl` | `shipping[].total_excl` |
| `discounts[].total` | `discounts[].total_incl` | `discounts[].total_excl` |
| `totals.subtotal` | `totals.subtotal_incl` | `totals.subtotal_excl` |
| `totals.discount_total` | `totals.discount_total_incl` | `totals.discount_total_excl` |
| `totals.sale_savings_total` | `totals.sale_savings_total_incl` | `totals.sale_savings_total_excl` |
| `totals.total_saved` | `totals.total_saved_incl` | `totals.total_saved_excl` |
| `totals.total` | `totals.total_incl` | `totals.total_excl` |

### दिनांक ऑब्जेक्ट {#date-objects}

दिनांक फ़ील्ड कई पूर्व-स्वरूपित वेरिएंट वाले ऑब्जेक्ट हैं। इससे Mustache के अंदर दिनांक फ़ॉर्मेटिंग करने की आवश्यकता नहीं रहती।

| फ़ील्ड | विवरण |
|-------|-------------|
| `datetime`, `date`, `time` | डिफ़ॉल्ट दिनांक/समय स्ट्रिंग |
| `datetime_short`, `datetime_long`, `datetime_full` | लोकेल-अवेयर संयुक्त प्रारूप |
| `date_short`, `date_long`, `date_full` | लोकेल-अवेयर केवल-दिनांक प्रारूप |
| `date_ymd`, `date_dmy`, `date_mdy` | निश्चित-क्रम दिनांक प्रारूप |
| `weekday_short`, `weekday_long` | दिनों के नाम |
| `day`, `month`, `month_short`, `month_long`, `year` | अलग-अलग दिनांक भाग |

उपलब्ध दिनांक ऑब्जेक्ट: `order.created`, `order.paid`, `order.completed`, `order.printed`, और `refunds[].date`। `order.printed` रेंडर के समय ताज़ा किया जाता है, जो दोबारा प्रिंट करने के लिए उपयोगी है।

## शीर्ष-स्तरीय अनुभाग {#top-level-sections}

| अनुभाग | प्रकार | विवरण |
|---------|------|-------------|
| `order` | ऑब्जेक्ट | ऑर्डर की पहचान, स्थिति, तिथियाँ, नोट, और भुगतान URL जानकारी |
| `store` | ऑब्जेक्ट | स्टोर की पहचान, पता, संपर्क विवरण, कर ID, लोगो, समय, और फ़ुटर टेक्स्ट |
| `cashier` | ऑब्जेक्ट | वह उपयोगकर्ता जिसने ऑर्डर प्रोसेस किया |
| `customer` | ऑब्जेक्ट | ग्राहक का प्रदर्शन नाम, पते, और कर ID |
| `lines` | ऐरे | उत्पाद लाइन आइटम |
| `fees` | ऐरे | शुल्क पंक्तियाँ |
| `shipping` | ऐरे | शिपिंग पंक्तियाँ |
| `discounts` | ऐरे | कूपन/छूट पंक्तियाँ |
| `totals` | ऑब्जेक्ट | ऑर्डर कुल, भुगतान कुल, रिफ़ंड सारांश, और आइटम गणना |
| `tax` | ऑब्जेक्ट | सेक्शन गार्ड के लिए कर प्रदर्शन मोड फ़्लैग |
| `tax_summary` | ऐरे | प्रति-दर कर सारांश पंक्तियाँ |
| `has_tax_summary` | बूलियन | `tax_summary` के लिए सुविधा गार्ड |
| `payments` | ऐरे | भुगतान पंक्तियाँ |
| `refunds` | ऐरे | ऑर्डर पर लागू किए गए रिफ़ंड रिकॉर्ड |
| `fiscal` | ऑब्जेक्ट | फ़िस्कल एकीकरण द्वारा भरे गए फ़िस्कल स्नैपशॉट फ़ील्ड |
| `presentation_hints` | ऑब्जेक्ट | फ़ॉर्मेटिंग और रेंडरर संकेत |
| `i18n` | ऑब्जेक्ट | बंडल किए गए और कस्टम टेम्पलेट के लिए अनुवादित लेबल |

## मूल्य आपस में कैसे जुड़े हैं {#price-model}

एक उत्पाद लाइन कई मूल्य लेकर चलती है, और नाम तभी समझ में आते हैं जब आप उन्हें राशि पर ही देखें। यह नमूना ऑर्डर की एस्प्रेसो लाइन है — $17.00 का उत्पाद, $14.50 पर सेल में, और ऊपर से 10% का कूपन:

पूरा फ़ील्ड संदर्भ नीचे अनुभाग के अनुसार समूहित है। सब कुछ डिफ़ॉल्ट रूप से बंद है — जिस समूह की आवश्यकता हो उसे विस्तृत करें।

### नियमित मूल्य और बचत दिखाना {#displaying-regular-price-and-savings}

इकाई-मूल्य वाले लेआउट के लिए, रिकॉर्ड किया गया नियमित मूल्य, विक्रय मूल्य, और बचत इस तरह दिखाएँ:

```mustache
{{#lines}}
  {{#unit_savings}}
    <span style="text-decoration: line-through;">{{regular_price_display}}</span>
    <span>{{selling_price_display}}</span>
    <span>{{i18n.savings}}: -{{unit_savings_display}}</span>
  {{/unit_savings}}
{{/lines}}
```

जब मात्रा मायने रखती हो, तब लाइन-कुल वाले फ़ील्ड उपयोग करें:

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    <span>{{i18n.savings}}: -{{line_savings_display}}</span>
  {{/line_savings}}
{{/lines}}
```

`selling_price` कूपनों से पहले का मूल्य है। WooCommerce छूटों के बाद की अंतिम राशि के लिए `unit_price` या `line_total` उपयोग करें।

:::note v1.9.0 से पहले बनाए गए ऑर्डर दोबारा प्रिंट करना
पुराने WCPOS ऑर्डरों में नियमित-से-विक्रय मूल्य की कमी पहले से ही `discounts` में शामिल हो सकती है। यदि आपका कस्टम टेम्पलेट लाइन बचत और लाइन छूट दोनों प्रिंट करता है, तो एक ही कमी दो बार दिखने से बचने के लिए `savings_in_discounts` का उपयोग करें:

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    {{^savings_in_discounts}}
      <span>{{i18n.savings}}: -{{line_savings_display}}</span>
    {{/savings_in_discounts}}
  {{/line_savings}}
  {{#discounts}}
    <span>{{i18n.discount}}: -{{discounts_display}}</span>
  {{/discounts}}
{{/lines}}
```

यदि टेम्पलेट लाइन-स्तर की `discounts` पंक्ति प्रिंट नहीं करता, तो `savings_in_discounts` सही होने पर भी `line_savings` दिखाते रहें। बंडल किए गए टेम्पलेट यह अंतर स्वतः संभाल लेते हैं।
:::

```mustache
{{#totals.total_saved_complete}}
  {{#totals.total_saved}}
    <span>{{i18n.total_saved}}: {{totals.total_saved_display}}</span>
  {{/totals.total_saved}}
{{/totals.total_saved_complete}}
```

बंडल किए गए मूल्य-वाहक टेम्पलेट यही गार्ड संरचना कर-समावेशी वैरिएंट (`total_saved_incl` और `total_saved_incl_display`) के साथ उपयोग करते हैं, और **कुल बचत** केवल तभी दिखाते हैं जब पूर्ण मान शून्य से अधिक हो।

### tax और tax_summary {#tax-and-tax_summary}

प्रदर्शन-मोड गार्ड के लिए `tax` और मदवार दर पंक्तियों के लिए `tax_summary` का उपयोग करें।

| कर फ़ील्ड | प्रकार | विवरण |
|-----------|------|-------------|
| `tax.display` | स्ट्रिंग | `incl` या `excl` |
| `tax.display_incl` | बूलियन | सही, जब मूल्य कर सहित प्रदर्शित होते हैं |
| `tax.display_excl` | बूलियन | सही, जब मूल्य कर रहित प्रदर्शित होते हैं |
| `tax.breakdown` | स्ट्रिंग | `hidden`, `single`, या `itemized` |
| `tax.breakdown_hidden` | बूलियन | सही, जब कर पंक्तियाँ छिपाई जानी चाहिए |
| `tax.breakdown_single` | बूलियन | सही, जब एकल कर कुल पसंद किया जाता है |
| `tax.breakdown_itemized` | बूलियन | सही, जब प्रति-दर पंक्तियाँ पसंद की जाती हैं |
| `has_tax_summary` | बूलियन | सही, जब `tax_summary` में पंक्तियाँ हों |

`tax_summary` पर `{{#tax_summary}}...{{/tax_summary}}` के साथ लूप करें।

| फ़ील्ड | प्रकार | विवरण |
|-------|------|-------------|
| `code` | स्ट्रिंग | कर दर ID/कोड |
| `rate` | संख्या/null | हल होने पर दर प्रतिशत |
| `label` | स्ट्रिंग | कर दर लेबल |
| `compound` | बूलियन | दर चक्रवृद्धि है या नहीं |
| `taxable_amount_excl` | संख्या/null | कर रहित कर-योग्य आधार |
| `tax_amount` | संख्या | वसूला गया कर |
| `taxable_amount_incl` | संख्या/null | कर सहित कर-योग्य आधार |

स्वरूपित वैरिएंट: `taxable_amount_excl_display`, `tax_amount_display`, और `taxable_amount_incl_display`।
