Cloudflare आपकी साइट की सुरक्षा के लिए आगंतुकों से सुरक्षा जाँच पूरी करवाता है। ब्राउज़र यह जाँच चुपचाप पूरी कर लेता है। WCPOS ऐप ब्राउज़र नहीं है: यह आपके स्टोर के REST API से बात करता है। जब Cloudflare डेटा के बजाय सुरक्षा-जाँच वाला पेज लौटाता है, तो ऐप कनेक्ट नहीं कर पाता।

यह पृष्ठ बताता है कि समस्या को कैसे पहचानें और Cloudflare को ऐप तक पहुँच देने के लिए कैसे कहें। यहाँ दिए गए हर चरण को स्टोर के मालिक या साइट का Cloudflare खाता प्रबंधित करने वाले व्यक्ति को करना है।

## इसे कैसे पहचानें {#how-to-recognise-it}

- कनेक्ट स्क्रीन पर त्रुटि कोड [HOST121](/error-codes/HOST121) के साथ **"इस स्टोर की होस्टिंग व्यवस्था ऐप को रोक रही है"** दिखता है।
- कनेक्ट या सिंक करते समय डेस्कटॉप ऐप एक छोटी **"your-store.com के लिए सुरक्षा जाँच"** विंडो खोलता है।
- पुराने संस्करण ऐसी साइट पर **"साइट WordPress साइट नहीं लगती"** या **"साइट ने जवाब देने में बहुत समय लिया"** दिखाते थे जो स्पष्ट रूप से ऑनलाइन थी।
- क्लाउड प्रिंटिंग रुक जाती है और "security service is blocking WCPOS Cloud Print" संदेश दिखता है।

पुष्टि करने के लिए, टर्मिनल खोलें और चलाएँ:

```bash
curl -sI https://your-store.com/wp-json/
```

रोक दी गई साइट `403` स्थिति और `cf-mitigated: challenge` हेडर लौटाती है। सामान्य साइट `200` और `content-type: application/json` लौटाती है। अगर `404` मिले, तो आपकी साइट pretty permalinks इस्तेमाल नहीं करती; इसके बजाय यही जाँच `'https://your-store.com/?rest_route=/'` पर करें। अगर WordPress सबफ़ोल्डर में है, तो उसे शामिल करें: `https://example.com/shop/wp-json/`।

:::note डेस्कटॉप ऐप एक बार की जाँच पूरी कर सकता है
डेस्कटॉप ऐप के हाल के संस्करण, संभव होने पर, Cloudflare की जाँच एक छोटी विंडो में पूरी करते हैं। इससे आपका काम जारी रहता है, लेकिन Cloudflare की दी हुई अनुमति की अवधि समाप्त हो जाती है (डिफ़ॉल्ट रूप से 30 मिनट में) और जाँच फिर दिखाई देती है। इस विंडो को अस्थायी उपाय मानें और नीचे दिया गया समाधान लागू करें।
:::

## कौन-सा Cloudflare फ़ीचर यह समस्या पैदा कर रहा है {#which-feature}

समाधान इस पर निर्भर करता है कि कौन-सा फ़ीचर ऐप को चुनौती दे रहा है। अपनी साइट के Cloudflare डैशबोर्ड में ये विकल्प देखें। Cloudflare अपने मेनू बदलता रहा है; पुराने स्थान को कोष्ठक में दिया गया है।

| फ़ीचर | स्थान | क्या यह API को छूट दे सकता है? |
| --- | --- | --- |
| **Bot Fight Mode** (Free plan) | Security → Settings → Bot traffic (पुराना डैशबोर्ड: Security → Bots) | **नहीं।** Cloudflare Skip या Allow नियमों को इसे पार करने की अनुमति नहीं देता। इसे बंद करें, या Pro में अपग्रेड करके Super Bot Fight Mode इस्तेमाल करें, जिसे नीचे दिया गया Skip नियम छूट दे सकता है। |
| **Under Attack Mode** | साइट Overview पर "Under Attack Mode" टॉगल, या Security → Settings | हाँ। नीचे दिया गया Skip नियम Security Level को छोड़ देता है, जिसे Under Attack Mode बढ़ाता है। या हमला समाप्त होने पर Under Attack Mode बंद करें। |
| **Super Bot Fight Mode** (Pro और उससे ऊपर) | Security → Settings → Bot traffic (पुराना डैशबोर्ड: Security → Bots) | हाँ, नीचे दिए गए Skip नियम से। |
| **WAF custom या managed rules**, जिन्हें _Managed Challenge_ पर सेट किया गया है | Security → Security rules (पुराना डैशबोर्ड: Security → WAF) | हाँ, नीचे दिए गए Skip नियम से; इसे चुनौती देने वाले किसी भी custom rule से ऊपर रखें। Managed rules हमेशा custom rules के बाद चलते हैं, इसलिए उनके लिए क्रम मायने नहीं रखता। |

Cloudflare का आधिकारिक WordPress प्लगइन Under Attack Mode टॉगल कर सकता है और WAF चालू कर सकता है, लेकिन Skip नियम नहीं बना सकता। वे Cloudflare डैशबोर्ड में बनाए जाते हैं।

## REST API के लिए Skip नियम जोड़ें {#add-a-skip-rule}

Bot Fight Mode को छोड़कर बाकी सभी स्थितियों का यही समाधान है। यह Cloudflare को आपके स्टोर के REST API अनुरोधों को चुनौती न देने के लिए कहता है। WordPress के अपने लॉगिन और अनुमति जाँचें इन एंडपॉइंट की सुरक्षा करती रहती हैं।

1. Cloudflare डैशबोर्ड में अपनी साइट खोलें, फिर **Security → Security rules** (पुराना डैशबोर्ड: **Security → WAF → Custom rules**) पर जाएँ और **Create rule → Custom rules** चुनें।
2. इसका नाम `WCPOS REST API` रखें।
3. **When incoming requests match** के अंतर्गत **Edit expression** चुनें और यह पेस्ट करें:

   ```text
   (starts_with(http.request.uri.path, "/wp-json/")) or (http.request.uri.path eq "/" and (starts_with(http.request.uri.query, "rest_route=") or http.request.uri.query contains "&rest_route="))
   ```

   दूसरा भाग WordPress के वैकल्पिक पते `/?rest_route=/...` से मेल खाता है और केवल साइट के रूट पर लागू होता है। इसलिए किसी दूसरे पेज की क्वेरी में छिपा `rest_route=` स्ट्रिंग उस पेज की सुरक्षा बंद नहीं करता। अगर WordPress सबफ़ोल्डर में है, जैसे `https://example.com/shop`, तो `/shop/wp-json/` और `/shop/` की जगह `/wp-json/` और `/` इस्तेमाल करें।

4. **Then take action** के अंतर्गत **Skip** चुनें।
5. **All remaining custom rules** चुनें। छोड़ने वाले घटकों की सूची में **All Super Bot Fight Mode rules** और **Security Level** चुनें। **All managed rules** केवल तभी चुनें जब चुनौती किसी managed rule से आ रही हो, और "(Previous version)" चिह्नित प्रविष्टियों को वैसे ही छोड़ दें।
6. नियम लागू करें। अगर आपके अन्य custom rules चुनौती देते हैं या रोकते हैं, तो इस नियम को उनसे ऊपर रखें।

`curl` जाँच फिर चलाएँ। `cf-mitigated` हेडर नहीं होना चाहिए और जवाब JSON होना चाहिए।

:::tip Free plan और Bot Fight Mode
अगर Skip नियम के बाद भी `curl` जाँच में चुनौती दिखती है और **Bot Fight Mode** चालू है, तो समस्या Bot Fight Mode के कारण है। Free plan में इसे Security → Settings → Bot traffic के अंतर्गत बंद करना ही एकमात्र समाधान है। Cloudflare के दस्तावेज़ पुष्टि करते हैं कि कोई नियम इसे पार नहीं कर सकता। अगर Bot Fight Mode पहले से बंद है, तो [अब भी अवरुद्ध?](#still-blocked) देखें।
:::

## कैशिंग {#caching}

Cloudflare REST API जवाबों को कैश भी कर सकता है, जिससे ऐप पुराने उत्पाद और ऑर्डर दिखाता है। ऊपर दिया गया Skip नियम कैशिंग नहीं बदलता। अगर आप HTML पृष्ठों या Automatic Platform Optimization के लिए Cloudflare कैश इस्तेमाल करते हैं, तो उसी एक्सप्रेशन के लिए **Bypass cache** सेट करने वाला **Cache Rule** जोड़ें।

## अब भी अवरुद्ध? {#still-blocked}

जाँचें कि Skip नियम लागू किया गया है, केवल ड्राफ़्ट के रूप में सहेजा नहीं गया, और कोई IP Access नियम POS के नेटवर्क को रोक नहीं रहा। आपकी साइट के आगे काम करने वाली अन्य सेवाएँ भी Cloudflare की तरह व्यवहार करती हैं: सुरक्षा प्लगइनों के लिए [प्लगइन टकराव](/support/troubleshooting/plugin-conflicts) और GoDaddy, WP Engine तथा अन्य के लिए [होस्टिंग नोट्स](/support/performance/server#hosting-specific-notes) देखें।
