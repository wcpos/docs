## कनेक्ट स्क्रीन का परिचय {#connect-screen-overview}

WCPOS डेस्कटॉप या मोबाइल ऐप खोलने पर कनेक्ट स्क्रीन दिखाई देती है। यहाँ आप अपने स्टोर कनेक्शन और उपयोगकर्ता लॉगिन प्रबंधित करते हैं।

{/* Screenshot: connect-screen.png */}

## नया स्टोर जोड़ना {#adding-a-new-store}

1. टेक्स्ट फ़ील्ड में अपने WooCommerce स्टोर का URL दर्ज करें (उदाहरण: `https://mystore.com`)
2. **कनेक्ट** पर क्लिक करें
3. आपको अपने WordPress क्रेडेंशियल से लॉग इन करने के लिए रीडायरेक्ट किया जाएगा
4. सफलतापूर्वक लॉग इन करने के बाद आप ऐप पर लौट आएँगे

## कई स्टोर {#multiple-stores}

आप जितने WooCommerce स्टोर चाहें, उनसे कनेक्ट कर सकते हैं। कनेक्ट स्क्रीन पर हर स्टोर एक अलग कार्ड के रूप में दिखता है, जिसमें ये जानकारी होती है:

- **स्टोर का नाम** और फ़ेविकॉन
- **स्टोर URL**
- उस स्टोर के **लॉग इन किए हुए उपयोगकर्ता**

यह तब उपयोगी है जब आप कई स्थानों या व्यवसायों का प्रबंधन करते हैं।

## हर स्टोर के लिए कई उपयोगकर्ता {#multiple-users-per-store}

हर स्टोर में एक साथ कई उपयोगकर्ता लॉग इन रह सकते हैं। यह इन स्थितियों में उपयोगी है:

- **शिफ़्ट बदलना** - पिछला कैशियर लॉग आउट करे, उससे पहले नया कैशियर लॉग इन कर सकता है
- **कई रजिस्टर सेटअप** - अलग-अलग डिवाइस पर अलग-अलग कैशियर
- **तेज़ी से स्विच करना** - उपयोगकर्ता खातों के बीच आसानी से स्विच करें

### उपयोगकर्ता जोड़ना {#adding-a-user}

उस स्टोर में एक और उपयोगकर्ता जोड़ने के लिए <Icon name="plus" /> बटन पर क्लिक करें, जो "लॉग इन किए हुए उपयोगकर्ता" के पास है।

### उपयोगकर्ता बदलना {#switching-users}

किसी उपयोगकर्ता के रूप में POS खोलने के लिए उसके बैज (उदाहरण: "Brenda") पर क्लिक करें।

### उपयोगकर्ता हटाना {#removing-a-user}

किसी उपयोगकर्ता को स्टोर से लॉग आउट करने के लिए उसके बैज पर **×** क्लिक करें।

## स्टोर हटाना {#removing-a-store}

स्टोर को अपनी सूची से हटाने के लिए उसके कार्ड पर लाल **×** बटन क्लिक करें। इससे सभी उपयोगकर्ता लॉग आउट हो जाते हैं और ऐप से स्टोर कनेक्शन हट जाता है।

## डेमो स्टोर {#demo-store}

स्क्रीन के नीचे आपको "डेमो स्टोर में प्रवेश करें" लिंक दिख सकता है। यह आपको डेमो WooCommerce स्टोर से जोड़ता है, जहाँ आप अपने स्टोर के डेटा को प्रभावित किए बिना WCPOS की सुविधाएँ आज़मा सकते हैं।

## समस्या निवारण {#troubleshooting}

:::tip सबसे पहले जाँचें: `X-Frame-Options`
डेस्कटॉप और मोबाइल ऐप लॉगिन, भुगतान और रसीदों के लिए **iframes** का उपयोग करते हैं। `X-Frame-Options: DENY` या `SAMEORIGIN` भेजने वाला **कोई भी** सर्वर हेडर या प्लगइन लॉगिन रोक देगा। ऐप में लॉगिन विफल होने का यह सबसे आम कारण है — कुछ और करने से पहले लॉगिन पेज के प्रतिक्रिया हेडर जाँचें (ब्राउज़र डेवलपर टूल या `curl -I https://yourstore.com/wp-login.php` से)।
:::

<Accordion>
  <AccordionItem question="मेरे स्टोर से कनेक्ट नहीं हो पा रहा?">

  - सुनिश्चित करें कि आपकी WordPress साइट पर WCPOS प्लगइन इंस्टॉल और सक्रिय है
  - जाँचें कि आप सही URL इस्तेमाल कर रहे हैं (`https://` शामिल करें — WooCommerce REST API के लिए SSL आवश्यक है)
  - प्लगइन काम कर रहा है या नहीं, इसकी पुष्टि के लिए पहले वेब ब्राउज़र में `yourdomain.com/pos` खोलें
  - पुष्टि करें कि WooCommerce REST API तक पहुँच उपलब्ध है
  - जाँचें कि आपके उपयोगकर्ता खाते को POS एक्सेस की अनुमति है

  </AccordionItem>

  <AccordionItem question="डेस्कटॉप या मोबाइल ऐप में लॉगिन विफल होता है">

  ऐप में लॉगिन की अधिकांश विफलताएँ सुरक्षा या कैशिंग प्लगइन द्वारा लॉगिन iframe रोके जाने के कारण होती हैं:

  - **`X-Frame-Options` हेडर** (सुरक्षा प्लगइन या आपके सर्वर द्वारा सेट) लॉगिन iframe को रोकते हैं — ऊपर दिया नोट देखें। सुरक्षा प्लगइन को अस्थायी रूप से बंद करें, लॉग इन करें, फिर उसे दोबारा चालू करें (आपका सेशन लगभग एक सप्ताह तक रहता है)।
  - **सुरक्षा प्लगइन** — Wordfence, Really Simple Security, WPS Hide Login, iThemes/Solid Security और Defender Pro आम कारण हैं। पूरी सूची और समाधान [प्लगइन टकराव](/1.x/support/troubleshooting/plugin-conflicts#security-and-login-plugins) में देखें।
  - **Wordfence 2FA** — लॉगिन iframe में 2FA कोड फ़ील्ड रेंडर नहीं होती। फ़िलहाल POS उपयोगकर्ताओं के लिए 2FA बंद करें।
  - **कस्टम लॉगिन URL** (जैसे WPS Hide Login) — ऐप को लॉगिन पेज नहीं मिलता। मानक `/wp-admin/` URL इस्तेमाल करें।
  - **कैशिंग प्लगइन** समस्या पैदा करने वाला प्लगइन बंद करने के बाद भी अवरुद्ध लॉगिन फ़ॉर्म दिखा सकते हैं — कैश साफ़ करें, या ऐप का कैश साफ़ करें / डेस्कटॉप ऐप फिर इंस्टॉल करें।

  </AccordionItem>

  <AccordionItem question='कनेक्ट स्क्रीन पर “REST API के लिए प्रमाणीकरण आवश्यक है” या सुरक्षा प्लगइन की त्रुटि'>

  कोई प्लगइन (जैसे Force Login या JWT प्रमाणीकरण प्लगइन) सभी REST API अनुरोधों के लिए प्रमाणीकरण अनिवार्य कर रहा है, इसलिए ऐप आपकी साइट की सार्वजनिक जानकारी नहीं पढ़ पाता। साइट का प्रकार गलत बताने के बजाय ऐप अब सर्वर का वास्तविक संदेश दिखाता है (जैसे _"केवल प्रमाणित उपयोगकर्ता REST API तक पहुँच सकते हैं"_)।

  **समाधान:** सुरक्षा प्लगइन को इस तरह कॉन्फ़िगर करें कि बिना प्रमाणीकरण के `/wp-json/wcpos/` और `/wp-json/wc/v3/` तक पहुँच की अनुमति हो, या पहला कनेक्शन पूरा करने भर के लिए उसे बंद करें।

  </AccordionItem>

  <AccordionItem question='“यह WordPress साइट नहीं लगती” (डेस्कटॉप ऐप)'>

  डेस्कटॉप ऐप HTTP `Link` हेडर के ज़रिए REST API खोजता है। यदि कोई प्लगइन (अक्सर **Image Prioritizer** या अन्य प्रदर्शन प्लगइन) उस हेडर में बहुत अधिक डेटा भर दे या उसे काट दे, तो खोज विफल हो जाती है। **समाधान:** इमेज ऑप्टिमाइज़ेशन / हेडर बदलने वाले प्रदर्शन प्लगइन बंद करके फिर प्रयास करें।

  </AccordionItem>

  <AccordionItem question="ऐप अपडेट माँगता है / अपडेट के बाद क्रैश होता है">

  ऐप और सर्वर प्लगइन के संस्करणों में अंतर जाँचें — ऐप स्टोर ने ऐप का अपडेट जारी किया हो सकता है, जबकि WCPOS प्लगइन को अब भी अपडेट करना हो (या इसका उलटा)। v1.10 के लिए ऐप और WCPOS प्लगइन, दोनों **v1.10 रिलीज़ लाइन** पर होने चाहिए, क्योंकि ऐप प्लगइन का v2 सिंक API इस्तेमाल करता है। यदि केवल एक पक्ष अपडेट हुआ है और अनुरोध `rest_no_route` के साथ विफल होते हैं, तो दूसरे पक्ष को अपडेट करें।

  </AccordionItem>

  <AccordionItem question='“तेज़ स्टोर डेटाबेस नहीं बना सकते” त्रुटि'>

  यह पहली बार लॉगिन करते समय होने वाली रेस कंडीशन है। **ऐप को पूरी तरह बंद करें और फिर प्रयास करें** — आम तौर पर दूसरे प्रयास में सफलता मिल जाती है।

  </AccordionItem>

  <AccordionItem question="उपयोगकर्ता चयन स्क्रीन पर अटके हैं (डेस्कटॉप ऐप)">

  लॉग इन करने के बाद आपका उपयोगकर्ता नाम दिखता है, लेकिन आगे बढ़ने का कोई स्पष्ट तरीका नहीं दिखता। POS में प्रवेश करने के लिए **अपने उपयोगकर्ता नाम/नाम पर क्लिक करें** — नाम ही बटन है।

  </AccordionItem>

  <AccordionItem question="कनेक्शन बार-बार विफल हो रहा है?">

  - प्लगइन काम कर रहा है या नहीं, इसकी पुष्टि के लिए पहले वेब ब्राउज़र में `yourdomain.com/pos` खोलें
  - किसी समस्या का पता लगाने के लिए अपनी साइट के त्रुटि लॉग जाँचें
  - पुष्टि करें कि आपका होस्ट REST API को रोक नहीं रहा है — [होस्टिंग संबंधी विशेष नोट्स](/1.x/support/performance/server#hosting-specific-notes) देखें
  - सुनिश्चित करें कि आपका सर्वर [न्यूनतम आवश्यकताएँ](/1.x/support/performance/server#minimum-server-requirements) पूरी करता है

  </AccordionItem>
</Accordion>
