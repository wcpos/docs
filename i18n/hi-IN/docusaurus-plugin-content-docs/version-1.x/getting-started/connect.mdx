## कनेक्ट स्क्रीन का परिचय {#connect-screen-overview}

WCPOS डेस्कटॉप या मोबाइल ऐप खोलने पर कनेक्ट स्क्रीन दिखाई देती है। यहाँ आप अपने स्टोर कनेक्शन और उपयोगकर्ता लॉगिन प्रबंधित करते हैं।

{/* Screenshot: connect-screen.png */}

## नया स्टोर जोड़ना {#adding-a-new-store}

1. टेक्स्ट फ़ील्ड में अपने WooCommerce स्टोर का URL दर्ज करें (उदाहरण: `https://mystore.com`)
2. **कनेक्ट** पर क्लिक करें
3. आपको अपने WordPress क्रेडेंशियल से लॉग इन करने के लिए रीडायरेक्ट किया जाएगा
4. सफलतापूर्वक लॉग इन करने के बाद आप ऐप पर लौट आएँगे

## कई स्टोर {#multiple-stores}

आप जितने WooCommerce स्टोर चाहें, उनसे कनेक्ट कर सकते हैं। कनेक्ट स्क्रीन पर हर स्टोर एक अलग कार्ड के रूप में दिखता है, जिसमें ये जानकारी होती है:

- **स्टोर का नाम** और फ़ेविकॉन
- **स्टोर URL**
- उस स्टोर के लिए **लॉग इन किए हुए उपयोगकर्ता**

यह तब उपयोगी है जब आप कई स्थान या व्यवसाय प्रबंधित करते हैं।

## हर स्टोर के लिए कई उपयोगकर्ता {#multiple-users-per-store}

हर स्टोर में एक साथ कई उपयोगकर्ता लॉग इन रह सकते हैं। यह इन स्थितियों में उपयोगी है:

- **शिफ़्ट बदलना** - पिछला कैशियर लॉग आउट करने से पहले नया कैशियर लॉग इन कर सकता है
- **कई रजिस्टर सेटअप** - अलग-अलग कैशियर अलग-अलग डिवाइस पर
- **तेज़ी से स्विच करना** - उपयोगकर्ता खातों के बीच आसानी से स्विच करें

### उपयोगकर्ता जोड़ना {#adding-a-user}

उस स्टोर में एक और उपयोगकर्ता जोड़ने के लिए <Icon name="plus" /> "लॉग इन किए हुए उपयोगकर्ता" के पास वाले बटन पर क्लिक करें।

### उपयोगकर्ता बदलना {#switching-users}

उस उपयोगकर्ता के रूप में POS खोलने के लिए किसी उपयोगकर्ता बैज (उदाहरण: "Brenda") पर क्लिक करें।

### उपयोगकर्ता हटाना {#removing-a-user}

उस उपयोगकर्ता को स्टोर से लॉग आउट करने के लिए उसके बैज पर **×** क्लिक करें।

## स्टोर हटाना {#removing-a-store}

स्टोर को अपनी सूची से हटाने के लिए उसके कार्ड पर लाल **×** बटन क्लिक करें। इससे सभी उपयोगकर्ता लॉग आउट हो जाते हैं और ऐप से स्टोर कनेक्शन हट जाता है।

## डेमो स्टोर {#demo-store}

स्क्रीन के नीचे आपको "डेमो स्टोर में प्रवेश करें" लिंक दिख सकता है। इससे आप अपने स्टोर के डेटा को प्रभावित किए बिना WCPOS सुविधाएँ आज़माने के लिए डेमो WooCommerce स्टोर से कनेक्ट होते हैं।

## समस्या निवारण {#troubleshooting}

:::tip सबसे पहले जाँचें: `X-Frame-Options`
डेस्कटॉप और मोबाइल ऐप लॉगिन, पेमेंट और रसीदों के लिए **iframes** का उपयोग करते हैं। `X-Frame-Options: DENY` या `SAMEORIGIN` भेजने वाला **कोई भी** सर्वर हेडर या प्लगइन लॉगिन रोक देगा। ऐप लॉगिन विफल होने का यह सबसे आम कारण है — कुछ और करने से पहले लॉगिन पेज के प्रतिक्रिया हेडर जाँचें (ब्राउज़र डेवलपर टूल या `curl -I https://yourstore.com/wp-login.php`)।
:::

<Accordion>
  <AccordionItem question="मेरे स्टोर से कनेक्ट नहीं हो पा रहा?">

  - सुनिश्चित करें कि WCPOS प्लगइन आपके WordPress साइट पर इंस्टॉल और सक्रिय है
  - जाँचें कि आप सही URL इस्तेमाल कर रहे हैं (`https://` शामिल करें — WooCommerce REST API के लिए SSL आवश्यक है)
  - प्लगइन काम कर रहा है या नहीं, इसकी पुष्टि के लिए पहले वेब ब्राउज़र में `yourdomain.com/pos` खोलें
  - पुष्टि करें कि WooCommerce REST API उपलब्ध है
  - जाँचें कि आपके उपयोगकर्ता खाते को POS एक्सेस की अनुमति है

  </AccordionItem>

  <AccordionItem question="डेस्कटॉप या मोबाइल ऐप में लॉगिन विफल होता है">

  ऐप लॉगिन की अधिकांश विफलताएँ सुरक्षा या कैशिंग प्लगइन द्वारा लॉगिन iframe रोके जाने के कारण होती हैं:

  - **`X-Frame-Options` हेडर** (सुरक्षा प्लगइन या सर्वर द्वारा सेट) लॉगिन iframe को रोकते हैं — ऊपर दिया नोट देखें। सुरक्षा प्लगइन को अस्थायी रूप से बंद करें, लॉग इन करें, फिर उसे दोबारा चालू करें (आपका सेशन लगभग एक सप्ताह तक रहता है)।
  - **सुरक्षा प्लगइन** — Wordfence, Really Simple Security, WPS Hide Login, iThemes/Solid Security और Defender Pro आम कारण हैं। पूरी सूची और समाधान [प्लगइन टकराव](/support/troubleshooting/plugin-conflicts#security-and-login-plugins) में देखें।
  - **Wordfence 2FA** — लॉगिन iframe में 2FA कोड फ़ील्ड रेंडर नहीं होता। फिलहाल POS उपयोगकर्ताओं के लिए 2FA बंद करें।
  - **कस्टम लॉगिन URL** (जैसे WPS Hide Login) — ऐप को लॉगिन पेज नहीं मिलता। मानक `/wp-admin/` URL इस्तेमाल करें।
  - **कैशिंग प्लगइन** समस्या पैदा करने वाला प्लगइन बंद करने के बाद भी अवरुद्ध लॉगिन फ़ॉर्म दिखा सकते हैं — कैश साफ़ करें, या ऐप कैश साफ़ करें / डेस्कटॉप ऐप फिर इंस्टॉल करें।

  </AccordionItem>

  <AccordionItem question='कनेक्ट स्क्रीन पर "REST API requires authentication" या सुरक्षा प्लगइन की त्रुटि'>

  कोई प्लगइन (जैसे Force Login या JWT प्रमाणीकरण प्लगइन) सभी REST API अनुरोधों के लिए प्रमाणीकरण अनिवार्य कर रहा है, इसलिए ऐप आपकी साइट की सार्वजनिक जानकारी नहीं पढ़ पाता। साइट का प्रकार गलत बताने के बजाय ऐप अब सर्वर का वास्तविक संदेश दिखाता है (जैसे _"Only authenticated users can access the REST API"_)।

  **समाधान:** सुरक्षा प्लगइन को इस तरह कॉन्फ़िगर करें कि बिना प्रमाणीकरण के `/wp-json/wcpos/` और `/wp-json/wc/v3/` तक पहुँच की अनुमति हो, या पहले कनेक्शन को पूरा करने भर के लिए उसे बंद करें।

  </AccordionItem>

  <AccordionItem question='"Does not appear to be a WordPress site" (डेस्कटॉप ऐप)'>

  डेस्कटॉप ऐप HTTP `Link` हेडर के ज़रिए REST API खोजता है। यदि कोई प्लगइन (अक्सर **Image Prioritizer** या अन्य प्रदर्शन प्लगइन) उस हेडर में बहुत अधिक डेटा भर दे या उसे छोटा कर दे, तो खोज विफल होती है। **समाधान:** इमेज ऑप्टिमाइज़ेशन / हेडर बदलने वाले प्रदर्शन प्लगइन बंद करके फिर प्रयास करें।

  </AccordionItem>

  <AccordionItem question="ऐप अपडेट माँगता है / अपडेट के बाद क्रैश होता है">

  ऐप और सर्वर प्लगइन के संस्करण में अंतर जाँचें — ऐप स्टोर ने ऐप अपडेट जारी किया हो सकता है जबकि WCPOS प्लगइन को अब भी अपडेट करना हो (या इसका उलटा)। v1.10 के लिए ऐप और WCPOS प्लगइन, दोनों **v1.10 रिलीज़ लाइन** पर होने चाहिए, क्योंकि ऐप प्लगइन का v2 सिंक API इस्तेमाल करता है। यदि केवल एक पक्ष अपडेट हुआ और अनुरोध `rest_no_route` के साथ विफल होते हैं, तो दूसरे पक्ष को अपडेट करें।

  </AccordionItem>

  <AccordionItem question='"Cannot create fast store database" त्रुटि'>

  यह पहले लॉगिन के समय होने वाली रेस कंडीशन है। **ऐप पूरी तरह बंद करके फिर कोशिश करें** — आम तौर पर दूसरी कोशिश में सफल हो जाता है।

  </AccordionItem>

  <AccordionItem question="उपयोगकर्ता चयन स्क्रीन पर अटका है (डेस्कटॉप ऐप)">

  लॉग इन करने के बाद आपको अपना उपयोगकर्ता नाम दिखता है, लेकिन आगे बढ़ने का स्पष्ट तरीका नहीं दिखता। POS में जाने के लिए **अपने उपयोगकर्ता नाम/नाम पर क्लिक करें** — नाम ही बटन है।

  </AccordionItem>

  <AccordionItem question="कनेक्शन बार-बार विफल हो रहा है?">

  - प्लगइन काम कर रहा है या नहीं, इसकी पुष्टि के लिए पहले वेब ब्राउज़र में `yourdomain.com/pos` खोलकर देखें
  - समस्याओं के लिए अपनी साइट के त्रुटि लॉग जाँचें
  - पुष्टि करें कि आपका होस्ट REST API को ब्लॉक नहीं कर रहा है — [होस्टिंग-विशिष्ट नोट्स](/support/performance/server#hosting-specific-notes) देखें
  - सुनिश्चित करें कि आपका सर्वर [न्यूनतम आवश्यकताओं](/support/performance/server#minimum-server-requirements) को पूरा करता है

  </AccordionItem>
</Accordion>
