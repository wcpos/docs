## इसका क्या अर्थ है {#what-this-means}

स्टोर का सर्वर लॉगिन टोकन को हर उस माध्यम पर रोक रहा है जिसका यह ऐप उपयोग कर सकता है।

ऐप ने पुष्टि की कि स्टोर तक पहुँचा जा सकता है, लेकिन सर्वर (या उसके सामने मौजूद फ़ायरवॉल, प्रॉक्सी या सुरक्षा प्लगइन) Authorization हेडर हटा देता है और URL पैरामीटर के रूप में भेजे जाने पर भी टोकन को रोक देता है। लॉगिन टोकन पहुँचाने का कोई तीसरा तरीका नहीं है, इसलिए इसे सर्वर पर ठीक करना होगा।

## आपका डेटा {#your-data}

किसी भी ऑर्डर या उत्पाद का डेटा प्रभावित नहीं होता।

## समस्या निवारण {#troubleshoot}

**आपके होस्ट / सर्वर के लिए** — जब तक सर्वर लॉगिन टोकन को आगे नहीं जाने देता, तब तक उसे पहुँचाने का कोई माध्यम नहीं है:

1. Authorization हेडर को WordPress तक पहुँचने दें — Apache पर आम तौर पर इसके लिए एक पंक्ति पर्याप्त होती है: `SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1`।
2. यदि साइट `.htaccess` रीराइट का उपयोग करती है, तो WordPress द्वारा बनाई गई वह RewriteRule पंक्ति बनाए रखें जो `HTTP_AUTHORIZATION` को आगे भेजती है — सुरक्षा प्लगइन कभी-कभी इसे हटा देते हैं।
3. यदि सर्वर प्रॉक्सी या CDN के पीछे है, तो उसकी अनुमत हेडर सूची जाँचें: Authorization अनुरोध हेडर मूल सर्वर तक आगे भेजा जाना चाहिए।
4. यदि वेब एप्लिकेशन फ़ायरवॉल (WAF) URL पैरामीटर फ़िल्टर कर रहा है, तो `/wcpos/` REST रूट पर authorization पैरामीटर को अनुमति दें।
