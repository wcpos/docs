## इसका क्या मतलब है {#what-this-means}

होस्ट इस स्टोर के बिक्री काउंटरों के अनुरोधों की दर सीमित कर रहा है।

सर्वर लगातार 429 (बहुत अधिक अनुरोध) लौटा रहा है, जबकि ऐप पहले से अनुरोधों के बीच अंतर बढ़ा रहा है और सर्वर के Retry-After विलंब का पालन कर रहा है। एक इंटरनेट कनेक्शन पर कई बिक्री काउंटर एक ही पता साझा करते हैं, इसलिए स्रोत के अनुसार लागू दर सीमा उन्हें एक बहुत व्यस्त क्लाइंट मानती है। सिंक अपने आप चलता रहता है, लेकिन सीमा बढ़ने तक डेटा पीछे रहेगा।

## आपका डेटा {#your-data}

किसी ऑर्डर या उत्पाद का डेटा प्रभावित नहीं होता।

## समस्या निवारण {#troubleshoot}

1. होस्ट से स्टोर के अपने ट्रैफ़िक के लिए REST API की दर सीमा बढ़ाने या उससे छूट देने को कहें — यदि दुकान का स्थिर IP है, तो वह बताएँ।
2. जो सुरक्षा सेवाएँ बार-बार आने वाली त्रुटि प्रतिक्रियाओं (429) की गिनती करके ब्लॉक करती हैं (जैसे Sucuri का IDS), उनमें स्टोर के API को उस गिनती से बाहर रखना पड़ सकता है।
3. यदि कई बिक्री काउंटर एक कनेक्शन साझा करते हैं, तो होस्ट को बताएँ: यहाँ एक IP पूरी दुकान का है, किसी एक उपयोगकर्ता का नहीं।
