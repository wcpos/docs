Un'estensione è un plugin WordPress creato per WCPOS: un terminale di pagamento, un catalogo multilingue, credito del negozio, scorte per sede. Le trovi tutte in un'unica directory in WordPress, in **WP Admin > POS > Impostazioni > Estensioni**.

Per installare dalla directory basta un pulsante e servono **WCPOS Pro** e un amministratore WordPress. Senza Pro, [Polylang](./polylang.mdx), [WPML](./wpml.mdx) e [WP Multilang](./wp-multilang.mdx) si possono installare manualmente.

Vai a: [Installare un'estensione](#installing-an-extension) · [Installare senza Pro](#install-by-hand) · [Se qualcosa non funziona](#troubleshooting)

## Installare un'estensione {#installing-an-extension}

:::note Prima di iniziare
Per installare dalla directory servono **WCPOS Pro** e un amministratore WordPress: i gestori del negozio non possono installare plugin (vedi [Accesso](../settings/wp-admin/access.mdx)). Per la versione gratuita, vedi [Senza Pro](#install-by-hand).
:::

1. In WordPress, vai in **WP Admin > POS > Impostazioni** e scegli **Estensioni**.
2. Trova l'estensione. Digita in **Cerca estensioni...** (la ricerca considera nome, descrizione e tag) oppure scegli una scheda: **Tutte**, **Catalogo**, **Coupon**, **Inventario**, **Pagamenti**.
3. Premi **Installa** sulla relativa scheda. WCPOS la scarica, la installa e la attiva in un'unica operazione e abilita **Aggiornamento automatico**. La scheda ora indica **Attiva**.
4. Configura l'estensione. Se il menu **⋮** (**Altre azioni**) della scheda contiene **Impostazioni**, selezionalo. La pagina dell'estensione indicata sopra spiega cosa compilare.

<details>
<summary>Impostazioni non presente nel menu o modalità di accesso alternativa</summary>

- **Impostazioni** compare nel menu solo se la directory indica una pagina delle impostazioni per quell'estensione. In caso contrario, segui le istruzioni nella pagina dell'estensione.
- Con WCPOS Pro, lo stesso link **Impostazioni** si trova sotto il nome dell'estensione in **WP Admin > Plugin**.
- Per un'estensione di pagamento, **Impostazioni** apre la relativa pagina nelle impostazioni di pagamento di WooCommerce.

</details>

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[190, 0], [200, 0], [-36, 0], [-28, 0]]} alt="La schermata Estensioni in WordPress con WCPOS Pro: il menu delle impostazioni di WCPOS con Estensioni selezionato, un campo di ricerca e il pulsante Ricarica, le schede delle categorie Tutte, Catalogo, Coupon, Inventario e Pagamenti e una griglia di schede delle estensioni.">

1. **Estensioni** — nel menu delle impostazioni di WCPOS. Il numero accanto indica quante estensioni hanno un aggiornamento in attesa.
2. **Cerca estensioni...** — cerca nel nome, nella descrizione e nei tag.
3. **Ricarica** — verifica subito la disponibilità di nuove versioni nella directory.
4. **Schede delle categorie** — **Tutte** oppure una singola categoria.

</JourneyShot>

### Cosa mostra una scheda {#browsing-extensions}

Ogni estensione ha una scheda con icona, nome e descrizione. Se l'estensione non ha un'icona propria, viene mostrato un pezzo di puzzle. La scheda di un'estensione installata:

<JourneyShot manifest={manifest} device="desktop" step={2} maxWidth={432} offsets={[[-28, 0], [115, 0], [-30, 0], [0, -30], [-34, 0]]} alt="La scheda di PayPal Reader for WooCommerce, installato ma con stato Inattiva: versione 0.1.0 in Pagamenti, Aggiornamento automatico abilitato e un pulsante Attiva.">

1. **Stato** — **Attiva**, **Inattiva** (come in questo caso) o **Aggiornamento disponibile**.
2. **Versione** — la versione installata. Quando c'è un aggiornamento in attesa, indica **v0.5.9 → v0.5.10**. Rimanda alla release su GitHub. La categoria che segue è la scheda in cui si trova l'estensione.
3. **⋮ Altre azioni** — **Visualizza su GitHub** e **Impostazioni**, se l'estensione ha una pagina delle impostazioni.
4. **Aggiornamento automatico** — abilitato o disabilitato per questa estensione.
5. **Attiva** — il pulsante mostra l'azione successiva: **Attiva**, **Aggiorna** o entrambi quando è disponibile un aggiornamento per un'estensione disattivata. **Disattiva** compare accanto quando l'estensione è in esecuzione.

</JourneyShot>

### Senza Pro {#install-by-hand}

La versione gratuita elenca tutte le estensioni, ma **Installa** è disabilitato e accompagnato da **Richiede Pro per l'installazione**. Le tre estensioni multilingue, Polylang, WPML e WP Multilang, funzionano senza Pro, quindi puoi installarle manualmente:

1. Sulla scheda dell'estensione, apri **⋮** (**Altre azioni**) e scegli **Visualizza su GitHub**.
2. Scarica il file `.zip` allegato all'ultima release.
3. In **WP Admin > Plugin > Aggiungi un nuovo plugin**, premi **Carica plugin**, scegli il file zip e attiva il plugin.

La directory la mostra quindi come **Attiva** e come **Aggiornamento disponibile** quando esce una nuova release. Senza Pro non c'è il pulsante **Aggiorna**: carica il file zip della nuova release nello stesso modo e WordPress ti propone di sostituire la versione installata.

## Aggiornare, disattivare o attivare {#activating-and-deactivating}

Senza Pro, aggiorna le estensioni manualmente: vedi [Senza Pro](#install-by-hand).

Con WCPOS Pro, i pulsanti sulla scheda di un'estensione installata funzionano così:

- **Aggiorna** — installa la nuova versione. Un'estensione in esecuzione continua a funzionare.
- **Disattiva** — interrompe l'esecuzione dell'estensione senza rimuoverla. Le impostazioni e i file restano e **Attiva** la riavvia. **Attiva** abilita nuovamente **Aggiornamento automatico**.

### Aggiornamenti {#updating-extensions}

Quando esce una nuova versione, sulla scheda compare **v0.5.9 → v0.5.10** e lo stato di un'estensione in esecuzione diventa **Aggiornamento disponibile** (un'estensione disattivata resta **Inattiva**). Con WCPOS Pro compare anche il pulsante **Aggiorna** e WordPress mostra lo stesso aggiornamento nella schermata **Plugin**, quindi puoi aggiornarla da entrambe le posizioni. Nella versione gratuita, aggiorna manualmente: vedi [Senza Pro](#install-by-hand).

La directory verifica la disponibilità di nuove versioni una volta all'ora. Premi **Ricarica** accanto al campo di ricerca per verificare subito.

### Aggiornamenti automatici {#auto-updates}

**Aggiornamento automatico** è abilitato per ogni estensione che installi o attivi dalla directory. Quando è abilitato, WordPress installa le nuove versioni in background, come per qualsiasi plugin con gli aggiornamenti automatici abilitati. Disabilitalo sulla scheda se preferisci aggiornare manualmente, ad esempio per provare prima una nuova versione.

Una nuova versione che richiede una versione di WCPOS più recente di quella in uso sul sito non viene proposta né sulla scheda né tramite l'aggiornamento automatico. Aggiorna prima WCPOS Pro e l'aggiornamento dell'estensione comparirà.

### Rimuovere un'estensione {#removing-an-extension}

Per rimuovere definitivamente un'estensione, disattivala ed eliminala in **WP Admin > Plugin**, come qualsiasi altro plugin. Con WCPOS Pro puoi prima disattivarla dalla sua scheda.

## Se qualcosa non funziona {#troubleshooting}

**Installa è disabilitato e indica "Richiede Pro per l'installazione".** Stai usando la versione gratuita: per installare dalla directory serve [WCPOS Pro](../getting-started/pro-license.mdx). Le estensioni multilingue possono essere [installate manualmente](#install-by-hand).

**"Non hai i permessi per gestire i plugin."** Il tuo utente WordPress non può installare plugin. Rivolgiti a un amministratore.

**"… richiede WCPOS 2.1 o successivo; questo sito usa WCPOS 2.0. Aggiorna prima WCPOS Pro."** La versione proposta è più recente di quelle supportate dal tuo WCPOS. Aggiorna WCPOS Pro, poi riprova.

**"Impossibile ricaricare le estensioni. Riprova." o "Nessuna estensione trovata." senza aver effettuato una ricerca.** Il sito non è riuscito a recuperare l'elenco delle estensioni. L'elenco proviene da GitHub e alcuni provider di hosting impediscono ai siti di connettersi all'esterno. Riprova più tardi oppure chiedi al tuo provider di consentire le connessioni a GitHub.

**L'installazione non riesce e sulla scheda compare un errore.** WordPress non è riuscito a scaricare o decomprimere il plugin e il messaggio sulla scheda ne indica la causa. Chiedi al tuo provider di hosting di verificare che WordPress possa salvare file nella cartella dei plugin (`wp-content/plugins`) e connettersi a GitHub.

**La scheda indica Inattiva dopo aver premuto Installa.** WordPress ha installato l'estensione ma non è riuscito ad attivarla e questa non funzionerà finché non verrà attivata. Premi **Attiva**: se l'operazione non riesce, il messaggio sulla scheda ne indica la causa.

**Una nuova versione non compare.** La directory conserva l'elenco per un'ora. Premi **Ricarica**.

:::info Con WCPOS Pro
La versione gratuita mostra l'intera directory, ma i comandi **Installa**, **Attiva**, **Aggiorna**, **Disattiva** e **Aggiornamento automatico** sono disponibili con Pro. Vedi [Versione gratuita e Pro a confronto](../getting-started/free-vs-pro.mdx).
:::

## Per gli sviluppatori {#for-developers}

Per creare un'estensione o aggiungere la tua alla directory. Le informazioni che seguono non sono necessarie per gestire un negozio.

### Nomi degli hook {#hook-naming}

A partire da WCPOS 2.0, ogni hook eseguito da WCPOS ha un nome nella forma `wcpos_*`. I vecchi nomi `woocommerce_pos_*` sono deprecati: funzionano ancora e verranno rimossi non prima della versione 2.2.

<details>
<summary>Hook di Pro, avvisi di deprecazione e nomi che restano invariati</summary>

Gli hook di WCPOS Pro hanno nomi nella forma `wcpos_pro_*`. I vecchi nomi sono alias: vengono ancora eseguiti e registrano un avviso di deprecazione con `WP_DEBUG` quando vi è collegata una callback. Cambiano solo gli hook: opzioni, chiavi meta e capacità mantengono i loro nomi.

</details>

<details>
<summary>Hook eseguiti dal tuo codice e quando passare ai nuovi nomi</summary>

Quattro hook vengono eseguiti dal tuo codice e intercettati da WCPOS: `woocommerce_pos_invalidate` (estensioni), `woocommerce_pos_receipt_head` (template PHP delle ricevute salvati) e `woocommerce_pos_head` / `woocommerce_pos_footer` (sovrascrittura di `pos.php` da parte di un tema). WCPOS continua ad ascoltare questi nomi fino alla versione 2.2; passa a `wcpos_invalidate`, `wcpos_receipt_head`, `wcpos_head` e `wcpos_footer`.

Estensioni: passa ai nomi `wcpos_` nella tua prima release dopo la versione 2.0 e richiedi WCPOS 2.0 o successivo. Non collegare mai la callback a entrambi i nomi: nelle versioni 2.0 e 2.1 verrebbe eseguita due volte. Vedi [ADR 0041](https://github.com/wcpos/woocommerce-pos/blob/main/docs/adr/0041-wcpos-is-the-hook-prefix.md).

</details>

<h3 id="creating-a-pos-extension">Creare un'estensione per il POS</h3>

Un'estensione WCPOS è un normale plugin WordPress che usa gli hook e le API di WCPOS. Per un'estensione di pagamento, parti dal [Template per gateway di pagamento](../reference/gateway-template.mdx).

<h3 id="pos-screens">Aggiungere elementi alle schermate del POS</h3>

Attualmente un plugin non può aggiungere un proprio pannello o pulsante alle schermate del POS. Le schermate del carrello, dei prodotti e dei clienti mostrano solo ciò che è incluso nell'app. La cassa fa eccezione: un gateway di pagamento mostra la propria pagina di pagamento nella [scheda Legacy](../pos/checkout/legacy-tab.mdx) oppure, tramite due filtri, ottiene un proprio riquadro e propri campi nella scheda **Pagamenti**. Vedi [Dichiarare i campi per il pannello di pagamento](../reference/declaring-pos-fields.mdx).

<details>
<summary>Come fare in modo che la directory riconosca il plugin una volta installato</summary>

- **Nome della cartella** — la cartella del plugin deve corrispondere allo `slug` nel catalogo, ad esempio `my-extension/my-extension.php`. La directory identifica le estensioni installate tramite questa cartella e le installa al suo interno.
- **Text Domain o Plugin URI** — uno dei due deve corrispondere allo `slug` o al nome del repository GitHub. Senza una corrispondenza, gli aggiornamenti automatici e la schermata **Plugin** di WordPress non propongono le tue release. Questo controllo impedisce che un fork che riutilizza il nome della tua cartella le riceva.

</details>

<h3 id="submitting-to-the-directory">Proporre un'estensione per la directory</h3>

La directory legge `catalog.json` nel repository [`wcpos/extensions`](https://github.com/wcpos/extensions) su GitHub. Per aggiungere la tua estensione, apri lì una pull request che aggiunga una voce a `catalog.json` e un'icona in `icons/`, se ne hai una. Una volta integrata, i siti WCPOS la vedranno entro circa un'ora.

<details>
<summary>Tutti i campi di una voce del catalogo</summary>

| Campo | Contenuto |
|---|---|
| `slug` | Il nome della cartella del plugin. |
| `name`, `description`, `author` | Le informazioni mostrate sulla scheda. |
| `category` | La scheda in cui compare: `payments`, `catalog`, `coupons`, `inventory` o una nuova. |
| `tags` | Parole aggiuntive considerate dalla ricerca. |
| `homepage` | Il repository GitHub, `https://github.com/owner/repo`. Le release vengono lette da qui. |
| `icon` | URL di un'icona quadrata, solitamente il file aggiunto in `icons/`. In sua assenza, la scheda mostra un pezzo di puzzle. |
| `requires_wp`, `requires_wc`, `requires_wcpos` | Le versioni minime di WordPress, WooCommerce e WCPOS su cui funziona. Ai siti con una versione inferiore a `requires_wcpos` la release non viene mai proposta. |
| `requires_pro` | Indica se serve WCPOS Pro per il funzionamento. |
| `settings_url` | La pagina delle impostazioni, con percorso relativo a `wp-admin/`, ad esempio `admin.php?page=wc-settings&tab=checkout&section=my_gateway`. Fornisce il link **Impostazioni** nel menu della scheda. |

Lascia `version`, `latest_version`, `download_url` e `released_at` al catalogo: vengono compilati a partire dalle tue release.

</details>

<h3 id="github-release-conventions">Convenzioni per le release su GitHub</h3>

Pubblica una release definitiva su GitHub con la versione come tag e il file zip del plugin in allegato. Ogni ora il catalogo legge l'ultima release di ciascun repository elencato e ne aggiorna la voce.

<details>
<summary>Cosa serve a una release per raggiungere i siti WCPOS</summary>

- **Assegna un tag** con la versione, `v1.2.3`. La `v` iniziale viene rimossa dal numero di versione, che deve corrispondere a `Version` nell'intestazione del plugin.
- **Allega il file zip del plugin** con lo stesso nome dello slug, `my-extension.zip`. In assenza di quel nome, viene usato il primo `.zip` della release. WCPOS lo installa nella cartella `slug`, indipendentemente dal nome della cartella contenuta nel file zip.
- **Pubblicala come release definitiva.** Le bozze e le pre-release vengono ignorate, quindi una pre-release è un modo sicuro per condividere una build di prova.
- **Aumenta `requires_wcpos`** in `catalog.json` quando una release richiede una versione più recente di WCPOS, così i siti meno aggiornati non riceveranno una versione che non può avviarsi.

</details>

I siti vedono la nuova versione quando il loro elenco viene ricaricato: entro un'ora oppure subito con **Ricarica**. I siti con **Aggiornamento automatico** abilitato la installano in background.

Per provare un tuo catalogo prima di proporlo, configura un sito perché lo usi tramite il filtro `wcpos_extensions_catalog_url`.

</details>
