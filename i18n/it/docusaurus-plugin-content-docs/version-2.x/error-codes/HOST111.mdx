## Cosa significa {#what-this-means}

La configurazione tra origini diverse (CORS) del server è errata, quindi il browser rifiuta le sue risposte.

Il negozio risponde, ma le intestazioni CORS delle risposte sono errate: duplicate, impostate sull'origine sbagliata o assenti nelle risposte di errore. Il browser nasconde quindi la risposta effettiva all'app web, mascherando anche ogni altro errore dietro un generico errore di rete. La correzione va effettuata sul server: deve esserci esattamente una sola intestazione Access-Control-Allow-Origin, presente per ogni codice di stato.

## I tuoi dati {#your-data}

Nessun dato di ordini o prodotti è interessato.

## Risoluzione dei problemi {#troubleshoot}

1. Cerca un secondo livello CORS (un plugin E la configurazione del server che aggiungono entrambi intestazioni) ed eliminane uno: un'intestazione Access-Control-Allow-Origin duplicata provoca un errore irreversibile nel browser.
2. Su nginx, le direttive add_header non si applicano alle risposte di errore se non terminano con 'always': le intestazioni CORS devono essere presenti anche nelle risposte 4xx/5xx.
3. Se una CDN o un proxy aggiunge intestazioni CORS, assicurati che non siano in conflitto con quelle di WordPress.
4. Le app desktop e mobili non utilizzano CORS e continueranno a funzionare durante la risoluzione del problema.
