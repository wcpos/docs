## Cosa significa {#what-this-means}

Il server del negozio blocca il token di accesso su tutti i canali utilizzabili da questa app.

L'app ha confermato che il negozio è raggiungibile, ma il server (o un firewall, un proxy o un plugin di sicurezza che lo precede) rimuove l'intestazione Authorization e blocca anche il token quando viene inviato come parametro dell'URL. Non esiste un terzo modo per inviare un token di accesso, quindi il problema va risolto sul server.

## I tuoi dati {#your-data}

I dati degli ordini e dei prodotti non sono interessati.

## Risoluzione dei problemi {#troubleshoot}

**Per l'hosting / il server** — il token di accesso non ha alcun canale di invio finché il server non ne consente il passaggio:

1. Consenti all'intestazione Authorization di raggiungere WordPress; su Apache di solito basta una riga: `SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1`.
2. Se il sito usa regole di riscrittura in `.htaccess`, mantieni la riga RewriteRule generata da WordPress che trasmette `HTTP_AUTHORIZATION`: i plugin di sicurezza a volte la rimuovono.
3. Se il server è dietro un proxy o una CDN, controlla l'elenco delle intestazioni consentite: l'intestazione Authorization della richiesta deve essere inoltrata al server di origine.
4. Se un firewall per applicazioni web (WAF) filtra i parametri degli URL, consenti il parametro authorization sui percorsi REST `/wcpos/`.
