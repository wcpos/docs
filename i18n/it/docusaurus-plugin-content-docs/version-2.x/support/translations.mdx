**Non è un'impostazione:** come correggere o aggiungere una traduzione del POS, del plugin o di questa documentazione.

WCPOS viene tradotto dall'IA e una persona controlla ogni gruppo di traduzioni prima della pubblicazione. Chi usa WCPOS nella propria lingua nota ciò che sfugge alla macchina. Se una parola nel POS, nel plugin o in questa documentazione non suona bene, puoi correggerla: basta modificare una riga su GitHub e aprire una pull request. Non devi essere uno sviluppatore.

Vai a: [Correggere il POS o il plugin](#apps-and-plugin) · [Correggere questa documentazione](#docs) · [Aggiungere una lingua](#add-a-language)

## Visualizza nella tua lingua {#see-it}

Prima di modificare una parola, cercala nella schermata in cui viene usata. Il POS si apre nella lingua del tuo negozio, cioè la lingua del sito impostata in WordPress. Per provare un'altra lingua su un dispositivo, apri **Impostazioni** dal menu, poi **Generale**.

1. **Impostazioni** — vicino alla fine del menu.
2. **Generale** — la prima pagina delle Impostazioni.
3. **Lingua** — la lingua visualizzata dal POS su questo dispositivo. Toccala per aprire l'elenco. Vedi [Lingua](../settings/store/general.mdx#language).

</JourneyShot>

Digita nel campo di ricerca dell'elenco per trovare la tua lingua, poi toccala:

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[110, 0], [150, 0], [292, 0]]} maxWidth={700} alt="L'elenco Lingua aperto: Deutsch digitato nella ricerca, con Tedesco (Deutsch) e Tedesco (Svizzera) (Deutsch (Schweiz)) sotto">

1. **Cerca** — digita il nome di una lingua in inglese o nella lingua stessa: **Deutsch** trova il tedesco.
2. **Tedesco (Deutsch)** — tocca una lingua per selezionarla. Ogni lingua mostra il proprio nome dopo quello inglese.
3. **Tedesco (Svizzera)** — la variante regionale si trova accanto a quella principale. Scegli quella usata dal tuo negozio.

</JourneyShot>

La modifica vale solo per questo dispositivo. Il negozio e gli altri dispositivi mantengono la propria lingua. Per tornare alla lingua del negozio, premi **Ripristina impostazioni del server** in fondo alla stessa pagina: verranno ripristinati anche la valuta e il formato dei numeri inviati dal negozio. Le schermate del plugin in WP Admin seguono invece la tua lingua in WordPress.

## Correggi una parola nel POS o nel plugin {#apps-and-plugin}

Tutte le traduzioni delle app e del plugin si trovano in [wcpos/translations](https://github.com/wcpos/translations).

1. **Trova il file** per la tua lingua e per la parte di WCPOS che stai correggendo. Per il tedesco, il testo del POS si trova in [POS in tedesco: `core.json`](https://github.com/wcpos/translations/blob/main/translations/js/de_DE/monorepo/core.json) e il testo PHP del plugin in [Plugin in tedesco: `woocommerce-pos-de_DE.po`](https://github.com/wcpos/translations/blob/main/translations/php/de_DE/woocommerce-pos-de_DE.po). La sezione **Cosa contiene ogni file**, qui sotto, elenca tutte le cartelle.
2. **Trova le parole.** Cerca nel file le parole che hai visto sullo schermo: premi Ctrl+F, oppure ⌘F su un Mac. In un file JSON la traduzione segue la sua chiave. In un file PO è nella riga `msgstr` sotto il `msgid` in inglese. Verifica che la chiave o il testo inglese corrispondano al punto in cui hai visto la parola.
3. **Modifica solo il testo tradotto.** Lascia la chiave, il `msgid` e tutti i segnaposto come `{name}`, `%s`, `%d` o `<strong>` esattamente come sono.

   In un file JSON, ogni voce è composta da una chiave, due punti e la traduzione. Qui il testo inglese è `Delete {name}` e il tedesco mette il verbo alla fine:

   ```json title="Before"
   "coupons.delete":
     "Löschen {name}",
   ```

   ```json title="After"
   "coupons.delete":
     "{name} löschen",
   ```

   Sono cambiate solo le parole in tedesco. La chiave, `"coupons.delete"`, e `{name}` rimangono invariati.

   In un file PO, `msgid` è il testo inglese e `msgstr` è quello nella tua lingua:

   ```text
   msgid "Copy of %s"
   msgstr "Kopie von %s"
   ```

   Modifica solo le parole nella riga `msgstr`. Lascia invariati la riga `msgid` e `%s`.

4. **Invia una pull request.** Vedi [Invia la tua correzione su GitHub](#send).

<details>
<summary>Cosa contiene ogni file</summary>

| Cartella | Contenuto |
|---|---|
| `source/` | Il testo inglese, raccolto automaticamente. Non modificarlo. |
| `translations/js/<locale>/monorepo/` | Il POS usato dal cassiere: pulsanti, carrello, cassa, finestre di dialogo, errori. |
| `translations/js/<locale>/electron/` | La finestra e i menu dell'app desktop, per Windows e macOS. |
| `translations/js/<locale>/woocommerce-pos/` | Le schermate del plugin gratuito in WP Admin, come Impostazioni e Template, un file per schermata. |
| `translations/js/<locale>/woocommerce-pos-pro/` | Le schermate del plugin Pro in WP Admin, come l'editor dei negozi e le impostazioni Pro. |
| `translations/php/<locale>/` | Il testo PHP del plugin. Modifica il file `.po` soltanto. I file `.mo` e `.l10n.php` accanto ad esso vengono rigenerati a partire da questo file dagli script del repository, quindi un controllo sulla tua pull request potrebbe segnalare che il file `.mo` non è aggiornato. Indica nella pull request che hai modificato il file `.po` soltanto. |

Molte lingue hanno una cartella di base e cartelle regionali, come `de` e `de_DE`, `de_AT`. Il POS legge la cartella regionale a cui punta la lingua: Tedesco (Deutsch) legge `de_DE`. A ogni rilascio, le cartelle di base `de`, `en`, `es`, `fr`, `nl`, `pt` e `zh` vengono copiate dalla rispettiva cartella regionale principale (`de` da `de_DE`), quindi apporta la correzione nella cartella regionale: una modifica fatta solo in una cartella di base viene sovrascritta.

</details>

Se la tua lingua non è presente, vedi [Aggiungi una lingua](#add-a-language).

## Correggi una pagina di questa documentazione {#docs}

Ogni lingua ha una propria copia di ciascuna pagina in [wcpos/docs](https://github.com/wcpos/docs).

1. **Trova il file.** **Modifica questa pagina**, in fondo alla pagina, apre il file inglese su GitHub. Nel percorso, sostituisci `versioned_docs/` con `i18n/<locale>/docusaurus-plugin-content-docs/`, usando il tuo [codice lingua](#locale-codes) al posto di `<locale>`: `de` per il tedesco. Il resto del percorso rimane invariato, come nella [versione 1.x in tedesco di questa pagina](https://github.com/wcpos/docs/blob/main/i18n/de/docusaurus-plugin-content-docs/version-1.x/support/translations.mdx).

   <details>
   <summary>Trova un'altra pagina o lingua</summary>

   Questa documentazione usa Docusaurus. Le pagine inglesi si trovano in `versioned_docs/`, in una cartella per ogni versione. Ogni lingua ha una propria copia in `i18n/<locale>/docusaurus-plugin-content-docs/`, in una cartella per la stessa versione, con lo stesso percorso della pagina inglese. I codici sono elencati in [Codici lingua](#locale-codes).

   Per il francese, il file inglese `versioned_docs/version-2.x/support/translations.mdx` diventa `i18n/fr/docusaurus-plugin-content-docs/version-2.x/support/translations.mdx`. Sfoglia la [cartella francese](https://github.com/wcpos/docs/tree/main/i18n/fr/docusaurus-plugin-content-docs) per vedere cosa contiene.

   </details>

2. **Modifica le parole.** Mantieni invariati la sintassi Markdown e MDX, i link, il codice e le chiavi del frontmatter. Traduci il testo, i titoli e le etichette visibili al lettore.
3. **Invia una pull request.** Modifica solo il file in `i18n/<locale>/`, mai la pagina inglese. Vedi [Invia la tua correzione su GitHub](#send).

Per interventi più ampi, un'intera sezione o una nuova lingua, apri prima una issue per poterli pianificare insieme.

## Invia la tua correzione su GitHub {#send}

Ti serve un account GitHub gratuito. Non devi installare nulla: fai tutto dal browser.

1. **Accedi a GitHub** e apri il file che vuoi correggere.
2. **Premi la matita**, **Modifica questo file**, in alto a destra nel file. La prima volta, GitHub ti chiede di creare un fork del repository: premi **Crea un fork di questo repository**. Avrai così una tua copia da modificare.
3. **Apporta la modifica** nell'editor.
4. **Premi Esegui il commit delle modifiche…** sopra l'editor. Si apre una finestra.
5. **Descrivi la correzione** in una riga nel campo del messaggio della finestra, poi premi **Proponi modifiche**.
6. **Premi Crea pull request** nella pagina successiva, poi di nuovo **Crea pull request** per inviarla.

Un revisore controlla la modifica e la integra, oppure ti fa delle domande nella pull request.

## Come una correzione arriva agli utenti {#how-it-works}

Una persona controlla ogni modifica prima della pubblicazione. Una correzione a questa documentazione viene pubblicata con il sito dopo essere stata integrata. Una correzione al POS, all'app desktop o al plugin arriva agli utenti con il successivo aggiornamento.

<details>
<summary>L'intero percorso, passo dopo passo</summary>

1. **Il testo inglese viene raccolto.** Quando le app o il plugin cambiano, le loro stringhe inglesi vengono inviate al repository [wcpos/translations](https://github.com/wcpos/translations). Questa documentazione conserva le proprie in [wcpos/docs](https://github.com/wcpos/docs).
2. **L'IA completa ciò che manca**, in ogni lingua. Segue una serie di regole e un glossario per ciascuna lingua. Una traduzione che danneggia un segnaposto o il markup, oppure usa il vecchio nome esteso del prodotto, viene rifiutata e ritentata in seguito.
3. **Una persona esamina il gruppo di traduzioni** sotto forma di pull request e lo integra.
4. **La correzione viene distribuita.** Per questa documentazione, il sito viene ricostruito a partire dalle pagine integrate e pubblicato. Per le app e il plugin, l'integrazione genera un nuovo rilascio delle traduzioni. Il POS, l'app desktop e il plugin usano ciascuno un rilascio specifico, quindi ricevono la correzione con il successivo aggiornamento. Una correzione a un file `.po` richiede anche che venga prima rigenerato il relativo file `.l10n.php`, quindi può richiedere più tempo.

Per le app e il plugin, un controllo giornaliero apre anche una issue su [wcpos/translations](https://github.com/wcpos/translations/issues) se manca ancora qualcosa.

</details>

Quindi raramente partirai da un file vuoto. Di solito si tratta di una traduzione già presente che non suona bene: una frase poco naturale, un termine diverso da quello usato da WooCommerce nella tua lingua, un'etichetta troppo lunga per il pulsante.

:::note Non su translate.wordpress.org
WCPOS non accetta più traduzioni tramite translate.wordpress.org. La piattaforma non consente la traduzione automatica, quindi la maggior parte delle lingue non è mai stata completata lì. Il plugin scarica le proprie traduzioni da wcpos/translations. Se hai già tradotto WCPOS su quella piattaforma, grazie: ora le correzioni vanno inviate alle destinazioni indicate in questa pagina.
:::

## Aggiungi una lingua {#add-a-language}

Le app e il plugin supportano più di 50 lingue e varianti regionali, elencate in [`locales.json`](https://github.com/wcpos/translations/blob/main/locales.json). Questa documentazione ne supporta meno, elencate qui sotto. Se la tua manca, apri una issue nel repository che ti interessa e la aggiungeremo. L'IA completa rapidamente una nuova lingua. Da lì in poi, chi la parla rende il testo naturale.

| `pt-BR` | Portoghese (Brasile) |

I due repository scrivono i codici in modo diverso. wcpos/translations usa il trattino basso, `de_DE`, `pt_BR`, `zh_CN`, e ha sia lingue di base (`de`, `fr`, `es`) sia varianti regionali (`de_AT`, `fr_CA`, `es_MX`). Questa documentazione usa il trattino, `pt-BR`, `hi-IN`, `zh-CN`. Usa il formato del repository che stai modificando.

</details>

## Cosa controlla un revisore {#translator-tips}

Queste sono le regole seguite dall'IA, quindi anche il revisore verifica che la tua modifica le rispetti.

- **I segnaposto rimangono esattamente come sono.** `{name}`, `%s`, `%d` e tag come `<strong>` vengono compilati o visualizzati da WCPOS. Traduci il testo che li circonda.
- **I nomi dei prodotti rimangono in inglese.** `WCPOS`, `WCPOS Pro`, `WooCommerce` e `WordPress` non si traducono mai, così come gli altri nomi di marchi e piattaforme, quali Stripe, PayPal, Square, Android, iOS, macOS e Windows. Scrivi **WCPOS** nel testo visibile agli utenti. Il vecchio nome esteso va usato solo negli slug, nei nomi dei file e negli indirizzi web.
- **La terminologia di WooCommerce ha la precedenza.** I proprietari dei negozi vedono WCPOS accanto a WooCommerce, quindi un termine usato anche da WooCommerce, come coupon, rimborso, imposta o metodo di pagamento, deve corrispondere alla traduzione di WooCommerce nella tua lingua. Per i termini che WooCommerce non usa, come cassiere, registratore di cassa o cassetto contanti, usa il termine nel glossario della tua lingua, `scripts/translation-glossary.json`.
- **Mantieni una lunghezza simile all'inglese.** Un pulsante di una parola deve rimanere di una o due parole. Le schermate del POS hanno poco spazio.
- **Il registro formale o informale segue le note della tua lingua.** Alcune lingue hanno note specifiche in `scripts/locale-context/` in wcpos/translations, con indicazioni sul registro, sul separatore decimale e sugli errori più comuni. Il tedesco usa **Sie**, per esempio.
- **Il codice rimane invariato.** I codici coupon, gli ID dei gateway di pagamento, i codici lingua, i percorsi dei file e gli shortcode non si traducono mai. Se hai dubbi, lascia il testo in inglese. C'è un'eccezione in questa documentazione: un percorso di menu formattato come codice, come `WP Admin > WooCommerce > Impostazioni > Pagamenti`, usa i nomi dei menu mostrati da WordPress e WooCommerce nella tua lingua. Mantieni i simboli `>` e le parole WP Admin, WooCommerce e WCPOS.
- **Controlla sullo schermo.** Una frase che entra in una schermata può andare a capo in un'altra. Vedi [Visualizza nella tua lingua](#see-it).

Per una lingua che si scrive da destra a sinistra, come arabo, ebraico, persiano o urdu, anche le ricevute richiedono un template da destra a sinistra. Li trovi nella galleria: vedi [Personalizza la tua ricevuta](../receipts/customise.mdx#the-bundled-templates) e [Ricevute con caratteri non latini](../hardware/printers/non-latin-receipts.mdx).
