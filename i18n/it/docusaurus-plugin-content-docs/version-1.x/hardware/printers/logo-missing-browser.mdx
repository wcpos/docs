**Sintomo:** le ricevute stampate da una scheda del browser escono complete tranne il logo del negozio. La stessa ricevuta stampata dall'app desktop o mobile riporta il logo normalmente.

## Perché succede {#why-it-happens}

Il logo si trova nella libreria multimediale di WordPress e il browser lo preleva da lì. Prima che una pagina web possa leggere i pixel di un'immagine caricata da un altro indirizzo, il server che la ospita deve autorizzarlo con un'intestazione chiamata `Access-Control-Allow-Origin`. WordPress non invia quell'intestazione sui file caricati per impostazione predefinita, quindi il browser passa l'immagine per visualizzarla ma non per stamparla.

L'app non può aggirare il problema: stampa la ricevuta senza logo invece di far fallire la vendita. Le app desktop e mobile scaricano il file da sole e non sono soggette a questa regola.

## Cosa fare {#do-this}

Scegli la soluzione più adatta al negozio:

- **Stampa dall'app desktop.** Non c'è niente da configurare ed è la risposta più rapida se la cassa l'ha già installata.
- **Autorizza l'intestazione sul tuo sito.** Chi gestisce il sito aggiunge `Access-Control-Allow-Origin` per la cartella dei caricamenti, nella configurazione del server web o con un plugin che imposta le intestazioni CORS. Poi ricarica il POS e stampa di nuovo.

## Se il logo esce come disturbo {#if-the-logo-prints-as-noise}

Una banda di puntini casuali al posto del logo è un problema diverso: alcune stampanti vecchie o economiche non riescono a decodificare il formato immagine usato. Rimuovi il logo dal modello di ricevuta di quella stampante.

## Ancora bloccato? {#still-stuck}

Usa **Copia il report di configurazione** nella schermata di problema e incollalo nel tuo messaggio, insieme all'indirizzo dell'immagine del logo.
