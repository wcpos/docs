:::note Solo desktop e dispositivi mobili
Questa schermata viene mostrata solo nelle app desktop e per dispositivi mobili. Gli utenti web accedono direttamente al POS da `yourdomain.com/pos` con le proprie credenziali WordPress.
:::

## Panoramica della schermata Connetti {#connect-screen-overview}

Quando apri l'app WCPOS desktop o per dispositivi mobili, viene visualizzata la schermata Connetti. Da qui puoi gestire le connessioni ai negozi e gli accessi degli utenti.

{/* Screenshot: connect-screen.png */}

## Aggiunta di un nuovo negozio {#adding-a-new-store}

1. Inserisci l'URL del tuo negozio WooCommerce nel campo di testo (ad es. `https://mystore.com`)
2. Fai clic su **Connetti**
3. Verrai reindirizzato alla schermata di accesso con le tue credenziali WordPress
4. Dopo aver effettuato l'accesso, tornerai all'app

## Più negozi {#multiple-stores}

Puoi connetterti a tutti i negozi WooCommerce di cui hai bisogno. Ogni negozio appare come scheda separata nella schermata Connetti e mostra:

- **Nome del negozio** e favicon
- **URL del negozio**
- **Utenti connessi** a quel negozio

È utile se gestisci più punti vendita o attività.

## Più utenti per negozio {#multiple-users-per-store}

Più utenti possono essere connessi contemporaneamente a ciascun negozio. È utile per:

- **Cambi turno** - Il nuovo cassiere può accedere prima che quello precedente esca
- **Configurazioni con più registratori di cassa** - Cassieri diversi su dispositivi diversi
- **Cambio rapido** - Passa facilmente da un account utente all'altro

### Aggiunta di un utente {#adding-a-user}

Fai clic sul <Icon name="plus" /> pulsante accanto a "Utenti connessi" per aggiungere un altro utente a quel negozio.

### Cambio utente {#switching-users}

Fai clic sul badge di un utente (ad es. "Brenda") per aprire il POS con quell'utente.

### Rimozione di un utente {#removing-a-user}

Fai clic su **×** sul badge dell'utente per disconnetterlo dal negozio.

## Rimozione di un negozio {#removing-a-store}

Fai clic sul pulsante rosso **×** nella scheda del negozio per rimuoverlo dall'elenco. Verranno disconnessi tutti gli utenti e rimossa la connessione al negozio dall'app.

## Negozio demo {#demo-store}

In fondo alla schermata potresti vedere il link "Accedi al negozio demo". Ti connette a un negozio WooCommerce dimostrativo per provare le funzionalità di WCPOS senza influire sui dati del tuo negozio.

## Risoluzione dei problemi {#troubleshooting}

:::tip Prima cosa da controllare: `X-Frame-Options`
Le app desktop e per dispositivi mobili usano **iframe** per l'accesso, i pagamenti e le ricevute. **Qualsiasi** intestazione del server o plugin che invii `X-Frame-Options: DENY` o `SAMEORIGIN` impedirà l'accesso. È la causa più comune dei problemi di accesso all'app: prima di tutto controlla le intestazioni di risposta della pagina di accesso (strumenti di sviluppo del browser oppure `curl -I https://yourstore.com/wp-login.php`).
:::

<Accordion>
  <AccordionItem question="Non riesci a connetterti al negozio?">

  - Verifica che il plugin WCPOS sia installato e attivato sul tuo sito WordPress
  - Controlla di usare l'URL corretto (includi `https://`: l'API REST di WooCommerce richiede SSL)
  - Prova prima ad aprire `yourdomain.com/pos` in un browser web per verificare che il plugin funzioni
  - Verifica che l'API REST di WooCommerce sia accessibile
  - Controlla che il tuo account utente disponga delle autorizzazioni di accesso al POS

  </AccordionItem>

  <AccordionItem question="L'accesso non riesce nell'app desktop o per dispositivi mobili">

  La maggior parte dei problemi di accesso all'app è causata da un plugin di sicurezza o di cache che blocca l'iframe di accesso:

  - Le **intestazioni `X-Frame-Options`** (impostate da un plugin di sicurezza o dal server) bloccano l'iframe di accesso: vedi la nota sopra. Disattiva temporaneamente il plugin di sicurezza, accedi e poi riattivalo (la sessione dura circa una settimana).
  - I **plugin di sicurezza** — Wordfence, Really Simple Security, WPS Hide Login, iThemes/Solid Security e Defender Pro — sono tra le cause più comuni. Consulta l'elenco completo e le soluzioni in [Conflitti tra plugin](/support/troubleshooting/plugin-conflicts#security-and-login-plugins).
  - **Wordfence 2FA** — il campo del codice 2FA non viene visualizzato nell'iframe di accesso. Per ora, disattiva la 2FA per gli utenti POS.
  - **URL di accesso personalizzato** (ad es. WPS Hide Login) — l'app non riesce a trovare la pagina di accesso. Usa l'URL standard `/wp-admin/`.
  - I **plugin di cache** possono continuare a mostrare il modulo di accesso bloccato anche dopo aver disattivato il plugin responsabile: svuota la cache oppure svuota la cache dell'app / reinstalla l'app desktop.

  </AccordionItem>

  <AccordionItem question='«L&#39;API REST richiede l&#39;autenticazione» oppure un errore di un plugin di sicurezza nella schermata di connessione'>

  Un plugin (ad es. Force Login o un plugin di autenticazione JWT) richiede l'autenticazione per tutte le richieste API REST, quindi l'app non riesce a leggere le informazioni pubbliche del tuo sito. Ora l'app mostra il messaggio effettivo del server (ad es. _"Solo gli utenti autenticati possono accedere all'API REST"_) invece di indicare un tipo di sito errato.

  **Soluzione:** configura il plugin di sicurezza per consentire l'accesso non autenticato a `/wp-json/wcpos/` e `/wp-json/wc/v3/`, oppure disattivalo solo per il tempo necessario a completare la prima connessione.

  </AccordionItem>

  <AccordionItem question='«Non sembra essere un sito WordPress» (app desktop)'>

  L'app desktop individua l'API REST tramite l'intestazione HTTP `Link`. Se un plugin (spesso **Image Prioritizer** o altri plugin per le prestazioni) sovraccarica o tronca questa intestazione, l'individuazione non riesce. **Soluzione:** disattiva i plugin di ottimizzazione delle immagini o delle prestazioni che modificano le intestazioni, quindi riprova.

  </AccordionItem>

  <AccordionItem question="L'app segnala che è necessario un aggiornamento / si arresta in modo anomalo dopo un aggiornamento">

  Verifica che non ci sia una discrepanza di versione tra l'app e il plugin sul server: lo store delle app potrebbe aver distribuito un aggiornamento dell'app mentre il plugin WCPOS deve ancora essere aggiornato (o viceversa). Per la v1.10, sia l'app sia il plugin WCPOS devono appartenere alla **linea di rilascio v1.10**, perché l'app usa l'API di sincronizzazione v2 del plugin. Se è stato aggiornato un solo componente e le richieste restituiscono `rest_no_route`, aggiorna anche l'altro.

  </AccordionItem>

  <AccordionItem question='Errore «Impossibile creare il database rapido del negozio»'>

  Si tratta di una condizione di competizione al primo accesso. **Chiudi completamente l'app e riprova**: di solito il secondo tentativo riesce.

  </AccordionItem>

  <AccordionItem question="Bloccato nella schermata di selezione dell'utente (app desktop)">

  Dopo aver effettuato l'accesso, vedi il tuo nome utente ma non è chiaro come proseguire. **Fai clic sul tuo nome utente/nome** per entrare nel POS: il nome stesso è il pulsante.

  </AccordionItem>

  <AccordionItem question="La connessione continua a non riuscire?">

  - Prova prima ad aprire `yourdomain.com/pos` in un browser web per verificare che il plugin funzioni
  - Controlla i log degli errori del tuo sito per individuare eventuali problemi
  - Conferma che il tuo host non blocchi la REST API: consulta le [note specifiche per hosting](/support/performance/server#hosting-specific-notes)
  - Assicurati che il server soddisfi i [requisiti minimi](/support/performance/server#minimum-server-requirements)

  </AccordionItem>
</Accordion>
