I conflitti tra plugin sono una delle cause più comuni di problemi con WCPOS. Quando altri plugin di WordPress interferiscono con le funzionalità di WooCommerce o WCPOS, potresti riscontrare arresti anomali, problemi di prestazioni o comportamenti imprevisti.

## Segnali di conflitti tra plugin {#signs-of-plugin-conflicts}

Potrebbe esserci un conflitto tra plugin se riscontri:

- **Errori fatali** - "Si è verificato un errore critico sul tuo sito web"
- **Problemi di prestazioni** - Caricamento lento, timeout o carico elevato del server
- **Problemi di funzionalità** - Funzionalità che non operano come previsto
- **Problemi di sincronizzazione dei dati** - Prodotti, ordini o clienti che non si sincronizzano correttamente
- **Problemi con i gateway di pagamento** - Errori al checkout o durante l'elaborazione dei pagamenti

## Prima di iniziare: usa un sito di staging {#before-you-start-use-a-staging-site}

:::warning Importante
**Non eseguire mai la diagnosi dei conflitti tra plugin sul sito in produzione.** Usa sempre un ambiente di staging per evitare di interrompere le attività del negozio.
:::

### Cos'è un sito di staging? {#what-is-a-staging-site}

Un sito di staging è una copia esatta del sito in produzione in cui puoi provare le modifiche in sicurezza senza ripercussioni sui clienti. La maggior parte dei moderni fornitori di hosting offre ambienti di staging come funzionalità standard.

### Se il tuo hosting non offre lo staging {#if-your-host-doesnt-offer-staging}

Se il tuo fornitore di hosting non offre siti di staging, **valuta il passaggio a un fornitore che li offra**. Oggi è una funzionalità standard ed è essenziale per:

- Testare plugin e temi in sicurezza
- Aggiornare WordPress
- Risolvere i problemi
- Svolgere attività di sviluppo

**Hosting consigliati con staging:**
- WP Engine
- SiteGround  
- Kinsta
- Cloudways
- Molti altri

## Passo 1: controlla gli errori fatali {#step-1-check-for-fatal-errors}

Se riscontri arresti anomali o errori critici, inizia controllando i log degli errori:

1. **Controlla i log di WCPOS** - Apri [**Stato del negozio → Log**](/1.x/support/logs) in WCPOS e cerca eventuali messaggi di errore
2. **Controlla i log degli errori fatali** - Segui la [guida alla risoluzione degli errori critici](/1.x/support/troubleshooting/critical-error) per trovare messaggi di errore dettagliati
3. **Annota i dettagli dell'errore** - Cerca nomi di plugin o percorsi di file menzionati nell'errore

Se trovi un errore fatale che menziona un plugin specifico, probabilmente è quello la causa. Puoi disattivarlo e verificare se il problema si risolve.

## Passo 2: il metodo di esclusione dei plugin {#step-2-the-plugin-elimination-method}

Se nei log non ci sono errori fatali, o vuoi individuare conflitti che influiscono sulle prestazioni, usa questo approccio sistematico:

### 2.1 Stabilisci una situazione di riferimento {#21-create-a-baseline}

1. **Accedi al tuo sito di staging**
2. **Prova la funzionalità problematica** - Annota esattamente cosa non funziona o è lento
3. **Registra le metriche delle prestazioni** - Se il problema riguarda le prestazioni, annota i tempi di esecuzione riportati nei [log](/1.x/support/logs)

### 2.2 Disattiva tutti i plugin (tranne quelli essenziali) {#22-disable-all-plugins-except-essential-ones}

**Mantieni attivi questi plugin:**
- WooCommerce
- WCPOS
- WCPOS Pro (se lo possiedi)

**Disattiva tutto il resto:**
1. Vai a `WP Admin > Plugin`
2. Seleziona tutti gli altri plugin
3. Scegli "Disattiva" dal menu a discesa delle azioni di gruppo
4. Fai clic su "Applica"

### 2.3 Verifica il problema {#23-test-the-issue}

1. **Svuota le cache** - Se usi plugin di caching, svuota tutte le cache
2. **Prova la funzionalità problematica** - Ora funziona?
3. **Controlla le prestazioni** - I tempi di esecuzione sono migliorati?

**Se il problema è risolto:** c'è un conflitto tra plugin. Procedi al passo 2.4.

**Se il problema persiste:** probabilmente non si tratta di un conflitto tra plugin. Considera:
- Problemi con le risorse del server (consulta [Prestazioni del server](/1.x/support/performance/server))
- Conflitti del tema (vedi il passo 3)
- Problemi del core di WordPress/WooCommerce

### 2.4 Attiva i plugin uno alla volta {#24-enable-plugins-one-by-one}

Ora devi individuare il plugin che causa il conflitto:

1. **Attiva un plugin** - Inizia da quelli più essenziali
2. **Prova la funzionalità** - Verifica se il problema si ripresenta
3. **Se non ci sono problemi** - Attiva il plugin successivo e ripeti la prova
4. **Se il problema si ripresenta** - Hai trovato il plugin in conflitto!

**Ordine di priorità dei plugin (attivali in questo ordine):**
1. **Plugin di sicurezza** - Wordfence, Sucuri, ecc.
2. **Plugin SEO** - Yoast, RankMath, ecc.  
3. **Plugin per le prestazioni** - Caching, ottimizzazione
4. **Gateway di pagamento** - Stripe, PayPal, ecc.
5. **Altre estensioni di WooCommerce**
6. **Plugin generici di WordPress**

### 2.5 Documenta i risultati {#25-document-your-findings}

Quando individui il plugin in conflitto:

1. **Annota il nome e la versione del plugin**
2. **Documenta il problema specifico che causa**
3. **Verifica se è disponibile una versione aggiornata**
4. **Cerca plugin alternativi che offrano funzionalità simili**

## Passo 3: verifica i conflitti del tema {#step-3-check-for-theme-conflicts}

Anche se i temi influiscono raramente su WCPOS (che usa una propria interfaccia), a volte possono causare problemi con:

- Procedure di checkout (se usi il gateway di checkout web)
- Funzionalità dell'area di amministrazione
- Risposte API

### Prova con un tema predefinito {#test-with-a-default-theme}

1. **Sul tuo sito di staging**, passa a un tema predefinito di WordPress:
   - Twenty Twenty-Four
   - Twenty Twenty-Three
   - Twenty Twenty-Two
2. **Prova la funzionalità problematica**
3. **Se il problema è risolto** - Il tuo tema causa un conflitto

:::info Impatto del tema
È molto meno probabile che i temi causino problemi a WCPOS rispetto ai plugin. L'interfaccia POS funziona indipendentemente dal tema. Tuttavia, i temi possono influire su:
- Pagine di checkout di WooCommerce
- Funzionalità di amministrazione di WordPress
- Risposte dell'API REST
:::

## Passo 4: risolvi i conflitti tra plugin {#step-4-resolving-plugin-conflicts}

Una volta individuato il plugin in conflitto, hai diverse opzioni:

### Opzione 1: aggiorna il plugin {#option-1-update-the-plugin}

1. **Verifica la disponibilità di aggiornamenti** - Il conflitto potrebbe essere stato risolto in una versione più recente
2. **Aggiorna il plugin** prima sul sito di staging
3. **Esegui test approfonditi** prima di aggiornare il sito in produzione

### Opzione 2: trova un'alternativa {#option-2-find-an-alternative}

1. **Cerca plugin alternativi** che offrano la stessa funzionalità
2. **Prova le alternative** sul sito di staging
3. **Migra le impostazioni** se cambi plugin

### Opzione 3: contatta lo sviluppatore del plugin {#option-3-contact-plugin-developer}

1. **Segnala il conflitto** allo sviluppatore del plugin
2. **Fornisci informazioni dettagliate:**
   - Versioni dei plugin coinvolti
   - Versioni di WordPress e WooCommerce
   - Messaggi di errore o comportamenti esatti
   - Passaggi per riprodurre il problema

### Opzione 4: soluzione personalizzata {#option-4-custom-solution}

Per i plugin essenziali che non possono essere sostituiti:

1. **Contatta uno sviluppatore WordPress** per creare una correzione personalizzata
2. **Valuta gli hook specifici del plugin** per disabilitare la funzionalità in conflitto
3. **Usa la logica condizionale** per disabilitare il plugin nelle pagine relative al POS

## Tipi di plugin che causano spesso conflitti {#common-conflicting-plugin-types}

### Categorie di plugin ad alto rischio {#high-risk-plugin-categories}

**Plugin di sicurezza:**
- Possono bloccare le richieste API
- Possono interferire con l'autenticazione
- Spesso hanno regole firewall aggressive

**Plugin di caching:**
- Possono memorizzare nella cache le risposte API in modo inappropriato
- Possono interferire con i dati in tempo reale
- Possono causare problemi dovuti a dati obsoleti

**Plugin SEO:**
- I plugin pesanti possono rallentare l'area di amministrazione
- Possono aggiungere query superflue al database
- Possono interferire con le risposte dell'API REST

**Strumenti per la creazione di pagine:**
- Spesso caricano script pesanti nell'area di amministrazione
- Possono entrare in conflitto con le pagine di amministrazione di WooCommerce
- Possono interferire con le procedure di checkout

**Plugin per iscrizioni e restrizioni di accesso:**
- Possono bloccare l'accesso alle API
- Possono interferire con l'autenticazione degli utenti
- Possono limitare l'accesso alle risorse necessarie

### Categorie di plugin a rischio inferiore {#lower-risk-plugin-categories}

**Moduli di contatto:** di solito non interferiscono con WCPOS
**Plugin per social media:** raramente causano conflitti
**Plugin di analisi:** generalmente non creano problemi, a meno che non siano molto pesanti
**Plugin di base per i contenuti:** solitamente compatibili
**WooCommerce Tax (imposte automatiche tramite TaxJar):** supportato. WCPOS ne richiede le aliquote quando viene salvato un ordine POS aperto, così gli ordini POS ricevono le stesse aliquote automatiche degli ordini online. Consulta [WooCommerce Tax](/1.x/integrations/woocommerce-tax).

## Conflitti noti tra plugin {#known-plugin-conflicts}

È noto che i plugin elencati di seguito interferiscono con WCPOS. Molti problemi sono già stati risolti automaticamente nelle versioni recenti di WCPOS: **l'aggiornamento all'ultima versione** li risolve senza alcuna configurazione.

:::tip La maggior parte delle soluzioni consiste nell'escludere il POS
Il punto in comune: WCPOS si basa sull'API REST di WooCommerce e visualizza alcuni flussi (accesso, pagamento, ricevute) in iframe. La soluzione abituale è **escludere gli endpoint/URL del POS** (`/wp-json/wcpos/`, `/wp-json/wc/v3/` e il percorso `/pos/`) dall'altro plugin, senza disabilitarlo completamente.
:::

### Plugin di sicurezza e accesso {#security-and-login-plugins}

Sono la causa **più comune** di conflitti, soprattutto durante l'accesso dall'app desktop o mobile.

| Plugin | Sintomo | Soluzione |
| --- | --- | --- |
| **Wordfence** | Il firewall blocca l'API REST; il campo del codice 2FA non viene visualizzato nell'iframe di accesso; una CSP restrittiva può bloccare le risorse del POS | Inserisci `/wp-json/wcpos/` e `/wp-json/wc/v3/` nell'elenco degli elementi consentiti del firewall. Per la 2FA: disabilitala temporaneamente per gli utenti POS. La CSP viene rimossa automaticamente in v1.9.0+ |
| **Really Simple Security** | Blocca l'accesso alle API / forza reindirizzamenti | Disabilita eventuali restrizioni dell'API REST nelle impostazioni **Advanced** del plugin |
| **WPS Hide Login** | L'URL di accesso personalizzato impedisce il funzionamento dell'iframe di accesso dell'app | Usa l'URL di accesso standard `/wp-admin/` per accedere al POS |
| **iThemes / Solid Security** | Blocca l'API REST o attiva blocchi contro gli attacchi a forza bruta in seguito alle chiamate del POS | Inserisci nell'elenco degli elementi consentiti solo gli endpoint del POS e l'IP del server stesso: evita regole IP indiscriminate |
| **Sucuri** | Il WAF blocca le richieste API | Inserisci gli endpoint dell'API REST nell'elenco degli elementi consentiti nella dashboard di Sucuri |
| **Security Optimizer** | Blocca l'accesso dell'amministratore al POS (_"usa l'URL di accesso personalizzato"_) | Accedi prima a WP Admin tramite l'URL personalizzato, poi vai a `/pos` |
| **Force Login** (e plugin simili di autenticazione REST) | `/wp-json/` restituisce 401/403; le app meno recenti segnalavano _"Il sito non sembra essere un sito WordPress"_ | Consenti l'accesso non autenticato agli endpoint del POS oppure disabilita il plugin durante la connessione iniziale. Le app v1.x ora mostrano il messaggio di errore effettivo |
| **LoginPress** | Impone l'accesso tramite email; impedisce l'accesso multiutente al POS | Consenti l'accesso tramite nome utente oppure disabilita il plugin per l'accesso al POS |
| **Plugin JWT Authentication** | Errore 403 su tutte le richieste API del POS dopo l'attivazione (l'accesso può riuscire, ma tutto il resto non funziona) | Risolto automaticamente in v1.8.x+. Nelle versioni precedenti, disattiva il plugin JWT o escludi gli endpoint del POS |
| **Captcha / reCAPTCHA** | Ciclo continuo di accesso nell'app desktop (il captcha non può essere visualizzato nell'iframe) | Disabilita il captcha per l'URL di accesso del POS |
| **Defender Pro** | L'header `X-Frame-Options` blocca tutti gli iframe del POS (accesso, pagamento, ricevute) | Aggiungi un'eccezione specifica per il POS per `/pos/` invece di disabilitare `X-Frame-Options` sull'intero sito |
| **Jetpack CRM Client Portal** | Impedisce completamente l'accesso al POS | Disabilita solo l'estensione Client Portal |

### Plugin per prestazioni, caching e ottimizzazione {#performance-caching-optimisation-plugins}

| Plugin | Sintomo | Soluzione |
| --- | --- | --- |
| **WP Rocket, Autoptimize, Hummingbird, Smush** | Il caricamento differito o la minificazione di JS impediscono il funzionamento del checkout e di Stripe Terminal | Escludi gli URL `/pos/` dall'ottimizzazione di JS |
| **LiteSpeed Cache** | Ciclo continuo di ricaricamento al checkout nell'app desktop; CSP restrittiva | Aggiorna WCPOS, svuota la cache ed escludi le pagine del POS dal caching. La CSP viene rimossa automaticamente in v1.9.0+ |
| **Image Prioritizer** | Sovraccarica l'header HTTP `Link`, impedendo il rilevamento dell'API REST; l'app desktop mostra _"non sembra essere un sito WordPress"_ | Disattiva il plugin |

### Strumenti per la creazione di pagine e plugin che inseriscono contenuti nel front-end {#page-builders-front-end-injectors}

| Plugin | Sintomo | Soluzione |
| --- | --- | --- |
| **Elementor** | `elementor-frontend.js` impedisce il funzionamento delle sezioni espandibili del checkout nell'iframe del POS: i metodi di pagamento non si espandono | Escludi le pagine del POS dal caricamento degli script di Elementor |
| **Omnisend / plugin di marketing** | Inseriscono script nell'iframe del checkout, compromettendo il layout e i pagamenti | Usa le **Checkout Settings** del POS per disabilitare gli script non essenziali |
| **MyStickyElements / Complianz** | Inseriscono elementi sovrapposti (pulsanti fissi, banner dei cookie) nell'iframe del checkout | Configurali in modo da escludere gli URL `/pos/` |

### Estensioni di WooCommerce e altri plugin {#woocommerce-extensions-other-plugins}

| Plugin | Sintomo | Soluzione |
| --- | --- | --- |
| **WooCommerce Subscriptions** | Conflitto dello script di migrazione durante l'aggiornamento v1.7→v1.8 | Disattiva Subscriptions, attiva POS Pro (lascia eseguire la migrazione), poi riattiva Subscriptions |
| **WP Activity Log** | Registra ogni azione del POS → crescita eccessiva dei postmeta → _"solo 10 prodotti"_ | Disabilitalo oppure escludi i tipi di post del POS dalla registrazione |
| **Jetpack / Astra / Xero** (qualsiasi plugin che si agganci a `save_post`) | Righe di metadati duplicate a ogni chiamata API del POS (un negozio ha raggiunto 36,867 righe per un solo prodotto) | Risolto automaticamente in v1.8.12+ (gratuito) / v1.8.14+ (Pro) con una migrazione di pulizia: basta aggiornare |
| **Stripe Tax** | Incompatibile con gli ordini creati tramite API REST (il metodo usato dal POS per creare gli ordini) | Nessuna soluzione alternativa: incompatibile. [WooCommerce Tax](/1.x/integrations/woocommerce-tax) è l'opzione supportata per le imposte automatiche |
| **Mollie** | Può nascondere il metodo BACS (bonifico bancario) dal checkout del POS | Aggiorna Mollie all'ultima versione |
| **CTX Feed** | Errori 403 intermittenti nella pagina delle impostazioni del POS | Disattivalo per confermare; nessuna soluzione alternativa nota |
| **Plugin di terze parti per scanner di codici a barre** | Corrompono il JSON dell'API degli ordini, impedendo la creazione/visualizzazione degli ordini | Disabilitali; usa la scansione dei codici a barre integrata nel POS |
| **MailerLite** (Signup Forms + WooCommerce) | Errore 500 durante la creazione degli ordini POS (esaurimento della memoria) | Disattivalo per confermare, poi contatta MailerLite |
| **The Courier Guy Shipping** | La creazione degli ordini POS non riesce a causa di un errore del server | Ripristina una versione precedente oppure contatta lo sviluppatore |
| **PixelYourSite / PixelMySite** | Errore fatale: _chiamata alla funzione membro `is_type()` su un valore bool_ | Disabilitalo temporaneamente |
| **Google Listings & Ads** | Conflitto dell'autoloader → errore critico _"Classe WCPOS\…\Stores non trovata"_ | Elimina tutti i plugin POS e reinstalla solo l'ultima versione autonoma di Pro |

:::warning Stripe Terminal: non abilitarlo globalmente
Il gateway di pagamento **Stripe Terminal** va abilitato **solo** nelle impostazioni del POS, mai in `WooCommerce > Impostazioni > Pagamenti`. Abilitarlo globalmente lo fa comparire nel checkout pubblico del negozio e provoca l'arresto del flusso di checkout online.
:::

### Conflitti a livello di server {#server-level-conflicts}

| Origine | Sintomo | Soluzione |
| --- | --- | --- |
| **Header CSP personalizzati** (`.htaccess`, Nginx o un plugin di sicurezza) | POS bloccato sul logo; JS/CSS bloccati | Rimossi automaticamente dalle pagine del POS in v1.9.0+. Per la CSP a livello di server, consenti `cdn.jsdelivr.net` in `script-src`/`style-src` oppure aggiungi un'eccezione per `/pos/` |
| **GoDaddy Website Firewall** | Blocca `/wp-json/` (_"Ricevuto 'undefined'"_) | Consenti il percorso URL `/wp-json/` nel firewall: consulta [Prestazioni del server](/1.x/support/performance/server#hosting-specific-notes) |

## Suggerimenti per la prevenzione {#prevention-tips}

### Manutenzione regolare {#regular-maintenance}

1. **Mantieni aggiornati i plugin** - Usa sempre le versioni più recenti
2. **Rimuovi i plugin inutilizzati** - Non limitarti a disattivarli: eliminali
3. **Prova gli aggiornamenti in staging** prima di applicarli al sito in produzione
4. **Monitora le prestazioni** regolarmente usando le metriche descritte in [Prestazioni del server](/1.x/support/performance/server)

### Buone pratiche per la scelta dei plugin {#plugin-selection-best-practices}

1. **Scegli sviluppatori affidabili** - Controlla le recensioni e la frequenza degli aggiornamenti
2. **Evita funzionalità ridondanti** - Non installare più plugin che svolgono la stessa funzione
3. **Leggi le informazioni sulla compatibilità** - Verifica se i plugin sono stati testati con WooCommerce
4. **Inizia con il minimo indispensabile di plugin** - Aggiungi funzionalità gradualmente, secondo necessità
