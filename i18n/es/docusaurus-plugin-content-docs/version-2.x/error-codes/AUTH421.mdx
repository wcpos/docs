## Qué significa {#what-this-means}

El servidor de la tienda bloquea el token de inicio de sesión en todos los canales que esta aplicación puede utilizar.

La aplicación ha confirmado que la tienda es accesible, pero el servidor (o un cortafuegos, proxy o plugin de seguridad situado delante de él) elimina la cabecera Authorization y también bloquea el token cuando se envía como parámetro de la URL. No existe una tercera vía para entregar un token de inicio de sesión, por lo que debe resolverse en el servidor.

## Sus datos {#your-data}

Los datos de pedidos y productos no se ven afectados.

## Solución de problemas {#troubleshoot}

**En el alojamiento / servidor** — el token de inicio de sesión no tiene ningún canal de entrega hasta que el servidor permita su paso:

1. Permita que la cabecera Authorization llegue a WordPress; en Apache suele bastar una línea: `SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1`.
2. Si el sitio utiliza reglas de reescritura en `.htaccess`, conserve la línea RewriteRule generada por WordPress que transmite `HTTP_AUTHORIZATION`; los plugins de seguridad a veces la eliminan.
3. Si hay un proxy o una CDN, revise su lista de cabeceras permitidas: la cabecera de solicitud Authorization debe reenviarse al servidor de origen.
4. Si un cortafuegos de aplicaciones web (WAF) filtra los parámetros de la URL, permita el parámetro authorization en las rutas REST de `/wcpos/`.
