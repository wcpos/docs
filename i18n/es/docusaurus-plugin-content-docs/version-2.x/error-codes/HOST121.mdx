## Qué significa {#what-this-means}

Una página de protección contra bots está respondiendo en lugar de la API de la tienda.

La API REST de la tienda devuelve una página HTML de comprobación (protección contra bots, CAPTCHA o página intermedia contra DDoS) donde la aplicación espera JSON. Una aplicación de punto de venta no puede resolver una comprobación del navegador; es necesario añadir la API REST de la tienda a la lista de permitidos del servicio de protección.

## Sus datos {#your-data}

No se ve afectado ningún dato de pedidos o productos.

## Solución de problemas {#troubleshoot}

1. Identifique la capa de protección por la página de comprobación (Cloudflare, Sucuri, Kinsta y otros muestran su marca en ella) y abra sus ajustes.
2. Añada las rutas de la API REST de la propia tienda (/wp-json/ y /?rest_route=) a la lista de permitidos para el tráfico de la API.
3. En Cloudflare, añada una regla **Omitir** del WAF para las rutas de la API REST; el modo de lucha contra bots (plan gratuito) no puede omitirse con ninguna regla y debe desactivarse. La [guía de Cloudflare](/troubleshooting/common-problems/cloudflare) incluye la regla exacta y una comprobación con `curl`.
4. En los ajustes de bots y cortafuegos de Kinsta, añada las rutas de la API REST a la lista de permitidos; en Sucuri, evite el modo DDoS con comprobación de JavaScript para las rutas de la API.
