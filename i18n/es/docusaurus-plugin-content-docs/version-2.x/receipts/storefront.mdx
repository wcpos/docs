**WP admin:** active el botón **Recibo** para los pedidos en línea en `WP Admin → POS → Settings → General`.

:::note Esta página está dirigida a quien administra el sitio web
Con [WCPOS Pro](../getting-started/pro-license.mdx), puede imprimir o enviar por correo electrónico desde la caja un recibo de cualquier pedido, incluidos los pedidos en línea: consulte [Reimprimir un recibo](../orders/index.mdx#receipt-reprinting) en la página **Pedidos**.
:::

:::tip Si un cliente solicita el recibo de su compra en línea
Una vez configurado en el sitio web, podrá obtenerlo con el botón **Recibo** en **Mi cuenta → Pedidos**, o mediante un enlace al recibo en la página de confirmación de su pedido, si la tienda lo ha añadido.
:::

Sus plantillas de recibo de WCPOS también funcionan en su sitio web. Un cliente que haya comprado en línea puede descargar su recibo en PDF desde **Mi cuenta**, o desde un enlace que usted añada a la página de confirmación del pedido.

## Activar el botón Recibo {#my-account}

:::warning Active primero una plantilla de recibo
Active una en **POS → Plantillas** antes de empezar. Si no hay ninguna activa, los clientes no verán el botón **Recibo**, aunque el ajuste esté activado. Consulte [Personalizar su recibo](./customise.mdx#option-1--pick-a-different-template).
:::

El botón está desactivado hasta que lo active. El PDF se genera a partir de su plantilla de recibo.

1. En WP Admin, vaya a **POS → Ajustes → General**.

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[95, 0], [105, 0]]} alt="WP Admin con POS, Ajustes seleccionado en el menú y General abierto en el menú de ajustes, donde se muestran Tiendas, Caja y el inicio de Productos">

1. **POS → Ajustes** — la opción del menú de WP Admin para los ajustes del POS.
2. **General** — la primera pantalla de ajustes, que ya está abierta al entrar.

</JourneyShot>

2. Desplácese hasta la sección **Clientes** y active **Permitir que los clientes descarguen recibos**. El cambio se guarda en cuanto lo active.

<JourneyShot manifest={manifest} device="desktop" step={2} maxWidth={880} offsets={[[100, 0], [310, 0]]} alt="La sección Clientes de General: Generar automáticamente el nombre de usuario a partir del correo electrónico del cliente, Cliente predeterminado del POS establecido en Invitado y Permitir que los clientes descarguen recibos, todavía desactivado">

1. **Clientes** — la sección que contiene el ajuste de recibos.
2. **Permitir que los clientes descarguen recibos** — desactivado hasta que lo active.

</JourneyShot>

3. Debajo aparece **Plantilla de recibo para clientes**. Deje seleccionada la opción **Usar la plantilla de recibo activa** o elija una. Consulte [Elegir la plantilla para el cliente](#template-choice).

Ahora, un cliente que haya iniciado sesión verá el botón **Recibo** junto a sus pedidos en **Mi cuenta → Pedidos**. Este descarga un PDF cuyo nombre corresponde al pedido, como `receipt-1234.pdf`.

El botón solo aparece en los pedidos que se han pagado:

| Estado del pedido | Botón Recibo |
|---|---|
| **Procesando** | Sí |
| **Completado** | Sí |
| **Reembolsado** | Sí |
| Cualquier otro estado, como **Pendiente de pago**, **En espera**, **Cancelado** o **Fallido** | No |

Un desarrollador puede [cambiar los estados en los que aparece el botón](#developers).

## Elegir la plantilla para el cliente {#template-choice}

**Plantilla de recibo para clientes** determina qué plantilla se utiliza en la descarga.

- **Usar la plantilla de recibo activa** (opción predeterminada): los clientes reciben la plantilla de recibo que tenga activa en **POS → Plantillas**. Si la cambia allí, las descargas también cambiarán.
- **Una plantilla concreta**: los clientes siempre reciben esa plantilla, independientemente de la que elija el cajero en la caja. Utilice esta opción cuando haya varias plantillas de recibo activas o para dar un aspecto propio a los pedidos en línea.

Una plantilla estrecha de estilo térmico genera un PDF estrecho. Para los pedidos en línea, una página completa suele resultar más legible: la plantilla **Factura** de la galería está diseñada para papel A4 y Carta. Consulte [Personalizar su recibo](./customise.mdx#option-1--pick-a-different-template) para añadirla.

El PDF se rellena con los mismos [datos del recibo](./receipt-data.mdx) que el recibo de caja, por lo que conserva su logotipo, los datos de la tienda y los ajustes de impuestos.

Si una plantilla seleccionada se elimina o deja de estar publicada, el desplegable muestra **Plantilla no disponible** y los clientes reciben la plantilla de recibo activa en su lugar. Elija otra.

## Añadir un enlace al recibo en la página de confirmación del pedido {#shortcode}

Ofrezca a los clientes un enlace **Descargar recibo (PDF)** en la página de agradecimiento que ven tras finalizar la compra. Los invitados que hayan comprado sin una cuenta obtienen su recibo de esta forma.

Si en WP Admin dispone de **Apariencia → Editor → Plantillas → Confirmación del pedido**, puede añadir el enlace a la página de agradecimiento usted mismo:

1. En WP Admin, vaya a **Apariencia → Editor → Plantillas** y abra **Confirmación del pedido**.
2. Añada un bloque **Shortcode** donde quiera colocar el enlace e introduzca `[wcpos_receipt]` en él.
3. Pulse **Guardar**.

Si no dispone de esa plantilla o quiere que el enlace aparezca en la página de un pedido en **Mi cuenta**, pida a un desarrollador que [añada el enlace al recibo mediante código](#developers).

El shortcode funciona tanto si **Permitir que los clientes descarguen recibos** está activado como si no: ese ajuste solo controla el botón de **Mi cuenta → Pedidos**.

<details>
<summary>Opciones y ejemplos del shortcode</summary>

`[wcpos_receipt]` funciona en la página de confirmación del pedido y en la página de un pedido en **Mi cuenta**. Allí identifica el pedido automáticamente, por lo que no tiene que introducir un número de pedido. En cualquier otra página no muestra nada a menos que se le indique un `order_id`.

| Opción | Valor predeterminado | Función |
|---|---|---|
| `order_id` | *(obtenido de la página)* | Enlace a un pedido concreto desde cualquier página. Solo se muestra al cliente al que pertenece el pedido si ha iniciado sesión. |
| `link_text` | `Download receipt (PDF)` | El texto del enlace. |
| `format` | `pdf` | `pdf` descarga un PDF. `html` abre el recibo en el navegador, listo para imprimir. |
| `template` | *(su plantilla de recibo activa)* | Utiliza esta plantilla en su lugar. |
| `class` | `wcpos-receipt-link` | Clase CSS del enlace. |
| `id` | *(ninguno)* | `id` HTML del enlace. |

La opción `template` del shortcode no tiene en cuenta **Plantilla de recibo para clientes**: si la omite, el enlace utiliza su plantilla de recibo activa.

Un enlace de descarga con su propio texto:

```text
[wcpos_receipt link_text="Download your invoice"]
```

Abrir el recibo en el navegador en lugar de descargar un PDF:

```text
[wcpos_receipt format="html" link_text="View your receipt"]
```

Utilizar una plantilla concreta, por ejemplo, una factura A4 en lugar del recibo de caja de 80mm:

```text
[wcpos_receipt template="123" link_text="Download invoice (PDF)"]
```

El número de la plantilla aparece en la barra de direcciones al editarla en **POS → Plantillas** (`post=123`). Si una plantilla no está publicada, se ignora y el enlace utiliza su plantilla de recibo activa.

</details>

## Quién puede abrir un recibo {#security}

- Los **clientes con una cuenta** inician sesión y utilizan el botón **Recibo** en **Mi cuenta → Pedidos**.
- Los **invitados** que hayan comprado sin una cuenta utilizan el enlace al recibo de la página de confirmación de su pedido, una vez que usted [lo haya añadido](#shortcode).

:::warning Comparta los enlaces a recibos únicamente con el cliente
Cualquier persona que tenga un enlace a un recibo puede abrirlo sin iniciar sesión. Trátelo con el mismo cuidado que el propio pedido.
:::

<details>
<summary>Cómo se protegen los enlaces a recibos</summary>

Cada enlace a un recibo incluye la clave privada del pedido, la misma que WooCommerce incorpora en su página de confirmación. Sin la clave correcta, el recibo no se abre. Un shortcode con la opción `order_id` solo muestra su enlace al cliente al que pertenece el pedido y que haya iniciado sesión.

</details>

## Si algo sale mal {#goes-wrong}

La mayoría de las soluciones siguientes se aplican en WP Admin. Si es cajero, transmita el mensaje que ve el cliente a quien administra el sitio web. Mientras tanto, con [WCPOS Pro](../getting-started/pro-license.mdx), puede imprimir o enviar por correo electrónico su recibo desde la caja: consulte [Reimprimir un recibo](../orders/index.mdx#receipt-reprinting) en la página **Pedidos**.

**El cliente no ve el botón Recibo.** Compruebe que **Permitir que los clientes descarguen recibos** esté activado, que el pedido tenga el estado **Procesando**, **Completado** o **Reembolsado**, y que haya al menos una plantilla de recibo activa en **POS → Plantillas**. El botón solo aparece en **Mi cuenta → Pedidos** para un cliente que haya iniciado sesión.

**«No hay ninguna plantilla de recibo configurada».** No hay ninguna plantilla disponible para generar el PDF. Active una plantilla de recibo en **POS → Plantillas**.

**«No tiene permiso para ver este recibo».** El enlace está incompleto o se ha copiado mal: cada enlace incluye una clave privada para su pedido. Vuelva a enviar al cliente el enlace de su página de confirmación o de **Mi cuenta**.

**«No se ha podido generar el PDF del recibo».** No se ha podido generar el PDF a partir de la plantilla. Ábrala en **POS → Plantillas** y obtenga una vista previa. Consulte [Personalizar su recibo](./customise.mdx).

**El enlace muestra el error «Página no encontrada».** En WP Admin, vaya a **Ajustes → Enlaces permanentes** y elija cualquier opción excepto **Simple**. Los enlaces a recibos no funcionan con **Simple**.

## Para desarrolladores {#developers}

<details>
<summary>Añadir el enlace al recibo mediante código</summary>

En un tema clásico, genere el enlace desde las dos acciones de WooCommerce que muestran esas páginas:

```php
// The order confirmation ("thank you") page.
add_action( 'woocommerce_thankyou', function () {
	echo do_shortcode( '[wcpos_receipt]' );
} );

// An order's page in My Account.
add_action( 'woocommerce_view_order', function () {
	echo do_shortcode( '[wcpos_receipt]' );
} );
```

El shortcode identifica el pedido en ambas páginas, por lo que no necesita un `order_id`.

</details>

<details>
<summary>Filtros para el botón Recibo y la plantilla del PDF</summary>

Hay tres filtros que prevalecen sobre los ajustes anteriores y permiten definir reglas que estos no contemplan, como reglas por pedido o por cliente:

```php
// Force the My Account Receipt button on or off, overriding the setting.
// Its default value is the "Let customers download receipts" setting,
// so you only need it to override that, e.g. show the button for one user role.
add_filter( 'wcpos_storefront_receipt_my_account_button', '__return_true' );

// Change which order statuses show the button (default: processing, completed, refunded).
add_filter( 'wcpos_storefront_receipt_order_statuses', function ( $statuses, $order ) {
	$statuses[] = 'on-hold';
	return $statuses;
}, 10, 2 );

// Use a different template for storefront PDF downloads, overriding the template
// chosen by the setting or the shortcode. Receives and returns the full template array
// (null when none is configured).
add_filter( 'wcpos_storefront_receipt_template', function ( $template, $order ) {
	return \WCPOS\WooCommercePOS\Templates::get_template( 123 );
}, 10, 2 );
```

Antes de WCPOS 2.0, estos filtros se llamaban `woocommerce_pos_storefront_receipt_*`. Esos nombres siguen funcionando, pero están obsoletos desde 2.0 y se eliminarán como pronto en 2.2. Consulte [Nombres de los hooks](../extensions/index.mdx#hook-naming).

La dirección del PDF es `/wcpos-checkout/wcpos-receipt/{order_id}` con `?key={order_key}&format=pdf`: la misma dirección del recibo protegida por clave que utiliza el POS, donde `format=pdf` devuelve un PDF en lugar de la página.

</details>
