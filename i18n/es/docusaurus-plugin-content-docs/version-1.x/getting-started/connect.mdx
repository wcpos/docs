## Descripción general de la pantalla de conexión {#connect-screen-overview}

Al abrir la aplicación de escritorio o móvil de WCPOS, verá la pantalla de conexión. Desde aquí puede gestionar las conexiones con sus tiendas y los inicios de sesión de los usuarios.

{/* Screenshot: connect-screen.png */}

## Agregar una nueva tienda {#adding-a-new-store}

1. Introduzca la URL de su tienda WooCommerce en el campo de texto (por ejemplo, `https://mystore.com`)
2. Haga clic en **Conectar**
3. Se le redirigirá para iniciar sesión con sus credenciales de WordPress
4. Tras iniciar sesión correctamente, volverá a la aplicación

## Múltiples tiendas {#multiple-stores}

Puede conectarse a tantas tiendas WooCommerce como necesite. Cada tienda aparece como una tarjeta independiente en la pantalla de conexión, que muestra:

- **Nombre de la tienda** y favicon
- **URL de la tienda**
- **Usuarios conectados** en esa tienda

Esto resulta útil si gestiona varias ubicaciones o empresas.

## Múltiples usuarios por tienda {#multiple-users-per-store}

Cada tienda puede tener varios usuarios con sesión iniciada al mismo tiempo. Esto resulta útil para:

- **Cambios de turno** - El nuevo cajero puede iniciar sesión antes de que el anterior cierre la sesión
- **Configuraciones con múltiples cajas** - Distintos cajeros en distintos dispositivos
- **Cambio rápido** - Cambie fácilmente entre cuentas de usuario

### Agregar un usuario {#adding-a-user}

Haga clic en el <Icon name="plus" /> botón situado junto a «Usuarios conectados» para agregar otro usuario a esa tienda.

### Cambiar de usuario {#switching-users}

Haga clic en la insignia de un usuario (por ejemplo, «Brenda») para abrir el POS como ese usuario.

### Eliminar un usuario {#removing-a-user}

Haga clic en la **×** de la insignia de un usuario para cerrar su sesión en la tienda.

## Eliminar una tienda {#removing-a-store}

Haga clic en el botón rojo **×** de la tarjeta de la tienda para eliminarla de su lista. Se cerrará la sesión de todos los usuarios y se eliminará de la aplicación la conexión con la tienda.

## Tienda de demostración {#demo-store}

En la parte inferior de la pantalla, puede que vea un enlace «Entrar a la tienda de demostración». Este le conecta con una tienda WooCommerce de demostración para probar las funciones de WCPOS sin afectar a los datos de su propia tienda.

## Solución de problemas {#troubleshooting}

:::tip Lo primero que debe comprobar: `X-Frame-Options`
Las aplicaciones de escritorio y móviles usan **iframes** para el inicio de sesión, los pagos y los recibos. **Cualquier** encabezado del servidor o plugin que envíe `X-Frame-Options: DENY` o `SAMEORIGIN` impedirá iniciar sesión. Esta es la causa más común de los errores de inicio de sesión en la aplicación: antes de nada, compruebe los encabezados de respuesta de la página de inicio de sesión (con las herramientas de desarrollo del navegador o mediante `curl -I https://yourstore.com/wp-login.php`).
:::

<Accordion>
  <AccordionItem question="¿No puede conectarse a su tienda?">

  - Asegúrese de que el plugin WCPOS esté instalado y activado en su sitio de WordPress
  - Compruebe que utiliza la URL correcta (incluya `https://`; la REST API de WooCommerce requiere SSL)
  - Pruebe a abrir primero `yourdomain.com/pos` en un navegador web para confirmar que el plugin funciona
  - Compruebe que se pueda acceder a la REST API de WooCommerce
  - Compruebe que su cuenta de usuario tenga permisos de acceso al POS

  </AccordionItem>

  <AccordionItem question="Falla el inicio de sesión en la aplicación de escritorio o móvil">

  La mayoría de los errores de inicio de sesión en la aplicación se deben a que un plugin de seguridad o de caché bloquea el iframe de inicio de sesión:

  - **Encabezados `X-Frame-Options`** (establecidos por un plugin de seguridad o por el servidor) bloquean el iframe de inicio de sesión; consulte la nota anterior. Desactive temporalmente el plugin de seguridad, inicie sesión y vuelva a activarlo (la sesión dura aproximadamente una semana).
  - **Plugins de seguridad** — Wordfence, Really Simple Security, WPS Hide Login, iThemes/Solid Security y Defender Pro suelen ser los causantes. Consulte la lista completa y las soluciones en [Conflictos de plugins](/support/troubleshooting/plugin-conflicts#security-and-login-plugins).
  - **Wordfence 2FA** — el campo del código 2FA no se muestra en el iframe de inicio de sesión. Por ahora, desactive la 2FA para los usuarios del POS.
  - **URL de inicio de sesión personalizada** (por ejemplo, WPS Hide Login) — la aplicación no encuentra la página de inicio de sesión. Use la URL estándar `/wp-admin/`.
  - **Los plugins de caché** pueden seguir mostrando el formulario de inicio de sesión bloqueado incluso después de desactivar el plugin causante. Borre la caché o borre la caché de la aplicación / vuelva a instalar la aplicación de escritorio.

  </AccordionItem>

  <AccordionItem question='«La REST API requiere autenticación» o un error de un plugin de seguridad en la pantalla de conexión'>

  Un plugin (por ejemplo, Force Login o un plugin de autenticación JWT) exige autenticación para todas las solicitudes de REST API, por lo que la aplicación no puede leer la información pública de su sitio. Ahora la aplicación muestra el mensaje real del servidor (por ejemplo, _«Solo los usuarios autenticados pueden acceder a la REST API»_) en lugar de indicar incorrectamente el tipo de sitio.

  **Solución:** configure el plugin de seguridad para permitir el acceso sin autenticación a `/wp-json/wcpos/` y `/wp-json/wc/v3/`, o desactívelo solo durante el tiempo necesario para completar la primera conexión.

  </AccordionItem>

  <AccordionItem question='«No parece ser un sitio de WordPress» (aplicación de escritorio)'>

  La aplicación de escritorio descubre la REST API mediante el encabezado HTTP `Link`. Si un plugin (normalmente **Image Prioritizer** u otros plugins de rendimiento) satura o trunca ese encabezado, no se podrá descubrir la API. **Solución:** desactive los plugins de optimización de imágenes o los que modifican encabezados y vuelva a intentarlo.

  </AccordionItem>

  <AccordionItem question="La aplicación indica que necesita una actualización o se bloquea después de actualizarse">

  Compruebe si hay una discrepancia de versiones entre la aplicación y el plugin del servidor: es posible que la tienda de aplicaciones haya publicado una actualización de la aplicación mientras todavía es necesario actualizar el plugin WCPOS (o viceversa). Para v1.10, tanto la aplicación como el plugin WCPOS deben estar en la **línea de versiones v1.10**, ya que la aplicación usa la API de sincronización v2 del plugin. Si solo se actualizó uno de los dos y las solicitudes fallan con `rest_no_route`, actualice el otro.

  </AccordionItem>

  <AccordionItem question='Error «No se puede crear la base de datos rápida de la tienda»'>

  Se trata de una condición de carrera en el primer inicio de sesión. **Cierre completamente la aplicación y vuelva a intentarlo**; normalmente funciona en el segundo intento.

  </AccordionItem>

  <AccordionItem question="Se queda bloqueado en la pantalla de selección de usuario (aplicación de escritorio)">

  Después de iniciar sesión, verá su nombre de usuario, pero no una forma evidente de continuar. **Haga clic en su nombre de usuario/nombre** para acceder al POS: el propio nombre es el botón.

  </AccordionItem>

  <AccordionItem question="¿Sigue fallando la conexión?">

  - Pruebe a acceder primero a `yourdomain.com/pos` en un navegador web para verificar que el plugin funciona
  - Compruebe si hay algún problema en los registros de errores de su sitio
  - Confirmar que el proveedor de hosting no está bloqueando la REST API — consultar [Notas específicas de hosting](/support/performance/server#hosting-specific-notes)
  - Asegurarse de que el servidor cumple con los [requisitos mínimos](/support/performance/server#minimum-server-requirements)

  </AccordionItem>
</Accordion>
