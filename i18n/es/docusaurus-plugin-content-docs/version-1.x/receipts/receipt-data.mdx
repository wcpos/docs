Las plantillas HTML sin lógica de WCPOS y las plantillas XML térmicas se renderizan a partir de la misma carga útil canónica de recibos. Utilice rutas con puntos de Mustache como `{{order.number}}`, `{{store.name}}` y `{{totals.total_display}}`. Las matrices se renderizan mediante secciones:

```mustache
{{#lines}}
  {{name}} x {{qty}} — {{line_total_display}}
{{/lines}}
```

El contrato canónico lo genera en el servidor el constructor de datos de recibos de WCPOS, y el renderizador de recibos sin conexión de la aplicación lo replica. Los recibos se abren de inmediato con datos locales y luego se actualizan con la respuesta del servidor cuando está disponible; por ello, las plantillas personalizadas deben usar los campos siguientes en lugar de los métodos de pedidos de PHP.

Datos de recibos v1.1 añade campos registrados de precio normal, precio de venta antes de aplicar cupones y ahorro para cada línea de producto. También proporciona totales de ahorro del pedido, incluido un valor de **Total ahorrado** que combina el ahorro sobre el precio normal con los descuentos de WooCommerce sin modificar los totales ni los informes del pedido.

Datos de recibos v1.2 añade `discount_type` a cada fila de descuento: el tipo de cupón de WooCommerce que origina el descuento.

## Ampliar los datos del recibo {#extending}

WCPOS mantiene el contrato anterior independiente del proveedor. Cuando un plugin necesita que el recibo incluya información que WooCommerce no modela, la añade mediante el filtro `woocommerce_pos_receipt_data`, del mismo modo que los plugins filtran los totales de pedido propios de WooCommerce. El filtro se ejecuta en cada recibo que genera el servidor: recibos en directo, instantáneas fiscales en el momento del pago, descargas PDF y plantillas PHP heredadas.

```php
add_filter( 'woocommerce_pos_receipt_data', function ( array $data, WC_Abstract_Order $order, string $mode ) {
    foreach ( $data['discounts'] as &$row ) {
        if ( 'smart_coupon' === $row['discount_type'] ) {
            $row['gift_card'] = true;
        }
    }
    return $data;
}, 10, 3 );
```

A continuación, una plantilla puede aplicar una condición a la nueva clave como a cualquier otra sección:

```
{{#discounts}}
  {{#gift_card}}Gift Card{{/gift_card}}{{^gift_card}}{{i18n.discount}}{{/gift_card}}{{#label}}: {{label}}{{/label}}
{{/discounts}}
```

Las claves definidas en el esquema deben conservar los tipos documentados. Las claves añadidas no forman parte del esquema, por lo que no aparecen en el selector de campos del editor de plantillas; además, las instantáneas fiscales solo incluyen lo que añadió el filtro en el momento del pago del pedido. El filtro está disponible desde WCPOS 1.10.8.

## Reglas de renderizado {#rendering-rules}

### Campos monetarios {#currency-fields}

Los campos monetarios numéricos se conservan como números y el renderizador añade campos `_display` adaptados a la configuración regional para usarlos en las plantillas:

| Campo numérico | Campo de visualización |
|---------------|---------------|
| `totals.total` | `totals.total_display` |
| `lines[].line_total` | `lines[].line_total_display` |
| `payments[].amount` | `payments[].amount_display` |
| `tax_summary[].tax_amount` | `tax_summary[].tax_amount_display` |

Prefiera los campos `_display` al imprimir recibos. Utilice campos numéricos solo para secciones condicionales o salidas legibles por máquina.

### Campos de visualización adaptados a impuestos {#tax-display-aware-fields}

Varios campos tienen variantes con impuestos incluidos y excluidos, además de un valor auxiliar para la visualización. Este valor sigue la configuración de visualización de impuestos del carrito de la tienda.

| Campo auxiliar | Campo con impuestos incluidos | Campo con impuestos excluidos |
|-------------------|-----------------|-----------------|
| `lines[].regular_price` | `lines[].regular_price_incl` | `lines[].regular_price_excl` |
| `lines[].selling_price` | `lines[].selling_price_incl` | `lines[].selling_price_excl` |
| `lines[].unit_savings` | `lines[].unit_savings_incl` | `lines[].unit_savings_excl` |
| `lines[].line_regular_total` | `lines[].line_regular_total_incl` | `lines[].line_regular_total_excl` |
| `lines[].line_selling_total` | `lines[].line_selling_total_incl` | `lines[].line_selling_total_excl` |
| `lines[].line_savings` | `lines[].line_savings_incl` | `lines[].line_savings_excl` |
| `lines[].unit_price` | `lines[].unit_price_incl` | `lines[].unit_price_excl` |
| `lines[].unit_subtotal` | `lines[].unit_subtotal_incl` | `lines[].unit_subtotal_excl` |
| `lines[].line_subtotal` | `lines[].line_subtotal_incl` | `lines[].line_subtotal_excl` |
| `lines[].discounts` | `lines[].discounts_incl` | `lines[].discounts_excl` |
| `lines[].line_total` | `lines[].line_total_incl` | `lines[].line_total_excl` |
| `fees[].total` | `fees[].total_incl` | `fees[].total_excl` |
| `shipping[].total` | `shipping[].total_incl` | `shipping[].total_excl` |
| `discounts[].total` | `discounts[].total_incl` | `discounts[].total_excl` |
| `totals.subtotal` | `totals.subtotal_incl` | `totals.subtotal_excl` |

| `totals.total` | `totals.total_incl` | `totals.total_excl` |

### Objetos de fecha {#date-objects}

Los campos de fecha son objetos con varias variantes preformateadas. Así se evita dar formato a las fechas dentro de Mustache.

| Campo | Descripción |
|-------|-------------|
| `datetime`, `date`, `time` | Cadenas de fecha y hora predeterminadas |
| `datetime_short`, `datetime_long`, `datetime_full` | Formatos combinados adaptados a la configuración regional |
| `date_short`, `date_long`, `date_full` | Formatos de solo fecha adaptados a la configuración regional |
| `date_ymd`, `date_dmy`, `date_mdy` | Formatos de fecha con orden fijo |
| `weekday_short`, `weekday_long` | Nombres de los días |
| `day`, `month`, `month_short`, `month_long`, `year` | Partes individuales de la fecha |

Objetos de fecha disponibles: `order.created`, `order.paid`, `order.completed`, `order.printed` y `refunds[].date`. `order.printed` se actualiza en el momento del renderizado, lo que resulta útil para las reimpresiones.

## Cómo se relacionan los precios {#price-model}

Una línea de producto contiene varios precios, y sus nombres se entienden mejor al verlos aplicados al importe. Esta es la línea de espresso del pedido de muestra: un producto de $17.00 rebajado a $14.50, más un cupón del 10 %:

  segments={[
    { kind: 'paid', amount: 13.05, label: "13.05 pagado" },
    { kind: 'coupon', amount: 1.45, label: "1.45" },
    { kind: 'savings', amount: 2.5, label: "2.50" },
  ]}
  summary={[
    { label: "Ahorro por rebajas en todo el pedido", value: '`totals.sale_savings_total` = 5.00' },
    { label: "Todos los descuentos de cupones del pedido", value: '`totals.discount_total` = 5.28' },
    { label: "Ahorro + descuentos, sin solapamiento heredado", value: '`totals.total_saved` = 10.28' },
  ]}
/>

Los ahorros por rebajas y los descuentos de cupones son conceptos distintos: los ahorros por rebajas comparan el precio de venta con el precio normal registrado, mientras que `discounts` representa los cálculos de cupones propios de WooCommerce. Los totales e informes de pedidos de WooCommerce solo incluyen la parte correspondiente a los cupones; por eso existe `total_saved`, la cifra que se muestra al cliente y que combina ambos conceptos.

### Mostrar el precio normal y los ahorros {#displaying-regular-price-and-savings}

Para un diseño con precios unitarios, muestre el precio normal registrado, el precio de venta y el ahorro de esta forma:

```mustache
{{#lines}}
  {{#unit_savings}}
    <span style="text-decoration: line-through;">{{regular_price_display}}</span>
    <span>{{selling_price_display}}</span>
    <span>{{i18n.savings}}: -{{unit_savings_display}}</span>
  {{/unit_savings}}
{{/lines}}
```

Use los campos de total de línea cuando la cantidad sea relevante:

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    <span>{{i18n.savings}}: -{{line_savings_display}}</span>
  {{/line_savings}}
{{/lines}}
```

`selling_price` es el precio anterior a los cupones. Use `unit_price` o `line_total` para el importe final después de los descuentos de WooCommerce.

:::note Reimpresión de pedidos creados antes de v1.9.0
Es posible que los pedidos antiguos de WCPOS ya incluyan en `discounts` la reducción del precio normal al precio de venta. Si su plantilla personalizada muestra tanto los ahorros de línea como los descuentos de línea, use `savings_in_discounts` para no mostrar dos veces la misma reducción:

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    {{^savings_in_discounts}}
      <span>{{i18n.savings}}: -{{line_savings_display}}</span>
    {{/savings_in_discounts}}
  {{/line_savings}}
  {{#discounts}}
    <span>{{i18n.discount}}: -{{discounts_display}}</span>
  {{/discounts}}
{{/lines}}
```

Si la plantilla no muestra una fila `discounts` por línea, siga mostrando `line_savings` aunque `savings_in_discounts` sea true. Las plantillas incluidas gestionan esta distinción automáticamente.
:::
