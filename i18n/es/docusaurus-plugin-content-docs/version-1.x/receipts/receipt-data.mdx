Las plantillas HTML sin lógica de WCPOS y las plantillas XML térmicas se generan a partir de la misma carga útil canónica de datos del recibo. Utilice rutas con puntos de Mustache como `{{order.number}}`, `{{store.name}}` y `{{totals.total_display}}`. Los arreglos se generan mediante secciones:

```mustache
{{#lines}}
  {{name}} x {{qty}} — {{line_total_display}}
{{/lines}}
```

El contrato canónico lo genera el constructor de datos de recibos de WCPOS en el servidor y se replica en el renderizador de recibos sin conexión de la aplicación. Los recibos se abren de inmediato a partir de datos locales y luego se actualizan con la respuesta del servidor cuando está disponible, por lo que las plantillas personalizadas deben usar los campos siguientes en lugar de los métodos de pedidos de PHP.

Receipt Data v1.1 añade campos registrados de precio normal, precio de venta antes de aplicar cupones y ahorro para cada línea de producto. También proporciona totales de ahorro a nivel de pedido, incluido un valor **Total ahorrado** que combina el ahorro respecto al precio normal con los descuentos de WooCommerce sin modificar los totales ni los informes del pedido.

Receipt Data v1.2 añade `discount_type` a cada fila de descuento: el tipo de cupón de WooCommerce que origina el descuento.

## Ampliar los datos de recibos {#extending}

WCPOS mantiene el contrato anterior independiente de los proveedores. Cuando un plugin necesita que el recibo incluya algo que WooCommerce no contempla, lo añade mediante el filtro `woocommerce_pos_receipt_data`, del mismo modo que los plugins filtran los totales de los pedidos de WooCommerce. El filtro se ejecuta para cada recibo que genera el servidor: recibos en vivo, instantáneas fiscales en el momento del pago, descargas PDF y plantillas PHP heredadas.

```php
add_filter( 'woocommerce_pos_receipt_data', function ( array $data, WC_Abstract_Order $order, string $mode ) {
    foreach ( $data['discounts'] as &$row ) {
        if ( 'smart_coupon' === $row['discount_type'] ) {
            $row['gift_card'] = true;
        }
    }
    return $data;
}, 10, 3 );
```

Una plantilla puede entonces comprobar la nueva clave como cualquier otra sección:

```
{{#discounts}}
  {{#gift_card}}Gift Card{{/gift_card}}{{^gift_card}}{{i18n.discount}}{{/gift_card}}{{#label}}: {{label}}{{/label}}
{{/discounts}}
```

Las claves definidas en el esquema deben conservar los tipos documentados. Las claves añadidas no forman parte del esquema, por lo que no aparecen en el selector de campos del editor de plantillas, y las instantáneas fiscales solo incluyen lo que el filtro añadió en el momento en que se pagó el pedido. El filtro está disponible a partir de WCPOS 1.10.8.

## Reglas de renderizado {#rendering-rules}

### Campos de moneda {#currency-fields}

Los campos monetarios numéricos se conservan como números y el renderizador añade campos `_display` adaptados a la configuración regional para la salida de la plantilla:

| Campo numérico | Campo de visualización |
|---------------|---------------|
| `totals.total` | `totals.total_display` |
| `lines[].line_total` | `lines[].line_total_display` |
| `payments[].amount` | `payments[].amount_display` |
| `tax_summary[].tax_amount` | `tax_summary[].tax_amount_display` |

Al imprimir recibos, se deben priorizar los campos `_display`. Los campos numéricos deben usarse únicamente para secciones condicionales o salidas legibles por máquina.

### Campos adaptados a la visualización de impuestos {#tax-display-aware-fields}

Varios campos tienen variantes con impuestos incluidos y excluidos, además de un valor auxiliar para la visualización. Este valor sigue la configuración de visualización de impuestos del carrito de la tienda.

| Campo auxiliar | Campo con impuestos incluidos | Campo con impuestos excluidos |
|-------------------|-----------------|-----------------|
| `lines[].regular_price` | `lines[].regular_price_incl` | `lines[].regular_price_excl` |
| `lines[].selling_price` | `lines[].selling_price_incl` | `lines[].selling_price_excl` |
| `lines[].unit_savings` | `lines[].unit_savings_incl` | `lines[].unit_savings_excl` |
| `lines[].line_regular_total` | `lines[].line_regular_total_incl` | `lines[].line_regular_total_excl` |
| `lines[].line_selling_total` | `lines[].line_selling_total_incl` | `lines[].line_selling_total_excl` |
| `lines[].line_savings` | `lines[].line_savings_incl` | `lines[].line_savings_excl` |
| `lines[].unit_price` | `lines[].unit_price_incl` | `lines[].unit_price_excl` |
| `lines[].unit_subtotal` | `lines[].unit_subtotal_incl` | `lines[].unit_subtotal_excl` |
| `lines[].line_subtotal` | `lines[].line_subtotal_incl` | `lines[].line_subtotal_excl` |
| `lines[].discounts` | `lines[].discounts_incl` | `lines[].discounts_excl` |
| `lines[].line_total` | `lines[].line_total_incl` | `lines[].line_total_excl` |
| `fees[].total` | `fees[].total_incl` | `fees[].total_excl` |
| `shipping[].total` | `shipping[].total_incl` | `shipping[].total_excl` |
| `discounts[].total` | `discounts[].total_incl` | `discounts[].total_excl` |
| `totals.subtotal` | `totals.subtotal_incl` | `totals.subtotal_excl` |
| `totals.discount_total` | `totals.discount_total_incl` | `totals.discount_total_excl` |
| `totals.sale_savings_total` | `totals.sale_savings_total_incl` | `totals.sale_savings_total_excl` |
| `totals.total_saved` | `totals.total_saved_incl` | `totals.total_saved_excl` |
| `totals.total` | `totals.total_incl` | `totals.total_excl` |

### Objetos de fecha {#date-objects}

Los campos de fecha son objetos con varias variantes preformateadas. Esto evita tener que dar formato a las fechas dentro de Mustache.

| Campo | Descripción |
|-------|-------------|
| `datetime`, `date`, `time` | Cadenas de fecha/hora predeterminadas |
| `datetime_short`, `datetime_long`, `datetime_full` | Formatos combinados adaptados a la configuración regional |
| `date_short`, `date_long`, `date_full` | Formatos solo de fecha adaptados a la configuración regional |
| `date_ymd`, `date_dmy`, `date_mdy` | Formatos de fecha con orden fijo |
| `weekday_short`, `weekday_long` | Nombres de los días |
| `day`, `month`, `month_short`, `month_long`, `year` | Componentes individuales de la fecha |

Objetos de fecha disponibles: `order.created`, `order.paid`, `order.completed`, `order.printed` y `refunds[].date`. `order.printed` se actualiza en el momento del renderizado, lo que resulta útil para las reimpresiones.

## Relación entre los precios {#price-model}

Una línea de producto contiene varios precios, y los nombres se entienden mejor al verlos sobre el importe. Esta es la línea de espresso del pedido de muestra: un producto de $17.00 en oferta por $14.50, más un cupón del 10%:

  scaleLabel="regular price 17.00"
  segments={[
    { kind: 'paid', amount: 13.05, label: "13.05 paid" },
    { kind: 'coupon', amount: 1.45, label: "1.45" },
    { kind: 'savings', amount: 2.5, label: "2.50" },
  ]}
  summary={[
    { label: "Ahorro por ofertas en todo el pedido", value: '`totals.sale_savings_total` = 5.00' },
    { label: "Todos los descuentos de cupones del pedido", value: '`totals.discount_total` = 5.28' },
    { label: "Ahorro y descuentos sin solapamiento heredado", value: '`totals.total_saved` = 10.28' },
  ]}

El ahorro por ofertas y los descuentos de cupones son conceptos distintos: el ahorro por ofertas compara el precio de venta con el precio normal registrado, mientras que `discounts` representa el cálculo de cupones de WooCommerce. Los totales e informes de pedidos de WooCommerce solo contienen la parte correspondiente al cupón; por eso `total_saved` es la cifra única de cara al cliente que combina ambos importes.

### Mostrar el precio habitual y el ahorro {#displaying-regular-price-and-savings}

Para un diseño con precio unitario, muestre el precio habitual registrado, el precio de venta y el ahorro de esta manera:

```mustache
{{#lines}}
  {{#unit_savings}}
    <span style="text-decoration: line-through;">{{regular_price_display}}</span>
    <span>{{selling_price_display}}</span>
    <span>{{i18n.savings}}: -{{unit_savings_display}}</span>
  {{/unit_savings}}
{{/lines}}
```

Use los campos del total de línea cuando la cantidad sea relevante:

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    <span>{{i18n.savings}}: -{{line_savings_display}}</span>
  {{/line_savings}}
{{/lines}}
```

`selling_price` es el precio antes de los cupones. Use `unit_price` o `line_total` para el importe final después de los descuentos de WooCommerce.

:::note Reimpresión de pedidos creados antes de v1.9.0
Es posible que los pedidos antiguos de WCPOS ya incluyan en `discounts` la reducción del precio habitual al precio de venta. Si su plantilla personalizada muestra tanto los ahorros por línea como los descuentos por línea, utilice `savings_in_discounts` para evitar mostrar dos veces la misma reducción:

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    {{^savings_in_discounts}}
      <span>{{i18n.savings}}: -{{line_savings_display}}</span>
    {{/savings_in_discounts}}
  {{/line_savings}}
  {{#discounts}}
    <span>{{i18n.discount}}: -{{discounts_display}}</span>
  {{/discounts}}
{{/lines}}
```

Si la plantilla no muestra una fila de `discounts` por línea, siga mostrando `line_savings` aunque `savings_in_discounts` sea true. Las plantillas incluidas gestionan esta distinción automáticamente.
:::
