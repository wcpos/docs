Las plantillas HTML sin lógica de WCPOS y las plantillas XML térmicas se generan a partir de la misma carga útil canónica de recibos. Utilice rutas con puntos de Mustache, como `{{order.number}}`, `{{store.name}}` y `{{totals.total_display}}`. Los arreglos se generan mediante secciones:

```mustache
{{#lines}}
  {{name}} x {{qty}} — {{line_total_display}}
{{/lines}}
```

El contrato canónico lo genera el constructor de datos de recibos de WCPOS en el servidor y lo replica el renderizador de recibos sin conexión de la aplicación. Los recibos se abren de inmediato con datos locales y luego se actualizan con la respuesta del servidor cuando está disponible, por lo que las plantillas personalizadas deben usar los campos siguientes en lugar de los métodos de pedido de PHP.

La versión v1.1 de Datos de recibos añade campos con el precio normal registrado, el precio de venta previo al cupón y el ahorro de cada línea de producto. También proporciona totales de ahorro del pedido, incluido el valor **Total ahorrado**, que combina el ahorro respecto al precio normal con los descuentos de WooCommerce sin modificar los totales ni los informes del pedido.

La versión v1.2 de Datos de recibos añade `discount_type` a cada fila de descuento: el tipo de cupón de WooCommerce que origina el descuento.

## Ampliar los datos del recibo {#extending}

WCPOS mantiene el contrato anterior independiente del proveedor. Cuando un plugin necesita que el recibo incluya algo que WooCommerce no modela, lo añade mediante el filtro `woocommerce_pos_receipt_data`, igual que los plugins filtran los propios totales de pedido de WooCommerce. El filtro se ejecuta en todos los recibos que genera el servidor: recibos en directo, instantáneas fiscales en el momento del pago, descargas PDF y plantillas PHP heredadas.

```php
add_filter( 'woocommerce_pos_receipt_data', function ( array $data, WC_Abstract_Order $order, string $mode ) {
    foreach ( $data['discounts'] as &$row ) {
        if ( 'smart_coupon' === $row['discount_type'] ) {
            $row['gift_card'] = true;
        }
    }
    return $data;
}, 10, 3 );
```

A continuación, una plantilla puede comprobar la nueva clave como cualquier otra sección:

```
{{#discounts}}
  {{#gift_card}}Gift Card{{/gift_card}}{{^gift_card}}{{i18n.discount}}{{/gift_card}}{{#label}}: {{label}}{{/label}}
{{/discounts}}
```

Las claves definidas en el esquema deben conservar los tipos documentados. Las claves añadidas no forman parte del esquema, por lo que no aparecen en el selector de campos del editor de plantillas; además, las instantáneas fiscales solo incluyen lo que añadió el filtro en el momento del pago del pedido. El filtro está disponible desde WCPOS 1.10.8.

## Reglas de renderizado {#rendering-rules}

### Campos de moneda {#currency-fields}

Los campos monetarios numéricos se conservan como números y el renderizador añade campos `_display` adaptados a la configuración regional para usarlos en las plantillas:

| Campo numérico | Campo de visualización |
|---------------|---------------|
| `totals.total` | `totals.total_display` |
| `lines[].line_total` | `lines[].line_total_display` |
| `payments[].amount` | `payments[].amount_display` |
| `tax_summary[].tax_amount` | `tax_summary[].tax_amount_display` |

Para imprimir recibos, prefiera los campos `_display`. Utilice campos numéricos solo en secciones condicionales o para generar salidas legibles por máquina.

### Campos adaptados a la visualización de impuestos {#tax-display-aware-fields}

Varios campos tienen variantes con impuestos incluidos y excluidos, además de un valor auxiliar para la visualización. Este valor sigue la configuración de visualización de impuestos del carrito de la tienda.

| Campo auxiliar | Campo con impuestos incluidos | Campo con impuestos excluidos |
|-------------------|-----------------|-----------------|
| `lines[].regular_price` | `lines[].regular_price_incl` | `lines[].regular_price_excl` |
| `lines[].selling_price` | `lines[].selling_price_incl` | `lines[].selling_price_excl` |
| `lines[].unit_savings` | `lines[].unit_savings_incl` | `lines[].unit_savings_excl` |
| `lines[].line_regular_total` | `lines[].line_regular_total_incl` | `lines[].line_regular_total_excl` |
| `lines[].line_selling_total` | `lines[].line_selling_total_incl` | `lines[].line_selling_total_excl` |
| `lines[].line_savings` | `lines[].line_savings_incl` | `lines[].line_savings_excl` |
| `lines[].unit_price` | `lines[].unit_price_incl` | `lines[].unit_price_excl` |
| `lines[].unit_subtotal` | `lines[].unit_subtotal_incl` | `lines[].unit_subtotal_excl` |
| `lines[].line_subtotal` | `lines[].line_subtotal_incl` | `lines[].line_subtotal_excl` |
| `lines[].discounts` | `lines[].discounts_incl` | `lines[].discounts_excl` |
| `lines[].line_total` | `lines[].line_total_incl` | `lines[].line_total_excl` |
| `fees[].total` | `fees[].total_incl` | `fees[].total_excl` |
| `shipping[].total` | `shipping[].total_incl` | `shipping[].total_excl` |
| `discounts[].total` | `discounts[].total_incl` | `discounts[].total_excl` |
| `totals.subtotal` | `totals.subtotal_incl` | `totals.subtotal_excl` |
| `totals.discount_total` | `totals.discount_total_incl` | `totals.discount_total_excl` |

| `totals.total` | `totals.total_incl` | `totals.total_excl` |

### Objetos de fecha {#date-objects}

Los campos de fecha son objetos con varias variantes preformateadas. Esto evita tener que dar formato a las fechas dentro de Mustache.

| Campo | Descripción |
|-------|-------------|
| `datetime`, `date`, `time` | Cadenas de fecha y hora predeterminadas |
| `datetime_short`, `datetime_long`, `datetime_full` | Formatos combinados adaptados a la configuración regional |
| `date_short`, `date_long`, `date_full` | Formatos de fecha sin hora adaptados a la configuración regional |
| `date_ymd`, `date_dmy`, `date_mdy` | Formatos de fecha con orden fijo |
| `weekday_short`, `weekday_long` | Nombres de los días |
| `day`, `month`, `month_short`, `month_long`, `year` | Partes individuales de la fecha |

Objetos de fecha disponibles: `order.created`, `order.paid`, `order.completed`, `order.printed` y `refunds[].date`. `order.printed` se actualiza en el momento del renderizado, lo que resulta útil para las reimpresiones.

## Cómo se relacionan los precios {#price-model}

Una línea de producto incluye varios precios, cuyos nombres se entienden al verlos reflejados en los importes. Esta es la línea de espresso del pedido de ejemplo: un producto de $17.00 rebajado a $14.50, con un cupón adicional del 10 %:

<PriceFlow
  caption="Granos de espresso — una unidad (el pedido contiene dos)"
  scaleLabel="precio normal 17.00"
  segments={[
    { kind: 'paid', amount: 13.05, label: "13.05 pagado" },
    { kind: 'coupon', amount: 1.45, label: "1.45" },
    { kind: 'savings', amount: 2.5, label: "2.50" },
  ]}
  summary={[
    { label: "Ahorro por rebajas en todo el pedido", value: '`totals.sale_savings_total` = 5.00' },
    { label: "Descuentos de cupones en todo el pedido", value: '`totals.discount_total` = 5.28' },
    { label: "Ahorros + descuentos, sin solapamiento heredado", value: '`totals.total_saved` = 10.28' },
  ]}
/>

Los ahorros por rebajas y los descuentos de cupones son conceptos distintos: los ahorros por rebajas comparan el precio de venta con el precio normal registrado, mientras que `discounts` corresponde al cálculo de cupones propio de WooCommerce. Los totales y los informes de pedidos de WooCommerce solo incluyen la parte de los cupones; por eso existe `total_saved` como cifra única para el cliente que combina ambos conceptos.

### Mostrar el precio normal y los ahorros {#displaying-regular-price-and-savings}

En un diseño con precio por unidad, muestre el precio normal registrado, el precio de venta y el ahorro de esta forma:

```mustache
{{#lines}}
  {{#unit_savings}}
    <span style="text-decoration: line-through;">{{regular_price_display}}</span>
    <span>{{selling_price_display}}</span>
    <span>{{i18n.savings}}: -{{unit_savings_display}}</span>
  {{/unit_savings}}
{{/lines}}
```

Utilice los campos de total de línea cuando la cantidad sea relevante:

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    <span>{{i18n.savings}}: -{{line_savings_display}}</span>
  {{/line_savings}}
{{/lines}}
```

`selling_price` es el precio antes de los cupones. Utilice `unit_price` o `line_total` para el importe final tras los descuentos de WooCommerce.

:::note Reimpresión de pedidos creados antes de v1.9.0
Es posible que los pedidos antiguos de WCPOS ya incluyan en `discounts` la reducción entre el precio normal y el precio de venta. Si su plantilla personalizada imprime tanto los ahorros como los descuentos de línea, utilice `savings_in_discounts` para no mostrar dos veces la misma reducción:

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    {{^savings_in_discounts}}
      <span>{{i18n.savings}}: -{{line_savings_display}}</span>
    {{/savings_in_discounts}}
  {{/line_savings}}
  {{#discounts}}
    <span>{{i18n.discount}}: -{{discounts_display}}</span>
  {{/discounts}}
{{/lines}}
```

Si la plantilla no imprime una fila de `discounts` a nivel de línea, siga mostrando `line_savings` aunque `savings_in_discounts` sea verdadero. Las plantillas incluidas gestionan esta distinción automáticamente.
:::
