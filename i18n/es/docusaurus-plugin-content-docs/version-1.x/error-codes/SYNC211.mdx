## Qué significa esto {#what-this-means}

La tienda rechazó un campo de un registro. En ocasiones, este código también indica que la tienda rechazó una solicitud de ajustes o autenticación.

Si se refiere a un registro, corrija el campo indicado y vuelva a intentarlo; la copia local seguirá disponible hasta que se sincronice. De lo contrario, siga el mensaje de la tienda para la solicitud indicada.

## Sus datos {#your-data}

Si se trataba de un cambio en un registro, sigue guardado en este dispositivo y aún no ha llegado a su tienda. Una solicitud de ajustes o autenticación no deja nada que guardar.

## Resolución de problemas {#troubleshoot}

1. Expanda la entrada del registro y compruebe primero el endpoint y la respuesta del servidor: este código también puede representar un HTTP 400 procedente de una solicitud de ajustes, de autenticación o de otro tipo que no afecte a registros.
2. Si el contexto indica un registro o un campo, edite ese campo en el POS —las causas habituales son un valor fuera de rango, un formato rechazado o una opción obligatoria dejada vacía— y reinténtelo.
3. Si no es una solicitud de registro, siga el mensaje del servidor para el endpoint indicado. Las herramientas de desarrollo del navegador (pestaña Red) —o **Avanzado → Alternar herramientas para desarrolladores** en la aplicación de escritorio— muestran la respuesta cuando los detalles no aparecen en el registro del POS.
4. **Administrador del sitio:** si un campo indicado parece correcto en el POS, compárelo con el mismo registro en WP Admin: la validación añadida por un plugin en la tienda puede rechazar valores que el POS considera correctos.
