## Qué significa {#what-this-means}

Una caché situada delante de la tienda está reproduciendo las respuestas de la API de una persona para todo el mundo.

Una capa de caché está sirviendo respuestas almacenadas de la API REST sin comprobar quién las solicita: la aplicación envió dos sondeos autenticados de forma diferente y recibió la respuesta del primer sondeo las dos veces. En una tienda en funcionamiento esto significa que un cajero podría ver los datos de otro, así que la conexión se bloquea hasta que la caché excluya la API de la tienda. Se trata de un problema de la capa de hosting — WordPress en sí siempre responde por usuario.

## Sus datos {#your-data}

Los datos de este dispositivo pueden estar en riesgo — no borre los datos locales. Si esto persiste, exporte los diagnósticos y contacte con el soporte de WCPOS.

## Solución de problemas {#troubleshoot}

1. Excluya las rutas de la API REST de la tienda (/wp-json/ y /?rest_route=) de la caché de páginas — en LiteSpeed desactive la caché de REST o añada una regla de no-caché; en WP Engine amplíe la exclusión de WooCommerce a /wp-json/wcpos; en Sucuri configure el nivel de caché para que respete Cache-Control.
2. La API de la tienda ya envía Cache-Control: no-store y Vary: Authorization — la capa de caché los está ignorando; oriente al host hacia esas cabeceras.
3. Tras cambiar los ajustes de caché, purgue la caché antes de volver a conectarse.
