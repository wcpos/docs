## Qué significa {#what-this-means}

La caché de su proveedor de alojamiento puede mostrar a una persona datos de la tienda destinados a otra.

No se pierde nada de este dispositivo. Pida a su proveedor de alojamiento que deje de almacenar en caché la API de la tienda (tanto las direcciones `/wp-json/` como `?rest_route=`). Si WCPOS no se conectó, vuelva a conectarlo después.

Una capa de caché sirve respuestas REST API almacenadas sin comprobar quién las solicita: la aplicación envió dos comprobaciones con autenticaciones distintas y recibió ambas veces la respuesta de la primera. En una tienda activa, esto significa que un cajero podría ver los datos de otra persona. Es un problema de la capa de alojamiento: WordPress siempre responde según el usuario.

Cuando esto ocurre, la aplicación vuelve a intentarlo con una clave de caché única en cada solicitud. Si así se demuestra que la clave evita la caché, WCPOS se conecta y sigue enviándola; esta entrada advierte entonces que aún hay que corregir la caché. Si no se puede demostrar que la conexión es segura, WCPOS no se conecta hasta que se corrija la caché.

## Sus datos {#your-data}

No se pierde nada de este dispositivo. Si WCPOS no pudo demostrar que la conexión era segura, no se conecta para evitar mostrar los datos de una persona a otra; todo lo que ya está en este dispositivo permanece aquí y se envía cuando se conecte.

## Solución de problemas {#troubleshoot}

**Para su proveedor de alojamiento o administrador del sitio:** la caché debe corregirse en el servidor, aunque WCPOS se haya conectado al sortear el problema:

1. Excluya las rutas REST API de la tienda (/wp-json/ y /?rest_route=) de la caché de páginas. En LiteSpeed, desactive la caché REST o añada una regla no-cache; en WP Engine, amplíe la exclusión de WooCommerce para incluir /wp-json/wcpos y el formato ?rest_route=; en Sucuri, configure el nivel de caché para que respete Cache-Control.
2. La API de la tienda ya envía Cache-Control: no-store y Vary: Authorization — la capa de caché los está ignorando; oriente al host hacia esas cabeceras.
3. Después de cambiar la configuración de caché, purgue la caché. Si WCPOS no se conectó, vuelva a conectarlo.
