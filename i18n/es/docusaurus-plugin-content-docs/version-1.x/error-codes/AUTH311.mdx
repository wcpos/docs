## Qué significa esto {#what-this-means}

La ruta de tienda de WCPOS no está disponible.

Solicite al administrador del sitio que compruebe si un plugin de seguridad o proxy está eliminando los encabezados de solicitud de WCPOS.

## Qué hacer {#what-to-do}

Es necesario cambiar una configuración para que esto funcione. Vuelva a intentarlo después de realizar el cambio anterior; volver a intentarlo sin hacerlo fallará de la misma manera.

## Sus datos {#your-data}

No se ven afectados los datos de pedidos ni de productos. Si el problema continúa, solicite ayuda a la persona que administra su sitio de WordPress.

## Solución de problemas {#troubleshoot}

1. Confirme que WCPOS está activo en el sitio: WP Admin → Plugins.
2. Pruebe la ruta directamente: abra la dirección /wp-json/ de su tienda en un navegador; una página HTML o un error 404 en lugar de JSON indica que la propia API REST está bloqueada.
3. Consulte al administrador del sitio si un plugin de seguridad, proxy o CDN está eliminando los encabezados de solicitudes de WCPOS o bloqueando /wp-json/; las reglas de firewall y las opciones de refuerzo para desactivar la API REST suelen ser las causas habituales.
4. En algunos proveedores de alojamiento, volver a guardar los enlaces permanentes (Ajustes → Enlaces permanentes → Guardar) restaura las rutas REST que faltan.

## Dónde buscar {#where-to-look}

Cada aparición de este código se registra en el dispositivo que la generó. Abra **Estado de la tienda → Registros** (el icono de pulso cardíaco situado en la parte inferior del panel de navegación), busque la entrada marcada con este código y expándala: la fila expandida muestra el motivo en lenguaje sencillo y el contexto capturado en el momento del error; para cualquier caso que haya implicado una solicitud a su tienda, esto incluye el propio código de error del servidor (`serverCode`), el `status` HTTP y el `endpoint`. Al informar de un problema, use **Copiar información de depuración** en la parte superior de la pantalla Registros (**Compartir información de depuración** en teléfonos y tabletas) en lugar de capturas de pantalla: incluye la versión de la aplicación, el estado de la conexión y los errores más recientes. Los registros se conservan durante un máximo de 30 días, por lo que conviene recopilarlos mientras el problema sea reciente.

Además del registro de la aplicación, este error puede dejar indicios en:

- **Inspector de red** (web y escritorio): abra las herramientas para desarrolladores; pulse F12 en el navegador o seleccione **Avanzado → Alternar herramientas para desarrolladores** en el menú de la aplicación de escritorio; después, seleccione la pestaña **Red** y repita la acción. La solicitud que falla muestra el estado HTTP y el cuerpo de respuesta sin procesar, incluidas las páginas de error que nunca llegan al registro de POS.
- **WooCommerce → Estado → Registros**: en el sitio de WordPress, revise el archivo `fatal-errors-*.log` más reciente para detectar bloqueos de PHP, además de cualquier origen de registro con el nombre de un plugin implicado en el error. Un error de la clase 500 procedente de la tienda casi siempre deja aquí su causa.
