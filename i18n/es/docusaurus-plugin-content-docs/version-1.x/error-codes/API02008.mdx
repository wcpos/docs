# API02008: Refresh Token no válido {#api02008-refresh-token-invalid}

## Qué Significa Esto {#what-this-means}

El refresh token almacenado por el POS no es reconocido por el servidor. Los refresh tokens se utilizan para obtener nuevos access tokens sin requerir que vuelvas a iniciar sesión.

## Causas Comunes {#common-causes}

- **Token revocado** — Un administrador invalidó tu sesión
- **Cambios en los secretos del servidor** — Las claves de seguridad de WordPress fueron actualizadas
- **Corrupción de datos** — El token se corrompió en el almacenamiento
- **Múltiples inicios de sesión** — Iniciar sesión en otro lugar puede haber invalidado este token

## Cómo Solucionarlo {#how-to-fix}

### 1. Inicia Sesión Nuevamente {#1-log-in-again}

Dado que el refresh token es inválido, necesitarás autenticarte de nuevo:
1. Cierra sesión en el POS
2. Ingresa tu nombre de usuario y contraseña
3. Esto generará nuevos tokens válidos

### 2. Verifica Sesiones Revocadas {#2-check-for-revoked-sessions}

Si un administrador revocó sesiones:
- Esto es una práctica de seguridad normal
- Simplemente inicia sesión nuevamente
- Tu nueva sesión funcionará normalmente

### 3. Verifica Cambios en el Servidor {#3-check-server-changes}

Si esto afecta a todos los usuarios:
- Las sales/claves de WordPress pueden haber cambiado
- La configuración del plugin JWT puede haber sido modificada
- Contacta a tu administrador de servidor

### 4. Borra Datos Almacenados {#4-clear-stored-data}

Si sigue teniendo problemas, y solo después de realizar la siguiente comprobación:

:::warning Compruebe primero si hay trabajo sin guardar
Al borrar los datos locales o reinstalar la aplicación, se elimina todo lo que haya en este dispositivo y aún no haya llegado a su tienda, incluidas las ventas realizadas sin conexión, los carritos abiertos y los cambios que no se guardaron. Antes de borrar nada, abra **Salud de la tienda → Base de datos** y compruebe que no haya elementos retenidos ni elementos que nunca hayan llegado a su servidor; después, revise **Salud de la tienda → Registros** para confirmar que haya **0 registros bloqueados** y **0 cambios pendientes de envío**. A continuación, finalice o anote cada carrito abierto. Si su WCPOS no tiene una página de Salud de la tienda, actualice primero WCPOS y vuelva a comprobarlo. Si aparece algún elemento o hay algo pendiente, o no puede comprobarlo, no borre nada: consulte con el propietario de su tienda o contacte con el servicio de asistencia.
:::

- Borra los datos de la aplicación POS
- Elimina las credenciales en caché
- Comienza con un inicio de sesión limpio
