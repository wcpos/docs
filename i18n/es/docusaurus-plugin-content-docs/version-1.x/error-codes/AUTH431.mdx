## Qué significa esto {#what-this-means}

La API REST de la tienda no respondió en ninguna forma de dirección que esta aplicación pueda usar.

La aplicación intentó acceder a la API REST de la tienda mediante su dirección habitual (/wp-json/...) y mediante la dirección alternativa integrada de WordPress (/?rest_route=...), pero ninguna respondió. Es posible que el sitio web de la tienda esté disponible; el problema es específicamente que no se puede acceder a la API REST, normalmente porque un plugin de seguridad la oculta o una regla de firewall la bloquea.

## Qué hacer {#what-to-do}

Exporte los diagnósticos y contacte con el soporte. Vuelva a intentarlo después de realizar el cambio anterior; volver a intentarlo sin hacerlo producirá el mismo error.

## Sus datos {#your-data}

No se ven afectados los datos de pedidos ni de productos.

## Solución de problemas {#troubleshoot}

1. Si un plugin de seguridad oculta o cambia el nombre de /wp-json/ (por ejemplo, WP Hide), permita también el formato integrado de WordPress /?rest_route=; la aplicación recurre a él automáticamente.
2. Compruebe las reglas del firewall (WAF) para detectar cualquier coincidencia con wp-json o rest_route y permita el acceso a la propia REST API de la tienda.
3. Compruebe desde un navegador: https://your-store.com/?rest_route=/ debería devolver JSON, no una página 403 ni la página de inicio del sitio.
4. Si el servidor está detrás de una página de mantenimiento o una comprobación contra bots, las solicitudes REST pueden responder con una página HTML; desactive la comprobación para la REST API.

## Dónde buscar {#where-to-look}

Cuando WCPOS puede guardar este error, se registra en el dispositivo que lo generó. Abra **Estado de la tienda → Registros** (el icono de pulso cardíaco en la parte inferior del panel de navegación), busque la entrada marcada con este código y expándala: la fila expandida muestra el motivo en lenguaje sencillo y el contexto capturado en el momento del fallo. En el caso de una solicitud de tienda, ese contexto puede incluir el propio código de error del servidor (`serverCode`), el `status` HTTP o el `endpoint`; los campos mostrados dependen de dónde se produjo el fallo. Al informar de un problema, utilice **Copiar información de depuración** en la parte superior de la pantalla Registros (**Compartir información de depuración** en teléfonos y tabletas) en lugar de capturas de pantalla: incluye la versión de la aplicación, el estado de conexión y los errores más recientes. Los registros se conservan durante un máximo de 30 días, así que recopílelos mientras el problema sea reciente. Copie también cualquier error de la consola del navegador que apareciera antes de que el POS pudiera escribir su propia entrada de registro.
