## Qué significa esto {#what-this-means}

La tienda no devolvió ningún resultado del proceso de pago, por lo que se desconoce el estado del pedido.

Compruebe si se creó el pedido antes de intentar finalizar la compra de nuevo.

## Qué hacer {#what-to-do}

Revise los detalles siguientes antes de volver a intentarlo. No lo intente de nuevo hasta haber confirmado lo que ocurrió realmente; volver a intentarlo a ciegas puede crear un cargo o pedido duplicado.

## Sus datos {#your-data}

No se pudo confirmar el resultado; verifíquelo antes de volver a intentarlo. Si el problema persiste, exporte los diagnósticos y contacte con el soporte de WCPOS.

## Solución de problemas {#troubleshoot}

1. Compruebe WooCommerce → Pedidos en WP Admin antes de realizar cualquier otra acción: una respuesta vacía suele indicar que el pedido se creó, pero la confirmación nunca llegó.
2. El inspector de red muestra la solicitud de pago: un estado correcto con un cuerpo vacío o truncado indica que un plugin o búfer del servidor está cortando la respuesta.
3. Compruebe WooCommerce → Estado → Registros para detectar un error fatal durante el pago: un bloqueo de PHP después de crear el pedido produce exactamente este resultado.
4. Vuelva a intentar el pago solo después de confirmar que no se ha creado ningún pedido.

## Dónde buscar {#where-to-look}

Cada aparición de este código se registra en el dispositivo que lo generó. Abra **Estado de la tienda → Registros** (el icono de pulso cardíaco situado en la parte inferior del panel de navegación), busque la entrada marcada con este código y expándala: la fila expandida muestra el motivo en lenguaje sencillo y el contexto capturado en el momento del error. Para cualquier caso que implique una solicitud a la tienda, esto incluye el código de error propio del servidor (`serverCode`), el `status` HTTP y el `endpoint`. Al informar de un problema, use **Copiar información de depuración** en la parte superior de la pantalla Registros (**Compartir información de depuración** en teléfonos y tabletas) en lugar de capturas de pantalla: reúne la versión de la aplicación, el estado de la conexión y los errores más recientes. Los registros se conservan durante un máximo de 30 días, por lo que conviene recopilarlos mientras el problema sea reciente.

Además del registro de la aplicación, este error puede dejar evidencias en:

- **Inspector de red** (web y escritorio): abra las herramientas para desarrolladores; pulse F12 en el navegador o seleccione **Avanzado → Alternar herramientas para desarrolladores** en el menú de la aplicación de escritorio. Seleccione la pestaña **Red** y repita la acción. La solicitud fallida muestra el estado HTTP y el cuerpo de respuesta sin procesar, incluidas las páginas de error que nunca llegan al registro de POS.
- **WooCommerce → Estado → Registros**: en el sitio de WordPress, revise el `fatal-errors-*.log` más reciente para detectar bloqueos de PHP, además de cualquier fuente de registro que lleve el nombre de un plugin implicado en el error. Un error de clase 500 procedente de la tienda casi siempre deja aquí su causa.
- **El registro de errores de PHP del sitio**: si la página de registros de WooCommerce no muestra nada para la hora del error, solicite al proveedor de alojamiento el registro de errores de PHP; algunos errores fatales solo se capturan en el nivel del servidor.
