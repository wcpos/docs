# Pasarela Windcave Terminal {#windcave-terminal-gateway}

La pasarela Windcave Terminal permite aceptar pagos con tarjeta en persona en un terminal Windcave mediante Windcave HIT. Los pagos se inician desde WCPOS y se completan en el terminal; la confirmación se registra en el pedido de WooCommerce.

:::warning Novedad en 0.1.0 — pendiente de certificación de Windcave
0.1.0 es la primera versión. Windcave exige la certificación de calidad (QA) de una integración antes de usarla en producción, y esta integración aún no está certificada. Utilícela con credenciales de Windcave **UAT** (pruebas) hasta que se complete la certificación. Windcave asigna el **Vendor ID** durante la certificación.
:::

## Cómo funciona {#how-it-works}

La pasarela utiliza Windcave **HIT (Host Initiated Transaction)** mediante HTTPS. **Environment** selecciona el punto de conexión UAT o de producción, y cada terminal se identifica mediante el **Station ID** asignado por Windcave.

Al iniciar un pago, se envían al terminal el total completo del pedido y la moneda. La página de pago consulta Windcave cada **1,5 segundos** y muestra las indicaciones y los botones disponibles del terminal. Las **notificaciones de resultados (FPRN)** opcionales permiten que Windcave notifique al sitio como alternativa a las consultas periódicas.

## Configuración {#setup}

<Steps>
  <StepCard number="1" title="Instalar Windcave Terminal para WooCommerce">

Descargue el **archivo zip del plugin** (no el zip del código fuente de GitHub) desde la [página de versiones de GitHub](https://github.com/wcpos/windcave-terminal-for-woocommerce/releases). Súbalo mediante `Plugins > Añadir nuevo > Subir plugin` y actívelo con WooCommerce instalado y activo.

La activación requiere **PHP 7.4+** y la **extensión PHP DOM (php-xml)**. Si falta alguno de estos requisitos, se rechazará la activación y se mostrará un mensaje.

  </StepCard>
  <StepCard number="2" title="Obtener credenciales HIT de Windcave">

Solicite a Windcave un **nombre de usuario HIT**, una **clave HIT** y un **Station ID** por terminal. Solicite una cuenta de desarrollo mediante el [formulario de requisitos de integración](https://www.windcave.com/merchant-attended-developer-hit) de Windcave.

Las credenciales UAT y de producción son distintas. Utilice las credenciales UAT mientras esta integración esté pendiente de certificación.

  </StepCard>
  <StepCard number="3" title="Configurar la pasarela">

1. Vaya a `WP Admin > WooCommerce > Ajustes > Pagos` y abra **Windcave Terminal**
2. Establezca **Environment** en `UAT (testing)` (valor predeterminado). `Production` se utiliza después de la certificación de Windcave y con credenciales de producción
3. Introduzca el **nombre de usuario HIT** y la **clave HIT** que le haya asignado Windcave
4. Introduzca sus **Station IDs**, uno por línea
5. *(Opcional)* Establezca un **Default Station ID**. Active **Lock terminal selection** para utilizar siempre ese valor predeterminado e impedir que los cajeros lo cambien
6. Deje **Vendor ID** vacío hasta que Windcave le asigne uno durante la certificación
7. Guarde la configuración

  </StepCard>
  <StepCard number="4" title="Activar las notificaciones de resultados (opcional)">

Active **Result notifications (FPRN)** y guarde para solicitar a Windcave que notifique a su sitio cuando esté listo el resultado de una transacción. Es una alternativa a las consultas periódicas.

  </StepCard>
  <StepCard number="5" title="Activar en WCPOS" isLast>

1. Vaya a `WP Admin > POS > Ajustes > Finalizar compra`
2. Busque la pasarela **Windcave Terminal** y actívela para el POS
3. Guarde la configuración

:::note
La casilla **Enable/Disable** de la pantalla de configuración de WooCommerce controla únicamente el pago de la tienda en línea. WCPOS utiliza esta pasarela una vez configurada, independientemente de si esa casilla está marcada.
:::

  </StepCard>
</Steps>

## Referencia de configuración {#settings}

| Configuración | Función |
|---|---|
| **Enable/Disable** | Activa la pasarela para el pago de la tienda en línea. La activación en el POS se controla en `POS > Ajustes > Finalizar compra` |
| **Title** | La etiqueta que se muestra al pagar; de forma predeterminada, `Windcave Terminal` |
| **Description** | La descripción que se muestra al pagar; de forma predeterminada, `Pay in person on the Windcave terminal.` |
| **Environment** | `UAT (testing)` (valor predeterminado) o `Production`. Cada entorno utiliza credenciales HIT distintas; la producción requiere la certificación de Windcave |
| **HIT username** | El nombre de usuario HIT que Windcave asignó para el entorno seleccionado |
| **HIT key** | La clave HIT que Windcave asignó para el entorno seleccionado |
| **Station IDs** | Un Station ID asignado por Windcave en cada línea, uno por terminal |
| **Default Station ID** | La estación preseleccionada, que también se utiliza si no se selecciona ninguna |
| **Lock terminal selection** | Utiliza siempre la estación predeterminada para que los cajeros no puedan cambiarla. Solo tiene efecto si se ha establecido una estación predeterminada |
| **Vendor ID** | Windcave lo asigna durante la certificación. Déjelo vacío hasta que Windcave se lo proporcione |
| **POS name** | El nombre que se envía a Windcave para identificar el POS; de forma predeterminada, `WCPOS` |
| **Result notifications (FPRN)** | Solicita a Windcave que notifique al sitio cuando esté listo el resultado de una transacción, como alternativa a las consultas periódicas. Desactivado de forma predeterminada |
| **Checkout logs** | Muestra herramientas de registro en el panel de pago. Desactivado de forma predeterminada |
| **Log level** | `Off`, `Errors only` o `Debug`. El valor predeterminado es Debug; registra solicitudes y respuestas con las claves y los datos de tarjeta ocultos |
| **Support** | Proporciona **Download support bundle** y un enlace para consultar los registros en `WooCommerce > Status > Registros` |

No hay ningún botón para probar la conexión: las credenciales y los Station IDs se comprueban al procesar el primer pago.

## Uso {#usage}

### Procesar pagos {#processing-payments}

1. **Añadir productos**: Añada productos al carrito en el POS
2. **Seleccionar pasarela**: Elija **Windcave Terminal** como método de pago
3. **Elegir terminal**: Seleccione una estación o utilice la predeterminada bloqueada. La selección es obligatoria si hay dos o más estaciones y no se ha establecido una predeterminada
4. **Iniciar pago**: Haga clic en **Start Terminal Payment** para enviar el total del pedido al terminal
5. **Seguir las indicaciones**: Las indicaciones y los botones disponibles del terminal aparecen en pantalla, incluidas las opciones **YES/NO** para verificar la firma y **CANCEL** cuando esté disponible
6. **Finalización automática**: Tras aprobarse y verificarse el pago, el pedido se completa y el POS muestra el recibo

### Controles de pago {#payment-controls}

- **Start Terminal Payment**: Envía una nueva solicitud de pago a la estación seleccionada
- **Cancel Terminal Payment**: Pulsa el botón **CANCEL** del terminal cuando esté disponible. De lo contrario, cancele la operación en el terminal o aparte el pago cuando aparezca esa opción
- **Apartar el pago**: Aparece tras un **tiempo de espera de 5 minutos**. Deja el intento pendiente para una **comprobación en segundo plano de 10 minutos** para que pueda cobrar de otra forma; no cancela el pago en Windcave
- **Volver a cargar la página**: Reanuda un pago que ya está en curso

### Recibos {#receipts}

El texto del recibo del terminal, si Windcave lo devuelve, se guarda como una **nota privada del pedido** en WooCommerce.

## Reembolsos {#refunds}

Los reembolsos desde WooCommerce **no están disponibles en 0.1.0**. Emita el reembolso en el portal de Windcave (**Payline**) o en el terminal y, después, registre el reembolso **manualmente** en WooCommerce.

## Registros y paquete de soporte {#logs-and-support-bundle}

Encontrará los registros en `WooCommerce > Status > Registros`, en el origen `windcave-terminal`. El nivel de registro predeterminado es **Debug**; registra solicitudes y respuestas de Windcave con las claves y los datos de tarjeta ocultos.

Haga clic en **Download support bundle** en la pantalla de ajustes de la pasarela para descargar un archivo `.json` y envíelo junto con el **número del pedido**. Contiene detalles del entorno, ajustes con la clave HIT y el nombre de usuario ocultos, intentos de pago de hasta 20 pedidos recientes sin los recibos y las últimas 1,000 líneas de los dos archivos de registro más recientes; las líneas del registro pueden incluir texto de recibos del terminal con los números de tarjeta ocultos.

Si WooCommerce utiliza el **controlador de registros de base de datos**, el paquete no contiene líneas de registro. En su lugar, exporte los registros desde `WooCommerce > Status > Registros`.

Active **Checkout logs** para mostrar las herramientas de registro en el panel de pago.

## Alcance y limitaciones {#scope-and-limitations}

:::warning Se requiere certificación
Windcave aún no ha certificado esta integración. Utilice credenciales **UAT** hasta que se complete la certificación de calidad de Windcave; no la utilice en producción antes de obtener la certificación.
:::

- Los reembolsos desde WooCommerce no están disponibles en 0.1.0
- No se admiten propinas, recargos ni retiros de efectivo
- Solo se admiten **monedas con dos decimales**
- Se cobra el **total completo del pedido** en el terminal; no se admite pagar solo una parte del pedido en el terminal
- Los **Station IDs** se introducen manualmente; los terminales no se detectan automáticamente
- La pasarela está diseñada para el POS. En la tienda en línea, solo funciona en la **página de pago del pedido (order-pay)**

## Solución de problemas {#troubleshooting}

### Problemas habituales {#common-issues}

<Accordion>
  <AccordionItem question="Se rechaza la activación: se requiere la extensión PHP DOM (php-xml)">

  - Falta la extensión PHP DOM en el servidor
  - Pida a su proveedor de alojamiento que active **php-xml**. La activación también requiere **PHP 7.4+**

  </AccordionItem>
  <AccordionItem question="No hay Station IDs configurados">

  - El ajuste **Station IDs** está vacío
  - Añada los Station IDs que le haya asignado Windcave en la configuración de la pasarela, uno por línea, y guarde los cambios

  </AccordionItem>
  <AccordionItem question="Las credenciales HIT de Windcave no están configuradas">

  - El **nombre de usuario HIT** o la **clave HIT** están vacíos
  - Introduzca ambos valores en la configuración de la pasarela y guarde los cambios. Asegúrese de que **Environment** coincida con esas credenciales

  </AccordionItem>
  <AccordionItem question="El terminal aún está finalizando una transacción anterior">

  - Hay una transacción anterior en curso en esa estación
  - Complete o cancele la operación en el terminal y vuelva a intentarlo

  </AccordionItem>
  <AccordionItem question="Windcave no tiene registro de esta transacción">

  - Windcave sigue sin tener ningún registro una vez transcurrido el periodo de gracia inicial de 30 segundos
  - Vuelva a iniciar el pago

  </AccordionItem>
  <AccordionItem question="Windcave aprobó un pago, pero no se pudo aplicar">

  - El resultado aprobado no superó las comprobaciones necesarias para completar este pedido
  - Consulte el **portal de Windcave** y las **notas del pedido antes de volver a cobrar**

  </AccordionItem>
  <AccordionItem question="Este pago se inició en un entorno distinto">

  - Se cambió **Environment** mientras el pago estaba en curso
  - Vuelva al entorno en el que se inició el pago o consulte el portal de Windcave

  </AccordionItem>
</Accordion>
