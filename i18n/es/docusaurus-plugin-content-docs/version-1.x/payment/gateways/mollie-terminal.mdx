# Pasarela Mollie Terminal

La pasarela Mollie Terminal le permite aceptar pagos presenciales en hardware [Mollie Terminal](https://www.mollie.com/products/point-of-sale) directamente desde WCPOS. El pago se inicia desde WooCommerce y se completa en el terminal, y la confirmación de Mollie se escribe de vuelta en el pedido.

## Cómo funciona {#how-it-works}

Mollie Terminal utiliza los **pagos `pointofsale` del lado del servidor** de Mollie. Cuando inicia un pago, WooCommerce crea un pago de Mollie para el pedido y Mollie lo envía al terminal seleccionado. El cliente paga en el dispositivo, y **Mollie es la fuente de verdad** del estado del pago y de los reembolsos: los metadatos locales del pedido de WooCommerce son solo una caché.

**Cómo se confirma un pago.** Mientras el pago está en curso, el POS consulta a Mollie (cada 2 segundos de forma predeterminada) y, cuando el terminal confirma, redirige directamente a la página de agradecimiento. También se utilizan los webhooks de Mollie para acelerarlo — y la URL del webhook se configura automáticamente en cada pago, así que **no hay nada que configurar en el panel de Mollie**.

El terminal debe estar registrado y activo en la misma cuenta de Mollie que el plugin.

## Instalación {#setup}

<Steps>
  <StepCard number="1" title="Instalar Mollie Terminal para WooCommerce">

Se puede instalar desde `WP Admin > POS > Ajustes > Extensiones`, o descargar el último **archivo zip del plugin** (no el zip ni el tarball del código fuente de GitHub) desde la [página de versiones de GitHub](https://github.com/wcpos/mollie-terminal-for-woocommerce/releases) y subirlo mediante `Plugins > Añadir nuevo > Subir plugin`.

  </StepCard>
  <StepCard number="2" title="Configurar sus credenciales de Mollie">

1. Vaya a `WP Admin > WooCommerce > Ajustes > Pagos` y abra **Mollie Terminal**
2. Establezca **Modo** en `Live`: los pagos con terminal requieren una cuenta real (consulte [Alcance y limitaciones](#scope-and-limitations))
3. Establezca el **Origen de la clave API** para reutilizar la clave del plugin oficial Mollie Payments for WooCommerce, o utilice la clave introducida en esta pantalla
4. Si introduce la clave aquí, pegue su **clave API real de Mollie** en **Clave API de Mollie**
5. Guarde

:::warning Utilice el modo Live
Los terminales de Mollie solo existen en cuentas **reales** (live), así que la clave API de prueba no puede controlar un terminal. La pantalla de ajustes le avisa cuando está seleccionado el modo de prueba: cambie a `Live` con su clave API real para aceptar pagos. Consulte [Alcance y limitaciones](#scope-and-limitations).
:::

:::note No hace falta ningún Profile ID
Los pagos `pointofsale` no requieren un **Profile ID** de Mollie, y los terminales se muestran de toda la cuenta, así que no hay nada más que pegar.
:::

  </StepCard>
  <StepCard number="3" title="Elegir sus terminales">

1. Elija un **Terminal predeterminado** en el desplegable. La lista se obtiene del entorno de Mollie seleccionado; los terminales inactivos se ocultan, porque Mollie no puede reactivarlos.
2. *(Opcional)* Limite los **Terminales habilitados** a los dispositivos que realmente estén en uso. El predeterminado guardado sigue estando disponible aunque no esté seleccionado aquí; deje el ajuste vacío para permitir todos los terminales activos. Para retirar un terminal, cambie o borre también el **Terminal predeterminado**.
3. *(Opcional)* Active **Bloquear la selección de terminal** para que los cajeros no puedan cambiar de terminal al cobrar: se utiliza siempre el terminal predeterminado, y esto también se aplica en el servidor.
4. Guarde

  </StepCard>
  <StepCard number="4" title="Habilitarla en WCPOS" isLast>

1. Vaya a `WP Admin > POS > Ajustes > Finalizar compra`
2. Busque la pasarela **Mollie Terminal** y habilítela para el POS
3. Guarde los ajustes

:::note
La casilla **Activar/Desactivar** de la pantalla de ajustes de WooCommerce solo controla el pago de la *tienda online*. WCPOS utiliza esta pasarela en cuanto está configurada, esté o no marcada esa casilla.
:::

  </StepCard>
</Steps>

## Referencia de ajustes {#settings}

| Ajuste | Qué hace |
|---|---|
| **Activar/Desactivar** | Habilita la pasarela para el pago de la tienda online (no es necesario para el POS) |
| **Título** / **Descripción** | Etiqueta y texto que se muestran al cliente al pagar |
| **Modo** | `Test` o `Live`. Los pagos con terminal requieren **Live**: la clave API de prueba no puede controlar un terminal |
| **Origen de la clave API** | Utiliza la clave introducida abajo, o reutiliza la clave de prueba/real correspondiente del plugin oficial Mollie Payments for WooCommerce. Si la clave compartida no está disponible, el plugin recurre a la clave de abajo |
| **Clave API de Mollie** | La clave API de prueba o real del modo seleccionado. Se utiliza cuando el **Origen de la clave API** está establecido en la clave introducida aquí, y como alternativa cuando falta la clave compartida |
| **Terminal predeterminado** | El terminal que se utiliza de forma predeterminada al cobrar, elegido en un desplegable de terminales activos del entorno de Mollie seleccionado |
| **Terminales habilitados** | Limita la lista del cobro a los terminales seleccionados. Vacío = todos los terminales activos. El predeterminado guardado siempre está disponible, así que cámbielo o bórrelo también al retirar un terminal |
| **Bloquear la selección de terminal** | Fuerza el terminal predeterminado al cobrar para que los cajeros no puedan cambiarlo (requiere un terminal predeterminado) |
| **Registros de depuración del cobro** | Muestra las herramientas **Ver registros**, **Copiar** y **Borrar** en el panel de pago del cobro. Déjelo desactivado salvo que esté recopilando registros para el soporte; la actividad de pago siempre se registra en `WooCommerce > Estado > Registros` |

La URL del webhook se aplica automáticamente en cada pago, así que no hay ningún campo de webhook que rellenar ni configuración alguna que hacer en el panel de Mollie.

## Uso {#usage}

### Procesar pagos {#processing-payments}

1. **Añadir artículos**: añada productos al carrito en el POS
2. **Seleccionar la pasarela**: elija «Mollie Terminal» como método de pago
3. **Elegir el terminal**: seleccione un terminal en el desplegable (por defecto, el configurado; se oculta si la selección de terminal está bloqueada)
4. **Iniciar el pago**: haga clic en **Iniciar pago con terminal** — Mollie envía el pago al dispositivo
5. **Pago del cliente**: el cliente acerca, inserta o pasa su tarjeta por el terminal. El estado se actualiza en directo: `Enviando al terminal…` → `Esperando al terminal…`
6. **Finalización automática**: cuando el terminal confirma, el pedido se marca como pagado y el POS redirige automáticamente al recibo

### Controles del pago {#payment-controls}

- **Iniciar pago con terminal**: envía una nueva solicitud de pago al terminal seleccionado
- **Cancelar pago**: cancela un pago que siga abierto. Una vez que el pago ha llegado al terminal, Mollie informa de que ya no se puede cancelar, y el cajero lo cancela en el propio dispositivo

### Gestión de pedidos {#order-management}

- **Finalización verificada**: cada webhook, consulta, cancelación y reintento obtiene el estado autorizado de Mollie antes de cambiar un pedido, de modo que los pedidos solo se marcan como pagados con un estado confirmado por Mollie
- **Seguimiento de los pagos**: los intentos de pago se registran como un historial de solo adición en el pedido
- **Generación del recibo**: tras los pagos correctos se generan los recibos estándar del POS

## Reembolsos {#refunds}

Los reembolsos son compatibles. Reembolse un pedido desde la pantalla habitual del pedido en WooCommerce y el reembolso se envía a Mollie. Como Mollie es la fuente de verdad, los reintentos de reembolso se concilian con los identificadores y los metadatos de reembolso de Mollie **antes** de crear otro reembolso, de modo que un reembolso nunca se emite dos veces por accidente.

## Limpieza de pagos obsoletos {#stale-payment-cleanup}

Un pago `pointofsale` de Mollie puede quedarse «abierto» en el lado de Mollie si se abandona un cobro. El plugin cancela automáticamente esos pagos abiertos cuando:

- se agota el tiempo de la consulta automática (5 minutos de forma predeterminada): se envía la cancelación en lugar de dejar el pago pendiente
- el pedido se completa con un método de pago **distinto** (por ejemplo, el cliente paga en efectivo), o el pedido se cancela en WooCommerce
- la página de cobro se cierra a mitad del pago: se lanza una cancelación en la medida de lo posible cuando la pestaña se abandona
- un barrido de WP-Cron se ejecuta cada 10 minutos y cancela o resuelve los pagos que sigan abiertos pasado el umbral de obsolescencia (10 minutos de forma predeterminada), incluidos los casos en que el navegador se cierra o la red se cae antes de que se ejecuten las demás vías de limpieza

Si el pago ya había llegado al terminal, Mollie informa de que no se puede cancelar y el cajero lo cancela en el propio dispositivo; en ese caso, estas limpiezas no tienen ningún efecto y son seguras.

## Alcance y limitaciones {#scope-and-limitations}

:::important Limitación del modo de prueba
Los terminales de Mollie solo existen en cuentas **reales** (live). La clave API de **prueba** de Mollie no puede controlar un terminal físico (ni de iOS/Android), así que los pagos con terminal no se pueden probar de extremo a extremo en modo de prueba. Es una limitación de la plataforma Mollie, no una restricción del plugin: la pantalla de ajustes muestra un aviso cuando está seleccionado el modo de prueba. Utilice el modo **Live** con su clave API real para aceptar pagos con terminal.
:::

:::note Moneda
Los pagos con terminal en el POS están limitados a **EUR** hasta que se confirme una compatibilidad más amplia de monedas en Mollie Terminal.
:::

## Solución de problemas {#troubleshooting}

### Problemas comunes {#common-issues}

<Accordion>
  <AccordionItem question="No aparece ningún terminal en el desplegable">

  - Confirme que el **Modo** está establecido en `Live` y que la clave API efectiva es una clave real: los terminales no existen en las cuentas de prueba
  - Compruebe que el terminal está registrado y **activo** en su cuenta de Mollie; los terminales inactivos se ocultan porque Mollie no puede reactivarlos
  - Asegúrese de que su sitio puede comunicarse con Mollie: la lista se obtiene en vivo a través de la API

  </AccordionItem>

  <AccordionItem question="El pago no se inicia">

  - Confirme que hay un terminal seleccionado (o que hay un **Terminal predeterminado** configurado cuando la selección está bloqueada)
  - Compruebe que el terminal está encendido, en línea y activo en la misma cuenta de Mollie
  - Verifique que la moneda del pedido es **EUR**

  </AccordionItem>

  <AccordionItem question="El terminal agotó el tiempo de espera o el pago se quedó abierto">

  - El plugin intenta cancelar automáticamente los pagos abiertos al agotarse el tiempo de espera (5 minutos de forma predeterminada)
  - Si el pago ya había llegado al terminal y no se puede cancelar automáticamente, cancélelo en el propio dispositivo
  - Después puede iniciar un pago nuevo o cobrar de otra manera

  </AccordionItem>

  <AccordionItem question="El pedido se completó en el terminal pero tarda en actualizarse">

  - El POS consulta a Mollie cada 2 segundos y redirige cuando el pago se confirma; normalmente un webhook lo confirma antes
  - Como Mollie es la fuente de verdad, el pedido se concilia con el estado autorizado de Mollie: no se pierde
  - Revise `WooCommerce > Estado > Registros` por si hay mensajes de la API de Mollie

  </AccordionItem>
</Accordion>
