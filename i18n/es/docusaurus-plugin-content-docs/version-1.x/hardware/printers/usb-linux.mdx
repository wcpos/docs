**Síntoma:** la impresora aparece al buscar, pero la impresión falla con un error de acceso o de permisos.

## Por qué ocurre {#why-it-happens}

En Linux, un dispositivo USB pertenece a `root` salvo que una regla indique lo contrario, así que una aplicación que se ejecuta con su usuario no puede abrirlo. Además, el propio controlador de impresoras del núcleo puede haber reclamado ya el dispositivo.

## Haga esto {#do-this}

1. Busque los identificadores de fabricante y producto de la impresora:

   ```bash
   lsusb
   ```

   Localice la línea de su impresora: los identificadores son los dos valores de cuatro caracteres que siguen a `ID`, por ejemplo `04b8:0e28`.

2. Cree un archivo de reglas, sustituyendo los identificadores por los suyos:

   ```bash
   sudo tee /etc/udev/rules.d/99-receipt-printer.rules <<'RULE'
   SUBSYSTEM=="usb", ATTRS{idVendor}=="04b8", ATTRS{idProduct}=="0e28", MODE="0666"
   RULE
   ```

3. Recargue las reglas y vuelva a aplicarlas:

   ```bash
   sudo udevadm control --reload-rules && sudo udevadm trigger
   ```

4. Desenchufe la impresora, vuelva a enchufarla y reinicie la aplicación. Imprima una página de prueba.

Ejecute la aplicación con su usuario normal, no con `sudo`: una regla que solo funciona para root no sirve de nada.

## ¿Sigue sin funcionar? {#still-stuck}

Utilice **Copiar informe de configuración** en la pantalla de problemas y péguelo en su mensaje, junto con la línea de `lsusb` de su impresora.
