Elke kassa communiceert de hele dag met je WordPress-site: ze controleert op wijzigingen, verstuurt verkopen en haalt op wat een kassamedewerker zoekt. Hoe snel je server antwoordt, bepaalt hoe snel de POS aanvoelt. Als je server het zwaar heeft, voert elke kassa haar eigen controles minder vaak uit en herstelt ze zich vanzelf. Op deze pagina lees je waar je dat kunt zien, wat het betekent en wat je aan je hosting kunt aanpassen.

Ben je hier vanwege iets wat je zag?

- [**Tempo verlaagd** of **Gepauzeerd tot …**](#pace) onder **Je server door de tijd heen**. Je kunt blijven verkopen: alleen achtergrondcontroles worden minder vaak uitgevoerd, waardoor wijzigingen van andere kassa's later zichtbaar kunnen worden. Zie je dit op de meeste dagen, [kies dan eerst een lichter profiel](#fix).
- [Een **503**-, **429**- of **414**-fout](#503-errors). Bij elke code staat eerst een kort antwoord; de details voor je websitebeheerder kun je eronder uitklappen.
- [Zoeken en verkopen gaan traag op elke kassa](#fix). Een verlaagd tempo vertraagt deze handelingen nooit, dus kijk eerst naar je server, niet naar de kassa's: geef [de informatie voor je hostingprovider](#when-to-seek-help) door aan degene die je website beheert.

## Bekijk hoe je server presteert {#store-health}

Open **Winkelstatus** via het hartslagpictogram onderaan het menu en vervolgens **Prestaties**. De cijfers gelden alleen voor deze kassa.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[50, 0], [160, 0], [370, 0], [480, 26], [180, 0], [470, 0]]} alt="Winkelstatus op het tabblad Prestaties: de statusregel met verzoeken, gegevens en de gebruikelijke responstijd van de afgelopen 24 uur, de beschikbaarheidsbalk per uur en de profielen Eco, Gebalanceerd en Realtime">

1. **Winkelstatus** — het hartslagpictogram onderaan het menu.
2. **Prestaties** — hoe vaak deze kassa je winkel controleert en hoe je server presteert.
3. **Afgelopen 24 uur** — **Normaal** betekent dat deze kassa nu online is en synchroniseert. Daarna volgen verzoeken, gegevens en de **gebruikelijke responstijd** in milliseconden: 2347 is hier ongeveer 2.3 seconden. Blijft die op de meeste dagen boven de 2000, vermeld dit dan bij [de informatie die je naar je hostingprovider stuurt](#when-to-seek-help).
4. **Beschikbaarheid van de engine** — één cel per uur. Oranje betekent dat er in dat uur minstens één verzoek is mislukt. Beweeg de muis over een cel of tik erop om de aantallen te zien.
5. **Eco** — het minst belastende van de drie profielen, naast **Gebalanceerd** en **Realtime**. Kies dit op kassa's die verkopen van andere kassa's niet snel hoeven te zien. Kies **Realtime** alleen als degene die je website beheert dat aangeeft. Zie [Synchronisatieprofielen](../store-health.mdx#sync-presets).
6. **Op dit moment** — wanneer de volgende controle plaatsvindt. Het aantal verzoeken per uur betreft de reguliere controles volgens je instellingen. Bij een verlaagd tempo voert de kassa er minder uit; daarom vindt de volgende controle hier over ~2 minuten plaats.

</JourneyShot>

## ‘Je server door de tijd heen’ lezen {#server-load}

Scrol op hetzelfde tabblad omlaag. **Je server door de tijd heen** geeft aan welk tempo de kassa aanhoudt en toont grafieken van de afgelopen 24 uur.

<JourneyShot manifest={manifest} device="tablet" step={2} maxWidth={710} offsets={[[400, -204], [430, 0], [110, -84], [120, -84]]} alt="Je server door de tijd heen op een kassa met verlaagd tempo: de oranje temporegel met Tempo verlaagd, 2× minder vaak controleren omdat de server een hoge belasting meldde, de grafiek Serverbelasting die om 3:00 's nachts stijgt naar 59.1 en de dalende grafiek POS-verzoeken">

1. **Je server door de tijd heen** — de serverbelasting omvat alles wat op je server draait, niet alleen de POS: de website, back-ups en andere sites bij dezelfde hostingprovider.
2. **Tempo** — hier **Tempo verlaagd — 2× minder vaak controleren: je server meldde een hoge belasting**, in oranje. Deze kassa controleert elke 2 minuten in plaats van elke minuut en keert vanzelf terug naar het oorspronkelijke tempo zodra je server herstelt. Zie [Wat de temporegel betekent](#pace).
3. **Serverbelasting** — de hoogste belasting die je server in elk uur meldde. Het getal naast de titel is dat van het laatste uur. Je hoeft het getal niet zelf te beoordelen: de temporegel geeft aan wanneer je server de belasting verhoogd of hoog noemt.
4. **POS-verzoeken** — elk verzoek dat deze kassa in elk uur naar je winkel stuurde: de reguliere controles, plus het downloaden van wijzigingen, het versturen van verkopen en zoekopdrachten. Daardoor kan dit aantal ruim boven het aantal verzoeken per uur uit je instellingen liggen.

</JourneyShot>

Bekijk de twee grafieken samen. Als de belasting meestijgt en -daalt met de POS-verzoeken, kunnen de kassa's eraan bijdragen. Stijgt de belasting onafhankelijk daarvan, dan is iets anders op je server bezig: de website, een back-up of een andere site bij dezelfde hostingprovider. In deze schermafbeelding dalen beide lijnen samen na middernacht; na 2:00 's nachts stijgt de belasting naar 59.1 terwijl het aantal verzoeken van deze kassa blijft dalen. Er is dus iets anders bezig en de kassa heeft het tempo verlaagd om de server te ontzien.

In beide gevallen heeft je hostingprovider een schermafbeelding van beide grafieken nodig. Is de **gebruikelijke responstijd** lang terwijl de belasting laag blijft, dan heeft je server geen tekort aan rekenkracht: kijk eerst naar de opslag van bestellingen en je plugins (stappen 2 en 3 van [Als je server het zwaar blijft hebben](#fix)).

<Accordion>
<AccordionItem question="Als de grafieken leeg zijn">

Beide grafieken tonen **Nog niet genoeg gegevens — deze trend wordt aangevuld terwijl de kassa actief is** totdat de kassa metingen uit twee verschillende uren heeft. Laat de kassa aanstaan en kijk later opnieuw.

</AccordionItem>
</Accordion>

### Wat de temporegel betekent {#pace}

De regel toont een van de volgende meldingen. Deze staat los van de status **Normaal** bovenaan het tabblad, die Normaal kan blijven terwijl de kassa het tempo verlaagt.

- **Normaal tempo** — de kassa controleert volgens je instelling.
- **Normaal tempo — je server meldt een verhoogde belasting** (of **hoge belasting**) — je server meldt dat het druk is, en de kassa houdt je instelling nog aan: één antwoord met een hoge belasting vertraagt haar niet. De kassa verlaagt het tempo ook bij aanhoudende belasting: als de meeste van de laatste tien antwoorden een hoge belasting melden, verandert de regel in **Tempo verlaagd**, zelfs als die antwoorden snel binnenkwamen (zie [Wat elke reden betekent](#reasons)). Je hoeft niets te doen, tenzij je dit op de meeste dagen ziet.
- **Tempo verlaagd — N× minder vaak controleren: …** — de kassa controleert minder vaak en noemt na de dubbele punt de reden. Zie [Wat elke reden betekent](#reasons) hieronder.
- **Gepauzeerd tot …** — je server heeft aangegeven wanneer de kassa het opnieuw mag proberen, en de kassa wacht tot dat moment. Je kunt ondertussen blijven verkopen.

De regel verandert van kleur zolang de kassa het tempo heeft verlaagd of is gepauzeerd. Beide toestanden verdwijnen vanzelf zodra je server herstelt. Zie je ze op de meeste dagen, kijk dan bij [Als je server het zwaar blijft hebben](#fix).

:::note Alleen achtergrondcontroles worden minder vaak uitgevoerd
Alleen de reguliere controle op wijzigingen en de achtergrondcontroles van de kassa worden minder vaak uitgevoerd. Een zoekopdracht, het opzoeken van een barcode of een verkoop gaat direct naar je server. Bij een verlaagd tempo duurt het langer voordat deze kassa wijzigingen ziet die op andere kassa's en in WooCommerce zijn gemaakt.
:::

<Accordion>
<AccordionItem question="Wat elke reden betekent, hoeveel de kassa vertraagt en hoe ze herstelt">

<Anchor id="reasons" />

- **je server vroeg de POS om het tempo te verlagen** — je server, of een firewall ervoor, antwoordde één keer met ‘te veel verzoeken’ (**429**).
- **je server gaf fouten terug** of **verzoeken aan je server hadden een time-out** — drie serverfouten (**5xx**) of time-outs binnen een minuut. De reden noemt de laatste van de drie.
- **je server antwoordde traag** — de gebruikelijke responstijd (mediaan) van de laatste tien antwoorden was meer dan twee seconden.
- **je server meldde een hoge belasting** — de meeste van de laatste tien antwoorden meldden een hoge serverbelasting terwijl de kassa het normale tempo aanhield, of twee opeenvolgende metingen waren minstens het dubbele van de gebruikelijke serverbelasting, zodra de belasting 1 of hoger is.

Elke keer controleert de kassa half zo vaak als daarvoor. Het interval wordt nooit langer dan 5 minuten, of tweemaal je ingestelde interval als dat langer is: elke 10 minuten bij **Eco**. Als een server zelf een pauze opgeeft (via een **Retry-After**-header), houdt de kassa die aan, tot maximaal 15 minuten.

Het herstel verloopt bewust langzamer: tien goede antwoorden, minstens een minuut na de laatste vertraging, halveren de wachttijd weer. Een plotselinge stijging van de belasting is de uitzondering: de kassa controleert half zo vaak, maar niet minder vaak dan dat, totdat twee opeenvolgende metingen weer binnen een kwart van de gebruikelijke serverbelasting liggen. Een kassa die opnieuw opstart, keert terug naar je instelling.

WCPOS vraagt zelf om korte pauzes: 5 seconden terwijl de plugin op je site wordt bijgewerkt en 30 seconden terwijl de synchronisatietabellen worden geïnstalleerd. Je kunt dan kort **Gepauzeerd tot …** zien.

Zie [Synchronisatieprestaties](../../reference/sync-performance.mdx#server-pressure) voor de achterliggende regels van de engine.

</AccordionItem>
<AccordionItem question="Waar de belastingscijfers vandaan komen">

Je server meldt bij elk synchronisatieantwoord de gemiddelde belasting: hoeveel processen actief waren of op een processor wachtten, gemiddeld over de afgelopen minuut. Vergelijk dit met het aantal processorkernen van je server. Een belasting van 4 op een server met 4 kernen betekent dat die volledig bezet is; op een server met 16 kernen is dat een lichte belasting.

De woorden **verhoogd** en **hoog** nemen die beoordeling van je over. WCPOS deelt de belasting door het aantal kernen: onder 0,9 per kern is laag, tot 1,8 is verhoogd en daarboven is hoog. Bij gedeelde hosting telt het cijfer alle sites op de machine mee, niet alleen die van jou.

**Je server meldt zijn belasting niet. Al het andere op deze pagina werkt nog steeds.** verschijnt in plaats van de grafiek wanneer PHP de gemiddelde belasting niet kan uitlezen. Dat is normaal op Windows-servers en bij hostingproviders die deze functie uitschakelen. De temporegel werkt ook zonder deze gegevens, omdat de kassa ook fouten en responstijden bijhoudt.

</AccordionItem>
</Accordion>

## Als je server het zwaar blijft hebben {#fix}

Werk deze lijst van boven naar beneden af. Elke stap kost minder dan de volgende. Iedereen aan de kassa kan stap 1 uitvoeren. Stappen 2 tot 4 zijn bedoeld voor degene die je website beheert: de winkeleigenaar, een ontwikkelaar of je hostingprovider.

1. **Kies een lichter profiel.** Open **Winkelstatus › Prestaties** op kassa's die elkaars verkopen niet binnen enkele seconden hoeven te zien en kies **Eco**. Kies **Realtime** alleen als degene die je website beheert dat aangeeft. Het profiel wordt per kassa opgeslagen. Zie [Synchronisatieprofielen](../store-health.mdx#sync-presets).
2. **Schakel WooCommerce over op HPOS** als het nog de verouderde opslag voor bestellingen gebruikt. Voor een winkel met veel bestellingen levert dit op zichzelf de grootste verbetering op. Zolang de winkel de verouderde opslag gebruikt, staat daar bovenaan **POS → Instellingen → Kassa** in WP Admin een waarschuwing over, met een link naar de instelling van WooCommerce. Zie [Opslag van bestellingen (HPOS)](./order-storage.mdx#switch-to-hpos).
3. **Zoek de plugin die elk verzoek vertraagt.** Test op een testomgeving met alleen WooCommerce en WCPOS actief en schakel de plugins vervolgens één voor één weer in. Zie [Pluginconflicten](../troubleshooting/plugin-conflicts.mdx#step-2-the-plugin-elimination-method).
4. **Vraag je hostingprovider** om objectcaching (Redis of Memcached), meer PHP-workers en geheugen, of een overstap van gedeelde hosting naar een andere oplossing. Zie [Wat je naar je hostingprovider stuurt](#when-to-seek-help).

## Wat je naar je hostingprovider stuurt {#when-to-seek-help}

Neem contact op met je hostingprovider of een WordPress-ontwikkelaar als **Tempo verlaagd** of **Gepauzeerd tot …** op de meeste dagen verschijnt, de gebruikelijke responstijd boven de 2 seconden blijft of de logboeken van je hostingprovider geheugenfouten tonen.

Stuur vanaf de kassa:

- Een schermafbeelding van **Winkelstatus → Prestaties**, omlaag gescrold naar **Je server door de tijd heen**.
- Het debugrapport via **Winkelstatus → Logboeken → Debuginfo kopiëren** (**Debuginfo delen** in de apps voor telefoons en tablets). Hierin staan je versies van WordPress, WooCommerce en WCPOS al vermeld. Zie [Logboeken](../store-health.mdx#logs).

Laat degene die je website beheert het volgende toevoegen:

- De lijst met actieve plugins, te vinden onder **Plugins** in WP Admin.
- De specificaties van je server: kernen, geheugen en opslagtype, te vinden in je hostingaccount.

De rest van deze pagina is bedoeld voor degene die je website beheert. Ben je hier vanwege een **503**-, **429**- of **414**-code, dan vind je bij [Fouten die je server terugstuurt](#503-errors) eerst een kort antwoord voor elke code.


## Serververeisten {#minimum-server-requirements}

WCPOS kan worden geïnstalleerd op elke site die aan de [minimumvereisten van de plugin](../../getting-started/installation.mdx#server-requirements) voldoet: PHP 7.4, WordPress 5.6 en WooCommerce 9.0. Een winkel die dagelijks verkoopt, heeft meer nodig; hieronder staan de specificaties die je naar je hostingprovider kunt sturen.

Bij WordPress.com-hosting zijn REST API-problemen voorgekomen, zoals het laden van slechts 9 of 10 producten uit een grote catalogus; met zelfgehoste WordPress vermijd je die.

## Fouten die je server terugstuurt {#503-errors}

### 503 Service niet beschikbaar {#503}

Je server, of iets ervoor, kon het verzoek niet verwerken. De achtergrondcontroles van de kassa worden minder vaak uitgevoerd en proberen het vanzelf opnieuw. Een kortstondige 503 is normaal terwijl WCPOS op je site wordt bijgewerkt of zijn tabellen installeert: de kassa wacht 5 tot 30 seconden en gaat verder. Blijft dit gebeuren, geef dan [de informatie voor je hostingprovider](#when-to-seek-help) door aan degene die je website beheert.

<Accordion>
<AccordionItem question="Voor je websitebeheerder: wat je controleert bij een 503">

Controleer de serverbelasting en het beschikbare geheugen, of alle PHP-workers bezet zijn en of de geheugenlimiet van PHP **256 MB** of meer is. De foutenlogboeken van je hostingprovider laten zien wat de POS niet kan tonen.

</AccordionItem>
</Accordion>

### 429 Te veel verzoeken {#429}

Je hostingprovider of firewall beperkt hoe vaak één adres je site mag aanroepen. De kassa verlaagt direct het tempo en probeert het later opnieuw. Meerdere kassa's achter één router in de winkel delen één adres. Kies daarom **Eco** op kassa's die verkopen van andere kassa's niet snel hoeven te zien. Blijft dit gebeuren, geef dan [de informatie voor je hostingprovider](#when-to-seek-help) door aan degene die je website beheert.

<Accordion>
<AccordionItem question="Voor je websitebeheerder: meer POS-verzoeken toestaan">

Vraag je hostingprovider om meer verzoeken vanaf het adres van de winkel naar `/wp-json/` toe te staan, of pas dit aan in de firewallinstellingen. Dit is het pad dat de POS aanroept.

</AccordionItem>
</Accordion>

### 414 URI te lang {#http-414-uri-too-long}

Je ziet deze fout op een betaalpagina onder het tabblad **Verouderd** in het afrekenscherm. Die pagina wordt geopend met je aanmeldgegevens in het adres, en de limiet van je server voor de adreslengte is te laag. Vraag degene die je website beheert, of je hostingprovider, om die te verhogen.

<Accordion>
<AccordionItem question="Voor je websitebeheerder: de limiet voor de adreslengte verhogen">

- **Apache:** `LimitRequestLine 65536` in `httpd.conf`
- **Nginx:** `large_client_header_buffers 4 65536;` in `nginx.conf`

</AccordionItem>
</Accordion>

## WooCommerce veilig bijwerken {#woocommerce-version-compatibility}

Een WooCommerce-update kan er soms voor zorgen dat de POS niet meer werkt. Werk WooCommerce eerst bij in een [testomgeving](../troubleshooting/plugin-conflicts.mdx#before-you-start-use-a-staging-site) en houd WCPOS up-to-date, zodat de nieuwste oplossingen voor compatibiliteitsproblemen aanwezig zijn. WCPOS 2.0 vereist WooCommerce 9.0 of nieuwer.

Werkt de POS na een update niet meer, laat het ons dan weten op [Discord](https://wcpos.com/discord) en overleg met degene die je website beheert over teruggaan naar de vorige versie. Een update kan de database van je winkel wijzigen. Laat de beheerder dat daarom eerst controleren en zorg dat er een back-up van vóór de update beschikbaar is.

<Accordion>
<AccordionItem question="Voor je websitebeheerder: teruggaan naar een eerdere WooCommerce-versie">

De link **Geavanceerde weergave** op de WordPress.org-pagina van WooCommerce toont eerdere versies. Herstel de back-up van vóór de update als de update de database heeft gewijzigd; installeer anders de versie die je daarvoor had. Probeer dit eerst in een testomgeving.

</AccordionItem>
</Accordion>

## Opslag van bestellingen (HPOS) {#woocommerce-high-performance-order-storage-hpos}

Met **Hoogwaardige opslag voor bestellingen** bewaart WooCommerce bestellingen in eigen tabellen in plaats van tussen je berichten. In een winkel met veel bestellingen gaat het opslaan van een verkoop daardoor veel sneller. Controleer welke opslag je winkel gebruikt en schakel over met de eigen tool van WooCommerce: [Opslag van bestellingen (HPOS)](./order-storage.mdx). De handleiding van WooCommerce vind je bij [Hoogwaardige opslag voor bestellingen](https://woocommerce.com/document/high-performance-order-storage/).

<Accordion>
<AccordionItem question="PHP- en WordPress-instellingen om met je hostingprovider te bespreken">

Dit zijn uitgangspunten, geen regels. Je hostingprovider weet wat zijn servers toelaten.

```ini
memory_limit = 512M
max_execution_time = 300
max_input_vars = 3000
```

Door in `wp-config.php` minder berichtrevisies te bewaren, blijft de database kleiner:

```php
define('WP_POST_REVISIONS', 3);
```

Plugins die vaak elk verzoek vertragen: zware SEO-plugins die actief zijn bij het opslaan van producten, complexe voorraadsystemen, realtime analyses en tracking, en aangepaste code die op WooCommerce inhaakt. Zoek de boosdoener met [Pluginconflicten](../troubleshooting/plugin-conflicts.mdx).

</AccordionItem>
</Accordion>

## Aandachtspunten per hostingprovider {#hosting-specific-notes}

Bij sommige hostingproviders en CDN's is een aanpassing nodig voordat de POS de REST API van je site kan bereiken. Open het onderdeel dat op jouw situatie van toepassing is:

<Accordion>
<AccordionItem question="GoDaddy">

De websitefirewall blokkeert `/wp-json/`, met fouten zoals _‘Received 'undefined'’_. Voeg `/wp-json/` toe onder **Websitebeveiliging › Firewall › Instellingen › Toegangsbeheer › URL-paden toestaan**.

</AccordionItem>
<AccordionItem question="WP Engine">

De REST API moet ingeschakeld zijn. Schakel deze in en sta indien nodig de bijbehorende paden toe in de firewall van WP Engine.

</AccordionItem>
<AccordionItem question="Cloudflare">

De botbestrijdingsmodus, de aanvalsmodus of WAF-controles blokkeren REST-verzoeken, en de cache kan verouderde antwoorden teruggeven. Volg de [Cloudflare-handleiding](../troubleshooting/cloudflare.mdx) om een WAF-regel **Overslaan** en een regel **Cache omzeilen** toe te voegen voor `/wp-json/`.

</AccordionItem>
<AccordionItem question="WordPress.com">

Producten worden soms niet geladen, waardoor er bijvoorbeeld maar 9 of 10 uit een grote catalogus verschijnen. Gebruik zelfgehoste WordPress.

</AccordionItem>
<AccordionItem question="Gedeelde hosting">

Te weinig PHP-workers en geheugen voor meerdere kassa's. Stap over op een VPS of beheerde WordPress-hosting.

</AccordionItem>
</Accordion>

Beveiligingsplugins zoals Wordfence kunnen de REST API op dezelfde manier blokkeren. Zie [Pluginconflicten](../troubleshooting/plugin-conflicts.mdx).
