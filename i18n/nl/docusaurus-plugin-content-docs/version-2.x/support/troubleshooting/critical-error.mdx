"Er heeft zich een kritieke fout voorgedaan op deze site." is de melding van WordPress wanneer je website vastloopt: een PHP-fout heeft de website gestopt voordat deze de POS kon antwoorden. De fout zit in de website, niet in de kassa. Op de kassa kunnen wijzigingen staan die je winkel nog niet heeft ontvangen. Wis daarom de gegevens niet terwijl de website wordt hersteld.

## Aan de kassa {#at-the-till}

:::warning Wis de gegevens van deze kassa niet
Bij de fout in Logboeken staat dit ook: "Wis de gegevens van dit apparaat niet — het kan wijzigingen bevatten die je winkel nog niet heeft ontvangen." Als je de gegevens wist, gaan die wijzigingen verloren. Als de onderstaande handeling ook bij een tweede poging mislukt, wacht dan totdat de website is hersteld.
:::

**Bezig met een betaling?** Breng het bedrag nog niet opnieuw in rekening. Volg de pagina voor de afrekencode in de melding:

- [CHECKOUT101](../../error-codes/CHECKOUT101.mdx): je kunt de winkelwagen veilig opnieuw afrekenen.
- [CHECKOUT201](../../error-codes/CHECKOUT201.mdx): de verkoop is mogelijk al verwerkt.

Voor alle andere handelingen:

1. Probeer de handeling nog één keer. Het vastlopen kan eenmalig zijn.
2. Als het opnieuw mislukt, open je **Winkelstatus** via het hartslagpictogram onderaan het menu, ga je naar **Logboeken** en druk je op **Fouten**.
3. Tik op de vermelding **SYNC131** om deze te openen. Daar lees je of je gegevens veilig zijn. Met **Help — SYNC131** open je de pagina van de code.
4. Druk op **Debuginfo kopiëren** en stuur deze informatie samen met het tijdstip waarop de fout optrad naar degene die je website beheert.

1. **Winkelstatus** — het hartslagpictogram onderaan het menu. Een rood getal erop geeft het aantal nieuwe fouten aan.
2. **Logboeken** — alles wat deze kassa heeft gedaan, 30 dagen bewaard.
3. **fouten vandaag** — fouten die vandaag zijn vastgelegd. Hier zijn er geen.
4. **Fouten** — toont alleen fouten. Een kritieke fout is een vermelding met **SYNC131** in de kolom **Status**.
5. **Logboeken doorzoeken** — zoek een vermelding op woorden of op de code, zoals SYNC131.
6. **Debuginfo kopiëren** — kopieert een rapport voor support. In de apps voor telefoon en tablet heet dit **Debuginfo delen**.

## Waar je de fout ziet {#where-you-see-it}

- **Op de kassa**, als melding na de mislukte handeling, met de code [SYNC131](../../error-codes/SYNC131.mdx): er is een fout opgetreden in je winkel en het verzoek is niet voltooid.
- **In de reden die de winkel zelf geeft**, waar de POS die toont, zoals bij het afrekenen of bij een wijziging die je winkel heeft geweigerd. De reden is de melding van WordPress, of de PHP-fout zelf wanneer je website foutdetails toont, zoals *Allowed memory size of 134217728 bytes exhausted in wp-includes/class-wpdb.php:2324*.
- **Bij het afrekenen** bevat de melding in plaats daarvan een afrekencode die aangeeft wat er met de betaling is gebeurd: [CHECKOUT101](../../error-codes/CHECKOUT101.mdx) wanneer je de winkelwagen veilig opnieuw kunt afrekenen, [CHECKOUT201](../../error-codes/CHECKOUT201.mdx) wanneer de POS niet kan vaststellen of de verkoop is verwerkt. Volg die pagina voordat je het bedrag opnieuw in rekening brengt.
- **In een browser**, wanneer de website vastloopt terwijl de POS-pagina zelf wordt geladen. WordPress toont dan zijn eigen foutpagina in plaats van de POS.
- **In Winkelstatus → Logboeken**, als foutvermelding met **SYNC131** in de kolom **Status**.

## Zoek de oorzaak op je website {#find-the-cause}

Voor dit onderdeel is iemand nodig die kan inloggen op WP Admin.

1. Ga naar **WooCommerce → Status → Logs** en open het nieuwste **fatal-errors**-logboek van rond het tijdstip waarop de fout optrad. Bij het vastlopen wordt de PHP-fout daar bijna altijd vastgelegd.
2. Lees de eerste regel van de fout en bekijk het bestand dat daarin wordt genoemd. Een bestand onder `wp-content/plugins/` geeft aan bij welke plugin het hoort; een bestand onder `wp-content/themes/` geeft het thema aan.
3. Als het vastlopen begon na een update van een plugin of thema, draai die update dan terug of deactiveer de plugin of het thema. Begon het na een PHP-upgrade? Vraag je hostingprovider dan om die wijziging te controleren. In [Pluginconflicten](./plugin-conflicts.mdx) lees je hoe je de verantwoordelijke plugin vindt.
4. Staat er niets in de logboeken van WooCommerce? De WooCommerce-handleiding [PHP-foutlogboeken vinden](https://woocommerce.com/document/finding-php-error-logs/) laat zien waar je nog meer kunt kijken. Je kunt je hostingprovider ook vragen om het PHP-foutlogboek van de server voor hetzelfde tijdstip.
5. Ga terug naar de kassa zodra het probleem is opgelost. Raadpleeg bij een betaling de pagina van de afrekencode voordat je het bedrag opnieuw in rekening brengt. Probeer bij alle andere handelingen de handeling opnieuw.

Onder **WP Admin > POS > Instellingen**, bij **Logboeken** onder **Gereedschap**, verschijnt **Fatale fouten gedetecteerd — bekijken in WooCommerce-logboeken** wanneer WooCommerce een fatal-errors-logbestand heeft aangemaakt. De link opent de logboeken van WooCommerce, gefilterd op fatale fouten.

:::tip De e-mail van WordPress
Wanneer een plugin of thema het vastlopen veroorzaakt, stuurt WordPress een e-mail naar het beheerdersadres van de site: **Je site ondervindt een technisch probleem**. De link in die e-mail opent WP Admin in de herstelmodus nadat je bent ingelogd. Daar kun je de verantwoordelijke plugin deactiveren, zelfs wanneer WP Admin niet op de normale manier opent.
:::

### Fouten die je kunt tegenkomen {#common-errors}

**Allowed memory size of … bytes exhausted.** PHP heeft onvoldoende geheugen. Vraag je hostingprovider om de geheugenlimiet van PHP te verhogen.

**Een fout in een bestand van een andere plugin.** Van sommige plugins is bekend dat ze conflicten met de POS veroorzaken. Zoek de plugin en de bijbehorende oplossing onder [Bekende pluginconflicten](./plugin-conflicts.mdx#known-plugin-conflicts).

**Een fatale fout of *Cannot modify header information* nadat je de gratis plugin hebt verwijderd en Pro hebt geüpload.** Pro heeft de gratis plugin niet nodig: de code daarvan zit al in Pro en Pro werkt zelfstandig. Je hoeft de gratis plugin dus niet terug te zetten. Lees de eerste regel van de fout en bekijk het genoemde bestand, zoals hierboven beschreven. Als WP Admin **WCPOS Pro kon niet worden geladen. Voer composer install uit.** toont, ontbreekt er een deel van Pro in het zipbestand: download het opnieuw via je [Downloads](https://wcpos.com/account/downloads) en upload dat bestand. Zie [De Pro-plugin installeren](../../getting-started/pro-license.mdx#installation).
