## Wat dit betekent {#what-this-means}

De hostingprovider beperkt het aantal verzoeken van de kassa's van deze winkel.

De server blijft 429 (te veel verzoeken) antwoorden, hoewel de app al minder vaak verzoeken verstuurt en de Retry-After-wachttijden van de server respecteert. Meerdere kassa's op één internetverbinding delen één adres, waardoor limieten per bron ze als één zeer actieve client behandelen. De synchronisatie gaat automatisch door, maar blijft achterlopen totdat de limiet wordt verhoogd.

## Je gegevens {#your-data}

Er worden geen bestel- of productgegevens aangetast.

## Problemen oplossen {#troubleshoot}

1. Vraag de hostingprovider om de verzoeklimiet voor de REST API te verhogen of het eigen verkeer van de winkel ervan uit te zonderen — vermeld het vaste IP-adres van de winkel als die er een heeft.
2. Bij beveiligingsdiensten die herhaalde foutantwoorden (429) meetellen voor een blokkade (bijvoorbeeld het IDS van Sucuri), moet de API van de winkel mogelijk van die telling worden uitgesloten.
3. Vermeld het bij de hostingprovider als meerdere kassa's één verbinding delen: één IP-adres staat hier voor een hele winkel, niet voor één gebruiker.
