## Wat dit betekent {#what-this-means}

Een pagina voor botbeveiliging antwoordt in plaats van de API van de winkel.

De REST API van de winkel geeft een HTML-controlepagina terug (botbeveiliging, CAPTCHA of een DDoS-tussenpagina) terwijl de app JSON verwacht. Een kassa-app kan geen browsercontrole oplossen. De REST API van de winkel moet op de toestemmingslijst van de beveiligingsdienst staan.

## Je gegevens {#your-data}

Er zijn geen bestel- of productgegevens aangetast.

## Problemen oplossen {#troubleshoot}

1. Bepaal aan de hand van de controlepagina welke beveiligingslaag wordt gebruikt (Cloudflare, Sucuri, Kinsta en andere diensten vermelden elk hun eigen merk) en open de instellingen daarvan.
2. Zet de eigen REST API-paden van de winkel (/wp-json/ en /?rest_route=) op de toestemmingslijst voor API-verkeer.
3. Voeg in Cloudflare een WAF-regel **Overslaan** toe voor de REST API-paden. Bot Fight Mode (gratis abonnement) kan met geen enkele regel worden omzeild en moet worden uitgeschakeld. De [Cloudflare-handleiding](/troubleshooting/common-problems/cloudflare) bevat de exacte regel en een controle met `curl`.
4. Zet in de bot-/firewallinstellingen van Kinsta de REST API-paden op de toestemmingslijst. Vermijd bij Sucuri de DDoS-modus met JavaScript-controle voor API-routes.
