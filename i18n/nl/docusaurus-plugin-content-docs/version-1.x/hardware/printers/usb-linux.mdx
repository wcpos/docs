**Symptoom:** de printer verschijnt wanneer u scant, maar afdrukken mislukt met een toegangs- of machtigingsfout.

## Waarom het gebeurt {#why-it-happens}

Op Linux is een USB-apparaat van `root` tenzij een regel iets anders zegt, dus een app die onder uw eigen account draait, kan het niet openen. Ook kan het printerstuurprogramma van de kernel het apparaat al hebben opgeëist.

## Doe dit {#do-this}

1. Zoek de vendor- en product-id van de printer op:

   ```bash
   lsusb
   ```

   Zoek de regel van uw printer — de id's zijn de twee waarden van vier tekens na `ID`, bijvoorbeeld `04b8:0e28`.

2. Maak een regelbestand aan en vervang de id's door de uwe:

   ```bash
   sudo tee /etc/udev/rules.d/99-receipt-printer.rules <<'RULE'
   SUBSYSTEM=="usb", ATTRS{idVendor}=="04b8", ATTRS{idProduct}=="0e28", MODE="0666"
   RULE
   ```

3. Laad de regels opnieuw en pas ze opnieuw toe:

   ```bash
   sudo udevadm control --reload-rules && sudo udevadm trigger
   ```

4. Haal de printer los, sluit hem weer aan en start de app opnieuw. Druk een testpagina af.

Draai de app als uw normale gebruiker, niet met `sudo` — een regel die alleen voor root werkt, mist het doel.

Gebruik **Installatierapport kopiëren** op het probleemscherm en plak dat in uw bericht, samen met de `lsusb`-regel van uw printer.
