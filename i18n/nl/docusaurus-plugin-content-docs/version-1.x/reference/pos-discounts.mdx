# Technische referentie voor POS-kortingen {#pos-discount-technical-reference}

Deze pagina beschrijft hoe WCPOS omgaat met prijsoverschrijvingen die kassamedewerkers op orderregels toepassen: hoe ze worden opgeslagen, hoe ze samenwerken met WooCommerce-coupons en welke filters beschikbaar zijn. Zie voor gebruikersdocumentatie [Winkelwagenkortingen](/1.x/pos/cart/discounts) en [Coupons](/1.x/coupons).

## Hoe POS-prijsoverschrijvingen worden opgeslagen {#how-pos-price-overrides-are-stored}

Wanneer een kassamedewerker de prijs van een orderregel instelt of wijzigt in de POS, worden de prijzen per eenheid als JSON opgeslagen in de orderregelmetadata `_woocommerce_pos_data`:

```json
{
  "price": "16.00",
  "regular_price": "18.00",
  "tax_status": "taxable"
}
```

Voor diverse (aangepaste) producten kan deze metadata ook de velden `virtual`, `downloadable` en `categories` bevatten, die bij couponvalidatie worden gebruikt.

Deze metadata is de leidende bron voor de prijzen per eenheid van de regel. Het door WooCommerce opgeslagen `subtotal` van de orderregel wordt afgeleid van `price * qty` (na het uitrekenen van de belasting en het toepassen van afronding). Het opgeslagen `total` kan lager zijn als couponkortingen zijn toegepast. Lees daarom voor nauwkeurige prijzen per eenheid altijd `_woocommerce_pos_data.price` en `regular_price` uit.

Nieuwe POS-bestellingen leggen ook de versie van de serverplugin vast in de privé-bestelmetadata `_woocommerce_pos_version`. Dit biedt een expliciete versiemarkering voor toekomstige compatibiliteitscontroles. Voor bonberekeningen blijft de opgeslagen structuur van de orderregel leidend, omdat een offline bestelling kan worden geaccepteerd door een server met een nieuwere versie dan de app waarin de bestelling is aangemaakt.

## Subtotaalmodel (v1.9.0+) {#subtotal-model-v190}

Vanaf v1.9.0 sluit WCPOS aan bij de standaardwerkwijze van WooCommerce voor aanbiedingsprijzen:

- `line_item.subtotal = price * qty` waarbij `price` de POS-prijs is (na een eventuele overschrijving).
- `line_item.total = subtotal - coupon_discount_for_line`.
- `order.discount_total` geeft **alleen couponkortingen** weer, geen POS-prijsoverschrijvingen.

Dit komt overeen met hoe WooCommerce een product in de aanbieding behandelt: de `sale_price` wordt het subtotaal en `discount_total` is gereserveerd voor coupons. Er is geen afzonderlijke regel ‘POS-korting’ op de bestelling.

:::note Migratie vanaf versies vóór 1.9.0
Eerdere versies verstuurden `subtotal = regular_price * qty`, waardoor WooCommerce `discount_total = subtotal - total` berekende en POS-prijsoverschrijvingen als korting opnam. Dit is gewijzigd omdat het botste met de couponberekening: `recalculate_coupons()` gebruikt `subtotal` als basisprijs, waardoor coupons werden berekend op basis van de oorspronkelijke prijs en onjuiste totalen opleverden.

De eerdere tijdelijke oplossing aan de serverzijde — een `woocommerce_order_item_get_subtotal`-filter dat actief was tijdens `recalculate_coupons()` — is verwijderd in v1.9.0. Bekijk de [ADR](https://github.com/wcpos/wiki/blob/main/architecture/decisions/2026-04-08-subtotal-parity.md) voor de volledige geschiedenis.
:::

## Gedrag van kortingsbonnen {#coupon-interaction-behaviour}

Ondersteuning voor kortingsbonnen is een functie van [WCPOS Pro](https://wcpos.com/pro). Wanneer een kortingsbon wordt toegepast op een bestelling met artikelen met POS-korting:

1. De coupon wordt berekend op basis van de **POS-kortingsprijs** (de waarde in `_woocommerce_pos_data.price`), niet op basis van de oorspronkelijke `regular_price`.
2. Wanneer een coupon wordt verwijderd, keert de orderregel terug naar de POS-kortingsprijs.

### Gedrag van `exclude_sale_items` {#exclude_sale_items-behaviour}

Artikelen met POS-korting worden door WooCommerce als ‘in de aanbieding’ behandeld wanneer `_woocommerce_pos_data.price < regular_price`. Coupons waarvoor `exclude_sale_items` is ingeschakeld, slaan deze artikelen daarom over, net zoals WooCommerce dat bij reguliere aanbiedingsprijzen doet.

Zie het filter `woocommerce_pos_item_is_on_sale` hieronder als je ander gedrag nodig hebt.

## Beschikbare filters {#available-filters}

### `woocommerce_pos_item_is_on_sale` {#woocommerce_pos_item_is_on_sale}

Overschrijf of een artikel met POS-korting bij couponvalidatie als ‘in de aanbieding’ wordt beschouwd.

```php
add_filter( 'woocommerce_pos_item_is_on_sale', function ( $is_on_sale, $product, $item, $pos_data ) {
    // Allow coupons with exclude_sale_items to apply to POS-discounted items
    return false;
}, 10, 4 );
```

**Parameters:**

| Parameter | Type | Beschrijving |
|---|---|---|
| `$is_on_sale` | `bool` | Of het artikel als in de aanbieding wordt beschouwd (standaard: `price < regular_price`) |
| `$product` | `WC_Product` | Het productobject |
| `$item` | `WC_Order_Item_Product` | De orderregel |
| `$pos_data` | `array` | De gedecodeerde JSON uit `_woocommerce_pos_data` |

## REST API-endpoint {#rest-api-endpoint}

Het REST-endpoint voor coupons bevindt zich in de **gratis plugin** op `/wp-json/wcpos/v1/coupons`, zodat de POS-app nooit een 404 ontvangt bij het opvragen van coupons — zelfs niet op sites zonder WCPOS Pro. De couponfunctie voor gebruikers vereist echter wel Pro.

De controller breidt `WC_REST_Coupons_Controller` uit met POS-specifieke toevoegingen:

- UUID-verwerking voor synchronisatie die uitgaat van offline gebruik
- De machtiging `access_woocommerce_pos` voor toegangscontroles
- Geoptimaliseerd querypad voor bulk-ID's wanneer `posts_per_page=-1` en `fields=id` (of `fields=id,date_modified_gmt`) worden aangevraagd

## Beschikbaarheid van bongegevens {#receipt-data-exposure}

De gegevensbuilder voor bonnen (`Receipt_Data_Builder`) stelt het volgende beschikbaar:

- `lines[].discounts`, `lines[].discounts_incl`, `lines[].discounts_excl` — kortingsbedrag per regel, berekend als `subtotal - total`. Vanaf v1.9.0 geeft dit bij POS-prijsoverschrijvingen **alleen couponkortingen** weer, omdat `subtotal === total` wanneer geen coupon is toegepast.
- `totals.discount_total`, `totals.discount_total_incl`, `totals.discount_total_excl` — totale couponkorting op bestelniveau uit `WC_Order::get_discount_total()`.
- `totals.sale_savings_total`, `totals.sale_savings_total_incl`, `totals.sale_savings_total_excl` — de totale vastgelegde besparing tussen reguliere prijzen en verkoopprijzen over alle productregels, inclusief catalogusaanbiedingen en prijsoverschrijvingen aan de kassa.
- `totals.total_saved`, `totals.total_saved_incl`, `totals.total_saved_excl` — gecombineerde totalen van WooCommerce-korting en besparing ten opzichte van de reguliere prijs. De builder sluit besparingen per regel uit die al zijn opgenomen in het WooCommerce-kortingstotaal van een bestelling van vóór v1.9.0.
- `totals.total_saved_complete` — false wanneer een regel onvoldoende vastgelegde prijsgegevens bevat voor een betrouwbaar totaal; de besparingstotalen die een null-waarde toestaan zijn in dat geval `null`.
- `discounts[]` — array van couponregels met `label`, `code` en `total`.

De metadata van de orderregel met een underscore als voorvoegsel (inclusief `_woocommerce_pos_data`) wordt door `Receipt_Data_Builder::get_item_meta_pairs()` uit `lines[].meta` gefilterd. Bongegevens v1.1 stelt in plaats daarvan de vastgelegde reguliere prijs, de verkoopprijs vóór couponkorting, de besparing per regel en de totale besparing beschikbaar via canonieke velden. Zie [Reguliere prijs en besparingen weergeven](/1.x/receipts/receipt-data#displaying-regular-price-and-savings) en [Totalen](/1.x/receipts/receipt-data#totals) voor sjabloonvoorbeelden.
