## Wat dit betekent {#what-this-means}

De server van de winkel blokkeert het inlogtoken op elk kanaal dat deze app kan gebruiken.

De app heeft bevestigd dat de winkel bereikbaar is, maar de server (of een firewall, proxy of beveiligingsplugin ervoor) verwijdert de Authorization-header en blokkeert het token ook wanneer dit als URL-parameter wordt verzonden. Er is geen derde manier om een inlogtoken te verzenden, dus dit moet op de server worden opgelost.

## Wat te doen {#what-to-do}

Exporteer diagnostische gegevens en neem contact op met ondersteuning. Probeer opnieuw nadat de bovenstaande wijziging is aangebracht; zonder die wijziging mislukt de poging op dezelfde manier.

## Uw gegevens {#your-data}

Er zijn geen bestel- of productgegevens betroffen.

## Problemen oplossen {#troubleshoot}

1. Vraag uw hostingprovider om de Authorization-header door te laten naar WordPress — op Apache is dit meestal één regel: SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1.
2. Als de site .htaccess-rewrites gebruikt, behoud dan de door WordPress gegenereerde RewriteRule-regel die HTTP_AUTHORIZATION doorgeeft — beveiligingsplugins verwijderen deze soms.
3. Controleer achter een proxy of CDN de allowlist voor headers: de aanvraagheader Authorization moet worden doorgestuurd naar de oorsprongsserver.
4. Als een web application firewall (WAF) URL-parameters filtert, vraag uw hostingprovider dan om de autorisatieparameter toe te staan op /wcpos/ REST-routes.

## Waar te zoeken {#where-to-look}

Wanneer WCPOS deze fout kan opslaan, wordt deze vastgelegd op het apparaat waarop deze is opgetreden. Open **Winkelstatus → Logboeken** (het hartslagpictogram onderaan de navigatielade), zoek de invoer met deze code en vouw deze uit: de uitgevouwen rij toont de begrijpelijke reden en de context die op het moment van de fout is vastgelegd. Voor een winkelverzoek kan die context de eigen foutcode van de server (`serverCode`), de HTTP-`status` of het `endpoint` bevatten; welke velden worden getoond, hangt af van waar de fout is opgetreden. Gebruik bij het melden van een probleem **Foutopsporingsinformatie kopiëren** bovenaan het scherm Logboeken (**Foutopsporingsinformatie delen** op telefoons en tablets) in plaats van schermafbeeldingen: hiermee worden de appversie, verbindingsstatus en de meest recente fouten gebundeld. Logboeken worden maximaal 30 dagen bewaard, dus verzamel ze terwijl het probleem nog actueel is. Kopieer ook eventuele foutmeldingen uit de browserconsole die verschenen voordat de POS een eigen logboeking kon schrijven.
