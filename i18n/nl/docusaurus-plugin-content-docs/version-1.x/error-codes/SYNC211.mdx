## Wat dit betekent {#what-this-means}

Een veld in een record is door je winkel afgewezen. Soms staat deze code ook voor een instellingen- of authenticatieverzoek dat door de winkel is geweigerd.

Als er een record wordt genoemd, corrigeer je het genoemde veld en probeer je het opnieuw; de lokale kopie blijft beschikbaar totdat deze is gesynchroniseerd. Volg anders het bericht van de winkel voor het genoemde verzoek.

## Je gegevens {#your-data}

Als dit een wijziging aan een record was, is deze nog steeds op dit apparaat opgeslagen en heeft deze je winkel nog niet bereikt. Bij een instellingen- of authenticatieverzoek valt er niets op te slaan.

## Probleemoplossing {#troubleshoot}

1. Vouw de logvermelding uit en controleer eerst het endpoint en de serverrespons: deze code kan ook staan voor een HTTP 400 van een verzoek voor instellingen, authenticatie of iets anders dan een record.
2. Als de context een record of veld noemt, bewerk dat veld dan in de POS — veelvoorkomende oorzaken zijn een waarde buiten het bereik, een geweigerde notatie of een verplichte optie die leeg is gelaten — en probeer het daarna opnieuw.
3. Gaat het niet om een recordverzoek, volg dan het bericht van de server voor het genoemde endpoint. De ontwikkelaarstools van de browser (tabblad Netwerk) — of **Geavanceerd → Ontwikkelaarstools in-/uitschakelen** in de desktopapp — tonen het antwoord als de details niet in het POS-log staan.
4. **Sitebeheerder:** als een genoemd veld er in het POS correct uitziet, vergelijk je het met hetzelfde record in WP Admin — validatie die door een plugin aan de winkel is toegevoegd, kan waarden afwijzen die het POS wel goed vindt.
