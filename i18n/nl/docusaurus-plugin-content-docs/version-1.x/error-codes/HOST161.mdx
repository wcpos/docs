## Wat dit betekent {#what-this-means}

De host beperkt de verkeerssnelheid van de kassa's van deze winkel.

De server blijft 429 (te veel verzoeken) antwoorden hoewel de app al terugschakelt en de Retry-After-vertragingen van de server respecteert. Meerdere kassa's op één internetverbinding delen één adres, dus limieten per bron behandelen ze als één zeer drukke client. Synchroniseren gaat automatisch door, maar loopt achter totdat de limiet wordt verhoogd.

## Je gegevens {#your-data}

Er zijn geen bestel- of productgegevens getroffen.

## Probleemoplossing {#troubleshoot}

1. Vraag de host om de REST API-verkeerssnelheidslimiet voor het eigen verkeer van de winkel te verhogen of uit te zonderen — noem het statische IP-adres van de winkel als die er een heeft.
2. Beveiligingsdiensten die herhaalde foutresponsen (429's) meetellen voor een blokkade (bijvoorbeeld de IDS van Sucuri) hebben mogelijk uitsluiting van de API van de winkel uit die teller nodig.
3. Als meerdere kassa's één verbinding delen, vermeld dat dan aan de host: één IP-adres is hier een hele winkel, niet één gebruiker.
