## Wat dit betekent {#what-this-means}

De REST API van de winkel gaf geen antwoord via een adresindeling die deze app kan gebruiken.

De app probeerde de REST API van de winkel via het normale adres (/wp-json/...) en via het ingebouwde terugvaladres van WordPress (/?rest_route=...), maar geen van beide gaf antwoord. De website van de winkel kan zelf wel online zijn — het gaat specifiek om een onbereikbare REST API, meestal doordat een beveiligingsplugin deze verbergt of een firewallregel deze blokkeert.

## Wat te doen {#what-to-do}

Exporteer diagnostische gegevens en neem contact op met de ondersteuning. Probeer het opnieuw nadat de bovenstaande wijziging is aangebracht; zonder die wijziging zal de poging opnieuw mislukken.

## Uw gegevens {#your-data}

Er zijn geen bestel- of productgegevens beïnvloed.

## Problemen oplossen {#troubleshoot}

1. Als een beveiligingsplugin /wp-json/ verbergt of hernoemt (bijvoorbeeld WP Hide), sta dan ook de ingebouwde /?rest_route=-vorm van WordPress toe — de app valt hier automatisch op terug.
2. Controleer de firewallregels (WAF) op items die overeenkomen met wp-json of rest_route en geef de eigen REST API van de winkel toegang.
3. Test in een browser: https://your-store.com/?rest_route=/ moet JSON retourneren, geen 403-pagina of de homepage van de site.
4. Als de server zich achter een onderhoudspagina of botcontrole bevindt, kunnen REST-verzoeken worden beantwoord met een HTML-pagina — schakel de controle uit voor de REST API.

## Waar te zoeken {#where-to-look}

Wanneer WCPOS deze fout kan opslaan, wordt deze vastgelegd op het apparaat waarop de fout is opgetreden. Open **Winkelstatus → Logboeken** (het pictogram met de hartslag onderaan de navigatielade), zoek het item met deze code en vouw het uit: de uitgevouwen rij toont de reden in gewone taal en de context die op het moment van de fout is vastgelegd. Voor een winkelverzoek kan die context de eigen foutcode van de server (`serverCode`), de HTTP-`status` of het `endpoint` bevatten; welke velden worden getoond, hangt af van waar de fout is opgetreden. Gebruik bij het melden van een probleem **Foutopsporingsinformatie kopiëren** bovenaan het scherm Logboeken (**Foutopsporingsinformatie delen** op telefoons en tablets) in plaats van screenshots: hiermee worden de appversie, verbindingsstatus en de meest recente fouten gebundeld. Logboeken worden maximaal 30 dagen bewaard, dus verzamel ze terwijl het probleem nog recent is. Kopieer ook eventuele browserconsolefouten die verschenen voordat de POS een eigen logitem kon schrijven.
