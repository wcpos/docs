WCPOS에서는 계산원이 빠른 비율 버튼, 항목별 직접 가격 수정, 주문 수준 할인 수수료 등 여러 방법으로 주문에 즉시 할인을 적용할 수 있습니다. 사용 규칙이 있는 사전 구성 프로모션은 [쿠폰](/coupons)(Pro)을 참조하세요.

:::info 할인 합계를 찾고 계신가요?
계산대에서 인하한 가격은 WooCommerce 할인이 아니라 품목의 세일 가격으로 기록됩니다 — 기본 **할인** 합계는 쿠폰용으로 예약되어 있습니다. [가격 변경과 쿠폰이 다르게 추적되는 이유](#why-tracked-differently)에서 이 모델을 설명합니다. v1.9.0으로 업데이트한 후 합계가 변경되었다면 [v1.9.0에서 변경된 사항](#what-changed-in-v190)을 참조하세요.
:::

## 빠른 할인 {#quick-discounts}

빠른 할인 버튼을 사용하면 한 번의 탭으로 전체 주문에 비율 할인을 적용할 수 있습니다.

구성하려면 장바구니 [표시 설정](/pos/cart#display-settings)을 열고 **빠른 할인** 필드에 쉼표로 구분한 비율 목록을 입력합니다. 예를 들어 `5,10,15,20`은 바로 가기 버튼 4개를 생성합니다.

빠른 할인 버튼을 탭하면 해당 비율이 장바구니의 모든 품목에 적용됩니다.

## 항목별 할인 {#line-item-discounts}

장바구니에서 개별 품목의 가격을 직접 변경할 수 있습니다:

1. 품목의 **가격** 필드를 클릭합니다
2. 새 가격을 입력합니다
3. **Enter** 키를 눌러 확인합니다

가격 맞춤, 직원 할인 또는 일회성 조정에 유용합니다. 품목 합계는 수량 × 새 가격을 기준으로 자동 업데이트됩니다.

장바구니 품목 편집에 대한 자세한 내용은 [품목](/pos/cart/line-items)을 참조하세요.

:::tip 품목 분할
고객이 같은 상품의 일부에 서로 다른 할인을 적용하려는 경우(예: 3개는 정상가, 2개는 할인), 장바구니 [표시 설정](/pos/cart#display-settings)에서 **분할** 옵션을 활성화하여 하나의 품목을 별도의 행으로 나눕니다.
:::

## 주문 전체 할인 {#order-level-discounts}

개별 품목이 아닌 전체 주문에 정액 할인을 적용하려면 **음수 수수료**를 추가합니다:

1. 장바구니 품목 아래의 **수수료 추가**를 클릭합니다
2. 이름을 입력합니다(예: "직원 할인")
3. 할인 금액을 음수로 입력합니다(예: `-5.00`)

수수료는 별도의 항목으로 표시되며 주문 합계를 줄입니다. 필요한 경우 점 3개 메뉴에서 수수료의 세금 상태와 세금 등급을 수정할 수 있습니다.

### 할인 수수료에 세금이 계산되는 방식 {#discount-fee-tax}

WCPOS는 음수 수수료에 **수수료 자체의 세금 설정**을 기준으로 세금을 부과합니다: 세금 상태를 **없음**으로 설정하면 세금이 적용되지 않고, **과세 대상**으로 두면 수수료 자체의 세금 등급으로 과세됩니다. 입력한 금액이 곧 차감되는 금액입니다 — `-10.00`을 입력하면 고객은 10만큼 적게 지불합니다.

WooCommerce 코어는 이를 다르게 처리합니다. WooCommerce는 기본적으로 음수 수수료를 장바구니 전체 할인으로 취급하고, 수수료에 설정한 세금 상태를 무시한 채 주문 내 다른 모든 품목의 세금 등급에 걸쳐 세금을 분산시킵니다. 또한 세금 포함 가격을 고려하지 않으므로, **세금 포함 가격 입력**이 *예*로 설정된 스토어에서는 20% 세율일 때 `-10.00` 수수료가 **12.00**을 차감합니다. WCPOS는 이를 재정의하여 계산대가 계산원이 입력한 금액을 정확히 차감하도록 합니다.

이 처리 방식은 사용하는 앱이 아니라 주문 자체에 속합니다 — **WP Admin → 주문**에서 POS 주문을 다시 계산해도 바뀌지 않습니다. POS 이외의 주문은 WooCommerce의 표준 동작을 유지합니다.

:::note 세금 포함 스토어의 알려진 제한 사항
가격에 세금이 포함되어 있는 경우, 할인 수수료는 고객에게 올바른 합계를 제공하지만 **주문에 기록된 세금은 변경하지 않습니다** — 따라서 세금 수치가 인하된 금액이 엄밀히 요구하는 것보다 약간 높게 나옵니다. 이는 항상 세무 당국에 유리한 방향으로 오차가 발생하며, 그 반대는 아닙니다. 기록된 세금이 회계에 중요하다면 할인에 [쿠폰](/coupons)을 대신 사용하세요: 쿠폰은 과세 대상 금액을 줄이고 그에 맞춰 세금을 올바르게 다시 계산합니다. 우리는 바로 이 이유로 향후 릴리스에서 주문 수준 POS 할인을 쿠폰으로 이전할 예정입니다.
:::

## POS 할인과 WooCommerce 쿠폰 비교 {#pos-discounts-vs-woocommerce-coupons}

이 페이지의 할인은 계산원이 계산대에서 적용하는 즉석 조정이며, WooCommerce **쿠폰**은 규칙과 추적 기능이 미리 설정된 프로모션입니다. 한눈에 비교하면 다음과 같습니다:

| | POS 할인 | WooCommerce 쿠폰(Pro) |
|---|---|---|
| **적용 방법** | 빠른 할인, 항목 가격 수정 또는 음수 수수료 | 장바구니에 쿠폰 코드 입력 |
| **설정 위치** | 계산원이 즉석에서 설정 | **WP Admin → 마케팅 → 쿠폰**에서 미리 설정 |
| **추적** | 세일 가격처럼 항목 가격으로 기록됨([이유](#why-tracked-differently) 참조) | WooCommerce 보고서에서 쿠폰 할인으로 추적됨 |
| **제한 사항** | 없음 — 계산원이 원하는 가격을 설정 | 사용 한도, 상품/카테고리 제한, 최소 구매 금액, 만료일, 이메일 규칙 |
| **적합한 용도** | 즉석 조정, 가격 맞춤 | 체계적인 프로모션, 추적 가능한 할인 |

:::tip 어떤 것을 사용해야 하나요?
일회성 가격 조정에는 이 페이지의 할인이 더 간편합니다. WooCommerce 보고서에서 할인 사용을 추적하거나 사용 횟수 제한과 같은 규칙을 적용해야 하는 경우 [쿠폰](/coupons)을 사용하세요.
:::

## 가격 변경과 쿠폰이 다르게 추적되는 이유 {#why-tracked-differently}

WooCommerce에는 할인에 대한 기본 개념이 정확히 하나 있습니다: **쿠폰**. 쿠폰은 주문에 속하며 — 자체 필드에 기록되고, 보고서의 **할인** 열에 집계되며, 사용 한도와 만료일 같은 자체 규칙을 지닙니다.

**세일 가격**은 WooCommerce에게 할인이 아닙니다. 그것은 단지 지금 이 순간의 상품 가격입니다: 세일 중인 품목이 판매되면 주문에는 지불한 가격만 기록될 뿐 그 외에는 없습니다. 정가는 주문에 절대 나타나지 않으며, 보고서는 해당 판매를 일반 매출로 집계합니다 — WooCommerce 자체는 고객이 무언가를 절약했다는 기록을 전혀 남기지 않습니다.

빠른 할인과 항목별 가격 수정은 세일 가격 모델을 따릅니다: 품목은 계산원이 설정한 가격으로 "세일" 판매됩니다. 그 하나의 규칙이 이 페이지의 나머지를 설명합니다 — WooCommerce **할인** 합계는 0으로 유지되고, 쿠폰은 인하된 가격을 기준으로 계산되며, "세일 품목 제외" 쿠폰은 계산대에서 인하한 품목을 건너뜁니다. (주문 수준 음수 수수료는 또 다릅니다: 가격 변경이 아니라 수수료 항목으로 기록됩니다.)

영수증은 고객이 자신이 얼마나 절약했는지 보기를 기대하는 유일한 곳이므로, WCPOS는 각 항목에 새 가격과 함께 정가를 기록합니다. 이를 통해 영수증은 WooCommerce의 주문 합계나 보고서를 변경하지 않고도 세일 절감액과 쿠폰 할인을 어느 쪽도 이중으로 집계하지 않으며 별도의 수치로 표시할 수 있습니다.

## POS 가격 변경과 쿠폰의 상호작용 {#how-pos-price-changes-interact-with-coupons}

계산원이 품목에 맞춤 가격을 설정하고(예: $18을 $16으로 인하) 이후 쿠폰이 적용되면, 쿠폰은 원래 가격($18)이 아닌 **POS 할인 적용 가격**($16)을 기준으로 계산됩니다. 이는 계산원 할인과 쿠폰을 원래 가격에 중복 적용하여 고객에게 과도한 할인이 제공되는 것을 방지합니다.

- WooCommerce에서는 POS 할인 적용 품목을 "세일 중"으로 취급합니다. 쿠폰에서 **세일 품목 제외**가 활성화되어 있으면, 일반 세일 품목을 건너뛰는 것과 같은 방식으로 POS 할인 적용 품목을 건너뜁니다. 개발자는 `woocommerce_pos_item_is_on_sale` 필터로 이 동작을 재정의할 수 있습니다.
- 쿠폰을 제거해도 품목은 POS 할인 적용 가격으로 유지됩니다.

:::note 개발자 참조
POS 가격 재정의가 저장되는 방식과 사용 가능한 필터에 대한 기술적 세부 정보는 [POS 할인 참조](/reference/pos-discounts)를 참조하세요.
:::

## v1.9.0에서 변경된 사항 {#what-changed-in-v190}

v1.8에서 업그레이드한 후 영수증과 보고서의 **할인** 합계가 이제 **0**으로 표시된다면, 그 이유는 다음과 같습니다: 이전 버전에서는 계산대 가격 변경을 WooCommerce 할인으로 기록했는데, 이는 쿠폰 계산을 깨뜨렸습니다 — 위에 적용된 쿠폰이 원래 가격을 기준으로 계산되어 주문에 과도한 할인이 적용되고 고객에게 적은 금액이 청구되었습니다. v1.9.0부터는 계산대에서 설정한 가격이 곧 항목 가격이며, WooCommerce가 세일 중인 상품을 기록하는 방식과 정확히 같고, 쿠폰만 할인으로 집계됩니다. 위의 [가격 변경과 쿠폰이 다르게 추적되는 이유](#why-tracked-differently)를 참조하세요.

### 이것이 의미하는 바 {#what-this-means-for-you}

- **영수증**에는 기록된 정가, 정가에서 판매가로의 절감액, 그리고 해당 절감액과 쿠폰을 합산한 **총 절감액** 값을 표시할 수 있습니다. 가격 절감액은 WooCommerce **할인** 필드와 별도로 유지됩니다.
- **보고서**에는 POS 항목별 가격 변경만 사용한 경우 `discount_total = 0`이 표시됩니다. 쿠폰 할인만 집계됩니다.
- **쿠폰**은 이제 POS 할인 적용 품목에 중복 적용해도 올바르게 계산됩니다.
- **기록된 정가와 판매가가 저장됩니다** — POS 항목 메타데이터(`_woocommerce_pos_data`)에 저장되므로, WooCommerce의 할인 합계를 변경하지 않고도 영수증에서 절감액을 도출할 수 있습니다.

### 영수증에 원래 가격과 절감액 표시 {#showing-the-original-price-and-saving-on-receipts}

현재 번들로 제공되는 가격 표시 템플릿은 상품이 세일 중이거나 계산대에서 가격이 변경된 경우 기록된 정가와 절감액을 표시합니다. 또한 WCPOS가 주문 전체 수준의 완전한 수치를 계산할 수 있을 때 **총 절감액**도 표시합니다. 이 총액은 정가 기준 절감액과 쿠폰 할인을 어느 쪽도 이중으로 집계하지 않고 합산합니다.

갤러리에서 복사한 템플릿은 편집 가능한 스냅샷이며 WCPOS 업데이트로 덮어쓰이지 않습니다. 이 변경 이전에 영수증을 만들었다면 다음 중 하나를 수행하세요:

1. 번들 템플릿의 새 복사본에서 **템플릿 사용**을 클릭하거나
2. 기존 템플릿을 [영수증 데이터 참조](/receipts/receipt-data#displaying-regular-price-and-savings)의 필드로 업데이트합니다.

주요 영수증 필드는 다음과 같습니다:

| 필드 | 의미 |
|-------|---------|
| `lines[].regular_price_display` | 기록된 정상 단가 |
| `lines[].selling_price_display` | 쿠폰 적용 전 판매 단가 |
| `lines[].unit_savings_display` | 항목당 절감액 |
| `lines[].line_regular_total_display` | 해당 항목의 정가 합계 |
| `lines[].line_savings_display` | 해당 항목의 총 절감액 |
| `totals.sale_savings_total_display` | 카탈로그 세일 및 계산대 가격 변경으로 인한 정가 대비 판매가 총 절감액 |
| `totals.discount_total_display` | WooCommerce 할인 합계이며, 일반적으로 현재 주문에 적용된 쿠폰입니다 |
| `totals.total_saved_display` | 정가 기준 절감액과 WooCommerce 할인의 합계 |
| `totals.total_saved_complete` | 합계가 완전하며 안전하게 표시할 수 있는지 여부 |

사용자 지정 템플릿에서는 이전 가격 데이터가 불완전하거나 절약된 금액이 없을 때 **총 절감액** 행이 사라지도록 처리해야 합니다 — 정확한 패턴은 [영수증 데이터 참조](/receipts/receipt-data#totals)를 확인하세요.

WooCommerce 보고서는 변경되지 않습니다: 기본 할인 합계에는 여전히 현재 세일 가격이나 계산대 가격 절감액이 아니라 쿠폰이 포함됩니다. 영수증에는 `totals.total_saved`를 사용하고, 절감액을 보고서에서도 WooCommerce 할인으로 추적해야 하는 경우 계속해서 [쿠폰](/coupons)을 사용하세요.

## 알려진 제한 사항 {#known-limitations}

- **자동 할인 규칙 없음** — POS는 "2개 구매 시 1개 무료" 방식의 자동 할인을 지원하지 않습니다. 체계적인 프로모션에는 WooCommerce 쿠폰을 사용하세요.
- **빠른 할인은 비율만 지원** — 고정 금액 할인을 위한 기본 제공 빠른 버튼은 없습니다. 대신 음수 수수료를 사용하거나 개별 가격을 수정하세요.
- **할인 수수료와 세금 포함 가격** — 주문 수준 할인 수수료는 올바른 합계를 청구하지만 주문에 기록된 세금은 줄이지 않습니다. [할인 수수료에 세금이 계산되는 방식](#discount-fee-tax)을 참조하세요.
