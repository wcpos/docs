WCPOS에서는 캐셔가 빠른 비율 할인 버튼, 품목별 직접 가격 수정, 주문 전체 할인 수수료 등 여러 방법으로 주문에 즉시 할인을 적용할 수 있습니다. 사용 규칙을 미리 설정한 프로모션은 [쿠폰](/1.x/coupons)(Pro)을 참조하세요.

:::info 할인 합계를 찾고 계신가요?
계산대에서 인하한 가격은 WooCommerce 할인이 아니라 품목의 세일 가격으로 기록됩니다 — 기본 **할인** 합계는 쿠폰용으로 예약되어 있습니다. [가격 변경과 쿠폰이 다르게 추적되는 이유](#why-tracked-differently)에서 이 모델을 설명합니다. v1.9.0으로 업데이트한 후 합계가 변경되었다면 [v1.9.0에서 변경된 사항](#what-changed-in-v190)을 참조하세요.
:::

## 빠른 할인 {#quick-discounts}

빠른 할인 버튼을 사용하면 한 번 눌러 항목 가격에서 일정 비율을 할인할 수 있습니다.

설정하려면 장바구니의 [표시 설정](/1.x/pos/cart#display-settings)을 열고 **빠른 할인** 필드에 쉼표로 구분한 할인율 목록을 입력하세요. 예를 들어 `5,10,15,20`을 입력하면 바로가기 버튼 네 개가 만들어집니다.

항목의 **가격** 필드를 클릭하면 열리는 숫자 패드에 버튼이 표시됩니다. 버튼을 누르면 해당 항목 가격이 선택한 비율만큼 낮아집니다. **완료**를 눌러 확정하세요. 각 항목은 개별적으로 할인되므로 여러 항목을 할인하려면 각 항목에서 반복하세요. 주문 전체를 한 번에 할인하는 버튼은 없습니다. 이 경우 [주문 수준 할인](#order-level-discounts)을 사용하세요.

## 항목별 할인 {#line-item-discounts}

장바구니에서 개별 품목의 가격을 직접 변경할 수 있습니다:

1. 품목의 **가격** 필드를 클릭하세요
2. 새 가격을 입력하세요
3. **Enter** 키를 눌러 확정하세요

가격 맞춤, 직원 할인 또는 일회성 조정에 유용합니다. 품목 합계는 수량 × 새 가격을 기준으로 자동 업데이트됩니다.

장바구니 품목 편집에 대한 자세한 내용은 [품목](/1.x/pos/cart/line-items)을 참조하세요.

:::tip 품목 분할
고객이 같은 상품의 일부에 서로 다른 할인을 적용하려는 경우(예: 3개는 정가, 2개는 할인), 장바구니 [표시 설정](/1.x/pos/cart#display-settings)에서 **분할** 옵션을 활성화하여 하나의 품목을 여러 행으로 나누세요.
:::

## 주문 전체 할인 {#order-level-discounts}

개별 품목이 아닌 주문 전체에 정액 할인을 적용하려면 **음수 수수료**를 추가하세요:

1. 장바구니 품목 아래의 **수수료 추가**를 클릭하세요
2. 이름을 입력하세요(예: “직원 할인”)
3. 할인 금액을 음수로 입력하세요(예: `-5.00`)

수수료는 별도의 품목으로 표시되며 주문 합계를 줄입니다. 필요한 경우 점 세 개 메뉴에서 수수료의 세금 상태와 세금 등급을 수정할 수 있습니다.

### 할인 수수료에 세금이 계산되는 방식 {#discount-fee-tax}

WCPOS는 **수수료 자체의 세금 설정**에 따라 음수 수수료에 세금을 적용합니다. 세금 상태를 **없음**으로 설정하면 세금이 적용되지 않으며, **과세 대상**으로 두면 수수료 자체의 세금 등급으로 과세됩니다. 입력한 금액만큼 차감되므로 `-10.00`을 입력하면 고객은 10만큼 적게 지불합니다.

WooCommerce 코어는 이를 다르게 처리합니다. WooCommerce는 기본적으로 음수 수수료를 장바구니 전체 할인으로 취급하고, 수수료에 설정한 세금 상태를 무시한 채 주문 내 다른 모든 품목의 세금 등급에 걸쳐 세금을 배분합니다. 또한 세금 포함 가격을 고려하지 않으므로 **세금 포함 가격 입력**이 *예*로 설정된 매장에서는 세율이 20%일 때 `-10.00` 수수료가 **12.00**을 차감합니다. WCPOS는 이 동작을 재정의하여 계산대에서 캐셔가 입력한 금액만큼 정확히 차감하도록 합니다.

이 처리 방식은 사용 중인 앱이 아닌 주문 자체에 적용됩니다. **WP Admin → 주문**에서 POS 주문을 다시 계산해도 달라지지 않습니다. POS 이외의 주문은 WooCommerce의 표준 동작을 유지합니다.

:::note 세금 포함 가격을 사용하는 매장의 알려진 제한 사항
가격에 세금이 포함되어 있으면 할인 수수료를 적용해도 고객에게 청구되는 합계는 정확하지만 **주문에 기록된 세금은 변경되지 않습니다**. 따라서 세금 금액이 인하된 금액을 기준으로 계산한 값보다 약간 높게 기록됩니다. 오차는 항상 세무 당국에 유리한 방향으로만 발생합니다. 장부 관리에서 기록된 세금이 중요하다면 할인에 [쿠폰](/1.x/coupons)을 대신 사용하세요. 쿠폰은 과세 대상 금액을 줄이고 그에 맞게 세금을 정확히 다시 계산합니다. 바로 이 이유로 향후 릴리스에서는 주문 전체 POS 할인을 쿠폰 방식으로 전환할 예정입니다.
:::

## POS 할인과 WooCommerce 쿠폰 비교 {#pos-discounts-vs-woocommerce-coupons}

이 페이지의 할인은 캐셔가 계산대에서 즉석으로 적용하는 조정입니다. 반면 WooCommerce **쿠폰**은 규칙과 추적 기능을 미리 설정한 프로모션입니다. 한눈에 비교하면 다음과 같습니다:

| | POS 할인 | WooCommerce 쿠폰(Pro) |
|---|---|---|
| **적용 방법** | 빠른 할인, 품목 가격 수정 또는 음수 수수료 | 장바구니에 쿠폰 코드 입력 |
| **설정 위치** | 캐셔가 즉석에서 설정 | **WP Admin → 마케팅 → 쿠폰**에서 미리 설정 |
| **추적** | 세일 가격처럼 항목 가격으로 기록됨([이유](#why-tracked-differently) 참조) | WooCommerce 보고서에서 쿠폰 할인으로 추적됨 |
| **제한 사항** | 없음 — 캐셔가 원하는 가격을 설정 | 사용 한도, 상품/카테고리 제한, 최소 구매 금액, 만료일, 이메일 규칙 |
| **적합한 용도** | 즉석 조정, 가격 맞춤 | 체계적인 프로모션, 추적 가능한 할인 |

:::tip 어떤 것을 사용해야 하나요?
일회성 가격 조정에는 이 페이지의 할인이 더 간편합니다. WooCommerce 보고서에서 할인 사용을 추적하거나 사용 한도와 같은 규칙을 적용해야 한다면 [쿠폰](/1.x/coupons)을 사용하세요.
:::

## 가격 변경과 쿠폰이 다르게 추적되는 이유 {#why-tracked-differently}

WooCommerce가 기본적으로 할인으로 취급하는 것은 **쿠폰**뿐입니다. 쿠폰은 주문에 속하며, 별도의 필드에 기록되고 보고서의 **할인** 열에 집계됩니다. 또한 사용 한도와 만료일 같은 자체 규칙이 있습니다.

WooCommerce는 **세일 가격**을 할인으로 취급하지 않습니다. 세일 가격은 단순히 상품의 현재 가격입니다. 세일 상품이 판매되면 주문에는 실제 지불한 가격만 기록됩니다. 정가는 주문에 기록되지 않고, 보고서에는 일반 매출로 집계됩니다. WooCommerce 자체는 고객이 절약한 금액을 기록하지 않습니다.

빠른 할인과 품목별 가격 수정은 세일 가격 방식을 따릅니다. 즉, 캐셔가 설정한 가격으로 상품을 ‘할인 판매’합니다. 이 규칙으로 이 페이지의 나머지 내용도 설명됩니다. WooCommerce의 **할인** 합계는 영으로 유지되고, 쿠폰은 인하된 가격을 기준으로 계산되며, ‘세일 품목 제외’ 쿠폰은 계산대에서 가격을 낮춘 품목을 건너뜁니다. (주문 전체에 적용한 음수 수수료는 또 다릅니다. 가격 변경이 아닌 수수료 항목으로 기록됩니다.)

고객은 영수증에서 절약한 금액을 확인하기를 기대하므로 WCPOS는 각 품목에 새 가격과 함께 정가를 기록합니다. 이를 통해 영수증에 세일 절감액과 쿠폰 할인을 각각 표시할 수 있습니다. 어느 쪽도 중복 집계하지 않으며, WooCommerce의 주문 합계나 보고서도 변경하지 않습니다.

## POS 가격 변경과 쿠폰의 상호작용 {#how-pos-price-changes-interact-with-coupons}

캐셔가 품목에 맞춤 가격을 설정한 뒤(예: $18에서 $16으로 인하) 쿠폰을 적용하면, 쿠폰은 원래 가격($18)이 아닌 **POS 할인 적용 가격**($16)을 기준으로 계산됩니다. 이렇게 하면 캐셔 할인과 쿠폰을 원래 가격에 중복 적용하여 과도하게 할인하는 일을 방지할 수 있습니다.

- WooCommerce는 POS 할인 적용 품목을 ‘세일 중’으로 취급합니다. 쿠폰에서 **세일 품목 제외**가 활성화되어 있으면 일반 세일 품목과 마찬가지로 POS 할인 적용 품목도 건너뜁니다. 개발자는 `woocommerce_pos_item_is_on_sale` 필터로 이 동작을 재정의할 수 있습니다.
- 쿠폰을 제거해도 품목은 POS 할인 적용 가격으로 유지됩니다.

:::note 개발자 참조
POS 가격 재정의가 저장되는 방식과 사용 가능한 필터에 대한 기술적 세부 정보는 [POS 할인 참조](/1.x/reference/pos-discounts)를 참조하세요.
:::

## v1.9.0에서 변경된 사항 {#what-changed-in-v190}

v1.8에서 업그레이드한 후 영수증과 보고서의 **할인** 합계가 이제 **0**으로 표시된다면, 그 이유는 다음과 같습니다: 이전 버전에서는 계산대 가격 변경을 WooCommerce 할인으로 기록했는데, 이는 쿠폰 계산을 깨뜨렸습니다 — 위에 적용된 쿠폰이 원래 가격을 기준으로 계산되어 주문에 과도한 할인이 적용되고 고객에게 적은 금액이 청구되었습니다. v1.9.0부터는 계산대에서 설정한 가격이 곧 항목 가격이며, WooCommerce가 세일 중인 상품을 기록하는 방식과 정확히 같고, 쿠폰만 할인으로 집계됩니다. 위의 [가격 변경과 쿠폰이 다르게 추적되는 이유](#why-tracked-differently)를 참조하세요.

### 사용자에게 미치는 영향 {#what-this-means-for-you}

- **영수증**에는 기록된 정가, 정가 대비 판매가 절감액, 해당 절감액과 쿠폰 할인을 합산한 **총 절감액**을 표시할 수 있습니다. 가격 절감액은 WooCommerce의 **할인** 필드와 별도로 유지됩니다.
- **보고서**에는 POS 품목별 가격 변경만 사용한 경우 `discount_total = 0`이 표시됩니다. 쿠폰 할인만 집계됩니다.
- **쿠폰**은 이제 POS 할인 적용 품목에 중복 적용해도 올바르게 계산됩니다.
- **기록된 정가와 판매가가 저장됩니다**. 저장 위치는 POS 품목 메타데이터(`_woocommerce_pos_data`)이며, 영수증에서는 WooCommerce의 할인 합계를 변경하지 않고도 이를 통해 절감액을 계산할 수 있습니다.

### 영수증에 원래 가격과 절감액 표시 {#showing-the-original-price-and-saving-on-receipts}

현재 기본 제공되는 가격 표시 템플릿은 상품이 세일 중이거나 계산대에서 가격이 변경되면 기록된 정가와 절감액을 표시합니다. WCPOS가 주문 전체의 완전한 절감액을 계산할 수 있으면 **총 절감액**도 표시합니다. 이 합계는 정가 대비 절감액과 쿠폰 할인을 중복 집계 없이 합산한 값입니다.

갤러리에서 복사한 템플릿은 편집 가능한 스냅샷이며 WCPOS 업데이트로 덮어쓰이지 않습니다. 이 변경 이전에 영수증을 만들었다면 다음 중 하나를 수행하세요:

1. 기본 제공 템플릿의 새 복사본에서 **템플릿 사용**을 클릭하거나
2. [영수증 데이터 참조](/1.x/receipts/receipt-data#displaying-regular-price-and-savings)의 필드로 기존 템플릿을 업데이트하세요.

주요 영수증 필드는 다음과 같습니다:

| 필드 | 의미 |
|-------|---------|
| `lines[].regular_price_display` | 기록된 정상 단가 |
| `lines[].selling_price_display` | 쿠폰 적용 전 판매 단가 |
| `lines[].unit_savings_display` | 품목당 절감액 |
| `lines[].line_regular_total_display` | 해당 품목의 정가 합계 |
| `lines[].line_savings_display` | 해당 품목의 총 절감액 |
| `totals.sale_savings_total_display` | 카탈로그 세일 및 계산대 가격 변경으로 인한 정가 대비 판매가 총 절감액 |
| `totals.discount_total_display` | WooCommerce 할인 합계. 현재 주문에서는 일반적으로 쿠폰 할인 |
| `totals.total_saved_display` | 정가 대비 절감액과 WooCommerce 할인의 합계 |
| `totals.total_saved_complete` | 합계가 완전하여 표시해도 되는지 여부 |

사용자 지정 템플릿에서는 과거 가격 데이터가 불완전하거나 절감액이 없을 때 **총 절감액** 행이 표시되지 않도록 조건을 설정해야 합니다. 정확한 구현 방식은 [영수증 데이터 참조](/1.x/receipts/receipt-data#totals)를 확인하세요.

WooCommerce 보고서는 변경되지 않습니다. 기본 할인 합계에는 현재 세일 가격이나 계산대 가격 변경으로 인한 절감액이 아닌 쿠폰 할인만 포함됩니다. 영수증에는 `totals.total_saved`를 사용하고, 절감액을 보고서에서도 WooCommerce 할인으로 추적해야 한다면 계속해서 [쿠폰](/1.x/coupons)을 사용하세요.

## 알려진 제한 사항 {#known-limitations}

- **자동 할인 규칙 없음** — POS는 ‘2개 구매 시 1개 무료’ 방식의 자동 할인을 지원하지 않습니다. 체계적인 프로모션에는 WooCommerce 쿠폰을 사용하세요.
- **빠른 할인은 비율만 지원** — 정액 할인을 위한 빠른 버튼은 기본 제공되지 않습니다. 대신 음수 수수료를 사용하거나 개별 가격을 수정하세요.
- **할인 수수료와 세금 포함 가격** — 주문 수준 할인 수수료는 올바른 합계를 청구하지만 주문에 기록된 세금은 줄이지 않습니다. [할인 수수료에 세금이 계산되는 방식](#discount-fee-tax)을 참조하세요.
