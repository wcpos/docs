# API06003: 잘못된 사이트 구성 {#api06003-invalid-site-configuration}

## 의미 {#what-this-means}

사이트 구성이 잘못되었거나 불완전합니다. 이는 잘못된 URL, 인증 설정 또는 기타 구성 문제와 관련이 있을 수 있습니다.

## 일반적인 원인 {#common-causes}

- **부분 구성** — 일부 설정이 누락됨
- **일치하지 않는 설정** — 구성과 사이트가 일치하지 않음
- **손상된 구성** — 설정이 손상됨
- **사이트 변경** — 사이트가 변경되었지만 POS 구성을 업데이트하지 않음

## 해결 방법 {#how-to-fix}

### 1. 모든 설정 검토 {#1-review-all-settings}

전체 구성을 확인합니다:
- 사이트 URL이 올바른지
- 인증이 제대로 구성되었는지
- 기타 추가 설정이 올바른지

### 2. 처음부터 재구성 {#2-reconfigure-from-scratch}

:::warning 저장되지 않은 작업을 먼저 확인하세요
로컬 데이터를 지우거나 앱을 다시 설치하면 오프라인에서 진행한 판매, 열린 장바구니, 저장되지 않은 수정 사항 등 매장에 아직 도착하지 않은 이 기기의 모든 데이터가 삭제됩니다. 삭제하기 전에 **매장 상태 → 데이터베이스**를 열어 보류 중이거나 서버에 도착하지 않은 항목이 없는지 확인한 다음, **매장 상태 → 로그**에서 **멈춘 레코드 0개** 및 **전송 대기 중인 변경 사항 0개**인지 확인하세요. 그런 다음 열린 장바구니를 모두 마무리하거나 기록해 두세요. WCPOS에 매장 상태 페이지가 없다면 먼저 WCPOS를 업데이트한 다음 확인하세요. 항목이 있거나 전송 대기 중이거나 확인할 수 없다면 삭제하지 마세요. 매장 소유자에게 문의하거나 지원팀에 연락하세요.
:::

구성이 손상된 경우에만, 위 확인 절차를 마친 뒤 진행하세요:
1. 모든 저장된 설정 지우기
2. 설치 프로세스를 다시 시작
3. 새로운 구성을 입력

### 3. 사이트 요구사항 확인 {#3-check-site-requirements}

귀하의 WordPress 사이트가 요구사항을 충족하는지 확인합니다:
- WordPress가 설치되어 있고 접근 가능
- WooCommerce가 설치되어 있고 활성화됨
- WCPOS 플러그인이 설치되어 있고 활성화됨
- 고유 링크가 활성화됨 (평범하지 않음)

### 4. 사이트 접근 테스트 {#4-test-site-access}

웹 브라우저에서 이 URL이 작동하는지 확인합니다:
- `https://yoursite.com/` — 메인 사이트
- `https://yoursite.com/wp-json/` — REST API
- `https://yoursite.com/wp-json/wcpos/v1/` — WCPOS API

### 5. WordPress 설정 확인 {#5-check-wordpress-settings}

WordPress 관리자에서:
1. 설정 → 일반 — URL 확인
2. 설정 → 고유 링크 — 평범하지 않도록 보장
3. WooCommerce → 상태 — 문제 확인

## 구성 요구사항 {#configuration-requirements}

유효한 구성에는 다음이 필요합니다:
- **사이트 URL** — 프로토콜이 포함된 전체 URL
- **인증** — 유효한 자격 증명 또는 API 키
- **권한** — 사용자가 POS 접근 권한이 있음
- **플러그인** — 필수 플러그인이 활성화됨
