## 이것이 의미하는 바 {#what-this-means}

이 기기의 레코드 사본이 매장의 사본과 일치하지 않습니다. 입력한 내용에는 영향이 없습니다.

**스토어 상태 → 데이터베이스**에서 해당 목록의 **초기화 후 다시 다운로드**를 사용해 이 기기의 사본을 매장 사본으로 바꾸세요. 그전까지 레코드에 오래된 가격이나 재고가 표시될 수 있습니다. 먼저 전송 대기 중인 항목이 없는지 확인하세요. 문제 해결 항목을 참조하세요.

## 내 데이터 {#your-data}

판매 내역이나 전송되지 않은 변경 사항에는 영향이 없습니다. 이 기기의 레코드 사본은 교체될 때까지 오래된 가격이나 재고를 표시할 수 있습니다. 계속 발생하면 **로그** 탭에서 **디버그 정보 복사**를 사용하고 WCPOS 지원팀에 문의하세요.

## 문제 해결 {#troubleshoot}

1. 계속 판매하세요. **스토어 상태 → 데이터베이스**를 여세요. 레코드가 맨 위에 표시됩니다. 사본이 다른 레코드는 **"… 매장에서 다운로드할 수 없음"**에, 매장에서 삭제한 레코드는 **"… 이 기기에서 제거해야 함"**에 표시됩니다.
2. 해당 상품을 판매하기 전에 진열대나 매장 관리자에게 가격과 재고를 확인하세요(관리자는 WP Admin에서 비교할 수 있습니다).
3. 무엇이든 지우기 전에 **스토어 상태 → 데이터베이스**에서 **전송 대기 중인 변경 사항**이 0인지, **"… 서버에 전달되지 않은 변경 사항"** 또는 **"… 보류된 변경 사항"** 패널이 표시되지 않는지 확인하세요. 이 변경 사항은 이 기기에만 있으며 목록을 지우면 손실될 수 있습니다. 개수가 0이 될 때까지 기다리고, 표시된 변경 사항은 먼저 처리하세요([SYNC201](/error-codes/SYNC201), [SYNC221](/error-codes/SYNC221)). **주문**을 지우기 전에 이 기기의 열린 카트를 모두 **서버에 저장**으로 저장하거나 완료하세요. 매장에 한 번도 저장하지 않은 카트는 이 기기에만 있고 위 확인 항목에는 집계되지 않으므로 **주문**을 지우면 삭제됩니다. 카트를 저장할 수 없다면 **주문** 행은 건너뛰고 지원팀에 문의하세요. 그런 다음 레코드 목록(예: **상품**)에서 **⋮** 메뉴를 열고 **초기화 후 다시 다운로드…**를 선택하세요. 기기의 사본을 삭제하고 매장 사본을 가져오며, 삭제된 레코드는 제거됩니다. 다음 백그라운드 확인까지 항목이 목록에 남아 있을 수 있으므로 가격과 재고가 일치하는지 확인하세요. 이후 알림에 다른 목록의 레코드가 표시되면 먼저 확인을 마친 뒤 해당 목록에서도 이 단계를 반복하세요.
4. **사이트 관리자:** 다시 다운로드한 뒤에도 같은 레코드가 계속 나타나면 WooCommerce의 저장 후크를 거치지 않은 대량 변경이 원인인 경우가 많습니다. 예를 들어 CSV 가져오기, 마이그레이션 플러그인, WP-CLI 또는 직접 SQL이 해당합니다. WooCommerce를 통해 편집하는 것이 좋습니다. 그러면 POS의 검사가 정확하게 유지됩니다. 같은 차이가 반복되면 WCPOS가 자체적으로 무결성 데이터를 다시 만듭니다.
5. 다시 다운로드한 뒤에도 POS에 잘못된 가격이나 재고가 계속 표시되면 **로그** 탭에서 **디버그 정보 복사**를 사용하고 지원팀에 문의하세요.
