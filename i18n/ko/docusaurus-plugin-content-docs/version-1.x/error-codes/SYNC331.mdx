## 이것이 의미하는 바 {#what-this-means}

기기의 이 레코드가 스토어와 일치하지 않아 로컬 복구가 필요합니다.

입력하신 내용 중 전송 대기 중인 것은 없습니다. 스토어가 소유한 레코드의 기기 사본이 스토어의 사본과 어긋난 것이므로, 로그에 표시된 상태에 따라 복구하세요.

## 조치 방법 {#what-to-do}

WCPOS를 다시 시작하세요. 이 문제가 계속되면 이 기기의 로컬 데이터를 복구해야 합니다. WCPOS는 이 작업을 자동으로 재시도하지 않습니다. 준비되면 직접 재시도하세요.

## 내 데이터 {#your-data}

주문이나 상품 데이터에는 영향이 없습니다. 이 문제가 계속되면 진단 정보를 내보내고 WCPOS 지원팀에 문의하세요.

## 문제 해결 {#troubleshoot}

1. 로그 항목을 펼쳐 보세요. 컨텍스트에 컬렉션, 레코드 ID, 상태, 그리고 차이를 발견한 검출기가 표시됩니다.
2. 변경되었거나 누락된 레코드의 경우, 해당 컬렉션에 대해 대상 다운로드를 실행해 기기의 사본을 스토어의 사본으로 교체하세요.
3. 삭제된 레코드의 경우 로컬 사본을 제거하세요. 서버의 삭제 표식은 내려받아서는 안 됩니다.
4. WP Admin의 레코드와 POS에 표시된 내용을 비교하세요. 가격이나 재고의 차이가 눈에 띄는 증상입니다.
5. 복구 후에도 동일한 레코드가 계속 다시 나타난다면 스토어에 저장된 다이제스트가 오래된 것입니다. 이는 WooCommerce의 저장 훅을 거치지 않는 대량 쓰기(CSV 가져오기, 마이그레이션 플러그인, WP-CLI 또는 직접 SQL) 이후에 발생합니다. 레코드 자체는 대개 정상이며, 사이트 관리자가 무결성 색인을 다시 구성하면 해소됩니다. 또한 특정 범위에서 같은 차이가 계속 보고되면 WCPOS가 해당 재구성을 자동으로 예약합니다.
6. 재구성 후에도 계속 나타난다면 디버그 정보를 내보내고 지원팀에 문의하세요.

## 확인할 위치 {#where-to-look}

WCPOS가 이 오류를 저장할 수 있는 경우, 오류는 이를 발생시킨 기기에 기록됩니다. **스토어 상태 → 로그**(내비게이션 서랍 하단의 심박 아이콘)를 열고 이 코드가 표시된 항목을 찾아 펼치세요. 펼쳐진 행에는 알기 쉽게 설명된 원인과 오류가 발생한 시점에 수집된 컨텍스트가 표시됩니다. 스토어 요청의 경우 이 컨텍스트에 서버 자체의 오류 코드(`serverCode`), HTTP `status` 또는 `endpoint`가 포함될 수 있으며, 표시되는 필드는 오류가 발생한 위치에 따라 다릅니다. 문제를 신고할 때는 스크린샷 대신 로그 화면 상단의 **디버그 정보 복사**(휴대폰과 태블릿에서는 **디버그 정보 공유**)를 사용하세요. 여기에는 앱 버전, 연결 상태, 가장 최근의 오류가 함께 담깁니다. 로그는 최대 30일간만 보관되므로 문제가 발생한 직후에 수집하세요. 또한 POS가 자체 로그 항목을 기록하기 전에 나타난 브라우저 콘솔 오류가 있다면 함께 복사하세요.
