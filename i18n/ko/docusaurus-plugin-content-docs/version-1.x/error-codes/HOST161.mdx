## 이것이 의미하는 바 {#what-this-means}

호스트가 이 스토어의 계산대에 대해 속도를 제한하고 있습니다.

앱이 이미 요청 속도를 낮추고 서버의 Retry-After 지연을 준수하고 있는데도 서버가 계속 429(요청이 너무 많음)로 응답합니다. 하나의 인터넷 연결에 있는 여러 계산대가 하나의 주소를 공유하므로, 출처별 속도 제한은 이들을 하나의 매우 바쁜 클라이언트로 취급합니다. 동기화는 자동으로 계속되지만 제한이 상향될 때까지 지연됩니다.

## 내 데이터 {#your-data}

주문이나 상품 데이터는 영향을 받지 않습니다.

## 문제 해결 {#troubleshoot}

1. 스토어 자체 트래픽에 대해 REST API 속도 제한을 높이거나 면제하도록 호스트에 요청하세요 — 상점에 고정 IP가 있다면 그 IP를 알려주세요.
2. 반복되는 오류 응답(429)을 차단 기준으로 집계하는 보안 서비스(예: Sucuri의 IDS)는 해당 집계에서 스토어의 API를 제외해야 할 수 있습니다.
3. 여러 계산대가 하나의 연결을 공유하는 경우, 이를 호스트에게 알리세요: 여기서 하나의 IP는 한 명의 사용자가 아니라 상점 전체입니다.
