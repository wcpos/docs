## 이것이 의미하는 바 {#what-this-means}

이 사이트에서 WooCommerce가 활성화되어 있지 않아 WCPOS가 연결할 수 없습니다.

WCPOS에는 WooCommerce 플러그인이 필요합니다. 사이트 관리자에게 WooCommerce를 설치하거나 다시 활성화해 달라고 요청한 다음 다시 연결하세요.

## 조치 방법 {#what-to-do}

이 기능이 작동하려면 먼저 설정을 변경해야 합니다. 위의 변경을 적용한 후에 재시도하세요. 변경하지 않고 재시도하면 같은 방식으로 실패합니다.

## 내 데이터 {#your-data}

주문이나 상품 데이터에는 영향이 없습니다. 이 문제가 계속되면 WordPress 사이트를 관리하는 담당자에게 문의하세요.

## 문제 해결 {#troubleshoot}

1. 사이트 관리자에게 WP Admin → 플러그인을 확인해 달라고 요청하세요. WCPOS가 연결하려면 WooCommerce가 설치되어 활성화되어 있어야 합니다.
2. 업데이트 실패로 WooCommerce가 비활성화되었다면 다시 활성화하고 오류 배너가 표시되는지 확인하세요. 실패 원인은 WooCommerce → 상태 → 로그에 기록됩니다.
3. WooCommerce가 다시 활성화되면 계산대에서 다시 연결하세요.

## 확인할 위치 {#where-to-look}

WCPOS가 이 오류를 저장할 수 있는 경우, 오류는 이를 발생시킨 기기에 기록됩니다. **스토어 상태 → 로그**(내비게이션 서랍 하단의 심박 아이콘)를 열고 이 코드가 표시된 항목을 찾아 펼치세요. 펼쳐진 행에는 알기 쉽게 설명된 원인과 오류가 발생한 시점에 수집된 컨텍스트가 표시됩니다. 스토어 요청의 경우 이 컨텍스트에 서버 자체의 오류 코드(`serverCode`), HTTP `status` 또는 `endpoint`가 포함될 수 있으며, 표시되는 필드는 오류가 발생한 위치에 따라 다릅니다. 문제를 신고할 때는 스크린샷 대신 로그 화면 상단의 **디버그 정보 복사**(휴대폰과 태블릿에서는 **디버그 정보 공유**)를 사용하세요. 여기에는 앱 버전, 연결 상태, 가장 최근의 오류가 함께 담깁니다. 로그는 최대 30일간만 보관되므로 문제가 발생한 직후에 수집하세요. 또한 POS가 자체 로그 항목을 기록하기 전에 나타난 브라우저 콘솔 오류가 있다면 함께 복사하세요.

앱 내 로그 외에도 이 오류는 다음 위치에 흔적을 남길 수 있습니다:

- **WooCommerce → 상태 → 로그**: WordPress 사이트에서 가장 최근의 `fatal-errors-*.log`에 PHP 충돌이 있는지 확인하고, 이 오류와 관련된 플러그인 이름이 붙은 로그 소스도 함께 확인하세요. 스토어에서 발생한 500번대 오류는 거의 항상 그 원인을 여기에 남깁니다.
