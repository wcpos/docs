## 이 오류의 의미 {#what-this-means}

매장에서 이 변경 사항을 거부하여 이 기기가 매장 버전으로 되돌아갔습니다.

변경 사항이 저장되지 않았습니다. 매장의 거부 사유를 읽고 해당 내용을 수정한 다음 변경 사항을 다시 적용하세요.

기존 상품, 상품 옵션, 쿠폰 및 고객을 수정할 때 발생합니다. 매장에서 변경 사항을 영구적으로 거부하면(예: 값이 유효하지 않거나 로그인한 사용자에게 변경 권한이 없는 경우) WCPOS는 거부된 수정 사항을 대기 상태로 유지하지 않습니다. 매장 버전을 이 기기에 복원하여 POS에서 매장과 동일한 정보로 판매할 수 있도록 합니다. 로그 항목에 레코드와 매장의 거부 사유가 표시됩니다.

## 데이터 {#your-data}

그 밖의 변경 사항은 없습니다. 매장에는 기존 버전이 그대로 남아 있고 이 기기에도 해당 버전이 다시 표시됩니다. 매장에서 레코드를 삭제했다면 이 기기에서도 제거됩니다. 거부된 수정 사항만 사라졌으므로 사유를 해결한 뒤 다시 적용하세요. 판매와 주문에는 영향이 없으며, 거부된 변경 사항 이후 같은 레코드에 적용한 수정 사항은 유지되어 계속 전송됩니다.

## 문제 해결 {#troubleshoot}

1. 로그 항목을 펼쳐 매장의 거부 사유를 읽으세요. 거부된 항목과 해당 레코드를 확인할 수 있습니다.
2. 거부 사유에 나온 내용을 수정하세요. 가격, SKU, 이메일 주소 또는 비워 둔 필수 입력란 같은 값이 원인이라면 올바른 값을 확인하세요. 사용자에게 변경 권한이 없다는 내용이라면 계정 역할에 해당 작업 권한이 없는 것입니다. [AUTH201](/error-codes/AUTH201)을 참조하세요.
3. 레코드를 열고(매장에서 삭제했다면 수정할 내용이 없습니다) 올바른 값으로 변경한 다음 저장하세요. 동기화된 후 레코드에 변경 사항이 표시되는지 확인하세요.
4. 이 기기에서 만든 새 레코드가 매장에서 거부된 경우 되돌릴 매장 버전이 없으므로 되돌려지지 않습니다. **매장 상태 → 데이터베이스**의 **"… 변경 사항이 서버에 도달하지 않음"** 아래에 계속 표시됩니다. [SYNC201](/error-codes/SYNC201)을 참조하세요.
5. **사이트 관리자:** 거부 사유에 POS에서 표시하지 않는 필드가 언급되면 WP Admin에서 같은 레코드를 여세요. 다른 플러그인이 POS에서 확인할 수 없는 유효성 검사를 추가했을 수 있습니다. 매장에서 계속 변경 사항을 거부하면 **로그** 탭에서 **디버그 정보 복사**를 눌러 지원팀에 문의하세요.
