# DB03002: 잘못된 데이터 유형 {#db03002-invalid-data-type}

## 의미 {#what-this-means}

데이터 유형이 데이터베이스에서 기대하는 것과 일치하지 않습니다. 예를 들어, 숫자가 기대되는 곳에 텍스트가 제공되었습니다.

## 일반적인 원인 {#common-causes}

- **사용자 입력 오류** — 숫자 필드에 텍스트 입력
- **가져오기 문제** — 가져온 데이터의 형식이 잘못됨
- **데이터 손상** — 전송 중 값이 손상됨
- **플러그인 충돌** — 다른 플러그인이 데이터 유형을 변경함

## 해결 방법 {#how-to-fix}

### 1. 입력 내용 확인 {#1-check-your-input}

입력하는 데이터를 검토하세요:
- **가격** — 숫자여야 합니다 (예: `19.99`)
- **수량** — 정수여야 합니다 (예: `5`)
- **ID** — 숫자여야 합니다

### 2. 지우고 다시 입력 {#2-clear-and-re-enter}

데이터가 손상된 경우:
- 필드를 지우세요
- 값을 수동으로 다시 입력하세요
- 외부 소스에서 복사-붙여넣기를 피하세요

### 3. 원본 데이터 확인 {#3-check-source-data}

WooCommerce에서 동기화하는 경우:
- WordPress 관리에서 데이터를 확인하세요
- 잘못 형식이 지정된 필드를 찾아보세요
- 원본 데이터에서 수정하세요

### 4. 데이터 다시 동기화 {#4-re-sync-data}

:::warning 저장되지 않은 작업을 먼저 확인하세요
로컬 데이터를 지우거나 앱을 다시 설치하면 매장에 도착하지 않은 이 기기의 모든 데이터가 삭제됩니다. 오프라인 중 발생한 판매, 열린 장바구니, 저장되지 않은 수정 사항이 여기에 포함됩니다. 삭제하기 전에 **매장 상태 → 데이터베이스**를 열어 보류 중이거나 서버에 도달한 적 없는 항목이 없는지 확인한 다음, **매장 상태 → 로그**에서 **중단된 레코드 0개** 및 **전송 대기 중인 변경 사항 0개**인지 확인하세요. 이어서 열린 장바구니를 모두 완료하거나 내용을 기록해 두세요. WCPOS에 매장 상태 페이지가 없다면 먼저 WCPOS를 업데이트한 후 확인하세요. 항목이 있거나 전송 대기 중이거나 확인할 수 없다면 삭제하지 말고 매장 관리자에게 문의하거나 지원팀에 연락하세요.
:::

이 페이지의 다른 단계가 도움이 되지 않았을 때만, 그리고 위 확인을 마친 경우에만 서버에서 최신 데이터를 가져오세요:
- 로컬 캐시를 지우세요
- 데이터를 다시 동기화하세요
- 문제가 해결되는지 확인하세요

### 5. 플러그인 충돌 확인 {#5-check-for-plugin-conflicts}

다른 WooCommerce 플러그인을 사용하는 경우:
- 예상치 못한 방식으로 데이터를 수정할 수 있습니다
- 테스트를 위해 일시적으로 비활성화하세요
- 호환성 문제를 보고하세요

## 일반적인 예시 {#common-examples}

| 필드 | 예상 | 잘못된 |
|-------|----------|---------|
| 가격 | `19.99` | `$19.99` |
| 수량 | `5` | `five` |
| SKU | `ABC123` | — (모든 형식 가능) |
| 제품 ID | `42` | `product-42` |
