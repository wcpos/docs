## 이것이 의미하는 바 {#what-this-means}

매장에서 이 변경을 거부하여 매장에 반영되지 않았습니다.

매장의 거부 사유를 확인하세요. **스토어 상태 → 데이터베이스**에 변경 사항이 표시되면 레코드를 수정하고 **다시 보내기**를 누르거나 **삭제**를 누르세요. 표시되지 않으면 매장의 버전이 복원된 것입니다. 여전히 필요하다면 변경을 다시 적용하세요([SYNC202](/error-codes/SYNC202) 참조). 거부된 변경은 자동으로 다시 시도되지 않습니다.

## 내 데이터 {#your-data}

이 기기의 데이터를 삭제하지 마세요. 매장에 아직 반영되지 않은 변경 사항이 있을 수 있습니다. **스토어 상태 → 데이터베이스**에 표시된 거부된 변경 사항은 다시 보내거나 삭제할 때까지 남아 있습니다. 기존 상품, 옵션, 고객 또는 쿠폰의 거부된 수정은 보통 자동으로 취소되고 대신 [SYNC202](/error-codes/SYNC202)로 기록됩니다. 이 코드가 표시되고 변경 사항이 **스토어 상태 → 데이터베이스**에 있으면 자동 취소가 되지 않은 것이므로 아래의 다른 표시된 변경 사항과 동일하게 처리하세요. 계속 발생하면 **로그** 탭에서 **디버그 정보 복사**를 사용하고 WCPOS 지원팀에 문의하세요.

## 문제 해결 {#troubleshoot}

1. 매장의 거부 사유를 확인하세요. 로그 항목과 **스토어 상태 → 데이터베이스**의 변경 사항 행에 표시됩니다.
2. **스토어 상태 → 데이터베이스**를 여세요. 변경 사항이 표시되지 않으면 매장의 버전이 이 기기에 이미 복원되어 전송할 내용이 없습니다. [SYNC202](/error-codes/SYNC202)를 참조하세요. 사유에 언급된 내용을 수정한 다음, 여전히 필요하다면 변경을 다시 적용하세요.
3. 목록에 표시되어 있다면 — 주문, 이 기기에서 만든 레코드 또는 자동 취소되지 않은 카탈로그 수정 — 거부된 변경 사항은 **"… 서버에 전달되지 않은 변경 사항"** 아래에 매장의 사유와 함께 표시됩니다. 변경 사항이 목록에 남아 있는 동안 주문의 필드 등 레코드 자체에서 사유에 언급된 내용을 수정하세요.
4. 다시 **스토어 상태 → 데이터베이스**로 돌아가 해당 행에서 **다시 보내기**를 누르세요. 그러면 이 기기에 현재 있는 내용으로 변경 사항을 다시 만들고 전송합니다.
5. 변경 사항이 더 이상 필요하지 않다면 대신 **삭제**를 누르세요. 매장의 버전이 유지됩니다. 먼저 확인 메시지를 읽으세요. 매장이 저장한 적 없는 레코드를 삭제하면 이 기기에서도 삭제됩니다.
6. **사이트 관리자:** 사유에 사용자가 변경할 권한이 없다고 표시되면 해당 역할에 그 작업 권한이 없습니다. [AUTH201](/error-codes/AUTH201)을 참조하세요. 사유에 POS에 표시되지 않는 필드가 언급되면 WP Admin에서 같은 레코드를 여세요. 다른 플러그인이 POS에서 확인할 수 없는 유효성 검사를 추가했을 수 있습니다. 계속 거부되면 **로그** 탭에서 **디버그 정보 복사**를 사용하고 지원팀에 문의하세요.
