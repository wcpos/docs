# DB02002: 기록을 찾을 수 없음 {#db02002-record-not-found}

## 이 의미 {#what-this-means}

요청한 기록이 로컬 데이터베이스에 존재하지 않습니다. POS는 로컬에 저장되지 않은 제품, 고객, 주문 또는 기타 기록에 액세스하려고 했습니다.

## 일반적인 원인 {#common-causes}

- **아직 동기화되지 않음** — 데이터가 아직 다운로드되지 않음
- **서버에서 삭제됨** — WooCommerce에서 기록이 제거됨
- **동기화 미완료** — 초기 동기화가 계속 실행 중
- **적용된 필터** — 활성 필터에 의해 기록이 제외됨

## 해결 방법 {#how-to-fix}

### 1. 동기화 대기 {#1-wait-for-sync}

최근 시작한 경우:
- 초기 동기화가 완료될 때까지 기다림
- 동기화 진행 상태 표시기를 확인함
- 동기화가 완료되면 기록이 나타나야 함

### 2. 새로 고침/재동기화 {#2-refreshre-sync}

데이터 새로 고침을 트리거합니다:
- 새로 고침/동기화 버튼 사용 (<Icon name="arrow-rotate-right" />) - 짧게 눌러 동기화
- 여기서는 **길게 누르기**로 실행하는 지우기 및 새로 고침 옵션을 사용하지 마세요. 저장된 적 없는 열린 장바구니를 포함해 이 기기의 목록 전체가 비워집니다. 먼저 5단계를 확인하세요
- 서버에서 최신 데이터 가져오기
- 완료될 때까지 기다림

### 3. WooCommerce 확인 {#3-check-woocommerce}

서버에 기록이 존재하는지 확인합니다:
- WordPress 관리자에 로그인
- 제품, 주문 또는 고객 확인
- 항목이 여전히 존재하는지 확인

### 4. 필터 확인 {#4-check-filters}

기록이 필터링될 수 있음:
- POS에서 활성 필터 검토
- 카테고리 필터 확인
- 가시성 설정 확인

### 5. 지우기 및 재동기화 {#5-clear-and-re-sync}

:::warning 저장되지 않은 작업을 먼저 확인하세요
로컬 데이터를 지우거나 앱을 다시 설치하면 매장에 도착하지 않은 이 기기의 모든 데이터가 삭제됩니다. 오프라인 중 발생한 판매, 열린 장바구니, 저장되지 않은 수정 사항이 여기에 포함됩니다. 삭제하기 전에 **매장 상태 → 데이터베이스**를 열어 보류 중이거나 서버에 도달한 적 없는 항목이 없는지 확인한 다음, **매장 상태 → 로그**에서 **중단된 레코드 0개** 및 **전송 대기 중인 변경 사항 0개**인지 확인하세요. 이어서 열린 장바구니를 모두 완료하거나 내용을 기록해 두세요. WCPOS에 매장 상태 페이지가 없다면 먼저 WCPOS를 업데이트한 후 확인하세요. 항목이 있거나 전송 대기 중이거나 확인할 수 없다면 삭제하지 말고 매장 관리자에게 문의하거나 지원팀에 연락하세요.
:::

동기화가 계속 멈춰 있을 때만, 그리고 위 확인을 마친 경우에만 진행하세요:
1. 로컬 데이터 지우기
2. 다시 로그인
3. 새 동기화 완료

## 일반적인 시나리오 {#common-scenarios}

- **제품이 표시되지 않음:** 게시되고 가시적인지 확인
- **고객을 찾을 수 없음:** 아직 동기화되지 않았을 수 있음
- **주문이 누락됨:** 동기화 날짜 범위를 벗어났을 수 있음
