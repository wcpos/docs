# DB01003: 거래 실패 {#db01003-transaction-failed}

## 이것이 의미하는 바 {#what-this-means}

데이터베이스 거래를 완료할 수 없습니다. 거래는 여러 작업을 그룹화합니다. 만약 어떤 부분이 실패하면 모든 것이 롤백되어 데이터 무결성을 유지합니다.

## 일반적인 원인 {#common-causes}

- **동시 접근** — 여러 작업이 동일한 데이터를 수정하려고 시도하는 경우
- **저장 공간 부족** — 새 데이터를 기록할 공간이 없는 경우
- **데이터베이스 잠금** — 다른 프로세스가 데이터베이스를 잠그고 있는 경우
- **전원 중단** — 예기치 않게 작업이 중단된 경우

## 해결 방법 {#how-to-fix}

### 1. 작업 재시도 {#1-retry-the-operation}

문제가 일시적일 수 있습니다:
- 잠시 기다리기
- 작업을 다시 시도하기
- 빠른 반복 시도를 피하기

### 2. 충돌 확인 {#2-check-for-conflicts}

여러 장치나 탭이 열려 있는 경우:
- 한 번에 하나의 인스턴스 사용
- 중복된 브라우저 탭 닫기
- 다중 장치 사용 조정하기

### 3. 저장 공간 확인 {#3-check-storage-space}

데이터를 위한 공간이 있는지 확인:
- 사용 가능한 디스크 공간 확인
- 필요한 경우 공간 확보
- 웹 버전에서 브라우저 캐시를 지우세요(“쿠키 및 기타 사이트 데이터”는 선택 해제하세요. 여기에 아직 전송되지 않은 데이터 등 POS의 저장 데이터가 포함됩니다)

### 4. 애플리케이션 재시작 {#4-restart-the-application}

데이터베이스 상태 재설정:
1. POS를 완전히 닫기
2. 몇 초 기다리기
3. 애플리케이션 다시 열기

### 5. 데이터 지우기 및 재동기화 {#5-clear-and-re-sync}

:::warning 저장하지 않은 작업이 있는지 먼저 확인하세요
로컬 데이터를 지우거나 앱을 다시 설치하면 이 장치에 저장된 데이터 중 매장에 전송되지 않은 모든 항목이 삭제됩니다. 여기에는 오프라인에서 처리한 판매, 열린 장바구니, 저장되지 않은 수정 사항이 포함됩니다. 데이터를 지우기 전에 **Store health → Database**를 열어 보류 중이거나 서버에 도달한 적이 없는 항목이 없는지 확인한 다음, **Store health → Logs**에서 **0 stuck records** 및 **0 changes waiting to send**인지 확인하세요. 그런 다음 열린 장바구니를 모두 완료하거나 내용을 기록해 두세요. WCPOS에 Store health 페이지가 없으면 먼저 WCPOS를 업데이트한 후 확인하세요. 항목이 표시되거나 전송 대기 중이거나 확인할 수 없다면 데이터를 지우지 말고 매장 소유자에게 문의하거나 지원팀에 연락하세요.
:::

이 페이지의 다른 모든 단계를 시도한 뒤에도 거래가 계속 실패하고 위 확인 절차를 마친 경우에만 진행하세요:
1. 로컬 데이터 지우기
2. 다시 로그인하기
3. 서버에서 새로 동기화하기

## 거래 안전성 {#transaction-safety}

WCPOS는 거래를 사용하여 다음을 보장합니다:
- 데이터 일관성
- 완전한 작업 (모두 또는 없음)
- 부분 업데이트에 대한 보호

거래가 실패할 때, 데이터는 일관성을 유지합니다.
