# API02007: 토큰 새로 고침 실패 {#api02007-token-refresh-failed}

## 의미 {#what-this-means}

POS가 인증 세션을 자동으로 갱신하려고 했으나 새로 고침 요청이 실패했습니다. 이는 일반적으로 다시 로그인해야 함을 의미합니다.

## 일반적인 원인 {#common-causes}

- **새로 고침 토큰 만료** — 새로 고침 토큰이 만료되었습니다.
- **새로 고침 토큰 취소** — 관리자에 의해 모든 세션이 무효화되었습니다.
- **서버 오류** — 서버가 새로 고침 요청을 처리할 수 없었습니다.
- **네트워크 문제** — 새로 고침 시도 중 연결 문제 발생

## 해결 방법 {#how-to-fix}

### 1. 다시 로그인하기 {#1-log-in-again}

가장 신뢰할 수 있는 해결 방법:
1. POS에서 로그아웃합니다.
2. 자격 증명으로 다시 로그인합니다.
3. 이렇게 하면 새 토큰으로 새로운 세션이 생성됩니다.

### 2. 네트워크 연결 확인 {#2-check-network-connection}

네트워크 문제로 새로 고침이 실패하는 경우:
- 인터넷 연결을 확인합니다.
- 브라우저에서 WordPress 사이트에 접근해 봅니다.
- 잠시 대기한 후 다시 시도합니다.

### 3. 서버 상태 확인 {#3-check-server-status}

서버에 문제가 있을 경우:
- WordPress가 제대로 실행되고 있는지 확인합니다.
- 서버 로그에서 PHP 오류를 확인합니다.
- 인증 플러그인이 활성화되어 있는지 확인합니다.

### 4. 세션 데이터 지우기 {#4-clear-session-data}

문제가 계속되는 경우, 아래 내용을 확인한 후에만 진행하세요:

:::warning 저장되지 않은 작업을 먼저 확인하세요
로컬 데이터를 지우거나 앱을 다시 설치하면 매장에 도착하지 않은 이 기기의 모든 데이터가 삭제됩니다. 오프라인 중 발생한 판매, 열린 장바구니, 저장되지 않은 수정 사항이 여기에 포함됩니다. 삭제하기 전에 **매장 상태 → 데이터베이스**를 열어 보류 중이거나 서버에 도달한 적 없는 항목이 없는지 확인한 다음, **매장 상태 → 로그**에서 **중단된 레코드 0개** 및 **전송 대기 중인 변경 사항 0개**인지 확인하세요. 이어서 열린 장바구니를 모두 완료하거나 내용을 기록해 두세요. WCPOS에 매장 상태 페이지가 없다면 먼저 WCPOS를 업데이트한 후 확인하세요. 항목이 있거나 전송 대기 중이거나 확인할 수 없다면 삭제하지 말고 매장 관리자에게 문의하거나 지원팀에 연락하세요.
:::

- POS 앱 캐시를 지웁니다.
- 저장된 자격 증명을 제거합니다.
- 새 로그인으로 새롭게 시작합니다.

## 자동 토큰 새로 고침 {#automatic-token-refresh}

WCPOS는 세션 유지를 위해 토큰이 만료되기 전에 자동으로 새로 고칩니다. 이 과정이 반복적으로 실패하면 구성 문제를 해결해야 할 수 있습니다.
