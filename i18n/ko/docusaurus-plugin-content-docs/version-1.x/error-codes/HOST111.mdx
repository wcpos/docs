## 이것이 의미하는 바 {#what-this-means}

서버의 교차 출처(CORS) 구성이 잘못되어 브라우저가 응답을 거부합니다.

스토어는 응답하지만 CORS 응답 헤더가 잘못되었습니다 — 중복되었거나, 잘못된 출처로 설정되었거나, 오류 응답에 누락되었습니다. 그러면 브라우저가 실제 응답을 웹 앱으로부터 숨기며, 이는 다른 모든 오류까지 일반적인 네트워크 오류 뒤에 가립니다. 해결은 서버 측에서 이루어집니다: 모든 상태 코드에 Access-Control-Allow-Origin이 정확히 하나만 있어야 합니다.

## 내 데이터 {#your-data}

주문이나 상품 데이터는 영향을 받지 않습니다.

## 문제 해결 {#troubleshoot}

1. CORS 계층이 두 개 있는지(플러그인과 서버 설정이 모두 헤더를 추가하는 경우) 확인하고 하나를 제거하세요 — Access-Control-Allow-Origin이 중복되면 브라우저에서 치명적인 오류가 발생합니다.
2. nginx에서는 add_header 줄이 'always'로 끝나지 않으면 오류 응답을 건너뜁니다 — CORS 헤더는 4xx/5xx에도 있어야 합니다.
3. CDN이나 프록시가 CORS 헤더를 추가하는 경우, WordPress 자체의 헤더와 충돌하지 않는지 확인하세요.
4. 데스크톱 및 모바일 앱은 CORS를 사용하지 않으므로 이 문제가 해결되는 동안에도 계속 작동합니다.
