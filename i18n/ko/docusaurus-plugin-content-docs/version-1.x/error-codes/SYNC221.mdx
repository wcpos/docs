## 이것이 의미하는 바 {#what-this-means}

이 기기의 변경 사항이 매장의 최신 수정 사항과 충돌했습니다. 데이터가 손실되지는 않았습니다.

이 레코드의 보류된 변경 사항이 **매장 상태 → 데이터베이스**에 표시되면 **다시 보내기**를 탭해 이 기기의 버전을 유지하거나 **서버 버전 사용**을 탭해 매장의 버전을 유지하세요. 표시되지 않으면 이미 처리된 것이므로 할 일이 없습니다.

## 내 데이터 {#your-data}

데이터가 손실되지는 않았습니다. 변경 사항이 보류되면 어느 쪽을 유지할지 선택할 때까지 매장에는 매장 버전이, 이 기기에는 이 기기의 변경 사항이 유지됩니다. 그동안 해당 레코드에 대한 추가 수정은 이 기기에서 대기합니다. 변경 사항이 보류된 동안 이 기기의 데이터를 지우지 마세요. 보류된 변경 사항이 삭제됩니다.

## 문제 해결 {#troubleshoot}

1. **매장 상태 → 데이터베이스**를 여세요. 보류된 변경 사항은 **"변경 사항 1개가 보류되었습니다"**(또는 **"…개 변경 사항이 보류되었습니다"**)로 시작하는 패널에 해당 레코드와 함께 표시됩니다.
2. 이 레코드의 변경 사항이 더 이상 보류되지 않는다면 여기나 다른 탭에서 이미 처리된 것이므로 할 일이 없습니다. WCPOS가 이 기기의 버전을 다시 보내 자동으로 처리한 주문 충돌은 대신 [SYNC222](/error-codes/SYNC222)로 기록됩니다.
3. 변경 사항이 보류되어 있으면 **레코드 열기**(표시되는 경우)를 눌러 이 기기의 버전을 확인하고 WP Admin의 같은 레코드와 비교하세요(사이트 관리자에게 확인을 요청해야 할 수도 있습니다).
4. 이 기기의 버전을 유지하려면 **다시 보내기**를 탭하세요. 변경 사항을 다시 전송해 이 기기에서 수정한 필드의 매장 값을 대체합니다. 매장 버전을 유지하려면 **서버 버전 사용**(일부 행에는 **기기 변경 사항 삭제**로 표시됨)을 탭하고 확인하세요. 이 기기의 변경 사항은 삭제됩니다. 선택할 때까지 해당 레코드의 추가 수정은 대기합니다.
5. 같은 레코드에서 충돌이 자주 발생한다면 보통 두 사람이 같은 데이터를 동시에 수정하고 있다는 뜻입니다. 예를 들어 계산대와 WP Admin에서 재고를 수정하는 경우입니다. 각 종류의 수정 작업을 어디에서 할지 합의하세요.
