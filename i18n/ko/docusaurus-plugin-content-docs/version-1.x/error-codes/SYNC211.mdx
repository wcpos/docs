## 이것이 의미하는 바 {#what-this-means}

매장에서 레코드의 필드를 거부했습니다. 드물게 이 코드는 매장에서 거부한 설정 또는 인증 요청을 나타내기도 합니다.

레코드가 언급되었다면 해당 필드를 수정한 뒤 다시 시도하세요. 동기화가 완료될 때까지 로컬 사본을 사용할 수 있습니다. 그렇지 않으면 매장에서 표시한 요청에 관한 메시지를 따르세요.

## 내 데이터 {#your-data}

레코드 변경이라면 변경 사항은 이 기기에 계속 저장되어 있지만 매장에는 아직 도달하지 않았습니다. 설정 또는 인증 요청이라면 저장할 내용은 없습니다.

## 문제 해결 {#troubleshoot}

1. 먼저 로그 항목을 펼쳐 endpoint와 서버 응답을 확인하세요. 이 코드는 설정, 인증 또는 그 밖의 레코드가 아닌 요청에서 발생한 HTTP 400을 나타낼 수도 있습니다.
2. 컨텍스트에 레코드나 필드가 표시되어 있다면 POS에서 해당 필드를 수정한 다음 재시도하세요. 흔한 원인은 범위를 벗어난 값, 거부된 형식, 비워 둔 필수 옵션입니다.
3. 레코드 요청이 아니라면 해당 엔드포인트에 관한 서버 메시지를 따르세요. 세부 정보가 POS 로그에 없으면 브라우저 개발자 도구의 네트워크 탭이나 데스크톱 앱의 **고급 → 개발자 도구 전환**에서 응답을 확인할 수 있습니다.
4. **사이트 관리자:** 지정된 필드가 POS에서 올바르게 보이면 WP Admin에서 같은 레코드와 비교하세요. 매장에 설치된 플러그인이 추가한 유효성 검사로 POS에서는 올바르게 판단한 값이 거부될 수 있습니다.
