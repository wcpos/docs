## 이것이 의미하는 바 {#what-this-means}

매장에서 전송된 값을 거부했습니다.

매장의 사유에 거부된 값이 표시됩니다. 값을 입력한 곳에서 수정한 다음 다시 저장하세요. 보통 상품, 고객 또는 주문 레코드의 값이지만, 매장에서 거부한 설정 또는 로그인 요청에서도 이 코드가 발생할 수 있습니다. 이 경우 해당 화면에서 값을 수정하세요.

## 내 데이터 {#your-data}

이 기기의 데이터를 삭제하지 마세요. 매장에 아직 반영되지 않은 변경 사항이 있을 수 있습니다. 기존 상품, 옵션, 고객 또는 쿠폰의 거부된 수정은 보통 자동으로 취소되고 대신 [SYNC202](/error-codes/SYNC202)로 기록됩니다. 이 코드가 표시되고 변경 사항이 **스토어 상태 → 데이터베이스**에 있으면 자동 취소가 되지 않은 것이므로 다른 표시된 변경 사항과 동일하게 처리하세요. 설정 또는 로그인 요청은 저장할 항목을 남기지 않습니다.

## 문제 해결 {#troubleshoot}

1. 로그 항목을 펼쳐 매장의 사유와 엔드포인트를 확인하세요. 사유에는 거부된 값이, 엔드포인트에는 레코드에서 온 요청인지 설정 또는 로그인 요청인지 표시됩니다.
2. 값을 입력한 곳에서 수정하세요. 일반적인 원인으로는 허용 범위를 벗어난 값, 거부된 형식 또는 비워 둔 필수 옵션이 있습니다. 그런 다음 다시 저장하세요. **스토어 상태 → 데이터베이스**에 변경 사항이 없다면 매장의 버전이 복원된 것이므로 올바른 값으로 다시 변경하세요. 값을 수정한 뒤에도 **스토어 상태 → 데이터베이스**의 **"… 서버에 전달되지 않은 변경 사항"** 아래에 표시되면 해당 행에서 **다시 보내기**를 누르세요.
3. 대신 레코드가 **"… 보류된 변경 사항"** 아래에 *"매장에서 최신 버전을 요구했습니다"*와 함께 표시된다면 잘못된 값이 원인이 아닙니다. [SYNC221](/error-codes/SYNC221)에 설명된 대로 **다시 보내기**와 **기기 변경 사항 삭제** 중에서 선택하세요.
4. 설정 또는 로그인 요청이었다면 값을 입력한 화면에서 수정하고 다시 저장하세요. **사이트 관리자:** POS 로그에 세부 정보가 없으면 브라우저 개발자 도구의 네트워크 탭이나 데스크톱 앱의 **고급 → 개발자 도구 전환**에서 매장의 응답을 확인할 수 있습니다.
5. **사이트 관리자:** POS에서 보기에는 올바른 값인데도 값이 거부되면 WP Admin의 같은 레코드와 비교하세요. 매장의 플러그인이 POS에서는 문제없어 보이는 값을 거부하도록 유효성 검사를 추가했을 수 있습니다.
