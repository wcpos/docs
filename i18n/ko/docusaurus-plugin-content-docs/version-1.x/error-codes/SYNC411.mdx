## 이것이 의미하는 바 {#what-this-means}

이 기기가 평소보다 훨씬 자주 스토어에 데이터를 요청했습니다.

느려지거나 차단된 것은 없으며 주문 데이터에도 영향이 없습니다. 이는 감지 전용 알림입니다. 요청 폭주가 지속되는 것은 대개 사용자의 조작 때문이 아니라 앱의 문제(어떤 화면이 같은 데이터를 반복해서 요청하는 루프)를 나타냅니다. 이 코드가 계속 나타난다면 진단 정보를 내보내고 지원팀에 문의하여 해당 루프를 찾아 수정할 수 있도록 해 주세요.

## 조치 방법 {#what-to-do}

계속 작업해도 됩니다. WCPOS가 자동으로 처리합니다. WCPOS가 자동으로 재시도합니다.

## 내 데이터 {#your-data}

주문이나 상품 데이터에는 영향이 없습니다. 이 문제가 계속되면 진단 정보를 내보내고 WCPOS 지원팀에 문의하세요.

## 문제 해결 {#troubleshoot}

1. 계속 작업하세요. 이는 감지 전용 알림입니다. WCPOS는 어떤 요청도 늦추거나 대기시키거나 폐기하지 않으며, 주문이나 상품 데이터에도 영향이 없습니다.
2. 코드가 한 번 나타났다가 멈춘다면 조치할 것이 없습니다. 반복된다면 그때 어떤 화면이 열려 있었고 어떤 작업을 하고 있었는지 기록해 두세요.
3. 해당 이벤트가 30일 로그 보관 기간 안에 있는 동안 디버그 정보 복사를 사용해 WCPOS 지원팀에 문의하세요. 내보낸 정보를 통해 지원팀이 요청 루프를 추적할 수 있습니다.

## 확인할 위치 {#where-to-look}

WCPOS가 이 오류를 저장할 수 있는 경우, 오류는 이를 발생시킨 기기에 기록됩니다. **스토어 상태 → 로그**(내비게이션 서랍 하단의 심박 아이콘)를 열고 이 코드가 표시된 항목을 찾아 펼치세요. 펼쳐진 행에는 알기 쉽게 설명된 원인과 오류가 발생한 시점에 수집된 컨텍스트가 표시됩니다. 스토어 요청의 경우 이 컨텍스트에 서버 자체의 오류 코드(`serverCode`), HTTP `status` 또는 `endpoint`가 포함될 수 있으며, 표시되는 필드는 오류가 발생한 위치에 따라 다릅니다. 문제를 신고할 때는 스크린샷 대신 로그 화면 상단의 **디버그 정보 복사**(휴대폰과 태블릿에서는 **디버그 정보 공유**)를 사용하세요. 여기에는 앱 버전, 연결 상태, 가장 최근의 오류가 함께 담깁니다. 로그는 최대 30일간만 보관되므로 문제가 발생한 직후에 수집하세요. 또한 POS가 자체 로그 항목을 기록하기 전에 나타난 브라우저 콘솔 오류가 있다면 함께 복사하세요.
