## 이것이 의미하는 바 {#what-this-means}

WCPOS Pro 라이선스가 이 스토어 또는 기기에서 활성화되어 있지 않습니다.

로컬, 라이선스 서버, 업데이터 상태를 확인한 다음 로그에 표시된 스토어에 대해 라이선스를 활성화하세요.

## 조치 방법 {#what-to-do}

이 기능이 작동하려면 먼저 설정을 변경해야 합니다. 위의 변경을 적용한 후에 재시도하세요. 변경하지 않고 재시도하면 같은 방식으로 실패합니다.

## 내 데이터 {#your-data}

주문이나 상품 데이터에는 영향이 없습니다. 이 문제가 계속되면 진단 정보를 내보내고 WCPOS 지원팀에 문의하세요.

## 문제 해결 {#troubleshoot}

1. WP Admin의 POS 설정에서 라이선스 상태를 확인하세요. 이 스토어의 정확한 URL에 대해 활성 상태로 표시되어야 합니다.
2. 사이트 URL이 변경되면(http에서 https로, www 추가 또는 제거, 도메인 이전, 스테이징 사본) 새 주소에서는 라이선스가 비활성화됩니다. 현재 주소에 대해 다시 활성화하세요.
3. 라이선스는 활성으로 표시되는데 POS에서는 그렇지 않다면, 한 번 비활성화했다가 다시 활성화한 다음 계산대를 새로 고치세요.
4. 그래도 잠겨 있나요? 디버그 정보를 내보내고 라이선스 참조 번호와 함께 지원팀에 문의하세요.

## 확인할 위치 {#where-to-look}

WCPOS가 이 오류를 저장할 수 있는 경우, 오류는 이를 발생시킨 기기에 기록됩니다. **스토어 상태 → 로그**(내비게이션 서랍 하단의 심박 아이콘)를 열고 이 코드가 표시된 항목을 찾아 펼치세요. 펼쳐진 행에는 알기 쉽게 설명된 원인과 오류가 발생한 시점에 수집된 컨텍스트가 표시됩니다. 스토어 요청의 경우 이 컨텍스트에 서버 자체의 오류 코드(`serverCode`), HTTP `status` 또는 `endpoint`가 포함될 수 있으며, 표시되는 필드는 오류가 발생한 위치에 따라 다릅니다. 문제를 신고할 때는 스크린샷 대신 로그 화면 상단의 **디버그 정보 복사**(휴대폰과 태블릿에서는 **디버그 정보 공유**)를 사용하세요. 여기에는 앱 버전, 연결 상태, 가장 최근의 오류가 함께 담깁니다. 로그는 최대 30일간만 보관되므로 문제가 발생한 직후에 수집하세요. 또한 POS가 자체 로그 항목을 기록하기 전에 나타난 브라우저 콘솔 오류가 있다면 함께 복사하세요.

앱 내 로그 외에도 이 오류는 다음 위치에 흔적을 남길 수 있습니다:

- **서버 측 POS 로그**: WP Admin에서 **POS → 설정 → 도구 → 로그**를 여세요. 이 페이지에는 서버 자체에서 발생한 POS 관련 경고와 오류가 기록되며, 이러한 항목은 앱 안에서는 전혀 표시되지 않을 수 있습니다. 메뉴에 빨간색 배지가 표시되면 읽지 않은 서버 측 오류가 있다는 뜻입니다.
