## 문제 해결 {#troubleshoot}

1. 이 코드가 항상 재시도된다고 가정하지 마세요. 먼저 로그 항목을 펼쳐 보세요. 변경 작업이 이미 대기열에 들어간 것으로 확인된다면 WCPOS가 자동으로 재시도하므로, 앱을 열어 둔 채 대기열이 비워지도록 두세요.
2. 엔진 레지던트가 없거나 변경 ID가 반환되기 전에 쓰기가 실패했다는 오류라면 대기열에 들어간 것이 없습니다. 해당 레코드나 주문으로 돌아가 다시 저장하세요.
3. 로그 항목을 펼쳐 이벤트 코드와 serverCode가 있다면 기록해 두세요. 999 코드는 구체적인 원인에 아직 전용 코드가 없다는 뜻이므로, 이 컨텍스트가 지원팀에 꼭 필요한 정보입니다.
4. 코드가 계속 나타난다면 디버그 정보 복사를 사용해 지원팀에 문의하세요. 이렇게 신고해 주셔야 전용 코드가 추가됩니다.

## 확인할 위치 {#where-to-look}

WCPOS가 이 오류를 저장할 수 있는 경우, 오류는 이를 발생시킨 기기에 기록됩니다. **스토어 상태 → 로그**(내비게이션 서랍 하단의 심박 아이콘)를 열고 이 코드가 표시된 항목을 찾아 펼치세요. 펼쳐진 행에는 알기 쉽게 설명된 원인과 오류가 발생한 시점에 수집된 컨텍스트가 표시됩니다. 스토어 요청의 경우 이 컨텍스트에 서버 자체의 오류 코드(`serverCode`), HTTP `status` 또는 `endpoint`가 포함될 수 있으며, 표시되는 필드는 오류가 발생한 위치에 따라 다릅니다. 문제를 신고할 때는 스크린샷 대신 로그 화면 상단의 **디버그 정보 복사**(휴대폰과 태블릿에서는 **디버그 정보 공유**)를 사용하세요. 여기에는 앱 버전, 연결 상태, 가장 최근의 오류가 함께 담깁니다. 로그는 최대 30일간만 보관되므로 문제가 발생한 직후에 수집하세요. 또한 POS가 자체 로그 항목을 기록하기 전에 나타난 브라우저 콘솔 오류가 있다면 함께 복사하세요.

앱 내 로그 외에도 이 오류는 다음 위치에 흔적을 남길 수 있습니다:

- **네트워크 검사기**(웹 및 데스크톱): 개발자 도구를 여세요. 브라우저에서는 F12를 누르고, 데스크톱 앱에서는 메뉴의 **고급 → 개발자 도구 전환**을 선택한 다음 **네트워크** 탭을 선택하세요. 먼저 이 페이지의 재시도 안내를 따르고, 안전하다고 안내된 경우에만 해당 작업을 재현하세요. 실패한 요청에는 HTTP 상태와 원시 응답 본문이 표시되며, 여기에는 POS 로그에 전혀 도달하지 않는 오류 페이지도 포함됩니다.
