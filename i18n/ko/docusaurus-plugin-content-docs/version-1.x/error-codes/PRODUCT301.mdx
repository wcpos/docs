## 이것이 의미하는 바 {#what-this-means}

현재 검색어와 필터에 일치하는 상품이 없습니다.

다시 검색하기 전에 공백, 카테고리 필터, 그리고 로컬 상품 색인의 동기화가 완료되었는지 확인하세요.

## 조치 방법 {#what-to-do}

다시 시도하기 전에 아래 세부 정보를 확인하세요. WCPOS는 이 작업을 자동으로 재시도하지 않습니다. 준비되면 직접 재시도하세요.

## 내 데이터 {#your-data}

주문이나 상품 데이터에는 영향이 없습니다.

## 문제 해결 {#troubleshoot}

1. 스캔한 코드는 검색창에 입력되므로 필터부터 확인하세요. 카테고리나 재고 필터가 모든 검색 범위를 조용히 좁히고 있을 수 있습니다.
2. 상품을 이름으로 찾아보세요. 이름으로는 나온다면 스토어의 바코드 필드에 스캔한 값이 들어 있지 않다는 뜻입니다. WP Admin에서 해당 상품에 바코드를 추가하세요.
3. POS 바코드 설정에서 바코드 필드를 확인하세요. 스토어가 바코드를 다른 필드에 보관한다면 POS가 잘못된 필드를 읽어 모든 스캔이 실패합니다.
4. 상품이 방금 등록된 것이라면 로컬 색인이 아직 동기화 중일 수 있습니다. 첫 동기화가 끝날 때까지 기다린 후 다시 스캔하세요.

## 확인할 위치 {#where-to-look}

WCPOS가 이 오류를 저장할 수 있는 경우, 오류는 이를 발생시킨 기기에 기록됩니다. **스토어 상태 → 로그**(내비게이션 서랍 하단의 심박 아이콘)를 열고 이 코드가 표시된 항목을 찾아 펼치세요. 펼쳐진 행에는 알기 쉽게 설명된 원인과 오류가 발생한 시점에 수집된 컨텍스트가 표시됩니다. 스토어 요청의 경우 이 컨텍스트에 서버 자체의 오류 코드(`serverCode`), HTTP `status` 또는 `endpoint`가 포함될 수 있으며, 표시되는 필드는 오류가 발생한 위치에 따라 다릅니다. 문제를 신고할 때는 스크린샷 대신 로그 화면 상단의 **디버그 정보 복사**(휴대폰과 태블릿에서는 **디버그 정보 공유**)를 사용하세요. 여기에는 앱 버전, 연결 상태, 가장 최근의 오류가 함께 담깁니다. 로그는 최대 30일간만 보관되므로 문제가 발생한 직후에 수집하세요. 또한 POS가 자체 로그 항목을 기록하기 전에 나타난 브라우저 콘솔 오류가 있다면 함께 복사하세요.
