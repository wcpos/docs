## 이것이 의미하는 바 {#what-this-means}

일부 이전 스토어 변경 사항이 건너뛰어져 다시 내려받아야 합니다.

영향을 받은 데이터에 대해 대상 다운로드를 실행하고, 누락이 남아 있다면 진단 정보를 내보내세요.

## 조치 방법 {#what-to-do}

WCPOS를 다시 시작하세요. 이 문제가 계속되면 이 기기의 로컬 데이터를 복구해야 합니다. WCPOS는 이 작업을 자동으로 재시도하지 않습니다. 준비되면 직접 재시도하세요.

## 내 데이터 {#your-data}

이 기기의 데이터가 위험할 수 있습니다. 로컬 데이터를 지우지 마세요. 이 문제가 계속되면 진단 정보를 내보내고 WCPOS 지원팀에 문의하세요.

## 문제 해결 {#troubleshoot}

1. 로그 항목을 펼쳐 보세요. 컨텍스트에 계산대가 얼마나 뒤처졌는지와 변경 사항이 건너뛰어졌는지가 기록되어 있습니다.
2. 영향을 받은 데이터에 대해 대상 다운로드를 실행해 건너뛴 스토어 변경 사항을 다시 가져오세요.
3. 그런 다음 최근에 편집된 레코드 몇 개를 WP Admin과 대조해 누락이 해소되었는지 확인하세요.
4. 누락이 다시 나타난다면 무언가를 초기화하지 말고 디버그 정보를 내보내 지원팀에 문의하세요.

## 확인할 위치 {#where-to-look}

WCPOS가 이 오류를 저장할 수 있는 경우, 오류는 이를 발생시킨 기기에 기록됩니다. **스토어 상태 → 로그**(내비게이션 서랍 하단의 심박 아이콘)를 열고 이 코드가 표시된 항목을 찾아 펼치세요. 펼쳐진 행에는 알기 쉽게 설명된 원인과 오류가 발생한 시점에 수집된 컨텍스트가 표시됩니다. 스토어 요청의 경우 이 컨텍스트에 서버 자체의 오류 코드(`serverCode`), HTTP `status` 또는 `endpoint`가 포함될 수 있으며, 표시되는 필드는 오류가 발생한 위치에 따라 다릅니다. 문제를 신고할 때는 스크린샷 대신 로그 화면 상단의 **디버그 정보 복사**(휴대폰과 태블릿에서는 **디버그 정보 공유**)를 사용하세요. 여기에는 앱 버전, 연결 상태, 가장 최근의 오류가 함께 담깁니다. 로그는 최대 30일간만 보관되므로 문제가 발생한 직후에 수집하세요. 또한 POS가 자체 로그 항목을 기록하기 전에 나타난 브라우저 콘솔 오류가 있다면 함께 복사하세요.
