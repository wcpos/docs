## 이것이 의미하는 바 {#what-this-means}

스토어 앞단의 캐시가 한 사람의 API 응답을 모든 사람에게 재생하고 있습니다.

캐싱 계층이 요청자가 누구인지 확인하지 않고 저장된 REST API 응답을 제공하고 있습니다: 앱이 서로 다르게 인증된 두 개의 탐침을 보냈는데 두 번 모두 첫 번째 탐침의 응답을 받았습니다. 운영 중인 스토어에서는 이것이 한 계산원이 다른 계산원의 데이터를 볼 수 있다는 의미이므로, 캐시가 스토어의 API를 제외할 때까지 연결이 차단됩니다. 이는 호스팅 계층의 문제입니다 — WordPress 자체는 항상 사용자별로 응답합니다.

## 내 데이터 {#your-data}

이 기기의 데이터가 위험에 처할 수 있습니다 — 로컬 데이터를 지우지 마세요. 이 문제가 계속되면 진단 정보를 내보내고 WCPOS 지원팀에 문의하세요.

## 문제 해결 {#troubleshoot}

1. 스토어의 REST API 경로(/wp-json/ 및 /?rest_route=)를 페이지 캐싱에서 제외하세요 — LiteSpeed에서는 REST 캐싱을 비활성화하거나 no-cache 규칙을 추가하고, WP Engine에서는 WooCommerce 제외 항목을 /wp-json/wcpos까지 확장하며, Sucuri에서는 캐싱 수준을 Cache-Control을 따르도록 설정하세요.
2. 스토어의 API는 이미 Cache-Control: no-store와 Vary: Authorization를 보냅니다 — 캐시 계층이 이를 무시하고 있으니, 호스트에게 이 헤더들을 확인하도록 안내하세요.
3. 캐시 설정을 변경한 후에는 다시 연결하기 전에 캐시를 비우세요.
