:::info v1.10.0 신규 기능
매장 상태는 **WCPOS v1.10.0**에서 도입되었습니다. 기존의 독립된 로그 화면을 대체하며, 동기화 상태와 로컬 데이터 커버리지, 서버 부하를 실시간으로 확인할 수 있습니다.
:::

**매장 상태**는 기기와 WooCommerce 매장 사이에서 일어나는 모든 일을 보여주는 POS 대시보드입니다. 내비게이션 서랍에서 심박 아이콘을 선택해 여세요. **성능**, **데이터베이스**, **로그**의 세 탭으로 구성됩니다.

## 성능 {#performance}

성능 탭에서는 POS가 서버에 얼마나 부담을 주는지, 동기화가 정상적으로 이루어지는지 확인할 수 있습니다.

- **상태 표시줄** — 엔진의 현재 상태에 따라 `✓ Normal` 또는 `⚠ Needs attention`이 표시됩니다(이미 복구된 일시적인 문제로 하루 종일 경고가 남아 있지는 않습니다).
- **측정된 활동** — 지난 24시간의 요청 수와 일반적인 응답 시간은 이 계산대에서 실제로 측정한 값입니다. 크기를 명시하지 않은 응답은 집계에 포함되지 않으므로 전송된 데이터 수치는 하한값입니다.
- **가동 시간 표시줄** — 지난 24시간을 시간당 한 칸으로 표시합니다. 초록색은 해당 시간에 요청이 오류 없이 완료되었다는 뜻이고, 주황색은 요청이 하나 이상 실패했다는 뜻입니다(단 한 건이어도 표시되며 별도의 기준값은 없습니다). 빈칸은 앱이 실행되지 않았다는 뜻입니다.
- **추세 차트** — 시간에 따른 요청량과 응답 시간을 표시하므로 단일 수치만 볼 때와 달리 부하가 안정적인지, 증가하는지, 급증하는지 확인할 수 있습니다.
- **다음 확인까지 남은 시간** — 다음 변경 사항 확인까지 남은 시간을 표시합니다. 유휴 상태의 계산대에서는 설정된 간격보다 길게 표시될 수 있습니다. 확인 간격에 지터가 적용되고 10분간 유휴 상태가 지속되면 확인 빈도가 줄어들기 때문입니다. 사용하지 않는 계산대에서 남은 시간이 길게 표시되는 것은 정상이며, 동기화가 멈춘 것이 아닙니다.

### 동기화 프리셋 {#sync-presets}

세 개의 프리셋 카드로 이 기기의 동기화 빈도와 양을 설정합니다. 두 다이얼은 POS가 변경 사항을 확인하는 간격과 한 번에 요청하는 레코드 수를 조절합니다:

| 프리셋 | 확인 간격 | 요청당 레코드 수 |
| --- | --- | --- |
| **에코** | 5분 | 25 |
| **균형** (기본값) | 60초 | 50 |
| **실시간** | 10초 | 75 |

공유 호스팅이나 저가형 호스팅에서는 **에코**를 선택하세요. 여러 계산대가 서로의 변경 사항을 빠르게 확인해야 하고 서버가 이를 감당할 수 있다면 **실시간**을 선택하세요. **사용자 지정** 슬라이더에서는 전체 범위(5초–5분, 레코드 10–100개)를 조절할 수 있습니다.

알아 둘 사항은 두 가지입니다:

- **설정은 기기별로 적용됩니다.** 한 계산대의 설정을 바꿔도 다른 기기의 설정은 변경되지 않습니다. 조정하려는 계산대마다 설정을 변경하세요.
- 다이얼 옆의 *하루 약 N건의 요청* 수치는 설정된 간격에서 산출한 명목상의 확인 빈도이며, 상한이나 예측값이 아닙니다. 지터에 따라 실제 요청 수는 늘거나 줄 수 있습니다. 변경 사항이 없음을 나타내는 `304`는 부하가 적지만 요청 수에는 포함됩니다. 유휴 상태에서의 빈도 감소는 하한인 60초보다 간격이 짧은 프리셋에서만 요청 수를 줄이므로 균형 프리셋의 확인 빈도는 더 낮아지지 않습니다.

변경 사항은 즉시 적용되며 재시작할 필요가 없습니다. 이 수치의 기술적 배경은 [동기화 성능](/1.x/reference/sync-performance)을 참조하세요.

## 데이터베이스 {#database}

데이터베이스 탭에서는 기기에 어떤 데이터가 있는지, 모든 데이터가 서버에 전달되었는지 확인할 수 있습니다.

상단에는 네 개의 타일이 있습니다. **판매 준비 완료** 단계, 이 기기의 레코드 수, 사용 중인 저장 공간, 전송 대기 중인 변경 사항입니다. 레코드 수에는 상위 상품과 함께 **옵션 합계**가 포함되며, **사용 중인 저장 공간**은 추정치가 아닌 실제 기기 사용량입니다. WCPOS는 기기의 시계와 서버의 시계도 비교하며, 동기화나 타임스탬프에 영향을 줄 만큼 차이가 커지면 여기에 **시계 오차**를 표시합니다.

:::tip 판매 준비 완료는 진행 단계이며, 전체 다운로드를 요구하는 조건이 아닙니다
첫 상품이 기기에 저장되는 즉시 판매 준비 완료로 전환됩니다. 오프라인 상태여도 전환됩니다. 기기에 상품이 있는 계산대는 오프라인에서 판매할 준비가 된 것입니다. 이것이 로컬 우선 POS의 목적입니다.
:::

### 커버리지 표 {#coverage}

동기화되는 각 컬렉션은 **기기에 있는 수**, **서버에 있는 수**, 커버리지 막대를 포함한 행으로 표시됩니다. 수치는 정확성을 엄격히 지킵니다. *서버에 있는 수*는 서버가 실제로 보고한 총계이며 추정값이 아닙니다:

- ***확인 중…*** — POS가 아직 최신 서버 총계를 확보하지 못했습니다. 어떤 행이 약 15분 넘게 이 상태로 남아 있다면 해당 컬렉션의 REST 경로에 문제가 있을 수 있으니 [로그](#logs)를 확인하세요.
- **막대가 일부만 채워져 있어도 정상인 경우가 많습니다.** 고객은 유휴 시간에 점진적으로 다운로드되고, 카테고리와 쿠폰은 처음 열 때 다운로드됩니다. **주문** 막대는 전체 주문 이력을 기준으로 하지만 계산대는 의도적으로 미완료 주문과 최근 주문만 보관합니다. 따라서 정상인 계산대에서도 주문 막대는 일부만 채워진 것으로 표시됩니다.
- **“초기화 후 다시 다운로드” 직후 레코드 수가 비어 있거나 적은 것은 의도된 결과이며, 동기화가 멈춘 것이 아닙니다** — 필요할 때 다운로드하는 컬렉션은 사용하면서 다시 채워집니다. 각 행의 설명에서 해당 컬렉션이 다시 채워지는 방식을 확인할 수 있습니다.

### 서버에 전달되지 않은 변경 사항 {#refused-changes}

서버가 변경 사항을 영구적으로 거부하면(예: 사이트가 요청을 유효하지 않다고 거부한 상태에서 생성된 판매), POS는 알림 없이 무한히 재시도하지 **않으며**, 해당 변경 사항을 숨기지도 않습니다. 변경 사항은 보류되고 서버가 제공한 사유, 발생 시각, 다음 두 작업과 함께 여기에 표시됩니다:

- **다시 보내기** — *현재* 상태의 레코드를 바탕으로 요청을 다시 구성하여 대기열에 넣습니다. 같은 필드가 다시 거부되면 성공한 것으로 표시하지 않고 시도 횟수가 늘어난 것을 보여줍니다.
- **삭제** — 변경 사항을 삭제합니다. 확인 대화 상자는 삭제가 해당 레코드에 어떤 영향을 주는지 정확하게 설명합니다(레코드가 이 기기에만 존재하여 변경 사항을 삭제하면 레코드 자체도 삭제되는 경우 포함).

복구는 언제나 사용자가 직접 수행하고 확인할 수 있는 작업입니다. 여기서는 아무 작업도 자동으로 수행되지 않습니다.

### 초기화 후 다시 다운로드 {#clear-and-redownload}

각 컬렉션 행의 **초기화 후 다시 다운로드**를 사용하면 해당 컬렉션의 로컬 사본을 삭제하고 다시 가져옵니다. 확인 창에는 삭제될 레코드 수와 대략적인 저장 공간, 서버에 안전하게 남는 데이터가 표시됩니다. 모든 로컬 데이터를 초기화하기 전에 이 방법을 먼저 사용하세요. 특정 컬렉션만 처리하며 로그아웃되지 않습니다. 전체 초기화에는 [모든 로컬 데이터 초기화](/1.x/support/troubleshooting/clear-local-data)를 사용합니다.

각 행에는 **지금 변경 사항 확인**도 있습니다. 다음 예약 확인을 기다리지 않고 해당 컬렉션의 변경 사항을 즉시 확인합니다. 서버에서 변경한 내용이 기기에 전달되었는지 확인할 때 유용합니다.

## 로그 {#logs}

로그 탭은 이 기기의 동기화 활동을 기록합니다. 각 행에 **시간, 레벨, 이벤트, 소요 시간, 상태**를 표시하며 30일 동안 보관합니다.

- **미리 정의된 필터** — 전체 / 작업 / 오류 / 동기화 필터와 **상세 진단** 토글이 있습니다. 이 토글을 켜면 24시간 동안 추가 세부 정보를 수집한 뒤 자동으로 꺼집니다.
- **행 세부 정보** — 오류와 경고 행을 펼치면 알기 쉬운 원인 설명, 데이터 안전성 안내, 권장 다음 단계, [오류 코드](/1.x/error-codes) 도움말 링크가 표시됩니다. 각 세부 정보 보기에는 복사할 수 있는 이벤트 코드가 있습니다. 지원팀에 문의할 때 이 코드를 함께 알려 주세요.
- **무한 스크롤** — 스크롤하면 기록이 더 로드되므로 ‘다음 페이지’ 버튼 없이도 전체 30일 기록을 살펴볼 수 있습니다.
- 로그 항목은 표시될 때 번역되므로, 몇 달 전에 기록된 행도 오늘 계산대가 사용하는 언어로 읽힙니다. 안정적인 식별자는 이벤트 코드입니다.

:::note 두 개의 탭, 두 개의 집계
로그 탭은 막힌 레코드 수를 로그 항목만으로 산출하지만, 데이터베이스 탭은 보류된 거부 변경 사항까지 포함합니다. 두 값이 다를 때 서버에 전달되지 않은 항목에 대한 기준은 **데이터베이스 탭**입니다.
:::
