플러그인 충돌은 WCPOS 문제의 가장 흔한 원인 중 하나입니다. 다른 WordPress 플러그인이 WooCommerce 또는 WCPOS 기능을 방해하면 앱이 중단되거나 성능 문제, 예기치 않은 동작이 발생할 수 있습니다.

## 플러그인 충돌의 징후 {#signs-of-plugin-conflicts}

다음과 같은 증상이 나타나면 플러그인 충돌이 원인일 수 있습니다:

- **치명적인 오류** - "이 웹사이트에 치명적인 오류가 있습니다"
- **성능 문제** - 느린 로딩, 시간 초과 또는 높은 서버 부하
- **기능 문제** - 기능이 예상대로 작동하지 않음
- **데이터 동기화 문제** - 제품, 주문 또는 고객이 제대로 동기화되지 않음
- **결제 게이트웨이 문제** - 결제 실패 또는 결제 처리 오류

## 시작하기 전: 스테이징 사이트 사용 {#before-you-start-use-a-staging-site}

:::warning 중요
**운영 중인 사이트에서 플러그인 충돌을 진단하지 마세요.** 매장 운영에 지장이 없도록 항상 스테이징 환경을 사용하세요.
:::

### 스테이징 사이트란 무엇인가요? {#what-is-a-staging-site}

스테이징 사이트는 운영 중인 웹사이트를 그대로 복제한 사이트로, 고객에게 영향을 주지 않고 변경 사항을 안전하게 테스트할 수 있습니다. 요즘은 대부분의 호스팅 제공업체가 스테이징 환경을 기본 기능으로 제공합니다.

### 호스팅 제공업체가 스테이징을 제공하지 않는 경우 {#if-your-host-doesnt-offer-staging}

호스팅 제공업체가 스테이징 사이트를 제공하지 않는다면 **스테이징을 제공하는 업체로 전환하는 것을 고려하세요**. 스테이징은 이제 기본적인 기능이며, 다음 작업에 필수적입니다:

- 안전한 플러그인/테마 테스트
- WordPress 업데이트
- 문제 해결
- 개발 작업

**스테이징을 제공하는 권장 호스팅 업체:**
- WP Engine
- SiteGround  
- Kinsta
- Cloudways
- 그 밖의 여러 업체

## 1단계: 치명적인 오류 확인 {#step-1-check-for-fatal-errors}

앱이 중단되거나 치명적인 오류가 발생하면 먼저 오류 로그를 확인하세요:

1. **WCPOS 로그 확인** - WCPOS에서 [**매장 상태 → 로그**](/1.x/support/logs)를 열어 오류 메시지를 확인하세요
2. **치명적인 오류 로그 확인** - [치명적인 오류 문제 해결 가이드](/1.x/support/troubleshooting/critical-error)에 따라 자세한 오류 메시지를 찾아보세요
3. **오류 세부 정보 기록** - 오류에 언급된 플러그인 이름이나 파일 경로를 확인하세요

특정 플러그인을 언급하는 치명적인 오류를 발견했다면 해당 플러그인이 원인일 가능성이 높습니다. 해당 플러그인을 비활성화한 뒤 문제가 해결되는지 테스트할 수 있습니다.

## 2단계: 플러그인을 하나씩 확인하는 방법 {#step-2-the-plugin-elimination-method}

로그에 치명적인 오류가 없거나 성능 관련 충돌을 확인하려면 다음 절차에 따라 체계적으로 점검하세요:

### 2.1 비교 기준 마련 {#21-create-a-baseline}

1. **스테이징 사이트에 접속하세요**
2. **문제가 있는 기능 테스트** - 정확히 무엇이 작동하지 않거나 느린지 기록하세요
3. **성능 지표 기록** - 성능 문제라면 [로그](/1.x/support/logs)에 표시된 실행 시간을 기록하세요

### 2.2 모든 플러그인 비활성화 (필수 플러그인 제외) {#22-disable-all-plugins-except-essential-ones}

**다음 플러그인은 활성 상태로 유지하세요:**
- WooCommerce
- WCPOS
- WCPOS Pro (사용 중인 경우)

**나머지는 모두 비활성화하세요:**
1. `WP Admin > 플러그인`으로 이동하세요
2. 다른 모든 플러그인을 선택하세요
3. 일괄 작업 드롭다운에서 "비활성화"를 선택하세요
4. "적용"을 클릭하세요

### 2.3 문제 테스트 {#23-test-the-issue}

1. **모든 캐시 지우기** - 캐싱 플러그인을 사용한다면 모든 캐시를 지우세요
2. **문제가 있는 기능 테스트** - 이제 작동하나요?
3. **성능 확인** - 실행 시간이 줄었나요?

**문제가 해결된 경우:** 플러그인 충돌이 원인입니다. 2.4단계로 진행하세요.

**문제가 지속되는 경우:** 플러그인 충돌이 원인이 아닐 가능성이 높습니다. 다음을 확인하세요:
- 서버 자원 문제 ([서버 성능](/1.x/support/performance/server) 참조)
- 테마 충돌 (3단계 참조)
- WordPress/WooCommerce 코어 문제

### 2.4 플러그인을 하나씩 활성화 {#24-enable-plugins-one-by-one}

이제 어떤 플러그인이 충돌을 일으키는지 확인해야 합니다:

1. **플러그인 하나 활성화** - 가장 필수적인 플러그인부터 시작하세요
2. **기능 테스트** - 문제가 다시 발생하는지 확인하세요
3. **문제가 없으면** - 다음 플러그인을 활성화하고 다시 테스트하세요
4. **문제가 다시 발생하면** - 충돌하는 플러그인을 찾은 것입니다!

**플러그인 우선순위 (이 순서로 활성화하세요):**
1. **보안 플러그인** - Wordfence, Sucuri 등
2. **SEO 플러그인** - Yoast, RankMath 등  
3. **성능 플러그인** - 캐싱, 최적화
4. **결제 게이트웨이** - Stripe, PayPal 등
5. **기타 WooCommerce 확장**
6. **일반 WordPress 플러그인**

### 2.5 확인한 내용 기록 {#25-document-your-findings}

충돌하는 플러그인을 찾았다면 다음을 진행하세요:

1. **플러그인 이름과 버전을 기록하세요**
2. **어떤 문제가 발생하는지 구체적으로 기록하세요**
3. **업데이트된 버전이 있는지 확인하세요**
4. **유사한 기능을 제공하는 대체 플러그인을 찾아보세요**

## 3단계: 테마 충돌 확인 {#step-3-check-for-theme-conflicts}

WCPOS는 자체 인터페이스를 사용하므로 테마의 영향을 거의 받지 않지만, 테마가 다음 항목에 문제를 일으키는 경우가 있습니다:

- 결제 과정 (웹 결제 게이트웨이를 사용하는 경우)
- 관리자 영역 기능
- API 응답

### 기본 테마로 테스트 {#test-with-a-default-theme}

1. **스테이징 사이트에서** 다음과 같은 WordPress 기본 테마로 전환하세요:
   - Twenty Twenty-Four
   - Twenty Twenty-Three
   - Twenty Twenty-Two
2. **문제가 있는 기능을 테스트하세요**
3. **문제가 해결되면** - 테마 충돌이 원인입니다

:::info 테마의 영향
테마는 플러그인보다 WCPOS 문제를 일으킬 가능성이 훨씬 낮습니다. POS 인터페이스는 테마와 독립적으로 실행됩니다. 다만 테마는 다음 항목에 영향을 줄 수 있습니다:
- WooCommerce 결제 페이지
- WordPress 관리자 기능
- REST API 응답
:::

## 4단계: 플러그인 충돌 해결 {#step-4-resolving-plugin-conflicts}

충돌하는 플러그인을 찾았다면 다음 방법 중에서 선택할 수 있습니다:

### 옵션 1: 플러그인 업데이트 {#option-1-update-the-plugin}

1. **업데이트 확인** - 새 버전에서 충돌이 수정되었을 수 있습니다
2. 먼저 스테이징 사이트에서 **플러그인을 업데이트하세요**
3. 운영 중인 사이트에 업데이트를 적용하기 전에 **충분히 테스트하세요**

### 옵션 2: 대체 플러그인 찾기 {#option-2-find-an-alternative}

1. 같은 기능을 제공하는 **대체 플러그인을 조사하세요**
2. 스테이징 사이트에서 **대체 플러그인을 테스트하세요**
3. 플러그인을 교체한다면 **설정을 이전하세요**

### 옵션 3: 플러그인 개발자에게 문의 {#option-3-contact-plugin-developer}

1. 플러그인 개발자에게 **충돌을 보고하세요**
2. **다음과 같은 상세 정보를 제공하세요:**
   - 관련 플러그인 버전
   - WordPress 및 WooCommerce 버전
   - 정확한 오류 메시지 또는 동작
   - 문제 재현 단계

### 옵션 4: 맞춤 솔루션 {#option-4-custom-solution}

대체할 수 없는 필수 플러그인이라면 다음 방법을 고려하세요:

1. 맞춤 수정 사항을 개발할 수 있도록 **WordPress 개발자에게 문의하세요**
2. 충돌하는 기능을 비활성화할 수 있는 **플러그인별 후크를 검토하세요**
3. POS 관련 페이지에서 플러그인을 비활성화하도록 **조건부 로직을 사용하세요**

## 충돌이 자주 발생하는 플러그인 유형 {#common-conflicting-plugin-types}

### 충돌 위험이 높은 플러그인 유형 {#high-risk-plugin-categories}

**보안 플러그인:**
- API 요청을 차단할 수 있음
- 인증을 방해할 수 있음
- 엄격한 방화벽 규칙을 적용하는 경우가 많음

**캐싱 플러그인:**
- API 응답을 부적절하게 캐시할 수 있음
- 실시간 데이터 처리를 방해할 수 있음
- 오래된 데이터로 인한 문제를 일으킬 수 있음

**SEO 플러그인:**
- 리소스를 많이 사용하는 플러그인은 관리자 영역을 느리게 할 수 있음
- 불필요한 데이터베이스 쿼리를 추가할 수 있음
- REST API 응답을 방해할 수 있음

**페이지 빌더:**
- 관리자 영역에 리소스를 많이 사용하는 스크립트를 로드하는 경우가 많음
- WooCommerce 관리자 페이지와 충돌할 수 있음
- 결제 과정을 방해할 수 있음

**회원/제한 플러그인:**
- API 접근을 차단할 수 있음
- 사용자 인증을 방해할 수 있음
- 필요한 리소스에 대한 접근을 제한할 수 있음

### 충돌 위험이 낮은 플러그인 유형 {#lower-risk-plugin-categories}

**연락처 양식:** 대체로 WCPOS에 영향을 주지 않음
**소셜 미디어 플러그인:** 충돌이 드물게 발생함
**분석 플러그인:** 리소스를 지나치게 많이 사용하지 않는 한 대체로 안전함
**기본 콘텐츠 플러그인:** 대체로 호환됨
**WooCommerce Tax (TaxJar를 통한 자동 세금):** 지원됩니다. WCPOS는 열려 있는 POS 주문을 저장할 때 세율을 요청하므로 POS 주문에도 온라인 주문과 동일한 자동 세율이 적용됩니다. [WooCommerce Tax](/1.x/integrations/woocommerce-tax)를 참조하세요.

## 알려진 플러그인 충돌 {#known-plugin-conflicts}

아래 플러그인은 WCPOS 작동을 방해하는 것으로 알려져 있습니다. 많은 문제는 최근 WCPOS 버전에서 이미 자동으로 수정되므로 **최신 버전으로 업데이트**하면 별도 설정 없이 해결됩니다.

:::tip 대부분은 "POS 제외"로 해결됩니다
공통점은 WCPOS가 WooCommerce REST API를 사용하고 일부 과정(로그인, 결제, 영수증)을 iframe에 표시한다는 것입니다. 일반적인 해결 방법은 다른 플러그인을 완전히 비활성화하는 것이 아니라 해당 플러그인에서 **POS 엔드포인트/URL을 제외**하는 것입니다(`/wp-json/wcpos/`, `/wp-json/wc/v3/` 및 `/pos/` 경로).
:::

### 보안 및 로그인 플러그인 {#security-and-login-plugins}

특히 데스크톱/모바일 앱 로그인에서 충돌을 일으키는 **가장 흔한** 원인입니다.

| 플러그인 | 증상 | 해결 방법 |
| --- | --- | --- |
| **Wordfence** | 방화벽이 REST API를 차단함; 로그인 iframe에 2FA 코드 필드가 표시되지 않음; 엄격한 CSP가 POS 리소스를 차단할 수 있음 | 방화벽에서 `/wp-json/wcpos/`와 `/wp-json/wc/v3/`를 허용 목록에 추가하세요. 2FA는 POS 사용자에 대해 일시적으로 비활성화하세요. CSP는 v1.9.0+에서 자동으로 제거됩니다 |
| **Really Simple Security** | API 접근 차단 / 강제 리디렉션 | 플러그인의 **고급** 설정에서 모든 REST API 제한을 비활성화하세요 |
| **WPS Hide Login** | 사용자 정의 로그인 URL로 인해 앱 로그인 iframe이 작동하지 않음 | POS에 접근할 때 표준 `/wp-admin/` 로그인 URL을 사용하세요 |
| **iThemes / Solid Security** | REST API를 차단하거나 POS 호출을 무차별 대입 공격으로 판단해 잠금 처리함 | POS 엔드포인트와 서버 자체 IP만 허용 목록에 추가하세요. 모든 IP에 일괄 적용되는 규칙은 피하세요 |
| **Sucuri** | WAF가 API 요청을 차단함 | Sucuri 대시보드에서 REST API 엔드포인트를 허용 목록에 추가하세요 |
| **Security Optimizer** | 관리자 POS 로그인을 차단함 (_"사용자 정의 로그인 URL을 사용하세요"_) | 먼저 사용자 정의 URL을 통해 WP Admin에 로그인한 다음 `/pos`로 이동하세요 |
| **Force Login** (및 유사한 REST 인증 플러그인) | `/wp-json/`이 401/403을 반환함; 이전 앱에서는 _"WordPress 사이트가 아닌 것 같습니다"_라고 표시됨 | POS 엔드포인트에 인증 없이 접근하도록 허용하거나 최초 연결 시 플러그인을 비활성화하세요. v1.x 앱은 이제 실제 오류 메시지를 표시합니다 |
| **LoginPress** | 이메일 기반 로그인을 강제함; 여러 사용자의 POS 로그인이 작동하지 않음 | 사용자 이름으로 로그인하도록 허용하거나 POS 접근 시 비활성화하세요 |
| **JWT Authentication 플러그인** | 활성화 후 모든 POS API 요청에서 403 발생 (로그인은 성공해도 나머지는 모두 실패할 수 있음) | v1.8.x+에서 자동으로 수정됩니다. 이전 버전에서는 JWT 플러그인을 비활성화하거나 POS 엔드포인트를 제외하세요 |
| **Captcha / reCAPTCHA** | 데스크톱 앱에서 로그인 화면이 반복됨 (iframe에 캡차를 표시할 수 없음) | POS 로그인 URL에 대해 캡차를 비활성화하세요 |
| **Defender Pro** | `X-Frame-Options` 헤더가 모든 POS iframe(로그인, 결제, 영수증)을 차단함 | 사이트 전체에서 `X-Frame-Options`를 비활성화하는 대신 `/pos/`에 POS 전용 예외를 추가하세요 |
| **Jetpack CRM Client Portal** | POS 로그인이 전혀 작동하지 않음 | Client Portal 확장만 비활성화하세요 |

### 성능, 캐싱 및 최적화 플러그인 {#performance-caching-optimisation-plugins}

| 플러그인 | 증상 | 해결 방법 |
| --- | --- | --- |
| **WP Rocket, Autoptimize, Hummingbird, Smush** | JS 지연 로딩/축소로 인해 결제 및 Stripe Terminal이 작동하지 않음 | JS 최적화에서 `/pos/` URL을 제외하세요 |
| **LiteSpeed Cache** | 데스크톱 앱에서 결제 시 새로 고침이 끊임없이 반복됨; 엄격한 CSP | WCPOS를 업데이트하고 캐시를 비운 뒤 POS 페이지를 캐싱에서 제외하세요. CSP는 v1.9.0+에서 자동으로 제거됩니다 |
| **Image Prioritizer** | HTTP `Link` 헤더를 과도하게 채워 REST API 탐색을 방해함; 데스크톱 앱에 _"WordPress 사이트가 아닌 것 같습니다"_라고 표시됨 | 플러그인을 비활성화하세요 |

### 페이지 빌더 및 프런트엔드 삽입 플러그인 {#page-builders-front-end-injectors}

| **Elementor** | `elementor-frontend.js`로 인해 POS iframe 안의 결제 아코디언이 작동하지 않아 결제 방법을 펼칠 수 없음 | Elementor 스크립트 로딩에서 POS 페이지를 제외하세요 |

### WooCommerce 확장 및 기타 플러그인 {#woocommerce-extensions-other-plugins}

| 플러그인 | 증상 | 해결 방법 |
| --- | --- | --- |
| **WooCommerce Subscriptions** | v1.7→v1.8 업그레이드 중 마이그레이션 스크립트 충돌 | Subscriptions를 비활성화하고 POS Pro를 활성화해 마이그레이션을 실행한 다음 Subscriptions를 다시 활성화하세요 |
| **WP Activity Log** | 모든 POS 작업 기록 → postmeta 비대화 → _"제품이 10개만 표시됨"_ | 비활성화하거나 POS 게시물 유형을 로그 기록에서 제외하세요 |
| **Jetpack / Astra / Xero** (`save_post`에 후크를 연결하는 모든 플러그인) | POS API를 호출할 때마다 메타 행이 중복 생성됨 (한 매장에서는 제품 하나에 36,867개 행이 생성됨) | v1.8.12+(무료) / v1.8.14+(Pro)에서 정리 마이그레이션으로 자동 수정됩니다. 업데이트만 하세요 |
| **Stripe Tax** | REST API로 생성한 주문(POS의 주문 생성 방식)과 호환되지 않음 | 우회 방법 없이 호환되지 않습니다. 지원되는 자동 세금 옵션은 [WooCommerce Tax](/1.x/integrations/woocommerce-tax)입니다 |
| **Mollie** | POS 결제에서 BACS(은행 송금) 결제 방법이 숨겨질 수 있음 | Mollie를 최신 버전으로 업데이트하세요 |
| **CTX Feed** | POS 설정 페이지에서 간헐적으로 403 오류 발생 | 비활성화해 원인인지 확인하세요. 알려진 우회 방법은 없습니다 |
| **서드파티 바코드 스캐너 플러그인** | 주문 API JSON을 손상시켜 주문 생성/표시에 문제를 일으킴 | 비활성화하고 POS에 내장된 바코드 스캔 기능을 사용하세요 |
| **MailerLite** (Signup Forms + WooCommerce) | POS 주문 생성 시 500 오류 발생 (메모리 고갈) | 비활성화해 원인인지 확인한 다음 MailerLite에 문의하세요 |
| **The Courier Guy Shipping** | 서버 오류로 POS 주문 생성 실패 | 이전 버전으로 되돌리거나 개발자에게 문의하세요 |
| **PixelYourSite / PixelMySite** | 치명적인 오류: _불리언 값에서 멤버 함수 `is_type()` 호출_ | 일시적으로 비활성화하세요 |
| **Google Listings & Ads** | 자동 로더 충돌 → _"WCPOS\…\Stores 클래스를 찾을 수 없음"_ 치명적인 오류 | 모든 POS 플러그인을 삭제하고 최신 Pro 독립형 버전만 다시 설치하세요 |

:::warning Stripe Terminal: 전체 사이트에서 활성화하지 마세요
**Stripe Terminal** 결제 게이트웨이는 **오직** POS 설정 안에서 활성화해야 하며, `WooCommerce > 설정 > 결제`에서는 절대 활성화하면 안 됩니다. 전체 사이트에서 활성화하면 고객용 온라인 매장의 결제 화면에도 나타나 온라인 결제가 중단됩니다.
:::

### 서버 수준의 충돌 {#server-level-conflicts}

| 원인 | 증상 | 해결 방법 |
| --- | --- | --- |
| **사용자 정의 CSP 헤더** (`.htaccess`, Nginx 또는 보안 플러그인) | POS가 로고 화면에서 멈춤; JS/CSS 차단됨 | v1.9.0+에서는 POS 페이지에서 자동으로 제거됩니다. 서버 수준의 CSP는 `script-src`/`style-src`에서 `cdn.jsdelivr.net`을 허용하거나 `/pos/` 예외를 추가하세요 |
| **GoDaddy Website Firewall** | `/wp-json/`을 차단함 (_"'undefined'를 수신함"_) | 방화벽에서 `/wp-json/` URL 경로를 허용하세요. [서버 성능](/1.x/support/performance/server#hosting-specific-notes)을 참조하세요 |

## 예방 팁 {#prevention-tips}

### 정기적인 유지 보수 {#regular-maintenance}

1. **플러그인을 최신 상태로 유지하세요** - 항상 최신 버전을 사용하세요
2. **사용하지 않는 플러그인을 제거하세요** - 비활성화만 하지 말고 삭제하세요
3. 운영 중인 사이트에 적용하기 전에 **스테이징에서 업데이트를 테스트하세요**
4. [서버 성능](/1.x/support/performance/server) 지표로 정기적으로 **성능을 모니터링하세요**

### 플러그인 선택 권장 사항 {#plugin-selection-best-practices}

1. **평판이 좋은 개발자를 선택하세요** - 리뷰와 업데이트 빈도를 확인하세요
2. **중복 기능은 피하세요** - 같은 기능을 하는 플러그인을 여러 개 설치하지 마세요
3. **호환성 정보를 읽어 보세요** - WooCommerce와 함께 테스트된 플러그인인지 확인하세요
4. **최소한의 플러그인으로 시작하세요** - 필요에 따라 기능을 점차 추가하세요
