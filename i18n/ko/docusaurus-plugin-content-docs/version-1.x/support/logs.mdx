POS에는 두 가지 로그 인터페이스가 있습니다: **앱 내 활동 로그**(POS 애플리케이션 내부)와 **WP Admin 로그 페이지**(WordPress 내부). 이 둘을 함께 사용하면 디버깅과 감사를 위한 POS 활동의 전체 그림을 얻을 수 있습니다.

## POS 애플리케이션 로그 {#pos-application-logs}

:::info v1.10.0에서 변경됨
v1.10.0부터 앱 내 로그는 **스토어 상태 → 로그**에 있습니다(탐색 드로어의 심장 박동 아이콘 — 이를 대체하기 전의 독립 로그 화면은 제거되었습니다). 이 섹션에서는 v1.10.0 로그를 설명하며, 해당 영역 전체에 대한 안내는 [스토어 상태](/support/store-health#logs)를 참조하세요.
:::

### 로그 접근하기 {#accessing-logs}

왼쪽 탐색 드로어에서 **스토어 상태**(심장 박동 아이콘)를 열고 **로그** 탭을 선택합니다.

### 인터페이스 개요 {#interface-overview}

로그는 이 기기의 활동 원장이며 30일간 보관됩니다. 각 행에는 다음이 표시됩니다:

| 열 | 설명 |
|--------|-------------|
| **시간** | 이벤트가 발생한 시간 |
| **레벨** | 심각도 — error, warning, action, sync, info |
| **이벤트** | 사람이 읽을 수 있는 설명(표시 시점에 번역됨) |
| **소요 시간** | 작업에 걸린 시간 |
| **상태** | 결과 |

원장 위에는 마지막 변경 확인 시각과 다음 확인 예정 시각을 보여주는 동기화 하트비트 상태 줄이 있고, 통계 헤더에는 오늘의 이벤트 및 오류 수, 멈춘 레코드 수, 전송 대기 중인 변경 사항 수가 표시됩니다. 대부분은 탭하면 필터로 작동합니다.

#### 필터링 {#filtering}

프리셋 칩으로 원장을 필터링합니다: **전체**, **작업**(사람이 수행한 일 — 판매, 편집, 설정 변경), **오류**, **동기화**. 별도의 **상세 진단** 토글은 24시간 동안 추가 세부 정보를 수집한 뒤 자동으로 꺼집니다.

### 행 세부 정보 및 오류 코드 {#row-details}

오류 또는 경고 행을 탭하면 펼쳐집니다. 세부 보기에서는 다음을 확인할 수 있습니다:

- **무슨 일이 있었는지**를 쉬운 표현으로 설명
- **내 데이터** — 명시적인 데이터 안전성 안내(예: 해당 변경 사항이 서버에 안전하게 저장되었는지, 아니면 이 기기에만 존재하는지)
- **해야 할 일** — 권장되는 다음 단계
- **도움말 링크** — 오류에는 [오류 코드](/error-codes) 문서로 연결되는 코드(예: `SYNC121`, `AUTH311`)가 포함됩니다
- **복사 가능한 이벤트 코드** — 행 제목은 표시 시점에 번역되므로 이벤트 코드가 변하지 않는 식별자입니다. 지원팀에 문의할 때 이 코드를 알려주세요.

## WP Admin 로그 페이지 {#wp-admin-logs-page}

POS 플러그인은 WordPress 관리 영역에 서버 측 로그 페이지도 제공합니다. 이 페이지는 서버에 기록된 POS 관련 경고 및 오류를 보여주며, POS 애플리케이션 자체에는 나타나지 않을 수 있는 문제를 진단하는 데 도움이 됩니다.

### WP Admin 로그 페이지 접근하기 {#accessing-the-wp-admin-logs-page}

**WP Admin > POS > 설정**으로 이동한 다음 **도구** 탭을 선택하고 **로그**를 클릭합니다.

### 읽지 않음 배지 {#unread-badge}

로그 메뉴 항목에는 읽지 않은 로그 항목을 나타내는 배지가 표시됩니다:

- **빨간색 배지** - 읽지 않은 오류 레벨 항목이 있음
- **호박색 배지** - 읽지 않은 경고 레벨 항목이 있음(단, 오류는 없음)

로그 페이지를 방문하면 읽지 않음 카운트가 재설정됩니다. 카운트는 사용자별로 추적되므로 각 관리자는 자신의 읽지 않음 상태를 봅니다.

### 항목 필터링 {#filtering-entries}

레벨 필터를 사용하여 로그 항목을 좁힐 수 있습니다:

- **전체** - 모든 로그 항목 표시
- **오류** - 오류 레벨 항목만 표시
- **경고** - 경고 레벨 항목만 표시

### 확장 가능한 항목 {#expandable-entries}

긴 로그 메시지는 약 100자에서 잘립니다. 항목을 클릭하면 확장되어 추가 컨텍스트 데이터와 함께 전체 메시지를 볼 수 있습니다.

### 페이지 매김 {#pagination}

로그 항목은 서버 측에서 페이지 매김됩니다. 페이지 매김 컨트롤을 사용하여 이전 항목을 탐색하세요.

### 치명적 오류 배너 {#fatal-errors-banner}

서버에 `fatal-errors-*.log` 파일이 있으면 로그 페이지 상단에 경고 배너가 표시됩니다. 이 배너는 전체 치명적 오류 로그를 볼 수 있는 **WooCommerce > 상태 > 로그**로 연결됩니다. 치명적 오류는 일반적으로 POS API가 응답하지 못하게 하는 PHP 수준의 충돌입니다.

## 지원을 위한 로그 사용 {#using-logs-for-support}

지원을 요청할 때:

1. **문제 재현** - 문제를 일으키는 작업을 수행합니다
2. **로그 확인** - **스토어 상태 → 로그**에서 오류나 경고를 찾습니다
3. **행 펼치기** - 데이터 안전성 안내와 권장 다음 단계를 읽습니다
4. **이벤트 코드 복사** - 지원 요청에 포함하세요. 무슨 일이 있었는지를 나타내는 변하지 않는 식별자입니다
5. **상세 진단 켜기** - 지원팀이 더 자세한 정보를 요청하면 사용하세요. 24시간 동안 추가 정보를 수집합니다

## 성능 모니터링 {#performance-monitoring}

종합 성능 정보는 **스토어 상태 → 성능**에 있습니다. 지난 24시간 동안의 요청 수, 전송된 데이터량(응답이 크기를 알려주지 않으면 하한값), 일반적인 응답 시간과 시간별 가동 상태 스트립을 보여줍니다. 응답 시간이 높아 보인다면 [서버 성능](/support/performance/server)을 참조하세요.
