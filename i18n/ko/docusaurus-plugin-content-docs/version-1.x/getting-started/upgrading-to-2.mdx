WCPOS 2.0은 주요 업데이트입니다. 레지스터와 결제 화면, 현금 서랍이 새로워졌으며, 플러그인에는 이제 **WooCommerce 9.0 이상**이 필요합니다. 이 페이지는 **업데이트**를 클릭할 담당자를 위한 사전 점검 안내입니다. 업데이트하기 전에 읽어 보세요.

## 지금 업그레이드할 수 있나요? {#can-you-upgrade-today}

**WP 관리자 → 플러그인**을 열고 WooCommerce 버전을 확인하세요.

- **WooCommerce 9.0 이상:** [매장이 준비된 경우](#if-your-store-is-ready)의 안내를 따르세요.
- **9.0 미만:** [매장이 아직 준비되지 않은 경우](#if-your-store-isnt-ready-yet)의 안내를 따르세요. 먼저 WCPOS를 업데이트하지 마세요.

## 매장이 준비된 경우 {#if-your-store-is-ready}

### 업데이트를 클릭하기 전에 {#before-you-click-update}

1. **모든 계산대를 동기화하세요.** 2.0은 각 계산대에 새 로컬 데이터베이스를 만들며, 1.11 계산대에서 아직 매장으로 보내지 않은 데이터는 가져오지 않습니다. 각 계산대를 열고 동기화가 완료될 때까지 기다린 후 업데이트하세요. **매장 상태 → 데이터베이스**에서 **전송 대기 중인 변경 사항**이 **0**으로 표시되고, 결정을 요청하는 패널이 없어야 합니다. 이 숫자에는 미결 주문이 포함되지 않습니다. 각 주문을 완료하거나 해당 주문에서 **서버에 저장**을 누르세요. 두 항목에는 현재 로그인한 사용자만 표시되므로, 모든 매장과 사용하는 각 계산대에서 해당 계산대를 사용하는 캐셔마다 이 작업을 반복하세요.
2. **사이트를 백업**하거나 호스팅 업체에 복원 지점을 요청하세요. 업데이트 자체는 주문이나 상품에 영향을 주지 않지만, 주요 업데이트를 하기 전에는 되돌릴 방법을 마련해 두는 것이 좋습니다.
3. **한가한 시간을 선택하세요.** 모든 계산대가 새 계산대로 다시 로드됩니다. 이전 버전에서 결제가 진행 중이던 판매 건은 처음부터 다시 처리해야 합니다.
4. **Pro 라이선스가 활성 상태인지 확인하세요**(WP 관리자 → POS → 설정 → 라이선스, [WCPOS Pro 설치](/getting-started/pro-license) 참고). 유효한 라이선스가 있어야 Pro 업데이트를 받을 수 있습니다.
5. **할인 처리 방식을 확인하세요.** 캐셔가 *음수 수수료*를 추가해 주문 금액을 낮췄다면, 이제 이 방법은 작동하지 않습니다. 2.0에서는 계산대에 **할인 추가** 기능이 있어 할인을 올바르게 기록합니다. [장바구니 할인](/pos/cart/discounts)을 참고하세요.
6. **결제 단말기 확장 기능도 업데이트하세요.** Stripe Terminal, SumUp, Mollie Terminal은 각각 2.0 릴리스를 제공합니다. 이전 확장 기능도 결제 화면의 **레거시** 탭에서 계속 작동하지만, 새 결제 수단 창에서 카드 리더기를 제어할 수는 없습니다.

### 업데이트하기 {#updating}

1. **플러그인을 업데이트하세요.** 무료 버전을 사용하는 사이트에서는 **WCPOS**를 업데이트하세요. Pro를 사용하는 경우에는 **WCPOS Pro**만 업데이트하세요. 무료 플러그인이 이미 포함되어 있으며 별도로 설치된 무료 플러그인은 비활성화됩니다.
2. 모든 기기에서 POS를 열고 첫 동기화가 끝날 때까지 기다리세요. 브라우저 계산대는 플러그인이 업데이트되는 즉시 2.0을 사용합니다. 데스크톱 및 모바일 앱은 평소와 같은 경로로 업데이트하세요. 2.0 플러그인에 연결한 1.11 앱은 업데이트 안내 화면에서 멈추며, 앱을 업데이트할 때까지 사용할 수 없습니다. 앱과 플러그인 모두 2.0이어야 합니다.

업데이트 후 계산대에 **AUTH331**이 표시되면 2.0 앱이 아직 업데이트되지 않은 매장에 연결된 것입니다. 플러그인을 업데이트한 다음 다시 연결하세요. [AUTH331](/error-codes/AUTH331)을 참고하세요.

### 첫날 달라지는 점 {#what-changes-on-day-one}

- **계산대 화면이 달라집니다.** 모든 화면에 통일된 디자인이 적용되며, 기기 크기에 맞춰 화면 크기를 작게, 보통, 크게 설정할 수 있습니다. 양식과 선택기는 팝업 대화상자 대신 패널로 나타납니다. 상단 막대에는 현재 매장 이름이 표시되며, 매장에 계산대가 여러 개 있으면 계산대 이름도 표시됩니다. 장바구니를 어느 쪽에 표시할지 선택하고 계산대 설정에서 빠른 필터 버튼을 한 줄로 구성할 수 있습니다.
- **결제는 결제 수단 창에서 진행합니다.** **결제**를 누르면 키패드가 열립니다. 고객이 건넨 금액을 입력하면 거스름돈이 표시됩니다. 현금과 카드로 나누거나 여러 카드로 나누어 결제할 수 있습니다. 계산대에 연결된 카드 리더기도 같은 화면에서 제어합니다(Pro). 자체 결제 페이지를 사용하는 게이트웨이는 **레거시** 탭에서 사용할 수 있습니다. [결제](/pos/checkout)를 참고하세요.
- **모든 계산대에 레지스터가 있습니다.** 캐셔가 POS를 처음 열 때 시재를 입력해 레지스터를 엽니다. **레지스터 닫기**를 누르면 서랍의 현금을 세고 해당 금액을 번호가 매겨진 마감 기록으로 저장합니다. 이후 표시되는 완료 화면에서 마감 보고서(Z 보고서)를 인쇄합니다. 이 기능은 무료 플러그인에 포함됩니다. 무료 플러그인에는 모든 기기에서 공유하는 레지스터가 하나 있습니다. 관리자는 **WP 관리자 → POS → 설정 → 레지스터**에서 이름과 기본 시재를 설정할 수 있으며, Pro에서는 레지스터를 더 추가할 수 있습니다. 현금 서랍을 사용하지 않는 경우 POS 설정에서 레지스터 세션을 끌 수 있습니다. [하루 마감 정산](/pos/reconciliation)을 참고하세요.
- **계산대에서 쿠폰을 사용하는 기능은 무료입니다.** 무료 플러그인을 사용하는 캐셔는 장바구니에 WooCommerce 쿠폰 코드를 적용할 수 있습니다. POS에서 쿠폰 화면을 둘러보는 기능은 계속 Pro에 포함됩니다.
- **음수 수수료는 더 이상 사용할 수 없습니다.** **할인 추가**를 사용하세요. 이미 음수 수수료가 포함된 주문은 변경되지 않습니다.
- **WooCommerce Analytics는 POS 주문이 결제되면 집계합니다.** 계산대에서 아직 열려 있거나 일부만 결제된 주문은 완료될 때까지 더 이상 판매로 표시되지 않으므로, 이 주문들을 포함했던 합계는 낮아집니다.
- **영수증에 더 많은 정보가 표시됩니다.** 모든 영수증에 레지스터 이름, 소프트웨어 버전, QR 코드가 표시됩니다. 환불 시에는 대변 메모로 별도의 영수증이 출력됩니다. 맞춤 영수증 템플릿도 계속 작동합니다.
- **마그네틱 카드 리더기는 더 이상 지원되지 않습니다.** 계산대의 카드 결제는 통합 카드 리더기(Pro)를 사용하거나 외부 카드 결제로 기록해야 합니다.

## 매장이 아직 준비되지 않은 경우 {#if-your-store-isnt-ready-yet}

**WCPOS 1.11을 계속 사용하세요.** 정상 작동하며 2.0 출시 후 6개월 동안 수정 사항도 계속 제공됩니다.

1. **WCPOS와 WCPOS Pro의 자동 업데이트를 끄세요.** **WP 관리자 → 플러그인**에서 각 플러그인 행에 **자동 업데이트 활성화** / **자동 업데이트 사용 안 함** 링크가 있습니다. *자동 업데이트 활성화*라고 표시되는지 확인하세요. 이렇게 하면 근무 중 자동 업데이트로 인해 캐셔 앞에 사용을 막는 안내가 표시되는 일을 방지할 수 있습니다.
2. **준비가 되면 WooCommerce를 9.0 이상으로 업데이트하세요.** WooCommerce의 자체 릴리스 노트에서 업데이트 내용을 확인할 수 있습니다.
3. **[매장이 준비된 경우](#if-your-store-is-ready)의 안내로 돌아오세요.**
4. **2.0으로 업데이트한 후에는 자동 업데이트를 다시 켜세요.** 자동 업데이트를 사용했다면 다시 켜야 이후 수정 사항이 자동으로 적용됩니다.

### WooCommerce보다 WCPOS를 먼저 업데이트한 경우 {#if-wcpos-updated-first}

POS에 WooCommerce 9.0이 필요하다는 안내가 표시되고 작업이 중단되지만, 데이터는 손실되지 않습니다. 지금 WooCommerce를 업데이트하거나 [WCPOS 1.11을 다시 설치](/getting-started/previous-versions)한 다음 위의 안내에 따라 자동 업데이트를 끄세요.

## 롤백하기 {#rolling-back}

### 1.11 계산대에 전송되지 않은 판매 건이 남아 있는 경우 {#unsent-sales}

계산대에 업데이트 화면이 표시되며 판매 건이 아직 매장에 도착하지 않았습니다. 계산대에서 2.0을 열기 전까지 해당 판매 건은 기기에 남아 있습니다. 매장으로 보내려면 다음을 따르세요.

1. **해당 계산대는 그대로 두세요.** 앱을 업데이트하지 말고, 브라우저 계산대에서는 페이지를 새로고침하지 마세요. 둘 중 하나라도 하면 2.0이 열리면서 전송되지 않은 판매 건이 삭제됩니다.
2. **[1.11 플러그인을 매장에 다시 설치](/getting-started/previous-versions)** 하세요.
3. **브라우저 계산대에서는 페이지를 새로고침하고, 앱에서는 앱을 종료한 다음 다시 여세요.** 이제 매장이 다시 1.11을 사용하므로 계산대가 다시 연결되어 판매 건을 전송합니다. **매장 상태 → 데이터베이스**의 **전송 대기 중인 변경 사항**이 **0**으로 표시되고 결정을 요청하는 패널이 없어질 때까지 기다리세요. 미결 주문은 이 숫자에 포함되지 않습니다. 각 주문을 완료하거나 해당 주문에서 **서버에 저장**을 누르세요. 이제 판매 건이 매장에 저장되었습니다.
4. [업데이트하기](#updating)의 안내에 따라 **2.0으로 다시 업데이트하세요.**

### 1.11로 돌아가기 {#back-to-1-11}

2.0이 제대로 작동하지 않으면 먼저 [Discord](https://wcpos.com/discord)에서 알려 주세요. 업그레이드 당일에 발생하는 대부분의 문제는 롤백보다 더 빠르게 해결할 수 있습니다.

:::warning 롤백하기 전에 동기화하세요
1.11로 되돌리면 각 계산대의 로컬 데이터베이스가 비워진 상태로 시작되며, 1.11에서는 2.0 계산대가 매장에 아직 보내지 않은 판매 건을 전송할 수 없습니다. 롤백하기 전에 모든 2.0 계산대의 동기화가 완료될 때까지 기다리세요. **매장 상태 → 데이터베이스**에서 **전송 대기 중인 변경 사항**이 **0**이어야 하며, 결정을 요청하는 패널이 없어야 하고 동기화되지 않은 미결 주문도 없어야 합니다.
:::

**이미 2.0을 사용하는 데스크톱 또는 모바일 앱은 1.11 플러그인에 연결할 수 없습니다**([AUTH331](/error-codes/AUTH331)이 표시됨). 앱 스토어에서는 이전 버전을 제공하지 않습니다. 다시 업그레이드할 때까지 해당 계산대에서 `yourdomain.com/pos`의 브라우저 POS를 사용하세요.

롤백하려면 [1.11 플러그인을 다시 설치](/getting-started/previous-versions)하세요. 계속 1.11을 사용하는 브라우저 계산대와 앱은 이전처럼 계속 작동합니다.

2.0에서 만든 주문은 일반 WooCommerce 주문이므로 그대로 유지됩니다. 2.0에서 기록한 레지스터 세션과 마감 기록도 데이터베이스에 남지만, 1.11에는 표시되지 않습니다.
