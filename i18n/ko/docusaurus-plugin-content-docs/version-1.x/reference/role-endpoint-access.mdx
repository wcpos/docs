이 페이지에서는 POS 워크플로에 사용되는 세 가지 기본 역할이 각각 접근할 수 있는 WCPOS REST 엔드포인트를 설명합니다:

- `administrator`
- `shop_manager`
- `cashier`

사용자용 역할 및 권한 설정은 [POS 접근](/1.x/settings/wp-admin/access)을 참조하세요.

## 요약 {#summary}

기본 접근 모델은 다음과 같습니다:

- **`administrator`** — 전체 POS 및 관리 기능에 접근할 수 있습니다.
- **`shop_manager`** — 플러그인 설치 권한이 필요한 플러그인 확장 작업을 제외한 전체 POS 및 관리 기능에 접근할 수 있습니다.
- **`cashier`** — 일반적인 POS 판매 워크플로에 접근할 수 있지만 관리, 설정, 로그 또는 매장 관리 기능에는 접근할 수 없습니다.

엔드포인트 매트릭스는 POS 앱과 동일한 인증 경로(단순한 `wp_set_current_user()`가 아닌 WCPOS 베어러 액세스 토큰)를 거치는 통합 테스트로 검증됩니다. 허용된 엔드포인트 검증에서는 해당 역할이 `401` 또는 `403` 응답을 받지 않는지 확인합니다. 최소한의 테스트 데이터를 사용할 경우 일부 엔드포인트는 정상 데이터나 `400`, `404` 같은 업무 처리 오류를 반환할 수 있습니다. 이러한 응답도 사용자가 인증/권한 계층을 통과했음을 보여 줍니다.

| 시나리오 | 관리자 | 매장 관리자 | 캐셔 | 예상 결과 |
|---|---:|---:|---:|---|
| 유효한 액세스 토큰 | ✅ 테스트됨 | ✅ 테스트됨 | ✅ 테스트됨 | 허용된 엔드포인트는 `401` 또는 `403`을 반환하지 않음 |

## 실패 진단 {#diagnosing-failures}

기본 `shop_manager`에게 다음과 같은 오류가 표시되는 경우:

> 토큰을 갱신한 후에도 요청이 승인되지 않습니다. 다시 로그인하세요.

엔드포인트 매트릭스에 따르면 이 오류는 기본 `shop_manager` 역할에 근본적으로 POS 접근 권한이 없기 때문이 **아닙니다**. 다음과 같은 원인을 조사하세요:

1. 해당 사이트의 역할/권한 손상.
2. 매트릭스에 포함되지 않은 엔드포인트.
3. 클라이언트가 오래되었거나 만료된 액세스 토큰으로 재시도하는 동작.
4. 서드파티 보안 또는 인증 플러그인의 간섭.
5. Pro 또는 매장별 접근 규칙이나 사용자 지정 코드.

### 권한 실패와 토큰 실패의 차이 {#permission-failure-vs-token-failure}

POS 프런트엔드는 `401` 또는 `403`을 받은 뒤 토큰 갱신을 시도하고 재시도한 요청도 승인되지 않으면 두 경우 모두 동일한 토큰 갱신 오류를 표시할 수 있습니다. 서버 측에서는 두 실패 유형이 다르게 나타납니다:

**실제 역할/권한 실패**는 일반적으로 다음과 같습니다:

```text
status: 403
current_user: <actual user id>
access token expired: false
```

**토큰/인증 실패**는 일반적으로 다음과 같습니다:

```text
status: 403
current_user: 0
access token expired: true or invalid
```

POS 접근 문제를 분류할 때 이 차이를 활용하세요. `current_user`가 영이 아니면 권한을, `current_user: 0`이면 인증/토큰 계층을 확인하세요.
