**WooCommerce REST API**는 매장 소유자가 자신의 WooCommerce 매장을 다른 애플리케이션 및 서비스에 연결할 수 있도록 해주는 표준화된 “채널” 집합과 같습니다.

작동 방식을 간단히 설명하면 다음과 같습니다:

1. WooCommerce 매장과 외부 애플리케이션 사이에서 다리 역할을 하여 서로 통신하고 데이터를 공유할 수 있게 합니다.

2. API는 특정 **엔드포인트**에 요청을 보내는 방식으로 작동합니다. 각 엔드포인트를 여러 유형의 매장 데이터에 연결되는 "채널"로 생각해 보세요. 예를 들어 상품, 주문, 고객을 위한 엔드포인트가 있습니다.

3. 외부 애플리케이션은 이러한 엔드포인트를 사용하여 다음 작업을 할 수 있습니다:

- 정보 가져오기(예: 상품 목록 가져오기)
- 새 데이터 추가(예: 새 주문 만들기)
- 기존 정보 업데이트(예: 상품 가격 변경)
- 데이터 삭제(예: 오래된 상품 제거)

많은 전통적인 WordPress 플러그인처럼 PHP 훅과 필터에 의존하는 대신, **JSON**이라고 하는 구조화되고 예측 가능한 형식으로 데이터를 전송하고 수신합니다.

## 일부 플러그인이 POS에서 작동하지 않는 이유는 무엇인가요? {#why-dont-some-plugins-work-in-the-pos}

WCPOS는 REST API를 통해 WooCommerce 매장에서 상품, 주문, 고객 데이터를 다운로드합니다.
그런 다음 인터넷 연결이 불안정해도 POS가 계속 작동할 수 있도록 해당 데이터의 로컬 사본을 유지합니다.
이 방식은 바쁜 결제 환경에서 POS를 더 빠르고 안정적으로 작동하게 합니다.

하지만 이 때문에 POS는 사이트에서 실시간으로 동적으로 발생하는 변경 사항을 "보지" 못합니다. 예를 들면 다음과 같습니다:

<table>
  <tr>
    <th style={{ width: "200px" }}>플러그인 유형</th>
    <th>작동하지 않는 이유</th>
  </tr>
  <tr>
    <td>동적 가격 책정</td>
    <td>
      매장의 다른 플러그인이
      로그인한 고객마다 고유한 가격을 계산하면 POS는 해당 가격을 자동으로

    </td>
  </tr>
  <tr>
    <td>상품 추가 기능</td>
    <td>
      매장의 다른 플러그인이 상품 데이터를 추가해도 POS는
      해당 데이터를 자동으로 가져오지 않습니다. POS는 REST API에 노출된 데이터만
      가져옵니다.
    </td>
  </tr>
</table>
