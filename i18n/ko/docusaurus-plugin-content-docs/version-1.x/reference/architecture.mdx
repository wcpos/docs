이 페이지는 개발자와 고급 사용자를 위한 WCPOS의 기술 아키텍처를 설명합니다.

## 두 부분으로 구성된 시스템 {#two-part-system}

WCPOS는 두 부분으로 구성된 시스템으로 설계되었습니다:

1. **PHP 플러그인:** 서버에서 호스팅되는 비교적 작은 플러그인으로, [WooCommerce REST API](/1.x/reference/wc-rest-api)에 POS 전용 엔드포인트를 추가합니다.

2. **JavaScript 클라이언트:** 브라우저, 데스크톱 앱, iOS/Android 앱에서 로컬로 실행됩니다.

두 개의 별도 영역으로 생각할 수 있습니다:

- _PHP 영역_에서는 WordPress와 WooCommerce를 사용해 데이터를 관리합니다.
- _JavaScript 영역_은 계산대에 필요한 매장 데이터의 사본을 로컬에 보관하여 오프라인에서도 사용할 수 있게 하며, 빠른 검색과 즉각적인 응답에 최적화되어 있습니다.

## 데이터 동기화 {#data-synchronization}

:::info v1.10.0에서 변경됨
v1.10.0에서는 기존 복제 계층을 전용 **동기화 엔진**으로 대체합니다. 아래는 간략한 요약이며, 전체 설명은 [동기화 엔진 작동 방식](/1.x/reference/sync-engine)을 참조하세요.
:::

클라이언트는 로컬 우선 방식입니다. 모든 화면이 기기의 로컬 데이터베이스를 읽고 쓰며, 백그라운드 동기화 엔진이 이 데이터베이스와 WooCommerce의 데이터를 일치시킵니다. 엔진은 매장 전체를 무작정 미러링하지 **않습니다**. 화면에 실제로 필요한 데이터를 기준으로 동작합니다:

- **변경 감지:** POS는 조건부 요청으로 가벼운 변경 로그를 주기적으로 조회합니다. 변경이 없는 매장은 본문 없는 `304` 응답 하나로 답합니다.
- **선언된 수요:** 화면이 표시할 데이터를 선언하면 엔진이 요청이 필요한지, 로컬 데이터만으로 처리할 수 있는지 판단합니다.
- **시드와 레인:** 범위가 제한된 카탈로그 시드, 최근 주문 조회 범위, 유휴 시간 유지 관리 레인이 기기별로 조정 가능한 일정에 따라 로컬 데이터를 채우고 검증합니다.
- **내구성 있는 쓰기:** 판매와 수정 내용은 로컬 큐에 저장된 후 WooCommerce로 전송됩니다. 서버가 거부한 항목에는 사용자가 확인할 수 있는 복구 절차가 제공됩니다.

동기화 대상은 상품 및 변형, 카테고리/태그/브랜드, 고객, 세율, 쿠폰(Pro), 주문입니다. 결제 게이트웨이는 결제 시점에 가져옵니다.

## 아키텍처 장단점 {#architecture-pros-and-cons}

| 장점 😊 | 단점 😟 |
| ------------------------------------------------------------------ | -------------------------------------------------------- |
| 로컬 데이터를 즉시 검색 | 데이터 동기화 유지가 어려움 |
| 캐시 데이터를 오프라인에서 사용 가능 | WooCommerce REST API의 제약을 받음 |
| 데스크톱, iOS, Android용으로 더 나은 네이티브 앱 개발 가능 | WordPress 테마와 훅으로 POS 앱을 사용자 지정할 수 없음 |

## 로컬 데이터베이스 {#local-database}

클라이언트는 각 기기의 로컬 데이터베이스에 데이터를 저장합니다. 웹과 데스크톱 앱은 **워커에서 실행되는 OPFS(Origin Private File System) 저장소**를 사용하며, 모바일 앱은 파일 시스템 엔진을 통해 동일한 디스크 저장 형식을 사용합니다. 모든 플랫폼이 하나의 저장 형식과 복구 도구를 공유합니다. 이를 통해 다음과 같은 이점을 제공합니다:

- **지속성:** 브라우저를 다시 시작하거나 기기를 재부팅해도 데이터가 유지됩니다
- **성능:** 네트워크 지연 없이 빠르게 조회합니다. 필터링, 정렬, 페이지네이션이 저장 계층 안에서 실행되므로 현재 표시할 페이지의 행만 UI로 전달됩니다
- **오프라인 탐색:** 인터넷 없이도 캐시 데이터에 접근할 수 있습니다

사이트 + 매장 + 캐셔 조합마다 별도의 로컬 데이터베이스가 생성되므로 한 기기에서도 캐셔와 매장 사이에 로컬 데이터가 공유되지 않습니다. 업그레이드할 때는 기존 로컬 데이터베이스를 직접 마이그레이션하지 않습니다. 항상 기준 원본인 서버에서 앱이 데이터를 다시 다운로드합니다.

## 결제 아키텍처 {#checkout-architecture}

결제 과정에서는 WooCommerce 주문 결제 페이지를 불러오는 iframe/webview를 사용합니다. 이 방식의 이점은 다음과 같습니다:

- **기존 결제 게이트웨이 활용:** 모든 WooCommerce 결제 게이트웨이를 POS에서 사용할 수 있습니다
- **보안 유지:** WooCommerce의 안전한 인프라를 통해 결제가 처리됩니다
- **복잡성 감소:** 결제 게이트웨이 연동을 다시 구현할 필요가 없습니다

## API 확장 {#api-extensions}

PHP 플러그인은 POS 전용 기능을 위한 엔드포인트를 추가하여 WooCommerce REST API를 확장합니다. 엔드포인트는 전용 `wcpos/v1` 및 `wcpos/v2` 네임스페이스에 등록됩니다. `wcpos/v2`가 v1.10.0의 동기화 인터페이스를 담당하므로 앱과 플러그인 버전은 함께 출시됩니다. 소개는 [WooCommerce REST API](/1.x/reference/wc-rest-api)를 참조하세요.

### `wcpos/v2` 네임스페이스 {#wcpos-v2-namespace}

v1.10에서는 `wcpos/v2` REST 네임스페이스가 도입됩니다. 동기화는 이 네임스페이스에서 제공되며, 이전에 `wcpos/v1`에서 제공하던 공통 POS 서비스도 이제 `wcpos/v2`에서 제공됩니다(`wcpos/v1` 서비스 경로는 해당 v2 구현으로 요청을 그대로 전달합니다). `wcpos/v1` 경로는 하위 호환성을 위해 여전히 등록되지만 **동결**된 상태입니다. 현재 클라이언트는 더 이상 이 경로를 호출하지 않습니다.

이 엔드포인트와 연동할 때 알아야 할 사항은 다음과 같습니다:

- **v2 경로는 항상 등록됩니다.** 기존 `woocommerce_pos_sync_api_enabled` 옵션이 제거되어 API를 켜거나 끄는 플래그가 더 이상 없습니다.
- **공개 엔드포인트.** `wcpos/v2/site`, `wcpos/v2/ping`, `wcpos/v2/echo`는 공개되어 있습니다. 기능과 연결 상태를 확인하는 데 사용되며, 제한이 많은 호스트를 위한 [전송 대체 방식](/1.x/error-codes)도 여기에 포함됩니다.
- **주문은 UUID를 기본 식별자로 사용합니다.** 전송 시 주문 식별자는 UUID이며, 기존 `wooOrderId` 필드는 주문 가져오기 응답 구조에서 제거되었습니다. 주문 메타데이터는 단일 정규화기를 통해 타입이 지정된 형태로 전송됩니다.
- 서드파티 동기화 호환성을 위해 **항목별 가격 저장 방식이 문서화되어 있습니다**. [POS 가격 재정의 저장 방식](/1.x/reference/pos-discounts#how-pos-price-overrides-are-stored)을 참조하세요.
- POS의 **기본 상품 정렬**은 이제 **이름 오름차순**입니다(이전에는 `menu_order, id`).
- **제거된 레거시 메서드.** 기존 `API\Settings` 컨트롤러의 여러 메서드(예: `get_general_settings()`, `update_access_settings()`, `get_general_endpoint_args()`, `remove_license_transient()`)가 제거되었습니다. 클래스 별칭은 유지되지만 해당 메서드는 남아 있지 않습니다.

:::note Pro도 동일한 분리를 따릅니다
WCPOS Pro도 동일한 V1/V2 분리를 따릅니다. 공통 서비스는 `wcpos/v2`로 이동하지만 주문 데이터는 v1에 동결된 상태로 유지됩니다. 매장별 상품 가격 처리는 v2 레인에서 실행되며, 계산대의 매장 범위가 주문 쓰기에도 전달됩니다. 따라서 다중 매장 주문도 올바른 매장을 기준으로 가격과 세금을 계산합니다. [Pro](/1.x/getting-started/free-vs-pro)를 참조하세요.
:::
