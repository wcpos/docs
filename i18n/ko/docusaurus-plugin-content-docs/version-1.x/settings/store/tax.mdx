:::warning 중요
초기 로드 시 POS는 WooCommerce에서 기본 세금 설정을 가져옵니다. 특별한 필요가 없다면 일반적으로 WooCommerce와 동일한 설정을 유지해야 합니다. 서버와 다른 세금 설정을 사용하면 POS와 WooCommerce에서 서로 다른 세금 값을 계산할 가능성이 매우 높으며, 이로 인해 불일치와 주문 동기화 문제가 발생할 수 있습니다.
:::

## 모든 세율 보기 {#view-all-tax-rates}

**모든 세율 보기** 버튼을 클릭하면 POS에 다운로드된 모든 세율을 확인할 수 있습니다. 다음 항목이 표시됩니다:

- 세율 이름
- 세율 백분율
- 적용 지역/위치

올바른 세율이 로드되었는지 확인하고 세금 계산 문제를 디버깅하는 데 유용합니다.

## 세금 계산 설정 {#tax-calculation-settings}

### 세금 포함 입력 가격 {#prices-entered-with-tax}

제품 가격에 세금이 포함되는지 결정합니다:

| 옵션 | 설명 |
|--------|-------------|
| **예** | 제품 가격에 세금이 포함됩니다. POS는 총 가격에서 역산하여 세금을 계산합니다 |
| **아니요** | 제품 가격에 세금이 포함되지 않습니다. POS는 입력한 가격에 세금을 추가합니다 |

자동 세금이 활성화된 [WooCommerce Tax](/integrations/woocommerce-tax)를 사용하는 매장은 WooCommerce에 의해 **아니요**로 고정되며, POS에도 이를 반영해야 합니다.

### 세금 계산 기준 {#calculate-tax-based-on}

세금 계산에 사용할 주소를 결정합니다:

| 옵션 | 설명 |
|--------|-------------|
| **고객 배송 주소** | 주문이 배송될 주소를 기준으로 한 세율 |
| **고객 청구지 주소** | 고객의 청구지 주소를 기준으로 한 세율 |
| **상점 기본 주소** | 매장의 실제 위치를 기준으로 한 세율 |

자동 세금이 켜진 상태로 [WooCommerce Tax](/integrations/woocommerce-tax)를 사용하는 매장은 WooCommerce에 의해 고객 배송 주소로 고정됩니다. 여기에서 다른 옵션을 선택해도 POS 및 매장 모두의 POS 주문에는 계속 적용됩니다.

### 배송 세금 클래스 {#shipping-tax-class}

배송비에 세금을 부과하는 방식을 결정합니다:

| 옵션 | 설명 |
|--------|-------------|
| **장바구니 항목 기준 배송 세금 클래스** | 장바구니 항목의 세금 클래스를 기준으로 배송 세금이 계산됩니다 |
| **표준** | 배송비에 표준 세율이 적용됩니다 |
| **감세율** | 배송비에 감세율이 적용됩니다 |
| **영세율** | 배송비에 세금이 적용되지 않습니다 |

### 반올림 {#rounding}

| 옵션 | 설명 |
|--------|-------------|
| **소계 수준에서 세금 반올림** | 각 개별 품목의 세금을 반올림하는 대신 전체 소계에 대해 세금을 계산한 후 반올림합니다 |

WCPOS는 WooCommerce의 세금 계산 방식을 따르므로 계산대에서 주문을 처리하든 웹사이트에서 주문하든 주문 총액이 동일합니다:

- **전체 정밀도** — 품목 및 주문 총액은 전체 정밀도로 유지되며 표시할 때만 반올림됩니다. 따라서 주문에 저장되는 금액은 표시 소수 자릿수에 맞춰 미리 반올림된 값이 아니라 WooCommerce에서 예상하는 정확한 값입니다.
- **매장 반올림** — 반올림은 통화의 센트 정밀도를 사용하며 위의 **소계 수준에서 세금 반올림** 설정을 따릅니다.
- **복합 세금** — 세율이 *복합*으로 표시된 경우 세율은 WooCommerce의 우선순위 순서(`tax_rate_priority`)에 따라 적용되므로, 다른 세금에 추가로 부과되는 세금은 그 이후에 계산됩니다.

## 표시 설정 {#display-settings}

### 상점의 가격 표시 {#display-prices-in-the-shop}

| 옵션 | 설명 |
|--------|-------------|
| **세금 포함** | 표시되는 가격에 세금이 포함됩니다 |
| **세금 제외** | 표시되는 가격에 세금이 포함되지 않습니다 |

### 장바구니 및 결제 시 가격 표시 {#display-prices-during-cart-and-checkout}

| 옵션 | 설명 |
|--------|-------------|
| **세금 포함** | 장바구니 및 결제 가격에 세금이 포함됩니다 |
| **세금 제외** | 장바구니 및 결제 가격에서 세금이 제외됩니다 |

### 가격 표시 접미사 {#price-display-suffix}

세금 상태를 나타내기 위해 가격 뒤에 표시되는 텍스트(예: "VAT 포함" 또는 "VAT 제외")입니다.

### 세금 합계 표시 {#display-tax-totals}

| 옵션 | 설명 |
|--------|-------------|
| **단일 합계로 표시** | 모든 세금이 하나의 합계 행으로 결합됩니다 |
| **항목별 표시** | 각 세율이 별도의 항목 행으로 표시됩니다 |

## 서버 설정 복원 {#restore-server-settings}

클릭하면 서버에서 현재 WooCommerce 세금 설정을 가져와 적용합니다.

:::tip 사용 방법 및 시점
세금 설정의 기준은 WooCommerce이며, POS는 이를 반영해야 합니다. **서버 설정 복원**은 매장에서 최신 구성을 가져오는 안전한 방법이며, `WP Admin > WooCommerce > 설정 > Tax` 경로에서 세금 설정을 변경한 후 POS에 반영하려는 경우에 적합한 작업입니다.

한 번 더 확인해야 할 유일한 경우는 POS 측 세금 설정을 서버와 다르게 **의도적으로** 재정의한 경우(고급 설정)입니다. 서버 설정 복원을 실행하면 해당 재정의가 덮어써집니다. 이를 설정했는지 확실하지 않다면, 대부분 설정하지 않은 것입니다.
:::

## 일반적인 문제 {#common-issues}

### POS와 WooCommerce에 서로 다른 합계가 표시되는 경우 {#pos-and-woocommerce-showing-different-totals}

가장 흔한 세금 문제는 POS 세금 설정과 WooCommerce 세금 설정이 일치하지 않는 것입니다. 이 설정들이 서로 다르면 동일한 주문이라도 주문이 생성되는 위치에 따라 합계가 다르게 계산됩니다. POS 설정은 항상 동기화된 상태로 유지하세요. `WP Admin > WooCommerce > 설정 > Tax` 경로에서 항목을 변경한 후 **서버 설정 복원**을 사용하세요.

WooCommerce Tax를 사용하는 매장에서는 추가로 확인할 원인이 있습니다. 바로 매장에서 한 번도 세금을 부과한 적이 없는 지역에서 발생하는 첫 번째 판매입니다. [WooCommerce Tax](/integrations/woocommerce-tax#what-to-expect)를 참조하세요.

### 세금 포함 가격 혼동 {#tax-inclusive-pricing-confusion}

"세금 포함 가격 입력"이 **예**로 설정되어 있지만 "상점 내 가격 표시"가 **세금 제외**로 설정되어 있으면, 표시되는 가격은 입력한 가격보다 낮습니다. 이는 올바른 동작입니다. POS가 표시를 위해 세금 부분을 제외하기 때문입니다. 하지만 가격표 가격이 표시될 것으로 예상한 계산원에게는 혼란스러울 수 있습니다.

### 고객 주소 및 세금 계산 {#customer-address-and-tax-calculation}

"세금 계산 기준"이 **고객 배송 주소** 또는 **고객 청구 주소**로 설정된 경우, POS는 올바른 세율을 조회하기 위해 유효한 주소가 필요합니다. 방문 고객에게 등록된 주소가 없으면 WCPOS는 계산에 **상점 기본 주소**를 사용합니다. 이는 일반적으로 매장 내 판매에 적합한 동작이지만, 특정 고객에게 예상치 못한 세율이 표시되면 해당 고객의 주소 정보를 확인하세요.

## 문제 해결 {#troubleshooting}

### 세금 금액이 올바르지 않음 {#tax-amounts-are-incorrect}

1. POS에서 **세금 설정**으로 이동한 다음 **서버 설정 복원**을 클릭하여 WooCommerce에서 최신 구성을 가져옵니다.
2. **모든 세율 보기**를 클릭하여 예상한 세율이 표시되는지 확인합니다. 세율이 누락된 경우 `WP Admin > WooCommerce > 설정 > Tax > Standard rates` 경로에서 올바르게 구성되었는지 확인합니다. [WooCommerce Tax](/integrations/woocommerce-tax) 자동 세금이 활성화된 경우 행을 수동으로 추가하지 마세요. 위치의 행은 해당 위치에서 첫 판매가 발생하면 표시되며, POS는 다음 변경 사항 확인 시 이를 가져옵니다. 또는 매장 상태의 **세율** 행에서 **지우기 및 다시 다운로드**를 사용하면 즉시 가져옵니다.
3. 제품의 세금 클래스를 확인하세요. "영세율" 세금 클래스가 지정된 제품에는 설정과 관계없이 세금이 적용되지 않습니다.

### 세금이 0으로 표시됨 {#tax-is-showing-as-zero}

- WooCommerce에서 세금이 활성화되어 있는지 확인합니다 (`WP Admin > WooCommerce > 설정 > General > Enable tax rates and calculations`).
- POS에서 **모든 세율 보기**를 사용하여 세율이 다운로드되었는지 확인합니다. 목록이 비어 있으면 전체 동기화를 시도합니다.
- 제품의 세금 상태가 "과세"로 설정되어 있는지 확인합니다("없음" 또는 "배송만"이 아님).

### 반올림 차이 {#rounding-discrepancies}

한 시스템에서는 "소계 수준에서 세금 반올림"이 활성화되어 있고 다른 시스템에서는 활성화되어 있지 않은 경우 POS와 WooCommerce 간에 작은 반올림 차이(1~2센트)가 발생할 수 있습니다. 두 곳에서 이 설정이 동일한지 확인합니다.
