결제 설정 페이지(`WP Admin > POS > 설정 > 결제`)에서는 POS에 표시되는 결제 게이트웨이, 주문 처리 방식, POS 판매에 대해 발송되는 알림 이메일을 제어합니다.

## 이메일 알림 {#email-notifications}

페이지 상단에는 **관리자 이메일**, **고객 이메일**, **계산원 이메일**이라는 세 가지 이메일 토글 그룹이 있으며, 사이트 전체 WooCommerce 이메일 설정과 별도로 POS 주문에 대해 어떤 WooCommerce 알림 이메일을 보낼지 제어합니다.

이메일별 토글 기본값, 계산원 수신자 모델, 일반적인 시나리오, 개발자 훅을 포함한 전체 참조는 **[이메일 알림](/settings/wp-admin/email-notifications)**을 참조하세요.

## 결제 게이트웨이 {#payment-gateways}

이 섹션에는 사이트에 설치된 모든 WooCommerce 결제 게이트웨이가 나열됩니다. 각 게이트웨이는 POS에서 독립적으로 활성화하거나 비활성화할 수 있습니다.

| 열 | 설명 |
|--------|-------------|
| **기본값** | 계산원이 결제를 열 때 미리 선택될 게이트웨이를 선택합니다 |
| **게이트웨이** | 결제 게이트웨이 이름 |
| **게이트웨이 ID** | WooCommerce 게이트웨이 식별자(개발자에게 유용) |
| **활성화됨** | POS 결제에서 게이트웨이를 켜거나 끕니다 |
| **주문 상태** | 이 게이트웨이로 결제된 POS 주문에 설정되는 상태입니다(아래 [주문 상태](#order-status) 참조) |

각 행에는 메뉴(⋮)도 있으며, **POS 설정**에서는 게이트웨이의 POS 전용 **제목**과 **설명**을 변경할 수 있고, **WooCommerce 설정**은 WooCommerce의 게이트웨이 전체 설정으로 바로 연결됩니다.

### 게이트웨이 활성화 {#enabling-a-gateway}

1. 목록에서 게이트웨이를 찾습니다
2. **활성화됨** 스위치를 켭니다
3. 다음 페이지 로드 시 POS 결제에 게이트웨이가 표시됩니다

:::note 무료와 Pro
무료 버전에서는 기본 제공 **현금** 및 **카드** 게이트웨이만 편집할 수 있습니다. POS에서 설치된 다른 WooCommerce 게이트웨이를 활성화하려면 [WCPOS Pro](/getting-started/pro-license)가 필요합니다.
:::

### 게이트웨이 순서 변경 {#reordering-gateways}

게이트웨이를 드래그하여 POS 결제 화면의 표시 순서를 변경합니다. 계산원이 결제 모달을 열 때 미리 선택될 게이트웨이를 **기본값** 열에서 선택합니다.

### POS와 온라인 매장 {#pos-vs-online-store}

여기의 게이트웨이 설정은 WooCommerce 결제 설정과 **독립적**입니다. 게이트웨이는 다음과 같이 설정할 수 있습니다:

- **POS에서는 활성화, 온라인에서는 비활성화** — 웹 주문에는 적용되지 않는 현금 결제에 유용합니다
- **온라인에서는 활성화, POS에서는 비활성화** — 대면 판매에 적합하지 않은 PayPal 같은 게이트웨이에 유용합니다
- **둘 다 활성화** — 게이트웨이가 모든 곳에서 작동합니다

:::note
게이트웨이가 POS 결제 설정 목록에 표시되려면 먼저 `WP Admin > WooCommerce > 설정 > 결제` 에 설치되어 활성화되어 있어야 합니다. 게이트웨이가 누락된 경우 플러그인이 설치되어 있고 WooCommerce 에서 게이트웨이가 활성화되어 있는지 확인합니다.
:::

## 주문 상태 {#order-status}

주문 상태는 게이트웨이 표의 **주문 상태** 열에서 **게이트웨이별로** 설정됩니다 — 따라서 판매는 결제 방식에 따라 서로 다른 상태로 처리될 수 있습니다:

- **현금** 및 **카드**는 판매 시점에 결제가 수금되므로 기본값이 **완료됨**입니다.
- **BACS**(직접 은행 송금) 또는 **수표**처럼 나중에 입금되는 게이트웨이는 기본값이 **대기 중**입니다.

각 게이트웨이에 대해 원하는 WooCommerce 주문 상태를 선택합니다. (이전 버전에서는 전역 기본값 하나를 사용했으며, 업그레이드 시 해당 값이 각 게이트웨이로 마이그레이션되었습니다.)

## 초과 판매 방지 {#prevent-overselling}

**초과 판매 방지** 토글은 재고가 부족한 항목의 POS 판매를 중단합니다. 기본값은 **꺼짐**이며, 활성화하기 전까지 결제 동작은 이전과 완전히 동일합니다.

WooCommerce REST API는 주문을 생성할 때 재고를 검증하지 않기 때문에, 바쁜 계산대(또는 오래된 상품 목록)에서는 보유 수량보다 많이 판매될 수 있습니다. 토글을 켜면 WCPOS는 두 곳에서 재고를 확인합니다:

1. **계산대에서** — 계산원은 사용 가능한 재고를 초과해 항목을 장바구니에 추가하거나 수량을 늘릴 수 없습니다. POS는 실제로 사용 가능한 수량을 표시합니다. 예: *"Hoodie – Blue, M은(는) 3개만 사용 가능합니다"*.
2. **결제 시, 서버에서** — 결제가 완료되기 전에 주문 자체가 검증됩니다. 계산대의 로컬 데이터가 오래되었더라도 초과 판매가 발생할 주문은 거부되며, 어떤 항목이 얼마나 부족하고 몇 개를 사용할 수 있는지 계산원에게 정확히 표시됩니다. 이후 POS는 해당 항목의 재고를 새로 고쳐 정확한 수량으로 장바구니를 수정할 수 있도록 합니다.

열린 장바구니의 동기화가 차단되는 일은 없습니다 — 검증은 결제 시점에만 실행됩니다.

### 재고를 판단하는 방식 {#prevent-overselling-stock-rules}

| 상품 설정 | 토글이 켜져 있을 때의 동작 |
|---|---|
| **재고 관리 사용**(수량을 추적함) | 판매가 재고 수량으로 제한됩니다. 장바구니에 있는 동일 상품의 여러 줄은 같은 한도에 합산됩니다. |
| **변형이 자체 재고를 관리함** | 한도가 변형별로 적용됩니다. |
| **변형이 상위 상품의 재고를 사용함** | 해당 상품의 모든 변형이 상위 상품의 수량을 공유합니다. |
| **재고 관리 사용 안 함** | 상품의 재고 상태가 결정합니다. *품절*은 판매할 수 없고, *재고 있음*과 *백오더*는 판매할 수 있습니다. |

### 백오더 설정이 우선합니다 {#prevent-overselling-backorders}

**상품별 백오더 설정이 우선합니다** — 토글을 켜 둔 상태에서 특정 상품에 대해 초과 판매를 허용하는 방법입니다.

- **허용 안 함** — 재고가 소진되면 판매가 중단됩니다(토글이 적용하는 동작입니다).
- **허용** — 재고가 0 미만이 되어도 해당 상품은 항상 판매할 수 있습니다.
- **허용하되 고객에게 알림** — 해당 상품은 항상 판매할 수 있으며, 판매 수량이 사용 가능한 재고 아래로 내려가면 계산원에게 *"백오더로 처리됩니다"* 라는 안내가 표시됩니다.

### 초과 판매 방지와 "품절 상품 표시"의 차이 {#prevent-overselling-vs-display}

두 설정은 서로 다른 재고 보호 장치를 다루지만, 둘 다 품절 항목이 추가되는 것을 막을 수 있습니다:

- **초과 판매 방지**(이 페이지)는 항목을 추가하거나 변경할 때 사용 가능한 수량을 확인하고, 결제 시 재고를 다시 검증합니다.
- **품절 상품 표시**(POS 상품 패널의 디스플레이 설정)는 품절 상품과 변형을 어떻게 선택할 수 있는지 제어합니다. 켜면 품절 상품은 계속 표시되지만 장바구니에 추가할 수 없습니다. 끄면 숨겨지며, 품절 변형 옵션도 흐리게 표시되고 일치하는 바코드 스캔은 거부됩니다.

초과 판매 방지를 꺼도 이러한 상품 패널 규칙은 무시되지 않습니다. 품절 항목을 계속 표시하면서 초과 판매 방지로 수량 및 결제 보호 장치를 추가할 수 있습니다 — 계산원에게는 해당 항목이 *품절* 배지와 비활성화된 장바구니 추가 버튼과 함께 표시됩니다.

:::note
토글 변경 사항은 계산원이 다음에 로그인하거나 앱이 다시 검증할 때 열린 POS 세션에 반영됩니다 — 서버 측 검사는 즉시 적용됩니다.
:::
