WCPOS에서는 사이트 전체 WooCommerce 이메일 설정과 별도로 POS 주문에 대해 발송할 WooCommerce 알림 이메일을 유형별로 제어할 수 있습니다. 판매를 처리한 **캐셔**에게도 알림을 보낼 수 있습니다.

설정은 **결제** 화면에 있습니다. **WP Admin > POS > 설정 > 결제**로 이동하세요. 이메일 제어 항목은 주문 상태 및 결제 게이트웨이 섹션 위에 있습니다.

:::info POS 주문 이메일 안내
WooCommerce의 기본 이메일 트리거는 POS 주문에서 항상 정상적으로 작동하지 않습니다. POS는 WooCommerce가 인식하지 못하는 *POS - 열림* 및 *POS - 부분 결제* 같은 사용자 지정 상태를 사용하기 때문입니다. WCPOS는 주문이 이러한 상태에서 완료됨, 처리 중 또는 보류 중으로 전환될 때 새 주문 이메일을 직접 다시 실행합니다. 따라서 주문이 어떤 결제 과정을 거쳤든 안정적으로 알림을 받을 수 있습니다.
:::

## 세 가지 이메일 그룹 {#the-three-email-groups}

각 그룹 상단에는 **마스터 토글**이 있습니다. 토글을 켜면 아래에 체크박스 목록이 표시되어 각 이메일 유형을 개별적으로 활성화하거나 비활성화할 수 있습니다. 토글을 끄면 개별 이메일 체크박스 상태와 관계없이 해당 그룹의 이메일은 POS 주문에 대해 발송되지 않습니다.

### 관리자 이메일 {#admin-emails}

*‘POS 주문에 대한 WooCommerce 관리자 알림 이메일’* — **기본적으로 켜져 있습니다.**

**WooCommerce → 설정 → 이메일 → (이메일 유형) → 수신자**에 설정된 주소로 발송됩니다.

| 이메일 | 기본값 | 발송 시점 |
|---|---|---|
| **새 주문** | ✓ 선택됨 | POS 주문이 처리 중 / 완료됨 / 보류 중 상태로 변경될 때 |
| **취소된 주문** | ✓ 선택됨 | POS 주문이 취소될 때 |
| **실패한 주문** | ✓ 선택됨 | POS 주문이 실패할 때(결제 게이트웨이 오류 등) |

### 고객 이메일 {#customer-emails}

*‘POS 주문에 대한 WooCommerce 고객 알림 이메일’* — **기본적으로 켜져 있습니다.**

고객의 청구 이메일 주소로 발송됩니다. 고객이 연결된 주문에 대해서만 발송되며, 비회원 판매는 별도 알림 없이 건너뜁니다.

| 이메일 | 기본값 | 발송 시점 |
|---|---|---|
| **보류 중인 주문** | ✓ 선택됨 | POS 주문이 보류 중 상태로 변경될 때 |
| **주문 처리 중** | ✓ 선택됨 | POS 주문이 처리 중 상태로 변경될 때 |
| **주문 완료** | ✓ 선택됨 | POS 주문이 완료될 때 |
| **주문 환불** | ✓ 선택됨 | POS 주문이 전체 또는 부분 환불될 때 |
| **주문 실패** | ✓ 선택됨 | POS 주문이 실패할 때 |

### 캐셔 이메일 {#cashier-emails}

*‘POS 주문을 처리한 캐셔에게 새 주문 알림 전송’* — **기본적으로 꺼져 있습니다.**

| 이메일 | 기본값 | 발송 시점 |
|---|---|---|
| **새 주문** | ✓ 선택됨 *(마스터 토글이 켜져 있을 때)* | 해당 캐셔가 POS 주문을 완료할 때 |

WCPOS는 주문의 `_pos_user` 메타(계산대에 로그인한 WP 사용자)에서 캐셔를 식별하고 해당 계정의 이메일 주소를 가져옵니다. 캐셔 이메일이 관리자 이메일과 같으면, 예를 들어 점주가 관리자와 캐셔를 겸하는 매장에서는 WCPOS가 수신자의 **중복을 제거**하므로 같은 이메일을 두 번 받지 않습니다.

관리자 토글과 캐셔 토글은 **독립적으로** 작동합니다. 하나를 꺼도 다른 하나에는 영향을 주지 않습니다.

## 일반적인 사용 사례 {#common-scenarios}

<Accordion>
  <AccordionItem question="바쁜 날 받은편지함에 알림이 쌓이지 않게 하기">

매장에서 하루 50건 이상 판매하며 관리자가 매번 알림을 받을 필요가 없다면 **관리자 이메일 → 새 주문**을 끄세요. **취소된 주문**과 **실패한 주문**은 실제로 확인이 필요한 알림이므로 켜두세요.

매출을 파악할 때도 새 주문 이메일 수를 세는 것보다 [보고서](/1.x/reports) 화면이 더 적합합니다.

  </AccordionItem>

  <AccordionItem question="관리자 대신 근무 중인 캐셔에게만 알림 보내기">

**관리자 이메일** 마스터 토글을 끄고 **캐셔 이메일** 마스터 토글을 켜세요. 각 판매를 완료한 캐셔가 개인 계정의 이메일 주소로 새 주문 이메일을 받으며, 관리자 받은편지함에는 쌓이지 않습니다.

캐셔가 여러 명인 매장에서 점주가 모든 거래에 대해 알림을 받고 싶지 않을 때 유용합니다.

  </AccordionItem>

  <AccordionItem question="매장 내 판매의 고객 이메일 끄기">

관광객이 많은 매장, 시장 노점, 빠른 서비스를 제공하는 카페에서는 고객에게 이미 인쇄된 영수증을 제공하므로 이메일 영수증을 보내고 싶지 않을 수 있습니다. **고객 이메일** 마스터 토글을 끄면 POS 판매의 처리 중 / 완료됨 / 환불됨 이메일이 발송되지 않습니다.

온라인 주문의 고객용 이메일은 POS 경로가 아닌 표준 WooCommerce 경로로 처리되므로 영향을 받지 않습니다.

  </AccordionItem>

  <AccordionItem question="고객 이메일은 켜두되 ‘처리 중’ 이메일만 끄기">

POS 주문이 즉시 완료되면(현금 + 대면 카드 결제) 고객은 같은 순간에 *처리 중* 이메일*과* *완료됨* 이메일을 받습니다. 고객 이메일 목록에서 **주문 처리 중**의 체크를 해제하여 불필요한 이메일을 줄이세요.

  </AccordionItem>

  <AccordionItem question="v1.8.9 이전 버전에서 업그레이드했더니 기존의 ‘이메일 활성화’ 스위치가 사라졌어요">

이전 버전의 단일 켜기/끄기 스위치가 위의 세 그룹 구조로 대체되었습니다. WCPOS는 기존 설정을 자동으로 이전합니다. 이전에 이메일을 꺼두었다면 세 마스터 토글이 모두 꺼집니다. 켜두었다면 관리자와 고객 마스터 토글은 켜지고 캐셔 토글은 꺼집니다(새 기본값).

별도로 할 일은 없습니다. 업그레이드 후 결제 설정 페이지를 열면 설정이 자동으로 이전됩니다.

  </AccordionItem>
</Accordion>

## 개발자 훅 {#developer-hooks}

UI 외에 프로그래밍 방식으로 제어하려면 다음 WordPress 필터를 사용할 수 있습니다:

| 필터 | 용도 |
|---|---|
| `woocommerce_pos_admin_email_enabled` | 관리자 마스터 토글 재정의 |
| `woocommerce_pos_customer_email_enabled` | 고객 마스터 토글 재정의 |
| `woocommerce_pos_admin_emails` | 활성화된 관리자 이메일 목록 필터링 |
| `woocommerce_pos_customer_emails` | 활성화된 고객 이메일 목록 필터링 |

캐셔 알림은 WooCommerce의 기존 `woocommerce_email_recipient_new_order` 필터를 사용하므로, 수신자별 재정의(예: 참조 주소 추가)는 다른 WooCommerce 이메일과 동일하게 작동합니다.
