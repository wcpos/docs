WCPOS는 각 기기에 상품의 로컬 사본을 보관하므로 카탈로그를 즉시 탐색·검색할 수 있고 오프라인에서도 계속 작동합니다. 이 가이드에서는 상품이 기기에 저장되는 방식과 최신 상태로 유지되는 방식을 설명합니다.

:::info v1.10.0에서 변경됨
v1.10.0에는 새로운 동기화 엔진이 도입되었습니다. 사용 중인 POS가 v1.10.0 이전 버전이라면 아래 [v1.10.0에서 달라진 점](#what-changed-in-v1100)을 참조하세요.
:::

## 상품이 기기에 저장되는 방식 {#how-products-arrive}

- **카탈로그 시드가 백그라운드에서 실행됩니다.** POS는 처음 실행할 때부터 별도의 조작 없이 정해진 일정에 따라 카탈로그를 소량씩 다운로드합니다. 첫 상품이 다운로드되는 즉시 판매를 시작할 수 있으며, 전체 다운로드가 끝나기 전에도 결제할 수 있습니다.
- **지금 보고 있는 항목은 필요할 때 다운로드됩니다.** 검색하거나 카테고리로 필터링하거나 바코드를 스캔하면, 해당 상품이 아직 로컬에 없는 경우 직접 가져옵니다. 이제 검색 시 관련 없는 상품을 함께 가져오지 않고 요청한 상품만 가져옵니다.
- **업데이트는 변경 확인을 통해 전달됩니다.** 상품이 로컬에 저장된 후에는 POS가 변경 여부를 확인하기 위해 상품을 다시 다운로드하지 않습니다. 가벼운 변경 로그를 주기적으로 조회하고(기본 프리셋에서는 60초마다) 실제로 변경된 항목만 가져옵니다. 변경 사항이 없는 매장은 서버 부담이 거의 없는 ‘변경 없음’ 응답 하나만 반환합니다.

## 한 번에 얼마나 다운로드하나요? {#batch-size}

기본적으로 POS는 **한 번에 상품 50개**를 요청합니다. 이제 이 값은 고정값이 아니라 **매장 상태 → 성능**의 동기화 프리셋으로 설정되는 두 가지 항목 중 하나입니다:

| 프리셋 | 확인 간격 | 요청당 레코드 수 |
| --- | --- | --- |
| 절약 | 5분 | 25 |
| 균형 (기본값) | 60초 | 50 |
| 실시간 | 10초 | 75 |

한 번에 적은 양을 가져오는 이유는 서버를 보호하기 위해서입니다. 데이터가 많은 페이지를 생성하려면 서버 처리 시간이 필요하며, 공유 호스팅에서는 온라인 매장이 느려지거나 요청 속도 제한에 걸릴 수 있습니다. 사양이 낮은 호스팅에서는 절약을, 성능이 좋은 호스팅에서 여러 계산대를 운영하는 매장에서는 실시간을 선택하세요. 자세한 내용은 [매장 상태](/1.x/support/store-health#sync-presets)를 참조하세요.

## 다운로드 진행 상황 확인 {#checking-progress}

**매장 상태 → 데이터베이스**를 열면 컬렉션별로 기기와 서버의 레코드 수를 다운로드 비율 막대와 함께 확인할 수 있습니다. *서버 기준* 수치는 서버가 보고한 실제 총계입니다. POS가 아직 확인 중일 때는 해당 행에 추정값 대신 *확인 중…*이 표시됩니다.

상품 막대가 일부만 채워져 있다면 시드가 아직 완료되지 않았다는 뜻이며, 백그라운드에서 계속 채워집니다. 특정 상품이 보이지 않는다면 검색해 보세요. 해당 상품을 직접 가져옵니다.

:::tip
특정 컬렉션의 진행이 멈춘 것 같다면 [모든 로컬 데이터 초기화](/1.x/support/troubleshooting/clear-local-data)를 실행하기 전에 매장 상태 → 데이터베이스에서 해당 행의 **지우고 다시 다운로드**를 사용하세요.
:::

## v1.10.0에서 달라진 점 {#what-changed-in-v1100}

이전 버전은 *사용하는 과정에서 점진적으로* 카탈로그를 다운로드했습니다. 검색하거나 스크롤할 때마다 다음 상품 묶음을 가져오고, 5분마다 전체 폴링을 실행했습니다. 이 방식은 더 이상 사용하지 않습니다. v1.10.0에서는 다음과 같이 작동합니다:

- 정해진 일정에 따라 백그라운드 시드가 카탈로그를 채우므로 상품을 다운로드하기 위해 검색하거나 스크롤할 필요가 없습니다.
- 검색 시 임의의 다음 상품 묶음이 아니라 검색 조건에 맞는 상품을 가져옵니다.
- 5분마다 전체 폴링을 실행하는 대신, 선택한 프리셋의 간격(기본 60초)에 따라 조건부 요청으로 변경 사항을 확인합니다.
- **매장 상태 → 데이터베이스**에서 컬렉션별 다운로드 진행 상황을 확인할 수 있습니다.

개발자는 [동기화 엔진 작동 방식](/1.x/reference/sync-engine)에서 전체 동작 원리를 확인할 수 있습니다.

## 자주 묻는 질문 {#faq}

<Accordion>
  <AccordionItem question="상품을 다운로드하려면 별도로 해야 할 일이 있나요?">

  아니요. 카탈로그 시드가 백그라운드에서 상품을 자동으로 다운로드합니다. 검색하거나 필터링하면 아직 로컬에 없는 특정 상품을 즉시 가져옵니다. 다만 전체 다운로드를 완료하는 것은 일반적인 탐색이 아니라 백그라운드 시드입니다.

  </AccordionItem>

  <AccordionItem question="상품 변경 사항은 얼마나 빨리 POS에 반영되나요?">

  기본 균형 프리셋에서 POS는 60초마다 변경 사항을 확인합니다(여러 계산대가 동시에 서버에 요청하지 않도록 확인 시점에 약간의 무작위 간격을 둡니다). 변경된 상품만 가져옵니다. 여러 계산대에서 서로의 변경 사항을 더 빨리 확인해야 한다면 실시간 프리셋을 사용하세요.

  </AccordionItem>

  <AccordionItem question="POS에서 모든 상품이 보이지 않습니다">

  다음과 같은 원인이 있을 수 있습니다:

  - 백그라운드 시드가 아직 완료되지 않았을 수 있습니다. **매장 상태 → 데이터베이스**의 상품 행을 확인하세요.
  - POS는 기본적으로 품절 상품을 숨깁니다. 상품 표시 설정에서 변경할 수 있습니다.
  - WooCommerce REST API는 표준 상품 유형(단순, 변동, 그룹, 외부)만 지원합니다. 사용자 정의 상품 유형은 POS에 표시되지 않을 수 있습니다.

  </AccordionItem>
</Accordion>
