## 의미 {#what-this-means}

이 기기에 있는 레코드 사본이 매장의 레코드와 일치하지 않습니다. 입력한 내용에는 영향이 없습니다.

**매장 상태 → 데이터베이스**의 해당 목록에서 **지우고 다시 다운로드**를 사용하여 이 기기의 사본을 매장의 레코드로 교체하세요. 그전까지는 레코드에 최신 상태가 아닌 가격이나 재고가 표시될 수 있습니다. 먼저 전송 대기 중인 항목이 없는지 확인하세요. 문제 해결을 참고하세요.

## 데이터 상태 {#your-data}

판매나 미전송 변경 사항에는 영향이 없습니다. 이 기기의 레코드 사본을 교체할 때까지 최신 상태가 아닌 가격이나 재고가 표시될 수 있습니다. 이 문제가 계속되면 **로그** 탭에서 **디버그 정보 복사**를 사용하고 WCPOS 지원팀에 문의하세요.

## 문제 해결 {#troubleshoot}

1. 판매를 계속하세요. **매장 상태 → 데이터베이스**를 열면 상단에 레코드가 표시됩니다. 사본이 다른 레코드는 **"… 매장에서 다운로드할 수 없음"**, 매장에서 삭제된 레코드는 **"… 이 기기에서 제거해야 함"** 으로 표시됩니다.
2. 해당 상품을 판매하기 전에 진열대의 가격 및 재고와 비교하거나 매장 담당자에게 확인하세요. 담당자는 WP Admin의 정보와 비교할 수 있습니다.
3. 무엇이든 지우기 전에 **매장 상태 → 데이터베이스**에서 **전송 대기 중인 변경 사항**이 0이고 **"…개 변경 사항이 서버에 도달하지 못했습니다"** 또는 **"…개 변경 사항이 보류되었습니다"** 패널이 표시되지 않는지 확인하세요. 해당 변경 사항은 이 기기에만 있으므로 해당 목록을 지우면 손실될 수 있습니다. 수가 0이 될 때까지 기다리고, 나열된 변경 사항을 먼저 해결하세요([SYNC201](/error-codes/SYNC201), [SYNC221](/error-codes/SYNC221)). **주문**을 지우기 전에는 이 기기에서 열려 있는 모든 장바구니를 **서버에 저장**으로 저장하거나 판매를 완료하세요. 매장에 한 번도 저장하지 않은 장바구니는 이 기기에만 존재하며, 위의 어떤 확인 항목에도 집계되지 않으므로 **주문**을 지우면 삭제됩니다. 장바구니를 저장할 수 없으면 **주문** 행은 건너뛰고 지원팀에 문의하세요. 그런 다음 해당 레코드의 목록(예: **상품**)에서 **⋮** 메뉴를 열고 **지우고 다시 다운로드…** 를 선택하세요. 기기의 사본이 지워지고 매장의 레코드를 가져오며, 매장에서 삭제된 레코드는 제거됩니다. 다음 백그라운드 확인 때까지 해당 항목이 목록에 남아 있을 수 있으므로, 가격과 재고가 이제 일치하는지로 판단하세요. 이후 안내에 다른 목록의 레코드가 표시되면 해당 목록에 대해서도 먼저 확인 절차를 거친 후 이 단계를 반복하세요.
4. **사이트 관리자:** 다시 다운로드한 뒤에도 같은 레코드가 계속 나타나면, 보통 WooCommerce의 저장 훅을 거치지 않은 일괄 변경이 원인입니다. CSV 가져오기, 마이그레이션 플러그인, WP-CLI 또는 직접 실행한 SQL 등이 해당합니다. 계산대의 확인 결과를 정확하게 유지하려면 WooCommerce를 통해 수정하는 것이 좋습니다. 같은 차이가 계속 반복되면 WCPOS가 무결성 데이터를 자동으로 다시 구축합니다.
5. 다시 다운로드한 뒤에도 계산대에 잘못된 가격이나 재고가 계속 표시되면 **로그** 탭에서 **디버그 정보 복사**를 사용하고 지원팀에 문의하세요.
