## 오류의 의미 {#what-this-means}

호스트가 이 매장의 POS 기기에서 보내는 요청 빈도를 제한하고 있습니다.

앱이 이미 요청 간격을 늘리고 서버의 Retry-After 대기 시간을 따르고 있는데도 서버가 계속 429(요청이 너무 많음)로 응답합니다. 여러 POS 기기가 하나의 인터넷 연결을 사용하면 주소를 공유하므로, 출발지별 요청 빈도 제한은 이들을 요청량이 매우 많은 단일 클라이언트로 취급합니다. 동기화는 자동으로 계속되지만 제한이 상향될 때까지 지연됩니다.

## 데이터에 미치는 영향 {#your-data}

주문이나 상품 데이터에는 영향이 없습니다.

## 문제 해결 {#troubleshoot}

1. 매장 자체 트래픽에 대한 REST API 요청 빈도 제한을 상향하거나 면제해 달라고 호스팅 업체에 요청하세요. 매장에 고정 IP가 있다면 함께 알려 주세요.
2. 반복되는 오류 응답(429)을 차단 기준으로 집계하는 보안 서비스(예: Sucuri의 IDS)에서는 매장 API를 집계 대상에서 제외해야 할 수 있습니다.
3. 여러 POS 기기가 하나의 연결을 공유한다면 호스팅 업체에 그 사실을 알려 주세요. 여기서 하나의 IP는 사용자 한 명이 아니라 매장 전체에 해당합니다.
