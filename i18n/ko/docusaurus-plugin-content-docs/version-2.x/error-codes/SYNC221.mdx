## 오류의 의미 {#what-this-means}

이 기기의 변경 사항이 매장의 더 최근 수정 사항과 충돌했습니다. 손실된 데이터는 없습니다.

**매장 상태 → 데이터베이스**에 이 레코드의 보류된 변경 사항이 표시된다면, 이 기기의 버전을 유지하려면 **다시 전송**을 누르고 매장의 버전을 유지하려면 **서버 버전 사용**을 누르세요. 표시되지 않는다면 이미 해결되었으므로 별도 조치는 필요하지 않습니다.

## 데이터 상태 {#your-data}

손실된 데이터는 없습니다. 변경 사항이 보류되면 어느 쪽을 유지할지 선택할 때까지 매장은 자체 버전을, 이 기기는 변경 사항을 유지합니다. 해당 레코드에 추가로 적용한 수정도 그때까지 이 기기에서 대기합니다. 변경 사항이 보류된 동안 이 기기의 데이터를 삭제하지 마세요. 삭제하면 보류된 변경 사항이 사라집니다.

## 문제 해결 {#troubleshoot}

1. **매장 상태 → 데이터베이스**를 여세요. 보류된 변경 사항은 **"1개의 변경 사항이 보류되었습니다"**(또는 **"…개의 변경 사항이 보류되었습니다"**)로 시작하는 패널에 해당 레코드와 함께 표시됩니다.
2. 이 레코드에 더 이상 보류된 항목이 없다면 여기나 다른 탭에서 이미 해결된 것이므로 별도 조치는 필요하지 않습니다. WCPOS가 이 기기의 버전을 다시 전송하여 자체적으로 해결한 주문 충돌은 대신 [SYNC222](/error-codes/SYNC222)로 기록됩니다.
3. 변경 사항이 보류되어 있다면 **레코드 열기**가 표시될 경우 이를 눌러 이 기기의 버전을 확인하고, WP Admin의 같은 레코드와 비교하세요(사이트 관리자가 해야 할 수도 있습니다).
4. 이 기기의 버전을 유지하려면 **다시 전송**을 누르세요. 변경 사항을 다시 전송하여 이 기기에서 수정한 필드의 매장 값을 덮어씁니다. 매장의 버전을 유지하려면 **서버 버전 사용**(일부 행에는 **기기 변경 사항 폐기**로 표시됨)을 누르고 확인하세요. 이 기기의 변경 사항이 삭제됩니다. 해당 레코드에 추가로 적용한 수정은 선택할 때까지 대기합니다.
5. 같은 레코드에서 충돌이 자주 발생한다면 보통 두 사람이 같은 데이터를 동시에 수정하고 있다는 뜻입니다. 예를 들어 POS 단말기와 WP Admin에서 재고를 동시에 수정하는 경우입니다. 각 유형의 수정을 어디에서 할지 정하세요.
