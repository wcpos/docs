## 오류의 의미 {#what-this-means}

매장에서 전송받은 값을 거부했습니다.

매장에서 보낸 사유에 해당 값이 명시되어 있습니다. 값을 입력한 곳에서 수정한 뒤 다시 저장하세요. 보통 상품, 고객 또는 주문 같은 레코드의 값이지만, 매장에서 설정이나 로그인 요청을 거부했을 때도 이 코드가 나타날 수 있습니다. 이 경우에는 해당 화면에서 수정하세요.

## 데이터 상태 {#your-data}

이 기기의 데이터를 삭제하지 마세요. 매장에 아직 없는 변경 사항이 있을 수 있습니다. 기존 상품, 옵션, 고객 또는 쿠폰에 대한 수정이 거부되면 대개 자동으로 되돌려지고 대신 [SYNC202](/error-codes/SYNC202)로 기록됩니다. 이 코드가 표시되고 **매장 상태 → 데이터베이스**에 변경 사항이 있다면 자동 되돌리기가 수행되지 않은 것입니다. 다른 표시된 변경 사항과 동일하게 처리하세요. 설정이나 로그인 요청의 경우 저장할 내용이 남지 않습니다.

## 문제 해결 {#troubleshoot}

1. 로그 항목을 펼쳐 매장에서 보낸 사유와 엔드포인트를 확인하세요. 사유에는 해당 값이 명시되어 있고, 엔드포인트에는 레코드 요청인지 설정 또는 로그인 요청인지 나타납니다.
2. 값을 입력한 곳에서 수정한 뒤 다시 저장하세요. 허용 범위를 벗어난 값, 허용되지 않는 형식, 비어 있는 필수 옵션이 흔한 원인입니다. **매장 상태 → 데이터베이스**에 변경 사항이 표시되지 않는다면 매장의 버전으로 복원된 것이므로 올바른 값으로 다시 수정하세요. 수정한 뒤에도 **매장 상태 → 데이터베이스**의 **"…개의 변경 사항이 서버에 전송되지 않았습니다"** 아래에 표시된다면 해당 행의 **다시 전송**을 누르세요.
3. 대신 레코드가 **"…개의 변경 사항이 보류되었습니다"** 아래에 *"매장에서 최신 버전을 요구했습니다"*와 함께 표시된다면 값에는 문제가 없습니다. [SYNC221](/error-codes/SYNC221)의 설명에 따라 **다시 전송** 또는 **기기 변경 사항 폐기** 중에서 선택하세요.
4. 설정이나 로그인 요청이었다면 값을 입력한 화면에서 수정한 뒤 다시 저장하세요. **사이트 관리자:** POS 로그에 세부 정보가 없다면 브라우저 개발자 도구(Network 탭) 또는 데스크톱 앱의 **고급 → 개발자 도구 전환**에서 매장의 응답을 확인할 수 있습니다.
5. **사이트 관리자:** 명시된 값이 POS에서 올바르게 보인다면 WP Admin의 같은 레코드와 비교하세요. 매장에 플러그인이 추가한 유효성 검사로 인해 POS에서는 정상으로 판단하는 값이 거부될 수 있습니다.
