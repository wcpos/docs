## 오류의 의미 {#what-this-means}

매장에서 이 변경 사항을 거부하여 매장에 반영되지 않았습니다.

매장에서 보낸 사유를 읽어 보세요. **매장 상태 → 데이터베이스**에 변경 사항이 표시된다면 레코드를 수정하고 **다시 전송**을 누르거나 **폐기**하세요. 표시되지 않는다면 매장의 버전으로 복원된 것입니다. 여전히 필요한 변경이라면 다시 수정하세요([SYNC202](/error-codes/SYNC202) 참고). 거부된 변경 사항은 자동으로 재시도되지 않습니다.

## 데이터 상태 {#your-data}

이 기기의 데이터를 삭제하지 마세요. 매장에 아직 없는 변경 사항이 있을 수 있습니다. **매장 상태 → 데이터베이스**에 표시된 거부된 변경 사항은 다시 전송하거나 폐기할 때까지 남아 있습니다. 기존 상품, 옵션, 고객 또는 쿠폰에 대한 수정이 거부되면 대개 자동으로 되돌려지고 대신 [SYNC202](/error-codes/SYNC202)로 기록됩니다. 이 코드가 표시되고 **매장 상태 → 데이터베이스**에 변경 사항이 있다면 자동 되돌리기가 수행되지 않은 것입니다. 아래 안내에 따라 다른 표시된 변경 사항과 동일하게 처리하세요. 문제가 계속되면 **로그** 탭에서 **디버그 정보 복사**를 사용하여 WCPOS 지원팀에 문의하세요.

## 문제 해결 {#troubleshoot}

1. 매장에서 보낸 사유를 읽어 보세요. 로그 항목과 **매장 상태 → 데이터베이스**의 해당 변경 사항 행에 표시됩니다.
2. **매장 상태 → 데이터베이스**를 여세요. 변경 사항이 표시되지 않는다면 이 기기에서 이미 매장의 버전으로 복원되었으며 전송할 내용이 없습니다. [SYNC202](/error-codes/SYNC202)를 참고하세요. 사유에 명시된 문제를 해결한 뒤, 여전히 필요한 변경이라면 다시 수정하세요.
3. 주문, 이 기기에서 생성한 레코드 또는 자동 되돌리기가 수행되지 않은 카탈로그 수정 등 변경 사항이 표시된다면, 거부된 변경 사항은 **"…개의 변경 사항이 서버에 전송되지 않았습니다"** 아래에 있으며 해당 행에 매장에서 보낸 사유가 표시됩니다. 변경 사항이 목록에 남아 있는 상태에서 주문의 필드 등 레코드 자체의 문제를 사유에 따라 수정하세요.
4. **매장 상태 → 데이터베이스**로 돌아가 해당 행의 **다시 전송**을 누르세요. 현재 기기에 있는 내용을 바탕으로 변경 사항을 다시 구성하여 전송합니다.
5. 변경 사항이 더 이상 필요 없다면 대신 **폐기**를 누르세요. 매장의 버전이 유지됩니다. 먼저 확인 안내를 읽어 보세요. 매장에 한 번도 저장되지 않은 레코드를 폐기하면 이 기기에서 해당 레코드가 삭제됩니다.
6. **사이트 관리자:** 사용자가 해당 변경을 할 수 없다는 사유라면 해당 역할에 그 작업의 권한이 없는 것입니다. [AUTH201](/error-codes/AUTH201)을 참고하세요. 사유에 POS에 표시되지 않는 필드가 언급된다면 WP Admin에서 같은 레코드를 여세요. 다른 플러그인이 POS에서 볼 수 없는 유효성 검사를 추가했을 수 있습니다. 여전히 거부되면 **로그** 탭에서 **디버그 정보 복사**를 사용하여 지원팀에 문의하세요.
