## 오류의 의미 {#what-this-means}

이 매장이 보고한 식별 정보가 기기에 이미 저장된 매장과 같습니다.

각 매장에는 WCPOS 플러그인이 한 번 생성하는 식별 정보가 있습니다. 스테이징 사이트를 만드는 등의 이유로 사이트를 복사하면 사본에도 원본의 식별 정보가 유지됩니다. 따라서 앱이 두 사이트를 구별할 수 없으며, 두 번째 매장을 첫 번째 매장과 혼동하지 않도록 두 번째 매장의 저장을 거부합니다.

두 사이트 중 하나는 다른 사이트의 사본입니다. 이 충돌만으로는 어느 쪽이 사본인지 알 수 없습니다. 사본을 먼저 연결했다면 방금 연결하려던 매장이 원본입니다. 사이트 관리자는 어느 쪽이 복사된 사이트인지 알고 있으며, 새 식별 정보가 필요한 것은 바로 그 사이트입니다.

## 데이터에 미치는 영향 {#your-data}

저장이 거부된 것만으로는 아무것도 변경되지 않습니다. 저장된 매장은 그대로 유지되었고 새 매장은 저장되지 않았습니다.

아래의 두 번째 해결 방법처럼 저장된 매장을 삭제하는 경우는 다릅니다. 해당 매장에서 동기화를 기다리는 판매 내역은 기기에 남지만 매장을 다시 추가해도 자동으로 불러오지 않습니다. 삭제하기 전에 저장된 매장에 동기화할 항목이 남아 있지 않은지 확인하세요. 남아 있다면 먼저 지원팀에 문의하세요.

## 문제 해결 {#troubleshoot}

**복사된 사이트에서** — 해당 WordPress 사이트 관리자 안내:

1. 두 사이트 중 어느 쪽이 사본인지 확인하세요(일반적으로 스테이징 또는 테스트 사이트입니다).
2. 사본에서 WP Admin → 플러그인으로 이동하여 WCPOS를 최신 버전으로 업데이트하세요. 1.10.21부터는 복사된 사이트의 새 주소에서 플러그인이 처음 실행될 때 고유한 식별 정보를 부여합니다. 원본은 주소가 바뀌지 않았으므로 원본을 업데이트해도 이 문제는 해결되지 않습니다.
3. 계산대에서 다시 연결하세요.

**계산대에서** — 아직 사본을 업데이트할 수 없는 경우:

1. 메시지에 표시된 저장된 매장의 모든 판매 내역이 동기화되었는지 확인하세요. 대기 중인 판매 내역이 있다면 먼저 동기화하거나, 계속하기 전에 지원팀에 문의하세요.
2. 연결 화면에서 해당 저장된 매장을 삭제하세요.
3. 원하는 매장의 주소를 사용하여 연결하세요.

사본에 고유한 식별 정보가 부여될 때까지는 둘 중 하나만 연결해 둘 수 있습니다.

**두 주소가 같은 매장을 가리킨다면**(예: 로컬 네트워크 주소와 공개 도메인) 저장된 항목을 삭제하고 앞으로 이 계산대에서 사용할 주소로 다시 연결하세요. 이 경우에도 삭제하기 전에 동기화되지 않은 판매 내역이 있는지 확인해야 합니다.
