## 이 오류의 의미 {#what-this-means}

이 계정에는 해당 작업을 수행할 권한이 없습니다.

손실된 데이터는 없습니다. 매장 관리자에게 사용자 역할에 해당 작업 권한을 부여하도록 요청한 다음 다시 시도하세요.

## 데이터 {#your-data}

손실된 데이터는 없으며, 주문이나 상품 데이터에는 영향이 없습니다.

## 문제 해결 {#troubleshoot}

1. **계산대에서:** 거부되었을 때 하던 작업(상품, 고객 또는 주문 수정 등)과 로그인한 계정을 기록하세요. 동기화 중에 자동으로 발생했다면 **매장 상태 → 로그**의 항목을 전달하면 됩니다. 거부된 요청이 기록되어 있습니다. 작업 내용과 계정 정보를 관리자에게 전달하세요. 거부된 작업이 판매 과정에 포함되지 않았다면 그동안 판매를 계속해도 됩니다.
2. **사이트 관리자:** 먼저 이 계정에 해당 작업을 허용해야 하는지 판단하세요. 허용할 필요가 없다면 의도대로 거부된 것이므로 역할은 그대로 두고 권한이 있는 계정으로 작업하도록 하세요. 허용해야 한다면 **WP Admin > POS > 설정 > 접근**으로 이동하여 계정의 역할을 선택하세요. **캐셔가 할 수 있는 작업**(제목에 해당 역할 이름이 표시됨) 아래에서 **POS 사용**, **상품 생성 및 편집**, **주문 관리**, **고객 관리** 등 거부된 작업에 해당하는 항목을 선택하세요. 대시와 함께 **7개 중 3개** 같은 배지가 표시되면 해당 작업의 권한이 일부만 부여된 것입니다. 선택하면 나머지 권한도 부여됩니다. **기본값 복원**은 역할의 권한을 새로 설치했을 때의 상태로 되돌립니다. WCPOS는 사용자 지정 역할에 기본적으로 POS 접근 권한을 부여하지 않으므로 사용자 지정 역할에서 이 기능을 사용하면 오히려 POS 접근 권한이 제거됩니다.
3. **사이트 관리자:** 계정으로 로그인할 수 있지만 상품, 고객, 주문 관련 요청이 모두 거부된다면 **역할이 둘 이상**인지 확인하세요. Members 같은 역할 편집 플러그인은 어느 한 역할에 설정된 *거부*를 계정 전체에 적용합니다. 따라서 고객 역할도 가진 관리자는 고객 역할에서 거부한 모든 권한을 잃게 됩니다. 추가 역할을 제거하거나 *거부* 표시를 해제하세요. [역할이 둘 이상인 사용자](/settings/wp-admin/access#more-than-one-role)를 참조하세요.
4. **다시 계산대에서:** 새 권한이 적용되도록 로그아웃한 다음 다시 로그인하고, 거부된 작업을 다시 시도하세요.
