각 계산대는 판매, 동기화, 설정 변경, 오류 등 수행한 작업을 로그로 남깁니다. 문제가 발생하면 로그에서 무슨 일이 있었는지, 판매에 어떤 영향이 있는지, 다음에 무엇을 해야 하는지 확인할 수 있습니다. 매장은 WordPress 측 문제를 기록하는 별도의 로그를 서버에 보관하며, WP Admin에서 확인할 수 있습니다.

지금 오류가 발생했나요? [항목을 열어](#open) 읽거나 [지원팀에 로그를 보내세요](#for-support).

## 계산대에 새 오류가 있을 때 {#unread-badge}

메뉴 하단의 **매장 상태**에 표시되는 빨간 숫자는 마지막으로 **로그**를 연 이후 기록된 오류 수입니다. 99를 넘으면 **99+** 로 표시됩니다.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[44, 10]]} maxWidth={316} alt="메뉴 하단: 설정 위에 있는 매장 상태 아이콘에 새 오류를 나타내는 빨간 숫자 33이 표시된 모습">

1. **매장 상태** — 빨간 숫자는 경고를 제외한 오류 수만 나타냅니다. 휴대폰에서는 메뉴를 열어 확인하세요.

</JourneyShot>

**매장 상태**를 연 다음 **로그**를 열면 숫자가 사라집니다. **데이터베이스**나 **성능**을 열어도 사라지지 않습니다. 각 계산대는 로그인한 매장과 캐셔별로 오류 수를 따로 관리하며, 앱을 닫아도 초기화되지 않습니다.

## 로그 읽기 {#read}

각 항목은 계산대에서 수행한 작업 하나를 나타내며, 최신 항목부터 표시됩니다. 항목은 최대 30일 동안 보관됩니다.

로그는 이 계산대의 작업 기록이며, 판매 기록은 아닙니다. 결제에 관한 문의라면 **WooCommerce → 주문**에서 해당 주문을 먼저 확인하세요. 각 결제의 간략한 이력이 기록되어 있습니다. 로그에서는 그 전후로 이 계산대에서 어떤 일이 있었는지 확인할 수 있습니다.

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[44, 0], [52, 0], [0, -26], [46, 0], [44, 22], [53, 0], [-36, 0], [41, 0], [-36, 0]]} alt="매장 상태의 로그 탭: 오늘의 수치, 디버그 정보 복사, 검색 필드, 필터 버튼과 시간, 수준, 이벤트, 소요 시간, 상태가 표시된 항목 목록">

1. **매장 상태** — 로그가 있는 곳입니다.
2. **로그** — 세 번째 탭입니다. 목록 위의 수치에 대해서는 [매장 상태](store-health.mdx#logs)를 참고하세요.
3. **오류** — 오류만 표시합니다. [항목 찾기](#find)를 참고하세요.
4. **시간** — 오늘 항목은 시간만, 이전 항목은 날짜와 시간을 표시합니다.
5. **수준** — **오류**, **경고**, **작업**(사람이 수행한 작업), **동기화**, **정보** 또는 **디버그**(**상세 진단**이 켜져 있을 때만)를 표시합니다.
6. **이벤트** — 발생한 일을 표시하며, 그 아래에 앱의 해당 영역과 레코드 이름이 있으면 함께 표시합니다. **×2**는 약 한 분 이내에 같은 일이 두 번 발생했다는 뜻입니다.
7. **소요 시간** — 작업에 걸린 시간입니다.
8. **상태** — 오류나 경고에는 오류 코드, 성공한 작업에는 **✓ 정상**, 그 외에는 **—** 를 표시합니다.
9. **상태 표시줄** — **변경 사항 확인 중**이라는 문구와 함께 이 계산대가 마지막으로 매장을 확인한 시점과 다음 확인 시점을 표시합니다. 첫 확인이 끝나기 전까지는 **첫 확인 대기 중…** 으로 표시됩니다.

</JourneyShot>

하나의 작업에 속하는 인접 항목에는 왼쪽에 같은 색의 테두리가 표시됩니다. 대부분의 항목은 기록 당시의 언어와 관계없이 현재 계산대에서 사용하는 언어로 표시됩니다.

## 항목 찾기 {#find}

- **로그 검색** — **SYNC131** 같은 오류 코드나 오류에 포함된 단어를 입력하세요.
- **전체**, **작업**, **오류**, **동기화** — **작업**은 사람이 수행한 작업이고, **동기화**는 계산대와 매장 간의 통신입니다.
- **오늘의 이벤트**, **오늘의 오류**, **처리가 막힌 레코드** — **오늘의 이벤트**를 누르면 **전체**, **오늘의 오류**를 누르면 **오류**, **처리가 막힌 레코드**를 누르면 **동기화**가 표시됩니다.
- **수준** — 항목에서 **오류** 같은 수준을 누르면 해당 수준만 표시됩니다. 다시 누르거나 추가된 버튼의 닫기 표시를 누르면 전체가 표시됩니다.

목록 하단의 **…개 중 …개 표시**는 조건에 맞는 항목 중 불러온 항목 수를 나타냅니다. 아래로 스크롤하면 더 불러옵니다.

## 항목 열기 {#open}

**매장 상태 → 로그**를 열고 **오류**를 누르세요. 문제가 발생한 시간에 해당하는 항목을 찾거나 **로그 검색**에 오류 코드를 입력하세요. 항목을 누르면 해당 행 아래에서 내용을 읽을 수 있고, 다시 누르면 닫힙니다.

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[50, 0], [64, -10], [-54, -97], [131, 0], [101, 0], [-33, 0]]} alt="오류 필터가 켜진 상태에서 AUTH201 항목을 행 아래에 펼친 모습: 서버의 응답, 조치 방법, 레코드 열기, 도움말 링크, 복사 버튼이 있는 이벤트 코드, 레코드, 작업 및 요청">

1. **오류** — 현재 켜진 필터입니다.
2. **항목** — **상태**에 표시된 **AUTH201**이 오류 코드입니다.
3. **발생한 일과 조치 방법** — 매장의 응답이 있으면 이를 표시하고, 다음 줄에 조치 방법을 안내합니다. 중요한 경우 **결제가 완료되었습니다 — 다시 청구하지 마세요.** 또는 **이 기기의 데이터를 삭제하지 마세요** 같은 경고가 먼저 표시됩니다.
4. **도움말 — AUTH201** — 이 문서에서 해당 코드의 페이지를 엽니다. [오류 코드](../error-codes/index.mdx)를 참고하세요.
5. **레코드 열기** — 해당 항목과 관련된 주문, 상품 또는 고객을 엽니다. 이 계산대에 해당 레코드가 있고, 매장에서 WCPOS Pro를 사용하며, 편집 권한이 있어야 합니다.
6. **복사** — 지원팀에 보낼 항목 전체를 복사합니다. 옆에 있는 **이벤트 코드**는 계산대가 수행하던 작업을 나타내며, 모든 언어에서 동일합니다.

</JourneyShot>

처리가 막히거나 거부된 변경 사항에는 **매장 상태 → 데이터베이스로 이동**이 표시되며, 그곳에서 사용자의 선택을 기다립니다. [조치가 필요할 때](store-health.mdx#needs-attention)를 참고하세요. **사이트 관리자에게 서버 로그 확인을 요청하세요**는 매장 자체 로그에 원인이 기록되어 있다는 뜻입니다. [WP Admin의 매장 로그](#wp-admin-logs)를 참고하세요.

<details>
<summary>항목의 추가 세부 정보</summary>

그 아래의 **레코드**, **작업**, **요청**, **세부 정보**는 항목이 무엇에 관한 것인지 알려줍니다. 다른 항목에는 **필드**, **시도 횟수** 또는 **매장에서 제공한 사유**가 표시될 수 있습니다. 추가 정보가 없으면 **이 항목에 대한 추가 세부 정보가 없습니다.** 라고 표시됩니다.

</details>

:::warning 삭제하기 전에 경고를 읽으세요
**이 기기의 데이터를 삭제하지 마세요**는 아직 매장에 전달되지 않은 판매나 변경 사항이 계산대에 있다는 뜻입니다. 계산대 데이터를 삭제하면 해당 내용이 사라집니다. [모든 로컬 데이터 삭제](troubleshooting/clear-local-data.mdx)를 참고하세요.
:::

## 지원팀에 로그 보내기 {#for-support}

1. **매장 상태 → 로그**를 열고 **오류**를 누르세요.
2. 문제가 발생했을 때의 항목을 여세요. **이벤트 코드**가 있으면 옆의 **복사**(휴대폰 및 태블릿 앱에서는 **공유**)를 누르고 메시지에 붙여넣으세요. 없으면 오류 코드와 시간을 보내세요.
3. **디버그 정보 복사**(휴대폰 및 태블릿 앱에서는 **디버그 정보 공유**)를 누르고 이 내용도 붙여넣으세요.

   <details>
   <summary>보고서에 포함된 내용</summary>

   앱, WordPress, WooCommerce 및 WCPOS 버전, 매장 이름, 연결 상태, 오늘의 수치, 처리가 막힌 레코드 최대 열 개와 최근 오류 열 개가 포함됩니다.

   </details>

4. 붙여넣은 내용을 확인하세요. 항목의 **복사** 기능에는 캐셔 이름이 있으면 포함되며, 오류 메시지에는 레코드 이름이 포함될 수 있습니다. 그런 다음 두 내용을 [Discord](https://wcpos.com/discord)의 지원팀에 보내거나 support@wcpos.com으로 이메일을 보내세요. [지원](index.mdx#where-to-ask)을 참고하세요.

:::warning 고객에게 다시 청구하지 마세요
지원팀에 보여 줄 문제를 재현하기 위해 결제를 다시 받는 일은 절대 하지 마세요.
:::

5. 지원팀에서 문제를 재현해 달라고 요청하면 먼저 **상세 진단**을 켜고, 문제를 다시 재현한 다음 새 보고서를 보내세요.

<JourneyShot manifest={manifest} device="phone" step={4} offsets={[[-28, 0], [107, 0], [15, -22], [164, 0], [115, -20], [-32, 0]]} maxWidth={390} alt="휴대폰에서 오류 필터를 켠 로그 탭: 오늘의 수치, 디버그 정보 복사, 검색 필드, 필터 버튼, 상세 진단, 이벤트 코드 옆에 복사 버튼이 있는 펼쳐진 AUTH201 항목">

1. **디버그 정보 복사** — 지원팀에 보낼 이 계산대의 보고서입니다. 휴대폰 및 태블릿 앱에서는 **디버그 정보 공유**입니다.
2. **로그 검색** — 요청받은 항목을 찾으세요.
3. **오류** — 켜져 있어 오류만 표시됩니다.
4. **상세 진단: 꺼짐** — 누르면 더 자세한 내용을 기록합니다. 24시간 후 자동으로 꺼집니다.
5. **항목** — 휴대폰에서는 위에 시간과 수준이 표시되고, 이어서 이벤트와 그 아래에 영역, 레코드 또는 소요 시간이 표시됩니다. 눌러서 여세요.
6. **복사** — 지원팀에 보낼 메시지에 넣을 항목 전체를 복사합니다.

</JourneyShot>

두 보고서는 계산대의 사용 언어와 관계없이 영어로 작성됩니다.

## WP Admin의 매장 로그 {#wp-admin-logs}

플러그인은 POS의 요청, 동기화, 결제, 인쇄, 계산대에 관한 자체 로그를 서버에 보관합니다. WP Admin에서 POS 설정을 열 수 있는 사람은 누구나 읽을 수 있습니다. **POS → 설정**으로 이동하여 **도구** 아래의 **로그**를 선택하세요.

**경고** 필터를 켠 모습입니다:

<JourneyShot manifest={manifest} device="desktop" step={5} offsets={[[70, 0], [33, 36], [60, 0], [650, 0], [690, 0], [200, 0]]} alt="WP Admin의 POS 설정에서 연 로그: 메뉴의 로그 옆에 있는 빨간 숫자 1과 주황색 숫자 426, 치명적 오류 감지 알림, 경고가 선택된 전체·오류·경고 필터, 출처 목록, 오늘과 어제 아래의 경고">

1. **로그** — **도구** 아래에 있습니다. 빨간 숫자는 새 오류 수, 주황색 숫자는 새 경고 수입니다.
2. **경고** — 현재 켜진 수준 필터입니다. 옆에는 **전체**와 **오류**가 있습니다.
3. **출처** — 확장 프로그램이 자체 로그를 작성할 때 어느 부분에서 항목을 작성했는지 나타냅니다.
4. **오늘** — 항목을 날짜별로 묶어 표시합니다.
5. **항목** — 클릭하여 여세요.
6. **WooCommerce 로그에서 보기** — WooCommerce 자체 로그를 엽니다. WordPress에 치명적인 PHP 오류가 기록되면 이 알림이 표시됩니다.

</JourneyShot>

<details>
<summary>사이트 관리자용: WP Admin의 로그</summary>

- 설정 메뉴의 **로그**에 있는 **빨간 숫자와 주황색 숫자**는 마지막으로 로그를 연 이후의 오류와 경고 수를 나타냅니다. 사용자마다 따로 집계되며, **로그**를 열면 0으로 초기화됩니다.
- **전체**, **오류**, **경고** — 수준별로 필터링합니다. 확장 프로그램이 자체 로그를 작성하면 **출처** 목록이 나타납니다.
- **날짜별 항목** — **오늘**, **어제** 또는 날짜 아래에 페이지당 50개씩 표시되며, **이전**과 **다음** 버튼이 있습니다.
- **항목을 클릭**하여 여세요. 수준, 출처, 정확한 시각, 메시지와 관련 정보, **복사** 버튼이 표시됩니다.

이 로그는 WooCommerce 자체 로그와 함께 저장되므로 항목 보관 기간은 WooCommerce에서 결정합니다. 이 페이지에서는 로그를 삭제하거나 다운로드할 수 없습니다.

WordPress에 치명적인 PHP 오류가 기록되면 상단에 **치명적 오류 감지 — WooCommerce 로그에서 보기**가 표시됩니다. 링크를 누르면 새 탭에서 **WooCommerce → 상태 → 로그**가 열립니다. 이런 오류로 POS가 매장에 연결하지 못할 수 있으니 웹사이트 운영자에게 보여 주세요.

</details>

## 문제가 발생한 경우 {#goes-wrong}

**빨간 숫자가 다시 나타납니다.** 마지막으로 확인한 이후 새 오류가 기록되었습니다. **로그**를 열고 **오류**를 눌러 최신 항목을 읽으세요.

**"로그를 찾을 수 없습니다".** 검색어나 필터에 맞는 항목이 없습니다. **전체**를 누르고 검색어를 지우세요.

**"마지막 확인이 완료되지 않았습니다 — 재시도 중".** 계산대가 마지막 확인 때 매장에 연결하지 못했습니다. 자동으로 다시 시도합니다. 변경 사항이 쌓이면 [매장 상태](store-health.mdx#waiting-to-send)를 참고하세요.

**여기와 데이터베이스에 표시되는 처리가 막힌 레코드 수가 다릅니다.** **매장 상태 → 데이터베이스**를 열어 조치가 필요한 내용을 확인하세요. 여기의 **처리가 막힌 레코드**는 로그에서 확인된 수이며, 데이터베이스에는 매장에서 거부하거나 보류한 변경 사항도 표시됩니다. [조치가 필요할 때](store-health.mdx#needs-attention)를 참고하세요.

**계산대가 느립니다.** **소요 시간**은 각 작업에 걸린 시간을 나타냅니다. 지난 24시간 전체에 대해서는 [성능](store-health.mdx#performance)과 [서버 성능](performance/server.mdx)을 참고하세요.
