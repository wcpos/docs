## 플러그인 충돌의 징후 {#signs-of-plugin-conflicts}

플러그인을 추가하거나 업데이트한 뒤 다음과 같은 현상이 나타나면 플러그인 충돌일 수 있습니다.

- **로그인 창에 오류나 빈 페이지가 표시됩니다.**
- **앱에 "이 사이트의 WordPress REST API를 사용하려면 인증이 필요합니다"라는 메시지가 표시되거나**, 로그인한 사용자만 REST API를 사용할 수 있다는 다른 플러그인의 메시지가 표시됩니다.
- **사이트에 "이 웹사이트에 치명적인 오류가 있습니다"라는 메시지가 표시됩니다.** POS 또는 WP Admin에서 나타날 수 있습니다.
- **상품, 주문 또는 고객 데이터 다운로드가 중단되거나**, 판매 내역이 매장에 저장되지 않습니다.
- **레거시 탭에서 결제 게이트웨이의 결제 페이지가 깨져 보이거나**, 버튼을 눌러도 반응이 없습니다.
- **모든 작업이 느려지거나**, 요청 시간이 초과됩니다. 결제 속도 저하는 별도 페이지인 [결제 성능](../performance/checkout.mdx)에서 다룹니다.

플러그인 업데이트 후 WP Admin에서 **POS** 메뉴가 사라졌다면 [플러그인 업데이트 후 POS가 사라짐](../../getting-started/upgrading-to-2.mdx#pos-gone)을 참고하세요.

## 시작하기 전에: 스테이징 사이트 사용하기 {#before-you-start-use-a-staging-site}

:::warning 운영 중인 사이트에서 문제를 진단하지 마세요
POS가 사용하는 사이트에서 플러그인을 비활성화하면 판매가 중단되거나 온라인 쇼핑몰이 변경될 수 있습니다. 스테이징 사이트에서 진행하세요.
:::

### 스테이징 사이트란? {#what-is-a-staging-site}

스테이징 사이트는 고객이나 POS에 영향을 주지 않고 변경 사항을 테스트할 수 있는 웹사이트 복사본입니다. 대부분의 호스팅 업체에서는 호스팅 대시보드에서 몇 번의 클릭만으로 만들 수 있습니다.

### 호스팅 업체에서 스테이징을 제공하지 않는 경우 {#if-your-host-doesnt-offer-staging}

호스팅 업체에 사이트 복사 방법을 문의하세요. 방법을 제공하지 않는다면 스테이징을 지원하는 업체로 옮기는 것도 고려해 보세요. 이번 문제뿐 아니라 플러그인, 테마, WordPress, WooCommerce를 업데이트할 때마다 스테이징이 필요합니다. WP Engine, SiteGround, Kinsta, Cloudways는 모두 이 기능을 제공합니다.

## 1단계: 치명적인 오류 확인하기 {#step-1-check-for-fatal-errors}

프로그램이 중단되면 대개 오류에 원인 플러그인의 이름이 표시됩니다. 먼저 다음을 확인하세요.

1. **POS 로그.** 서랍 메뉴에서 **매장 상태**를 열고 **로그**, **오류**를 차례로 선택하세요. [로그](../logs.mdx)를 참고하세요.
2. **WooCommerce 치명적인 오류 로그.** [치명적인 오류](./critical-error.mdx)의 안내에 따라 WP Admin에서 찾아보세요.
3. **파일 경로를 확인하세요.** 다음과 같은 경로에 `wp-content/plugins/<plugin-name>/…` 플러그인의 이름이 표시됩니다.

오류에 WooCommerce나 WCPOS가 아닌 다른 플러그인의 이름이 표시되면 스테이징 사이트에서 해당 플러그인을 비활성화하고 다시 시도하세요. 플러그인 이름을 찾을 수 없다면 2단계로 진행하세요.

## 2단계: 플러그인을 비활성화한 뒤 하나씩 다시 활성화하기 {#step-2-the-plugin-elimination-method}

치명적인 오류가 없거나 속도 저하가 문제일 때 이 방법을 사용하세요.

### 2.1 발생하는 문제 기록하기 {#21-create-a-baseline}

1. **스테이징 사이트에서 POS를 여세요.** 웹 브라우저에서는 스테이징 주소의 `/pos`로 이동하세요. 앱에서는 스테이징 주소를 다른 매장으로 연결하고([연결](../../getting-started/connect.mdx) 참고), 계속하기 전에 **내 사이트**에서 주소를 확인하세요.
2. **문제가 발생하는 작업을 실행하고**, 표시되는 메시지와 화면, 소요 시간을 정확히 기록하세요.
3. **속도 저하가 문제라면**, 나중에 비교할 수 있도록 [로그](../logs.mdx)의 시간을 기록하세요.

### 2.2 POS를 제외한 모든 플러그인 비활성화하기 {#22-disable-all-plugins-except-essential-ones}

**다음 플러그인은 활성 상태로 유지하세요:**
- WooCommerce
- WCPOS
- WCPOS Pro(사용 중인 경우)
- 결제 게이트웨이(해당 결제 페이지에 문제가 있는 경우)

**나머지는 모두 비활성화하세요:**
1. `WP Admin > 플러그인`으로 이동하세요.
2. 나머지 플러그인을 모두 선택하세요.
3. **일괄 작업**에서 **비활성화**를 선택하세요.
4. **적용**을 클릭하세요.

무료 플러그인을 사용하는 매장의 **플러그인** 목록 하단입니다. 아직 아무 항목도 선택하지 않은 상태입니다.

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[59, 52], [59, 52], [59, 52], [105, 0], [78, 0]]} alt="WP Admin의 플러그인 목록 하단: 체크박스가 있는 WCPOS Pro, WCPOS, WooCommerce 행과 WooCommerce 새 버전 알림이 표시되고, 목록 아래에 일괄 작업과 적용이 표시됨">

1. **WCPOS Pro** — 선택하지 마세요. 이 매장에는 설치되어 있지만 활성화되어 있지 않습니다.
2. **WCPOS** — 선택하지 마세요.
3. **WooCommerce** — WCPOS에 필요한 동안 체크박스가 비활성화되므로 활성 상태가 유지됩니다.
4. **일괄 작업** — 나머지 플러그인을 모두 선택한 뒤 **비활성화**를 선택하세요.
5. **적용** — 선택한 플러그인을 비활성화합니다.

### 2.3 다시 시도하기 {#23-test-the-issue}

1. **모든 캐시를 비우세요**: 호스팅 업체, CDN, 캐싱 플러그인의 캐시를 모두 비우세요.
2. **실패했던 작업을 실행하세요.** 이제 정상적으로 작동하나요?
3. **속도 저하가 문제라면**, 기록해 둔 시간과 비교하세요.

**이제 정상적으로 작동하는 경우:** 비활성화한 플러그인 중 하나가 원인일 가능성이 높습니다. [플러그인을 하나씩 다시 활성화하기](#24-enable-plugins-one-by-one)로 이동해 어떤 플러그인을 켰을 때 문제가 다시 나타나는지 확인하세요.

**여전히 실패하는 경우:** 이 테스트로는 원인을 찾지 못했습니다. 플러그인을 하나씩 다시 활성화하지 마세요. [3단계](#step-3-check-for-theme-conflicts)에서 테마를 확인하세요. 테마도 원인이 아니라면 다음을 확인하세요.
- 서버 리소스와 방화벽: [서버 성능](../performance/server.mdx) 참고
- [Cloudflare](./cloudflare.mdx)처럼 사이트 앞단에서 작동하는 서비스
- WordPress, WooCommerce 또는 WCPOS 자체: [발생하는 문제 기록하기](#21-create-a-baseline)에 기록해 둔 내용과 함께 [지원팀에 문의](#getting-help)하세요

### 2.4 플러그인을 하나씩 다시 활성화하기 {#24-enable-plugins-one-by-one}

<details>
<summary>먼저 시도할 플러그인</summary>

충돌할 가능성이 높은 유형의 플러그인부터 시작하면 원인을 더 빨리 찾을 수 있습니다:
1. **보안 및 로그인 플러그인**: Wordfence, Sucuri, Solid Security 등
2. **캐싱 및 최적화 플러그인**
3. **결제 게이트웨이**
4. **기타 WooCommerce 확장 기능**
5. **SEO 플러그인**
6. **그 밖의 모든 플러그인**

</details>

**각 플러그인을 테스트하세요:**

1. **플러그인 하나를 활성화하세요.**
2. **다시 시도하세요.**
3. **계속 정상 작동하는 경우:** 다음 플러그인을 활성화하고 다시 시도하세요.
4. **다시 실패하는 경우:** 방금 활성화한 플러그인을 기록하세요. 충돌의 원인일 가능성이 높습니다.

**해당 플러그인이 원인인지 확인하세요:**

1. WooCommerce, WCPOS, WCPOS Pro와 계속 활성 상태로 두었던 결제 게이트웨이만 남기고 **다시 켰던 플러그인을 비활성화하세요**.
2. **기록한 플러그인만 활성화하고**, 다시 시도하세요.
3. **문제가 다시 나타나는 경우:** 해당 플러그인이 충돌의 원인입니다.
4. **문제가 다시 나타나지 않는 경우:** 다른 플러그인도 관련되어 있을 수 있습니다. 나머지를 하나씩 활성화하면서 어떤 두 플러그인을 함께 켰을 때 문제가 다시 나타나는지 기록하세요.

### 2.5 확인한 내용 기록하기 {#25-document-your-findings}

1. **플러그인 이름과 버전.**
2. 2.1에서 기록한 표현 그대로 **발생하는 문제**.
3. **새 버전 출시 여부.**

이 정보는 [4단계](#step-4-resolving-plugin-conflicts)와 [지원팀에 문의](#getting-help)할 때 필요합니다.

## 3단계: 테마 확인하기 {#step-3-check-for-theme-conflicts}

POS 화면은 사이트의 테마를 사용하지 않으므로 테마 때문에 POS에 문제가 생기는 경우는 드뭅니다. 하지만 WordPress가 POS에 보내는 다음 항목에는 영향을 줄 수 있습니다.

- 결제 화면의 **레거시** 탭에 있는 결제 게이트웨이의 결제 페이지와 [웹 결제](../../payment/gateways/web-checkout.mdx) 게이트웨이가 고객을 안내하는 온라인 쇼핑몰 결제 페이지
- POS 설정을 비롯한 WP Admin 화면
- POS가 보내는 REST API 요청. WordPress는 이 요청을 처리할 때도 테마 코드를 실행합니다.

### 기본 테마로 테스트하기 {#test-with-a-default-theme}

1. **스테이징 사이트에서** Twenty Twenty-Five 또는 Twenty Twenty-Four 같은 WordPress 기본 테마로 변경하세요.
2. **다시 시도하세요.**
3. **이제 정상적으로 작동하는 경우:** 테마가 원인입니다. 어떤 문제가 발생하는지 테마 개발자에게 알리세요.

## 4단계: 충돌 해결하기 {#step-4-resolving-plugin-conflicts}

원인 플러그인을 찾았다면 다음 방법을 순서대로 시도하세요.

### 방법 1: 플러그인 업데이트하기 {#option-1-update-the-plugin}

1. **업데이트가 있는지 확인하세요.** 충돌이 이미 해결되었을 수 있습니다.
2. **먼저 스테이징에서 업데이트하고**, 다시 시도하세요.
3. **문제가 해결되고**, POS와 온라인 쇼핑몰 결제가 모두 정상적으로 작동한다면 운영 사이트를 업데이트하세요.

### 방법 2: 플러그인 적용 대상에서 POS 제외하기 {#option-2-exclude-the-pos}

대부분의 충돌은 다른 플러그인을 비활성화하지 않고 해당 플러그인의 설정에서 해결할 수 있습니다. [제외할 항목](#what-to-exclude)과 [알려진 플러그인 충돌](#known-plugin-conflicts)에 있는 해당 플러그인의 해결 방법을 참고하세요.

### 방법 3: 대체 플러그인 찾기 {#option-2-find-an-alternative}

1. 같은 기능을 제공하는 **다른 플러그인을 찾아보세요**.
2. **스테이징에서 테스트하세요.**
3. 교체하기 전에 **설정을 옮기세요**.

### 방법 4: 플러그인 개발자에게 알리기 {#option-3-contact-plugin-developer}

다음 정보를 보내세요.
- 플러그인 버전과 WordPress, WooCommerce, WCPOS 버전
- 발생하는 문제와 정확한 메시지
- 문제를 재현하는 단계

### 방법 5: 개발자에게 우회 방법 요청하기 {#option-4-custom-solution}

꼭 사용해야 하는 플러그인이라면 WordPress 개발자가 해당 플러그인의 훅을 이용해 충돌하는 부분이 POS 요청과 POS 페이지에서 실행되지 않도록 조정할 수 있는 경우가 많습니다.

## 제외할 항목 {#what-to-exclude}

아래 해결 방법은 대부분 다른 플러그인을 비활성화하는 대신 POS에 영향을 주지 않도록 설정하는 방식입니다. [알려진 플러그인 충돌](#known-plugin-conflicts)에 해당 플러그인이 있다면 변경할 내용을 해당 항목에서 확인하세요. 없다면 아래 정보를 웹사이트 관리자나 플러그인 지원팀에 전달하세요.

<details>
<summary>웹사이트 관리자를 위한 주소와 설정</summary>

POS는 WordPress 사이트의 REST API를 통해 매장 데이터를 읽고 저장합니다. 이 요청을 차단하거나 캐싱하거나 변경하는 플러그인은 문제를 일으킬 수 있습니다. 플러그인이 목록에 없다면 다음을 확인하세요.

- **방화벽 및 REST API 설정:** `/wp-json/` 자체와 `/wp-json/wcpos/` 아래의 모든 주소를 허용하세요. 다른 모든 주소에는 보호 기능을 유지하세요.
- **캐싱 및 스크립트 최적화 설정:** `/pos`와 `/wcpos-checkout/`을 제외하세요.
- **설정을 찾을 수 없는 경우:** 이 표를 플러그인 지원팀에 보내고 해당 주소를 어디에 추가해야 하는지 문의하세요.

| 주소 | POS에서 사용하는 용도 |
| --- | --- |
| `/wp-json/wcpos/` | POS가 읽고 저장하는 모든 데이터 |
| `/wp-json/` | 앱 연결 시 매장을 찾는 데 사용합니다. 앱은 이 주소 아래의 경로가 아니라 이 주소 자체를 읽습니다 |
| `/pos` | 웹 브라우저에서 사용하는 POS입니다. 기본값이며, 사이트의 `WP Admin > 설정 > Permalinks`에서 다른 **POS 기본 경로**를 사용할 수도 있습니다 |
| `/wcpos-auth/` | 앱의 로그인 창 |
| `/wcpos-checkout/` | **레거시** 탭에 있는 결제 게이트웨이의 결제 페이지와 영수증 |


:::note 앱의 로그인 창은 WordPress 로그인 페이지를 사용하지 않습니다
데스크톱 및 모바일 앱은 별도 창에서 `/wcpos-auth/`의 WCPOS 자체 양식으로 로그인합니다. 사용자 지정 로그인 주소, 두 단계 인증 코드, 캡차, 이메일 전용 로그인 등 WordPress 로그인 페이지를 변경하는 플러그인은 여기에 적용되지 않습니다. 웹 브라우저에서 POS를 열 때는 일반 WordPress 로그인 페이지로 먼저 이동하므로 이러한 플러그인이 적용됩니다.
:::

</details>

## 충돌이 자주 발생하는 플러그인 유형 {#common-conflicting-plugin-types}

<details>
<summary>어떤 종류의 플러그인이 영향을 줄 수 있나요?</summary>

**충돌 가능성이 높은 유형:**

- **보안 및 방화벽 플러그인**은 REST API 요청을 차단하거나, 요청이 많아지면 POS의 접근을 차단하거나, 로그인을 막을 수 있습니다.
- **캐싱 및 최적화 플러그인**은 POS에 오래된 응답을 보내거나 WordPress가 POS용으로 생성하는 페이지의 스크립트를 망가뜨릴 수 있습니다.
- **로그인, 회원 및 접근 제어 플러그인**은 로그인하지 않은 사용자의 REST API 접근을 막거나 로그인 방식을 변경할 수 있습니다.
- **페이지 빌더 및 프런트엔드 삽입 플러그인**은 결제 게이트웨이의 결제 페이지에 자체 스크립트와 오버레이를 불러올 수 있습니다.
- **주문이나 상품이 저장될 때 실행되는 모든 기능**은 매번 판매 처리 속도를 늦추거나 판매 내역 저장을 실패하게 할 수 있습니다.

**문제가 드문 유형:** 문의 양식, 소셜 미디어, 분석 및 콘텐츠 플러그인은 POS에 거의 영향을 주지 않습니다. [WooCommerce Tax](../../integrations/woocommerce-tax.mdx)는 POS와 함께 사용할 수 있으며, POS 판매에도 온라인 주문과 동일한 자동 세율이 적용됩니다.

</details>

## 알려진 플러그인 충돌 {#known-plugin-conflicts}

다음 플러그인은 WCPOS와 충돌한다는 보고가 있었습니다. 사용하는 플러그인의 항목을 펼쳐 증상과 해결 방법을 확인한 뒤, 먼저 스테이징 사이트에서 해결 방법을 적용하세요.

바로 가기: [보안 및 로그인](#security-and-login-plugins) · [캐싱 및 최적화](#performance-caching-optimisation-plugins) · [페이지 빌더](#page-builders-front-end-injectors) · [WooCommerce 확장 기능 및 기타 플러그인](#woocommerce-extensions-other-plugins) · [서버 수준](#server-level-conflicts) · [WCPOS에서 처리하는 충돌](#handled-by-wcpos)

### 보안 및 로그인 플러그인 {#security-and-login-plugins}

가장 흔한 원인입니다. POS가 보내는 요청을 차단하여 앱이 연결하거나 로그인하거나 매장 데이터를 다운로드하지 못하게 합니다.

<details>
<summary>Wordfence: POS 연결 또는 다운로드 불가</summary>

**증상:** 방화벽이 POS의 REST API 요청을 차단합니다.

**해결 방법:** 방화벽에서 `/wp-json/wcpos/`을 허용하세요. REST API 전체가 아닌 해당 주소만 허용하세요.

</details>

<details>
<summary>Really Simple Security: REST API 차단 또는 리디렉션</summary>

**증상:** REST API 접근을 차단하거나 강제로 리디렉션합니다.

**해결 방법:** 플러그인의 **고급** 설정에서 REST API 제한을 끄세요.

</details>

<details>
<summary>Solid Security (iThemes Security): REST API 또는 POS 접근 차단</summary>

**증상:** REST API를 차단하거나 POS 요청을 무차별 대입 공격으로 판단하여 접근을 차단합니다.

**해결 방법:** POS 주소인 `/wp-json/`과 `/wp-json/wcpos/`, 그리고 서버 자체의 IP 주소를 허용하세요. IP 주소를 사이트 전체에 걸쳐 허용하지 마세요.

</details>

<details>
<summary>Sucuri: POS 연결 또는 다운로드 불가</summary>

**증상:** 방화벽이 REST API 요청을 차단합니다.

**해결 방법:** Sucuri 대시보드에서 `/wp-json/wcpos/`을 허용하세요.

</details>

<details>
<summary>Force Login 및 REST API 접근을 막는 플러그인: "인증이 필요합니다"</summary>

**증상:** 앱에 _"이 사이트의 WordPress REST API를 사용하려면 인증이 필요합니다"_라는 메시지가 표시되거나, 로그인한 사용자만 REST API를 사용할 수 있다는 플러그인 자체 메시지가 표시됩니다.

**해결 방법:** 로그인하지 않은 방문자도 REST API에 접근할 수 있도록 허용하세요. 최소한 `/wp-json/`과 `/wp-json/wcpos/`에는 접근할 수 있어야 합니다.

</details>

<details>
<summary>Security Optimizer: 웹 브라우저 POS에서 사용자 지정 로그인 URL 요구</summary>

**증상:** 웹 브라우저에서 POS를 열면 사용자 지정 로그인 URL을 사용하라는 메시지에서 더 진행되지 않습니다.

**해결 방법:** 먼저 사용자 지정 로그인 URL로 WP Admin에 로그인한 뒤 `/pos`로 이동하세요.

</details>

<details>
<summary>Jetpack CRM Client Portal: 사용자 로그인 불가</summary>

**증상:** 사용자가 POS에 로그인할 수 없습니다.

**해결 방법:** Jetpack CRM 전체가 아닌 Client Portal 확장 기능만 비활성화하세요.

</details>

### 성능, 캐싱 및 최적화 플러그인 {#performance-caching-optimisation-plugins}

<details>
<summary>WP Rocket, Autoptimize, Hummingbird, Smush: 레거시 결제 페이지 오류</summary>

**증상:** JavaScript 실행을 지연시키거나 코드를 압축하면 **레거시** 탭의 결제 게이트웨이 결제 페이지가 제대로 작동하지 않습니다.

**해결 방법:** JavaScript 최적화 대상에서 `/wcpos-checkout/`과 `/pos`를 제외하세요.

</details>

<details>
<summary>LiteSpeed Cache: 결제 시 데스크톱 앱이 다시 로드됨</summary>

**증상:** 결제 시 데스크톱 앱이 계속 다시 로드됩니다.

**해결 방법:** WCPOS와 LiteSpeed Cache를 업데이트하고 캐시를 비운 뒤, 캐싱 대상에서 `/wcpos-checkout/`과 `/pos`를 제외하세요.

</details>

### 페이지 빌더 및 프런트엔드 삽입 플러그인 {#page-builders-front-end-injectors}

이 플러그인들은 **레거시** 탭의 결제 게이트웨이가 POS 안에서 여는 결제 페이지에 자체 스크립트와 오버레이를 불러옵니다. 해당 페이지의 **결제 설정** 버튼으로 스크립트와 스타일을 제거할 수 있습니다. [결제 게이트웨이의 결제 페이지가 이상하게 보이는 경우](../../pos/checkout/troubleshooting.mdx#checkout-settings-troubleshooting)를 참고하세요.

<details>
<summary>Elementor: 결제 수단이 열리지 않음</summary>

**증상:** `elementor-frontend.js`가 결제 페이지에 문제를 일으켜 결제 수단이 열리지 않습니다.

**해결 방법:** **결제 설정**의 **선택한 스크립트 비활성화**에서 Elementor의 프런트엔드 스크립트를 제거하거나, Elementor가 `/wcpos-checkout/`에서 해당 스크립트를 불러오지 않도록 설정하세요.

</details>

<details>
<summary>Omnisend 및 기타 마케팅 플러그인: 결제 페이지 레이아웃 깨짐</summary>

**증상:** 해당 플러그인의 스크립트가 결제 페이지의 레이아웃과 결제 기능에 문제를 일으킵니다.

**해결 방법:** **결제 설정**의 **선택한 스크립트 비활성화**에서 해당 스크립트를 제거하세요.

</details>

<details>
<summary>MyStickyElements, Complianz: 버튼이나 배너가 결제 페이지를 가림</summary>

**증상:** 고정 버튼이나 쿠키 배너가 결제 페이지를 가립니다.

**해결 방법:** `/wcpos-checkout/`을 제외하도록 설정하거나 **결제 설정**에서 해당 스크립트를 제거하세요.

</details>

### WooCommerce 확장 기능 및 기타 플러그인 {#woocommerce-extensions-other-plugins}

<details>
<summary>Stripe Tax: POS 주문에서 작동하지 않음</summary>

**증상:** REST API로 생성한 주문에서는 작동하지 않습니다. POS는 모든 주문을 REST API로 저장합니다.

**해결 방법:** 우회 방법은 없습니다. POS에서 사용할 수 있는 자동 세금 계산 기능은 [WooCommerce Tax](../../integrations/woocommerce-tax.mdx)입니다.

</details>

<details>
<summary>WP Activity Log: 데이터베이스 용량 증가 및 매장 속도 저하</summary>

**증상:** POS에서 이루어지는 모든 변경을 기록하므로 데이터베이스가 가득 차고 매장 속도가 느려집니다.

**해결 방법:** 플러그인을 비활성화하거나 로그 기록 대상에서 POS 상품과 주문을 제외하세요.

</details>

<details>
<summary>MailerLite: 판매 내역 저장 시 서버 오류(500)</summary>

**증상:** MailerLite Signup Forms와 MailerLite WooCommerce 연동 기능을 모두 활성화하면 POS가 주문을 저장할 때 서버 메모리가 부족해져 서버 오류(500)가 반환됩니다.

**해결 방법:** 둘 다 비활성화하여 원인을 확인한 뒤 MailerLite에 문의하세요.

</details>

<details>
<summary>The Courier Guy Shipping: 주문 저장 불가</summary>

**증상:** 서버 오류로 POS가 주문을 저장하지 못합니다.

**해결 방법:** 플러그인의 이전 버전으로 돌아가거나 개발자에게 문의하세요.

</details>

<details>
<summary>Mollie: 직접 은행 계좌 이체가 표시되지 않음</summary>

**증상:** POS 결제 화면에서 직접 은행 계좌 이체를 숨깁니다.

**해결 방법:** Mollie를 업데이트하세요.

</details>

<details>
<summary>CTX Feed: POS 설정 페이지에서 403 오류</summary>

**증상:** POS 설정 페이지에서 간헐적으로 403 오류가 발생합니다.

**해결 방법:** 플러그인을 비활성화하여 원인을 확인하세요. 이 문제를 해결하는 설정은 알려져 있지 않습니다.

</details>

<details>
<summary>바코드 스캐너 플러그인: 주문이 저장되거나 표시되지 않음</summary>

**증상:** REST API가 보내는 주문 데이터를 손상시켜 주문이 저장되거나 표시되지 않습니다.

**해결 방법:** 해당 플러그인을 비활성화하세요. POS는 자체적으로 바코드를 읽습니다. [바코드 스캔](../../pos/product-panel/barcode-scanning.mdx)을 참고하세요.

</details>

<details>
<summary>PixelYourSite, PixelMySite: 치명적인 오류</summary>

**증상:** _bool에서 멤버 함수 `is_type()`을 호출_하는 치명적인 오류가 발생합니다.

**해결 방법:** 플러그인을 비활성화하세요.

</details>

<details>
<summary>Google Listings & Ads: WCPOS 클래스를 찾을 수 없다는 치명적인 오류</summary>

**증상:** WCPOS 클래스를 _찾을 수 없다_는 치명적인 오류가 발생합니다.

**해결 방법:** WCPOS 플러그인을 모두 삭제한 뒤 최신 WCPOS Pro만 설치하세요.

</details>

<details>
<summary>WooCommerce Subscriptions: 1.7 이하 버전에서 Pro 업그레이드 차단</summary>

**증상:** WCPOS Pro의 업그레이드 단계를 차단합니다.

**해결 방법:** Subscriptions를 비활성화하고 WCPOS Pro를 활성화하여 업그레이드가 완료되도록 한 뒤, Subscriptions를 다시 활성화하세요.

</details>

:::warning Stripe Terminal: WooCommerce 결제에서는 비활성 상태로 두세요
Stripe Terminal은 `WP Admin > POS > 설정 > 결제`에서 POS용으로만 활성화하세요. `WP Admin > WooCommerce > 설정 > 결제`에서는 활성화할 필요가 없습니다. 여기서 활성화하면 온라인 쇼핑몰 결제 화면에 표시되며, 이로 인해 온라인 고객의 결제에 문제가 발생한 사례가 있습니다. [Stripe Terminal](../../payment/gateways/stripe-terminal.mdx)을 참고하세요.
:::

### 서버 수준 충돌 {#server-level-conflicts}

<details>
<summary>웹 서버에서 설정한 보안 헤더: POS가 로고 화면에서 멈추거나 빈 페이지 표시</summary>

`.htaccess`, Nginx 또는 호스팅 제어판의 `Content-Security-Policy`나 `X-Frame-Options` 설정입니다.

**증상:** POS가 로고 화면에서 멈추거나, 레거시 탭의 결제 페이지 또는 영수증이 빈 화면으로 표시됩니다.

**해결 방법:** 해당 헤더의 적용 대상에서 `/pos`, `/wcpos-auth/`, `/wcpos-checkout/`을 제외하세요. POS 페이지는 인라인 스크립트로 시작하고 `cdn.wcpos.com`과 `cdn.jsdelivr.net`에서 파일을 가져오므로 CDN 주소만 허용해서는 충분하지 않습니다. WordPress나 플러그인이 추가한 헤더는 WCPOS가 자체 페이지에서 제거하지만, 웹 서버가 추가한 헤더는 제거할 수 없습니다.

</details>

<details>
<summary>GoDaddy Website Firewall: "'undefined'를 수신함"</summary>

**증상:** `/wp-json/`을 차단하며 _"'undefined'를 수신함"_이라는 메시지가 표시됩니다.

**해결 방법:** 방화벽에서 `/wp-json/` 경로를 허용하세요. [서버 성능](../performance/server.mdx#hosting-specific-notes)을 참고하세요.

</details>

### WCPOS가 자체적으로 처리하는 충돌 {#handled-by-wcpos}

<details>
<summary>이전에 충돌했지만 이제는 별도 조치가 필요 없는 플러그인</summary>

WCPOS를 최신 상태로 유지하면 다음 항목은 별도로 설정할 필요가 없습니다.

- **플러그인이 추가하는 보안 헤더.** Wordfence, LiteSpeed Cache 등의 플러그인은 POS 로딩을 막는 `Content-Security-Policy`를 추가할 수 있습니다. WCPOS는 자체 페이지에서 `Content-Security-Policy`와 `X-Frame-Options`를 제거합니다. 해당 페이지에 정책이 필요한 개발자는 `wcpos_content_security_policy` 필터로 설정할 수 있습니다.
- **JWT Authentication 플러그인.** 이전에는 POS의 로그인 토큰을 거부하여 로그인 후 모든 요청이 403 오류로 실패했습니다. 이제 WCPOS가 직접 요청에 서명한 경우 해당 플러그인의 오류를 지웁니다. 다른 플러그인의 오류는 그대로 전달됩니다.
- **Image Prioritizer.** 앱이 WordPress 사이트를 찾는 데 사용하는 `Link` 헤더를 채웁니다. 해당 헤더에 사이트의 REST API가 명시되어 있지 않으면 앱은 대신 `/wp-json/`에서 찾습니다. 앱에 여전히 _"WordPress 사이트가 아닌 것 같습니다"_라는 메시지가 표시되면 이 플러그인을 비활성화하세요.
- **상품 저장 시 실행되는 플러그인**(Jetpack, Astra, Xero 등). 이전 WCPOS 버전에서는 이 플러그인들이 요청마다 중복 행을 추가했습니다. 이 문제는 1.8.12에서 수정되었으며 업그레이드 과정에서 중복 행이 제거되었습니다.
- **WooCommerce Stripe 11.1.0.** 카드 스크립트가 **레거시** 탭의 결제 페이지에서 다른 모든 결제 수단의 결제를 막았습니다. Stripe 플러그인이 11.1.1 미만이면 WCPOS는 해당 페이지에서 Stripe의 카드 스크립트와 스타일을 제거합니다. 그러면 다른 결제 수단은 작동하지만 Stripe 카드 양식은 표시되지 않습니다. Stripe는 11.1.1에서 이 충돌을 수정했습니다. Stripe를 업데이트하면 이전에 **결제 설정**을 저장하면서 카드 양식을 껐더라도 WCPOS가 페이지에 카드 양식을 다시 유지합니다.
- **MyParcel.** [기타 상품](../../pos/cart/index.mdx#miscellaneous-products)이 담긴 장바구니는 주문 저장 중 MyParcel에서 치명적인 오류가 발생하여 결제할 수 없었습니다. 이제 WCPOS는 WooCommerce와 마찬가지로 해당 항목에 카탈로그 상품이 없음을 MyParcel에 알려 판매가 완료되도록 합니다.

</details>

## 예방 팁 {#prevention-tips}

### 정기 유지 관리 {#regular-maintenance}

1. **플러그인을 최신 상태로 유지하세요.**
2. 비활성 상태로 두지 말고 **사용하지 않는 플러그인은 삭제하세요**.
3. 운영 사이트에 적용하기 전에 **모든 업데이트를 스테이징에서 테스트하세요**.
4. [서버 성능](../performance/server.mdx)을 참고하여 **서버 속도를 확인하세요**.

### 플러그인 선택하기 {#plugin-selection-best-practices}

1. 평가가 좋고 **꾸준히 업데이트되는 플러그인을 선택하세요**.
2. **같은 기능을 하는 플러그인 두 개를 동시에 실행하지 마세요.**
3. **사용 중인 WooCommerce 버전에서 테스트되었다고 명시된 플러그인인지 확인하세요.**
4. **플러그인은 하나씩 추가하고**, 추가할 때마다 POS를 확인하세요.
