일부 매장은 Cloudflare를 거쳐 접속하며, Cloudflare가 방문자에게 보안 검사를 요구할 수 있습니다. WCPOS 앱이 이 검사를 통과하지 못하면 매장에 연결하거나 동기화할 수 없습니다. 해결하려면 매장 소유자나 사이트의 Cloudflare 계정 관리자가 Cloudflare 설정을 변경해야 합니다. 이 페이지에서는 어떤 설정을 어떻게 변경해야 하는지 설명합니다.

- **캐셔:** [계산대에서 할 일](#at-the-till)을 확인하세요.
- **매장 소유자:** [앱을 차단하는 Cloudflare 기능 찾기](#which-feature)로 이동하세요.

## 계산대에서 할 일 {#at-the-till}

- **데스크톱 앱에 보안 검사 창이 표시되는 경우:** 이 분 안에 확인란을 선택하세요. 그러면 앱이 계속 작동합니다. Cloudflare는 30분 후 또는 매장 소유자가 설정한 시간이 지난 후 다시 검사를 요청합니다.
- **iPad, iPhone 또는 Android 앱에 HOST121이 표시되는 경우:** 이 앱들은 Cloudflare 검사를 통과할 수 없습니다. 매장 소유자가 아래 설정을 변경할 때까지 차단된 상태가 유지됩니다.
- **어느 경우든,** 매장 소유자에게 이 페이지를 보내세요. 데스크톱 앱에서 검사를 통과하면 일단 연결할 수 있지만, 나중에 검사가 다시 나타납니다.

**매장 소유자:** [앱을 차단하는 Cloudflare 기능 찾기](#which-feature)부터 시작하세요.

## Cloudflare가 앱을 차단할 때 나타나는 증상 {#how-to-recognise-it}

- 연결 화면에 **"이 매장의 호스팅 설정이 앱을 차단하고 있습니다"** 메시지와 오류 코드 [HOST121](../../error-codes/HOST121.mdx)이 표시됩니다.
- 데스크톱 앱이 연결하거나 동기화하는 동안 **your-store.com 보안 검사**라는 제목의 작은 창이 열립니다.

<details>
<summary>매장 소유자가 볼 수 있는 다른 증상</summary>

- **WP Admin > POS > 설정 > 일반** 상단에 **"매장이 Cloudflare를 사용하고 있습니다"** 메시지가 표시됩니다. 플러그인은 Cloudflare를 거치는 모든 사이트에 문제가 발생하기 전부터 이 메시지를 표시합니다.
- 클라우드 인쇄가 중단되고 **WP Admin > POS > 설정 > 클라우드 인쇄**의 프린터 카드에 **"보안 서비스(Cloudflare 또는 방화벽 플러그인 등)가 WCPOS Cloud Print를 차단하고 있습니다"** 메시지가 표시됩니다. [릴레이](../../receipts/cloud-printing.mdx#relay)는 앱과 같은 방식으로 매장에 접속하므로 아래 방법으로 인쇄 문제도 해결됩니다.
- 이전 앱 버전에서는 브라우저에서 정상적으로 열리는 매장에서도 **"WordPress 사이트가 아닌 것 같습니다"** 또는 **"사이트 응답 시간이 너무 오래 걸립니다"** 메시지가 표시되었습니다.

</details>

## 앱을 차단하는 Cloudflare 기능 찾기 {#which-feature}

이하 내용은 매장 소유자를 위한 안내입니다. Cloudflare 대시보드에서 사이트를 열고 다음 단계를 따르세요.

1. **보안 > 분석**으로 이동하여 **이벤트** 탭을 선택하세요. 앱이 차단된 시간대의 `/wp-json/` 요청을 찾으세요. 해당 요청의 **서비스** 필드에는 **봇 방어 모드**나 **관리형 규칙**처럼 요청을 차단한 기능이 표시됩니다.
2. 아래에서 해당 기능의 설명을 펼치세요. 설정 위치와 해결 방법이 나와 있습니다.
3. 일치하는 이벤트가 없나요? 무료 요금제에서는 일부 요청만 로그에 남기므로 앱의 요청이 누락될 수 있습니다. 이 경우 아래 네 가지 기능 중 어떤 기능이 켜져 있는지 확인하세요.

Cloudflare가 원인인지 먼저 확인하려면 선택 사항인 [터미널 확인](#check)을 수행하세요.

<details>
<summary>봇 방어 모드(무료 요금제): 끄기</summary>

- 위치: **보안 > 설정**에서 **봇 트래픽**으로 필터링하세요.
- 해결 방법: 기능을 끄세요. 건너뛰기 규칙으로는 이 기능에서 앱을 예외 처리할 수 없습니다([이유](#bot-fight-mode)).

</details>

<details>
<summary>슈퍼 봇 방어 모드(Pro 요금제 이상): 건너뛰기 규칙 추가</summary>

- 위치: **보안 > 설정**에서 **봇 트래픽**으로 필터링하세요.
- 해결 방법: [건너뛰기 규칙을 추가하세요](#add-a-skip-rule).

</details>

<details>
<summary>방문자에게 보안 검사를 요구하는 사용자 지정 규칙 또는 관리형 규칙: 건너뛰기 규칙 추가</summary>

- 위치: **보안 규칙**.
- 해결 방법: [건너뛰기 규칙을 추가하세요](#add-a-skip-rule).

</details>

<Anchor id="under-attack" />

<details>
<summary>공격받는 중 모드: 끄거나 구성 규칙 추가</summary>

- 위치: 사이트 개요의 **빠른 작업** 또는 **보안 > 설정**의 **보안 수준** 설정.
- 해결 방법: 공격이 끝나면 기능을 끄세요. 사이트의 나머지 부분에서는 계속 사용하려면 [건너뛰기 규칙의 표현식](#add-a-skip-rule)으로 **구성 규칙**(**규칙 > 개요 > 규칙 생성 > 구성 규칙**)을 추가하고 **공격받는 중**을 끄세요.

</details>

WordPress용 Cloudflare 플러그인에서는 이 페이지의 규칙을 추가할 수 없습니다. Cloudflare 대시보드에서 변경하세요.

## REST API용 건너뛰기 규칙 추가 {#add-a-skip-rule}

건너뛰기 규칙은 매장 REST API 요청에 대해 아래에서 선택한 Cloudflare 검사만 건너뜁니다. 다른 검사는 그대로 적용됩니다. WordPress는 여전히 모든 로그인과 권한을 확인합니다.

:::note
무료 요금제의 봇 방어 모드는 이 규칙을 무시합니다. 봇 방어 모드가 앱을 차단하고 있다면 규칙을 추가하는 대신 [해당 기능을 끄세요](#bot-fight-mode).
:::

1. Cloudflare 대시보드에서 사이트를 열고 **보안 규칙**으로 이동한 다음 **규칙 생성 > 사용자 지정 규칙**을 선택하세요.
2. **규칙 이름**에 `WCPOS REST API`를 입력하세요.
3. **수신 요청이 일치하는 경우**에서 **표현식 편집**을 선택하고 다음 내용을 붙여 넣으세요.

   ```text
   (starts_with(http.request.uri.path, "/wp-json/")) or (http.request.uri.path eq "/" and (starts_with(http.request.uri.query, "rest_route=") or http.request.uri.query contains "&rest_route="))
   ```

   WordPress가 `https://example.com/shop` 같은 하위 폴더에 있다면 `/wp-json/`과 `/` 대신 각각 `/shop/wp-json/`과 `/shop/`을 사용하세요.

   <details>
   <summary>표현식이 일치시키는 대상</summary>

   앞부분은 API의 일반 주소인 `/wp-json/`과 일치합니다. 뒷부분은 대체 주소인 `/?rest_route=/`과 일치하며, 사이트의 홈 주소에만 적용됩니다. 따라서 링크에 우연히 `rest_route=`가 포함된 페이지도 계속 보호됩니다.

   </details>

4. **수행할 작업**에서 **건너뛰기**를 선택하세요.
5. 규칙이 건너뛸 항목을 선택하세요. 다음 항목은 항상 선택하세요.
   - **나머지 모든 사용자 지정 규칙**: 다른 사용자 지정 규칙이 앱에 보안 검사를 요구하거나 앱을 차단하지 않도록 합니다.
   - **보안 수준**. 공격받는 중 모드가 켜져 있다면 해당 [구성 규칙](#under-attack)도 추가하세요.

   다음 항목은 해당하는 경우에만 선택하세요.
   - **모든 슈퍼 봇 방어 모드 규칙**: 슈퍼 봇 방어 모드가 켜져 있는 경우 선택하세요.
   - **모든 관리형 규칙**: 이벤트 로그에서 앱 요청의 **서비스** 필드에 **관리형 규칙**이 표시되는 경우 선택하세요. 일치하는 이벤트를 찾지 못했다면 선택하지 말고 [여전히 차단되나요?](#still-blocked)를 확인하세요.

   **(이전 버전)** 으로 표시된 항목은 선택하지 마세요.
6. **배포**를 선택하세요. 다른 사용자 지정 규칙이 방문자에게 보안 검사를 요구하거나 방문자를 차단한다면 **보안 규칙** 목록에서 이 규칙을 해당 규칙들 위로 끌어다 놓으세요. 관리형 규칙은 항상 사용자 지정 규칙 다음에 실행되므로 순서는 상관없습니다.

앱에서 연결하거나 동기화하여 요청이 통과하는지 확인하세요. 컴퓨터에서 확인하려면 [터미널 확인](#check)을 수행하세요. 응답은 `200`이어야 하고 `content-type: application/json`이 포함되어야 하며, `cf-mitigated` 줄은 없어야 합니다.

### 봇 방어 모드가 켜져 있는 경우 {#bot-fight-mode}

무료 요금제의 봇 방어 모드는 건너뛰기 규칙과 허용 규칙을 무시합니다. Cloudflare 공식 문서에 따르면 사용자 지정 규칙과 페이지 규칙으로도 이 기능을 우회할 수 없습니다. **봇 방어 모드**가 켜져 있고 건너뛰기 규칙을 추가한 후에도 앱이 차단된다면 **보안 > 설정**에서 **봇 트래픽**으로 필터링한 뒤 봇 방어 모드를 끄세요. 그런 다음 앱을 사용해 보거나 [확인](#check)을 다시 수행하세요. 봇 보호를 유지하려면 Pro 요금제로 전환하고 **슈퍼 봇 방어 모드**를 사용하세요. 위의 건너뛰기 규칙은 이 기능에 대해 예외 처리를 적용합니다. 봇 방어 모드가 이미 꺼져 있다면 [여전히 차단되나요?](#still-blocked)를 확인하세요.

## 컴퓨터에서 확인하기 {#check}

이 확인은 선택 사항입니다. 수정 전이나 후에 Cloudflare가 매장 대신 응답하는지 자신의 컴퓨터에서 확인할 수 있습니다.

<details>
<summary>터미널로 확인하기</summary>

터미널(Mac에서는 터미널, Windows에서는 PowerShell)을 열고 `your-store.com`을 매장 주소로 바꿔 다음 명령을 실행하세요. Windows에서는 `curl` 대신 `curl.exe`를 입력하세요.

```bash
curl -sI https://your-store.com/wp-json/
```

응답의 첫 부분을 확인하세요.

- **`403` 및 `cf-mitigated: challenge`:** Cloudflare가 앱을 차단하고 있습니다. 차단하는 [기능을 찾으세요](#which-feature).
- **`200` 및 `content-type: application/json`:** 이 컴퓨터의 요청은 통과했습니다. 앱에서 연결하거나 동기화해 보세요. 앱이 여전히 차단된다면 Cloudflare가 앱과 컴퓨터를 다르게 처리하고 있을 수 있습니다. 위의 기능들을 확인한 다음 [플러그인 충돌](./plugin-conflicts.mdx)을 확인하세요.
- **`404`:** 이 주소에 REST API가 없습니다. 고유주소를 사용하지 않는 사이트는 다른 주소를 사용합니다. `'https://your-store.com/?rest_route=/'`로 다시 확인하세요(따옴표를 유지하세요).

WordPress가 하위 폴더에 있다면 주소에 포함하세요: `https://example.com/shop/wp-json/`.

</details>

<details>
<summary>데스크톱 앱이 보안 검사를 통과하는 방식</summary>

앱은 매장의 REST API와 통신합니다. REST API는 앱에 데이터를 응답으로 제공하는 WordPress의 구성 요소입니다. 웹 브라우저는 사용자가 알아차리지 못하는 사이에 Cloudflare 검사를 통과하지만, 앱은 대개 그러지 못합니다. Cloudflare가 데이터 대신 보안 검사로 응답하면 데스크톱 앱은 숨겨진 브라우저 창을 열어 자동으로 검사를 통과하려고 합니다. Cloudflare가 확인란 선택을 요구하면 창이 표시되고 2분 동안 기다립니다. 이후 Cloudflare는 **챌린지 통과**에 설정된 시간(기본값 30분) 동안 앱의 접속을 허용하며, 그 시간이 지나면 검사가 다시 나타납니다. iPad, iPhone 및 Android 앱에는 이러한 창이 없습니다.

</details>

## Cloudflare의 API 캐싱 중지 {#caching}

Cloudflare는 REST API 응답의 복사본을 저장할 수도 있습니다. 그러면 앱에 오래된 상품, 가격, 주문이 표시됩니다. 건너뛰기 규칙은 보안 검사만 끄므로 이 동작에는 영향을 주지 않습니다. HTML 페이지를 캐싱하거나 Automatic Platform Optimization(APO)을 사용한다면 같은 표현식으로 **캐시 규칙**을 추가하고 **캐시 우회**로 설정하세요.

## 여전히 차단되나요? {#still-blocked}

- 건너뛰기 규칙을 열고 초안으로 저장된 상태(**초안으로 저장**)가 아니라 배포된 상태인지 확인하세요.
- 매장의 인터넷 연결을 차단하거나 보안 검사를 요구하는 **IP 액세스 규칙**이 없는지 확인하세요.
- **이벤트** 로그에 앱의 이벤트가 없나요? 관리형 규칙을 건너뛰기 전에 [터미널 확인](#check) 결과와 함께 아래 지원팀으로 문의하세요.
- 사이트 앞단의 다른 서비스도 같은 방식으로 앱을 차단할 수 있습니다. 보안 플러그인과 방화벽에 대해서는 [플러그인 충돌](./plugin-conflicts.mdx#server-level-conflicts)을, GoDaddy, WP Engine 및 기타 호스팅 업체에 대해서는 [호스팅 참고 사항](../performance/server.mdx#hosting-specific-notes)을 확인하세요.
