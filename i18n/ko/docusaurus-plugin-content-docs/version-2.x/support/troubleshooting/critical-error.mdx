"이 웹사이트에 치명적인 오류가 있습니다."는 웹사이트가 작동을 멈췄을 때 WordPress 자체에서 표시하는 메시지입니다. PHP 오류로 인해 POS에 응답하기 전에 웹사이트가 중단된 것입니다. 문제는 계산대가 아니라 웹사이트에 있습니다. 계산대에 아직 매장으로 전송되지 않은 변경 사항이 있을 수 있으므로 웹사이트를 수정하는 동안 계산대 데이터를 삭제하지 마세요.

## 계산대에서 할 일 {#at-the-till}

:::warning 이 계산대의 데이터를 삭제하지 마세요
로그의 오류 항목에도 "이 기기의 데이터를 삭제하지 마세요. 아직 매장으로 전송되지 않은 변경 사항이 있을 수 있습니다."라고 안내되어 있습니다. 데이터를 삭제하면 해당 변경 사항이 사라집니다. 아래 안내에 따라 한 번 더 시도해도 실패한다면 웹사이트가 복구될 때까지 기다리세요.
:::

**결제 처리 중인가요?** 아직 다시 결제하지 마세요. 메시지에 표시된 결제 코드의 안내 페이지를 따르세요.

- [CHECKOUT101](../../error-codes/CHECKOUT101.mdx): 장바구니 결제를 안전하게 다시 시도할 수 있습니다.
- [CHECKOUT201](../../error-codes/CHECKOUT201.mdx): 판매가 이미 처리되었을 수 있습니다.

그 외의 경우에는 다음 단계를 따르세요.

1. 작업을 한 번 더 시도하세요. 일시적인 오류일 수 있습니다.
2. 다시 실패하면 메뉴 하단의 맥박 아이콘으로 **매장 상태**를 열고 **로그**로 이동한 다음 **오류**를 누르세요.
3. **SYNC131** 항목을 눌러 여세요. 데이터가 안전한지 확인할 수 있으며, **도움말 — SYNC131**을 누르면 해당 코드의 안내 페이지가 열립니다.
4. **디버그 정보 복사**를 누르고 오류 발생 시간과 함께 웹사이트 관리자에게 보내세요.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[52, 0], [60, 0], [20, -32], [6, 28], [100, 0], [-40, 0]]} alt="매장 상태의 로그 탭: 메뉴의 맥박 아이콘, 로그 탭, 오늘의 오류, 오류 필터, 검색 필드 및 디버그 정보 복사">

1. **매장 상태** — 메뉴 하단의 맥박 아이콘입니다. 아이콘에 표시되는 빨간 숫자는 새 오류의 수입니다.
2. **로그** — 이 계산대에서 수행한 모든 작업을 30일 동안 보관합니다.
3. **오늘의 오류** — 오늘 기록된 오류입니다. 여기에는 오류가 없습니다.
4. **오류** — 오류만 표시합니다. 치명적인 오류는 **상태** 열에 **SYNC131**이 표시된 항목입니다.
5. **로그 검색** — 항목의 텍스트나 SYNC131 같은 코드로 항목을 찾습니다.
6. **디버그 정보 복사** — 지원팀에 보낼 보고서를 복사합니다. 휴대폰과 태블릿 앱에서는 **디버그 정보 공유**로 표시됩니다.

## 오류가 표시되는 위치 {#where-you-see-it}

- **계산대에서는** 작업이 실패한 후 [SYNC131](../../error-codes/SYNC131.mdx) 코드와 함께 메시지가 표시됩니다. 매장에 오류가 발생하여 요청을 완료하지 못했다는 뜻입니다.
- **매장에서 전달한 사유에는** 결제 시 또는 매장이 변경 사항을 거부했을 때처럼 POS가 사유를 표시하는 곳에서 나타납니다. 이 사유는 WordPress의 오류 문장이거나, 웹사이트가 오류 세부 정보를 표시하는 경우 *wp-includes/class-wpdb.php:2324에서 허용된 메모리 크기 134217728바이트를 모두 사용했습니다*와 같은 PHP 오류 자체입니다.
- **결제 시에는** 결제가 어떻게 처리되었는지 알려 주는 결제 코드가 대신 표시됩니다. 장바구니 결제를 안전하게 다시 시도할 수 있으면 [CHECKOUT101](../../error-codes/CHECKOUT101.mdx), 판매가 처리되었는지 POS가 확인할 수 없으면 [CHECKOUT201](../../error-codes/CHECKOUT201.mdx)이 표시됩니다. 다시 결제하기 전에 해당 페이지의 안내를 따르세요.
- **브라우저에서는** POS 페이지 자체를 불러오는 동안 웹사이트가 작동을 멈추면 표시됩니다. WordPress는 POS 대신 자체 오류 페이지를 표시합니다.
- **매장 상태 → 로그에서는** **상태** 열에 **SYNC131**이 표시된 오류 항목으로 나타납니다.

## 웹사이트에서 원인 찾기 {#find-the-cause}

이 작업은 WP Admin에 로그인할 수 있는 사람이 수행해야 합니다.

1. **WooCommerce → 상태 → 로그**로 이동하여 오류가 발생한 시간대의 가장 최근 **fatal-errors** 로그를 여세요. 웹사이트가 작동을 멈추면 거의 항상 PHP 오류가 이곳에 남습니다.
2. 오류의 첫 줄과 거기에 표시된 파일을 확인하세요. `wp-content/plugins/` 아래의 파일이면 해당 플러그인을, `wp-content/themes/` 아래의 파일이면 해당 테마를 알 수 있습니다.
3. 플러그인이나 테마를 업데이트한 후부터 오류가 발생했다면 업데이트를 되돌리거나 해당 플러그인 또는 테마를 비활성화하세요. PHP를 업그레이드한 후부터 발생했다면 호스팅 업체에 해당 변경 사항을 확인해 달라고 요청하세요. [플러그인 충돌](./plugin-conflicts.mdx)에서 문제를 일으키는 플러그인을 찾는 방법을 안내합니다.
4. WooCommerce 로그에 아무것도 없나요? WooCommerce의 [PHP 오류 로그 찾기](https://woocommerce.com/document/finding-php-error-logs/) 안내에서 다른 확인 위치를 살펴보거나, 호스팅 업체에 같은 시간대의 서버 PHP 오류 로그를 요청하세요.
5. 문제가 해결되면 계산대로 돌아가세요. 결제 중이었다면 다시 결제하기 전에 결제 코드의 안내 페이지를 확인하세요. 그 외의 경우에는 작업을 다시 시도하세요.

WooCommerce가 fatal-errors 로그 파일을 기록하면 **WP Admin > POS > 설정**의 **도구** 아래 **로그**에 **치명적인 오류 감지됨 — WooCommerce 로그에서 확인**이 표시됩니다. 이 링크를 누르면 치명적인 오류만 표시하도록 필터링된 WooCommerce 로그가 열립니다.

:::tip WordPress에서 보낸 이메일
플러그인이나 테마로 인해 웹사이트가 작동을 멈추면 WordPress는 사이트 관리자 이메일 주소로 **사이트에 기술적 문제가 발생했습니다**라는 이메일을 보냅니다. 이메일의 링크를 열고 로그인하면 복구 모드로 WP Admin에 접속할 수 있습니다. WP Admin이 정상적으로 열리지 않을 때도 여기서 문제가 있는 플러그인을 비활성화할 수 있습니다.
:::

### 확인할 수 있는 오류 {#common-errors}

**허용된 메모리 크기 …바이트를 모두 사용했습니다.** PHP에 메모리가 부족합니다. 호스팅 업체에 PHP 메모리 한도를 높여 달라고 요청하세요.

**다른 플러그인 파일의 오류.** 일부 플러그인은 POS와 충돌하는 것으로 알려져 있습니다. [알려진 플러그인 충돌](./plugin-conflicts.mdx#known-plugin-conflicts)에서 해당 플러그인과 해결 방법을 찾아보세요.

**무료 플러그인을 제거하고 Pro를 업로드한 후 치명적인 오류 또는 *헤더 정보를 수정할 수 없습니다* 오류가 발생하는 경우.** Pro는 무료 플러그인의 코드를 포함하고 독립적으로 작동하므로 무료 플러그인이 필요하지 않습니다. 따라서 무료 플러그인을 다시 설치할 필요가 없습니다. 위에서 설명한 대로 오류의 첫 줄과 거기에 표시된 파일을 확인하세요. WP Admin에 **WCPOS Pro를 불러오지 못했습니다. composer install을 실행하세요.** 라고 표시된다면 zip 파일에 Pro의 일부가 빠져 있는 것입니다. [다운로드](https://wcpos.com/account/downloads)에서 다시 내려받아 업로드하세요. [Pro 플러그인 설치](../../getting-started/pro-license.mdx#installation)를 참고하세요.
