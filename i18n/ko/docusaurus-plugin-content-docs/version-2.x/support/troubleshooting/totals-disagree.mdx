POS는 계산대에서 모든 합계를 계산한 다음 주문을 매장에 저장합니다. 매장은 합계를 다시 계산합니다. 두 결과가 일치하지 않으면 장바구니와 결제 화면에 **매장에서 이 주문의 합계를 변경했습니다**라는 경고가 표시됩니다.

## 알림의 의미 {#what-the-notice-means}

상품을 건네기 전에 고객과 합계를 확인하세요. 판매가 차단되거나 데이터가 손실되지는 않습니다. 주문에는 매장에서 계산한 금액이 유지되며, WooCommerce 보고서와 고객의 주문에도 이 금액이 표시됩니다. 그런 다음 [세 가지 확인 절차를 시작](#first-resync-the-pos)하여 POS와 매장의 계산 결과를 다시 일치시키세요.

:::warning 해결될 때까지 이 매장에서 오프라인 판매를 하지 마세요
오프라인에서도 POS는 같은 방식으로 계산하지만, 매장이 계산 결과를 바로잡을 수 없습니다. 원인을 찾기 전에는 이 매장의 오프라인 판매에 잘못된 합계가 적용될 수 있으며, 연결이 복구될 때까지 이를 알 수 없습니다.
:::

알림은 장바구니 항목 아래, 합계 바로 위에 표시되며 변경된 내용을 나열합니다:

- **매장에서 계산한 금액이 기준입니다. 상품을 건네기 전에 합계를 확인하세요.** — 제목 아래에 표시되는 문구입니다.
- 변경된 금액마다 한 행씩 표시됩니다. **합계**, **세금**, **상품 세금**, **할인**, **할인 세금**, **배송비** 또는 **배송비 세금**이 각각 계산대 금액 → 매장 금액 순서로 표시됩니다.
- **N개 항목의 금액도 다릅니다** — 개별 항목의 금액도 변경된 경우입니다. 해당 항목을 나열하지 않고 개수만 표시합니다.
- **합계가 다른 이유** — 이 페이지를 엽니다.

이 알림은 닫을 수 없습니다. 주문이 장바구니에서 제거되거나 다른 매장으로 전환할 때까지 해당 주문에 표시됩니다. WCPOS를 닫아도(브라우저에서는 페이지를 새로고침해도) 알림은 사라지지만 원인은 해결되지 않습니다.

## 먼저 POS에 매장 설정이 반영되어 있는지 확인하세요 {#first-resync-the-pos}

POS는 매장 설정과 세율의 사본을 자체적으로 보관합니다. WooCommerce에서 설정을 변경했는데 이 사본이 최신 상태가 아니면 두 결과가 일치하지 않습니다. 다음 절차를 순서대로 진행한 다음 [시험 판매를 해 보세요](#test-sale). WooCommerce와 설정을 비교하려면 `WP Admin` 접근 권한이 필요합니다. 권한이 없다면 매장 관리자에게 이 페이지를 보여주세요.

1. [WooCommerce에서 설정한 세금 항목 확인](#check-set-in-woocommerce)
2. [서버 설정 복원](#restore-server-settings)
3. [세율 다시 가져오기](#refresh-tax-rates)

### 1. WooCommerce에서 설정한 세금 항목 확인 {#check-set-in-woocommerce}

메뉴 하단의 **설정**을 열고 **세금**을 선택하세요.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[245,0],[245,0],[245,0],[245,0],[0,-28]]} alt="설정의 세금 화면: 세금 계산 기준, 그 아래 세금 활성화, 세금 포함 가격 입력, 배송 세금 클래스, 소계 수준에서 세금 반올림 항목에 각각 WooCommerce에서 설정 표시와 열기 링크가 있습니다">

1. **세금 활성화** — 끄면 모든 판매에 세금이 부과되지 않습니다.
2. **세금 포함 가격 입력** — 입력한 가격에 세금이 이미 포함되어 있는지 여부입니다.
3. **배송 세금 클래스** — 배송에 적용되는 세금 클래스입니다.
4. **소계 수준에서 세금 반올림** — 켜면 주문 전체의 세금을 한 번 반올림하고, 끄면 항목별로 반올림합니다. 항목이 여러 개인 주문에서는 합계에 한두 센트 차이가 생깁니다.
5. **열기** — 브라우저에서 WooCommerce의 세금 설정을 엽니다. 네 항목 각각에 이 링크가 있습니다.

</JourneyShot>

이 네 항목은 [WooCommerce에서 설정](../../settings/store/tax.mdx#set-in-woocommerce)하며 POS에서는 변경할 수 없습니다. `WP Admin > WooCommerce > 설정 > Tax`과 일치하는지 확인하세요. POS는 매장을 불러올 때마다 이 설정을 다시 읽으므로 WooCommerce에서 설정을 변경한 후에는 WCPOS를 닫았다가 다시 여세요(브라우저에서는 페이지를 새로고침하세요). 그 위의 **세금 계산 기준**은 세율을 결정할 주소를 선택하는 항목입니다. [세금 계산 기준](../../settings/store/tax.mdx#calculate-tax-based-on)을 참고하세요.

### 2. 서버 설정 복원 {#restore-server-settings}

일부 설정은 한 번만 복사되므로 이 기기에서 변경한 값이 유지됩니다. POS가 매장 판매의 세금을 계산할 때 사용하는 매장 주소도 여기에 포함됩니다. WooCommerce에서 매장 주소를 변경했더라도 복원하기 전까지 POS는 이전 주소를 유지합니다.

**설정**을 열고 **일반**을 선택한 다음 맨 아래로 스크롤하세요. **서버 설정 복원**을 누르고 대화 상자에서 다시 **서버 설정 복원**을 누르세요. 버튼 옆에 **복원됨**이 표시됩니다. 변경되는 내용은 [서버 설정 복원](../../settings/store/general.mdx#restore-server-settings)을 참고하세요.

### 3. 세율 다시 가져오기 {#refresh-tax-rates}

메뉴 하단의 맥박 아이콘으로 **매장 상태**를 열고 **데이터베이스**를 선택하세요. **세율** 행에서 **⋮** 를 누르세요.

<JourneyShot manifest={manifest} device="tablet" step={2} alt="매장 상태의 데이터베이스 화면: 세율 행의 메뉴가 열려 있으며 지금 변경 사항 확인과 지우고 다시 다운로드가 표시됩니다">

1. **지금 변경 사항 확인** — 다음 확인 시점까지 기다리지 않고 매장에 새로 추가되거나 변경된 세율을 즉시 요청합니다.
2. **지우고 다시 다운로드…** — 이 기기에 저장된 세율 사본을 삭제하고 다시 다운로드합니다. 매장에는 세율이 그대로 유지됩니다. **지금 변경 사항 확인**으로 해결되지 않을 때 사용하세요.

</JourneyShot>

[지금 확인하거나 지우고 다시 다운로드](../store-health.mdx#clear-and-redownload)를 참고하세요.

### 시험 판매 {#test-sale}

실제로 결제를 받을 필요는 없습니다.

1. 알림이 표시된 판매와 동일한 상품, 동일한 고객 또는 과세 주소로 새 주문을 만드세요.
2. **결제** 옆의 **⋮** 를 누른 다음 **주문 동기화**를 누르세요. 주문이 매장으로 전송되고 매장에서 합계를 다시 계산합니다. [주문 동기화](../../pos/cart/order-actions.mdx#sync-order)를 참고하세요.
3. **주문 #… 동기화됨**이 표시될 때까지 기다리세요. 이 메시지가 표시되기 전에는 매장이 아직 응답하지 않은 상태이므로, 알림이 없다고 해서 문제가 해결된 것은 아닙니다. 동기화에 실패하면 연결 문제를 해결한 다음 다시 동기화하세요.
4. 장바구니 항목 아래를 확인하세요. 합계가 일치하고 알림이 표시되지 않으면 시험 판매를 통과한 것입니다.
5. 시험 주문을 [무효화](../../pos/cart/order-actions.mdx#void)하세요. WooCommerce의 휴지통으로 이동합니다.

`WP Admin > WooCommerce > 설정 > Tax`에서 설정을 변경할 때마다 세 가지 확인 절차를 다시 진행하세요.

<details>
<summary>WooCommerce Tax를 사용하나요? 새로운 지역의 첫 판매에서는 차이가 생길 수 있습니다</summary>

[WooCommerce Tax](../../integrations/woocommerce-tax.mdx#what-to-expect)의 자동 세금을 켜면, 매장에서 한 번도 세금을 부과한 적 없는 지역의 첫 판매에서 알림이 한 번 표시될 수 있으며 해당 관할 지역의 세율이 변경되면 다시 한 번 표시될 수 있습니다. 그 판매를 통해 세율 행이 생성되므로 POS에는 아직 해당 세율이 없었기 때문입니다. POS는 다음 확인 시점에 해당 세율을 다운로드합니다. 보통 일 분 이내에 이루어지며, 그 지역의 다음 판매부터는 합계가 일치합니다. **세율** 행의 **지금 변경 사항 확인**을 누르면 즉시 가져옵니다. 고객 주소를 기준으로 과세하는 경우 새로운 우편번호마다 한 번씩 이런 일이 발생할 수 있습니다.

</details>

시험 판매에서도 알림이 계속 표시되면 아래 원인을 확인하세요.

## 발생 원인 {#what-causes-it}

원인은 세 가지입니다. 어느 경우든 알림은 동일하게 표시됩니다. 해당하는 원인이 없다면 [자세한 정보를 보내주세요](#what-to-send-us).

### POS가 다르게 해석하는 세금 설정 또는 세율 {#a-tax-or-rounding-setting}

가장 흔한 원인입니다. WooCommerce에서 다음 항목을 확인하세요:

- **세금 포함 가격 입력** — `WP Admin > WooCommerce > 설정 > Tax`에 있습니다.
- **소계 수준에서 세금 반올림** — 같은 페이지에 있습니다. POS는 매장의 값을 사용합니다. **설정 > 세금**에 회색으로 표시되며 POS에서는 변경할 수 없습니다.
- **세율** — **우선순위** 또는 **복합** 설정이 예상과 다른 세율이나 우편번호별 또는 도시별로 설정된 세율을 확인하세요.
- **소수 자릿수** — `WP Admin > WooCommerce > 설정 > General`에 있습니다. POS는 매장의 자릿수에 맞춰 반올림합니다. POS에서 **소수 자릿수**를 변경하면 금액의 표시 방식만 바뀝니다.

매장에서 최근 이 중 하나를 변경했다면 해당 설정부터 살펴보세요.

### 주문 합계를 변경하는 플러그인 {#a-plugin-that-rewrites-totals}

추가 요금, 수수료, 통화, 고객 보상, 역할별 가격 플러그인은 POS가 자체 계산을 마친 후 매장에서 합계를 다시 계산하는 경우가 많습니다. POS는 이러한 규칙을 알 수 없으므로 해당 플러그인이 영향을 미치는 모든 판매에서 합계가 불일치합니다.

의도한 동작이라면 문제가 있는 것은 아닙니다. 매장은 판매를 올바르게 기록합니다. 다만 POS는 매장에 있는 규칙을 복사할 수 없으므로, 해당 플러그인이 영향을 미치는 모든 판매에서 알림이 표시되며 사라지지 않습니다. 같은 이유로 해당 매장의 오프라인 판매 금액도 매장에서 청구할 금액과 일치하지 않습니다.

어떤 플러그인인지 찾으려면 [플러그인 충돌](plugin-conflicts.mdx)을 참고하세요.

### POS의 버그 {#a-bug-in-the-pos}

[위의 세 가지 확인 절차](#first-resync-the-pos)를 마친 후에도 합계가 일치하지 않고 합계를 변경하는 플러그인도 없다면, 조사할 수 있도록 [아래 정보를 보내주세요](#what-to-send-us).

## 여러 판매에서 발생하는 경우 {#when-it-happens-on-several-sales}

알림이 한 번 표시되면 해당 판매를 확인해야 합니다. 이 매장에서 WCPOS를 연 이후 서로 다른 판매 세 건에서 합계가 불일치하면 알림에 다음 두 줄이 추가됩니다:

- **N건의 판매에서 이 문제가 발생했습니다**
- **매장과 POS가 합계를 다르게 계산하고 있습니다. 매장 관리자에게 이 내용을 보여주세요.**

저장 횟수가 아닌 판매 건수를 셉니다. 같은 주문을 다시 저장해도 건수는 늘어나지 않습니다.

[WooCommerce Tax](../../integrations/woocommerce-tax.mdx#what-to-expect)를 사용하는 매장에서는 문제가 없어도 세 건에 도달할 수 있습니다. 새로운 우편번호마다 첫 판매에서 한 번씩 합계가 불일치할 수 있기 때문입니다([시험 판매](#test-sale)의 **WooCommerce Tax를 사용하나요?** 참고). 각 우편번호의 다음 판매에서 합계가 일치하면 문제가 없습니다. 같은 지역의 이후 판매에서도 계속 불일치하면 매장 관리자에게 [위의 원인](#what-causes-it)을 차례로 확인해 달라고 요청하세요.

<details>
<summary>다른 알림: 결제를 받기 전에 이 주문의 금액을 확인하세요</summary>

같은 알림 상자에 두 번째 메시지가 단독으로 표시되거나 **매장에서 이 주문의 합계를 변경했습니다** 아래에 표시될 수 있습니다. 이는 POS가 주문 합계를 계산하는 데 필요한 정보를 읽지 못했다는 뜻입니다. 이 메시지에는 **합계가 다른 이유** 링크가 없습니다.

- **항목에 저장된 가격 정보를 읽지 못했습니다** — 해당 항목을 삭제한 다음 다시 추가하세요.
- **이 주문은 매장에 더 이상 없는 세율을 사용합니다** — 항목이 추가된 후 WooCommerce에서 해당 세율이 삭제된 경우입니다. 결제를 받기 전에 주문의 세금을 확인하세요.

</details>

## 지원팀에 보낼 정보 {#what-to-send-us}

알림에는 변경된 금액마다 양쪽의 금액이 모두 표시됩니다. 여기에 아래 정보를 함께 보내주시면 대부분 화면을 공유하지 않아도 원인을 찾을 수 있습니다:

1. 금액이 보이는 알림 스크린샷.
2. [위의 세 가지 확인 절차](#first-resync-the-pos)를 진행했지만 알림이 다시 표시되었다는 사실.
3. 세금 설정: 자동 세금 사용 여부를 포함한 `WP Admin > WooCommerce > 설정 > Tax`의 모든 필드와 **일반**의 **소수 자릿수**.
4. **소계 수준에서 세금 반올림**의 사용 여부.
5. 설정 페이지뿐 아니라 **세율 표 자체**도 필요합니다. 각 세금 클래스 아래의 행에 있는 **국가**, **주**, **우편번호**, **도시**, **세율 %**, **우선순위**, **복합**, **배송**을 포함하세요. 대부분의 원인은 이 행들에 있으므로, 빠져 있으면 다시 요청해야 합니다.
6. 가격, 세금, 수수료 또는 통화에 영향을 미치는 활성 플러그인.
7. 알림이 표시된 판매의 주문 번호.
8. **매장 상태 → 로그**의 **매장 합계가 계산대와 다릅니다** 행과 해당 이벤트 코드. [로그](../logs.mdx#for-support)를 참고하세요.
