매장이 계산대에 늦게 응답하면 결제가 느려집니다. 한 번의 판매에서 매장의 응답을 두 번 기다립니다. **결제**를 누르면 주문이 매장에 저장되고, **받기**를 누르면 매장에 결제가 기록된 후 영수증이 표시됩니다. 이 페이지에서는 계산대가 기다리는 단계와 매장 응답 시간 측정 방법, 변경할 사항을 안내합니다.

:::note 캐셔: 측정 후 담당자에게 전달하세요
문제 해결 작업은 웹사이트에서, 주로 WP Admin에서 수행합니다. 웹사이트 운영자가 아니라면 [테스트 판매 시간을 측정](#time-a-sale)하고 측정값과 이 페이지 링크를 운영자에게 보내세요.
:::

## 테스트 판매 시간 측정하기 {#time-a-sale}

변경 전후에 테스트 판매 시간을 측정하여 효과를 확인하세요. 각 측정값은 계산대가 매장의 응답을 기다리는 시간입니다:

1. **결제**를 누른 시점부터 **받기** 버튼의 **주문 저장 중…** 문구가 사라질 때까지 측정하세요.
2. 결제한 다음, 결제 방식에 따라 대기 시간을 측정하세요:
   - **현금, 카드 또는 계산대에서 기록하는 다른 결제** — **받기**를 누른 시점부터 영수증이 표시될 때까지입니다.
   - **카드 리더기** — 타일을 누른 시점부터 **단말기에서 처리 중** 단계에 도달할 때까지, 그리고 **승인됨**부터 영수증이 표시될 때까지를 각각 측정합니다. 고객이 리더기를 사용하는 시간은 제외하세요.
   - **레거시 탭** — 탭을 연 시점부터 **결제 처리**를 누를 수 있을 때까지입니다.
3. [매장 상태 → 성능](#store-health)의 **평균 응답 시간**을 적어 두세요.

사용하는 각 결제 방식에 대해 2단계를 반복하고, 테스트 사이에는 한 번에 하나만 변경하세요. 각 측정값의 의미는 [계산대가 기다리는 단계](#where-it-waits)에서 설명합니다. 실제 판매에 사용하는 기기와 연결 환경에서 측정하세요. 다른 기기나 네트워크에서는 시간이 다를 수 있습니다.

## 계산대가 매장 응답을 기다리는 단계 {#where-it-waits}

**결제** — 주문이 매장에 저장됩니다. 결제 화면은 즉시 열리지만 매장이 응답할 때까지 키패드가 반응하지 않고 **받기** 버튼에 **주문 저장 중…** 이 표시됩니다. 4초가 지나면 매장이 응답하지 않는다는 메시지가 표시됩니다. [조치 방법](#store-not-answering)을 참고하세요.

현금, 카드 또는 계산대에서 기록하는 다른 결제의 **받기** — 매장에 결제가 기록된 후 영수증이 표시됩니다. 매장이 응답하지 않으면 계산대가 1초, 3초, 9초 후에 다시 요청합니다. 그래도 응답이 없으면 [조치 방법](#payment-not-answered)을 참고하세요.

**카드 리더기 타일** — 먼저 매장에서 결제를 생성합니다. 그러면 타일이 **단말기에서 처리 중** 단계로 넘어가고 **단말기에서 고객 대기 중**이 표시됩니다. 이 계산대에 직접 연결된 리더기에는 **리더기에 카드를 대세요**가 표시됩니다. 기다리는 동안 계산대가 매장에 계속 연결하지 못하면 타일에는 해당 메시지가 유지되고 **세부 정보** 로그에 **연결이 불안정합니다. 계속 시도 중입니다**가 추가됩니다. 리더기에서 승인되면 매장이 결제를 확인하는 동안 타일에 **승인됨**이 표시되고, 이후 영수증이 표시됩니다. [결제 받기](../../pos/checkout/taking-a-payment.mdx#card-reader)를 참고하세요.

**레거시 탭** — 매장에서 결제 페이지를 보냅니다. 로딩 표시가 나타나고, 페이지가 로드될 때까지 **결제 처리**는 비활성화된 상태로 유지됩니다. 로드되지 않으면 [조치 방법](#payment-form-didnt-load)을 참고하세요. [레거시 탭](../../pos/checkout/legacy-tab.mdx)도 참고하세요.

각 대기 단계는 매장에 보내는 요청이므로 매장 응답이 느리면 모든 판매가 느려집니다. 오프라인에서 계산대에 기록하는 결제는 기다리지 않습니다. 판매 내역은 이 기기에 보관되었다가 매장이 다시 연결되면 전송됩니다. [오프라인 모드](../../getting-started/offline.mdx)를 참고하세요.

## 매장 응답 시간 측정하기 {#measure}

테스트 판매로는 한 번의 판매 시간을 측정합니다. **매장 상태**에서는 하루 동안 매장이 이 계산대에 어떻게 응답했는지 확인할 수 있습니다.

### 매장 상태 → 성능 {#store-health}

**매장 상태 → 성능**은 지난 24시간 동안 매장이 이 계산대에 얼마나 빠르게 응답했는지 보여 줍니다.

1. **매장 상태** — 메뉴 하단 근처의 맥박 아이콘입니다.
2. **성능** — 이 탭입니다.
3. **상태 표시줄** — 이 계산대가 지난 24시간 동안 보낸 요청과 **평균 응답 시간**, 즉 모든 요청에 대해 매장이 응답하는 데 걸린 평균 시간을 표시합니다. [테스트 판매](#time-a-sale)에서 측정한 시간과 비교하세요.
4. **엔진 가동 상태** — 한 칸이 한 시간을 나타냅니다. 주황색이면 해당 시간에 매장으로 보낸 요청이 하나 이상 실패했다는 뜻입니다.
5. **균형** — 이 계산대가 매장의 변경 사항을 확인하는 주기를 나타냅니다. 공유 호스팅이나 저가 호스팅에서는 **절약**을 사용하면 요청 빈도를 낮춰 매장이 판매를 처리할 여유를 확보할 수 있습니다. [동기화 프리셋](../store-health.mdx#sync-presets)을 참고하세요.
6. **변경 사항 확인** — 같은 설정을 슬라이더로 조정하며, 범위는 5초부터 5분까지입니다.
7. **현재** — 이 설정으로 발생하는 시간당 대략적인 요청 수입니다.

## 저장 및 결제 속도 높이기 {#saving}

다음과 같은 원인을 하나씩 확인하고, 변경할 때마다 [테스트 판매 시간을 다시 측정하세요](#time-a-sale).

### 주문 저장 방식 {#order-storage}

WooCommerce에서 아직 주문을 WordPress 글에 저장하는 기존 저장 방식을 사용한다면 매장이 커질수록 결제 시 저장 속도가 느려집니다. 사용 중인 저장 방식을 확인하고 HPOS로 전환하세요. [주문 저장 방식(HPOS)](./order-storage.mdx)을 참고하세요.

### 주문 저장 시 실행되는 플러그인 {#2-plugin-interference-during-order-creation}

일부 플러그인은 주문이 저장되거나 결제될 때마다 자체 작업을 수행하며, 계산대는 해당 작업이 끝날 때까지 기다립니다. 예를 들어 주문을 Xero로 보내는 회계 플러그인이 있으면 판매할 때마다 Xero가 응답할 때까지 기다려야 합니다. 웹사이트 복사본에서 플러그인을 하나씩 끄면 원인을 찾을 수 있습니다.

<details>
<summary>원인 플러그인 찾는 단계</summary>

주문마다 작업을 수행하는 경우가 많은 플러그인:

- 회계 및 장부 관리(Xero, QuickBooks)
- 새 주문에 반응하는 이메일 마케팅 도구
- 재고 관리 시스템
- 배송비 계산 도구
- 분석 및 추적

원인 플러그인을 찾으려면:

1. [스테이징 사이트](../troubleshooting/plugin-conflicts.mdx#before-you-start-use-a-staging-site)에서 WooCommerce와 WCPOS를 제외한 모든 플러그인을 끄세요.
2. [테스트 판매 시간을 측정하세요](#time-a-sale).
3. 훨씬 빨라졌다면 플러그인을 하나씩 다시 켜고, 켤 때마다 판매 시간을 측정하여 다시 느려지는 지점을 찾으세요.
4. 해당 플러그인 개발자에게 작업을 백그라운드에서 실행할 수 있는지 문의하세요.

전체 방법은 [플러그인 충돌](../troubleshooting/plugin-conflicts.mdx#step-2-the-plugin-elimination-method)에 있습니다.

</details>

### 호스팅 {#hosting}

결제 시간뿐 아니라 **평균 응답 시간**도 느리다면 서버 리소스가 부족할 수 있습니다. 호스팅 업체가 조사할 수 있도록 [테스트 판매](#time-a-sale)에서 측정한 시간과 **서버 부하** 수치를 전달하세요. 권장 사양은 [서버 성능](./server.mdx)을 참고하세요.

<details>
<summary>호스팅 업체에 문의할 사항</summary>

- 판매 중 CPU 및 메모리 사용량
- PHP 메모리 제한과 PHP 워커 수
- 느린 데이터베이스 쿼리와 정리할 수 있는 오래된 데이터
- 객체 캐싱(본격적으로 사용하기 전에 POS에서 테스트하세요)
- 상위 요금제 또는 공유 호스팅 대신 VPS 사용

</details>

## 레거시 탭의 결제 페이지 속도 높이기 {#legacy-page}

**레거시** 탭의 결제 게이트웨이만 결제 시 웹페이지를 로드합니다. 고객이 온라인에서 주문 금액을 결제할 때 사용하는 WooCommerce 페이지를 간소화한 것으로, 웹사이트에서 매번 전송합니다. 테마의 머리글, 바닥글, 레이아웃은 이미 제거되어 있지만 테마와 플러그인이 모든 페이지에 추가하는 스타일과 스크립트는 여전히 로드되므로 페이지가 느려지거나 제대로 작동하지 않을 수 있습니다. 로드할 항목은 상점 관리자가 변경해야 합니다. 계산대에서 페이지가 로드되지 않으면 [조치 방법](#payment-form-didnt-load)을 참고하세요.

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[28, 34], [28, 34], [337, -273], [-30, 0], [-30, 0]]} alt="결제 화면의 레거시 탭: 매장에서 보낸 결제 페이지 오른쪽 상단에 결제 설정 버튼이 있고, 페이지 아래에 결제 처리 버튼이 있습니다">

1. **결제** — 앱의 현금, 카드, 카드 리더기 및 기타 타일입니다. 웹페이지를 로드하지 않습니다.
2. **레거시** — 매장 자체 결제 페이지에서 실행되는 결제 게이트웨이입니다.
3. **결제 설정** — 이 페이지에서 로드할 스타일과 스크립트를 선택하는 양식을 엽니다. 양식 주변의 페이지는 웹사이트에서 전송합니다.
4. **결제 처리** — 페이지가 로드될 때까지 비활성화됩니다.
5. **✕** — 주문을 유지한 채 장바구니로 돌아갑니다.

</JourneyShot>

이 페이지에서 스타일과 스크립트를 제거하려면:

1. 상점 관리자 또는 관리자로 POS에 로그인하세요. 캐셔는 양식을 열 수 있지만 저장할 수는 없습니다.
2. **결제**를 누르고 **레거시** 탭을 연 다음 결제 페이지에서 **결제 설정**을 누르세요.
3. 스타일이나 스크립트의 선택을 해제하면 제거됩니다. 클래식 테마의 `classic-theme-styles` 같은 테마 스타일부터 시작한 다음, `selectWoo`처럼 결제 게이트웨이에 필요하지 않은 스크립트를 제거하세요.
4. **제출**을 누른 다음 사용하는 각 레거시 결제 게이트웨이로 테스트 결제를 해 보세요.

<details>
<summary>결제 설정 양식에 표시되는 내용</summary>

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[28, 34], [-28, 0]]} alt="레거시 탭의 결제 페이지에서 연 결제 설정 양식: 상단에 wp_head 비활성화와 wp_footer 비활성화가 있고, 그 아래에 스타일 목록과 스크립트 목록이 나란히 표시되며, 항상 제거되는 항목은 회색으로 표시됩니다">

1. **레거시** — 이 양식이 속한 탭입니다.
2. **결제 설정** — 결제 페이지 위에 표시되는 양식입니다. 페이지의 모든 스타일과 스크립트에 체크박스가 있으며, 로드되는 항목은 선택되어 있습니다.

</JourneyShot>

양식은 위에서부터 세 부분으로 구성됩니다:

- **모든 스타일 및 스크립트 비활성화** — **wp_head 비활성화**와 **wp_footer 비활성화**는 페이지의 머리글이나 바닥글에서 로드하는 모든 항목을 제거하며, 결제 양식에 필요한 항목도 포함됩니다. 스타일과 스크립트가 원인인지 테스트할 때만 사용하세요.
- 왼쪽의 **선택한 스타일 비활성화** — 스타일마다 항목이 하나씩 있습니다. 테마 스타일은 `twentytwentyfive-style`처럼 테마 이름을 따서 명명됩니다.
- 오른쪽의 **선택한 스크립트 비활성화** — 스크립트마다 항목이 하나씩 있습니다.

끝에 *POS 결제 페이지에서 항상 제거됨*이 붙은 회색 항목은 이미 제거되어 있으며 선택할 수 없습니다.

</details>

:::warning 결제 게이트웨이에 필요한 항목은 유지하세요
스크립트를 제거한 후 결제 수단이 작동하지 않으면 다시 선택하고 **제출**을 누르세요.
:::

<details>
<summary>WCPOS가 자동으로 제거하는 항목과 개발자용 옵션</summary>

결제 페이지에서는 관리자 표시줄, WordPress가 페이지 머리글에 추가하는 링크, 다음 WooCommerce 스타일과 스크립트가 항상 제거됩니다:

- 스타일: `admin-bar`, `woocommerce-general`, `woocommerce-inline`, `woocommerce-layout`, `woocommerce-smallscreen`, `woocommerce-blocktheme`, `wp-block-library`
- 스크립트: `admin-bar`, `wc-add-to-cart`
- WooCommerce Stripe 11.1.1 이전 버전에서는 해당 플러그인의 `wc-stripe-upe-classic` 스크립트와 스타일, `stripelink_styles`도 제거됩니다.

개발자 참고 사항:

- 양식을 저장하려면 `manage_woocommerce` 권한이 필요합니다.
- `wcpos_payment_template_dequeue_style_handles`와 `wcpos_payment_template_dequeue_script_handles` 필터로 제거 목록에 핸들을 추가할 수 있습니다.
- 템플릿을 `yourtheme/woocommerce-pos/payment.php`에 복사하여 재정의할 수 있습니다. 원본은 플러그인의 [templates/payment.php](https://github.com/wcpos/woocommerce-pos/blob/main/templates/payment.php)입니다.
- `wp_enqueue_style`과 `wp_enqueue_script`로 추가된 스타일과 스크립트만 제거할 수 있습니다. 테마나 플러그인이 코드를 페이지에 직접 출력하는 경우에는 이 방법으로 제거할 수 없습니다. 개발자에게 해당 함수를 통해 추가하도록 요청하거나, 해당 플러그인 또는 테마의 자체 훅으로 제거하세요. 테마인 경우 자식 테마에서 작업하세요.

</details>

## 문제가 발생한 경우 {#goes-wrong}

### 매장이 응답하지 않습니다 {#store-not-answering}

*"매장이 응답하지 않습니다. 계속 기다리거나 장바구니로 돌아가세요."* 매장에서 주문을 저장하는 데 4초 넘게 걸리고 있습니다. 계속 기다리거나 **✕** 를 눌러 주문을 유지한 채 장바구니로 돌아가세요. 이 메시지가 자주 나타나면 [테스트 판매 시간을 측정](#time-a-sale)하고 [저장 및 결제 속도 높이기](#saving)에서 원인을 확인하세요.

### 매장이 마지막 결제에 응답하지 않았습니다 {#payment-not-answered}

*"매장이 마지막 결제에 응답하지 않았습니다. 다시 시도하여 확인하세요. 이중으로 결제되지 않습니다."* **다시 시도**를 누르세요.

### 결제 양식을 불러오지 못했습니다 {#payment-form-didnt-load}

*"결제 양식을 불러오지 못했습니다 — 매장 연결을 확인한 다음 다시 시도하세요."* 레거시 탭이 결제 페이지를 90초 동안 기다린 뒤 새로고침하고, 다시 90초를 기다렸지만 불러오지 못했습니다. 연결을 확인하고 **재시도**를 누르세요. 매번 페이지가 느리다면 [레거시 탭의 결제 페이지 속도 높이기](#legacy-page)를 참고하세요.

### 결제 설정을 수정할 권한이 없습니다 {#no-permission}

*"결제 설정을 수정할 권한이 없습니다."* 캐셔 계정으로 **결제 설정**에서 **제출**을 눌렀습니다. 상점 관리자 또는 관리자로 로그인하세요.

### 여전히 느린 경우 {#still-slow}

이 조치를 모두 취한 후에도 결제에 계속 10초 넘게 걸리거나 플러그인이 의심되지만 원인을 찾지 못했다면 [Discord](https://wcpos.com/discord)에 문의하세요. **매장 상태 → 로그**에서 **디버그 정보 복사**를 누르고 [테스트 판매](#time-a-sale)에서 측정한 시간 및 시도한 조치와 함께 붙여넣으세요. [도움말 및 문제 해결](../index.mdx)을 참고하세요.

:::info WCPOS Pro 사용 시
현금과 카드 이외의 결제 게이트웨이에는 [WCPOS Pro](../../getting-started/pro-license.mdx)가 필요합니다.
:::
