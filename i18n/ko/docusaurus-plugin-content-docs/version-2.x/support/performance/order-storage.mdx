**증상:** WCPOS에서 결제에 몇 초씩 걸리며 시간이 지날수록 점점 느려집니다.

:::note 단말기가 아닌 WordPress 관리자에서 진행합니다
이 작업은 WordPress 관리자에서 한 번만 진행하면 됩니다. WooCommerce 설정에 접근할 수 있어야 합니다. 권한이 없다면 웹사이트 관리자에게 아래 절차를 진행해 달라고 요청하세요. 결제가 느리다고 설명하고 이 페이지를 보내세요.
:::

흔한 원인 중 하나는 WooCommerce가 주문을 저장하는 방식입니다. 매장에서 사용하는 저장 방식을 확인하고, 기존 방식이라면 WooCommerce 자체 도구로 고성능 주문 저장소(HPOS)로 전환하세요.

## 매장의 주문 저장 방식 확인하기 {#check-which-storage-your-store-uses}

1. WordPress 관리자에서 **WooCommerce → 설정 → 고급 → 기능**으로 이동하세요.
2. **주문 데이터 저장소**를 찾으세요:
   - **고성능 주문 저장소(권장)** 가 선택된 경우: 이미 HPOS를 사용하고 있으므로 저장 방식이 원인은 아닙니다. [결제가 느려지는 다른 원인](#other-causes-of-slow-checkout)을 참고하세요.
   - **WordPress 게시물 저장소(레거시)** 가 선택된 경우: 아래 절차에 따라 HPOS로 전환하세요. 모든 결제에서 느렸던 단계가 빨라지며([이유](#why-legacy-order-storage-slows-checkout)), 매장 규모가 클수록 효과가 큽니다.

이 매장은 이미 HPOS를 사용하고 있습니다:

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[77, 0], [80, 0], [186, 18]]} alt="WooCommerce 설정의 고급 탭에 있는 기능 페이지: 주문 데이터 저장소에서 고성능 주문 저장소가 선택되어 있고 호환성 모드 활성화는 선택 해제되어 있으며 그 아래에 다른 기능이 표시됩니다">

1. **고급** — **WooCommerce → 설정**의 마지막 탭입니다.
2. **기능** — 탭 아래에 있는 마지막 링크입니다.
3. **주문 데이터 저장소** — 선택된 옵션이 매장에서 사용하는 저장 방식입니다. 여기서는 **고성능 주문 저장소(권장)** 입니다. HPOS를 사용하는 매장에서는 **호환성 모드 활성화** 아래의 동기화 불일치 메시지를 무시해도 됩니다. 이 메시지는 [이전 방식으로 되돌릴](#switch-back) 때만 중요합니다.

</JourneyShot>

2023년부터 새 WooCommerce 매장은 HPOS를 사용하므로, 오래된 매장일수록 레거시 저장소를 계속 사용하고 있을 가능성이 높습니다.

:::tip WCPOS에서도 알려 줍니다
레거시 저장소를 사용하는 매장에서는 **POS → 설정 → [결제](../../settings/wp-admin/checkout.mdx)** 상단에 경고가 표시됩니다. 경고의 **WooCommerce 주문 저장소 설정 열기** 링크를 누르면 기능 페이지로 바로 이동하고, **전환 방법**을 누르면 이 페이지로 돌아옵니다.
:::

## HPOS로 전환하기 {#switch-to-hpos}

WooCommerce가 주문을 옮겨 줍니다. 먼저 주문을 새 저장소로 복사(동기화)한 다음 저장 방식을 전환합니다. 복사가 완료될 때까지는 WooCommerce에서 전환할 수 없습니다.

:::warning 먼저 백업하세요
시작하기 전에 사이트와 데이터베이스를 전체 백업하고 복원할 수 있는지 확인하세요. [스테이징 사이트](../troubleshooting/plugin-conflicts.mdx#before-you-start-use-a-staging-site)가 있다면 그곳에서 먼저 전환해 보세요.
:::

1. **WooCommerce → 설정 → 고급 → 기능**으로 이동하세요. 이 페이지의 경고에 HPOS와 호환되지 않는 플러그인이 표시되면 먼저 해당 문제를 해결하세요. [고성능 주문 저장소만 비활성화되어 있습니다](#goes-wrong)를 참고하세요.
2. **호환성 모드 활성화**를 선택하고 **변경 사항 저장**을 클릭하세요. WooCommerce가 백그라운드에서 주문 복사를 시작합니다. 규모가 큰 매장에서는 시간이 걸릴 수 있습니다. 체크박스 아래에 **현재 주문 동기화 중...** 과 아직 대기 중인 주문 수가 표시되어 진행 상황을 알 수 있습니다.
3. **호환성 모드 활성화** 아래의 메시지가 사라질 때까지 가끔 페이지를 새로고침하세요. 메시지가 사라지면 복사가 완료된 것입니다. 대신 **현재 동기화되지 않은 주문이 있습니다.** 메시지가 표시되면 **지금 주문 동기화**를 클릭하세요. 옵션이 계속 비활성화되어 있다면 [문제가 발생한 경우](#goes-wrong)를 참고하세요.
4. **고성능 주문 저장소(권장)** 를 선택하고 **변경 사항 저장**을 클릭하세요.
5. 모든 기능이 계속 정상적으로 작동하는지 확인하는 동안 **호환성 모드 활성화**를 선택한 상태로 두세요:
   - WCPOS에서 테스트 판매를 진행하고 완료되는지 확인하세요.
   - **WooCommerce → 주문**에서 해당 판매 내역을 찾으세요.
   - 회계, 배송, 이메일 플러그인 등 주문과 연동되는 플러그인에서 새 주문이 계속 표시되는지 확인하세요.

   호환성 모드가 켜져 있는 동안에는 두 저장소의 주문이 동기화된 상태를 유지하므로, 복사본이 최신 상태가 되면 [이전 방식으로 되돌릴](#switch-back) 수 있습니다.
6. 확인이 끝나면 **호환성 모드 활성화**를 선택 해제하고 **변경 사항 저장**을 클릭하세요. 이후에는 되돌리기 전에 먼저 주문을 이전 저장소로 다시 복사해야 합니다. [레거시 저장소로 되돌리기](#switch-back)를 참고하세요.

자세한 내용은 WooCommerce의 [고성능 주문 저장소](https://woocommerce.com/document/high-performance-order-storage/#how-to-enable-high-performance-order-storage) 가이드를 참고하세요.

## 레거시 저장소로 되돌리기 {#switch-back}

전환 후 작동하지 않는 기능이 있다면 레거시 저장소로 되돌리세요. 다시 전환하기 전에 문제를 일으킨 플러그인을 찾으세요.

1. **WooCommerce → 설정 → 고급 → 기능**으로 이동하세요.
2. **호환성 모드 활성화**가 선택 해제되어 있다면 선택하고 **변경 사항 저장**을 클릭하세요. WooCommerce가 주문을 레거시 저장소로 다시 복사합니다.
3. **호환성 모드 활성화** 아래의 메시지가 사라질 때까지 기다리세요. 가끔 페이지를 새로고침하고, **지금 주문 동기화**가 표시되면 클릭하세요. 완료될 때까지 두 옵션 모두 비활성화된 상태로 유지됩니다.
4. **WordPress 게시물 저장소(레거시)** 를 선택하고 **변경 사항 저장**을 클릭하세요.

전환 이후 접수된 주문도 함께 옮겨집니다. 호환성 모드가 이 주문들도 레거시 저장소로 복사합니다.

## 문제가 발생한 경우 {#goes-wrong}

**전환하려는데 두 저장소 옵션이 모두 비활성화되어 있습니다.**
WooCommerce에서는 어느 방향으로든 두 저장소의 주문이 일치해야만 저장 방식을 변경할 수 있습니다. 아직 복사가 완료되지 않은 것입니다. **호환성 모드 활성화** 아래를 확인하세요:
- **현재 주문 동기화 중...** 과 숫자가 표시되는 경우: 복사가 진행 중입니다. 기다리면서 가끔 페이지를 새로고침하세요.
- **현재 동기화되지 않은 주문이 있습니다.** 메시지와 **지금 주문 동기화** 링크가 표시되는 경우: 복사가 실행되고 있지 않습니다. **지금 주문 동기화**를 클릭하고 복사가 완료될 때까지 기다린 다음 전환하세요.

이미 HPOS를 사용하고 호환성 모드가 꺼져 있는 매장에서는 저장 방식을 전환할 때가 아니라면 이 화면은 정상입니다. 여기서는 두 옵션이 모두 비활성화되어 있고 복사가 실행되고 있지 않습니다:

<JourneyShot manifest={manifest} device="desktop" step={2} offsets={[[262, 0], [362, 0], [-46, 0], [-44, 0]]} alt="주문 데이터 저장소 확대 화면: 고성능 주문 저장소가 선택된 채 두 저장소 옵션이 모두 비활성화되어 있고, 호환성 모드 활성화는 선택 해제되어 있으며, 그 아래에 현재 동기화되지 않은 주문이 있다는 메시지와 지금 주문 동기화 링크가 표시됩니다">

1. **WordPress 게시물 저장소(레거시)** — 복사가 완료될 때까지 비활성화됩니다.
2. **고성능 주문 저장소(권장)** — 선택되어 있으며, 이 옵션도 비활성화되어 있습니다.
3. **호환성 모드 활성화** — 아래 메시지에서 복사가 진행 중인지 알 수 있습니다.
4. **지금 주문 동기화** — 복사를 시작합니다.

</JourneyShot>

**고성능 주문 저장소만 비활성화되어 있습니다.**
활성 플러그인이 HPOS와 호환되지 않는 것으로 표시되어 있으면 WooCommerce가 전환을 차단합니다. 기능 페이지의 경고에 해당 플러그인과 **보기 및 관리** 링크가 표시됩니다. 전환하기 전에 플러그인을 업데이트하거나 개발자에게 HPOS 지원 여부를 문의하세요.

**전환 후 작동하지 않는 기능이 있습니다.**
[레거시 저장소로 되돌린](#switch-back) 다음, 다시 전환하기 전에 문제를 일으킨 플러그인을 찾으세요.

**전환 후에도 결제가 여전히 느립니다.**
주문 저장 방식만이 원인은 아니었던 것입니다. 아래 [결제가 느려지는 다른 원인](#other-causes-of-slow-checkout)을 참고하세요.

## 레거시 저장소에서 결제가 느려지는 이유 {#why-legacy-order-storage-slows-checkout}

레거시 저장소에서는 매장 규모가 커질수록 WCPOS에서 판매 내역을 저장하는 속도가 느려집니다. HPOS에서는 이러한 지연을 일으키는 주문 조회가 거의 즉시 완료됩니다. 호스팅이나 다른 플러그인 때문에 결제가 여전히 느릴 수 있습니다. [결제가 느려지는 다른 원인](#other-causes-of-slow-checkout)을 참고하세요.

<details>
<summary>얼마나 빨라지는지와 그 이유</summary>

WCPOS는 주문을 저장할 때마다 먼저 WCPOS가 부여한 ID로 해당 주문을 조회합니다. 레거시 저장소에서는 WooCommerce가 주문을 WordPress 게시물과 같은 테이블에 보관합니다. 이 테이블에는 해당 ID로 주문을 빠르게 찾을 방법이 없어 매장의 기록을 하나씩 확인합니다. HPOS는 주문을 전용 테이블에 보관하므로 동일한 조회가 거의 즉시 완료됩니다.

측정한 매장 한 곳(상품 및 변형 약 30,000개, 레거시 저장소 사용)에서는 조회 한 번에 약 0.46초가 걸렸고 결제 한 번에 조회가 약 두 번 발생했습니다. HPOS에서는 동일한 조회에 약 1밀리초가 걸렸습니다. 매장마다 결과는 다르지만 규모가 클수록 효과가 큽니다.

</details>

## WCPOS의 지원 범위 {#what-wcpos-supports}

- **HPOS는 완전히 지원되며 권장하는 방식입니다.**
- **레거시 저장소도 계속 사용할 수 있습니다.** 기능에는 문제가 없으며 규모가 큰 매장에서 결제만 더 느려집니다.

## 결제가 느려지는 다른 원인 {#other-causes-of-slow-checkout}

결제를 느리게 하는 요인은 주문 저장 방식만이 아닙니다. 이미 HPOS를 사용하고 있거나 전환 후에도 결제가 느리다면 다음을 확인하세요:

- **호스팅.** 서버가 바쁘거나 성능이 부족하면 모든 단계가 느려집니다. [서버 성능](./server.mdx)을 참고하세요.
- **주문을 저장할 때 실행되는 다른 플러그인**을 확인하세요. 회계, 이메일 마케팅, 재고 관리 플러그인 등이 해당합니다. [플러그인 충돌](../troubleshooting/plugin-conflicts.mdx)과 [결제 성능](./checkout.mdx#2-plugin-interference-during-order-creation)을 참고하세요.
