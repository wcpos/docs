결제 중 문제가 생겨 판매가 중단되었다면 계산대에 표시된 문구를 찾아 해당 항목의 안내를 따르세요. 결제를 받기 전에는 결제 화면 상단의 **✕** 를 누르면 주문을 유지한 채 장바구니로 돌아갑니다. 주문에 결제 내역이 생긴 후에는 **✕** 를 누르면 **결제 취소**가 열립니다. 카드 리더기가 아직 결제를 처리 중일 때 **✕** 를 누르면 결제를 취소하지 않고 장바구니로 돌아갑니다.

## 연결이 없거나 결제 수단이 보이지 않는 경우 {#needs-a-connection}

매장에 주문이 이미 있는지에 따라 표시되는 화면이 달라집니다.

- **오프라인에서 판매를 시작한 경우** 매장에 아직 주문이 없으므로 어떤 수단으로도 결제를 받을 수 없습니다. 결제 수단 대신 [연결 없음](#no-connection)이 표시됩니다.
- **연결이 끊기기 전에 주문이 매장에 전달된 경우** 현금과 카드는 계속 사용할 수 있으며 [나중에 전송 · 매장에서 거부할 수 있음](#sent-later)이 표시됩니다. 카드 리더기와 온라인 결제 게이트웨이는 **연결 필요**라는 안내와 함께 [접혀 표시됩니다](#not-available).

### 연결 없음 {#no-connection}

**"연결이 없습니다. 결제하려면 연결이 필요합니다. 판매는 진행 중인 주문에 저장되어 있습니다."** 계산대가 매장에 연결할 수 없으며, 연결 없이는 어떤 결제 수단으로도 이 판매의 결제를 받을 수 없습니다. 청구된 금액은 없습니다. **계산대로 돌아가기**를 누르세요. 판매가 장바구니에 유지되므로 다음 고객을 응대할 수 있습니다. 연결이 복구되면 해당 판매를 열고 **결제**를 다시 누르세요.

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[-12, -44], [145, 0], [25, -52], [-45, 0]]} alt="오프라인에서 시작한 판매의 결제 화면: 결제 수단 대신 연결 없음 안내와 계산대로 돌아가기 버튼이 표시되고, 머리글에는 오프라인, 판매 탭에는 결제 중 · 오프라인이 표시됨">

1. **연결 없음** — 계산대가 매장에 연결될 때까지 어떤 결제 수단으로도 이 판매의 결제를 받을 수 없습니다.
2. **계산대로 돌아가기** — 결제 화면에서 나가 다음 고객을 응대할 수 있습니다.
3. **결제 중 · 오프라인** — 이 판매의 탭입니다. 결제 화면에서 나가도 장바구니의 탭에 남아 있습니다.
4. **✕** — 주문을 유지한 채 장바구니로 돌아갑니다.

</JourneyShot>

사용하는 모든 결제 수단에 연결이 필요한 경우에는 매장에 이미 있는 주문에도 이 안내가 표시됩니다. 카드 리더기로만 결제를 받는 계산대가 그 예입니다. [연결이 필요한 기능](../../getting-started/offline.mdx#what-requires-a-connection)을 참고하세요.

### 나중에 전송 · 매장에서 거부할 수 있음 {#sent-later}

주문이 매장에 전달된 후 연결이 끊기면 현금과 카드는 계속 사용할 수 있습니다. 해당 타일에는 **나중에 전송 · 매장에서 거부할 수 있음**이 표시됩니다. 계산대가 결제를 바로 기록하고 매장에 다시 연결되면 전송합니다. **받기**를 누르면 먼저 확인을 요청합니다. [오프라인에서 결제 받기](../../getting-started/offline.mdx#take-payment-offline)를 참고하세요. 매장이 나중에 결제를 거부하면 [오프라인에서 받은 결제를 매장이 거부한 경우](#payment-refused-offline)를 참고하세요.

### 결제 수단이 접혀 표시되는 경우 {#not-available}

일부 결제 수단을 여전히 사용할 수 있을 때, 현재 결제를 받을 수 없는 수단은 타일로 표시되지 않습니다. **결제할 금액** 아래에 **지금은 카드를 사용할 수 없습니다**라는 한 줄로 접혀 표시되며, 여러 개라면 **현재 2개 사용 불가**로 표시됩니다. 해당 줄을 탭하면 각 결제 수단과 사유를 확인할 수 있습니다. 연결이 필요한 수단에는 **연결 필요**가 표시됩니다.

<details>
<summary>결제 수단을 사용할 수 없는 다른 사유</summary>

- **주문 전체 금액을 결제하므로 이미 받은 결제가 있으면 사용할 수 없습니다** — 남은 금액을 다른 방법으로 결제하거나 [지금까지 받은 결제를 취소하세요](./cancelling-a-payment.mdx).
- **…에 설정된 단말기가 없습니다** — 해당 결제 게이트웨이에 온라인 상태인 단말기가 없습니다. 전원이 켜져 있고 연결되어 있는지 확인하세요.
- **주문 #…에서 사용 중** — 해당 결제 게이트웨이의 모든 단말기가 다른 주문을 처리 중입니다. 먼저 해당 결제를 완료하거나 취소하세요.
- **…을(를) 사용하려면 앱을 업데이트하세요** — 이 기기에 더 최신 버전의 WCPOS가 필요합니다.
- **리더기를 사용하려면 Bluetooth를 켜세요**, **앱 설정에서 리더기 접근을 허용하세요**, **결제 서비스 제공업체에 로그인하세요** — 기기 설정 또는 **설정 → 카드 리더기**에서 해결하세요.
- **이 결제 수단에는 앱의 리더기만 허용됩니다. 이 계산대에서 결제하려면 해당 결제 수단의 WooCommerce 설정 페이지에서 스마트 리더기를 허용하세요.** — 웹 브라우저에서 이 결제 게이트웨이는 휴대폰이나 태블릿의 WCPOS 앱과 페어링된 리더기로만 카드 결제를 받습니다. 매장 관리자에게 결제 게이트웨이의 WooCommerce 설정 페이지에서 스마트 리더기를 허용해 달라고 요청하세요.

각 사유와 확인할 사항은 [타일을 사용할 수 없는 경우](../../payment/index.mdx#unavailable-tiles)에 나와 있습니다. 타일과 이 목록 모두에 없는 결제 수단은 포스에서 켜져 있지 않은 것입니다. [결제 화면에 결제 게이트웨이가 나타나지 않는 경우](../../payment/index.mdx#gateway-not-appearing-at-checkout)를 참고하세요.

</details>

## 매장이 응답하지 않는 경우 {#slow-store}

### 주문 저장이 느린 경우 {#store-not-answering}

**"매장이 응답하지 않습니다. 계속 기다리거나 장바구니로 돌아가세요."** 매장에서 주문을 저장하는 데 4초 넘게 걸리고 있으며 **받기**가 **주문 저장 중…** 으로 표시됩니다. 계속 기다리거나 **✕** 를 누르세요. 자주 발생하면 [결제 성능](../../support/performance/checkout.mdx)을 참고하세요.

### 마지막 결제에 응답이 없는 경우 {#payment-unanswered}

**"매장에서 마지막 결제에 응답하지 않았습니다. 다시 시도하여 확인하세요. 중복으로 결제되지 않습니다."** **다시 시도**를 누르세요. 계산대가 동일한 결제를 조회하므로 매장에서 결제를 다시 받지 않습니다. [매장에서 결제에 응답하지 않은 경우](../../error-codes/PAYMENT201.mdx)를 참고하세요.

### 제공업체의 응답이 없는 경우 {#provider-no-answer}

**"…에 대해 아직 제공업체의 응답이 없습니다."** 계산대에서 제공업체로 결제를 보냈지만 응답을 받지 못했습니다. 매장은 계속 확인하며, 금액이 결제되었다면 기록합니다. 아직 결제를 다시 받지 마세요. 매장 관리자에게 제공업체 대시보드에서 이 주문을 찾아 달라고 요청하세요. 청구 내역이 없으면 **시도 지우기**를 누르고 결제를 다시 받으세요. 청구 내역이 있으면 다시 받지 말고 주문이 업데이트될 때까지 기다리세요. [카드 리더기 결제가 멈춘 경우](../../payment/index.mdx#card-reader-problems)를 참고하세요.

## 주문 및 결제 메시지 {#refused}

### 매장이 주문을 거부한 경우 {#store-refused}

**"주문이 저장되지 않았습니다 — 매장에서 거부했습니다".** 제목 아래에 매장의 거부 사유가 표시되고, 장바구니의 판매 탭에는 **저장 거부됨**이 표시됩니다. 품절된 상품 등 매장에서 지적한 문제를 해결한 다음 **결제**를 다시 누르세요. **매장 상태**에는 거부된 변경 사항과 함께 **다시 보내기**, **버리기**가 표시됩니다. [서버에 전달되지 않은 변경 사항](../../support/store-health.mdx#refused-changes)을 참고하세요.

### 오프라인에서 받은 결제를 매장이 거부한 경우 {#payment-refused-offline}

**"주문 #…은(는) 이미 온라인으로 결제되었습니다. 계산대에서도 …을(를) 받았습니다 — 해당 결제를 환불하세요."** 또는 **"주문 #…에서 결제 금액 전액을 수락할 수 없었습니다. 계산대에서 …을(를) 받았습니다 — 차액을 환불하세요."** 오프라인 상태에서 결제를 받았지만 연결이 복구되었을 때 매장이 해당 결제를 주문에 추가하지 않았습니다. 고객이 주문에 필요한 금액보다 더 많이 지불한 상태입니다.

1. **주문**으로 이동하세요. 상단의 **판매 1건 확인 필요** 아래에 같은 메시지가 계속 표시됩니다.
2. 메시지의 **주문 열기**를 누르고 표시된 금액을 고객에게 돌려주세요. [계산대에서 환불하기](../refunds.mdx)를 참고하세요.
3. **주문**으로 돌아가 메시지의 **처리 완료**를 누르세요.

### 주문이 아직 전송 중인 경우 {#still-sending}

**"이 주문은 아직 매장으로 전송 중입니다. 잠시 기다린 다음 결제를 다시 누르세요."** 청구된 금액은 없습니다. 매장은 주문이 도착하면 동일한 주문으로 인식하므로 중복 주문이 생성되지 않습니다.

### 계산대가 열려 있지 않은 경우 {#register-closed}

**"판매를 완료하기 전에 계산대를 여세요".** 이 판매를 시작한 후 다른 계산대 등에서 계산대를 마감했으므로 결제를 받을 수 없습니다. 판매는 유지됩니다.

1. **✕** 를 눌러 장바구니로 돌아가세요. **결제**가 있던 자리에 **계산대 열기**가 표시됩니다.
2. **계산대 열기**를 누르고 [계산대 열기](../register/index.mdx#open)의 안내에 따라 서랍의 현금을 센 다음 계산대를 여세요. 다른 계산대에서 마감했다면 열기 카드에 마감한 사람과 시간이 표시됩니다.
3. **결제**를 누르고 결제를 다시 받으세요.

계산대가 여러 개일 때 **"판매를 완료하기 전에 계산대를 선택하세요"** 라는 메시지가 나오면 먼저 계산대를 하나 선택하세요.

### 기록되지 않은 결제 — 다시 받으세요 {#payment-not-recorded}

**"결제가 기록되지 않았습니다 — 받은 금액이 없습니다. 다시 시도하세요."** **받기**를 다시 누르세요. [받은 금액이 없는 경우](../../error-codes/PAYMENT999.mdx)를 참고하세요.

### 이미 기록된 결제 — 다시 받지 마세요 {#payment-already-recorded}

**"매장에 이 결제가 기록되어 있습니다 — 이 계산대에서 사본을 저장하지 못했습니다. 다시 받지 마세요."** 주문에 결제가 기록되어 있습니다. 다시 받지 마세요. [매장에 결제가 이미 기록된 경우](../../error-codes/PAYMENT111.mdx)를 참고하세요.

### 판매 완료 후 팝업이 나타나는 경우 {#popup-after-sale}

**오류 팝업이 나타났지만 판매는 완료되었습니다.** 결제를 다시 받기 전에 주문을 확인하세요. 그런 다음 매장 관리자에게 팝업 내용을 알려주세요.

<details>
<summary>매장 관리자용: 로그에서 원인 찾기</summary>

**매장 상태 → 로그**를 열고 해당 판매의 행을 찾으세요. 행 끝의 코드가 문제를 나타냅니다.

- **PAYMENT101** — 매장에서 결제를 확인했습니다. 이후 POS의 업데이트만 실패했으므로 다시 청구하지 마세요. [결제는 완료되었지만 상태가 새로 고쳐지지 않은 경우(PAYMENT101)](../../error-codes/PAYMENT101.mdx)를 참고하세요.
- **SYNC131** 또는 **CHECKOUT201** — 매장의 응답이 손상되었습니다. PHP 경고 또는 플러그인이나 테마의 오류 페이지가 원인인 경우가 많습니다. POS에서 응답을 읽지 못했더라도 매장에는 판매가 저장되었을 수 있습니다. 웹사이트 담당자에게 경고를 해결해 달라고 요청하세요. [응답 오류](../../support/troubleshooting/response-error.mdx#codes)를 참고하세요.

</details>

### 결제 중 주문이 변경된 경우 {#order-changed}

**"결제 중 주문이 변경되었습니다. 금액을 확인하고 다시 시도하세요."** **결제할 금액**과 주문 항목을 확인한 다음 결제를 다시 받으세요.

### 매장에서 주문이 삭제된 경우 {#order-deleted}

**"매장에서 주문이 삭제되었습니다"** 아래에 두 가지 문구 중 하나가 표시됩니다. 이 계산대에 주문이 남아 있는 동안 누군가 웹사이트에서 해당 주문을 삭제했습니다.

- **"주문 #…이(가) 매장에서 삭제되었습니다. 장바구니는 새 주문으로 유지되었습니다."** 판매를 계속 진행하세요. 새 주문으로 매장에 전송됩니다.
- **"주문 #…이(가) 매장에서 삭제되어 이 기기에서도 제거되었습니다."** 진행 중인 판매가 아니었으므로 계산대에서 사본을 제거했습니다. 실수로 삭제했다면 매장 관리자가 웹사이트의 주문 휴지통에서 찾아 복원할 수 있습니다.

[매장에서 기록이 삭제된 경우](../../error-codes/SYNC203.mdx)를 참고하세요.

### 다시 연 판매에 결제할 금액이 없는 경우 {#reopened-paid}

결제 수단 대신 **완료**가 표시됩니다. **주문**에서 판매를 다시 열었으며, 이미 받은 결제가 전체 금액을 충당합니다. **완료**를 눌러 다시 완료하세요. 추가로 금액을 받지 않습니다.

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[0, 0], [205, 10], [30, -48], [10, 34]]} alt="다시 연 판매의 결제 화면: 결제 수단 대신 완료 버튼이 표시되고, 주문의 현금 결제가 매입 완료 및 전액 결제로 표시되며, 장바구니에서 해당 판매의 탭이 선택됨">

1. **완료** — 판매를 다시 완료하며 금액을 받지 않습니다.
2. **현금 · 매입 완료** — 판매를 다시 열기 전에 받은 결제입니다. 합계 전액을 충당하므로 주문에 **전액 결제**가 표시됩니다.
3. **비회원** — 다시 연 판매의 탭입니다.
4. **✕** — 주문에 결제 내역이 있으면 장바구니로 돌아가는 대신 **결제 취소**를 엽니다.

</JourneyShot>

### 결제할 금액보다 많이 입력한 경우 {#more-than-due}

**"결제할 금액은 …입니다 — …은(는) 거스름돈을 줄 수 없습니다".** 거스름돈을 줄 수 없는 결제 수단에 미결제 잔액보다 큰 금액을 입력했습니다. 결제할 금액을 입력하거나 현금을 사용하세요.

### 계산대에서 저장된 데이터를 열 수 없는 경우 {#local-database}

**"로컬 데이터베이스를 사용할 수 없습니다 — 결제를 받거나 환불하기 전에 앱을 새로 고치세요".** 앱을 새로 고치세요.

## 카드 리더기 결제가 실패하는 경우 {#card-reader}

### 카드 결제가 실패한 경우 {#card-payment-failed}

**결제 실패: 카드 승인 거절**, **결제 취소됨** 또는 **시간 초과 — 결제 취소됨**. **다시 시도** 또는 **다른 방법 선택**을 누르세요.

### 카드에 청구되었지만 주문이 완료되지 않은 경우 {#card-charged-order-open}

**"카드에 청구되었지만 주문이 완료되지 않았습니다."** 매장은 금액을 받았습니다. 카드에 다시 청구하지 말고 **✕** 도 누르지 마세요. 주문에 결제 내역이 있으므로 **결제 취소**가 열립니다. 앱을 새로 고치면 계산대가 판매 완료를 다시 시도합니다. 주문이 여전히 진행 중이면 고객을 응대한 뒤 매장 관리자나 관리자에게 주문을 완료해 달라고 요청하세요. [카드에 청구되었지만 주문이 완료되지 않은 경우](../../error-codes/PAYMENT121.mdx)를 참고하세요.

### 승인되었지만 매입되지 않은 경우 {#authorised-not-captured}

결제 단말기에 **"승인되었지만 매입되지 않음: …"** 이 표시됩니다. 카드는 승인되었지만 매장에서 아직 금액을 받지 않았습니다. **매입 다시 시도**를 누르거나 **단말기에서 취소**를 눌러 카드 승인을 해제하세요.

### 결제 확인 미완료 {#confirmation-incomplete}

앱과 페어링된 리더기에 **"결제 확인 미완료: …"** 이 표시됩니다. 리더기가 카드를 승인했지만 계산대에서 매장에 결제를 확인하지 못했습니다. **결제 다시 확인**을 누르세요. 계산대가 동일한 결제를 다시 시도하므로 카드에 중복으로 청구되지 않습니다.

### 단말기에서 취소를 확인하지 않는 경우 {#cancel-not-confirmed}

결제 단말기에 **"취소 중 — 단말기의 확인을 기다리는 중"** 이 표시됩니다. 계산대에서 단말기에 취소를 요청했지만 응답이 없습니다. 다른 방법으로 결제하려면 **이 결제 해제**를 누르세요. 주문을 다른 수단으로 결제할 수 있게 하며, 매장은 계속 단말기를 확인합니다.

해제해도 결제가 취소되지는 않으므로 카드에 청구될 수 있습니다. 금액을 다시 받기 전에 단말기 화면을 확인하세요. 결제가 완료되었다면 다시 받지 말고 주문이 업데이트될 때까지 기다리세요. 확인할 수 없다면 [결제 중단하기](../../payment/gateways/square-terminal.mdx#stop)의 안내를 따르세요.

### 연결된 리더기 없음 {#no-reader}

계산대에 **연결된 리더기 없음**이 표시되고 옆에 **설정 → 카드 리더기에서 연결** 링크가 표시됩니다. 링크를 누르고 해당 화면에서 리더기를 페어링하세요.

모든 리더기 메시지와 지원 요청에 필요한 결제의 **상세 정보** 로그는 [카드 리더기 결제가 멈춘 경우](../../payment/index.mdx#card-reader-problems)에 나와 있습니다.

## 레거시 탭의 페이지가 로드되지 않는 경우 {#legacy-wont-load}

**"결제 양식을 로드하지 못했습니다 — 매장 연결을 확인한 다음 다시 시도하세요."** 연결을 확인하고 **재시도**를 누르세요.

**"결제 양식을 로드할 수 없습니다 — 이 주문에는 아직 서버에서 받은 결제 링크가 없습니다."** 매장에서 주문 처리를 완료하지 못했습니다. **✕** 를 누르고 다시 시도하세요.

**"처리 후 결제 페이지를 로드하지 못했습니다 — 결제 화면을 닫고 다시 결제하기 전에 주문 상태를 확인하세요."** 결제 게이트웨이에서 이미 금액을 받았을 수 있습니다. 결제를 다시 받기 전에 주문을 확인하세요.

**"이미 받은 결제가 있으면 레거시 결제 게이트웨이를 사용할 수 없습니다".** 주문에 결제 내역이 생기면 탭 아래에 **전체 금액만 결제 가능**이 표시됩니다. 레거시 결제 게이트웨이는 주문 전체 금액을 청구합니다. 사용하려면 [지금까지 받은 결제를 취소하세요](./cancelling-a-payment.mdx).

[레거시 탭의 결제 페이지가 로드되지 않는 경우](../../payment/index.mdx#legacy-notices)를 참고하세요.

## 결제 게이트웨이의 결제 페이지가 잘못 표시되는 경우 {#checkout-settings-troubleshooting}

[레거시 탭](./legacy-tab.mdx)은 웹사이트에서 보내는 결제 페이지를 표시합니다. 이 페이지에도 테마와 플러그인의 스타일 및 스크립트가 로드되며, 이로 인해 문제가 생길 수 있습니다. 페이지의 **결제 설정** 버튼으로 이를 제거할 수 있습니다.

**캐셔인 경우:** 매장 관리자나 관리자에게 페이지를 수정해 달라고 요청하세요. 양식을 열 수는 있지만 저장은 관리자만 할 수 있습니다. **결제 처리**를 눌렀다면 다른 방법으로 결제를 받기 전에 주문과 제공업체 대시보드를 확인하세요.

<details>
<summary>매장 관리자용: 결제 페이지 수정하기</summary>

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[28, 34], [332, -273], [-20, 0], [-30, 0]]} alt="결제 화면의 레거시 탭: 매장에서 보낸 결제 페이지의 오른쪽 상단에 결제 설정 버튼이 있고 아래에 결제 처리 버튼이 있음">

1. **레거시** — 매장 자체 결제 페이지에서 실행되는 결제 게이트웨이입니다.
2. **결제 설정** — 이 페이지에 로드할 항목을 선택하는 양식을 엽니다.
3. **결제 처리** — 페이지에서 선택한 결제 게이트웨이로 결제합니다. 페이지가 로드된 후에 작동합니다.
4. **✕** — 주문을 유지한 채 장바구니로 돌아갑니다.

</JourneyShot>

1. 매장 관리자, 관리자 또는 `manage_woocommerce` 권한이 있는 사용자로 POS에 로그인하세요. 캐셔로 로그인한 상태에서는 **제출**을 누르면 **"결제 설정을 수정할 권한이 없습니다."** 라는 메시지가 표시됩니다.
2. **결제**를 누르고 **레거시** 탭을 연 다음 **결제 설정**을 누르세요.
3. 스타일이나 스크립트의 체크를 해제하면 제거됩니다. 먼저 테마의 스타일을 제거하고, 그다음 결제 게이트웨이에 필요 없는 스크립트를 제거하세요.
4. **제출**을 누른 다음 사용하는 각 레거시 결제 게이트웨이로 테스트 결제를 해 보세요.

**결제 설정 양식에 표시되는 항목**

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[28, 34], [-28, -222]]} alt="레거시 탭의 결제 페이지 위에 열린 결제 설정 양식: 상단에 wp_head 비활성화와 wp_footer 비활성화가 있고, 그 아래에는 스타일 목록과 스크립트 목록이 나란히 표시되며, 항상 제거되는 항목은 회색으로 표시됨">

1. **레거시** — 이 양식이 속한 탭입니다.
2. **결제 설정** — 결제 페이지 위에 열리는 양식입니다. 페이지에 로드되는 모든 스타일과 스크립트에 체크박스가 선택되어 있습니다.

</JourneyShot>

- **wp_head 비활성화** / **wp_footer 비활성화** — 결제 양식에 필요한 스크립트를 포함해 페이지의 머리글 또는 바닥글에 있는 모든 항목을 제거합니다. 스타일과 스크립트가 원인인지 확인할 때만 사용하세요.
- **선택한 스타일 비활성화** — 스타일마다 항목 하나가 있습니다. 테마의 스타일은 `twentytwentyfive-style`처럼 테마 이름을 따서 표시됩니다.
- **선택한 스크립트 비활성화** — `selectWoo`와 같이 스크립트마다 항목 하나가 있습니다.
- 회색으로 표시되며 끝에 *POS 결제 페이지에서 항상 제거됨*이 붙은 항목은 이미 제거된 상태입니다.
- 이미 체크가 해제된 항목은 이전에 **제출**을 눌러 제거한 항목입니다. 다시 로드하려면 체크한 다음 **제출**을 누르세요.

WCPOS가 자동으로 제거하는 항목과 개발자용 옵션은 [레거시 탭의 결제 페이지 속도 높이기](../../support/performance/checkout.mdx#legacy-page)에 나와 있습니다.

:::tip
스크립트를 제거한 후 결제 게이트웨이가 작동하지 않으면 다시 체크하고 **제출**을 누르세요.
:::

</details>

:::info WCPOS Pro 사용 시
카드 리더기와 현금 및 카드 이외의 결제 수단에는 WCPOS Pro가 필요합니다. 무료 버전에서는 **결제** 탭에서 현금과 카드를, **레거시** 탭에서 카드를 받습니다. [무료 버전과 Pro 비교](../../getting-started/free-vs-pro.mdx)를 참고하세요.
:::
