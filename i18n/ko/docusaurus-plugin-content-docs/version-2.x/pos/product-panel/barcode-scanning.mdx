바코드를 스캔하면 상품이 바로 장바구니에 담깁니다. 대부분의 스캐너는 별도 설정 없이 작동합니다. 매우 빠른 키보드처럼 코드를 입력하고, WCPOS는 그 속도로 스캔과 일반 입력을 구분하기 때문입니다. 스캐너가 없다면 [카메라](#camera-scanning)를 사용하세요.

## 상품 스캔하기 {#scan}

카메라를 사용하나요? 매장에서 계산대를 사용한다면 먼저 계산대를 연 다음 [카메라로 스캔하기](#camera-scanning)를 따르세요. 스캐너를 사용하는 경우:

1. 스캐너를 페어링하거나 케이블로 연결하세요([스캐너 연결하기](#connection-modes)).
2. 매장에서 계산대를 사용한다면 먼저 [계산대를 여세요](../register/index.mdx#open). 계산대가 닫혀 있으면 장바구니에 아무것도 담을 수 없습니다.
3. 기기에 맞는 위치에 커서를 두세요.
   - **웹 브라우저 또는 데스크톱 앱:** 입력란 바깥을 클릭하거나 누르세요.
   - **iPad, iPhone 또는 Android의 WCPOS 앱:** **상품 검색**을 누르세요. {/* pending: monorepo#3368 */}
4. 스캔하세요.

<Accordion>
  <AccordionItem question="커서 위치가 중요한 이유">

키보드 모드의 스캐너는 키보드처럼 코드를 입력합니다.

웹 브라우저나 데스크톱 앱에서는 어떤 기기든 화면의 빈 영역에 커서를 두면 됩니다. 검색창을 포함한 입력란에 커서가 있으면 WCPOS는 스캐너의 입력을 일반 입력으로 처리하여 해당 입력란에 남겨 둡니다.

WCPOS 앱에서는 스캐너의 입력이 **상품 검색**으로 들어갑니다. [Android에 등록한 스캐너](#android)는 커서 위치와 관계없이 작동합니다.

  </AccordionItem>
</Accordion>

[아무 반응이 없거나 코드가 일반 입력으로 표시되나요?](#goes-wrong)

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[0, 0], [165, 0], [205, 0]]} alt="스캔으로 재킷이 장바구니에 추가된 화면: 장바구니에 추가됨 메시지, 비어 있는 검색창, 장바구니의 새 품목">

1. **장바구니에 추가됨** — 추가된 상품 이름과 함께 잠시 표시되므로 장바구니를 확인할 필요가 없습니다. 옵션별 상품이면 이름에 옵션이 표시되며, 여기서는 **XS, 회색**입니다.
2. **검색** — 모든 기기에서 스캔 후 다시 비워져 다음 스캔을 받을 준비가 됩니다.
3. **새 품목** — 스캔한 사이즈와 색상입니다. 같은 코드를 다시 스캔하면 하나 더 추가됩니다.

</JourneyShot>

브라우저나 데스크톱 앱에서는 장바구니와 결제 화면을 포함하여 POS 어디서나 스캔할 수 있습니다.

**바코드 최소 길이**(기본값 8)보다 짧은 코드는 추가할 수 없습니다. [감지 설정](#configuring-barcode-scanning)을 참고하세요.

:::note
[서랍의 현금을 세는](../register/index.mdx#close) 동안에는 계수가 끝날 때까지 스캔이 거부됩니다.
:::

**상품**과 **주문** 화면에서는 스캔한 코드가 해당 화면의 검색창에 입력됩니다. 상품을 스캔하여 그 상품이나 관련 주문을 찾을 수 있습니다.

### WCPOS가 검색하는 항목 {#what-matches}

WCPOS는 먼저 이 기기에서 바코드가 일치하는 상품이나 옵션별 상품을 찾습니다. 없으면 매장에 조회합니다(**매장 검색 중…**). 매장에서 상품을 찾으면 WCPOS가 장바구니에 추가합니다. 바코드로 사용할 필드는 [바코드 필드](../../settings/wp-admin/general.mdx#barcode-field)에서 설정합니다.

<Accordion>
  <AccordionItem question="SKU, GTIN, UPC, EAN 및 ISBN 코드">

[바코드 필드](../../settings/wp-admin/general.mdx#barcode-field) 외에도 상품의 SKU와 GTIN, UPC, EAN 또는 ISBN 필드는 이 기기와 매장에서 항상 사용할 수 있습니다.

  </AccordionItem>
  <AccordionItem question="12자리 및 13자리 바코드">

12자리 UPC-A 코드와 그에 해당하는 13자리 EAN 형식은 서로 일치하는 것으로 처리됩니다. 따라서 포장에 12자리로 인쇄되어 있어도 맨 앞에 0이 붙어 저장된 상품을 찾을 수 있습니다.

  </AccordionItem>
  <AccordionItem question="매장에서 찾은 상품">

매장에서 찾은 상품은 이 기기에 다운로드된 뒤 추가되므로, 다음 스캔에서는 매장에 조회할 필요가 없습니다. 새 기기는 나머지 상품 목록도 자동으로 받아옵니다. [상품 동기화](../../products/sync.mdx)를 참고하세요.

  </AccordionItem>
</Accordion>

## 화면 메시지의 의미 {#messages}

스캔으로 정확히 하나의 상품을 추가할 수 없으면 상단에 이유를 알리는 메시지가 6초 동안 표시됩니다.

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[0, 0], [0, 0]]} alt="알 수 없는 코드를 스캔한 화면: 바코드를 찾을 수 없음 메시지, 검색창에 남은 코드, 비어 있는 상품 목록">

1. **바코드를 찾을 수 없음** — 읽은 코드와 함께 표시됩니다. 이 매장의 로컬 데이터에도 온라인 데이터에도 해당 코드가 없습니다.
2. **코드** — 스캐너가 읽은 내용을 확인할 수 있도록 검색창에 남습니다. 검색창 끝의 닫기 표시로 코드를 지울 때까지 목록에는 아무것도 표시되지 않습니다.

</JourneyShot>

**상품 검색**에 코드가 남아 있으면 검색창 끝의 닫기 표시로 지워야 상품이 다시 표시됩니다. 대처 방법을 보려면 화면의 메시지와 일치하는 아래 제목을 여세요.

<Accordion>
  <AccordionItem question="바코드를 찾을 수 없음">

이 기기와 매장 어디에도 이 코드를 가진 상품이 없습니다. 검색창의 코드가 상품과 일치하는지 확인하세요. 올바른 코드라면 WooCommerce에서 상품에 바코드를 추가하세요.

  </AccordionItem>
  <AccordionItem question="여러 상품이 일치함">

이 코드를 가진 상품이 여러 개 있어 코드가 검색창에 남습니다. 검색 결과에서 올바른 상품을 선택한 다음, 상품마다 고유한 바코드를 지정하세요.

  </AccordionItem>
  <AccordionItem question="옵션 선택">

코드가 개별 옵션이 아닌 옵션 상품 자체에 해당하여 검색창에 남습니다. 검색 결과에서 옵션을 선택하세요. 옵션별 상품마다 고유한 바코드를 지정하면 스캔으로 바로 추가할 수 있습니다.

  </AccordionItem>
  <AccordionItem question="… 품절">

일치하는 상품을 찾았지만 재고가 없습니다. **품절 상품 표시**가 꺼져 있으면 추가가 거부됩니다. [표시 설정](display-settings.mdx#show-out-of-stock-products)을 참고하세요.

  </AccordionItem>
  <AccordionItem question="스캔을 사용할 수 없음">

*이 기기에 없으며 오프라인 상태에서는 매장을 검색할 수 없습니다*: 매장에 연결할 수 없어 코드가 검색창에 남습니다. **상태 보기**를 눌러 [매장 상태](../../support/store-health.mdx#database)를 확인하고, 온라인으로 돌아오면 다시 스캔하세요.

*로컬 데이터베이스를 사용할 수 없습니다*: POS가 자체 데이터베이스를 읽을 수 없습니다. 판매를 더 진행하기 전에 앱을 새로고침하세요.

  </AccordionItem>
  <AccordionItem question="조회 실패">

매장이 10초 이내에 응답하지 않았거나 오류를 반환했습니다. 코드는 검색창에 남습니다. 연결을 확인하고 다시 스캔하세요.

  </AccordionItem>
  <AccordionItem question="장바구니에 추가할 수 없음">

일치하는 상품을 찾았지만 추가하지 못했습니다. 다시 스캔하거나 상품을 누르세요.

  </AccordionItem>
</Accordion>

## 카메라로 스캔하기 {#camera-scanning}

기기에 카메라가 있다면 별도의 스캐너 없이 스캔할 수 있습니다. 검색창 옆의 스캔 버튼을 누르세요. 필터 아래에 카메라 패널이 열리므로 상품 목록을 계속 볼 수 있습니다.

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[0, 0], [0, 0]]} alt="필터 표시줄 아래의 카메라 패널에서 카메라 허용 버튼과 함께 카메라 접근 권한을 요청하는 화면">

1. **스캔** — 카메라 패널을 엽니다. 다시 누르면 닫힙니다.
2. **카메라 허용** — 처음에는 WCPOS가 카메라 접근 권한을 요청합니다. 버튼을 누른 다음 표시되는 안내에서 카메라 사용을 허용하세요.

</JourneyShot>

바코드를 카메라 앞에 비추세요. 코드가 읽히면 패널 테두리가 초록색으로 깜박이고, 스캐너로 스캔한 것과 똑같이 처리되며 동일한 [메시지](#messages)가 표시됩니다. 계속 비추고 있어도 한 번만 추가됩니다. 하나 더 추가하려면 잠시 화면 밖으로 치웠다가 다시 비추세요.

카메라를 시작할 수 없으면 패널의 상태 줄에 이유가 표시됩니다. 여기서는 사용할 수 있는 카메라를 찾지 못했습니다.

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[454, 0], [234, 0], [0, 0]]} maxWidth={589} alt="카메라를 사용할 수 없습니다 — 다른 앱에서 사용 중인지 확인하세요라는 메시지가 표시된 카메라 패널 확대 화면">

1. **상태** — 카메라 화면 하단에 현재 카메라 상태가 표시됩니다. 카메라가 시작되면 위쪽의 검은 영역에 카메라 영상이 나타납니다.
2. **크기 조절** — 드래그하여 카메라 화면의 높이를 조절하세요. WCPOS는 이 기기에서 설정한 높이를 기억합니다.
3. **닫기** — 패널을 닫습니다.

</JourneyShot>

대처 방법을 보려면 패널의 상태와 일치하는 아래 제목을 여세요.

<Accordion>
  <AccordionItem question="카메라 시작 중…">

잠시 기다리세요.

  </AccordionItem>
  <AccordionItem question="WCPOS에서 바코드를 스캔하려면 카메라 접근 권한이 필요합니다.">

**카메라 허용**을 누르세요. 이전에 거부했다면 권한 요청이 다시 표시되지 않을 수 있습니다. 브라우저의 사이트 설정이나 기기 설정에서 WCPOS의 카메라 사용을 허용한 뒤 패널을 다시 여세요.

  </AccordionItem>
  <AccordionItem question="카메라를 사용할 수 없습니다 — 다른 앱에서 사용 중인지 확인하세요.">

카메라를 사용 중인 다른 앱이나 탭을 닫거나, 카메라가 연결되어 있는지 확인하세요.

  </AccordionItem>
  <AccordionItem question="바코드 해독에 실패했습니다 — 스캐너를 닫고 다시 시도하세요.">

**닫기**로 패널을 닫은 뒤 스캔 버튼으로 다시 여세요.

  </AccordionItem>
</Accordion>

스캔으로 모든 상품을 찾지 못할 수 있는 경우에는 상태 아래에 안내가 표시됩니다.

- **오프라인 — 이 기기에 이미 저장된 상품만 스캔할 수 있습니다.** 다른 상품은 온라인으로 돌아온 뒤 스캔할 수 있습니다.
- **동기화를 시작하는 중입니다 — 일부 상품은 아직 찾을 수 없습니다.** 잠시 기다렸다가 다시 스캔하세요. 안내가 계속 표시되면 [매장 상태](../../support/store-health.mdx#database)를 확인하세요.
- **로컬 데이터베이스를 사용할 수 없습니다 — 스캔 기능을 복구하려면 앱을 새로고침하세요.** 앱을 새로고침한 뒤 다시 스캔하세요.

## 스캔 소리 {#sounds}

스캔할 때마다 소리가 나면 고객에게 시선을 두고 응대할 수 있습니다. **설정** → **바코드 스캔**의 **소리**에서 **스캔 시 소리 재생**을 켜세요. 기본적으로 꺼져 있으며 이 기기에만 저장되므로 계산대마다 다르게 설정할 수 있습니다.

<Accordion>
  <AccordionItem question="스캔 소리 선택 및 테스트">

<JourneyShot manifest={manifest} device="tablet" step={6} offsets={[[0, 0], [0, 0], [0, 0]]} maxWidth={726} alt="스캔 시 소리 재생이 켜진 바코드 스캔 설정의 소리 영역: 미리 듣기 버튼이 있는 세 가지 소리 테마, 음량, 성공 소리, 실패 소리">

1. **▶** — 해당 테마의 성공 소리를 재생합니다.
2. **▶✕** — 해당 테마의 실패 소리를 재생합니다.
3. **음량 ▶** — 설정한 음량으로 성공 소리를 재생합니다.

</JourneyShot>

- **스캔 시 소리 재생** — 맨 위의 스위치입니다. 소리를 켜고 아래에 옵션을 표시합니다.
- **소리 테마** — **클래식**(밝게 올라가는 짧은 소리 / 낮은 버저음), **결제**(슈퍼마켓 같은 일정한 높이의 삑 소리 / 두 번의 낮은 소리), **부드러움**(조용한 매장에 어울리는 은은한 차임 소리 / 작게 두드리는 소리) 중에서 선택합니다.
- **음량** — 슬라이더를 드래그하세요.
- **성공 소리** — 상품이 장바구니에 담기면 재생됩니다.
- **실패 소리** — [화면 메시지의 의미](#messages)에 나오는 나머지 메시지마다 재생됩니다. **매장 검색 중…** 에는 소리가 나지 않습니다.
- **실패 시 진동** — iPhone, iPad, Android에서만 사용할 수 있습니다. 실패하면 실패 소리와 함께 기기가 진동하며, **실패 소리**가 꺼져 있으면 진동만 울립니다. **스캔 시 소리 재생**이 켜져 있어야 합니다.

</AccordionItem>
</Accordion>

## 감지 설정 {#configuring-barcode-scanning}

같은 화면의 **스캔** 영역에서 어떤 입력을 스캔으로 인식할지 정합니다. 대부분의 매장에서는 변경할 필요가 없습니다. 스캔이 일반 입력으로 처리되거나 짧은 코드가 거부되면 이곳에서 **바코드 스캔 테스트**를 실행하세요. 스캐너의 입력 시간을 측정하고 설정값을 제안합니다. [바코드 설정](../../settings/store/barcode.mdx)을 참고하세요.

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[195, 0], [195, 0], [194, 0], [194, 0]]} alt="설정의 바코드 스캔 화면: 임계값 24, 최소 길이 8, 비어 있는 접두사와 접미사가 있는 스캔 영역 아래에 소리, 스캐너, 바코드 스캔 테스트 영역이 있습니다">

1. **바코드 평균 입력 시간 임계값 (ms)** — 스캔으로 인식하려면 키가 얼마나 빠르게 입력되어야 하는지 정합니다.
2. **바코드 최소 길이** — 이보다 짧은 코드는 추가되지 않습니다.
3. **바코드 스캐너 접두사** — 스캐너가 코드 앞에 추가하는 한 글자이며, 조회 전에 제거됩니다. 스캐너에 접두사가 설정되어 있지 않다면 비워 두세요.
4. **바코드 스캐너 접미사** — 코드 뒤에 추가하는 한 글자에 같은 방식으로 적용됩니다.

</JourneyShot>

| 설정 | 기능 | 기본값 |
|---|---|---|
| **바코드 평균 입력 시간 임계값 (ms)** | 키 입력 사이의 평균 간격이 이 값보다 짧으면 스캔으로 인식합니다. 더 느린 입력은 일반 입력으로 처리합니다. | 24 |
| **바코드 최소 길이** | 이보다 짧은 코드는 추가되지 않습니다. 사용하는 바코드 중 가장 짧은 길이로 설정하세요. | 8 |
| **바코드 스캐너 접두사** | 스캐너가 코드 앞에 추가하는 한 글자이며, 조회 전에 제거됩니다. | 비어 있음 |

## 스캐너 연결하기 {#connection-modes}

대부분의 스캐너는 키보드 모드로 출고되며, 키보드 모드에서는 설정이 필요 없습니다. 페어링하거나 케이블로 연결한 뒤 스캔하면 됩니다. 대부분의 매장에 적합한 방식입니다. 설정이나 문제 해결을 단계별로 안내받으려면 [스캐너 설정 마법사](../../hardware/scanners/setup-wizard.mdx)를 이용하세요.

키보드 배열 때문에 대문자와 기호가 뒤섞이는 등 스캔 결과에 잘못된 문자가 들어가거나, 커서가 입력란에 있는 상태에서 스캔해야 한다면 직접 연결이 도움이 될 수 있습니다.

<Accordion>
  <AccordionItem question="스캐너 직접 연결(고급)">

직접 연결한 스캐너는 입력 속도, 키보드 배열, 포커스가 아니라 장치 자체로 식별됩니다. 모든 바코드 스캐너는 몇 가지 모드 중 하나로 출고되며, 모드에 따라 WCPOS가 스캔을 받는 방식이 달라집니다.

| 모드 | 입력 방식 | 설정 |
|---|---|---|
| **키보드 (HID)**, 거의 모든 스캐너의 출고 시 기본값 | 스캐너가 코드를 입력하고 WCPOS가 빠른 키 입력을 인식합니다 | 불필요: 페어링하거나 케이블로 연결한 뒤 스캔하세요 |
| **HID-POS** | USB로 직접 연결 | 스캐너의 모드를 바꾼 다음 **USB로 연결**을 누르세요 |
| **직렬 (SPP / USB-COM)** | Bluetooth 또는 USB를 통한 직접 직렬 연결 | 스캐너의 모드를 바꾼 다음 **Bluetooth 직렬로 연결**을 누르세요. 목록에 없는 Bluetooth 스캐너는 자체 서비스 UUID를 사용할 수 있습니다. **내 스캐너가 목록에 없습니다**에서 추가하세요. |
| **Bluetooth LE** | iPhone 및 iPad 앱에서 Bluetooth Low Energy로 직접 연결 | 기기의 Bluetooth 설정에서 스캐너를 제거하고 다시 페어링하지 않은 상태로 **Bluetooth 스캐너 연결**을 누르세요. 처음 발견한 Bluetooth LE 스캐너에 연결하므로 다른 스캐너는 꺼 두세요. |

연결 버튼은 **설정** → **바코드 스캔** → **스캐너** → **스캐너 직접 연결(고급)** 에 있습니다.

:::info 키보드 모드의 스캐너는 직접 연결할 수 없습니다
기기는 키보드 모드의 스캐너를 키보드와 똑같이 취급하며, 어떤 앱도 키보드를 독점할 수 없습니다. 연결 버튼을 눌러도 스캐너가 목록에 나타나지 않는다면 거의 확실히 아직 키보드 모드인 상태입니다.
:::

**모드를 전환하려면** 스캐너 설명서에서 설정용 바코드(*“SPP 모드”*, *“직렬 모드”*, *“HID-POS 모드”*를 찾으세요)를 찾아 스캔하세요. 스캐너가 자동으로 재설정됩니다. Bluetooth 스캐너라면 기기의 Bluetooth 설정에서 기존 페어링을 삭제하고 모드 전환 후 다시 페어링하세요. 언제든 설명서의 *“HID”* 또는 *“키보드”* 바코드를 스캔하면 원래 모드로 돌아갑니다.

USB 및 Bluetooth 직렬 연결은 데스크톱 앱과 Chrome 기반 브라우저에서 작동합니다. 데스크톱 앱은 앱 안에 장치 선택 창을 표시하고, Chrome은 자체 선택 창을 표시합니다. iPhone 및 iPad 앱은 Bluetooth LE 스캐너에 직접 연결합니다. Safari와 Firefox는 직접 연결을 지원하지 않습니다. 키보드 모드나 카메라를 사용하세요.

  </AccordionItem>
</Accordion>

### Android에서 스캐너 등록하기 {#android}

Android에서는 키보드 모드의 스캐너를 등록하면 입력란을 포함해 커서가 어디에 있든 스캔할 수 있습니다. **바코드 최소 길이**는 계속 적용됩니다.

1. 스캐너를 페어링하거나 케이블로 연결하세요.
2. **설정** → **바코드 스캔**의 **스캐너** 영역에서 **스캐너 등록하기**를 누른 다음 **스캐너 등록**을 누르세요.
3. 해당 스캐너로 아무 바코드나 스캔하세요. WCPOS에 **“…” 감지됨 — 이름을 지정하고 저장하세요**가 표시됩니다.
4. 이름을 지정하고 **스캐너 저장**을 누르세요.

스캐너가 **등록됨**으로 표시된 별도 행에 나타납니다. 다른 키보드 모드 스캐너는 등록하지 않아도 계속 작동합니다. [Android에서 스캐너 등록하기](../../hardware/scanners/setup-wizard.mdx)를 참고하세요.

<Accordion>
  <AccordionItem question="Android 스캐너 등록의 작동 방식">

Android는 스캐너에 직접 연결할 수 없지만 등록된 스캐너는 입력을 보낸 장치로 식별합니다. 입력 속도로 추측할 필요 없이, 스캔이 입력란에 도달하기 전에 처리됩니다.

  </AccordionItem>
</Accordion>

## 문제가 발생한 경우 {#goes-wrong}

- **스캔해도 아무 반응이 없음** — 웹 브라우저나 데스크톱 앱에서는 화면의 빈 영역을 클릭한 뒤 다시 스캔하세요. iPad, iPhone 또는 Android용 WCPOS 앱에서는 먼저 검색창을 누르세요. 그런 다음 **바코드 스캔 테스트**에서 스캐너를 확인하세요. [바코드 설정](../../settings/store/barcode.mdx)을 참고하세요.
- **코드가 검색창에 일반 입력으로 들어감** — 웹 브라우저나 데스크톱 앱에서는 커서가 입력란에 있었기 때문입니다. 화면의 빈 영역을 클릭한 뒤 다시 스캔하세요. iPad, iPhone 또는 Android용 WCPOS 앱에서는 커서를 검색창에 두세요. 어느 경우든 스캐너의 입력 간격이 **바코드 평균 입력 시간 임계값 (ms)** 보다 길 수 있습니다. 테스트를 실행하고 제안된 값에서 **적용**을 누르세요.
- **등록된 상품인데 바코드를 찾을 수 없음** — [바코드 필드](../../settings/wp-admin/general.mdx#barcode-field) 설정과 WooCommerce의 상품 바코드를 확인하세요. 온라인 전용으로 지정된 상품은 POS에 표시되지 않습니다. 새 기기에서는 첫 동기화가 끝날 때까지 기다리세요. **매장 상태 → 데이터베이스**에서 진행 상황을 확인할 수 있습니다.
- **스캔을 사용할 수 없음** — 오프라인 상태이며 상품이 아직 이 기기에 없습니다. [매장 상태](../../support/store-health.mdx#database)를 확인하세요.
- **카메라가 시작되지 않음** — [카메라 메시지](#camera-scanning)를 참고하세요.

## 자주 묻는 질문 {#faq}

<Accordion>
  <AccordionItem question="매장에 방금 추가한 상품이 스캔되지 않습니다. 왜 그런가요?">

WCPOS는 이 기기에 없는 코드를 매장에 조회하므로 온라인 상태라면 새 상품도 스캔됩니다. **바코드를 찾을 수 없음**이 표시되면 매장에도 해당 코드가 없는 것입니다. WooCommerce에서 상품의 바코드 필드를 확인하세요. **스캔을 사용할 수 없음**이 표시되면 오프라인 상태입니다. 온라인으로 돌아온 뒤 다시 스캔하세요.

  </AccordionItem>

  <AccordionItem question="POS에서 바코드를 생성하고 인쇄할 수 있나요?">

현재는 지원하지 않습니다. WCPOS는 기존 바코드를 스캔하고 읽을 수 있지만 생성하거나 인쇄하지는 않습니다.
상품 바코드를 생성하려면 다음과 같은 바코드 생성 및 인쇄 전문 WooCommerce 플러그인을 사용하세요.

- [EAN for WooCommerce](https://wordpress.org/plugins/ean-for-woocommerce/)
- [A4 Barcode Generator](https://wordpress.org/plugins/a4-barcode-generator/)

그런 다음 각 코드를 상품의 바코드 필드에 추가하면 계산대에서 스캔할 수 있습니다.

  </AccordionItem>
</Accordion>
