# Authorize.net 탭 결제 {#authorizenet-tap-to-pay}

고객은 휴대폰에서 Authorize.net 자체 앱을 열고 카드로 결제합니다. 결제 금액은 직접 앱에 입력해야 하며, POS에서 전송하지 않습니다. 그런 다음 POS가 Authorize.net에서 결제를 찾아 주문에 기록합니다.

이 기능은 Stripe Terminal을 사용하는 [WCPOS 앱 자체의 탭 결제](../../hardware/card-readers/index.mdx#tap-to-pay)와 별개입니다. 매장 관리자라면 [Authorize.net 탭 결제 설정](#setup)에서 자격 증명, 휴대폰 설정 및 작동 확인 방법을 알아보세요.

:::info Pro 기능
Authorize.net 탭 결제를 사용하려면 [WCPOS Pro](../../getting-started/pro-license.mdx) 2.0 이상이 필요합니다.
:::

:::warning 베타: 먼저 테스트 결제를 진행하세요
**버전 0.1.0은 베타이며 Authorize.net 앱에서 실제 탭 결제를 아직 시도하지 않았습니다.** 고객 카드를 받기 전에 본인 카드로 소액 결제를 진행한 다음 환불하세요.

<details>
<summary>테스트한 항목과 아직 테스트하지 않은 항목</summary>

버전 0.1.0은 Authorize.net 샌드박스에서 테스트했습니다. 탭 결제 대신 Authorize.net API를 통해 카드 대면 결제를 진행해 판매, 결제 대조, 취소, 정산 후 환불을 확인했습니다. 아직 테스트하지 않은 항목은 앱에서 실제로 탭 결제하기, 실제 탭 결제 후 Store checkout 탭에서 일치하는 결제 목록 확인하기, Authorize.net 앱과 카드 리더기 페어링하기입니다. 문제가 있으면 주문 번호, 판매 시각, 스크린샷을 함께 보고하세요.

</details>
:::

## 결제 받기 {#take-payment}

:::note 먼저 금전 등록기를 여세요
**금전 등록기 열기 및 닫기**가 켜져 있으면 금전 등록기가 닫힌 동안 POS가 결제를 기록하지 않습니다. 이미 카드를 받았다면 환불해야 합니다. 설정은 [금전 등록기](../../settings/wp-admin/registers.mdx#one-register)를 참조하세요.
:::

1. 장바구니에서 **결제**를 누르세요.
2. **결제 수단** 탭에서 **Authorize.net Tap to Pay** 타일을 누르세요(매장 관리자가 이름을 변경했을 수 있습니다). 키패드 위에는 **단말기:** 와 휴대폰 이름이 표시됩니다. 관리자가 변경하지 않았다면 **Authorize.net 앱**으로 표시됩니다.
3. **Authorize.net Tap to Pay로 … 보내기**를 누르세요. 예: **Authorize.net Tap to Pay로 $10.00 보내기**. POS에 **단말기에서 고객 대기 중**이라고 표시됩니다.
4. 휴대폰에서 Authorize.net 앱을 열고 **정확히 같은 금액**을 입력하세요. 앱에서 팁을 추가하지 마세요. [팁](../../pos/checkout/tips.mdx)을 참조하세요.
5. 고객이 휴대폰에 카드를 탭합니다.
6. POS가 처리할 때까지 기다리세요. 결제를 찾으면 POS가 기록하고, 결제할 금액이 남지 않았을 때 영수증이 열립니다.

보내기를 누른 후 5분 안에 탭 결제를 진행하세요. 5분이 지나면 POS가 결제를 취소하고 **시간 초과 — 결제 취소됨**을 표시하며 더 이상 결제를 찾지 않습니다.

<details>
<summary>POS가 결제를 찾는 방법</summary>

POS가 대기하는 동안 WCPOS는 해당 금액의 결제가 있는지 Authorize.net을 계속 확인합니다. **보내기**를 누르기 30초 전부터 정확히 하나의 결제가 도착했고 **자동 연결**이 켜져 있으면 해당 결제를 자동으로 기록합니다. 기록하기 전에 WCPOS는 금액과 통화를 포함해 Authorize.net에서 결제를 확인합니다. 하나의 결제는 한 주문에만 기록됩니다.

결제가 진행되면 POS에 **전송됨**, **단말기에서 처리 중**, **승인됨**, **매입 완료**가 차례로 표시됩니다.

</details>

### 결제 취소하기 {#cancel}

**단말기에서 취소**를 누르세요. WCPOS에서 취소해도 Authorize.net 앱의 결제는 중단되지 않으므로 고객에게 카드를 탭하지 말라고 안내하세요.

POS가 마지막으로 Authorize.net을 확인합니다. 해당 금액의 새 결제가 정확히 하나 도착했다면 이를 기록하고 판매를 완료합니다. 그렇지 않으면 결제가 취소됩니다.

## 문제가 발생한 경우 {#goes-wrong}

### 고객이 결제했을 수 있는 경우 {#may-have-paid}

:::warning 카드를 다시 받지 마세요
이 경우 주문은 아직 미결제 상태인데 금액은 이미 Authorize.net 계정에 들어왔을 수 있습니다. 아래의 Store checkout 탭 절차를 따르거나 매니저에게 문의하세요.
:::

**고객이 탭한 뒤에도 POS가 계속 대기합니다.** POS는 어느 결제인지 확실할 때만 자동으로 기록합니다. 확실하지 않으면 계속 대기하고 5분 후 시간 초과됩니다. 다음과 같은 경우에 발생합니다:

- 앱에 입력한 금액과 POS의 금액이 다릅니다. 예를 들어 앱에서 팁을 추가한 경우입니다.
- 다른 금전 등록기나 온라인 매장에서 같은 금액의 결제가 동시에 들어왔습니다.
- 관리자가 결제 게이트웨이 설정에서 **자동 연결**을 껐습니다.

**결제** 탭에서는 어떤 결제가 해당 주문의 결제인지 선택할 수 없습니다. 주문의 [**Store checkout**](../../pos/checkout/legacy-tab.mdx) 탭에서는 지난 15분간의 결제 중에서 선택할 수 있습니다. 캐셔나 매니저가 다음 절차를 진행합니다:

1. 계산대에서 같은 주문을 연 상태로 **Store checkout** 탭을 선택한 다음 **Authorize.net Tap to Pay**를 선택하세요.
2. **Authorize.net 앱으로 10.00 USD 보내기**를 누르세요(이 탭의 버튼에는 타일 이름 대신 휴대폰이 표시됩니다). 카드를 다시 받지 마세요.
3. POS에 예를 들어 **Authorize.net 결제 2건(USD 10.00)이 일치할 수 있습니다. 방금 받은 결제를 선택하세요.** 라는 제목의 목록이 표시됩니다.
4. 각 행에는 카드 종류, 마지막 4자리, 시간 및 Authorize.net 거래 번호가 표시됩니다. 고객의 카드와 탭한 시간이 일치하는 항목을 누르세요. 주문이 결제됩니다.

목록이 표시되지 않으면 카드를 다시 받지 마세요. 관리자가 Authorize.net 계정에서 결제를 찾아 [해당 계정에서 환불](#refunds)해야 합니다.

**취소한 뒤 고객이 탭 결제했습니다.** 취소해도 앱 작동은 중지되지 않습니다. 위와 같이 Store checkout 탭에서 결제를 기록하거나 매니저가 Authorize.net 계정에서 환불하세요.

**결제 실패: 단말기가 다른 금액을 확인했습니다.** 위의 팁 사례와는 다릅니다. 계산대에서 선택한 결제와 다른 금액이나 통화를 Authorize.net 자체에서 보고한 경우에만 표시됩니다. 예를 들어 매장 통화가 계정에 설정되어 있지 않을 수 있습니다. 계산대에는 결제가 기록되지 않고 주문 메모가 추가됩니다. Store checkout 탭을 사용하지 마세요. 매니저에게 연락해 Authorize.net 계정에서 결제를 찾아 환불하도록 하세요.

다른 이유로 POS에서 결제가 멈춘 경우 [카드 리더 결제가 멈춘 경우](../index.mdx#card-reader-problems)를 참조하세요.

  </AccordionItem>

  </AccordionItem>

## Authorize.net 결제 환불하기 {#refunds}

1. POS에서 주문의 환불 화면을 여세요. [환불](../../pos/refunds.mdx)을 참조하세요.
2. **Authorize.net Tap to Pay로 환불**을 선택하고 **환불 처리**를 누르세요.

Authorize.net이 결제를 정산하기 전(보통 밤사이)에는 전액 환불만 가능하며, 결제 승인 취소로 처리됩니다. 정산 후에는 카드로 전액 또는 일부를 환불할 수 있습니다. WP Admin의 주문에서 환불하는 방법도 같습니다.

<details>
<summary>환불 메시지</summary>

- **Authorize.net은 이 결제를 밤사이 정산합니다. 지금 승인 취소하려면 전액 환불하거나, 정산 후 일부 환불하세요.** — 전액 환불하거나 일부 환불을 위해 내일까지 기다리세요.
- **지난 8시간 동안 동일한 환불 요청을 보냈습니다. 다시 시도하기 전에 Authorize.net Merchant Interface를 확인하세요.**
- **이 Authorize.net 결제는 이미 승인 취소되었습니다.** — 정산 전에 결제 전체가 승인 취소되었습니다.
- **Authorize.net에서 환불을 확인하지 않았습니다. 다시 시도하기 전에 Authorize.net Merchant Interface를 확인하세요.**
- **지금은 Authorize.net에서 이 결제를 환불할 수 없습니다. Authorize.net Merchant Interface를 확인하세요.**
- **이 결제는 다른 Authorize.net 환경에서 처리되었습니다.** — **환경**을 원래대로 전환하거나 Merchant Interface에서 환불하세요.
- **이 결제에는 환불할 Authorize.net 거래가 없습니다.**
- **환불 금액은 0보다 커야 합니다.**

</details>

## Authorize.net 탭 결제 설정 {#setup}

관리자는 WP Admin에서 결제 게이트웨이를 한 번 설정하고 휴대폰에서 Authorize.net 앱에 로그인합니다.

### 요구 사항 {#requirements}

<RequirementsList>
  <RequirementItem label="프로세서">Authorize.net 판매자 계정은 TSYS 프로세서를 사용해야 하며 Authorize.net에서 탭 결제를 켜야 합니다. 휴대폰을 구입하기 전에 Authorize.net에 확인하세요.</RequirementItem>
  <RequirementItem label="Authorize.net 계정">미국 판매자 계정, 해당 계정의 API Login ID와 Transaction Key, 그리고 켜져 있는 Transaction Details API가 필요합니다.</RequirementItem>
  <RequirementItem label="휴대폰">Authorize.net 안내에 따르면 iPhone에서 탭 결제를 사용하려면 iOS 18 이상이 설치된 iPhone XS 이상이 필요합니다. Android에서는 Tap to Pay Ready 휴대폰에 Android 15가 필요합니다. 동일한 Authorize.net 계정에 속한 사용자로 Authorize.net 2.0 앱에 로그인하세요.</RequirementItem>
  <RequirementItem label="통화">USD: Authorize.net 2.0 앱은 USD만 지원합니다.</RequirementItem>
  <RequirementItem label="WCPOS">WCPOS Pro 2.0 이상과 POS의 네트워크 연결이 필요합니다.</RequirementItem>
  <RequirementItem label="서버">WCPOS 2.0에 필요한 WooCommerce 9.0 이상 및 PHP 7.4 이상, 그리고 오차가 30초 이내인 서버 시계</RequirementItem>
</RequirementsList>

### 확장 프로그램 설치 {#install}

`WP Admin > POS > 설정 > 확장`에서 **Authorize.net Tap to Pay for WooCommerce (beta)** 를 찾아 **설치**를 클릭하세요. WCPOS가 확장 프로그램을 설치하고 활성화합니다. 카드에서 **자동 업데이트**를 켤 때까지 자동 업데이트는 꺼져 있습니다. 켜면 새 베타 버전이 자동으로 설치됩니다. 사이트 전체에서 플러그인 자동 업데이트를 꺼 둔 경우 카드에 **이 사이트에서는 자동 업데이트가 꺼져 있습니다**라고 표시됩니다. [확장 프로그램](../../extensions/index.mdx#installing-an-extension)과 [자동 업데이트](../../extensions/index.mdx#auto-updates)를 참조하세요.

<details>
<summary>다운로드한 zip 파일에서 설치하기</summary>

[GitHub 릴리스 페이지](https://github.com/wcpos/authorize-net-terminal-for-woocommerce/releases)에서 `authorize-net-terminal-for-woocommerce.zip`을 다운로드하고 `플러그인 > Add Plugin`에서 업로드한 다음 **플러그인 업로드**를 클릭하세요. GitHub의 "Source code" zip 파일은 설치할 수 없습니다.

</details>

### API 자격 증명 확인하기 {#credentials}

Authorize.net Merchant Interface에서:

1. **Account → Settings → API Credentials & Keys**를 열고 **API Login ID**를 복사하세요. Authorize.net은 **Transaction Key**를 생성할 때만 표시합니다. 저장해 둔 키가 없다면 새 키를 만들어 즉시 복사하세요. 새 키는 기존 키를 대체하므로 온라인 매장에서 이미 이 계정을 사용한다면 기존 키를 재사용하거나 매장의 키도 업데이트하세요. **프로덕션**에는 실제 계정의 자격 증명을 사용하고, 샌드박스 계정의 자격 증명은 **샌드박스**에서만 사용할 수 있습니다.
2. **Account → Settings → Transaction Details API**를 열고 켜세요. 이 기능이 없으면 매장에서 결제를 읽을 수 없어 POS가 결제를 기록하지 못합니다.

### 자격 증명 입력하기 {#enter-credentials}

`WP Admin > WooCommerce > 설정 > 결제`를 열고 **Authorize.net Tap to Pay**를 클릭하세요.

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[410, 0], [410, 0], [410, 0], [410, 0], [-30, 0], [410, 0]]} maxWidth={720} alt="아직 설정하지 않은 매장의 WP Admin에 표시된 Authorize.net Tap to Pay 설정: 제목 Authorize.net Tap to Pay, 환경 샌드박스, 비어 있는 API Login ID 및 Transaction Key 필드에 저장된 값 없음 표시, 자동 연결 선택됨, 리더 이름 Authorize.net 앱">

1. **제목** — POS에서 타일에 표시할 이름입니다.
2. **환경** — **프로덕션**을 선택하세요. 휴대폰 없이 매장 측 기능만 테스트할 때만 기본값인 **샌드박스**를 유지하세요. [샌드박스와 프로덕션](#environments)을 참조하세요.
3. **API Login ID** — 여기에 붙여넣으세요.
4. **Transaction Key** — 여기에 붙여넣으세요. 저장한 후에는 두 필드가 비어 있고 마지막 4자리만 표시됩니다. 저장된 값을 유지하려면 비워 두세요. 저장해도 자격 증명을 테스트하지 않습니다. [작동 확인](#check)에서 확인하세요.
5. **자동 연결** — 선택된 상태로 두세요. 이 옵션을 끄면 POS가 결제를 자동으로 기록하지 않습니다.
6. **리더 이름** — POS에서 키패드 위에 표시할 이름입니다.

</JourneyShot>

**변경 사항 저장**을 클릭하세요.

### 휴대폰 설정하기 {#phone}

휴대폰에 Authorize.net 앱을 설치하고 입력한 자격 증명에 해당하는 Authorize.net 계정 사용자로 로그인하세요. **프로덕션**을 사용하는 경우 실제 계정을 사용해야 합니다.

### WCPOS에서 켜기 {#enable}

결제 게이트웨이 설정 페이지에는 **사용** 상자가 없습니다. `WP Admin > POS > 설정 > 결제`를 여세요.

<JourneyShot manifest={manifest} device="desktop" step={2} offsets={[[-22, 0], [50, 0]]} maxWidth={720} alt="WP Admin의 POS 설정, 결제 화면: 게이트웨이 표의 세 행, 카드 켜짐, Authorize.net Tap to Pay 및 계좌 이체 꺼짐">

1. **Authorize.net Tap to Pay** — **결제 게이트웨이** 표에서 확장 프로그램에 해당하는 행입니다.
2. **사용** — 켜세요. POS를 새로고침하면 타일이 표시됩니다.

</JourneyShot>

이 결제 게이트웨이는 온라인 매장의 결제 화면에 표시되지 않습니다. [결제 설정](../../settings/wp-admin/checkout.mdx#enabling-a-gateway)을 참조하세요.

### 작동 확인하기 {#check}

1. POS에서 POS를 새로고침하고 **결제**를 누르세요. 결제 수단 중에 **Authorize.net Tap to Pay** 타일이 표시됩니다.
2. 타일을 누르세요. 키패드 위에 **단말기:** 와 **리더 이름**이 표시됩니다.
3. **환경**이 **프로덕션**인지 확인한 다음 본인 카드로 소액 결제를 진행하세요.
4. 당일에 전액 환불하세요. 정산 전 전액 환불은 결제 승인 취소로 처리됩니다.

POS가 결제를 자동으로 기록하고 영수증을 열며 주문 결제 내역에 Authorize.net 거래 ID가 표시되면 정상 작동한 것입니다.

POS에 **연결이 불안정합니다. 계속 시도 중**이 표시되면 자격 증명, **환경**, Transaction Details API를 확인하세요.

## 샌드박스와 프로덕션 {#environments}

**샌드박스**가 기본값이며 `apitest.authorize.net`을 사용합니다. **프로덕션**은 `api.authorize.net`을 사용하며 실제 금액이 결제됩니다. 자격 증명은 특정 환경에 연결되므로 선택한 환경에 해당하는 자격 증명을 입력하세요. 매장 측 기능은 샌드박스에서 작동합니다. 베타는 Authorize.net API로 결제하여 샌드박스에서 테스트했습니다. Authorize.net은 앱에서 샌드박스 계정에 로그인할 수 있는지 안내하지 않으므로 프로덕션에서 실제 탭 결제를 시도하세요.

어느 POS에서도 Authorize.net 결제를 진행 중이지 않을 때만 **환경**을 전환하세요. 대기 중인 결제는 실패합니다. 한 환경에서 받은 결제는 전환 후 POS에서 환불할 수 없습니다.

## 설정 참조 {#settings}

`WP Admin > WooCommerce > 설정 > 결제 > Authorize.net Tap to Pay`에서:

| 설정 | 설명 |
|---|---|
| **제목** | POS에서 타일에 표시할 이름입니다. 기본값은 **Authorize.net Tap to Pay**입니다. |
| **환경** | **샌드박스**(기본값) 또는 **프로덕션**입니다. |
| **API Login ID** | Merchant Interface의 **Account → Settings → API Credentials & Keys**에서 확인합니다. 저장 후에는 마지막 4자리만 표시되며, 값을 유지하려면 비워 두세요. |
| **Transaction Key** | 서버에만 저장되며 다시 표시되지 않습니다. API Login ID와 같은 방식으로 저장되고 표시됩니다. |
| **자동 연결** | 조건에 맞는 Authorize.net 결제가 정확히 하나일 때 자동으로 기록합니다. 기본적으로 켜져 있습니다. |
| **리더 이름** | POS에서 키패드 위에 표시할 이름입니다. 기본값은 **Authorize.net 앱**입니다. |

숨겨진 문자가 포함된 자격 증명을 붙여넣으면 **Authorize.net 자격 증명에는 제어 문자를 포함할 수 없습니다.** 라는 오류와 함께 거부됩니다. 다시 붙여넣으세요.

**먼저 Authorize.net API Login ID와 Transaction Key를 입력하세요.** 는 자격 증명이 누락되었다는 뜻입니다. 두 값을 모두 입력하고 **변경 사항 저장**을 클릭하세요.

## 로그 및 지원 번들 {#logs}

<JourneyShot manifest={manifest} device="desktop" step={3} offsets={[[-20, 0]]} maxWidth={720} alt="WP Admin의 Authorize.net Tap to Pay 설정 하단: 지원 번들과 지원 번들 다운로드 버튼">

1. **지원 번들 다운로드** — WCPOS 지원팀에 전달할 파일입니다. 사이트의 모든 POS 결제 제공업체를 포함하며 비밀 정보와 카드 번호는 제거됩니다.

</JourneyShot>

로그는 `WooCommerce > Status > 로그`의 `authorize-net-terminal-for-woocommerce` 소스에 있으며 자격 증명과 카드 번호는 제거됩니다. 결제에 문제가 생기면 **주문 번호**와 **판매 시간**을 함께 지원 번들로 보내세요.

확장 프로그램에 **Authorize.net Tap to Pay for WooCommerce POS needs WooCommerce POS Pro 2.0.0 or newer.** 가 표시되면 WCPOS Pro를 설치하거나 업데이트하세요. WCPOS Pro가 없으면 확장 프로그램이 POS에 아무 기능도 추가하지 않습니다.

## 지원하지 않는 기능 {#scope-and-limitations}

- 휴대폰으로 금액 전송: 앱에 직접 입력해야 합니다.
- 앱에서 팁 추가: 금액이 정확히 일치해야 합니다.
- 가능한 결제 목록을 **결제** 탭에 표시하고 [Store checkout 탭](#may-have-paid)에서 해당 결제를 선택하세요.
- 실물 카드 단말기. Authorize.net 앱과 페어링한 리더는 테스트하지 않았습니다.
- 수동 매입 또는 Authorize.net에서 검토를 위해 보류한 결제: POS가 계속 대기합니다.
- 미국 외 계정 또는 USD 이외의 통화.
- 거래량이 매우 많은 계정: 버전 0.1.0은 Authorize.net이 아직 정산하지 않은 최신 결제 50건만 확인합니다. 탭 결제 후 POS가 해당 결제를 찾기 전에 계정의 다른 결제(다른 금전 등록기 및 온라인 매장 포함)가 50건 이상 들어오면 POS가 해당 결제를 찾지 못합니다.
- 두 금전 등록기 구분: 두 등록기에서 같은 순간에 같은 금액을 결제하면 서로의 결제를 각각 기록할 수 있습니다.
