# Windcave Terminal 결제 게이트웨이 {#windcave-terminal-gateway}

Windcave Terminal은 계산대에서 Windcave 단말기로 판매 정보를 전송합니다. 고객이 단말기에서 결제하면 Windcave의 확인 후 계산대에 결제가 기록됩니다.

이 페이지는 계산대 사용부터 설명합니다. 매장 관리자: 인증 정보, WP Admin 설정 및 작동 확인 방법은 [Windcave Terminal 설정](#setup)을 참조하세요.

:::info Pro 기능
Windcave Terminal을 사용하려면 [WCPOS Pro](../../getting-started/pro-license.mdx) 2.0 이상과 확장 기능 1.0 이상이 필요합니다.
:::

:::warning 아직 Windcave 인증을 받지 않았습니다
**테스트 결제 전용: 아직 Windcave에서 실제 고객의 카드를 결제하지 마세요.** Windcave는 실제 결제를 받기 전에 모든 POS 연동을 승인하며, 아직 이 연동을 승인하지 않았습니다.

<details>
<summary>아직 테스트하지 않은 항목</summary>

아직 실제 Windcave 단말기에서 확장 기능을 실행하지 않았습니다. Windcave 문서를 바탕으로 만든 HIT 서비스 대체 환경에서 결제와 환불을 테스트했습니다. 사용하기 전에 UAT로 소액 판매를 진행하고 환불해 보세요.

</details>
:::

## 카드 결제 받기 {#take-payment}

:::note 먼저 계산대를 여세요
**계산대 열기 및 닫기**를 켜면 계산대가 닫혀 있을 때 결제를 기록하지 않습니다. 이미 받은 카드 결제는 환불해야 합니다. 설정은 [계산대](../../settings/wp-admin/registers.mdx#one-register)를 참조하세요.
:::

1. 장바구니에서 **결제**를 누르고 **결제** 탭에서 **Windcave Terminal** 타일을 누르세요. 단말기에서 서명을 요청한다면 **레거시** 탭을 사용하세요. [단말기에서 질문하는 경우](#terminal-questions)를 참조하세요.
2. 키패드 위를 확인하세요. **단말기 선택**이 보이면 계산대에 있는 단말기의 **스테이션 ID**를 누르세요. 스테이션 ID는 Windcave가 각 단말기에 지정하는 이름입니다(예: `DOCS-STATION-1`). **단말기:** 와 ID가 보이면 현재 계산대에서 사용하는 단말기입니다. **변경**을 눌러 다른 단말기를 선택할 수 있습니다. 계산대는 선택을 기억합니다.
3. 잔액의 일부만 카드로 결제하려면 금액을 입력하세요. 나머지는 다음 결제 때 받으면 됩니다.
4. **Windcave Terminal로 … 전송**을 누르세요. 계산대에 **단말기에서 처리 중**과 네 단계인 **전송됨**, **단말기에서 처리 중**, **승인됨**, **매입 완료**가 표시되며, 매입 완료는 금액이 청구되었다는 뜻입니다.
5. 고객이 단말기에 카드를 대거나 삽입하거나 긁습니다. 결제가 매입되고 미결제 금액이 없으면 영수증이 열립니다. 남은 금액이 있으면 다른 타일로 결제받으세요.

1. **Windcave Terminal** — 누르면 테두리가 표시되는 타일입니다.
2. **단말기 선택** 아래의 **스테이션 ID** — 계산대에 있는 단말기를 누르세요. 계산대에서 하나를 선택하면 이 행에 **단말기:** 와 해당 ID, **변경**이 표시됩니다.
3. **결제 금액** — 이번 결제에 사용할 금액입니다. 더 적은 금액을 입력해 잔액 일부만 카드로 결제할 수 있습니다.
4. **전체 잔액** — 아직 결제되지 않은 전체 금액을 **결제 금액**에 다시 입력합니다.
5. **Windcave Terminal로 … 전송** — 단말기 결제를 시작합니다. 단말기를 선택할 때까지 비활성화됩니다.
6. **레거시** — 자체 결제 페이지가 있는 게이트웨이를 위한 다른 결제 탭입니다. 단말기에서 서명을 요청하면 사용하세요.

네 단계 아래의 **세부 정보**를 누르면 결제 기록과 결제가 전송된 스테이션을 볼 수 있습니다. 단말기에서는 팁, 추가 요금 또는 현금 인출을 처리할 수 없습니다.

### 단말기에서 질문하는 경우 {#terminal-questions}

단말기에서 고객의 서명이 일치하는지 묻는 등 결제가 멈추고 질문할 수 있습니다. 이 버전의 **결제** 탭에는 질문이 표시되지 않습니다. **레거시** 탭에는 표시됩니다.

1. **레거시** 탭을 열고 **Windcave Terminal**을 선택하세요. [레거시 탭](../../pos/checkout/legacy-tab.mdx)을 참조하세요.
2. 그 탭에서 결제를 시작하세요. 주문 전체 금액을 한 번에 결제합니다.
3. 단말기에서 질문하면 결제 페이지에 단말기 자체 버튼(예: **예**, **아니요**)과 질문이 표시됩니다. 답변을 누르세요.

### 결제 취소 {#cancel}

고객이 결제하기 전에 **단말기에서 취소**를 누르세요. 단말기 자체에 **취소** 버튼이 표시될 때만 작동합니다. 그렇지 않으면 계산대에 *지금은 단말기에서 취소를 제공하지 않습니다. 단말기에서 취소하세요.*라고 표시됩니다.

취소는 요청입니다. 카드 정보를 이미 읽었다면 결제가 완료될 수 있습니다. 계산대에는 **취소 중 — 단말기 확인 대기 중**이 표시되고 계속 확인한 뒤 결과를 보여 줍니다. 다른 방식으로 결제받기 전에 결과를 기다리세요.

계산대에서 응답을 받지 못하면 **이 결제 해제**가 표시됩니다. 해제는 취소를 뜻하지 않습니다. 관리자가 Windcave 포털에서 주문에 승인된 결제가 없음을 확인한 다음에만 누르세요. 이후 다른 방식으로 주문을 결제할 수 있으며, 매장은 계속 단말기 상태를 확인합니다.

## 문제 해결 {#goes-wrong}

### 고객이 결제했을 수 있는 경우 {#may-have-paid}

:::warning 결제를 다시 받지 마세요
다음 두 경우에는 카드로 이미 결제했을 수 있습니다. 관리자는 먼저 Windcave 포털에서 주문 번호로 판매 내역을 확인해야 합니다.
:::

**단말기 결과를 확인할 수 없습니다. 결제를 다시 받기 전에 Windcave를 확인하세요.** 계산대가 이미 전송한 결제를 다시 확인했지만 Windcave의 응답이 불분명했습니다. 관리자가 포털에서 판매 내역을 찾아 확인한 뒤에만 결제를 다시 받으세요.

**결제 실패: 단말기에서 다른 금액을 확인했습니다.** 단말기가 계산대에서 보낸 금액과 다른 금액을 승인해 계산대에는 기록되지 않았지만 카드로 청구되었을 수 있습니다. 다시 결제받지 마세요. 관리자에게 포털에서 주문 번호로 판매 내역을 찾아 단말기에서 청구한 금액과 주문 금액을 비교해 달라고 요청하세요.

## Windcave 결제 환불 {#refunds}

환불은 Windcave를 통해 판매를 받은 스테이션으로 처리되며, 전체 금액 또는 일부 금액을 환불할 수 있습니다.

1. POS에서 주문의 환불 화면을 여세요. [환불](../../pos/refunds.mdx)을 참조하세요.
2. **Windcave Terminal로 환불**을 선택하고 **환불 처리**를 누르세요.
3. 매장은 Windcave의 응답을 최대 20초 동안 기다린 다음 결과를 주문 메모에 추가합니다.

WooCommerce의 **Windcave Terminal을 통해 환불 …** 버튼을 사용하는 WP Admin 환불도 같은 방식으로 처리됩니다.

환불이 **대기 중** 상태로 남아 있으면 다시 환불하기 전에 Windcave 포털에서 확인하세요.

<Accordion>
  <AccordionItem question="환불이 대기 중 상태로 남아 있습니다">

  Windcave가 20초 안에 응답하지 않았거나 요청한 금액과 다른 금액을 승인했습니다. 매장은 재시도하지 않습니다. Windcave 포털에서 환불을 확인하세요. 환불이 처리되었다면 고객이 금액을 돌려받았고, 처리되지 않았다면 다시 환불하세요.

  </AccordionItem>
  <AccordionItem question="버전 0.1에서 받은 판매 건을 환불할 수 없습니다">

  환불이 *이 판매 건을 환불하기 전에 POS 설정에서 기본 스테이션을 구성하세요.*라는 메시지와 함께 중지됩니다. 확장 기능 버전 0.1은 판매를 받은 스테이션을 기록하지 않았으므로 버전 1.0에서는 매장 전체 기본 스테이션으로 환불합니다. 이제 각 계산대에서 **설정 > 카드 리더기** 아래 스테이션을 선택하며, WCPOS 2.0에는 아직 매장 전체 기본값이 없습니다. Windcave 포털이나 단말기에서 환불한 다음 WooCommerce에서 **수동으로 환불 …** 을 기록하세요.

  </AccordionItem>
</Accordion>

## Windcave Terminal 설정 {#setup}

관리자가 매장마다 한 번 WP Admin에서 설정한 다음 각 계산대에서 스테이션을 선택합니다. 매장은 인터넷을 통해 Windcave 경유로 각 단말기에 연결되므로 페어링할 필요가 없고 어느 계산대에서든 모든 단말기를 사용할 수 있습니다.

### 요구 사항 {#requirements}

HIT 인증 정보인 **HIT 사용자 이름**과 **HIT 키**, 그리고 각 단말기의 **스테이션 ID**가 필요합니다. 모두 Windcave에서 발급하며 WP Admin에서 조회하거나 만들 수 없습니다. Windcave에 연락해 **UAT** HIT 인증 정보와 각 단말기의 스테이션 ID를 요청하거나, 개발자 계정용 Windcave [연동 요구 사항 양식](https://www.windcave.com/merchant-attended-developer-hit)을 사용하세요. UAT와 운영 환경은 각각 별도의 사용자 이름과 키를 사용하며, Windcave는 연동을 인증하면 **공급업체 ID**를 발급합니다.

<RequirementsList>
  <RequirementItem label="Windcave 계정">HIT 인증 정보와 단말기마다 하나의 스테이션 ID. Windcave가 연동을 인증할 때까지 UAT 인증 정보 사용</RequirementItem>
  <RequirementItem label="단말기">HIT 결제를 지원하는 Windcave 단말기</RequirementItem>
  <RequirementItem label="WCPOS">WCPOS Pro 2.0 이상과 확장 기능 버전 1.0 이상</RequirementItem>
  <RequirementItem label="서버">WooCommerce 및 DOM 확장 모듈(php-xml)이 포함된 PHP 7.4 이상</RequirementItem>
</RequirementsList>

### 확장 기능 설치 {#install}

`WP Admin > POS > 설정 > 확장`을 열고 **Windcave Terminal for WooCommerce**를 찾아 설치하고 활성화하세요. 버전 1.0 이상이 필요하며 버전 0.1은 WCPOS 2.0 이전 버전용입니다. [확장 기능](../../extensions/index.mdx#installing-an-extension)을 참조하세요.

[GitHub 릴리스 페이지](https://github.com/wcpos/windcave-terminal-for-woocommerce/releases)에서 **플러그인 zip**(소스 코드 zip이 아님)을 다운로드해 `플러그인 > Add Plugin > 플러그인 업로드`에서 업로드할 수도 있습니다.

WCPOS Pro 2.0이 없으면 WP Admin에 *Windcave Terminal을 사용하려면 WooCommerce POS Pro 2.0 이상이 필요합니다.*라고 표시되며 결제 게이트웨이가 추가되지 않습니다. PHP 7.4 미만이거나 DOM 확장 모듈이 없으면 활성화가 거부됩니다. 호스팅 업체에 **php-xml**을 활성화해 달라고 요청하세요.

### HIT 인증 정보 입력 {#credentials}

`WP Admin > WooCommerce > 설정 > 결제`로 이동하여 **Windcave Terminal**을 여세요.

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[410, 0], [410, 0], [410, 0], [850, 0], [410, 0], [410, 0]]} maxWidth={720} alt="WP Admin, Windcave Terminal 설정 화면: 환경은 UAT(테스트), HIT 사용자 이름, HIT 키, 스테이션 ID 및 공급업체 ID는 비어 있고 POS 이름은 WCPOS인 모습">

1. **환경** — 기본값인 **UAT(테스트)** 로 두세요. **운영 환경**은 Windcave가 연동을 인증하고 운영 환경 인증 정보를 받은 뒤 사용합니다.
2. **HIT 사용자 이름** — 선택한 환경에 대해 Windcave에서 받은 값입니다.
3. **HIT 키** — Windcave에서 받은 값입니다. 저장하면 필드가 비어 있습니다. 저장된 키를 유지하려면 비워 두세요.
4. **스테이션 ID** — 단말기마다 하나씩 한 줄에 입력하세요. Windcave에서 발급하며 자동으로 검색되지 않습니다.
5. **공급업체 ID** — Windcave에서 발급할 때까지 비워 두세요.
6. **POS 이름** — Windcave에 표시되는 POS 이름입니다. 기본값은 `WCPOS`입니다.

</JourneyShot>

아래의 **결과 알림(FPRN)** 은 선택 사항입니다. 선택하면 계산대 자체 확인을 보완하도록 결과가 준비될 때 Windcave가 매장에도 알립니다. 작동하려면 사이트에 인터넷에서 접속할 수 있어야 합니다.

**변경 사항 저장**을 클릭하세요.

### WCPOS에서 활성화 {#enable}

`WP Admin > POS > 설정 > 결제`로 이동해 **게이트웨이** 표에서 **Windcave Terminal**을 찾아 **활성화됨**을 켜세요. 이 화면은 변경 사항을 즉시 저장하므로 저장 버튼이 없습니다.

WooCommerce 설정 페이지의 **활성화/비활성화**는 끄세요. 여기서 **활성화됨**을 켜면 해당 상자의 선택 여부와 관계없이 POS에서 결제 게이트웨이를 사용합니다. [결제 설정](../../settings/wp-admin/checkout.mdx#enabling-a-gateway)을 참조하세요.

<JourneyShot manifest={manifest} device="desktop" step={2} offsets={[[172, 0], [-26, 0]]} maxWidth={720} alt="WP Admin의 POS 설정, 결제 화면: 게이트웨이 표의 두 행으로, Vipps MobilePay는 켜져 있고 Windcave Terminal은 꺼져 있는 모습">

1. **Windcave Terminal** — **게이트웨이** 표에서 확장 기능에 해당하는 행입니다.
2. **활성화됨** — 게이트웨이 ID 옆의 스위치입니다. 켜세요. 계산대를 새로고침하면 **Windcave Terminal** 타일이 표시됩니다.

</JourneyShot>

### 각 계산대에서 스테이션 선택 {#till-terminal}

각 계산대에서 **설정 > 카드 리더기**를 여세요. 입력한 각 스테이션 ID가 **스마트 리더기** 아래에 리더기로 표시되고 모두 **온라인**으로 표시됩니다. 확장 기능은 Windcave에 단말기가 켜져 있는지 묻지 않습니다. 해당 계산대의 스테이션에서 **이 리더기 사용**을 누르세요. 해당 행에 **선택됨**이 표시됩니다. 캐셔는 결제 시 계속 **변경**을 누를 수 있습니다.

스테이션이 하나뿐이면 선택할 필요가 없습니다. 모든 계산대에서 이미 **선택됨**으로 표시됩니다. [스마트 리더기 선택](../../hardware/card-readers/index.mdx#smart-readers)을 참조하세요.

### 작동 확인 {#check}

1. Windcave Terminal 설정 페이지로 돌아가면 설정 아래에 `uat: HIT credentials configured (not verified).`라고 표시됩니다. 사용자 이름과 키를 저장했다는 뜻이며 Windcave가 승인했다는 뜻은 아닙니다. `HIT credentials missing.`은 둘 중 하나가 비어 있다는 뜻입니다.
2. 계산대에서 POS를 새로고침하고 **결제**를 누르세요. 결제 방법 중 하나로 **Windcave Terminal** 타일이 표시됩니다. 누르면 키패드 위의 **단말기 선택** 아래에 스테이션 ID가 표시되거나 **단말기:** 와 해당 계산대에서 사용하는 단말기가 표시됩니다.
3. UAT 단말기에서 소액 판매를 진행한 다음 환불하세요. 연결 테스트 버튼은 없습니다. 첫 판매로 인증 정보와 스테이션 ID를 확인합니다.

### 버전 0.1에서 업그레이드 {#upgrade}

- 먼저 WCPOS, WCPOS Pro 및 앱을 2.0으로 업데이트한 다음 확장 기능을 업데이트하세요.
- 업그레이드 중 진행 중인 결제는 이어집니다. 이중으로 청구되지 않습니다.
- 버전 0.1에서 보류한 결제는 주문이 아직 미결제 상태라면 이어집니다. 그렇지 않으면 주문에 *Windcave TxnRef …는 1.0.0 업그레이드 전에 보류되었으며 더 이상 자동으로 추적되지 않습니다.*라는 메모가 추가됩니다. Windcave 포털에서 해당 결제를 확인하세요. 승인되었다면 포털에서 환불하거나 주문에 직접 기록하세요.
- 버전 0.1의 다음 설정은 제거되었습니다: **기본 스테이션 ID**, **단말기 선택 잠금**, **결제 로그**, **로그 수준**. 이제 각 계산대에서 **설정 > 카드 리더기** 아래 스테이션을 선택합니다.
- 보류 기능도 제거되었으며 단말기 영수증 텍스트가 더 이상 주문의 비공개 메모로 추가되지 않습니다.
- 버전 0.1에서 받은 판매 건의 환불은 [Windcave 결제 환불](#refunds)을 참조하세요.

## 설정 참고 {#settings}

`WP Admin > WooCommerce > 설정 > 결제 > Windcave Terminal`에 있습니다:

| 설정 | 기능 |
|---|---|
| **활성화/비활성화** | 온라인 매장의 결제 화면에 게이트웨이를 제공합니다. 끄세요. POS에는 `POS > 설정 > 결제` 아래에 별도의 스위치가 있습니다 |
| **제목** | 계산대에 표시되는 타일 이름입니다. 기본값은 `Windcave Terminal`입니다 |
| **설명** | 기본값은 `Pay in person on the Windcave terminal.`입니다 |
| **환경** | **UAT(테스트)**(기본값) 또는 **운영 환경**입니다. 각 환경에 별도의 HIT 인증 정보가 있습니다. 운영 환경을 사용하려면 Windcave 인증이 필요합니다. 한 환경에서 시작한 결제는 항상 해당 환경에서 확인합니다 |
| **HIT 사용자 이름** | 선택한 환경에 맞게 Windcave에서 발급합니다 |
| **HIT 키** | Windcave에서 발급합니다. 저장 후에는 표시되지 않으므로 그대로 두려면 비워 두세요 |
| **스테이션 ID** | 단말기마다 하나씩 한 줄에 입력합니다. 중복 항목은 제거됩니다 |
| **공급업체 ID** | 인증 중 Windcave와 협의합니다. 그때까지 비워 두세요 |
| **POS 이름** | Windcave에서 POS를 식별하는 이름입니다. 기본값은 `WCPOS`입니다 |
| **결과 알림(FPRN)** | 계산대의 상태 확인을 보완하도록 결과가 준비되면 Windcave도 매장에 알려줍니다. 기본값은 꺼짐입니다 |

## 로그 및 지원 번들 {#logs-and-support-bundle}

설정 페이지 아래쪽에 지원 번들, 인증 정보 상태 줄, 로그 링크가 있습니다.

<JourneyShot manifest={manifest} device="desktop" step={3} offsets={[[200, 0], [80, 0], [-20, 0]]} maxWidth={720} alt="아직 설정되지 않은 매장의 Windcave Terminal 설정 페이지 아래쪽. 지원 번들 및 지원 번들 다운로드 버튼, uat: HIT credentials missing 상태 줄, 로그 보기가 표시된 모습">

1. **인증 정보 상태 줄** — 아직 설정되지 않은 이 매장에는 `HIT credentials missing.`이라고 표시됩니다. 설정을 마치면 `HIT credentials configured (not verified).`라고 표시되어야 합니다.
2. **로그 보기** — `WooCommerce > Status > 로그`를 열고 소스 `windcave-terminal`을 표시합니다.
3. **지원 번들 다운로드** — WCPOS 지원팀에 보낼 파일입니다.

</JourneyShot>

로그에는 Windcave에 보낸 각 요청과 응답이 기록되며 HIT 키와 카드 번호는 가려집니다.

결제에 문제가 생기면 **지원 번들 다운로드**를 클릭해 파일과 **주문 번호**를 WCPOS 지원팀에 보내세요. 이 버튼은 WCPOS Pro에서 제공하며 사이트의 모든 POS 결제 제공업체 정보를 포함합니다. 비밀 정보와 카드 번호는 제거됩니다.

## 지원하지 않는 기능 {#scope-and-limitations}

- Windcave가 연동을 인증하기 전의 실제 결제.
- 팁, 추가 요금, 현금 인출 또는 지금 승인하고 나중에 매입하는 기능.
- **결제** 탭에서 단말기의 질문에 답하는 기능. **레거시** 탭을 사용하세요.
- 단말기 자동 검색: 각 스테이션 ID를 직접 입력해야 합니다.
- 첫 결제 전에 HIT 인증 정보를 확인하는 기능.

<details>
<summary>개발자용 작동 방식</summary>

결제 게이트웨이는 HTTPS를 통해 Windcave **HIT(Host Initiated Transaction)** 를 사용합니다. UAT는 `uat.windcave.com`, 운영 환경은 `sec.windcave.com`입니다. 각 단말기는 **스테이션 ID**로 식별됩니다.

결제 시 계산대의 금액으로 Purchase를 전송하고 `Order #`와 주문 번호를 판매자 참조 번호로 사용한 다음 WCPOS Pro가 완료될 때까지 상태를 확인합니다. 계산대에서 다시 요청하면 확장 기능은 다른 Purchase를 시작하지 않고 먼저 같은 거래 참조 번호를 조회합니다. Windcave가 30초 이내에 Purchase를 등록하지 않으면 전송되지 않은 것으로 간주합니다.

**결과 알림(FPRN)** 을 켜면 각 Purchase에서 Windcave가 매장의 WCPOS 결제 웹훅 `wp-json/wcpos/v2/payments/webhook`을 `provider=windcave`와 거래 참조 번호를 포함해 호출하도록 요청합니다. 이 호출은 알림일 뿐이며 매장은 Windcave에 직접 결과를 조회합니다.

환불은 원래 Windcave 거래를 대상으로 하는 HIT 연결 환불이며 입력한 금액만큼 처리됩니다. 매장은 최대 20초 동안 2초마다 상태를 확인합니다.

</details>
