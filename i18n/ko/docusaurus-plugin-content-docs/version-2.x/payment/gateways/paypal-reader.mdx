# PayPal Reader(Zettle) 결제 게이트웨이 {#paypal-reader-zettle-gateway}

POS 단말기가 주문 합계를 PayPal Reader로 전송하면 고객이 리더기에 카드를 대거나 삽입합니다. 리더기가 결제 완료를 알리면 판매가 자동으로 완료됩니다. 이 페이지는 POS 단말기에서 [결제 받기](#take-payment)와 WP Admin에서 [설정하기](#setup)의 두 부분으로 구성되어 있습니다.

:::info Pro 기능
PayPal Reader 확장 기능을 확장 기능 디렉터리에서 설치하거나 POS 단말기에서 사용하려면 [WCPOS Pro](../../getting-started/pro-license.mdx)가 필요합니다.
:::

## 결제 받기 {#take-payment}

:::note 시작하기 전에
- POS 단말기와 매장 사이트가 온라인 상태여야 합니다. 결제는 POS 내부에 표시되는 매장 자체 결제 페이지에서 진행됩니다.
- WP Admin 접근 권한이 있는 담당자가 [결제 게이트웨이를 설정하고 리더기를 페어링](#setup)해 두어야 합니다.
- 매장에서 **계산대 열기 및 닫기**를 사용한다면 계산대가 열려 있어야 합니다. 계산대가 닫혀 있으면 POS 단말기에서 결제를 기록할 수 없습니다. [계산대](../../settings/wp-admin/registers.mdx#one-register)를 참고하세요.
:::

1. 장바구니에 상품을 담고 **결제**를 누르세요.
2. **레거시** 탭을 여세요. POS 내부에 매장 결제 페이지가 열립니다. [레거시 탭](../../pos/checkout/legacy-tab.mdx)을 참고하세요.
3. **PayPal Reader**를 선택하세요. 매장에서 다른 이름으로 설정했을 수도 있습니다. 패널에 **리더기를 불러오는 중…** 이 표시된 다음 **모드: 테스트. 결제를 시작할 준비가 되었습니다.** 가 표시됩니다(매장이 [실제 결제로 전환](#going-live)한 후에는 **모드: 실제 결제.** 가 표시됩니다).
4. 리더기를 선택하세요. 페어링된 각 리더기는 **앞쪽 카운터(준비됨)** 와 같이 이름이 표시된 버튼으로 나타나며, 첫 번째 리더기가 미리 선택되어 있습니다. 다른 리더기를 사용하려면 해당 버튼을 누르세요.

   :::warning
   패널 상단의 **테스트 모드**는 표시 문구일 뿐입니다. 리더기에서 실제 금액이 청구될 수 있습니다. [테스트 모드와 실제 결제로 전환하기](#going-live)를 참고하세요.
   :::

5. **리더기 결제 시작**을 누르세요. 패널에 **리더기에 연결 중…** 이 표시된 다음 **리더기가 준비되었습니다. 결제를 요청하는 중…** 이 표시되며, 주문 합계 전액이 해당 리더기로 전송됩니다.
6. 고객이 리더기에 카드를 대거나 삽입합니다. 리더기가 처리하는 동안 패널에는 **결제 진행 중…** 과 함께 리더기의 현재 단계가 괄호 안에 표시됩니다.
7. 리더기가 결제 완료를 알리면 패널에 **결제가 완료되었습니다. 주문을 제출하는 중…** 이 표시되고 POS가 영수증 화면으로 넘어갑니다.

판매가 자동으로 완료되므로 레거시 탭 하단의 **결제 처리**를 누를 필요가 없습니다. 리더기의 처리가 끝나기 전에 누르면 POS에 **주문을 제출하기 전에 PayPal Reader 결제를 완료하세요.** 가 표시됩니다.

버튼 아래의 어두운 상자에는 각 단계가 시간과 함께 한 줄씩 기록됩니다. 결제가 도중에 멈추면 이 기록을 확인하세요.

리더기로는 항상 주문 전액을 결제하므로 다른 결제 수단과 나누어 결제할 수 없습니다. 주문에 대해 이미 결제를 받은 경우 **레거시** 탭에 **전액 결제만 가능**이 표시되며 사용할 수 없습니다. 먼저 [해당 결제를 취소](../../pos/checkout/cancelling-a-payment.mdx)하세요.

### 결제 중단하기 {#cancel}

결제가 진행 중일 때 **결제 취소**를 누르세요. 리더기에 취소를 요청하고 POS 단말기가 리더기의 응답 수신을 중단하며, 패널에 **결제가 취소되었습니다.** 가 표시됩니다.

:::warning 다시 청구하기 전에 리더기를 확인하세요
**결제 취소**를 누르거나 리더기가 처리 중일 때 결제 페이지를 닫거나 새로고침하면 POS 단말기가 더 이상 리더기의 응답을 받지 않습니다. 그런데도 리더기에 결제가 승인되었다고 표시된다면 고객은 이미 결제한 것입니다. 다시 청구하지 마세요. **결제** 탭의 **카드** 타일로 결제를 기록하고 Zettle 계정에서 해당 결제를 확인하세요.
:::

고객에게 청구되지 않았음을 확인한 후 **리더기 결제 시작**을 눌러 다시 시도하거나, 탭을 닫고 다른 수단으로 결제를 받으세요.

## 판매 후 {#after-the-sale}

주문은 결제 완료로 표시되며, **거래 ID**는 해당 카드 결제의 Zettle ID이므로 Zettle 계정에서 같은 결제를 찾을 수 있습니다. 주문 메모에는 결제 시작 시각과 사용한 리더기(링크 ID 기준), 결제 완료 시각, 금액 불일치로 거부된 시각 또는 **결제 취소**로 취소한 시각이 기록됩니다.

## 환불 {#refunds}

이 확장 기능은 Zettle을 통한 환불을 지원하지 않으므로 **PayPal Reader로 환불**을 사용할 수 없습니다.

:::warning
고객에게 현금을 건네지 마세요. 카드 환불은 Zettle에서 처리하며, **현금으로 환불**은 WCPOS에 환불을 기록하기만 합니다. 계산대가 열려 있다면 계산대에서 예상하는 금전함의 현금 잔액도 같은 금액만큼 줄어듭니다. [현금 환불과 금전함](../../pos/refunds.mdx#drawer)을 참고하세요.
:::

1. Zettle 계정에서 카드 결제를 환불하세요.
2. **현금으로 환불**을 사용하여 주문에 환불을 기록하세요. [환불 대상](../../pos/refunds.mdx#destination)을 참고하세요.

## 문제가 발생한 경우 {#goes-wrong}

**아직 페어링된 리더기가 없습니다. 매장 관리자에게 페어링을 요청하세요…** Zettle 계정에 페어링된 리더기가 없어 **리더기 결제 시작**이 비활성화된 상태로 유지됩니다. WP Admin 접근 권한이 있는 담당자가 리더기를 페어링해야 합니다. [설정하기](#setup)의 **리더기 페어링하기**를 참고하세요.

**패널에 리더기에 연결 중…이 계속 표시됨** 리더기가 결제할 준비가 되지 않은 상태입니다. 절전 상태이거나 전원이 꺼져 있거나 오프라인 상태이거나 다른 작업을 처리 중일 수 있습니다. 리더기의 절전 상태를 해제하고 홈 화면이 표시되는지, 온라인 상태인지 확인하세요. **결제 취소**를 누르고 [결제 중단하기](#cancel)의 설명대로 리더기에 결제 내역이 없는지 확인한 다음 **리더기 결제 시작**을 다시 누르세요.

**결제가 취소되었습니다.** 리더기에서 또는 **결제 취소**를 눌러 결제가 취소되었습니다. **결제 취소**를 눌렀다면 [결제 중단하기](#cancel)의 설명대로 먼저 리더기를 확인하세요. 그런 다음 다시 시작하거나 다른 수단으로 결제를 받으세요.

### 결제에 실패했습니다. 카드에 청구되었나요? {#payment-failed}

**결제에 실패했습니다.** 뒤에 표시되는 내용으로 고객의 결제 여부와 다시 청구해도 되는지를 알 수 있습니다. 메시지를 확인하고 해당하는 안내를 따르세요.

- **결제 금액이 일치하지 않습니다.**: [청구됨, 먼저 환불하세요](#failed-mismatch).
- 괄호 안에 사유가 표시됨: [청구되지 않음, 다시 시도하세요](#failed-reason).
- **요청에 실패했습니다.**, **잘못된 서버 응답입니다.**, **잘못된 요청입니다.** 또는 **잘못된 주문 접근입니다.**: [청구됨, 결제를 기록하세요](#failed-not-recorded).
- 뒤에 아무 내용도 없거나 여기에 없는 메시지가 표시됨: [다시 시도하기 전에 확인하세요](#failed-connection).

#### 결제 금액 불일치: 청구됨, 먼저 환불하세요 {#failed-mismatch}

**카드 청구 여부: 청구됨.** 패널에 **결제에 실패했습니다. 결제 금액이 일치하지 않습니다.** 가 표시됩니다. 리더기에서 금액은 청구했지만 결제 시작 후 주문 합계가 변경되어 주문이 거부되고 미결제 상태로 남습니다. Zettle 계정에서 해당 결제를 환불한 다음 올바른 합계로 새 결제를 시작하세요. 이를 방지하려면 리더기 결제가 진행되는 동안 장바구니를 변경하지 마세요. **결제 취소**를 누르고 장바구니를 변경한 다음 새 결제를 시작하세요.

#### 괄호 안에 사유가 표시됨: 청구되지 않음, 다시 시도하세요 {#failed-reason}

**카드 청구 여부: 청구되지 않음.** 패널에 **결제에 실패했습니다.** 와 함께 괄호 안에 사유가 표시됩니다. 카드 승인 거절 등의 이유로 리더기나 Zettle에서 결제를 받지 않았습니다. **리더기 결제 시작**을 누르거나 다른 수단으로 결제를 받으세요.

#### **결제에 실패했습니다.** 만 표시되거나 여기에 없는 메시지가 표시됨: 다시 시도하기 전에 확인하세요 {#failed-connection}

**카드 청구 여부: 확인 불가.** 패널에 **결제에 실패했습니다.** 만 표시됩니다. POS 단말기와 Zettle의 연결이 끊겨 카드에 청구되었는지 확인할 수 없습니다. 이 페이지에 없는 메시지도 같은 방식으로 처리하세요. 리더기와 Zettle 계정의 결제 목록을 확인하세요. 결제 내역이 있으면 [결제 중단하기](#cancel)의 설명대로 기록하세요. 결제되지 않았음을 확실히 확인한 후에만 다시 시작하세요. 확인할 수 없다면 다시 청구하기 전에 Zettle 계정 담당자에게 문의하세요.

#### 요청에 실패했습니다. 또는 여기에 나열된 다른 메시지: 청구됨, 결제를 기록하세요 {#failed-not-recorded}

이 경우는 **결제에 실패했습니다.** 뒤에 **요청에 실패했습니다.**, **잘못된 서버 응답입니다.**, **잘못된 요청입니다.**, **잘못된 주문 접근입니다.** 가 표시될 때만 해당합니다. 다른 메시지가 표시되면 [결제에 실패했습니다.만 표시됨](#failed-connection)의 안내를 따르세요.

**카드 청구 여부: 청구됨.** 패널에는 리더기가 결제 완료를 알린 후에만 이 메시지가 표시됩니다. 리더기에서 결제를 받았지만 매장 사이트에서 기록하지 못해 주문이 미결제 상태로 남아 있습니다. Zettle 계정에서 해당 결제를 찾아 [결제 중단하기](#cancel)의 설명대로 기록하세요. Zettle 계정에 결제 내역이 없다면 [결제에 실패했습니다.만 표시됨](#failed-connection)의 안내를 따르고, 확실히 확인하기 전에는 다시 청구하지 마세요.

### 기타 메시지 {#other-messages}

**Zettle 인증 정보가 설정되지 않았습니다.** **Zettle 클라이언트 ID** 또는 **Zettle 어설션**이 비어 있습니다. 결제 게이트웨이를 설정한 담당자에게 입력을 요청하세요. [설정하기](#setup)의 **결제 게이트웨이 설정 입력하기**를 참고하세요.

**Zettle OAuth 교환에서 HTTP …을 반환했습니다로 시작하는 메시지** Zettle에서 인증 정보를 거부했습니다. 결제 게이트웨이를 설정한 담당자에게 **Zettle 클라이언트 ID**와 **Zettle 어설션**을 확인해 달라고 요청하세요.

**패널에 버튼은 표시되지만 리더기를 불러오는 중…이 표시되지 않음** 결제 페이지의 스크립트가 로드되지 않고 있습니다. [결제 게이트웨이의 결제 페이지가 이상하게 표시되는 경우](../../pos/checkout/troubleshooting.mdx#checkout-settings-troubleshooting)를 참고하세요.

<details>
<summary>설정 중 표시되는 메시지</summary>

**리더기를 페어링하기 전에 위의 Zettle 클라이언트 ID와 어설션을 저장하세요.** **페어링된 리더기** 섹션은 두 인증 정보가 모두 입력될 때까지 기다립니다. 인증 정보를 입력하고 저장하세요.

**먼저 페어링 코드를 입력하세요.** **페어링 코드** 입력란이 비어 있습니다. 리더기에 표시된 코드를 확인하고 입력하세요.

**페어링된 리더기를 불러올 수 없습니다:** 뒤에 Zettle의 응답이 표시됩니다. 설정 페이지에서 Zettle에 연결할 수 없거나 Zettle에서 인증 정보를 거부했습니다. 인증 정보를 확인하고 다시 저장하세요.

**리더기 페어링 시 Zettle API에서 HTTP …을 반환했습니다로 시작하는 메시지가 표시됨** Zettle에서 페어링 코드를 거부했습니다. 리더기에서 **설정 → 개발자와 연결**을 열어 새 코드를 받고, 표시된 그대로 입력한 다음 리더기가 온라인 상태인지 확인하세요. 계속 실패하면 **Zettle 클라이언트 ID**와 **Zettle 어설션**이 저장되어 있는지 확인하세요.

**PayPal Reader: 모의 리더기가 활성화되어 있습니다.** 개발자 설정인 `PRWC_USE_MOCK_READER`가 `wp-config.php`에 정의되어 있습니다. 이 설정이 적용되어 있는 동안에는 실제 결제를 받지 않습니다. 개발자나 호스팅 업체에 해당 설정을 제거해 달라고 요청하세요.

</details>

## 설정하기 {#setup}

이 부분은 매장의 WP Admin을 관리하는 담당자를 위한 안내입니다. 확장 기능 설치부터 POS에서 활성화하기까지 다섯 단계로 설명합니다.

<details>
<summary>설치, 인증 정보 입력, 리더기 페어링 및 POS에서 활성화하기</summary>

<Steps>
  <StepCard number="1" title="확장 기능 설치하기">

`WP Admin > POS > 설정 > 확장`을 열고 **PayPal Reader for WooCommerce**를 찾아 **설치**를 클릭한 다음 **활성화**를 클릭하세요. [확장 기능 설치하기](../../extensions/index.mdx#installing-an-extension)를 참고하세요.

디렉터리를 사용하지 않는 경우 [GitHub 릴리스 페이지](https://github.com/wcpos/paypal-reader-for-woocommerce/releases)에서 **플러그인 zip**(소스 코드 zip이 아님)을 다운로드하고 `플러그인 > Add Plugin`에서 **플러그인 업로드**를 선택하여 업로드하세요. WooCommerce가 활성화되어 있어야 합니다.

  </StepCard>
  <StepCard number="2" title="Zettle 인증 정보 발급받기">

Zettle 개발자 포털에서 Zettle 계정의 **클라이언트 ID**와 **어설션**(JWT)을 발급받으세요. 실제 금액을 청구하지 않고 결제 게이트웨이를 사용해 보려면 먼저 Zettle 개발자(테스트) 가맹점 계정을 사용하세요.

사용할 수 있는 PayPal Reader 모델과 국가는 WCPOS가 아닌 Zettle 계정에 따라 결정됩니다. 리더기를 구매하기 전에 PayPal에 확인하세요.

  </StepCard>
  <StepCard number="3" title="결제 게이트웨이 설정 입력하기">

1. `WP Admin > WooCommerce > 설정 > 결제`로 이동하여 **PayPal Reader**를 여세요.
2. 테스트 계정으로 사용해 보는 동안에는 기본값인 **테스트 모드 활성화**의 선택 상태를 유지하세요.
3. **Zettle 클라이언트 ID**와 **Zettle 어설션**을 입력하세요.
4. 선택 사항: 캐셔가 결제 페이지에서 선택할 **제목**과 그 **설명**을 변경하세요.
5. 저장하세요.

  </StepCard>
  <StepCard number="4" title="리더기 페어링하기">

1. 같은 설정 페이지 하단의 **페어링된 리더기**로 스크롤하세요. 두 인증 정보를 모두 저장하면 표시됩니다.
2. PayPal Reader에서 **설정 → 개발자와 연결**을 여세요. 리더기에 페어링 코드가 표시됩니다.
3. **새 리더기 페어링**에서 **페어링 코드**와 `Front counter` 같은 **리더기 이름**을 입력하세요. 이름을 입력하지 않으면 `WCPOS PayPal Reader`라는 이름이 지정됩니다.
4. **리더기 페어링**을 클릭하세요. 페이지에 **리더기가 페어링되었습니다.** 가 표시되고 리더기가 목록에 추가됩니다.

모든 POS 단말기에는 Zettle 계정에 페어링된 모든 리더기가 표시되며, 캐셔가 결제할 때 하나를 선택합니다. 리더기를 제거하려면 해당 리더기 옆의 **페어링 해제**를 클릭하고 확인하세요.

  </StepCard>
  <StepCard number="5" title="POS에서 활성화하기" isLast>

`WP Admin > POS > 설정 > 결제`로 이동하여 **PayPal Reader**를 찾고 **활성화됨**을 켜세요. [결제 게이트웨이 활성화하기](../../settings/wp-admin/checkout.mdx#enabling-a-gateway)를 참고하세요.

:::note
**웹 결제에 PayPal Reader 활성화(WCPOS에는 필요하지 않음)** 는 선택하지 않은 상태로 두세요. 이 옵션은 온라인 매장에 결제 게이트웨이를 표시하는 역할만 합니다. POS에서는 여기에서 활성화하면 사용할 수 있습니다.
:::

  </StepCard>
</Steps>

</details>

## 테스트 모드와 실제 결제로 전환하기 {#going-live}

**테스트 모드**는 리더기를 샌드박스로 전환하지 않습니다. Zettle은 테스트 결제와 실제 결제에 동일한 주소를 사용하며, 실제 금액이 오가는지는 인증 정보에 연결된 계정에 따라 결정됩니다. 테스트 모드는 결제 패널의 표시 문구만 변경합니다. **테스트 모드** 배지와 상태 줄의 **모드: 테스트.** 가 이에 해당합니다.

실제 결제로 전환하려면 다음 단계를 따르세요.

1. **Zettle 클라이언트 ID**와 **Zettle 어설션**을 실제 Zettle 계정의 정보로 교체하세요.
2. **테스트 모드 활성화**의 선택을 해제하고 저장하세요.
3. **페어링된 리더기**를 확인하세요. 목록은 Zettle 계정에서 가져오므로 테스트 계정에 페어링된 리더기는 표시되지 않습니다. [설정하기](#setup)의 **리더기 페어링하기**에 따라 다시 페어링하세요.
4. 소액으로 실제 결제를 진행하고 Zettle에서 환불하세요.

## 설정 참조 {#settings}

`WP Admin > WooCommerce > 설정 > 결제 > PayPal Reader`에서 확인할 수 있습니다. 위 단계에서는 필요한 설정을 다뤘습니다. 모든 설정과 기본값을 확인하려면 목록을 펼치세요.

<details>
<summary>전체 6개 설정과 페어링 패널</summary>

| 설정 | 기능 |
|---|---|
| **활성화/비활성화** | **웹 결제에 PayPal Reader 활성화(WCPOS에는 필요하지 않음)**. 온라인 매장에 결제 게이트웨이를 표시합니다. 온라인에서는 기존 주문의 결제 페이지에서만 작동하므로 꺼 두세요. 기본값은 꺼짐입니다. POS에는 `POS > 설정 > 결제`에 별도의 스위치가 있습니다 |
| **제목** | 캐셔가 결제 페이지에서 선택하는 이름입니다. 기본값은 `PayPal Reader`입니다 |
| **설명** | 제목 아래에 표시되는 문구입니다. 기본값은 `Pay in person using PayPal Reader.`입니다 |
| **테스트 모드** | **테스트 모드 활성화**. 결제 패널에 **테스트 모드** 배지를 표시합니다. 기본값은 켜짐입니다. 결제가 전송되는 대상은 변경하지 않습니다 |
| **Zettle 클라이언트 ID** | Zettle 개발자 포털에서 발급받은 Zettle OAuth 클라이언트 ID입니다 |
| **Zettle 어설션** | Zettle OAuth 어설션(JWT)입니다. 비밀번호처럼 숨겨집니다 |

설정 아래의 **페어링된 리더기**에는 각 리더기의 이름과 **링크 ID**, **페어링 해제**가 표시됩니다. **새 리더기 페어링**에는 **페어링 코드**와 **리더기 이름**을 입력합니다.

</details>

## 로그 {#logs}

먼저 주문 메모를 확인하세요. 결제 시작, 완료 또는 금액 불일치로 인한 거부, POS 단말기에서 **결제 취소**를 누른 사실이 해당 주문에 기록됩니다. 카드 승인 거절, 리더기에서의 취소, 연결 끊김은 기록되지 않습니다. 결제 페이지의 로그 상자를 확인하세요.

Zettle의 리더기 서비스가 요청을 거부하거나 서비스에 연결할 수 없는 경우, 확장 기능은 `WP Admin > WooCommerce > Status > 로그`에도 `paypal-reader-for-woocommerce`라는 소스로 기록을 남깁니다. 도움을 요청할 때 해당 로그와 **주문 번호**를 보내세요.

## 지원하지 않는 기능 {#limitations}

- WooCommerce 또는 POS에서 Zettle을 통한 환불.
- 리더기에서 팁 받기.
- 분할 결제: 리더기로는 항상 주문 전액을 결제합니다.
- 결제 페이지를 닫거나 새로고침한 후 결제 이어서 진행하기.
- 온라인 매장의 일반 결제. 온라인에서는 기존 주문의 결제 페이지에서만 작동합니다.

<details>
<summary>개발자를 위한 작동 방식</summary>

매장 사이트는 JWT-bearer OAuth 인증 방식(`oauth.zettle.com`)으로 Zettle에 로그인하며, 액세스 토큰을 만료 30초 전까지 캐시합니다. 페어링, 리더기 목록 및 결제 세션에는 Zettle의 **Reader Connect** API(`reader-connect.zettle.com/v1/integrator`)를 사용합니다. 페어링 시 리더기의 코드로 링크 제안을 수락하며, 각 리더기는 하나의 링크입니다.

**리더기 결제 시작**은 매장 사이트에 선택한 링크의 세션을 열도록 요청합니다. 그러면 결제 페이지가 Zettle에 WebSocket 연결을 열고 리더기의 상태를 요청합니다. 리더기가 준비되면 팁 없이 주문 합계에 대한 결제 요청을 전송합니다. 진행 상황은 같은 소켓으로 수신됩니다. **결제 취소**는 이 소켓으로 취소 요청을 보냅니다.

리더기가 `COMPLETED`를 보고하면 페이지가 매장 사이트에 결과를 전송합니다. 매장 사이트는 금액이 주문 합계와 일치하는 경우에만 결과를 수락합니다. Zettle의 카드 결제 ID를 거래 ID로 저장하고 주문을 제출합니다. 이 검사를 통과하기 전에는 주문을 제출할 수 없습니다.

자동화 테스트에서는 `PRWC_USE_MOCK_READER`(또는 `paypal_reader_for_woocommerce_use_mock_reader` 필터)를 `PRWC_MOCK_CANCEL_BEHAVIOR`와 함께 사용하여 Zettle을 모의 리더기로 대체합니다. 설정 화면에는 표시되지 않으며, 켜져 있는 동안 WP Admin에 경고가 표시됩니다.

</details>
