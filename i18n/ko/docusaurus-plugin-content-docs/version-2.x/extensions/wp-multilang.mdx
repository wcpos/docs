**WP Admin:** `WP Admin → POS → Settings → Extensions`에서 설치하고, `WP Admin → POS → Stores`에서 매장별로 설정합니다.

[WP Multilang](https://wordpress.org/plugins/wp-multilang/)은 상품의 모든 번역을 하나의 상품 안에 저장하며, 상품을 일부 언어로만 제한할 수 있습니다. 무료 **WCPOS WP Multilang** 확장 기능은 POS에서 사용할 언어를 하나 지정하므로, 다른 언어로만 제한한 상품은 POS에 표시되지 않습니다.

캐셔가 설정할 항목은 없습니다. 첫 번째 섹션에서는 캐셔에게 달라지는 점을 설명합니다. 나머지 내용은 매장 관리자를 위한 안내입니다.

## 캐셔에게 표시되는 내용 {#what-the-cashier-sees}

상품 검색, 상품 격자, 옵션 상품의 옵션에는 매장 언어로 판매되는 상품이 표시됩니다.

- **언어 제한이 없는** 상품은 모든 매장에 표시됩니다.
- **일부 언어로 제한된** 상품은 매장 언어가 해당 언어에 포함되는 매장에만 표시됩니다.

캐셔의 판매 방식은 달라지지 않습니다. 평소처럼 장바구니에 담고, 결제를 받고, 영수증을 인쇄하세요. [결제](../pos/checkout/index.mdx)를 참고하세요.

## 확장 기능 설치 {#install}

:::note 시작하기 전에
[WooCommerce](https://woocommerce.com/)와 [WP Multilang](https://wordpress.org/plugins/wp-multilang/)이 활성화되어 있어야 하며, WP Multilang에 언어가 설정되어 있어야 합니다. **WP Admin**에 로그인할 관리자 계정도 필요합니다. 두 플러그인이 모두 활성화되어야 WordPress에서 이 확장 기능을 활성화할 수 있습니다.
:::

관리자가 **WP Admin**에서 한 번 설치하면 됩니다. [매장 언어를 선택](#store-language)하지 않으면 POS는 WP Multilang의 **기본 언어**를 사용합니다.

### WCPOS Pro 사용 시 {#install-pro}

1. **POS → 설정 → 확장 기능**으로 이동하세요.
2. **WCPOS WP Multilang**을 찾아 **설치**를 누르세요.
3. **활성화**를 누르세요.

업데이트와 자동 업데이트는 [확장 기능 설치](./index.mdx#installing-an-extension)를 참고하세요.

확장 기능을 활성화한 후에는 다음과 같이 진행하세요.

- 매장에 별도의 언어를 지정하려면 먼저 [매장 언어를 선택](#store-language)한 다음 [정상 작동 여부를 확인](#check)하세요.
- 그렇지 않으면 바로 [정상 작동 확인](#check)으로 이동하세요.

### 무료 플러그인 사용 시 {#install-free}

확장 기능 화면에 이 확장 기능이 표시되지만, **설치** 버튼을 사용하려면 Pro가 필요합니다. 대신 다음과 같이 설치하세요.

1. 확장 기능의 [최신 릴리스](https://github.com/wcpos/wcpos-wp-multilang/releases/latest)에서 `wcpos-wp-multilang.zip`을 다운로드하세요.
2. **플러그인 → 새 플러그인 추가**로 이동하고 **플러그인 업로드**를 누르세요.
3. 다운로드한 파일을 선택하고 **지금 설치**를 누르세요.
4. **플러그인 활성화**를 누르세요.

그런 다음 [정상 작동 여부를 확인](#check)하세요. Pro가 없으면 매장은 하나이며, WP Multilang의 기본 언어를 사용합니다.

### 정상 작동 확인 {#check}

POS는 각 기기에 상품 사본을 저장하므로, 변경 사항을 반영하려면 한 번 삭제해야 합니다.

#### WP Admin: 상품 두 개 준비하기 {#check-prepare}

테스트할 재고가 있는 상품 두 개를 고르세요. 하나는 매장 언어로 판매되는 상품, 다른 하나는 그렇지 않은 상품이어야 합니다. 상품 언어는 POS가 아닌 **WP Admin**에서 설정합니다. 두 상품 각각에 대해 다음 단계를 진행하세요.

1. **WP Admin**에서 상품 편집 화면을 여세요.
2. WP Multilang의 **언어** 상자에서 **다음 언어로만 글 표시:** 아래에 해당 상품을 판매할 언어를 선택하세요. 아무것도 선택하지 않으면 모든 언어에 상품이 표시되므로, 적어도 하나는 선택하세요.
3. 상품을 저장하세요.

#### 각 POS 기기: 결과 확인하기 {#check-device}

POS를 사용하는 각 기기에서 다음 단계를 진행하세요.

1. 상품 아래의 동기화 버튼을 길게 누르고 **삭제 후 새로고침**을 선택하세요. 상품이 다시 다운로드될 때까지 기다리세요.
2. 필터 모음에서 **재고 있음**을 제외하고 켜져 있는 필터를 모두 끄세요. **상품 검색**에 매장 언어가 포함된 상품의 이름을 입력하세요. 해당 상품이 표시됩니다.
3. 다른 상품을 검색하세요. 해당 상품은 표시되지 않습니다.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[240, 0], [0, 0], [0, 0], [-42, 0]]} alt="상품 하나를 검색한 후의 POS 상품 패널: 검색창, 켜진 재고 있음 필터, 상품 타일 하나, 상품 수">

1. **상품 검색** — 상품 이름을 입력하세요.
2. **재고 있음** — [표시 설정](../pos/product-panel/display-settings.mdx#show-out-of-stock-products)에서 **품절 상품 표시**가 켜져 있지 않으면 처음부터 켜져 있습니다. 이 필터가 켜져 있는 동안 품절 상품은 표시되지 않습니다. 따라서 두 상품 모두 재고가 있어야 합니다. [재고 상태](../pos/product-panel/search-filtering.mdx#stock-status)를 참고하세요.
3. **상품** — 매장 언어로 판매되는 경우에만 표시됩니다.
4. **상품 수** — 이 기기에서 검색 조건에 맞는 상품의 수입니다. 새로고침이 완료되면 매장 언어로 판매되는 상품만 집계합니다.

</JourneyShot>

동기화 버튼을 길게 누르면 메뉴가 열립니다.

1. **동기화 버튼** (<Icon name="arrow-rotate-right" />) — 길게 누르면 이 메뉴가 열립니다. 참고: [패널 하단](../pos/product-panel/display-settings.mdx#footer).
2. **동기화** — 버튼을 짧게 누르는 것과 같습니다. 매장 언어가 바뀐 뒤 새로 숨겨진 상품을 제거하지는 않으므로, **삭제 후 새로고침**을 선택하세요.
3. **삭제 후 새로고침** — 이 기기의 상품을 삭제하고 매장의 상품을 다시 다운로드합니다.

</JourneyShot>

다른 상품이 여전히 표시되면 [문제가 발생한 경우](#goes-wrong)를 참고하세요.

## 매장 언어 선택 {#store-language}

WCPOS Pro에서는 각 [매장](../stores/index.mdx)이 자체 언어를 사용할 수 있습니다. 같은 사이트의 프랑스어 매장과 영어 매장에 각자의 언어로 판매되는 상품이 표시됩니다.

:::note 언어 페이지에는 세 가지 조건이 필요합니다
WCPOS Pro가 있어야 하고, **WCPOS WP Multilang** 확장 기능이 활성화되어 있어야 하며, WP Multilang이 적어도 하나의 언어와 함께 활성화되어 있어야 합니다. 이 조건을 충족하지 않으면 매장 메뉴에 **언어** 페이지가 표시되지 않습니다.
:::

1. **WP Admin**에서 **POS → 매장**으로 이동하고 매장 이름을 클릭하세요.
2. 매장 메뉴의 **확장 기능** 아래에서 **언어**를 여세요. 화면과 영수증의 표시 언어를 바꾸는 **통화 및 언어 → 언어**가 아닙니다. [아래 설명](#product-and-screen-language)을 참고하세요.
3. **매장 언어**에서 언어를 선택하세요. 목록에는 WP Multilang에 설정된 모든 언어가 표시됩니다. **기본 언어**는 WP Multilang의 기본값을 따릅니다. 선택 사항은 자동으로 저장됩니다.
4. 이 매장의 POS를 열고 [정상 작동 여부를 확인](#check)하세요.

다른 매장은 각자의 언어를 그대로 유지합니다.

### 상품 언어와 화면 언어 {#product-and-screen-language}

매장 메뉴의 두 위치에 **언어**라는 이름의 설정이 있습니다.

- **확장 기능 → 언어 → 매장 언어**는 POS에 표시할 상품을 결정합니다.
- **통화 및 언어 → 언어**는 POS 화면과 영수증에 표시할 언어를 결정합니다. [매장 페이지 작성](../stores/setup.mdx#store-pages)을 참고하세요.

:::tip
프랑스어 매장이라면 두 설정을 모두 프랑스어로 지정하세요.
:::

## 문제가 발생한 경우 {#goes-wrong}

**다른 언어로 제한한 상품이 여전히 표시됩니다.** **플러그인**에서 **WCPOS WP Multilang**이 활성화되어 있는지 확인한 다음, 해당 기기에서 동기화 버튼을 길게 누르고 **삭제 후 새로고침**을 선택하세요.

**특정 매장에 상품이 표시되지 않습니다.** WP Multilang에서 상품의 언어에 해당 매장의 언어가 포함되어 있는지 확인하세요. 포함되어 있지 않으면 추가한 다음 POS를 새로고침하세요. 이미 포함되어 있다면 [상품을 찾을 수 없는 경우](../pos/product-panel/index.mdx#goes-wrong)를 참고하세요.

**WordPress에서 확장 기능이 활성화되지 않습니다.** 먼저 WooCommerce와 WP Multilang을 활성화하세요.

**매장 메뉴의 확장 기능 아래에 언어 페이지가 없습니다.** 이 페이지를 사용하려면 WCPOS Pro가 있어야 하고, 확장 기능이 활성화되어 있어야 하며, WP Multilang이 적어도 하나의 언어와 함께 활성화되어 있어야 합니다.

:::info WCPOS Pro 사용 시
각 매장이 자체 언어를 선택합니다. Pro가 없으면 매장은 하나이며, WP Multilang의 기본 언어를 사용합니다.
:::

<details>
<summary>개발자 안내: 필터 및 저장 데이터</summary>

이 확장 기능은 POS가 보내는 상품 및 상품 옵션 요청에만 적용됩니다. 해당 상품 쿼리에 WP Multilang의 `lang` 쿼리 변수와 `_languages` 메타 쿼리를 추가합니다. 상품에 `_languages` 메타가 없거나 `_languages`에 해당 언어가 포함되어 있으면 조건에 일치합니다. 다른 REST 클라이언트에는 영향을 주지 않습니다. 언어는 먼저 요청에서 지정한 매장(`store_id`)에서 가져오고, 없으면 WP Multilang의 기본 언어를 사용합니다.

- 매장에서 선택한 언어는 매장의 `_wcpos_wp_multilang_language` 메타에 저장됩니다. 빈 값은 WP Multilang의 기본 언어를 의미합니다. 매장 API(`/wcpos/v1/stores`)는 사용 중인 언어를 `language`로 반환합니다. 매장에서 선택한 언어를 반환하며, 메타가 비어 있으면 기본 언어 코드를 반환합니다.
- `wcpos_wp_multilang_resolved_language`는 개별 요청에서 사용할 언어를 변경합니다.
- `wcpos_wp_multilang_default_language`는 기본 언어를 변경합니다.
- `wcpos_wp_multilang_is_supported`는 확장 기능을 켜거나 끕니다.
- `wcpos_wp_multilang_minimum_version`은 이 확장 기능이 작동하는 최소 WP Multilang 버전을 설정합니다. 기본적으로 최소 버전 제한은 없습니다.
- 1.x 앱의 경우, 확장 기능은 `/wcpos/v1/products` 및 상품 옵션 경로에 대한 ID 목록 요청(`posts_per_page=-1` 및 `fields=id`)에도 동일한 언어 필터를 적용하여 응답합니다. 2.x 앱은 이러한 요청을 보내지 않습니다.

소스: [github.com/wcpos/wcpos-wp-multilang](https://github.com/wcpos/wcpos-wp-multilang).

</details>
