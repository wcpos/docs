확장 기능은 카드 단말기, 다국어 카탈로그, 매장 적립금, 위치별 재고 등의 기능을 제공하는 WCPOS용 WordPress 플러그인입니다. WordPress의 **WP Admin > POS > 설정 > 확장 기능**에 있는 디렉터리에서 모두 찾아볼 수 있습니다.

디렉터리에서는 버튼 하나로 설치할 수 있으며, **WCPOS Pro**와 WordPress 관리자 권한이 필요합니다. Pro 없이도 [Polylang](./polylang.mdx), [WPML](./wpml.mdx), [WP Multilang](./wp-multilang.mdx)은 수동으로 설치할 수 있습니다.

바로 가기: [확장 기능 설치](#installing-an-extension) · [Pro 없이 설치](#install-by-hand) · [문제가 발생한 경우](#troubleshooting)

## 확장 기능 설치 {#installing-an-extension}

:::note 시작하기 전에
디렉터리에서 설치하려면 **WCPOS Pro**와 WordPress 관리자 권한이 필요합니다. 상점 관리자는 플러그인을 설치할 수 없습니다([접근 권한](../settings/wp-admin/access.mdx) 참조). 무료 버전을 사용하는 경우 [Pro 없이 설치](#install-by-hand)를 참조하세요.
:::

1. WordPress에서 **WP Admin > POS > 설정**으로 이동한 다음 **확장 기능**을 선택하세요.
2. 확장 기능을 찾으세요. **확장 기능 검색...** 에 입력하면 이름, 설명, 태그를 검색합니다. 또는 **전체**, **카탈로그**, **쿠폰**, **재고**, **결제** 탭 중 하나를 선택하세요.
3. 카드에서 **설치**를 누르세요. WCPOS가 다운로드, 설치, 활성화를 한 번에 처리하고 **자동 업데이트**를 켭니다. 이제 카드에 **활성**이 표시됩니다.
4. 확장 기능을 설정하세요. 카드의 **⋮** (**추가 작업**) 메뉴에 **설정**이 있으면 선택하세요. 입력할 내용은 위에 있는 해당 확장 기능의 페이지에서 확인할 수 있습니다.

<details>
<summary>메뉴에 설정이 없는 경우 또는 다른 접근 방법</summary>

- 디렉터리에 해당 확장 기능의 설정 페이지가 등록된 경우에만 메뉴에 **설정**이 표시됩니다. 없다면 해당 확장 기능의 페이지에 있는 안내를 따르세요.
- WCPOS Pro에서는 **WP Admin > 플러그인**의 확장 기능 이름 아래에도 같은 **설정** 링크가 표시됩니다.
- 결제 확장 기능의 **설정**을 선택하면 WooCommerce 결제 설정에 있는 해당 페이지가 열립니다.

</details>

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[190, 0], [200, 0], [-36, 0], [-28, 0]]} alt="WCPOS Pro를 사용하는 WordPress의 확장 기능 화면: 확장 기능이 선택된 WCPOS 설정 메뉴, 검색창과 새로고침 버튼, 전체·카탈로그·쿠폰·재고·결제 카테고리 탭, 확장 기능 카드 그리드가 표시됩니다.">

1. **확장 기능** — WCPOS 설정 메뉴에 있습니다. 옆의 숫자는 업데이트가 대기 중인 확장 기능의 수입니다.
2. **확장 기능 검색...** — 이름, 설명, 태그를 검색합니다.
3. **새로고침** — 디렉터리에서 새 버전을 즉시 확인합니다.
4. **카테고리 탭** — **전체** 또는 특정 카테고리를 선택합니다.

</JourneyShot>

### 카드에 표시되는 정보 {#browsing-extensions}

각 확장 기능의 카드에는 아이콘, 이름, 설명이 표시됩니다. 자체 아이콘이 없는 확장 기능에는 퍼즐 조각이 표시됩니다. 설치된 확장 기능의 카드는 다음과 같습니다.

<JourneyShot manifest={manifest} device="desktop" step={2} maxWidth={432} offsets={[[-28, 0], [115, 0], [-30, 0], [0, -30], [-34, 0]]} alt="설치되었지만 비활성 상태인 PayPal Reader for WooCommerce 카드: 결제 카테고리의 버전 0.1.0, 켜진 자동 업데이트, 활성화 버튼이 표시됩니다.">

1. **상태** — **활성**, **비활성**(이 예시의 상태), **업데이트 가능** 중 하나입니다.
2. **버전** — 설치된 버전입니다. 업데이트가 대기 중이면 **v0.5.9 → v0.5.10**으로 표시됩니다. GitHub 릴리스로 연결됩니다. 뒤에 표시되는 카테고리는 해당 확장 기능이 속한 탭입니다.
3. **⋮ 추가 작업** — **GitHub에서 보기**가 있으며, 확장 기능에 설정 페이지가 있으면 **설정**도 표시됩니다.
4. **자동 업데이트** — 이 확장 기능의 자동 업데이트를 켜거나 끕니다.
5. **활성화** — 다음에 할 수 있는 작업이 버튼으로 표시됩니다. **활성화**, **업데이트**, 또는 비활성화된 확장 기능에 업데이트가 있으면 두 버튼이 모두 표시됩니다. 확장 기능이 실행 중이면 옆에 **비활성화**가 표시됩니다.

</JourneyShot>

설치되지 않은 확장 기능의 카드는 다음과 같습니다.

<JourneyShot manifest={manifest} device="desktop" step={3} maxWidth={432} offsets={[[-34, 0]]} alt="설치되지 않은 Square Terminal for WooCommerce 카드: 상태 표시 없이 결제 카테고리의 버전 0.8.7과 설치 버튼이 표시됩니다.">

1. **설치** — 카드에 상태나 **자동 업데이트**가 표시되지 않으며, 버전은 최신 버전입니다.

</JourneyShot>

### Pro 없이 설치 {#install-by-hand}

무료 버전에서도 모든 확장 기능이 나열되지만, **설치** 버튼은 회색으로 비활성화되며 **설치하려면 Pro가 필요합니다**가 표시됩니다. 다국어 확장 기능인 Polylang, WPML, WP Multilang은 Pro 없이도 실행되므로 다음과 같이 수동으로 설치할 수 있습니다.

1. 확장 기능 카드에서 **⋮** (**추가 작업**)를 열고 **GitHub에서 보기**를 선택하세요.
2. 최신 릴리스에 첨부된 `.zip`을 다운로드하세요.
3. **WP Admin > 플러그인 > 새 플러그인 추가**에서 **플러그인 업로드**를 누르고 zip 파일을 선택한 다음 활성화하세요.

그러면 디렉터리에 **활성**으로 표시되고, 새 릴리스가 나오면 **업데이트 가능**으로 표시됩니다. Pro가 없으면 **업데이트** 버튼이 표시되지 않습니다. 같은 방법으로 새 릴리스의 zip 파일을 업로드하면 WordPress가 설치된 버전을 교체할지 묻습니다.

## 업데이트, 비활성화 또는 활성화 {#activating-and-deactivating}

Pro가 없으면 확장 기능을 수동으로 업데이트하세요. [Pro 없이 설치](#install-by-hand)를 참조하세요.

WCPOS Pro에서는 설치된 확장 기능 카드의 버튼으로 다음 작업을 할 수 있습니다.

- **업데이트** — 새 버전을 설치합니다. 실행 중이던 확장 기능은 계속 실행됩니다.
- **비활성화** — 확장 기능을 제거하지 않고 실행을 중지합니다. 설정과 파일은 유지되며, **활성화**를 누르면 다시 실행됩니다. **활성화**하면 **자동 업데이트**도 다시 켜집니다.

### 업데이트 {#updating-extensions}

새 버전이 나오면 카드의 버전이 **v0.5.9 → v0.5.10**으로 표시되고, 실행 중인 확장 기능의 상태가 **업데이트 가능**으로 바뀝니다(꺼진 확장 기능은 **비활성**으로 유지됩니다). WCPOS Pro에서는 **업데이트** 버튼도 표시됩니다. WordPress의 **플러그인** 화면에도 같은 업데이트가 표시되므로 어느 쪽에서든 업데이트할 수 있습니다. 무료 버전에서는 수동으로 업데이트하세요. [Pro 없이 설치](#install-by-hand)를 참조하세요.

디렉터리는 한 시간마다 새 버전을 확인합니다. 지금 확인하려면 검색창 옆의 **새로고침**을 누르세요.

### 자동 업데이트 {#auto-updates}

디렉터리에서 설치하거나 활성화한 모든 확장 기능에는 **자동 업데이트**가 켜집니다. 이 기능이 켜져 있으면 WordPress가 자동 업데이트를 사용하는 다른 플러그인과 같은 방식으로 백그라운드에서 새 버전을 설치합니다. 새 버전을 먼저 테스트하는 등 수동으로 업데이트하고 싶다면 카드에서 이 기능을 끄세요.

사이트에서 실행 중인 WCPOS보다 더 최신 버전이 필요한 새 릴리스는 카드에도 자동 업데이트에도 제공되지 않습니다. 먼저 WCPOS Pro를 업데이트하면 확장 기능의 업데이트가 표시됩니다.

### 확장 기능 제거 {#removing-an-extension}

확장 기능을 완전히 제거하려면 다른 플러그인과 마찬가지로 **WP Admin > 플러그인**에서 비활성화한 다음 삭제하세요. WCPOS Pro에서는 먼저 카드에서 비활성화할 수 있습니다.

## 문제가 발생한 경우 {#troubleshooting}

**설치 버튼이 회색으로 비활성화되고 “설치하려면 Pro가 필요합니다”가 표시됩니다.** 무료 버전을 사용 중입니다. 디렉터리에서 설치하려면 [WCPOS Pro](../getting-started/pro-license.mdx)가 필요합니다. 다국어 확장 기능은 [수동으로 설치](#install-by-hand)할 수 있습니다.

**“플러그인을 관리할 권한이 없습니다.”** WordPress 사용자 계정에 플러그인 설치 권한이 없습니다. 관리자에게 문의하세요.

**“…에는 WCPOS 2.1 이상이 필요합니다. 이 사이트는 WCPOS 2.0을 실행 중입니다. 먼저 WCPOS Pro를 업데이트하세요.”** 제공되는 버전이 현재 WCPOS에서 지원하는 버전보다 최신입니다. WCPOS Pro를 업데이트한 다음 다시 시도하세요.

**“확장 기능을 새로고침할 수 없습니다. 다시 시도하세요.”가 표시되거나, 아무것도 검색하지 않았는데 “확장 기능을 찾을 수 없습니다.”가 표시됩니다.** 사이트가 확장 기능 목록을 가져오지 못했습니다. 목록은 GitHub에서 가져오는데, 일부 호스팅 업체는 웹사이트의 외부 연결을 차단합니다. 나중에 다시 시도하거나 호스팅 업체에 GitHub 연결을 허용해 달라고 요청하세요.

**설치에 실패하고 카드에 오류가 표시됩니다.** WordPress가 플러그인을 다운로드하거나 압축을 풀지 못했으며, 카드의 메시지에 원인이 표시됩니다. WordPress가 플러그인 폴더(`wp-content/plugins`)에 파일을 저장하고 GitHub에 연결할 수 있는지 호스팅 업체에 확인을 요청하세요.

**설치 후 카드에 비활성이 표시됩니다.** WordPress가 확장 기능을 설치했지만 활성화하지 못했습니다. 활성화하기 전까지는 실행되지 않습니다. **활성화**를 누르세요. 실패하면 카드의 메시지에 원인이 표시됩니다.

**새 버전이 표시되지 않습니다.** 디렉터리는 목록을 한 시간 동안 유지합니다. **새로고침**을 누르세요.

:::info WCPOS Pro 사용 시
무료 버전에서도 전체 디렉터리를 볼 수 있지만, **설치**, **활성화**, **업데이트**, **비활성화**, **자동 업데이트** 기능은 Pro에서 제공됩니다. [무료 버전과 Pro 비교](../getting-started/free-vs-pro.mdx)를 참조하세요.
:::

## 개발자 안내 {#for-developers}

확장 기능을 개발하거나 직접 만든 확장 기능을 등록하기 위한 안내입니다. 매장을 운영하는 데 아래 내용은 필요하지 않습니다.

### 훅 이름 규칙 {#hook-naming}

WCPOS 2.0부터 WCPOS가 호출하는 모든 훅의 이름은 `wcpos_*` 형식입니다. 기존 `woocommerce_pos_*` 이름은 사용 중단 예정입니다. 아직 작동하지만 빨라도 2.2부터 제거됩니다.

<details>
<summary>Pro 훅, 사용 중단 예정 알림, 이름이 유지되는 항목</summary>

WCPOS Pro의 훅 이름은 `wcpos_pro_*` 형식입니다. 기존 이름은 별칭으로 계속 호출되며, 연결된 콜백이 있으면 `WP_DEBUG`에서 사용 중단 예정 알림을 기록합니다. 훅 이름만 바뀌며 옵션, 메타 키, 권한의 이름은 유지됩니다.

</details>

<details>
<summary>코드에서 호출하는 훅과 전환 시점</summary>

사용자 코드가 호출하고 WCPOS가 수신하는 훅은 네 가지입니다. `woocommerce_pos_invalidate`(확장 기능), `woocommerce_pos_receipt_head`(저장된 PHP 영수증 템플릿), `woocommerce_pos_head` / `woocommerce_pos_footer`(테마의 `pos.php` 재정의)입니다. WCPOS는 2.2까지 이 이름으로 계속 수신합니다. `wcpos_invalidate`, `wcpos_receipt_head`, `wcpos_head`, `wcpos_footer`로 전환하세요.

확장 기능의 경우 2.0 이후 첫 릴리스에서 `wcpos_` 이름으로 전환하고 WCPOS 2.0 이상을 필수로 지정하세요. 두 이름에 모두 연결하지 마세요. 2.0과 2.1에서는 콜백이 두 번 실행됩니다. [ADR 0041](https://github.com/wcpos/woocommerce-pos/blob/main/docs/adr/0041-wcpos-is-the-hook-prefix.md)을 참조하세요.

</details>

<details>
<summary>확장 기능 개발 및 디렉터리 등록</summary>

<h3 id="creating-a-pos-extension">POS 확장 기능 만들기</h3>

WCPOS 확장 기능은 WCPOS 훅과 API를 사용하는 일반 WordPress 플러그인입니다. 결제 확장 기능을 개발하려면 [결제 게이트웨이 템플릿](../reference/gateway-template.mdx)에서 시작하세요.

<h3 id="pos-screens">POS 화면에 기능 추가</h3>

현재 플러그인은 POS 화면에 자체 패널이나 버튼을 추가할 수 없습니다. 장바구니, 상품, 고객 화면에는 앱에 기본 제공되는 요소만 표시됩니다. 결제는 예외입니다. 결제 게이트웨이는 [레거시 탭](../pos/checkout/legacy-tab.mdx)에 자체 결제 페이지를 표시하거나, 두 필터를 통해 **결제** 탭에 자체 타일과 필드를 추가할 수 있습니다. [결제 수단 패널의 필드 선언](../reference/declaring-pos-fields.mdx)을 참조하세요.

<details>
<summary>설치 후 디렉터리에서 플러그인을 인식하게 하려면</summary>

- **폴더 이름** — 플러그인의 폴더 이름은 카탈로그의 `slug`와 같아야 합니다. 예: `my-extension/my-extension.php`. 디렉터리는 이 폴더로 설치된 확장 기능을 찾고, 이 폴더에 설치합니다.
- **텍스트 도메인 또는 플러그인 URI** — 둘 중 하나가 `slug` 또는 GitHub 저장소 이름과 일치해야 합니다. 일치하지 않으면 자동 업데이트와 WordPress의 **플러그인** 화면에서 릴리스가 제공되지 않습니다. 이 확인 절차는 같은 폴더 이름을 사용하는 포크에 원본 릴리스가 제공되는 것을 막습니다.

</details>

<h3 id="submitting-to-the-directory">디렉터리에 등록 신청</h3>

디렉터리는 GitHub의 [`wcpos/extensions`](https://github.com/wcpos/extensions) 저장소에 있는 `catalog.json`을 읽습니다. 확장 기능을 등록하려면 해당 저장소에서 `catalog.json`에 항목을 추가하는 풀 리퀘스트를 여세요. 아이콘이 있으면 `icons/` 아래에 추가하세요. 병합되면 약 한 시간 이내에 WCPOS 사이트에 표시됩니다.

<details>
<summary>카탈로그 항목의 모든 필드</summary>

| 필드 | 내용 |
|---|---|
| `slug` | 플러그인의 폴더 이름입니다. |
| `name`, `description`, `author` | 카드에 표시되는 정보입니다. |
| `category` | 확장 기능이 속한 탭입니다. `payments`, `catalog`, `coupons`, `inventory` 또는 새 카테고리를 사용합니다. |
| `tags` | 검색에 사용할 추가 단어입니다. |
| `homepage` | GitHub 저장소 주소인 `https://github.com/owner/repo`입니다. 여기서 릴리스를 읽습니다. |
| `icon` | 정사각형 아이콘의 URL입니다. 보통 `icons/` 아래에 추가한 파일을 사용합니다. 없으면 카드에 퍼즐 조각이 표시됩니다. |
| `requires_wp`, `requires_wc`, `requires_wcpos` | 실행에 필요한 WordPress, WooCommerce, WCPOS의 최소 버전입니다. `requires_wcpos`보다 낮은 버전의 사이트에는 릴리스가 제공되지 않습니다. |
| `requires_pro` | 실행에 WCPOS Pro가 필요한지 여부입니다. |
| `settings_url` | `wp-admin/`을 기준으로 한 설정 페이지의 상대 경로입니다. 예: `admin.php?page=wc-settings&tab=checkout&section=my_gateway`. 카드 메뉴의 **설정** 링크에 사용됩니다. |

`version`, `latest_version`, `download_url`, `released_at`은 카탈로그에 맡기세요. 릴리스에서 자동으로 채워집니다.

</details>

<h3 id="github-release-conventions">GitHub 릴리스 규칙</h3>

버전을 태그로 지정하고 플러그인 zip 파일을 첨부하여 정식 GitHub 릴리스를 게시하세요. 카탈로그는 매시간 등록된 각 저장소의 최신 릴리스를 읽고 항목을 업데이트합니다.

<details>
<summary>WCPOS 사이트에 릴리스를 제공하기 위한 조건</summary>

- 버전 `v1.2.3`으로 **태그를 지정하세요**. 버전 번호에서는 맨 앞의 `v`가 제거되며, 이 번호는 플러그인 헤더의 `Version`과 일치해야 합니다.
- 슬러그와 이름이 같은 `my-extension.zip`으로 **플러그인 zip 파일을 첨부하세요**. 이 이름의 파일이 없으면 릴리스의 첫 번째 `.zip`을 사용합니다. zip 내부 폴더 이름과 관계없이 WCPOS는 `slug` 폴더에 설치합니다.
- **정식 릴리스로 게시하세요.** 초안과 사전 릴리스는 건너뛰므로 테스트 빌드는 사전 릴리스로 안전하게 공유할 수 있습니다.
- 릴리스에 더 최신 WCPOS가 필요하면 `catalog.json`에서 **`requires_wcpos`를 높이세요**. 그러면 이전 버전의 사이트에 실행할 수 없는 버전이 제공되지 않습니다.

</details>

사이트의 목록이 갱신되면 새 버전이 표시됩니다. 한 시간 이내에 갱신되며, **새로고침**을 누르면 즉시 확인할 수 있습니다. **자동 업데이트**가 켜진 사이트는 백그라운드에서 설치합니다.

등록 신청 전에 자체 카탈로그를 테스트하려면 `wcpos_extensions_catalog_url` 필터로 사이트가 해당 카탈로그를 사용하도록 지정하세요.

</details>
