**WP 관리자:** HTML 템플릿은 `WP Admin → POS → Templates`에서 편집합니다.

HTML 템플릿을 편집하여 영수증의 문구나 레이아웃을 바꿔보세요. HTML 템플릿은 웹 페이지처럼 구성된 영수증으로, 주문 세부 정보가 들어갈 자리에 `{{placeholders}}`를 사용합니다. 다른 기본 제공 영수증으로 바꾸려면 [영수증 맞춤 설정](./customise.mdx)을 참조하세요.

<details>
<summary>HTML과 감열식 중 무엇을 사용할까요?</summary>

브라우저 인쇄, PDF, A4 청구서, 웹 페이지를 인쇄하는 프린터에는 HTML을 사용하세요. ESC/POS 명령을 받는 영수증 프린터에는 [감열식 템플릿](./thermal-templates.mdx)을 사용하세요. 대부분의 매장에는 HTML 엔진을 권장합니다. POS가 기기 자체에서 HTML 템플릿을 채우므로 매장과의 연결이 끊겨도 미리보기와 인쇄가 가능합니다.

</details>

## 템플릿 작성 {#write}

빈 페이지에서 시작하지 말고 갤러리 템플릿을 복사한 뒤 복사본을 편집하세요.

1. **템플릿 갤러리**에서 원하는 형태에 가장 가까운 카드의 **템플릿 사용**을 누르세요. **내 템플릿**에 나만의 복사본이 생기며 갤러리 원본은 그대로 유지됩니다.
2. 복사본을 여세요. **필드**에는 모든 자리 표시자가 나열됩니다. 검색한 뒤 **삽입**을 누르면 이름을 외울 필요가 없습니다. **미리보기**는 입력하는 동안 **샘플 데이터**나 POS 주문 중 하나로 템플릿을 채웁니다.
3. 필요한 부분을 수정하세요. 예를 들어 **표준 영수증** 복사본에 반품 안내 문구를 추가하려면 끝부분에서 `{{i18n.thank_you_purchase}}` 를 찾으세요. 그다음에 나오는 `</div>` 가 바닥글을 닫습니다. 다음 코드를 해당 `</div>`뒤에 복사하세요:

   ```html
   <div style="text-align: center;">
     Returns within 30 days
     with this receipt.
   </div>
   ```

   직접 입력한 텍스트는 입력한 그대로 한 언어로 인쇄됩니다. 이 예제처럼 각 요소에 스타일을 지정하세요(`style="…"`). 스타일을 `<style>` 블록에 넣지 마세요. 자세한 내용은 [인쇄 시 스타일이 사라질 수 있음](#styling)을 참조하세요.

4. **업데이트**를 누르세요. 이제 복사본으로 인쇄하는 모든 영수증에 바닥글 메시지 아래의 반품 안내 등 변경 사항이 표시됩니다.
5. **내 템플릿**에서 **활성**을 켜면 계산대의 POS에서 해당 템플릿을 사용할 수 있습니다.

   <details>
   <summary>계산대에서 이 템플릿을 첫 번째로 사용하기</summary>

   계산대는 **내 템플릿**의 순서대로 활성 템플릿을 나열하고 매 판매를 첫 번째 템플릿으로 시작합니다. 해당 행의 **≡** 손잡이를 드래그하거나 **작업** 열의 **↑**, **↓** 버튼으로 템플릿을 위로 옮기세요. 자체 템플릿 목록이 있는 매장은 자체 순서를 유지합니다. [계산대에서 캐셔에게 표시되는 내용](./customise.mdx#at-the-till)을 참조하세요.

   </details>

6. 계산대에서 사용하기 전에 POS에서 확인하세요. [POS에서 확인](#check)을 참조하세요.

### POS에서 확인 {#check}

편집기의 미리보기에서는 문제가 없어 보여도 POS에서는 오류가 생길 수 있으므로 계산대에서 올바르게 표시되는지 확인해야 템플릿을 사용할 준비가 된 것입니다.

**레이아웃을 간단히 확인하려면** 판매를 완료할 필요가 없습니다. 장바구니에 상품을 넣고 **결제** 옆의 **⋮** 를 누른 뒤 **인쇄**를 누르세요. 장바구니 주문의 템플릿 선택기와 미리보기가 열립니다. HTML 템플릿은 주문이 매장에 도달하기 전에도 미리 볼 수 있지만, **레거시 PHP 템플릿**은 먼저 주문을 동기화하라는 안내를 표시합니다.

**계산대에서 사용하기 전에** 실제 판매로 모든 금액을 확인하세요:

1. 복잡한 판매 상황을 반영하여 주문을 처리하세요. 할인 항목, 과세 상품, 거스름돈이 있는 현금 결제를 포함하세요.
2. 결제 완료 화면의 **템플릿**에서 사용할 템플릿을 선택하세요.
3. 미리보기에서 이름, 가격, 할인, 세금 행, 받은 금액과 거스름돈을 확인하세요.
4. 계산대에서 사용할 방식대로 **영수증 인쇄** 또는 **PDF 다운로드**로 인쇄하고 용지나 파일도 확인하세요. [인쇄 시 스타일이 사라질 수 있습니다](#styling).

갤러리의 **표준 영수증**을 선택한 결제 완료 화면:

<JourneyShot manifest={checkoutManifest} device="tablet" step={6} offsets={[[279, 0], [260, 0], [292, 0], [292, 0], [0, 0], [48, -38], [49, -38], [128, 0]]} alt="현금 판매 후 표준 영수증 HTML 템플릿을 선택한 결제 완료 화면: 거스름돈과 결제 금액, 템플릿 및 프린터 선택기, 확대/축소 컨트롤이 있는 데이터가 채워진 영수증 미리보기, 영수증 이메일 전송, PDF 다운로드, 영수증 인쇄 및 새 판매 버튼">

1. **거스름돈** — 돌려줄 금액입니다. 영수증에서는 `{{#payments}}` 안의 `{{change_display}}`에 해당합니다.
2. **결제 수단** — 결제 금액과 방법입니다. 영수증에서는 `{{amount_display}}`와 `{{method_title}}`에 해당합니다.
3. **템플릿** — 여기에서 템플릿을 선택하세요. 활성 템플릿만 나열되며 선택은 이번 판매에만 적용됩니다. [영수증 맞춤 설정](./customise.mdx)을 참조하세요.
4. **프린터** — 인쇄할 위치입니다. [영수증 인쇄](./at-checkout.mdx#print-receipt)를 참조하세요.
5. **미리보기** — POS가 이번 판매 데이터로 채운 템플릿으로, 실제 인쇄될 영수증을 보여줍니다. **−** 와 **+** 로 확대/축소합니다.
6. **영수증 인쇄** — 위에서 선택한 프린터로 인쇄합니다.
7. **영수증 이메일 전송** — 고객에게 전송합니다.
8. **새 판매** — 다음 고객을 위한 빈 장바구니를 엽니다.

</JourneyShot>

**영수증 이메일 전송** 옆의 **PDF 다운로드**는 매장에서 영수증을 PDF로 렌더링하므로 연결이 필요합니다. 이 화면에 대한 자세한 내용은 [결제 시 영수증](./at-checkout.mdx)을 참조하세요.

:::tip 원본 보관
**템플릿 사용**을 누를 때마다 새 복사본이 생성됩니다. 시험하는 동안 복사본 두 개(*영수증 v1*, *영수증 v2*)를 만들어 계산대에서 번갈아 사용하세요.
:::

## 구문 {#syntax}

자리 표시자는 간단한 템플릿 언어인 [Mustache](https://mustache.github.io/mustache.5.html)를 사용합니다. 자체 로직은 없으며, 값을 채우기, 목록의 각 항목에 대해 블록 반복하기, 블록 표시 또는 숨기기의 세 가지 작업을 수행합니다.

### 변수 {#variables}

이중 중괄호 안에 필드 이름을 넣으세요:

```html
<h1>{{store.name}}</h1>
<p>Order #{{order.number}}</p>
<p>Total: {{totals.total_display}}</p>
```

`_display`로 끝나는 필드는 매장에 맞게 형식이 지정된 금액입니다(`12.5` 대신 `$12.50`). 모든 필드는 [영수증 데이터 참조](./receipt-data.mdx)에 나열되어 있습니다.

### 이스케이프 처리 {#escaping}

`{{field}}`는 값을 일반 텍스트로 인쇄합니다. 상품명의 `<`는 HTML이 아닌 `<`로 표시됩니다. 중괄호 세 개를 사용한 `{{{field}}}`는 값을 HTML로 인쇄합니다. 이 HTML도 인쇄 전에 정리되므로([스타일 지정](#styling) 참조) 필드로 스크립트를 추가할 수는 없습니다.

### 섹션(반복문과 조건문) {#sections-loops-and-conditionals}

`{{#section}}...{{/section}}`은 목록의 각 항목에 대해 블록을 반복하거나 값이 있을 때 한 번 표시합니다.

<details>
<summary>예제: 주문 항목마다 한 행</summary>

```html
{{#lines}}
<div class="line-item">
  <span>{{name}} × {{qty}}</span>
  <span>{{line_total_display}}</span>
</div>
{{/lines}}
```

</details>

섹션 안에서는 먼저 현재 항목에서 이름을 찾은 뒤 바깥에서 찾습니다. 따라서 `{{#payments}}` 안에서도 `{{i18n.tendered}}`가 작동합니다. `store.address_lines`처럼 일반 텍스트로 이루어진 목록에서 `{{.}}`는 현재 항목 자체를 의미합니다.

### 반전 섹션 {#inverted-sections}

`{{^section}}...{{/section}}`은 값이 없거나 비어 있거나 `false` 또는 `0`일 때 블록을 표시합니다.

<details>
<summary>예제: 고객 이름 또는 ‘비회원 결제’</summary>

```html
{{#customer.id}}
  <p>Customer: {{customer.name}}</p>
{{/customer.id}}
{{^customer.id}}
  <p>Guest checkout</p>
{{/customer.id}}
```

</details>

### 현지화된 라벨 {#localised-labels}

`{{i18n.key}}`는 매장 언어로 라벨을 인쇄하므로 하나의 템플릿을 모든 매장에서 사용할 수 있습니다.

<details>
<summary>예제: 번역된 소계 라벨</summary>

```html
<th>{{i18n.subtotal}}</th>
<td>{{totals.subtotal_display}}</td>
```

</details>

라벨은 캐셔가 앱에서 선택한 언어가 아닌 매장의 WordPress 언어를 따릅니다. 모든 키는 [i18n 참조](./receipt-data.mdx#i18n)에 있습니다.

<details>
<summary>POS에서 지원하지 않는 기능</summary>

- **부분 템플릿**(`{{> name}}`)은 POS에서 아무것도 인쇄하지 않습니다. 모든 내용을 하나의 템플릿에 넣으세요.
- **람다**(값 대신 사용하는 함수)는 사용할 수 없습니다. 영수증 데이터에는 일반 값만 들어 있습니다.
- **주석**(`{{! a note }}`)과 변경된 구분자(`{{=<% %>=}}`)는 일반 Mustache와 동일하게 작동합니다.

</details>

## 자주 사용하는 패턴 {#common-patterns}

### 매장 머리글 {#store-header}

`store.address_lines`에는 주소가 이미 여러 줄로 나뉘어 들어 있습니다. 주소 필드를 직접 조합하지 말고 이 목록을 반복하세요.

<details>
<summary>예제: 로고, 이름, 주소, 전화번호 및 세금 ID</summary>

```html
<div style="text-align: center;">
  {{#store.logo}}<img src="{{store.logo}}" alt="{{store.name}}" style="max-width: 200px;" />{{/store.logo}}
  <h1 style="margin: 8px 0;">{{store.name}}</h1>
  {{#store.address_lines}}<div>{{.}}</div>{{/store.address_lines}}
  {{#store.phone}}<div>{{store.phone}}</div>{{/store.phone}}
  {{#store.tax_ids}}<div>{{label}}: {{value}}</div>{{/store.tax_ids}}
</div>
```

</details>

로고는 템플릿이 아닌 매장 설정에서 가져옵니다. [영수증 맞춤 설정](./customise.mdx)을 참조하세요.

### 할인이 있는 주문 항목 {#line-items-with-discounts}

항목의 `discounts`는 양수로 표시된 할인 금액이며 할인이 없으면 `0`입니다. Mustache는 `0`을 빈 값으로 취급하므로 `{{#discounts}}...{{/discounts}}`는 할인된 항목에만 블록을 표시합니다.

<details>
<summary>예제: 각 항목과 할인</summary>

```html
{{#lines}}
<div class="line-item" style="display: flex; justify-content: space-between;">
  <div>
    <div>{{name}} × {{qty}}</div>
    {{#discounts}}
      <div style="font-size: 0.9em;">
        <s>{{line_subtotal_display}}</s> −{{discounts_display}}
      </div>
    {{/discounts}}
  </div>
  <div>{{line_total_display}}</div>
</div>
{{/lines}}
```

</details>

`line_subtotal_display`는 할인 전 항목 금액이고 `line_total_display`는 할인 후 금액입니다. 할인가와 절약 금액은 [정상가 및 절약 금액 표시](./receipt-data.mdx#displaying-regular-price-and-savings)를 참조하세요.

### 세금 요약 {#tax-summary}

`tax_summary`에는 세율마다 한 행이 있습니다. `rate`는 `10`과 같은 백분율입니다. 세율이 0%이거나 오프라인에서 인쇄한 영수증이면 비어 있을 수 있으므로 `{{#rate}}` 조건으로 영수증에 `(%)`만 인쇄되지 않도록 합니다.

<details>
<summary>예제: 세율마다 한 행</summary>

```html
{{#tax_summary}}
<div class="tax-line" style="display: flex; justify-content: space-between;">
  <span>{{label}}{{#rate}} ({{rate}}%){{/rate}}</span>
  <span>{{tax_amount_display}}</span>
</div>
{{/tax_summary}}
```

</details>


### 결제 세부 정보 {#payment-details}

오프라인 상태 등으로 주문이 매장에 도달하기 전에 인쇄했나요? 영수증에는 받은 현금과 거스름돈이 표시되지 않습니다. 주문이 동기화되면 다시 인쇄하세요. 결제 완료 화면에는 어느 경우든 거스름돈이 표시됩니다.

<details>
<summary>그 이유와 받은 금액 및 거스름돈 예제</summary>

결제 완료 화면의 **거스름돈**은 POS가 직접 계산합니다. 영수증의 `tendered`와 `change` 필드는 매장에서 가져오므로 주문이 동기화될 때까지 비어 있으며 `{{#tendered}}` 블록은 건너뜁니다.

```html
{{#payments}}
<div class="payment" style="display: flex; justify-content: space-between;">
  <span>{{method_title}}</span>
  <span>{{amount_display}}</span>
</div>
{{#tendered}}
  <div style="display: flex; justify-content: space-between;">
    <span>{{i18n.tendered}}</span><span>{{tendered_display}}</span>
  </div>
  <div style="display: flex; justify-content: space-between;">
    <span>{{i18n.change}}</span><span>{{change_display}}</span>
  </div>
{{/tendered}}
{{/payments}}
```

</details>


### 바코드와 QR 코드 {#barcodes-and-qr-codes}

[감열식 템플릿](./thermal-templates.mdx)과 같은 요소를 사용하세요. 요소 안에 값을 넣으면 POS가 그 자리에 코드를 그립니다.

<details>
<summary>예제: Code 128, EAN-13 및 QR 코드</summary>

```html
<!-- Code 128 barcode of the order number -->
<barcode type="code128" height="40">{{order.number}}</barcode>

<!-- EAN-13 of each product, when your SKUs are EAN numbers -->
{{#lines}}<barcode type="ean13" height="30">{{sku}}</barcode>{{/lines}}

<!-- QR code: size sets how big, 4 by default -->
{{#order.payment_url}}<qrcode size="4">{{order.payment_url}}</qrcode>{{/order.payment_url}}
```

</details>

- **항상 `type`을 설정하세요.** 설정하지 않으면 POS는 Code 128을, 매장의 PDF는 QR 코드를 그립니다.
- **주문 번호에는 Code 128을 사용하세요.** SKU가 유효한 EAN 상품 코드일 때만 EAN-13을 사용하세요.

<details>
<summary>바코드 유형, QR 크기 및 자리 표시자로 지정하는 유형</summary>

- **다음 유형 중에서 선택하세요:** `code128`, `code39`, `code93`, `ean13`, `ean8`, `upca`, `upce`, `codabar`, `itf`, `qrcode`. POS는 `pdf417` 같은 다른 [bwip-js 유형](https://github.com/metafloor/bwip-js/wiki/Supported-Barcode-Types)도 그릴 수 있지만 편집기 미리보기와 PDF에서는 이를 Code 128로 그립니다.
- **QR 코드에는 `<qrcode size="…">` 를 사용하세요.** `<barcode type="qrcode">` (또는 `qr`)도 QR 코드를 그리지만 POS는 크기를 `height` 기준으로, PDF는 `size`기준으로 정하므로 둘이 일치하지 않습니다.
- **`type`에 자리 표시자를 사용할 수 있습니다**. 코드를 그리기 전에 자리 표시자가 채워지기 때문입니다:

  ```html
  <barcode type="{{presentation_hints.order_barcode_type}}">{{order.number}}</barcode>
  ```

</details>

값이 유형에 맞지 않으면 POS는 해당 값이 들어 있는 **바코드 오류** 또는 **QR 코드 오류** 블록을 표시합니다. 값을 수정하거나 그 값을 지원하는 유형을 선택하세요. PDF는 대신 값만 인쇄합니다.

## 스타일 지정 {#styling}

갤러리 템플릿처럼 `style="…"` 속성으로 각 요소에 **인라인** 스타일을 지정하세요:

```html
<div style="font-family: monospace; font-size: 12px; max-width: 300px; margin: 0 auto;">
  <div style="text-align: center; margin-bottom: 16px;">
    <strong style="font-size: 16px;">{{store.name}}</strong>
  </div>
  <div style="display: flex; justify-content: space-between; font-weight: 700; border-top: 1px solid black; padding-top: 8px;">
    <span>{{i18n.total}}</span>
    <span>{{totals.total_display}}</span>
  </div>
</div>
```

:::warning 인쇄 시 스타일이 사라질 수 있음
편집기는 작성한 HTML을 그대로 표시하므로 `<style>` 블록이 템플릿 편집기의 미리보기에서는 정상적으로 보입니다. 매장의 PDF와 모바일 앱은 인쇄 전에 `<style>` 블록을 제거하므로 동일한 영수증도 스타일 없이 출력됩니다. 모든 스타일을 인라인으로 지정하세요.
:::

<details>
<summary>어떤 HTML이 제거되나요?</summary>

영수증은 인쇄 전에 정리되므로 템플릿이 코드를 실행할 수 없습니다. 어디서 인쇄하든 스크립트, `<link>` 및 `<meta>` 태그와 `on…` 속성이 제거됩니다. 매장의 PDF는 `<style>` 블록, `<head>` 및 기타 문서 수준 태그를 제거하며 모바일 앱도 `<style>` 블록을 제거합니다.

</details>

:::tip 흑백 인쇄에 맞게 디자인
영수증은 보통 흑백 감열식 또는 레이저 프린터로 인쇄합니다. 색상 채우기 대신 **글꼴 두께, 여백, 글자 크기 및 가로선**으로 정보의 위계를 표현하세요. 색상 배경과 회색 텍스트는 사라지거나 탁한 하프톤으로 인쇄될 수 있습니다.
:::

:::tip 감열식 프린터 없이 감열지 같은 모양을 원하나요?
갤러리의 **좁은 영수증** 카드에서 **템플릿 사용**을 누르세요. 폭이 72 mm인 고정폭 글꼴 레이아웃으로, 브라우저와 웹 페이지를 인쇄하는 프린터(Sunmi 및 iMin 기기)에서, 그리고 일반 용지에도 깔끔하게 인쇄됩니다. ESC/POS 명령을 직접 받는 프린터에는 **간단한 감열식 영수증**(58mm 또는 80mm)을 사용하세요.
:::

## 권장 사항 {#best-practices}

- 금액에는 **`_display` 필드를 사용하세요**. 매장의 통화 형식이 적용되어 있습니다.
- 직접 입력한 텍스트 대신 **`{{i18n.*}}` 라벨을 사용하세요**. 모든 매장의 언어로 템플릿을 사용할 수 있습니다.
- **선택적 필드를 섹션으로 감싸세요**. `{{#field}}...{{/field}}`를 사용하면 필드가 비어 있을 때 아무것도 인쇄되지 않습니다.
- 빈 페이지 대신 **갤러리 템플릿으로 시작하세요**.
- 계산대에서 사용하기 전에 할인, 세금 행, 현금 결제가 포함된 실제 주문으로 **POS에서 확인하세요**.

## 문제 해결 {#goes-wrong}

**편집기에서는 스타일이 보이지만 영수증에서는 보이지 않습니다.** 스타일을 인라인으로 옮기세요. [인쇄 시 스타일이 사라질 수 있음](#styling)을 참조하세요.

**필드에 아무것도 인쇄되지 않습니다.** [영수증 데이터 참조](./receipt-data.mdx)에서 이름을 확인하세요. 철자가 틀렸거나 알 수 없는 필드는 오류 없이 빈 값으로 인쇄됩니다. 섹션 안에서는 먼저 현재 항목에서 이름을 찾습니다.

**영수증에 바코드 오류 블록이 표시됩니다.** 값이 바코드 유형에 맞지 않습니다. [바코드와 QR 코드](#barcodes-and-qr-codes)를 참조하세요.

**영수증에 받은 금액과 거스름돈이 없습니다.** 주문이 매장에 도달하기 전에 오프라인에서 인쇄한 것입니다. 결제 완료 화면에는 거스름돈이 표시되었어도 그렇습니다. 주문이 동기화되면 다시 인쇄하세요. [오프라인 모드](../getting-started/offline.mdx)를 참조하세요.

**계산대의 템플릿 목록에 템플릿이 없습니다.** **활성** 상태가 아니거나 매장에 자체 템플릿 목록이 있습니다. [영수증 맞춤 설정](./customise.mdx#per-store-assignments)을 참조하세요.

**편집기 미리보기에 ‘템플릿 렌더링 오류’가 표시됩니다.** 섹션이 닫히지 않았거나 닫는 태그가 여는 태그와 일치하지 않습니다. 모든 `{{#x}}`와 `{{^x}}`에는 각각의 `{{/x}}`가 필요합니다.
