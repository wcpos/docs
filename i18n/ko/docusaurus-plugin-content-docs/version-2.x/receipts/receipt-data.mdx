**WP 관리자:** 템플릿은 `WP Admin → POS → Templates`에서 편집합니다. 이 페이지에서는 템플릿으로 인쇄할 수 있는 필드를 안내합니다.

영수증 인쇄 및 이메일 전송은 [영수증과 결제 완료 화면](./at-checkout.mdx)을, 템플릿 선택이나 AI를 통한 수정은 [영수증 맞춤 설정](./customise.mdx)을 참조하세요.

이 페이지는 템플릿 코드를 직접 편집할 때 참고하는 문서입니다. HTML 템플릿과 감열식 템플릿 모두 매장, 주문, 품목, 합계, 결제 정보가 담긴 동일한 영수증 데이터로 인쇄합니다. 필드 인쇄 방법과 자주 사용하는 세 가지 예제, 전체 필드 목록을 제공합니다.

**바로 가기:** [필드 찾기](#field-reference) · [일반적인 예제](#common-recipes) · [문제가 발생한 경우](#if-something-goes-wrong)

## 필드 인쇄 {#print-a-field}

1. **WP Admin → POS → 템플릿**에서 템플릿을 여세요(자세한 내용은 [직접 편집](./customise.mdx#option-3--edit-it-by-hand)을 참조하세요).
2. 필드를 인쇄할 위치에 `{{store.name}}`, `{{order.number}}`, `{{totals.total_display}}`처럼 이중 중괄호로 감싼 필드 경로를 입력하거나, 코드 옆 필드 목록에서 삽입하세요.
3. 코드 아래의 미리보기를 확인한 다음 **업데이트**를 클릭하여 저장하세요.

품목처럼 목록을 인쇄하려면 행을 섹션으로 감싸세요. 품목마다 해당 행이 한 번씩 반복됩니다.

```mustache
{{#lines}}
  {{name}} x {{qty}} —
  {{line_total_display}}
{{/lines}}
```

필드가 비어 있거나 0 또는 거짓이면 섹션 안의 내용도 생략됩니다. 따라서 `{{#customer.id}}…{{/customer.id}}`는 이름이 있는 고객에게만 인쇄됩니다. 금액을 인쇄하려면 `_display`로 끝나는 필드를 사용하세요. [통화 필드](#currency-fields)를 참조하세요.

오프라인에서도 영수증을 인쇄할 수 있습니다. 앱이 기기에 저장된 주문으로 영수증 데이터 사본을 생성합니다.

### 데이터의 출처 {#where-the-data-comes-from}

매장 서버는 주문별 영수증 데이터를 생성하고, 앱은 기기의 주문으로 간략한 사본을 생성합니다. 이 사본에는 `cashier`, 매장 영업시간, 메모, 정책, `totals.paid_total`, `totals.change_total`이 없습니다. HTML 또는 감열식 템플릿은 기기의 사본으로 즉시 열리고 서버 데이터가 도착하면 해당 데이터로 전환됩니다. 오프라인에서는 기기의 사본으로 인쇄하므로 위 필드는 비어 있게 됩니다. WCPOS Pro를 사용하면 기기의 사본에도 매장 로고가 포함됩니다. Pro를 사용하지 않으면 로고는 서버 데이터와 함께 도착합니다. 레거시 PHP 템플릿은 항상 서버에서 렌더링됩니다. 이 때문에 템플릿은 PHP 주문 메서드 대신 아래 필드를 사용합니다. 일부 필드는 PDF 다운로드처럼 서버에서 템플릿을 렌더링할 때만 인쇄됩니다. 해당 목록은 [문제가 발생한 경우](#if-something-goes-wrong)를 참조하세요.

## 필드 참조 {#field-reference}

섹션을 펼쳐 필드를 확인하세요. 첫 번째 항목에는 모든 섹션과 자료형이 나열되어 있습니다.

### 최상위 섹션 {#top-level-sections}

| 섹션 | 포함된 내용 |
|---------|---------------|
| `order` (객체) | 주문 식별 정보, 상태, 날짜, 메모, 결제 URL 정보 |
| `store` (객체) | 매장 식별 정보, 주소, 연락처, 세금 ID, 로고, 영업시간, 바닥글 |
| `cashier` (객체) | 주문을 처리한 사용자 |
| `customer` (객체) | 고객 표시 이름, 주소, 세금 ID |
| `lines` (배열) | 상품 품목 |
| `fees` (배열) | 수수료 행 |
| `shipping` (배열) | 배송 행 |
| `discounts` (배열) | 쿠폰/할인 행 |
| `totals` (객체) | 주문 합계, 결제 합계, 환불 요약, 품목 수 |
| `tax` (객체) | 섹션 표시 조건에 사용하는 세금 표시 모드 플래그 |
| `tax_summary` (배열) | 세율별 세금 요약 행 |
| `has_tax_summary` (불리언) | `tax_summary`의 표시 조건으로 간편하게 사용하는 값 |
| `payments` (배열) | 결제 행 |
| `refunds` (배열) | 주문에 적용된 환불 기록 |
| `fiscal` (객체) | 세무 연동 기능이 채우는 세무 스냅샷 필드 |
| `register` (객체) | 판매를 처리한 계산대의 `id`와 `name`. 알 수 없으면 빈 문자열 |
| `software` (객체) | 영수증을 발행한 소프트웨어: `name` (`WCPOS`), `plugin_version`, `app_version`, `app_build`, `platform` |
| `presentation_hints` (객체) | 서식 및 렌더러 힌트 |
| `i18n` (객체) | 기본 제공 템플릿과 사용자 지정 템플릿의 번역된 레이블 |

  </AccordionItem>

### order {#order}

| 필드 | 자료형 | 예시 / 설명 |
|-------|------|-----------------------|
| `order.id` | 숫자 | `1042` |
| `order.number` | 문자열 | 사용자에게 표시되는 주문 번호. 예: `"1042"` |
| `order.currency` | 문자열 | ISO 통화 코드. 예: `"USD"` |
| `order.customer_note` | 문자열 | 고객/주문 메모 |
| `order.wc_status` | 문자열 | WooCommerce 상태 슬러그 원본. 예: `"processing"` |
| `order.status_label` | 문자열 | 사용자 지정 상태를 포함한 현지화된 상태 레이블 |
| `order.created_via` | 문자열 | 출처/채널. 예: `"woocommerce-pos"` |
| `order.needs_payment` | 불리언 | 결제 섹션을 표시해야 하는지 여부 |
| `order.payment_url` | 문자열 | 주문 결제 URL(있는 경우) |
| `order.created` | 날짜 객체 | 주문 생성일 |
| `order.paid` | 날짜 객체 | 결제일. 미결제 상태이면 빈 문자열 |
| `order.completed` | 날짜 객체 | 완료일. 미완료 상태이면 빈 문자열 |
| `order.printed` | 날짜 객체 | 렌더링 시점의 인쇄/재인쇄 타임스탬프 |

  </AccordionItem>

### 정상가와 절약액 표시 {#displaying-regular-price-and-savings}

단가 기준 레이아웃에서는 기록된 정상가, 판매가, 절약액을 다음과 같이 표시하세요.

```mustache
{{#lines}}
  {{#unit_savings}}
    <span style="text-decoration: line-through;">{{regular_price_display}}</span>
    <span>{{selling_price_display}}</span>
    <span>{{i18n.savings}}: -{{unit_savings_display}}</span>
  {{/unit_savings}}
{{/lines}}
```

수량을 반영해야 할 때는 품목 합계 필드를 사용하세요.

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    <span>{{i18n.savings}}: -{{line_savings_display}}</span>
  {{/line_savings}}
{{/lines}}
```

`selling_price`는 쿠폰 적용 전 가격입니다. WooCommerce 할인 적용 후 최종 금액에는 `unit_price` 또는 `line_total`을 사용하세요.

:::note v1.9.0 이전에 생성된 주문 재인쇄
이전 WCPOS 주문에서는 정상가와 판매가의 차액이 `discounts`에 이미 포함되어 있을 수 있습니다. 사용자 지정 템플릿이 품목 절약액과 품목 할인액을 모두 인쇄한다면 `savings_in_discounts`를 사용하여 같은 차액이 두 번 표시되지 않도록 하세요.

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    {{^savings_in_discounts}}
      <span>{{i18n.savings}}: -{{line_savings_display}}</span>
    {{/savings_in_discounts}}
  {{/line_savings}}
  {{#discounts}}
    <span>{{i18n.discount}}: -{{discounts_display}}</span>
  {{/discounts}}
{{/lines}}
```

템플릿이 품목별 `discounts` 행을 인쇄하지 않는다면 `savings_in_discounts`가 참이어도 `line_savings`를 계속 표시하세요. 기본 제공 템플릿은 이 차이를 자동으로 처리합니다.
:::

상품 품목 중 하나라도 신뢰할 수 있는 합계를 구하기에 충분한 가격 데이터가 기록되어 있지 않으면 절약액 합계는 `null`이고 `total_saved_complete`는 거짓입니다. `total_saved_complete`를 행의 표시 조건으로 사용하고, 이어서 `total_saved`로 값이 0인 경우를 숨기세요.

```mustache
{{#totals.total_saved_complete}}
  {{#totals.total_saved}}
    <span>{{i18n.total_saved}}: {{totals.total_saved_display}}</span>
  {{/totals.total_saved}}
{{/totals.total_saved_complete}}
```

기본 제공 템플릿은 하나의 `{{#totals.total_saved_incl}}` 조건 안에서 세금 포함 버전인 `totals.total_saved_incl_display`로 **총 절약액**을 인쇄합니다. 가격 이력이 불완전하면 값이 `null`이고 절약액이 없으면 0이므로 이 조건 하나로 충분합니다.

## 가격 간의 관계 {#price-model}

영수증의 한 품목에는 여러 가격이 있으며, 실제 금액으로 보면 각 이름을 쉽게 이해할 수 있습니다. 아래는 샘플 주문의 에스프레소 품목입니다. $17.00 상품을 $14.50에 세일하고 여기에 10% 쿠폰을 추가 적용했습니다.

### 날짜 객체 {#date-objects}

각 날짜는 여러 서식으로 미리 제공되므로 템플릿에서 직접 날짜 서식을 지정할 필요가 없습니다.

| 필드 | 설명 |
|-------|-------------|
| `datetime`, `date`, `time` | 기본 날짜/시간 문자열 |
| `datetime_short`, `datetime_long`, `datetime_full` | 로케일을 반영한 날짜 및 시간 결합 형식 |
| `date_short`, `date_long`, `date_full` | 로케일을 반영한 날짜 전용 형식 |
| `date_ymd`, `date_dmy`, `date_mdy` | 순서가 고정된 날짜 형식 |
| `weekday_short`, `weekday_long` | 요일 이름 |
| `day`, `month`, `month_short`, `month_long`, `year` | 개별 날짜 구성 요소 |

사용 가능한 날짜 객체: `order.created`, `order.paid`, `order.completed`, `order.printed`, `refunds[].date`, `fiscal.sale_time`, `fiscal.received_at`. `order.printed`는 렌더링 시점에 갱신되므로 재인쇄에 유용합니다. 영수증에 세무 기록이 없으면 두 `fiscal` 날짜는 `null`이므로 섹션으로 감싸세요.

## 영수증 데이터 확장 {#extending}

플러그인은 `wcpos_receipt_data` 필터를 통해 영수증 데이터에 자체 필드를 추가할 수 있습니다.

<Accordion>
  <AccordionItem question="필터 — 인수, 여섯 가지 모드, 예제">

WCPOS는 위 필드에 특정 플러그인의 데이터를 포함하지 않습니다. 플러그인이 WooCommerce에서 모델링하지 않는 정보를 영수증에 제공해야 할 때는 WooCommerce 자체 주문 합계를 필터링하는 것과 같은 방식으로 `wcpos_receipt_data` 필터를 통해 직접 추가합니다. 이 필터는 실시간 영수증, 결제 시점의 세무 스냅샷, PDF 다운로드, 레거시 PHP 템플릿 등 서버가 생성하는 모든 영수증에 실행됩니다. WCPOS 2.0 이전에는 이 필터의 이름이 `woocommerce_pos_receipt_data`였습니다. 이전 이름은 여전히 작동하지만 2.0부터 사용 중단되었으며, 빨라도 2.2부터 제거됩니다([훅 명명 규칙](../extensions/index.mdx#hook-naming) 참조).

세 번째 인수인 `$mode`는 생성할 문서를 나타냅니다. 값은 `live`, `fiscal`, `refund`, `preview`(템플릿 편집기 및 갤러리의 샘플 영수증), `closure`, `xreport`(계산대 마감 및 X 보고서 문서)입니다. `preview`, `closure`, `xreport`에서 주문은 ID가 `0`인 저장되지 않은 주문입니다. 저장된 주문이 필요한 플러그인은 `$order->get_id()`가 `0`이면 `$data`를 변경 없이 반환해야 합니다.

```php
add_filter( 'wcpos_receipt_data', function ( array $data, WC_Abstract_Order $order, string $mode ) {
    foreach ( $data['discounts'] as &$row ) {
        if ( 'smart_coupon' === $row['discount_type'] ) {
            $row['gift_card'] = true;
        }
    }
    return $data;
}, 10, 3 );
```

이후 템플릿에서 다른 섹션과 마찬가지로 새 키를 표시 조건으로 사용할 수 있습니다.

```
{{#discounts}}
  {{#gift_card}}Gift Card{{/gift_card}}{{^gift_card}}{{i18n.discount}}{{/gift_card}}{{#label}}: {{label}}{{/label}}
{{/discounts}}
```

스키마에 정의된 키는 문서에 명시된 자료형을 유지해야 합니다. 추가한 키는 스키마에 속하지 않으므로 템플릿 편집기의 필드 선택기에 나타나지 않으며, 세무 스냅샷에는 주문 결제 시점에 필터가 추가한 내용만 담깁니다. 이 필터는 WCPOS 1.10.8부터 사용할 수 있습니다.

  </AccordionItem>

  <AccordionItem question="추가한 키를 인쇄할 수 있는 영수증">

추가한 모든 키는 서버가 직접 렌더링하는 PDF 다운로드와 레거시 PHP 템플릿에 전달됩니다. POS 앱에서 렌더링되는 HTML 및 감열식 템플릿은 먼저 데이터를 다시 구성합니다. `order`, `store`, `cashier`, `customer` 안에 추가한 키는 전달되지만, 위의 할인 행처럼 다른 위치에 추가한 키는 생략됩니다. {/* pending: monorepo#3363 */} 세무 스냅샷이 있는 실시간 영수증에서는 필터 실행 후 세무 식별 정보, `register`, `software`를 스냅샷에서 복사합니다. 따라서 이 필터에서 해당 값을 변경해도 효과가 없습니다. 대신 스냅샷에 정보를 추가하세요.

  </AccordionItem>
</Accordion>

## 문제가 발생한 경우 {#if-something-goes-wrong}

**어떤 영수증에서는 행에 `$0.00`이 인쇄되고 다른 영수증에서는 아무것도 인쇄되지 않습니다.** `totals.change_total_display`, `totals.refund_total_display`, `payments[].tendered_display` 같은 일부 `_display` 필드는 값이 0일 때 서버에서 렌더링하면 빈 값이고 앱에서 렌더링하면 `$0.00`입니다. 두 경우 모두 행을 생략하려면 숫자 필드를 조건으로 하는 섹션 안에 행을 넣으세요: `{{#totals.change_total}}…{{/totals.change_total}}`.

**총 절약액 행이 표시되지 않습니다.** `totals.total_saved_complete`가 거짓입니다. 하나 이상의 품목에 정상가가 기록되어 있지 않아 절약액을 계산할 수 없습니다. 보통 WCPOS 1.9.0 이전에 처리한 주문에서 발생합니다.

**합계가 고객이 결제한 금액보다 적습니다.** 매장에서 세금 제외 가격을 표시하므로 `totals.total`은 세전 합계입니다. 실제 청구 금액을 표시하려면 `totals.total_incl_display`를 인쇄하세요. WCPOS에 기본 제공되는 레거시 PHP 영수증은 이 금액을 인쇄합니다.

**PDF 다운로드에서는 필드가 인쇄되지만 POS에서는 인쇄되지 않습니다.** 앱에서 렌더링되는 템플릿은 먼저 데이터를 다시 구성하며 일부 필드를 생략합니다. 이 필드는 PDF 다운로드와 레거시 PHP 템플릿에서만 인쇄됩니다. 아래 목록의 필드는 해당 템플릿에서만 인쇄하거나, 섹션 조건으로 감싸 POS 영수증에서 생략되도록 하세요. {/* pending: monorepo#3363 */}

<Accordion>
  <AccordionItem question="PDF 영수증과 POS 영수증에서 다른 필드">

- `lines[].attributes`, `lines[].total_refunded_display`, `lines[].unit_subtotal_display`(해당 필드의 `_incl` 및 `_excl` 버전 포함)
- `software.platform`
- `display_tax`, `prices_entered_with_tax`, `rounding_mode`, `locale`, `order_barcode_type`을 제외한 `presentation_hints` 필드
- 독일, 네덜란드, 프랑스, 영국 기업, 스위스 유형의 고객 세금 ID
- 플러그인이 `order`, `store`, `cashier`, `customer` 외부에 추가한 키. [영수증 데이터 확장](#extending) 참조

</AccordionItem>
</Accordion>

## 버전 {#versions}

영수증 데이터는 플러그인과 별개의 버전 번호를 사용합니다. 필드가 생기기 전에 생성된 세무 스냅샷 등 이전 영수증에는 새로운 필드가 없으므로 섹션 조건으로 감싸세요.

| 버전 | 추가된 내용 |
|---------|-------|
| 1.1 | 각 품목의 정상가, 판매가, 절약액 및 **총 절약액**을 포함한 주문 절약액 합계. 어느 값도 주문 합계나 WooCommerce 보고서를 변경하지 않습니다 |
| 1.2 | `discounts[].discount_type` |
| 1.3 | `customer.first_name` 및 `i18n`의 고객 표시 레이블 |
| 1.4 | `register`, `software`, 세무 문서 필드(`fiscal.document_type`, `is_…` 플래그, `sale_time`, `received_at`, `sale_tz`, `sale_counter`, `corrects`) 및 해당 `i18n` 레이블 |
