WCPOS 2.0은 새로운 계산대, 새로운 결제 화면, 현금 서랍 기능을 도입하는 대규모 업데이트입니다. 이 페이지는 **업데이트**를 누르는 분을 위한 안내입니다. 업데이트하기 전에 끝까지 읽어 보세요.

:::warning 먼저 모든 POS 기기를 동기화하세요
POS 기기에서 2.0을 처음 열면 해당 기기의 1.11 데이터가 삭제됩니다. 그때까지 매장으로 전송하지 못한 판매 데이터는 사라집니다. 업데이트하기 전에 모든 POS 기기의 동기화가 완료될 때까지 기다리세요.

이미 매장을 업데이트했는데 POS 기기에 미전송 판매 데이터가 남아 있나요? [1.11 POS 기기에 미전송 판매 데이터가 남아 있는 경우](#unsent-sales)를 참고하세요.
:::

## 지금 업그레이드할 수 있나요? {#can-you-upgrade-today}

**WP Admin → 플러그인**을 열고 두 가지를 확인하세요.

- **WooCommerce가 9.0 이상이어야 합니다.** 2.0의 필수 조건입니다. 9.0보다 낮다면 [매장이 아직 준비되지 않은 경우](#if-your-store-isnt-ready-yet)를 참고하고, WCPOS부터 업데이트하지 마세요.
- **카드 단말기 확장 기능을 사용한다면 WCPOS Pro가 있어야 합니다.** 2.0부터 Stripe Terminal, SumUp, Mollie Terminal 등 단말기 확장 기능에는 Pro가 필요합니다. 이런 기능을 사용하면서 Pro가 없다면 여기서 멈추고, 업데이트하기 전에 [무료 버전과 Pro 비교](./free-vs-pro.mdx)를 읽어 보세요.

WooCommerce가 9.0 이상이고 카드 단말기 확장 기능을 사용하지 않거나 WCPOS Pro가 있다면 [업데이트를 누르기 전에](#before-you-click-update)로 계속 진행하세요.

## 업데이트를 누르기 전에 {#before-you-click-update}

1. **모든 POS 기기를 동기화하세요.** 각 POS 기기를 열고 메뉴에서 **매장 상태 → 데이터베이스**를 여세요. **전송 대기 중인 변경 사항**이 **0**이어야 하며, [판단을 요청하는 패널](../support/store-health.mdx#needs-attention)이 없어야 합니다. 0보다 크면 아직 매장에 도착하지 않은 데이터가 있다는 뜻이므로, POS 기기를 온라인 상태로 유지하고 기다리세요. 이 수에는 미완료 주문이 포함되지 않습니다. 각 주문을 완료하거나 **서버에 저장**을 누르세요(2.0에서는 [주문 동기화](../pos/cart/open-orders.mdx#sync-order)). 두 항목 모두 현재 로그인한 사용자의 데이터만 표시하므로, 해당 POS 기기를 사용하는 각 캐셔에 대해 사용하는 모든 매장과 모든 계산대에서 이 과정을 반복하세요. POS 기기에서 매장으로 전송하지 못한 판매, 미완료 주문, 변경 사항은 2.0을 열 때 모두 삭제됩니다.
2. **사이트를 백업**하거나 호스팅 업체에 복원 지점을 요청하세요. 업데이트로 주문이 변경되지는 않지만, 대규모 업데이트인 만큼 되돌릴 방법을 마련해 두는 것이 좋습니다.
3. **한가한 시간을 선택하세요.** 플러그인을 업데이트한 뒤에는 각 POS 기기도 2.0으로 전환해야 판매 데이터가 다시 매장으로 전송됩니다. 이전 버전에서 결제 도중이던 판매는 다시 입력해야 합니다.
4. **WCPOS Pro를 사용한다면 라이선스가 활성 상태인지 확인하세요.** **WP Admin → POS → 설정 → 라이선스**에서 확인할 수 있습니다. 유효한 라이선스가 있어야 Pro 업데이트를 받을 수 있습니다. [WCPOS Pro 설치](./pro-license.mdx)를 참고하세요.
5. **캐셔에게 할인 변경 사항을 알려 주세요.** *음수 수수료*를 추가해 금액을 차감하던 방식은 더 이상 사용할 수 없습니다. 2.0에서는 대신 **할인 추가**를 사용합니다. [첫날 달라지는 점](#what-changes-on-day-one)을 참고하세요.
6. **카드 단말기 확장 기능을 사용한다면 2.0 릴리스가 있는지 확인하세요.** Stripe Terminal, SumUp, Mollie Terminal에는 모두 있습니다. 아래 절차에서 WCPOS를 업데이트한 직후 확장 기능을 업데이트합니다.

## 플러그인과 POS 기기 업데이트 {#updating}

1. **플러그인을 업데이트하세요.** 무료 버전을 사용하는 사이트에서는 **WCPOS**를 업데이트하세요. Pro를 사용한다면 **WCPOS Pro**만 업데이트하세요. Pro에는 무료 플러그인이 이미 포함되어 있으며, 별도로 설치된 무료 플러그인은 비활성화됩니다. 이를 알리는 안내가 표시되며, 무료 플러그인은 삭제해도 됩니다.
2. 카드 단말기 확장 기능을 사용한다면 **카드 단말기 확장 기능을 업데이트**하여 2.0 릴리스로 전환하세요. 업데이트하지 않은 확장 기능은 결제 화면의 **레거시** 탭에 계속 표시되지만, 결제 패널에서 리더기를 제어할 수는 없습니다.
3. **모든 POS 기기를 2.0으로 전환하세요.** 브라우저 POS에서는 페이지를 새로고침하면 매장에서 2.0을 불러옵니다. 데스크톱 앱과 모바일 앱은 평소 업데이트하는 방식으로 2.0으로 업데이트한 다음 여세요. 각 POS 기기의 첫 동기화가 완료될 때까지 기다리세요.
4. **각 POS 기기가 2.0인지 확인하세요.** 메뉴 맨 아래의 버전(**v 2.0.0**, 휴대전화에서는 **버전 2.0.0**)을 누르세요. **WCPOS 정보**가 열립니다.

앱과 플러그인 모두 2.0이어야 합니다. 버전이 맞지 않는 POS 기기는 이를 알리는 화면에서 멈춥니다.

- **2.0 매장에 연결한 1.11 앱**은 앱 업데이트를 요청합니다. [SYNC341](../error-codes/SYNC341.mdx)을 참고하세요. 아직 미전송 판매 데이터가 있다면 업데이트하지 말고 [1.11 POS 기기에 미전송 판매 데이터가 남아 있는 경우](#unsent-sales)를 참고하세요.{/* pending: docs#675 */}
- **아직 1.11인 매장에 연결한 2.0 앱**은 **AUTH331**을 표시합니다. 플러그인을 업데이트한 다음 다시 연결하세요. [AUTH331](../error-codes/AUTH331.mdx)을 참고하세요.

## 첫날 달라지는 점 {#what-changes-on-day-one}

캐셔가 POS를 처음 열면 새로운 계산대 화면이 표시됩니다. 대부분은 이전과 같이 작동하지만, 다음과 같은 변화를 확인할 수 있습니다. 전체 목록은 [2.0의 새로운 기능](./whats-new.mdx)에 있습니다.

### 음수 수수료를 대체하는 할인 {#discounts}

수수료에 더 이상 음수를 사용할 수 없습니다. 금액을 차감하려면 장바구니에서 **+** 를 누르고 **할인 추가**를 선택하세요. 이미 음수 수수료가 포함된 주문은 변경되지 않습니다.

### 결제 패널에서 진행하는 결제 {#checkout}

**결제**를 누르면 WooCommerce 결제 페이지 대신 장바구니 옆에 키패드가 열립니다. 고객에게 받은 금액을 입력하면 거스름돈이 표시됩니다. 한 건의 판매를 현금과 카드로 나누어 결제할 수 있습니다.

1. **결제 내역** — 매장에서 POS로 받는 결제 수단과 이 POS 기기에 페어링된 카드 리더기입니다. [결제 패널](../pos/checkout/payment-methods.mdx)을 참고하세요.

### 첫날 확인할 수 있는 다른 변화 {#also-new}

- **새로운 디자인.** 입력 양식과 선택 화면이 패널 형태로 밀려 들어옵니다. **설정 → 테마**의 **화면 배율** 설정으로 기기에 맞게 POS 크기를 조절할 수 있습니다. 장바구니를 왼쪽에 배치하고 나만의 빠른 필터 버튼을 추가할 수도 있습니다. [새로운 기능: 새로운 계산대](./whats-new.mdx#a-new-register)를 참고하세요.
- **WooCommerce Analytics는 결제가 완료된 POS 주문을 집계합니다.** POS에서 아직 열려 있거나 일부만 결제된 주문은 더 이상 매출로 집계되지 않으므로, 이런 주문이 포함되어 있던 합계는 줄어듭니다.
- **영수증에 계산대 이름과 소프트웨어 버전이 표시됩니다.** 환불 시에는 **환불**이라는 제목과 정정 대상 판매가 표시된 별도의 영수증이 인쇄됩니다. 사용자 지정 영수증 템플릿은 계속 작동하며, 새 정보는 직접 추가해야 표시됩니다. [영수증](../receipts/index.mdx)을 참고하세요.
- 플러그인이 업데이트될 때 **POS 전용 상품의 카탈로그 표시 설정이 숨김으로 변경**됩니다. 이 변경은 한 번만 이루어지며, 해당 상품이 온라인 상점에 표시되지 않도록 합니다.
- **마그네틱 카드 리더기는 더 이상 지원되지 않습니다.** 페어링된 리더기(Pro) 또는 별도의 단말기로 카드 결제를 받고, POS에서 결제를 기록하세요.

### 계산대와 현금 서랍 {#registers-and-cash-drawer}

<details>
<summary>계산대와 현금 서랍: 직접 켜기 전까지 비활성 상태</summary>

2.0에서는 무료 플러그인에서도 준비금 입력과 현금 집계로 계산대를 개점하고 마감할 수 있습니다. 첫날에는 달라지는 것이 없습니다. 관리자가 **WP Admin → POS → 설정 → 일반**의 **계산대**에서 **계산대 개점 및 마감**을 켜기 전까지 비활성 상태로 유지됩니다. 같은 곳에서 **개점 준비금**도 설정합니다. 이 기능을 켜면 POS가 첫 판매 전에 준비금 입력을 요청합니다. **계산대 마감**으로 서랍의 현금을 집계하면 번호가 있는 마감 기록이 작성되며, 이어지는 화면에서 **마감 인쇄**로 인쇄할 수 있습니다. [일일 마감 정산](../pos/reconciliation.mdx)을 참고하세요.

무료 플러그인에는 모든 기기가 공유하는 계산대 하나가 있습니다. 계산대를 추가하려면 Pro가 필요합니다. [계산대](../settings/wp-admin/registers.mdx#one-register)와 [계산대 개점](../pos/register/index.mdx)을 참고하세요.

</details>

## 매장이 아직 준비되지 않은 경우 {#if-your-store-isnt-ready-yet}

**WCPOS 1.11을 계속 사용하세요.** 계속 정상 작동하며, 2.0 출시 후 6개월 동안 수정 업데이트도 제공됩니다.

1. WCPOS와 WCPOS Pro의 **자동 업데이트를 끄세요**. **WP Admin → 플러그인**의 각 플러그인 행에는 **자동 업데이트 활성화** / **자동 업데이트 비활성화** 링크가 있습니다. 링크에 **자동 업데이트 활성화**라고 표시되어 있는지 확인하세요. 이 상태가 자동 업데이트가 꺼져 있다는 뜻입니다. 이렇게 하면 근무 도중 POS 기기에 자동 업데이트가 적용되는 것을 막을 수 있습니다.
2. 준비가 되면 **WooCommerce를 9.0 이상으로 업데이트하세요**. 해당 업데이트는 WooCommerce 자체 릴리스 노트에 설명되어 있습니다.
3. **[업데이트를 누르기 전에](#before-you-click-update)로 돌아오세요.**
4. 자동 업데이트를 사용했다면 **2.0으로 전환한 뒤 자동 업데이트를 다시 켜세요**. 그렇지 않으면 이후 수정 사항이 자동으로 적용되지 않습니다.

### WooCommerce보다 WCPOS가 먼저 업데이트된 경우 {#if-wcpos-updated-first}

{/* pending: docs#675 */}
WooCommerce가 9.0 이상이 되기 전까지 POS가 열리지 않습니다. 매장에 이미 저장된 주문은 유지됩니다. 미전송 판매 데이터는 POS 기기에서 2.0을 열기 전까지만 남아 있으므로, 해당 기기를 업데이트하거나 새로고침하지 마세요. [1.11 POS 기기에 미전송 판매 데이터가 남아 있는 경우](#unsent-sales)의 절차를 따르세요. 지금 WooCommerce를 업데이트하거나, [WCPOS 1.11을 다시 설치](./previous-versions.mdx)하고 위 안내대로 자동 업데이트를 끄세요.

## 플러그인 업데이트 후 POS가 사라진 경우 {#pos-gone}

WP Admin에서 **POS** 메뉴가 사라지고 `yourdomain.com/pos`에서도 POS가 열리지 않는 경우입니다. WCPOS 2.0은 사이트가 [요구 사항](./installation.mdx#server-requirements)을 충족할 때만 실행됩니다. 충족하지 못하면 플러그인은 설치된 상태로 남지만 어떤 기능도 활성화하지 않습니다. 주문은 WooCommerce에 그대로 남습니다.

1. **WooCommerce를 확인하세요.** **WP Admin → 플러그인**에서 WooCommerce가 활성화되어 있고 버전이 9.0 이상이어야 합니다. 업데이트하거나 활성화하세요. 아직 업데이트할 수 없다면 [WooCommerce보다 WCPOS가 먼저 업데이트된 경우](#if-wcpos-updated-first)를 참고하세요.
2. **PHP를 확인하세요.** 2.0에는 PHP 7.4 이상이 필요합니다. 사이트에서 실행 중인 버전을 호스팅 업체에 문의하세요.
3. **Pro를 사용한다면 WCPOS Pro가 활성화되어 있는지 확인하세요.** 무료 **WCPOS** 플러그인은 의도적으로 비활성화됩니다. Pro에 포함되어 있기 때문입니다. [플러그인과 POS 기기 업데이트](#updating)를 참고하세요.
4. WP Admin 상단에 **“WCPOS 플러그인을 올바르게 불러오지 못했습니다.”가 표시되는지 확인하세요.** 플러그인 자체 파일을 불러오지 못해 실행이 중단된 상태입니다. 같은 버전을 다시 다운로드하고 [현재 버전 위에 업로드](./previous-versions.mdx#install)에 설명된 대로 기존 버전 위에 업로드하세요. 먼저 플러그인을 삭제하지 마세요.

POS 기기에 업데이트 전 판매 데이터가 남아 있다면 새로고침하기 전에 [1.11 POS 기기에 미전송 판매 데이터가 남아 있는 경우](#unsent-sales)를 읽어 보세요.

## 이전 버전으로 되돌리기 {#rolling-back}

### 1.11 POS 기기에 미전송 판매 데이터가 남아 있는 경우 {#unsent-sales}

POS 기기에 업데이트 화면이 표시되고 판매 데이터가 매장에 도착하지 않은 상태입니다. 2.0을 열기 전까지는 해당 기기에 데이터가 남아 있습니다. 전송하려면 다음 절차를 따르세요.

1. **해당 POS 기기를 그대로 두세요.** 앱을 업데이트하지 말고, 브라우저 POS에서는 페이지를 새로고침하지 마세요. 어느 쪽이든 2.0이 열리면서 미전송 판매 데이터가 삭제됩니다.
2. 매장에 **[1.11 플러그인을 다시 설치하세요](./previous-versions.mdx)**.
3. **브라우저 POS에서는 페이지를 새로고침하고, 앱에서는 종료 후 다시 여세요.** 매장이 다시 1.11이 되었으므로 POS 기기가 다시 연결되어 판매 데이터를 전송합니다. **매장 상태 → 데이터베이스**의 **전송 대기 중인 변경 사항**이 **0**이 되고 [판단을 요청하는 패널](../support/store-health.mdx#needs-attention)이 없을 때까지 기다리세요. 이 수에는 미완료 주문이 포함되지 않습니다. 각 주문을 완료하거나 **서버에 저장**을 누르세요. 이제 판매 데이터가 매장에 저장됩니다.
4. [플러그인과 POS 기기 업데이트](#updating)부터 진행하여 **다시 2.0으로 업데이트하세요**.

### 1.11로 돌아가기 {#back-to-1-11}

2.0이 제대로 작동하지 않는다면 먼저 [Discord](https://wcpos.com/discord)로 알려 주세요. 업그레이드 당일 발생하는 대부분의 문제는 이전 버전으로 되돌리는 것보다 빠르게 해결할 수 있습니다.

:::warning 이전 버전으로 되돌리기 전에 동기화하세요
1.11로 돌아가면 각 POS 기기는 비어 있는 로컬 데이터베이스로 시작합니다. 또한 1.11은 2.0 POS 기기에서 아직 매장으로 전송하지 못한 판매 데이터를 보낼 수 없습니다. 먼저 모든 2.0 POS 기기의 동기화가 끝날 때까지 기다리세요. **매장 상태 → 데이터베이스**의 **전송 대기 중인 변경 사항**이 **0**이어야 하며, [판단을 요청하는 패널](../support/store-health.mdx#needs-attention)이나 동기화되지 않은 미완료 주문([주문 동기화](../pos/cart/open-orders.mdx#sync-order))이 남아 있으면 안 됩니다.
:::

**이미 2.0인 데스크톱 앱이나 모바일 앱은 1.11 플러그인에 연결할 수 없습니다**([AUTH331](../error-codes/AUTH331.mdx)이 표시됩니다). 앱 스토어에서는 이전 버전을 제공하지 않습니다. 다시 업그레이드할 때까지 해당 기기에서 `yourdomain.com/pos`의 브라우저 POS를 사용하세요.

이전 버전으로 되돌리려면 [1.11 플러그인을 다시 설치하세요](./previous-versions.mdx). 아직 1.11인 브라우저 POS와 앱은 이전처럼 계속 작동합니다.

2.0에서 생성한 주문은 일반 WooCommerce 주문이므로 그대로 유지됩니다. 2.0에서 기록한 계산대 세션과 마감 기록도 데이터베이스에 남지만, 1.11에서는 표시되지 않습니다.
