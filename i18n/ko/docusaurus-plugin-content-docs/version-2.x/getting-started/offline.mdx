POS는 상품, 고객, 진행 중인 주문을 기기에 보관합니다. 인터넷 연결이 끊기거나 매장 서버가 응답하지 않아도 판매를 계속할 수 있습니다. 연결이 끊기기 전에 매장 서버에 도달한 판매라면 현금, 별도 단말기의 카드 결제, 계산대에서 기록하는 다른 결제 수단으로 결제받을 수 있습니다. 각 판매는 기기에서 대기하다가 매장 서버 연결이 복구되면 자동으로 전송됩니다. 이 페이지에서는 연결이 끊기는 순간부터 복구되는 순간까지 오프라인에서 결제받은 판매 한 건의 과정을 안내합니다.

## 오프라인 상태 확인하기 {#offline-signs}

연결이 끊겨도 따로 할 일은 없습니다. POS가 알려주므로 그대로 작업을 계속하면 됩니다.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[60, 14], [-16, 0], [150, 0], [0, 0], [10, 0]]} alt="장바구니에 상품 하나가 담긴 오프라인 상태의 POS: 금전등록기 표시줄의 매장 이름 옆에 표시된 오프라인, 기기가 오프라인 상태가 되었습니다 메시지, 검색창, 결제 버튼, 상태 버튼">

1. **오프라인** — 금전등록기 표시줄의 매장 이름 옆에 표시됩니다. 기기는 인터넷에 연결되어 있지만 매장 서버가 응답하지 않을 때도 **오프라인**으로 표시됩니다. 다른 화면(주문, 상품, 고객)에서도 페이지 표시줄에 동일한 **오프라인** 배지가 표시됩니다.
2. **기기가 오프라인 상태가 되었습니다** — 연결이 끊긴 뒤 몇 초가 지나면 표시됩니다. **도움말**을 누르면 메시지의 의미를 확인할 수 있습니다. 기기 연결 대신 매장 서버가 응답하지 않는 경우에는 **웹사이트에 연결할 수 없습니다**라는 메시지가 표시됩니다.
3. **상품 검색** — 기기에 있는 상품을 검색하므로 이미 다운로드한 상품은 계속 찾아서 판매할 수 있습니다.
4. **결제** — 판매를 구성하는 기능은 평소처럼 작동합니다. 오프라인에서 시작한 판매는 매장 서버 연결이 복구될 때까지 결제받을 수 없으며, 진행 중인 주문에서 대기합니다. 이미 매장 서버에 저장된 판매는 결제 수단에 따라 다릅니다. [오프라인에서 결제받기](#take-payment-offline)를 참고하세요.
5. **상태** — [매장 상태](../support/store-health.mdx)에서 기기에 있는 데이터와 아직 전송을 기다리는 데이터를 확인할 수 있습니다.

</JourneyShot>

## 계속 사용할 수 있는 기능 {#what-works-offline}

- **상품 및 고객 찾기** — 기기에 있는 데이터를 검색하고 필터링하고 스캔할 수 있습니다.
- **장바구니 구성** — 상품 추가, 수량 및 가격 변경, 할인 및 수수료 추가, 기기에 이미 있는 쿠폰 코드 적용, [진행 중인 주문](../pos/cart/open-orders.mdx) 간 전환이 가능합니다.
- **결제받기** — **현금**, 별도 단말기로 받은 카드 결제를 기록하는 **카드**, 그리고 대금 상환, 은행 송금, 수표처럼 계산대에서 기록하는 다른 결제 수단을 사용할 수 있습니다. 모두 매장 서버에 이미 저장된 판매에 사용할 수 있습니다. [오프라인에서 결제받기](#take-payment-offline)를 참고하세요.
- **영수증** — 결제 완료 화면, 계산대에 연결된 프린터로 인쇄, 이메일 전송 대기가 가능합니다.
- **금전등록기** — 판매 대금은 평소처럼 서랍에 반영됩니다. 다른 캐셔에게 계산대를 인계하거나 금전등록기를 전환할 수도 있습니다.
- **변경 사항 저장** — 새 고객, 수정한 주문, 영수증 이메일을 각각 기기에 보관했다가 나중에 전송합니다.

## 오프라인에서 결제받기 {#take-payment-offline}

:::warning 매장 서버에 이미 저장된 판매만 가능
연결이 끊기기 전에 매장 서버에 도달한 판매만 오프라인에서 결제받을 수 있습니다. 해당 판매의 주문 번호는 결제 화면의 상품 위에 표시됩니다. 오프라인에서 시작한 판매에는 아직 번호가 없습니다. **결제**를 누르면 결제 수단 대신 **연결 없음**이 표시됩니다. 판매는 진행 중인 주문에 저장되고 탭에는 **결제 중 · 오프라인**이 표시됩니다. **금전등록기로 돌아가기**를 눌러 다음 고객을 응대하고 매장 서버 연결이 복구되면 결제받으세요. [연결 없음](../pos/checkout/troubleshooting.mdx#no-connection)을 참고하세요.
:::

1. **결제**를 누르고 상품 위에 **#224371**과 같은 주문 번호가 있는지 확인하세요.
2. **현금**, 별도 단말기로 받은 카드 결제를 기록하는 **카드**, 또는 계산대에서 기록하는 다른 결제 수단을 탭하세요.
3. 고객에게 받은 금액을 입력하거나 정확한 금액을 탭하세요.
4. **받기**를 누른 뒤 확인하세요.

오프라인에서는 결제 패널의 금액 옆에 **오프라인**이 표시되며, 각 결제 수단에는 지금 결제받을 수 있는지가 표시됩니다.

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[60, 14], [0, -32], [0, -32], [-18, 4], [-18, 4], [440, 0]]} alt="오프라인 상태의 결제 패널: 결제할 금액 옆의 오프라인 표시, 나중에 전송과 매장에서 거부할 수 있음이 각각 표시된 현금 및 카드 타일, 현금으로 $45.00 받기 버튼">

1. **오프라인** — 금전등록기 표시줄에 계속 표시됩니다.
2. **현금** — 계산대에서 직접 받으므로 오프라인에서도 사용할 수 있습니다.
3. **카드** — 별도 단말기로 결제받고 계산대에 기록하는 카드 결제도 오프라인에서 사용할 수 있습니다. 계산대와 페어링된 카드 리더기나 온라인 결제 게이트웨이는 **… 지금 사용할 수 없음** 아래에 **연결 필요**로 표시됩니다.
4. **나중에 전송 · 매장에서 거부할 수 있음** — 결제는 지금 기록되고 매장 서버 연결이 복구되면 전송됩니다. 매장 서버는 그때 결제를 확인합니다.
5. **나중에 전송 · 매장에서 거부할 수 있음** — 카드에도 동일하게 적용됩니다.
6. **현금으로 $45.00 받기** — 평소와 같이 금액과 결제 수단을 표시합니다.

</JourneyShot>


**받기**를 누르면 POS가 확인을 요청합니다. 매장 서버가 아직 이 결제 정보를 받지 못했기 때문입니다.

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[80, -60], [-24, 0], [0, -26], [0, -26]]} alt="어두워진 결제 패널 위의 확인 창: 오프라인에서 현금으로 $45.00을 받으시겠습니까? 문구와 취소 및 현금으로 $45.00 받기 버튼">

1. **질문 뒤의 화면** — 결제 패널이 어두워진 채 대기합니다. 선택하기 전에는 결제가 기록되지 않습니다.
2. **오프라인에서 … 받으시겠습니까?** — 판매는 이 기기에 보관되었다가 매장 서버 연결이 복구되면 전송됩니다. 매장 서버가 거부하면 [주문](../orders/index.mdx)의 **확인 필요** 아래에 표시됩니다.
3. **취소** — 결제를 기록하지 않고 결제 패널로 돌아갑니다.
4. **현금으로 $45.00 받기** — 결제를 기록합니다. 평소처럼 거스름돈을 주세요.

</JourneyShot>

## 매장 서버가 확인하기 전의 영수증 {#awaiting-store}

결제는 완료되었습니다. 매장 서버가 판매 정보를 받을 때까지 결제 완료 화면과 영수증에 이 상태가 표시됩니다.

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[62, 0], [-30, 0], [80, 16], [0, -28], [0, -28], [0, -28], [0, -28]]} alt="오프라인 상태의 결제 완료 화면: 체크 표시 대신 시계, 매장 확인 대기 중 · 현금, 금전등록기 표시줄의 오프라인 · 전송할 판매 1건, 영수증 이메일 보내기, PDF 다운로드, 영수증 인쇄, 새 판매 버튼">

1. **시계** — 결제는 완료되었지만 매장 서버가 아직 확인하지 않았습니다. 매장 서버가 판매 정보를 받으면 평소의 체크 표시로 바뀝니다.
2. **매장 확인 대기 중** — 결제에 사용한 수단 앞에 표시됩니다. 진행 중인 주문의 탭에는 **결제 완료 · 매장 확인 대기 중**이, 장바구니의 결제에는 **오프라인에서 기록됨**이 표시됩니다.
3. **오프라인 · 전송할 판매 1건** — 이 기기가 매장 서버로 전송하기 위해 보관 중인 판매 건수입니다.
4. **영수증 인쇄** — 계산대에 연결된 프린터로 인쇄합니다. 영수증에는 **매장 확인 대기 중 · 아직 확인되지 않음**이라는 문구가 표시됩니다. 매장 서버에 저장된 영수증을 인쇄하는 프린터는 대기합니다. 매장 서버가 판매를 확인하면 다시 인쇄하라는 안내가 표시됩니다. [영수증 인쇄](../receipts/at-checkout.mdx#print-receipt)를 참고하세요.
5. **영수증 이메일 보내기** — 계속 사용할 수 있으며, 이메일은 전송 대기 상태가 됩니다. 아래 내용을 참고하세요.
6. **PDF 다운로드** — 매장 서버 연결이 필요하므로 비활성화됩니다.
7. **새 판매** — 다음 고객을 위한 빈 장바구니를 엽니다.

</JourneyShot>

미리보기에 **이 주문에서는 이 템플릿을 미리 볼 수 없습니다**라고 표시될 수 있습니다. 매장 서버의 템플릿을 불러오려면 서버 연결이 필요하지만, 인쇄된 영수증에는 영향이 없습니다.

이 상태에서도 고객에게 영수증을 보내려면 **영수증 이메일 보내기**를 누르세요.

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[-18, 0], [0, -28]]} alt="오프라인 상태의 영수증 이메일 보내기 양식: 연결이 복구되면 영수증을 이메일로 보낸다는 안내와 온라인 상태가 되면 보내기 버튼">

1. **현재 이 기기에서 매장에 연결할 수 없습니다** — 연결이 복구되면 영수증이 자동으로 이메일로 전송됩니다.
2. **온라인 상태가 되면 보내기** — **보내기** 대신 표시됩니다. 누르면 **영수증 이메일이 전송 대기 중입니다**라고 표시됩니다. [영수증 이메일 보내기](../receipts/at-checkout.mdx#email-receipt)를 참고하세요.

</JourneyShot>

## 전송 대기 중인 판매 {#offline-writes}

판매 도중 연결이 끊기거나 앱을 닫아도 오프라인에서 한 모든 작업은 이 기기에 남습니다. 로그인되어 있고 매장 서버에 연결할 수 있게 되면 자동으로 전송되므로 아무것도 누를 필요가 없습니다. 대기 중인 내용을 보려면 금전등록기 표시줄 끝의 아바타를 탭하세요.

<JourneyShot manifest={manifest} device="tablet" step={6} offsets={[[0, 0], [-30, 0]]} alt="오프라인 상태의 캐셔 창: 매장 확인 대기 중 · 판매 1건 영역, 온라인에서 로그인하면 전송됩니다 문구, 매장 연결이 있어야 전환 가능이라고 표시된 매장 행">

1. **매장 확인 대기 중 · 판매 1건** — 이 기기에서 결제받았지만 매장 서버가 아직 받지 못한 판매입니다. **온라인에서 로그인하면 전송됩니다**: 아무것도 누를 필요가 없습니다.
2. **전환** — **매장 연결이 있어야 전환 가능**이라는 문구와 함께 비활성화됩니다. 매장 변경은 연결이 복구될 때까지 기다려야 합니다. 계산대 인계, 금전등록기 전환, 로그아웃은 계속 가능합니다.

</JourneyShot>

금전등록기 표시줄에는 다음과 같이 표시됩니다.

- **오프라인** — 연결이 없고 대기 중인 판매도 없습니다.
- **오프라인 · 전송할 판매 1건** — 연결이 없고 대기 중인 판매가 있습니다.
- **판매 1건 매장 확인 대기 중** — 연결은 복구되었지만 매장 서버가 아직 해당 판매에 응답하지 않았습니다.

다음과 같은 문구가 표시될 수도 있습니다.

- **판매 1건 동기화 대기 중** — 매장 서버가 다시 로그인을 요청할 때 배너에 표시됩니다. [로그인과 현금 서랍](#goes-wrong-sign-in)을 참고하세요.
- **여기에서 대기합니다** — 대기 중인 판매가 남아 있는 상태에서 계산대를 인계하면 미전송 판매 건수와 함께 표시됩니다. 해당 판매는 이 기기에 남아 있다가 로그인하고 다시 온라인 상태가 되면 전송됩니다.
- **전송 대기 중인 변경 사항** — [매장 상태 → 데이터베이스](../support/store-health.mdx#database)에 표시되며, 고객, 수정 사항, 영수증 이메일을 포함해 아직 이 기기에 남아 있는 모든 변경 사항입니다.

:::warning 전송 대기 중인 변경 사항이 있으면 로컬 데이터를 지우지 마세요
[로컬 데이터를 지우면](../support/troubleshooting/clear-local-data.mdx) 아직 매장 서버에 도달하지 않은 모든 변경 사항이 삭제됩니다. 오프라인에서 결제받은 판매의 대금은 이미 현금 서랍에 들어 있습니다.
:::

## 연결이 복구되면 {#back-online}

대기 중인 판매는 자동으로 전송되며, 보통 몇 초 안에 완료됩니다.

화면 상단에 **연결이 복구되었습니다** 메시지가 나타납니다. 금전등록기 표시줄에는 매장 서버가 모든 판매 정보를 받을 때까지 **판매 1건 매장 확인 대기 중**이 표시되다가 사라집니다. 카드 리더기, 온라인 결제 게이트웨이, [연결이 필요한 기능](#what-requires-a-connection)의 모든 기능을 다시 사용할 수 있습니다.

오프라인인 동안 매장 서버에서 변경된 상품, 가격, 고객 정보는 다시 온라인 상태가 된 직후 자동으로 다운로드됩니다. 모든 판매 정보가 도착했는지 확인하려면 [매장 상태 → 데이터베이스](../support/store-health.mdx#database)를 여세요. **전송 대기 중인 변경 사항**이 0이고 표 위의 어떤 패널에서도 선택을 요청하지 않으면 됩니다. [조치가 필요한 경우](../support/store-health.mdx#needs-attention)를 참고하세요.

## 연결이 필요한 기능 {#what-requires-a-connection}

- **계산대와 페어링된 카드 리더기 및 온라인 결제 게이트웨이** — 타일에 **연결 필요**가 표시됩니다. 판매에 이미 주문 번호가 있다면 현금을 받거나 별도 단말기로 받은 카드 결제를 기록하세요. 그렇지 않으면 주문을 열어 둔 채 매장 서버 연결이 복구된 후 결제받으세요. 카드 리더기를 통한 오프라인 결제는 [로드맵](roadmap.mdx)에 포함되어 있습니다.
- **오프라인에서 시작한 판매의 결제** — 판매는 진행 중인 주문에 남습니다. 매장 서버 연결이 복구되면 결제받으세요. [위의 안내](#take-payment-offline)를 참고하세요.
- **레거시 탭** — 자체 결제 페이지를 사용하는 결제 게이트웨이입니다. [레거시 탭](../pos/checkout/legacy-tab.mdx)을 참고하세요.
- **환불** — 오프라인에서는 환불이 처리되지 않습니다. [환불](../orders/refunds.mdx)을 참고하세요.
- **새 쿠폰 만들기**(WCPOS Pro) — 버튼에 **매장에 연결할 수 있을 때 쿠폰이 생성됩니다**라고 표시됩니다.
- 영수증 **PDF 다운로드**.
- **매장 전환** 및 기기에 **캐셔 추가**. 기기에 이미 등록된 캐셔에게 계산대를 인계하는 것은 오프라인에서도 가능합니다.
- 다른 매장으로 **현금 서랍 가져가기**. 전송 대기 중인 판매를 먼저 전송해야 합니다. 전송이 끝날 때까지 이 옵션에는 예를 들어 **판매 2건을 먼저 전송하세요**라고 표시됩니다.
- 마감 시 **금액이 맞지 않는 현금 확인 결과 승인**. [금전등록기 열기](../pos/register/index.mdx#goes-wrong)를 참고하세요.
- 매장 서버의 **새 상품, 가격, 고객 정보**. 연결이 복구될 때까지 기기에 있는 정보로 판매합니다.

:::tip 연결 상태가 좋지 않은 환경에서 근무하기 전에
신호가 양호할 때 POS를 열고 상품 목록이 다운로드되도록 하세요. [매장 상태 → 데이터베이스](../support/store-health.mdx#database)에서 기기에 얼마나 다운로드되었는지 확인할 수 있습니다.
:::

## 문제가 발생한 경우 {#goes-wrong}

계산대에 표시된 메시지를 문제가 발생한 판매 단계에 해당하는 항목에서 찾아보세요.

### 스캔 {#goes-wrong-scanning}

**“스캔할 수 없음” — 이 기기에 없으며, 오프라인에서는 매장을 검색할 수 없습니다.** 해당 상품이 아직 이 기기에 없습니다. 이름으로 검색하거나 다시 온라인 상태가 되면 판매하세요. **상태 보기**를 누르면 [매장 상태](../support/store-health.mdx#database)가 열립니다. [바코드 스캔](../pos/product-panel/barcode-scanning.mdx)을 참고하세요.

**“조회 실패” — 매장이 응답하지 않았습니다.** 기기는 인터넷에 연결되어 있지만 매장 서버가 스캔에 응답하지 않았습니다. 연결을 확인하고 다시 스캔하세요.

### 결제 및 주문 {#goes-wrong-checkout}

**“주문이 저장되지 않음 — 매장에서 거부했습니다”.** 매장 서버가 주문을 거부했으며 제목 아래에 이유가 표시됩니다. 판매는 장바구니로 돌아가고 탭에는 **저장 거부됨**이 표시됩니다. 매장 서버가 지적한 문제(예: 품절 상품)를 해결하고 **결제**를 다시 누르세요. **매장 상태**를 누르면 거부된 변경 사항이 **다시 전송** 및 **삭제**와 함께 열립니다. [서버에 도달하지 못한 변경 사항](../support/store-health.mdx#refused-changes)을 참고하세요.

**“이 주문은 아직 매장으로 전송 중입니다”.** 잠시 기다렸다가 **결제**를 다시 누르세요. 청구된 금액은 없으며 매장 서버가 주문을 식별하므로 주문이 중복 생성되지 않습니다.

**“… 항목이 매장에 저장되지 않았습니다”.** 오프라인에서 추가한 고객을 매장 서버가 거부했습니다. 판매에는 고객 주소가 유지되지만 비회원 판매로 남습니다. [매장 상태](../support/store-health.mdx#refused-changes)에서 고객 정보를 다시 전송하면 판매가 해당 고객과 연결됩니다.

**주문의 “확인 필요” 아래에 표시된 판매.** 매장 서버가 오프라인에서 받은 결제를 거부했습니다. 주문을 열고 고객과 결제를 정산하세요. [주문](../orders/index.mdx)을 참고하세요.

### 로그인과 현금 서랍 {#goes-wrong-sign-in}

**“세션이 만료되었습니다” 또는 “판매 1건 동기화 대기 중”.** 매장 서버가 이 기기에서 데이터를 더 받으려면 다시 로그인해야 합니다. **로그인**을 누르세요. 데이터는 사라지지 않으며, 로그인하면 미전송 판매가 전송됩니다. **세션이 자동으로 갱신되었습니다**가 표시되면 POS가 자동으로 다시 로그인한 것이므로 할 일은 없습니다.

**“현금 서랍이 이동되었습니다. 다음 동기화 시 이 기기에 기록됩니다.”** 현금 서랍을 다른 매장으로 가져갔으며 매장 서버에 반영되었습니다. 할 일은 없습니다. 대신 **현금 서랍 이동이 완료되지 않았습니다**가 표시되면 다시 시도하기 전에 두 금전등록기를 모두 확인하세요.

### 영수증 {#goes-wrong-receipts}

**“서버에서 이메일을 보내지 않았습니다.”** 매장 서버가 영수증 이메일 요청을 받았지만 전송하지 않았습니다. 아직 대기 중이거나 전송 시도가 중단된 영수증 이메일은 [매장 상태 → 데이터베이스](../support/store-health.mdx#database)의 **발송 대기 중인 영수증 이메일** 아래에 나열되며, 각각 **다시 전송** 및 **제거**가 표시됩니다.

영수증에 표시된 **“매장에 저장되지 않음 · 주문 번호 없음”**. 매장 서버가 이 판매 정보를 받은 적이 없으므로 주문 번호가 없고 아직 영수증을 이메일로 보낼 수 없습니다. **주문 동기화**를 눌러 전송하세요.

:::info WCPOS Pro 사용 시
매장이 여러 곳이면 매장 전환에 연결이 필요합니다. 연결이 복구될 때까지 매장 행에 **매장 연결이 있어야 전환 가능**이라고 표시됩니다.
:::
