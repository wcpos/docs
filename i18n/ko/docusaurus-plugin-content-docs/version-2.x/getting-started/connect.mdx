브라우저에서는 POS가 자체 사이트에서 실행되므로 따로 연결할 필요가 없습니다. 데스크톱과 모바일 앱은 **연결** 화면에서 시작합니다. 여기서 매장을 한 번 추가한 다음 WordPress 계정으로 로그인하고 POS를 엽니다.

## 브라우저에서 POS 열기 {#web}

`yourdomain.com/pos`로 이동하여 WordPress 사용자명과 비밀번호로 로그인하세요. POS가 바로 열립니다.

기본 주소는 `pos`입니다. 변경하려면 관리자가 WP Admin의 **설정 › 고유주소**를 열고 **선택 사항** 아래의 **POS 기본 경로**를 입력합니다. `pos`를 유지하려면 비워 두세요.

브라우저에서 **로그아웃**하면 WordPress에서도 로그아웃됩니다.

## 앱에서 매장 연결하기 {#adding-a-new-store}

1. **매장 주소**에 `mystore.com`과 같은 매장 주소를 입력하고 **연결**을 누르세요. 앱에 각 확인 과정이 차례로 표시됩니다. **매장 찾는 중…**, **WordPress 확인 중…**, 플러그인 확인, **저장 중…** 순서입니다.
2. 매장 카드에서 **WordPress로 로그인**을 누르세요. 매장 사이트의 로그인 창이 열립니다. WordPress 사용자명과 비밀번호로 로그인하세요.
3. 연결 화면으로 돌아옵니다. **WordPress 사용자** 아래에 이름이 표시되고 옆에 **로그인됨**이 표시됩니다.
4. **매장** 아래에는 이미 매장이 선택되어 있습니다. WCPOS Pro에서 여러 매장을 사용하면 제목이 **매장 선택**으로 표시됩니다. 판매할 매장을 선택하세요.
5. **POS 열기**를 누르세요.

주소에 접속할 수 없으면 **연결** 아래에 이유가 빨간색으로 표시됩니다. 해당 오류 코드 페이지로 연결되는 **자세히 알아보기** 링크도 함께 표시되는 경우가 많습니다. [문제가 발생한 경우](#troubleshooting)를 참조하세요.

앱을 처음 열면 주소만 입력하도록 안내합니다.

3. **데모 매장 체험하기** — 자신의 매장 없이도 둘러볼 수 있습니다. [데모 매장 체험하기](#demo-store)를 참조하세요.

**연결**을 누르면 매장 카드가 생깁니다. 아직 로그인한 사용자는 없습니다.

1. **WordPress로 로그인** — 로그인 창을 엽니다.
2. **작업** — **사이트 제거**가 있습니다. [한 기기에서 여러 매장 사용하기](#multiple-stores)를 참조하세요.
3. **다른 매장 연결** — 이 기기에 두 번째 매장을 추가합니다.
4. **데모 매장 체험하기** — 연결한 후에도 여기서 이용할 수 있습니다.

로그인하면 카드에 사용자, 매장, **POS 열기**가 표시됩니다.

1. **WordPress 사용자** — 본인의 이름 옆에 **로그인됨**이 표시됩니다. 이름을 눌러 판매할 사용자를 선택하세요.
2. **매장 선택** — 판매할 매장입니다.
3. **POS 열기** — 해당 사용자로 해당 매장의 POS를 엽니다.
4. **다른 사용자 추가** — 이 기기에서 다음 캐셔를 로그인시킵니다. [한 매장에서 여러 캐셔 사용하기](#multiple-users-per-store)를 참조하세요.
5. **×** — 이 기기에서 해당 사용자를 제거합니다.
6. **작업** — **사이트 제거**가 있습니다.
7. **다른 매장 연결** — 두 번째 매장을 추가합니다.
8. **데모 매장 체험하기** — WCPOS 데모 매장입니다.

## 한 기기에서 여러 매장 사용하기 {#multiple-stores}

매장 목록 아래의 **다른 매장 연결**을 눌러 다음 매장을 추가하세요. 매장이 둘 이상이면 **내 사이트** 아래에 나열되며, 한 번에 하나씩 펼쳐집니다. 각 매장에는 이름, 주소와 함께 **사용자 2명**처럼 로그인한 사용자 수가 표시됩니다. 매장을 눌러 펼치세요.

이 기기에서 매장을 제거하려면 카드의 **작업** 메뉴를 열고 **사이트 제거**를 선택한 다음 **제거**를 눌러 확인하세요. 앱에 **매장과 연결된 사용자를 제거할까요?** 라는 확인 메시지가 표시됩니다. 해당 매장에 로그인한 모든 사용자가 이 기기에서 로그아웃됩니다. 매장 자체에는 아무런 변화가 없습니다.

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[-35, 0], [305, 0], [63, 0], [142, 0], [-35, 0], [115, 0]]} alt="매장 두 개가 있는 내 사이트: 첫 번째 카드는 접혀 있으며 이름, 주소, 사용자 1명이 표시되고 작업 메뉴의 사이트 제거가 열려 있습니다. 두 번째 카드는 펼쳐져 사용자, 매장, POS 열기가 표시됩니다. 아래에는 다른 매장 연결이 있습니다.">

1. **접힌 매장** — 누르면 펼쳐집니다. 기존에 펼쳐져 있던 매장은 접힙니다.
2. **사용자 1명** — 이 기기에서 해당 매장에 로그인한 사용자 수입니다.
3. **작업** — 해당 매장의 메뉴입니다.
4. **사이트 제거** — 확인 후 이 기기에서 매장을 제거합니다.
5. **펼쳐진 매장** — 사용자, 매장, **POS 열기**가 표시됩니다.
6. **다른 매장 연결** — 매장을 하나 더 추가합니다.

</JourneyShot>

## 한 매장에서 여러 캐셔 사용하기 {#multiple-users-per-store}

판매하는 사람은 각자 자신의 WordPress 계정으로 로그인합니다.

- **캐셔 추가.** **WordPress 사용자** 아래의 **다른 사용자 추가**를 누르고 해당 캐셔의 계정으로 로그인하세요. 목록에 추가됩니다.
- **판매할 사용자 선택.** 이름을 누르세요. 선택한 사용자에 맞춰 매장과 **POS 열기**가 바뀝니다.
- **다시 로그인.** 이름에 **다시 로그인**이 표시되면 매장에서 로그아웃된 상태입니다. 로그인이 만료되었거나 관리자가 [세션](../settings/wp-admin/sessions.mdx#signing-devices-out)에서 종료한 것입니다. 해당 행의 **재인증**을 누르고 해당 사용자로 로그인하세요.
- **캐셔 제거.** 해당 행의 **×** 를 누르고 **제거**를 눌러 확인하세요. 이 기기에서만 제거되며 서버에는 아무런 변화가 없습니다.

:::note 해당 행의 사용자로 로그인하세요
**재인증** 과정에서 다른 사용자로 로그인하면 앱에 **다른 사용자로 로그인됨**이라고 표시됩니다. 그 사용자는 목록에 추가되지만 처음 선택한 사용자는 여전히 로그아웃 상태입니다. **재인증**을 다시 누르고 원래 사용자의 계정으로 로그인하세요.
:::

## 다른 캐셔에게 계산대 인계하기 {#switching-users}

POS를 연 상태에서는 캐셔 패널에서 담당자를 바꿉니다. 계산대 표시줄 끝의 아바타를 누르세요.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[182, -19], [0, 0], [-75, 0], [0, -30], [0, -30], [90, 0]]} alt="POS의 캐셔 패널: 계산대 인계 대상과 그 아래의 다른 계정, 전환 버튼이 있는 매장, WordPress 관리자 및 데스크톱 앱 링크, 로그아웃">

1. **계산대 인계 대상** — 이 기기에 로그인한 다른 캐셔와 각 캐셔의 미완료 장바구니 수를 보여 줍니다. 한 명을 선택하고 **…에게 인계**를 누르세요. 해당 사용자로 POS가 다시 로드되며, 열려 있는 계산대는 열린 상태를 유지합니다. 본인의 미완료 장바구니와 미전송 판매 내역은 돌아올 때까지 그대로 남습니다. 이 화면에서는 아직 다른 사용자가 로그인하지 않았습니다.
2. **다른 계정…** — 이 기기에서 새로운 사용자를 로그인시킵니다. 위 목록과 연결 화면에 추가됩니다.
3. **전환** — 매장이 여러 개일 때 다른 매장으로 이동합니다(WCPOS Pro). [매장과 계산대 선택하기](../stores/registers-and-devices.mdx#choosing-a-store-and-a-register)를 참조하세요.
4. **WordPress 관리자** — 사이트의 WP Admin을 엽니다. 브라우저에서만 사용할 수 있습니다.
5. **데스크톱 앱** — 데스크톱 앱 다운로드 페이지입니다. 브라우저에서만 사용할 수 있습니다.
6. **로그아웃** — 앱에서는 연결 화면으로 돌아가고, 브라우저에서는 WordPress에서 로그아웃됩니다. 열려 있는 계산대는 다음 캐셔를 위해 열린 상태를 유지하며, POS에서 먼저 마감할지 묻습니다. [캐셔 패널](../pos/register/index.mdx#cashier-sheet)을 참조하세요.

</JourneyShot>

결제가 진행 중이거나(**먼저 결제를 완료하세요**) 금전함의 현금을 확인하는 중에는(**먼저 현금 확인을 완료하거나 취소하세요**) 인계할 수 없습니다.

## 데모 매장 체험하기 {#demo-store}

연결 화면 아래의 **데모 매장 체험하기**를 누르면 앱이 WCPOS 데모 매장에 연결되고 로그인 창이 열립니다. 자신의 매장에 영향을 주지 않고 둘러볼 수 있습니다.

## 문제가 발생한 경우 {#troubleshooting}

메시지가 나타난 시점에 해당하는 항목에서 메시지를 찾아보세요.

### 연결 또는 로그인 중 {#while-connecting}

<Accordion>
  <AccordionItem question="로그인이 완료되지 않았습니다.">

  로그인 후 앱으로 돌아오지 못했습니다. 데이터는 손실되지 않습니다. 아직 전송하지 않은 내역은 로그인하면 전송됩니다. **WordPress로 로그인** 또는 **재인증**을 다시 누르세요.

  </AccordionItem>

  <AccordionItem question="로그인 창에 오류나 빈 페이지가 표시됩니다">

  보통 사이트의 보안, 방화벽 또는 로그인 플러그인이 차단하는 경우입니다. [플러그인 충돌](../support/troubleshooting/plugin-conflicts.mdx#security-and-login-plugins)을 참조하세요.

  </AccordionItem>

  <AccordionItem question="이 사이트의 WordPress REST API는 인증이 필요합니다">

  웹사이트 관리자에게 이 설정을 확인해 달라고 요청하세요. 앱에 차단한 플러그인 자체의 메시지가 대신 표시될 수도 있습니다. 예를 들어 로그인한 사용자만 REST API를 사용할 수 있다는 메시지입니다.

  관리자 안내: Force Login 같은 플러그인이 로그인하지 않은 모든 사용자의 REST API 접근을 막아 앱에서 매장 정보를 읽을 수 없는 상태입니다. 해당 플러그인에서 로그인하지 않은 방문자도 REST API에 접근할 수 있도록 허용하세요. [플러그인 충돌](../support/troubleshooting/plugin-conflicts.mdx#security-and-login-plugins)을 참조하세요.

  </AccordionItem>

  <AccordionItem question="WordPress 사이트가 아닌 것 같습니다">

  앱이 해당 주소에서 WordPress를 찾지 못했습니다. 브라우저에서 해당 주소로 매장이 열리는지, `yourdomain.com/pos`가 작동하는지 확인하세요. 사이트 응답 시간이 너무 길다는 메시지가 나오면 서버를 확인하고 다시 시도하세요.

  </AccordionItem>

  <AccordionItem question="로컬 또는 테스트 사이트에 연결할 수 없습니다">

  앱은 사이트 홈페이지가 보내는 `Link` 헤더에서 매장을 찾습니다. 이 헤더는 사이트의 REST API를 가리킵니다. 헤더를 읽을 수 없으면 대신 `yourdomain.com/wp-json/`을 시도합니다. 둘 다 작동하지 않으면 **WordPress 사이트가 아닌 것 같습니다**가 표시됩니다.

- 이 기기에서 접속할 수 있는 주소를 사용하세요. `localhost`는 항상 기기 자체를 뜻하므로 휴대폰이나 태블릿에서 이 이름으로 컴퓨터의 매장에 접속할 수는 없습니다.
- 같은 기기의 브라우저에서 `yourdomain.com/wp-json/`을 여세요. 오류나 로그인 페이지가 아니라 사이트의 REST API 데이터가 표시되어야 합니다.
- 사이트에서 WCPOS가 활성화되어 있는지 확인하세요. WCPOS는 앱이 `Link` 헤더를 읽을 수 있게 하는 헤더를 보냅니다.
- CORS 또는 `Link` 헤더에 관한 메시지는 사이트의 교차 출처(CORS) 헤더에 문제가 있다는 뜻입니다. 서버나 프록시에서 CORS를 중복으로 처리하는 경우가 많습니다. [HOST111](../error-codes/HOST111.mdx)을 참조하세요.

</AccordionItem>

  <AccordionItem question="이 사용자의 매장이 없습니다">

  앱이 이 계정의 POS 매장을 찾지 못했습니다. 관리자가 매장을 설정한 후 다시 로그인하세요. [매장 설정](../stores/setup.mdx)을 참조하세요.

  </AccordionItem>
</Accordion>

### 업데이트가 필요한 경우 {#update-needed}

<Accordion>
  <AccordionItem question="이 기기의 POS 앱을 업데이트하세요.">

  사이트의 WCPOS 플러그인이 이 앱보다 최신 버전입니다. 브라우저에서는 **새로고침**을 누르세요. 데스크톱 또는 모바일 앱에서는 앱 업데이트를 설치하고 다시 여세요. 미전송 판매 내역은 기기에 남습니다. **로그아웃**도 사용할 수 있습니다. 연결 화면의 매장에도 같은 메시지와 함께 업데이트 후 누를 수 있는 **재시도**가 표시됩니다. [SYNC341](../error-codes/SYNC341.mdx)을 참조하세요.

  </AccordionItem>

  <AccordionItem question="WordPress 사이트의 WCPOS 플러그인을 업데이트하세요.">

  앱이 매장의 플러그인보다 최신 버전입니다. 관리자가 WP Admin의 **플러그인**에서 WCPOS를 업데이트한 후 다시 로그인하세요. 그전에는 **로그아웃**으로만 나갈 수 있습니다. 연결 화면의 매장 카드에도 같은 플러그인 업데이트 안내와 **자세히 알아보기**가 표시됩니다. [AUTH331](../error-codes/AUTH331.mdx)을 참조하세요.

  </AccordionItem>
</Accordion>

### POS 열기 이후 {#after-open-pos}

<Accordion>
  <AccordionItem question="이 매장의 계산대가 없습니다">

  이 매장은 계산대를 사용하도록 설정되어 있지만 아직 등록된 계산대가 없습니다. 관리자가 **WooCommerce › POS › 매장**에서 추가해야 합니다. 관리자에게는 해당 페이지로 바로 이동하는 **매장 열기** 버튼이, 캐셔에게는 **계산대 안내**가 표시됩니다. 그런 다음 **다시 시도**를 누르세요. [계산대](../settings/wp-admin/registers.mdx)를 참조하세요.

  </AccordionItem>

  <AccordionItem question="이 매장의 계산대에 접근할 수 없습니다">

  POS가 매장의 계산대 정보를 읽지 못했습니다. 연결을 확인한 다음 **다시 시도**를 누르세요.

  </AccordionItem>
</Accordion>

### 여전히 해결되지 않는 경우 {#still-stuck}

매장이 [서버 요구 사항](../support/performance/server.mdx#minimum-server-requirements)을 충족하는지, 호스팅 업체가 REST API를 차단하고 있지 않은지 확인하세요.
