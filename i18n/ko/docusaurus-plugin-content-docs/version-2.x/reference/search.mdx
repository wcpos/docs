기억나는 각 단어의 일부 글자를 순서에 상관없이 입력해 보세요. 입력한 내용이 모두 포함된 항목만 목록에 남습니다. 이 페이지에서는 각 검색창의 검색 대상, 매장 검색과 기기 검색의 차이, 개발자가 자체 필드를 추가하는 방법을 설명합니다. 찾는 항목이 없나요? [검색 결과가 없을 때](#goes-wrong)를 참조하세요.

각 검색창의 검색 대상: [상품](#products) · [주문](#orders) · [고객](#customers) · [쿠폰](#coupons) · [카테고리, 태그, 브랜드](#category-tag-brand) · [전화번호](#phone-numbers)

## 입력한 단어의 일치 방식 {#how-a-search-is-matched}

- **모든 단어가 일치해야 합니다.** 공백을 기준으로 검색어를 단어로 나눕니다. 각 단어는 [아래에 나열된](#what-each-screen-searches) 상품, 주문 또는 고객 정보 중 어딘가에 있어야 하며, 순서는 상관없습니다. `shirt lovelace`를 입력하면 셔츠가 포함된 Ada Lovelace의 주문을 찾습니다.
- **단어의 어느 부분이든 일치합니다.** `saippua`로 `Kuorintasaippua`를, `jo`로 `Bjorn`을 찾습니다. 로그 화면 외에는 최소 길이 제한이 없습니다.
- **대소문자나 악센트는 구분하지 않습니다.** `creme`로 `Crème`을 찾습니다.
- **단어 안의 문장 부호는 유지됩니다.** `0.4`, `K-2`, `3/4`, 전체 이메일 주소는 각각 하나의 단어이며 마침표나 하이픈에서 나뉘지 않습니다.

예시:

2. **Aim Analog Watch** — 두 단어가 모두 포함된 유일한 상품입니다.
3. **…개 상품** — 일치하는 상품 수입니다. **재고 있음** 필터가 켜져 있는 동안에는 품절 상품이 집계되지 않습니다. [검색 및 필터링](../pos/product-panel/search-filtering.mdx#no-match)을 참조하세요.

입력을 멈추면 잠시 후 목록이 업데이트됩니다. 전체 목록을 다시 보려면 입력란을 지우세요. 매장에서 가져온 결과에도 이 규칙이 적용되지만 [몇 가지 차이](#device-and-store)가 있습니다.

## 전화번호 {#phone-numbers}

전화번호는 공백, 괄호, 하이픈 없이 숫자만 입력하세요. 저장된 번호의 표기 방식과 관계없이 숫자끼리 비교합니다:

- `0412`로 `(04) 1234 5678`을 찾습니다.
- `412345`로 `+61 412-345-678`을 찾습니다.
- `0412`로는 `+61 412 345 678`을 찾을 수 **없습니다**.

국가 코드와 맨 앞의 `0`은 변환되지 않습니다. `0412`와 `+61 412`는 서로 다른 숫자입니다.

## 각 검색창의 검색 대상 {#what-each-screen-searches}

### 상품 {#products}

상품 패널과 상품 화면에서 검색하는 항목:

- 이름, SKU, 바코드.
- 옵션 상품은 해당 옵션 중 하나의 SKU 또는 바코드가 일치해도 표시됩니다.

바코드는 매장에서 바코드용으로 사용하는 필드입니다. [바코드 필드](../settings/wp-admin/general.mdx#barcode-field)를 참조하세요. 바코드 **스캔**은 검색과 다릅니다. 정확히 일치하는 코드를 찾아 상품을 장바구니에 추가합니다. [바코드 스캔](../pos/product-panel/barcode-scanning.mdx)을 참조하세요.

### 주문 {#orders}

주문 화면에서 검색하는 항목:

- **주문:** 주문 번호.
- **청구:** 이름, 성, 회사, 이메일, 전화번호.
- **배송:** 이름, 성, 회사, 전화번호.
- **항목:** 각 주문 항목의 이름과 SKU.

주문 항목은 **판매 당시의 이름**으로 검색되므로 상품 이름이 변경된 후에도 주문을 찾을 수 있습니다. 배송이나 매장 수령 주문은 수령인의 이름으로 조회하는 경우가 많고 수령인이 결제자와 항상 같지는 않기 때문에 배송 정보의 이름도 검색합니다.

### 고객 {#customers}

고객 화면과 장바구니의 고객 검색에서 검색하는 항목:

- **고객:** 이름, 성, 이메일, 사용자명, 세금 ID.
- **청구:** 이름, 성, 회사, 이메일, 전화번호.
- **배송:** 이름, 성, 회사, 전화번호.

### 쿠폰 {#coupons}

쿠폰 화면과 장바구니의 쿠폰 검색에서 검색하는 항목:

- 코드와 설명.

### 카테고리, 태그, 브랜드 {#category-tag-brand}

카테고리, 태그, 브랜드 필터 목록에서 검색하는 항목:

- 이름.

## 기기 검색과 매장 검색 {#device-and-store}

검색은 기기에 이미 있는 데이터를 먼저 조회하므로 결과가 즉시 표시됩니다. **상품**, **고객**, **주문**은 매장에도 조회하므로 이 기기에 아직 다운로드되지 않은 기록도 나타납니다. **쿠폰**과 **카테고리**, **태그**, **브랜드** 목록은 기기에서만 검색합니다. 오프라인에서는 모든 검색이 기기에 있는 데이터만 찾습니다.

매장에서도 같은 필드에 같은 규칙을 적용하지만 몇 가지 차이가 있습니다.

<details>
<summary>주문 번호, 고객 이름, 항목 SKU, 긴 검색어의 차이</summary>

- **주문 번호.** 매장에서는 정확히 일치하는 번호의 주문을 찾으며, 순차 주문 번호 플러그인이 부여한 번호도 검색합니다. 기기에서는 입력한 숫자가 포함된 번호도 찾습니다. 기기에서 `412`로 주문 4120을 찾을 수 있습니다.
- **고객 표시 이름.** 매장에서는 WordPress에 표시되는 고객 이름도 검색합니다.
- **주문 항목 SKU.** 매장에서는 상품의 현재 SKU를 검색합니다. 기기에서는 해당 주문을 마지막으로 다운로드했을 때 주문 항목에 있던 SKU를 검색합니다.
- **긴 검색어.** 매장에서는 최대 열 단어를 하나씩 비교합니다. 검색어는 몇 단어 정도로 짧게 입력하세요.

</details>

## 검색 결과가 없을 때 {#goes-wrong}

- **결과가 전혀 없습니다** — 각 단어에 오타가 없는지 확인하세요. 하나라도 일치하지 않는 단어가 있으면 모든 결과가 숨겨집니다. 단어 하나를 빼고 다시 시도하세요.
- **전화번호를 찾을 수 없습니다** — 저장된 형태 그대로 숫자만 입력하세요. 국가 코드 없이 저장된 번호라면 국가 코드를 빼고, 국가 코드와 함께 저장되었다면 포함하세요.
- **오프라인 상태입니다** — 기기에 이미 있는 기록만 찾을 수 있습니다. 이 기기에 저장된 데이터 범위는 [매장 상태 → 데이터베이스](../support/store-health.mdx#coverage)에서 확인하세요.
- **[로그](../support/logs.mdx) 화면에서는** — 세 글자보다 짧은 단어를 검색에서 제외합니다.
- **상품 목록이 계속 짧습니다** — 필터가 여전히 켜져 있습니다. [검색 및 필터링](../pos/product-panel/search-filtering.mdx#no-match)을 참조하세요.

## 개발자용: 검색 가능한 필드 변경하기 {#developers}

<details>
<summary>설정이 없는 이유와 자체 필드를 추가하는 방법</summary>

### 검색 필드 설정이 없는 이유 {#why-there-is-no-setting}

위의 필드는 POS와 WP Admin에서 고정되어 있습니다. 기록의 필드에 입력한 단어가 포함되어 있을 때만 일치하므로, 검색 필드가 늘어나도 잘못된 결과가 나오지 않습니다. 또한 목록을 고정하면 기기와 매장에서 같은 필드를 검색할 수 있습니다. 회원 번호와 같이 매장에서 추가한 필드는 개발자가 필터 하나로 추가할 수 있습니다.

### 매장의 검색 일치 방식 {#store-matching}

- **주문 번호**는 WooCommerce 주문 ID와 순차 주문 번호 플러그인이 기록한 `_order_number` 및 `_order_number_formatted` 메타를 대상으로 비교합니다.
- **대소문자와 악센트**의 처리는 데이터베이스 정렬 규칙에 따릅니다. WordPress의 기본 정렬 규칙은 둘 다 무시하므로 `creme`로도 `Crème`을 찾습니다.

### 자체 필드 추가하기 {#adding-a-custom-field}

`wcpos_search_fields`는 컬렉션의 검색 선언과 컬렉션 슬러그를 받습니다. WCPOS 2.0 이전에는 이 필터의 이름이 `woocommerce_pos_search_fields`였습니다. 이 이름은 여전히 작동하지만 2.0부터 사용이 중단될 예정으로 지정되었으며, 빨라도 2.2에 제거됩니다([훅 이름 규칙](../extensions/index.mdx#hook-naming) 참조). 사용자 메타에 저장된 회원 번호로 고객을 찾을 수 있도록 하려면 다음과 같이 작성하세요:

```php
add_filter( 'wcpos_search_fields', function ( array $search, string $collection ) {
	if ( 'customers' === $collection ) {
		$search['meta'][] = 'loyalty_number';
	}
	return $search;
}, 10, 2 );
```

주문의 경우 `$search['posts']['meta']`에 추가하세요. 기존 저장 방식에서는 게시물 메타에서, HPOS에서는 주문 메타 테이블에서 해당 키를 검색합니다.

**고객**이나 **주문**에 추가한 키는 양쪽 모두에서 검색합니다. 매장은 쿼리에 해당 키를 포함하고 POS도 기기 검색에 이를 추가합니다. `wcpos/v2/site`가 매장에서 추가한 키를 제공하기 때문입니다. 다음 세 가지 제한이 있습니다:

- **맨 앞에 밑줄이 없는** 키만 기기에 전달됩니다. `_private`와 같은 키는 매장에서만 검색합니다.
- 나중에 추가한 키는 POS를 다음에 시작할 때 전달됩니다. 브라우저를 새로고침하거나 앱을 다시 열면 됩니다.
- **상품**이나 **옵션**에 추가한 키(`$search['posts']['meta']`)는 매장에서만 검색합니다.

값은 캐셔가 입력할 형태로 저장하고, 번호라면 숫자만 저장하세요. 필터는 목록에 필드를 추가할 뿐 단어의 일치 방식을 바꾸지는 않습니다.

</details>
