결제 설정에서는 판매 대금을 받는 방법과 이후 주문 처리 방식을 정합니다.

여기에서 할 수 있는 작업:

- [계산대에서 재고 초과 판매 방지하기](#prevent-overselling) (새 매장에서는 꺼져 있음)
- [POS 주문에서 보낼 이메일 선택하기](#email-notifications)

사용자 정의 필드는 여기에서 설정하지 않습니다. 주문에 추가하려면 [주문 세부 정보](../../pos/cart/order-actions.mdx#order-meta)의 **+ 사용자 정의 필드**를 사용하고, 고객 계정에 추가하려면 [고객 양식](../../customers/index.mdx#add-new-customer)을 사용하세요.

이 화면의 변경 사항은 즉시 저장됩니다. **저장 중** 메시지에 이어 **저장됨** 메시지가 표시되며 저장 버튼은 없습니다. 유일한 예외는 결제 게이트웨이의 [POS 설정](#gateway-pos-settings) 대화 상자로, 여기에서는 **저장**을 눌러야 합니다.

계산대는 POS를 시작할 때 이 설정을 읽으므로, 변경 후에는 각 계산대에서 POS를 새로고침하세요.

## 화면 한눈에 보기 {#at-a-glance}

화면에는 위에서부터 **초과 판매 방지**, **관리자 이메일**, **고객 이메일**, **캐셔 이메일** 스위치와 **결제 게이트웨이** 표가 있습니다. WooCommerce의 이전 주문 저장 방식을 사용하는 매장에서는 상단에 경고도 표시됩니다. [주문 저장 방식](#order-storage)을 참고하세요.

## 결제 게이트웨이 {#payment-gateways}

**결제 게이트웨이** 표에는 WooCommerce에서 게이트웨이라고 부르는 결제 수단이 나열됩니다. 사이트에 설치된 모든 결제 수단과 POS 자체의 **현금**, **카드**가 포함됩니다. 각 행은 하나의 결제 수단이며, 계산대에서 제공할지 정하는 **활성화** 스위치, **주문 상태**, 위치를 정하는 드래그 핸들이 있습니다. 나머지 열은 아래 펼쳐보기에서 설명합니다.

<details>
<summary>결제 게이트웨이 표의 열</summary>

| 열 | 기능 |
|--------|-------------|
| 드래그 핸들 | 행을 위아래로 드래그하여 계산대에서 해당 타일의 위치를 옮깁니다. [맨 앞에 표시할 결제 수단 선택하기](#reordering-gateways)를 참고하세요. |
| **기본값** | [레거시 탭](../../pos/checkout/legacy-tab.mdx)에 표시되는 매장 자체 결제 페이지에서 미리 선택되는 결제 게이트웨이입니다. 켜져 있는 결제 게이트웨이만 선택할 수 있습니다. **현금**은 해당 페이지에 표시되지 않으며 현금 타일에서만 받을 수 있습니다. 결제 탭의 타일에는 이 설정이 적용되지 않습니다. [맨 앞에 표시할 결제 수단 선택하기](#reordering-gateways)를 참고하세요. |
| **결제 게이트웨이** | 결제 게이트웨이의 이름입니다. |
| **결제 게이트웨이 ID** | `pos_cash`와 같은 WooCommerce 식별자입니다. 개발자가 요청하는 경우에만 필요합니다. |
| **활성화** | 계산대에서 제공할지 정합니다. |
| **주문 상태** | 이 수단으로 결제한 판매에 부여되는 상태입니다. [주문 상태](#order-status)를 참고하세요. |
| **⋮** | **POS 설정**이 있으며, 현금과 카드를 제외한 결제 게이트웨이에는 **WooCommerce 설정**도 있습니다. [타일 이름 변경 또는 현금 합계 반올림하기](#gateway-pos-settings)를 참고하세요. |

</details>

:::note 무료 버전과 Pro
[WCPOS Pro](../../getting-started/pro-license.mdx)가 없으면 **현금**과 **카드**만 켤 수 있습니다. 나머지 행에서는 **활성화** 스위치, **주문 상태**, **⋮** 가 비활성화되며, 표 위에 이를 알리는 안내와 **Pro로 업그레이드** 링크가 표시됩니다.
:::

### 계산대에서 결제 수단 제공하기 {#enabling-a-gateway}

**시작하기 전에:** 카드 리더기처럼 플러그인에서 제공하는 결제 수단은 해당 플러그인이 사이트에 설치되고 활성화되어야 표에 표시됩니다. [결제 게이트웨이](../../payment/gateways/index.mdx)에서 POS가 지원하는 결제 수단과 각각의 설정 안내를 확인할 수 있습니다.

1. **결제 게이트웨이** 표에서 결제 수단을 찾으세요.
2. **활성화**를 켜세요.
3. POS를 새로고침하세요. 계산대는 시작할 때마다 결제 수단을 읽습니다.

이제 결제 화면에 해당 결제 수단이 타일로 표시됩니다. 자체 결제 페이지를 사용하는 결제 게이트웨이라면 [레거시 탭](../../pos/checkout/legacy-tab.mdx)에 표시됩니다.

### 맨 앞에 표시할 결제 수단 선택하기 {#reordering-gateways}

행의 핸들을 드래그하여 이동하세요. 계산대의 타일은 이 순서대로 표시되며, 새 판매에서 결제 화면을 열면 사용할 수 있는 첫 번째 타일이 미리 선택됩니다. 대부분의 판매에서 현금이 선택되게 하려면 현금을 맨 위로 드래그하세요. **기본값** 열은 선택되는 타일에 영향을 주지 않으며, 순서만 영향을 줍니다.

이 설정은 계산대의 결제 처리 창에 다음과 같이 반영됩니다.

<JourneyShot manifest={checkoutManifest} device="tablet" step={5} offsets={[[28, 42], [29, 42], [-55, 0], [66, 0], [-4, 0], [122, 0], [0, 0], [0, 0]]} alt="현금 판매의 결제 처리 창: 결제 및 레거시 탭, 잔액, 분할, 첫 번째인 현금이 선택된 현금 및 카드 타일, 빠른 금액 선택, 키패드, 받기 버튼">

1. **결제** 탭 — 켜 둔 결제 게이트웨이마다 타일이 표의 순서대로 표시됩니다.
2. **레거시** 탭 — 자체 결제 페이지를 사용하는 결제 게이트웨이가 표시됩니다. [레거시 탭](../../pos/checkout/legacy-tab.mdx)을 참고하세요.
3. **결제할 금액** — 아직 받아야 할 잔액입니다. 현금에 **반올림**이 설정되어 있으면 계산대에서 반올림한 금액을 요청합니다. [현금 반올림](../../payment/index.mdx#cash-rounding)을 참고하세요.
4. **분할** — 주문을 여러 번의 결제로 나눕니다.
5. **결제 수단 타일** — 각 타일에 결제 게이트웨이의 [POS 설정](#gateway-pos-settings)에 지정된 **제목**이 표시됩니다. 첫 번째 타일이 선택됩니다.
6. **빠른 금액 선택** — 정확한 금액 또는 지폐 단위로 올림한 금액을 선택합니다.
7. **키패드** — 고객이 건넨 금액을 입력합니다.
8. **받기** — 이번 결제를 기록합니다. 결제 금액이 합계를 충족하면 결제 절차가 끝나고 해당 결제 게이트웨이의 [주문 상태](#order-status)가 주문에 부여됩니다.

</JourneyShot>

캐셔가 이 화면을 사용하는 방법은 [결제 처리 창](../../pos/checkout/payment-methods.mdx)을 참고하세요.

### 타일 이름 변경 또는 현금 합계 반올림하기 {#gateway-pos-settings}

**⋮ > POS 설정**을 누르면 해당 결제 수단의 대화 상자가 열립니다. 여기에서 바꾼 내용은 계산대에만 반영되며 웹사이트에는 영향을 주지 않습니다.

- **제목** — 타일에 표시되는 이름입니다.
- **설명** — 결제 게이트웨이와 함께 저장됩니다. 계산대에는 표시되지 않으며, 타일에는 **제목**만 표시됩니다.
- **반올림** (현금만 해당) — 보유한 동전에 맞춰 현금 합계를 **0.05**, **0.10**, **0.25**, **0.50**, **1**, **5**, **10** 단위로 반올림합니다. 기본값은 **반올림 안 함**입니다. 카드 및 온라인 결제에는 정확한 금액이 유지됩니다. [현금 반올림](../../payment/index.mdx#cash-rounding)을 참고하세요.

변경 사항을 유지하려면 **저장**을 누르고, 취소하려면 **취소**를 누르세요.

**⋮ > WooCommerce 설정**을 누르면 WooCommerce에서 해당 결제 게이트웨이의 자체 설정이 열립니다. 여기에서 계정을 연결하고 웹사이트에 표시할 내용을 설정합니다.

### POS와 온라인 매장 {#pos-vs-online-store}

여기의 **활성화** 스위치는 WooCommerce 자체 결제 설정과 별개입니다. 결제 수단을 다음과 같이 설정할 수 있습니다.

- **POS에서는 켜고 온라인에서는 끄기** — 웹사이트에서 받을 수 없는 현금이 한 예입니다.
- **온라인에서는 켜고 POS에서는 끄기** — PayPal 결제처럼 고객이 컴퓨터를 사용해야 하는 결제 수단에 해당합니다.
- **양쪽 모두 켜기.**

:::note
결제 게이트웨이가 표에 표시되려면 해당 플러그인이 설치되고 활성화되어 있어야 합니다. `WP Admin > WooCommerce > 설정 > 결제`에서 켤 필요는 없습니다. POS에는 WooCommerce가 인식하는 모든 결제 게이트웨이가 표시됩니다. 누락된 항목이 있다면 해당 플러그인이 활성화되어 있는지 확인하세요.
:::

## 주문 상태 {#order-status}

각 결제 수단에는 결제 절차가 끝났을 때 주문에 부여할 **주문 상태**가 있습니다. **처리 중**과 **완료됨**은 주문을 결제된 것으로 표시하고, **보류 중**과 **결제 대기 중**은 미결제 상태로 둡니다. 대금을 받는 방식에 따라 선택하세요.

- **계산대에서 대금을 받는 경우:** **처리 중** 또는 **완료됨**.
- 결제 링크 없이 **고객이 직접 송금할 대금**: **보류 중**. BACS와 수표의 기본값입니다.
- **주문의 결제 링크를 통해 나중에 결제하는 경우**, 예를 들어 BACS를 이용한 ‘청구서로 결제’ 방식: **결제 대기 중**. 고객이 링크를 통해 결제할 때까지 주문은 미결제 상태로 유지됩니다.

변경 방법:

1. **결제 게이트웨이** 표에서 결제 수단을 찾으세요.
2. 해당 행의 **주문 상태** 열에서 상태를 선택하세요.

즉시 저장되며 새 판매에 적용됩니다. 이미 접수한 주문에는 적용되지 않습니다.

결제 절차가 끝났다고 대금을 받은 것은 아닙니다. 계산대에 기록된 결제 금액이 합계를 충족하면 결제 절차가 끝나고 주문에 이 상태가 부여됩니다. 따라서 **보류 중** 또는 **결제 대기 중**으로 설정된 주문은 계산대 처리는 끝났지만 여전히 미결제 상태입니다.

<details>
<summary>결제 링크 보내기</summary>

WooCommerce는 결제 대기 중인 주문을 결제 가능한 상태로 유지합니다. 결제 완료로 표시하지 않고 재고도 차감하지 않으며, 주문이 결제 대기 중인 동안 결제 링크가 작동합니다. POS에서는 링크를 보내지 않습니다. 주문에 고객 이메일이 있어야 하며, WooCommerce 주문 화면에서 청구서를 이메일로 보내거나 다른 방법으로 링크를 공유해야 합니다.

</details>

**현금**, **카드** 및 대부분의 결제 게이트웨이는 계산대에서 대금을 받으므로 기본 상태가 **완료됨**입니다. **BACS** (직접 은행 송금)와 **수표**는 나중에 대금이 들어오므로 기본 상태가 **보류 중**입니다. WooCommerce의 모든 주문 상태를 선택할 수 있습니다. 이전 POS 버전에서 모든 결제 게이트웨이에 하나의 상태를 설정했다면, 각 결제 게이트웨이는 그 상태를 기본값으로 사용합니다.

### 계산대에서 상태를 처리하는 방식 {#order-status-at-the-till}

계산대에 기록되는 결제는 현금, 카드, 카드 리더기, 직접 은행 송금 등의 타일로 받은 결제입니다. 이 금액이 합계를 충족하면 결제 게이트웨이에 선택한 상태가 주문에 부여됩니다.

<details>
<summary>분할 결제 판매와 레거시 탭의 결제 게이트웨이</summary>

- **분할 결제 판매**에는 결제 금액이 가장 큰 결제 게이트웨이의 상태가 부여됩니다. 금액이 같으면 그중 가장 먼저 결제한 결제 게이트웨이의 상태가 적용됩니다.
- **[레거시 탭](../../pos/checkout/legacy-tab.mdx)의 결제 게이트웨이**: 주문이 해당 상태에 도달하면 POS에서 판매를 마칩니다.

</details>

<details>
<summary>Email Invoice 결제 게이트웨이와 결제 대기 중 상태</summary>

**Email Invoice Gateway**는 직접 청구서를 보내고 **결제 대기 중**으로 설정하므로, 이 결제 게이트웨이의 **주문 상태**는 다른 상태로 두세요. **결제 대기 중**으로 설정하면 계산대에 **청구서 전송됨** 화면이 표시되지 않으며, 주문에 **다시 보내기**와 **청구서 취소**도 표시되지 않습니다. [이메일 청구서](../../payment/gateways/email-invoice.mdx#set-up)를 참고하세요.

</details>

## 초과 판매 방지 {#prevent-overselling}

**초과 판매 방지**는 POS에서 보유 재고보다 많은 수량을 판매하지 못하게 합니다. 새 매장에서는 **꺼져** 있으며, 켜기 전에는 계산대에서 장바구니에 있는 상품을 모두 판매할 수 있습니다. 켜는 방법:

1. `WP Admin > POS > 설정 > 결제`를 여세요.
2. **초과 판매 방지**를 켜고 **저장됨**이 표시될 때까지 기다리세요.
3. 각 계산대에서 POS를 새로고침하세요.

끌 때도 같은 방법을 사용합니다. 이월 주문을 허용하는 상품은 계속 판매할 수 있습니다. [이월 주문 설정이 우선](#prevent-overselling-backorders)을 참고하세요.

스위치를 켜면 계산대에서 보유 재고보다 많은 수량을 추가할 수 없고, 장바구니 항목의 재고가 부족하면 결제가 차단되며, 매장에서 매번 결제를 받기 전에 재고를 다시 확인합니다. 아직 진행 중인 판매를 저장하는 작업은 거부되지 않습니다.

<details>
<summary>세 단계의 재고 확인과 캐셔에게 표시되는 내용</summary>

1. **상품을 장바구니에 넣을 때.** 캐셔는 보유 재고를 초과하여 상품을 추가하거나 수량을 늘릴 수 없습니다. 계산대에 **후드 티 재고가 3개만 남아 있습니다** 또는 **후드 티 품절**이 표시되고 장바구니는 그대로 유지됩니다. 전체 메시지는 [품절 상품](../../pos/product-panel/display-settings.mdx#show-out-of-stock-products)을 참고하세요.
2. **판매가 장바구니에 있는 동안.** 다른 계산대에서 마지막 상품을 판매하는 등의 이유로 진행 중인 판매의 재고가 줄어들면, 장바구니 항목 위에 재고가 부족한 각 항목과 **수량 줄이기** 또는 **제거**가 안내로 표시됩니다. 항목에는 판매 가능한 수량이 표시되고, 장바구니를 수정할 때까지 **결제**가 비활성화됩니다. 결제 처리 창에서도 같은 방식으로 결제가 거부됩니다. [결제가 차단될 때](../../pos/cart/line-items.mdx#checkout-blocked)를 참고하세요.
3. **매장에서 결제를 받을 때.** 매장은 대금이 이동하기 전과 판매가 종료될 때 주문의 재고를 확인합니다. 계산대의 수량 정보가 오래된 경우 매장은 **주문을 완료할 수 없습니다: 1개 항목이 가용 재고를 초과합니다.** 메시지와 함께 결제를 거부하고, POS에 그 이유가 표시됩니다. [레거시 탭](../../pos/checkout/legacy-tab.mdx)에서는 매장의 결제 페이지에 이유가 표시됩니다. 오프라인 계산대에서 나중에 전송한 판매도 같은 방식으로 거부될 수 있습니다. [주문이 저장되지 않음 — 매장에서 거부함](../../support/store-health.mdx#order-refused)을 참고하세요.

매장은 저장만 하는 판매의 재고는 확인하지 않으므로, 진행 중인 판매는 제한 없이 동기화됩니다.

</details>

<details>
<summary>계산대뿐 아니라 매장에서도 확인하는 이유</summary>

WooCommerce는 POS가 주문을 보내는 방식인 REST API를 통해 주문이 들어오면 재고를 확인하지 않습니다. 바쁜 계산대 두 곳에서 동시에 판매하거나 계산대의 재고 정보가 오래되면 보유 수량을 초과해 판매할 수 있습니다. 매장의 재고 확인으로 계산대에서 파악하지 못한 상황을 감지합니다.

</details>

### 재고 한도가 결정되는 방식 {#prevent-overselling-stock-rules}

상품 단위로 재고를 관리하는지, 각 변형 단위로 관리하는지에 따라 한도가 결정됩니다.

<details>
<summary>상품 설정별 재고 규칙</summary>

| 상품 설정 | 스위치를 켰을 때 |
|---|---|
| **재고 관리** (수량을 추적함) | 재고 수량까지만 판매할 수 있습니다. 같은 상품이 여러 항목에 있으면 같은 한도에 합산됩니다. |
| **변형이 자체 재고를 관리함** | 변형별로 한도가 적용됩니다. |
| **변형이 상위 상품의 재고를 사용함** | 상품의 모든 변형이 상위 상품의 수량을 공유합니다. |
| **재고를 관리하지 않음** | 재고 상태에 따라 결정됩니다. **품절**이면 판매할 수 없고, **재고 있음**과 **이월 주문 중**이면 판매할 수 있습니다. |

</details>

### 이월 주문 설정이 우선 {#prevent-overselling-backorders}

WooCommerce에서 상품별로 지정한 **이월 주문을 허용하시겠습니까?** 설정이 우선합니다. 스위치가 켜져 있어도 일부 상품은 재고가 없어도 판매할 수 있도록 이 설정을 사용하세요.

- **허용하지 않음** — 재고가 소진되면 판매가 중단됩니다.
- **허용** — 재고가 음수가 되더라도 항상 판매할 수 있습니다.
- **허용하되 고객에게 알림** — 항상 판매할 수 있습니다. 판매 수량이 재고를 초과하면 계산대에 **후드 티는 이월 주문으로 처리됩니다**가 표시됩니다.

이월 주문 상품 때문에 결제가 차단되지는 않습니다.

### 초과 판매 방지와 ‘품절 상품 표시’ {#prevent-overselling-vs-display}

두 설정의 역할은 서로 다릅니다.

- **초과 판매 방지** (이 페이지)는 상품을 장바구니에 넣을 때, 판매가 진행 중일 때, 매번 결제를 받기 전에 수량을 확인합니다. 매장의 모든 계산대에 적용됩니다.
- **품절 상품 표시**는 각 기기의 상품 패널에 있는 설정입니다. 끄면 재고가 없는 상품이 숨겨지고 해당 상품을 스캔해도 추가되지 않습니다. 켜면 목록에 남아 있지만 회색으로 비활성화되고 **품절**로 표시됩니다. [품절 상품](../../pos/product-panel/display-settings.mdx#show-out-of-stock-products)을 참고하세요.

초과 판매 방지를 꺼도 상품 패널에 표시되는 내용은 달라지지 않습니다.

:::note
계산대는 POS를 시작할 때 매장 정보와 함께 초과 판매 방지 설정을 가져옵니다. 매장 자체에서 매번 결제 전에 수행하는 확인은 즉시 적용되며, 아직 새로고침하지 않은 계산대에도 적용됩니다.
:::

## 이메일 알림 {#email-notifications}

세 개의 스위치로 POS 주문에서 보낼 WooCommerce 이메일을 선택합니다. 웹사이트 자체 이메일 설정과는 별개입니다.

- **관리자 이메일** — WooCommerce에 설정된 수신자에게 **새 주문**, **취소된 주문**, **실패한 주문**을 보냅니다. 기본적으로 켜져 있습니다.
- **고객 이메일** — 고객에게 **보류 중인 주문**, **처리 중인 주문**, **완료된 주문**, **환불된 주문**, **실패한 주문**을 보냅니다. 기본적으로 켜져 있습니다.
- **캐셔 이메일** — 판매를 처리한 캐셔에게 **새 주문**을 보냅니다. 기본적으로 꺼져 있습니다.

그룹을 켜면 해당 이메일이 체크박스로 표시되며, 처음에는 모두 선택되어 있습니다. 원하지 않는 항목은 선택을 해제하세요. 각 이메일의 발송 시점, 수신자 및 일반적인 설정은 [이메일 알림](./email-notifications.mdx)을 참고하세요.

## 주문 저장 방식 {#order-storage}

화면 상단에 주문 저장 방식에 관한 경고가 있으면 [주문 저장 방식](../../support/performance/order-storage.mdx)에 따라 매장을 WooCommerce의 고성능 주문 저장소로 전환하세요. 이미 사용 중인 매장에는 경고가 표시되지 않습니다.

<details>
<summary>주문 저장 방식 경고 알아보기</summary>

**이 매장은 기존 주문 저장 방식을 사용하므로 상품 카탈로그와 주문 내역이 늘어날수록 WCPOS의 결제가 느려집니다. 고성능 주문 저장소로 전환할 것을 강력히 권장합니다.** 라는 메시지가 표시됩니다. 이 경고는 닫을 수 없습니다. 아래의 **WooCommerce 주문 저장 설정 열기**를 누르면 설정으로 이동하고, **전환 방법**을 누르면 같은 안내가 열립니다.

</details>

## 문제가 발생한 경우 {#goes-wrong}

**결제 수단이 표에 없습니다.** 해당 플러그인이 설치되지 않았거나 활성화되지 않았습니다. 활성화한 후 이 화면을 새로고침하세요.

**활성화 스위치가 비활성화되어 있습니다.** 매장에서 현금과 카드만 제공하는 무료 버전을 사용하고 있습니다. [WCPOS Pro](../../getting-started/pro-license.mdx)를 참고하세요.

**결제 수단을 켰지만 결제 화면에 없습니다.** POS를 새로고침하세요. 그런 다음 [레거시 탭](../../pos/checkout/legacy-tab.mdx)을 확인하세요. 자체 결제 페이지를 사용하는 결제 게이트웨이는 타일이 아닌 해당 탭에 있습니다.

**결제 화면을 열면 원하지 않는 타일이 선택됩니다.** 계산대는 표의 순서대로 사용할 수 있는 첫 번째 타일을 선택합니다. 원하는 결제 수단을 맨 위로 드래그하세요. **기본값** 열은 영향을 주지 않습니다.

**은행 송금으로 결제한 주문이 보류 중으로 표시됩니다.** 대금이 나중에 들어오는 BACS와 수표의 기본값입니다. 입금되면 `WP Admin > WooCommerce > Orders`에서 해당 주문의 상태를 변경하세요. 앞으로 이 방식으로 결제하는 모든 판매에서 대금을 이미 받게 되는 경우에만 여기에서 결제 게이트웨이의 **주문 상태**를 변경하세요. 이 설정은 새 판매에만 적용되며 이미 접수한 주문에는 적용되지 않습니다.

**계산대에서 보유 재고보다 많이 판매했습니다.** **초과 판매 방지**가 꺼져 있거나 상품에서 이월 주문을 허용하고 있습니다. [이월 주문 설정이 우선](#prevent-overselling-backorders)을 참고하세요.
