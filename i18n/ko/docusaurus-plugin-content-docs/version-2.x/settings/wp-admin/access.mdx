POS를 사용할 수 있는 사람과 POS에서 할 수 있는 일은 WordPress 역할별로 설정합니다. 각 계정은 해당 역할의 권한을 받으므로 캐셔마다 따로 바꿀 필요 없이 한 번의 변경으로 모든 캐셔에게 적용할 수 있습니다. WCPOS는 계산대 직원을 위한 **캐셔** 역할을 추가합니다. 관리자는 WordPress에서, 상점 관리자는 WooCommerce에서 제공하는 역할입니다.

## 역할별로 할 수 있는 일 변경 {#change-a-role}

:::warning POS 사용 또는 주문 관리를 끄면 로그인할 수 없습니다
**POS 사용** 권한이 없거나 **주문 관리** 권한이 제거되면 POS는 로그인을 거부하고 부족한 권한을 알려 줍니다. [문제가 발생한 경우](#goes-wrong)를 참조하세요.
:::

**접근 권한 화면을 열 수 있는 사람:** WP Admin의 **POS** 메뉴 전체에는 **POS 설정 관리** 권한이 필요합니다. 관리자와 상점 관리자에게는 이 권한이 있지만 캐셔에게는 없습니다. 접근 권한 화면을 열 수 없거나 변경 사항이 저장되지 않으면 사이트 관리자에게 문의하세요.

1. **WP Admin > POS > 설정**으로 이동한 다음 사이드바에서 **접근 권한**을 선택하세요. POS 내부의 **설정** 화면과는 다릅니다. POS 내부 설정에는 [이 기기의 환경설정](../index.mdx)만 있으며, 모든 POS 사용자가 열 수 있습니다.
2. 왼쪽 역할 목록에서 역할을 선택하세요. 처음에는 관리자가 선택되어 있습니다. 주황색 점이 있는 역할은 WCPOS 기본값에서 변경된 상태입니다.
3. **캐셔가 할 수 있는 일** 아래에서 작업을 선택하면 권한을 부여하고 선택을 해제하면 권한을 제거합니다. 제목에는 선택한 역할의 이름이 표시됩니다.
4. 저장 버튼은 없습니다. 선택 상태를 바꿀 때마다 바로 저장됩니다. **저장 중**이 표시된 다음 **저장됨**으로 바뀝니다. 매장에서 변경을 거부하면 체크박스가 이전 상태로 돌아가고 안내에 이유가 표시됩니다.
5. 해당 역할로 로그인한 사용자에게 POS에서 로그아웃한 뒤 다시 로그인하도록 요청하세요. 그래야 POS가 새 권한을 반영합니다. 매장에서는 권한이 즉시 적용됩니다.

<details>
<summary>변경 사항을 저장하는 데 필요한 권한</summary>

저장하려면 **POS 설정 관리** 외에도 WordPress 권한인 `edit_users`와 `promote_users`가 필요합니다. 단일 WordPress 사이트에서는 관리자에게 두 권한이 모두 있습니다.

</details>

### 작업과 캐셔 기본값 {#tasks}

각 작업이 역할에 허용하는 일을 새로 설치했을 때 캐셔 역할에 부여되는 권한에 따라 나누어 설명합니다.

**캐셔에게 기본적으로 허용되는 작업:**

- **POS 사용**: POS에 로그인하여 판매합니다.
- **상품 생성 및 편집**: 상품을 추가하고 이름, 가격, 재고, 바코드, 원가를 변경합니다. 상품 옵션도 포함됩니다.
- **쿠폰 생성 및 편집**: 쿠폰을 추가하고 코드, 금액, 만료일, 설명을 변경합니다(WCPOS Pro).
- **주문 관리**: 주문을 저장하고 다시 열어 변경합니다. 다른 캐셔가 접수한 주문과 온라인 쇼핑몰 주문도 포함됩니다.
- **고객 관리**: 고객을 찾고 새 고객을 추가하며 고객 정보를 변경합니다.
- **카테고리 및 태그 관리**: 상품 카테고리와 태그를 추가하고 변경합니다.

**캐셔에게 기본적으로 허용되지 않는 작업:**

- **POS 설정 관리**: WP Admin의 **POS** 메뉴를 엽니다. 현재 화면, 영수증 템플릿, 매장 로그가 포함됩니다.
- **상품 삭제**: 상품과 상품 옵션을 삭제합니다.
- **쿠폰 삭제**: 쿠폰을 삭제합니다(WCPOS Pro).

관리자와 상점 관리자는 처음부터 모든 POS 권한을 갖습니다. 이 역할들의 상품, 주문, 고객 작업에는 WooCommerce와 WordPress가 부여한 권한이 표시되며 WCPOS는 이를 변경하지 않습니다.

## 기본 역할별로 할 수 있는 일 한눈에 보기 {#what-each-default-role-can-do-at-a-glance}

- **관리자**: POS와 WP Admin에서 모든 작업을 수행합니다.
- **상점 관리자**: WP Admin의 **POS** 메뉴, 계산대 권한, WooCommerce가 상점 관리자에게 허용하는 상품, 주문, 고객 관련 작업을 수행합니다. POS 확장 기능 설치는 제외되며, 이 작업에는 플러그인 설치 권한이 필요합니다.
- **캐셔**: 판매하고 상품, 쿠폰, 주문, 고객을 생성 및 편집하며 금전등록기를 열고 현금을 세고 마감합니다. 삭제, POS 설정, 금액 차이가 발생한 정산 승인은 할 수 없습니다.

각 역할이 매장에 보낼 수 있는 요청은 [역할별 엔드포인트 접근 권한](../../reference/role-endpoint-access.mdx)을 참조하세요.

## 캐셔에게 ‘권한이 없습니다’가 표시되는 경우 {#no-permission-hint}

WCPOS Pro에서는 상품, 쿠폰, 고객 화면과 장바구니의 **새 쿠폰**, **새 고객 추가** 버튼에 캐셔의 역할이 적용됩니다. 해당 역할에서 사용할 수 없는 항목은 회색으로 비활성화되고, 도움말에 누가 권한을 부여할 수 있는지 표시됩니다.

> 쿠폰을 생성할 권한이 없습니다. 관리자가 WP Admin > POS > 설정 > 접근 권한에서 권한을 부여할 수 있습니다.

각 안내에는 캐셔 역할에 대해 선택해야 할 작업이 표시됩니다.

- ‘**쿠폰 생성** 권한이 없습니다’ 또는 ‘**쿠폰 편집** 권한이 없습니다’: **쿠폰 생성 및 편집**을 선택하세요.
- ‘**상품 편집** 권한이 없습니다’ 또는 ‘**상품 옵션 편집** 권한이 없습니다’: **상품 생성 및 편집**을 선택하세요.
- ‘**고객 생성** 권한이 없습니다’ 또는 ‘**고객 편집** 권한이 없습니다’: **고객 관리**를 선택하세요.

Pro가 없으면 같은 항목에 **Pro로 업그레이드**가 표시됩니다. 화면에 무엇이 표시되든 매장은 모든 변경 사항을 다시 확인합니다. 매장에서 거부한 상품, 쿠폰, 고객 변경 사항은 기기에서도 되돌려지며, **매장 상태 > 로그**에 **매장에서 거부한 변경 사항을 되돌렸습니다**로 기록됩니다.

장바구니의 **새 쿠폰**은 **할인 추가** 대화 상자에서 **쿠폰** 필드 옆에 있는 **+** 버튼입니다. 역할에 따라 사용 여부가 달라지는 것은 이 버튼뿐이며, 기존 쿠폰을 선택하고 적용하는 데는 **POS 사용** 권한만 있으면 됩니다.

7. **적용** — 장바구니에 쿠폰을 적용합니다. 쿠폰 권한은 필요하지 않습니다. [쿠폰 적용](../../coupons/applying-coupons.mdx)을 참조하세요.

## 계산대 권한 {#till-permissions}

금전등록기에는 별도의 권한 네 가지가 있습니다. 작업 항목에 속하지 않으므로 접근 권한 화면 맨 아래의 **고급**을 열어 변경하세요. 해당 화면에서 사용하는 이름은 아래 목록의 **고급에서 찾을 권한 이름**을 열어 확인하세요. 각 권한을 기본으로 갖는 역할은 기울임꼴로 표시되어 있습니다.

- **계산대 운영**: 금전등록기를 열고, 입금, 출금, 판매 없는 열기를 기록하며, 현금을 세고 마감합니다. *캐셔, 상점 관리자, 관리자.*
- **계산대 금액 조회**: 예상 현금, X 보고서, 인쇄된 마감 내역, 보고서를 확인합니다. 이 권한이 없으면 캐셔는 **예상 금액을 보지 않고** 현금을 셉니다. 화면에 예상 현금과 차액이 표시되지 않으며 마감 내역을 인쇄할 수 없습니다. *캐셔, 상점 관리자, 관리자.*
- **마감 승인**: 차액이 한도를 초과한 정산을 승인하고 마감한 현금을 다시 셉니다. 승인자는 금전등록기를 연 캐셔 및 마감하는 캐셔와 다른 사람이어야 합니다. *상점 관리자, 관리자.*
- **판매 담당자 재지정**: 판매가 완료된 후 해당 판매의 캐셔를 변경하기 위해 마련된 권한입니다. POS는 아직 이 기능을 제공하지 않으므로 현재는 변경해도 아무 효과가 없습니다. *상점 관리자, 관리자.*

<details>
<summary>고급에서 찾을 권한 이름</summary>

**고급**의 **WCPOS** 아래에는 이 네 가지가 권한 이름으로 표시됩니다.

- 계산대 운영: `manage_woocommerce_pos_cash`
- 계산대 금액 조회: `view_woocommerce_pos_reports`
- 마감 승인: `manage_woocommerce_pos_closures`
- 판매 담당자 재지정: `reassign_woocommerce_pos_sales`

</details>

한도는 [금전등록기](./registers.mdx#one-register)의 **정산 차액이 다음 금액을 초과하면 관리자에게 요청**에서 설정합니다. 현금을 세는 절차는 [금전등록기 열기](../../pos/register/index.mdx#close)를 참조하세요.

## 일부만 부여된 작업과 기본값 복원 {#restore-defaults}

**체크박스에 가로줄과 ‘7개 중 3개’ 같은 배지가 표시되는 경우:** 해당 역할에는 그 작업의 권한 중 일부만 있습니다. 체크박스를 선택하면 작업 전체를 부여하고, 선택을 해제하면 제거합니다.

**역할을 새로 설치했을 때의 상태로 되돌리려면:** 역할을 선택하고 제목 아래의 **기본값 복원**을 누른 다음, 대화 상자에서 변경 목록을 확인하고 **기본값 복원**을 다시 누르세요. 역할이 기본값과 일치하는 동안에는 버튼이 회색으로 비활성화됩니다.

:::warning 기본값을 복원하면 다른 플러그인이 부여한 권한이 제거될 수 있습니다
복원 시 WCPOS가 설정하는 권한만 변경됩니다. 캐셔의 경우 접근 권한 화면에 나열된 모든 권한이, 다른 역할의 경우 **고급**의 **WCPOS** 아래에 있는 여섯 가지 권한만 변경됩니다. 역할의 나머지 권한은 그대로 유지되지만, 복원 대상 권한은 다른 플러그인이 부여했더라도 WCPOS 기본값으로 돌아갑니다.
:::

<details>
<summary>일부만 부여된 작업의 작동 방식</summary>

각 작업은 여러 권한의 묶음입니다. 역할에 일부 권한만 있으면 체크박스에 가로줄이 표시되고 작업 옆에 **7개 중 3개** 같은 배지가 나타납니다. 배지에 포인터를 올려 의미를 확인하거나 **검토**를 눌러 **고급**을 열고 어떤 권한이 없는지 확인하세요. 가로줄이 표시된 체크박스를 선택하면 나머지 권한을 부여하고, 선택을 해제하면 해당 묶음 전체를 제거합니다.

</details>

<details>
<summary>기본값 복원 시 역할별 변경 사항</summary>

역할 제목 아래의 **WCPOS 기본값 사용 중** 또는 **WCPOS 기본값에서 변경됨**은 해당 역할이 새로 설치했을 때의 상태와 일치하는지 알려 줍니다. 실제로 변경하기 전에 **캐셔의 기본 권한을 복원할까요?** 대화 상자의 **변경될 내용** 아래에 **부여**, **제거**, **유지**할 작업과 **고급**에서 변경할 권한이 차례로 표시됩니다. **기본값 복원**을 눌러 확인하거나 **취소**를 누르세요.

- **캐셔**: 위의 작업 목록과 계산대 권한에 설명된, WCPOS가 설치할 때 설정하는 전체 권한입니다.
- **관리자** 및 **상점 관리자**: POS 권한만 복원합니다. WCPOS는 이 역할들의 WooCommerce나 WordPress 권한을 관리하지 않습니다.
- **그 외 모든 역할**: POS 접근 권한이 없는 상태로 돌아갑니다. 이 경우 대화 상자 제목은 **…의 POS 권한을 제거할까요?** 입니다.

</details>

<details>
<summary>플러그인을 다시 활성화하거나 업데이트할 때의 권한 변경</summary>

WCPOS 플러그인을 비활성화했다가 다시 활성화하면 관리자, 상점 관리자, 캐셔에게 모든 기본 권한을 다시 부여합니다. **상품 삭제**처럼 직접 추가한 권한은 제거하지 않습니다. 플러그인 업데이트는 해당 릴리스에서 새로 추가된 권한만 부여하므로 꺼 둔 작업은 계속 꺼진 상태로 유지됩니다. 예외는 1.10.17 이하 버전에서 처음 업데이트할 때입니다. 이때는 다시 활성화할 때와 마찬가지로 모든 기본 권한을 한 번 다시 부여합니다.

</details>

<details>
<summary>접근 권한 화면의 모든 권한</summary>

**고급**은 각 권한을 **WCPOS**, **WooCommerce**, **WordPress**로 나누어 표시합니다. 작업 단위로 설정하기에 적합하지 않을 때만 권한을 하나씩 변경하세요.

| 권한 | 작업 | POS에서 하는 일 |
| --- | --- | --- |
| `access_woocommerce_pos` | POS 사용 | POS에 로그인하여 사용합니다. 이 권한이 없으면 POS가 로그인을 거부합니다. |
| `manage_woocommerce_pos` | POS 설정 관리 | WP Admin의 **POS** 메뉴와 설정을 사용합니다. 관리자는 항상 이 권한을 유지합니다. |
| `manage_woocommerce_pos_cash`, `view_woocommerce_pos_reports`, `manage_woocommerce_pos_closures`, `reassign_woocommerce_pos_sales` | 없음 | [계산대 권한](#till-permissions)을 참조하세요. |
| `edit_products`, `edit_others_products`, `edit_published_products` | 상품 생성 및 편집 | 상품을 변경합니다. |
| `edit_product` | 상품 생성 및 편집 | 상품 옵션을 변경합니다. |
| `publish_products`, `edit_private_products` | 상품 생성 및 편집 | 상품을 추가하고 비공개 상품을 변경합니다. |
| `read_private_products` | 상품 생성 및 편집 | 상품 목록을 불러옵니다. 이 권한이 없으면 비공개 상품뿐 아니라 모든 상품을 불러올 수 없습니다. |
| `delete_product`, `delete_products`, `delete_others_products`, `delete_private_products`, `delete_published_products` | 상품 삭제 | 상품과 상품 옵션을 삭제합니다. |
| `edit_shop_coupons`, `edit_others_shop_coupons`, `edit_private_shop_coupons`, `edit_published_shop_coupons`, `publish_shop_coupons` | 쿠폰 생성 및 편집 | 쿠폰을 추가하고 변경합니다. |
| `read_private_shop_coupons` | 쿠폰 생성 및 편집 | WooCommerce 권한 묶음의 일부입니다. POS는 **POS 사용** 권한만으로 쿠폰을 읽으므로 이 권한을 꺼도 쿠폰이 숨겨지지 않습니다. |
| `delete_shop_coupons`, `delete_others_shop_coupons`, `delete_private_shop_coupons`, `delete_published_shop_coupons` | 쿠폰 삭제 | 쿠폰을 삭제합니다. |
| `publish_shop_orders` | 주문 관리 | 새 주문을 저장합니다. 이 권한이 없으면 POS가 로그인을 거부합니다. |
| `read_private_shop_orders` | 주문 관리 | 주문을 불러옵니다. |
| `edit_shop_orders` | 주문 관리 | 주문을 변경합니다. |
| `edit_others_shop_orders` | 주문 관리 | 다른 캐셔가 접수한 주문과 온라인 쇼핑몰 주문을 변경합니다. |
| `list_users` | 고객 관리 | 고객을 찾습니다. 이 권한이 없으면 고객 목록이 비어 있습니다. |
| `edit_users` | 고객 관리 | 고객 정보를 변경합니다. |
| `create_customers` (WooCommerce 9.9 이상) 또는 `promote_users` (이전 버전) | 고객 관리 | 새 고객을 추가합니다. |
| `manage_product_terms` | 카테고리 및 태그 관리 | 카테고리와 태그를 추가하고 변경합니다. |
| `read` | 없음 | WordPress 알림판과 사용자 본인의 프로필에 접근합니다. 관리자는 항상 이 권한을 유지합니다. |

</details>

## 고객 목록의 직원 계정 {#staff-accounts}

어떤 계정이든 주문의 고객이 될 수 있으므로 POS 고객 목록에는 직원을 포함한 모든 WordPress 사용자가 표시됩니다. 계정을 변경할 수 있는 범위는 검색할 수 있는 범위보다 좁습니다. **고객 관리** 설정과 관계없이 POS에서 직원 계정을 편집하거나 삭제할 수 있는 사람은 관리자뿐입니다. 다른 사용자에게는 **관리자만 POS에서 직원 계정을 편집하거나 삭제할 수 있습니다.** 라는 메시지가 표시됩니다. 모든 사용자는 여전히 본인 계정을 편집할 수 있습니다.

직원에는 관리자, 상점 관리자, 캐셔, 편집자, 글쓴이, 기여자가 포함됩니다.

<details>
<summary>직원 계정 판별 방식</summary>

계정에 `manage_options`, `manage_woocommerce`, `edit_users`, `edit_posts` 중 하나라도 있으면 직원으로 간주합니다. 이 권한 중 하나가 있는 사용자 지정 역할도 직원으로 간주합니다.

</details>

## 역할이 여러 개인 사용자 {#more-than-one-role}

**증상:** 관리자와 고객처럼 역할이 두 개인 사용자가 어느 한 역할에서 부여하는 권한을 거부당합니다.

**해결 방법:** 계정에서 추가 역할을 제거하거나(**사용자 > 모든 사용자**에서 계정 편집), 역할 편집기에서 해당 역할을 열어 *거부* 표시를 해제하세요. 그런 다음 사용자가 다시 로그인하면 됩니다.

<details>
<summary>두 번째 역할로 인해 권한이 사라질 수 있는 이유</summary>

계정 하나에 여러 역할을 부여할 수 있으며, 보통 Members 같은 역할 편집 플러그인으로 설정합니다. WordPress는 각 역할이 부여하는 권한을 합치므로 두 번째 역할 자체가 권한을 없애는 경우는 드뭅니다. 하지만 역할 편집기의 *거부*는 다릅니다. 한 역할에서 거부한 권한이 다른 역할에서 부여한 권한보다 우선할 수 있으며, Members는 거부를 먼저 적용합니다. 고객 역할도 가진 관리자는 고객 역할이 거부하는 권한을 잃을 수 있습니다.

접근 권한 화면에는 각 역할 자체의 선택 상태가 표시됩니다. *거부*는 해당 역할에서 선택되지 않은 체크박스로만 나타나므로 ‘부여되지 않음’과 똑같아 보입니다. 그 체크박스를 선택하면 거부를 덮어쓰고 권한을 부여합니다.

</details>

## 문제가 발생한 경우 {#goes-wrong}

**‘이 계정은 POS를 사용할 수 없습니다. 부족한 권한: …’** 역할에 **POS 사용** 또는 **주문 관리** 권한이 없어 POS가 로그인을 거부합니다. 사용자 역할에서 해당 작업을 선택하세요. 역할이 두 개 이상이면 [역할이 여러 개인 사용자](#more-than-one-role)를 참조하세요.

<details>
<summary>역할이 하나일 때와 여러 개일 때의 전체 메시지</summary>

메시지는 **주문 관리**의 `publish_shop_orders`처럼 부족한 권한을 나열합니다. 역할이 하나면 WCPOS 설정의 접근 권한에서 권한을 부여하거나 필요한 권한을 가진 역할을 지정하라고 안내합니다. 역할이 두 개 이상인 계정에는 다음과 같은 메시지가 표시됩니다.

> 이 계정은 POS를 사용할 수 없습니다. 부족한 권한: publish_shop_orders, read_private_products, read_private_shop_orders, list_users. 이 계정의 역할은 고객, 관리자입니다. 한 역할에서 거부한 권한이 다른 역할에서 부여한 권한보다 우선할 수 있으며, Members 같은 역할 편집 플러그인은 거부를 먼저 적용합니다. 추가 역할을 제거하거나 역할 편집기에서 거부를 해제하세요.

</details>

**캐셔가 로그인했지만 상품, 고객, 주문이 불러와지지 않습니다.** 캐셔 역할에서 **상품 생성 및 편집**, **고객 관리**, **주문 관리**를 다시 선택하거나 두 번째 역할에 *거부*가 있는지 확인하세요.

<details>
<summary>화면이 비어 있는 이유</summary>

역할에 `read_private_products`, `list_users`, `read_private_shop_orders` 중 필요한 권한이 없습니다. 이 권한들은 로그인을 막지 않으므로 대신 각 화면이 비어 있게 됩니다. **매장 상태 > 로그**의 계산대 로그에는 거부된 각 요청이 [AUTH201](../../error-codes/AUTH201.mdx)로 기록됩니다.

</details>

**꺼 둔 캐셔 권한이 다시 생겼습니다.** 누군가 플러그인을 비활성화했다가 다시 활성화했거나 매장이 1.10.17 이하 버전에서 업데이트되었습니다. 두 경우 모두 기본 권한이 다시 부여됩니다. 해당 작업의 선택을 다시 해제하세요.

**관리자의 선택을 해제할 수 없습니다.** 관리자는 항상 **POS 설정 관리**와 `read`를 유지하므로 실수로 자신의 화면 접근 권한을 잃지 않습니다.

:::info WCPOS Pro 사용 시
Pro는 매장 기능을 추가합니다. 매장의 **직원** 목록에는 역할을 통해서든 개인에게 직접 부여되어서든 **POS 사용** 권한이 있는 모든 사람이 표시되며, 매장을 편집하려면 **POS 설정 관리** 권한이 필요합니다. [매장 설정](../../stores/setup.mdx#staff)을 참조하세요. 상품, 쿠폰, 고객 화면에서 데이터를 변경하려면 Pro가 있어야 합니다.
:::
