**WP 관리자:** `WP Admin → POS → Settings → Sessions`.

**세션**에는 POS에 로그인한 사용자와 기기가 표시됩니다. 따라서 기기를 직접 조작하지 않고도 분실한 태블릿이나 퇴사한 캐셔를 로그아웃할 수 있습니다.

**WP Admin > POS > 설정 > 세션**에서 여세요. 관리자와 상점 관리자가 사용할 수 있습니다. 상점 관리자는 관리자를 제외한 모든 사용자의 세션을 볼 수 있습니다.

<details>
<summary>세션이란</summary>

사용자가 POS에 로그인할 때마다 매장은 해당 기기의 세션을 보관합니다. 데스크톱 앱에서는 로그인할 때마다 하나씩, 브라우저의 POS에서는 보통 브라우저마다 하나씩 생성됩니다.

</details>

## 사용자의 기기 찾기 {#find}

화면은 두 열로 구성됩니다.

- **왼쪽에는 사용자가 표시됩니다.** 관리할 수 있는 세션이 하나 이상 있는 모든 사용자입니다. 본인은 **나** 칩과 함께 맨 위에 표시되고, 나머지 사용자는 최근 활동순으로 표시됩니다. 각 행의 숫자는 해당 사용자의 세션 수이며, 녹색 점은 **현재 활동 중**을 뜻합니다. 점이 없어도 계산대가 사용 중일 수 있습니다([마지막 활동](#card) 참고). **사용자 필터**에 입력하여 이름이나 사용자명으로 검색하세요.
- **오른쪽에는 해당 사용자의 세션이 표시됩니다.** 사용자를 선택하면 이름, 사용자명, 세션 수, **모두 로그아웃** 버튼 및 기기별 카드가 최근 순으로 표시됩니다. 각 카드의 내용은 [세션 카드 읽기](#card)에서 설명합니다.

## 기기 로그아웃 {#signing-devices-out}

:::warning 세션을 종료해도 비밀번호는 바뀌지 않습니다
비밀번호를 아는 사람은 바로 다시 로그인할 수 있습니다.

- **퇴사한 캐셔:** [접근 권한](./access.mdx)에서 POS 접근 권한도 제거하거나 비밀번호를 변경하세요.
- **분실하거나 도난당한 기기:** 해당 기기에 로그인했던 모든 사용자의 비밀번호를 변경하세요.
:::

녹색 점이나 **마지막 활동**만으로는 계산대가 사용 중이 아닌지 알 수 없습니다. 로그아웃하기 전에 해당 사용자에게 확인하세요.

### 기기 하나 로그아웃 {#one-device}

1. 왼쪽에서 사용자를 선택하세요.
2. **애플리케이션**, **IP**, **생성 시각**으로 기기를 찾으세요.
3. 카드에서 **종료**를 누르세요. **세션을 종료할까요?** 라는 확인 메시지가 표시됩니다. **종료**를 누르세요.

**세션이 정상적으로 종료되었습니다**라는 메시지가 표시되고 세션이 목록에서 사라집니다.

### 사용자의 모든 기기 로그아웃 {#all-devices}

1. 왼쪽에서 사용자를 선택하세요.
2. **모두 로그아웃**을 누르세요. **모든 세션을 종료할까요?** 라는 확인 메시지가 표시됩니다. **모두 로그아웃**을 누르세요.

**세션들이 정상적으로 종료되었습니다**라는 메시지가 표시되고 해당 사용자의 세션이 목록에서 사라집니다.

<details>
<summary>비밀번호를 변경하면</summary>

해당 사용자의 모든 기기에 있는 POS 세션이 즉시 종료되며, 이전 비밀번호로 다시 로그인할 수 없게 됩니다. 다른 기기에서도 새 비밀번호로 다시 로그인해야 합니다.

</details>

### 기기에서 일어나는 일 {#on-the-device}

기기의 로그인이 즉시 취소됩니다. 다음에 POS가 매장에 연결되면 로그인 유효기간이 끝났을 때와 마찬가지로 WordPress 로그인 창이 열리고 **세션 만료**가 표시됩니다. [AUTH101](../../error-codes/AUTH101.mdx)을 참고하세요.

기기의 데이터는 삭제되지 않습니다. 매장으로 전송되지 않은 판매 내역은 기기에서 대기하다가 누군가 다시 로그인하면 전송됩니다. 연결 화면의 해당 사용자 행에는 **다시 로그인**이 표시됩니다. [매장 연결](../../getting-started/connect.mdx#multiple-users-per-store)을 참고하세요.

여기에서 본인의 세션을 종료하면 POS에서 로그아웃되며, WP Admin에서는 로그아웃되지 않습니다.

## 세션 카드 읽기 {#card}

다음 세 필드로 기기를 구분할 수 있습니다:

- **애플리케이션:** 사용자가 로그인한 앱의 종류와 버전으로, **iOS 애플리케이션**, **Android 애플리케이션**, **데스크톱 애플리케이션** 또는 **웹 애플리케이션**입니다. 그 아래에는 브라우저와 운영체제가 표시됩니다.
- **IP:** 기기가 로그인한 인터넷 주소이며, 없으면 _해당 없음_으로 표시됩니다.
- **생성 시각:** 사용자가 해당 기기에서 로그인한 시각입니다.

**마지막 활동**은 기기가 마지막으로 로그인하거나 로그인을 갱신한 시각으로, _방금_, _5분 전_, _3시간 전_처럼 표시됩니다. 사용 중인 POS는 약 30분마다 갱신합니다.

**현재 활동 중:** 이 표시가 없어도 계산대가 사용 중일 수 있습니다. 녹색 점은 사용자가 최근 5분 이내에 로그인하거나 로그인을 갱신했다는 뜻입니다.

<details>
<summary>추가 세션 정보: 만료 시각 및 사용자 에이전트</summary>

- **만료 시각**은 로그인 유효기간이 끝나 사용자가 다시 로그인해야 하는 시각으로, **생성 시각**으로부터 30일 후입니다. POS를 사용해도 연장되지 않습니다.
- **사용자 에이전트**: 누르면 기기가 전송한 원문을 볼 수 있습니다. 지원팀에서 이 정보를 요청할 수 있습니다.

</details>

## 세션이 종료되는 다른 경우 {#other-ways}

세션을 직접 삭제할 필요는 없습니다. 다음 경우에도 세션이 종료됩니다:

- 로그인 후 30일이 지나 **만료 시각**에 도달한 경우.
- 사용자의 비밀번호가 변경되거나 재설정된 경우. 해당 사용자의 모든 POS 세션이 종료됩니다.
- 사용자가 브라우저에서 WordPress를 로그아웃한 경우. 해당 브라우저의 POS 세션이 종료되며, 다른 기기는 로그인 상태를 유지합니다.

<details>
<summary>개발자 참고: 세션 기간 및 세션 수 제한</summary>

30일은 `wcpos_jwt_refresh_token_expire` 필터에서, 30분 갱신 주기는 `wcpos_jwt_access_token_expire`에서 정해집니다. [토큰 만료 적용 범위](../../reference/role-endpoint-access.mdx#token-expiry-coverage)를 참고하세요.

사용자 한 명은 최대 200개의 세션을 보유할 수 있습니다. 새 로그인으로 이 수를 초과하게 되면 매장은 일주일 동안 활동이 없었던 세션 중 가장 오래 사용하지 않은 세션부터 제거합니다. 사용 중인 기기는 이 방식으로 제거되지 않습니다.

</details>

## 문제가 발생한 경우 {#goes-wrong}

**활성 세션을 찾을 수 없습니다.** 관리할 수 있는 사용자 중 POS에 로그인한 사람이 없습니다.

**예상한 사용자가 목록에 없습니다.** 만료되지 않은 세션이 없거나, 해당 사용자가 관리자이고 본인은 상점 관리자로 로그인한 경우입니다.

**기기가 바로 다시 로그인되었습니다.** 해당 기기를 사용하는 누군가가 여전히 비밀번호를 알고 있습니다. 비밀번호를 변경하거나 [접근 권한](./access.mdx)에서 해당 사용자의 POS 접근 권한을 제거하세요.
