**WP 관리자:** `WP Admin → POS → Settings → General`, 모든 계산대에 적용됩니다.

일반은 WordPress의 POS 설정에서 첫 번째 화면입니다: **`WP Admin > POS > 설정 > General`**. 모든 캐셔의 POS에 적용되는 매장 전체 설정을 관리합니다. 변경 사항은 즉시 저장되고 **저장됨** 메시지로 확인할 수 있습니다. 별도의 저장 버튼은 없습니다.

:::note 설정을 변경할 수 있는 사용자
**POS 설정 관리** 권한이 있는 사용자(기본적으로 관리자 또는 상점 관리자)가 이 화면을 열 수 있습니다. 캐셔는 열 수 없습니다. [POS 접근](./access.mdx)을 참조하세요.
:::

## POS에서 이 설정이 나타나는 위치 {#in-the-pos}

<JourneyShot manifest={manifest} device="tablet" step={1} alt="장바구니에 Aim Analog Watch가 담긴 POS: 계산대 표시줄, 상품 검색 필드, 상품 타일, 장바구니의 고객 및 항목 수량">

1. **계산대 표시줄** — 매장을 표시하며, [계산대 열기 및 마감](#register)이 켜져 있으면 계산대 상태도 표시합니다.
2. **검색** — 스캔 시 [바코드 필드](#barcode-field)에 설정된 필드로 상품을 찾습니다.
3. **상품** — [POS 전용 상품](#enable-pos-only-products)이 켜져 있으면 *온라인 전용* 상품은 표시되지 않습니다.
4. **고객** — [기본 POS 고객](#default-pos-customer)이며, 여기서는 **비회원**입니다. 탭하여 [다른 고객을 선택](../../pos/cart/index.mdx#customer-selector)하세요.
5. **수량** — [소수 수량](#enable-decimal-quantities)이 켜져 있어야 0.5 같은 소수를 입력할 수 있습니다.

## 매장 정보 {#store-details}

POS 영수증과 청구서에 표시할 매장 정보입니다. **매장 이름**, **전화번호**, **이메일**, 그리고 POS 영수증에 짧게 인쇄되는 **환불 및 반품 정책**을 설정합니다.

필드를 비워 두면 필드 안에 회색으로 표시된 기본값이 사용됩니다. WooCommerce 자체 POS 설정(WooCommerce 10.5 이상)에 해당 필드가 입력되어 있으면 그 값이 기본값이 됩니다. 그렇지 않으면 다음과 같습니다.

| 필드 | 비워 둘 때의 기본값 |
|---|---|
| **매장 이름** | WordPress 사이트 제목 |
| **전화번호** | 없음 |
| **이메일** | WooCommerce 이메일의 발신자 주소, 없으면 WordPress 관리자 이메일 |
| **환불 및 반품 정책** | 없음 |

<Anchor id="store-tax-ids" />

이 필드들 아래에는 **매장 세금 ID**가 있습니다. 영수증과 청구서에 인쇄되는 VAT 번호, ABN, GSTIN 또는 기타 사업자 번호입니다. [매장 세금 ID](./store-tax-ids.mdx)를 참조하세요.

:::info WCPOS Pro 사용 시
매장을 생성하면 이 영역이 **매장** 목록으로 바뀌며, 각 매장은 자체 정보, 영수증 템플릿, 가격, 세율, 사용자를 유지합니다. [매장 설정](../../stores/setup.mdx)을 참조하세요.
:::

## 계산대 {#register}

**계산대 열기 및 마감**을 켜면 계산대 세션이 활성화됩니다. 캐셔는 준비금을 넣어 계산대를 열고, 현금 입출금을 기록하며, 마감 시 현금 서랍의 금액을 셉니다. 끄면 POS는 세션 없이 판매합니다.

켜져 있으면 **시작 준비금**, **시재 차이가 …을 초과하면 관리자에게 요청**, **…에 캐셔에게 마감 알림** 항목이 추가로 나타납니다. 각 항목은 [계산대 설정](./registers.mdx#one-register)에서 설명합니다. 무료 플러그인에는 계산대가 하나 있으며, **Pro로 더 많은 계산대와 매장 사용**은 업그레이드로 연결됩니다.

## 상품 {#products}

<JourneyShot manifest={manifest} device="desktop" step={3} offsets={[[204, 0], [204, 0], [228, 0], [60, 0]]} maxWidth={640} alt="일반 화면의 상품 영역: POS 전용 상품 활성화, 소수 수량 활성화, 주문 삭제 시 재고 복원이 켜져 있고 바코드 필드는 _sku로 설정되어 있음">

1. **POS 전용 상품 활성화** — 상품에 POS 전용 표시 옵션을 추가합니다. [아래](#enable-pos-only-products)를 참조하세요.
2. **소수 수량 활성화** — 항목 수량을 소수로 입력할 수 있게 합니다. [아래](#enable-decimal-quantities)를 참조하세요.
3. **주문 삭제 시 재고 복원** — POS에서 주문을 삭제하면 재고를 되돌립니다. [아래](#restore-stock-on-order-delete)를 참조하세요.
4. **바코드 필드** — 스캔 시 바코드를 찾는 위치이며, 여기서는 `_sku`입니다. [바코드 필드](#barcode-field)를 참조하세요.

</JourneyShot>

### POS 전용 상품 활성화 {#enable-pos-only-products}

WP Admin의 모든 상품에 **POS 및 온라인**, **POS 전용**, **온라인 전용** 표시 옵션을 추가합니다. *POS 전용* 상품은 온라인 상점에서 숨겨지고, *온라인 전용* 상품은 POS에서 숨겨집니다.

모든 상품을 양쪽에서 판매한다면 꺼 두세요. 이 설정을 꺼도 상품이 숨겨지지는 않으며, 다시 켤 때 적용할 수 있도록 각 상품의 선택 사항이 유지됩니다. 상품 하나 또는 여러 상품의 표시 여부를 설정하려면 [POS 전용 상품](../../products/pos-only-products.mdx)을 참조하세요.

### 소수 수량 활성화 {#enable-decimal-quantities}

항목 수량에 `0.25`, `1.5`, `2.75` 같은 소수를 사용할 수 있게 합니다. 원두 0.5 kg, 작업 시간 1.5시간처럼 무게, 길이, 시간 단위로 판매할 때 사용하세요.

켜면 장바구니의 수량 키패드에 소수점이 표시됩니다. 끄면 소수점이 표시되지 않으며, 매장에서 소수 수량이 포함된 주문을 거부합니다.

:::note 무게 단위 판매
WCPOS는 저울에 연결하거나 저울에서 무게를 읽지 않습니다. 상품의 무게를 잰 다음 해당 항목의 수량으로 입력하세요. 킬로그램당 가격이 정해진 상품의 경우 350 g의 수량은 `0.35`입니다.

일부 저울이 인쇄하는 바코드 라벨에 인코딩된 무게나 가격도 WCPOS는 읽지 않습니다.
:::

### 주문 삭제 시 재고 복원 {#restore-stock-on-order-delete}

기본적으로 켜져 있습니다. POS에서 주문을 휴지통으로 옮기거나 삭제하면 해당 상품의 재고가 다시 늘어나므로, 잘못된 판매를 제거하면 상품이 재고에 다시 반영됩니다.

:::warning POS에서 삭제한 주문에만 적용
WP Admin에서 삭제한 주문의 재고는 복원되지 않습니다. 휴지통에서 주문을 복원해도 재고가 다시 차감되지 않습니다.
:::

다른 방식으로 재고를 관리하며 주문 삭제가 재고에 영향을 주지 않게 하려면 이 설정을 끄세요.

### 바코드 필드 {#barcode-field}

상품 바코드 번호가 저장되는 위치를 선택하세요. 캐셔가 바코드를 스캔하거나 **상품 검색**에 입력하면 POS는 해당 위치에 그 바코드가 저장된 상품을 찾습니다.

**바코드 필드** 목록에서 해당 위치를 선택하세요. 대부분의 매장은 다음 두 가지 중 하나를 사용합니다.

<Anchor id="default-option" />

- **WooCommerce 바코드 필드**가 기본값입니다. 상품의 재고 탭에 있는 **GTIN, UPC, EAN 또는 ISBN** 입력란이며, 새 매장에서는 이 필드를 사용하세요. 목록에는 `_global_unique_id`로 표시됩니다.
- 바코드로 SKU를 사용한다면 **상품 SKU**를 선택하세요. 목록에는 `_sku`로 표시됩니다.

바코드 플러그인이 코드를 저장한다면 해당 플러그인의 필드를 선택하세요. 플러그인의 필드가 목록에 없다면 아래의 **플러그인 및 사용자 정의 바코드 필드**를 열어 입력할 이름을 확인하세요.

<Anchor id="other-common-options" />
<Anchor id="third-party-plugin-meta-keys" />

<details>
<summary>플러그인 및 사용자 정의 바코드 필드</summary>

#### 주요 플러그인 → 메타 키 {#common-plugins-meta-key}

바코드 플러그인이 코드를 저장한다면 해당 플러그인의 메타 키를 사용하세요.

| 플러그인 또는 필드 | 메타 키 |
|---|---|
| WooCommerce GTIN, UPC, EAN 또는 ISBN *(기본값)* | `_global_unique_id` |
| 상품 SKU | `_sku` |
| EAN 플러그인(유럽 상품 번호) | `_ean`, `_ean13`, `_ean8` |
| EAN for WooCommerce(WPFactory의 EAN Barcode Generator) | 고급 설정에서 **메타 키**를 변경하지 않았다면 `_alg_ean` |
| UPC 플러그인(통일 상품 코드) | `_upc`, `_upc_code` |
| GTIN 플러그인(국제 거래 단품 식별 번호) | `_gtin`, `_gtin13`, `_gtin14` |
| 일반 바코드 필드 | `_barcode`, `_product_barcode` |
| WooCommerce Product Barcodes | `_barcode_text` |
| ATUM Inventory | `_atum_barcode` |

<Anchor id="custom-meta-keys" />

**바코드 필드** 목록에는 상품과 변형 상품이 이미 사용하는 모든 메타 키와 `_sku`, `_global_unique_id`가 표시됩니다. 목록에 없는 필드는 플러그인 화면에 표시되는 이름이 아니라 실제 저장된 정확한 이름(메타 키)이 필요합니다. 맨 앞에 밑줄이 있다면 그것까지 정확히 입력하고 **"…" 만들기**를 선택하세요.

#### 플러그인의 메타 키 찾기 {#finding-your-plugins-meta-key}

1. WP Admin에서 상품을 편집하고 플러그인을 사용해 바코드를 지정하세요.
2. 플러그인 문서에서 메타 키 이름을 확인하세요.
3. 또는 데이터베이스의 `wp_postmeta` 테이블에서 해당 상품에 생성된 키를 찾아보세요.

</details>

필드를 변경하면 POS는 다음 동기화 때 바코드 조회 정보를 다시 구성하여 스캔 시 새 필드를 사용합니다. 직접 지울 필요는 없습니다.

## 고객 {#customers}

### 고객 이메일에서 사용자 이름 자동 생성 {#automatically-generate-username-from-customer-email}

기본적으로 켜져 있습니다. 캐셔가 POS에서 고객을 추가하면 WooCommerce가 고객의 이메일 주소로 사용자 이름을 만듭니다. 끄면 캐셔가 고객 양식에 사용자 이름을 입력합니다. 이 POS 설정은 POS에서 추가한 고객에게만 적용되며, 온라인 결제에는 별도의 WooCommerce 설정이 그대로 적용됩니다.

### 기본 POS 고객 {#default-pos-customer}

새 장바구니를 만들 때 지정되는 고객과 자동으로 입력되는 정보를 설정합니다. **비회원**은 주문이 어떤 계정에도 속하지 않는다는 뜻입니다. 드롭다운에서 검색하여 WordPress 사용자를 선택할 수도 있습니다. 예를 들어 계산대 판매용으로 만든 ‘방문 고객’ 계정을 사용할 수 있습니다. 드롭다운이 비활성화되어 있다면 아래의 [캐셔 계정 사용](#use-cashier-account)을 끄세요.

캐셔는 언제든 장바구니에서 고객을 변경할 수 있습니다. [고객 선택](../../pos/cart/index.mdx#customer-selector)을 참조하세요.

각 POS는 매장을 처음 불러올 때 **기본 POS 고객**과 **캐셔 계정 사용** 설정을 복사하며, 각 기기의 [설정](../store/general.mdx#default-customer)에서 두 항목을 변경할 수 있습니다. 이미 매장을 불러온 기기는 복사해 둔 설정을 유지합니다. 여기에서 새로 선택한 값을 해당 기기에 적용하려면 기기에서 [서버 설정 복원](../store/general.mdx#restore-server-settings)을 사용하세요.

### 캐셔 계정 사용 {#use-cashier-account}

선택하면 새 장바구니를 만들 때 로그인한 캐셔가 고객으로 지정됩니다. 선택된 동안에는 **기본 POS 고객**이 비활성화됩니다.

### 고객의 영수증 다운로드 허용 {#storefront-receipts}

기본적으로 꺼져 있습니다. 켜면 온라인 상점의 **내 계정 > 주문**에 **영수증** 버튼이 표시되어, 고객이 WCPOS 영수증 템플릿으로 생성된 본인의 영수증을 PDF로 다운로드할 수 있습니다. 처리 중, 완료 또는 환불된 주문에 표시됩니다.

켜면 **고객용 영수증 템플릿**이 표시됩니다. 처음에는 **활성 영수증 템플릿 사용**으로 설정되어 고객에게도 POS와 같은 영수증이 제공됩니다. 전체 페이지 청구서처럼 다른 형식을 제공하려면 다른 템플릿을 선택하세요. [온라인 상점 영수증](../../receipts/storefront.mdx)을 참조하세요.

### 세금 ID {#customer-tax-ids}

WCPOS는 고객 계정에 세금 번호를 저장하고 결제 시 주문에 복사합니다. 이 영역에서 어떤 세금 플러그인이 감지되었는지 확인하세요. **자동 감지됨**에는 플러그인 이름이 표시되며 별도로 할 일이 없습니다. **감지된 플러그인 없음**은 WCPOS가 자체 내장 필드를 사용한다는 뜻입니다. 플러그인이 사용자 정의 필드 이름을 사용하는 경우에만 **고급: 다른 필드 이름 사용**에서 설정하세요. [고객 세금 ID](./customer-tax-ids.mdx)를 참조하세요.

## 개인정보 보호 {#privacy}

**익명 사용 데이터 및 오류 보고 허용**을 켜면 WCPOS가 버그를 찾기 위해 사용 환경과 발생한 문제에 관한 정보를 수집할 수 있습니다. 선택하기 전까지 이 영역에 **허용**과 **괜찮습니다**가 표시됩니다. 선택은 언제든 변경할 수 있습니다.

**수집 항목 알아보기**를 누르면 화면에 전체 목록이 표시됩니다.

<details>
<summary>수집되는 항목</summary>

- **수집 항목:** 사용 환경(PHP 및 WooCommerce 버전, 국가, 통화), 매장 규모(대략적인 상품, 주문, POS 사용자 수), 사용하는 화면과 기능, 오류 및 관련 버전 정보입니다.
- **수집하지 않는 항목:** 고객 정보, 주문 내용, 가격, 사이트 주소 또는 매장 운영자나 고객을 식별할 수 있는 모든 정보입니다.

</details>

## 고급: SSL 강제 사용 {#force-ssl}

기본적으로 켜져 있습니다. POS가 보안 연결을 유지하도록 하므로 켜 두세요.

<details>
<summary>SSL 강제 사용의 동작</summary>

POS는 HTTPS로 열립니다. 일반 `http://`로 POS 페이지에 접속하면 `https://`로 이동하며, WCPOS가 생성하는 POS 링크도 `https://`를 사용합니다. 사이트에 SSL 인증서가 없는 경우에만 끄세요.

</details>

## 문제 해결 {#if-something-goes-wrong}

화면 상단에 **"매장이 Cloudflare 뒤에 있습니다"** 표시
: 사이트가 Cloudflare를 통해 실행되며, Cloudflare의 보안 검사로 인해 POS가 매장에 연결하지 못할 수 있습니다. POS에 HOST121 또는 보안 검사가 표시되면 **규칙 추가 방법**을 따르세요. [Cloudflare](../../support/troubleshooting/cloudflare.mdx)를 참조하세요.

**바코드 필드를 변경한 후 스캔으로 상품을 찾을 수 없습니다**
: POS는 다음 동기화 때 바코드 조회 정보를 다시 구성합니다. 지금 처음부터 다시 불러오려면 POS의 상품 수 옆에 있는 동기화 화살표를 길게 누르고 **지우고 새로 고침**을 선택하세요. [새로 고침 또는 처음부터 다시 시작](../../products/sync.mdx#refresh)을 참조하세요.

**수량이 0.5 같은 값인 주문이 저장되지 않습니다**
: [소수 수량 활성화](#enable-decimal-quantities)를 켜세요.
