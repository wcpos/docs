## O que isso significa {#what-this-means}

O servidor da loja está bloqueando o token de login em todos os canais que este aplicativo pode usar.

O aplicativo confirmou que a loja está acessível, mas o servidor (ou um firewall, proxy ou plugin de segurança à frente dele) remove o cabeçalho Authorization e também bloqueia o token quando ele é enviado como parâmetro da URL. Não há uma terceira forma de entregar um token de login, então isso precisa ser corrigido no servidor.

## Seus dados {#your-data}

Nenhum dado de pedido ou produto é afetado.

## Solução de problemas {#troubleshoot}

**Para sua hospedagem / servidor** — o token de login não tem um canal de entrega até que o servidor permita sua passagem:

1. Permita que o cabeçalho Authorization chegue ao WordPress — no Apache, isso geralmente exige uma linha: `SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1`.
2. Se o site usa regras de reescrita em `.htaccess`, mantenha a linha RewriteRule gerada pelo WordPress que repassa `HTTP_AUTHORIZATION` — plugins de segurança às vezes a removem.
3. Se houver um proxy ou CDN, verifique sua lista de cabeçalhos permitidos: o cabeçalho Authorization da solicitação precisa ser encaminhado ao servidor de origem.
4. Se um firewall de aplicativos web (WAF) estiver filtrando parâmetros de URL, permita o parâmetro de autorização nas rotas REST `/wcpos/`.
