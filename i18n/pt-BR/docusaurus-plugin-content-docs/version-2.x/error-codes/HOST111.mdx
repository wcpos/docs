## O que isso significa {#what-this-means}

A configuração de acesso entre origens (CORS) do servidor está incorreta, por isso o navegador recusa suas respostas.

A loja responde, mas os cabeçalhos CORS da resposta estão errados — duplicados, configurados para a origem errada ou ausentes nas respostas de erro. O navegador então oculta a resposta real do aplicativo web, o que também esconde todos os outros erros por trás de uma falha genérica de rede. A correção deve ser feita no servidor: exatamente um Access-Control-Allow-Origin, presente em todos os códigos de status.

## Seus dados {#your-data}

Nenhum dado de pedido ou produto é afetado.

## Solução de problemas {#troubleshoot}

1. Procure uma segunda camada de CORS (um plugin E a configuração do servidor adicionando cabeçalhos ao mesmo tempo) e remova uma delas — Access-Control-Allow-Origin duplicado causa um erro fatal no navegador.
2. No nginx, as linhas add_header não se aplicam a respostas de erro, a menos que terminem com 'always' — os cabeçalhos CORS também precisam estar nas respostas 4xx/5xx.
3. Se uma CDN ou um proxy adicionar cabeçalhos CORS, verifique se eles não entram em conflito com os do próprio WordPress.
4. Os aplicativos para computador e dispositivos móveis não usam CORS e continuarão funcionando enquanto isso é corrigido.
