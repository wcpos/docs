## O que isso significa {#what-this-means}

Uma página de proteção contra bots está respondendo no lugar da API da loja.

A API REST da loja está retornando uma página de desafio em HTML (proteção contra bots, CAPTCHA ou uma página intermediária de proteção contra DDoS) onde o aplicativo espera JSON. Um aplicativo de ponto de venda não consegue resolver um desafio de navegador; a API REST da loja precisa ser adicionada à lista de permissões do serviço de proteção.

## Seus dados {#your-data}

Nenhum dado de pedido ou produto é afetado.

## Solução de problemas {#troubleshoot}

1. Identifique a camada de proteção pela página de desafio (Cloudflare, Sucuri, Kinsta e outros exibem suas marcas) e abra as configurações dela.
2. Adicione os caminhos da própria API REST da loja (/wp-json/ e /?rest_route=) à lista de permissões para o tráfego da API.
3. No Cloudflare, adicione uma regra **Ignorar** do WAF para os caminhos da API REST; o Modo de Combate a Bots (plano gratuito) não pode ser ignorado por nenhuma regra e precisa ser desativado. O [guia do Cloudflare](/troubleshooting/common-problems/cloudflare) contém a regra exata e uma verificação com `curl`.
4. Nas configurações de bots/firewall da Kinsta, adicione os caminhos da API REST à lista de permissões; no Sucuri, evite o modo de proteção contra DDoS com desafio JavaScript nas rotas da API.
