# Gateway de pagamento Web Checkout {#web-checkout-gateway}

:::info Recurso Pro
Você precisa do [WCPOS Pro](../../getting-started/free-vs-pro.mdx) para receber pagamentos com o Web Checkout.
:::

O Web Checkout permite que o cliente pague um pedido do POS na própria página de pagamento da sua loja online, com os meios de pagamento disponíveis nela, como um formulário de cartão online ou uma carteira digital. Use quando o cliente quiser pagar de uma forma que o caixa não aceita.

Vá direto para: [Receber um pagamento](#take-payment) · [Configurar](#set-up) · [Se algo der errado](#goes-wrong)

## Receber um pagamento {#take-payment}

O Web Checkout fica na aba **Legado** da tela de finalização da compra. Ele precisa de conexão e cobra o pedido inteiro: se algum pagamento já foi recebido, consulte primeiro [Parte do pedido já está paga](#split).

:::warning Permaneça na tela de finalização da compra até pressionar Processar pagamento
O caixa não monitora a outra aba. Ele só conclui a venda quando você pressiona **Processar pagamento** em um pedido que o cliente já pagou. Por isso, mantenha a tela de finalização da compra aberta enquanto o cliente paga.
:::

1. Registre a venda normalmente e pressione **Finalizar Compra**.
2. Abra a aba **Legado**. A página de pagamento da sua loja é carregada dentro do POS.
3. Escolha **Web Checkout**. A mensagem do gateway e um link **Pagar este pedido** aparecem abaixo dele.
4. Pressione **Pagar este pedido**. A página de pagamento da sua loja online para esse pedido abre em uma nova aba do navegador; no aplicativo para desktop, ela abre no navegador do computador.
5. Disponibilize a tela para o cliente. Ele escolhe um meio de pagamento e paga, como faria no seu site.
6. Quando o cliente terminar de pagar, a aba dele mostrará a confirmação do pedido da sua loja. Deixe essa aba aberta e volte ao POS.
7. Pressione **Processar pagamento**. Se o pedido estiver pago, o caixa mostrará a tela de pagamento concluído e o recibo, como em qualquer venda. Caso contrário, o caixa permanecerá nesta página: consulte [Se algo der errado](#goes-wrong).
8. Feche a aba do cliente quando o caixa mostrar o recibo.

1. Aba **Pagamentos** — os blocos: Dinheiro, Cartão e os gateways de pagamento que têm um bloco próprio.
2. Aba **Legado** — gateways de pagamento que funcionam na página de pagamento da loja. Consulte [A aba Legado](../../pos/checkout/legacy-tab.mdx).
3. **Fechar** — volta ao carrinho sem receber o pagamento. O pedido permanece aberto.
4. **A página de pagamento da loja** — o pedido, seguido dos gateways de pagamento ativados para o POS. O Web Checkout entra nessa lista quando é ativado; a loja desta imagem não o tem. **Configurações do caixa**, no topo, serve para corrigir uma página com aparência incorreta; consulte [Se algo der errado](#goes-wrong).
5. **Processar pagamento** — pressione depois que o cliente pagar. Até o pedido estar pago, o caixa permanece nesta página.
6. **O pedido** — seu número, cliente e horário.
7. **Restante** — o que falta pagar. O Web Checkout cobra o pedido inteiro, por isso não pode ser usado depois que outro pagamento foi recebido.

### Parte do pedido já está paga {#split}

Um gateway de pagamento legado cobra o pedido inteiro. Por isso, depois que um pagamento é recebido, a aba Legado informa **Não é possível usar um gateway de pagamento legado depois que um pagamento foi recebido**. Você tem duas opções:

- **Receba o restante por um bloco**, como Dinheiro ou Cartão, na aba Pagamentos. Consulte [Pagamentos divididos](../../pos/checkout/split-payments.mdx).
- **Cancele os pagamentos recebidos até agora** e use o Web Checkout para o pedido inteiro. Antes de desfazer qualquer coisa, o caixa lista o que acontece com cada pagamento: o dinheiro é devolvido ao cliente, os outros pagamentos são anulados no respectivo meio de pagamento, e aqueles que não podem ser anulados são reembolsados pelo pedido. Consulte [Cancelar um pagamento](../../pos/checkout/cancelling-a-payment.mdx).

:::tip O cliente quer pagar depois, no próprio celular
O Web Checkout abre a página de pagamento no dispositivo que está executando o POS. Para enviar ao cliente um link pelo qual ele possa pagar depois, use [Enviar fatura por e-mail](./email-invoice.mdx).
:::

## Configurar {#set-up}

Alguém que gerencia sua loja no WP Admin faz isso uma única vez, antes da primeira venda com o Web Checkout. O Web Checkout é um plugin gratuito, mas o POS só o oferece com o WCPOS Pro; sem o Pro, o caixa aceita Dinheiro e Cartão. Ele usa os meios de pagamento que sua loja online já tem. Não precisa de conta nem de chaves.

<details>
<summary>Gerente da loja: instalar e ativar</summary>

1. **Instale.** O Web Checkout não está em `WP Admin > POS > Configurações > Extensões`. Baixe **woocommerce-pos-web-checkout-gateway.zip** (não o zip do código-fonte) na [página de versões do GitHub](https://github.com/wcpos/web-checkout-gateway/releases), envie o arquivo em `WP Admin > Plugins > Add Plugin`, depois **Enviar plugin**, e ative-o.
2. **Ative para o POS.** Em `WP Admin > POS > Configurações > Finalização de compra`, ative **Web Checkout** e salve. Consulte [Configurações do caixa](../../settings/wp-admin/checkout.mdx#enabling-a-gateway). Ele nunca aparece na finalização de compra da sua loja online: os clientes só chegam até ele pelo POS.
3. **Verifique seus meios de pagamento online.** O cliente paga com as opções ativadas para a web em `WP Admin > WooCommerce > Configurações > Pagamentos`. Pelo menos uma delas precisa estar pronta para receber pagamentos.

</details>

<details>
<summary>Alterar o nome ou a mensagem</summary>

O nome e a mensagem na página de pagamento são o **Título** e a **Descrição** do gateway de pagamento, em `WP Admin > WooCommerce > Configurações > Pagamentos > Web Checkout Gateway`. A mensagem padrão diz "Vá à página de finalização da compra para pagar o pedido. Após o pagamento, clique no botão Processar pagamento para prosseguir para o recibo." Para renomeá-lo apenas no POS, altere o **Título** em **Configurações do POS**, no menu **⋮** do gateway de pagamento em [Configurações do caixa](../../settings/wp-admin/checkout.mdx#payment-gateways); a mensagem sempre vem do WooCommerce.

</details>

<details>
<summary>Para desenvolvedores: como funciona</summary>

O plugin adiciona um gateway de pagamento ao WooCommerce com o ID `wcpos_web_checkout`. Ele é desativado para a finalização de compra online no código, por isso só o POS pode oferecê-lo. Seus campos de pagamento exibem a descrição e um link para a URL de pagamento do próprio pedido (`$order->get_checkout_payment_url()`), aberto em uma nova janela.

O gateway de pagamento não recebe dinheiro diretamente. Quando **Processar pagamento** envia um pedido já pago, criado pelo POS, com `wcpos_web_checkout` selecionado, o plugin redireciona a página de pagamento para a página de pedido recebido, e o POS conclui a venda a partir daí. Um pedido não pago não avança. O código-fonte está no [repositório web-checkout-gateway](https://github.com/wcpos/web-checkout-gateway).

</details>

## Se algo der errado {#goes-wrong}

**O Web Checkout não está na lista da aba Legado.** O plugin não está ativo ou o Web Checkout não está ativado em [Configurações do caixa](../../settings/wp-admin/checkout.mdx#enabling-a-gateway). Sem o WCPOS Pro, o POS oferece apenas Dinheiro e Cartão.

**"Nenhum gateway de pagamento legado está ativado para o POS."** Nenhum gateway de pagamento sem bloco está ativado. Ative o Web Checkout em Configurações do caixa.

**Processar pagamento não avança para o recibo.** A loja não registra o pedido como pago. Antes de pedir ao cliente que pague novamente, confira a aba dele: se ela ainda mostrar a página de pagamento, ele não terminou. Se mostrar a confirmação do pedido, pressione **Processar pagamento** novamente e, se o caixa ainda não avançar, verifique o pedido em `WP Admin > WooCommerce > Orders`.

**Nenhum meio de pagamento que o cliente possa usar aparece na página de pagamento.** Sua loja online não tem nenhuma opção adequada ativada. Ative uma opção para a web em `WP Admin > WooCommerce > Configurações > Pagamentos`.

**A página de pagamento dentro do POS está com aparência incorreta.** Um tema ou plugin pode estar interferindo nela. Consulte [A página de pagamento de um gateway está com aparência incorreta](../../pos/checkout/troubleshooting.mdx#checkout-settings-troubleshooting).
