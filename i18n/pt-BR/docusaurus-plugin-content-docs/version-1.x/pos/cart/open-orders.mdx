O WCPOS permite trabalhar com vários pedidos simultaneamente. Isso é útil para lidar com pedidos em espera, alternar entre transações e se recuperar de interrupções.

## Carrossel de Pedidos Abertos {#open-orders-carousel}

Na parte inferior do Painel do Carrinho, um carrossel horizontal exibe todos os pedidos abertos:

{/* Screenshot: open-orders-carousel.png */}

- Cada carrinho mostra seu **valor total**
- O **pedido atual** fica destacado
- Clique em qualquer carrinho para alternar para ele
- Role para a esquerda/direita para ver mais carrinhos

## Criando um Novo Pedido {#creating-a-new-order}

Um novo carrinho vazio está sempre disponível. Basta clicar em um carrinho vazio no carrossel ou começar a adicionar produtos quando o carrinho atual estiver vazio.

## Alternando Entre Pedidos {#switching-between-orders}

Clique em qualquer pedido no carrossel para alternar para ele. O Painel do Carrinho é atualizado para mostrar o conteúdo do pedido selecionado.

**Casos de uso:**

- O cliente se afasta para pegar outro item
- Você precisa atender rapidamente outro cliente enquanto um pedido grande está em andamento
- Comparar preços ou itens entre pedidos

## Salvando Pedidos no Servidor {#saving-orders-to-server}

Os pedidos existem em dois estados:

### Somente Local {#local-only}

Por padrão, os novos pedidos são armazenados apenas no banco de dados local do navegador/app. Eles permanecem após atualizar a página, mas:

- Não ficam visíveis no admin do WooCommerce
- Serão perdidos se o banco de dados local for limpo
- Não podem ser acessados em outros dispositivos

### Salvos no Servidor {#saved-to-server}

Clique em **Salvar no Servidor** para criar um pedido no WooCommerce com o status `pos-open`. Isso:

- Cria um pedido real no WooCommerce
- É mantido mesmo que o banco de dados local seja limpo
- Pode ser acessado em outros dispositivos
- Aparece em WP Admin > WooCommerce > Pedidos

:::tip Quando Salvar
Salve os pedidos no servidor quando:
- Um cliente quiser deixar um pedido separado para retirar mais tarde
- Você estiver encerrando seu turno e outro caixa for continuar
- Você quiser ter um backup para o caso de problemas com o app/navegador
:::

## Recuperando Pedidos Salvos {#recovering-saved-orders}

Se você salvou pedidos no servidor, poderá acessá-los novamente:

1. Abrindo a tela de **Pedidos** (recurso Pro)
2. Filtrando pelo status `pos-open`
3. Reabrindo o pedido

## Persistência de Pedidos {#order-persistence}

### Armazenamento Local {#local-storage}

O WCPOS armazena os pedidos no banco de dados local do dispositivo. Isso oferece:

- Persistência entre sessões do navegador
- Acesso rápido sem solicitações de rede
- Uso offline

### Sincronização com o Servidor {#sync-with-server}

Quando você salva no servidor ou finaliza a compra:

- O pedido é enviado ao WooCommerce
- Uma confirmação é recebida
- Os dados locais e do servidor são sincronizados

## Anulando Pedidos {#voiding-orders}

Para remover um pedido aberto:

1. Alterne para o pedido que deseja remover
2. Clique no botão **Anular**

**O que acontece:**

- **Pedidos não salvos:** Excluídos permanentemente do banco de dados local
- **Pedidos salvos:** Movidos para a Lixeira no WooCommerce e excluídos localmente

Para recuperar um pedido salvo que foi anulado:
1. Acesse `WP Admin > WooCommerce > Orders > Trash`
2. Restaure o pedido

## Dicas {#tips}

### Mantenha os Pedidos Organizados {#keep-orders-organized}

Quando há vários pedidos abertos, é útil:

- Adicionar nomes de clientes aos pedidos para identificá-los facilmente
- Adicionar notas ao pedido descrevendo o motivo da espera
- Salvar pedidos importantes no servidor

### Transição de Turno {#shift-handoffs}

Ao encerrar um turno com pedidos abertos:

1. Salve todos os pedidos importantes no servidor
2. Adicione notas ao pedido explicando o status
3. O próximo caixa poderá acessá-los na tela de Pedidos

### Considerações para Uso Offline {#offline-considerations}

Se você perder a conexão:

- Os pedidos locais continuam acessíveis e você pode continuar adicionando itens
- Você pode concluir um pedido com uma forma de pagamento que funcione offline; os gateways de pagamento que dependem do servidor permanecem indisponíveis até que seus serviços voltem a ficar acessíveis
- Você não pode salvar pedidos no servidor até se reconectar
- Você não pode criar novos clientes até se reconectar
