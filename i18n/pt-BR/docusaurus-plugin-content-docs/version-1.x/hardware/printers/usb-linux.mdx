**Sintoma:** a impressora aparece na busca, mas a impressão falha com um erro de acesso ou de permissão.

## Por que isso acontece {#why-it-happens}

No Linux, um dispositivo USB pertence ao `root` a menos que uma regra diga o contrário, então um aplicativo rodando como você não consegue abri-lo. O driver de impressora do próprio kernel também pode já ter reivindicado o dispositivo.

## Faça isto {#do-this}

1. Descubra os ids de fabricante e de produto da impressora:

   ```bash
   lsusb
   ```

   Procure a linha da sua impressora — os ids são os dois valores de quatro caracteres depois de `ID`, por exemplo `04b8:0e28`.

2. Crie um arquivo de regra, trocando os ids pelos seus:

   ```bash
   sudo tee /etc/udev/rules.d/99-receipt-printer.rules <<'RULE'
   SUBSYSTEM=="usb", ATTRS{idVendor}=="04b8", ATTRS{idProduct}=="0e28", MODE="0666"
   RULE
   ```

3. Recarregue as regras e aplique-as novamente:

   ```bash
   sudo udevadm control --reload-rules && sudo udevadm trigger
   ```

4. Desconecte a impressora, conecte de novo e reinicie o aplicativo. Imprima uma página de teste.

Rode o aplicativo com o seu usuário comum, não com `sudo` — uma regra que só funciona para o root perde o sentido.

## Ainda com problema? {#still-stuck}

Use **Copiar relatório de configuração** na tela de problema e cole o conteúdo na sua mensagem, junto com a linha do `lsusb` da sua impressora.
