Conflitos de plugins são uma das causas mais comuns de problemas com o WCPOS. Quando outros plugins do WordPress interferem no funcionamento do WooCommerce ou do WCPOS, você pode enfrentar falhas, problemas de desempenho ou comportamento inesperado.

## Sinais de Conflitos de Plugins {#signs-of-plugin-conflicts}

Você pode ter um conflito de plugins se estiver enfrentando:

- **Erros fatais** - "Ocorreu um erro crítico neste site"
- **Problemas de desempenho** - Carregamento lento, tempos limite excedidos ou alta carga no servidor
- **Problemas de funcionalidade** - Recursos que não funcionam como esperado
- **Problemas de sincronização de dados** - Produtos, pedidos ou clientes que não sincronizam corretamente
- **Problemas com gateways de pagamento** - Falhas no checkout ou erros no processamento de pagamentos

## Antes de Começar: Use um Site de Testes {#before-you-start-use-a-staging-site}

:::warning Importante
**Nunca investigue conflitos de plugins no seu site em produção.** Sempre use um ambiente de testes para evitar interromper as operações do seu negócio.
:::

### O que é um Site de Testes? {#what-is-a-staging-site}

Um site de testes é uma cópia exata do seu site em produção, onde você pode testar alterações com segurança sem afetar seus clientes. A maioria dos provedores de hospedagem modernos oferece ambientes de testes como um recurso padrão.

### Se Seu Provedor Não Oferecer um Ambiente de Testes {#if-your-host-doesnt-offer-staging}

Se seu provedor de hospedagem não oferece sites de testes, **considere mudar para um provedor que ofereça**. Esse é um recurso padrão hoje em dia e essencial para:

- Testar plugins/temas com segurança
- Atualizações do WordPress
- Solução de problemas
- Trabalho de desenvolvimento

**Provedores recomendados com ambiente de testes:**
- WP Engine
- SiteGround  
- Kinsta
- Cloudways
- Muitos outros

## Etapa 1: Verifique Erros Fatais {#step-1-check-for-fatal-errors}

Se você está enfrentando falhas ou erros críticos, comece verificando os logs de erro:

1. **Verifique os Logs do WCPOS** - Abra [**Saúde da loja → Logs**](/1.x/support/logs) no WCPOS e procure mensagens de erro
2. **Verifique os Logs de Erros Fatais** - Siga o [guia de resolução de erros críticos](/1.x/support/troubleshooting/critical-error) para encontrar mensagens de erro detalhadas
3. **Anote os detalhes do erro** - Procure nomes de plugins ou caminhos de arquivos mencionados no erro

Se você encontrar um erro fatal que mencione um plugin específico, esse provavelmente é o responsável. Você pode desativar esse plugin e testar se o problema foi resolvido.

## Etapa 2: Método de Eliminação de Plugins {#step-2-the-plugin-elimination-method}

Se não houver erros fatais nos logs ou se você quiser identificar conflitos relacionados ao desempenho, use esta abordagem sistemática:

### 2.1 Crie uma Linha de Base {#21-create-a-baseline}

1. **Acesse seu site de testes**
2. **Teste a funcionalidade problemática** - Anote exatamente o que não está funcionando ou está lento
3. **Registre métricas de desempenho** - Se for um problema de desempenho, anote os tempos de execução dos [Logs](/1.x/support/logs)

### 2.2 Desative Todos os Plugins (Exceto os Essenciais) {#22-disable-all-plugins-except-essential-ones}

**Mantenha estes plugins ativos:**
- WooCommerce
- WCPOS
- WCPOS Pro (se você o tiver)

**Desative todo o resto:**
1. Vá para `WP Admin > Plugins`
2. Selecione todos os outros plugins
3. Escolha "Desativar" no menu suspenso de ações em massa
4. Clique em "Aplicar"

### 2.3 Teste o Problema {#23-test-the-issue}

1. **Limpe os caches** - Se você usa plugins de cache, limpe todos os caches
2. **Teste a funcionalidade problemática** - Ela funciona agora?
3. **Verifique o desempenho** - Os tempos de execução melhoraram?

**Se o problema estiver resolvido:** Você tem um conflito de plugins. Prossiga para a Etapa 2.4.

**Se o problema persistir:** Provavelmente não se trata de um conflito de plugins. Considere:
- Problemas de recursos do servidor (veja [Desempenho do Servidor](/1.x/support/performance/server))
- Conflitos de tema (veja a Etapa 3)
- Problemas no núcleo do WordPress/WooCommerce

### 2.4 Ative os Plugins Um a Um {#24-enable-plugins-one-by-one}

Agora você precisa identificar qual plugin está causando o conflito:

1. **Ative um plugin** - Comece pelos mais essenciais
2. **Teste a funcionalidade** - Verifique se o problema retorna
3. **Se não houver problema** - Ative o próximo plugin e teste novamente
4. **Se o problema retornar** - Você encontrou o plugin em conflito!

**Ordem de Prioridade dos Plugins (ative nesta ordem):**
1. **Plugins de segurança** - Wordfence, Sucuri, etc.
2. **Plugins de SEO** - Yoast, RankMath, etc.  
3. **Plugins de desempenho** - Cache, otimização
4. **Gateways de pagamento** - Stripe, PayPal, etc.
5. **Outras extensões do WooCommerce**
6. **Plugins gerais do WordPress**

### 2.5 Documente suas Descobertas {#25-document-your-findings}

Quando você identificar o plugin em conflito:

1. **Anote o nome e a versão do plugin**
2. **Documente o problema específico que ele causa**
3. **Verifique se há uma versão atualizada disponível**
4. **Procure plugins alternativos que ofereçam funcionalidade semelhante**

## Etapa 3: Verifique Conflitos de Tema {#step-3-check-for-theme-conflicts}

Embora os temas raramente afetem o WCPOS (pois ele usa sua própria interface), às vezes eles podem causar problemas com:

- Processos de checkout (se estiver usando o gateway de checkout da web)
- Funcionalidades da área administrativa
- Respostas da API

### Teste com um Tema Padrão {#test-with-a-default-theme}

1. **No seu site de testes**, mude para um tema padrão do WordPress:
   - Twenty Twenty-Four
   - Twenty Twenty-Three
   - Twenty Twenty-Two
2. **Teste a funcionalidade problemática**
3. **Se o problema estiver resolvido** - Seu tema tem um conflito

:::info Impacto do Tema
Os temas têm muito menos probabilidade de causar problemas com o WCPOS do que os plugins. A interface do POS funciona independentemente do seu tema. No entanto, os temas podem afetar:
- Páginas de checkout do WooCommerce
- Funcionalidades administrativas do WordPress
- Respostas da REST API
:::

## Etapa 4: Resolvendo Conflitos de Plugins {#step-4-resolving-plugin-conflicts}

Depois de identificar o plugin em conflito, você tem várias opções:

### Opção 1: Atualizar o Plugin {#option-1-update-the-plugin}

1. **Verifique se há atualizações** - O conflito pode ter sido corrigido em uma versão mais recente
2. **Atualize o plugin** primeiro no seu site de testes
3. **Teste minuciosamente** antes de atualizar no site em produção

### Opção 2: Encontrar uma Alternativa {#option-2-find-an-alternative}

1. **Pesquise plugins alternativos** que ofereçam a mesma funcionalidade
2. **Teste as alternativas** no seu site de testes
3. **Migre as configurações** se trocar de plugin

### Opção 3: Contatar o Desenvolvedor do Plugin {#option-3-contact-plugin-developer}

1. **Relate o conflito** ao desenvolvedor do plugin
2. **Forneça informações detalhadas:**
   - Versões dos plugins envolvidos
   - Versões do WordPress e do WooCommerce
   - Mensagens de erro ou comportamentos exatos
   - Etapas para reproduzir o problema

### Opção 4: Solução Personalizada {#option-4-custom-solution}

Para plugins essenciais que não podem ser substituídos:

1. **Contate um desenvolvedor WordPress** para criar uma correção personalizada
2. **Considere hooks específicos do plugin** para desativar funcionalidades conflitantes
3. **Use lógica condicional** para desativar o plugin em páginas relacionadas ao POS

## Tipos Comuns de Plugins em Conflito {#common-conflicting-plugin-types}

### Categorias de Plugins de Alto Risco {#high-risk-plugin-categories}

**Plugins de Segurança:**
- Podem bloquear solicitações à API
- Podem interferir na autenticação
- Costumam ter regras de firewall agressivas

**Plugins de Cache:**
- Podem armazenar respostas da API em cache de forma inadequada
- Podem interferir em dados em tempo real
- Podem causar problemas de dados desatualizados

**Plugins de SEO:**
- Plugins pesados podem deixar a área administrativa lenta
- Podem adicionar consultas desnecessárias ao banco de dados
- Podem interferir nas respostas da REST API

**Construtores de Páginas:**
- Costumam carregar scripts pesados na área administrativa
- Podem causar conflitos com páginas administrativas do WooCommerce
- Podem interferir nos processos de checkout

**Plugins de Membros/Restrições:**
- Podem bloquear o acesso à API
- Podem interferir na autenticação de usuários
- Podem restringir o acesso a recursos necessários

### Categorias de Plugins de Baixo Risco {#lower-risk-plugin-categories}

**Formulários de Contato:** Geralmente não interferem no WCPOS
**Plugins de Mídia Social:** Raramente causam conflitos
**Plugins de Análise:** Geralmente seguros, a menos que sejam muito pesados
**Plugins Básicos de Conteúdo:** Normalmente compatíveis
**WooCommerce Tax (impostos automatizados via TaxJar):** Compatível. O WCPOS solicita as alíquotas quando um pedido aberto do POS é salvo, para que os pedidos do POS recebam as mesmas alíquotas automatizadas que os pedidos online. Consulte [WooCommerce Tax](/1.x/integrations/woocommerce-tax).

## Conflitos de Plugins Conhecidos {#known-plugin-conflicts}

Os plugins abaixo são conhecidos por interferir no WCPOS. Muitos problemas já foram corrigidos automaticamente em versões recentes do WCPOS — **atualizar para a versão mais recente** resolve esses problemas sem nenhuma configuração.

:::tip A maioria das correções consiste em "excluir o POS"
O ponto em comum: o WCPOS depende da REST API do WooCommerce e renderiza alguns fluxos (login, pagamento, recibos) em iframes. A correção habitual é **excluir os endpoints/URLs do POS** (`/wp-json/wcpos/`, `/wp-json/wc/v3/` e o caminho `/pos/`) da atuação do outro plugin — e não desativá-lo por completo.
:::

### Plugins de segurança e login {#security-and-login-plugins}

Estes são a fonte **mais comum** de conflitos, especialmente no login dos aplicativos para computador e dispositivos móveis.

| Plugin | Sintoma | Correção |
| --- | --- | --- |
| **Wordfence** | O firewall bloqueia a REST API; o campo de código 2FA não é renderizado no iframe de login; uma CSP restritiva pode bloquear os recursos do POS | Adicione `/wp-json/wcpos/` e `/wp-json/wc/v3/` à lista de permissões do firewall. Para 2FA: desative-o temporariamente para usuários do POS. A CSP é removida automaticamente na v1.9.0+ |
| **Really Simple Security** | Bloqueia o acesso à API / força redirecionamentos | Desative quaisquer restrições da REST API nas configurações **Avançadas** do plugin |
| **WPS Hide Login** | A URL de login personalizada impede o funcionamento do iframe de login do aplicativo | Use a URL de login padrão `/wp-admin/` para acessar o POS |
| **iThemes / Solid Security** | Bloqueia a REST API ou aciona bloqueios por força bruta devido às chamadas do POS | Adicione à lista de permissões apenas os endpoints do POS e o próprio IP do servidor — evite regras de IP abrangentes |
| **Sucuri** | O WAF bloqueia solicitações à API | Adicione os endpoints da REST API à lista de permissões no painel do Sucuri |
| **Security Optimizer** | Bloqueia o login administrativo do POS (_"use a URL de login personalizada"_) | Primeiro faça login no WP Admin pela URL personalizada e depois acesse `/pos` |
| **Force Login** (e plugins semelhantes de autenticação REST) | `/wp-json/` retorna 401/403; aplicativos mais antigos informavam _"O site não parece ser um site WordPress"_ | Permita acesso não autenticado aos endpoints do POS ou desative o plugin durante a conexão inicial. Os aplicativos v1.x agora exibem a mensagem de erro real |
| **LoginPress** | Força o login por e-mail; impede o login multiusuário do POS | Permita o login por nome de usuário ou desative o plugin para o acesso ao POS |
| **Plugins de autenticação JWT** | Erro 403 em todas as solicitações à API do POS após a ativação (o login pode funcionar, mas todo o resto falha) | Corrigido automaticamente na v1.8.x+. Em versões anteriores, desative o plugin JWT ou exclua os endpoints do POS |
| **Captcha / reCAPTCHA** | Ciclo de login no aplicativo para computador (o captcha não pode ser renderizado no iframe) | Desative o captcha para a URL de login do POS |
| **Defender Pro** | O cabeçalho `X-Frame-Options` bloqueia todos os iframes do POS (login, pagamento, recibos) | Adicione uma exceção específica para o POS em `/pos/` em vez de desativar `X-Frame-Options` em todo o site |
| **Jetpack CRM Client Portal** | Impede completamente o login do POS | Desative apenas a extensão Client Portal |

### Plugins de desempenho, cache e otimização {#performance-caching-optimisation-plugins}

| Plugin | Sintoma | Correção |
| --- | --- | --- |
| **WP Rocket, Autoptimize, Hummingbird, Smush** | Adiar a execução de JS ou minificá-lo impede o funcionamento do checkout e do Stripe Terminal | Exclua as URLs `/pos/` da otimização de JS |
| **LiteSpeed Cache** | Ciclo constante de recarregamento no checkout do aplicativo para computador; CSP restritiva | Atualize o WCPOS, limpe o cache e exclua as páginas do POS do cache. A CSP é removida automaticamente na v1.9.0+ |
| **Image Prioritizer** | Sobrecarrega o cabeçalho HTTP `Link`, impedindo a descoberta da REST API; o aplicativo para computador mostra _"não parece ser um site WordPress"_ | Desative o plugin |

### Construtores de páginas e injetores de front-end {#page-builders-front-end-injectors}

| Plugin | Sintoma | Correção |
| --- | --- | --- |
| **Elementor** | `elementor-frontend.js` impede o funcionamento do acordeão do checkout dentro do iframe do POS — os métodos de pagamento não se expandem | Exclua as páginas do POS do carregamento de scripts do Elementor |
| **Omnisend / plugins de marketing** | Injetam scripts no iframe do checkout, prejudicando o layout e os pagamentos | Use as **Configurações de checkout** do POS para desativar scripts não essenciais |
| **MyStickyElements / Complianz** | Injetam sobreposições (botões fixos, banners de cookies) no iframe do checkout | Configure-os para excluir as URLs `/pos/` |

### Extensões do WooCommerce e outros plugins {#woocommerce-extensions-other-plugins}

| Plugin | Sintoma | Correção |
| --- | --- | --- |
| **WooCommerce Subscriptions** | Conflito de script de migração durante a atualização da v1.7→v1.8 | Desative o Subscriptions, ative o WCPOS Pro (deixe a migração ser executada) e depois reative o Subscriptions |
| **WP Activity Log** | Registra todas as ações do POS → crescimento excessivo de postmeta → _"apenas 10 produtos"_ | Desative-o ou exclua os tipos de post do POS do registro de logs |
| **Jetpack / Astra / Xero** (qualquer plugin que use o hook `save_post`) | Linhas de metadados duplicadas em cada chamada à API do POS (uma loja chegou a 36,867 linhas em um único produto) | Corrigido automaticamente na v1.8.12+ (gratuito) / v1.8.14+ (Pro) com uma migração de limpeza — basta atualizar |
| **Stripe Tax** | Incompatível com pedidos criados pela REST API (como o POS cria pedidos) | Não há solução alternativa — é incompatível. [WooCommerce Tax](/1.x/integrations/woocommerce-tax) é a opção compatível para impostos automatizados |
| **Mollie** | Pode ocultar o método BACS (transferência bancária) do checkout do POS | Atualize o Mollie para a versão mais recente |
| **CTX Feed** | Erros 403 intermitentes na página de configurações do POS | Desative para confirmar; não há solução alternativa conhecida |
| **Plugins de leitores de código de barras de terceiros** | Corrompem o JSON da API de pedidos, impedindo a criação/exibição de pedidos | Desative-os; use a leitura de código de barras integrada do POS |
| **MailerLite** (Signup Forms + WooCommerce) | Erro 500 na criação de pedidos do POS (esgotamento de memória) | Desative para confirmar e depois entre em contato com o MailerLite |
| **The Courier Guy Shipping** | A criação de pedidos do POS falha com um erro do servidor | Volte para uma versão anterior ou entre em contato com o desenvolvedor |
| **PixelYourSite / PixelMySite** | Erro fatal: _chamada à função membro `is_type()` em um valor bool_ | Desative temporariamente |
| **Google Listings & Ads** | Conflito no carregador automático → erro crítico _"Classe WCPOS\…\Stores não encontrada"_ | Exclua todos os plugins do POS e reinstale apenas a versão independente mais recente do Pro |

:::warning Stripe Terminal: não o habilite globalmente
O gateway de pagamento **Stripe Terminal** deve ser habilitado **apenas** nas Configurações do POS, nunca em `WooCommerce > Configurações > Pagamentos`. Habilitá-lo globalmente faz com que ele apareça no checkout público da sua loja e cause falhas no fluxo de checkout online.
:::

### Conflitos no nível do servidor {#server-level-conflicts}

| Origem | Sintoma | Correção |
| --- | --- | --- |
| **Cabeçalhos CSP personalizados** (`.htaccess`, Nginx ou um plugin de segurança) | O POS fica parado no logotipo; JS/CSS bloqueados | Removidos automaticamente das páginas do POS na v1.9.0+. Para CSP no nível do servidor, permita `cdn.jsdelivr.net` em `script-src`/`style-src` ou adicione uma exceção para `/pos/` |
| **GoDaddy Website Firewall** | Bloqueia `/wp-json/` (_"Recebido 'undefined'"_) | Permita o caminho de URL `/wp-json/` no firewall — veja [Desempenho do Servidor](/1.x/support/performance/server#hosting-specific-notes) |

## Dicas de Prevenção {#prevention-tips}

### Manutenção Regular {#regular-maintenance}

1. **Mantenha os plugins atualizados** - Sempre use as versões mais recentes
2. **Remova plugins não utilizados** - Não apenas desative, exclua-os
3. **Teste atualizações no ambiente de testes** antes de aplicá-las ao site em produção
4. **Monitore o desempenho** regularmente usando métricas de [Desempenho do Servidor](/1.x/support/performance/server)

### Boas Práticas para Selecionar Plugins {#plugin-selection-best-practices}

1. **Escolha desenvolvedores de boa reputação** - Verifique avaliações e a frequência das atualizações
2. **Evite funcionalidades redundantes** - Não instale vários plugins que fazem a mesma coisa
3. **Leia as informações de compatibilidade** - Verifique se os plugins foram testados com o WooCommerce
4. **Comece com o mínimo de plugins** - Adicione funcionalidades gradualmente, conforme necessário
