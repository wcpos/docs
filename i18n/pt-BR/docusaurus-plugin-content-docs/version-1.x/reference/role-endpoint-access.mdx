Esta página documenta quais endpoints REST do WCPOS são acessíveis a cada uma das três funções padrão usadas nos fluxos de trabalho do POS:

- `administrator`
- `shop_manager`
- `cashier`

Para configurar funções e capacidades na interface do usuário, consulte [Acessando o POS](/1.x/settings/wp-admin/access).

## Resumo {#summary}

O modelo de acesso padrão é:

- **`administrator`** — acesso total ao POS e à gestão.
- **`shop_manager`** — acesso total ao POS e à gestão, exceto ações de extensões que exigem capacidades de instalação de plugins.
- **`cashier`** — acesso ao fluxo normal de vendas do POS, mas sem acesso à gestão, às configurações, aos logs ou à administração da loja.

A matriz de endpoints é verificada por testes de integração que usam o mesmo caminho de autenticação do aplicativo POS (tokens de acesso bearer do WCPOS, não apenas `wp_set_current_user()`). As asserções de endpoints permitidos confirmam que uma função não recebe `401` ou `403`. Alguns endpoints ainda podem retornar dados normais ou erros de negócio, como `400` ou `404`, quando o teste usa dados de teste mínimos — essas respostas ainda comprovam que o usuário passou pela camada de autenticação/permissão.

## Cobertura de Expiração de Token {#token-expiry-coverage}

| Cenário | Administrador | Gerente de loja | Caixa | Resultado esperado |
|---|---:|---:|---:|---|
| Token de acesso válido | ✅ testado | ✅ testado | ✅ testado | Endpoints permitidos não retornam `401` ou `403` |
| Token de acesso expirado | ✅ testado | ✅ testado | ✅ testado | A requisição falha na verificação de autenticação do WCPOS com usuário `0` |
| Token de atualização válido após expiração do token de acesso | ✅ testado | ✅ testado | ✅ testado | Um novo token de acesso é emitido e o acesso é restaurado |
| Token de atualização expirado | ✅ testado | ✅ testado | ✅ testado | Não é possível gerar um novo token de acesso |

## Diagnosticando Falhas {#diagnosing-failures}

Se um `shop_manager` padrão vê um erro como:

> A requisição continua não autorizada após a atualização do token — faça login novamente

A matriz de endpoints indica que isso **não** ocorre por uma falta inerente de acesso ao POS na função `shop_manager` padrão. Causas prováveis a investigar:

1. Corrupção de funções/capacidades específica do site.
2. Um endpoint não coberto pela matriz.
3. Comportamento de novas tentativas com token de acesso desatualizado ou expirado no cliente.
4. Interferência de plugins de segurança ou autenticação de terceiros.
5. Regras de acesso do Pro ou específicas da loja, ou código personalizado.

### Falha de permissão vs. falha de token {#permission-failure-vs-token-failure}

O frontend do POS pode exibir o mesmo erro de atualização de token nos dois casos: ele recebe um `401` ou `403`, tenta atualizar o token e a nova tentativa continua não autorizada. Os dois tipos de falha se apresentam de formas diferentes no servidor:

Uma **falha real de função/capacidade** geralmente se apresenta assim:

```text
status: 403
current_user: <actual user id>
access token expired: false
```

Uma **falha de token/autenticação** geralmente se apresenta assim:

```text
status: 403
current_user: 0
access token expired: true or invalid
```

Use essa distinção ao fazer a triagem de problemas de acesso ao POS — um `current_user` diferente de zero aponta para as capacidades, enquanto `current_user: 0` aponta para a camada de autenticação/token.
