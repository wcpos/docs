# DB01003: Transação Falhou {#db01003-transaction-failed}

## O que Isso Significa {#what-this-means}

Uma transação de banco de dados não pode ser concluída. Transações agrupam múltiplas operações — se alguma parte falhar, tudo é revertido para manter a integridade dos dados.

## Causas Comuns {#common-causes}

- **Acesso concorrente** — Várias operações tentando modificar os mesmos dados
- **Armazenamento cheio** — Sem espaço para gravar novos dados
- **Banco de dados bloqueado** — Outro processo está bloqueando o banco de dados
- **Interrupção de energia** — Operação interrompida inesperadamente

## Como Corrigir {#how-to-fix}

### 1. Tente Repetir a Operação {#1-retry-the-operation}

O problema pode ser temporário:
- Espere um momento
- Tente a operação novamente
- Evite tentativas rápidas e repetidas

### 2. Verifique Conflitos {#2-check-for-conflicts}

Se vários dispositivos ou abas estão abertas:
- Use uma instância por vez
- Feche as abas duplicadas do navegador
- Coordene o uso em múltiplos dispositivos

### 3. Verifique o Espaço de Armazenamento {#3-check-storage-space}

Garanta que há espaço para dados:
- Verifique o espaço disponível em disco
- Libere espaço se necessário
- Limpe o cache do navegador na versão web (desmarque “Cookies e outros dados do site” — essa opção armazena os dados salvos do POS, inclusive tudo o que ainda não foi enviado)

### 4. Reinicie o Aplicativo {#4-restart-the-application}

Redefina o estado do banco de dados:
1. Feche completamente o POS
2. Espere alguns segundos
3. Reabra o aplicativo

### 5. Limpar e Re-sincronizar {#5-clear-and-re-sync}

:::warning Verifique se há trabalho não salvo
Limpar os dados locais ou reinstalar o aplicativo exclui tudo neste dispositivo que ainda não chegou à sua loja — incluindo vendas feitas offline, carrinhos abertos e edições que não foram salvas. Antes de limpar qualquer coisa, abra **Saúde da loja → Banco de dados** e confirme que nada está listado como retido ou como ainda não tendo chegado ao servidor; depois, confira em **Saúde da loja → Logs** se há **0 registros travados** e **0 alterações aguardando envio**. Em seguida, finalize ou anote todos os carrinhos abertos. Se o WCPOS não tiver uma página Saúde da loja, atualize o WCPOS primeiro e verifique novamente. Se houver algo listado ou aguardando, ou se você não puder verificar, não limpe — fale com o responsável pela loja ou entre em contato com o suporte.
:::

Somente se as transações continuarem falhando após todas as outras etapas desta página e depois de fazer a verificação acima:
1. Limpe os dados locais
2. Faça login novamente
3. Sincronize os dados frescos do servidor

## Segurança da Transação {#transaction-safety}

O WCPOS usa transações para garantir:
- Consistência dos dados
- Operações completas (tudo ou nada)
- Proteção contra atualizações parciais

Quando uma transação falha, seus dados permanecem consistentes.
