## O que isso significa {#what-this-means}

Um campo de um registro foi rejeitado pela sua loja. Ocasionalmente, este código também indica uma solicitação de configuração ou autenticação recusada pela loja.

Se ele mencionar um registro, corrija o campo indicado e tente novamente; a cópia local continuará disponível até ser sincronizada. Caso contrário, siga a mensagem da loja para a solicitação indicada.

## Seus dados {#your-data}

Se foi uma alteração em um registro, ela ainda está salva neste dispositivo e não chegou à sua loja. Uma solicitação de configuração ou autenticação não deixa nada para salvar.

## Solução de problemas {#troubleshoot}

1. Expanda a entrada de log e verifique primeiro o endpoint e a resposta do servidor: este código também pode representar um HTTP 400 vindo de uma requisição de configurações, de autenticação ou de outro tipo que não seja de registro.
2. Se o contexto indicar um registro ou um campo, edite esse campo no POS — as causas mais comuns são um valor fora do intervalo, um formato recusado ou uma opção obrigatória deixada em branco — e tente novamente.
3. Se não for uma solicitação de registro, siga a mensagem do servidor para o endpoint indicado. As ferramentas de desenvolvedor do navegador (aba Rede) — ou **Avançado → Alternar ferramentas de desenvolvedor** no aplicativo para desktop — mostram a resposta quando os detalhes não aparecem no log do POS.
4. **Administrador do site:** se um campo indicado parecer correto no POS, compare-o com o mesmo registro no WP Admin — uma validação adicionada por um plugin na loja pode rejeitar valores que o POS considera válidos.
