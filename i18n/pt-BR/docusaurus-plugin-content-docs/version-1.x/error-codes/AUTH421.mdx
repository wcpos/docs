## O que isso significa {#what-this-means}

O servidor da loja está bloqueando o token de login em todos os canais que este aplicativo pode usar.

O aplicativo confirmou que a loja está acessível, mas o servidor (ou um firewall, proxy ou plugin de segurança à frente dele) remove o cabeçalho Authorization e também bloqueia o token quando ele é enviado como um parâmetro de URL. Não há uma terceira forma de enviar um token de login, portanto isso deve ser corrigido no servidor.

## O que fazer {#what-to-do}

Exporte os diagnósticos e entre em contato com o suporte. Tente novamente após fazer a alteração acima; tentar novamente sem ela falhará da mesma forma.

## Seus dados {#your-data}

Nenhum dado de pedido ou produto é afetado.

## Solução de problemas {#troubleshoot}

1. Peça à sua hospedagem para permitir que o cabeçalho Authorization passe para o WordPress — no Apache, geralmente é uma única linha: SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1.
2. Se o site usar reescritas de .htaccess, mantenha a linha RewriteRule gerada pelo WordPress que transmite HTTP_AUTHORIZATION — plugins de segurança às vezes a removem.
3. Por trás de um proxy ou CDN, verifique a lista de permissões de cabeçalhos: o cabeçalho de solicitação Authorization deve ser encaminhado à origem.
4. Se um firewall de aplicações web (WAF) estiver filtrando parâmetros de URL, peça à hospedagem para permitir o parâmetro authorization nas rotas REST de /wcpos/.

## Onde procurar {#where-to-look}

Quando o WCPOS consegue salvar este erro, ele é registrado no dispositivo que o gerou. Abra **Saúde da loja → Logs** (o ícone de batimento cardíaco na parte inferior do painel de navegação), encontre a entrada marcada com este código e expanda-a: a linha expandida mostra o motivo em linguagem simples e o contexto capturado no momento da falha. Para uma solicitação da loja, esse contexto pode incluir o próprio código de erro do servidor (`serverCode`), o `status` HTTP ou o `endpoint`; os campos exibidos dependem de onde a falha ocorreu. Ao relatar um problema, use **Copiar informações de depuração** na parte superior da tela de Logs (**Compartilhar informações de depuração** em telefones e tablets) em vez de capturas de tela: essa opção reúne a versão do app, o estado da conexão e os erros mais recentes. Os logs são mantidos por no máximo 30 dias, portanto, colete-os enquanto o problema ainda estiver recente. Copie também qualquer erro do console do navegador que tenha aparecido antes de o POS conseguir gravar sua própria entrada de log.
