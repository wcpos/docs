## O que isso significa {#what-this-means}

Um cache à frente da loja está reproduzindo para todos as respostas de API de uma só pessoa.

Uma camada de cache está servindo respostas armazenadas da API REST sem verificar quem está solicitando: o aplicativo enviou duas sondagens com autenticações diferentes e recebeu a resposta da primeira sondagem nas duas vezes. Em uma loja em produção, isso significa que um operador de caixa poderia ver os dados de outro, então a conexão é bloqueada até que o cache exclua a API da loja. Este é um problema da camada de hospedagem — o próprio WordPress sempre responde por usuário.

Antes de emitir este erro, o app tenta novamente usando uma chave de cache exclusiva em cada solicitação. Quando essa nova tentativa comprova que a chave contorna o cache, o app se conecta e continua enviando a chave; portanto, você só vê este erro quando a tentativa também não conseguiu comprovar que a conexão era segura.

## Seus dados {#your-data}

Os dados neste dispositivo podem estar em risco — não limpe os dados locais. Se o problema persistir, exporte os diagnósticos e entre em contato com o suporte do WCPOS.

## Solução de problemas {#troubleshoot}

1. O app já tentou novamente usando uma chave de cache exclusiva em cada solicitação e ainda assim não conseguiu comprovar que a conexão era segura; por isso, é necessário corrigir o cache na hospedagem.
2. Exclua do cache de página os caminhos da API REST da loja (/wp-json/ e /?rest_route=) — no LiteSpeed, desative o cache de REST ou adicione uma regra de no-cache; no WP Engine, estenda a exclusão do WooCommerce para /wp-json/wcpos; na Sucuri, defina o nível de cache para respeitar o Cache-Control.
3. A API da loja já envia Cache-Control: no-store e Vary: Authorization — a camada de cache está ignorando-os; oriente o host a observar esses cabeçalhos.
4. Após alterar as configurações de cache, limpe o cache antes de reconectar.
