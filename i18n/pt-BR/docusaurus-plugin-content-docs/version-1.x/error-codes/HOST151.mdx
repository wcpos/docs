## O que isso significa {#what-this-means}

O cache do seu provedor de hospedagem pode exibir os dados da loja de uma pessoa para outra.

Nada neste dispositivo será perdido. Peça ao seu provedor de hospedagem para parar de armazenar em cache a API da loja (os endereços `/wp-json/` e `?rest_route=`). Se o WCPOS não conectar, conecte novamente depois.

Uma camada de cache está fornecendo respostas armazenadas da REST API sem verificar quem está fazendo a solicitação: o aplicativo enviou duas verificações com autenticações diferentes e recebeu a resposta da primeira em ambas. Em uma loja ativa, isso significa que um caixa poderia ver os dados de outra pessoa. Este é um problema na camada de hospedagem — o próprio WordPress sempre responde de acordo com o usuário.

Quando isso acontece, o aplicativo tenta novamente usando uma chave de cache exclusiva em cada solicitação. Se isso comprovar que a chave consegue passar pelo cache, o WCPOS se conecta e continua enviando a chave — esta entrada é então um aviso de que o cache ainda precisa ser corrigido. Se não for possível comprovar uma conexão segura, o WCPOS não se conecta até que o cache seja corrigido.

## Seus dados {#your-data}

Nada neste dispositivo será perdido. Se o WCPOS não conseguiu comprovar uma conexão segura, ele não se conecta, em vez de correr o risco de exibir os dados de uma pessoa para outra; tudo o que já está neste dispositivo permanece nele e será enviado quando a conexão for estabelecida.

## Solução de problemas {#troubleshoot}

**Para o provedor de hospedagem ou administrador do site** — o cache precisa ser corrigido no provedor, mesmo que o WCPOS tenha se conectado contornando o problema:

1. Exclua os caminhos da REST API da loja (/wp-json/ e /?rest_route=) do cache de páginas — no LiteSpeed, desative o cache REST ou adicione uma regra para não armazenar em cache; no WP Engine, amplie a exclusão do WooCommerce para /wp-json/wcpos e a forma ?rest_route=; no Sucuri, configure o nível de cache para respeitar Cache-Control.
2. A API da loja já envia Cache-Control: no-store e Vary: Authorization — a camada de cache está ignorando-os; oriente o host a observar esses cabeçalhos.
3. Depois de alterar as configurações de cache, limpe o cache. Se o WCPOS não conectar, conecte novamente.
