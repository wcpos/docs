## O que isso significa {#what-this-means}

Alguns registros foram sincronizados, mas um ou mais não foram.

Este código aparece de duas formas — o título da linha do log indica qual delas ocorreu:

- **"Sync partial"** (títulos de registros): alguns registros foram sincronizados, mas os registros indicados não. Confira cada registro indicado e o motivo antes de tentar sincronizar somente esses registros novamente.
- **"Gave up on a stuck data request"**: o fluxo de solicitações de dados do mecanismo de sincronização parou de avançar em uma solicitação; após aguardar bastante, o aplicativo a abandonou para que ela não bloqueasse tudo o que estava na fila. Não é necessário tentar novamente manualmente — o mecanismo de sincronização reenvia a solicitação automaticamente — e isso costuma ocorrer após uma chamada ao banco de dados local ficar travada, registrada separadamente como [SYNC181](/error-codes/SYNC181).

## Seus dados {#your-data}

Para registros que não foram sincronizados: a alteração está salva neste dispositivo, mas ainda não chegou à sua loja. Se isso persistir, exporte os diagnósticos e entre em contato com o suporte do WCPOS. Para uma solicitação de dados abandonada: nada foi alterado — a solicitação é reenviada automaticamente.

## Solução de problemas {#troubleshoot}

1. Em uma sincronização parcial: expanda a entrada do log para ver quais registros não foram sincronizados e o motivo informado para cada um.
2. Trate cada registro indicado conforme o motivo dele — um campo inválido precisa de edição; um conflito precisa de comparação com a loja.
3. Repita apenas os registros que falharam; os demais já estão sincronizados e não precisam de nada.
4. Para uma entrada "Gave up on a stuck data request", nenhuma ação é necessária, a menos que a tela permaneça travada — nesse caso, recarregue o aplicativo e, se o problema continuar, exporte as informações de depuração e entre em contato com o suporte.
