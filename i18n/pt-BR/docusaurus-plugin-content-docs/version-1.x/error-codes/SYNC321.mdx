## O que isso significa {#what-this-means}

Alguns dados não foram sincronizados desta vez.

Este código aparece de duas formas — o título da linha do log indica qual delas ocorreu:

- **"Sync partial"** (títulos dos registros): alguns registros foram sincronizados, mas os registros indicados não. Não é preciso fazer nada se a próxima sincronização resolver o problema. Se **Saúde da loja → Banco de dados** listar alterações que precisam de atenção, resolva-as ali.
- **"Gave up on a stuck data request"**: o fluxo de solicitações de dados do mecanismo de sincronização parou de avançar em uma solicitação; após aguardar bastante, o aplicativo a abandonou para que ela não bloqueasse tudo o que estava na fila. Não é necessário tentar novamente manualmente — o mecanismo de sincronização reenvia a solicitação automaticamente — e isso costuma ocorrer após uma chamada ao banco de dados local ficar travada, registrada separadamente como [SYNC181](/error-codes/SYNC181).

## Seus dados {#your-data}

Não limpe os dados deste dispositivo: pode haver alterações que ainda não chegaram à sua loja. Se uma solicitação de dados foi abandonada, nada foi alterado: ela será enviada novamente automaticamente. Se isso continuar acontecendo, use **Copiar informações de depuração** na aba **Logs** e entre em contato com o suporte do WCPOS.

## Solução de problemas {#troubleshoot}

1. Para uma entrada **"Gave up on a stuck data request"**, não é preciso fazer nada, a menos que uma tela continue travada. Nesse caso, recarregue o app — na web, recarregue a aba do navegador; em computadores e dispositivos móveis, feche e abra o app novamente.
2. Em uma sincronização parcial, não é preciso fazer nada se a próxima sincronização resolver o problema. Caso contrário, abra **Saúde da loja → Banco de dados**: os registros que ainda não foram sincronizados aparecem no topo. O aviso **"… registros precisam de atenção"** identifica o primeiro e informa o motivo (corrija-o para ver o próximo); os painéis **"… alterações que nunca chegaram ao seu servidor"** e **"… alterações foram retidas"** listam os demais. Não é preciso fazer nada com os registros sincronizados.
3. Resolva cada registro listado de acordo com seu motivo. No aviso, **Corrigir registro** (quando exibido) abre o registro para edição; corrija uma alteração recusada no próprio registro ([SYNC201](/error-codes/SYNC201)); para uma alteração retida, escolha qual versão manter ([SYNC221](/error-codes/SYNC221)).
4. Depois, envie-os novamente: use **Tentar novamente** no aviso (isso executa uma sincronização) ou **Enviar novamente** na linha do registro nos painéis. Um registro que o aviso informa que *não pode ser baixado da sua loja* não tem **Tentar novamente**: consulte [SYNC331](/error-codes/SYNC331).
5. Se um registro ainda não for sincronizado, use **Copiar informações de depuração** na aba **Logs** e entre em contato com o suporte.
