Os modelos HTML sem lógica e os modelos XML térmicos do WCPOS são renderizados a partir da mesma carga útil canônica de recibo. Use caminhos com ponto do Mustache, como `{{order.number}}`, `{{store.name}}` e `{{totals.total_display}}`. Os arrays são renderizados com seções:

```mustache
{{#lines}}
  {{name}} x {{qty}} — {{line_total_display}}
{{/lines}}
```

O contrato canônico é produzido no servidor pelo construtor de dados de recibo do WCPOS e espelhado pelo renderizador de recibos offline no aplicativo. Os recibos são abertos imediatamente a partir dos dados locais e, quando disponível, são atualizados com a resposta do servidor; portanto, os modelos personalizados devem usar os campos abaixo em vez de métodos de pedido PHP.

Os dados de recibo v1.1 adicionam campos registrados de preço normal, preço de venda antes do cupom e economia para cada linha de produto. Também fornecem totais de economia no nível do pedido, incluindo um valor de **Total economizado** que combina a economia do preço normal com os descontos do WooCommerce sem alterar os totais ou relatórios do pedido.

Os dados de recibo v1.2 adicionam `discount_type` a cada linha de desconto: o tipo de cupom do WooCommerce por trás do desconto.

## Estender os dados do recibo {#extending}

O WCPOS mantém o contrato acima independente de fornecedores. Quando um plugin precisa incluir no recibo algo que o WooCommerce não modela, ele mesmo o adiciona pelo filtro `woocommerce_pos_receipt_data`, assim como os plugins filtram os totais dos pedidos do próprio WooCommerce. O filtro é executado em todos os recibos criados pelo servidor: recibos em tempo real, instantâneos fiscais no momento do pagamento, downloads de PDF e modelos PHP legados.

```php
add_filter( 'woocommerce_pos_receipt_data', function ( array $data, WC_Abstract_Order $order, string $mode ) {
    foreach ( $data['discounts'] as &$row ) {
        if ( 'smart_coupon' === $row['discount_type'] ) {
            $row['gift_card'] = true;
        }
    }
    return $data;
}, 10, 3 );
```

Um modelo pode então verificar a nova chave em uma seção como qualquer outra:

```
{{#discounts}}
  {{#gift_card}}Gift Card{{/gift_card}}{{^gift_card}}{{i18n.discount}}{{/gift_card}}{{#label}}: {{label}}{{/label}}
{{/discounts}}
```

As chaves definidas no esquema devem manter seus tipos documentados. As chaves adicionadas não fazem parte do esquema; portanto, não aparecem no seletor de campos do editor de modelos, e os instantâneos fiscais só contêm os dados adicionados pelo filtro no momento em que o pedido foi pago. O filtro está disponível a partir do WCPOS 1.10.8.

## Regras de renderização {#rendering-rules}

### Campos de moeda {#currency-fields}

Os campos monetários numéricos são preservados como números, e o renderizador adiciona campos `_display` adaptados à localidade para a saída do modelo:

| Campo numérico | Campo de exibição |
|---------------|---------------|
| `totals.total` | `totals.total_display` |
| `lines[].line_total` | `lines[].line_total_display` |
| `payments[].amount` | `payments[].amount_display` |
| `tax_summary[].tax_amount` | `tax_summary[].tax_amount_display` |

Prefira os campos `_display` ao imprimir recibos. Use os campos numéricos apenas em seções condicionais ou em saídas legíveis por máquina.

### Campos que consideram a exibição de impostos {#tax-display-aware-fields}

Vários campos têm variantes com e sem impostos, além de um valor de conveniência para exibição. Esse valor segue a configuração de exibição de impostos no carrinho da loja.

| Campo de conveniência | Campo com impostos | Campo sem impostos |
|-------------------|-----------------|-----------------|
| `lines[].regular_price` | `lines[].regular_price_incl` | `lines[].regular_price_excl` |
| `lines[].selling_price` | `lines[].selling_price_incl` | `lines[].selling_price_excl` |
| `lines[].unit_savings` | `lines[].unit_savings_incl` | `lines[].unit_savings_excl` |
| `lines[].line_regular_total` | `lines[].line_regular_total_incl` | `lines[].line_regular_total_excl` |
| `lines[].line_selling_total` | `lines[].line_selling_total_incl` | `lines[].line_selling_total_excl` |
| `lines[].line_savings` | `lines[].line_savings_incl` | `lines[].line_savings_excl` |
| `lines[].unit_price` | `lines[].unit_price_incl` | `lines[].unit_price_excl` |
| `lines[].unit_subtotal` | `lines[].unit_subtotal_incl` | `lines[].unit_subtotal_excl` |
| `lines[].line_subtotal` | `lines[].line_subtotal_incl` | `lines[].line_subtotal_excl` |
| `lines[].discounts` | `lines[].discounts_incl` | `lines[].discounts_excl` |
| `lines[].line_total` | `lines[].line_total_incl` | `lines[].line_total_excl` |
| `fees[].total` | `fees[].total_incl` | `fees[].total_excl` |
| `shipping[].total` | `shipping[].total_incl` | `shipping[].total_excl` |
| `discounts[].total` | `discounts[].total_incl` | `discounts[].total_excl` |
| `totals.subtotal` | `totals.subtotal_incl` | `totals.subtotal_excl` |
| `totals.discount_total` | `totals.discount_total_incl` | `totals.discount_total_excl` |
| `totals.sale_savings_total` | `totals.sale_savings_total_incl` | `totals.sale_savings_total_excl` |
| `totals.total_saved` | `totals.total_saved_incl` | `totals.total_saved_excl` |
| `totals.total` | `totals.total_incl` | `totals.total_excl` |

### Objetos de data {#date-objects}

Os campos de data são objetos com diversas variantes pré-formatadas. Isso evita formatar datas dentro do Mustache.

| Campo | Descrição |
|-------|-------------|
| `datetime`, `date`, `time` | Strings padrão de data/hora |
| `datetime_short`, `datetime_long`, `datetime_full` | Formatos combinados adaptados à localidade |
| `date_short`, `date_long`, `date_full` | Formatos apenas de data adaptados à localidade |
| `date_ymd`, `date_dmy`, `date_mdy` | Formatos de data com ordem fixa |
| `weekday_short`, `weekday_long` | Nomes dos dias da semana |
| `day`, `month`, `month_short`, `month_long`, `year` | Partes individuais da data |

Objetos de data disponíveis: `order.created`, `order.paid`, `order.completed`, `order.printed` e `refunds[].date`. `order.printed` é atualizado no momento da renderização, o que é útil para reimpressões.

| `shipping` | array | Linhas de entrega |
| `discounts` | array | Linhas de cupons/descontos |
| `totals` | objeto | Totais do pedido, totais de pagamento, resumo de reembolsos e contagem de itens |
| `tax` | objeto | Indicadores do modo de exibição de impostos para seções condicionais |

## Como os preços se relacionam {#price-model}

Uma linha de produto contém vários preços, cujos nomes ficam mais claros quando vistos nos próprios valores. Esta é a linha de espresso do pedido de exemplo — um produto de $17.00 em promoção por $14.50, com mais um cupom de 10%:

<PriceFlow
  caption="Grãos de espresso — uma unidade (o pedido contém duas)"
  scaleLabel="preço normal 17.00"
  segments={[
    { kind: 'paid', amount: 13.05, label: "13.05 pago" },
    { kind: 'coupon', amount: 1.45, label: "1.45" },
    { kind: 'savings', amount: 2.5, label: "2.50" },
  ]}
  summary={[
    { label: "Economia com promoções em todo o pedido", value: '`totals.sale_savings_total` = 5.00' },
    { label: "Todos os descontos de cupons no pedido", value: '`totals.discount_total` = 5.28' },
    { label: "Economia + descontos, sem sobreposição legada", value: '`totals.total_saved` = 10.28' },
  ]}
/>

A economia com promoções e os descontos de cupons são coisas diferentes: a economia com promoções compara o preço de venda com o preço normal registrado, enquanto `discounts` representa os cálculos de cupons do próprio WooCommerce. Os totais e relatórios de pedidos do WooCommerce incluem apenas a parte dos cupons — por isso, `total_saved` existe como o valor único, exibido ao cliente, que combina ambos.

### Exibição do preço normal e da economia {#displaying-regular-price-and-savings}

Para um layout de preço unitário, mostre o preço normal registrado, o preço de venda e a economia assim:

```mustache
{{#lines}}
  {{#unit_savings}}
    <span style="text-decoration: line-through;">{{regular_price_display}}</span>
    <span>{{selling_price_display}}</span>
    <span>{{i18n.savings}}: -{{unit_savings_display}}</span>
  {{/unit_savings}}
{{/lines}}
```

Use os campos de total da linha quando a quantidade importar:

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    <span>{{i18n.savings}}: -{{line_savings_display}}</span>
  {{/line_savings}}
{{/lines}}
```

`selling_price` é o preço antes dos cupons. Use `unit_price` ou `line_total` para o valor final após os descontos do WooCommerce.

:::note Reimpressão de pedidos criados antes da v1.9.0
Pedidos mais antigos do WCPOS podem já incluir a redução do preço normal para o preço de venda em `discounts`. Se seu modelo personalizado imprimir tanto a economia da linha quanto os descontos da linha, use `savings_in_discounts` para evitar mostrar a mesma redução duas vezes:

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    {{^savings_in_discounts}}
      <span>{{i18n.savings}}: -{{line_savings_display}}</span>
    {{/savings_in_discounts}}
  {{/line_savings}}
  {{#discounts}}
    <span>{{i18n.discount}}: -{{discounts_display}}</span>
  {{/discounts}}
{{/lines}}
```

Se o modelo não imprimir uma linha de `discounts` por item, continue exibindo `line_savings` mesmo quando `savings_in_discounts` for verdadeiro. Os modelos incluídos tratam dessa distinção automaticamente.
:::
