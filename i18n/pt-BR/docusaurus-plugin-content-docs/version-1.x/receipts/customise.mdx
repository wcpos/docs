Se você deseja alterar a aparência do seu recibo, há três opções. Escolha a mais simples que atenda à sua necessidade — a maioria das lojas nunca precisa ir além da primeira.

## Três formas de personalizar {#three-ways-to-customise}

<FeatureGrid>
  <FeatureCard icon="grid" title="1. Escolha um modelo diferente">
    Use um dos modelos prontos na galeria. **Sem nenhum código.** Ideal para: um layout diferente, ocultar preços, uma fatura A4, uma comanda de cozinha.
  </FeatureCard>
  <FeatureCard icon="sparkles" title="2. Peça à IA para ajustar">
    Cole o modelo no ChatGPT ou Claude e descreva o que deseja. **Não é necessário saber programar** — basta descrever em linguagem simples. Ideal para: pequenos ajustes como textos, cores ou reposicionamento de elementos.
  </FeatureCard>
  <FeatureCard icon="code" title="3. Edite manualmente">
    O editor integrado permite alterar o modelo diretamente. Ideal para: controle preciso ou se você já conhece HTML.
  </FeatureCard>
</FeatureGrid>

Todos os três começam no mesmo lugar: **WP Admin → POS → Modelos**. A página tem duas partes — **Seus Modelos** no topo (os que você está usando no momento) e a **Galeria de Modelos** abaixo (a biblioteca de modelos iniciais).

## Opção 1 — Escolher um modelo diferente {#option-1--pick-a-different-template}

Este é o caminho mais fácil e atende a maioria das necessidades.

<Steps>
  <StepCard number="1" title="Abrir a galeria de modelos">

No WP Admin, acesse **POS → Modelos**. Role a página além de *Seus Modelos* até a seção **Galeria de Modelos** — essa é a biblioteca inicial.

  </StepCard>
  <StepCard number="2" title="Explorar e visualizar">

Filtre por **categoria** (Recibo, Fatura, Recibo de Presente, Comanda de Cozinha, Orçamento / Ordem de Compra), **formato** (HTML para impressão no navegador, Térmico para impressoras térmicas) ou **direção** (Da esquerda para a direita ou Da direita para a esquerda). Clique na miniatura de qualquer cartão — ou no link **Visualizar** no rodapé — para abrir uma pré-visualização ao vivo com os dados reais da sua loja.

  </StepCard>
  <StepCard number="3" title="Usar" isLast>

Clique em **Usar Modelo** no cartão. O WCPOS cria uma cópia editável e a adiciona em **Seus Modelos** no topo da página. Ative o botão **Ativo** na linha para começar a usá-lo nos recibos; arraste a alça da linha para reordenar. É possível ter vários ativos ao mesmo tempo — o operador de caixa escolhe no momento da venda.

  </StepCard>
</Steps>

:::tip Usar Modelo nunca substitui nada
Clicar em **Usar Modelo** sempre cria uma nova cópia. O modelo original da galeria permanece intacto, permitindo voltar e escolher um ponto de partida diferente a qualquer momento. Se vários modelos de recibo estiverem ativos, a tela de recibo exibe um menu suspenso para que o operador de caixa alterne entre eles na hora.
:::

### Os modelos inclusos {#the-bundled-templates}

| Modelo | Formato | Finalidade |
|---|---|---|
| **Recibo Padrão** | HTML | Padrão — logotipo, itens, totais, pagamento. Atende a maioria das lojas |
| **Recibo Padrão (RTL)** | HTML | Igual ao Padrão, espelhado para árabe / hebraico / persa / urdu |
| **Minimalista / Moderno** | HTML | Mesmas informações do Padrão, em menos espaço vertical |
| **Recibo Detalhado** | HTML | Nota fiscal completa — coluna de SKU, preço unitário, detalhamento de impostos por alíquota, endereços |
| **Recibo de Presente** | HTML | Apenas itens — preços ocultos. Inclui mensagem de presente e política de devolução |
| **Fatura** | HTML | Fatura em página inteira A4/Carta. Adiciona um painel "Como pagar" para pedidos não pagos |
| **Romaneio** | HTML | Documento para o depósito — itens + quantidades, endereço de entrega, sem preços |
| **Orçamento / Estimativa** | HTML | Documento pré-venda com preços e condições — sem seção de pagamento |
| **Recibo Estreito** | HTML | Recibo em fonte monoespaçada para papel estreito ou impressoras térmicas compatíveis com HTML |
| **Recibo Térmico Simples (58mm)** | Térmico | Layout térmico limpo de 58mm |
| **Recibo Térmico Simples (80mm)** | Térmica | Layout térmico limpo de 80mm — o mais comum |
| **Recibo Térmico Simples 80mm (RTL)** | Térmica | Versão RTL para 80mm. Requer uma impressora com codepage árabe |
| **Recibo Térmico Detalhado (58mm / 80mm)** | Térmica | Inclui detalhamento de impostos, endereços, reembolsos, pagamentos, termos e código de barras |
| **Comanda de Cozinha** | Térmica | Apenas itens, fonte grande, sem preços — para estações de preparo |

A maioria dos modelos inclusos **se adapta automaticamente às configurações de impostos da sua loja** — lojas com impostos inclusos exibem preços brutos e uma linha "Impostos inclusos"; lojas com impostos não inclusos exibem preços líquidos com os impostos adicionados em uma linha separada. A família **Detailed** sempre exibe um detalhamento completo de impostos, independentemente da configuração.

### Modelos de fatura e romaneio do WP Overnight {#wp-overnight-invoice-and-packing-slip-templates}

Se o seu site também utiliza o [PDF Invoices & Packing Slips for WooCommerce](https://wordpress.org/plugins/woocommerce-pdf-invoices-packing-slips/) do WP Overnight, o WCPOS adiciona automaticamente dois modelos extras em **Seus Modelos**:

| Modelo | Formato | Finalidade |
|---|---|---|
| **Fatura (WP Overnight)** | HTML renderizado no servidor | Usa o documento de fatura configurado no WP Overnight para o pedido do POS |
| **Romaneio (WP Overnight)** | HTML renderizado no servidor | Usa o documento de romaneio configurado no WP Overnight para o pedido do POS |

Esses modelos não copiam os layouts de fatura ou romaneio integrados do WCPOS. Eles solicitam ao WP Overnight a renderização do documento para o pedido do POS, de modo que os números de fatura existentes, a identidade visual, os campos legais/fiscais e as personalizações dos modelos do WP Overnight permaneçam consistentes entre pedidos online e na loja.

Eles aparecem apenas enquanto o plugin WP Overnight está ativo. O resultado é aberto como HTML na tela de impressão do WCPOS, em vez de ser baixado como um PDF separado. Como o documento é renderizado no servidor, o POS precisa de uma conexão com seu site para imprimir esses modelos; use os modelos HTML ou térmicos incluídos para imprimir offline.

## Atribuições por loja {#per-store-assignments}

Se você tiver mais de uma [loja](/1.x/stores) (Pro), cada loja pode ter sua **própria seleção e ordenação de modelos**, separada dos padrões globais do site. A cafeteria da esquina pode usar um recibo térmico pequeno com logotipo e endereço diferentes; o depósito pode usar um romaneio; a loja principal pode manter o recibo padrão — tudo a partir da mesma galeria de modelos.

Acesse **WP Admin → POS → Lojas** e abra a loja que deseja configurar. A página **Editar Loja** tem uma seção **Modelos de Recibo** com a opção *"Modelos de recibo específicos da loja"*:

- **Desativado** *(padrão)* — a loja herda a lista global de modelos da página principal **POS → Modelos**.
- **Ativado** — a loja recebe sua própria seleção e ordenação de modelos, separada dos padrões globais do site. A reordenação por arrastar funciona da mesma forma.

A mesma página Editar Loja também contém o **papel timbrado** de cada loja (logotipo, endereço, dados de contato e o bloco *Mensagens do Recibo* — Encerramento, Política de Devolução, Rodapé). Os modelos incluídos usam esses campos de cada loja, de modo que um único modelo "Recibo Padrão" pode ter identidades visuais diferentes em locais diferentes.

Quando um operador de caixa faz login em uma loja, apenas os modelos ativos daquela loja aparecem no menu suspenso de recibos.

:::tip Global ou por loja
A página **Modelos** no WP Admin define o padrão para todo o site. A configuração específica por loja permite que um único modelo (por exemplo, um Recibo Padrão) tenha identidades visuais diferentes em locais diferentes, ou que uma loja use um layout que as outras não usam. Se todas as suas lojas usam os mesmos modelos, basta deixar as atribuições por loja vazias para que os padrões globais do site sejam aplicados.
:::

## Opção 2 — Peça à IA para ajustar {#option-2--ask-ai-to-tweak-it}

Se um modelo da galeria estiver próximo do que você precisa, mas ainda precisar de ajustes, um assistente de IA pode alterá-lo para você em minutos — e você não precisa saber HTML.

<Steps>
  <StepCard number="1" title="Copiar o modelo">

Abra o modelo que deseja usar como base em **WP Admin → POS → Modelos**, clique no editor e selecione todo o texto do lado esquerdo (Ctrl/Cmd + A). Copie-o.

  </StepCard>
  <StepCard number="2" title="Colar no ChatGPT ou Claude">

Abra o [ChatGPT](https://chat.openai.com) ou o [Claude](https://claude.ai). Cole o modelo e escreva o que deseja, em linguagem simples:

  </StepCard>
  <StepCard number="3" title="Descrever o que alterar">

Diga à IA exatamente o que você deseja. Exemplos que funcionam bem:

- *"Aumente o nome da loja e centralize-o."*
- *"Adicione uma mensagem de agradecimento em itálico no final."*
- *"Oculte o nome do cliente. Em vez disso, adicione o número de telefone abaixo do número do pedido."*
- *"Altere o código de barras para um QR code que direcione para minha página de devoluções."*
- *"Adicione o slogan 'Empresa familiar desde 1987' abaixo do nome da loja."*

A IA retornará um modelo modificado.

  </StepCard>
  <StepCard number="4" title="Cole de volta" isLast>

Copie a resposta da IA. De volta ao editor de modelos do WCPOS, selecione tudo (Ctrl/Cmd + A), cole a nova versão e clique em **Atualizar**. A pré-visualização à direita será atualizada para você conferir o resultado. Se não estiver como esperado, peça à IA para corrigir — descreva o que deu errado.

  </StepCard>
</Steps>

:::tip Boa prática
Cada clique em **Usar Modelo** na galeria cria uma nova cópia editável, mantendo o original intacto. Se estiver experimentando, você pode usar o mesmo modelo da galeria mais de uma vez — renomeie suas cópias *(Recibo v1, Recibo v2)* e alterne entre elas enquanto decide.
:::

:::info E as variáveis?
Os trechos como `{{store.name}}` e `{{order.number}}` são **espaços reservados** para seus dados reais. A IA entende esses marcadores — você não precisa entendê-los. Se quiser conhecer todos os espaços reservados disponíveis, consulte a [Referência de Dados do Recibo](/1.x/receipts/receipt-data).
:::

## Opção 3 — Editar manualmente {#option-3--edit-it-by-hand}

Se você tem conhecimentos básicos de HTML (ou está trabalhando com um desenvolvedor), pode editar o modelo diretamente no editor integrado do aplicativo. O editor oferece pré-visualização em tempo real, destaque de sintaxe, seletor de campos com busca, desfazer/refazer e localizar e substituir.

Escolha seu mecanismo de modelos:

- **[Modelos HTML](/1.x/receipts/html-templates)** — Espaços reservados `{{variable}}` no estilo Mustache. Renderiza no lado do cliente e funciona offline. **Recomendado para a maioria das lojas.**
- **[Modelos Térmicos](/1.x/receipts/thermal-templates)** — XML para impressoras térmicas ESC/POS. O mesmo modelo produz tanto a pré-visualização na tela quanto a saída da impressora.
- **[Referência de Dados do Recibo](/1.x/receipts/receipt-data)** — Todos os espaços reservados que você pode usar, agrupados por seção.

:::note Modelos PHP legados
Se você costumava substituir o recibo por um arquivo PHP no seu tema (`yourtheme/woocommerce-pos/receipt.php`), isso ainda funciona. Agora ele aparece como **Modelo PHP Legado** na galeria, ao lado dos novos mecanismos sem lógica e térmico. A integração com WP Overnight também usa a renderização no servidor, porque a API de documentos de terceiros renderiza HTML no servidor. Para novas personalizações, use a galeria ou o editor integrado — eles funcionam offline, oferecem pré-visualização em tempo real e não precisam se comunicar com o servidor a cada renderização.
:::

## Personalizações comuns {#common-customisations}

Respostas rápidas para as perguntas mais frequentes.

<Accordion>
  <AccordionItem question="Como adiciono o logotipo da minha loja?">

Os logotipos vêm das configurações da sua loja, não do próprio modelo. Acesse **WP Admin > POS > Configurações > Lojas**, edite sua loja e envie um logotipo. Todos os modelos incluídos que exibem um logotipo o usarão automaticamente.

Se quiser alterar *onde* o logotipo aparece no modelo, edite o modelo e mova o bloco `{{#store.logo}}<img src="{{store.logo}}" ...>{{/store.logo}}` para onde desejar.

  </AccordionItem>

  <AccordionItem question="Como altero o texto do rodapé (por exemplo, 'Obrigado pela sua compra!')?">

Duas opções:

1. **Mais fácil** — defina uma vez para todos os recibos em **WP Admin > POS > Configurações > Lojas > Detalhes da loja > Rodapé do recibo / nota pessoal**. Os modelos incluídos usam essa configuração automaticamente; se nenhum rodapé estiver definido, usam uma mensagem padrão amigável, como *"Obrigado pela sua compra!"*.
2. **Em um único modelo** — edite o modelo e substitua o texto do rodapé diretamente. Procure `{{store.personal_notes}}` ou a linha com o texto de agradecimento.

  </AccordionItem>

  <AccordionItem question="Como adiciono uma frase ou um slogan abaixo do nome da loja?">

Edite o modelo e adicione uma linha abaixo de `{{store.name}}`:

```html
<div style="font-style: italic; color: #6b7280;">Family-owned since 1987</div>
```

Em um modelo térmico:

```xml
<align mode="center"><text>Family-owned since 1987</text></align>
```

  </AccordionItem>

  <AccordionItem question="Como oculto os preços (para um recibo de presente)?">

Clique em **Usar Modelo** no cartão **Recibo de Presente** da galeria — ele oculta todos os preços e totais, mas mantém os itens, SKU, atributos e a mensagem de presente. Nenhuma edição é necessária.

Se preferir criar seu próprio recibo sem preços, copie qualquer modelo e exclua os blocos `{{...total...}}`, `{{...price...}}` e `{{#totals}}...{{/totals}}`.

  </AccordionItem>

  <AccordionItem question="Como altero o código de barras para um QR code?">

Encontre o elemento `<barcode>` no seu modelo e altere o atributo `type` :

```html
<!-- Default: Code 128 barcode of the order number -->
<barcode type="code128">{{order.number}}</barcode>

<!-- Switch to a QR code -->
<barcode type="qrcode">{{order.number}}</barcode>

<!-- Or encode something else, like a returns URL -->
<barcode type="qrcode">https://example.com/returns?order={{order.number}}</barcode>
```

A mesma sintaxe de `<barcode>` funciona tanto em modelos HTML quanto térmicos. Outros tipos compatíveis incluem `ean13`, `ean8`, `upca`, `pdf417` e [tudo que o bwip-js suporta](https://github.com/metafloor/bwip-js/wiki/Supported-Barcode-Types).

  </AccordionItem>

  <AccordionItem question="Como enviar um modelo diferente para uma impressora específica?">

No app do POS, acesse **POS > Configurações > Impressão** e procure **Modelos de recibo**. Você verá cada um dos seus modelos ativos com um menu suspenso de impressoras ao lado. Escolha a impressora desejada ou deixe como **Automático**.

- **Automático** associa modelos a impressoras automaticamente — modelos térmicos vão para impressoras térmicas, modelos HTML vão para a caixa de diálogo de impressão do sistema.
- Uma **impressora específica** substitui o modo Automático e sempre envia o modelo para ela.
- No momento da impressão, o operador de caixa pode substituir qualquer uma das opções acima usando o menu suspenso de impressora na tela de recibo.

O roteamento é armazenado por dispositivo, então cada iPad ou computador pode ter sua própria configuração.

  </AccordionItem>

  <AccordionItem question="Meu recibo ainda mostra a versão antiga após a edição">

Clique no botão **Atualizar** do WordPress na tela de edição do modelo. O editor não salva automaticamente — suas alterações só são mantidas quando você clica em Atualizar.

Para **modelos PHP legados**, a pré-visualização no editor mostra a *última versão salva*, não o que você está digitando. Salve primeiro e depois atualize a pré-visualização.

  </AccordionItem>

  <AccordionItem question="A pré-visualização está em branco ou exibe 'Nenhum pedido POS encontrado'">

Isso só acontece com **modelos Legacy PHP**, que precisam de um pedido real para gerar a pré-visualização. Processe um único pedido no POS — mesmo uma venda de teste de $0 — e a pré-visualização começará a funcionar.

Modelos Logicless (HTML) e térmicos sempre possuem dados de exemplo como fallback, portanto a pré-visualização funciona normalmente mesmo em uma loja recém-criada.

  </AccordionItem>

  <AccordionItem question="Fiz uma bagunça — como recomeçar do zero?">

Três redes de segurança:

1. O editor possui **Desfazer** (Ctrl/Cmd + Z) para alterações realizadas durante a sessão.
2. Cada salvamento cria uma **revisão** no WordPress — abra **Revisões** na tela de edição para comparar e restaurar qualquer versão anterior.
3. Se você começou a partir de um modelo da galeria, clique em **Excluir** na sua cópia em *Seus Modelos* e depois clique em **Usar Modelo** no mesmo cartão da galeria novamente. Você obterá uma cópia nova e intacta.

  </AccordionItem>
</Accordion>

## Quando pedir ajuda {#when-to-ask-for-help}

- O editor de modelos não carrega ou as alterações salvas não são mantidas.
- O recibo é impresso corretamente em um dispositivo, mas não em outro.
- Você precisa de um layout fiscal/legal para um país específico (Itália, Brasil, Espanha etc.) — esses casos geralmente são atendidos pelo [WCPOS Pro](/1.x/getting-started/pro-license) ou por uma integração específica do país.
- Você está tentando fazer algo personalizado e a IA não consegue acertar.

Abra um [ticket de suporte](https://wcpos.com/support) e cole o modelo com o qual está trabalhando — isso nos fornece tudo o que precisamos para ajudar.
