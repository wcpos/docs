Os modelos térmicos usam um formato XML que gera tanto uma pré-visualização na tela quanto comandos ESC/POS para a impressora a partir do mesmo modelo. Eles usam os mesmos placeholders `{{variable}}` dos [modelos HTML](/1.x/receipts/html-templates) para vinculação de dados.

Escolha este mecanismo se você tiver uma impressora de recibos conectada por meio da [Configuração de Impressora](/1.x/hardware/printers).

## Elementos XML {#xml-elements}

### Elemento Raiz {#root-element}

Todo modelo térmico começa com um elemento `<receipt>` raiz:

```xml
<receipt paper-width="48">
  <!-- 48 characters = 80mm paper -->
  <!-- 32 characters = 58mm paper -->
</receipt>
```

### Texto e Formatação {#text-and-formatting}

```xml
<text>Plain text</text>
<bold>Bold text</bold>
<underline>Underlined text</underline>
<invert>Inverted (white on black)</invert>
```

### Alinhamento {#alignment}

```xml
<align mode="left">Left aligned</align>
<align mode="center">Centered</align>
<align mode="right">Right aligned</align>
```

### Tamanho do Texto {#text-size}

Dimensione a largura e a altura do texto de forma independente:

```xml
<size width="2" height="2">Double-size text</size>
<size width="2" height="1">Wide text</size>
<size width="1" height="2">Tall text</size>
```

### Layout Tabular {#tabular-layout}

Use `<row>` e `<col>` para alinhar colunas:

```xml
<row>
  <col width="24">Item name</col>
  <col width="8" align="right">Qty</col>
  <col width="16" align="right">Price</col>
</row>
```

As larguras das colunas são medidas em caracteres. Use `width="*"` para uma coluna flexível que absorve o espaço restante — isso permite que os modelos funcionem em diferentes larguras de papel sem modificação:

```xml
<row>
  <col width="*">{{name}}</col>
  <col width="12" align="right">{{line_total_display}}</col>
</row>
```

### Separadores e Espaçamento {#separators-and-spacing}

```xml
<line />                       <!-- Default single rule -->
<line style="double" />        <!-- Printer-native double rule -->
<line style="dashed" />        <!-- Character dashes across the width -->
<line style="dotted" />        <!-- Character dots across the width -->
<feed lines="2" />             <!-- Blank lines -->
```

`<line/>` (ou `style="single"`) e `style="double"` imprimem a linha nativa da impressora. `dashed` e `dotted` imprimem separadores baseados em caracteres por toda a largura ativa da coluna — útil quando você quer um separador que permaneça visível em uma captura de tela da pré-visualização térmica.

### Comandos da impressora {#printer-commands}

```xml
<cut />              <!-- Full paper cut -->
<cut mode="partial" /> <!-- Partial cut (leaves a tab) -->
<drawer />           <!-- Open cash drawer -->
```

### Códigos de barras e QR Codes {#barcodes-and-qr-codes}

```xml
<barcode type="code128" height="40">{{order.number}}</barcode>
<barcode type="qrcode" scale="3">{{fiscal.qr_payload}}</barcode>
```

## Exemplo: recibo simples de 80mm {#example-simple-80mm-receipt}

```xml
<receipt paper-width="48">
  <align mode="center">
    <size width="2" height="2">{{store.name}}</size>
  </align>
  <feed lines="1" />
  <align mode="center">
    <text>{{store.address_1}}</text>
    <text>{{store.city}} {{store.state}} {{store.postcode}}</text>
    {{#store.phone}}<text>{{store.phone}}</text>{{/store.phone}}
  </align>
  <line />

  <text>Order: #{{order.number}}</text>
  <text>Date: {{order.created.datetime}}</text>
  {{#cashier.name}}<text>Cashier: {{cashier.name}}</text>{{/cashier.name}}
  <line />

  <!-- Column headers -->
  <row>
    <col width="*"><bold>Item</bold></col>
    <col width="4" align="right"><bold>Qty</bold></col>
    <col width="12" align="right"><bold>Total</bold></col>
  </row>
  <line />

  <!-- Line items -->
  {{#lines}}
  <row>
    <col width="*">{{name}}</col>
    <col width="4" align="right">{{qty}}</col>
    <col width="12" align="right">{{line_total_display}}</col>
  </row>
  {{/lines}}

  <line />

  <!-- Totals -->
  <row>
    <col width="*">Subtotal</col>
    <col width="16" align="right">{{totals.subtotal_display}}</col>
  </row>
  {{#totals.tax_total}}
  <row>
    <col width="*">Tax</col>
    <col width="16" align="right">{{totals.tax_total_display}}</col>
  </row>
  {{/totals.tax_total}}
  <row>
    <col width="*"><bold>TOTAL</bold></col>
    <col width="16" align="right"><bold>{{totals.total_display}}</bold></col>
  </row>

  <line />

  {{#payments}}
  <row>
    <col width="*">{{method_title}}</col>
    <col width="16" align="right">{{amount_display}}</col>
  </row>
  {{#tendered}}
  <row>
    <col width="*">Tendered</col>
    <col width="16" align="right">{{tendered_display}}</col>
  </row>
  <row>
    <col width="*">Change</col>
    <col width="16" align="right">{{change_display}}</col>
  </row>
  {{/tendered}}
  {{/payments}}

  <feed lines="2" />
  <align mode="center">
    <text>Thank you for your purchase!</text>
  </align>
  <feed lines="3" />
  <cut />
</receipt>
```

## Colunas com largura asterisco {#star-width-columns}

O recurso `width="*"` torna os modelos independentes da largura do papel. Em vez de definir larguras de coluna fixas para um tamanho de papel específico, use `*` para a coluna que deve se expandir:

```xml
<!-- Works on 58mm (32 char) AND 80mm (48 char) printers -->
<row>
  <col width="*">{{name}}</col>
  <col width="10" align="right">{{line_total_display}}</col>
</row>
```

Em uma impressora de 80mm (48 caracteres), o nome do item ocupa 38 caracteres. Em uma impressora de 58mm (32 caracteres), ocupa 22 caracteres. As colunas fixas mantêm o mesmo tamanho em ambas.

:::warning Adaptador legado de layout fixo StarPRNT removido
O antigo **adaptador de saída de layout fixo** StarPRNT foi removido na v1.10. Se um modelo dependia dele, substitua-o por um modelo térmico atual (o mecanismo XML desta página), que gera a saída Star usando o layout térmico compartilhado. Recrie o layout com `<row>`/`<col>` e `width="*"` em vez do adaptador fixo.
:::

## Pré-visualização do modelo {#template-preview}

O editor de modelos exibe uma **pré-visualização térmica em tempo real** durante a edição. A pré-visualização renderiza seu XML como HTML monoespaçado estilizado, simulando a aparência do recibo no papel. As alterações são atualizadas após um breve atraso (debounce de 300ms).

O mesmo modelo gera tanto a pré-visualização quanto a saída ESC/POS para a impressora — não há um modelo de "impressão" separado. Códigos de barras e QR Codes são renderizados como SVGs inline na pré-visualização e como comandos ESC/POS nativos (ou imagens rasterizadas) na impressora.

## Dicas e armadilhas na criação de modelos {#authoring-tips-and-pitfalls}

A impressão térmica tem algumas armadilhas que não existem em HTML. Estas são as que os autores encontram com mais frequência.

### Envolva cabeçalhos estilizados em `<text>` para criar uma quebra de linha {#wrap-styled-headings-in-text-for-a-line-break}

Contêineres estilizados — `<bold>`, `<size>`, `<underline>`, `<align>` — **não produzem uma quebra de linha por si só**. Apenas `<text>` e elementos de bloco (`<line/>`, `<row>`, `<feed>`) fazem isso.

```xml
<!-- ❌ Bug: the heading runs together with whatever follows -->
<bold>{{i18n.bill_to}}</bold>
{{customer.name}}

<!-- ✅ Fix: wrap the inner content in <text> -->
<bold><text>{{i18n.bill_to}}</text></bold>
<text>{{customer.name}}</text>
```

Os modelos de 80mm incluídos na galeria usam esse padrão em todos os cabeçalhos.

### Evite `<size width="2">` em linhas estreitas {#avoid-size-width2-inside-narrow-rows}

Texto com largura dupla **dobra a contagem efetiva de caracteres**. Um título que cabe em uma impressora de 80mm pode ultrapassar o limite de uma impressora genérica de 80mm com 42 colunas e, em papel de 58mm, deixa espaço para apenas 16 caracteres.

Para valores em destaque (totais grandes, números de pedidos da cozinha), gere uma linha redimensionada independente em vez de colocá-la em uma estrutura com várias colunas `<row>`:

```xml
<!-- For store names, prefer normal-width, double-height -->
<bold><size height="2"><text>{{store.name}}</text></size></bold>

<!-- For a bold total, put it on its own line above the row -->
<align mode="right">
  <bold><size height="2"><text>{{totals.total_display}}</text></size></bold>
</align>
```

### Use `width="*"` para layouts independentes da largura do papel {#use-width-for-paper-width-agnostic-layouts}

A coluna `width="*"` (asterisco) absorve a largura restante após as colunas de largura fixa. Assim, o mesmo modelo é renderizado corretamente em impressoras de 32 colunas (58mm), 42 colunas (80mm padrão) e 48 colunas (80mm largo) sem modificação:

```xml
<!-- Works on 58mm AND 80mm without changes -->
<row>
  <col width="*">{{name}}</col>
  <col width="10" align="right">{{line_total_display}}</col>
</row>
```

Se você usar larguras numéricas fixas, **planeje-as para 42**, não 48. Linhas que somam 48 serão quebradas nas impressoras comuns de 80mm com 42 colunas.

### Cabeçalhos estilizados centralizados dentro de blocos `<align>` {#centred-styled-headings-inside-align-blocks}

Dentro de `<align mode="center">` (ou `right`), um cabeçalho estilizado direto — `<bold>`, `<size>`, `<underline>`, `<invert>` colocado diretamente dentro de `<align>` — seguido por outra linha é automaticamente encerrado em sua própria linha. Um nome de loja centralizado e redimensionado acima de uma linha de endereço centralizada é impresso corretamente mesmo sem um elemento `<text>` envolvendo o texto.

Fora de um bloco de alinhamento, mantenha o elemento `<text>` envolvendo o texto.

### Normalização de pontuação ESC/POS {#escpos-punctuation-normalisation}

Quando a linguagem da impressora é ESC/POS, o codificador normaliza a pontuação tipográfica para caracteres ASCII seguros antes da escrita:

- Travessão curto, travessão longo, travessão numérico, sinal de menos Unicode → `-`
- Aspas curvas → aspas retas
- Espaço não separável → espaço comum

Assim, `Mon–Sat 9:00–18:00` e `"open"` são impressos corretamente mesmo em impressoras sem fonte Unicode. Impressoras Star (`star-line` / `star-prnt`) **preservam** a tipografia original, portanto use caracteres compatíveis com a fonte da impressora.

### Sistemas de escrita não latinos e da direita para a esquerda {#non-latin-and-rtl-scripts}

Impressoras térmicas imprimem texto usando uma fonte e uma página de códigos integradas, portanto árabe, hebraico, persa, urdu e outros sistemas de escrita não latinos só são impressos corretamente se a impressora estiver configurada com uma página de códigos correspondente (por exemplo, CP864 / Windows-1256 para árabe) — caso contrário, aparecem espaços em branco ou caracteres ilegíveis.

A abordagem confiável para esses sistemas de escrita é **Recibo completo em raster**, que renderiza o recibo inteiro como imagem para que seja impresso exatamente como projetado, independentemente das fontes integradas da impressora. Consulte [Configuração de Impressora](/1.x/hardware/printers) para ativar o modo raster.

:::note Hardware térmico requer um modelo térmico
Uma impressora térmica não consegue imprimir um modelo **HTML** de página inteira — o trabalho precisa ser renderizado em comandos ESC/POS ou Star, que o HTML não consegue expressar. Use um modelo térmico para hardware térmico; para HTML em página inteira A4/Carta, imprima em uma impressora do sistema/PDF ou via [PrintNode](/1.x/receipts/cloud-printing#setup-printnode).
:::

### Logotipos e imagens {#logos-and-images}

Use `<image>` para inserir um logotipo:

```xml
<align mode="center">
  <image src="data:image/png;base64,..." />
</align>
```

O WCPOS rasteriza imagens no cliente — decodifica, substitui a transparência por branco, redimensiona conforme o limite de pontos da impressora, converte para monocromático (dithering Atkinson para logotipos, limiar para códigos de barras) — e então envia comandos de imagem ESC/POS ou Star.

- **Limites de pontos**: 384 pontos de largura para 58mm, 576 pontos de largura para 80mm.
- **Fontes aceitas**: URLs de dados `data:image/png` e `data:image/jpeg`, URLs absolutas `http(s)` e caminhos relativos à raiz da mesma origem. URLs relativas ao protocolo `//`, barras invertidas e travessia de diretórios com `..` codificado em percentual são rejeitadas.
- **Formato recomendado**: PNG de alto contraste com fundo transparente ou branco. JPEG funciona, mas artefatos de compressão podem aparecer como ruído na impressão.
- **SVG ainda não é suportado** para saída térmica bruta.

### Dicas {#tips}

- **Comece a partir de um modelo da galeria** — os modelos térmicos da galeria usam todos os padrões acima e são validados com impressoras reais.
- **Teste ambos os tamanhos de papel** se suas lojas usam impressoras diferentes ou use apenas colunas com `width="*"`.
- **Use os campos `_display`** para valores monetários — eles já consideram a configuração regional.
- **Mantenha a simplicidade** — o formato térmico tem menos ferramentas de formatação que o HTML por definição. Use `<row>` + `<col width="*">` e deixe a impressora fazer o trabalho.
