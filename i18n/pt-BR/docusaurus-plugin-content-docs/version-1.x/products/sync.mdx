O WCPOS mantém uma cópia local dos seus produtos em cada dispositivo, para que o catálogo seja navegado e pesquisado instantaneamente e continue funcionando offline. Este guia explica como os produtos chegam ao dispositivo e como se mantêm atualizados.

:::info Alterado na versão 1.10.0
A versão 1.10.0 introduz um novo motor de sincronização. Se o seu POS for anterior à 1.10.0, veja [O que mudou na versão 1.10.0](#what-changed-in-v1100) abaixo.
:::

## Como os produtos chegam ao dispositivo {#how-products-arrive}

- **Uma carga inicial do catálogo roda em segundo plano.** Desde o primeiro início, o POS baixa seu catálogo em pequenos lotes, de forma programada, sem que você precise fazer nada. Você pode começar a vender assim que os primeiros produtos chegarem — o checkout não espera o download completo.
- **O que você está visualizando é baixado sob demanda.** Pesquisar, filtrar por categoria ou ler um código de barras busca os produtos correspondentes diretamente, caso ainda não estejam locais. Uma busca não traz mais produtos não relacionados junto com ela — ela busca exatamente o que você pediu.
- **As atualizações chegam por verificações de mudanças.** Uma vez que um produto está local, o POS não o baixa de novo só para ver se ele mudou. Ele consulta um registro leve de alterações (a cada 60 segundos na predefinição padrão) e busca apenas o que realmente mudou — uma loja ociosa responde com uma única resposta "nada mudou", praticamente gratuita.

## Qual é o tamanho dos lotes? {#batch-size}

Por padrão, o POS solicita **50 produtos por vez**. Isso não é mais uma constante fixa — é um de dois ajustes definidos pela predefinição de sincronização em **Saúde da loja → Desempenho**:

| Predefinição | Intervalo de verificação | Registros por requisição |
| --- | --- | --- |
| Eco | 5 min | 25 |
| Equilibrado (padrão) | 60 s | 50 |
| Tempo real | 10 s | 75 |

Os lotes pequenos existem para proteger seu servidor: páginas grandes consomem tempo real de servidor para serem montadas e, em hospedagem compartilhada, podem deixar a loja virtual lenta ou atingir limites de requisições. Escolha Eco para hospedagens modestas e Tempo real para lojas com vários caixas em hospedagem robusta. Veja [Saúde da loja](/support/store-health#sync-presets) para mais detalhes.

## Como acompanhar o progresso do download {#checking-progress}

Abra **Saúde da loja → Banco de dados** para ver, por coleção, quantos registros estão neste dispositivo em comparação com o seu servidor, junto de uma barra de cobertura. O número *no servidor* é um total real informado pelo servidor — enquanto o POS ainda o está confirmando, a linha mostra *verificando…* em vez de uma estimativa.

Uma barra de produtos parcial significa apenas que a carga inicial ainda não terminou; ela continuará se preenchendo em segundo plano. Se um produto específico parecer ausente, pesquise por ele — isso o busca diretamente.

:::tip
Se uma coleção parecer travada, use **Limpar e baixar novamente** na linha dela em Saúde da loja → Banco de dados antes de recorrer à redefinição completa de [limpar todos os dados locais](/support/troubleshooting/clear-local-data).
:::

## O que mudou na versão 1.10.0 {#what-changed-in-v1100}

As versões anteriores baixavam o catálogo *progressivamente conforme o uso*: cada busca ou rolagem trazia mais um lote de produtos, e uma consulta completa era executada a cada 5 minutos. Esse modelo foi aposentado. Na versão 1.10.0:

- O catálogo é preenchido por uma carga inicial programada em segundo plano — você não precisa pesquisar nem rolar para que os produtos sejam baixados.
- Uma busca traz os produtos que correspondem a ela, não um próximo lote arbitrário.
- As verificações de mudanças rodam no intervalo da predefinição escolhida (60 segundos por padrão) usando requisições condicionais, em vez de uma consulta completa fixa a cada 5 minutos.
- O progresso do download fica visível por coleção em **Saúde da loja → Banco de dados**.

Desenvolvedores encontram a mecânica completa em [Como funciona o motor de sincronização](/reference/sync-engine).

## Perguntas frequentes {#faq}

<Accordion>
  <AccordionItem question="Preciso fazer algo para baixar meus produtos?">

  Não. A carga inicial do catálogo baixa seus produtos em segundo plano automaticamente. Pesquisar ou filtrar busca produtos específicos imediatamente, caso ainda não estejam locais, mas não é a navegação comum que completa o download — é a carga inicial em segundo plano.

  </AccordionItem>

  <AccordionItem question="Com que rapidez as alterações de produtos chegam ao POS?">

  Na predefinição padrão Equilibrado, o POS verifica se há alterações a cada 60 segundos (as verificações são levemente aleatorizadas para que vários caixas não acessem o servidor ao mesmo tempo). Somente os produtos alterados são buscados. Se vários caixas precisam ver as alterações uns dos outros mais rapidamente, use a predefinição Tempo real.

  </AccordionItem>

  <AccordionItem question="Não consigo ver todos os meus produtos no POS">

  Algumas possibilidades:

  - A carga inicial em segundo plano pode simplesmente não ter terminado — verifique a linha de produtos em **Saúde da loja → Banco de dados**.
  - O POS oculta itens sem estoque por padrão. Isso pode ser alterado nas configurações de exibição de produtos.
  - A API REST do WooCommerce só oferece suporte aos tipos de produto padrão (simples, variável, agrupado, externo). Tipos de produto personalizados podem não aparecer no POS.

  </AccordionItem>
</Accordion>
