Esta tela é exibida somente nos aplicativos para desktop e dispositivos móveis. Quem usa a versão Web acessa o POS diretamente em `yourdomain.com/pos` e faz login com as credenciais do WordPress.

## Visão geral da tela de conexão {#connect-screen-overview}

Ao abrir o aplicativo WCPOS para desktop ou dispositivos móveis, você verá a tela de conexão. Nela, você gerencia as conexões com suas lojas e os logins de usuários.

{/* Screenshot: connect-screen.png */}

## Adicionar uma nova loja {#adding-a-new-store}

1. Insira a URL da sua loja WooCommerce no campo de texto (por exemplo, `https://mystore.com`)
2. Clique em **Conectar**
3. Você será redirecionado para fazer login com suas credenciais do WordPress
4. Após fazer login, você retornará ao aplicativo

## Várias lojas {#multiple-stores}

Você pode se conectar a quantas lojas WooCommerce precisar. Cada loja aparece como um cartão separado na tela Conectar, com:

- **Nome da loja** e favicon
- **URL da loja**
- **Usuários conectados** a essa loja

Isso é útil se você gerencia vários locais ou empresas.

## Vários usuários por loja {#multiple-users-per-store}

Vários usuários podem estar conectados simultaneamente a cada loja. Isso é útil para:

- **Trocas de turno** - O novo caixa pode fazer login antes que o anterior saia
- **Configurações com vários caixas registradores** - Caixas diferentes em dispositivos diferentes
- **Alternância rápida** - Alterne facilmente entre contas de usuário

### Adicionar um usuário {#adding-a-user}

Clique no <Icon name="plus" /> botão ao lado de "Usuários conectados" para adicionar outro usuário a essa loja.

### Alternar usuários {#switching-users}

Clique no selo de um usuário (por exemplo, "Brenda") para abrir o POS como esse usuário.

### Remover um usuário {#removing-a-user}

Clique no **×** no selo do usuário para desconectá-lo da loja.

## Remover uma loja {#removing-a-store}

Clique no botão vermelho **×** no cartão da loja para removê-la da sua lista. Isso desconecta todos os usuários e remove a conexão da loja do aplicativo.

## Loja de demonstração {#demo-store}

Na parte inferior da tela, talvez você veja um link "Entrar na loja de demonstração". Ele conecta você a uma loja WooCommerce de demonstração para testar os recursos do WCPOS sem afetar os dados da sua própria loja.

## Solução de problemas {#troubleshooting}

:::tip Primeiro item a verificar: `X-Frame-Options`
Os aplicativos para desktop e dispositivos móveis usam **iframes** para login, pagamento e recibos. **Qualquer** cabeçalho do servidor ou plugin que envie `X-Frame-Options: DENY` ou `SAMEORIGIN` impedirá o login. Esta é a causa mais comum de falhas de login no aplicativo — antes de qualquer outra coisa, confira os cabeçalhos de resposta da página de login (nas ferramentas de desenvolvedor do navegador ou com `curl -I https://yourstore.com/wp-login.php`).
:::

<Accordion>
  <AccordionItem question="Não consegue se conectar à minha loja?">

  - Verifique se o plugin WCPOS está instalado e ativado no seu site WordPress
  - Confira se você está usando a URL correta (inclua `https://` — a API REST do WooCommerce exige SSL)
  - Tente abrir `yourdomain.com/pos` primeiro em um navegador para confirmar se o plugin está funcionando
  - Verifique se a API REST do WooCommerce está acessível
  - Verifique se sua conta de usuário tem permissões de acesso ao POS

  </AccordionItem>

  <AccordionItem question="O login falha no aplicativo para desktop ou dispositivos móveis">

  A maioria das falhas de login no aplicativo é causada por um plugin de segurança ou cache que bloqueia o iframe de login:

  - **Cabeçalhos `X-Frame-Options`** (definidos por um plugin de segurança ou pelo servidor) bloqueiam o iframe de login — veja a observação acima. Desative temporariamente o plugin de segurança, faça login e ative-o novamente (sua sessão dura cerca de uma semana).
  - **Plugins de segurança** — Wordfence, Really Simple Security, WPS Hide Login, iThemes/Solid Security e Defender Pro são causas comuns. Veja a lista completa e as soluções em [Conflitos entre plugins](/support/troubleshooting/plugin-conflicts#security-and-login-plugins).
  - **Wordfence 2FA** — o campo do código 2FA não é exibido no iframe de login. Por enquanto, desative o 2FA para usuários do POS.
  - **URL de login personalizada** (por exemplo, WPS Hide Login) — o aplicativo não consegue encontrar a página de login. Use a URL padrão `/wp-admin/`.
  - **Plugins de cache** podem continuar exibindo o formulário de login bloqueado mesmo depois que você desativa o plugin problemático — limpe o cache ou limpe o cache do aplicativo / reinstale o aplicativo para desktop.

  </AccordionItem>

  <AccordionItem question='"A REST API requer autenticação" ou um erro de plugin de segurança na tela de conexão'>

  Um plugin (por exemplo, Force Login ou um plugin de autenticação JWT) está exigindo autenticação para todas as solicitações da REST API, então o aplicativo não consegue ler as informações públicas do seu site. Agora, o aplicativo exibe a mensagem real do servidor (por exemplo, _"Somente usuários autenticados podem acessar a REST API"_) em vez de informar incorretamente o tipo de site.

  **Correção:** configure o plugin de segurança para permitir acesso não autenticado a `/wp-json/wcpos/` e `/wp-json/wc/v3/`, ou desative-o apenas pelo tempo necessário para concluir a primeira conexão.

  </AccordionItem>

  <AccordionItem question='"Não parece ser um site WordPress" (aplicativo para desktop)'>

  O aplicativo para desktop localiza a REST API por meio do cabeçalho HTTP `Link`. Se um plugin (com frequência o **Image Prioritizer** ou outros plugins de desempenho) sobrecarregar ou truncar esse cabeçalho, a descoberta falhará. **Correção:** desative os plugins de otimização de imagens ou de desempenho que modificam cabeçalhos e tente novamente.

  </AccordionItem>

  <AccordionItem question="O aplicativo informa que precisa de uma atualização / trava após uma atualização">

  Verifique se há incompatibilidade de versão entre o aplicativo e o plugin do servidor — a loja de aplicativos pode ter disponibilizado uma atualização enquanto o plugin WCPOS ainda precisa ser atualizado (ou vice-versa). Na v1.10, o aplicativo e o plugin WCPOS precisam estar na **linha de lançamento v1.10**, pois o aplicativo usa a API de sincronização v2 do plugin. Se apenas um lado foi atualizado e as solicitações falharem com `rest_no_route`, atualize o outro.

  </AccordionItem>

  <AccordionItem question='Erro "Não foi possível criar o banco de dados rápido da loja"'>

  Isso é uma condição de corrida no primeiro login. **Feche o aplicativo completamente e tente novamente** — geralmente funciona na segunda tentativa.

  </AccordionItem>

  <AccordionItem question="Travado na tela de seleção de usuário (aplicativo para desktop)">

  Após fazer login, você vê seu nome de usuário, mas não há uma opção óbvia para continuar. **Clique no seu nome de usuário/nome** para entrar no POS — o próprio nome é o botão.

  </AccordionItem>

  <AccordionItem question="A conexão continua falhando?">

  - Tente acessar `yourdomain.com/pos` primeiro em um navegador para verificar se o plugin está funcionando
  - Confira se há problemas nos logs de erro do seu site
  - Confirme se o provedor de hospedagem não está bloqueando a REST API — consulte as [observações específicas sobre hospedagem](/support/performance/server#hosting-specific-notes)
  - Verifique se o servidor atende aos [requisitos mínimos](/support/performance/server#minimum-server-requirements)

  </AccordionItem>
</Accordion>
