O WCPOS armazena os dados de produtos e clientes em um banco de dados local em cada dispositivo. Isso significa que partes do POS funcionam sem conexão com a internet, enquanto outras exigem conectividade.

## O que Funciona Offline {#what-works-offline}

- **Navegar por produtos** — pesquisar, filtrar e visualizar detalhes de produtos a partir dos dados locais
- **Navegar por clientes** — consultar nomes, e-mails e endereços de clientes
- **Montar um carrinho** — adicionar itens, alterar quantidades, editar preços e aplicar descontos do POS
- **Aplicar cupons** (Pro) — os códigos são validados localmente com os dados de cupons sincronizados; o servidor revalida quando o pedido enfileirado chega até ele
- **Concluir uma venda com um método de pagamento compatível com o modo offline** — vendas em Dinheiro e em Cartão processadas externamente são salvas localmente e enfileiradas para o WooCommerce
- **Leitura de código de barras** — escanear códigos de barras para encontrar produtos no banco de dados local
- **Visualizar relatórios** — o tipo de relatório padrão (offline) gera relatórios a partir dos pedidos armazenados localmente

## O que Requer Conexão {#what-requires-a-connection}

- **Ações de checkout que dependem do servidor** — o Checkout Web, os gateways online ou de terminal integrados e o **Salvar no Servidor** precisam que seus respectivos serviços estejam acessíveis
- **Sincronizar dados** — baixar novos produtos, preços atualizados ou novos clientes do WooCommerce
- **Fazer login** — a autenticação inicial requer conexão com o seu site WordPress
- **Ativação de licença** — as verificações de licença Pro precisam acessar o servidor de licenças do WCPOS
- **Processar reembolsos** — os reembolsos não podem ser enfileirados offline; o gateway e a sua loja precisam estar acessíveis (veja [Reembolsos](/orders/refunds))

## Como o Banco de Dados Local Funciona {#how-the-local-database-works}

Quando você abre o WCPOS pela primeira vez, ele faz a carga inicial do seu catálogo de produtos em segundo plano e busca os demais dados conforme você usa o POS — você pode começar a vender assim que os primeiros produtos estiverem no dispositivo. A partir daí, uma verificação de mudanças em segundo plano (a cada 60 segundos por padrão, ajustável em [Saúde da loja](/support/store-health)) busca apenas o que mudou no servidor.

O banco de dados local:

- **Persiste entre sessões** — os dados são mantidos após reiniciar o navegador ou o dispositivo
- **É individual por dispositivo (e por operador de caixa)** — cada dispositivo mantém sua própria cópia local; os operadores não compartilham dados locais
- **Permanece sincronizado** — as verificações de mudanças em segundo plano trazem as atualizações; suas alterações são enfileiradas localmente e enviadas ao servidor

Você pode ver exatamente o que está no dispositivo — e o que ainda está aguardando envio — em **Saúde da loja → Banco de dados**. Para mais detalhes técnicos, consulte [Como funciona o motor de sincronização](/reference/sync-engine).

## As Alterações Feitas Offline São Enfileiradas {#offline-writes}

Toda alteração feita no POS — uma venda, a edição de um produto, a atualização de um cliente — é salva primeiro no dispositivo e enfileirada para envio. Enquanto você está offline, a fila simplesmente aguarda; nada se perde ao ficar sem conexão no meio do expediente.

Quando a conexão volta, a fila é drenada automaticamente. Se o seu servidor recusar uma alteração de forma definitiva (algo raro — por exemplo, um registro que o servidor considera inválido), o POS não fica tentando de novo em silêncio para sempre: a alteração é estacionada em **Saúde da loja → Banco de dados**, sob *"alterações que nunca chegaram ao seu servidor"*, com o motivo informado pelo servidor e as ações explícitas **Enviar novamente** / **Descartar**. Veja [Saúde da loja](/support/store-health#refused-changes).

## Indicador de Conectividade {#connectivity-indicator}

O cabeçalho do POS exibe um ponto colorido indicando o status da conexão:

- **Verde** — conectado ao servidor, todos os recursos disponíveis
- **Amarelo** — conexão intermitente, algumas operações podem ficar lentas
- **Vermelho** — offline, limitado aos dados locais

## O Que Acontece Durante a Perda de Conectividade {#what-happens-during-connectivity-loss}

Se a conexão com a internet for perdida durante o uso do POS:

1. **Produtos e clientes permanecem navegáveis** a partir dos dados locais.
2. **É possível continuar montando carrinhos** e editando itens — cada alteração é enfileirada localmente.
3. **Você pode concluir o checkout com um método de pagamento compatível com o modo offline** — a venda entra na fila de saída. Os gateways de pagamento que dependem do servidor permanecem indisponíveis até que seus serviços estejam acessíveis.
4. **Pedidos em aberto são preservados** no banco de dados local até que a conectividade seja restabelecida.

## Quando a Conexão é Restabelecida {#when-connection-restores}

Quando a conexão for restabelecida:

- O indicador de conectividade fica verde.
- **As alterações enfileiradas são drenadas para o seu servidor automaticamente** — vendas e edições feitas offline são enviadas sem nenhuma ação manual.
- Os gateways de pagamento que dependem do servidor e o **Salvar no Servidor** voltam a ficar disponíveis.
- A sincronização em segundo plano é retomada, baixando quaisquer alterações de produtos ou clientes que ocorreram enquanto você estava offline.

## Dicas para Conexões Instáveis {#tips-for-unreliable-connections}

- **Use "Salvar no Servidor" em pedidos importantes** — isso envia o pedido para o WooCommerce imediatamente, evitando perdas caso o banco de dados local do dispositivo seja limpo.
- **Verifique a Saúde da loja após uma queda** — o bloco *alterações aguardando envio* em **Saúde da loja → Banco de dados** confirma quando tudo já chegou ao seu servidor.
- **Sincronize enquanto houver sinal** — se você sabe que a conectividade será intermitente, deixe a carga inicial do catálogo terminar enquanto houver uma boa conexão.
