## ماذا يعني هذا {#what-this-means}

وكيل أمام المتجر يرفض استجابات الخادم لاحتوائها على عدد كبير جدًا من الترويسات.

تفرض طبقة تخزين مؤقت أو وكيل (وعادةً Varnish) حدًّا على عدد ترويسات الاستجابة أو حجمها. تتسع النقاط الطرفية الخفيفة للمتجر ضمن الحد، لكن استجابات API الكاملة تتجاوزه وتعود بأخطاء 503 من الوكيل، لا من WordPress. ويجب رفع الحد على تلك الطبقة.

## بياناتك {#your-data}

لم تتأثر أي بيانات طلبات أو منتجات.

## استكشاف الأخطاء وإصلاحها {#troubleshoot}

1. على Varnish، ارفع http_max_hdr (عدد الترويسات) وhttp_resp_hdr_len / http_resp_size (الأحجام).
2. اسأل المضيف عن طبقة الوكيل التي تعيد خطأ 503 — فسجل أخطاء WordPress لن يُظهر شيئًا لأن الطلب لا يفشل هناك أبدًا.
3. فحص سريع: تستجيب النقطة الطرفية /wcpos/v2/ping الخاصة بالمتجر بشكل سليم بينما تعيد نقاط بيانات API خطأ 503.
