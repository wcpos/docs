**العَرَض:** تظهر الطابعة عند الفحص، لكن الطباعة تفشل مع خطأ في الوصول أو الأذونات.

## سبب حدوث ذلك {#why-it-happens}

على Linux، يكون جهاز USB مملوكًا لـ `root` ما لم تنص قاعدة على غير ذلك، لذا لا يستطيع تطبيق يعمل باسمك فتحه. وقد يكون تعريف الطابعة الخاص بالنواة قد استحوذ على الجهاز مسبقًا أيضًا.

## افعل هذا {#do-this}

1. اعرف معرّفي المورّد والمنتج للطابعة:

   ```bash
   lsusb
   ```

   ابحث عن سطر طابعتك — والمعرّفان هما القيمتان المكوّنتان من أربعة أحرف بعد `ID`، مثل `04b8:0e28`.

2. أنشئ ملف قاعدة، مع استبدال المعرّفين بمعرّفيك:

   ```bash
   sudo tee /etc/udev/rules.d/99-receipt-printer.rules <<'RULE'
   SUBSYSTEM=="usb", ATTRS{idVendor}=="04b8", ATTRS{idProduct}=="0e28", MODE="0666"
   RULE
   ```

3. أعد تحميل القواعد وطبّقها من جديد:

   ```bash
   sudo udevadm control --reload-rules && sudo udevadm trigger
   ```

4. افصل الطابعة، وأعد توصيلها، وأعد تشغيل التطبيق. ثم اطبع صفحة اختبار.

شغّل التطبيق بحساب المستخدم العادي لديك، لا عبر `sudo` — فالقاعدة التي تعمل مع root فقط تُفقد الغرض من ذلك.

## هل ما زالت المشكلة قائمة؟ {#still-stuck}

استخدم **نسخ تقرير الإعداد** على شاشة المشكلة وألصقه في رسالتك، مع سطر `lsusb` الخاص بطابعتك.
