إن **WooCommerce REST API** أشبه بمجموعة من «القنوات» المعيارية التي تتيح لأصحاب المتاجر ربط متجر WooCommerce بتطبيقات وخدمات أخرى.

إليك شرحًا مبسطًا لكيفية عملها:

1. تعمل كجسر بين متجر WooCommerce والتطبيقات الخارجية، وتتيح لها التواصل وتبادل البيانات.

2. تعمل API بإرسال الطلبات إلى **نقاط نهاية** محددة — تخيلها «قنوات» لأنواع مختلفة من بيانات المتجر. فمثلًا، توجد نقاط نهاية للمنتجات والطلبات والعملاء.

3. يمكن للتطبيقات الخارجية استخدام نقاط النهاية هذه من أجل:

- الحصول على المعلومات (مثل جلب قائمة بالمنتجات)
- إضافة بيانات جديدة (مثل إنشاء طلب جديد)
- تحديث معلومات موجودة (مثل تغيير سعر منتج)
- حذف البيانات (مثل إزالة منتج قديم)

بدلًا من الاعتماد على خطافات PHP ومرشحاته (كما تفعل كثير من إضافات WordPress التقليدية)، تعمل API بإرسال البيانات واستقبالها بتنسيق منظم ومتوقع يُعرف باسم **JSON**.

## عرض بيانات JSON في POS {#viewing-the-json-data-in-the-pos}

لمساعدتك على فهم ما «يراه» POS، أضفنا عرضًا لبيانات JSON في أجزاء كثيرة من الواجهة.
على سبيل المثال، عند تعديل البيانات الوصفية للطلب أو عنصر سطر في عربة التسوق ضمن POS، ستظهر علامة تبويب JSON (كما في لقطة الشاشة أدناه).

## لماذا لا تعمل بعض الإضافات في POS؟ {#why-dont-some-plugins-work-in-the-pos}

ينزّل WCPOS بيانات المنتجات والطلبات والعملاء من متجر WooCommerce عبر REST API.
ثم يحتفظ بنسخة محلية من تلك البيانات ليواصل العمل حتى إذا كان اتصال الإنترنت متقطعًا.
يجعل هذا النهج POS أسرع وأكثر موثوقية في بيئة دفع مزدحمة.

لكن هذا يعني أن POS لا «يرى» التغييرات التي تحدث ديناميكيًا على موقعك في الوقت الفعلي. على سبيل المثال:
