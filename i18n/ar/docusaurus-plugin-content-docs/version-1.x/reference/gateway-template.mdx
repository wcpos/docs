# نموذج بوابة الدفع {#gateway-template}

يمنحك نموذج بوابة الدفع نقطة انطلاق لإنشاء بوابة دفع خاصة بنقاط البيع. وينشئ إضافة WordPress جاهزة للعمل في ملف PHP واحد يمكنك تثبيته وتخصيصه لتلبية احتياجاتك.

```bash
./create-gateway.sh
```

سيطلب البرنامج بعض التفاصيل — اسم بوابة الدفع ووصفًا موجزًا واسم مستخدم GitHub — ثم ينشئ إضافة جاهزة للاستخدام في الدليل الذي تختاره.

  </StepCard>
  <StepCard number="3" title="تثبيت الإضافة">

**الخيار أ — نسخ المجلد مباشرةً** (إذا كان لديك وصول إلى الخادم):
انسخ مجلد بوابة الدفع الذي تم إنشاؤه إلى دليل `wp-content/plugins/` في موقعك.

**الخيار ب — ضغط المجلد ورفعه** (الأسهل لمعظم المستخدمين):
1. اضغط المجلد الذي تم إنشاؤه في ملف `.zip`
2. في WordPress، انتقل إلى **الإضافات > أضف إضافة جديدة > رفع إضافة**
3. اختر ملف zip وانقر **التثبيت الآن**

  </StepCard>

1. انتقل إلى **WP Admin > نقاط البيع > الإعدادات > الدفع**
2. ابحث عن بوابة الدفع الجديدة في القائمة وفعّلها

:::note
تكون بوابة الدفع معطّلة افتراضيًا في صفحة الدفع العادية عبر الويب. ويتحكم WCPOS في بوابات الدفع التي تظهر في نقاط البيع من خلال إعداداته الخاصة.
:::

## الإعداد اليدوي {#manual-setup}

إذا كنت تفضل عدم استخدام البرنامج النصي، يمكنك استبدال العناصر النائبة بنفسك. افتح كل ملف في محرر نصوص وابحث عن القيم التالية واستبدلها:

| العنصر النائب | ما يجب إدخاله | مثال |
|---|---|---|
| `{{GATEWAY_NAME}}` | الاسم المعروض لبوابة الدفع | الدفع نقدًا |
| `{{GATEWAY_SLUG}}` | معرّف آمن للاستخدام في URL (أحرف صغيرة وواصلات) | cash-payment |
| `{{GATEWAY_DESCRIPTION}}` | وصف موجز لبوابة الدفع | قبول المدفوعات النقدية في WCPOS |
| `{{GATEWAY_DEFAULT_DESCRIPTION}}` | النص الذي يظهر لأمين الصندوق عند الدفع | ادفع نقدًا عند نقطة البيع |
| `{{GITHUB_USERNAME}}` | اسم مستخدم GitHub الخاص بك | kilbot |
| `{{REPO_NAME}}` | اسم المستودع الخاص بك | cash-payment-gateway |
| `{{AUTHOR_NAME}}` | اسمك | kilbot |
| `{{GATEWAY_ID}}` | المعرّف المختصر مع شرطات سفلية بدلًا من الواصلات | cash_payment |
| `{{GATEWAY_CLASS_NAME}}` | كتابة أول حرف من كل كلمة كبيرًا وربط الكلمات بشرطات سفلية | Cash_Payment |
| `{{GATEWAY_FUNCTION_PREFIX}}` | مثل معرّف بوابة الدفع | cash_payment |

ثم أعد تسمية `wcpos-{{GATEWAY_SLUG}}.php` ليتطابق الاسم مع المعرّف المختصر الخاص بك (مثل `wcpos-cash-payment.php`).

:::tip
يستخرج سكربت الإعداد تلقائيًا `GATEWAY_ID` و`GATEWAY_CLASS_NAME` و`GATEWAY_FUNCTION_PREFIX` من الاسم والمعرّف اللطيف (slug)، لذا لا تحتاج إلى التفكير فيها إلا عند إجراء الإعداد يدويًا.
:::

## آلية العمل {#how-it-works}

تسجل الإضافة المُنشأة فئة بوابة دفع في WooCommerce. إليك أهم النقاط:

- **`$this->enabled = 'no'`** — يخفي بوابة الدفع من صفحة الدفع عبر الويب. ويفعّلها WCPOS في نقاط البيع وفقًا لإعدادات نقاط البيع.
- **`process_payment()`** — تستدعي `$order->payment_complete()`، ما يعلّم الطلب بأنه مدفوع ويتولى خفض المخزون تلقائيًا.
- **`init_form_fields()`** — تحدد حقلي العنوان والوصف اللذين يظهران في إعدادات WooCommerce.

## تخصيص بوابة الدفع {#customising-your-gateway}

### إضافة حقول الدفع {#adding-payment-fields}

إذا كانت بوابة الدفع تحتاج إلى إدخال من أمين الصندوق (مثل رقم مرجعي)، فتجاوز الطريقة `payment_fields()`:

```php
public function payment_fields() {
    if ( $this->description ) {
        echo wpautop( wptexturize( $this->description ) );
    }

    woocommerce_form_field( 'my_gateway_reference', array(
        'type'        => 'text',
        'label'       => __( 'Reference Number', 'your-text-domain' ),
        'required'    => true,
    ) );
}
```

يمكنك بعد ذلك قراءة القيمة المرسلة في `process_payment()` عبر `$_POST['my_gateway_reference']`. تذكّر تنقية أي إدخال باستخدام `sanitize_text_field()`.

### تغيير سلوك الدفع {#changing-payment-behaviour}

يعلّم النموذج الافتراضي الطلبات بأنها مدفوعة فورًا. إذا كان سير عملك يتطلب الدفع لاحقًا (مثل الفاتورة)، فاستبدل `payment_complete()` بتحديث للحالة:

```php
public function process_payment( $order_id ) {
    $order = wc_get_order( $order_id );

    // Set to pending — the customer will pay later.
    $order->update_status( 'pending', __( 'Awaiting payment', 'your-text-domain' ) );

    // Stock must be reduced manually when not using payment_complete().
    wc_reduce_stock_levels( $order_id );

    return array(
        'result'   => 'success',
        'redirect' => $this->get_return_url( $order ),
    );
}
```

## إجراء التغييرات والتحديث {#making-changes-and-updating}

بعد تثبيت بوابة الدفع، يمكنك مواصلة تعديل ملف الإضافة لضبط منطق الدفع. لتثبيت إصدار محدّث:

1. عدّل `wcpos-your-slug.php` في المجلد الذي تم إنشاؤه
2. حدّث رقم `Version:` في ترويسة الإضافة (مثلًا من `0.1.0` إلى `0.2.0`)
3. اضغط المجلد وارفعه مجددًا عبر **الإضافات > أضف إضافة جديدة > رفع إضافة**، أو استبدل المجلد مباشرةً في `wp-content/plugins/`

:::tip
سيسألك WordPress عما إذا كنت تريد استبدال الإضافة الحالية عند رفع ملف zip بالاسم نفسه — انقر **استبدال الحالية بالملف المرفوع** للتحديث.
:::

### الإصدارات التلقائية باستخدام GitHub {#automated-releases-with-github}

إذا دفعت بوابة الدفع إلى مستودع GitHub، فسيشمل النموذج سير عمل GitHub Actions ينشئ الإصدارات تلقائيًا:

1. حدّث رقم `Version:` في ترويسة الإضافة
2. أنشئ commit وادفعه إلى الفرع `main`
3. ترصد GitHub Actions تغيير الإصدار وتنشئ إصدارًا جديدًا يتضمن ملف ZIP قابلًا للتنزيل

يمكن للمستخدمين الآخرين بعد ذلك تنزيل ملف ZIP من صفحة **الإصدارات** في مستودعك وتثبيته مثل أي إضافة WordPress.

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

<Accordion>
  <AccordionItem question="بوابة الدفع لا تظهر في نقاط البيع">

  - تحقق من تفعيل الإضافة ضمن **WP Admin > الإضافات**
  - انتقل إلى **WP Admin > نقاط البيع > الإعدادات > الدفع** وتأكد من تفعيل بوابة الدفع
  - تحقق من تثبيت WooCommerce وتفعيله

  </AccordionItem>

  <AccordionItem question="تظهر بوابة الدفع في صفحة الدفع عبر الويب">

  - تأكد من تعيين `$this->enabled = 'no';` في مُنشئ بوابة الدفع
  - يتجاوز WCPOS هذا الإعداد لطلبات نقاط البيع، لذا ينبغي ألا تظهر بوابة الدفع إلا في نقاط البيع

  </AccordionItem>

  <AccordionItem question="تبقى الطلبات بحالة 'قيد المعالجة' بدلًا من 'مكتمل'">

  - يحدد WooCommerce حالة الطلب وفقًا لأنواع المنتجات. تبقى الطلبات التي تتضمن منتجات مادية بحالة "قيد المعالجة" — وهذا سلوك طبيعي في WooCommerce. أما الطلبات التي تحتوي على منتجات افتراضية أو قابلة للتنزيل فقط فتُعلّم تلقائيًا بأنها "مكتمل".

  </AccordionItem>
</Accordion>
