**إدارة WordPress:** تُحرَّر النماذج في `WP Admin → POS → Templates`؛ وتسرد هذه الصفحة الحقول التي يمكنها طباعتها.

لطباعة إيصال أو إرساله بالبريد الإلكتروني، راجع [الإيصالات وشاشة إتمام الدفع](./at-checkout.mdx)؛ ولاختيار نموذج أو تعديله باستخدام الذكاء الاصطناعي، راجع [تخصيص إيصالك](./customise.mdx).

هذه الصفحة مخصصة لتحرير شيفرة النموذج يدويًا. تطبع جميع النماذج، سواء كانت HTML أو حرارية، من بيانات الإيصال نفسها: المتجر والطلب والأصناف والإجماليات والمدفوعات. توضح الصفحة كيفية طباعة حقل، وتقدم ثلاثة أمثلة شائعة، وتسرد جميع الحقول.

**انتقل إلى:** [البحث عن حقل](#field-reference) · [أمثلة شائعة](#common-recipes) · [عند حدوث مشكلة](#if-something-goes-wrong)

## طباعة حقل {#print-a-field}

1. افتح النموذج في **WP Admin → نقاط البيع → النماذج** (راجع التفاصيل في [تحريره يدويًا](./customise.mdx#option-3--edit-it-by-hand)).
2. في الموضع الذي تريد طباعة الحقل فيه، اكتب مساره بين قوسين معقوفين مزدوجين، مثل `{{store.name}}` أو `{{order.number}}` أو `{{totals.total_display}}`، أو أدرجه من قائمة الحقول بجانب الشيفرة.
3. راجع المعاينة أسفل الشيفرة، ثم انقر على **تحديث** للحفظ.

لطباعة قائمة، مثل الأصناف، ضع الصف داخل قسم ليتكرر مرة لكل صنف:

```mustache
{{#lines}}
  {{name}} x {{qty}} —
  {{line_total_display}}
{{/lines}}
```

يحذف القسم محتوياته أيضًا عندما يكون الحقل فارغًا أو صفرًا أو ذا قيمة منطقية خاطئة، لذا لا تُطبع محتويات `{{#customer.id}}…{{/customer.id}}` إلا لعميل له اسم. لطباعة المبالغ، استخدم الحقل المنتهي بـ `_display`؛ راجع [حقول العملة](#currency-fields).

يمكن طباعة الإيصالات دون اتصال أيضًا: ينشئ التطبيق نسخة من بيانات الإيصال من الطلب الموجود على الجهاز.

### مصدر البيانات {#where-the-data-comes-from}

ينشئ خادم متجرك بيانات الإيصال لكل طلب، وينشئ التطبيق نسخة مختصرة من الطلب الموجود على الجهاز: لا تتضمن `cashier`، ولا ساعات عمل المتجر أو ملاحظاته أو سياساته، ولا `totals.paid_total` أو `totals.change_total`. يُفتح نموذج HTML أو النموذج الحراري فورًا من نسخة الجهاز، ثم ينتقل إلى نسخة الخادم عند وصولها؛ وعند عدم الاتصال، تُطبع نسخة الجهاز، فتظهر تلك الحقول فارغة. مع WCPOS Pro، تتضمن نسخة الجهاز شعار المتجر أيضًا؛ وبدون Pro، يصل الشعار مع نسخة الخادم. يُصيَّر نموذج PHP القديم دائمًا على الخادم. ولهذا يستخدم النموذج الحقول أدناه ولا يستخدم دوال الطلب في PHP مطلقًا. لا تُطبع بعض الحقول إلا عندما يُصيِّر الخادم النموذج، كما يحدث عند تنزيل PDF؛ وتسردها فقرة [عند حدوث مشكلة](#if-something-goes-wrong).

  </AccordionItem>
</Accordion>

## خريطة الإيصال {#receipt-map}

يأتي كل جزء من الإيصال المطبوع من قسم في بيانات الإيصال. وجّه المؤشر إلى جزء من الإيصال أو إلى بطاقته لإبراز الاثنين؛ وانقر أو اضغط على أي منهما للانتقال إلى حقول ذلك القسم. على الهاتف، تأتي البطاقات بعد الإيصال بالترتيب نفسه، من الأعلى إلى الأسفل.

يستخدم الإيصال أدناه والمثالان الأولان وتفصيل السعر الطلب النموذجي نفسه. مبالغ أصنافه هي المبالغ قبل الكوبون (`line_subtotal_display`)؛ أما نماذج الإيصال في المعرض فتطبعها بعده (`line_total_display`، ومبلغه 26.10 للإسبريسو).

### أقسام المستوى الأعلى {#top-level-sections}

| القسم | محتوياته |
|---------|---------------|
| `order` (كائن) | هوية الطلب وحالته وتواريخه وملاحظته ومعلومات URL الدفع |
| `store` (كائن) | هوية المتجر وعنوانه وبيانات الاتصال به ومعرّفاته الضريبية وشعاره وساعات عمله ونص التذييل |
| `cashier` (كائن) | المستخدم الذي عالج الطلب |
| `customer` (كائن) | اسم العرض للعميل وعناوينه ومعرّفاته الضريبية |
| `lines` (مصفوفة) | بنود المنتجات |
| `fees` (مصفوفة) | صفوف الرسوم |
| `shipping` (مصفوفة) | صفوف الشحن |
| `discounts` (مصفوفة) | صفوف الكوبونات/الخصومات |
| `totals` (كائن) | إجماليات الطلب وإجماليات المدفوعات وملخص المبالغ المسترجعة وأعداد الأصناف |
| `tax` (كائن) | أعلام وضع عرض الضريبة لشروط إظهار الأقسام |
| `tax_summary` (مصفوفة) | صفوف ملخص الضريبة لكل معدل |
| `has_tax_summary` (قيمة منطقية) | شرط مبسّط لإظهار `tax_summary` |
| `payments` (مصفوفة) | صفوف المدفوعات |
| `refunds` (مصفوفة) | سجلات الاسترجاع المطبقة على الطلب |
| `fiscal` (كائن) | حقول اللقطة الضريبية التي تملؤها التكاملات الضريبية |
| `register` (كائن) | صندوق البيع الذي سجّل عملية البيع: `id` و`name`. سلاسل فارغة عندما يكون غير معروف |
| `software` (كائن) | البرنامج الذي أصدر الإيصال: `name` (`WCPOS`) و`plugin_version` و`app_version` و`app_build` و`platform` |
| `presentation_hints` (كائن) | تلميحات التنسيق والتصيير |
| `i18n` (كائن) | تسميات مترجمة للنماذج المرفقة والمخصصة |

### كائنات المعرّفات الضريبية {#tax-id-objects}

يحتوي `store.tax_ids` و`customer.tax_ids` على كائنات بالبنية نفسها:

| الحقل | النوع | الوصف |
|-------|------|-------------|
| `type` | سلسلة نصية | معرّف مثل `eu_vat` أو `de_steuernummer` أو `au_abn` أو `br_cpf` أو `us_ein` أو `other` |
| `value` | سلسلة نصية | قيمة المعرّف الضريبي المطلوب طباعتها |
| `country` | سلسلة نصية/null | رمز البلد وفق ISO؛ وتكون القيمة null لكل من `eu_vat` و`other` |
| `label` | سلسلة نصية | تسمية عرض مترجمة تُحدَّد قبل التصيير |

مثال:

```mustache
{{#store.tax_ids}}
  {{label}}: {{value}}
{{/store.tax_ids}}
```

### عرض السعر العادي والتوفير {#displaying-regular-price-and-savings}

لتخطيط يعرض سعر الوحدة، اعرض السعر العادي المسجّل وسعر البيع والتوفير كما يلي:

```mustache
{{#lines}}
  {{#unit_savings}}
    <span style="text-decoration: line-through;">{{regular_price_display}}</span>
    <span>{{selling_price_display}}</span>
    <span>{{i18n.savings}}: -{{unit_savings_display}}</span>
  {{/unit_savings}}
{{/lines}}
```

استخدم حقول إجمالي البند عندما تكون الكمية مهمة:

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    <span>{{i18n.savings}}: -{{line_savings_display}}</span>
  {{/line_savings}}
{{/lines}}
```

`selling_price` هو السعر قبل الكوبونات. استخدم `unit_price` أو `line_total` للمبلغ النهائي بعد خصومات WooCommerce.

:::note إعادة طباعة الطلبات المنشأة قبل v1.9.0
قد تتضمن طلبات WCPOS القديمة بالفعل التخفيض من السعر العادي إلى سعر البيع ضمن `discounts`. إذا كان نموذجك المخصص يطبع توفير البند وخصوماته معًا، فاستخدم `savings_in_discounts` لتجنب عرض التخفيض نفسه مرتين:

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    {{^savings_in_discounts}}
      <span>{{i18n.savings}}: -{{line_savings_display}}</span>
    {{/savings_in_discounts}}
  {{/line_savings}}
  {{#discounts}}
    <span>{{i18n.discount}}: -{{discounts_display}}</span>
  {{/discounts}}
{{/lines}}
```

إذا لم يكن النموذج يطبع صف `discounts` على مستوى البند، فاستمر في عرض `line_savings` حتى عندما تكون قيمة `savings_in_discounts` صحيحة. تتعامل النماذج المرفقة مع هذا الاختلاف تلقائيًا.
:::

## توسيع بيانات الإيصال {#extending}

يمكن لإضافة أن تضيف حقولها الخاصة إلى بيانات الإيصال عبر المرشّح `wcpos_receipt_data`.

<Accordion>
  <AccordionItem question="المرشّح — وسائطه وأوضاعه الستة ومثال">

يحافظ WCPOS على الحقول أعلاه خالية من البيانات الخاصة بأي إضافة بعينها. عندما تحتاج إضافة إلى تضمين الإيصال معلومات لا يمثّلها WooCommerce، تضيفها بنفسها عبر المرشّح `wcpos_receipt_data`، بالطريقة نفسها التي ترشّح بها الإضافات إجماليات طلبات WooCommerce. يعمل المرشّح على كل إيصال ينشئه الخادم: الإيصالات المباشرة واللقطات الضريبية وقت الدفع وتنزيلات PDF ونماذج PHP القديمة. قبل WCPOS 2.0 كان هذا المرشّح يُسمّى `woocommerce_pos_receipt_data`؛ ولا يزال ذلك الاسم يعمل، لكنه مهمل منذ 2.0 وسيُزال في 2.2 على أقرب تقدير (راجع [تسمية الخطافات](../extensions/index.mdx#hook-naming)).

يحدد الوسيط الثالث، `$mode`، المستند الجاري إنشاؤه: `live` أو `fiscal` أو `refund` أو `preview` (إيصالات نموذجية في محرر النماذج والمعرض) أو `closure` أو `xreport` (مستندات إغلاق صندوق البيع وتقرير X). في `preview` و`closure` و`xreport` يكون الطلب غير محفوظ ومعرّفه `0`؛ وينبغي لأي إضافة تحتاج إلى طلب محفوظ أن تعيد `$data` دون تغيير عندما تكون قيمة `$order->get_id()` هي `0`.

```php
add_filter( 'wcpos_receipt_data', function ( array $data, WC_Abstract_Order $order, string $mode ) {
    foreach ( $data['discounts'] as &$row ) {
        if ( 'smart_coupon' === $row['discount_type'] ) {
            $row['gift_card'] = true;
        }
    }
    return $data;
}, 10, 3 );
```

يمكن للنموذج بعد ذلك استخدام المفتاح الجديد كشرط إظهار، مثل أي قسم آخر:

```
{{#discounts}}
  {{#gift_card}}Gift Card{{/gift_card}}{{^gift_card}}{{i18n.discount}}{{/gift_card}}{{#label}}: {{label}}{{/label}}
{{/discounts}}
```

ينبغي أن تحتفظ المفاتيح المعرّفة في المخطط بأنواعها الموثّقة. المفاتيح المضافة ليست جزءًا من المخطط، لذا لا تظهر في منتقي الحقول في محرر النماذج، ولا تتضمن اللقطات الضريبية إلا ما أضافه المرشّح وقت دفع الطلب. يتوفر المرشّح بدءًا من WCPOS 1.10.8.

  </AccordionItem>

  <AccordionItem question="الإيصالات التي تطبع مفتاحًا مضافًا">

يصل كل مفتاح مضاف إلى الإيصالات التي يصيّرها الخادم بنفسه: تنزيلات PDF ونماذج PHP القديمة. تعيد نماذج HTML والنماذج الحرارية المصيَّرة في تطبيق POS بناء البيانات أولًا: يصل المفتاح المضاف داخل `order` أو `store` أو `cashier` أو `customer`، لكن يُحذف أي مفتاح مضاف في موضع آخر، مثل صف الخصومات أعلاه. {/* pending: monorepo#3363 */} في الإيصال المباشر الذي له لقطة ضريبية، تُنسخ الهوية الضريبية و`register` و`software` من اللقطة بعد تشغيل المرشّح، لذا لا يؤثر تغييرها في هذا المرشّح؛ بل أضف المعلومات إلى اللقطة نفسها.

  </AccordionItem>
</Accordion>

## عند حدوث مشكلة {#if-something-goes-wrong}

**يطبع صف `$0.00` في إيصال ولا يطبع شيئًا في آخر.** تكون بعض حقول `_display`، مثل `totals.change_total_display` و`totals.refund_total_display` و`payments[].tendered_display`، فارغة عند الصفر عندما يصيّر الخادم الإيصال، وتكون `$0.00` عندما يصيّره التطبيق. ضع الصف داخل قسم مشروط بالرقم بدلًا من ذلك، ليُحذف في الحالتين: `{{#totals.change_total}}…{{/totals.change_total}}`.

**صف إجمالي التوفير غير موجود.** قيمة `totals.total_saved_complete` خاطئة: يوجد صنف واحد على الأقل ليس له سعر عادي مسجّل، لذا لا يمكن حساب التوفير. يحدث ذلك عادةً في الطلبات المسجّلة قبل WCPOS 1.9.0.

**الإجمالي أقل مما دفعه العميل.** يعرض المتجر الأسعار دون ضريبة، لذا فإن `totals.total` هو الإجمالي قبل الضريبة. اطبع `totals.total_incl_display` لعرض المبلغ المحصّل. يطبع إيصال PHP القديم المرفق مع WCPOS ذلك المبلغ.

**يُطبع حقل في ملف PDF المنزّل، لكنه لا يُطبع في POS.** تعيد النماذج المصيَّرة في التطبيق بناء البيانات أولًا وتحذف بعض الحقول، التي لا تُطبع إلا في تنزيلات PDF ونماذج PHP القديمة. اطبع أي حقل من القائمة أدناه في تلك النماذج فقط، أو اجعل إظهاره مشروطًا بقسم حتى يحذفه إيصال POS. {/* pending: monorepo#3363 */}

<Accordion>
  <AccordionItem question="الحقول التي تختلف بين إيصالات PDF وPOS">

- `lines[].attributes` و`lines[].total_refunded_display` و`lines[].unit_subtotal_display` (مع صيغتيه `_incl` و`_excl`)
- `software.platform`
- حقول `presentation_hints` باستثناء `display_tax` و`prices_entered_with_tax` و`rounding_mode` و`locale` و`order_barcode_type`
- المعرّفات الضريبية للعملاء من الأنواع الألمانية والهولندية والفرنسية والشركات البريطانية والسويسرية
- المفاتيح التي تضيفها إضافة خارج `order` و`store` و`cashier` و`customer`؛ راجع [توسيع بيانات الإيصال](#extending)

</AccordionItem>

## الإصدارات {#versions}

لبيانات الإيصال رقم إصدار خاص بها، منفصل عن إصدار الإضافة. لا تتوفر الحقول الأحدث في الإيصالات القديمة، مثل لقطة ضريبية أُخذت قبل وجود الحقل، لذا اجعل إظهارها مشروطًا بقسم.

| الإصدار | الإضافات |
|---------|-------|
| 1.1 | السعر العادي وسعر البيع والتوفير لكل صنف، وإجماليات التوفير للطلب، بما فيها **إجمالي التوفير**. لا يغيّر أي منها إجماليات الطلب أو تقارير WooCommerce |
| 1.2 | `discounts[].discount_type` |
| 1.3 | `customer.first_name` وتسميات عرض العميل في `i18n` |
| 1.4 | `register` و`software` وحقول المستند الضريبي (`fiscal.document_type` وأعلام `is_…` و`sale_time` و`received_at` و`sale_tz` و`sale_counter` و`corrects`) وتسمياتها في `i18n` |
