  <WizardStep id="kb-first-d" title="まずはキーボードモードで — 設定は不要です">

ほとんどすべてのスキャナーは、初期状態で**キーボード**として動作し、バーコードを「入力」します。WCPOS はその高速なキー入力をスキャンとして認識します。設定するものは何もありません。

1. **USB スキャナー：** 接続するだけです。
2. **Bluetooth スキャナー：** ペアリングモードにして（説明書をご確認ください。多くの場合はトリガーの長押しか、ビープ音の操作です）、通常のキーボードと同じように**システムの Bluetooth 設定**でペアリングします。
3. WCPOS を開き、商品のバーコードをスキャンしてください。商品が表示され、売上に追加されるはずです。

  <WizardFix id="fix-nothing" title="スキャンしても何も起こらないとき">

1. **スキャナーは反応していますか？** トリガーを引いてみてください。ビープ音もランプの点灯もない場合は、WCPOS ではなく電源やバッテリーの問題です。
2. **接続されていますか？** Bluetooth 設定が「ペアリング済み」ではなく**接続済み**になっている必要があります。不明な場合は再ペアリングしてください。
3. **入力されることを確認する：** メモアプリや空のテキスト欄を開いてスキャンしてください。そこに文字が表示されるならスキャナーは正常で、POS がその入力をスキャンとして認識できていないだけです。
4. 入力されるのに WCPOS が反応しない場合は、開いてください <kbd>設定</kbd> → <kbd>バーコードスキャン</kbd> を開き、**テストパネル**にスキャンしてください。各回の入力がなぜ手入力として扱われたのかが正確に表示され、**適用**ボタン付きで対処方法（タイミングのしきい値を上げるなど）が提案されます。

    <WizardGate id="g-fix-nothing" question="スキャンできるようになりましたか？">
      <WizardChoice value="yes" label="はい、直りました" goTo="success-kb" />
      <WizardChoice value="no" label="いいえ、まだ何も起こりません" goTo="support" />
    </WizardGate>
  </WizardFix>

  <WizardFix id="fix-garbled-d" title="スキャン結果が文字化けするとき">

キーボードモードのスキャナーは、**キーボードレイアウト**を使って「入力」します。スキャナーのレイアウトがデバイスのレイアウトと一致していないと（QWERTY と AZERTY、記号の位置の違いなど）、文字が入れ替わります。

1. **テストパネル**にスキャンしてください(<kbd>設定</kbd> → <kbd>バーコードスキャン</kbd>)。スキャナーが Shift を独立したキーとして送信している場合など、よくあるケースを検出し、何が起きているかを表示します。
2. スキャナーの説明書で **「キーボード言語」**または**「キーボードレイアウト」** を設定するバーコードを確認し、お使いのデバイスに合わせて設定してください（通常はUSレイアウトが無難です）。
3. 最も確実な対処は**直接接続**です。直接接続したスキャナーはバーコードをデータとして送信するため、キーボードレイアウトが関与せず、文字化けは起こりません。

      <WizardChoice value="direct" label="直接接続を設定する" goTo="conn" />
      <WizardChoice value="help" label="まだ文字化けする — 助けが必要です" goTo="support" />
    </WizardGate>
  </WizardFix>

  <WizardFix id="fix-focus-d" title="スキャンが別の場所に入力される、またはフォーカスがないと失われる">

これはキーボードモードに元々ある制約です。スキャナーは**フォーカスがあるところ**に入力します。カーソルが数量の欄にあればバーコードはそこに入り、別のウィンドウにフォーカスがあればスキャンはそちらに送られます。

このプラットフォームでの本質的な解決策は**直接接続**です。フォーカスの位置に関係なく、POS がバックグラウンドのタブにある場合でも、すべてのスキャンが WCPOS に直接届きます。

  <WizardFix id="fix-osk-a" title="画面上のキーボードを再表示する">

ハードウェアキーボードが接続されている間、スマートフォンやタブレットでは画面上のキーボードが非表示になります。キーボードモードのスキャナーもハードウェアキーボードとして扱われます。これはオペレーティングシステムの動作であり、WCPOS の設定ではありません。

1. **多くのスキャナーには再表示するショートカットがあります。** 一般的にはトリガーまたは小さな機能ボタンを数秒間長押しします（Inateck の場合、スキャンボタンを約3&nbsp;s長押し）。説明書で *「iOS キーボード」*または*「仮想キーボード」*を探してください。

  <WizardFix id="fix-chooser" title="スキャナーが選択画面に表示されない場合">

1. **まだキーボードモードの可能性が高いです** — これが最もよくある原因です。モード切り替え用バーコードが読み取られていない可能性があります。もう一度読み取り、スキャナーの電源を入れ直してください。簡単な確認方法：テキスト欄をクリックしてトリガーを引き、文字が表示されるなら、まだキーボードモードです。Eyoyo の場合は Bluetooth 名を確認してください。`ScannerSPP` と表示されている必要があります。
2. **以前のペアリングが妨げになっています**（Bluetooth）。システムの Bluetooth 設定でスキャナーの登録を解除または削除し、モードを切り替えた*後*にもう一度ペアリングしてください。選択画面に表示されるのは、正しくペアリングされたシリアルデバイスだけです。
3. **表示されるが接続できない：** ポートを使用している可能性のあるメーカーの設定ツールを閉じ、スキャナーを近づけて、もう一度お試しください。
4. **それでも解決しませんか？** 一部のスキャナーは、メーカー固有の **service UUID** でシリアル接続を識別します。この UUID は既定では選択画面に登録されていません。マニュアルの Bluetooth に関する章で、長い `8-4-4-4-12` コードを探します（多くの場合、SPP の項目の近くにあります）。次に、 <kbd>設定</kbd> → <kbd>バーコードスキャン</kbd> UUID 欄の横にある **追加**ボタンで登録し、もう一度接続をお試しください。
5. **マニュアルにも UUID が見当たりませんか？** スキャナーのブランドとモデルを添えてサポートにお問い合わせください。
