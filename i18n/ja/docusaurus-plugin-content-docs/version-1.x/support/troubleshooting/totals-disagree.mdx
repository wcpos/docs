POSでは販売時に **"店舗がこの注文の合計金額を変更しました"** という通知が表示され、金額が一覧表示されます
両者で異なる金額が表示されます。

## 通知の意味 {#what-the-notice-means}

WooCommerceは各注文の合計金額を独自に計算します。POSは、その計算をローカルで再現するため、
レジで販売金額を計算してすぐに支払いを受け付けられます。また、インターネット接続が切れても動作を継続します。

両者の金額は完全に一致する必要があります。POSが販売を保存し、店舗から
異なる金額が返された場合は、その再現計算が誤っており、通知によってレジ担当者に知らせます **商品が
カウンターを離れる前に**。

:::info 店舗側の金額が正しい金額です
販売はブロックされず、何も失われません。店舗の数値は記録された内容であり、
WooCommerceのレポートと顧客の注文に表示される内容です。この通知は、レジ担当者が確認できるように表示されます
商品を渡す前に合計金額を確認するためです。
:::

:::warning 問題が解決するまでオフライン販売を行わないでください
POSがローカルで計算する金額は、接続がない場合に使用する金額と同じです。
オフライン時には修正するサーバーがありません。そのため、理由を問わず販売金額に差異がある間は、オフライン
この店舗での販売は誤っている可能性があり、再接続するまで検出できません。

これはプラグインに起因する場合だけでなく、以下のすべての原因に当てはまります。
:::

## まず、POSを再同期します {#first-resync-the-pos}

POSは店舗の税設定を独自に保持しており、自動的には更新されません
WooCommerce を変更した場合です。古いコピーが残っていることが、両者の金額が一致しない最も一般的な理由であり、
ワンクリックで修正できます。

POS で **税設定** を開き、**サーバー設定を復元** を使用して最新の
設定を店舗から取得してから、新しいテスト販売を行ってください。

これで解消した場合は完了です。以下の項目を変更した場合は、毎回この操作を行ってください
**WooCommerce → 設定 → 税**。[税設定](/settings/store/tax) で各フィールドの意味を確認できます
また、復元を行わない方がよい唯一のケースについても説明しています。

:::note WooCommerce Tax を使用する店舗
店舗で自動税計算を有効にした [WooCommerce Tax](/integrations/woocommerce-tax) を使用している場合、
店舗でこれまで課税したことのない場所で最初の販売を行ったときにこの通知が一度表示され、さらに
管轄区域の税率が変更された場合にもう一度表示されます。TaxJar は販売の発生に応じて税率テーブルを補完するため、
POS に必要な行は、その販売によって作成されるまで存在しません。POS は次回の変更時にその行をダウンロードします
確認すると、通常は1分以内に解消され、その場所での次の販売では一致します。**消去して再ダウンロード**
**ストアの健全性 → データベース** の **税率** 行で実行すると、直ちに取得されます。税の計算基準が
顧客の住所である場合、店舗で一度も課税されたことのない郵便番号ごとに、これが一度発生する可能性があります。
:::

POS を同期した直後にも通知が表示される場合は、以下の原因を確認してください。

## 原因 {#what-causes-it}

可能性は 3 つあり、いずれの場合も通知の表示は同じです。

### POS での読み取り方が異なる税または端数処理の設定 {#a-tax-or-rounding-setting}

最も一般的な原因です。**WooCommerce → 設定 → 税** で、次を確認してください。

- **価格に税を含めて入力** — カタログの価格にすでに税が含まれているかどうか
- **端数処理** — 「小計レベルで税を丸める」を有効にすると、複数行の販売で結果が変わります
- **税率** — *優先度* または *複合* の設定が想定と異なる税率
- **小数点以下の桁数** — **一般**で、3 桁以上の小数を使用する店舗では、2 桁の店舗とは異なる丸め処理が行われます

これらのいずれかを最近変更した店舗、または郵便番号別・市区町村別に税率を設定している店舗では、
まずここを確認してください。

### 注文合計を書き換えるプラグイン {#a-plugin-that-rewrites-totals}

追加料金、手数料、通貨換算、ロイヤルティ、「役割ベースの価格設定」プラグインでは、一般的に再計算が行われます
POS が独自に計算した後、サーバー上で合計が再計算されます。POS からはこれらのルールを確認できないため、
影響を受けるすべての販売で差異が発生します。

これが意図した動作であり許容できる場合は、故障ではありません。販売は店舗によって正しく記録されます。
ただし、影響を受けるすべての販売で通知が表示されます。また、これが唯一の原因です
解消されません。これらのルールはサーバー上にあり、POS では再現できないため、この方法で合計を
計算する店舗では、単に修正されるまでではなく、**オフラインではまったく正しく販売できません**。
修正されるまで。

原因となっているプラグインを特定する方法については、[プラグインの競合](/support/troubleshooting/plugin-conflicts)を参照してください。
原因となっているかを確認してください。

### POS のバグ {#a-bug-in-the-pos}

店舗が合計額を変更するプラグインのない標準的な WooCommerce インストールであり、金額が
それでも一致しない場合は、WCPOS のバグです。ぜひお知らせください。

## 複数の販売で発生する場合 {#when-it-happens-on-several-sales}

不一致のある販売が 1 件だけでも確認する価値があります。POS では、**複数の異なる
販売** で不一致が発生すると、通知の重要度を上げます。その時点では、これは 1 件の注文だけの問題ではなく、
インストール環境に起因する問題であり、原因が見つかるまで発生し続けます。

この状態になる無害な例として、顧客住所に基づいて税金を計算する WooCommerce Tax の店舗があり、
新しい郵便番号での最初の販売が複数あり、それぞれで 1 回だけ不一致が発生した場合が挙げられます。それらの各郵便番号で次の販売が
一致すれば、問題はありません。

## お送りいただく情報 {#what-to-send-us}

通知には差異のある各金額と両方の数値が表示されます。これに加えて、以下の情報があれば、
通常は画面共有なしで原因を特定できます。

1. 金額が表示された通知のスクリーンショット。
2. POS で **サーバー設定を復元** を実行しても、通知が表示され続けることの確認。
3. 税金設定: **WooCommerce → 設定 → 税**（自動税計算が
   有効かどうかを含むすべての項目）および **一般 → 小数点以下の桁数**。
4. 「小計レベルで税金を丸める」が有効かどうか。
5. 設定ページだけでなく、**税率表そのもの**も必要です。各税率クラスの行、
   *国/都道府県/郵便番号/市区町村*、*税率 %*、*優先度*、*複合*、*送料*を含めてください。多くの
   原因は上記の設定ではなく、それらの行にあります。これらの情報がない場合、
   追加で確認する必要があります。
6. 価格、税、手数料、または通貨に影響する有効なプラグインの一覧。
7. 影響を受けた販売の注文番号。
