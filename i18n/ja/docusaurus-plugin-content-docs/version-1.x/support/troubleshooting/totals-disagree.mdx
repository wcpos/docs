POS は、売上に **「ストアがこの注文の合計を変更しました」** という通知を表示し、両者で異なる金額を一覧で示します。

## この通知の意味 {#what-the-notice-means}

WooCommerce は、すべての注文の合計を自身で計算します。POS はその計算をローカルで再現するため、レジは売上を即座に集計して支払いを受け取れ、インターネットが切れても動作し続けます。

両者は正確に一致するはずです。POS が売上を保存し、ストアが異なる金額で応答した場合、その再現が誤っていたことになり、通知は**商品がカウンターを離れる前に**レジ担当者にそれを知らせます。

:::info 有効なのはストアの金額です
売上はブロックされず、失われるものもありません。記録されたのはストアの数値であり、WooCommerce のレポートや顧客の注文に表示されるのもそれです。この通知は、レジ担当者が何かを引き渡す前に合計を確認できるようにするために存在します。
:::

:::warning 解決するまでオフライン販売を行わないでください
POS がローカルで計算する金額は、接続がないときに使用する金額と同じです — そしてオフラインでは、それを修正するサーバーがありません。したがって、**何らかの理由**で売上が食い違っている間は、このストアでのオフライン販売が誤っている可能性があり、再接続するまで検出できません。

これは以下のすべての原因に当てはまり、プラグインのケースだけではありません。
:::

## まず、POS を再同期してください {#first-resync-the-pos}

POS は、ストアの税設定を独自にコピーして保持しており、WooCommerce を変更しても自動的には更新されません。古いコピーは両者が一致しない最も一般的な原因であり、ワンクリックで解決できます。

POS で **税設定** を開き、**サーバー設定を復元** を使用してストアから現在の設定を取得し、その後で新しくテスト販売を行ってください。

それで解消すれば完了です — **WooCommerce → 設定 → 税** で何かを変更するたびに、この操作を行うことを忘れないでください。各フィールドの意味と、復元が望ましくない唯一のケースについては、[税設定](/settings/store/tax)を参照してください。

POS を最新の状態に同期したのに通知がまだ表示される場合は、以下の原因を確認してください。

## 原因 {#what-causes-it}

可能性は 3 つあり、通知はそのいずれでも同じように見えます。

### POS が異なる形で読み取る税または端数処理の設定 {#a-tax-or-rounding-setting}

圧倒的に最も一般的な原因です。**WooCommerce → 設定 → 税** で以下を確認してください:

- **税込価格を入力** — カタログ価格にすでに税が含まれているかどうか
- **端数処理** — 「小計レベルで税を丸める」は、複数明細の売上で結果を変えます
- **税率** — *優先度* または *複合* の設定が想定と異なる税率
- **小数点以下の桁数** — **一般** の下にある設定で、3 桁以上のストアは 2 桁のストアと異なる丸め方をします

これらのいずれかを最近変更したストアや、郵便番号ごと・市区町村ごとに税率を設定しているストアは、最初に確認すべき点です。

### 注文の合計を書き換えるプラグイン {#a-plugin-that-rewrites-totals}

追加料金、手数料、通貨換算、ロイヤルティ、「役割ベースの価格設定」プラグインは、POS が独自に計算を終えた後で、サーバー側で合計を再計算することがよくあります。POS はそれらのルールを認識できないため、それらが関わるすべての売上で食い違いが生じます。

それが意図的で、受け入れる場合は、何も壊れていません — 売上はストアによって正しく記録されています。しかし通知は影響を受けるすべての売上に表示され、これは解消しない唯一の原因です: それらのルールはサーバー上に存在し、POS は再現できないため、このように合計を計算するストアは、何かが修正されるまでの間だけでなく、**そもそもオフラインで正しく販売できません**。

どのプラグインが原因かを特定する方法については、[プラグインの競合](/support/troubleshooting/plugin-conflicts)を参照してください。

### POS のバグ {#a-bug-in-the-pos}

ストアが標準的な WooCommerce のインストールで、合計を変更するプラグインがないにもかかわらず、金額がまだ食い違う場合、それは私たちのバグであり、ぜひお知らせいただきたいものです。

## 複数の売上で発生する場合 {#when-it-happens-on-several-sales}

食い違う売上が 1 件だけでも確認する価値があります。POS は、**複数の異なる売上**で食い違いが生じた時点で通知を格上げします。その段階では、もはや 1 つの注文の特性ではなく、インストール全体の特性であり、原因が見つかるまで発生し続けるからです。

## 私たちに送っていただくもの {#what-to-send-us}

通知は食い違う各金額を挙げ、両方の数値を示します。それに加えて以下があれば、通常は画面共有なしで原因を特定するのに十分です:

1. 金額を示した通知のスクリーンショット。
2. POS で **サーバー設定を復元** を実行しても通知が消えなかったことの確認。
3. 税設定: **WooCommerce → 設定 → 税**（すべてのフィールド）、および **一般 → 小数点以下の桁数**。
4. 「小計レベルで税を丸める」が有効かどうか。
5. 設定ページだけでなく、**税率表そのもの** — 各税率クラスの下の行で、*国/都道府県/郵便番号/市区町村*、*税率 %*、*優先度*、*複合*、*配送* を含むもの。上記の原因のほとんどは、その上にある設定ではなく、これらの行の中に潜んでいるため、これがないと私たちは改めて尋ねる必要が生じます。
6. 価格、税、手数料、通貨に関わる有効なプラグインの一覧。
7. 影響を受けた売上の注文番号。
