POS では、販売時に **「店舗がこの注文の合計金額を変更しました」** という通知が表示され、
店舗と POS で一致していない金額が一覧表示されます。

## 通知の意味 {#what-the-notice-means}

WooCommerce は各注文の合計金額を独自に計算します。POS はその計算をローカルで再現することで、
レジですぐに販売金額を計算して支払いを受け付けられるようにし、インターネット接続が切れても動作を継続できるようにしています。

本来、両者の金額は完全に一致するはずです。POS が販売を保存した際に、店舗から
異なる金額が返された場合は、計算を正しく再現できていなかったことになります。この通知は、**商品を
カウンターで引き渡す前に**そのことをレジ係に知らせます。

:::info 店舗側の金額が正式な金額です
販売がブロックされることはなく、データが失われることもありません。記録されるのは店舗側の金額で、
WooCommerce のレポートや顧客の注文にもその金額が表示されます。この通知は、商品を引き渡す前に
レジ係が合計金額を確認できるようにするためのものです。
:::

:::warning 問題が解決するまでオフライン販売を行わないでください
POS がローカルで計算する金額は、接続がないときにもそのまま使用されます。
オフラインでは、金額を修正するサーバーに接続できません。そのため、**どのような**理由であっても販売金額に差異がある間は、
この店舗のオフライン販売の金額も誤っている可能性があり、再接続するまで検出できません。

これはプラグインが原因の場合だけでなく、以下のすべての原因に当てはまります。
:::

## まず POS を再同期する {#first-resync-the-pos}

POS は店舗の税設定のコピーを独自に保持していますが、
WooCommerce で設定を変更しても自動更新されません。このコピーが古いことが金額の不一致の最も一般的な原因で、
ワンクリックで修正できます。

POS で **税設定** を開き、**サーバー設定を復元** を使って店舗の最新の
設定を取得してから、新たにテスト販売を行ってください。

これで通知が消えれば完了です。今後も設定を変更するたびにこの操作を行ってください。対象は
**WooCommerce → 設定 → 税** の各項目です。各フィールドの意味については[税設定](/1.x/settings/store/tax)を参照してください。
復元しないほうがよい唯一のケースについても説明しています。

:::note WooCommerce Tax を使用する店舗
店舗で [WooCommerce Tax](/1.x/integrations/woocommerce-tax) の自動税計算を有効にしている場合、
これまで課税したことのない地域で初めて販売すると、この通知が一度表示されます。また、
管轄区域の税率が変更されたときにも、もう一度表示されます。TaxJar は販売の発生に応じて税率表に行を追加するため、
POS に必要な行は、その販売で作成されるまで存在しません。POS は次回の変更確認時に、
通常は一分以内にその行をダウンロードし、その地域での次の販売では金額が一致します。**消去して再ダウンロード**を
**ストアの健全性 → データベース** の **税率** 行で実行すると、すぐに取得できます。税額を顧客の住所に基づいて
計算する場合は、これまで課税したことのない郵便番号ごとに、一度ずつ発生する可能性があります。
:::

POS を再同期した直後でも通知が表示される場合は、以下の原因を確認してください。

## 原因 {#what-causes-it}

考えられる原因は三つあり、どの場合も同じ通知が表示されます。

### 税や端数処理の設定を POS が異なる形で読み取っている {#a-tax-or-rounding-setting}

最も多い原因です。**WooCommerce → 設定 → 税** で、以下を確認してください。

- **価格に税を含めて入力** — カタログの価格にすでに税が含まれているかどうか
- **端数処理** — 「小計レベルで税を丸める」を有効にすると、複数の明細行がある販売の計算結果が変わります
- **税率** — *優先度* または *複合* の設定が想定と異なる税率がないか
- **小数点以下の桁数** — **一般** にある設定で、小数点以下 3 桁以上の店舗と 2 桁の店舗では端数処理の結果が異なります

最近これらの設定を変更した店舗や、郵便番号別・市区町村別に税率を設定している店舗では、
まずこれらの項目を確認してください。

### 注文合計を書き換えるプラグイン {#a-plugin-that-rewrites-totals}

追加料金、手数料、通貨換算、ロイヤルティ、「役割ベースの価格設定」のプラグインは、一般的に、
POS が独自に計算した後で、サーバー上で合計金額を再計算します。POS ではその計算ルールを把握できないため、
これらのプラグインが関与するすべての販売で金額が一致しなくなります。

意図した動作で、許容できるのであれば、不具合ではありません。販売は店舗側で
正しく記録されます。ただし、影響を受ける販売には毎回通知が表示されます。また、この原因だけは
解消されません。計算ルールがサーバー上にあり、POS では再現できないためです。この方法で合計金額を
計算する店舗では、**オフライン販売を正しく処理することはまったくできません**。何かを修正するまでの
一時的な問題ではないのです。

原因となっているプラグインの特定方法については、[プラグインの競合](/1.x/support/troubleshooting/plugin-conflicts)を
参照してください。

### POS のバグ {#a-bug-in-the-pos}

合計金額を変更するプラグインを使わず、標準的な WooCommerce の構成で運用している店舗でも、
金額が一致しない場合は、WCPOS 側のバグです。ぜひお知らせください。

## 複数の販売で発生する場合 {#when-it-happens-on-several-sales}

金額が一致しない販売が一件だけでも、確認する必要があります。POS は、**異なる複数の
販売**で金額の不一致が発生すると、通知のレベルを引き上げます。その時点で、個々の注文ではなく、
インストール環境に起因する問題と考えられ、原因を特定するまで繰り返し発生するためです。

ただし、問題のないケースもあります。WooCommerce Tax で顧客の住所に基づいて税額を計算する店舗で、
未使用の郵便番号に対する初回の販売が複数あり、それぞれで一度だけ金額が一致しなかった場合です。各郵便番号での次の販売で
金額が一致すれば、問題ありません。

## お送りいただく情報 {#what-to-send-us}

通知には、差異のある金額の項目名と、双方の数値が表示されます。その内容に加えて以下の情報があれば、
通常は画面を共有しなくても原因を特定できます。

1. 金額が表示された通知のスクリーンショット。
2. POS で **サーバー設定を復元** を実行しても、通知が表示され続けることの確認。
3. 税設定：**WooCommerce → 設定 → 税**（自動税計算の
   有効・無効を含むすべての項目）、および **一般 → 小数点以下の桁数**。
4. 「小計レベルで税を丸める」が有効かどうか。
5. 設定ページだけでなく、**税率表そのもの**。各税率クラスの行を、
   *国/都道府県/郵便番号/市区町村*、*税率 %*、*優先度*、*複合*、*送料*を含めてお送りください。上記の原因の多くは、
   税率表の上にある設定ではなく、表の各行にあります。これらの情報がない場合は、
   改めて確認をお願いする必要があります。
6. 価格、税、手数料、通貨に関与する有効なプラグインの一覧。
7. 影響を受けた販売の注文番号。
