プラグインの競合は、WCPOS で問題が発生する最も一般的な原因の一つです。他の WordPress プラグインが WooCommerce や WCPOS の機能に干渉すると、クラッシュやパフォーマンスの問題、予期しない動作が発生することがあります。

## プラグイン競合の兆候 {#signs-of-plugin-conflicts}

以下の症状がある場合、プラグインの競合が発生している可能性があります。

- **致命的エラー** - 「このサイトで重大なエラーが発生しました」
- **パフォーマンスの問題** - 読み込みの遅さ、タイムアウト、サーバーの高負荷
- **機能の問題** - 機能が期待どおりに動作しない
- **データ同期の問題** - 商品、注文、顧客が正しく同期されない
- **決済ゲートウェイの問題** - チェックアウトの失敗や決済処理エラー

## 始める前に：ステージングサイトを使用する {#before-you-start-use-a-staging-site}

:::warning 重要
**本番サイトでは、プラグイン競合のトラブルシューティングを絶対に行わないでください。** 業務に支障をきたさないよう、必ずステージング環境を使用してください。
:::

### ステージングサイトとは？ {#what-is-a-staging-site}

ステージングサイトは本番サイトの正確なコピーで、顧客に影響を与えずに変更を安全にテストできます。現在、多くのホスティングプロバイダーがステージング環境を標準機能として提供しています。

### ホスティングプロバイダーがステージングを提供していない場合 {#if-your-host-doesnt-offer-staging}

ホスティングプロバイダーがステージングサイトを提供していない場合は、**提供しているプロバイダーへの切り替えを検討してください**。現在では標準的な機能であり、以下の作業に欠かせません。

- プラグインやテーマの安全なテスト
- WordPress の更新
- 問題のトラブルシューティング
- 開発作業

**ステージングを提供するおすすめのホスティングプロバイダー：**
- WP Engine
- SiteGround  
- Kinsta
- Cloudways
- その他多数

## ステップ 1：致命的エラーを確認する {#step-1-check-for-fatal-errors}

クラッシュや重大なエラーが発生している場合は、まずエラーログを確認してください。

1. **WCPOS のログを確認** - WCPOS で [**ストアヘルス → ログ**](/1.x/support/logs) を開き、エラーメッセージを確認します
2. **致命的エラーログを確認** - [クリティカルエラーのトラブルシューティングガイド](/1.x/support/troubleshooting/critical-error)に従って、詳しいエラーメッセージを確認します
3. **エラーの詳細を記録** - エラーに記載されているプラグイン名やファイルパスを探します

特定のプラグインに言及した致命的エラーが見つかった場合、そのプラグインが原因である可能性が高いです。そのプラグインを無効化して、問題が解消するかテストできます。

## ステップ 2：プラグインを順に切り分ける {#step-2-the-plugin-elimination-method}

ログに致命的エラーがない場合や、パフォーマンスに関わる競合を特定したい場合は、次の手順で切り分けます。

### 2.1 比較の基準を記録する {#21-create-a-baseline}

1. **ステージングサイトにアクセスします**
2. **問題のある機能をテスト** - どの機能が動作しないのか、何が遅いのかを正確に記録します
3. **パフォーマンス指標を記録** - パフォーマンスの問題であれば、[ログ](/1.x/support/logs)から実行時間を記録します

### 2.2 必須のもの以外のプラグインをすべて無効化する {#22-disable-all-plugins-except-essential-ones}

**以下のプラグインは有効なままにします：**
- WooCommerce
- WCPOS
- WCPOS Pro（使用している場合）

**それ以外はすべて無効化します：**
1. `WP Admin > プラグイン` に移動します
2. それ以外のプラグインをすべて選択します
3. 一括操作のドロップダウンから「無効化」を選択します
4. 「適用」をクリックします

### 2.3 問題が解消したかテストする {#23-test-the-issue}

1. **キャッシュをクリア** - キャッシュプラグインを使用している場合は、すべてのキャッシュをクリアします
2. **問題のある機能をテスト** - 今度は動作するか確認します
3. **パフォーマンスを確認** - 実行時間が改善したか確認します

**問題が解消した場合：** プラグインの競合が原因です。ステップ 2.4 に進んでください。

**問題が解消しない場合：** 原因はプラグインの競合ではない可能性が高いため、以下を確認してください。
- サーバーリソースの問題（[サーバーパフォーマンス](/1.x/support/performance/server)を参照）
- テーマの競合（ステップ 3 を参照）
- WordPress/WooCommerce 本体の問題

### 2.4 プラグインを一つずつ有効化する {#24-enable-plugins-one-by-one}

次に、競合を引き起こしているプラグインを特定します。

1. **プラグインを一つ有効化** - 必要性の高いものから始めます
2. **機能をテスト** - 問題が再発するか確認します
3. **問題がない場合** - 次のプラグインを有効化して再度テストします
4. **問題が再発した場合** - 競合しているプラグインを特定できました

**プラグインの優先順位（この順番で有効化）：**
1. **セキュリティプラグイン** - Wordfence、Sucuri など
2. **SEO プラグイン** - Yoast、RankMath など  
3. **パフォーマンスプラグイン** - キャッシュ、最適化
4. **決済ゲートウェイ** - Stripe、PayPal など
5. **その他の WooCommerce 拡張機能**
6. **一般的な WordPress プラグイン**

### 2.5 調査結果を記録する {#25-document-your-findings}

競合しているプラグインを特定したら、以下を行います。

1. **プラグイン名とバージョンを記録します**
2. **そのプラグインが引き起こす具体的な問題を記録します**
3. **新しいバージョンが公開されているか確認します**
4. **同様の機能を提供する代替プラグインを探します**

## ステップ 3：テーマの競合を確認する {#step-3-check-for-theme-conflicts}

WCPOS は独自のインターフェースを使用するため、テーマの影響を受けることはまれですが、以下の機能では問題が発生する場合があります。

- チェックアウト処理（Web チェックアウトゲートウェイを使用している場合）
- 管理画面の機能
- API レスポンス

### デフォルトテーマでテストする {#test-with-a-default-theme}

1. **ステージングサイトで**、WordPress のデフォルトテーマに切り替えます。
   - Twenty Twenty-Four
   - Twenty Twenty-Three
   - Twenty Twenty-Two
2. **問題のある機能をテストします**
3. **問題が解消した場合** - 使用しているテーマが競合の原因です

:::info テーマの影響
テーマが WCPOS の問題を引き起こす可能性は、プラグインに比べてはるかに低くなります。POS インターフェースはテーマとは独立して動作します。ただし、テーマは以下に影響することがあります。
- WooCommerce のチェックアウトページ
- WordPress の管理機能
- REST API レスポンス
:::

## ステップ 4：プラグインの競合を解決する {#step-4-resolving-plugin-conflicts}

競合しているプラグインを特定したら、以下の方法で対処できます。

### 方法 1：プラグインを更新する {#option-1-update-the-plugin}

1. **更新を確認** - 新しいバージョンで競合が修正されている場合があります
2. まずステージングサイトで**プラグインを更新します**
3. 本番サイトで更新する前に**十分にテストします**

### 方法 2：代替プラグインを探す {#option-2-find-an-alternative}

1. 同じ機能を提供する**代替プラグインを調べます**
2. ステージングサイトで**代替プラグインをテストします**
3. プラグインを切り替える場合は**設定を移行します**

### 方法 3：プラグイン開発者に連絡する {#option-3-contact-plugin-developer}

1. プラグイン開発者に**競合を報告します**
2. **詳しい情報を提供します：**
   - 関係するプラグインのバージョン
   - WordPress と WooCommerce のバージョン
   - 正確なエラーメッセージや動作
   - 問題の再現手順

### 方法 4：個別の対処方法を用意する {#option-4-custom-solution}

代替できない必須プラグインの場合は、以下の方法を検討してください。

1. **WordPress 開発者に連絡**して、個別の修正を依頼します
2. 競合する機能を無効化するため、**プラグイン固有のフックを検討します**
3. **条件分岐を使用**して、POS 関連ページでプラグインを無効化します

## 競合を起こしやすいプラグインの種類 {#common-conflicting-plugin-types}

### リスクの高いプラグインのカテゴリ {#high-risk-plugin-categories}

**セキュリティプラグイン：**
- API リクエストをブロックすることがあります
- 認証を妨げることがあります
- 厳しいファイアウォールルールが設定されていることがよくあります

**キャッシュプラグイン：**
- API レスポンスを不適切にキャッシュすることがあります
- リアルタイムのデータ処理を妨げることがあります
- 古いデータが残る問題を引き起こすことがあります

**SEO プラグイン：**
- 負荷の高いプラグインは管理画面の動作を遅くすることがあります
- 不要なデータベースクエリを追加することがあります
- REST API レスポンスに干渉することがあります

**ページビルダー：**
- 管理画面で負荷の高いスクリプトを読み込むことがよくあります
- WooCommerce の管理ページと競合することがあります
- チェックアウト処理を妨げることがあります

**メンバーシップ・アクセス制限プラグイン：**
- API アクセスをブロックすることがあります
- ユーザー認証を妨げることがあります
- 必要なリソースへのアクセスを制限することがあります

### リスクの低いプラグインのカテゴリ {#lower-risk-plugin-categories}

**お問い合わせフォーム：** 通常は WCPOS に干渉しません
**ソーシャルメディアプラグイン：** 競合を起こすことはまれです
**アクセス解析プラグイン：** 極端に負荷が高くなければ、通常は問題ありません
**基本的なコンテンツプラグイン：** 通常は互換性があります
**WooCommerce Tax（TaxJar による自動税計算）：** 対応しています。WCPOS は未完了の POS 注文を保存する際に税率を問い合わせるため、POS 注文にもオンライン注文と同じ税率が自動適用されます。[WooCommerce Tax](/1.x/integrations/woocommerce-tax)を参照してください。

## 既知のプラグイン競合 {#known-plugin-conflicts}

以下のプラグインは、WCPOS に干渉することが確認されています。多くの問題は最近の WCPOS バージョンで自動修正されているため、**最新バージョンに更新する**だけで、設定を変更せずに解消できます。

:::tip 多くの場合は「POS を対象から除外」すれば解決します
これらの問題には共通点があります。WCPOS は WooCommerce REST API を利用し、一部の処理（ログイン、決済、レシート）を iframe 内で表示します。通常は、他のプラグインを丸ごと無効化するのではなく、そのプラグインの処理対象から **POS のエンドポイントや URL を除外**（`/wp-json/wcpos/`、`/wp-json/wc/v3/`、`/pos/` パス）することで解決します。
:::

### セキュリティ・ログインプラグイン {#security-and-login-plugins}

これらは競合の**最も一般的な**原因で、特にデスクトップ・モバイルアプリのログインに影響します。

| プラグイン | 症状 | 対処方法 |
| --- | --- | --- |
| **Wordfence** | ファイアウォールが REST API をブロックする、ログイン iframe に 2FA コード欄が表示されない、厳しい CSP が POS のアセットをブロックすることがある | ファイアウォールで `/wp-json/wcpos/` と `/wp-json/wc/v3/` を許可リストに追加します。2FA は POS ユーザーに対して一時的に無効化します。v1.9.0+ では CSP が自動的に除去されます |
| **Really Simple Security** | API アクセスをブロックする、リダイレクトを強制する | プラグインの **詳細** 設定で REST API の制限をすべて無効化します |
| **WPS Hide Login** | カスタムログイン URL によりアプリのログイン iframe が動作しなくなる | POS へのアクセスには標準の `/wp-admin/` ログイン URL を使用します |
| **iThemes / Solid Security** | REST API をブロックする、POS からの呼び出しがブルートフォース対策のロックアウトを引き起こす | POS のエンドポイントとサーバー自身の IP だけを許可リストに追加します。広範囲の IP を一律に許可するルールは避けてください |
| **Sucuri** | WAF が API リクエストをブロックする | Sucuri のダッシュボードで REST API エンドポイントを許可リストに追加します |
| **Security Optimizer** | 管理者の POS ログインをブロックする（_「カスタムログイン URL を使用してください」_） | まずカスタム URL から WP Admin にログインし、その後 `/pos` に移動します |
| **Force Login**（および同様の REST 認証プラグイン） | `/wp-json/` が 401/403 を返す。古いアプリでは _「WordPress サイトではないようです」_ と表示される | POS のエンドポイントへの未認証アクセスを許可するか、初回接続時に無効化します。v1.x のアプリでは、実際のエラーメッセージが表示されるようになっています |
| **LoginPress** | メールアドレスによるログインを強制し、複数ユーザーでの POS ログインが動作しなくなる | ユーザー名でのログインを許可するか、POS へのアクセス時には無効化します |
| **JWT Authentication プラグイン** | 有効化後、すべての POS API リクエストで 403 が発生する（ログインは成功しても、それ以外はすべて失敗する場合がある） | v1.8.x+ で自動修正済みです。古いバージョンでは JWT プラグインを無効化するか、POS のエンドポイントを除外します |
| **Captcha / reCAPTCHA** | デスクトップアプリでログインがループする（iframe 内に CAPTCHA を表示できない） | POS のログイン URL では CAPTCHA を無効化します |
| **Defender Pro** | `X-Frame-Options` ヘッダーが POS のすべての iframe（ログイン、決済、レシート）をブロックする | サイト全体で `X-Frame-Options` を無効化するのではなく、`/pos/` に POS 専用の例外を追加します |
| **Jetpack CRM Client Portal** | POS にまったくログインできなくなる | Client Portal 拡張機能だけを無効化します |

### パフォーマンス・キャッシュ・最適化プラグイン {#performance-caching-optimisation-plugins}

| プラグイン | 症状 | 対処方法 |
| --- | --- | --- |
| **WP Rocket, Autoptimize, Hummingbird, Smush** | JS の遅延読み込みや圧縮によりチェックアウトと Stripe Terminal が動作しなくなる | JS 最適化の対象から `/pos/` の URL を除外します |
| **LiteSpeed Cache** | デスクトップアプリのチェックアウトで再読み込みが繰り返される、CSP の制限が厳しい | WCPOS を更新し、キャッシュを消去して、POS ページをキャッシュ対象から除外します。v1.9.0+ では CSP が自動的に除去されます |
| **Image Prioritizer** | HTTP の `Link` ヘッダーを大量に追加して REST API の検出を妨げる。デスクトップアプリに _「WordPress サイトではないようです」_ と表示される | プラグインを無効化します |

### ページビルダー・フロントエンドへの挿入プラグイン {#page-builders-front-end-injectors}

| プラグイン | 症状 | 対処方法 |
| --- | --- | --- |
| **Elementor** | `elementor-frontend.js` により POS の iframe 内のチェックアウトのアコーディオンが動作せず、決済方法を展開できない | Elementor のスクリプト読み込み対象から POS ページを除外します |
| **Omnisend / マーケティングプラグイン** | チェックアウトの iframe にスクリプトを挿入し、レイアウトや決済に支障が出る | POS の **チェックアウト設定** で不要なスクリプトを無効化します |
| **MyStickyElements / Complianz** | チェックアウトの iframe にオーバーレイ（固定ボタン、Cookie バナー）を挿入する | `/pos/` の URL を除外するように設定します |

### WooCommerce 拡張機能・その他のプラグイン {#woocommerce-extensions-other-plugins}

| プラグイン | 症状 | 対処方法 |
| --- | --- | --- |
| **WooCommerce Subscriptions** | v1.7→v1.8 へのアップグレード時に移行スクリプトが競合する | Subscriptions を無効化し、WCPOS Pro を有効化して移行を実行させてから、Subscriptions を再度有効化します |
| **WP Activity Log** | POS のすべての操作を記録する → postmeta が肥大化する → _「商品が 10 件しかない」_ | 無効化するか、POS の投稿タイプをログ記録の対象から除外します |
| **Jetpack / Astra / Xero**（`save_post` にフックするもの全般） | POS API 呼び出しのたびにメタデータの行が重複する（ある店舗では一つの商品で 36,867 行に達した） | v1.8.12+（無料版）/ v1.8.14+（Pro）で、クリーンアップを伴う移行により自動修正されます。更新するだけで対応できます |
| **Stripe Tax** | REST API 経由で作成された注文（POS の注文作成方法）と互換性がない | 互換性がなく、回避策はありません。自動税計算には [WooCommerce Tax](/1.x/integrations/woocommerce-tax) が対応しています |
| **Mollie** | POS のチェックアウトで BACS（銀行振込）が非表示になることがある | Mollie を最新バージョンに更新します |
| **CTX Feed** | POS の設定ページで断続的に 403 エラーが発生する | 無効化して原因かどうかを確認します。既知の回避策はありません |
| **サードパーティのバーコードスキャナープラグイン** | 注文 API の JSON を破損させ、注文の作成や表示ができなくなる | 無効化し、POS に組み込まれたバーコードスキャン機能を使用します |
| **MailerLite**（Signup Forms + WooCommerce） | POS での注文作成時に 500 エラーが発生する（メモリ不足） | 無効化して原因かどうかを確認し、MailerLite に連絡します |
| **The Courier Guy Shipping** | POS での注文作成がサーバーエラーで失敗する | 以前のバージョンに戻すか、開発者に連絡します |
| **PixelYourSite / PixelMySite** | 致命的エラー：_bool に対するメンバー関数 `is_type()` の呼び出し_ | 一時的に無効化します |
| **Google Listings & Ads** | オートローダーの競合 → _「Class WCPOS\…\Stores not found」_ という重大なエラー | POS プラグインをすべて削除し、最新の Pro スタンドアロン版だけを再インストールします |

:::warning Stripe Terminal：サイト全体で有効化しないでください
**Stripe Terminal** ゲートウェイは POS 設定内で**のみ**有効化し、`WooCommerce > 設定 > 支払い` では絶対に有効化しないでください。サイト全体で有効化すると、公開ストアのチェックアウトにも表示され、オンラインのチェックアウト処理がクラッシュします。
:::

### サーバーレベルの競合 {#server-level-conflicts}

| 原因 | 症状 | 対処方法 |
| --- | --- | --- |
| **カスタム CSP ヘッダー**（`.htaccess`、Nginx、セキュリティプラグインなど） | POS がロゴ画面で止まり、JS/CSS がブロックされる | v1.9.0+ では POS ページで自動的に除去されます。サーバーレベルの CSP の場合は、`script-src`/`style-src` で `cdn.jsdelivr.net` を許可するか、`/pos/` の例外を追加します |
| **GoDaddy Website Firewall** | `/wp-json/` をブロックする（_「Received 'undefined'」_） | ファイアウォールで `/wp-json/` の URL パスを許可します。[サーバーパフォーマンス](/1.x/support/performance/server#hosting-specific-notes)を参照してください |

## 予防のヒント {#prevention-tips}

### 定期的なメンテナンス {#regular-maintenance}

1. **プラグインを最新に保つ** - 常に最新バージョンを使用します
2. **未使用のプラグインを削除する** - 無効化するだけでなく、削除します
3. 本番サイトに適用する前に**ステージング環境で更新をテストします**
4. [サーバーパフォーマンス](/1.x/support/performance/server)の指標を使って、定期的に**パフォーマンスを監視します**

### プラグイン選択のベストプラクティス {#plugin-selection-best-practices}

1. **信頼できる開発者を選ぶ** - レビューと更新頻度を確認します
2. **機能の重複を避ける** - 同じ機能を持つプラグインを複数インストールしないでください
3. **互換性情報を読む** - WooCommerce との組み合わせでテストされているか確認します
4. **最小限のプラグインから始める** - 必要に応じて機能を少しずつ追加します

## サポートを受ける {#getting-help}

プラグインの競合を解決できない場合は、サポートをご利用ください。

### Pro ユーザー向け {#for-pro-users}

:::info Pro サポート
Pro ユーザーは、プラグイン競合の解決について優先サポートを受けられます。サポートチームが競合の特定と解決をお手伝いします。
:::

### サポートに連絡する際に必要な情報 {#when-contacting-support}

以下の情報をお送りください。

1. **有効なプラグインの一覧**と各バージョン
2. **WordPress と WooCommerce のバージョン**
3. 問題の**詳しい説明**
4. **すでに試した手順**
5. ログに記録された**エラーメッセージ**
6. 該当する場合は**サーバーパフォーマンスの指標**
