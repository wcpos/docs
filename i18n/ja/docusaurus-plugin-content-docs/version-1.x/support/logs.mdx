POS には、POS アプリ内の **アプリ内アクティビティログ** と、WordPress 内の **WP Admin のログページ** という二種類のログ画面があります。両方を確認することで、デバッグや監査に必要な POS の動作全体を把握できます。

## POS アプリケーションのログ {#pos-application-logs}

:::info v1.10.0 での変更
v1.10.0 以降、アプリ内のログは **ストアヘルス → ログ** にあります（ナビゲーションドロワーのハートビートアイコンから開きます。従来の独立したログ画面は削除されました）。このセクションでは v1.10.0 のログについて説明します。この画面全体の説明については、[ストアヘルス](/1.x/support/store-health#logs)をご覧ください。
:::

### ログへのアクセス {#accessing-logs}

左側のナビゲーションドロワーから **ストアヘルス**（ハートビートアイコン）を開き、**ログ** タブを選択します。

### インターフェースの概要 {#interface-overview}

ログには、このデバイス上のアクティビティが 30 日間記録されます。各行には次の情報が表示されます：

| 列 | 説明 |
|--------|-------------|
| **時刻** | イベントが発生した時刻 |
| **レベル** | 重要度 — エラー、警告、アクション、同期、情報 |
| **イベント** | わかりやすい説明（表示時に翻訳されます） |
| **所要時間** | 操作にかかった時間 |
| **ステータス** | 結果 |

記録の上には、同期の定期チェック状況（前回の変更チェックの実行時刻と次回の予定時刻）を示すステータス行があります。また、当日のイベント数とエラー数、処理が滞っているレコード数、送信待ちの変更数を示す統計ヘッダーがあります。ほとんどの項目は、タップするとフィルターとして使用できます。

#### フィルタリング {#filtering}

プリセットのチップで記録を絞り込めます。**すべて**、**アクション**（人が行った操作 — 販売、編集、設定変更）、**エラー**、**同期** があります。別途 **詳細診断** の切り替えがあり、24 時間にわたって追加の詳細情報を記録した後、自動的にオフになります。

### 行の詳細とエラーコード {#row-details}

エラーまたは警告の行をタップすると展開されます。詳細表示には次の情報が含まれます：

- **何が起きたか** — わかりやすい言葉での説明
- **データについて** — データの安全性に関する明確な説明（たとえば、変更がサーバー上に安全に保存されているか、このデバイス上にしか存在しないか）
- **対処方法** — 次に行うことの推奨
- **ヘルプリンク** — エラーにはコード（例：`SYNC121`、`AUTH311`）が付いており、[エラーコード](/1.x/error-codes)のドキュメントにリンクしています
- **コピー可能なイベントコード** — 行のタイトルは表示時に翻訳されるため、イベントコードが言語に左右されない識別子になります。サポートに問い合わせる際は、このコードを添えてください。

## WP Admin のログページ {#wp-admin-logs-page}

POS プラグインは、WordPress 管理画面にサーバー側のログページも提供します。このページには、サーバー上で記録された POS 固有の警告とエラーが表示され、POS アプリケーション自体には表示されない問題の診断に役立ちます。

### WP Admin のログページへのアクセス {#accessing-the-wp-admin-logs-page}

**WP Admin > POS > 設定** に移動し、**ツール** タブを選択して **ログ** をクリックします。

### 未読バッジ {#unread-badge}

ログのメニュー項目には、未読のログエントリを示すバッジが表示されます：

- **赤いバッジ** - 未読のエラーレベルのエントリがあります
- **オレンジのバッジ** - 未読の警告レベルのエントリがあります（エラーはありません）

ログページを開くと、未読件数はリセットされます。件数はユーザーごとに管理されるため、各管理者には自分の未読状況が表示されます。

### エントリのフィルタリング {#filtering-entries}

レベルフィルターを使用して、ログエントリを絞り込みます：

- **すべて** - すべてのログエントリを表示します
- **エラー** - エラーレベルのエントリのみを表示します
- **警告** - 警告レベルのエントリのみを表示します

### 展開可能なエントリ {#expandable-entries}

長いログメッセージは約 100 文字で省略されます。エントリをクリックして展開すると、メッセージの全文と追加の関連データを確認できます。

### ページネーション {#pagination}

ログエントリはサーバー側でページ分割されます。ページネーションの操作ボタンを使って、過去のエントリを参照してください。

### 致命的エラーのバナー {#fatal-errors-banner}

サーバーに `fatal-errors-*.log` ファイルがある場合、ログページの上部に警告バナーが表示されます。このバナーから **WooCommerce > ステータス > ログ** に移動し、致命的エラーのログ全文を確認できます。致命的エラーは通常、POS API が応答できなくなる PHP レベルのクラッシュです。

## サポートのためのログの活用 {#using-logs-for-support}

サポートを依頼する際は、次の手順で情報を集めてください：

1. **問題を再現します** - 問題が発生する操作を実行します
2. **ログを確認します** - **ストアヘルス → ログ** でエラーや警告を探します
3. **行を展開します** - データの安全性に関する記述と、推奨される次の手順を読みます
4. **イベントコードをコピーします** - サポートへの問い合わせに含めてください。発生した事象を特定するための、言語に左右されない識別子です
5. サポートから詳しい情報を求められた場合は、**詳細診断をオンにします** — 24 時間にわたって追加情報が記録されます

## パフォーマンスの監視 {#performance-monitoring}

パフォーマンスの集計は **店舗の状態 → パフォーマンス** で確認できます。過去 24 時間のリクエスト数、転送データ量（レスポンスにサイズが含まれない場合は下限値）、通常の応答時間に加え、時間ごとの稼働状況を示す帯状の表示があります。応答時間が長い場合は、[サーバーパフォーマンス](/1.x/support/performance/server)をご覧ください。
