# WooCommerce Tax {#woocommerce-tax}

[WooCommerce Tax](https://woocommerce.com/document/woocommerce-tax/) は、税率表を手動で管理する代わりに TaxJar を通じて売上税を自動的に検索する WooCommerce プラグインです。WCPOS はこれに対応しており、POS での販売にもオンライン注文と同じ管轄区域の税率が適用されます。WCPOS 側で有効化する必要はありません。

## 仕組み {#how-it-works}

WooCommerce Tax が TaxJar に税率を問い合わせるのは、注文がオンラインのチェックアウトを通る場合、または WooCommerce の注文画面で編集される場合のみです。POS 注文はいずれの経路も通らないため、WCPOS が代わりに問い合わせます。

1. POS で未確定注文を保存すると、WCPOS は注文の課税所在地の税率を WooCommerce Tax に問い合わせます。所在地は POS の **税計算の基準** 設定に従い、店舗の基本住所、または顧客の請求先住所・配送先住所になります。
2. WooCommerce Tax は、オンライン注文と同じように、管轄区域ごとに一行ずつ店舗の通常の税率テーブルに税率を書き込みます。`WP Admin > WooCommerce > 設定 > Tax > Standard rates` に、郵便番号と市区町村をキーとして表示されます。
3. WooCommerce はこれらの行を注文に適用します。注文には管轄区域ごとに税行が追加され、WooCommerce Tax 独自の名称（例：*CA STATE TAX*、*CA COUNTY TAX*）が使われます。
4. POS は次回の変更確認時に新しい行をダウンロードします。通常は1分以内で、それ以降はローカルの合計が店舗側の合計と一致します。すぐに取得するには、[店舗の健全性 → データベース](/1.x/support/store-health#clear-and-redownload)の **税率** 行にある **クリアして再ダウンロード** を使用します。

未確定の POS 注文で行を追加または削除すると、現在の行に基づいて税額が再計算されます。注文の支払い完了後は WCPOS が変更を加えることはなく、WooCommerce Tax は他の注文と同様に動作します。

自動税計算をオフにすると、WCPOS は特別な処理を行わず、POS は通常どおり店舗の税率テーブルを使用します。

## 設定 {#setup}

<Steps>
  <StepCard number="1" title="WooCommerce Tax を接続する">

WooCommerce Tax をインストールして有効化し、WordPress.com に接続します。`WP Admin > WooCommerce > Status > WooCommerce Tax` に **WordPress.com に接続済み** と表示されていることを確認してください。

  </StepCard>
  <StepCard number="2" title="自動税計算を有効にする">

`WP Admin > WooCommerce > 設定 > Tax` で、**自動税計算** を **自動税計算を有効化** に設定します。店舗は WooCommerce Tax がサポートする国に所在している必要があります。

これを有効にすると、手動で入力した税率は CSV ファイルにバックアップされ、テーブルから削除されます。再び必要になる可能性がある場合は、`WP Admin > WooCommerce > Status > WooCommerce Tax` からバックアップをダウンロードしてください。

  </StepCard>
  <StepCard number="3" title="POS の設定を同期する">

POS で[税設定](/1.x/settings/store/tax)を開き、**サーバー設定を復元** をクリックします。自動税計算が有効な間、WooCommerce Tax は WooCommerce の設定を、顧客の配送先住所に基づく税計算と、*税抜き*での価格入力・表示に固定します。POS でもこれらの設定を合わせる必要があります。

店頭販売用に POS で店舗の基本住所を意図的に使い続ける場合、WCPOS は店舗側の POS 注文にもその基準を使用するため、両者の計算結果は引き続き一致します。

  </StepCard>
  <StepCard number="4" title="テスト販売を行う" isLast>

**標準** 税クラスの課税対象商品で販売を行い、注文が保存されるのを待ちます。WP Admin で確認すると、管轄区域名の税行が注文に含まれ、対応する行が **標準税率** に追加されているはずです。別の税クラスの商品では、その商品を含む販売が初めて行われたときに、該当クラスに税率行が追加されます。

  </StepCard>
</Steps>

## 想定される動作 {#what-to-expect}

- **新しい地域での最初の販売では、一度だけ合計が一致しないことがあります。** POS はダウンロード済みの税率行を使って販売の合計を計算します。店舗でその住所に課税したことがなければ、該当する行がまだないため、その販売に限り POS に[合計の通知](/1.x/support/troubleshooting/totals-disagree)が表示されることがあります。記録されるのは店舗側の金額です。通常は1分以内に税率行が POS に届き、その地域での次回以降の販売では合計が一致します。顧客住所を課税基準にする場合は新しい郵便番号ごとに一度、店舗の基本住所を基準にする場合は通常、最初の販売時だけ発生します。管轄区域の税率が変更された場合にも、再び発生することがあります。
- **税率行を手動で追加しないでください。** 各地域の税率行は、その地域で最初の販売が行われたときに表示されます。POS の **すべての税率を表示** に特定の地域の税率が表示されない場合、その地域への販売はまだ行われていません。
- **手数料は TaxJar に送信されません。** 課税対象の手数料には、その税クラスに対してテーブルにすでに保存されている税率が適用されます。WooCommerce Tax 自身の注文画面でも、手数料は同じように扱われます。
- **税率の検索に失敗しても販売は妨げられません。** TaxJar に接続できない場合や、WooCommerce Tax が注文の税率検索を行わない場合（住所に郵便番号がない、顧客が免税対象である、店舗にネクサスがない地域である場合）でも、テーブルに保存済みの税率で注文は保存されます。サーバー上の POS ログで原因を確認できます。障害の場合は *WooCommerce Tax rate priming failed*、検索が行われなかった場合は *WooCommerce Tax returned no rates for the POS order* と記録されます。[ログ](/1.x/support/logs)を参照してください。
- **Stripe Tax は別のサービスです。** Stripe Tax は POS 注文には対応していません。[プラグインの競合](/1.x/support/troubleshooting/plugin-conflicts)を参照してください。
