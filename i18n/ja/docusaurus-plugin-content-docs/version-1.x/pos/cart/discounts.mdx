WCPOS には、レジ係がその場で注文を割引する方法がいくつかあります。割引率のクイックボタン、明細価格の直接編集、注文レベルの割引手数料です。利用ルールを事前に設定するプロモーションについては、[クーポン](/1.x/coupons)（Pro）を参照してください。

:::info 割引合計をお探しですか？
レジで値下げした価格は、WooCommerce の割引としてではなく、その商品のセール価格として記録されます — ネイティブの **割引** 合計はクーポン専用です。その仕組みは[価格変更とクーポンが別々に追跡される理由](#why-tracked-differently)で説明しています。v1.9.0 への更新後に合計が変わった場合は、[v1.9.0 での変更点](#what-changed-in-v190)を参照してください。
:::

## クイック割引 {#quick-discounts}

クイック割引ボタンを使うと、明細の価格からワンタップで指定した割合を値引きできます。

設定するには、カートの[表示設定](/1.x/pos/cart#display-settings)を開き、**クイック割引** フィールドに割引率をカンマ区切りで入力します。たとえば、`5,10,15,20` と入力すると、4つのショートカットボタンが作成されます。

ボタンは、明細の**価格**フィールドをクリックすると開くテンキーに表示されます。タップすると、その明細の価格が指定した割合だけ下がります。**完了**を押して確定してください。割引は明細ごとに適用されるため、複数の商品を値引きするには各明細で操作を繰り返します。注文全体を一度に値引きするボタンはありません。その場合は[注文レベルの割引](#order-level-discounts)を使用してください。

## 明細ごとの割引 {#line-item-discounts}

カート内の各明細の価格は直接変更できます。

1. 明細の **価格** フィールドをクリックします
2. 新しい価格を入力します
3. **Enter** を押して確定します

他店の価格に合わせる場合や、スタッフ割引、個別の価格調整に便利です。明細の合計は、数量 × 新しい価格に基づいて自動的に更新されます。

カート内の商品を編集する方法の詳細は、[明細](/1.x/pos/cart/line-items)を参照してください。

:::tip 商品の分割
同じ商品の一部に異なる割引を適用したい場合（例：3 点は通常価格、2 点は割引価格）、カートの[表示設定](/1.x/pos/cart#display-settings)で **分割** オプションを有効にすると、明細を別々の行に分けられます。
:::

## 注文レベルの割引 {#order-level-discounts}

個々の商品ではなく注文全体に定額の割引を適用するには、**負の手数料** を追加します。

1. カート内の商品の下にある **手数料を追加** をクリックします
2. 名前を入力します（例：「スタッフ割引」）
3. 割引額を負の数で入力します（例：`-5.00`）

手数料は別の明細行として表示され、注文合計が減額されます。必要に応じて、三点メニューから手数料の課税ステータスと税区分を編集できます。

### 割引手数料の税の計算方法 {#discount-fee-tax}

WCPOS は **手数料自身の税設定** に基づいて負の手数料に課税します。課税ステータスを **なし** に設定すると税は適用されず、**課税対象** のままにすると、その手数料の税区分に従って課税されます。入力した金額がそのまま差し引かれるため、`-10.00` と入力すると顧客の支払額は 10 少なくなります。

WooCommerce 本体では処理方法が異なります。WooCommerce 単体では、負の手数料をカート全体の割引として扱い、手数料に設定した課税ステータスを無視して、注文内の他のすべての商品の税区分に税額を配分します。また、税込価格も考慮しないため、**税込価格を入力** が *はい* の店舗では、税率が 20% の場合、`-10.00` の手数料で **12.00** が差し引かれます。WCPOS はこの処理を変更し、レジ係が入力した金額どおりに値引きします。

この処理は使用中のアプリではなく注文に紐づくため、**WP Admin → 注文** から POS 注文を再計算しても変わりません。POS 以外の注文は WooCommerce の標準動作のままです。

:::note 税込価格の店舗における既知の制限
価格に税が含まれている場合、割引手数料によって顧客への請求合計は正しくなりますが、**注文に記録される税額は変更されません**。そのため、記録される税額は減額後の金額から厳密に算出した税額よりも少し高くなります。誤差は税務当局に有利な方向にのみ生じ、逆にはなりません。帳簿上、記録される税額を正確にする必要がある場合は、代わりに[クーポン](/1.x/coupons)で割引してください。クーポンは課税対象額を減らし、それに基づいて税を正しく再計算します。この理由から、今後のリリースでは注文レベルの POS 割引をクーポンに移行する予定です。
:::

## POS 割引と WooCommerce クーポンの比較 {#pos-discounts-vs-woocommerce-coupons}

このページで紹介する割引は、レジ係がレジでその都度行う調整です。WooCommerce の **クーポン** は、ルールと追跡機能を備えた事前設定済みのプロモーションです。両者の違いを一覧で示します。

| | POS 割引 | WooCommerce クーポン（Pro） |
|---|---|---|
| **適用方法** | クイック割引、明細価格の編集、または負の手数料 | カートでクーポンコードを入力 |
| **設定場所** | レジ係がその場で設定 | **WP Admin → マーケティング → クーポン** で事前設定 |
| **追跡** | セール価格と同様に明細価格として記録（[理由](#why-tracked-differently)） | WooCommerce レポートでクーポン割引として追跡 |
| **制限** | なし — レジ係が任意の価格を設定 | 使用回数制限、商品・カテゴリー制限、最低利用額、有効期限、メールアドレスの条件 |
| **最適な用途** | 個別の調整、他店の価格への対応 | 計画的なプロモーション、追跡可能な割引 |

:::tip どちらを使うべきですか？
単発の価格調整には、このページの割引の方が簡単です。WooCommerce のレポートで割引の使用状況を追跡したり、使用回数制限などのルールを適用したりする必要がある場合は、[クーポン](/1.x/coupons)を使用してください。
:::

## 価格変更とクーポンが別々に追跡される理由 {#why-tracked-differently}

WooCommerce に組み込まれている割引の仕組みは、**クーポン** だけです。クーポンは注文に紐づき、専用フィールドに記録され、レポートの **割引** 列に集計されます。また、使用回数制限や有効期限など、独自のルールがあります。

**セール価格** は、WooCommerce では割引として扱われません。単にその商品の現在の価格です。セール中の商品を販売すると、注文には実際に支払われた価格だけが記録されます。通常価格は注文に記録されず、レポートでも通常の売上として集計されるため、WooCommerce 自体には顧客がいくら節約したかという記録は残りません。

クイック割引や明細価格の編集も、セール価格と同じ仕組みです。商品はレジ係が設定した価格で「セール中」として販売されます。このルールにより、WooCommerce の **割引** 合計はゼロのままとなり、クーポンは値下げ後の価格に対して計算され、「セール品を除外」するクーポンはレジで値下げした商品には適用されません。（注文レベルの負の手数料はこれとも異なり、価格変更ではなく手数料明細として記録されます。）

レシートでは顧客が節約額を確認できることが期待されるため、WCPOS は各明細に新しい価格とともに通常価格も記録します。これにより、WooCommerce の注文合計やレポートを変えずに、セールによる節約額とクーポン割引を二重計上せず、それぞれ別の金額としてレシートに表示できます。

## POS の価格変更とクーポンの関係 {#how-pos-price-changes-interact-with-coupons}

レジ係が明細に独自の価格を設定し（例：$18 から $16 に値下げ）、その後クーポンを適用すると、クーポンは **POS 割引後の価格**（$16）に対して計算され、元の価格（$18）は使われません。これにより、レジ係の値引きとクーポンを元の価格に重ねて適用して、過剰に割り引くことを防ぎます。

- POS で割引した商品は、WooCommerce では「セール中」として扱われます。クーポンで **セール品を除外** が有効になっている場合、通常のセール品と同じように、POS で割引した商品も対象外になります。開発者は `woocommerce_pos_item_is_on_sale` フィルターでこの動作を変更できます。
- クーポンを削除しても、明細は POS 割引後の価格のままです。

:::note 開発者向けリファレンス
POS で上書きした価格の保存方法や、利用可能なフィルターの技術的な詳細については、[POS 割引リファレンス](/1.x/reference/pos-discounts)を参照してください。
:::

## v1.9.0 での変更点 {#what-changed-in-v190}

v1.8 からアップグレードして、レシートやレポートの **割引** 合計が **0** と表示されるようになった場合、その理由は次のとおりです: 以前のバージョンでは、レジでの価格変更を WooCommerce の割引として記録していましたが、これはクーポンの計算を壊していました — 上から適用したクーポンが元の価格に対して計算され、注文を過剰に割引して顧客への請求が不足していました。v1.9.0 以降、レジで設定した価格**が**明細の価格そのものであり、これは WooCommerce がセール中の商品を記録する方法とまったく同じで、割引としてカウントされるのはクーポンだけです。上記の[価格変更とクーポンが別々に追跡される理由](#why-tracked-differently)を参照してください。

### この変更による影響 {#what-this-means-for-you}

- **レシート** には、記録された通常価格、通常価格と販売価格の差額による節約額、その節約額とクーポン割引を合わせた **合計節約額** を表示できます。価格変更による節約額は、WooCommerce の **割引** フィールドとは別に扱われます。
- **レポート** では、POS の明細価格の変更のみを行った場合、`discount_total = 0` と表示されます。集計されるのはクーポン割引のみです。
- **クーポン** は、POS で割引した商品に重ねて適用した場合も、正しく計算されるようになりました。
- **記録された通常価格と販売価格は保存されます**。保存先は POS の明細メタデータ(`_woocommerce_pos_data`)で、WooCommerce の割引合計を変えることなく、レシートで節約額を算出できます。

### レシートに元の価格と節約額を表示する {#showing-the-original-price-and-saving-on-receipts}

現在同梱されている価格表示対応のテンプレートでは、商品がセール中の場合やレジで価格を変更した場合に、記録された通常価格と節約額が表示されます。また、WCPOS が注文全体の金額を完全に計算できる場合は **合計節約額** も表示されます。この合計は、通常価格からの節約額とクーポン割引を二重計上せずに合算したものです。

ギャラリーからコピーしたテンプレートは編集可能なスナップショットで、WCPOS の更新では上書きされません。この変更より前にレシートを作成した場合は、次のいずれかを行ってください。

1. 同梱テンプレートの新しいコピーで **テンプレートを使用** をクリックする、または
2. [レシートデータリファレンス](/1.x/receipts/receipt-data#displaying-regular-price-and-savings)のフィールドを使用して既存のテンプレートを更新します。

主なレシートフィールドは次のとおりです。

| フィールド | 意味 |
|-------|---------|
| `lines[].regular_price_display` | 記録された通常の単価 |
| `lines[].selling_price_display` | クーポン適用前の販売単価 |
| `lines[].unit_savings_display` | 商品一点あたりの節約額 |
| `lines[].line_regular_total_display` | 明細の通常価格での合計 |
| `lines[].line_savings_display` | 明細の節約額合計 |
| `totals.sale_savings_total_display` | カタログのセールとレジでの価格変更による、通常価格と販売価格の差額の合計 |
| `totals.discount_total_display` | WooCommerce の割引合計。現在の注文では通常、クーポンによる割引 |
| `totals.total_saved_display` | 通常価格からの節約額と WooCommerce の割引の合計 |
| `totals.total_saved_complete` | 合算した金額が完全で、表示しても問題ないかどうか |

カスタムテンプレートでは、過去の価格データが不完全な場合や節約額がない場合に **合計節約額** の行を非表示にする条件を設けてください。具体的な記述方法は[レシートデータリファレンス](/1.x/receipts/receipt-data#totals)を参照してください。

WooCommerce のレポートに変更はありません。標準の割引合計に含まれるのは引き続きクーポンのみで、現在のセール価格やレジでの価格変更による節約額は含まれません。レシートには `totals.total_saved` を使用し、レポートでも節約額を WooCommerce の割引として追跡する必要がある場合は、引き続き[クーポン](/1.x/coupons)を使用してください。

## 既知の制限事項 {#known-limitations}

- **自動割引ルールはありません** — POS は「2 個購入で 1 個無料」のような自動割引には対応していません。ルールに基づくプロモーションには WooCommerce クーポンを使用してください。
- **クイック割引はパーセントのみです** — 定額割引用のクイックボタンは組み込まれていません。代わりに負の手数料を使用するか、個々の価格を編集してください。
- **割引手数料と税込価格** — 注文レベルの割引手数料は正しい合計を請求しますが、注文に記録される税は減額しません。[割引手数料の税の計算方法](#discount-fee-tax)を参照してください。
