WCPOS は各デバイスに商品のローカルコピーを保持します。そのため、カタログの閲覧と検索は瞬時に行われ、オフラインでも動作し続けます。このガイドでは、商品がどのようにデバイスに取り込まれ、どのように最新の状態に保たれるかを説明します。

:::info v1.10.0 での変更
v1.10.0 では新しい同期エンジンが導入されました。ご利用の POS が v1.10.0 より前の場合は、後述の [v1.10.0 での変更点](#what-changed-in-v1100)を参照してください。
:::

## 商品がデバイスに取り込まれる仕組み {#how-products-arrive}

- **カタログのシードがバックグラウンドで実行されます。** 初回起動時から、POSはスケジュールに従ってカタログを小分けにダウンロードします。操作は不要です。最初の商品が取り込まれた時点で販売を開始でき、チェックアウトのためにダウンロードの完了を待つ必要はありません。
- **表示する商品は必要に応じてダウンロードされます。** 検索、カテゴリーでの絞り込み、バーコードスキャンを行うと、該当する商品がまだローカルにない場合は直接取得されます。検索時に無関係な商品まで取得することはなく、指定した商品だけを取得します。
- **変更の確認によって更新が反映されます。** 商品がローカルに保存されると、POSは変更の有無を確認するためだけに商品を再ダウンロードすることはありません。軽量な変更ログを定期的に確認し（デフォルトのプリセットでは60秒ごと）、実際に変更されたものだけを取得します。変更のない店舗では、ほとんど負荷のかからない「変更なし」という応答だけが返されます。

## バッチのサイズはどれくらいですか？ {#batch-size}

デフォルトでは、POSは**一度に50件の商品**をリクエストします。この値は固定ではなく、**店舗の健全性 → パフォーマンス**の同期プリセットで設定される二つの調整項目の一つです。

| プリセット | チェック間隔 | リクエストあたりのレコード数 |
| --- | --- | --- |
| エコ | 5分 | 25 |
| バランス（デフォルト） | 60秒 | 50 |
| リアルタイム | 10秒 | 75 |

バッチを小さくするのは、サーバーの負荷を抑えるためです。大量のデータを含むページの生成にはサーバーの処理時間がかかり、共有ホスティングではストアフロントの動作が遅くなったり、レート制限に達したりする可能性があります。性能が控えめなホスティングではエコを、高性能なホスティングで複数のレジを運用する店舗ではリアルタイムを選んでください。詳細は[ストアヘルス](/1.x/support/store-health#sync-presets)を参照してください。

## ダウンロードの進捗を確認する {#checking-progress}

**ストアヘルス → データベース**を開くと、コレクションごとに、このデバイスとサーバー上のレコード数をカバレッジバーとともに確認できます。*サーバー上*の数値は、サーバーが実際に報告した合計です。POSがまだ確認中の場合、その行には推測値ではなく *確認中…* と表示されます。

商品のバーが途中までしか埋まっていない場合は、シードがまだ完了していないだけです。バックグラウンドで引き続き処理されます。特定の商品が見当たらない場合は、検索すると直接取得できます。

:::tip
コレクションの処理が止まっているように見える場合は、[すべてのローカルデータのクリア](/1.x/support/troubleshooting/clear-local-data)で全体をリセットする前に、ストアヘルス → データベースの該当行で**クリアして再ダウンロード**を使用してください。
:::

## v1.10.0での変更点 {#what-changed-in-v1100}

以前のバージョンでは、カタログは*使用に伴って段階的に*ダウンロードされていました。検索やスクロールのたびに次のバッチの商品が取得され、5分ごとに全件のポーリングが実行されていました。この方式は廃止されました。v1.10.0では次のように動作します。

- スケジュールに従ってバックグラウンドでシードが実行され、カタログが取り込まれます。商品をダウンロードするために検索やスクロールを行う必要はありません。
- 検索では、任意の次のバッチではなく、検索条件に一致する商品を取得します。
- 変更の確認は、固定の5分間隔での全件ポーリングではなく、選択したプリセットの間隔（デフォルトは60秒）で条件付きリクエストを使って行われます。
- ダウンロードの進捗は、**ストアヘルス → データベース**でコレクションごとに確認できます。

開発者向けの詳しい仕組みは、[同期エンジンの仕組み](/1.x/reference/sync-engine)を参照してください。

## よくある質問 {#faq}

<Accordion>
  <AccordionItem question="商品をダウンロードするために何か操作が必要ですか？">

  いいえ。カタログのシードがバックグラウンドで自動的に商品をダウンロードします。検索や絞り込みを行うと、対象の商品がまだローカルにない場合はすぐに取得されます。ただし、ダウンロード全体を完了させるのは通常の閲覧操作ではなく、バックグラウンドのシードです。

  </AccordionItem>

  <AccordionItem question="商品の変更はどれくらいの速さでPOSに反映されますか？">

  デフォルトのバランスプリセットでは、POSは60秒ごとに変更を確認します（複数のレジが同時にサーバーへアクセスしないよう、確認のタイミングには少しランダムなずれを設けています）。取得されるのは変更された商品だけです。複数のレジ間で変更をより早く反映する必要がある場合は、リアルタイムプリセットを使用してください。

  </AccordionItem>

  <AccordionItem question="POSですべての商品が表示されません">

  次のような原因が考えられます。

  - バックグラウンドのシードがまだ完了していない可能性があります。**ストアヘルス → データベース**の商品の行を確認してください。
  - POSはデフォルトで在庫切れ商品を非表示にします。これは商品表示設定で変更できます。
  - WooCommerce REST APIは標準の商品タイプ（シンプル、バリエーション、グループ化、外部）のみに対応しています。カスタム商品タイプはPOSに表示されない場合があります。

  </AccordionItem>
</Accordion>
