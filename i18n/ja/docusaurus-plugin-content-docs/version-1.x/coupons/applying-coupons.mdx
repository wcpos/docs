:::info Pro 機能
レジでクーポンを適用するには [WCPOS Pro](/1.x/getting-started/pro-license) が必要です。無料版では[クーポン](/1.x/coupons)画面をぼかし表示のプレビューで確認できますが、カートの**クーポンを追加**アクションは無効になっています。
:::

このページでは、レジでのクーポンの検索、適用、複数クーポンの併用、エラーへの対処について説明します。クーポンの種類、設定、検証ルールについては[クーポン](/1.x/coupons)を、レジ係がその場で設定する割引については[カート割引](/1.x/pos/cart/discounts)を参照してください。

## クーポン追加の流れ {#the-add-coupon-flow}

カートの明細行の下に**クーポンを追加**ボタンがあります。タップすると小さな入力欄が開き、コードを入力するか検索できます。

1. カートの**クーポンを追加**をタップします
2. 入力を始めると、同期済みのすべてのクーポンのコードと説明を検索できます
3. 候補リストからクーポンを選択するか、コードを最後まで入力して **Enter** を押します

クーポンはローカルに同期されたデータに基づいて即座に検証され、割引がカート合計に反映されます。サーバーとの往復通信は発生しません。その後カートの内容を変更すると（商品の追加、数量の変更、顧客の変更など）、割引は自動的に再計算されます。

{/* Screenshot: cart-add-coupon-search.png */}

:::tip コード入力と検索
レジ係がコード（例：「SUMMER10」）を知っている場合は、コードを入力して Enter を押すのが最も速い方法です。検索は、顧客が印刷されたクーポンを持参したもののスタッフが正確なコードを覚えていない場合や、顧客名でロイヤルティ割引を探す場合に便利です。
:::

## カート内のクーポンピル {#coupon-pills-in-the-cart}

適用されたクーポンはそれぞれ、カートの合計金額のすぐ上に小さな**ピル**として表示されます。ピルにはクーポンの説明（未設定の場合はコード）と割引額が表示されます。ピルの **×** をタップすると、そのクーポンが削除され、カート合計が即座に再計算されます。

{/* Screenshot: cart-coupon-pills.png */}

複数のクーポンが適用されている場合、ピルは縦に並びます。表示順は追加された順序であり、この順序は[順次割引](#sequential-discounts)に影響します。

:::note レシートのラベル
ピルのテキストはレシートにも印刷されます。クーポンコードそのものよりわかりやすいラベル（例：*「LOYAL10」* ではなく *「ロイヤルティ割引」*）を使いたい場合は、`WP Admin → Marketing → Coupons` でクーポンの**説明**フィールドを設定してください。WCPOS は説明が設定されている場合、それを割引ラベルとして使用します。
:::

## 順次割引 {#sequential-discounts}

注文には複数のクーポンを適用できます。WooCommerce はクーポンを**順番に**処理します。各クーポンは元のカート合計ではなく、直前のクーポン適用後の小計に対して割引を適用します。

### 計算例 {#worked-example}

カート小計：**$100.00**

| ステップ | クーポン | 計算 | 適用後の合計 |
|---|---|---|---|
| 1 | `LOYAL10`（10%オフ） | $100 × 0.90 | **$90.00** |
| 2 | `WELCOME5`（カートから$5オフ） | $90 − $5 | **$85.00** |
| 3 | `EXTRA20`（20%オフ） | $85 × 0.80 | **$68.00** |

適用する順序によって最終的な金額が変わります。10%クーポンを二つ併用すると、元の金額からの割引は20%ではなく19%になります。二つ目の10%は、すでに割引された合計額に適用されるためです。

### クーポンを併用できない場合 {#when-coupons-cant-stack}

WooCommerce で**個別利用のみ**に設定されたクーポンは、他のクーポンと併用できません。`SUMMER25` が個別利用に設定されている場合：

- `SUMMER25` を先に適用 → 他のクーポンを追加すると *「このクーポンは他のクーポンと併用できません。」* と表示されます
- 他のクーポンを先に適用 → `SUMMER25` を追加すると同じメッセージが表示されます。

競合するクーポンを削除してから、もう一方を適用してください。

### 商品固定割引クーポン {#fixed-product-coupons}

**商品固定割引**クーポン（例：*Tシャツ各点につき$2割引*）は、条件に一致する商品明細のみを割引し、他のクーポンの計算に使う小計は減額しません。カート全体への割合割引クーポンと併用しても、想定どおりの割引になります。

## クーポンの削除 {#removing-a-coupon}

- クーポンピルの **×** をタップすると、そのクーポンだけが削除されます。
- カートをクリアすると（**その他**メニュー → *カートをクリア*）、適用済みのクーポンがすべて削除されます。
- 商品制限付きクーポンの*唯一の*対象商品である明細を削除すると、クーポンも自動的に削除され、「クーポンを削除しました：対象商品がありません」というトースト通知が短時間表示されます。

## 検証エラーとその解決方法 {#validation-errors-and-how-to-resolve-them}

POS は WooCommerce と同じ検証ルールを適用します。すべてのルールは[バリデーションの仕組み](/1.x/coupons#how-validation-works)を参照してください。クーポンが拒否されると、レジ係に具体的なメッセージが表示されます：

| メッセージ | 意味 | 対処方法 |
|---|---|---|
| *「クーポンが存在しません」* | 同期済みデータにコードが見つかりませんでした。 | 入力が正しいか確認してください。WP Admin でクーポンを作成した直後の場合は、[クーポン](/1.x/coupons)画面から同期を実行してください（同期アイコンを長押しして**クリアして更新**を選択）。 |
| *「このクーポンは有効期限切れです」* | 現在の日付がクーポンの有効期限を過ぎています。 | WP Admin で有効期限を延長するか、別のコードを使用してください。 |
| *「使用回数の上限に達しました」* | クーポン全体の使用回数上限に達しています。 | WP Admin で上限を引き上げるか、別のコードを使用してください。 |
| *「この顧客はすでにこのクーポンを使用しています」* | 選択した顧客がユーザーごとの使用回数上限を超えています。 | 顧客を切り替えるか、ユーザーごとの上限を引き上げてください。 |
| *「最低利用金額に達していません」* | カート小計がクーポンの最低利用金額を下回っています。 | 商品を追加するか、別のコードを使用してください。 |
| *「最高利用金額を超えています」* | カート小計がクーポンの最高利用金額を超えています。 | 注文を分割するか、別のコードを使用してください。 |
| *「このクーポンは他のクーポンと併用できません」* | 新しいクーポンか適用済みのクーポンが**個別利用のみ**に設定されています。 | 競合するクーポンを削除してから、使用したいクーポンを適用してください。 |
| *「このクーポンはカート内の商品には使えません」* | カート内にクーポンの商品・カテゴリ制限に一致する商品がありません。 | 対象商品を追加するか、別のクーポンを選択してください。 |
| *「このクーポンはこの顧客には使えません」* | 選択した顧客のメールアドレスがクーポンの**許可メールアドレス**の条件に一致しません。 | メールアドレスが一致する顧客に切り替えるか、メールアドレスの制限を解除してください。 |

クーポンがローカルの検証を通過したのに会計時に注文が拒否された場合、サーバーがより新しいデータで再検証した結果です。通常は、同じシフト中の別の販売で使用回数の上限に達したことが原因です。クーポンを再適用するか、別のクーポンを選択してください。

## 一般的なワークフロー {#common-workflows}

<Accordion>
  <AccordionItem question="マネージャー割引 — 追跡可能なコードによる臨時の10%オフ">

`WP Admin → Marketing → Coupons` で、`MGR10` などの名前のクーポンを作成します：
- **割引タイプ：** 割合割引
- **クーポン金額：** 10
- **クーポンごとの使用回数制限：** *（空欄 — 無制限）*
- **個別利用のみ：** オフ（ロイヤルティコードやプロモーションコードと併用できるようにします）
- **説明：** *「マネージャー割引」*（レシートに印刷される文言です）

コードはマネージャーにだけ共有してください。このクーポンは WooCommerce のレポートに追跡可能な割引として表示されます。一方、[POSでの価格変更](/1.x/pos/cart/discounts)は、現在は明細の価格を下げるだけです。

  </AccordionItem>

  <AccordionItem question="ロイヤルティ特典 — リピーター向けの$5オフ">

`LOYAL5` を作成します：
- **割引タイプ：** カート定額割引
- **クーポン金額：** 5
- **最低利用金額：** 25 *（または任意のしきい値）*
- **ユーザーごとの使用制限：** 1 *（特典が一度限りの場合）*
- **説明：** *「ロイヤルティ特典」*

レジで「ロイヤルティ」と検索すれば、コードを覚えていなくても見つけられます。

  </AccordionItem>

  <AccordionItem question="一度限りのプロモーション — チラシや印刷物を使ったキャンペーン">

キャンペーンごとにクーポンを作成し、一度だけ使えるチラシの場合は**クーポンごとの使用回数制限：1**に、複数回使えるプロモーションの場合はそれより大きい数に設定します。後日誤ってコードが再利用されないよう、**有効期限**を短く設定してください。

複数回使えるプロモーションで各顧客の利用を一度に制限する場合は、**クーポンごとの使用回数制限** *と* **ユーザーごとの使用制限：1**の両方を設定してください。

  </AccordionItem>

  <AccordionItem question="顧客が持参したクーポンコードにマネージャー割引を追加する">

顧客のコードを先に適用し、その後にマネージャーのコードを適用します。WooCommerce は順番に処理するため、マネージャー割引は割引済みの合計額に対して計算されます。通常、これは顧客が期待する動作です。

顧客のクーポンが**個別利用のみ**に設定されている場合、マネージャーのコードは拒否されます。先に顧客のクーポンを削除するか（必要なら後で再適用）、WP Admin で顧客のクーポンを更新して併用を許可してください。

  </AccordionItem>

  <AccordionItem question="顧客が注文の一部を返品し、別のクーポンで会計し直したい場合">

まず元の注文を払い戻し（[払い戻し](/1.x/orders/refunds)を参照）、新しいクーポンを使って新規の販売を開始してください。クーポンは販売時に注文に紐づくため、POS から完了済み注文のクーポンを後で差し替えることはできません。払い戻すとクーポンの使用回数が戻るので、新しい注文で再び適用できます。

  </AccordionItem>
</Accordion>

## POSでの価格変更との関係 {#interaction-with-pos-price-changes}

レジ係が明細の価格を下げた後（[POSでの価格変更](/1.x/pos/cart/discounts)）にクーポンを適用すると、元の価格ではなく**値下げ後の価格**で割引が計算されます。POS で値下げした明細は「セール中」として扱われるため、**セール商品を除外**が有効なクーポンは適用されません。

これは意図した動作です。レジ係による割引とクーポンが元の価格に対して二重に適用されるのを防ぎます。詳しい仕組みは[POS価格変更とクーポンの相互作用](/1.x/pos/cart/discounts#how-pos-price-changes-interact-with-coupons)を参照してください。

## オフライン時の動作 {#offline-behaviour}

- **クーポンの適用はオフラインでも動作します** — ローカルに同期されたクーポンデータに基づいて検証します。
- **オフラインでも販売を完了できます**。オフライン対応の支払い方法が必要です。注文はローカルで送信待ちとなり、WooCommerce に届くとサーバーがクーポンを再検証し、使用回数を更新します。
- **WP Adminで作成したばかりのクーポン**は、次回の同期までレジで適用できません。次の画面から操作します： [クーポン](/1.x/coupons) 画面フッターの同期アイコン（<Icon name="arrow-rotate-right" />）をタップします。最新データを取得するには、長押しして**クリアして更新**を選択してください。
