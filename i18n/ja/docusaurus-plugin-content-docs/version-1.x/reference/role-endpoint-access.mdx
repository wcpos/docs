このページでは、POSのワークフローで使用する3つのデフォルトロールについて、それぞれがアクセスできるWCPOS RESTエンドポイントを説明します。

- `administrator`
- `shop_manager`
- `cashier`

ユーザー向けのロールと権限の設定については、[POSへのアクセス](/1.x/settings/wp-admin/access)を参照してください。

## 概要 {#summary}

デフォルトのアクセスモデルは次のとおりです。

- **`administrator`** — POSと管理機能へのフルアクセス。
- **`shop_manager`** — プラグインのインストール権限が必要な拡張機能の操作を除き、POSと管理機能へのフルアクセス。
- **`cashier`** — 通常のPOS販売ワークフローにアクセスできますが、管理、設定、ログ、店舗管理にはアクセスできません。

エンドポイントマトリックスは、POSアプリと同じ認証経路を使用する統合テストで検証されています（`wp_set_current_user()` だけでなく、WCPOSのベアラーアクセストークンを使用します）。許可されたエンドポイントのアサーションでは、そのロールに `401` や `403` が返されないことを確認します。最小限のフィクスチャでテストすると、一部のエンドポイントは通常のデータや、`400`、`404` などの業務処理上のエラーを返す場合があります。こうしたレスポンスでも、ユーザーが認証・権限レイヤーを通過したことを確認できます。

## エラーの診断 {#diagnosing-failures}

デフォルトの `shop_manager` に次のようなエラーが表示される場合：

> トークンを更新してもリクエストが認証されません - もう一度ログインしてください

エンドポイントマトリックスが示すとおり、デフォルトの `shop_manager` ロールにそもそもPOSへのアクセス権がないことが原因では**ありません**。次の原因が考えられるため、調査してください。

1. サイト固有のロール・権限の破損。
2. マトリックスの対象外のエンドポイント。
3. 古い、または期限切れのアクセストークンを使用したクライアント側の再試行動作。
4. サードパーティのセキュリティプラグインや認証プラグインによる干渉。
5. Proや店舗固有のアクセスルール、またはカスタムコード。

### 権限エラーとトークンエラーの違い {#permission-failure-vs-token-failure}

POSフロントエンドが `401` または `403` を受け取り、トークンを更新して再試行しても認証されない場合、どちらのケースでも同じトークン更新エラーが表示されることがあります。サーバー側では、この2種類のエラーを次のように区別できます。

**実際のロール・権限エラー**は、通常次のようになります。

```text
status: 403
current_user: <actual user id>
access token expired: false
```

**トークン・認証エラー**は、通常次のようになります。

```text
status: 403
current_user: 0
access token expired: true or invalid
```

POSアクセスの問題を切り分ける際は、この違いを確認してください。`current_user` がゼロ以外なら権限の問題、`current_user: 0` なら認証・トークンレイヤーの問題が考えられます。
