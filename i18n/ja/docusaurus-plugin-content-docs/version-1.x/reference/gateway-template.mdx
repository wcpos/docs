# ゲートウェイテンプレート {#gateway-template}

Gateway Template は、POS専用の決済ゲートウェイを作成するための出発点です。必要に合わせてインストール、カスタマイズできる、単一のPHPファイルからなる動作可能なWordPressプラグインを生成します。

## 機能 {#features}

<FeatureGrid>
  <FeatureCard icon="code" title="最小限のコード">
    必要なものだけを含む単一のPHPファイルで、読みやすく変更も簡単です
  </FeatureCard>
  <FeatureCard icon="store" title="POS専用">
    デフォルトではウェブのチェックアウトで無効になっており、WCPOSの設定から有効にできます
  </FeatureCard>
  <FeatureCard icon="terminal" title="セットアップの自動化">
    シェルスクリプトがプレースホルダーをすべて置き換えます
  </FeatureCard>
  <FeatureCard icon="rocket" title="GitHubリリース">
    バージョンを更新してプッシュすると、GitHub Actionsがダウンロード可能なZIPをビルドします
  </FeatureCard>
</FeatureGrid>

## はじめに {#getting-started}

<Steps>
  <StepCard number="1" title="テンプレートリポジトリをクローンする">

```bash
git clone https://github.com/wcpos/woocommerce-gateway-template.git
cd woocommerce-gateway-template
```

または、[GitHubリポジトリ](https://github.com/wcpos/woocommerce-gateway-template)の**このテンプレートを使用**ボタンをクリックして、自分用のコピーを作成してください。

  </StepCard>
  <StepCard number="2" title="セットアップスクリプトを実行する">

```bash
./create-gateway.sh
```

スクリプトでゲートウェイ名、短い説明、GitHubユーザー名などを入力すると、指定したディレクトリにすぐに使えるプラグインが生成されます。

  </StepCard>
  <StepCard number="3" title="プラグインをインストールする">

選択肢は2つあります。

**方法A — フォルダーを直接コピーする**（サーバーにアクセスできる場合）:
生成されたゲートウェイフォルダーをサイトの`wp-content/plugins/`ディレクトリにコピーします。

**方法B — ZIPにしてアップロードする**（ほとんどの方におすすめ）:
1. 生成されたフォルダーを`.zip`ファイルに圧縮します
2. WordPressで**プラグイン > 新規追加 > プラグインのアップロード**に進みます
3. ZIPファイルを選択し、**今すぐインストール**をクリックします

  </StepCard>
  <StepCard number="4" title="WCPOSで有効にする" isLast>

1. **WP Admin > POS > 設定 > チェックアウト**に進みます
2. 一覧から新しいゲートウェイを見つけて有効にします

:::note
ゲートウェイはデフォルトで通常のウェブチェックアウトでは無効です。POSに表示するゲートウェイは、WCPOS独自の設定で制御します。
:::

  </StepCard>
</Steps>

## 手動でセットアップする {#manual-setup}

スクリプトを使わない場合は、プレースホルダーを自分で置き換えることができます。各ファイルをテキストエディターで開き、次の項目を検索して置換してください:

| プレースホルダー | 入力する値 | 例 |
|---|---|---|
| `{{GATEWAY_NAME}}` | ゲートウェイの表示名 | 現金払い |
| `{{GATEWAY_SLUG}}` | URLで使用できる識別子（小文字、ハイフン） | cash-payment |
| `{{GATEWAY_DESCRIPTION}}` | ゲートウェイの短い説明 | WCPOSで現金払いを受け付ける |
| `{{GATEWAY_DEFAULT_DESCRIPTION}}` | チェックアウト時にレジ係に表示するテキスト | POSで現金で支払う |
| `{{GITHUB_USERNAME}}` | GitHubユーザー名 | kilbot |
| `{{REPO_NAME}}` | リポジトリ名 | cash-payment-gateway |
| `{{AUTHOR_NAME}}` | 名前 | kilbot |
| `{{GATEWAY_ID}}` | ハイフンをアンダースコアに置き換えたスラッグ | cash_payment |
| `{{GATEWAY_CLASS_NAME}}` | 各単語を大文字で始め、アンダースコアで連結した名前 | Cash_Payment |
| `{{GATEWAY_FUNCTION_PREFIX}}` | Gateway IDと同じ値 | cash_payment |

次に、`wcpos-{{GATEWAY_SLUG}}.php`をスラッグに合わせて名前変更します（例: `wcpos-cash-payment.php`）。

:::tip
セットアップスクリプトは名前とスラッグから`GATEWAY_ID`、`GATEWAY_CLASS_NAME`、`GATEWAY_FUNCTION_PREFIX`を自動的に生成します。手動でセットアップする場合にのみ、これらを指定してください。
:::

## 仕組み {#how-it-works}

生成されたプラグインはWooCommerceの決済ゲートウェイクラスを登録します。主なポイントは次のとおりです:

- **`$this->enabled = 'no'`** — ゲートウェイをウェブチェックアウトでは非表示にします。WCPOSはPOSの設定に基づいて有効にします。
- **`process_payment()`** — `$order->payment_complete()`を呼び出し、注文を支払い済みにして在庫を自動的に減らします。
- **`init_form_fields()`** — WooCommerceの設定に表示される「タイトル」と「説明」フィールドを定義します。

## ゲートウェイをカスタマイズする {#customising-your-gateway}

### 決済フィールドを追加する {#adding-payment-fields}

ゲートウェイでレジ係からの入力（参照番号など）が必要な場合は、`payment_fields()`メソッドをオーバーライドします:

```php
public function payment_fields() {
    if ( $this->description ) {
        echo wpautop( wptexturize( $this->description ) );
    }

    woocommerce_form_field( 'my_gateway_reference', array(
        'type'        => 'text',
        'label'       => __( 'Reference Number', 'your-text-domain' ),
        'required'    => true,
    ) );
}
```

送信された値は、`process_payment()`を使って`$_POST['my_gateway_reference']`で読み取れます。入力値は必ず`sanitize_text_field()`でサニタイズしてください。

### 決済動作を変更する {#changing-payment-behaviour}

デフォルトのテンプレートでは、注文はすぐに支払い済みになります。請求書のように後から支払うワークフローでは、`payment_complete()`をステータス更新に置き換えてください:

```php
public function process_payment( $order_id ) {
    $order = wc_get_order( $order_id );

    // Set to pending — the customer will pay later.
    $order->update_status( 'pending', __( 'Awaiting payment', 'your-text-domain' ) );

    // Stock must be reduced manually when not using payment_complete().
    wc_reduce_stock_levels( $order_id );

    return array(
        'result'   => 'success',
        'redirect' => $this->get_return_url( $order ),
    );
}
```

## 変更と更新 {#making-changes-and-updating}

ゲートウェイのインストール後も、プラグインファイルを編集して決済ロジックを調整できます。更新版をインストールするには:

1. 生成されたフォルダー内の`wcpos-your-slug.php`を編集します
2. プラグインヘッダーの`Version:`番号を更新します（例: `0.1.0`から`0.2.0`）
3. フォルダーをZIPにして**プラグイン > 新規追加 > プラグインのアップロード**から再度アップロードするか、`wp-content/plugins/`内のフォルダーを直接置き換えます

:::tip
同じプラグイン名のZIPをアップロードすると、WordPressは既存のプラグインを置き換えるか尋ねます。更新するには**アップロードしたもので現在のものを置き換える**をクリックします。
:::

### GitHubでリリースを自動化する {#automated-releases-with-github}

ゲートウェイをGitHubリポジトリにプッシュすると、テンプレートに含まれるGitHub Actionsワークフローがリリースを自動作成します:

1. プラグインヘッダーの`Version:`番号を更新します
2. `main`ブランチにコミットしてプッシュします
3. GitHub Actionsがバージョン変更を検出し、ダウンロード可能なZIP付きの新しいリリースを作成します

他のユーザーはリポジトリの**リリース**ページからZIPをダウンロードし、他のWordPressプラグインと同じようにインストールできます。

## トラブルシューティング {#troubleshooting}

<Accordion>
  <AccordionItem question="ゲートウェイがPOSに表示されない">

  - **WP Admin > プラグイン**でプラグインが有効化されていることを確認します
  - **WP Admin > POS > 設定 > チェックアウト**に進み、ゲートウェイが有効になっていることを確認します
  - WooCommerceがインストールされ、有効化されていることを確認します

  </AccordionItem>

  <AccordionItem question="ゲートウェイがウェブのチェックアウトに表示される">

  - ゲートウェイのコンストラクターで`$this->enabled = 'no';`が設定されていることを確認します
  - WCPOSはPOSリクエストに対してこの設定を上書きするため、ゲートウェイはPOSにのみ表示されるはずです

  </AccordionItem>

  <AccordionItem question="注文が「処理中」のままで「完了」にならない">

  - WooCommerceは商品タイプに基づいて注文ステータスを設定します。物理商品を含む注文が「処理中」のままになるのは、WooCommerceの通常の動作です。仮想商品またはダウンロード商品のみを含む注文だけが自動的に「完了」になります。

  </AccordionItem>
</Accordion>
