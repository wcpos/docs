WCPOSは、商品データと顧客データを各デバイスのローカルデータベースに保存します。そのため、POSの一部の機能はインターネット接続なしで動作しますが、接続が必要な機能もあります。

## オフラインで利用可能な機能 {#what-works-offline}

- **商品の閲覧** — ローカルデータから商品の検索、絞り込み、詳細表示ができます
- **顧客の閲覧** — 顧客名、メールアドレス、住所を検索できます
- **カートの作成** — 商品の追加、数量の変更、価格の編集、POS割引の適用ができます
- **クーポンの適用**（Pro） — コードは同期済みのクーポンデータに照らしてローカルで検証されます。キューに入った注文がサーバーに届くと、サーバーが再検証します
- **注文の保存** — 注文を保留または保存するとデバイスに保存され、送信キューに追加されます。接続が復旧するとWooCommerceに送信されます
- **バーコードスキャン** — バーコードをスキャンしてローカルデータベースから商品を検索できます
- **レポートの表示** — デフォルトのレポートタイプ（オフライン）では、ローカルに保存された注文からレポートを生成します

## 接続が必要な機能 {#what-requires-a-connection}

- **決済** — チェックアウトを完了するには、サーバーでホストされる決済ページを表示するため、オフラインでは決済手続きを完了できません。オフライン中でも注文を作成して**保存**し、オンラインに戻ってから決済できます。
- **サーバーに依存するチェックアウト操作** — Webチェックアウト、統合型のオンラインゲートウェイや決済端末ゲートウェイ、**サーバーに保存**は、それぞれのサービスに接続できる必要があります
- **データの同期** — WooCommerceから新しい商品、更新された価格、新しい顧客を取得します
- **ログイン** — 初回の認証にはWordPressサイトへの接続が必要です
- **ライセンスの有効化** — Proライセンスの確認にはWCPOSライセンスサーバーへの接続が必要です
- **返金の処理** — 返金はオフラインでキューに追加できません。ゲートウェイと店舗の両方に接続できる必要があります（[返金](/1.x/orders/refunds)を参照）

:::note 販売の完了には接続が必要です
オフラインでも注文を作成して**保存**できますが、決済手続きには接続が必要です。まず現金販売から、オフラインで販売を*完了*できるようにする機能が[ロードマップ](/1.x/getting-started/roadmap)に掲載されています。
:::

## ローカルデータベースの仕組み {#how-the-local-database-works}

WCPOSを初めて開くと、バックグラウンドで商品カタログの初期データを取得し、その他のデータは使用に応じて取得します。最初の商品がデバイスに保存された時点で、販売を開始できます。それ以降は、バックグラウンドの変更チェック（デフォルトでは60秒ごと。[ストアヘルス](/1.x/support/store-health)で調整できます）で、サーバー側で変更されたものだけを取得します。

ローカルデータベースには次の特徴があります。

- **セッション間で保持されます** — ブラウザーやデバイスの再起動後もデータは残ります
- **デバイス単位（およびレジ係単位）です** — 各デバイスが独自のローカルコピーを保持し、レジ係の間でローカルデータは共有されません
- **同期された状態を保ちます** — バックグラウンドの変更チェックで更新を取得します。操作による変更はローカルのキューに追加され、サーバーに送信されます

デバイスに保存されているデータと、まだ送信待ちのデータは、**ストアヘルス → データベース**で正確に確認できます。技術的な詳細については、[同期エンジンの仕組み](/1.x/reference/sync-engine)を参照してください。

## オフラインで行った変更はキューに追加されます {#offline-writes}

POSで行った変更（注文の保存、顧客の追加や編集、クーポン、在庫や価格の編集（Pro）、レシートメールなど）は、まずデバイスに保存され、送信キューに追加されます。オフライン中はキューが待機するため、勤務中に接続が切れてもデータは失われません。アプリの再起動やクラッシュ後もキューは保持されます。エラー画面が表示された場合は、**再試行**を選ぶと、未送信の販売データを破棄せずに再読み込みできます。

接続が戻ると、キュー内の変更は自動的に送信されます。サーバーが変更を明確に拒否した場合（まれですが、たとえばサーバーが無効とみなすレコードなど）、POSが通知なしに再試行を続けることはありません。その変更は**ストアヘルス → データベース**の*「サーバーに届かなかった変更」*に保留され、サーバーからの理由と、**再送信** / **破棄**の操作が表示されます。[ストアヘルス](/1.x/support/store-health#refused-changes)を参照してください。

## 接続インジケーター {#connectivity-indicator}

POSのヘッダーには、接続状態を示す色付きのドットが表示されます。

- **緑** — サーバーに接続されており、すべての機能を利用できます
- **黄色** — 接続が断続的で、一部の操作が遅くなることがあります
- **赤** — オフラインで、ローカルデータのみ利用できます

## 接続が失われたときの動作 {#what-happens-during-connectivity-loss}

POSの使用中にインターネット接続が失われた場合：

1. ローカルデータから**商品と顧客を引き続き閲覧できます**。
2. **カートの作成を継続できます**。商品の編集も可能で、すべての変更はローカルのキューに追加されます。
3. **注文の作成と保存はできますが、決済はできません** — カートや編集内容はローカルのキューに追加され、注文を保存して後で送信できます。チェックアウトはサーバーで表示されるため、決済の完了には接続の復旧が必要です。
4. 接続が戻るまで、ローカルデータベースに**未完了の注文が保持されます**。

## 接続が復旧したとき {#when-connection-restores}

接続が戻ると、次のようになります。

- 接続インジケーターが緑に変わります。
- **キューに入った変更は自動的にサーバーへ送信されます** — オフライン中に行った販売や編集は、手動操作なしで送信されます。
- サーバーに依存する支払いゲートウェイと**サーバーに保存**が再び利用できるようになります。
- バックグラウンド同期が再開され、オフライン中に行われた商品や顧客の変更が取得されます。

## 接続が不安定な場合のヒント {#tips-for-unreliable-connections}

- **重要な注文には「サーバーに保存」を使用してください** — 注文がすぐにWooCommerceへ送信されるため、デバイスのローカルデータベースが消去されても失われません。
- **接続が途切れた後はストアヘルスを確認してください** — **ストアヘルス → データベース**の*送信待ちの変更*タイルで、すべてがサーバーに届いたことを確認できます。
- **電波があるうちに同期してください** — 接続が断続的になることが分かっている場合は、接続が安定しているうちにカタログの初期データの取得を完了させてください。
