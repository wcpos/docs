:::note デスクトップ版・モバイル版のみ
この画面はデスクトップ版とモバイル版のアプリにのみ表示されます。Web版では、`yourdomain.com/pos`からPOSに直接アクセスし、WordPressの認証情報でログインします。
:::

## 接続画面の概要 {#connect-screen-overview}

WCPOSのデスクトップ版またはモバイル版アプリを開くと、接続画面が表示されます。この画面で店舗への接続とユーザーログインを管理します。

{/* Screenshot: connect-screen.png */}

## 店舗を新規追加する {#adding-a-new-store}

1. テキストフィールドにWooCommerce店舗のURLを入力します（例：`https://mystore.com`）。
2. **接続**をクリックします。
3. WordPressの認証情報でログインする画面に移動します。
4. ログインに成功すると、アプリに戻ります。

## 複数の店舗 {#multiple-stores}

必要な数だけWooCommerce店舗に接続できます。接続画面では各店舗が個別のカードとして表示され、次の情報を確認できます。

- **店舗名**とファビコン
- **店舗のURL**
- その店舗に**ログイン中のユーザー**

複数の拠点や事業を管理する場合に便利です。

## 店舗ごとの複数ユーザー {#multiple-users-per-store}

各店舗には複数のユーザーが同時にログインできます。次のような場合に便利です。

- **シフト交代** - 前のレジ係がログアウトする前に、新しいレジ係がログインできます。
- **複数レジの構成** - 別々の端末で異なるレジ係が操作できます。
- **すばやい切り替え** - ユーザーアカウントを簡単に切り替えられます。

### ユーザーを追加する {#adding-a-user}

「ログイン中のユーザー」の横にある <Icon name="plus" /> ボタンをクリックすると、その店舗に別のユーザーを追加できます。

### ユーザーを切り替える {#switching-users}

ユーザーバッジ（例：「Brenda」）をクリックすると、そのユーザーとしてPOSが開きます。

### ユーザーを削除する {#removing-a-user}

ユーザーバッジの**×**をクリックすると、そのユーザーは店舗からログアウトします。

## 店舗を削除する {#removing-a-store}

店舗カードの赤い**×**ボタンをクリックすると、一覧から店舗を削除できます。すべてのユーザーがログアウトし、アプリから店舗への接続が削除されます。

## デモ店舗 {#demo-store}

画面下部に「デモ店舗に入る」リンクが表示される場合があります。このリンクからデモ用のWooCommerce店舗に接続し、自分の店舗データに影響を与えずにWCPOSの機能を試せます。

## トラブルシューティング {#troubleshooting}

:::tip 最初に確認する項目：`X-Frame-Options`
デスクトップ版とモバイル版のアプリは、ログイン、支払い、レシート表示に**iframe**を使用します。`X-Frame-Options: DENY`または`SAMEORIGIN`を送信するサーバーヘッダーやプラグインが**一つでもあると**、ログインできません。これはアプリのログイン失敗で最もよくある原因です。まず、ログインページのレスポンスヘッダーを確認してください（ブラウザーの開発者ツール、または`curl -I https://yourstore.com/wp-login.php`）。
:::

<Accordion>
  <AccordionItem question="店舗に接続できませんか？">

  - WordPressサイトにWCPOSプラグインがインストールされ、有効化されていることを確認します。
  - 正しいURLを使用していることを確認します（`https://`を含めてください。WooCommerce REST APIにはSSLが必要です）。
  - まずWebブラウザーで`yourdomain.com/pos`を開き、プラグインが動作することを確認します。
  - WooCommerce REST APIにアクセスできることを確認します。
  - ユーザーアカウントにPOSへのアクセス権限があることを確認します。

  </AccordionItem>

  <AccordionItem question="デスクトップ版またはモバイル版アプリでログインできません">

  アプリのログイン失敗の多くは、セキュリティプラグインやキャッシュプラグインがログイン用iframeをブロックすることが原因です。

  - **`X-Frame-Options`ヘッダー**（セキュリティプラグインまたはサーバーが設定）がログイン用iframeをブロックしています。上記の注意事項を参照してください。セキュリティプラグインを一時的に無効にしてログインし、その後再び有効にします（セッションは約一週間有効です）。
  - **セキュリティプラグイン** — Wordfence、Really Simple Security、WPS Hide Login、iThemes/Solid Security、Defender Proなどがよく原因になります。詳しい一覧と対処方法は[プラグインの競合](/support/troubleshooting/plugin-conflicts#security-and-login-plugins)を参照してください。
  - **Wordfence 2FA** — ログイン用iframeに2FAコード欄が表示されません。現時点ではPOSユーザーの2FAを無効にしてください。
  - **カスタムログインURL**（例：WPS Hide Login）— アプリがログインページを見つけられません。標準の`/wp-admin/` URLを使用してください。
  - **キャッシュプラグイン**は、問題のプラグインを無効にした後もブロックされたログインフォームを返し続けることがあります。キャッシュをクリアするか、アプリのキャッシュを消去するか、デスクトップ版アプリを再インストールしてください。

  </AccordionItem>

  <AccordionItem question='接続画面に「REST APIには認証が必要です」またはセキュリティプラグインのエラーが表示される'>

  プラグイン（Force LoginやJWT認証プラグインなど）がすべてのREST APIリクエストに認証を要求しているため、アプリがサイトの公開情報を読み取れません。現在、サイトの種類を誤って判定する代わりに、サーバーからの実際のメッセージ（例：_「認証済みユーザーのみがREST APIにアクセスできます」_）を表示します。

  **対処方法：**セキュリティプラグインを設定し、`/wp-json/wcpos/`と`/wp-json/wc/v3/`への未認証アクセスを許可するか、初回接続が完了するまで一時的に無効にします。

  </AccordionItem>

  <AccordionItem question='「WordPressサイトではないようです」と表示される（デスクトップ版アプリ）'>

  デスクトップ版アプリはHTTPの`Link`ヘッダーを使ってREST APIを検出します。プラグイン（よくある例は**Image Prioritizer**やその他のパフォーマンスプラグイン）がこのヘッダーを大量の情報で埋めたり、切り詰めたりすると、検出に失敗します。**対処方法：**画像最適化プラグインやヘッダーを変更するパフォーマンスプラグインを無効にして、再試行してください。

  </AccordionItem>

  <AccordionItem question="アプリが更新を求める／更新後にクラッシュする">

  アプリとサーバープラグインのバージョンが一致しているか確認してください。アプリストアでアプリが更新されても、WCPOSプラグインの更新が必要な場合があります（またはその逆もあります）。v1.10では、アプリがプラグインのv2同期APIを使用するため、アプリとWCPOSプラグインの両方を**v1.10リリース系列**にする必要があります。片方だけを更新してリクエストが`rest_no_route`で失敗する場合は、もう片方も更新してください。

  </AccordionItem>

  <AccordionItem question='「高速店舗データベースを作成できません」エラー'>

  初回ログイン時の競合状態が原因です。**アプリを完全に終了してから、もう一度試してください**。通常、二回目は成功します。

  </AccordionItem>

  <AccordionItem question="ユーザー選択画面から先に進めない（デスクトップ版アプリ）">

  ログイン後、ユーザー名が表示されても次に進む方法が見つからない場合があります。**ユーザー名／名前をクリック**するとPOSに進めます。表示名自体がボタンです。

  </AccordionItem>

  <AccordionItem question="接続に何度も失敗しますか？">

  - まずWebブラウザーで`yourdomain.com/pos`にアクセスし、プラグインが動作していることを確認してください。
  - サイトのエラーログに問題が記録されていないか確認してください。
  - ホストがREST APIをブロックしていないことを確認してください — [ホスティング固有の注意事項](/support/performance/server#hosting-specific-notes)を参照してください
  - サーバーが[最小要件](/support/performance/server#minimum-server-requirements)を満たしていることを確認してください

  </AccordionItem>
</Accordion>
