:::warning 重要
初回読み込み時に、POS は WooCommerce からデフォルトの税設定を取得します。特別な理由がない限り、WooCommerce と同じ設定を使用してください。サーバーと異なる税設定にすると、POS と WooCommerce でほぼ確実に異なる税額が計算され、金額の不一致や注文同期の問題につながる可能性があります。唯一の例外は[税額の計算基準](#calculate-tax-based-on)で、WCPOS 1.x はこの設定を WooCommerce からコピーしません。
:::

## すべての税率を表示 {#view-all-tax-rates}

**すべての税率を表示**ボタンをクリックすると、POS にダウンロードされたすべての税率を確認できます。次の情報が表示されます。

- 税率名
- 税率（%）
- 適用対象の地域/場所

正しい税率が読み込まれていることの確認や、税額計算に関する問題のデバッグに役立ちます。

## 税額計算の設定 {#tax-calculation-settings}

### 税込価格の入力 {#prices-entered-with-tax}

商品価格に税が含まれるかどうかを指定します。

| オプション | 説明 |
|--------|-------------|
| **はい** | 商品価格に税が含まれます。POS は合計価格から逆算して税額を計算します |
| **いいえ** | 商品価格に税は含まれません。POS は入力した価格に税を加算します |

自動税計算を有効にして [WooCommerce Tax](/1.x/integrations/woocommerce-tax) を使用している店舗では、WooCommerce により**いいえ**に固定されるため、POS もそれに合わせる必要があります。

### 税額の計算基準 {#calculate-tax-based-on}

税額計算に使用する住所を指定します。

| オプション | 説明 |
|--------|-------------|
| **顧客の配送先住所** | 注文の配送先に基づく税率 |
| **顧客の請求先住所** | 顧客の請求先住所に基づく税率 |
| **店舗の基本住所** | 店舗の実際の所在地に基づく税率 |

WCPOS 1.x（すべての 1.11 リリースを含む）では、この設定は WooCommerce からコピーされません。WooCommerce の*税額の計算基準*の設定にかかわらず、POS は**店舗の基本住所**で開始し、**サーバー設定を復元**すると**店舗の基本住所**に戻ります。`WP Admin > WooCommerce > 設定 > Tax` で設定を変更しても、POS 側には反映されません。

顧客の住所を基準に POS の売上に課税するには、次の手順を行います。

1. POS で**設定 > 税**を開きます。
2. **税額の計算基準**を**顧客の配送先住所**または**顧客の請求先住所**に設定します。
3. 各レジでこの操作を繰り返します。この設定はデバイス間で共有されません。

POS はこの設定を各注文に保存し、WooCommerce は同じ住所を基準にその注文の税額を計算するため、レジと店舗で税額が一致します。**サーバー設定を復元**した後は、もう一度設定してください。

WCPOS Pro では、**店舗の基本住所**は店舗独自の*税額の計算基準*設定で選択された住所を指します。デフォルトの店舗住所、または WooCommerce の基本地域です。[店舗の設定](/1.x/stores/setup)を参照してください。

自動税計算を有効にして [WooCommerce Tax](/1.x/integrations/woocommerce-tax) を使用している店舗では、WooCommerce により顧客の配送先住所に固定されます。ただし、ここで別の選択肢を指定すると、POS 注文には POS と店舗の両方でその選択が適用されます。

### 配送の税区分 {#shipping-tax-class}

配送料への課税方法を指定します。

| オプション | 説明 |
|--------|-------------|
| **カートの商品に基づく配送の税区分** | カート内の商品の税区分に基づいて配送料の税額を計算します |
| **標準** | 配送料に標準税率で課税します |
| **軽減税率** | 配送料に軽減税率で課税します |
| **ゼロ税率** | 配送料には課税しません |

### 端数処理 {#rounding}

| オプション | 説明 |
|--------|-------------|
| **小計レベルで税を丸める** | 各明細行の税を個別に丸めるのではなく、小計全体の税を計算してから丸めます |

WCPOS は WooCommerce の税計算に従うため、レジで受け付けた注文でもウェブサイトで受け付けた注文でも、注文合計は同じになります。

- **完全精度** — 明細と注文の合計はすべての桁の精度を保持し、表示時にのみ丸めます。そのため、注文に保存される金額は、表示用の小数桁数にあらかじめ丸めた値ではなく、WooCommerce が想定する正確な値になります。
- **店舗での端数処理** — 通貨の最小単位に応じた精度で端数処理を行い、上記の**小計レベルで税を丸める**設定に従います。
- **複合税** — 税率が*複合*に指定されている場合、WooCommerce の優先順位(`tax_rate_priority`)に従って税率が適用されます。そのため、別の税に上乗せされる税は、その税の後に計算されます。

## 表示設定 {#display-settings}

### ショップでの価格表示 {#display-prices-in-the-shop}

| オプション | 説明 |
|--------|-------------|
| **税込** | 表示価格に税額が含まれます |
| **税抜** | 表示価格に税は含まれません |

### カートとチェックアウト時の価格表示 {#display-prices-during-cart-and-checkout}

| オプション | 説明 |
|--------|-------------|
| **税込** | カートとチェックアウトの価格に税が含まれます |
| **税抜** | カートとチェックアウトの価格に税は含まれません |

### 価格表示の接尾辞 {#price-display-suffix}

税の扱いを示すために価格の後に表示されるテキストです（例：「VAT 込み」または「VAT 別」）。

### 税額合計の表示 {#display-tax-totals}

| オプション | 説明 |
|--------|-------------|
| **合計にまとめる** | すべての税を一つの合計行にまとめます |
| **項目別** | 各税率を個別の明細行として表示します |

## サーバー設定を復元 {#restore-server-settings}

クリックすると、現在の WooCommerce の税設定をサーバーから取得して適用します。WCPOS 1.x では、**税額の計算基準**も**店舗の基本住所**に戻ります（[上記](#calculate-tax-based-on)を参照）。

:::tip 使用方法と使用するタイミング
税設定の基準となるのは WooCommerce であり、POS はその設定に合わせる必要があります。**サーバー設定を復元**を使うと、店舗の最新の設定を安全に取得できます。`WP Admin > WooCommerce > 設定 > Tax` で税設定を変更し、POS に反映させたい場合に行う操作です。

注意が必要なのは、**税額の計算基準**を顧客の住所にするなど、POS 側の税設定を**意図的に**変更している場合です。サーバー設定を復元すると、その変更は上書きされます。復元後にもう一度設定してください。
:::

## よくある問題 {#common-issues}

### POS と WooCommerce で合計額が異なる {#pos-and-woocommerce-showing-different-totals}

税に関する問題で最も多いのは、POS と WooCommerce の税設定の不一致です。設定が異なると、同じ注文でも作成した場所によって合計額が異なります。POS の設定は常に同期してください。`WP Admin > WooCommerce > 設定 > Tax` で何らかの変更を行った後は、**サーバー設定を復元**を使用します。

WooCommerce Tax を使用している店舗では、これまで課税したことのない場所での最初の販売も、原因として確認する必要があります。[WooCommerce Tax](/1.x/integrations/woocommerce-tax#what-to-expect)を参照してください。

### 税込価格設定に関する混乱 {#tax-inclusive-pricing-confusion}

「税込価格の入力」が**はい**で、「ショップでの価格表示」が**税抜**の場合、表示価格は入力した価格より低くなります。POS が表示用に税額分を除いているためで、これは正しい動作です。ただし、値札の価格が表示されると思っているレジ係には意外に感じられる場合があります。

### 顧客住所と税額計算 {#customer-address-and-tax-calculation}

「税額の計算基準」が**顧客の配送先住所**または**顧客の請求先住所**の場合、POS が正しい税率を調べるには有効な住所が必要です。来店客の住所が登録されていない場合、WCPOS は**店舗の基本住所**を使って計算します。通常は店頭販売に適した動作ですが、特定の顧客で想定外の税率が表示される場合は、住所の詳細を確認してください。

## トラブルシューティング {#troubleshooting}

### 税額が正しくない {#tax-amounts-are-incorrect}

1. POS の**税金設定**を開き、**サーバー設定を復元**をクリックして、WooCommerce から最新の設定を取得します。
2. **すべての税率を表示**をクリックし、想定する税率が表示されることを確認します。税率がない場合は、`WP Admin > WooCommerce > 設定 > Tax > Standard rates` で正しく設定されているか確認してください。[WooCommerce Tax](/1.x/integrations/woocommerce-tax) の自動税計算が有効な場合、手動で行を追加しないでください。その地域の税率行は、その地域での最初の販売時に作成され、POS は次回の変更確認時に取得します。また、店舗の状態の**税率**行にある**消去して再ダウンロード**を使えば、すぐに取得できます。
3. 商品の税区分を確認してください。「ゼロ税率」の税区分に割り当てられた商品には、設定にかかわらず課税されません。

### 税額がゼロと表示される {#tax-is-showing-as-zero}

- WooCommerce で税が有効になっていることを確認します(`WP Admin > WooCommerce > 設定 > General > Enable tax rates and calculations`)。
- POS の**すべての税率を表示**で、税率がダウンロードされていることを確認します。一覧が空の場合は、完全同期を試してください。
- 商品の税ステータスが「なし」や「配送のみ」ではなく、「課税対象」に設定されていることを確認します。

### 端数処理による差異 {#rounding-discrepancies}

「小計レベルで税を丸める」が一方のシステムだけで有効になっていると、POS と WooCommerce の間で、端数処理によるわずかな差（一、二セント）が生じることがあります。両方で同じ設定になっていることを確認してください。
