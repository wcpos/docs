WCPOS では、サイト全体の WooCommerce メール設定とは別に、POS 注文に対する WooCommerce 通知メールをメールごとに制御できます。販売を処理した **レジ係** にも通知を送信できます。

設定は **レジ** 画面にあります。**WP Admin > POS > 設定 > レジ** に移動してください。メールの設定は、注文ステータスと決済ゲートウェイのセクションより上にあります。

:::info POS 注文のメールについて
POS では WooCommerce が認識しない *POS - 未完了* や *POS - 一部支払い済み* といったカスタムステータスを使用するため、WooCommerce の標準のメールトリガーが POS 注文で正常に動作しないことがあります。WCPOS は、注文がこれらのステータスから完了、処理中、保留中へ移行した際に、新規注文メールの送信を明示的に再実行します。これにより、チェックアウトで注文がどの経路をたどっても、確実に通知を受け取れます。
:::

## 3つのメールグループ {#the-three-email-groups}

各グループの上部には **マスタートグル** があります。オンにすると、その下にチェックボックスの一覧が表示され、メールの種類ごとに有効・無効を設定できます。オフにすると、個別のチェックボックスの設定に関係なく、そのグループのメールは POS 注文に対して一切送信されません。

### 管理者メール {#admin-emails}

*「POS 注文に対する WooCommerce 管理者通知メール」* — **デフォルトで有効。**

**WooCommerce → 設定 → メール → （メールの種類） → 受信者** に設定されたアドレスに送信されます。

| メール | デフォルト | 送信タイミング |
|---|---|---|
| **新規注文** | ✓ チェック済み | POS 注文が処理中 / 完了 / 保留中に移行したとき |
| **キャンセルされた注文** | ✓ チェック済み | POS 注文がキャンセルされたとき |
| **失敗した注文** | ✓ チェック済み | POS 注文が失敗したとき（ゲートウェイのエラーなど） |

### 顧客メール {#customer-emails}

*「POS 注文に対する WooCommerce 顧客通知メール」* — **デフォルトで有効。**

顧客の請求先メールアドレスに送信されます。顧客が紐付けられた注文のみが対象で、ゲストへの販売では通知なしでスキップされます。

| メール | デフォルト | 送信タイミング |
|---|---|---|
| **保留中の注文** | ✓ チェック済み | POS 注文が保留中になったとき |
| **処理中の注文** | ✓ チェック済み | POS 注文が処理中になったとき |
| **完了した注文** | ✓ チェック済み | POS 注文が完了したとき |
| **返金された注文** | ✓ チェック済み | POS 注文が全額または一部返金されたとき |
| **失敗した注文** | ✓ チェック済み | POS 注文が失敗したとき |

### レジ係メール {#cashier-emails}

*「POS 注文を処理したレジ係に新規注文通知を送信する」* — **デフォルトではオフ。**

| メール | デフォルト | 送信タイミング |
|---|---|---|
| **新規注文** | ✓ チェック済み *（マスタートグルがオンの場合）* | そのレジ係が POS 注文を完了したとき |

WCPOS は注文の `_pos_user` メタ（レジにログインしている WP ユーザー）からレジ係を特定し、そのアカウントのメールアドレスを取得します。レジ係と管理者のメールアドレスが同じ場合、たとえば同じ人が管理者とレジ係を兼ねる個人経営の店舗では、WCPOS が受信者の **重複を排除** し、メールが二重に届かないようにします。

管理者とレジ係のトグルは **独立して** 動作します。一方をオフにしても、もう一方には影響しません。

## よくあるシナリオ {#common-scenarios}

<Accordion>
  <AccordionItem question="繁忙日に受信トレイがメールであふれるのを防ぎたい">

1日に50件以上の販売があり、管理者がすべての注文通知を必要としない場合は、**管理者メール → 新規注文** をオフにしてください。**キャンセルされた注文** と **失敗した注文** はオンのままにします。こうした注文こそ、通知を受け取っておきたいものです。

売上を把握するには、新規注文メールを数えるよりも[レポート](/1.x/reports)画面が適しています。

  </AccordionItem>

  <AccordionItem question="管理者ではなく、担当中のレジ係だけに通知を送りたい">

**管理者メール** のマスタートグルをオフにし、**レジ係メール** のマスタートグルをオンにしてください。会計を完了したレジ係の個人アカウントのアドレスに新規注文メールが届き、管理者の受信トレイには届かなくなります。

レジ係が複数いて、オーナーがすべての取引の通知を受け取る必要のない店舗に適しています。

  </AccordionItem>

  <AccordionItem question="店頭販売では顧客メールを無効にしたい">

観光客の多い店舗、市場の屋台、短時間で提供するカフェなどでは、印刷したレシートをすでに渡しているため、メールで送る必要がないことがよくあります。**顧客メール** のマスタートグルをオフにすると、POS 販売に対して処理中 / 完了 / 返金のメールが送信されなくなります。

オンライン注文の顧客向けメールは、POS 経由ではなく標準の WooCommerce の処理で送信されるため、影響を受けません。

  </AccordionItem>

  <AccordionItem question="顧客メールは有効のまま、「処理中」メールだけ送りたくない">

POS 注文が即時に完了する場合（現金や対面でのカード決済）、顧客には *処理中* のメール *と* *完了* のメールが同じ秒に届きます。重複する通知を減らすには、顧客メールの一覧で **処理中の注文** のチェックを外してください。

  </AccordionItem>

  <AccordionItem question="v1.8.9 より前のバージョンからアップグレードしたら、以前の単一の「メールを有効化」スイッチがなくなった">

以前のバージョンの単一のオン・オフスイッチは、上記の3グループ構成に置き換えられました。WCPOS は以前の設定を自動的に移行します。以前メールをオフにしていた場合は、すべてのマスタートグルがオフになります。オンにしていた場合は、管理者と顧客のマスタートグルがオンになり、レジ係はオフ（新しいデフォルト）になります。

操作は不要です。アップグレード後にレジ設定ページを開くと、移行が自動的に実行されます。

  </AccordionItem>
</Accordion>

## 開発者向けフック {#developer-hooks}

UI での設定を超えるプログラムによる制御には、次の WordPress フィルターを利用できます。

| フィルター | 用途 |
|---|---|
| `woocommerce_pos_admin_email_enabled` | 管理者のマスタートグルを上書き |
| `woocommerce_pos_customer_email_enabled` | 顧客のマスタートグルを上書き |
| `woocommerce_pos_admin_emails` | 有効な管理者メールの一覧をフィルター |
| `woocommerce_pos_customer_emails` | 有効な顧客メールの一覧をフィルター |

レジ係への通知は、WooCommerce の既存の `woocommerce_email_recipient_new_order` フィルターを通じて設定されています。そのため、別のアドレスを CC に追加するなど、受信者ごとの変更は他の WooCommerce メールと同じように機能します。
