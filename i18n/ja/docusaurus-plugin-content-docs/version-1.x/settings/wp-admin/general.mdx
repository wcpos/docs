## POS専用商品を有効化 {#enable-pos-only-products}

この設定により、商品に表示オプションが追加され、オンライン店舗、POS、またはその両方に表示するかを制御できます。

:::warning パフォーマンスへの影響
この設定は、オンライン店舗または POS のいずれかで商品を非表示にする必要がある場合にのみ有効にしてください。有効にすると、すべての商品リクエストで追加のデータベース検索が発生します。
:::

個別商品の表示設定や一括編集など、この機能の使用方法について詳しくは、[POS専用商品](/products/pos-only-products)を参照してください。

## 小数数量を有効化 {#enable-decimal-quantities}

この設定により、顧客とスタッフは商品をカートに追加するときに小数数量を入力できます。

**小数数量の例:**
- 0.25（4分の1単位）
- 1.5（1単位半）
- 2.75（2と4分の3単位）

**次の用途に便利です:**
- 重量単位で販売する商品（例: コーヒー豆0.5kg）
- 端数単位のサービス（例: 1.5時間のコンサルティング）
- 一部数量で販売できるバルク商品

:::note 重量単位での販売
WCPOSは計量器に接続したり、計量器から重量を読み取ったりしません。商品を計量し、カートの行の数量として重量を入力してください。キログラム単価の商品では、350 gは数量`0.35`になります。小数の数量を含む注文は、この設定を有効にしないと店舗で拒否されるため、先に設定を有効にしてください。

一部の計量器が印刷するバーコードラベルに記録された重量や価格も、WCPOSでは読み取れません。
:::

## 注文削除時に在庫を復元 {#restore-stock-on-order-delete}

有効にすると、POS注文がゴミ箱に移動または削除されたときに、WCPOSが商品の在庫を自動的に復元します。これにより、誤った販売をキャンセルした場合に商品が在庫へ戻されます。この設定は**デフォルトでオン**です。

別の方法で在庫を照合しており、削除されたPOS注文で在庫を調整したくない場合は無効にします。

## 顧客のメールアドレスからユーザー名を自動生成 {#automatically-generate-username-from-customer-email}

有効にすると、WCPOSはチェックアウト時に、新規顧客のメールアドレスに基づいてユーザー名を自動的に作成します。これにより顧客作成プロセスが効率化され、ユーザー名の形式を一貫させることができます。

## デフォルトPOS顧客 {#default-pos-customer}

新しいPOS注文に割り当てるデフォルト顧客を選択します。一般的なオプションは次のとおりです。

- **ゲスト**: 注文はどのユーザーアカウントにも関連付けられません
- **レジ担当者**: 注文はログイン中のレジ担当者のアカウントに関連付けられます
- **来店顧客**: 注文は特定の顧客アカウントに関連付けられます（このアカウントを先に作成する必要があります）

## レジ担当者アカウントを使用 {#use-cashier-account}

有効にすると、選択したデフォルトPOS顧客の代わりに、レジ担当者のユーザーアカウントがPOS注文のデフォルト顧客として使用されます。

## 顧客によるレシートのダウンロードを許可する {#storefront-receipts}

有効にすると、WCPOS はオンライン店舗の **マイアカウント → 注文** に **レシート** ボタンを追加します。お客様はこのボタンから、WCPOS のテンプレートを使って生成された注文レシートの PDF をダウンロードできます。この設定はデフォルトで **オフ** です。

切り替えの下にある**顧客向けレシートテンプレート**のドロップダウンで、顧客に表示するテンプレートを選択します。デフォルトは**有効なレシートテンプレートを使用**です。POSと同期したままにするにはこの設定を使い、オンライン注文に異なるデザイン（たとえば全面サイズの請求書）を使うには特定のテンプレートを選択してください。

対象となる注文ステータス、`[wcpos_receipt]`ショートコード、開発者向けフィルターを含む詳細なガイドは、[オンラインストアのレシート](/receipts/storefront)をご覧ください。

## バーコードフィールド {#barcode-field}

この設定では、バーコードをスキャンする場合、またはバーコード検索機能を使用する場合に、WCPOSが検索する商品フィールドを指定します。

<a id="default-option"></a>

:::note デフォルトのメタキー
**`_global_unique_id`** を使用します。これはWooCommerce 8.2（2024年7月）で導入されたWooCommerceのグローバル一意IDフィールドです。GTIN、UPC、EAN、ISBNコードを保存するために設計されており、新規インストールで推奨される設定です。グローバル一意IDフィールドを使わない場合は、代替として **`_sku`**（商品SKU／在庫管理単位フィールド）を使用できます。
:::

### 一般的なプラグイン → メタキー {#common-plugins-meta-key}

バーコード管理プラグインを使用している場合は、プラグイン固有のメタキーが必要になることがあります。

| プラグイン／フィールドの種類 | メタキー |
|---|---|
| WooCommerceのグローバル一意ID *(デフォルト、推奨)* | `_global_unique_id` |
| 商品SKU *(代替)* | `_sku` |
| EANプラグイン（欧州商品番号） | `_ean`、`_ean13`、`_ean8` |
| UPCプラグイン（共通商品コード） | `_upc`、`_upc_code` |
| GTINプラグイン（国際商品識別番号） | `_gtin`、`_gtin13`、`_gtin14` |
| 汎用バーコードフィールド | `_barcode`、`_product_barcode` |
| WooCommerce Product Barcodes | `_barcode_text` |
| ATUM Inventory | `_atum_barcode` |

<a id="custom-meta-keys"></a>

:::tip カスタムメタキー
バーコードデータを保存する**任意の**カスタムメタキーを使用できます。該当する場合は先頭のアンダースコアも含め、メタキー名をこのフィールドに入力してください。
:::

### プラグインのメタキーを確認する {#finding-your-plugins-meta-key}

上記にプラグインがない場合は、次の手順で正しいメタキーを確認します。

<Steps>
  <StepCard number="1" title="商品にバーコードを追加する">

WP Adminで商品を編集し、プラグインを使ってバーコードを追加します。

  </StepCard>
  <StepCard number="2" title="プラグインのドキュメントを確認する">

プラグインのドキュメントで、使用するメタキー名を確認します。

  </StepCard>
  <StepCard number="3" title="データベースを確認する" isLast>

データベースの`wp_postmeta`テーブルを調べ、商品に作成されたメタキーを確認します。

  </StepCard>
</Steps>

:::note この設定を変更するとバーコードインデックスが再構築されます
バーコードフィールドを変更すると、WCPOSはローカルカタログのバーコードインデックスを再構築します。スキャンが新しく選択したフィールドに一致するようになるため、商品を手動で消去して再ダウンロードする必要はありません。

それでもスキャン結果が一致しない場合は、完全更新を実行できます。商品画面に移動し、画面下部の同期アイコン（↻）を**長押し**して、**「クリアして更新」** を選択します。その後、スキャンをテストして、新しいフィールドが使われていることを確認してください。
:::

## プライバシー {#privacy}

**匿名の使用状況データを許可** トグルでは、製品改善のために WCPOS が匿名の使用状況分析データを収集するかどうかを制御します。これは実際のオプトイン/オプトアウトであり、顧客データ、価格、店舗住所が収集されることはありません。設定の横にある **詳細を見る** リンクから、収集される内容と収集されない内容を正確に確認できます。

## 店舗税 ID {#store-tax-ids}

WCPOS が POS レシートや請求書に印刷する事業者の税務識別番号（VAT番号、ABN、GSTIN、EIN、または各地域の会社登録番号）を追加します。WooCommerce にはこれらの組み込みフィールドがなく、多くの地域では複数の番号が必要です。

詳しいガイドは [店舗の税務ID](/settings/wp-admin/store-tax-ids) を参照してください。

## 顧客の税務ID {#customer-tax-ids}

WCPOS は顧客に税務IDフィールドを保持し、購入手続き時にその顧客の注文へコピーします。プラグインによってこのフィールドの保存名が異なるため、WCPOS はインストールされているプラグインを検出し、適切なフィールドへ自動的に書き込みます。必要に応じて、この **税務ID** セクションでフィールド名を上書きすることもできます。

詳しいガイドは [顧客の税務ID](/settings/wp-admin/customer-tax-ids) を参照してください。
