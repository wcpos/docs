レジ設定ページ(`WP Admin > POS > 設定 > 支払い`)では、POSに表示する決済ゲートウェイ、注文の処理方法、POS販売で送信する通知メールを設定します。

## メール通知 {#email-notifications}

ページ上部には、**管理者メール**、**顧客メール**、**レジ係メール**の3つのメール切り替えグループがあります。サイト全体のWooCommerceメール設定とは別に、POS注文に対して送信するWooCommerce通知メールを設定できます。

メールごとのデフォルト設定、レジ係を受信者とする仕組み、一般的な利用例、開発者向けフックなどの詳細については、**[メール通知](/1.x/settings/wp-admin/email-notifications)** をご覧ください。

## 決済ゲートウェイ {#payment-gateways}

このセクションには、サイトにインストールされているすべてのWooCommerce決済ゲートウェイが一覧表示されます。各ゲートウェイは、POSで個別に有効化または無効化できます。

| 列 | 説明 |
|--------|-------------|
| **デフォルト** | レジ係がチェックアウトを開いたときに、あらかじめ選択されるゲートウェイを指定します |
| **ゲートウェイ** | 決済ゲートウェイ名 |
| **ゲートウェイ ID** | WooCommerceゲートウェイの識別子（開発者向け） |
| **有効** | POSのチェックアウトでゲートウェイをオンまたはオフに切り替えます |
| **注文ステータス** | このゲートウェイで支払われた POS 注文に設定されるステータス（下記の[注文ステータス](#order-status)を参照） |

各行には (⋮) メニューもあります。**POS 設定** ではゲートウェイの POS 専用の **タイトル** と **説明** を変更でき、**WooCommerce 設定** では WooCommerce 内のゲートウェイの全設定へ直接移動できます。

### ゲートウェイの有効化 {#enabling-a-gateway}

1. 一覧でゲートウェイを探します
2. **有効** スイッチをオンにします
3. 次回ページを読み込むと、ゲートウェイが POS チェックアウトに表示されます

:::note 無料版と Pro 版
無料版で編集できるのは、組み込みの**現金**と**カード**のゲートウェイのみです。インストール済みのその他のWooCommerceゲートウェイをPOSで有効にするには、[WCPOS Pro](/1.x/getting-started/pro-license)が必要です。
:::

### ゲートウェイの並べ替え {#reordering-gateways}

ゲートウェイをドラッグして、POSのチェックアウトでの表示順を変更します。**デフォルト**列で、レジ係がチェックアウトモーダルを開いたときに、あらかじめ選択されるゲートウェイを指定します。

### POSとオンラインストア {#pos-vs-online-store}

ここでのゲートウェイ設定は、WooCommerceの支払い設定から**独立**しています。ゲートウェイは次のように設定できます。

- **POSで有効、オンラインでは無効** — オンライン注文には適用されない現金支払いなどに便利です
- **オンラインで有効、POSでは無効** — PayPalなど、対面販売には実用的でないゲートウェイに便利です
- **両方で有効** — どちらでもゲートウェイを使用できます

:::note
ゲートウェイをPOSのレジ設定一覧に表示するには、まず `WP Admin > WooCommerce > 設定 > 支払い` でインストールして有効化する必要があります。ゲートウェイが見つからない場合は、プラグインがインストールされていることと、そのゲートウェイがWooCommerceで有効になっていることを確認してください。
:::

## 注文ステータス {#order-status}

注文ステータスは、ゲートウェイ一覧の**注文ステータス**列から**ゲートウェイごとに**設定します。そのため、支払い方法によって販売後のステータスが異なります。

- **現金**と**カード**は、販売時に代金を受け取るため、デフォルトで**完了**になります。
- **BACS**（銀行振込）や**小切手**のように入金が後になるゲートウェイは、デフォルトで**保留中**になります。

各ゲートウェイには、任意のWooCommerce注文ステータスを選択できます。（以前のバージョンでは全体で共通のデフォルト値を使用していました。この値はアップグレード時に各ゲートウェイへ移行されています。）

### レジでの注文ステータスの扱い {#order-status-at-the-till}

注文がゲートウェイに設定したステータスになると、POS は会計を完了してカートに戻ります。WooCommerce で支払い済みとみなされるのは **処理中** と **完了** のみです。**保留中** と **支払い待ち** は支払い済みのステータスではありません。

カウンターで代金を受け取る場合は、**処理中** または **完了** を選択してください。顧客が支払いリンクを使わずに自分で振り込む場合は、BACS と小切手のデフォルトである **保留中** を選択します。

たとえば **BACS** を使った「請求書払い」のように、注文の支払いリンクから顧客に後払いしてもらう場合は **支払い待ち** を選択してください。WooCommerce では支払い待ちの注文は支払い可能な状態に保たれます。支払い済みにはならず、在庫も減らず、注文が支払い待ちの間は支払いリンクを使用できます。POS からリンクは送信されません。注文には顧客のメールアドレスが必要です。WooCommerce の注文画面から請求書をメールで送るか、別の方法でリンクを共有してください。

:::caution v1.10.25 以前の「支払い待ち」
WCPOS v1.10.25 以前では、ゲートウェイを「支払い待ち」に設定すると、レジ係が確定した後も支払いウィンドウが開いたままになり、注文がカートに残ります。POS を再読み込みすると解消されます。プラグイン画面に v1.10.25 より新しいバージョンが表示されたら、プラグインを更新し、次に各レジの POS アプリを更新してください。両方の更新が必要です。それまではゲートウェイを **保留中** に設定してください。この設定では会計は完了しますが、顧客に支払いリンクは提供されないため、請求書は別の方法で送ってください。
:::

## 過剰販売の防止 {#prevent-overselling}

**過剰販売を防止** のトグルは、在庫が足りない商品の POS 販売を停止します。**デフォルトではオフ** になっており、有効にするまでチェックアウトの動作はこれまでと変わりません。

WooCommerce の REST API は注文作成時に在庫を検証しないため、レジが混雑している場合や商品リストが古い場合、在庫数を超えて販売してしまう可能性があります。このトグルをオンにすると、WCPOS は次の2か所で在庫を確認します。

1. **レジで** — レジ係は、販売可能な在庫数を超えて商品をカートに追加したり、数量を増やしたりできません。POS には *実際に販売できる* 数量が表示されます。例：*「パーカー – ブルー、M は残り3点です」*。
2. **チェックアウト時、サーバー側で** — 支払いが完了する前に注文自体が検証されます。レジのローカルデータが古い場合でも、過剰販売になる注文は拒否され、在庫が不足している商品と販売可能な数量がレジ係に正確に表示されます。その後 POS は該当商品の在庫を更新し、正確な数量でカートを修正できるようにします。

未完了のカートの同期が妨げられることはありません。検証はチェックアウトの時点でのみ実行されます。

### 在庫の判定方法 {#prevent-overselling-stock-rules}

| 商品の設定 | トグルがオンのときの動作 |
|---|---|
| **在庫を管理する**（数量を管理している） | 販売数は在庫数量までに制限されます。同じ商品がカート内の複数行にある場合は、数量を合算して上限を判定します。 |
| **バリエーションが独自の在庫を管理する** | 上限はバリエーションごとに適用されます。 |
| **バリエーションが親商品の在庫を使用する** | その商品のすべてのバリエーションが親商品の在庫数量を共有します。 |
| **在庫を管理しない** | 商品の在庫状況で決まります。*在庫切れ* は販売できず、*在庫あり* と *入荷待ち* は販売できます。 |

:::note 在庫数量を変更するプラグイン
WCPOS は在庫の減算を WooCommerce に任せます。WooCommerce はオンライン注文と同様に、POS 注文が在庫を減らすステータス（処理中、完了、保留中）になると在庫を減らし、POS 注文が削除されると在庫を戻します（[注文削除時に在庫を復元](/1.x/settings/wp-admin/general#restore-stock-on-order-delete)を参照）。そのため、パック販売やケース販売で在庫の減算数に倍率をかけるプラグインなども、WooCommerce の在庫減算処理に作用するものであれば POS 注文で機能します。オンラインストアのカートだけを変更するプラグインは、POS 販売には影響しません。POS はそのカートを使用しないためです。

過剰販売の防止では、倍率をかけた数量ではなく、カートの明細行にある数量を商品の在庫と比較します。倍率を使用している場合、このチェックを通過しても、残りの在庫を超えて消費することがあります。テスト販売を1回行い、その後の在庫数を確認してください。
:::

### 入荷待ち注文の設定が優先されます {#prevent-overselling-backorders}

商品ごとの **入荷待ち注文の設定が優先されます**。これにより、トグルがオンでも特定の商品では在庫数を超えた販売を許可できます。

- **許可しない** — 在庫がなくなると販売を停止します（この制限をトグルで適用します）。
- **許可する** — 在庫がゼロを下回っても、常に販売できます。
- **許可するが顧客に通知する** — 常に販売できますが、販売可能な在庫数を超えると、レジ係に *「入荷待ちになります」* という注記が表示されます。

### 過剰販売の防止と「在庫切れを表示」の違い {#prevent-overselling-vs-display}

これらの設定は異なる方法で在庫を保護しますが、どちらも在庫切れ商品の追加を防ぐことができます。

- **過剰販売を防止**（このページ）は、商品の追加や更新時に販売可能な数量を確認し、チェックアウト時にも在庫を再検証します。
- **在庫切れ商品を表示**（POS 商品パネルの表示設定）は、在庫切れの商品やバリエーションの選択方法を制御します。有効にすると在庫切れの商品は表示されますが、カートには追加できません。無効にすると非表示になります。在庫切れのバリエーションの選択肢もグレー表示になり、該当するバーコードのスキャンも拒否されます。

過剰販売の防止をオフにしても、商品パネルのこれらのルールは変わりません。在庫切れの商品を表示したまま、過剰販売の防止で数量とチェックアウト時の保護を追加できます。レジ係には商品に *在庫切れ* バッジが表示され、カートへの追加は無効になります。

:::note
トグルの変更は、次回レジ係がログインするかアプリが設定を再検証した際に、開いている POS セッションへ反映されます。サーバー側のチェックには即座に適用されます。
:::
