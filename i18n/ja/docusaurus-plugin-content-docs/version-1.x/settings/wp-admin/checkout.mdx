チェックアウト設定ページ (`WP Admin > POS > 設定 > 支払い`) では、POS に表示される決済ゲートウェイ、注文の処理方法、POS 販売で送信される通知メールを制御します。

## メール通知 {#email-notifications}

ページ上部には、**管理者メール**、**顧客メール**、**キャッシャーメール**の 3 つのメール切り替えグループがあります。これらは、サイト全体の WooCommerce メール設定とは独立して、POS 注文で送信される WooCommerce 通知メールを制御します。

メールごとの切り替えのデフォルト、キャッシャー受信者モデル、一般的なシナリオ、開発者フックを含む完全なリファレンスについては、**[メール通知](/settings/wp-admin/email-notifications)**を参照してください。

## 決済ゲートウェイ {#payment-gateways}

このセクションには、サイトにインストールされているすべての WooCommerce 決済ゲートウェイが一覧表示されます。各ゲートウェイは、POS で個別に有効化または無効化できます。

| 列 | 説明 |
|--------|-------------|
| **デフォルト** | レジ担当者がチェックアウトを開いたときに事前選択されるゲートウェイを指定します |
| **ゲートウェイ** | 決済ゲートウェイ名 |
| **ゲートウェイ ID** | WooCommerce ゲートウェイ識別子（開発者向け） |
| **有効** | POS チェックアウトでゲートウェイをオンまたはオフに切り替えます |
| **注文ステータス** | このゲートウェイで支払われた POS 注文に設定されるステータス（下記の[注文ステータス](#order-status)を参照） |

各行には (⋮) メニューもあります。**POS 設定** ではゲートウェイの POS 専用の **タイトル** と **説明** を変更でき、**WooCommerce 設定** では WooCommerce 内のゲートウェイの全設定へ直接移動できます。

### ゲートウェイの有効化 {#enabling-a-gateway}

1. 一覧でゲートウェイを探します
2. **有効** スイッチをオンにします
3. 次回ページを読み込むと、ゲートウェイが POS チェックアウトに表示されます

:::note 無料版と Pro 版
無料版で編集できるのは、組み込みの **現金** と **カード** のゲートウェイのみです。インストール済みのその他の WooCommerce ゲートウェイを POS で有効にするには、[WCPOS Pro](/getting-started/pro-license) が必要です。
:::

### ゲートウェイの並べ替え {#reordering-gateways}

ゲートウェイをドラッグして、POS チェックアウトでの表示順を変更します。**デフォルト** 列で、レジ担当者がチェックアウトモーダルを開いたときに事前選択されるゲートウェイを指定します。

### POS とオンラインストア {#pos-vs-online-store}

ここでのゲートウェイ設定は、WooCommerce の支払い設定から **独立** しています。ゲートウェイは次のように設定できます。

- **POS で有効、オンラインでは無効** — Web 注文には適用されない現金支払いに便利です
- **オンラインで有効、POS では無効** — 対面販売には実用的でない PayPal のようなゲートウェイに便利です
- **両方で有効** — ゲートウェイはすべての場所で動作します

:::note
決済方法は、POSチェックアウト設定の一覧に表示される前に、まず `WP Admin > WooCommerce > 設定 > 支払い` でインストールされ、有効化されている必要があります。決済方法が見つからない場合は、プラグインがインストールされていること、およびその決済方法が WooCommerce で有効になっていることを確認してください。
:::

## 注文ステータス {#order-status}

注文ステータスは、ゲートウェイ一覧の **注文ステータス** 列から **ゲートウェイごとに** 設定します。そのため、支払い方法によって売上の扱いが変わります。

- **現金** と **カード** は、販売時点で支払いが回収されるため、デフォルトで **完了** になります。
- **BACS**（銀行振込）や **小切手** のように入金が後になるゲートウェイは、デフォルトで **保留中** になります。

各ゲートウェイには、任意の WooCommerce 注文ステータスを選択できます。（以前のバージョンでは単一のグローバルなデフォルト値を使用していました。この値はアップグレード時に各ゲートウェイへ移行されています。）

## 過剰販売の防止 {#prevent-overselling}

**過剰販売を防止** のトグルは、在庫が足りない商品のPOS販売を停止します。初期設定では **オフ** になっており、有効にするまでチェックアウトの動作はこれまでと変わりません。

WooCommerceのREST APIは注文作成時に在庫を検証しないため、混雑したレジ（または古い商品リスト）では手持ちより多い数量を販売してしまう可能性があります。トグルをオンにすると、WCPOSは次の2か所で在庫を確認します：

1. **レジで** — レジ担当者は、利用可能な在庫を超えて商品をカートに追加したり数量を増やしたりできません。POSには実際に利用可能な数量が表示されます（例: *「Hoodie – Blue, M は残り3点です」*）。
2. **チェックアウト時、サーバー側で** — 支払いが完了する前に注文自体が検証されます。レジのローカルデータが古かった場合でも、過剰販売になる注文は拒否され、どの商品がどれだけ不足しているかがレジ担当者に正確に表示されます。その後POSは該当商品の在庫を更新し、正確な数量でカートを修正できるようにします。

開いているカートの同期が妨げられることはありません。検証はチェックアウトの時点でのみ実行されます。

### 在庫の判定方法 {#prevent-overselling-stock-rules}

| 商品の設定 | トグルがオンのときの動作 |
|---|---|
| **在庫を管理する**（数量を管理している） | 販売は在庫数量までに制限されます。カート内の同じ商品の複数行は同じ上限に合算されます。 |
| **バリエーションが独自の在庫を管理する** | 上限はバリエーションごとに適用されます。 |
| **バリエーションが親商品の在庫を使用する** | その商品のすべてのバリエーションが親商品の数量を共有します。 |
| **在庫を管理しない** | 商品の在庫状況で決まります。*在庫切れ* は販売できず、*在庫あり* と *入荷待ち* は販売できます。 |

### 取り寄せ設定が優先されます {#prevent-overselling-backorders}

**商品ごとの取り寄せ設定が優先されます**。トグルをオンにしたまま、特定の商品だけ過剰販売を許可する方法です。

- **許可しない** — 在庫がなくなった時点で販売を停止します（トグルが強制するのはこの動作です）。
- **許可する** — 在庫がゼロを下回っても、その商品は常に販売できます。
- **許可するが顧客に通知する** — その商品は常に販売できます。販売数が利用可能な在庫を下回ると、レジ担当者に *「取り寄せになります」* という注記が表示されます。

### 過剰販売の防止と「在庫切れの商品を表示」の違い {#prevent-overselling-vs-display}

これらの設定は異なる在庫の保護を担いますが、どちらも在庫切れ商品の追加を防ぐことがあります。

- **過剰販売を防止**（このページ）は、商品の追加や更新時に利用可能な数量を確認し、チェックアウト時に再度在庫を検証します。
- **在庫切れの商品を表示**（POS商品パネルの表示設定）は、在庫切れの商品やバリエーションをどのように選択できるかを制御します。有効にすると、在庫切れの商品は表示されたままですがカートには追加できません。無効にすると非表示になり、在庫切れのバリエーションのオプションもグレー表示になり、一致するバーコードスキャンは拒否されます。

過剰販売を防止をオフにしても、これらの商品パネルのルールは上書きされません。在庫切れの商品を表示したまま、過剰販売を防止によって数量とチェックアウトの保護を追加できます。その場合、レジ担当者には *在庫切れ* のバッジと無効化されたカート追加ボタンが表示されます。

:::note
トグルの変更が開いているPOSセッションに反映されるのは、レジ担当者が次回ログインするか、アプリが再検証したときです。サーバー側のチェックは即座に適用されます。
:::
