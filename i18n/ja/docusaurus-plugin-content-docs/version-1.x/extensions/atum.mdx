# WCPOS ATUM 連携 {#wcpos-atum-integration}

[ATUM Multi-Inventory](https://www.stockmanagementlabs.com/addons/atum-multi-inventory/) を [WCPOS Pro](/1.x/getting-started/pro-license) と連携し、POS でロケーション別の在庫、価格、SKU を利用できるようにします。

ATUM Multi-Inventory では、商品の在庫を倉庫や小売店舗など複数の在庫ロケーションに分割できます。このプラグインは、それらの ATUM ロケーションを WCPOS Pro の[店舗](/1.x/stores)に接続し、各 POS 端末が設置場所に合った在庫数、価格、SKU を表示できるようにします。

  <FeatureCard icon="box" title="ロケーション別在庫">

  </FeatureCard>
  <FeatureCard icon="store" title="柔軟な価格設定">
    WooCommerce の標準価格、WCPOS Pro の店舗別価格、または ATUM のロケーション別価格から選択できます。
  </FeatureCard>
  <FeatureCard icon="barcode" title="ロケーション SKU">
    必要に応じて、POS で商品のメイン SKU を ATUM のロケーション別 SKU に置き換えられます。
  </FeatureCard>
  <FeatureCard icon="sync" title="監査可能な在庫移動">
    注文に応じて正しい ATUM ロケーションの在庫を減算・復元し、`atum_inventory_orders` に完全な監査履歴を残します。
  </FeatureCard>
  <FeatureCard icon="arrow-right" title="商品編集の書き戻し">
    POS で行った在庫、価格、SKU の編集を、そのロケーションに対応する ATUM 在庫行へ同期します。
  </FeatureCard>

## インストール {#installation}

<Steps>
  <StepCard number="1" title="ATUM と Multi-Inventory をインストール">

[ATUM Inventory Management](https://wordpress.org/plugins/atum-stock-manager-for-woocommerce/) と [ATUM Multi-Inventory アドオン](https://www.stockmanagementlabs.com/addons/atum-multi-inventory/)をインストールします。ATUM で在庫ロケーションを設定してください。

  </StepCard>
  <StepCard number="2" title="WCPOS ATUM 連携をインストール">

`WP Admin > POS > 設定 > 拡張機能` からインストールするか、[GitHub リリースページ](https://github.com/wcpos/wcpos-atum/releases)から最新リリースをダウンロードして `プラグイン > 新規追加 > プラグインのアップロード` からアップロードします。

  </StepCard>
  <StepCard number="3" title="店舗を ATUM ロケーションにマッピング" isLast>

`POS > 店舗` に移動し、店舗を編集して **ATUM 在庫**サイドバーセクションを設定します。店舗が使用する在庫ロケーションを選び、価格ソースを選択し、必要なら SKU 上書きを有効にします。

  </StepCard>
</Steps>

## 店舗設定 {#store-configuration}

このプラグインを使うと、WCPOS Proの店舗編集サイドバーに**ATUM Inventory**セクションが追加され、店舗ごとに三つの設定を行えます。

- **在庫ロケーション** — この店舗が在庫を取得する ATUM ロケーション。
- **価格ソース** — 商品価格の取得元:
  - *デフォルト* — WooCommerce の標準価格
  - *WCPOS Pro* — WCPOS Pro で設定した店舗別価格
  - *ATUM* — ATUM 在庫のロケーション別価格
- **SKU 上書き** — 商品のメイン SKU の代わりに、ATUM のロケーション別 SKU を使用できます。

## POS の動作 {#pos-behavior}

店舗に ATUM ロケーションが割り当てられている場合、POS に提供される商品データは自動的に調整されます。

- **在庫数量** は WooCommerce の合計在庫ではなく、特定ロケーションの在庫を反映します。
- **在庫ステータス** はそのロケーションの数量に基づいて再計算されます。
- **価格** は設定された価格ソースから取得されます。
- **SKU** は上書きが有効な場合、ATUM ロケーション SKU に置き換えられます。

すべての調整は WCPOS REST API を通じて透過的に行われます。POS アプリ側の変更は不要です。POS から行った商品編集も、対応する ATUM 在庫行に書き戻されます。詳しくは下の[商品編集の書き戻し](#product-edit-write-back)を参照してください。

## 在庫管理 {#stock-management}

ATUM ロケーションがマッピングされた店舗の POS 注文では、プラグインが書き込み先を正しいロケーションに指定し、ATUM 標準の在庫減算処理に書き込みを任せます。

1. **REST ペイロードへの注入。** POS が注文を作成または更新するとき、プラグインは各明細に `mi_inventories` エントリを注入し、ATUM がどのロケーションから在庫を引くべきか分かるようにします。これがないと ATUM はメイン在庫を使用します。
2. **ロケーション単位の在庫フィルター。** プラグインは ATUM の候補在庫リストを、店舗にマッピングされたロケーションタームに紐づくものだけに絞り、減算時と復元時の両方で正しい在庫が選ばれるようにします。

注文時と返金時の実際の在庫変更は ATUM 自体が行い、実際の `order_id` を使って `atum_inventory_orders` に行を記録します。これにより、ATUM の監査履歴が保持されます。

## 商品編集の書き戻し {#product-edit-write-back}

レジ係または管理者が POS から商品やバリエーションを編集すると、その変更は WooCommerce のメイン商品だけでなく、その店舗のロケーションにマッピングされた ATUM 在庫行へ同期されます。これにより、`WP Admin` で手動更新しなくても、各ロケーションの在庫、価格、SKU を ATUM と同期できます。

書き戻しは、`store_id` を含む WCPOS の商品・バリエーションの REST 更新（`/wcpos/v1/products/...` への `POST`、`PUT`、`PATCH`）時に実行されます。プラグインは店舗にマッピングされた ATUM ロケーションを参照し、そのロケーションの在庫行だけを更新します。他のロケーションは変更しません。

### 同期される内容 {#what-syncs}

書き戻しは各店舗の設定に従い、その店舗が管理するデータだけを ATUM 側で変更します。

| フィールド | 同期される条件 |
| --- | --- |
| **在庫数量** | 常に同期します。ATUM ロケーションがマッピングされたすべての店舗で、対応するロケーションの行を同期状態に保ちます。 |
| **通常価格 / セール価格 / 価格** | 店舗の **価格ソース** が *ATUM* に設定されている場合のみ。 |
| **SKU** | 店舗で **SKU 上書き** が有効な場合のみ。 |

店舗が *デフォルト* または *WCPOS Pro* の価格を使用する場合、ATUM の価格フィールドは変更されません。ATUM の価格は適用価格の取得元ではなく、参照価格として維持されます。SKU 上書きが無効な場合も同様です。

### 書き戻しが実行されない場合 {#what-doesnt-trigger-write-back}

- 商品を作成した場合（書き戻しは更新時のみ実行され、新規商品は WooCommerce の通常の保存処理に従います）。
- `store_id` のないリクエストの場合。POS が書き込み先のロケーションをプラグインに伝える必要があります。
- 店舗に ATUM ロケーションがマッピングされていない場合。
- 店舗のロケーションに対応する ATUM 在庫行が商品に存在しない場合。プラグインは新しい在庫行を作成せず、既存の行のみを更新します。
