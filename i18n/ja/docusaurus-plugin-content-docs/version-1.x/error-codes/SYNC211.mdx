## これが意味すること {#what-this-means}

レコードのフィールドが店舗によって拒否されました。このコードは、店舗が拒否した設定または認証リクエストを示す場合もあります。

レコードが示されている場合は、該当フィールドを修正して再試行してください。同期されるまでローカルコピーは利用できます。それ以外の場合は、指定されたリクエストに対する店舗のメッセージに従ってください。

## データへの影響 {#your-data}

レコードの変更の場合、その変更はこのデバイスに保存されていますが、店舗にはまだ反映されていません。設定または認証リクエストの場合、保存対象はありません。

## トラブルシューティング {#troubleshoot}

1. まずログエントリーを展開して、endpointとサーバーの応答を確認してください。このコードは、設定、認証、その他レコード以外のリクエストで返されたHTTP 400を表す場合もあります。
2. コンテキストにレコードやフィールドが記載されている場合は、POSでそのフィールドを編集してから再試行してください。よくある原因は、値が範囲外である、形式が受け付けられない、必須の選択肢が空のままである、といったものです。
3. レコードへのリクエストでない場合は、指定されたエンドポイントに対するサーバーのメッセージに従ってください。ブラウザーの開発者ツール（Networkタブ）、またはデスクトップアプリの**Advanced → Toggle Developer Tools**で、ログに詳細がない場合の応答を確認できます。
4. **サイト管理者：** POSで正しく見えるフィールドが指定されている場合は、WP Adminで同じレコードと比較してください。店舗側のプラグインが、POSでは問題ないと判断される値を拒否している可能性があります。
