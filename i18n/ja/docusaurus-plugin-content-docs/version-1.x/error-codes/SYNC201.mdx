## これが意味すること {#what-this-means}

店舗でこの変更が拒否されたため、店舗に反映されていません。

店舗が示した理由を確認してください。**店舗の状態 → データベース**に変更が表示されている場合は、レコードを修正して**もう一度送信**をタップするか、**破棄**してください。表示されていない場合は、店舗のバージョンに戻されています。まだ必要であれば変更をやり直してください（[SYNC202](/error-codes/SYNC202)を参照）。拒否された変更が自動的に再試行されることはありません。

## データへの影響 {#your-data}

このデバイスのデータは消去しないでください。店舗にまだ届いていない変更が含まれている可能性があります。**店舗の状態 → データベース**に表示された拒否済みの変更は、再送信または破棄するまで残ります。既存の商品、バリエーション、顧客、クーポンへの拒否された編集は通常、自動的に元に戻され、代わりに[SYNC202](/error-codes/SYNC202)として記録されます。このコードで表示され、変更が**店舗の状態 → データベース**にある場合、自動取り消しが行われていません。以下の一覧にある他の変更と同様に扱ってください。繰り返し発生する場合は、**ログ**タブで**デバッグ情報をコピー**し、WCPOSサポートにお問い合わせください。

## トラブルシューティング {#troubleshoot}

1. ログ項目と、**店舗の状態 → データベース**にある変更の行で、店舗が示した理由を確認してください。
2. **店舗の状態 → データベース**を開いてください。変更が表示されていない場合、このデバイスではすでに店舗のバージョンに戻されており、送信するものはありません。[SYNC202](/error-codes/SYNC202)を参照してください。理由に記載された箇所を修正し、まだ必要であれば変更をやり直してください。
3. 表示されている場合（注文、このデバイスで作成されたレコード、自動取り消しされなかったカタログ編集など）、拒否された変更は**「… サーバーに届かなかった変更」**の下にあり、その行に店舗が示した理由が表示されます。変更が一覧に残っている間に、注文のフィールドなど、レコード自体の理由に該当する箇所を修正してください。
4. **店舗の状態 → データベース**に戻り、その行の**もう一度送信**をタップしてください。このデバイス上の現在の内容から変更を作り直して送信します。
5. 変更が不要になった場合は、代わりに**破棄**をタップしてください。店舗のバージョンが保持されます。確認メッセージを先に読んでください。店舗に保存されたことのないレコードを破棄すると、このデバイスから削除されます。
6. **サイト管理者:** 理由にユーザーに変更権限がないと記載されている場合、そのユーザーの権限では操作できません。[AUTH201](/error-codes/AUTH201)を参照してください。POSに表示されないフィールドが理由に挙がっている場合は、WP Adminで同じレコードを開いてください。別のプラグインがPOSで確認できない検証を追加している可能性があります。それでも拒否される場合は、**ログ**タブで**デバッグ情報をコピー**し、サポートにお問い合わせください。
