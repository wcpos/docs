## これが意味すること {#what-this-means}

このデバイスは、店舗側の新しい編集を上書きして自分のバージョンを保存しました。

WP Adminでログエントリーに記載されたフィールドを確認してください。店舗側の編集が正しい場合は、そこで再度編集してください。

注文で発生します。このデバイスが最後にダウンロードした後、WP Adminのユーザー、プラグイン、または決済通知によって店舗側の注文が変更されました。その後、このデバイスが注文への変更を保存すると、店舗から競合が報告されました。レジでの販売を止めないよう、WCPOSは店舗側のバージョンをこのデバイスのバージョンで上書きして再送信し、店舗はそれを受け入れました。ログエントリーには、このデバイスの値が店舗側の別の値を置き換えたすべてのフィールドが記載されています。レジで追加した明細や設定したステータスなど、店舗側の編集ではなく、このデバイスでの変更が含まれていることもあります。

同じ競合が連続して2回発生すると、WCPOSは変更を保留し、選択を求めます。[SYNC221](/error-codes/SYNC221)を参照してください。

## データへの影響 {#your-data}

注文はこのデバイスのバージョンで店舗に保存されており、レジ側のデータは失われていません。記載されたフィールドについて、店舗側の新しい編集をやり直す必要がある場合があります。ログに記載されるのは置き換えられたフィールドで、以前の値ではありません。一部のフィールドのみを表示していると記載されている場合は、一覧にないフィールドも置き換えられています。注文全体を確認してください。

## トラブルシューティング {#troubleshoot}

1. ログエントリーを展開してください。注文と、このデバイスの値が店舗側の値を置き換えたフィールドが記載されています。
2. WP Adminの**WooCommerce → 注文**で注文を開き、該当フィールドを確認してください。注文のメモに、店舗側の編集を行ったユーザーや処理が記録されている場合があります。
3. フィールドが現在のままで正しい場合（たとえばレジで行った変更の場合）は、何もする必要はありません。
4. 店舗側の編集が正しい場合は、WP Adminで再度編集してください。次回の同期時にレジ側へ反映されます。
5. この問題が続く場合、2か所で同じ注文を同時に変更しています。たとえば、レジで販売を続けている間にWP Adminでステータスを設定している場合や、注文作成後に注文を更新するプラグインがある場合です。注文の編集をどこで行うかを決めてください。サイト管理者は、注文を編集するプラグインを確認できます。
