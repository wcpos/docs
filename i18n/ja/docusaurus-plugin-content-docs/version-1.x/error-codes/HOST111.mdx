## この意味 {#what-this-means}

サーバーのクロスオリジン（CORS）設定が壊れているため、ブラウザーがその応答を拒否しています。

店舗から応答はありますが、CORSの応答ヘッダーが正しくありません。重複している、オリジンの指定が間違っている、またはエラー応答に含まれていない可能性があります。その結果、ブラウザーは実際の応答をWebアプリに表示せず、他のすべてのエラーも一般的なネットワークエラーとして隠されます。サーバー側で、すべてのステータスコードにAccess-Control-Allow-Originを必ず1つだけ設定してください。

## お客様のデータ {#your-data}

注文データや商品データには影響しません。

## トラブルシューティング {#troubleshoot}

1. CORS の層が二重になっていないか（プラグインとサーバー設定の両方がヘッダーを追加している）を確認し、一方を削除してください — Access-Control-Allow-Origin の重複はブラウザーにとって致命的なエラーです。
2. nginx では、add_header 行は 'always' で終わっていない限りエラー応答をスキップします — CORS ヘッダーは 4xx/5xx にも付与する必要があります。
3. CDN やプロキシが CORS ヘッダーを追加している場合は、WordPress 自身のものと競合しないようにしてください。
4. デスクトップアプリとモバイルアプリは CORS を使用しないため、これが修正されるまでの間も引き続き動作します。
