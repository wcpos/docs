## これが意味すること {#what-this-means}

店舗がこの変更を拒否したため、このデバイスは店舗側のバージョンに戻りました。

変更は保存されませんでした。店舗が示した理由を確認し、該当箇所を修正してから、もう一度変更してください。

既存の商品、バリエーション、クーポン、顧客の編集で発生します。値が無効、またはサインイン中のユーザーに変更権限がないなどの理由で店舗が変更を完全に拒否した場合、WCPOSは拒否された編集を送信待ちにしません。店舗と同じ詳細でレジ販売できるよう、このデバイスを店舗側のバージョンに戻します。ログエントリーにはレコードと店舗が示した理由が記載されています。

## データへの影響 {#your-data}

ほかのデータは変更されていません。店舗には変更前のバージョンが引き続き保存され、このデバイスにもそのバージョンが再表示されます。店舗がレコードを削除している場合は、このデバイスからも削除されます。取り消されるのは拒否された編集のみです。理由を修正した後、もう一度編集してください。販売と注文には影響しません。また、拒否された編集の後に同じレコードに加えた編集は保持され、引き続き送信されます。

## トラブルシューティング {#troubleshoot}

1. ログエントリーを展開して、店舗が示した理由を確認してください。拒否された内容と対象のレコードが分かります。
2. 理由に記載された内容を修正してください。価格、SKU、メールアドレス、未入力の必須項目などの値が原因であれば、正しい値を確認してください。ユーザーに変更権限がないと記載されている場合は、アカウントの権限ではその操作を実行できません。[AUTH201](/error-codes/AUTH201)を参照してください。
3. レコードを開き（店舗が削除済みの場合は変更不要です）、正しい値に修正して保存してください。同期後、レコードに変更が反映されていることを確認してください。
4. このデバイスで新規作成したレコードが店舗に拒否された場合、戻す処理は行われません。戻す先となる店舗側のバージョンがないためです。**店舗の状態 → データベース**の**「… 件の変更がサーバーに届いていません」**に引き続き表示されます。[SYNC201](/error-codes/SYNC201)を参照してください。
5. **サイト管理者：**理由にPOSで表示されないフィールドが記載されている場合は、WP Adminで同じレコードを開いてください。別のプラグインがPOSでは確認できない検証ルールを追加している可能性があります。店舗が引き続き変更を拒否する場合は、**ログ**タブの**デバッグ情報をコピー**を使用してサポートへお問い合わせください。
