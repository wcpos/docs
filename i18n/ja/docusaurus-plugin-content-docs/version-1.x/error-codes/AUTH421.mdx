## このエラーの意味 {#what-this-means}

店舗のサーバーが、このアプリで使用可能なすべての経路でログイントークンをブロックしています。

アプリは店舗に接続できることを確認しましたが、サーバー（またはその手前にあるファイアウォール、プロキシ、セキュリティプラグイン）が Authorization ヘッダーを削除し、URL パラメータとして送信された場合もトークンをブロックしています。ログイントークンを送信する方法は他にないため、サーバー側で修正する必要があります。

## 対処方法 {#what-to-do}

診断情報をエクスポートしてサポートにお問い合わせください。上記の変更後に再試行してください。変更せずに再試行しても、同じように失敗します。

## データについて {#your-data}

注文データや商品データには影響ありません。

## トラブルシューティング {#troubleshoot}

1. Authorization ヘッダーが WordPress まで通過するよう、ホスティング事業者に依頼してください。Apache では通常、次の 1 行を追加します: SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1。
2. サイトで .htaccess のリライトルールを使用している場合は、HTTP_AUTHORIZATION を渡す WordPress 生成の RewriteRule 行を保持してください。セキュリティプラグインによって削除されることがあります。
3. プロキシまたは CDN の背後にある場合は、ヘッダー許可リストを確認してください。Authorization リクエストヘッダーがオリジンサーバーへ転送されている必要があります。
4. Web アプリケーションファイアウォール（WAF）が URL パラメータをフィルタリングしている場合は、/wcpos/ REST ルートで認証パラメータを許可するようホスティング事業者に依頼してください。

## 確認場所 {#where-to-look}

WCPOS がこのエラーを保存できる場合、エラーを発生させたデバイスに記録されます。**店舗の状態 → ログ**（ナビゲーションドロワー下部の心拍アイコン）を開き、このコードが付いたエントリを見つけて展開してください。展開した行には、わかりやすい原因と、失敗時に取得されたコンテキストが表示されます。店舗リクエストの場合、このコンテキストにはサーバー独自のエラーコード (`serverCode`)、HTTP `status`、または `endpoint` が含まれることがあります。表示される項目は、失敗した場所によって異なります。問題を報告する際は、スクリーンショットではなくログ画面上部の **デバッグ情報をコピー**（スマートフォンおよびタブレットでは **デバッグ情報を共有**）を使用してください。アプリのバージョン、接続状態、最新のエラーがまとめられます。ログは最長 30 日間保持されるため、問題が発生した直後に収集してください。また、POS が独自のログエントリを書き込める前に表示されたブラウザーコンソールエラーもコピーしてください。
