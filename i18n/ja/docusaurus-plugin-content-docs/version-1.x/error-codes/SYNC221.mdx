## これが意味すること {#what-this-means}

このデバイスでの変更が、店舗側の新しい編集と競合しました。データは失われていません。

**店舗の状態 → データベース**にこのレコードの保留中の変更が表示されている場合は、**もう一度送信**をタップしてこのデバイスのバージョンを保持するか、**サーバーのバージョンを使用**をタップして店舗側のバージョンを保持してください。表示されていない場合は、すでに解決しているため何もする必要はありません。

## データへの影響 {#your-data}

データは失われていません。変更が保留中の場合、どちらを保持するか選ぶまで、店舗には店舗側のバージョンが、このデバイスには変更内容が保持されます。それまでは、そのレコードへの追加の編集もこのデバイスで保留されます。保留中の変更を消去してしまうため、保留中はこのデバイスのデータを消去しないでください。

## トラブルシューティング {#troubleshoot}

1. **店舗の状態 → データベース**を開いてください。保留中の変更は、対象のレコードとともに**「1件の変更が保留中です」**（または**「… 件の変更が保留中です」**）というパネルに表示されます。
2. このレコードの保留中の変更が表示されなくなっている場合は、ここまたは別のタブですでに解決しているため、何もする必要はありません。WCPOSが自動的にこのデバイスのバージョンを再送信して解決した注文の競合は、代わりに[SYNC222](/error-codes/SYNC222)として記録されます。
3. 変更が保留中の場合は、**レコードを開く**（表示される場合）を押して、このデバイスのバージョンを確認してください。WP Adminで同じレコードを開き、比較してください（サイト管理者による操作が必要な場合があります）。
4. このデバイスのバージョンを保持するには、**もう一度送信**をタップしてください。このデバイスで変更したフィールドの店舗側の値を置き換えて、変更が再送信されます。店舗側のバージョンを保持するには、**サーバーのバージョンを使用**（一部の行では**デバイスの変更を破棄**）をタップして確定してください。このデバイスの変更は破棄されます。選択するまで、そのレコードへの追加の編集は保留されます。
5. 同じレコードで頻繁に競合が起きる場合、通常は2人が同じデータを並行して編集しています。たとえば、レジとWP Adminで在庫を編集している場合です。編集の種類ごとに、どこで編集するかを決めてください。
