## このエラーの意味 {#what-this-means}

このアプリで使用可能な、どのアドレス形式でも店舗の REST API から応答がありませんでした。

このアプリは、通常のアドレス（/wp-json/...）と WordPress の組み込みフォールバックアドレス（/?rest_route=...）で店舗の REST API への接続を試みましたが、どちらからも応答がありませんでした。店舗のウェブサイト自体は稼働している可能性がありますが、これは特に REST API に到達できない状態を示しています。通常は、セキュリティプラグインによって API が非表示にされているか、ファイアウォールルールによってブロックされています。

## 対処方法 {#what-to-do}

診断情報をエクスポートしてサポートにお問い合わせください。上記の変更を行った後に再試行してください。変更せずに再試行しても、同じ原因で失敗します。

## データへの影響 {#your-data}

注文または商品データへの影響はありません。

## トラブルシューティング {#troubleshoot}

1. セキュリティプラグインが /wp-json/ を非表示または名称変更している場合（例: WP Hide）は、WordPress 組み込みの /?rest_route= 形式も許可してください。アプリは自動的にこの形式にフォールバックします。
2. wp-json または rest_route に一致するファイアウォール（WAF）ルールを確認し、店舗自身の REST API を許可してください。
3. ブラウザからテストします: https://your-store.com/?rest_route=/ は、403 ページやサイトのホームページではなく JSON を返す必要があります。
4. サーバーの前にメンテナンスページまたはボットチャレンジがある場合、REST リクエストが HTML ページで応答されることがあります。REST API に対するチャレンジを無効にしてください。

## 確認場所 {#where-to-look}

WCPOS がこのエラーを保存できる場合、エラーを発生させたデバイスに記録されます。**店舗の状態 → ログ**（ナビゲーションドロワー下部にある心拍アイコン）を開き、このコードが付いたエントリーを見つけて展開してください。展開した行には、わかりやすい原因と障害発生時に取得されたコンテキストが表示されます。店舗リクエストの場合、このコンテキストにはサーバー固有のエラーコード (`serverCode`)、HTTP `status`、または `endpoint` が含まれることがあります。表示される項目は、障害が発生した場所によって異なります。問題を報告する際は、スクリーンショットではなく、ログ画面上部の **デバッグ情報をコピー**（スマートフォンおよびタブレットでは **デバッグ情報を共有**）を使用してください。アプリのバージョン、接続状態、直近のエラーがまとめられます。ログは最大 30 日間保持されるため、問題が新しいうちに収集してください。また、POS が独自のログエントリーを書き込めるようになる前に表示されたブラウザコンソールのエラーもコピーしてください。
