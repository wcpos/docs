# DB02002: レコードが見つかりません {#db02002-record-not-found}

## これはどういう意味か {#what-this-means}

リクエストされたレコードはローカルデータベースに存在しません。POSは、ローカルに保存されていない製品、顧客、注文、またはその他のレコードにアクセスしようとしました。

## 一般的な原因 {#common-causes}

- **まだ同期されていない** — データがまだダウンロードされていない
- **サーバーで削除された** — WooCommerceでレコードが削除された
- **同期が完了していない** — 最初の同期がまだ実行中
- **フィルターが適用されている** — アクティブなフィルターによってレコードが除外されている

## 修正方法 {#how-to-fix}

### 1. 同期を待つ {#1-wait-for-sync}

最近始めた場合:
- 最初の同期が完了するまで待つ
- 同期進行状況インジケーターを確認
- 同期が完了するとレコードが表示される

### 2. 更新/再同期 {#2-refreshre-sync}

データの更新をトリガーします:
- 更新/同期ボタンを使用する（<Icon name="arrow-rotate-right" />）- 短押しで同期
- ここでは**長押し**の「クリアして更新」オプションを使わないでください。このデバイス上のリスト全体が消去され、未保存の開いているカートも含まれます。先に手順5を確認してください。
- サーバーから最新データを取得
- 完了するまで待つ

### 3. WooCommerceを確認 {#3-check-woocommerce}

サーバー上にレコードが存在するか確認します:
- WordPress管理画面にログイン
- 製品、注文、または顧客を確認
- アイテムがまだ存在することを確認

### 4. フィルターを確認 {#4-check-filters}

レコードがフィルターで除外されている可能性があります:
- POS内のアクティブフィルターを確認
- カテゴリーフィルターをチェック
- 可視性設定を確認

### 5. データをクリアし再同期 {#5-clear-and-re-sync}

:::warning 未保存の作業がないか、先に確認してください
ローカルデータを消去したり、アプリを再インストールしたりすると、店舗にまだ送信されていないデータがこのデバイスから削除されます。オフライン中の販売、開いたままのカート、保存されなかった編集も含まれます。消去する前に、**Store health → Database**を開き、保留中またはサーバーに未到達の項目がないことを確認してください。次に**Store health → Logs**で、**stuck recordsが0件**、**changes waiting to sendが0件**であることを確認し、開いているカートはすべて完了するか内容を記録してください。WCPOSにStore healthページがない場合は、先にWCPOSを更新してから確認してください。項目や待機中の変更がある場合、または確認できない場合は消去せず、店舗のオーナーに相談するかサポートにお問い合わせください。
:::

同期が停止したままで、上記の確認を済ませた場合に限ります：
1. ローカルデータをクリア
2. 再度ログイン
3. 新たに同期を完了

## 一般的なシナリオ {#common-scenarios}

- **製品が表示されない:** 発行されており、可視であるか確認
- **顧客が見つからない:** まだ同期されていない可能性がある
- **注文が欠落している:** 同期の期間外かもしれない
