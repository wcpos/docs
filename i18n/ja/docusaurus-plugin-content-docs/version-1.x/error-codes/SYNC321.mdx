## これが意味すること {#what-this-means}

一部のデータが今回同期されませんでした。

このコードには二つの形式があります。ログ行のタイトルでどちらかを確認できます。

- **「同期が部分的」**（レコードのタイトル）: 一部のレコードは同期されましたが、記載されたレコードは同期されていません。次回の同期で解消すれば対応は不要です。対応が必要な変更が**店舗の状態 → データベース**に表示されている場合は、そこで解決してください。
- **「停滞したデータリクエストを中止」**：同期エンジンのデータリクエスト処理が一つのリクエストで進まなくなったため、アプリは十分に待ってからそのリクエストを破棄し、後続のキュー全体が停止するのを防ぎました。同期エンジンが自動的にリクエストを再発行するため、手動で再試行する必要はありません。多くの場合、別途 [SYNC181](/1.x/error-codes/SYNC181) として記録されるローカルデータベース呼び出しの停止に続いて発生します。

## データへの影響 {#your-data}

このデバイスのデータは消去しないでください。店舗にまだ届いていない変更が含まれている可能性があります。データリクエストを断念した場合、変更は加えられておらず、破棄されたリクエストは自動的に再発行されます。繰り返し発生する場合は、**ログ**タブで**デバッグ情報をコピー**し、WCPOSサポートにお問い合わせください。

## トラブルシューティング {#troubleshoot}

1. **「停止したデータリクエストを断念」** というログ項目の場合、画面が停止したままでなければ対応は不要です。停止したままの場合はアプリを再読み込みしてください。Webではブラウザーのタブを再読み込みし、デスクトップまたはモバイルではアプリを終了して再度開きます。
2. 部分同期の場合、次回の同期で解消すれば対応は不要です。解消しない場合は、**店舗の状態 → データベース**を開いてください。同期されなかったレコードが上部に表示されます。**「… 対応が必要なレコード」**の通知には最初のレコードと理由が表示されます（修正すると次のレコードが表示されます）。**「… サーバーに届かなかった変更」**と**「… 保留中の変更」** のパネルにも該当する項目が表示されます。同期済みのレコードには対応不要です。
3. 一覧の各レコードを、それぞれの理由に従って解決してください。通知内の**レコードを修正**（表示されている場合）を選ぶと、編集用にレコードが開きます。拒否された変更はレコード自体で修正し（[SYNC201](/1.x/error-codes/SYNC201)）、保留中の変更はどちらのバージョンを保持するか選択してください（[SYNC221](/1.x/error-codes/SYNC221)）。
4. その後、通知内の**再試行**（同期を実行します）、またはパネル内のレコード行にある**もう一度送信**で再送信してください。通知に*店舗からダウンロードできない*と表示されたレコードには**再試行**がありません。[SYNC331](/1.x/error-codes/SYNC331)を参照してください。
5. レコードがまだ同期されない場合は、**ログ**タブで**デバッグ情報をコピー**し、サポートにお問い合わせください。
