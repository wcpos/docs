**WP管理画面：** `WP Admin → POS → Settings → General → Tax IDs`。番号自体は顧客情報に追加します。

事業用に購入する顧客は、VAT番号、ABN、CPF、GSTINなどの納税者番号をレシートに記載する必要がある場合があります。顧客情報に一度追加すれば、POSがその顧客の各注文にコピーし、レシートに印刷します。無料プラグインでも、[個別の販売に追加](#one-sale)できます。

ほとんどの店舗では設定は不要です。**WP Admin > POS > 設定 > 一般** の **納税者番号** セクションでは、番号を保存するWordPressフィールドだけを指定します。これにより、すでに利用しているVATプラグインをそのまま使えます。[納税者番号の保存先を選ぶ](#plugins-and-field-names)をご覧ください。

## 顧客に納税者番号を追加する {#add}

:::info WCPOS Proで利用可能
POSで顧客を追加・編集するにはProが必要です。無料プラグインでは、代わりに[販売に](#one-sale)納税者番号を追加してください。
:::

1. 顧客フォームを開きます。
   - **新規顧客：** カートで **+** をタップして **新規顧客を追加** を選択するか、**顧客** 画面の検索欄の横にある **新規顧客を追加** を押します。
   - **既存の顧客：** **顧客** 画面で、その顧客の行にある矢印（›）を押して開きます。
2. **納税者番号** を押すと、入力行が表示されます。
3. **種類** を選択し、**ID** を入力して、**国** を確認します。[納税者番号の入力行](#row)をご覧ください。
4. **新規顧客：** **顧客を追加** を押します。**既存の顧客：** 保存ボタンはなく、変更するたびに保存されます。フォームのその他の項目は[顧客](../../customers/index.mdx#add-new-customer)をご覧ください。

## 個別の販売に納税者番号を追加する {#one-sale}

無料プラグインでも利用できます。

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[50, 0]]} maxWidth={420} alt="カート上部：顧客、ゲスト、その横に住所を操作するピンアイコン">

1. **住所** — 顧客名の横にあるピンです。販売に番地、市区町村、郵便番号のいずれかが設定されるまでは灰色ですが、タップできます。

</JourneyShot>

1. カート上部で、顧客名の横にある住所をタップします。**顧客の住所を編集** が開きます。
2. **納税者番号** を押し、[納税者番号の入力行](#row)の説明に従って **種類** を選択し、**ID** を入力して、**国** を確認します。
3. **閉じる** を押します。番号は入力時にこの注文に保存されており、レシートに印刷されます。

<JourneyShot manifest={cartManifest} device="tablet" step={7} offsets={[[80, 0], [250, 0], [200, 0], [200, 0], [285, 0], [0, 0], [0, -40]]} alt="Linda Smithの顧客の住所を編集画面：名前、メールアドレス、電話番号、国と都道府県を含む請求先住所の入力欄、配送先住所、会社と納税者番号のボタン、閉じると顧客情報も更新のボタン">

1. **名前** — 姓名です。その下に **メールアドレス** と **電話番号** があります。
2. **請求先住所** — **編集** で入力欄を開き、**削除** で内容を消去します。
3. **国** — 一覧から選択します。国が十か国を超える場合は検索できます。
4. **都道府県** — 選択肢が用意されている国では一覧、それ以外ではテキスト入力欄が表示されます。
5. **配送先住所** — **別の住所を使用** を押すまでは **請求先と同じ** になります。
6. **納税者番号** — この注文に[納税者番号の入力行](#row)を追加します。
7. **顧客情報も更新** — これらの情報を顧客プロフィールにも保存します。

</JourneyShot>

番号を顧客プロフィールにも保存するには、**顧客情報も更新** を押します。このボタンは、アカウントを持つ顧客に対して、顧客の編集権限があるレジ係にのみ表示されます。[注文の住所を編集する](../../pos/cart/index.mdx#address)をご覧ください。

## 納税者番号の入力行 {#row}

入力行は、顧客フォームでも、ここに示すカートの **顧客の住所を編集** 画面でも同じです。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[0, 0], [40, -38], [24, -38], [64, -39], [-24, 0]]} maxWidth={560} alt="納税者番号を入力した顧客の住所を編集画面：種類はEU VAT、IDはDE123456789、国はDE。行の横に削除、その下に納税者番号ボタン">

1. **納税者番号** — 入力行を追加します。イタリアの顧客のCodice FiscaleとPartita IVAなど、二つ目の番号を追加するには、もう一度押します。
2. **種類** — 番号の種類です。新しい行では、顧客の請求先の国に対応する最初の種類が選択されます。請求先住所が空の場合は店舗の国が使われ、その国に対応する種類がない場合は **その他** が選択されます。[納税者番号の種類](#supported-types)をご覧ください。
3. **ID** — 番号を入力します。空の欄には、選択した種類に合う形式の例が表示されます。長い番号は欄内でスクロールできます。保存時にスペースが削除され、英字は大文字になります。
4. **国** — 英字二文字の国コードです。種類を選ぶと自動入力され、**英国VAT** では **GB**、**ブラジルCPF** では **BR** になります。**EU VAT** と **その他** では請求先の国が使われるため、別の加盟国のEU顧客の場合は確認してください。
5. **削除** — その行を削除します。

</JourneyShot>

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[-16, 0], [0, 0]]} maxWidth={520} alt="米国の店舗で、新しい納税者番号の行の種類一覧を開いた状態：最上部の米国EINにチェックが付き、区切り線の下にEU VAT、英国VAT、オーストラリアABNなどの種類が並ぶ">

1. **その国に対応する種類** — 区切り線より上に、請求先の国または店舗の国に対応する種類が表示されます。この例では店舗が米国にあるため、**米国EIN** のみです。
2. **その他すべての種類** — 区切り線より下に、**EU VAT** から順に表示されます。

</JourneyShot>

EU VAT番号は、**DE123456789** のように国コードを付けて入力します。国コードなしで入力した場合、**EU VAT** と **英国VAT** に限り、保存時に **国** の値が番号の先頭に付加されます。

## 注文に保持される情報 {#tax-ids-are-copied-onto-orders}

販売時に顧客を選択すると、POSがその顧客の納税者番号を注文にコピーします。番号は[注文の住所](../../pos/cart/index.mdx#address)の下に表示され、その販売用に変更できます。注文には販売時の番号が保持されます。

- 後で顧客の納税者番号を変更しても過去の注文は変わらないため、以前のレシートは元の内容で再印刷されます。
- カートで変更または追加した納税者番号は、顧客情報の番号に代わって、その注文に使用されます。
- 注文の納税者番号を変更しても、変更されるのはその注文だけです。顧客情報から再びコピーされることはありません。
- ゲストへの販売には、その販売に追加しない限り納税者番号はありません。

## レシートへの印刷 {#on-receipts}

**標準レシート**、**詳細レシート**、**請求書**、**見積書** テンプレートと詳細な感熱紙レシートでは、顧客情報とともに顧客の納税者番号が印刷されます。各番号には **VAT ID**、**ABN**、**CPF** など、それぞれのラベルが付きます。[納税者番号の種類](#supported-types)の表をご覧ください。独自のテンプレートで印刷する方法は、[納税者番号オブジェクト](../../receipts/receipt-data.mdx#tax-id-objects)をご覧ください。

## 納税者番号で顧客を検索する {#finding-customers-by-tax-id}

カートまたは **顧客** 画面の顧客検索欄に番号を入力します。[納税者番号の保存先を選ぶ](#plugins-and-field-names)に記載されたVATプラグインが、WCPOSを使い始める前に保存した番号も検索できます。[顧客の検索](../../customers/index.mdx#find)をご覧ください。

## 納税者番号の保存先を選ぶ {#plugins-and-field-names}

WCPOSは、VATプラグインがすでに使っている保存先に納税者番号を保存します。そのため、レジで入力した番号はプラグインに表示され、プラグインが保存した番号はPOSに表示されます。このセクションでの設定が必要なのは、両者が一致しない場合だけです。

確認するには、**WP Admin > POS > 設定 > 一般** を開き、**納税者番号** までスクロールします。VATプラグインがWCPOSによって検出されたかどうかがバナーに表示されます。

<JourneyShot manifest={manifest} device="desktop" step={5} offsets={[[-60, 0], [-60, 0], [76, 0], [166, 0], [96, 0], [108, 0]]} alt="一般設定の顧客の下にある納税者番号セクション：プラグインが検出されませんでしたというバナーと、詳細設定：別のフィールド名を使用を展開した表。列は種類、使用中のフィールド名、設定元、上書きで、すべての行の設定元は組み込み、上書き欄は空">

1. **プラグインが検出されませんでした** — WCPOSはVATプラグインを検出できず、組み込みのフィールド名を使用しています。
2. **詳細設定：別のフィールド名を使用** — 下の表を開きます。[別のフィールド名を使用する](#choosing-the-field-name-yourself)をご覧ください。
3. **種類** — 納税者番号の種類ごとに一行あります。
4. **使用中のフィールド名** — WCPOSが現在、その種類の番号を保存している場所です。
5. **設定元** — そのフィールド名の選択元です。この例では、すべての種類が **組み込み** です。
6. **上書き** — 独自のフィールド名です。空欄の場合はデフォルトが使われます。

</JourneyShot>

<details>
<summary>WCPOSによるフィールドの選択方法と検出対象のプラグイン</summary>

WordPressは、名前付きのフィールド（メタキー）に顧客の納税者番号を保存します。VATプラグインは、それぞれ独自のフィールド名を使います。バナーには次のように表示されます。

- **自動検出** — 「…がインストールされています」と、検出したプラグイン名が表示されます。WCPOSはVAT形式の納税者番号を、そのプラグインが読み取るフィールドに保存します。操作は不要です。
- **プラグインが検出されませんでした** — WCPOSは、組み込みのフィールド名、または最近の注文ですでに使われているフィールドを使用します。

WCPOSは種類ごとに、次のうち最初に該当するものを使用します。

1. [別のフィールド名を使用する](#choosing-the-field-name-yourself)で設定した独自のフィールド名。
2. 検出したプラグインのフィールド。
3. プラグインが検出されなかった場合は、直近200件の注文で最も多く使われているフィールド。
4. 組み込みのフィールド名。

検出対象のプラグイン：

- WooCommerce EU VAT Number
- Aelia EU VAT Assistant（Aeliaによる番号の有効性の判定も含みます）
- WPFactory EU/UK VAT Manager
- WooCommerce Germanized、およびGermanized Pro
- Brazilian Market on WooCommerce、およびExtra Checkout Fields for Brazil
- NIF/CIF Spain for WooCommerce

組み込みのフィールド名：

| 種類 | フィールド名 |
|---|---|
| EU VAT、英国VAT、サウジアラビアVAT、オーストラリアABN、カナダGST/HST、米国EIN、その他 | `_billing_vat_number` |
| ブラジルCPF | `_billing_cpf` |
| ブラジルCNPJ | `_billing_cnpj` |
| インドGSTIN | `_billing_gstin` |
| イタリアCodice Fiscale | `_billing_cf` |
| イタリアP. IVA | `_billing_piva` |
| スペインNIF/CIF | `_billing_nif` |
| アルゼンチンCUIT | `_billing_cuit` |

</details>

### 別のフィールド名を使用する {#choosing-the-field-name-yourself}

プラグインが、WCPOSの認識しないフィールド名で納税者番号を保存している場合にのみ行ってください。

<details>
<summary>フィールド名を変更する</summary>

**納税者番号** セクションで **詳細設定：別のフィールド名を使用** を開きます。種類ごとに一行ずつ表示されます。

- **種類** — 納税者番号の種類です。
- **使用中のフィールド名** — WCPOSが現在、その種類の番号を保存している場所です。
- **設定元** — **プラグイン**（検出されたプラグイン）、**組み込み**（WCPOSのデフォルト）、**カスタム**（独自の上書き設定）のいずれかです。
- **上書き** — プラグインが使用するフィールド名を入力します。WCPOSが他のプラグインから認識している名前が候補として表示されます。候補を選ぶか、独自の名前を入力してEnterを押すか入力欄からフォーカスを外すと保存されます。保存ボタンはありません。

自動選択される名前に戻すには、「（デフォルトを使用するには空欄にしてください）」と表示される **上書き** 欄を空にします。**詳細設定：別のフィールド名を使用** の行には、有効な上書き設定の数が表示されます。

</details>

:::note
ここに表示されるのは顧客の納税者番号だけです。USt-IdNr.、KVK、SIRET番号など、自社の番号は[店舗の納税者番号](./store-tax-ids.mdx)で設定します。
:::

## 問題が発生した場合 {#goes-wrong}

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[-28, 0]]} maxWidth={560} alt="種類にEU VAT、IDにDE1234が入力された納税者番号の行。IDの下に「形式が選択した種類と一致しません。」という警告が表示されている">

1. **形式の警告** — **ID** の下に表示されます。対処方法は以下の最初の項目をご覧ください。

</JourneyShot>

- **形式が選択した種類と一致しません。** — まず **種類** を確認し、次に数字の抜けがないか顧客と番号を確認してください。これは警告のみで、番号は保存されます。EU VAT番号を国コードなしで入力した場合も表示されます。保存時に **国** の値が番号の先頭に付加されるため、**国** が正しいことを確認してください。POSが確認するのは番号の形式のみで、税務当局が実際に発行した番号かどうかは確認しません。
- **以前のレシートに古い番号が表示される** — 注文には販売時の番号が保持されています。顧客情報ではなく、その注文の納税者番号を変更してください。
- **レシートに納税者番号が表示されない** — ゲストへの販売だったか、販売時に顧客の番号が登録されていなかったことが原因です。支払い前に販売に番号を追加し、顧客情報を表示するレシートテンプレートを使っていることを確認してください。
- **レジで入力した番号がVATプラグインに表示されない** — **WP Admin > POS > 設定 > 一般 > 納税者番号** で **詳細設定：別のフィールド名を使用** を開き、**使用中のフィールド名** とプラグインが読み取るフィールドを比較してください。異なる場合は **上書き** を設定します。
- **顧客情報も更新が表示されない** — ゲストへの販売か、WordPressの権限グループに顧客の編集権限がないことが原因です。納税者番号は注文には保存されます。
- **新規顧客を追加がグレーアウトしている** — Proと、顧客を作成できる権限グループが必要です。
