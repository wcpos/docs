**WP管理画面：** `WP Admin → POS → Settings → General → Register`。

ここではレジを有効にし、開始時の釣銭準備金、集計にマネージャーの承認が必要となる条件、レジ係に締めを通知する時刻を設定します。各設定によってレジ係に何が表示されるかは、後述します。

レジとは何か、店舗や端末との違いについては、[店舗・レジ・端末](../../stores/registers-and-devices.mdx)を参照してください。

## レジを有効にする {#one-register}

Proを使用し、店舗が1つ以上ある場合、これらの設定はサイトのデフォルトとなり、各レジの釣銭準備金の設定は店舗側に移ります。[店舗のレジ一覧ページ](#store-registers)を参照してください。

1. **一般**設定ページで、**レジ**までスクロールします。
2. **レジの開始と締め**をオンにします。その下にルールが表示されます。オフの場合、POSは直接カートを表示し、レジ係はレジの開始や現金の集計を行いません。
3. **開始時の釣銭準備金**を確認します。初めてレジを有効にすると、**200.00**に設定されます。1日の開始時にドロワーに入れておく金額に変更してください。Proの店舗がある場合、このフィールドはここにはありません。[店舗のレジ一覧ページ](#store-registers)で各レジの釣銭準備金を設定します。
4. 必要に応じて、**集計の差額が指定額を超えたらマネージャーに確認**をオンにし、金額を設定します。
5. 必要に応じて、**レジ係に締めを通知する時刻**をオンにし、時刻を設定します。

変更すると、すぐに、またはフィールドからフォーカスを外したときに保存されます。フィールドを空欄にすると、直前の値に戻ります。

<Accordion>
<AccordionItem question="開始時の釣銭準備金、マネージャーの承認、締めの通知">

各設定は文の形で表示され、その中に設定値が入ります。

- **レジの開始と締め**はレジセッションを有効にします。レジ係は釣銭準備金を用意して開始し、現金の入出金を記録し、締め時にドロワーの現金を数えます。オフの場合、POSは直接カートを表示し、開始や集計の操作は不要です。
- **開始時の釣銭準備金**は、開始時にドロワーに入れる現金です。レジ係がレジを開始するときに**ドロワー内の現金**に入力され、レジ係は実際の金額に変更できます。レジが有効な場合にのみ表示されます。
- **集計の差額が指定額を超えたらマネージャーに確認 …**はデフォルトでオフです。オンにすると初期値は**5.00**です。締め時の不足額または超過額がこの金額を超える場合、レジを締める前にマネージャーの承認が必要です。オフの場合、差額にかかわらず承認なしで締められます。
- **レジ係に締めを通知する時刻 …**はデフォルトでオフです。オンにすると初期値は**17:30**です。この時刻を過ぎるとレジに**締め時刻超過**と表示され、カートが空の場合は**チェックアウト**の代わりに**レジを締める**が表示されます。[締め時刻になったとき](#overdue)を参照してください。

任意のルールをオンにすると初期値が入力されます。オフにすると値がクリアされ、再びオンにすると再度初期値から始まります。

</AccordionItem>
</Accordion>

設定の下に**Proでレジと店舗を追加**リンクがあります。

無料プラグインで使えるレジは1台のみです。

<Accordion>
<AccordionItem question="複数の端末で同じレジを使う">

サインインしたすべての端末が1台のレジを使用します。同じカウンターのブラウザー、デスクトップアプリ、スマートフォンは、すべて同じドロワーへの販売を記録し、1つのレジセッションを共有します。そのため、現金の集計と締めは1回だけ行います。レジに名前を付ける設定はなく、レジバーには店舗のみが表示されます。

</AccordionItem>
</Accordion>

## レジ係に表示される内容 {#what-the-cashier-sees}

レジが締め済みの場合、レジ係はドロワー内の現金を数え、カート列からレジを開始します。

<JourneyShot manifest={registerManifest} device="tablet" step={1} offsets={[[81, 0], [-34, 0], [0, 0], [255, 0], [157, 0], [0, 0]]} alt="レジが締め済みのPOS。締め済みステータスのレジバー、商品上部の価格確認バー、カート列の現金フィールド、前回の集計額、レジを開始ボタンが表示されています">

1. **レジのステータス** — ここでは**締め済み**です。**締め時刻超過**（[締め時刻になったとき](#overdue)を参照）や**承認が必要**（[集計に差額があるとき](#count-out)を参照）と表示される場合もあります。
2. **レジバー** — この端末で販売を行う店舗です。Proで店舗に複数のレジがある場合は、レジ名も表示されます。
3. **価格確認バー** — レジが締め済みの間も、レジ係は商品の検索や価格の確認ができますが、カートには追加できません。
4. **ドロワー内の現金** — 初期値は**開始時の釣銭準備金**です。釣銭準備金が未設定の場合は前回の集計額です。レジ係は実際に数えた金額を入力します。
5. **前回の集計額** — 前回のレジ締めで集計した金額のチップです。タップするとその金額を使用できます。予定現金額を見ずに集計するレジ係には、これも表示されません。この設定は[アクセス](./access.mdx)で行います。
6. **レジを開始** — セッションを開始します。釣銭準備金と異なる金額は**開始時の差額**として表示されます。

</JourneyShot>

釣銭準備金の用意から締めまでのセッション全体の手順は、[レジの開始](../../pos/register/index.mdx)で説明しています。

### 締め時刻になったとき {#overdue}

**レジ係に締めを通知する時刻**は、レジを締めたり販売を停止したりする設定ではありません。店舗の時刻で設定時刻を過ぎると、POSはそのときレジを担当している人に次のように通知します。

- レジバーに**締め時刻超過**と表示されます。
- カートが空の場合、**チェックアウト**が**レジを締める**に変わります。商品が入ったカートでは、通常どおりチェックアウトできます。
- レジパネルのボタンには、設定した時刻に合わせて**レジを締める · 17:30を過ぎています**と表示されます。

設定時刻を過ぎてから開始したレジの締め時刻は、翌日の同じ時刻になります。一晩開いたままのレジは、誰かが締めるまで**締め時刻超過**のままです。

{/* reshoot: Overdue bar and Close register in an empty cart, see reshoot.md */}

### 集計に差額があるとき {#count-out}

締め時に、レジ係は釣銭準備金を含めて実際に数えた金額を入力します。入力すると差額が表示されます。その下の**メモ**フィールドには、差額の理由を記入します。

<JourneyShot manifest={registerManifest} device="tablet" step={7} offsets={[[150, 0], [-90, 0], [-12, -24]]} alt="レジ締め画面。集計した現金のフィールド、一致と表示された予定額、締めて印刷ボタンがあります">

1. **集計した現金（釣銭準備金を含む）** — レジ係が数えた金額です。
2. **予定額**と差額 — ここでは**一致**です。集計に差額がある場合は、**不足**額または**超過**額が表示されます。上限を超えると、*上限 … を超えています · マネージャーの承認が必要です*と追加表示されます。
3. **締めて印刷** — レジを締めます。差額が**集計の差額が指定額を超えたらマネージャーに確認**で設定した上限を超える場合、ボタンは**承認して締める**になり、マネージャーがサインインして承認します。承認には接続が必要です。

</JourneyShot>

承認できるユーザーと、予定額を見ずに集計するユーザーは[アクセス](./access.mdx)で設定します。締めと承認の記録は[照合](../../reports/reconciliation.mdx)に保存されます。

:::note セッション画面とは異なります
[セッション](./sessions.mdx)には、POSにサインインしているユーザーとその端末が表示されます。*レジセッション*はこれとは異なり、釣銭準備金を用意してレジを開始してから、現金を集計して締めるまでの期間を指します。
:::

## Proでレジを増やす {#more-registers-with-pro}

2つ目のキャッシュドロワーには2台目のレジが必要です。これは[WCPOS Pro](../../getting-started/free-vs-pro.mdx)の機能です。Proではレジは店舗に所属します。Proを有効にすると、一般設定の**レジ**セクションは次のように変わります。

<Accordion>
<AccordionItem question="最初の店舗を作成する前">

- 無料プラグインと同様に、**レジの開始と締め**と2つのルールは、サイトの1台のレジに適用されます。
- **開始時の釣銭準備金**は、その1台のレジ用としてここに残ります。
- 設定の下に、*複数のレジを使うには、店舗を作成し、そのページでレジを追加してください。*という案内と**店舗を追加**リンクが表示されます。

</AccordionItem>
<AccordionItem question="店舗を作成した後">

- **レジの開始と締め**と2つのルールは**サイトのデフォルト**になります。このセクションには、*サイトのデフォルトです。各店舗のページで個別に変更できます。*と表示されます。
- **開始時の釣銭準備金**はこのセクションからなくなります。各レジの釣銭準備金は、その店舗の**レジ一覧**ページで設定します。
- 設定の下の**店舗を管理**で、店舗一覧を開きます。

</AccordionItem>
</Accordion>

店舗を作成するとき：

- 最初に作成した店舗は、既存のレジをそのまま引き継ぎます。その店舗用の新しいレジは作成されません。
- それ以降に作成する店舗には、それぞれ専用のレジが作成されます。
- 公開済みの店舗にレジがない場合、次にPOSまたは店舗のページでレジ一覧を表示したときに、**レジ**という名前のレジが追加されます。
- レジは同時に1つの店舗にのみ所属できます。

### 店舗のレジ一覧ページ {#store-registers}

**POS → 店舗**を開いて店舗をクリックし、店舗メニューの**販売**にある**レジ一覧**を選択します。**レジ台**の表に店舗のレジが表示されます。**+ レジを追加**で追加すると、**レジ 2**、**レジ 3**のような名前が付き、変更できます。新しい店舗では先に**作成**が必要です。それまでは表に**レジを追加するには、先に店舗を保存してください。** と表示されます。

<Accordion>
  <AccordionItem question="レジ台の表：列、ステータス、⋯メニュー">

| 列 | 表示内容 |
| --- | --- |
| **レジ** | POSに表示されるレジの名前。 |
| **開始時の釣銭準備金** | レジ係がこのレジを開始するときの現金。変更は次回の開始時から適用されます。 |
| **ステータス** | 緑の点とともに、**開始時刻**、時刻、**·**、開始した人を表示します。集計中は黄色の点とともに、**集計中**、**·**、開始した人を表示します。締め済みの場合はグレーの点とともに、**締め済み · 前回のレジ締め #**、番号、日付を表示します。初回の締め前は**締め済み**のみです。 |
| **⋯** | **名前を変更**、別の店舗へ**移動**、または**使用終了**。セッションが開いているか集計中のレジは使用終了にできず、**先にセッションを締めてください**と表示されます。 |

店舗メニューの**レジ一覧**のバッジには、開いているレジの台数が表示されます。開いているレジがない場合は、すべてのレジの台数が表示されます。

  </AccordionItem>
  <AccordionItem question="店舗別のキャッシュドロワールール">

店舗が一般設定のルールを使用している間は、表の下の**キャッシュドロワールール**は折りたたまれたままで、**サイトのデフォルト**と表示されます。**カスタマイズ**をクリックすると、**毎日レジの開始と締めを行う**、**集計の差額が指定額を超えたらマネージャーに確認**、**レジ係に締めを通知する時刻**という同じ3つの設定が表示されます。ここで変更するまでは、それぞれに**サイトのデフォルト**と表示されます。**サイトのデフォルトを使用**で1つのルールを戻し、**サイトのデフォルトにリセット**で3つすべてを戻せます。

その下の**レポートとレジ締め**では、この店舗でレジを締めたとき（**レジ締め印刷物**）と、売上レポートを実行したとき（**売上レポート**）に印刷するものを設定します。

  </AccordionItem>
</Accordion>

店舗のレシートやスタッフを含む詳しい手順は、[店舗の設定](../../stores/setup.mdx#registers)にあります。

### Proを無効化した場合 {#if-pro-is-deactivated}

無料プラグインの1台のレジに戻ります。他のレジでまだ開いているセッションは、集計して締められますが、Proを再び有効にするまで、それらのレジを再度開始することはできません。

## 問題が起きた場合 {#goes-wrong}

**レジを保存できませんでした。** 開始時の釣銭準備金が保存されていません。接続を確認し、もう一度入力してください。

**開始時の釣銭準備金フィールドがグレー表示になっています。** 読み込み中か保存中です。少し待ち、グレー表示のままであればページを再読み込みしてください。

**レジ係に締め時刻超過が表示されません。** **レジ係に締めを通知する時刻**がオンか確認してください。Proの場合は、店舗独自の**キャッシュドロワールール**も確認します。店舗でルールをカスタマイズしている場合は、一般設定に従いません。設定時刻を過ぎてから開始したレジの締め時刻は翌日です。

**レジを追加するには、先に店舗を保存してください。** 新しい店舗は、作成されるまで**レジ台**の表がありません。**作成**をクリックしてから、レジを追加してください。

**先にセッションを締めてください。** 使用終了にしようとしたレジは、開いているか集計中です。POSで現金を集計して締めてから、使用終了にしてください。
