**WP 管理画面：** `WP Admin → POS → Settings → Checkout`。レジ係には表示されません。

レジ設定では、販売時の支払い方法と、その後の注文の扱いを決めます。

ここでできること：

- [レジで支払い方法を利用できるようにする](#enabling-a-gateway)
- [最初に表示する支払い方法を選ぶ](#reordering-gateways)
- [タイル名を変更する、または現金の合計額を丸める](#gateway-pos-settings)
- [会計後の注文ステータスを選ぶ](#order-status)
- [在庫を超える販売を防ぐ](#prevent-overselling)（新規店舗ではオフ）
- [POS の注文で送信するメールを選ぶ](#email-notifications)

カスタムフィールドはここでは設定しません。注文に追加するには[注文の詳細](../../pos/cart/order-actions.mdx#order-meta)の **+ カスタムフィールド**、顧客アカウントに追加するには[顧客フォーム](../../customers/index.mdx#add-new-customer)を使います。

この画面では変更するたびに保存され、**保存中**、続いて **保存済み** と表示されます。保存ボタンはありません。例外はゲートウェイの [POS 設定](#gateway-pos-settings)ダイアログで、ここでは **保存** を押します。

各レジは POS の起動時に設定を読み込むため、変更後は各レジの POS を再読み込みしてください。

## 画面の概要 {#at-a-glance}

画面には上から順に **過剰販売を防止**、**管理者メール**、**顧客メール**、**レジ係メール** のスイッチと、**ゲートウェイ** の表があります。WooCommerce の従来の注文ストレージを使用している店舗では、上部に警告も表示されます。[注文ストレージ](#order-storage)を参照してください。

## 決済ゲートウェイ {#payment-gateways}

**ゲートウェイ** の表には、WooCommerce でゲートウェイと呼ばれる支払い方法が一覧表示されます。サイトにインストールされているすべての支払い方法に加え、POS 独自の **現金** と **カード** が含まれます。各行が 1 つの支払い方法を表し、レジで利用できるようにする **有効** スイッチ、**注文ステータス**、表示位置を決めるドラッグハンドルがあります。その他の列は、以下を展開すると確認できます。

<details>
<summary>ゲートウェイの表の列</summary>

| 列 | 機能 |
|--------|-------------|
| ドラッグハンドル | 行を上下にドラッグすると、レジのタイルの位置が変わります。[最初に表示する支払い方法を選ぶ](#reordering-gateways)を参照してください。 |
| **デフォルト** | [レガシータブ](../../pos/checkout/legacy-tab.mdx)に表示される、店舗独自の決済ページであらかじめ選択されるゲートウェイです。有効なゲートウェイのみ選択できます。**現金** はこのページには表示されず、専用のタイルでのみ受け付けます。支払いタブのタイルにはこの設定は適用されません。[最初に表示する支払い方法を選ぶ](#reordering-gateways)を参照してください。 |
| **ゲートウェイ** | ゲートウェイの名前です。 |
| **ゲートウェイ ID** | `pos_cash` など、WooCommerce 内での識別子です。開発者から尋ねられた場合にのみ必要です。 |
| **有効** | レジで利用できるようにするかどうかを指定します。 |
| **注文ステータス** | この方法で支払った注文に設定されるステータスです。[注文ステータス](#order-status)を参照してください。 |
| **⋮** | **POS 設定** を開けます。現金とカード以外のゲートウェイでは **WooCommerce 設定** も開けます。[タイル名を変更する、または現金の合計額を丸める](#gateway-pos-settings)を参照してください。 |

</details>

:::note 無料版と Pro の違い
[WCPOS Pro](../../getting-started/pro-license.mdx) がない場合、有効にできるのは **現金** と **カード** のみです。他の行では **有効** スイッチ、**注文ステータス**、**⋮** がグレー表示になり、表の上にその旨の案内と **Pro にアップグレード** リンクが表示されます。
:::

### レジで支払い方法を利用できるようにする {#enabling-a-gateway}

**始める前に：** カードリーダーなど、プラグインで提供される支払い方法は、そのプラグインをサイトにインストールして有効化すると表に表示されます。[決済ゲートウェイ](../../payment/gateways/index.mdx)には、POS が対応するゲートウェイとそれぞれの設定ガイドが掲載されています。

1. **ゲートウェイ** の表で支払い方法を見つけます。
2. **有効** をオンにします。
3. POS を再読み込みします。レジは起動するたびに支払い方法を読み込みます。

支払い方法が会計画面のタイルとして表示されます。独自の決済ページで動作するものは、[レガシータブ](../../pos/checkout/legacy-tab.mdx)にゲートウェイとして表示されます。

### 最初に表示する支払い方法を選ぶ {#reordering-gateways}

行のハンドルをドラッグして移動します。レジのタイルはこの順番に並び、新しい販売の会計画面を開くと、利用可能な最初のタイルが選択されています。通常は現金を選択しておきたい場合、現金を一番上にドラッグしてください。どのタイルが選択されるかは順番のみで決まり、**デフォルト** 列では変わりません。

設定はレジの支払いパネルの次の場所に反映されます。

1. **支払い** タブ — 有効にした各ゲートウェイのタイルが、表の順番で並びます。
2. **レガシー** タブ — 独自の決済ページで動作するゲートウェイです。[レガシータブ](../../pos/checkout/legacy-tab.mdx)を参照してください。
3. **支払額** — 残りの未払額です。現金の **丸め** を設定している場合、レジには丸め後の金額が表示されます。[現金の端数処理](../../payment/index.mdx#cash-rounding)を参照してください。
4. **分割** — 注文の支払いを複数回に分けます。
5. **支払い方法のタイル** — 各ゲートウェイの [POS 設定](#gateway-pos-settings)にある **タイトル** が表示されます。最初のタイルが選択されます。
6. **金額の候補** — ちょうどの金額、または紙幣で支払う場合の切り上げた金額です。
7. **テンキー** — 顧客から受け取った金額を入力します。
8. **受け取る** — この支払いを記録します。支払いの合計が注文の合計額に達すると会計が終了し、ゲートウェイの[注文ステータス](#order-status)が注文に設定されます。

この画面でのレジ係の操作は、[支払いパネル](../../pos/checkout/payment-methods.mdx)で説明しています。

### タイル名を変更する、または現金の合計額を丸める {#gateway-pos-settings}

**⋮ > POS 設定** を開くと、その支払い方法のダイアログが表示されます。変更されるのはレジの表示だけで、ウェブサイトには影響しません。

- **タイトル** — タイルに表示される名前です。
- **説明** — ゲートウェイとともに保存されます。レジには表示されず、タイルには **タイトル** だけが表示されます。
- **丸め**（現金のみ）— 使用する硬貨に合わせて、現金の合計額を **0.05**、**0.10**、**0.25**、**0.50**、**1**、**5**、**10** 単位に丸めます。デフォルトは **丸めなし** です。カードやオンラインの支払いでは、正確な金額を使用します。[現金の端数処理](../../payment/index.mdx#cash-rounding)を参照してください。

変更を保存するには **保存**、取り消すには **キャンセル** を押します。

**⋮ > WooCommerce 設定** を開くと、WooCommerce 内のゲートウェイ独自の設定が表示されます。ここでアカウントを接続し、ウェブサイトでの表示を設定します。

### POS とオンラインストアの違い {#pos-vs-online-store}

ここの **有効** スイッチは、WooCommerce 独自の決済設定とは別です。支払い方法は次のように設定できます。

- **POS ではオン、オンラインではオフ** — ウェブサイトでは受け取れない現金などです。
- **オンラインではオン、POS ではオフ** — PayPal 決済など、顧客がパソコンで操作する必要がある支払い方法です。
- **両方でオン。**

:::note
ゲートウェイを表に表示するには、そのプラグインをインストールして有効化する必要があります。`WP Admin > WooCommerce > 設定 > 支払い` でオンにする必要はありません。POS には、WooCommerce が認識するすべてのゲートウェイが表示されます。表示されない場合は、プラグインが有効か確認してください。
:::

## 注文ステータス {#order-status}

各支払い方法には、会計終了時に注文に設定される **注文ステータス** があります。**処理中** と **完了** では支払い済みとなり、**保留中** と **支払い待ち** では未払いのままになります。代金の受け取り方に合わせて選んでください。

- **店頭で代金を受け取る場合：** **処理中** または **完了**。
- 支払いリンクを使わず、**顧客が自分で振り込む場合**：**保留中**。BACS と小切手のデフォルトです。
- BACS などで請求書払いにするなど、**注文の支払いリンクから後払いする場合**：**支払い待ち**。顧客がリンクから支払うまで、注文は未払いのままです。

変更するには：

1. **ゲートウェイ** の表で支払い方法を見つけます。
2. その行の **注文ステータス** 列でステータスを選びます。

すぐに保存され、新しい販売に適用されます。すでに受け付けた注文には適用されません。

会計の終了と支払い済みは同じではありません。レジに記録した支払いが合計額に達すると会計が終了し、このステータスが注文に設定されます。そのため、**保留中** または **支払い待ち** に設定した注文は、レジでの処理が終わっても未払いのままです。

<details>
<summary>支払いリンクを送信する</summary>

WooCommerce では、支払い待ちの注文は支払い可能な状態を維持します。支払い済みにはならず、在庫も減らず、支払い待ちの間は支払いリンクが機能します。POS からリンクは送信されません。注文には顧客のメールアドレスが必要です。WooCommerce の注文画面から請求書をメールで送信するか、別の方法でリンクを共有してください。

</details>

**現金**、**カード**、ほとんどのゲートウェイは、店頭で代金を受け取るため、初期設定が **完了** です。**BACS**（銀行振込）と **小切手** は後から入金されるため、初期設定が **保留中** です。WooCommerce のどの注文ステータスでも選択できます。以前の POS バージョンですべてのゲートウェイに共通のステータスを設定していた場合は、各ゲートウェイの初期設定にそのステータスが使われます。

### レジでのステータスの扱い {#order-status-at-the-till}

レジに記録されるのは、現金、カード、カードリーダー、銀行振込などのタイルで受け付けた支払いです。その合計が注文の合計額に達すると、ゲートウェイで選んだステータスが注文に設定されます。

<details>
<summary>分割払いとレガシータブのゲートウェイ</summary>

- **分割払いの販売** には、支払い額が最大のゲートウェイのステータスが設定されます。同額の場合は、先に支払ったものが使われます。
- **[レガシータブ](../../pos/checkout/legacy-tab.mdx)のゲートウェイ**：注文がそのステータスになると、POS で販売が完了します。

</details>

<details>
<summary>Email Invoice ゲートウェイと支払い待ち</summary>

**Email Invoice Gateway** は請求書を送信し、自ら **支払い待ち** に設定するため、**注文ステータス** はそれ以外にしておいてください。**支払い待ち** に設定すると、レジに **請求書送信済み** 画面が表示されず、注文に **再送信** や **請求書をキャンセル** も表示されません。[請求書のメール送信](../../payment/gateways/email-invoice.mdx#set-up)を参照してください。

</details>

## 過剰販売を防止 {#prevent-overselling}

**過剰販売を防止** は、POS で在庫数を超えて商品を販売するのを防ぎます。新規店舗では **オフ** です。オンにするまでは、レジはカート内の商品をそのまま販売します。オンにするには：

1. `WP Admin > POS > 設定 > 支払い` を開きます。
2. **過剰販売を防止** をオンにし、**保存済み** と表示されるまで待ちます。
3. 各レジの POS を再読み込みします。

オフにする手順も同じです。取り寄せを許可している商品は引き続き販売できます。[取り寄せ設定が優先されます](#prevent-overselling-backorders)を参照してください。

オンの場合、レジでは在庫数を超えて商品を追加できず、カートに在庫不足の明細がある間は会計できません。また、支払いを受け付けるたびに店舗側でも在庫を再確認します。処理中の販売を保存するだけなら拒否されることはありません。

<details>
<summary>3 段階の在庫確認とレジ係に表示される内容</summary>

1. **商品をカートに入れるとき。** レジ係は在庫数を超えて商品を追加したり、数量を増やしたりできません。レジに **パーカーの在庫は 3 個のみです** または **パーカーは在庫切れです** と表示され、カートは変更されません。各メッセージについては、[在庫切れの商品](../../pos/product-panel/display-settings.mdx#show-out-of-stock-products)を参照してください。
2. **販売がカートにある間。** 別のレジで最後の商品が売れた場合など、販売処理中に在庫が減ると、カート明細の上に通知が表示されます。在庫不足の明細ごとに **数量を減らす** または **削除** が表示され、明細には販売可能数が示されます。カートを修正するまで **チェックアウト** はグレー表示になります。支払いパネルでの支払いも同様に拒否されます。[会計がブロックされる場合](../../pos/cart/line-items.mdx#checkout-blocked)を参照してください。
3. **支払いを受け付けるとき、店舗側で確認。** 代金が移動する前と販売の完了時に、店舗側で注文商品の在庫を確認します。レジの数値が古い場合、店舗側で支払いが拒否され、**注文を完了できません：1 件の商品が在庫数を超えています。** と POS に理由が表示されます。[レガシータブ](../../pos/checkout/legacy-tab.mdx)では、店舗の決済ページに理由が表示されます。オフラインのレジから後で送信した販売も、同様に拒否されることがあります。[注文が保存されない — 店舗側で拒否された](../../support/store-health.mdx#order-refused)を参照してください。

保存するだけの販売については店舗側で確認しないため、処理中の販売はそのまま同期できます。

</details>

<details>
<summary>レジに加えて店舗側でも確認する理由</summary>

POS は REST API を使って注文を送信しますが、WooCommerce は REST API で注文を受け取る際に在庫を確認しません。2 台のレジが同時に多くの販売を処理したり、レジの在庫数が古かったりすると、在庫を超えて販売するおそれがあります。店舗側の確認で、レジが把握できなかった不足を検出します。

</details>

### 在庫上限の決まり方 {#prevent-overselling-stock-rules}

商品単位で在庫を管理するか、バリエーションごとに管理するかによって、上限が決まります。

<details>
<summary>商品設定ごとの在庫ルール</summary>

| 商品設定 | スイッチがオンの場合 |
|---|---|
| **在庫を管理する**（数量を管理） | 在庫数に達すると販売を停止します。同じ商品の明細が複数ある場合は、同じ上限に対して合算されます。 |
| **バリエーション独自の在庫を管理する** | 上限はバリエーションごとに適用されます。 |
| **バリエーションが親商品の在庫を使用する** | すべてのバリエーションで親商品の在庫数を共有します。 |
| **在庫を管理しない** | 在庫状況で決まります。**在庫切れ** は販売できず、**在庫あり** と **取り寄せ中** は販売できます。 |

</details>

### 取り寄せ設定が優先されます {#prevent-overselling-backorders}

WooCommerce の商品ごとの **取り寄せを許可しますか？** 設定が優先されます。この設定を使うと、スイッチがオンでも、一部の商品を在庫がゼロになった後も販売できます。

- **許可しない** — 在庫がなくなると販売を停止します。
- **許可する** — 在庫がゼロを下回っても、常に販売できます。
- **許可するが、顧客に通知する** — 常に販売できます。販売数が在庫を超えると、レジに **パーカーは取り寄せになります** と表示されます。

取り寄せ商品が原因で会計がブロックされることはありません。

### 「過剰販売を防止」と「在庫切れの商品を表示」の違い {#prevent-overselling-vs-display}

この 2 つの設定は、役割が異なります。

- **過剰販売を防止**（このページ）は、商品をカートに入れるとき、販売の処理中、各支払いの受け付け前に数量を確認します。店舗のすべてのレジに適用されます。
- **在庫切れの商品を表示** は、各端末の商品パネルにある設定です。オフの場合、在庫がない商品は非表示になり、スキャンしても受け付けられません。オンの場合、一覧に残りますが、グレー表示になり **売り切れ** と表示されます。[在庫切れの商品](../../pos/product-panel/display-settings.mdx#show-out-of-stock-products)を参照してください。

「過剰販売を防止」をオフにしても、商品パネルの表示は変わりません。

:::note
各レジは POS の起動時に、店舗情報とともに「過剰販売を防止」の設定を取得します。支払いごとに行う店舗側の確認は、再読み込みしていないレジにもすぐに適用されます。
:::

## メール通知 {#email-notifications}

3 つのスイッチで、POS の注文から送信する WooCommerce メールを選択します。ウェブサイト独自のメール設定とは別です。

- **管理者メール** — WooCommerce で設定した受信者に **新規注文**、**キャンセルされた注文**、**失敗した注文** を送信します。オンです。
- **顧客メール** — 顧客に **保留中の注文**、**処理中の注文**、**完了した注文**、**払い戻し済みの注文**、**失敗した注文** を送信します。オンです。
- **レジ係メール** — 販売を担当したレジ係に **新規注文** を送信します。オフです。

グループをオンにすると、各メールのチェックボックスが表示されます。最初はすべて選択されています。不要なメールのチェックを外してください。各メールの送信タイミング、受信者、よく使う設定については、[メール通知](./email-notifications.mdx)を参照してください。

## 注文ストレージ {#order-storage}

画面上部に注文ストレージの警告が表示される場合は、[注文ストレージ](../../support/performance/order-storage.mdx)の手順に従い、WooCommerce の高パフォーマンス注文ストレージに切り替えてください。すでに使用している店舗には警告は表示されません。

<details>
<summary>注文ストレージの警告の見分け方</summary>

## 問題が起きた場合 {#goes-wrong}

**支払い方法が表に表示されない。** プラグインがインストールされていないか、有効化されていません。有効化してから、この画面を再読み込みしてください。

**有効スイッチがグレー表示になっている。** 店舗で使用している無料版では、現金とカードのみ利用できます。[WCPOS Pro](../../getting-started/pro-license.mdx)を参照してください。

**支払い方法をオンにしたのに会計画面に表示されない。** POS を再読み込みしてください。その後、[レガシータブ](../../pos/checkout/legacy-tab.mdx)を確認してください。独自の決済ページで動作するゲートウェイは、タイルではなくこのタブに表示されます。

**会計画面を開くと、意図しないタイルが選択される。** レジは表の順番で、利用できる最初のタイルを選びます。希望する支払い方法を一番上にドラッグしてください。**デフォルト** 列では変わりません。

**銀行振込で支払った注文が保留中になる。** BACS と小切手は後から入金されるため、これがデフォルトです。振込が入金されたら、`WP Admin > WooCommerce > Orders` でその注文のステータスを変更してください。ここでゲートウェイの **注文ステータス** を変更するのは、今後その方法で支払うすべての販売で、会計時点ですでに入金済みとなる場合だけです。この設定は新しい販売に適用され、すでに受け付けた注文には適用されません。

**在庫を超えて販売できてしまった。** **過剰販売を防止** がオフになっているか、その商品が取り寄せを許可しています。[取り寄せ設定が優先されます](#prevent-overselling-backorders)を参照してください。
