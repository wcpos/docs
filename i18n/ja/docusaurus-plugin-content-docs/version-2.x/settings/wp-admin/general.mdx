**WP管理画面：** `WP Admin → POS → Settings → General`。すべてのレジに適用されます。

「一般」はWordPressのPOS設定の最初の画面です：**`WP Admin > POS > 設定 > General`**。各レジ係のPOSに適用される、店舗全体の設定を行います。変更はその都度すぐに保存され、**保存済み** と表示されます。保存ボタンはありません。

:::note 設定を変更できるユーザー
**POS設定の管理** 権限を持つユーザー（デフォルトでは管理者またはショップマネージャー）がこの画面を開けます。レジ係は開けません。[POSへのアクセス](./access.mdx)をご覧ください。
:::

## これらの設定がPOSに反映される場所 {#in-the-pos}

<JourneyShot manifest={manifest} device="tablet" step={1} alt="Aim Analog Watchがカートに入ったPOS画面：レジバー、商品検索欄、商品タイル、カートの顧客、明細の数量">

1. **レジバー** — 店舗を表示します。[レジの開閉](#register)がオンの場合は、レジの状態も表示します。
2. **検索** — スキャン時は、[バーコードフィールド](#barcode-field)に設定したフィールドで商品を検索します。
3. **商品** — [POS専用商品](#enable-pos-only-products)がオンの場合、*オンラインのみ*の商品は表示されません。
4. **顧客** — [デフォルトのPOS顧客](#default-pos-customer)を表示します。この例では **ゲスト** です。タップして[別の顧客を選択](../../pos/cart/index.mdx#customer-selector)できます。
5. **数量** — [小数数量](#enable-decimal-quantities)がオンの場合にのみ、0.5などの小数を入力できます。

</JourneyShot>

画面は上から[店舗詳細](#store-details)、[レジ](#register)、[商品](#products)、[顧客](#customers)、[プライバシー](#privacy)、[詳細設定](#force-ssl)の順に並んでいます。無料版プラグインの画面上部は次のようになります。

<JourneyShot manifest={manifest} device="desktop" step={2} offsets={[[90, 0], [115, 0], [105, -6], [110, 0]]} alt="無料版プラグインのWP Admin、POS、設定、一般の画面：一般が選択されたWCPOSメニュー、店舗ごとの設定を有効化するボックスと店舗名、電話番号、メールアドレス、払い戻し・返品ポリシーがある店舗詳細、一行と税務IDを追加ボタンがある店舗の税務ID">

1. **一般** — WCPOSメニューの **設定** 内にある最初の画面です。
2. **店舗詳細** — レシートに印刷する店舗名、電話番号、メールアドレス、返品ポリシーです。[店舗詳細](#store-details)をご覧ください。
3. **店舗の税務ID** — 事業者の税務番号です。[店舗の税務ID](./store-tax-ids.mdx)をご覧ください。
4. **税務IDを追加** — 一覧に番号を追加します。

## 店舗詳細 {#store-details}

POSのレシートや請求書に表示する店舗情報です。**店舗名**、**電話番号**、**メールアドレス** と、POSレシートに印刷する短い説明文である **払い戻し・返品ポリシー** を設定します。

フィールドを空欄にすると、その欄に灰色で表示されているデフォルト値が使用されます。WooCommerce自体のPOS設定（WooCommerce 10.5以降）で同じフィールドが入力済みの場合は、その値がデフォルトになります。未入力の場合は次のとおりです。

| フィールド | 空欄の場合のデフォルト値 |
|---|---|
| **店舗名** | WordPressのサイトタイトル |
| **電話番号** | なし |
| **メールアドレス** | WooCommerceのメールの送信元アドレス。なければWordPress管理者のメールアドレス |
| **払い戻し・返品ポリシー** | なし |

<Anchor id="store-tax-ids" />

これらのフィールドの下に **店舗の税務ID** があります。レシートや請求書に印刷するVAT番号、ABN、GSTINなどの事業者番号です。[店舗の税務ID](./store-tax-ids.mdx)をご覧ください。

:::info WCPOS Proの場合
店舗を作成すると、このブロックは **店舗** 一覧に変わります。店舗ごとに詳細情報、レシートテンプレート、価格、税率、ユーザーを保持します。[店舗の設定](../../stores/setup.mdx)をご覧ください。
:::

## レジ {#register}

**レジの開閉** をオンにすると、レジセッションが有効になります。レジ係は釣銭準備金を用意してレジを開き、現金の入出金を記録し、締め時にドロワーの現金を数えます。オフの場合、POSはセッションなしで販売を行います。

オンの間は、**開始時の釣銭準備金**、**差額が…を超えた場合にマネージャーに確認**、**…にレジ係に締めを通知** の三項目が追加表示されます。各項目については[レジ設定](./registers.mdx#one-register)をご覧ください。無料版プラグインのレジは一台です。**Proでレジと店舗を追加** からアップグレードに進めます。

## 商品 {#products}

<JourneyShot manifest={manifest} device="desktop" step={3} offsets={[[204, 0], [204, 0], [228, 0], [60, 0]]} maxWidth={640} alt="「一般」の商品セクション：POS専用商品を有効化、小数数量を有効化、注文削除時に在庫を戻すがオンで、バーコードフィールドが_skuに設定された状態">

1. **POS専用商品を有効化** — 商品の公開範囲にPOS専用の選択肢を追加します。[下記](#enable-pos-only-products)をご覧ください。
2. **小数数量を有効化** — 明細の数量に小数を使用できます。[下記](#enable-decimal-quantities)をご覧ください。
3. **注文削除時に在庫を戻す** — POSで注文を削除したときに在庫を戻します。[下記](#restore-stock-on-order-delete)をご覧ください。
4. **バーコードフィールド** — スキャン時にバーコードを検索するフィールドです。この例では `_sku` です。[バーコードフィールド](#barcode-field)をご覧ください。

</JourneyShot>

### POS専用商品を有効化 {#enable-pos-only-products}

WP Adminの各商品に、**POSとオンライン**、**POSのみ**、**オンラインのみ** という公開範囲の選択肢を追加します。*POSのみ*の商品はオンラインストアで非表示になり、*オンラインのみ*の商品はPOSで非表示になります。

すべての商品を両方で販売する場合は、オフのままにしてください。オフにしても商品が非表示になることはありません。また、各商品の選択内容は保持され、再びオンにしたときに適用されます。一件または複数の商品の公開範囲を設定するには、[POS専用商品](../../products/pos-only-products.mdx)をご覧ください。

### 小数数量を有効化 {#enable-decimal-quantities}

明細の数量に `0.25`、`1.5`、`2.75` などの小数を使用できます。コーヒー豆0.5 kg、作業時間1.5時間など、重量、長さ、時間で販売する商品に使用します。

オンにすると、カートの数量入力用キーパッドに小数点が表示されます。オフの場合は小数点が表示されず、小数の数量を含む注文は受け付けられません。

:::note 量り売り
WCPOSは、はかりへの接続や、はかりからの重量の読み取りには対応していません。商品を量ってから、その重量を明細の数量として入力してください。キログラム単価が設定された商品の場合、350 gの数量は `0.35` です。

一部のはかりが印刷するバーコードラベルに埋め込まれた重量や価格も、WCPOSでは読み取れません。
:::

### 注文削除時に在庫を戻す {#restore-stock-on-order-delete}

デフォルトでオンです。POSから注文をゴミ箱に移動または削除すると、その注文の商品の在庫数が元に戻ります。誤った販売を削除すれば、商品を在庫に戻せます。

:::warning POSから削除した注文のみが対象
WP Adminで削除した注文の在庫は戻りません。また、注文をゴミ箱から復元しても在庫は再び減りません。
:::

別の方法で在庫を管理しており、注文の削除で在庫を変更したくない場合はオフにしてください。

### バーコードフィールド {#barcode-field}

商品のバーコード番号の保存先を選択します。レジ係がバーコードをスキャンするか、**商品を検索** に入力すると、POSはその保存先に一致するバーコードがある商品を見つけます。

**バーコードフィールド** の一覧から保存先を選択してください。多くの店舗では、次のいずれかを使用します。

<Anchor id="default-option" />

- **WooCommerceのバーコードフィールド** がデフォルトです。商品の「在庫」タブにある **GTIN、UPC、EAN または ISBN** 欄で、新しい店舗ではこちらを使用します。一覧では `_global_unique_id` と表示されます。
- バーコードがSKUの場合は、**商品のSKU** を使用します。一覧では `_sku` と表示されます。

バーコードプラグインでコードを保存している場合は、そのプラグインのフィールドを選択してください。一覧にない場合は、下の **プラグインとカスタムバーコードフィールド** を開き、入力する名前を確認してください。

<Anchor id="other-common-options" />
<Anchor id="third-party-plugin-meta-keys" />

<details>
<summary>プラグインとカスタムバーコードフィールド</summary>

#### 主なプラグイン → メタキー {#common-plugins-meta-key}

バーコードプラグインでコードを保存している場合は、そのメタキーを使用してください。

| プラグインまたはフィールド | メタキー |
|---|---|
| WooCommerceのGTIN、UPC、EANまたはISBN *（デフォルト）* | `_global_unique_id` |
| 商品のSKU | `_sku` |
| EANプラグイン（欧州統一商品番号） | `_ean`、`_ean13`、`_ean8` |
| EAN for WooCommerce（WPFactoryのEAN Barcode Generator） | 詳細設定の **メタキー** を変更していなければ `_alg_ean` |
| UPCプラグイン（統一商品コード） | `_upc`、`_upc_code` |
| GTINプラグイン（国際取引商品番号） | `_gtin`、`_gtin13`、`_gtin14` |
| 汎用バーコードフィールド | `_barcode`、`_product_barcode` |
| WooCommerce Product Barcodes | `_barcode_text` |
| ATUM Inventory | `_atum_barcode` |

<Anchor id="custom-meta-keys" />

**バーコードフィールド** の一覧には、商品とバリエーションがすでに使用しているすべてのメタキーに加え、`_sku` と `_global_unique_id` が表示されます。一覧にないフィールドを使う場合は、プラグインの画面上の名称ではなく、保存に使用される正確な名前（メタキー）が必要です。先頭にアンダースコアがある場合はそれも含めて正確に入力し、**「…」を作成** を選択してください。

#### プラグインのメタキーを調べる {#finding-your-plugins-meta-key}

1. WP Adminで商品を編集し、プラグインを使ってバーコードを設定します。
2. プラグインのドキュメントでメタキー名を調べます。
3. または、データベースの `wp_postmeta` テーブルで、その商品に作成されたキーを確認します。

</details>

フィールドを変更すると、POSは次回の同期時にバーコード検索用のデータを再構築し、新しいフィールドでスキャンを照合します。手動で何かを消去する必要はありません。

## 顧客 {#customers}

### 顧客のメールアドレスからユーザー名を自動生成 {#automatically-generate-username-from-customer-email}

デフォルトでオンです。レジ係がPOSで顧客を追加すると、WooCommerceは顧客のメールアドレスからユーザー名を生成します。オフの場合は、レジ係が顧客フォームでユーザー名を入力します。このPOS設定はPOSで追加した顧客にのみ適用されます。オンラインでの購入手続きには、WooCommerce側の設定が引き続き適用されます。

### デフォルトのPOS顧客 {#default-pos-customer}

新しいカートの初期顧客と、自動入力される顧客情報を設定します。**ゲスト** は、注文がどのアカウントにも属さないことを意味します。ドロップダウンで検索すると、店頭販売用に作成した「来店客」アカウントなど、任意のWordPressユーザーを代わりに選択できます。ドロップダウンがグレーアウトしている場合は、下の[レジ係のアカウントを使用](#use-cashier-account)をオフにしてください。

レジ係はカートでいつでも顧客を変更できます。[顧客を選択する](../../pos/cart/index.mdx#customer-selector)をご覧ください。

各POSは店舗を初めて読み込むときに、**デフォルトのPOS顧客** と **レジ係のアカウントを使用** をコピーします。各端末の[設定](../store/general.mdx#default-customer)で、どちらも変更できます。店舗をすでに読み込んだ端末は、コピーした設定を保持します。ここで変更した設定を反映するには、その端末で[サーバー設定を復元](../store/general.mdx#restore-server-settings)を使用してください。

### レジ係のアカウントを使用 {#use-cashier-account}

チェックを入れると、新しいカートの顧客には、サインイン中のレジ係が設定されます。チェックが入っている間は、**デフォルトのPOS顧客** がグレーアウトします。

### 顧客によるレシートのダウンロードを許可 {#storefront-receipts}

デフォルトでオフです。オンにすると、オンラインストアの **マイアカウント > 注文** に **レシート** ボタンが追加されます。顧客は、WCPOSのレシートテンプレートで作成された自分のレシートをPDFでダウンロードできます。このボタンは、処理中、完了、払い戻し済みの注文に表示されます。

オンにすると **顧客用レシートテンプレート** が表示されます。初期設定は **有効なレシートテンプレートを使用** で、顧客はPOSと同じレシートを受け取ります。用紙全体を使った請求書など、別のものを提供するには他のテンプレートを選択してください。[オンラインストアのレシート](../../receipts/storefront.mdx)をご覧ください。

### 税務ID {#customer-tax-ids}

WCPOSは顧客の税務番号をアカウントに保存し、会計時に注文にコピーします。このセクションで、検出された税務プラグインを確認できます。**自動検出** にはプラグイン名が表示され、操作は不要です。**プラグインが検出されませんでした** は、WCPOSの組み込みフィールドを使用することを意味します。プラグインが独自のフィールド名を使っている場合にのみ、**詳細設定：別のフィールド名を使用** で設定してください。[顧客の税務ID](./customer-tax-ids.mdx)をご覧ください。

## プライバシー {#privacy}

**匿名の使用状況データとエラーレポートを許可** を有効にすると、WCPOSは不具合を見つけるために、利用環境や発生した問題の情報を収集します。選択するまでは、このセクションに **許可** と **許可しない** が表示されます。選択はいつでも変更できます。

**収集される情報を確認** を選択すると、画面に全項目の一覧が表示されます。

<details>
<summary>収集される情報</summary>

- **収集する情報：** 利用環境（PHPとWooCommerceのバージョン、国、通貨）、店舗の規模（商品、注文、POSユーザーのおおよその数）、使用する画面や機能、エラーと関連するバージョン。
- **収集しない情報：** 顧客情報、注文内容、価格、サイトのアドレス、店舗運営者や顧客を特定できるあらゆる情報。

</details>

## 詳細設定：SSLを強制 {#force-ssl}

デフォルトでオンです。POSの接続を安全に保つため、オンのままにしてください。

<details>
<summary>SSLの強制の動作</summary>

POSはHTTPSで開きます。POSページに通常の `http://` でアクセスすると `https://` に転送され、WCPOSが生成するPOSリンクにも `https://` が使われます。サイトにSSL証明書がない場合にのみオフにしてください。

</details>

## 問題が起きた場合 {#if-something-goes-wrong}

画面上部に **「店舗はCloudflareを経由しています」** と表示される
: サイトがCloudflareを経由しており、そのセキュリティチェックによってPOSから店舗にアクセスできなくなることがあります。POSにHOST121やセキュリティチェックが表示される場合は、**ルールの追加方法** に従ってください。[Cloudflare](../../support/troubleshooting/cloudflare.mdx)をご覧ください。

**バーコードフィールドを変更した後、スキャンしても商品が見つからない**
: POSは次回の同期時にバーコード検索用のデータを再構築します。すぐにやり直すには、POSの商品数の横にある同期の矢印を長押しし、**消去して更新** を選択してください。[更新する、または最初からやり直す](../../products/sync.mdx#refresh)をご覧ください。

**0.5などの数量を含む注文を保存できない**
: [小数数量を有効化](#enable-decimal-quantities)をオンにしてください。
