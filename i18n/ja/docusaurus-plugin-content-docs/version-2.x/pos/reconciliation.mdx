一日の終わりにドロワーの現金を数え、レジを締め、カード端末の金額と照合します。集計結果は番号付きの締め記録として保存され、印刷や後からの参照ができます。このページでは、ドロワーの確認からサインアウトまで、レジ締めの一連の手順を説明します。

:::note このページの操作にはレジ機能の有効化が必要です
ここで説明する操作には、**レジの開閉**を有効にする必要があります。無効の場合、集計対象のドロワーはありません。設定については[レジ](../settings/wp-admin/registers.mdx#one-register)、一日の開始手順については[レジを開ける](./register/index.mdx)を参照してください。
:::

## ドロワーを確認する {#check}

**レポート**を開きます。上部の帯には、このレジで進行中のセッションと、ドロワー内の現金の計算内訳が表示されます。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[14, -40], [55, -40], [61, -42], [10, -42]]} alt="上部にレジの帯があるレポート画面：00:23 から開いているレジ、前回の締め記録、ドロワー内の予定額を算出する各金額、X レポートを印刷、締め履歴への矢印">

1. **営業中** — レジの状態です。現在は**営業中**で、締めた後は**締め済み**になります。
2. **開始日時** — レジを開けた日時と担当者です。
3. **X レポートを印刷** — レジを締めずに、セッションの現時点までの内容を印刷します。
4. **締め履歴** (WCPOS Pro) — 過去の日付や他のレジを含むすべての締め記録です。最初に差額の合計が表示され、各行に予定額、実際の集計額、差額が表示されます。[精算](../reports/reconciliation.mdx)を参照してください。

</JourneyShot>

その下にはドロワー内の金額の計算内訳が表示され、その上には前回の締め記録が表示されます。

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[0, 38], [0, 38], [0, 38], [0, 38], [0, 38]]} alt="帯の拡大表示：開始時の釣銭準備金に現金売上と入金を加え、出金と現金での払い戻しを差し引いた結果が、青色のドロワー内の予定額になります">

1. **開始時の釣銭準備金** — レジを開けた時点の現金です。
2. **現金売上** — 件数と金額です。
3. **出金** — ドロワーから取り出した現金とその回数です。
4. **現金での払い戻し** — 現金で返金した金額です。
5. **ドロワー内の予定額** — 青色の金額で、レジが算出したドロワーにあるはずの現金です。実際に数えた金額がこれと一致することを確認します。

</JourneyShot>

**ドロワー内の予定額**は、開始時の釣銭準備金に現金売上と入金を加え、現金での払い戻しと出金を差し引いた金額です。**現金売上**、**現金での払い戻し**、**入金**、**出金**は、セッション中にそれぞれ発生すると帯に追加されます（[現金を出し入れする](./register/index.mdx#cash-movements)を参照）。レジを開けたデバイス以外では、帯に**ドロワー内の予定額**だけが表示されます。予定額を見ずに集計するレジ係には、ここに金額は表示されません。

レジ締め後は、同じ帯に**締め済み**と締めた日時・担当者、番号付きの**前回の締め記録**、**予定額**、**実際の集計額**、**ドロワーの結果**が表示されます。ボタンは**締め記録を印刷**に変わり、締め記録を再印刷できます。

## ドロワーの現金を数える {#count}

まず最後の販売を完了します。アバターをタップし、**ドロワー内の現金**をタップします。レジパネルが開き、上部にドロワー内の現金が表示されます。

<JourneyShot manifest={manifest} device="tablet" step={7} offsets={[[-29, 0], [-29, 0], [77, -38]]} alt="レジパネル：大きく表示されたドロワー内の現金とその下のセッション売上、入金、出金、空開け、ドロワー内の予定額、レジを締めるボタン">

1. **ドロワー内の現金** — 現在ドロワーにあるはずの現金です。その下にセッションの売上が表示されます。
2. **ドロワー内の予定額** — タップすると計算内訳が表示されます。
3. **レジを締める** — 集計を開始します。

</JourneyShot>

**入金**、**出金**、**空開け**は、営業時間中の現金の出し入れに使います。[レジを開ける](./register/index.mdx#cash-movements)を参照してください。

**レジを締める**を押します。集計中はレジで販売できなくなります。お客様が来た場合は、集計画面上部の戻る矢印（**‹**）でカートに戻れます。

釣銭準備金を含めて現金を数え、金額の下のテンキーで合計を入力します。メモやボタンに移るとテンキーは折りたたまれます。金額を変更するには、その金額をタップします。

カード決済があった場合は、この時点でカード端末のバッチ合計を確認します。**締めて印刷**を押す前に、**その他の支払い方法**を開き、**カード集計額**に入力してください。締め記録には、POS が記録した金額と並んでカード集計額が表示されます。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[-29, 0], [-55, 0], [-35, 0], [-29, -23], [-30, 0], [-30, 0], [-29, 0], [-29, 0], [61, -38]]} alt="ドロワーの集計：大きな枠内の現金集計額、差額と一緒に表示された予定額、メモ、紙幣・硬貨別に集計、その他の支払い方法、締めて印刷ボタン">

1. **‹ 販売に戻る** — 集計を離れて販売を再開します。レジを締める前に、もう一度数えてください。
2. **現金集計額（釣銭準備金を含む）** — ドロワー内の現金です。
3. **金額をタップして編集** — 金額をタップするとテンキーが再表示されます。
4. **予定額** — レジが算出した金額です。金額を入力すると表示されます。予定額を見ずに集計するレジ係（予定額を閲覧できない権限グループ）には、この金額も差額も表示されません。[アクセス](../settings/wp-admin/access.mdx)を参照してください。
5. **一致** — 差額の状態です。チェックマーク付きの**一致**、または**不足**や**超過**の金額が表示されます。
6. **メモ** — **差額の理由を説明**します。釣銭の間違いや伝票のない出金などを記入してください。メモは締め記録に保存されます。
7. **紙幣・硬貨別に集計** — 数えた紙幣や硬貨を一枚につき一回タップします。長押しすると十枚分を追加できます。金額はその合計になり、**クリア**で最初からやり直せます。
8. **その他の支払い方法** — このセッションで使われた他の支払い方法ごとに、**カード集計額**などの入力欄が表示されます。端末や伝票の合計を入力してください。現金売上だけの場合は空欄です。
9. **締めて印刷** — 締め記録を保存します。差額が自分の承認限度額を超えると**承認して締める**に変わり、マネージャーがサインインします。

</JourneyShot>

## 締め記録を保存する {#closure}

**締めて印刷**を押します。集計結果がそのレジの次の番号の締め記録として保存され、結果を先頭に表示した締め記録が開きます。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[-141, 0], [-50, 0], [-42, 0], [-41, 0], [-29, -141], [75, -38], [32, -38]]} alt="保存された締め記録：締め番号、大きく表示された差額、その横の実際の集計額と予定額、ドロワーの内訳、締め記録を印刷、完了">

1. **締め記録 N を保存しました** — 締め番号、店舗とレジ、セッションの日時、締めた担当者です。
2. **差額** — 結果が大きく表示されます。**一致**、または**不足**や**超過**の金額です。
3. **実際の集計額** — 入力した現金の金額です。
4. **予定額** — レジが算出していた金額です。
5. **ドロワー** — 釣銭準備金から現金集計額までのすべての内訳です。**実際の集計額**の前に**ドロワー内の予定額**が表示されます。
6. **締め記録を印刷** — 印刷または再印刷します。印刷すると、画面に**印刷日時**と日時が表示されます。予定額を見ずに集計するレジ係には、ここに印刷ボタンは表示されません。
7. **完了** — 締め済みのレジに戻り、翌日の釣銭準備金を受け入れる状態になります。

</JourneyShot>

集計時のメモは、金額の下に**メモ**として表示されます。ドロワーの内訳の下には**その他の支払い方法**と**セッション**があり、レジ係、売上、販売点数、割引、平均売上、ドロワーを開けた回数が表示されます。最後の**締め帳票**には、締め記録の印刷状況（**印刷済み**または**未印刷**）が表示されます。開くと、この締め記録に使うテンプレートとプリンター、帳票のプレビューが表示されます。

<details>
<summary>締め記録の印刷先プリンター</summary>

デバイスごとに**設定 → 印刷 → 締め記録テンプレート**で設定します。X レポートと引き継ぎ票もこのテンプレートで印刷されます。レポート画面から印刷する集計には**レポートテンプレート**を使います。[印刷先の振り分け](../hardware/printers/index.mdx#print-routing)を参照してください。

</details>

## カードを照合し、現金を回収する {#card}

1. 締め記録の**その他の支払い方法**で**カードの行を確認**します。これは POS が記録したカード決済額で、端末のバッチ合計と一致するはずです。カード集計額を入力した場合は、その行の下に差額とともに表示されます。端末が自動でバッチを確定しない場合は、ここで確定してください。
2. ドロワーに**翌日の釣銭準備金を戻します**。
3. 印刷した締め記録と一緒に**残りの現金を袋に入れ**、金庫に保管します。

## サインアウトする {#sign-out}

アバターをタップし、**サインアウト**をタップします。レジが締め済みなら、すぐにサインアウトします。

<details>
<summary>レジがまだ営業中の場合</summary>

POS に確認が表示されます。

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[-24, -66], [51, 42], [59, 42], [-32, 0]]} alt="サインアウトの確認：営業中のレジと予定現金額、レジを締める、そのままサインアウト、キャンセル">

1. **まだ営業中です** — レジ名と予定現金額です。予定額を見ずに集計するレジ係には金額は表示されません。
2. **レジを締める** — [集計](#count)に直接進みます。
3. **そのままサインアウト** — 次のレジ係のためにレジを開けたままにします。締め記録には、実際に締めた担当者が記録されます。
4. **キャンセル** — レジ係シートに戻ります。

</JourneyShot>

</details>

## 問題が発生した場合 {#goes-wrong}

**集計額が合いません。** まず硬貨も含めて数え直します。その後、実際に数えた金額を入力し、**メモ**に理由を記入します。差額が**集計額の差が次の金額を超えたらマネージャーに確認**（[レジ](../settings/wp-admin/registers.mdx#one-register)）の設定額を超える場合、マネージャーが WordPress のユーザー名とパスワードで承認します。承認には店舗への接続が必要です。オフラインの場合、マネージャーのサインイン画面に**承認には接続が必要です**と表示され、**承認**ボタンは無効のままになります。[精算](../reports/reconciliation.mdx#variance-handling)の手順では、差額が生じやすい箇所を紹介しています。

**「N 件の売上がまだサーバーにありません — 締め記録に記録されます」。** このデバイスの売上がまだ店舗に届いていません。それでもレジを締めることはできます。売上が届くと、締め後に届く他の売上と同様に、その締め記録に関連する**締め後の修正**として追加されます。

**「金額は次回の同期で反映されます。」** レジは店舗からの金額データを待っています。届くまで**レジを締める**は無効です。接続を確認し、ページを開いたままにしてください。

**「未完了のカートが N 件あります · 担当のレジ係が引き続き対応できます」。** 未完了のカートがあってもレジは締められます。カートは作成した担当者のために残ります。

**「現金 $N が店舗で拒否されました」。** このセッションの入金または出金が店舗で拒否されたため、その現金の記録が店舗にありません。**理解したうえで締める**にチェックを入れると、**締めて印刷**が再び有効になります。締め記録には、その現金がサーバーに未記録であることが表示されます。その後、別の入出金が店舗で拒否されると、集計画面で再び確認されます。

**「N 件の入出金が店舗で拒否されました」。** レジパネルに該当の入出金と**再試行**が表示されます。押すと再送信します。その入出金によって送信が保留されていた締め記録もキューに戻り、入出金がサーバーに記録されると送信されます。

**「店舗がこのレジ締めを拒否しました。集計額は保持されています。」** 集計額は残っており、ボタンは**再試行**になっています。集計額を確認して**再試行**を押してください。**詳細を見る**で拒否の理由を確認できます。

**レジ締め後に売上が届きました。** その締め記録に関連する締め後の修正として記録されます。締め記録自体が書き換えられることはありません。[レジ締め後に売上が処理された](../reports/reconciliation.mdx#multi-cashier-or-multi-store-scenarios)を参照してください。

**レポートに「このデバイスにレジがありません」と表示されます。** このデバイスでレジが選択されていないか、店舗がレジ機能を使用していません。[店舗とレジを選ぶ](../stores/registers-and-devices.mdx#choosing-a-store-and-a-register)を参照してください。

<details>
<summary>店舗の健全性チェックでレジに問題が表示される</summary>

**健全性**を開き、**データベース**を開きます。**レジ**の項目で各レジの番号を確認できます。

- **締め番号が順番どおり** — このチェックに失敗すると、欠番の締め番号、別の番号で印刷された締め記録、合計がサーバーと一致しない締め記録が表示されます。締め番号が振り直されることはなく、このチェックは最近のものだけでなく、すべての締め記録を対象にします。
- **N 件の欠番** — レシート番号が取得されましたが、販売が完了しませんでした。データは失われていません。
- **レジ N でカウンターが再開されました** — 複数の売上に同じレシート番号が付いています。データは失われていません。
- **N 件の売上に進んだ時計の時刻が記録されています** — 表示されたレジの日付と時刻を設定してください。

[店舗の健全性](../support/store-health.mdx#database)を参照してください。

</details>

:::info WCPOS Pro をお使いの場合
Pro では、店舗ごとのレジを増やせるほか、レポートで当日以前の履歴と**締め履歴**を閲覧できます。店舗設定で、店舗ごとに締め記録とレポートのテンプレートを選ぶこともできます。[店舗の設定](../stores/setup.mdx)を参照してください。
:::
