刻印の文面など、今回の販売にだけ使うメッセージを追加する場合は、[明細行にフィールドを追加する](#custom-field)に進んでください。商品に保存済みのフィールドをコピーする場合は、[キーを選ぶ](#choose-keys)に従ってください。

商品には名前や価格のほかに、刻印の文面、仕入先コード、別のプラグインが追加した項目などの追加フィールドが含まれることがあります。WooCommerce ではこれをメタデータと呼び、設定画面の **メタデータキー** にコピー対象を指定します。各フィールドには、名前にあたる **キー**（`engraving` など）と **値**（`Happy Birthday` など）があります。

商品をカートに追加しても、**メタデータキー** にキーを指定していない追加フィールドは引き継がれません。指定したフィールドはカートの明細行にコピーされ、注文のその明細行とともに保存されます。

注文全体のカスタムフィールドは[注文詳細](../cart/order-actions.mdx#order-meta)の **+ カスタムフィールド** で、顧客アカウントのカスタムフィールドは[顧客フォーム](../../customers/index.mdx#add-new-customer)の **カスタムフィールド** で追加します。

## キーをコピーする場面 {#when-to-use}

- **プラグインの商品データ**：瓶の預り金を扱うプラグインが各商品に `_bottle_deposit` を保存している場合、このキーを追加すると、預り金が注文の明細行とともに保存されます。`_` で始まるため、明細行には表示されません。[_ で始まるフィールド](#hidden-fields)を参照してください。
- **独自の商品フィールド**：刻印の文面や仕入先コードを注文に引き継ぎます。
- **ほかのプラグイン用のデータ**：注文明細を読み取るプラグインが、その明細から値を取得できます。
- **バッチ、ロット、追跡用のコード**：販売した商品とともに保存します。

## キーを選ぶ {#choose-keys}

商品に保存されているキーを正確に指定してください。不明な場合は、フィールドを設定した担当者に確認してください。ここでキーを選ぶ操作はコピー対象の指定だけで、商品にフィールドを追加するものではありません。キーはこの端末に店舗ごとに保存されるため、対象商品を販売するすべてのレジで設定してください。同じキーがグリッド表示とテーブル表示の両方に適用されます。

:::note キーは完全に一致する必要があります
`Engraving` と `engraving` は別のキーです。商品に保存されているとおりに入力してください。
:::

1. 商品パネルの検索バーの末尾にある [**設定**](index.mdx#find) を押し、**メタデータキー** まで下にスクロールします。
2. **メタデータキー** を開き、一覧からキーを選びます。見つからない場合は入力し、**「…」をカスタムキーとして追加** を選びます。
3. 同じ方法で必要なキーを追加し、**閉じる** を押します。
4. そのフィールドを持つ商品をカートに追加し、新しい明細行にキーと値があるか確認します。選択肢のある商品や `_` で始まるキーについては、[コピーされる内容](#what-gets-copied)を参照してください。

<JourneyShot manifest={manifest} device="tablet" step={6} offsets={[[38, 0]]} alt="検索バーに Aim Analog Watch と入力された商品パネルと、その横の空のカート">

1. **設定** — 検索バーの末尾のボタンです。パネルの設定が開き、下部近くに **メタデータキー** があります。

</JourneyShot>

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[40, 0], [100, 0], [260, 0], [-30, 0]]} alt="商品設定のメタデータキー。engraving キーがチップとして選択され、一覧が開いています。検索欄には gift_message と入力され、その下にカスタムキーとして追加する行があります">

1. **選択済みのキー** — このフィールドを持つすべての商品からコピーします。× を押すとコピー対象から外れます。
2. **メタデータキー** — この端末の商品から見つかったキーの一覧を開きます。
3. **検索** — キーを入力します。一覧にない場合は、その下の **「…」をカスタムキーとして追加** を選びます。この端末がまだダウンロードしていない商品にしかないキーには、この方法を使います。
4. **閉じる** — キーを保持したまま設定画面を閉じます。

</JourneyShot>

設定画面の下部にある **デフォルト設定に戻す** を押すと、ほかのパネル設定とともにキーも消去されます。

### コピーされる内容 {#what-gets-copied}

- **選んだキーだけです。** 商品のほかのフィールドはコピーされません。
- **今後追加する明細行だけです。** カートにすでにある明細行の内容は変わりません。新しいキーを取り込むには、その明細行を削除して商品を追加し直してください。
- **バリエーション自体のフィールドです。** 選択肢のある商品では、親商品ではなく、選んだ選択肢からフィールドがコピーされます。
- **表示される場所。** コピーしたフィールドは、カートの明細行の商品名の下に `key: value` の形式で表示され、注文のその明細行とともに保存されます。`_` で始まるキーもコピーされますが、表示はされません。[_ で始まるフィールド](#hidden-fields)を参照してください。

商品を追加する前に商品一覧でこれらのフィールドを見るには、テーブル表示に切り替えて **設定** を開き、**商品名** の下にある **メタデータ** をオンにします。

## 明細行にフィールドを追加する {#custom-field}

レジ係は、この時計に刻印する文面などのフィールドを、1 つの明細行に手動で追加できます。

1. 明細行の合計をタップするか、明細行をスワイプしてから、**編集** をタップします。
2. **カスタムフィールド** を押します。最初の入力欄にキー、次の入力欄に値を入力します。明細行のフィールドは **カスタムフィールド** の下に一覧表示されます。
3. 変更は入力するたびに保存されます。終わったら **閉じる** を押し、明細行の合計をもう一度タップして **編集** と **削除** を非表示にします。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[110, 0], [110, 0], [12, 34], [40, 34], [60, 0]]} alt="Aim Analog Watch の明細行の編集画面。カスタムフィールドの下に engraving フィールドがあり、値が Happy Birthday に設定されています。その下に通常価格とカスタムフィールドのボタンがあります">

1. **カスタムフィールド** — 明細行のフィールドです。それぞれにキーと値があります。**メタデータキー** でコピーしたフィールドもここに表示されます。
2. **フィールド** — 最初の入力欄がキー、次の入力欄が値です。どちらもその場で変更でき、変更するたびに保存されます。
3. **削除** — 明細行からフィールドを削除します。
4. **カスタムフィールド** — 空のフィールドをもう 1 つ追加します。隣の **通常価格** は、明細行に別の詳細項目を追加します。[明細行](../cart/line-items.mdx)を参照してください。
5. **JSON** — `_` で始まるものを含め、明細行のすべてのフィールドを表示します。[_ で始まるフィールド](#hidden-fields)を参照してください。

</JourneyShot>

カートでは、商品名の下に `key: value` の形式でフィールドが表示され、注文のこの明細行とともに保存されます。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[130, 8]]} alt="Aim Analog Watch の明細行が 1 つあるカート。商品名の下に engraving: Happy Birthday と表示されています">

1. **フィールド** — 商品名の下にある `engraving: Happy Birthday` です。キー、コロン、値の順に表示されます。

</JourneyShot>

## _ で始まるフィールド {#hidden-fields}

キーが `_` で始まるフィールドは注文とともに保存されますが、カートの明細行、その編集画面の **フォーム** タブ、レシートには表示されません。

<details>
<summary>非公開フィールドの確認、または拒否されたキーの修正</summary>

これらの非公開フィールドは、WCPOS または別のプラグインが管理しています。たとえば、WCPOS は `_woocommerce_pos_data` に明細行の価格と課税状況を保存します。

`_woocommerce_pos_data` など、明細行にすでにある非公開キーは、新しいフィールドには使えません。フィールドのキーに貼り付けると POS に拒否され、キーは空のままで、画面上部に **このキーは WCPOS が管理しています。別のキーを選んでください。** と表示されます。

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[110, 0], [12, 34]]} alt="明細行の編集画面。上部に赤字で「次のエラーを修正してください」「このキーは WCPOS が管理しています。別のキーを選んでください。」と表示され、新しいカスタムフィールドのキーは空のままです">

1. **拒否されたフィールド** — キーは空のままです。`_` で始まらない独自のキーを指定すれば、フィールドを明細行で確認できます。
2. **削除** — 入力途中のフィールドを削除します。

</JourneyShot>

非公開フィールドも含めて明細行のすべてのフィールドを確認するには、明細行の画面上部にある **JSON** タブを開きます。

<JourneyShot manifest={manifest} device="tablet" step={5} alt="明細行の JSON タブ。meta_data が展開され、非公開の _woocommerce_pos_uuid、Happy Birthday が設定された engraving、非公開の _woocommerce_pos_data の 3 つのフィールドが表示されています" />

注文詳細などのほかの画面では、非公開フィールドは件数付きの **非表示フィールド** という 1 行に折りたたまれています。**表示** を押すと確認・変更でき、**非表示** を押すと再び折りたたまれます。

</details>

## 問題が起きたとき {#goes-wrong}

- **明細行にフィールドがない** — **メタデータキー** のつづりと大文字・小文字を確認し、この商品または選択肢にフィールドがあることを確認してください。キーを選ぶ前に追加した明細行には反映されないため、明細行を削除して商品を追加し直してください。別のレジでも、そのレジでキーを設定する必要があります。
- **使いたいキーが候補に出ない** — 一覧に表示されるのは、この端末の商品にあるキーだけです。キーを入力し、**「…」をカスタムキーとして追加** を選んでください。
- **このキーは WCPOS が管理しています。別のキーを選んでください。** — そのキーは、この明細行の非公開フィールドとしてすでに使われています。別のキーを指定してください。
- **注文にはフィールドがあるのに明細行の下に表示されない** — キーが `_` で始まっています。明細行の合計をタップし、**編集** をタップして **JSON** タブを開くと確認できます。
