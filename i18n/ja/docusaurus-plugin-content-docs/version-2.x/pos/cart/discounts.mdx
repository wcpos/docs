販売時の値引きには二つの方法があります。商品の価格をタップすると、その商品だけを値引きできます。注文全体を値引きするには、追加メニューの **割引を追加** を選び、金額、割合、またはクーポンを指定します。

## 個別商品を値引きする {#quick-discounts}

明細行の価格をタップします。その下にテンキーが開き、上部にクイック割引キーが並びます。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[-120, 0], [-88, 0], [-88, -24], [65, 0], [-24, 0]]} alt="$45.00の明細行で価格入力用のテンキーを開き、−10%を押した状態。新しい価格$40.50と、その上に$45.00 −10%が表示され、三つのクイック割引キー、数字キー、削除キー、完了キーが並んでいます">

1. **新しい価格** — 変更後の商品価格と、変更前の価格からの計算内容です。
2. **クイック割引キー** — 各キーの割合で明細行の価格を値引きします。間違ったキーを押した場合は、**完了** を押す前に別のキーを押すと、最初の選択を置き換えられます。点灯しているキーが現在の選択です。キーは自由に設定できます。[クイック割引キーを設定する](#quick-discount-keys)をご覧ください。
3. **数字キー** — キーによる割引の代わりに、新しい価格を入力します。
4. **削除** — 最後の桁を削除します。
5. **完了** — 新しい価格を確定します。テンキーの外側をタップしても確定できます。

</JourneyShot>

**完了** を押すと、明細行の合計が数量 × 新しい価格に変わります。

クイック割引キーは、テンキーを開いた時点の明細行の価格を基準に計算します。さらに10%引きにするには、**完了** を押してからテンキーを開き直し、**−10%** を押します。

<details>
<summary>例：$45.00の商品で二つのキーを使う</summary>

**−10%** を押すと$40.50と表示されます。代わりに **−5%** を押すと$42.75になります。もう一度 **−10%** を押して **完了** を押すと、明細行の価格が$40.50に確定します。テンキーを開き直して **−10%** を押すと、$40.50が$36.45になります。

</details>

### 新しい価格を入力する {#line-item-discounts}

他店の価格に合わせる場合や従業員価格など、その場限りの価格を設定するには、お客様が支払う価格を入力して **完了** を押します。キーボードでは、価格を入力して **Enter** を押します。

価格は明細行ごとに設定します。異なる三つの商品を10%引きにするには、それぞれの明細行で設定するか、[割引を追加](#order-level-discounts)で注文全体を値引きします。明細行で変更できるその他の項目については、[明細項目](line-items.mdx#price)をご覧ください。

## 注文全体を値引きする {#order-level-discounts}

カート上部の **+** を押し、**割引を追加** を選びます。**クイック割引** タブが開きます。値を入力し、**$** または **%** を選んでから、**割引を追加** を押します。

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[0, 0], [0, 0], [0, 0], [12, 46], [50, -52]]} alt="「割引を追加」ダイアログの「クイック割引」タブ。「クイック割引」と「クーポン」のタブ、入力値10、パーセントが選択されたドルとパーセントの切り替え、「割引を追加」ボタンが表示されています。隣のカートには$45.00のAim Analog Watchが入っています">

1. **クイック割引** — この注文を定額または割合で値引きします。
2. **クーポン** — 代わりに店舗のクーポンを使います。[クーポンを適用する](#coupon)をご覧ください。
3. **金額** — タップしてテンキーで入力します。
4. **$ または %** — 定額の値引きか、注文金額に対する割合での値引きかを選びます。
5. **割引を追加** — 注文に割引を適用します。

</JourneyShot>

注文の合計欄に割引が表示され、それに合わせて各明細行の合計も調整されます。

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[12, 46], [100, 0], [50, 0], [0, 0]]} alt="$45.00の腕時計に10%の割引を適用したカート。明細行の合計$45.00に取り消し線が付き、その下に$40.50が表示されています。小計$45.00、$4.50を差し引く「割引 (10%)」の行と削除ボタン、「チェックアウト $40.50」が表示されています">

1. **明細行の合計** — 取り消し線付きの割引前の価格と、お客様が実際に支払う金額です。
2. **小計** — 割引前の注文金額です。
3. **割引 (10%)** — 割引の内容と差し引く金額です。**割引** とだけ表示されている場合は定額割引です。削除するには **✕** を押します。
4. **チェックアウト** — 割引後の合計です。

</JourneyShot>

定額割引は、各商品の価格に比例して配分されます。割合による割引は、すべての商品に適用されます。一つの注文に複数の割引を追加でき、それぞれ別の行に表示されます。

**割引を追加** はオフラインでも使えます。税額は値引き後の価格で計算されます。店舗にクーポンが作成されることはありません。

### 割引を削除する {#remove-discount}

合計欄の割引行にある **✕** を押します。各明細行の合計が元に戻り、**割引を削除しました** と表示されます。明細行で個別に変更した価格は、そのまま維持されます。

## クーポンを適用する {#coupon}

**割引を追加** で **クーポン** に切り替えます。この機能は無料版プラグインでも使えます。

<JourneyShot manifest={manifest} device="tablet" step={6} offsets={[[-40, 0], [10, 46], [24, -52]]} alt="「割引を追加」ダイアログの「クーポン」タブ。「クーポンを選択」フィールド、その隣の「新規クーポン」ボタン、「適用」ボタンが表示されています。隣のカートでは「割引 (10%)」の適用後、腕時計が$40.50になっています">

1. **クーポンを選択** — コードの一部を入力して検索します。
2. **新規クーポン** (WCPOS Pro) — その場でクーポンを作成します。[レジでクーポンを作成する](#new-coupon)をご覧ください。
3. **適用** — クーポンの条件を確認し、注文に適用します。

</JourneyShot>

この注文に使えないクーポンには、その理由が表示されます。各メッセージの意味、クーポンの削除、オフラインでのクーポン利用については、[クーポンの適用](../../coupons/applying-coupons.mdx)をご覧ください。

## レジでクーポンを作成する {#new-coupon}

:::info Pro機能
レジでクーポンを作成するには、[WCPOS Pro](../../getting-started/pro-license.mdx)が必要です。無料版プラグインでは、**新規クーポン** に **Proにアップグレード** と表示されます。
:::

1. **クーポン** タブで **新規クーポン** を押します。
2. コードを入力するか、**生成** を押します。
3. 割引の種類を選び、割引額または割引率を入力します。
4. **有効期限** と、クーポンに必要なその他の条件を設定します。
5. **クーポンを追加** を押します。クーポンはまず店舗に保存され、その後この販売に適用されます。**…を保存し、この販売に適用しました** と表示されます。

<JourneyShot manifest={manifest} device="tablet" step={7} offsets={[[-40, 0], [22, -40], [-40, 0], [100, 0], [-60, 0], [0, 0], [50, -52]]} alt="コードSPRING10を入力した「クーポンを追加」フォーム。コードの隣の「生成」リンク、「パーセント」に設定された割引の種類、有効期限の選択肢、「一回限りの使用」スイッチ、「最低購入金額」などの追加条件ボタン、「クーポンを追加」ボタンが表示されています。隣には同じカートがあります">

1. **コード** — お客様が使うコードです。入力が必須のフィールドはこれだけです。
2. **生成** — コードを自動生成します。
3. **割引** — 割合による割引、注文全体の定額割引、商品ごとの定額割引から選び、割引率または割引額を設定します。
4. **有効期限** — クーポンを使える期間です。
5. **一回限りの使用** — 一度使うと、そのクーポンは使えなくなります。
6. **その他の条件** — **最低購入金額**、**合計使用回数**、**併用不可** など、それぞれWooCommerceのクーポン条件を追加します。
7. **クーポンを追加** — クーポンを店舗に保存してから、この販売に適用します。

</JourneyShot>

作成されるのは通常のWooCommerceクーポンです。次の販売でも使うことができ、**WP Admin → マーケティング → クーポン** やレポートにも表示されます。クーポン画面から作成する方法については、[クーポンの作成](../../coupons/index.mdx#creating-coupons)をご覧ください。

## クイック割引キーを設定する {#quick-discount-keys}

キーは端末ごとに設定します。カート上部のスライダーボタンを押して **カート設定** を開きます。**クイック割引** には、レジ係が価格入力用のテンキーで見るものと同じキーが表示されます。新しい端末の初期値は5%、10%、15%です。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[0, 0], [0, 0], [0, 0], [-34, 0]]} alt="「カート設定」の「クイック割引」行。5%、10%、15%の三つのキーが価格入力用のテンキーと同じように表示され、「列」の「数量」スイッチはオン、その下の「分割」スイッチはオフになっています">

1. **最初のキー** — タップして、5や12.5など、100以下の割合を入力します。
2. **二つ目のキー** — 同じように設定します。
3. **三つ目のキー** — 同じように設定します。キーは三つまで設定できます。
4. **分割** — オンにすると、明細行の数量の下に **分割** が表示されます。[同じ商品に異なる価格を設定する](#split)をご覧ください。

</JourneyShot>

キーを削除するには、そのキーに0を入力します。残ったキーが横に広がり、行全体を埋めます。キーをすべて削除すると、価格入力用のテンキーには数字キーだけが表示されます。定額割引用のキーはありません。定額で値引きするには、新しい価格を入力するか、[割引を追加](#order-level-discounts)を使います。

## 同じ商品に異なる価格を設定する {#split}

お客様が同じ商品を三つ購入し、そのうち一つを値引きする場合を考えます。[カート設定](index.mdx#columns)の **列 → 数量** で **分割** をオンにします。数量が一つを超える明細行では、数量の下に **分割** が表示されます。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[0, 36], [-38, 0], [12, 28]]} alt="単価$45.00のAim Analog Watchが三つ入った、合計$135.00のカート明細行。数量の下に「分割」が表示されています">

1. **分割** — 商品一つにつき一行になるように明細行を分けます。
2. **価格** — 分割後の各明細行は、変更するまでこの価格を維持します。
3. **明細行の合計** — 三つ分の合計です。**分割** 後は、それぞれの明細行に個別の合計が表示されます。

</JourneyShot>

**分割** を押すと、商品一つにつき一行に分かれ、すべて同じ価格になります。値引きしたい明細行の価格を下げてください。数量が2.5などの場合は、数量一つの行が二行と、数量0.5の行に分かれます。[明細項目の分割](line-items.mdx#splitting-line-items)をご覧ください。

## うまくいかない場合 {#goes-wrong}

- **誤って価格入力を開いてしまった場合。** 点灯しているキーをもう一度押すか、**削除** で入力欄を空にしてから **完了** を押すと、価格は変わりません。キーボードでは **Escape** を押します。
- **明細行に誤った価格を設定した場合。** 価格をもう一度タップして正しい価格を入力するか、明細行を削除して商品を追加し直すと、店舗に登録された価格からやり直せます。
- **ゼロより大きい金額を入力してください** または **0より大きく100以下の割合を入力してください** — **割引を追加** の入力値が空か、範囲外です。
- **…はすでに注文に適用されており、他のクーポンと併用できません。** — **個別使用のみ** のクーポンが注文に適用されています。先にそのクーポンを削除するか、割引の追加を見送ってください。
- **新規クーポンがグレー表示になっている** — ツールチップに理由が表示されます。**Proにアップグレード**、権限がない（管理者が **WP Admin → POS → 設定 → アクセス** で付与します）、または **店舗に接続できるときにクーポンを作成できます** のいずれかです。店舗にある既存のクーポンは引き続き適用できます。
- **…を保存しましたが、適用されませんでした** — クーポンは店舗に保存されていますが、この注文が条件を満たしていません。条件を確認するか、注文が条件を満たしてから **クーポンを選択** でもう一度選びます。
- **手数料に負の値は指定できません。「割引を追加」を使ってください。** — POSでは負の手数料による値引きはできません。[割引を追加](#order-level-discounts)を使ってください。**金額に税を含む** など、手数料自体の説明は[手数料](index.mdx#fees)をご覧ください。

## POSの割引とWooCommerceクーポンの違い {#pos-discounts-vs-woocommerce-coupons}

**明細行の価格**（クイック割引キーまたは価格の直接入力）— レジ係が一つの明細行に設定します。条件はありません。他店の価格に合わせる場合や従業員価格、傷のある商品の値引きに適しています。

**割引を追加** — レジ係が注文全体に設定します。独自の条件はありませんが、**個別使用のみ** のクーポンとは併用できません。その場限りの定額割引や割合による割引に適しています。

**WooCommerceクーポン** — 使用回数の上限、対象商品、最低購入金額、有効期限、お客様のメールアドレスなど、条件に応じて適用されます。店舗で設定する（[クーポンの作成](../../coupons/index.mdx#creating-coupons)を参照）か、Proを使ってレジで作成します。利用条件を設け、レポートで確認したい販促に適しています。

## 既知の制限事項 {#known-limitations}

- **自動割引のルールはありません。** POSは「2個購入で1個無料」などの割引を自動適用しません。条件付きの販促にはWooCommerceクーポンを使ってください。
- **クイック割引キーは割合による割引専用です。** 定額で値引きするには、新しい価格を入力するか、**割引を追加** で **$** を選びます。

## 割引の記録方法 {#how-discounts-are-recorded}

ここで説明する内容によって、レジでの操作が変わることはありません。レポートやレシートに何が表示されるか、過去の注文の表示が異なることがあるのはなぜかを説明します。価格の保存方法を含む詳しい背景は、[POS割引リファレンス](../../reference/pos-discounts.mdx)をご覧ください。

<Accordion>
  <AccordionItem question="管理者向け：レポートとレシートでの割引の表示">

### 価格変更とクーポンが別々に記録される理由 {#why-tracked-differently}

クイック割引キーや直接入力による価格は、WooCommerceのセール価格と同じ方法で記録されます。つまり、レジ係が設定した価格で商品を販売したものとして扱われます。そのため、**割引** の合計はゼロのままで、クーポンは値引き後の価格を基準に計算されます。**セール品を除外** が設定されたクーポンは、値引きした商品には適用されません。

**割引を追加** はクーポン行として、WooCommerceクーポンはそのクーポン自体として記録されるため、どちらも **割引** の合計に含まれます。

<details>
<summary>WooCommerceによるクーポンとセール価格の記録方法</summary>

WooCommerceに標準搭載されている割引の仕組みは、**クーポン** だけです。クーポンは注文に紐づきます。専用のフィールドに記録され、レポートの **割引** 列に集計されます。また、使用回数の上限や有効期限など、独自の条件を持ちます。

WooCommerceでは、**セール価格** は割引として扱われません。単にその時点の商品価格です。セール中の商品が売れると、注文には実際に支払われた価格だけが記録されます。レポートでは通常の売上として集計されます。

お客様はレシートでいくら安くなったかを確認したいため、WCPOSは各明細行に新しい価格とあわせて通常価格を記録します。これにより、二重計上することなく、またWooCommerceの合計やレポートを変えることなく、セールによる値引き額とクーポン割引額をレシートに別々の金額として表示できます。

</details>

### POSでの価格変更とクーポンの関係 {#how-pos-price-changes-interact-with-coupons}

例えば、レジ係が商品の価格を$18から$16に下げ、その後クーポンを適用したとします。クーポンは$18ではなく **$16** を基準に計算されるため、元の価格に対して二重に割引されることはありません。

- レジで値下げした商品は、WooCommerceのセール価格と同様にセール品として扱われます。レジで値上げした商品はセール品にはなりません。**セール品を除外** が設定されたクーポンはセール品には適用されず、同じく **セール品を除外** が設定されたカート全体の定額割引クーポンは、カートにセール品がある間は一切使えません。
- クーポンを削除しても、各明細行の価格はレジで設定したまま維持されます。

:::note 開発者向けリファレンス
**割引を追加** の行は、`pos-discount`、`pos-discount-2` のような名前のクーポン行です。`wcpos_item_is_on_sale` フィルターで、何をセール品とみなすかを変更できます。レジで設定した価格の保存方法やその他のフィルターについては、[POS割引リファレンス](../../reference/pos-discounts.mdx)をご覧ください。
:::

### 負の手数料がある注文 {#discount-fee-tax}

2.0より前は、レジ係が負の手数料で注文を値引きできました。現在のPOSではできませんが、過去の注文には負の手数料が残っている場合があります。

<details>
<summary>WCPOSの負の手数料に対する課税方法と、WooCommerceとの違い</summary>

WCPOSは、**手数料自体の税設定** に基づいて負の手数料の税額を計算します。税ステータスが **なし** の場合、その手数料には課税されず、手数料の金額がそのまま差し引かれます。つまり、手数料が `-10.00` なら、お客様の支払額は10減ります。**課税** のままにすると、その手数料の税区分に基づいて課税されるため、税額も差し引かれます。

WooCommerce単体では処理が異なります。手数料の税ステータスを無視し、負の手数料の税額を注文内の他のすべての商品に配分します。また、**税込み価格を入力** が *はい* の店舗では、税率20%で `-10.00` の手数料を設定すると **12.00** が差し引かれます。WCPOSでは、レジ係が入力した金額を維持します。

この動作は注文に紐づいており、注文を開くアプリには依存しません。**WP Admin → 注文** からPOSの注文を再計算しても維持されます。POS以外で作成された注文は、WooCommerceの動作のままです。

:::note 負の手数料にかかる税
手数料の税ステータスが **なし** の場合、お客様が支払う合計は正しくなりますが、**注文に記録される税額は減りません**。そのため、値引き後の合計に対する本来の税額より少し高くなります。税務当局に有利な方向にずれることはあっても、その逆にはなりません。課税対象の負の手数料は、その手数料の税区分の税率で税額を差し引きます。**割引を追加** による割引はクーポン行なので、税額は値引き後の価格で計算されます。
:::

</details>

### v1.9.0での変更点 {#what-changed-in-v190}

v1.8からアップグレードした後、レシートやレポートの **割引** の合計が **0** になった場合、その理由は次のとおりです。以前のバージョンはレジでの価格変更をWooCommerceの割引として記録していたため、クーポンの計算が正しくありませんでした。追加で適用したクーポンが元の価格を基準に計算され、お客様への請求額が本来より少なくなっていました。v1.9.0以降は、WooCommerceがセール品を記録する方法と同じく、レジで設定した価格が **そのまま** 明細行の価格となり、クーポンだけが割引として扱われます。[価格変更とクーポンが別々に記録される理由](#why-tracked-differently)をご覧ください。

#### 運用への影響 {#what-this-means-for-you}

<details>
<summary>v1.9.0以降のレシート、レポート、クーポン、保存される価格</summary>

- **レシート** には、通常価格、通常価格からの値引き額、さらにクーポン割引額も加えた **合計値引き額** を表示できます。価格変更による値引き額は、WooCommerceの **割引** フィールドとは別に扱われます。
- **レポート** では、明細行の価格だけを変更した場合、`discount_total = 0` となります。集計されるのはクーポンだけで、**割引を追加** もクーポンとして数えられます。
- **クーポン** は、レジで値下げした商品に対しても正しく計算されます。
- 明細行のPOSメタデータ(`_woocommerce_pos_data`)に **通常価格と販売価格が保存される** ため、WooCommerceの割引合計を変更せずに、レシートに値引き額を表示できます。

</details>

#### 元の価格と値引き額をレシートに表示する {#showing-the-original-price-and-saving-on-receipts}

価格を表示する同梱テンプレートでは、商品がセール中の場合やレジで価格を変更した場合に、通常価格と値引き額も表示されます。また、WCPOSが注文全体の値引き額を漏れなく計算できる場合は、**合計値引き額** も表示されます。これは通常価格からの値引き額とクーポン割引額を、二重計上せずに合算したものです。

<details>
<summary>v1.9.0より前に作成したレシートテンプレートを更新する</summary>

ギャラリーからコピーしたテンプレートは独立したコピーであり、WCPOSの更新では上書きされません。この変更より前にレシートを作成した場合は、次のいずれかを行ってください。

1. 同梱テンプレートの新しいコピーで **テンプレートを使用** をクリックするか、
2. [レシートデータリファレンス](../../receipts/receipt-data.mdx#displaying-regular-price-and-savings)のフィールドをテンプレートに追加します。

値引き額に関するフィールド：

| フィールド | 意味 |
|-------|---------|
| `lines[].regular_price_display` | 記録された通常単価 |
| `lines[].selling_price_display` | クーポン適用前の販売単価 |
| `lines[].unit_savings_display` | 商品一つあたりの値引き額 |
| `lines[].line_regular_total_display` | 明細行の通常価格での合計 |
| `lines[].line_savings_display` | 明細行の値引き額合計 |
| `totals.sale_savings_total_display` | 商品カタログのセールとレジでの価格変更による、通常価格から販売価格への値引き額合計 |
| `totals.discount_total_display` | WooCommerceの割引合計：**割引を追加** を含むクーポン割引 |
| `totals.total_saved_display` | 通常価格からの値引き額とWooCommerce割引の合計 |
| `totals.total_saved_complete` | 合算した値引き額に不足がなく、表示しても問題ないかどうか |

これらのフィールドの多くは、元になるデータが注文にある場合にのみ存在します。カスタムテンプレートでは各フィールドの有無を確認し、値引き額を漏れなく計算できない場合や値引きがない場合は、**合計値引き額** の行を非表示にしてください。実装例は[レシートデータリファレンス](../../receipts/receipt-data.mdx#totals)にあります。

WooCommerceのレポートは変わりません。割引合計にはクーポンが含まれ、セール価格やレジでの価格変更による値引き額は含まれません。レシートには `totals.total_saved` を使い、レポートでもWooCommerceの割引として値引き額を表示する必要がある場合は、クーポンまたは **割引を追加** を使ってください。

</details>
