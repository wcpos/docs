## このエラーの意味 {#what-this-means}

このデバイスでの変更が、店舗側のより新しい編集と競合しました。データは失われていません。

**店舗の状態 → データベース** にこのレコードの保留中の変更が表示されている場合は、このデバイスのバージョンを残すには **再送信**、店舗側のバージョンを残すには **サーバーのバージョンを使用** をタップしてください。表示されていなければ、すでに解決済みのため対応は不要です。

## データへの影響 {#your-data}

データは失われていません。変更が保留されている場合、どちらを残すかを選ぶまで、店舗は店舗側のバージョンを、このデバイスは変更を保持します。それまで、そのレコードに対する追加の編集もこのデバイスで待機します。変更が保留されている間は、このデバイスのデータを消去しないでください。消去すると、保留中の変更が削除されます。

## トラブルシューティング {#troubleshoot}

1. **店舗の状態 → データベース** を開いてください。保留中の変更は、**「1 件の変更が保留されました」** （または **「… 件の変更が保留されました」** ）で始まるパネルに、対象のレコードとともに表示されます。
2. このレコードに保留中の変更がなくなっている場合は、このタブまたは別のタブですでに解決済みのため、対応は不要です。このデバイスのバージョンを再送信することで WCPOS が自動的に解決した注文の競合は、代わりに [SYNC222](/error-codes/SYNC222) として記録されます。
3. 変更が保留されている場合は、表示されていれば **レコードを開く** を押してこのデバイスのバージョンを確認し、WP Admin の同じレコードと比較してください（サイト管理者による操作が必要な場合があります）。
4. このデバイスのバージョンを残すには、**再送信** をタップしてください。変更が再送信され、このデバイスで変更したフィールドの店舗側の値が置き換わります。店舗側のバージョンを残すには、**サーバーのバージョンを使用**（行によっては **デバイスの変更を破棄**）をタップして確定してください。このデバイスの変更は破棄されます。どちらかを選ぶまで、そのレコードに対する追加の編集は待機します。
5. 同じレコードで頻繁に競合する場合は、通常、端末と WP Admin で在庫を編集するなど、二人が同じデータを並行して編集しています。編集の種類ごとに、どこで行うかを決めてください。
