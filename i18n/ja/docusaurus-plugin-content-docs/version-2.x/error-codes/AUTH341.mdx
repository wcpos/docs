## このエラーの意味 {#what-this-means}

この店舗は、このデバイスに保存済みの店舗と同じ識別情報を返しています。

各店舗には、WCPOS プラグインが一度だけ生成する識別情報があります。ステージングサイトの作成などでサイトをコピーすると、コピー先にも元の識別情報が引き継がれます。そのためアプリは両者を区別できず、既存の店舗と混在しないよう、もう一方の保存を拒否します。

一方のサイトは他方のコピーです。この重複だけでは、どちらがコピーなのかはわかりません。コピーを先に接続していた場合、今回接続しようとした店舗が元のサイトです。サイト管理者に、どちらがコピーかを確認してください。そのコピー先に新しい識別情報が必要です。

## データへの影響 {#your-data}

拒否されたこと自体による変更はありません。保存済みの店舗はそのまま残り、新しい店舗は保存されませんでした。

ただし、以下の二つ目の対処方法で保存済みの店舗を削除する場合は異なります。その店舗の同期待ちの売上はデバイスに残りますが、店舗を追加し直しても自動では引き継がれません。削除前に、保存済みの店舗に未同期のデータがないことを確認してください。残っている場合は、先にサポートに連絡してください。

## 対処方法 {#troubleshoot}

**コピー先のサイトでの対応** — その WordPress サイトの管理者の方：

1. どちらのサイトがコピー先かを確認してください（通常はステージングサイトやテストサイトです）。
2. コピー先の WP Admin → プラグインで、WCPOS を最新バージョンに更新してください。1.10.21 以降では、コピーされたサイトが新しいアドレスで初めて実行されたときに、プラグインがそのサイト固有の識別情報を付与します。元のサイトはアドレスが変わっていないため、そちらを更新してもこの問題は解消されません。
3. レジから再度接続してください。

**レジでの対応** — コピー先をまだ更新できない場合：

1. メッセージに表示されている保存済みの店舗で、すべての売上が同期済みであることを確認してください。同期待ちの売上がある場合は、先に同期するか、続行する前にサポートに連絡してください。
2. 接続画面で、その保存済みの店舗を削除してください。
3. 接続したい店舗のアドレスを入力して接続してください。

コピー先に固有の識別情報が付与されるまでは、どちらか一方だけを接続しておくことができます。

**両方のアドレスが同じ店舗を指している場合**（ローカルネットワークのアドレスと公開ドメインなど）は、保存済みの項目を削除し、今後このレジで使うアドレスで再接続してください。この場合も、削除前に未同期の売上がないか確認する必要があります。
