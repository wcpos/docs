## このエラーの意味 {#what-this-means}

店舗側でこの変更が拒否されたため、店舗には届いていません。

店舗側が示す理由を確認してください。**店舗の状態 → データベース** に変更が表示されている場合は、レコードを修正して **再送信** をタップするか、**破棄** してください。表示されていなければ、店舗側のバージョンに戻されています。引き続き必要であれば、もう一度変更してください（[SYNC202](/error-codes/SYNC202) を参照）。拒否された変更は、自動では再試行されません。

## データへの影響 {#your-data}

このデバイスのデータは消去しないでください。店舗にまだない変更が保存されている可能性があります。拒否された変更が **店舗の状態 → データベース** に表示されている場合は、再送信するか破棄するまでそこに残ります。既存の商品、バリエーション、顧客、クーポンに対する編集が拒否された場合、通常は自動的に元に戻され、代わりに [SYNC202](/error-codes/SYNC202) として記録されます。このコードが表示され、変更が **店舗の状態 → データベース** に載っている場合は、自動で元に戻されていません。以下の手順に従い、他の表示されている変更と同じように対応してください。繰り返し発生する場合は、**ログ** タブの **デバッグ情報をコピー** を使用して WCPOS サポートにお問い合わせください。

## トラブルシューティング {#troubleshoot}

1. 店舗側が示す理由を確認してください。ログと、**店舗の状態 → データベース** の該当する変更の行に記載されています。
2. **店舗の状態 → データベース** を開いてください。変更が表示されていない場合は、このデバイスのデータがすでに店舗側のバージョンに戻されており、送信するものはありません。[SYNC202](/error-codes/SYNC202) を参照してください。理由として挙げられた問題を解消し、引き続き必要であれば、もう一度変更してください。
3. 変更が表示されている場合、対象は注文、このデバイスで作成したレコード、または自動で元に戻されなかったカタログの編集です。拒否された変更は **「… 件の変更がサーバーに届きませんでした」** の下にあり、その行に店舗側が示す理由が記載されています。変更を一覧に残したまま、注文のフィールドなど、レコード自体の該当箇所を修正してください。
4. **店舗の状態 → データベース** に戻り、その行の **再送信** をタップしてください。このデバイスの現在の内容から変更を作り直して送信します。
5. 変更が不要になった場合は、代わりに **破棄** をタップしてください。店舗側のバージョンが維持されます。先に確認メッセージを読んでください。店舗側に一度も保存されていないレコードは、破棄するとこのデバイスから削除されます。
6. **サイト管理者：** ユーザーに変更が許可されていないと表示される場合、そのユーザーの権限グループには該当する操作の権限がありません。[AUTH201](/error-codes/AUTH201) を参照してください。理由に POS に表示されないフィールドが挙げられている場合は、WP Admin で同じレコードを開いてください。別のプラグインが、POS では確認できない検証を追加している可能性があります。それでも拒否される場合は、**ログ** タブの **デバッグ情報をコピー** を使用してサポートにお問い合わせください。
