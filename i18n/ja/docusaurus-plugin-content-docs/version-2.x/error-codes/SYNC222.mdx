## このエラーの意味 {#what-this-means}

この端末のデータが保存され、店舗側で行われた新しい編集が上書きされました。

ログ項目に記載されたフィールドを WP Admin で確認してください。店舗側の編集が正しかった場合は、そこで同じ編集をもう一度行ってください。

これは注文で発生します。この端末が最後に注文をダウンロードした後、WP Admin での操作、またはプラグインや支払い通知による自動処理で、店舗側の注文が変更されました。その後、この端末で注文への変更を保存した際に、店舗側が競合を報告しました。レジでの販売を止めないよう、WCPOS は店舗側のデータを上書きする形でこの端末のデータを再送信し、店舗側がそれを受け入れました。ログ項目には、店舗側の異なる値がこの端末の値に置き換えられたフィールドがすべて記載されます。その中には、店舗側での編集ではなく、レジで追加した明細や設定したステータスなど、この端末で行った変更も含まれることがあります。

同じ競合が続けて2回発生した場合、WCPOS は変更を保留し、どちらを残すかを確認します。[SYNC221](/error-codes/SYNC221) を参照してください。

## データへの影響 {#your-data}

注文はこの端末のデータで店舗側に保存されており、レジのデータは失われていません。やり直しが必要になる可能性があるのは、記載されたフィールドに対して店舗側で行われた新しい編集です。ログには置き換えられたフィールドが記載されますが、元の値は記載されません。一部のフィールドのみを表示していると記載されている場合、表示されている以外にも置き換えられたフィールドがあります。注文全体を確認してください。

## トラブルシューティング {#troubleshoot}

1. ログ項目を展開してください。注文名と、店舗側の値がこの端末の値に置き換えられたフィールドが記載されています。
2. WP Admin の **WooCommerce → 注文** で注文を開き、該当するフィールドを確認してください。注文メモに、店舗側の編集を行った人や処理が記録されている場合があります。
3. レジで行った変更が反映されているなど、フィールドの現在の値が正しければ、対応は不要です。
4. 店舗側の編集が正しかった場合は、WP Admin で同じ編集をもう一度行ってください。次回の同期で、その変更がレジに反映されます。
5. これが繰り返し発生する場合、同じ注文が2か所で同時に変更されています。たとえば、レジで販売処理がまだ完了していない間に WP Admin でステータスを設定している場合や、作成後の注文をプラグインが更新している場合です。注文の編集内容ごとに、どこで編集するかを決めてください。どのプラグインが注文を編集しているかは、サイト管理者が確認できます。
