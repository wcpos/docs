## このエラーの意味 {#what-this-means}

サイトの API の代わりに、ボット対策ページが応答しています。

アプリは JSON を想定していますが、サイトの REST API が HTML の確認ページ（ボット対策、CAPTCHA、DDoS 対策の中間ページ）を返しています。POS アプリではブラウザー向けの確認を通過できません。保護サービスの許可リストに、サイトの REST API を追加する必要があります。

## データへの影響 {#your-data}

注文や商品のデータには影響しません。

## トラブルシューティング {#troubleshoot}

1. 確認ページから保護サービスを特定し、その設定を開いてください。Cloudflare、Sucuri、Kinsta などは、それぞれのページにサービス名を表示しています。
2. API 通信を許可するため、サイト自体の REST API パス（/wp-json/ と /?rest_route=）を許可リストに追加してください。
3. Cloudflare では、REST API パスに対して WAF の**スキップ**ルールを追加してください。ボットファイトモード（無料プラン）はどのルールでも回避できないため、無効にする必要があります。[Cloudflare ガイド](/troubleshooting/common-problems/cloudflare)に、具体的なルールと `curl` による確認方法を記載しています。
4. Kinsta では、ボット対策・ファイアウォール設定の許可リストに REST API パスを追加してください。Sucuri では、API ルートに JavaScript による確認を行う DDoS 対策モードを使用しないでください。
