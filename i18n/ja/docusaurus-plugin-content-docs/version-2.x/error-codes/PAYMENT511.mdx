## このエラーの意味 {#what-this-means}

店舗側で管理しているこの注文の未払い額を超える支払いをレジで受け取ったため、店舗側がその反映を拒否しました。この操作は支払い失敗として注文に残るので、記録が隠されることはありません。

注文には何も反映されていませんが、現金はすでにドロワーに入っているか、お客様のカードに請求済みです。そのため、差額をお客様に返し、実際の未払い額に相当する分を、すでに受け取っている金額から注文の支払いとして記録する必要があります。

通常、このレジが最後に注文を読み込んだ後に、別のレジや WooCommerce 自体で注文が変更されたことを意味します。

## データへの影響 {#your-data}

金銭の移動はありましたが、店舗側には反映されていません。受領額と注文の未払い額の差額をお客様に返す必要があります。

## トラブルシューティング {#troubleshoot}

**レジでの対応** — お客様が帰る前に次の操作を行ってください。

1. お客様に再度支払いを求めないでください。拒否された支払いは反映されていませんが、その現金はすでにドロワーに入っているか、カードに請求済みです。
2. 店舗側に記録されている注文の未払い額を確認してください。その金額が正しい金額です。通常、**店舗の状態 → ログ**に、たとえば *「注文 #… の未払い額は … でしたが、レジでは … を受領しました」* と記載されています。金額の記載がない場合は、手順 3 で更新した支払いパネルに表示されます。
3. 支払いを記録する前に注文を更新してください。**店舗の状態 → データベース**を開き、**注文**行の **⋮** メニューから**今すぐ変更を確認**を選択すると、支払いパネルに店舗側の未払い額が表示されます。
4. すでに受け取った金額から、その未払い額を注文の支払いとして記録してください。このエラーは、現金や手動入力のカード決済など、記録のみを行う方法で発生します。支払いパネルで同じ方法を選び、**ちょうど …**（現金）または**未払い額全額 …** をタップして受領を記録してください。この操作では、カード端末や決済ゲートウェイによる方法を絶対に選ばないでください。新たな請求が発生します。お客様から新たにお金を受け取らないでください。
5. 受領額と注文の未払い額の差額をお客様に返してください。ドロワーから現金で返すか、カード決済端末または決済サービスのダッシュボードで差額を返金します。

**店舗側での対応** — サイト管理者向け：

1. 拒否された操作とその理由は、支払いを受け取ったレジの**店舗の状態 → ログ**に記録されています。**WooCommerce → 注文**の注文には、店舗側が受け付けたものだけが表示されます。
2. 同じ注文で繰り返し発生する場合、別のレジでの処理や、カウンターで注文を開いている間に届いたオンライン決済など、別の処理が同時にその注文を精算しています。
