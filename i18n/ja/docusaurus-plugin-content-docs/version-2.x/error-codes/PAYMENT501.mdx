## このエラーの意味 {#what-this-means}

店舗から、この注文はすでに支払い済みであるとの応答がありましたが、レジでもすでに支払いを受け取っていました。そのため、お客様は二重に支払っています。

レジでの支払いは注文の台帳に残り、理由 `order_already_paid` とともに失敗として記録されます。情報は隠されず、重複した支払いが黙って破棄されることもありません。残る対応は返金です。

## データへの影響 {#your-data}

代金は移動済みで、お客様に二重に請求されています。レジで受け取った支払いを返金してください。注文とオンラインの支払いはそのまま保持され、余分な支払いも破棄されず注文に記録されています。

## 対処方法 {#troubleshoot}

**レジでの対応** — お客様がお帰りになる前に行ってください：

1. 注文はすでにオンラインで支払い済みであり、重複した支払いを返金することをお客様にお伝えください。
2. レジで受け取った金額と支払方法を確認してください。**店舗の状態 → データベース** の **… 対応が必要です** に注文が表示され、*「注文 #… はオンラインで支払い済みです。レジでも … を受け取っています。この支払いを返金してください」* などの文が記載されています。同じ文は **店舗の状態 → ログ** にも表示されます。
3. 受け取った方法で返金してください。現金はドロワーから返し、カードへの請求はカード決済端末または決済サービス事業者のダッシュボードから払い戻します。返した現金を出金として記録しないでください。拒否された支払いはドロワーの現金予定額に計上されていないため、返金後のドロワーの残高はすでに一致しています。
4. この対応には、WCPOS の注文の **払い戻し** を使わないでください。この機能は、店舗が拒否したレジでの支払いではなく、注文自体、つまり正当なオンラインの支払いを払い戻します。
5. 注文を取り消したり削除したりしないでください。注文は正当な支払い済みの注文です。誤っているのは余分な支払いだけです。

**店舗側での対応** — サイト管理者の方へ：

1. WooCommerce でオンラインの支払いをゲートウェイの記録と照合し、重複した支払いのうちどちらを残すか確認してください。**WooCommerce → 注文** で、レジでの重複した支払いを返金したこと、その方法と日時を注文メモに追加してください。
2. 払い戻しが完了したか確認してください。カードへの払い戻しがお客様の利用明細に反映されるまで、数日かかる場合があります。
3. これが繰り返し発生する場合、通常はレジですでに開いている注文がオンラインで支払われることが原因です。決済前の注文がどのように POS に取り込まれるかを見直してください。
