## このエラーの意味 {#what-this-means}

レジ係が支払いパネルで選んだ決済ゲートウェイが支払いを拒否したか、代金を受け取らずに処理を終了しました。ゲートウェイの拒否には、失敗と独自のメッセージを返す、処理中にエラーが発生する、POS が対応できない別サイトへの移動を要求する、というパターンがあります。

ゲートウェイ独自のメッセージ、または移動先のサイト名を示す文が、レジのトースト通知とログ行に表示されます。

受け付けられないメールアドレスなど、入力内容だけを拒否した場合は、代わりに支払いフォームの該当フィールドの下またはフィールド群の下にメッセージが表示され、エラーコードは付きません。

## データへの影響 {#your-data}

POS に支払いは記録されていません。支払方法は以前のものに戻され、注文は変更されておらず、残額は未払いのままです。

ゲートウェイの処理開始後にエラーが発生した場合は、代金が受領されたかどうかを決済サービス事業者に確認するよう促す注文メモが店舗側で追加されます。

## 対処方法 {#troubleshoot}

**レジでの対応** — お客様がお帰りになる前に行ってください：

1. トースト通知またはログ行で、ゲートウェイのメッセージを確認してください。
2. 入力内容（メールアドレスや選択したオプション）を修正し、再送信してください。
3. ゲートウェイが拒否し続ける場合は、別の支払方法で受け付け、店舗オーナーに伝えてください。

**店舗側での対応** — サイト管理者の方へ：

1. WooCommerce の決済ページでゲートウェイの設定を確認してください。毎回拒否するゲートウェイは、通常、設定が誤っているか認証情報が不足しています。
2. *WooCommerce > ステータス > ログ* を確認してください。ソースが `woocommerce-pos` の WCPOS ログには、ゲートウェイのエラーや別サイトへのリダイレクトが記録されます。多くのゲートウェイも、ここに独自のログを保存します。
3. 注文メモに、今回の支払い処理について店舗側が追加したメモがないか確認してください。
