## このエラーの意味 {#what-this-means}

店舗のサーバーが、このアプリで利用できるすべての送信経路でログイントークンをブロックしています。

アプリは店舗に接続できることを確認しましたが、サーバー（またはその手前のファイアウォール、プロキシ、セキュリティプラグイン）が Authorization ヘッダーを削除し、URL パラメーターとして送信したトークンもブロックしています。ログイントークンを送る第三の方法はないため、サーバー側で修正する必要があります。

## データへの影響 {#your-data}

注文や商品データへの影響はありません。

## 対処方法 {#troubleshoot}

**ホスト／サーバー側での対応** — サーバーが通過を許可するまで、ログイントークンを届ける経路はありません：

1. Authorization ヘッダーが WordPress に届くようにしてください。Apache では通常、`SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1` の一行で設定できます。
2. サイトで `.htaccess` のリライトルールを使用している場合は、WordPress が生成する `HTTP_AUTHORIZATION` を引き渡す RewriteRule 行を残してください。セキュリティプラグインがこの行を削除することがあります。
3. プロキシや CDN を経由している場合は、そのヘッダーの許可リストを確認してください。Authorization リクエストヘッダーをオリジンサーバーに転送する必要があります。
4. ウェブアプリケーションファイアウォール（WAF）が URL パラメーターをフィルタリングしている場合は、`/wcpos/` の REST ルートで authorization パラメーターを許可してください。
