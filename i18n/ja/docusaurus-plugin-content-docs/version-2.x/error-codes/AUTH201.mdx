## これが意味すること {#what-this-means}

このアカウントには、この操作を実行する権限がありません。

データは失われていません。ユーザーの権限グループにこの操作の権限を付与するよう店舗管理者に依頼してから、もう一度お試しください。

## データへの影響 {#your-data}

データは失われていません。注文や商品データへの影響はありません。

## トラブルシューティング {#troubleshoot}

1. **レジ側：** 拒否されたときに行っていた操作（商品、顧客、注文の編集など）と、サインイン中のアカウントを記録してください。同期中に自動的に表示された場合は、**店舗の状態 → ログ**のエントリーを伝えるだけで十分です。拒否されたリクエストが記録されています。操作とアカウントの両方を管理者に伝えてください。拒否された操作が販売の一部でなければ、その間も販売を続けられます。
2. **サイト管理者：** まず、このアカウントにその操作を許可すべきか判断してください。許可すべきでない場合、拒否は意図した動作です。権限グループを変更せず、権限のあるアカウントで操作してください。許可すべき場合は、**WP Admin > POS > 設定 > アクセス**に移動し、アカウントの権限グループを選択してください。**レジ係ができること**（見出しには権限グループ名が表示されます）で、拒否された操作に該当する項目（**POSを使用**、**商品の作成と編集**、**注文の管理**、**顧客の管理**など）にチェックを入れてください。ダッシュと **7件中3件** などのバッジが表示される場合、その操作に必要な権限の一部だけが付与されています。チェックを入れると残りの権限も付与されます。**デフォルトに戻す**を選択すると、新規インストール時に付与される権限に戻ります。カスタムの権限グループには、WCPOSはデフォルトでPOSへのアクセスを許可しないため、この場合はPOSへのアクセス権が削除されます。
3. **サイト管理者：** サインインはできても、商品、顧客、注文のリクエストがすべて拒否される場合は、アカウントに**複数の権限グループ**が割り当てられていないか確認してください。Membersなどの権限編集プラグインでは、いずれかの権限グループに設定された *拒否* がアカウント全体に適用されます。そのため、管理者が顧客の権限グループも持っていると、顧客の権限グループで拒否されている権限を失います。追加の権限グループを削除するか、*拒否* のチェックを外してください。[複数の権限グループを持つユーザー](/manage-store/staff-permissions#more-than-one-role)を参照してください。
4. **レジに戻って：** 新しい権限を適用するため、サインアウトして再度サインインし、拒否された操作をもう一度お試しください。
