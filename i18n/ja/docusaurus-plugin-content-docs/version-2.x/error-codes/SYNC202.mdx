## このエラーの意味 {#what-this-means}

店舗側でこの変更が拒否されたため、このデバイスのデータは店舗側のバージョンに戻りました。

変更は保存されませんでした。店舗側が示す理由を確認し、該当する問題を解消してから、もう一度変更してください。

これは、既存の商品、バリエーション、クーポン、顧客を編集したときに発生します。値が無効である、ログイン中のユーザーに変更が許可されていないなどの理由で、店舗側が編集を恒久的に拒否した場合、WCPOS はその編集を待機状態にしません。このデバイスのデータを店舗側のバージョンに戻し、端末が店舗と同じ情報を使って販売できるようにします。ログには対象のレコードと店舗側が示す理由が記載されます。

## データへの影響 {#your-data}

それ以外の変更はありません。店舗側のバージョンは変更されずに維持され、このデバイスにも再びそのバージョンが表示されます。店舗側でレコードが削除されている場合は、このデバイスからも削除されます。失われたのは拒否された編集だけなので、原因を解消してからもう一度編集してください。売上や注文への影響はありません。また、拒否された編集の後に同じレコードに加えた編集は保持され、そのまま送信されます。

## トラブルシューティング {#troubleshoot}

1. ログを展開し、店舗側が示す理由を確認してください。何が拒否され、どのレコードに関するものなのかが記載されています。
2. 理由として挙げられた問題を解消してください。価格、SKU、メールアドレス、未入力の必須フィールドなど、値の問題であれば、正しい値を確認してください。ユーザーに変更が許可されていないと表示される場合は、アカウントの権限グループに該当する操作の権限がありません。[AUTH201](/error-codes/AUTH201) を参照してください。
3. レコードを開き、正しい値でもう一度変更して保存してください（店舗側で削除されている場合は、変更できるレコードはありません）。同期後、レコードに変更が反映されているか確認してください。
4. このデバイスで作成した新しいレコードが店舗側で拒否された場合は、元に戻す対象となる店舗側のバージョンがないため、元には戻されません。**店舗の状態 → データベース** の **「… 件の変更がサーバーに届きませんでした」** に残ります。[SYNC201](/error-codes/SYNC201) を参照してください。
5. **サイト管理者：** 理由に POS に表示されないフィールドが挙げられている場合は、WP Admin で同じレコードを開いてください。別のプラグインが、POS では確認できない検証を追加している可能性があります。店舗側で変更が繰り返し拒否される場合は、**ログ** タブの **デバッグ情報をコピー** を使用してサポートにお問い合わせください。
