## このエラーの意味 {#what-this-means}

送信した値が店舗側で拒否されました。

店舗側が示す理由に、対象の値が記載されています。入力した場所で修正し、もう一度保存してください。通常は商品、顧客、注文などのレコードの値ですが、設定やログインのリクエストが店舗側で拒否された場合にもこのコードが表示されることがあります。その場合は、該当する画面で修正してください。

## データへの影響 {#your-data}

このデバイスのデータは消去しないでください。店舗にまだない変更が保存されている可能性があります。既存の商品、バリエーション、顧客、クーポンに対する編集が拒否された場合、通常は自動的に元に戻され、代わりに [SYNC202](/error-codes/SYNC202) として記録されます。このコードが表示され、変更が **店舗の状態 → データベース** に載っている場合は、自動で元に戻されていません。他の表示されている変更と同じように対応してください。設定やログインのリクエストの場合、保存待ちのデータは残りません。

## トラブルシューティング {#troubleshoot}

1. ログを展開し、店舗側が示す理由とエンドポイントを確認してください。理由には対象の値が記載され、エンドポイントからは、レコードに関するものか、設定やログインのリクエストに関するものかがわかります。
2. 入力した場所で値を修正し、もう一度保存してください。よくある原因は、値が範囲外である、形式が受け付けられない、必須のオプションが未入力であることです。変更が **店舗の状態 → データベース** に表示されていない場合は、店舗側のバージョンに戻されているため、正しい値でもう一度変更してください。修正後も **店舗の状態 → データベース** の **「… 件の変更がサーバーに届きませんでした」** に表示されている場合は、その行の **再送信** をタップしてください。
3. 代わりに、レコードが **「… 件の変更が保留されました」** に表示され、*「店舗側で最新のバージョンが必要とされました」* と記載されている場合、値に問題はありません。[SYNC221](/error-codes/SYNC221) の説明に従って、**再送信** するか **デバイスの変更を破棄** するかを選んでください。
4. 設定やログインのリクエストだった場合は、入力した画面で値を修正し、もう一度保存してください。**サイト管理者：** POS のログに詳細がない場合は、ブラウザーの開発者ツール（ネットワークタブ）、またはデスクトップアプリの **詳細設定 → 開発者ツールの切り替え** で店舗側の応答を確認できます。
5. **サイト管理者：** 指摘された値が POS では正しく見える場合は、WP Admin の同じレコードと比較してください。店舗側でプラグインが追加した検証によって、POS では問題ないと判断される値が拒否されることがあります。
