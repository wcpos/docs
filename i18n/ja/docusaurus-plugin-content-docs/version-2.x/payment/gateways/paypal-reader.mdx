# PayPal Reader (Zettle)決済ゲートウェイ {#paypal-reader-zettle-gateway}

レジからPayPal Readerに注文の合計金額が送信され、お客様がリーダーにカードをかざすか挿入します。リーダーから決済完了が通知されると、販売処理は自動で完了します。このページでは、レジでの[決済の受け付け](#take-payment)と、WP Adminでの[設定](#setup)を説明します。

:::info Proの機能
PayPal Reader拡張機能を拡張機能ディレクトリからインストールする場合も、レジで使用する場合も、[WCPOS Pro](../../getting-started/pro-license.mdx)が必要です。
:::

## 決済を受け付ける {#take-payment}

:::note 始める前に
- レジと店舗のサイトがオンラインであることを確認してください。決済は、POS内に表示される店舗のサイトの支払いページで行われます。
- WP Adminにアクセスできる担当者が、[ゲートウェイの設定とリーダーのペアリング](#setup)を済ませている必要があります。
- 店舗で**レジの開閉**を使用している場合は、レジを開いてください。レジが閉じている間は決済を記録できません。[レジ](../../settings/wp-admin/registers.mdx#one-register)を参照してください。
:::

1. カートに商品を追加し、**チェックアウト**を押します。
2. **レガシー**タブを開きます。POS内に店舗のサイトの支払いページが表示されます。[レガシータブ](../../pos/checkout/legacy-tab.mdx)を参照してください。
3. **PayPal Reader**を選択します。店舗によっては別の名前が設定されている場合があります。パネルには**リーダーを読み込み中…**と表示され、続いて**モード：テスト。決済を開始できます。** と表示されます（[本番運用に切り替えた](#going-live)後は**モード：本番。** と表示されます）。
4. リーダーを選択します。ペアリング済みのリーダーはそれぞれ、**フロントカウンター（準備完了）** のように名前付きのボタンで表示され、最初のリーダーが選択済みになっています。別のリーダーを使用する場合は、そのボタンをタップします。

   :::warning
   パネル上部の**テストモード**は表示上のラベルにすぎません。リーダーでは実際の請求が発生する可能性があります。[テストモードと本番運用への切り替え](#going-live)を参照してください。
   :::

5. **リーダー決済を開始**を押します。パネルに**リーダーに接続中…**、続いて**リーダーの準備ができました。決済を要求中…** と表示され、注文の合計金額全額がそのリーダーに送信されます。
6. お客様がリーダーにカードをかざすか挿入します。処理中は、パネルに**決済処理中…** と表示され、リーダーで実行中の処理が括弧内に表示されます。
7. リーダーから決済完了が通知されると、パネルに**決済が完了しました。注文を送信中…** と表示され、POSはレシート画面に進みます。

販売処理は自動で完了するため、レガシータブ下部の**支払いを処理**を押す必要はありません。リーダーの処理が完了する前に押すと、POSに**注文を確定する前にPayPal Readerでの決済を完了してください。** と表示されます。

ボタンの下にある暗い背景のボックスには、処理の各段階が時刻付きで行ごとに記録されます。決済が途中で止まった場合に確認してください。

リーダーでは常に注文の全額を決済するため、ほかの支払い方法と併用できません。注文に対して一度でも支払いを受け付けると、**レガシー**タブに**全額決済のみ**と表示され、使用できなくなります。先に[その支払いをキャンセル](../../pos/checkout/cancelling-a-payment.mdx)してください。

### 決済を中止する {#cancel}

決済中に**決済をキャンセル**を押します。リーダーにキャンセル要求が送信され、レジはリーダーからの通知の受信を停止します。パネルには**決済がキャンセルされました。** と表示されます。

:::warning 再度請求する前にリーダーを確認してください
**決済をキャンセル**を押した後、またはリーダーでの処理中に支払いページを閉じたり再読み込みしたりした場合、レジはリーダーからの通知を受信しなくなります。それでもリーダーに決済承認が表示されている場合、お客様は支払い済みです。再度請求しないでください。**支払い**タブの**カード**タイルでその支払いを記録し、Zettleアカウントで決済を確認してください。
:::

お客様に請求されていないことを確認してから、**リーダー決済を開始**を押して再試行するか、タブを閉じて別の支払い方法を使用してください。

## 販売後 {#after-the-sale}

注文は支払い済みになり、**取引ID**にはZettleのカード決済IDが設定されます。このIDでZettleアカウント内の同じ決済を検索できます。注文メモには、決済の開始時刻と使用したリーダー（リンクID）、決済が完了した時刻、金額の不一致で拒否された時刻、または**決済をキャンセル**でキャンセルされた時刻が記録されます。

## 払い戻し {#refunds}

この拡張機能ではZettle経由で払い戻しできないため、**PayPal Readerに払い戻し**は使用できません。

:::warning
お客様に現金を渡さないでください。カードへの払い戻しはZettleで行い、**現金で払い戻し**ではWCPOSにその記録を残すだけです。レジが開いている場合は、ドロワー内にあるはずの現金残高も同額だけ減少します。[現金での払い戻しとドロワー](../../pos/refunds.mdx#drawer)を参照してください。
:::

1. Zettleアカウントでカードへの払い戻しを行います。
2. **現金で払い戻し**を使用して、注文に払い戻しを記録します。[払い戻し先](../../pos/refunds.mdx#destination)を参照してください。

## 問題が発生した場合 {#goes-wrong}

**ペアリング済みのリーダーがありません。店舗の管理者にペアリングを依頼してください…** Zettleアカウントにペアリングされたリーダーがないため、**リーダー決済を開始**はグレー表示のままです。WP Adminにアクセスできる担当者がペアリングする必要があります。[設定する](#setup)の**リーダーをペアリングする**を参照してください。

**パネルが「リーダーに接続中…」のまま変わらない** リーダーで決済を受け付ける準備ができていません。スリープ中、電源がオフ、オフライン、または別の処理中の可能性があります。スリープを解除し、ホーム画面が表示されていてオンラインであることを確認してください。**決済をキャンセル**を押し、[決済を中止する](#cancel)の説明に従ってリーダーで決済が行われていないことを確認してから、もう一度**リーダー決済を開始**を押してください。

**決済がキャンセルされました。** リーダー上の操作、または**決済をキャンセル**で決済がキャンセルされました。 **決済をキャンセル**を押した場合は、[決済を中止する](#cancel)の説明に従って、まずリーダーを確認してください。その後、再度開始するか、別の支払い方法を使用してください。

### 決済に失敗しました。カードに請求されていますか？ {#payment-failed}

**決済に失敗しました。** に続くメッセージから、お客様が支払い済みかどうか、つまり再度請求してよいかどうかを判断できます。メッセージを確認し、該当する手順に従ってください。

- **決済金額が一致しません。**：[請求済みのため、先に払い戻す](#failed-mismatch)。
- 括弧内に理由が表示される：[未請求のため、再試行する](#failed-reason)。
- **リクエストに失敗しました。**、**サーバーの応答が無効です。**、**リクエストが無効です。**、または**注文へのアクセスが無効です。**：[請求済みのため、支払いを記録する](#failed-not-recorded)。
- 後続のメッセージがない、またはここに記載されていないメッセージが表示される：[再試行する前に確認する](#failed-connection)。

#### 決済金額が一致しません：請求済みのため、先に払い戻す {#failed-mismatch}

**カードへの請求：あり。** パネルに**決済に失敗しました。決済金額が一致しません。** と表示されます。リーダーで代金は受領していますが、決済開始後に注文の合計金額が変わったため、注文が拒否され、未払いのままになっています。Zettleアカウントでその決済を払い戻し、正しい合計金額で新たに決済を開始してください。これを防ぐため、リーダーでの決済中はカートを変更しないでください。**決済をキャンセル**を押し、カートを変更してから、新たに決済を開始してください。

#### 括弧内に理由が表示される：未請求のため、再試行する {#failed-reason}

**カードへの請求：なし。** パネルに**決済に失敗しました。** と表示され、括弧内に理由が示されます。カードの承認が拒否された場合など、リーダーまたはZettleで決済が行われていません。**リーダー決済を開始**を押すか、別の支払い方法を使用してください。

#### 「決済に失敗しました。」のみ、または記載のないメッセージ：再試行する前に確認する {#failed-connection}

**カードへの請求：不明。** パネルには**決済に失敗しました。** とだけ表示されます。レジとZettleの接続が切れたため、カードに請求されたかどうかを判断できません。このページに記載のないメッセージも同様に扱ってください。リーダーとZettleアカウントの決済一覧を確認します。該当する決済があれば、[決済を中止する](#cancel)の説明に従って記録してください。決済が行われていないと確認できた場合にのみ、再度開始してください。判断できない場合は、再度請求する前にZettleアカウントの管理担当者に確認してください。

#### 「リクエストに失敗しました。」など、ここに記載のメッセージ：請求済みのため、支払いを記録する {#failed-not-recorded}

この手順が当てはまるのは、**決済に失敗しました。** の後に**リクエストに失敗しました。**、**サーバーの応答が無効です。**、**リクエストが無効です。**、**注文へのアクセスが無効です。** のいずれかが表示される場合のみです。ほかのメッセージの場合は、[「決済に失敗しました。」のみ](#failed-connection)の手順に従ってください。

**カードへの請求：あり。** これらのメッセージは、リーダーが決済完了を通知した後にのみ表示されます。リーダーで決済は行われましたが、店舗のサイトに記録できなかったため、注文は未払いのままです。Zettleアカウントで該当する決済を見つけ、[決済を中止する](#cancel)の説明に従って記録してください。Zettleアカウントに該当する決済がない場合は、[「決済に失敗しました。」のみ](#failed-connection)の手順に従い、確認できるまで再度請求しないでください。

### その他のメッセージ {#other-messages}

**Zettleの認証情報が設定されていません。** **ZettleクライアントID**または**Zettleアサーション**が空欄です。ゲートウェイの設定担当者に入力を依頼してください。[設定する](#setup)の**ゲートウェイの設定を入力する**を参照してください。

**「Zettle OAuth交換でHTTP …が返されました」で始まるメッセージ** Zettleが認証情報を拒否しました。ゲートウェイの設定担当者に、**ZettleクライアントID**と**Zettleアサーション**の確認を依頼してください。

**パネルにボタンは表示されるが、「リーダーを読み込み中…」が表示されない** 支払いページのスクリプトが読み込まれていません。[ゲートウェイの支払いページが正しく表示されない](../../pos/checkout/troubleshooting.mdx#checkout-settings-troubleshooting)を参照してください。

<details>
<summary>設定中のメッセージ</summary>

**リーダーをペアリングする前に、上のZettleクライアントIDとアサーションを保存してください。** **ペアリング済みのリーダー**セクションは、両方の認証情報が保存されるまで使用できません。入力して保存してください。

**先にペアリングコードを入力してください。** **ペアリングコード**欄が空です。リーダーに表示されているコードを確認し、入力してください。

**ペアリング済みのリーダーを読み込めませんでした：** この後にZettleからの応答が表示されます。設定ページからZettleに接続できなかったか、Zettleが認証情報を拒否しました。認証情報を確認し、再度保存してください。

**「リーダーをペアリング」で「Zettle APIがHTTP …を返しました」で始まるメッセージが表示される** Zettleがペアリングコードを拒否しました。リーダーで**設定 → 開発者とリンク**を開いて新しいコードを取得し、表示どおりに入力してください。また、リーダーがオンラインであることを確認してください。それでも失敗する場合は、**ZettleクライアントID**と**Zettleアサーション**が保存されているか確認してください。

**PayPal Reader：モックリーダーが有効です。** 開発者向けの設定`PRWC_USE_MOCK_READER`が`wp-config.php`に定義されています。この設定がある間は、実際の決済は行われません。開発者またはホスティング会社に削除を依頼してください。

</details>

## 設定する {#setup}

ここでは店舗のWP Adminを管理する担当者向けに、拡張機能のインストールからPOSでの有効化までを五つの手順で説明します。

<details>
<summary>インストール、認証情報の入力、リーダーのペアリング、POSでの有効化</summary>

<Steps>
  <StepCard number="1" title="拡張機能をインストールする">

`WP Admin > POS > 設定 > 拡張機能`を開き、**PayPal Reader for WooCommerce**を見つけて、**インストール**、**有効化**の順にクリックします。[拡張機能のインストール](../../extensions/index.mdx#installing-an-extension)を参照してください。

ディレクトリを使用しない場合は、[GitHubのリリースページ](https://github.com/wcpos/paypal-reader-for-woocommerce/releases)から**プラグインのzip**（ソースコードのzipではありません）をダウンロードし、`プラグイン > Add Plugin`、**プラグインのアップロード**の順に進んでアップロードします。WooCommerceが有効になっている必要があります。

  </StepCard>
  <StepCard number="2" title="Zettleの認証情報を取得する">

Zettle Developer Portalで、Zettleアカウントの**クライアントID**と**アサーション**（JWT）を取得します。実際の請求を行わずにゲートウェイを試すには、まずZettleの開発者用（テスト用）加盟店アカウントを使用してください。

利用できるPayPal Readerの機種と国は、WCPOSではなくZettleアカウントによって決まります。リーダーを購入する前にPayPalに確認してください。

  </StepCard>
  <StepCard number="3" title="ゲートウェイの設定を入力する">

1. `WP Admin > WooCommerce > 設定 > 支払い`に移動し、**PayPal Reader**を開きます。
2. テストアカウントで試す間は、**テストモードを有効化**をデフォルトのチェック付きのままにします。
3. **ZettleクライアントID**と**Zettleアサーション**を入力します。
4. 必要に応じて、レジ係が支払いページで選択する**タイトル**と、その**説明**を変更します。
5. 保存します。

  </StepCard>
  <StepCard number="4" title="リーダーをペアリングする">

1. 同じ設定ページの下部にある**ペアリング済みのリーダー**までスクロールします。両方の認証情報を保存すると表示されます。
2. PayPal Readerで**設定 → 開発者とリンク**を開きます。リーダーにペアリングコードが表示されます。
3. **新しいリーダーをペアリング**で、**ペアリングコード**と、`Front counter`などの**リーダー名**を入力します。名前を入力しない場合は、`WCPOS PayPal Reader`という名前になります。
4. **リーダーをペアリング**をクリックします。ページに**リーダーをペアリングしました。** と表示され、リーダーが一覧に追加されます。

すべてのレジに、Zettleアカウントにペアリングされたすべてのリーダーが表示されます。レジ係はチェックアウト時に使用するリーダーを選択します。削除するには、該当するリーダーの横にある**ペアリングを解除**をクリックし、確認します。

  </StepCard>
  <StepCard number="5" title="POSで有効にする" isLast>

`WP Admin > POS > 設定 > 支払い`に移動し、**PayPal Reader**の**有効**をオンにします。[ゲートウェイの有効化](../../settings/wp-admin/checkout.mdx#enabling-a-gateway)を参照してください。

:::note
**WebチェックアウトでPayPal Readerを有効化（WCPOSでは不要）** のチェックは外したままにしてください。この設定はオンラインショップにゲートウェイを表示するためだけのものです。POSでは、ここの設定で有効にすると使用できます。
:::

  </StepCard>
</Steps>

</details>

## テストモードと本番運用への切り替え {#going-live}

**テストモード**は、リーダーをサンドボックスに切り替える設定ではありません。Zettleではテスト決済と実際の決済に同じ接続先を使用しており、実際のお金が動くかどうかは認証情報に紐づくアカウントで決まります。テストモードで変わるのは、決済パネルの**テストモード**バッジと、ステータス行の**モード：テスト。** という表示だけです。

本番運用に切り替えるには：

1. **ZettleクライアントID**と**Zettleアサーション**を、本番用Zettleアカウントのものに置き換えます。
2. **テストモードを有効化**のチェックを外し、保存します。
3. **ペアリング済みのリーダー**を確認します。一覧はZettleアカウントから取得されるため、テストアカウントにペアリングしたリーダーは表示されません。[設定する](#setup)の**リーダーをペアリングする**の手順に従って、再度ペアリングしてください。
4. 少額の実際の決済を行い、Zettleで払い戻します。

## 設定リファレンス {#settings}

設定は`WP Admin > WooCommerce > 設定 > 支払い > PayPal Reader`にあります。必要な設定は上記の手順で説明しています。すべての設定とデフォルト値を確認するには、一覧を開いてください。

<details>
<summary>全6項目の設定とペアリングパネル</summary>

| 設定 | 機能 |
|---|---|
| **有効化/無効化** | **WebチェックアウトでPayPal Readerを有効化（WCPOSでは不要）**。オンラインショップにゲートウェイを表示します。オンラインでは既存の注文の支払いページでしか機能しないため、オフのままにしてください。デフォルトはオフです。POSには、`POS > 設定 > 支払い`に専用のスイッチがあります |
| **タイトル** | レジ係が支払いページで選択する名前です。デフォルトは`PayPal Reader`です |
| **説明** | タイトルの下に表示される文です。デフォルトは`Pay in person using PayPal Reader.`です |
| **テストモード** | **テストモードを有効化**。決済パネルに**テストモード**バッジを表示します。デフォルトはオンです。決済の接続先は変わりません |
| **ZettleクライアントID** | Zettle Developer Portalで取得するZettle OAuthクライアントIDです |
| **Zettleアサーション** | Zettle OAuthアサーション（JWT）です。パスワードと同様に非表示で保持されます |

設定の下にある**ペアリング済みのリーダー**には、各リーダーの名前と**リンクID**、**ペアリングを解除**が表示されます。**新しいリーダーをペアリング**には、**ペアリングコード**と**リーダー名**を入力します。

</details>

## ログ {#logs}

まず注文メモを確認してください。決済の開始、完了、金額不一致による拒否、およびレジでの**決済をキャンセル**の操作が、その注文に記録されます。カードの承認拒否、リーダーでのキャンセル、接続の切断は記録されないため、支払いページのログボックスを確認してください。

Zettleのリーダーサービスがリクエストを拒否した場合や接続できない場合は、拡張機能が`WP Admin > WooCommerce > Status > ログ`にも記録を残します。ソースは`paypal-reader-for-woocommerce`です。サポートを依頼する際は、このログと**注文番号**を送ってください。

## 対応していない機能 {#limitations}

- WooCommerceまたはPOSからZettle経由で行う払い戻し。
- リーダーでのチップの受け付け。
- 一部金額の支払い。リーダーでは常に注文の全額を決済します。
- 支払いページを閉じたり再読み込みしたりした後の決済の再開。
- オンラインショップの通常のチェックアウト。オンラインでは既存の注文の支払いページでのみ機能します。

<details>
<summary>開発者向け：仕組み</summary>

店舗のサイトはJWT-bearer OAuthグラント(`oauth.zettle.com`)でZettleにサインインし、有効期限の30秒前までアクセストークンをキャッシュします。ペアリング、リーダー一覧、決済セッションにはZettleの**Reader Connect** API(`reader-connect.zettle.com/v1/integrator`)を使用します。ペアリングではリーダーのコードを使ってリンクオファーを取得し、各リーダーをリンクとして扱います。

**リーダー決済を開始**は、選択したリンクのセッションを開くよう店舗のサイトに要求します。続いて支払いページがZettleへのWebSocket接続を開き、リーダーの状態を要求します。リーダーの準備ができると、チップなしで注文の合計金額の決済リクエストを送信します。進捗は同じソケット経由で返されます。**決済をキャンセル**は、そのソケットでキャンセル要求を送信します。

リーダーが`COMPLETED`を通知すると、ページは結果を店舗のサイトに送信します。店舗のサイトは、金額が注文の合計金額と一致する場合にのみ受け入れます。Zettleのカード決済IDを取引IDとして保存し、注文を確定します。この確認が完了するまで注文は確定できません。

自動テストでは、`PRWC_USE_MOCK_READER`（または`paypal_reader_for_woocommerce_use_mock_reader`フィルター）と`PRWC_MOCK_CANCEL_BEHAVIOR`を使用して、Zettleをモックリーダーに置き換えます。これは設定画面には表示されず、有効な間はWP Adminに警告が表示されます。

</details>
