# Windcave Terminalゲートウェイ {#windcave-terminal-gateway}

Windcave Terminalは、レジからWindcave端末へ販売情報を送信します。お客様が端末で支払い、Windcaveの確認後にレジへ支払いが記録されます。

このページではレジでの操作から説明します。店舗の管理者向けの[Windcave Terminalの設定](#setup)では、認証情報やWP Adminの設定、動作確認の方法を説明します。

:::info Pro機能
Windcave Terminalを使うには、[WCPOS Pro](../../getting-started/pro-license.mdx) 2.0以降と、拡張機能のバージョン1.0以降が必要です。
:::

:::warning Windcaveの認証はまだ取得していません
**テスト決済のみ：Windcaveでは、まだ実際のお客様のカードを使わないでください。** WindcaveはPOS連携をすべて審査してから実決済を許可しますが、この連携はまだ承認されていません。

<details>
<summary>まだテストされていない点</summary>

この拡張機能は、まだ実機のWindcave端末で動作していません。Windcaveのドキュメントをもとに作成したHITサービスの代替環境で、決済と払い戻しをテストしました。利用を始める前に、少額のUAT販売を行い、払い戻しも試してください。

</details>
:::

## カード決済を受け付ける {#take-payment}

:::note 先にレジを開いてください
**レジの開閉**が有効な場合、レジが閉じている間は支払いを記録できません。すでに受け付けたカード決済は払い戻しが必要になります。この設定については[レジ](../../settings/wp-admin/registers.mdx#one-register)をご覧ください。
:::

1. カートで**チェックアウト**を押し、**Payments**タブにある**Windcave Terminal**のタイルをタップします。端末で署名を求められる場合は、代わりに**Legacy**タブを使います。[端末から質問された場合](#terminal-questions)をご覧ください。
2. キーパッドの上を確認します。**Choose a terminal**と表示されている場合は、レジカウンターにある端末の**Station ID**をタップします。これはWindcaveが各端末に付ける名前で、たとえば`DOCS-STATION-1`です。**Terminal:** とIDが表示されていれば、そのレジで使う端末です。別の端末を選ぶには**Change**を押します。レジは選択を記憶します。
3. カードで残額の一部を支払うには、金額を入力します。残りは別の支払い方法で精算するまで未払いのままです。
4. **Send … to Windcave Terminal**を押します。レジには4段階の進行状況、**Sent**、**On terminal**、**Approved**、**Captured**が表示されます。Capturedになると決済が完了しています。
5. お客様は端末でカードをタッチ、挿入、またはスワイプします。決済が完了し、支払う残額がなければレシートが開きます。残額がある場合は、別のタイルで支払いを受け付けます。

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[105, 0], [-40, 0], [190, 0], [-45, 0], [0, 0], [85, 0]]} maxWidth={720} alt="45.00ドルの販売でPaymentsタブを開いたCheckout画面：Windcave Terminalタイルが選択され、Choose a terminalの下に2つのStation ID、その下にFull balanceが表示されている。端末を選ぶまでSend $45.00 to Windcave Terminalボタンは無効">

1. **Windcave Terminal** — タップすると枠線が付くタイルです。
2. **Choose a terminal**の下にある**Station IDs** — カウンターの端末をタップします。このレジで端末を選択すると、この行には**Terminal:** とそのID、**Change**が表示されます。
3. **To pay** — 今回の支払い金額です。残額の一部だけをカードで支払う場合は、より小さい金額を入力します。
4. **Full balance** — 未払いの全額を**To pay**に戻します。
5. **Send … to Windcave Terminal** — 端末で決済を開始します。端末を選ぶまでは無効です。
6. **Legacy** — 独自の支払いページを持つゲートウェイ用の別の支払いタブです。端末で署名を求められる場合に使います。

</JourneyShot>

4つのステップの下にある**Details**を開くと、支払いと送信先のStationのログが表示されます。端末でチップ、追加料金、キャッシュアウトはできません。

### 端末から質問された場合 {#terminal-questions}

端末が処理を中断して、たとえばお客様の署名が一致するかを尋ねることがあります。このバージョンでは、**Payments**タブに質問が表示されません。**Legacy**タブには表示されます。

1. **Legacy**タブを開き、**Windcave Terminal**を選択します。[Legacyタブ](../../pos/checkout/legacy-tab.mdx)をご覧ください。
2. そこで決済を開始します。注文全額を1回で支払います。
3. 端末から質問されると、支払いページには端末固有のボタン（**YES**や**NO**など）とともに質問が表示されます。回答を押してください。

### 決済をキャンセルする {#cancel}

お客様が支払う前に**Cancel on terminal**を押します。端末自体に**CANCEL**が表示されている間だけ操作できます。表示されていない場合、レジには*現在、端末からキャンセルできません。端末でキャンセルしてください。*と表示されます。

キャンセルは要求を送る操作です。カード情報がすでに読み取られている場合、決済が完了することがあります。レジには**Cancelling — waiting for the terminal to confirm**と表示され、結果が出るまで確認が続きます。別の方法で支払いを受け付ける前に、結果を待ってください。

レジが応答を受け取れない場合、**Release this payment**が表示されます。解放してもキャンセルされたことにはなりません。管理者がWindcaveポータルを確認し、注文に対する承認済み決済がないと確認した後にだけ押してください。その後、別の方法で注文の支払いを受け付けられますが、店舗は端末の確認を続けます。

## 問題が発生した場合 {#goes-wrong}

### お客様が支払った可能性がある場合 {#may-have-paid}

:::warning 決済をもう一度受け付けないでください
次の2つのケースでは、カードに請求済みの可能性があります。管理者はまずWindcaveポータルで、注文番号から販売を確認してください。
:::

**端末の結果を確認できませんでした。再度支払いを受け付ける前にWindcaveを確認してください。** レジがすでに送信した決済を再確認しましたが、Windcaveから明確な回答を得られませんでした。管理者がポータルで販売を検索し、見つからなかった場合にだけ、もう一度支払いを受け付けてください。

**決済に失敗しました：端末で確認された金額が異なります。** 端末がレジから送られた金額とは異なる金額を承認したため、レジには記録されていませんが、カードに請求された可能性があります。別の決済を受け付けないでください。管理者にポータルで注文番号から販売を探し、端末で受け付けた金額と注文金額を比較してもらってください。

## Windcave決済を払い戻す {#refunds}

払い戻しは、販売を受け付けたStationを通じてWindcaveへ送信されます。全額または一部を払い戻せます。

1. POSで注文の払い戻しを開きます。[払い戻し](../../pos/refunds.mdx)をご覧ください。
2. **Refund to Windcave Terminal**を選び、**Process Refund**を押します。
3. 店舗はWindcaveの応答を最大20秒待ち、その結果を注文メモに追加します。

WooCommerceの**Refund … via Windcave Terminal**ボタンを使ったWP Adminからの払い戻しも、同じように処理されます。

払い戻しが**pending**のままの場合は、もう一度払い戻す前にWindcaveポータルで確認してください。

<Accordion>
  <AccordionItem question="払い戻しが保留中のままになる">

  Windcaveが20秒以内に応答しなかったか、要求と異なる金額を承認しました。店舗は再試行しません。Windcaveポータルで払い戻しを確認してください。処理済みならお客様に返金されています。未処理なら、もう一度払い戻してください。

  </AccordionItem>
  <AccordionItem question="バージョン0.1で受け付けた販売を払い戻せない">

  払い戻しが停止し、*この販売を払い戻す前にPOS設定で既定のStationを設定してください。*と表示されます。拡張機能のバージョン0.1は販売を受け付けたStationを記録しなかったため、バージョン1.0では店舗全体の既定Stationを使って払い戻します。現在、各レジは**Settings > Card readers**でStationを選びますが、WCPOS 2.0には店舗全体の既定値がまだありません。Windcaveポータルまたは端末で販売を払い戻し、WooCommerceでは**Refund … manually**を使って記録してください。

  </AccordionItem>
</Accordion>

## Windcave Terminalを設定する {#setup}

管理者が店舗ごとにWP Adminで一度設定し、その後、各レジでStationを選びます。店舗から各端末にはインターネット経由でWindcaveを通じて接続するため、ペアリングは不要です。どのレジからでも任意の端末を使えます。

### 要件 {#requirements}

HIT認証情報（**HIT username**と**HIT key**）と、各端末の**Station ID**が必要です。これらはすべてWindcaveが発行し、WP Adminから検索したり作成したりすることはできません。Windcaveに連絡して、**UAT**用HIT認証情報と各端末のStation IDを依頼するか、開発用アカウントにはWindcaveの[Integration Requirementsフォーム](https://www.windcave.com/merchant-attended-developer-hit)を利用してください。UATと本番環境にはそれぞれ別のユーザー名とキーが必要です。連携の認証後、Windcaveから**Vendor ID**が発行されます。

<RequirementsList>
  <RequirementItem label="Windcaveアカウント">HIT認証情報と端末ごとのStation ID。Windcaveが連携を認証するまではUAT認証情報を使用</RequirementItem>
  <RequirementItem label="端末">HIT決済に対応するWindcave端末</RequirementItem>
  <RequirementItem label="WCPOS">WCPOS Pro 2.0以降と、拡張機能のバージョン1.0以降</RequirementItem>
  <RequirementItem label="サーバー">WooCommerce、およびDOM拡張機能（php-xml）を備えたPHP 7.4以降</RequirementItem>
</RequirementsList>

### 拡張機能をインストールする {#install}

`WP Admin > POS > 設定 > 拡張機能`を開き、**Windcave Terminal for WooCommerce**を探してインストールし、有効化します。バージョン1.0以降が必要です。バージョン0.1はWCPOS 2.0より前のバージョン用です。[拡張機能](../../extensions/index.mdx#installing-an-extension)をご覧ください。

[GitHubリリースページ](https://github.com/wcpos/windcave-terminal-for-woocommerce/releases)から**プラグインzip**（ソースコードzipではありません）をダウンロードし、`プラグイン > Add Plugin > プラグインのアップロード`からアップロードすることもできます。

WCPOS Pro 2.0がない場合、WP Adminには*Windcave Terminal requires WooCommerce POS Pro 2.0 or newer.*と表示され、ゲートウェイは追加されません。PHP 7.4未満、またはDOM拡張機能がない場合は有効化できません。ホスティング会社に**php-xml**を有効にするよう依頼してください。

### HIT認証情報を入力する {#credentials}

`WP Admin > WooCommerce > 設定 > 支払い`に移動し、**Windcave Terminal**を開きます。

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[410, 0], [410, 0], [410, 0], [850, 0], [410, 0], [410, 0]]} maxWidth={720} alt="WP AdminのWindcave Terminal設定：環境はUAT（テスト）、HIT username、HIT key、Station IDs、Vendor IDは空欄、POS nameはWCPOS">

1. **Environment** — 既定の**UAT (testing)** のままにします。**Production**は、Windcaveによる連携認証後に本番用認証情報とともに使います。
2. **HIT username** — 選択した環境用にWindcaveから発行されたものです。
3. **HIT key** — Windcaveから発行されます。保存後はこの欄が空になります。保存済みのキーを保持する場合は、空欄のままにしてください。
4. **Station IDs** — 端末ごとに1つ、1行に1つ入力します。Windcaveが発行するもので、自動検出はされません。
5. **Vendor ID** — Windcaveから発行されるまでは空欄にします。
6. **POS name** — Windcave側で使われるPOSの名前です。既定値は`WCPOS`です。

</JourneyShot>

その下にある**Result notifications (FPRN)** は任意です。有効にすると、レジによる確認を補うため、結果が確定したときにWindcaveからも店舗へ通知されます。利用するには、サイトがインターネットからアクセス可能である必要があります。

**Save changes**をクリックします。

### WCPOSで有効にする {#enable}

`WP Admin > POS > 設定 > 支払い`を開き、**Gateways**テーブルから**Windcave Terminal**を探し、**Enabled**をオンにします。この画面では変更が随時保存されるため、保存ボタンはありません。

WooCommerce設定ページの**Enable/Disable**はオフのままにします。ここで**Enabled**をオンにすれば、そのチェックボックスの状態にかかわらず、POSでゲートウェイを使えます。[チェックアウト設定](../../settings/wp-admin/checkout.mdx#enabling-a-gateway)をご覧ください。

<JourneyShot manifest={manifest} device="desktop" step={2} offsets={[[172, 0], [-26, 0]]} maxWidth={720} alt="WP AdminのPOS設定、Checkout画面：Gatewaysテーブルの2行。Vipps MobilePayはオン、Windcave Terminalはオフ">

1. **Windcave Terminal** — **Gateways**テーブルにある拡張機能の行です。
2. **Enabled** — ゲートウェイIDの横にあるスイッチです。オンにすると、レジを再読み込みした後に**Windcave Terminal**タイルが表示されます。

</JourneyShot>

### 各レジのStationを選ぶ {#till-terminal}

各レジで**Settings > Card readers**を開きます。入力したStation IDはすべて**Smart readers**の下にリーダーとして一覧表示され、状態は**Online**です。拡張機能はWindcaveに端末の電源状態を問い合わせません。カウンターにあるStationの**Use this reader**を押します。その行に**Selected**と表示されます。レジ係はチェックアウト時に**Change**を押して変更することもできます。

Stationが1つだけの場合、選択は不要です。すべてのレジですでに**Selected**になっています。[スマートリーダーを選ぶ](../../hardware/card-readers/index.mdx#smart-readers)をご覧ください。

### 動作を確認する {#check}

1. Windcave Terminalの設定ページに戻ると、設定の下に`uat: HIT credentials configured (not verified).`と表示されます。ユーザー名とキーが保存されていることを示しますが、Windcaveがそれらを受け付けたことを意味しません。`HIT credentials missing.`は、どちらかが未入力であることを示します。
2. レジでPOSを再読み込みし、**チェックアウト**を押します。支払い方法の1つとして**Windcave Terminal**タイルが表示されます。タップすると、キーパッドの上にStation IDが表示されます。**Choose a terminal**の下、または**Terminal:** とそのレジで使う端末として表示されます。
3. UAT端末で少額の販売を行い、払い戻してください。接続テスト用のボタンはありません。この最初の販売で認証情報とStation IDを確認します。

### バージョン0.1からアップグレードする {#upgrade}

- まずWCPOS、WCPOS Pro、アプリを2.0に更新し、その後に拡張機能を更新します。
- アップグレード中の決済は引き継がれます。二重に請求されることはありません。
- バージョン0.1で保留にした決済は、注文が未払いのままであれば引き継がれます。それ以外の場合、注文には*Windcave TxnRef … was set aside before the 1.0.0 upgrade and is no longer followed automatically.*というメモが追加されます。Windcaveポータルで決済を確認してください。承認済みなら、ポータルで払い戻すか、注文に手動で記録してください。
- バージョン0.1の次の設定は削除されました：**Default Station ID**、**Lock terminal selection**、**Checkout logs**、**Log level**。現在、各レジは**Settings > Card readers**でStationを選びます。
- 保留機能も削除され、端末のレシートテキストは注文の非公開メモに追加されなくなりました。
- バージョン0.1で受け付けた販売の払い戻しについては、[Windcave決済を払い戻す](#refunds)をご覧ください。

## 設定リファレンス {#settings}

`WP Admin > WooCommerce > 設定 > 支払い > Windcave Terminal`を開きます。

| 設定 | 機能 |
|---|---|
| **Enable/Disable** | オンラインストアのチェックアウトでゲートウェイを利用可能にします。オフのままにしてください。POSには`POS > 設定 > 支払い`に専用のスイッチがあります |
| **Title** | レジに表示されるタイル名です。既定値は`Windcave Terminal`です |
| **Description** | 既定値は`Pay in person on the Windcave terminal.`です |
| **Environment** | **UAT (testing)**（既定）または**Production**です。それぞれに専用のHIT認証情報があり、本番環境にはWindcaveの認証が必要です。決済は開始時の環境で常に確認されます |
| **HITユーザー名** | 選択した環境用にWindcaveから発行されます |
| **HIT key** | Windcaveが発行します。保存後は表示されません。保持する場合は空欄のままにしてください |
| **Station IDs** | 端末ごとに1つ、1行に1つ入力します。重複は削除されます |
| **Vendor ID** | 認証時にWindcaveと取り決めます。それまでは空欄にしてください |
| **POS名** | Windcave側で使われるPOSの名前です。既定値は`WCPOS`です |
| **結果通知（FPRN）** | レジ側の確認を補うため、結果が確定した際にWindcaveからも店舗へ通知します。既定ではオフです |

## ログとサポートバンドル {#logs-and-support-bundle}

設定ページの下部には、サポートバンドル、認証情報の状態、ログへのリンクがあります。

<JourneyShot manifest={manifest} device="desktop" step={3} offsets={[[200, 0], [80, 0], [-20, 0]]} maxWidth={720} alt="まだ設定されていない店舗のWindcave Terminal設定ページ下部にあるWP Admin画面：Download support bundleボタン付きのSupport bundle、uat: HIT credentials missingの表示、View logs">

1. **Credentials line** — この未設定の店舗では`HIT credentials missing.`と表示されます。設定済みの場合は`HIT credentials configured (not verified).`と表示されます。
2. **View logs** — `WooCommerce > Status > ログ`を開きます。ソースは`windcave-terminal`です。
3. **Download support bundle** — WCPOSサポートに送るファイルです。

ログにはWindcaveへの各リクエストと応答が記録されます。HITキーとカード番号はマスキングされます。

決済に問題が起きた場合は、**Download support bundle**をクリックしてファイルを**order number**とともにWCPOSサポートへ送ってください。このボタンはWCPOS Proで追加されます。バンドルにはサイト上のすべてのPOS決済プロバイダーが含まれ、秘密情報とカード番号は削除されます。

## 対応していない機能 {#scope-and-limitations}

- Windcaveが連携を認証するまでの実決済。
- チップ、追加料金、キャッシュアウト、またはオーソリ後に後から売上を確定する処理。
- **Payments**タブで端末からの質問に回答すること。**Legacy**タブを使ってください。
- 端末の自動検出。ステーションIDは1つずつ入力します。
- 最初の決済前にHIT認証情報を確認すること。

<details>
<summary>開発者向けの仕組み</summary>

このゲートウェイはHTTPS経由でWindcaveの**HIT（Host Initiated Transaction）** を使用します。UATには`uat.windcave.com`、本番環境には`sec.windcave.com`を使います。各端末は**Station ID**で指定します。

決済では、レジの金額と、加盟店参照としての`Order #`および注文番号を含むPurchaseが送信されます。その後、WCPOS Proは完了まで状態を確認します。レジが再度要求した場合、拡張機能は別のPurchaseを開始せず、同じ取引参照を先に照会します。Windcaveに30秒以内に登録されないPurchaseは、未送信として扱われます。

**Result notifications (FPRN)** を有効にすると、各PurchaseでWindcaveに店舗のWCPOS決済Webhookを呼び出すよう要求します。Webhookは`wp-json/wcpos/v2/payments/webhook`で、`provider=windcave`と取引参照を含みます。この呼び出しは通知にすぎず、その後、店舗がWindcaveに結果を直接問い合わせます。

払い戻しは、入力した金額について元のWindcave取引に照合するHIT matched Refundです。店舗は最大20秒間、2秒ごとに状態を確認します。

</details>
