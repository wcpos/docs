POS は、商品、顧客、未完了の注文をデバイスに保存します。インターネット接続が切れたり、ショップが応答しなくなったりしても、接続が切れる前にショップに届いていた販売であれば、現金、別途お使いの決済端末で処理したカード決済、その他レジで記録する支払いを受け付け、販売を続けられます。各販売データはデバイスで待機し、ショップへの接続が復旧すると自動で送信されます。このページでは、接続が切れてから復旧するまで、オフラインで行う販売の流れを説明します。

## オフラインになったことを確認する {#offline-signs}

接続が切れても操作は不要です。POS が通知するので、そのまま作業を続けられます。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[60, 14], [-16, 0], [150, 0], [0, 0], [10, 0]]} alt="カートに商品が 1 点入ったオフラインの POS。レジバーの店舗名の横にあるオフライン表示、デバイスがオフラインになりましたというメッセージ、検索ボックス、チェックアウトボタン、稼働状況ボタンが表示されています">

1. **オフライン** — レジバーの店舗名の横に表示されます。デバイスがインターネットに接続していても、ショップが応答しない場合は**オフライン**と表示されます。他の画面（注文、商品、顧客）でも、ページバーに同じ**オフライン**バッジが表示されます。
2. **デバイスがオフラインになりました** — 接続が切れて数秒経つと表示されます。**ヘルプ**を押すと、メッセージの意味を確認できます。ショップが応答しなくなった場合は、**ウェブサイトに接続できません**と表示されます。
3. **商品を検索** — デバイスに保存された商品を検索するため、ダウンロード済みの商品は引き続き検索して販売できます。
4. **チェックアウト** — 販売内容の作成は通常どおり行えます。オフラインで開始した販売は、ショップへの接続が復旧するまで支払いを受け付けられず、未完了の注文として待機します。ショップにすでに届いている販売では、支払い方法によって異なります。[オフラインで支払いを受け付ける](#take-payment-offline)をご覧ください。
5. **稼働状況** — [ショップの稼働状況](../support/store-health.mdx)を開きます。デバイスに保存されているデータや、送信待ちのデータを確認できます。

</JourneyShot>

## 引き続き使える機能 {#what-works-offline}

- **商品と顧客の検索** — デバイスに保存されたデータを対象に、検索、絞り込み、スキャンを利用できます。
- **カートの作成** — 商品の追加、数量と価格の変更、割引や手数料の追加、デバイスに保存済みのクーポンコードの適用、[未完了の注文](../pos/cart/open-orders.mdx)の切り替えができます。
- **支払いの受け付け** — **現金**、別途お使いの決済端末で処理した支払いを記録する**カード**、代金引換、銀行振込、小切手など、レジで記録するその他の支払い方法が使えます。いずれもショップにすでに届いている販売が対象です。[オフラインで支払いを受け付ける](#take-payment-offline)をご覧ください。
- **レシート** — 支払い済み画面の表示、レジに接続されたプリンターでの印刷、メールの送信予約ができます。
- **レジ** — 売上は通常どおりドロアーに記録されます。他のレジ係への引き継ぎやレジの切り替えもできます。
- **変更の保存** — 新しい顧客、編集した注文、レシートメールは、それぞれデバイスに保存され、後から送信されます。

## オフラインで支払いを受け付ける {#take-payment-offline}

:::warning ショップにすでに届いている販売のみ
オフラインで支払いを受け付けられるのは、接続が切れる前にショップに届いていた販売だけです。該当する販売は、チェックアウト画面の商品一覧の上に注文番号が表示されます。オフラインで開始した販売には、まだ番号がありません。**チェックアウト**を押すと、支払い方法の代わりに**接続がありません**と表示されます。販売は未完了の注文として保存され、タブには**チェックアウト中 · オフライン**と表示されます。**レジに戻る**を押して次の顧客に対応し、ショップへの接続が復旧してから支払いを受け付けてください。[接続がありません](../pos/checkout/troubleshooting.mdx#no-connection)をご覧ください。
:::

1. **チェックアウト**を押し、商品一覧の上に **#224371** などの注文番号があることを確認します。
2. **現金**、別途お使いの決済端末で処理した支払いを記録する**カード**、またはレジで記録するその他の支払い方法をタップします。
3. 顧客から受け取った金額を入力するか、ちょうどの金額をタップします。
4. **受け取る**を押し、確認します。

オフライン時は、支払いパネルの金額の横に**オフライン**と表示され、各支払い方法に今すぐ受け付けられるかどうかが表示されます。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[60, 14], [0, -32], [0, -32], [-18, 4], [-18, 4], [440, 0]]} alt="オフラインの支払いパネル。支払い金額の横にオフライン、現金とカードの各タイルに後で送信とショップが拒否する場合がありますが表示され、現金で $45.00 を受け取るボタンがあります">

1. **オフライン** — レジバーに引き続き表示されます。
2. **現金** — レジで受け取るため、オフラインでも利用できます。
3. **カード** — 別途お使いの決済端末で処理し、レジで記録するカード決済もオフラインで利用できます。レジとペアリングしたカードリーダーやオンライン決済ゲートウェイは、**… 現在利用できません**の下に**接続が必要です**と表示されます。
4. **後で送信 · ショップが拒否する場合があります** — 支払いはその場で記録され、ショップへの接続が復旧すると送信されます。ショップはその時点で内容を確認します。
5. **後で送信 · ショップが拒否する場合があります** — カード決済も同様です。
6. **現金で $45.00 を受け取る** — 通常どおり、金額と支払い方法が表示されます。

</JourneyShot>


**受け取る**を押すと、POS に確認画面が表示されます。この支払いがまだショップに届いていないためです。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[80, -60], [-24, 0], [0, -26], [0, -26]]} alt="暗くなった支払いパネルの上に表示される確認画面。オフラインで現金 $45.00 を受け取りますか？という質問と、キャンセル、現金で $45.00 を受け取るの各ボタンがあります">

1. **質問の背後** — 支払いパネルは暗くなって待機します。選択するまで支払いは受け付けられません。
2. **オフラインで … を受け取りますか？** — 販売データはこのデバイスに保存され、ショップへの接続が復旧すると送信されます。ショップが拒否した場合は、[注文](../orders/index.mdx)の**要対応**に表示されます。
3. **キャンセル** — 支払いを受け付けずに支払いパネルに戻ります。
4. **現金で $45.00 を受け取る** — 支払いを記録します。通常どおり釣銭を渡してください。

</JourneyShot>

## ショップが確認する前のレシート {#awaiting-store}

支払いは完了しています。販売データがショップに届くまでは、支払い済み画面とレシートの両方に、その状態が表示されます。

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[62, 0], [-30, 0], [80, 16], [0, -28], [0, -28], [0, -28], [0, -28]]} alt="オフラインの支払い済み画面。チェックマークの代わりに時計、ショップの確認待ち · 現金、レジバーにオフライン · 送信待ちの販売 1 件が表示され、レシートをメール送信、PDF をダウンロード、レシートを印刷、新しい販売の各ボタンがあります">

1. **時計** — 支払いは完了していますが、ショップではまだ確認されていません。販売データがショップに届くと、通常のチェックマークに変わります。
2. **ショップの確認待ち** — 使用した支払い方法の前に表示されます。未完了の注文のタブには**支払い済み · ショップの確認待ち**、カート内の支払いには**オフラインで記録済み**と表示されます。
3. **オフライン · 送信待ちの販売 1 件** — ショップへの送信を待って、このデバイスに保存されている販売の件数です。
4. **レシートを印刷** — レジに接続されたプリンターで印刷します。レシートには**ショップの確認待ち · 未確認**という行が入ります。ショップ側のデータを印刷するプリンターは待機し、ショップが販売を確認した後に再度印刷するよう案内されます。[レシートを印刷](../receipts/at-checkout.mdx#print-receipt)をご覧ください。
5. **レシートをメール送信** — 引き続き利用できます。メールは送信待ちになります。詳しくは以下をご覧ください。
6. **PDF をダウンロード** — ショップへの接続が必要なため、グレー表示になります。
7. **新しい販売** — 次の顧客用に空のカートを開きます。

</JourneyShot>

プレビューに**この注文ではこのテンプレートをプレビューできません**と表示されることがあります。ショップ側のテンプレートがショップへの接続を待っているためで、印刷されるレシートには影響しません。

この状態でも、**レシートをメール送信**を押せば顧客へのレシート送信を予約できます。

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[-18, 0], [0, -28]]} alt="オフラインのレシートメール送信フォーム。接続が復旧したらレシートがメール送信されるという案内と、オンライン時に送信ボタンがあります">

1. **このデバイスは現在ショップに接続できません** — 接続が復旧すると、レシートが自動的にメール送信されます。
2. **オンライン時に送信** — **送信**の代わりに表示されます。押すと、**レシートメールを送信待ちに追加しました**と表示されます。[レシートをメール送信](../receipts/at-checkout.mdx#email-receipt)をご覧ください。

</JourneyShot>

## 送信待ちの販売 {#offline-writes}

販売の途中で接続が切れたり、アプリを閉じたりしても、オフラインで行った操作はすべてこのデバイスに保存されます。ログイン済みでショップに接続できる状態になると自動送信されるため、ボタンを押す必要はありません。レジバーの端にある自分のアバターをタップすると、送信待ちの内容を確認できます。

<JourneyShot manifest={manifest} device="tablet" step={6} offsets={[[0, 0], [-30, 0]]} alt="オフラインのレジ係シート。ショップの確認待ち · 販売 1 件の帯、オンラインでログインしているときに送信の表示、切り替えにはショップへの接続が必要ですと表示された店舗の行があります">

1. **ショップの確認待ち · 販売 1 件** — このデバイスで受け付けたものの、ショップにはまだ届いていない販売です。**オンラインでログインしているときに送信**されるため、ボタンを押す必要はありません。
2. **切り替え** — グレー表示になり、**切り替えにはショップへの接続が必要です**と表示されます。店舗の切り替えは接続の復旧を待つ必要があります。レジの引き継ぎ、レジの切り替え、ログアウトは引き続き行えます。

</JourneyShot>

レジバーには、次のように表示されます。

- **オフライン** — 接続がなく、送信待ちの販売もありません。
- **オフライン · 送信待ちの販売 1 件** — 接続がなく、送信待ちの販売があります。
- **販売 1 件がショップの確認待ち** — 接続は復旧しましたが、これらの販売についてショップからまだ応答がありません。

次の表示が出ることもあります。

- **販売 1 件が同期待ち** — ショップが再ログインを求めたときに、バナーに表示されます。[ログインとドロアー](#goes-wrong-sign-in)をご覧ください。
- **ここで待機します** — 送信待ちの販売が残った状態でレジを引き継ぐと、未送信の販売件数とともに表示されます。販売データはこのデバイスに保存され、ログインしてオンラインに戻ると送信されます。
- **送信待ちの変更** — [ショップの稼働状況 → データベース](../support/store-health.mdx#database)に表示されます。顧客、編集内容、レシートメールなど、まだこのデバイスに残っているすべての変更が含まれます。

:::warning 送信待ちの変更があるときはローカルデータを消去しないでください
[ローカルデータを消去](../support/troubleshooting/clear-local-data.mdx)すると、ショップに届いていない変更がすべて失われます。オフラインで受け付けた販売の代金は、すでにドロアーに入っているお金です。
:::

## 接続が復旧したら {#back-online}

送信待ちの販売は自動的に送信されます。通常は数秒以内に完了します。

画面上部に**接続が復旧しました**と表示されます。レジバーには、すべての販売データがショップに届くまで**販売 1 件がショップの確認待ち**と表示され、その後消えます。カードリーダー、オンライン決済ゲートウェイ、および[接続が必要な機能](#what-requires-a-connection)で挙げたすべての機能が再び使えるようになります。

オフラインの間にショップ側で変更された商品、価格、顧客は、オンラインに戻ってからまもなく自動的にダウンロードされます。すべての販売データが届いたことを確認するには、[ショップの稼働状況 → データベース](../support/store-health.mdx#database)を開いてください。**送信待ちの変更**が 0 で、表の上に判断を求めるパネルがなければ完了です。[対応が必要な場合](../support/store-health.mdx#needs-attention)をご覧ください。

## 接続が必要な機能 {#what-requires-a-connection}

- **レジとペアリングしたカードリーダーとオンライン決済ゲートウェイ** — タイルに**接続が必要です**と表示されます。販売にすでに注文番号がある場合は、現金を受け取るか、別途お使いの決済端末で処理したカード決済を記録してください。番号がない場合は注文を開いたままにし、ショップへの接続が復旧してから支払いを受け付けてください。カードリーダーを使ったオフライン決済は[ロードマップ](roadmap.mdx)に含まれています。
- **オフラインで開始した販売の支払い** — 販売は未完了の注文に残ります。ショップへの接続が復旧したら支払いを受け付けてください。[上記の注意事項](#take-payment-offline)をご覧ください。
- **レガシータブ** — 専用の支払いページを使う決済ゲートウェイです。[レガシータブ](../pos/checkout/legacy-tab.mdx)をご覧ください。
- **払い戻し** — オフラインでは払い戻しを行えません。[払い戻し](../orders/refunds.mdx)をご覧ください。
- **新しいクーポンの作成**（WCPOS Pro）— ボタンに**ショップに接続できるときにクーポンを作成できます**と表示されます。
- レシートの **PDF をダウンロード**。
- **店舗の切り替え**と、デバイスへの**レジ係の追加**。すでにデバイスに登録されているレジ係への引き継ぎは、オフラインでも行えます。
- 別の店舗への**ドロアーの持ち越し**。送信待ちの販売を先に送信する必要があります。送信が完了するまで、選択肢には、たとえば**先に販売 2 件を送信してください**と表示されます。
- レジ締め時の**差額がある現金確認の承認**。[レジを開く](../pos/register/index.mdx#goes-wrong)をご覧ください。
- ショップからの**新しい商品、価格、顧客**の取得。接続が復旧するまでは、デバイスに保存されたデータを使って販売します。

:::tip 接続が不安定な場所で勤務を始める前に
通信状態がよいうちに POS を開き、商品カタログをダウンロードしておいてください。[ショップの稼働状況 → データベース](../support/store-health.mdx#database)で、デバイスに保存済みの量を確認できます。
:::

## 問題が発生した場合 {#goes-wrong}

メッセージが表示された販売の段階に該当する項目で、レジに表示されているメッセージを探してください。

### スキャン {#goes-wrong-scanning}

**「スキャンを利用できません」— このデバイスにデータがなく、オフライン中はショップを検索できません。** その商品はまだこのデバイスに保存されていません。商品名で検索するか、接続が復旧してから販売してください。**状態を表示**を押すと、[ショップの稼働状況](../support/store-health.mdx#database)が開きます。[バーコードスキャン](../pos/product-panel/barcode-scanning.mdx)をご覧ください。

**「検索に失敗しました」— ショップが応答しませんでした。** デバイスはインターネットに接続していますが、スキャンに対してショップから応答がありませんでした。接続を確認して、再度スキャンしてください。

### チェックアウトと注文 {#goes-wrong-checkout}

**「注文は保存されませんでした — ショップが拒否しました」。** ショップが注文を拒否し、タイトルの下に理由が表示されています。販売はカートに戻り、タブに**保存が拒否されました**と表示されます。在庫切れの商品など、ショップが示す問題を修正し、もう一度**チェックアウト**を押してください。**ショップの稼働状況**を押すと拒否された変更が開き、**再送信**と**破棄**を選べます。[サーバーに届かなかった変更](../support/store-health.mdx#refused-changes)をご覧ください。

**「この注文はまだショップに送信中です」。** 少し待ってから、もう一度**チェックアウト**を押してください。請求はまだ行われていません。また、ショップは同じ注文として認識するため、注文が重複して作成されることはありません。

**「… はショップに保存されませんでした」。** オフラインで追加した顧客がショップに拒否されました。販売には住所が保持されますが、ゲストとしての販売のままになります。[ショップの稼働状況](../support/store-health.mdx#refused-changes)から顧客データを再送信すると、販売がその顧客に紐づきます。

**注文の「要対応」に表示される販売。** オフラインで受け付けた支払いがショップに拒否されました。注文を開き、顧客と精算してください。[注文](../orders/index.mdx)をご覧ください。

### ログインとドロアー {#goes-wrong-sign-in}

**「セッションの有効期限が切れました」または「販売 1 件が同期待ち」。** このデバイスからのデータをショップが引き続き受け付けるには、再ログインが必要です。**ログイン**を押してください。データは失われていません。ログインすると、未送信の販売が送信されます。**セッションが自動更新されました**と表示された場合は、POS が自動的に再ログインしたため、操作は不要です。

**「ドロアーを持ち越しました。このデバイスには次回の同期時に記録されます。」** ドロアーを別の店舗に持ち越した情報が、ショップに届いています。操作は不要です。代わりに**ドロアーの持ち越しが完了しませんでした**と表示された場合は、再試行する前に両方のレジを確認してください。

### レシート {#goes-wrong-receipts}

**「サーバーがメールを送信しませんでした。」** ショップはレシートメールを受け取りましたが、送信しませんでした。送信待ち、または再試行が停止したレシートメールは、[ショップの稼働状況 → データベース](../support/store-health.mdx#database)の**送信待ちのレシートメール**に表示され、それぞれ**再送信**と**削除**を選べます。

レシートに **「ショップに未保存 · 注文番号なし」** と表示される場合。この販売はまだ一度もショップに届いていないため、注文番号がなく、レシートもまだメール送信できません。**注文を同期**を押して送信してください。

:::info WCPOS Pro の場合
複数の店舗がある場合、店舗の切り替えには接続が必要です。接続が復旧するまで、店舗の行に**切り替えにはショップへの接続が必要です**と表示されます。
:::
