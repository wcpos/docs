ブラウザでは接続の設定は不要です。POS はご自身のサイト上で動作します。デスクトップアプリとモバイルアプリでは、最初に **接続** 画面が表示されます。そこで店舗を一度追加し、WordPress アカウントでサインインして POS を開きます。

## ブラウザで POS を開く {#web}

`yourdomain.com/pos` にアクセスし、WordPress のユーザー名とパスワードでサインインすると、すぐに POS が開きます。

デフォルトのアドレスは `pos` です。変更するには、管理者が WP Admin の **設定 › パーマリンク** を開き、**オプション** の **POS ベース** に入力します。`pos` のままにする場合は空欄にします。

ブラウザで **サインアウト** すると、WordPress からもサインアウトします。

## アプリで店舗に接続する {#adding-a-new-store}

1. **店舗のアドレス** に `mystore.com` などの店舗のアドレスを入力し、**接続** を押します。アプリには **店舗を検索中…**、**WordPress を確認中…**、プラグインの確認、**保存中…** の順に進行状況が表示されます。
2. 店舗カードの **WordPress でサインイン** を押すと、店舗のログインウィンドウが開きます。WordPress のユーザー名とパスワードでサインインします。
3. 接続画面に戻ります。**WordPress ユーザー** に自分の名前が表示され、その横に **サインイン済み** と表示されます。
4. **店舗** には、すでに店舗が選択されています。WCPOS Pro で複数の店舗がある場合、見出しは **店舗を選択** になります。販売する店舗を選んでください。
5. **POS を開く** を押します。

アドレスに接続できない場合、**接続** の下に理由が赤字で表示されます。エラーコードのページへの **詳細を見る** リンクが表示されることもあります。[問題が発生した場合](#troubleshooting)を参照してください。

アプリを初めて開いたときは、アドレスだけを入力します。

1. **店舗のアドレス** — アドレスを入力する欄です。
2. **接続** — 下に確認状況が表示され、問題があれば赤字で表示されます。
3. **デモ店舗を試す** — 自分の店舗がなくても操作を試せます。[デモ店舗を試す](#demo-store)を参照してください。

</JourneyShot>

**接続** を押すと、店舗カードが表示されます。この時点では、まだ誰もサインインしていません。

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[-35, 0], [63, 0], [115, 0], [130, 0]]} alt="接続後の接続画面。店舗カードに名前とアドレス、「WordPress ユーザー」の下に「WordPress でサインイン」、さらに下に「別の店舗に接続」と「デモ店舗を試す」が表示されています">

1. **WordPress でサインイン** — ログインウィンドウを開きます。
2. **アクション** — **サイトを削除** があります。[1 台のデバイスで複数の店舗を使う](#multiple-stores)を参照してください。
3. **別の店舗に接続** — このデバイスに別の店舗を追加します。
4. **デモ店舗を試す** — 接続後もここに表示されます。

</JourneyShot>

サインインすると、カードに自分と店舗の情報、**POS を開く** が表示されます。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[-35, 0], [-35, 0], [-35, 0], [-35, 0], [453, 0], [63, 0], [115, 0], [130, 0]]} alt="サインイン後の接続画面。店舗カードの「WordPress ユーザー」にサインイン済みの Demo Cashier、「別のユーザーを追加」、AL 12345 Store が選択された「店舗を選択」、「POS を開く」ボタンが表示され、カードの下に「別の店舗に接続」と「デモ店舗を試す」があります">

1. **WordPress ユーザー** — 自分の名前と、その横に **サインイン済み** が表示されます。名前をタップして販売担当者を選びます。
2. **店舗を選択** — 販売する店舗です。
3. **POS を開く** — 選んだユーザーとして、その店舗の POS を開きます。
4. **別のユーザーを追加** — このデバイスで別のレジ係をサインインさせます。[1 つの店舗を複数のレジ係で使う](#multiple-users-per-store)を参照してください。
5. **×** — このデバイスからそのユーザーを削除します。
6. **アクション** — **サイトを削除** があります。
7. **別の店舗に接続** — 別の店舗を追加します。
8. **デモ店舗を試す** — WCPOS のデモ店舗です。

</JourneyShot>

## 1 台のデバイスで複数の店舗を使う {#multiple-stores}

店舗の下にある **別の店舗に接続** を押して、次の店舗を追加します。複数の店舗がある場合は **サイト一覧** に表示され、一度に開けるのは 1 つです。各店舗には名前、アドレス、**2 人のユーザー** などのサインイン人数が表示されます。店舗をタップして開きます。

このデバイスから店舗を削除するには、カードの **アクション** メニューを開き、**サイトを削除** を選んで **削除** で確定します。**店舗と関連するユーザーを削除しますか？** と確認され、その店舗にサインインしている全員がこのデバイスからサインアウトします。店舗自体には何も変更されません。

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[-35, 0], [305, 0], [63, 0], [142, 0], [-35, 0], [115, 0]]} alt="店舗が 2 つあるサイト一覧。最初のカードは閉じており、名前、アドレス、1 人のユーザーが表示され、アクションメニューの「サイトを削除」が開いています。次のカードは開いており、ユーザー、店舗、「POS を開く」が表示され、その下に「別の店舗に接続」があります">

1. **閉じている店舗** — タップすると開き、現在開いている店舗は閉じます。
2. **1 人のユーザー** — このデバイスでその店舗にサインインしている人数です。
3. **アクション** — その店舗のメニューです。
4. **サイトを削除** — 確認後、このデバイスから店舗を削除します。
5. **開いている店舗** — ユーザー、店舗、**POS を開く** が表示されます。
6. **別の店舗に接続** — 店舗をもう 1 つ追加します。

</JourneyShot>

## 1 つの店舗を複数のレジ係で使う {#multiple-users-per-store}

販売を担当する各ユーザーは、自分の WordPress アカウントでサインインします。

- **レジ係を追加する。** **WordPress ユーザー** の下にある **別のユーザーを追加** を押してサインインすると、そのレジ係が一覧に加わります。
- **販売担当者を選ぶ。** 名前をタップすると、選んだユーザーに応じて店舗と **POS を開く** が切り替わります。
- **再度サインインする。** 名前に **再度サインイン** と表示されているユーザーは、店舗側でサインアウトされています。ログインの有効期限が切れたか、管理者が[セッション](../settings/wp-admin/sessions.mdx#signing-devices-out)で終了したためです。その行の **再認証** を押し、そのユーザーとしてサインインします。
- **レジ係を削除する。** その行の **×** を押し、**削除** で確定します。このデバイスから削除されるだけで、サーバー上の情報は変更されません。

:::note 選んだ行のユーザーとしてサインインしてください
**再認証** で別のユーザーとしてサインインすると、**別のユーザーとしてサインインしました** と表示されます。そのユーザーは一覧に追加されますが、選んだユーザーはサインアウトしたままです。もう一度 **再認証** を押し、選んだユーザーのアカウントでサインインしてください。
:::

## 別のレジ係にレジを引き継ぐ {#switching-users}

POS を開いた後は、レジ係パネルで担当者を交代します。レジバーの端にある自分のアバターをタップしてください。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[182, -19], [0, 0], [-75, 0], [0, -30], [0, -30], [90, 0]]} alt="POS のレジ係パネル。「レジの引き継ぎ先」とその下の「別のアカウント」、店舗と「切り替え」ボタン、「WordPress 管理画面」と「デスクトップアプリ」のリンク、「サインアウト」が表示されています">

1. **レジの引き継ぎ先** — このデバイスにサインインしている他のレジ係と、それぞれが開いているカートの数が表示されます。レジ係を選んで **… に引き継ぐ** を押すと、そのユーザーとして POS が再読み込みされます。開いているレジはそのままです。自分の未完了のカートと未送信の売上はここに残ります。この例では、まだ他のユーザーはサインインしていません。
2. **別のアカウント…** — このデバイスで新しいユーザーをサインインさせます。そのユーザーは上の一覧と接続画面に追加されます。
3. **切り替え** — 店舗が複数ある場合に、別の店舗へ移動します（WCPOS Pro）。[店舗とレジの選択](../stores/registers-and-devices.mdx#choosing-a-store-and-a-register)を参照してください。
4. **WordPress 管理画面** — サイトの WP Admin を開きます。ブラウザでのみ利用できます。
5. **デスクトップアプリ** — デスクトップアプリのダウンロードページです。ブラウザでのみ利用できます。
6. **サインアウト** — アプリでは接続画面に戻り、ブラウザでは WordPress からサインアウトします。開いているレジは次のレジ係のためにそのまま残るため、先に閉じるかどうかを POS が確認します。[レジ係パネル](../pos/register/index.mdx#cashier-sheet)を参照してください。

</JourneyShot>

支払い処理中（**先に支払いを完了してください**）、またはドロアー内の現金を集計中（**先に集計を完了または中止してください**）は引き継ぎできません。

## デモ店舗を試す {#demo-store}

接続画面の下部にある **デモ店舗を試す** を押すと、アプリが WCPOS のデモ店舗に接続し、ログイン画面を開きます。自分の店舗に影響を与えずに操作を試せます。

## 問題が発生した場合 {#troubleshooting}

メッセージが表示されたタイミングに該当する項目を確認してください。

### 接続中またはサインイン中 {#while-connecting}

<Accordion>
  <AccordionItem question="ログインが完了しませんでした。">

  サインイン処理がアプリまで戻りませんでした。データは失われていません。未送信のデータはサインイン後に送信されます。もう一度 **WordPress でサインイン** または **再認証** を押してください。

  </AccordionItem>

  <AccordionItem question="ログインウィンドウにエラーまたは空白のページが表示される">

  通常は、サイトのセキュリティ、ファイアウォール、ログイン関連のプラグインが処理をブロックしています。[プラグインの競合](../support/troubleshooting/plugin-conflicts.mdx#security-and-login-plugins)を参照してください。

  </AccordionItem>

  <AccordionItem question="このサイトの WordPress REST API には認証が必要です">

  ウェブサイトの管理担当者に、この設定の確認を依頼してください。アプリには、ブロックしているプラグイン独自のメッセージが表示される場合もあります。たとえば、REST API はサインイン済みのユーザーのみ利用できる、というメッセージです。

  管理担当者向け：Force Login などのプラグインが、サインインしていないユーザーによる REST API へのアクセスを禁止しているため、アプリが店舗の情報を読み取れません。そのプラグインで、サインインしていない訪問者にも REST API へのアクセスを許可してください。[プラグインの競合](../support/troubleshooting/plugin-conflicts.mdx#security-and-login-plugins)を参照してください。

  </AccordionItem>

  <AccordionItem question="このサイトは WordPress サイトではないようです">

  入力したアドレスで WordPress が見つかりませんでした。ブラウザでそのアドレスを開くと店舗が表示され、`yourdomain.com/pos` も動作することを確認してください。サイトの応答に時間がかかりすぎたというメッセージの場合は、サーバーを確認して再試行してください。

  </AccordionItem>

  <AccordionItem question="ローカルサイトやテストサイトに接続できない">

  アプリは、サイトのホームページが送信する `Link` ヘッダーから店舗を見つけます。このヘッダーは REST API を指しています。ヘッダーを読み取れない場合は、代わりに `yourdomain.com/wp-json/` を試します。どちらも失敗すると、**このサイトは WordPress サイトではないようです** と表示されます。

- このデバイスからアクセスできるアドレスを使ってください。`localhost` は常にデバイス自身を指すため、スマートフォンやタブレットからその名前でパソコン上の店舗にアクセスすることはできません。
- 同じデバイスのブラウザで `yourdomain.com/wp-json/` を開いてください。エラーやログインページではなく、サイトの REST API データが表示される必要があります。
- サイトで WCPOS が有効になっていることを確認してください。WCPOS は、アプリが `Link` ヘッダーを読み取れるようにするヘッダーを送信します。
- CORS または `Link` ヘッダーに関するメッセージは、サイトのクロスオリジン（CORS）ヘッダーに問題があることを示します。サーバーやプロキシに追加された CORS 処理が原因であることがよくあります。[HOST111](../error-codes/HOST111.mdx)を参照してください。

</AccordionItem>

  <AccordionItem question="このユーザーの店舗がありません">

  このアカウントで利用できる POS 店舗が見つかりませんでした。管理者が店舗を設定した後、再度サインインしてください。[店舗の設定](../stores/setup.mdx)を参照してください。

  </AccordionItem>
</Accordion>

### 更新が必要な場合 {#update-needed}

<Accordion>
  <AccordionItem question="このデバイスの POS アプリを更新してください。">

  サイトの WCPOS プラグインが、このアプリより新しいバージョンです。ブラウザでは **再読み込み** を押してください。デスクトップアプリやモバイルアプリでは、アプリを更新して開き直します。未送信の売上はデバイスに残ります。**ログアウト** も利用できます。接続画面でも店舗に同じメッセージが表示され、更新後に押す **再試行** があります。[SYNC341](../error-codes/SYNC341.mdx)を参照してください。

  </AccordionItem>

  <AccordionItem question="WordPress サイトの WCPOS プラグインを更新してください。">

  アプリが店舗のプラグインより新しいバージョンです。管理者が WP Admin の **プラグイン** を開いて WCPOS を更新した後、再度サインインしてください。それまでは **ログアウト** しかできません。接続画面の店舗カードにも、同じプラグインの更新を求める通知と **詳細を見る** が表示されます。[AUTH331](../error-codes/AUTH331.mdx)を参照してください。

  </AccordionItem>
</Accordion>

### 「POS を開く」を押した後 {#after-open-pos}

<Accordion>
  <AccordionItem question="この店舗にはレジがありません">

  この店舗はレジを使用する設定ですが、まだレジがありません。管理者が **WooCommerce › POS › 店舗** で追加します。管理者にはその画面に直接移動する **店舗を開く** ボタンが、レジ係には **レジガイド** が表示されます。追加後に **もう一度試す** を押してください。[レジ](../settings/wp-admin/registers.mdx)を参照してください。

  </AccordionItem>

  <AccordionItem question="この店舗のレジにアクセスできません">

  POS が店舗のレジ情報を読み取れませんでした。接続を確認してから **もう一度試す** を押してください。

  </AccordionItem>
</Accordion>

### 解決しない場合 {#still-stuck}

店舗が[サーバー要件](../support/performance/server.mdx#minimum-server-requirements)を満たしていることと、ホスティング側で REST API がブロックされていないことを確認してください。
