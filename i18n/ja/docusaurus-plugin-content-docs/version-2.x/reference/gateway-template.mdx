- **ゲートウェイの設定はお済みですか？** [レジでテスト決済を試してください](#at-the-till)。
- **ゲートウェイを作成するには？** このページは開発者向けです。[独自の POS 決済ゲートウェイを作成](#build)し、インストールして有効にする方法を説明します。

:::info Pro 機能
現金とカード以外のゲートウェイには [WCPOS Pro](../getting-started/pro-license.mdx) が必要です。WCPOS Pro がない場合も POS のレジ設定には表示されますが、有効にはできません。
:::

ゲートウェイテンプレートは、レジで使う独自の支払い方法を作成するためのひな形で、PHP ファイル1つで構成された WordPress プラグインです。セットアップスクリプトがゲートウェイ名を設定し、プラグインを生成します。オンラインストアのチェックアウトでは無効のままで、POS 設定で有効にすると POS に表示されます。

レジでは、チェックアウトの[レガシータブ](../pos/checkout/legacy-tab.mdx)にゲートウェイが表示されます。このタブは、ゲートウェイの WooCommerce 支払いページを POS 内で開きます。レジ係はそこでゲートウェイを選び、タブの下部にある **支払いを処理** を押します。

## レジで決済を試す {#at-the-till}

ゲートウェイを[作成して有効にする](#build)と、次の手順で決済できます。開発者がゲートウェイを作成・インストールし、レジ係が支払いを受け付けます。

レガシータブを使うには店舗のサイトに接続できる必要があります。また、注文全体を決済するため、その注文に対して一部でも支払いを受け付けた後は使用できません。[レガシータブ](../pos/checkout/legacy-tab.mdx)をご覧ください。

:::warning テスト注文を使用してください
変更を加えていないテンプレートは、実際には代金を回収せず、注文を支払い済みにするだけです。実際の顧客の販売ではなく、テスト注文で試してください。独自の決済処理は `process_payment()` に実装します。
:::

1. 店舗でレジセッションを使用している場合は、レジを開いてください。商品をカートに追加し、**チェックアウト** を押します。
2. 支払い画面の上部で、**支払い** の隣にある **レガシー** タブを開きます。
3. 支払いページでゲートウェイを選び、タブの下部にある **支払いを処理** を押します。
4. [支払い済み画面](../pos/checkout/index.mdx#paid)と同様に会計が完了してレシートが表示され、注文はゲートウェイの **注文ステータス** になります。以下のように設定した[後払いゲートウェイ](#pay-later)でも会計は完了しますが、注文は **支払い待ち** のままです。

<details>
<summary>開発者向け：POS が決済完了を判断する仕組み</summary>

**支払いを処理** を押すと支払いページが送信され、WooCommerce がゲートウェイの `process_payment()` を実行します。このメソッドが注文受付ページのアドレス `get_return_url( $order )` を返すと、POS は注文ステータスを確認します。

- **支払い済み（処理中または完了）、または POS のレジ設定で指定したゲートウェイの注文ステータス** — POS は会計を完了します。
- **それ以外** — POS は待機を続け、会計は未完了のままになります。

</details>

## ゲートウェイを作成する {#build}

### テンプレートを取得する {#get-template}

```bash
git clone https://github.com/wcpos/woocommerce-gateway-template.git
cd woocommerce-gateway-template
```

または、[GitHub リポジトリ](https://github.com/wcpos/woocommerce-gateway-template)の **このテンプレートを使用** を押して自分用のコピーを作成し、それをクローンします。

### セットアップスクリプトを実行する {#setup-script}

```bash
./create-gateway.sh
```

Bash スクリプトが次の項目を尋ねます。

- **ゲートウェイ名** — 唯一の必須項目です。例：`Cash Payment`。
- **ゲートウェイのスラッグ** — Enter を押すと、名前から生成された値(`cash-payment`)を使用します。使用できるのは小文字、数字、ハイフンのみです。
- **ゲートウェイの説明** と **チェックアウトでのデフォルトの説明** — 任意です。
- **GitHub ユーザー名**、**リポジトリ名**、**作成者名** — 任意です。リポジトリ名のデフォルトは、スラッグに `-gateway` を付けたものです。
- **出力先ディレクトリ** — プラグインの配置先です。デフォルトはテンプレートが入っているフォルダーです。

プラグインはリポジトリ名にちなんだフォルダー（例：`cash-payment-gateway/`）に生成され、その中に `wcpos-cash-payment.php` が配置されます。

### プラグインをインストールする {#install}

生成されたフォルダーをサイトの `wp-content/plugins/` ディレクトリにコピーします。または、フォルダーを zip に圧縮し、WordPress 管理画面の **プラグイン > 新規プラグインを追加** で **プラグインのアップロード** を押し、zip を選んで **今すぐインストール** を押します。

次にプラグインを有効化します。WooCommerce も有効である必要があります。無効の場合、このプラグインは何も読み込みません。

### POS で有効にする {#enable}

1. **WP Admin > POS > 設定 > レジ** に移動します。
2. **ゲートウェイ** 一覧から、設定した名前のゲートウェイを探します。**ゲートウェイ ID** は `wcpos_` に、ハイフンをアンダースコアに置き換えたスラッグを付けたものです。例：`wcpos_cash_payment`。
3. **有効** をオンにし、この方法で支払った会計の最終的な **注文ステータス** を選びます。[チェックアウト設定](../settings/wp-admin/checkout.mdx#payment-gateways)をご覧ください。

次回 POS を読み込むと、レガシータブにゲートウェイが表示されます。動作確認には、[レジで決済を試してください](#at-the-till)。

## プラグインファイルの内容 {#how-it-works}

このプラグインは WooCommerce の決済ゲートウェイクラスを1つ登録します。オンラインストアのチェックアウトでは無効のままで、注文を支払い済みにし（POS 販売ではゲートウェイの **注文ステータス** に設定）、POS を注文受付ページへ移動させます。

<details>
<summary>重要なコード</summary>

- コンストラクター内の **`$this->enabled = 'no';`** — WooCommerce の支払い設定で有効になっていても、オンラインストアのチェックアウトではゲートウェイを無効に保ちます。WCPOS は、POS のレジ設定で有効になっている場合に限り、POS からのリクエストに対してのみ有効にします。
- **`process_payment()`** — `$order->payment_complete()` を呼び出し、注文を支払い済みにして在庫を減らします。POS 注文では、WCPOS が POS のレジ設定にあるゲートウェイの **注文ステータス**（変更しなければ **完了**）を設定します。POS が待機している注文受付ページのアドレス `get_return_url( $order )` を返します。
- **`init_form_fields()`** — WooCommerce の支払い設定にある **タイトル** と **説明** のフィールドです。POS では、ゲートウェイのメニューにある **POS 設定** から POS 専用のタイトルを設定できます。

プラグインは独自のテキストドメインも読み込みます： `woocommerce-pos-<your-slug>-gateway`。対応する `.pot` ファイルの配置先は `languages/`です。

</details>

## ゲートウェイをカスタマイズする {#customise}

### レジ係に入力を求める {#payment-fields}

参照番号など、レジ係による入力が必要な場合は、コンストラクターに `$this->has_fields = true;` を設定し、`payment_fields()` メソッドを追加します。フィールドはレガシータブ内のゲートウェイの支払いページに表示されます。`process_payment()` で `$_POST['my_gateway_reference']` から値を読み取り、`sanitize_text_field( wp_unslash( ... ) )` でサニタイズします。

<details>
<summary>payment_fields() のコードを表示</summary>

```php
public function payment_fields() {
    if ( $this->description ) {
        echo wpautop( wptexturize( $this->description ) );
    }

    woocommerce_form_field( 'my_gateway_reference', array(
        'type'     => 'text',
        'label'    => __( 'Reference Number', 'your-text-domain' ),
        'required' => true,
    ) );
}
```

</details>

### 顧客が後払いできるようにする {#pay-later}

テンプレートは注文を直ちに支払い済みにします。請求書払いなど入金が後になるゲートウェイでは、`process_payment()` で注文を **支払い待ち** に設定してください。`payment_complete()` が呼び出されないため、在庫の減算も独自に行います。

<details>
<summary>process_payment() のコードを表示</summary>

```php
public function process_payment( $order_id ) {
    $order = wc_get_order( $order_id );

    if ( ! $order ) {
        return array( 'result' => 'failure' );
    }

    // The customer pays later.
    $order->update_status( 'pending', __( 'Awaiting payment', 'your-text-domain' ) );

    // payment_complete() is not called, so reduce stock here.
    wc_reduce_stock_levels( $order_id );

    return array(
        'result'   => 'success',
        'redirect' => $this->get_return_url( $order ),
    );
}
```

</details>

次に、**WP Admin > POS > 設定 > レジ** でゲートウェイの **注文ステータス** を **支払い待ち** に設定します。**支払い待ち** は支払い済みのステータスではないため、この設定をしないと POS は待機を続け、会計が未完了のままになります。[レジでの注文ステータスの扱い](../settings/wp-admin/checkout.mdx#order-status-at-the-till)をご覧ください。

<details>
<summary>プレースホルダーを手動で置き換える</summary>

スクリプトを実行しない場合は、GitHub の **このテンプレートを使用** を使い、すべてのファイルで次のプレースホルダーを検索して置き換えてください。

| プレースホルダー | 入力内容 | 例 |
|---|---|---|
| `{{GATEWAY_NAME}}` | ゲートウェイ名 | 現金払い |
| `{{GATEWAY_SLUG}}` | 小文字とハイフンを使用 | cash-payment |
| `{{GATEWAY_DESCRIPTION}}` | ゲートウェイの簡単な説明 | WCPOS で現金払いを受け付けます |
| `{{GATEWAY_DEFAULT_DESCRIPTION}}` | 支払いページに表示する説明 | 店頭で現金でお支払いください |
| `{{GITHUB_USERNAME}}` | GitHub ユーザー名 | kilbot |
| `{{REPO_NAME}}` | リポジトリ名 | cash-payment-gateway |
| `{{AUTHOR_NAME}}` | 作成者名 | kilbot |
| `{{GATEWAY_ID}}` | スラッグのハイフンをアンダースコアに置き換えたもの | cash_payment |
| `{{GATEWAY_CLASS_NAME}}` | 名前の各単語の先頭を大文字にしてアンダースコアでつないだもの | Cash_Payment |
| `{{GATEWAY_FUNCTION_PREFIX}}` | ゲートウェイ ID と同じ値 | cash_payment |

次に、`wcpos-{{GATEWAY_SLUG}}.php` をスラッグに合わせて変更します。例：`wcpos-cash-payment.php`。スクリプトを使う場合は、最後の3つの値が名前とスラッグから自動生成されます。

</details>

## 更新版をリリースする {#updates}

編集対象は `wcpos-<your-slug>.php`です。プラグインヘッダーの `Version:` の番号を上げ（例： `0.1.0` から `0.2.0`へ）、再インストールします。フォルダーの置き換え先は `wp-content/plugins/`です。または、新しい zip をアップロードします。WordPress はインストール済みのプラグインを置き換える前に確認を求めます。**現在のものをアップロードしたもので置き換える** を選んでください。

### GitHub での自動リリース {#github-releases}

生成されるプラグインには、GitHub Actions のワークフローが2つ含まれています。GitHub リポジトリにプッシュする場合は、次の手順でリリースできます。

1. プラグインヘッダーの `Version:` の番号を上げます。
2. コミットして `main` にプッシュします。
3. リリースワークフローは、そのバージョンに対応する `v<version>` タグがまだないことを検出すると、リリースを公開します。添付ファイルは `woocommerce-pos-<your-slug>-gateway.zip` です。

リポジトリの **リリース** ページから誰でも zip をダウンロードし、通常の WordPress プラグインと同じようにインストールできます。もう1つのワークフローは、`main` 上で PHP ファイルが変更されるたびに `.pot` 翻訳ファイルを再生成します。

## 問題が発生した場合 {#troubleshooting}

<details>
<summary>POS のレジ設定にゲートウェイが表示されない</summary>

**WP Admin > プラグイン** で、ゲートウェイのプラグインと WooCommerce が有効になっていることを確認してください。

</details>

<details>
<summary>ゲートウェイは表示されるが「有効」スイッチがグレー表示になっている</summary>

無料版で有効にできるのは **現金** と **カード** のみです。[WCPOS Pro](../getting-started/pro-license.mdx) を有効化してください。

</details>

<details>
<summary>レガシータブに表示されない</summary>

レジ側：注文に対してすでに支払いを受け付けている場合、その支払いを[キャンセル](../pos/checkout/cancelling-a-payment.mdx)するまでレガシータブは使用できません。

WP Admin 側：**WP Admin > POS > 設定 > レジ** で **有効** をオンにし、POS を再読み込みします。

</details>

<details>
<summary>支払い後に会計が完了しない</summary>

注文が支払い済みになっておらず、ゲートウェイの **注文ステータス** にもなっていません。

WP Admin 側：**WP Admin > POS > 設定 > レジ** で、ゲートウェイの **注文ステータス** を `process_payment()` が設定するステータスに合わせてください。

コード側：`process_payment()` が `get_return_url( $order )` を返すことを確認してください。

</details>

<details>
<summary>注文が想定と異なるステータスになる</summary>

POS 販売では、注文内の商品ではなく、POS のレジ設定にあるゲートウェイの **注文ステータス** によって決まります。[注文ステータス](../settings/wp-admin/checkout.mdx#order-status)をご覧ください。

</details>

<details>
<summary>オンラインストアのチェックアウトに表示される</summary>

コード側：コンストラクターの `init_settings()` の後に `$this->enabled = 'no';` が残っていることを確認してください。

</details>

## 実装例と参考資料 {#resources}

次の2つの WCPOS ゲートウェイも、それぞれ PHP ファイル1つで同じ仕組みを使って実装されています。テンプレートと併せて読むと参考になります。

- **[Email Invoice](../payment/gateways/email-invoice.mdx)** — 注文を **支払い待ち** に設定し、在庫を減らして、顧客に支払いリンクをメールで送信します（[ソースコード](https://github.com/wcpos/email-invoice-gateway)）。
- **[Web Checkout](../payment/gateways/web-checkout.mdx)** — 顧客をオンラインストアのチェックアウトへ誘導し、支払いを受け付けます（[ソースコード](https://github.com/wcpos/web-checkout-gateway)）。

テンプレートは [GitHub](https://github.com/wcpos/woocommerce-gateway-template) にあります。ゲートウェイクラスでできることの詳細は、WooCommerce の [WC_Payment_Gateway リファレンス](https://woocommerce.github.io/code-reference/classes/WC-Payment-Gateway.html)をご覧ください。
