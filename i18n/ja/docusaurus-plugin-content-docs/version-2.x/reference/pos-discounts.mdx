販売時に値引きするには、次の 3 つの方法から選びます。レジ係向けの操作は、[カートの割引](../pos/cart/discounts.mdx)ですべて説明しています。開発者やレポートを確認する方は、[各割引の記録先](#where-recorded)に直接進めます。

## レジで値引きする {#at-the-till}

- **商品の単価を下げる** — [価格を変更します](#change-price)。
- **注文全体を値引きする** — **割引を追加**で[注文全体を値引きします](#add-discount)。
- **お客様がクーポンを持っている** — [店舗のクーポンを適用します](#apply-coupon)。

同じ注文で併用できるかどうかは、[クーポンのルール](../coupons/applying-coupons.mdx#more-than-one)によります。**割引を追加**は、**個別使用のみ**に設定されたクーポンとは併用できません。

### 商品の単価を変更する {#change-price}

1. 明細の価格をタップすると、キーパッドが開きます。
2. 割引率キー（−5%、−10%、−15%）を押すか、新しい価格を入力します。
3. チェックマーク（**✓**）を押して確定します。スマートフォンでは**完了**を押します。明細の合計が、数量 × 新しい価格に変わります。

<JourneyShot manifest={cartManifest} device="tablet" step={1} offsets={[[-68, 0], [56, 21], [-88, -24], [65, 0], [-24, 0]]} alt="$45.00 の明細で価格キーパッドを開き、−10% を押した状態。新しい価格 $40.50 とその上の $45.00 −10%、3 つの割引率キー、数字キー、削除キー、完了キーが表示されています">

1. **新しい価格** — 変更後の商品価格と、変更前の価格からの計算内容です。
2. **割引率キー** — それぞれの割合で、この明細の価格を値引きします。点灯しているキー（ここでは −10%）が適用中です。もう一度押すと元の価格に戻ります。キーは**カート設定**の[**クイック割引**](../pos/cart/index.mdx#quick-discounts)で選択できます。
3. **数字キー** — 割引率を使わず、新しい価格を入力できます。
4. **削除** — 末尾の数字を削除します。
5. **✓** — 新しい価格を確定します。

</JourneyShot>

操作を間違えた場合：

- **割引率キーを間違えた** — **✓** を押す前に別のキーを押すと、最初に選んだ割引率が置き換わります。
- **元の価格に戻したい** — **✓** を押す前なら、点灯しているキーをもう一度押します。**✓** を押した後なら、価格を再度タップして希望の価格を入力します。
- **キーパッドを閉じる** — キーパッドの外側をタップすると、入力した価格が保持されます。キーボードの **Escape** を押すと、元の価格が保持されます。

その他の対処方法は[問題が起きた場合](#if-something-goes-wrong)、詳しい操作は[商品を値引きする](../pos/cart/discounts.mdx#quick-discounts)を参照してください。

### 注文全体を値引きする {#add-discount}

1. カート上部の **+** を押し、**割引を追加**を選択します。
2. **クイック割引**で金額または割引率を入力し、**$** または **%** を選択します。
3. **割引を追加**を押します。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[0, 0], [0, 0], [0, 0], [12, 46], [50, -52]]} alt="$45.00 の Aim Analog Watch が 1 点入ったカート上で、「割引を追加」ダイアログの「クイック割引」タブを開いた状態。「クイック割引」と「クーポン」のタブ、入力値 10、パーセントを選択したドルとパーセントの切り替え、「割引を追加」ボタンが表示されています">

1. **クイック割引** — 個別の明細ではなく、注文全体から指定の金額または割合で値引きします。
2. **クーポン** — 代わりに店舗のクーポンを使います。[クーポンを適用する](#apply-coupon)を参照してください。
3. **金額** — タップしてキーパッドで入力します。
4. **$ または %** — 定額の値引き、または注文金額に対する割合での値引きです。
5. **割引を追加** — 注文に割引を適用します。

</JourneyShot>

割引が合計欄に表示されます：

<JourneyShot manifest={cartManifest} device="tablet" step={5} offsets={[[12, 46], [100, 0], [50, 0], [0, 0]]} alt="$45.00 の時計に 10% の割引を適用したカート。取り消し線付きの明細合計 $45.00 とその下の $40.50、小計 $45.00、$4.50 を値引きする「割引 (10%)」行と削除ボタン、「チェックアウト $40.50」が表示されています">

1. **明細合計** — 取り消し線付きの割引前の価格と、割引後にお客様が支払う金額です。
2. **小計** — 割引前の注文金額です。
3. **割引 (10%)** — 割引とその値引き額です。**割引**のみの表示は定額の値引きを意味します。**✕** を押すと削除できます。
4. **チェックアウト** — 割引後の合計です。

</JourneyShot>

取り消すには、割引の行の **✕** を押します。明細合計が元に戻り、明細で変更した価格は設定したまま保持されます。その他の対処方法は[問題が起きた場合](#if-something-goes-wrong)、詳しい操作は[注文全体を値引きする](../pos/cart/discounts.mdx#order-level-discounts)を参照してください。

### クーポンを適用する {#apply-coupon}

1. カート上部の **+** を押し、**割引を追加**を選択します（クーポンもここにあります）。
2. **クーポン**に切り替え、**クーポンを選択**を押し、コードの一部を入力して検索します。
3. クーポンをタップし、**適用**を押します。

<JourneyShot manifest={couponManifest} device="tablet" step={1} offsets={[[0, 0], [0, 0], [-24, 0], [-30, 0], [-30, 0], [0, -34], [0, -44]]} alt="「割引を追加」ダイアログの「クーポン」タブでクーポン一覧を開いた状態。「クイック割引」と「クーポン」のタブ、「クーポンを選択」フィールド、検索ボックス、種類と金額が表示されたクーポン、「新規クーポン」ボタン、「適用」ボタンが表示されています">

1. **クイック割引** — クーポンを使わず、注文から指定の金額または割合で値引きします。[注文全体を値引きする](#add-discount)を参照してください。
2. **クーポン** — 店舗のクーポンです。
3. **クーポンを選択** — 一覧を開きます。選択すると、そのクーポンのコードがここに表示されます。
4. **クーポンを検索** — コードまたは説明の一部を入力します。
5. **クーポン** — コード、説明または種類、値引き額が表示されます。
6. **新規クーポン**（WCPOS Pro）— その場でクーポンを作成し、今回の販売に適用します。
7. **適用** — この注文がクーポンのルールに合うか確認してから適用します。

</JourneyShot>

クーポンが合計欄に表示されます。使用できない場合は、POS に理由が表示されます：

<JourneyShot manifest={couponManifest} device="tablet" step={3} offsets={[[-28, 0], [100, 0], [40, 0], [40, 0], [0, 0]]} alt="クーポンを 2 枚適用したカート。追加メニュー、小計、各クーポンのコード・削除ボタン・値引き額が記載された行、元の金額に取り消し線が付いた商品の合計、「チェックアウト」ボタンが表示されています">

1. **+** — **割引を追加**をもう一度開き、別のクーポンを追加します。
2. **小計** — クーポン適用前の注文金額です。その下にクーポンの行が表示されます。
3. **クーポン** — コード、削除用の **✕**、値引き額が表示されます。
4. **次のクーポン** — クーポンごとに行が分かれ、適用した順に表示されます。
5. **チェックアウト** — 注文の支払いを受け付けます。[チェックアウト](../pos/checkout/index.mdx)を参照してください。

</JourneyShot>

間違ったクーポンを選んだ場合は、その行の **✕** を押すと値引き分が元に戻ります。拒否された場合は、[クーポンが拒否された場合](#coupon-refused)を参照してください。詳しくは[クーポンを適用する](../pos/cart/discounts.mdx#coupon)と[クーポンの適用](../coupons/applying-coupons.mdx)を参照してください。

## 問題が起きた場合 {#if-something-goes-wrong}

- **明細の価格を間違えた** — 価格をもう一度タップし、正しい価格を入力します。**✓** を押す前なら、点灯している割引率キーをもう一度押すと元の価格に戻ります。
- **誤ってキーパッドを閉じた** — 外側をタップした場合は入力した価格が保持され、**Escape** を押した場合は元の価格が保持されます。
- **注文の割引を間違えた** — 合計欄にある割引の行の **✕** を押します。明細合計が元に戻りますが、明細で変更した価格は保持されます。
- **クーポンを間違えた** — その行の **✕** を押すと、値引き分が元に戻ります。
- **クーポンが拒否された** — [クーポンが拒否された場合](#coupon-refused)を参照してください。

### クーポンが拒否された場合 {#coupon-refused}

ダイアログは開いたままになり、理由が赤字で表示されます。注文に適用済みの他の割引が原因となるケースは、次の 2 つです：

- **…は他のクーポンと併用できません**、または **…はすでに注文に適用されており、他のクーポンとは併用できません** — **個別使用のみ**に設定されたクーポンは単独で使う必要があります。併用の妨げになっているクーポンを削除するか、そのクーポンを残して新しいクーポンの適用をやめます。
- **セール品を除外** — レジで値下げした商品はセール品として扱われます。クーポンはその商品には適用されません。また、注文全体を定額で値引きするクーポンは、その商品がカートにある間は一切使えません。その商品を削除するか、別のクーポンを選んでください。理由は[セール品の判定基準](#exclude_sale_items-behaviour)を参照してください。

その他のメッセージと対処方法は、[レジでクーポンが拒否された場合](../coupons/applying-coupons.mdx#refused)を参照してください。

## 各割引の記録先 {#where-recorded}

:::note 開発者とレポートを確認する方向け
以下の内容はレジ操作には不要です。開発者、およびレポート、エクスポート、他のプラグインで WCPOS の注文データを参照する方向けの情報です。
:::

各方法の結果は、注文の異なる場所に記録されます：

- **変更した価格**は明細の価格であり、`_woocommerce_pos_data` メタデータと明細の `subtotal` に記録されます。`discount_total` には**含まれず**、クーポンのルールも適用されません。
- **割引を追加**は、コード `pos-discount` と `_wcpos_quick_discount` メタデータを持つクーポン明細です。`discount_total` に**含まれます**。セール品を含むすべての商品明細に適用されますが、**個別使用のみ**に設定されたクーポンとは併用できません。
- **店舗のクーポン**は、そのクーポンのコードを持つクーポン明細です。`discount_total` に**含まれ**、そのクーポン自体のルールが適用されます。

次の例では、$45.00 の時計の価格をレジで $40.00 と入力し、その後**割引を追加**で注文に 10% の割引を適用しています：

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[0, 46], [0, 46], [0, -40], [20, 0], [0, 0]]} alt="Aim Analog Watch が 1 点入ったカート。レジで $45.00 から $40.00 に値下げした価格、取り消し線付きの明細合計 $40.00 とその下の $36.00、小計 $40.00、$4.00 を値引きする「割引 (10%)」行、「チェックアウト $36.00」が表示されています">

1. **価格** — レジで変更した価格です。明細の `_woocommerce_pos_data` メタデータに単価として保存されます。明細の `subtotal` は、この価格 × 数量です。[POS で上書きした価格の保存方法](#how-pos-price-overrides-are-stored)を参照してください。
2. **明細合計** — 明細の `total` です。`subtotal` から、その明細に割り当てられたクーポンや**割引を追加**の値引き額を引いた値です。
3. **小計** — 各明細の小計の合計です。レジで設定した価格がすでに反映されているため、その値引き額は注文に別の値としては記録されません。
4. **割引 (10%)** — **割引を追加**による明細です。コード `pos-discount` と `_wcpos_quick_discount` メタデータを持つクーポン明細で、注文の `discount_total` に含まれます。[「割引を追加」の明細](#add-discount-lines)を参照してください。
5. **チェックアウト** — 注文の `total` です。

</JourneyShot>

この画像の価格は税込です。合計欄の下にある **US** と **US AL** の行は、金額に含まれる税額を示しています。カートには税込金額が表示されますが、各明細の `subtotal` と `total`、および注文の `discount_total` には税抜金額が保存されます。注文の `total` は、税を含む総合計です。

## POS で上書きした価格の保存方法 {#how-pos-price-overrides-are-stored}

POS が作成するすべての商品明細は、明細の `_woocommerce_pos_data` メタデータに単価を保持します：

```json
{
  "price": "40.00",
  "regular_price": "45.00",
  "tax_status": "taxable"
}
```

- `price` は、レジでの変更を反映した、その明細の販売単価です。
- `regular_price` は、商品を追加した時点の通常価格です。レジで価格を変更してもこの値は変わらないため、レジで値上げした場合の価格はこの値より高くなります。
- [その他の商品](../pos/cart/index.mdx#miscellaneous-products)には `virtual`、`downloadable`、`categories` も保存され、クーポンのルールで確認できます。

このメタデータが単価の正規の値です。明細の `subtotal` は `price` × 数量から税額を除き、丸め処理をして算出されます。クーポンや**割引を追加**が適用されると、`total` はそれより小さくなります。正確な単価が必要な場合は、メタデータの `price` と `regular_price` を読み取ってください。

このメタデータは WooCommerce の注文画面には表示されません。

<details>
<summary>コードからメタデータを読み取る</summary>

**両方の形式に対応するデコーダーを使ってください。** 古いアプリが作成した明細では、メタデータが JSON 文字列として保存されています。2.0 のアプリはオブジェクトとして書き込むため、WordPress はシリアライズされた配列を保存し、値が文字列ではなく数値になる場合があります。`json_decode()` をそのまま使うと、配列では失敗します。

新しい POS 注文には、非公開の注文メタデータ `_woocommerce_pos_version` も保存されます。これは注文を保存した WCPOS プラグインのバージョンです。オフラインで受け付けた注文が、作成元のアプリより新しいプラグインに届く場合があるため、レシートでは引き続き、保存されている明細の形式を基準に扱います。

</details>

## 明細合計と割引合計 {#subtotal-model-v190}

WCPOS は、WooCommerce がセール価格を記録するのと同じ方法で、レジで設定した価格を記録します：

- `line_item.subtotal` = `price` × 数量です。`price` はレジで設定した価格です。
- `line_item.total` = `subtotal` − その明細に割り当てられたクーポンと**割引を追加**の値引き額です。
- `order.discount_total` = クーポンと**割引を追加**の明細のみです。レジでの価格変更による値引きは含まれません。

<details>
<summary>計算例：$45.00 → レジで $40.00 に変更 → $36.00</summary>

税なしの場合：通常価格 $45.00 の時計に対し、レジで価格を $40.00 と入力し、さらに**割引を追加**で 10% を適用します。$40.00 − $4.00 = **$36.00** です。注文には次のように保存されます：

- `_woocommerce_pos_data.regular_price`: **45.00**
- `_woocommerce_pos_data.price`: **40.00**、レジで設定した価格
- `line_items[0].subtotal`: **40.00**、40.00 × 1
- `line_items[0].total`: **36.00**、**割引を追加**の値引き額を引いた値
- `discount_total`: **4.00**、**割引を追加**の値引き額のみ
- `total`: **36.00**

レジでの価格変更による $5.00 の値引きは、`regular_price` と `price` を比較することでのみ確認できます。レシートではこの比較が自動で行われます。[レシートデータ](#receipt-data-exposure)を参照してください。

</details>

<details>
<summary>v1.9.0 より前の注文</summary>

v1.9.0 より前は、アプリが `subtotal` = `regular_price` × 数量を送信していました。その後 WooCommerce が `discount_total` = `subtotal` − `total` を計算するため、レジでの価格変更による値引きも割引に含まれていました。これによりクーポンの計算に問題が生じていました。`recalculate_coupons()` は `subtotal` を基準とするため、クーポンが元の価格に対して計算されていたのです。サーバー側の `woocommerce_order_item_get_subtotal` フィルターで、`recalculate_coupons()` の実行中にこの問題を回避していました。

v1.9.0 で上記のセール価格モデルに移行し、このフィルターは削除されました。それ以前に保存された注文は古い値を保持するため、古い注文のレポートではレジでの価格変更による値引きが `discount_total` に含まれることがあります。レシートではこの違いを考慮しています。[レシートデータ](#receipt-data-exposure)を参照してください。

</details>

## 「割引を追加」の明細 {#add-discount-lines}

**割引を追加**は、注文全体から指定の金額または割合で値引きします。店舗に登録されたクーポンではなく、クーポン明細として扱われます：

- **コード** — 注文内の最初の割引は `pos-discount`、以降は `pos-discount-2`、`pos-discount-3` と続きます。
- **メタデータ** — クーポン明細の `_wcpos_quick_discount` に `{ "discount_type": "percent", "amount": "10" }` が保存されます。`discount_type` は `percent`（最大 100）または `fixed_cart`、`amount` は正の小数を表す文字列です。
- **ルール** — レジで値下げした商品を含め、セール品にも適用されます。**個別使用のみ**に設定されたクーポンとは併用できません。
- **再計算** — WCPOS は明細にクーポンの詳細を保存するため、WooCommerce の注文画面で**再計算**しても割引は保持されます。

この仮想クーポンは、WCPOS が POS 注文を保存する間だけ存在します。オンライン店舗では `pos-discount` は利用できません。リクエストで使用するコードが店舗のクーポンにすでに使われている場合は、**クイック割引コード「…」は店舗のクーポンに使用されています。別のコードを使用してください。** というメッセージが表示され、保存は拒否されます。

2.0 のアプリはマイナスの手数料による値引きを行わず、代わりに**割引を追加**を要求します。プラグインは引き続き、古いアプリや他のクライアントからのマイナスの手数料明細を受け付けます。

## クーポンとの相互作用 {#coupon-interaction-behaviour}

レジで店舗のクーポンを適用する機能は無料プラグインで利用できます。レジでのクーポン作成には [WCPOS Pro](../getting-started/pro-license.mdx) が必要です。レジで価格を変更した商品を含む注文にクーポンを適用すると、次のように動作します：

1. クーポンは `regular_price` ではなく、**レジで設定した価格**(`_woocommerce_pos_data.price`)を基準に計算されます。
2. クーポンを削除すると、明細はレジで設定した価格に戻ります。

アプリは端末上でクーポンを計算するため、オフラインでも適用できます。プラグインは注文の保存時に、同じ商品情報を使って再計算します。

価格が税込で、複数のクーポンや**割引を追加**が同じ明細に適用される場合、アプリは WooCommerce と同様に、まず明細の値引き額を合計してから税額を一度だけ差し引きます。これにより、レジの明細合計は保存された注文と小数点以下の最終桁まで一致します。

### `exclude_sale_items` の動作 {#exclude_sale_items-behaviour}

`_woocommerce_pos_data.price` が `regular_price` を下回る明細は、WooCommerce のセール価格と同様にセール品として扱われます。レジで設定した価格が `regular_price` 以上の場合は該当しません。そのため、**セール品を除外**を設定したクーポンは次のように動作します：

- レジで設定した価格が `regular_price` を下回る明細には適用されません。
- カート全体を定額で値引きするクーポンの場合、そのような商品がカートにある間は一切使えません。これは、カート定額割引クーポンに対する WooCommerce 自体のルールです。

セール品の判定基準を変更するには、以下の `wcpos_item_is_on_sale` フィルターを使います。

## 利用可能なフィルター {#available-filters}

### `wcpos_item_is_on_sale` {#wcpos_item_is_on_sale}

プラグインがクーポンを検証する際に、POS の価格データを持つ明細を「セール品」と見なすかどうかを上書きします。WCPOS 2.0 より前のフィルター名は `woocommerce_pos_item_is_on_sale` でした。この名前は今も動作しますが、2.0 以降は非推奨であり、早くても 2.2 で削除されます（[フックの命名規則](../extensions/index.mdx#hook-naming)を参照）。

<details>
<summary>使用例とパラメーター</summary>

```php
add_filter( 'wcpos_item_is_on_sale', function ( $is_on_sale, $product, $item, $pos_data ) {
    // Let coupons with exclude_sale_items apply to lines lowered at the till.
    return false;
}, 10, 4 );
```

- `$is_on_sale`(`bool`)— 明細をセール品と見なすかどうかです。デフォルト：`price < regular_price`。
- `$product`(`WC_Product`)— 商品オブジェクトです。
- `$item`(`WC_Order_Item_Product`)— 注文の商品明細です。
- `$pos_data`(`array`)— デコード済みの `_woocommerce_pos_data` です。

</details>

このフィルターはサーバーで実行されます。レジ係がカートを編集中にアプリ側で行うセール品の判定は、常に `price < regular_price` です。サーバーの判定は、注文の保存時に適用されます。

## REST API エンドポイント {#rest-api-endpoint}

クーポンのエンドポイントは**無料プラグイン**に含まれるため、WCPOS Pro がなくても、アプリがクーポンを要求して 404 になることはありません。

2.0 のアプリは `GET /wp-json/wcpos/v2/coupons` を通じてクーポンを同期します。このエンドポイントは、POS の読み取り権限で WooCommerce の `wc/v3/coupons` に転送します。レジで作成したクーポン（Pro）は通常の WooCommerce クーポンとして保存され、レジ係にはクーポンの作成権限が必要です。

<details>
<summary>2.0 より前のアプリ向けの v1 エンドポイント</summary>

2.0 より前のアプリは `/wp-json/wcpos/v1/coupons` を使います。このコントローラーは `WC_REST_Coupons_Controller` を拡張し、オフライン同期用の UUID、`access_woocommerce_pos` 権限を持つすべてのユーザーへの読み取りアクセス、および `posts_per_page=-1` と `fields=id`（または `fields=id,date_modified_gmt`）が要求された場合に ID のみを高速に取得する処理を追加しています。

</details>

どのユーザーがどのエンドポイントにアクセスできるかは、[ロールとエンドポイントへのアクセス](./role-endpoint-access.mdx)を参照してください。

## レシートデータでの提供 {#receipt-data-exposure}

レシートテンプレートは `_woocommerce_pos_data` を直接読み取らずに、各明細の値引き額、クーポンまたは**割引を追加**ごとの行、およびそれぞれの注文合計を取得できます。

<details>
<summary>割引と値引き額のレシートフィールド</summary>

- **各明細** — `regular_price`、`unit_savings`、`line_savings` で、レジでの価格変更やセール価格による値引き額を確認できます。`discounts` は明細の `subtotal` − `total` で、クーポンと**割引を追加**による値引きのうち、その明細に割り当てられた額です。レジでの価格変更による値引きは含まれません。ただし、v1.9.0 より前の注文では、その値引き額がすでに含まれている場合があり、その場合は `savings_in_discounts` が true になります。
- **`discounts[]`** — **割引を追加**も含め、クーポン明細ごとに `label`、`code`、`discount_type`、`total` を持つ行があります。**割引を追加**の行のラベルは**割引 (10%)**、定額の場合は**割引**です。`code` は `pos-discount`、`discount_type` は `percent` または `fixed_cart` です。
- **合計** — `discount_total`（`WC_Order::get_discount_total()` から取得した、クーポンと**割引を追加**の合計）、`sale_savings_total`（レジでの価格変更を含む、通常価格と販売価格の差額の合計）、および全体をまとめた `total_saved` があります。`total_saved` は v1.9.0 より前の注文での重複分を除きます。
- **`total_saved_complete`** — 正確な合計に必要な価格データが明細にない場合は false になります。その場合、値引き額の合計は `null` になります。

それぞれに `_incl` と `_excl` のバリエーションがあります。`Receipt_Data_Builder::get_item_meta_pairs()` は、`_woocommerce_pos_data` を含め、アンダースコアで始まるすべてのメタキーを `lines[].meta` から除外します。

</details>

テンプレートの例は、[通常価格と値引き額の表示](../receipts/receipt-data.mdx#displaying-regular-price-and-savings)と[合計](../receipts/receipt-data.mdx#totals)を参照してください。
