拡張機能は、WCPOS向けに作られたWordPressプラグインです。カード決済端末、多言語カタログ、ストアクレジット、拠点別の在庫管理などに対応します。WordPressの **WP Admin > POS > 設定 > 拡張機能** にあるディレクトリで、すべてまとめて探せます。

ディレクトリからはボタンひとつでインストールできます。**WCPOS Pro** とWordPressの管理者権限が必要です。Proがなくても、[Polylang](./polylang.mdx)、[WPML](./wpml.mdx)、[WP Multilang](./wp-multilang.mdx)は手動でインストールできます。

このページの内容：[拡張機能のインストール](#installing-an-extension) · [Proなしでインストール](#install-by-hand) · [問題が発生した場合](#troubleshooting)

## 拡張機能のインストール {#installing-an-extension}

:::note 始める前に
ディレクトリからのインストールには、**WCPOS Pro** とWordPressの管理者権限が必要です。ショップマネージャーはプラグインをインストールできません（[アクセス](../settings/wp-admin/access.mdx)を参照）。無料版の場合は、[Proなしの場合](#install-by-hand)をご覧ください。
:::

1. WordPressで **WP Admin > POS > 設定** を開き、**拡張機能** を選択します。
2. 拡張機能を探します。**拡張機能を検索...** に入力するか（名前、説明、タグが検索対象です）、**すべて**、**カタログ**、**クーポン**、**在庫**、**決済** のいずれかのタブを選択します。
3. カードの **インストール** を押します。WCPOSがダウンロード、インストール、有効化をまとめて実行し、**自動更新** をオンにします。カードには **有効** と表示されます。
4. 設定を行います。カードの **⋮**（**その他の操作**）メニューに **設定** があれば、選択してください。入力する内容は、上記の各拡張機能のページで説明しています。

<details>
<summary>メニューに「設定」がない場合と、別の開き方</summary>

- メニューに **設定** が表示されるのは、ディレクトリにその拡張機能の設定ページが登録されている場合のみです。表示されない場合は、拡張機能の個別ページの案内に従ってください。
- WCPOS Proでは、**WP Admin > プラグイン** の拡張機能名の下にも同じ **設定** リンクがあります。
- 決済の拡張機能では、**設定** を選ぶとWooCommerceの決済設定内にある、その拡張機能のページが開きます。

</details>

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[190, 0], [200, 0], [-36, 0], [-28, 0]]} alt="WCPOS Proを使用したWordPressの拡張機能画面。WCPOS設定メニューで拡張機能が選択され、検索ボックスと再読み込みボタン、すべて・カタログ・クーポン・在庫・決済のカテゴリータブ、拡張機能カードの一覧が表示されています。">

1. **拡張機能** — WCPOSの設定メニュー内にあります。横の数字は、更新待ちの拡張機能の数です。
2. **拡張機能を検索...** — 名前、説明、タグを検索します。
3. **再読み込み** — ディレクトリに新しいバージョンがないか、その場で確認します。
4. **カテゴリータブ** — **すべて** または特定のカテゴリーを選択します。

</JourneyShot>

### Proなしの場合 {#install-by-hand}

無料版でもすべての拡張機能が一覧に表示されますが、**インストール** はグレー表示になり、**インストールにはProが必要です** と表示されます。多言語対応の拡張機能であるPolylang、WPML、WP Multilangの3つはProなしで動作するため、手動でインストールできます。

1. 拡張機能のカードで **⋮**（**その他の操作**）を開き、**GitHubで表示** を選択します。
2. 最新リリースに添付されている `.zip` をダウンロードします。
3. **WP Admin > プラグイン > 新規プラグインを追加** で **プラグインのアップロード** を押し、zipを選択して有効化します。

ディレクトリには **有効** と表示され、新しいリリースが公開されると **更新があります** に変わります。Proなしでは **更新** ボタンは表示されません。同じ手順で新しいリリースのzipをアップロードすると、WordPressがインストール済みのバージョンを置き換えるか確認します。

## 更新・無効化・有効化 {#activating-and-deactivating}

Proなしでは拡張機能を手動で更新します。[Proなしの場合](#install-by-hand)をご覧ください。

WCPOS Proでは、インストール済みの拡張機能のカードにあるボタンで、次の操作ができます。

- **更新** — 新しいバージョンをインストールします。有効だった拡張機能は、そのまま有効な状態を保ちます。
- **無効化** — 拡張機能を削除せずに停止します。設定とファイルは残り、**有効化** で再び使えるようになります。**有効化** すると **自動更新** も再びオンになります。

### 更新 {#updating-extensions}

新しいバージョンが公開されると、カードのバージョン表示が **v0.5.9 → v0.5.10** に変わり、有効な拡張機能のステータスは **更新があります** になります（無効なものは **無効** のままです）。WCPOS Proでは **更新** ボタンも表示され、WordPressの **プラグイン** 画面にも同じ更新が表示されるため、どちらからでも更新できます。無料版では手動で更新します。[Proなしの場合](#install-by-hand)をご覧ください。

ディレクトリは1時間ごとに新しいバージョンを確認します。すぐに確認するには、検索ボックスの横の **再読み込み** を押してください。

### 自動更新 {#auto-updates}

ディレクトリからインストールまたは有効化した拡張機能は、すべて **自動更新** がオンになります。オンの間は、自動更新が有効なほかのプラグインと同じように、WordPressが新しいバージョンをバックグラウンドでインストールします。新しいバージョンを先にテストするなど、手動で更新したい場合は、カード上でオフにしてください。

サイトで使用中のWCPOSより新しいバージョンを必要とする更新は、カードにも自動更新にも表示されません。先にWCPOS Proを更新すると、拡張機能の更新が表示されます。

### 拡張機能の削除 {#removing-an-extension}

拡張機能を完全に削除するには、ほかのプラグインと同様に **WP Admin > プラグイン** で無効化してから削除します。WCPOS Proでは、先にカード上で無効化することもできます。

## 問題が発生した場合 {#troubleshooting}

**インストールがグレー表示になり、「インストールにはProが必要です」と表示される。** 無料版を使用しています。ディレクトリからのインストールには [WCPOS Pro](../getting-started/pro-license.mdx) が必要です。多言語対応の拡張機能は[手動でインストール](#install-by-hand)できます。

**「プラグインを管理する権限がありません。」** お使いのWordPressユーザーにはプラグインをインストールする権限がありません。管理者に依頼してください。

**「…にはWCPOS 2.1以降が必要です。このサイトはWCPOS 2.0を使用しています。先にWCPOS Proを更新してください。」** 提供されているバージョンは、お使いのWCPOSが対応するものより新しいバージョンです。WCPOS Proを更新してから、もう一度お試しください。

**「拡張機能を再読み込みできませんでした。もう一度お試しください。」と表示される、または何も検索していないのに「拡張機能が見つかりませんでした。」と表示される。** サイトが拡張機能の一覧を取得できませんでした。一覧はGitHubから取得しますが、一部のホスティング環境ではサイトから外部への接続が制限されています。後でもう一度試すか、GitHubへの接続を許可するようホスティング事業者に依頼してください。

**インストールが失敗し、カードにエラーが表示される。** WordPressがプラグインをダウンロードまたは展開できませんでした。カードのメッセージに原因が表示されます。WordPressがプラグインフォルダー(`wp-content/plugins`)にファイルを保存できるか、GitHubに接続できるかをホスティング事業者に確認してもらってください。

**インストール後にカードが「無効」と表示される。** WordPressは拡張機能をインストールしましたが、有効化できませんでした。有効化されるまで動作しません。**有効化** を押してください。失敗した場合は、カードのメッセージに原因が表示されます。

**新しいバージョンが表示されない。** ディレクトリは一覧を1時間保持します。**再読み込み** を押してください。

:::info WCPOS Proの場合
無料版でもディレクトリ全体を表示できますが、**インストール**、**有効化**、**更新**、**無効化**、**自動更新** の操作にはProが必要です。[無料版とProの比較](../getting-started/free-vs-pro.mdx)をご覧ください。
:::

## 開発者向け {#for-developers}

拡張機能を開発したり、自作の拡張機能を掲載したりするための情報です。店舗を運営するだけなら、以下の内容は必要ありません。

### フックの命名 {#hook-naming}

WCPOS 2.0以降、WCPOSが実行するすべてのフックは `wcpos_*` という名前になります。旧名の `woocommerce_pos_*` は非推奨です。引き続き動作しますが、早ければ2.2で削除されます。

<details>
<summary>Proのフック、非推奨の通知、名前が変わらないもの</summary>

WCPOS Proのフック名は `wcpos_pro_*` です。旧名はエイリアスとして引き続き実行され、コールバックが登録されている場合、`WP_DEBUG` が有効であれば非推奨の通知がログに記録されます。変更されるのはフックのみで、オプション、メタキー、権限の名前は変わりません。

</details>

<details>
<summary>自分のコードで実行するフックと切り替え時期</summary>

自分のコードで実行し、WCPOSが受け取るフックは4つあります。`woocommerce_pos_invalidate`（拡張機能）、`woocommerce_pos_receipt_head`（保存済みのPHPレシートテンプレート）、`woocommerce_pos_head` / `woocommerce_pos_footer`（テーマの `pos.php` による上書き）です。WCPOSは2.2までこれらの名前を受け付けます。`wcpos_invalidate`、`wcpos_receipt_head`、`wcpos_head`、`wcpos_footer` に切り替えてください。

拡張機能では、2.0以降の最初のリリースで `wcpos_` の名前に切り替え、WCPOS 2.0以降を必須にしてください。両方の名前に登録しないでください。2.0と2.1ではコールバックが2回実行されてしまいます。[ADR 0041](https://github.com/wcpos/woocommerce-pos/blob/main/docs/adr/0041-wcpos-is-the-hook-prefix.md)をご覧ください。

</details>

<details>
<summary>拡張機能の開発とディレクトリへの掲載</summary>

<h3 id="creating-a-pos-extension">POS拡張機能の作成</h3>

WCPOSの拡張機能は、WCPOSのフックとAPIを使う通常のWordPressプラグインです。決済の拡張機能を作る場合は、[ゲートウェイテンプレート](../reference/gateway-template.mdx)から始めてください。

<h3 id="pos-screens">POS画面への追加</h3>

現在、プラグインからPOS画面に独自のパネルやボタンを追加することはできません。カート、商品、顧客の画面には、アプリに組み込まれたものだけが表示されます。例外はチェックアウトです。決済ゲートウェイは、[レガシータブ](../pos/checkout/legacy-tab.mdx)に独自の支払いページを表示するか、2つのフィルターを使って **決済** タブに独自のタイルとフィールドを追加できます。[支払いペインのフィールド宣言](../reference/declaring-pos-fields.mdx)をご覧ください。

<details>
<summary>インストール後にディレクトリがプラグインを認識できるようにするには</summary>

- **フォルダー名** — プラグインのフォルダー名は、カタログの `slug` と一致する必要があります。例：`my-extension/my-extension.php`。ディレクトリはこのフォルダーでインストール済みの拡張機能を見つけ、インストール先にもこのフォルダーを使います。
- **Text DomainまたはPlugin URI** — どちらかが `slug` またはGitHubリポジトリ名と一致する必要があります。一致しない場合、自動更新やWordPressの **プラグイン** 画面にリリースが提供されません。この確認により、同じフォルダー名を使うフォークに元のリリースが配信されるのを防ぎます。

</details>

<h3 id="submitting-to-the-directory">ディレクトリへの掲載申請</h3>

ディレクトリは、GitHubの [`wcpos/extensions`](https://github.com/wcpos/extensions) リポジトリにある `catalog.json` を読み込みます。拡張機能を掲載するには、そのリポジトリで `catalog.json` に項目を追加するプルリクエストを作成してください。アイコンがあれば `icons/` に追加します。マージされると、約1時間以内にWCPOSサイトに表示されます。

<details>
<summary>カタログ項目の全フィールド</summary>

| フィールド | 内容 |
|---|---|
| `slug` | プラグインのフォルダー名。 |
| `name`, `description`, `author` | カードに表示する内容。 |
| `category` | 表示先のタブ。`payments`、`catalog`、`coupons`、`inventory`、または新しいカテゴリー。 |
| `tags` | 検索対象にする追加の語句。 |
| `homepage` | GitHub リポジトリの `https://github.com/owner/repo`。リリースはここから読み込まれます。 |
| `icon` | 正方形のアイコンのURL。通常は `icons/` に追加したファイルです。指定しない場合、カードにパズルのピースが表示されます。 |
| `requires_wp`, `requires_wc`, `requires_wcpos` | 動作に必要なWordPress、WooCommerce、WCPOSの最低バージョン。`requires_wcpos` より古いサイトには、リリースは提供されません。 |
| `requires_pro` | 動作にWCPOS Proが必要かどうか。 |
| `settings_url` | `wp-admin/` からの相対パスで指定する設定ページ。例：`admin.php?page=wc-settings&tab=checkout&section=my_gateway`。カードのメニューの **設定** のリンク先になります。 |

`version`、`latest_version`、`download_url`、`released_at` はカタログに任せてください。リリースから自動で入力されます。

</details>

<h3 id="github-release-conventions">GitHubリリースの規約</h3>

バージョンをタグにし、プラグインのzipを添付して、GitHubで正式リリースを公開してください。カタログは1時間ごとに掲載済みの各リポジトリの最新リリースを読み取り、項目を更新します。

<details>
<summary>リリースをWCPOSサイトに配信するための要件</summary>

- `v1.2.3` のようにバージョンで **タグを付けます**。バージョン番号では先頭の `v` が除かれ、プラグインヘッダーの `Version` と一致する必要があります。
- スラッグに合わせて `my-extension.zip` と名付けた **プラグインのzipを添付します**。その名前のファイルがない場合は、リリースにある最初の `.zip` が使われます。zip内のフォルダー名にかかわらず、WCPOSは `slug` フォルダーにインストールします。
- **正式リリースとして公開します。** 下書きとプレリリースは対象外のため、テスト用ビルドはプレリリースとして安全に共有できます。
- 新しいWCPOSが必要なリリースでは、`catalog.json` の **`requires_wcpos` を引き上げます**。これにより、古いサイトに起動できないバージョンが配信されるのを防ぎます。

</details>

サイトの一覧が再読み込みされると、新しいバージョンが表示されます。通常は1時間以内、**再読み込み** を押せばすぐに表示されます。**自動更新** がオンのサイトでは、バックグラウンドでインストールされます。

掲載申請の前に独自のカタログをテストするには、`wcpos_extensions_catalog_url` フィルターでサイトの参照先をそのカタログに変更します。

</details>
