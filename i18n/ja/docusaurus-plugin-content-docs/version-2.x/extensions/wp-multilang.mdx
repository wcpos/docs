**WP管理画面:** `WP Admin → POS → Settings → Extensions`でインストールし、`WP Admin → POS → Stores`で店舗ごとに設定します。

[WP Multilang](https://wordpress.org/plugins/wp-multilang/)は、商品のすべての翻訳を同じ商品内に保存し、商品を特定の言語に限定できるようにします。無料の**WCPOS WP Multilang**拡張機能を使うと、POSで使用する言語が1つに決まり、他の言語に限定した商品は表示されなくなります。

レジ係が設定することはありません。最初のセクションで、レジ係の画面にどのような変化があるかを説明します。それ以降は店舗管理者向けの説明です。

## レジ係の画面に表示される内容 {#what-the-cashier-sees}

商品検索、商品グリッド、バリエーション商品の選択肢には、店舗の言語で販売する商品が表示されます。

- **言語の制限がない**商品は、すべての店舗に表示されます。
- **特定の言語に限定された**商品は、店舗の言語がそのいずれかに含まれる場合のみ表示されます。

レジ係の販売操作は変わりません。通常どおりカートに追加し、支払いを受け付け、レシートを印刷します。[チェックアウト](../pos/checkout/index.mdx)を参照してください。

## 拡張機能をインストールする {#install}

:::note 始める前に
[WooCommerce](https://woocommerce.com/)と[WP Multilang](https://wordpress.org/plugins/wp-multilang/)を有効にし、WP Multilangで言語を設定しておく必要があります。また、**WP Admin**に管理者としてログインできることが必要です。両方が有効になるまで、WordPressでこの拡張機能を有効化することはできません。
:::

管理者が**WP Admin**で一度インストールします。[店舗の言語を選択](#store-language)しない限り、POSはWP Multilangの**デフォルト言語**を使用します。

### WCPOS Proを使用する場合 {#install-pro}

1. **POS → 設定 → 拡張機能**に移動します。
2. **WCPOS WP Multilang**を探し、**インストール**を押します。
3. **有効化**を押します。

更新と自動更新については、[拡張機能のインストール](./index.mdx#installing-an-extension)を参照してください。

拡張機能を有効化した後は、次の手順に進みます。

- 店舗独自の言語を指定するには、まず[言語を選択](#store-language)してから[動作を確認](#check)します。
- それ以外の場合は、そのまま[動作を確認する](#check)に進みます。

### 無料プラグインを使用する場合 {#install-free}

拡張機能画面にはこの拡張機能が表示されますが、**インストール**ボタンの使用にはProが必要です。代わりに、次の手順でインストールします。

1. 拡張機能の[最新リリース](https://github.com/wcpos/wcpos-wp-multilang/releases/latest)から`wcpos-wp-multilang.zip`をダウンロードします。
2. **プラグイン → 新規プラグインを追加**に移動し、**プラグインのアップロード**を押します。
3. ダウンロードしたファイルを選択し、**今すぐインストール**を押します。
4. **プラグインを有効化**を押します。

次に[動作を確認](#check)します。Proを使用しない場合、店舗は1つで、WP Multilangのデフォルト言語を使用します。

### 動作を確認する {#check}

POSは各端末に商品のコピーを保存しているため、変更を反映するには一度消去します。

#### WP Adminでの準備: 2つの商品を用意する {#check-prepare}

テスト用に在庫のある商品を2つ選びます。1つは店舗の言語で販売する商品、もう1つはその言語では販売しない商品にします。商品の言語はPOSではなく**WP Admin**で設定します。2つの商品それぞれについて、次の操作を行います。

1. **WP Admin**で商品の編集画面を開きます。
2. WP Multilangの**言語**ボックスにある**投稿を表示する言語:** で、商品を販売する言語にチェックを入れます。何も選ばないとすべての言語で表示されるため、少なくとも1つにチェックを入れてください。
3. 商品を保存します。

#### 各POS端末での確認: 結果を確認する {#check-device}

POSを使用する各端末で、次の操作を行います。

1. 商品一覧の下にある同期ボタンを長押しし、**クリアして更新**を選択します。商品が再ダウンロードされるまで待ちます。
2. バーで有効になっているフィルターのうち、**在庫あり**以外をすべて無効にします。**商品を検索**に、店舗の言語を含む商品の名前を入力します。その商品が表示されます。
3. もう一方の商品を検索します。その商品は表示されません。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[240, 0], [0, 0], [0, 0], [-42, 0]]} alt="商品を1つ検索した後のPOS商品パネル: 検索ボックス、有効な在庫ありフィルター、1つの商品タイル、商品数">

1. **商品を検索** — 商品名を入力します。
2. **在庫あり** — [表示設定](../pos/product-panel/display-settings.mdx#show-out-of-stock-products)で**在庫切れ商品を表示**が有効になっていない限り、最初から有効です。このフィルターが有効な間は、在庫切れの商品は表示されません。そのため、テストする両方の商品に在庫が必要です。[在庫状況](../pos/product-panel/search-filtering.mdx#stock-status)を参照してください。
3. **商品** — 店舗の言語で販売する場合のみ表示されます。
4. **商品数** — この端末で検索条件に一致する商品の数です。更新が終わると、店舗の言語で販売する商品だけが数えられます。

</JourneyShot>

同期ボタンを長押しすると、メニューが開きます。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[80, 0], [-38, -94], [42, -41]]} maxWidth={580} alt="同期ボタンを長押しして「同期」と「クリアして更新」のメニューを開いた商品パネル下部">

1. **同期ボタン** (<Icon name="arrow-rotate-right" />) — 長押しするとこのメニューが開きます。詳細は [パネル下部](../pos/product-panel/display-settings.mdx#footer)を参照してください。
2. **同期** — ボタンを押す場合と同じ動作です。店舗の言語を変更した後も、新たに非表示となった商品は削除されないため、**クリアして更新**を選択してください。
3. **クリアして更新** — この端末の商品を消去し、店舗の商品を再ダウンロードします。

</JourneyShot>

もう一方の商品が引き続き表示される場合は、[問題が起きた場合](#goes-wrong)を参照してください。

## 店舗の言語を選択する {#store-language}

WCPOS Proでは、[店舗](../stores/index.mdx)ごとに独自の言語を使用できます。同じサイトにフランス語の店舗と英語の店舗があっても、それぞれの言語で販売する商品が表示されます。

:::note 言語ページの表示には3つの条件があります
WCPOS Proを使用していること、**WCPOS WP Multilang**拡張機能が有効であること、WP Multilangが有効で少なくとも1つの言語が設定されていることが必要です。これらを満たさない場合、店舗のメニューに**言語**ページは表示されません。
:::

1. **WP Admin**で、**POS → 店舗**に移動し、店舗名をクリックします。
2. 店舗のメニューで、**拡張機能**の**言語**を開きます。画面やレシートの文言を変更する**通貨と言語 → 言語**ではありません。[後述の説明](#product-and-screen-language)を参照してください。
3. **店舗の言語**で言語を選択します。一覧には、WP Multilangで設定したすべての言語が表示されます。**デフォルト言語**はWP Multilangのデフォルト設定に従います。選択は自動的に保存されます。
4. この店舗のPOSを開き、[動作を確認](#check)します。

他の店舗の言語は変わりません。

### 商品の言語と画面の言語 {#product-and-screen-language}

店舗のメニューには、**言語**という名前の設定が2か所あります。

- **拡張機能 → 言語 → 店舗の言語**では、POSに表示する商品を選択します。
- **通貨と言語 → 言語**では、POS画面とレシートの文言を選択します。[店舗の各ページを設定する](../stores/setup.mdx#store-pages)を参照してください。

:::tip
フランス語の店舗では、両方をフランス語に設定してください。
:::

## 問題が起きた場合 {#goes-wrong}

**他の言語に限定した商品が引き続き表示されます。** **プラグイン**で**WCPOS WP Multilang**が有効になっているか確認し、その端末で同期ボタンを長押しして**クリアして更新**を選択してください。

**ある店舗で商品が表示されません。** WP Multilangで、その商品の言語に店舗の言語が含まれているか確認してください。含まれていなければ追加してから、POSを更新します。含まれている場合は、[商品が見つからない場合](../pos/product-panel/index.mdx#goes-wrong)を参照してください。

**WordPressで拡張機能を有効化できません。** 先にWooCommerceとWP Multilangを有効化してください。

**店舗のメニューの拡張機能に言語ページがありません。** このページの表示には、WCPOS Pro、この拡張機能の有効化、少なくとも1つの言語が設定されたWP Multilangの有効化が必要です。

:::info WCPOS Proを使用する場合
店舗ごとに言語を選択できます。Proを使用しない場合、店舗は1つで、WP Multilangのデフォルト言語を使用します。
:::

<details>
<summary>開発者向け: フィルターと保存データ</summary>

この拡張機能はPOSからの商品およびバリエーションのリクエストだけに作用し、商品クエリにWP Multilangの`lang`クエリ変数と`_languages`メタクエリを追加します。`_languages`メタデータがない商品、または`_languages`に対象の言語を含む商品が一致します。他のRESTクライアントには影響しません。言語はまずリクエストが指定する店舗(`store_id`)から取得し、次にWP Multilangのデフォルトを使用します。

- 店舗で選択した言語は、その店舗の`_wcpos_wp_multilang_language`メタデータに保存されます。空の値はWP Multilangのデフォルト言語を意味します。店舗API(`/wcpos/v1/stores`)は、使用中の言語を`language`として返します。店舗で選択した言語、またはメタデータが空の場合はデフォルト言語のコードです。
- `wcpos_wp_multilang_resolved_language`は、1回のリクエストで使用する言語を変更します。
- `wcpos_wp_multilang_default_language`は、デフォルト言語を変更します。
- `wcpos_wp_multilang_is_supported`は、拡張機能の有効と無効を切り替えます。
- `wcpos_wp_multilang_minimum_version`は、動作に必要なWP Multilangの最低バージョンを設定します。デフォルトでは指定されていません。
- 1.xアプリに対しては、`/wcpos/v1/products`とバリエーションルートへのID一覧リクエスト（`posts_per_page=-1`と`fields=id`）にも、同じ言語フィルターを適用して応答します。2.xアプリはこれらのリクエストを送信しません。

ソース: [github.com/wcpos/wcpos-wp-multilang](https://github.com/wcpos/wcpos-wp-multilang)。

</details>
