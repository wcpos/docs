# WCPOS Polylang {#wcpos-polylang}

**WP Admin：** `WP Admin → POS → Settings → Extensions` でインストールし、`WP Admin → POS → Stores` で店舗ごとに設定します。

WCPOS Polylangは、検索結果と商品グリッドに各商品を店舗の言語でひとつずつ表示します。この拡張機能がない場合、[Polylang](https://wordpress.org/plugins/polylang/)で翻訳した商品は、言語ごとに別々の商品としてPOSに表示されます。

## レジ係に表示される内容 {#what-it-does}

- **各商品がひとつずつ表示されます。** 検索結果、商品グリッド、バリエーションは、すべて同じ言語で表示されます。
- **店舗の言語で表示されます。** WCPOS Proでは、店舗ごとに言語を設定できます。Proなしでは、POSはPolylangのデフォルト言語を使用します。
- **POS専用の設定は引き続き適用されます。** **オンラインのみ** に設定した商品は、POSには表示されません。[POS専用商品](../products/pos-only-products.mdx)をご覧ください。

店舗の言語への翻訳がない商品は、その店舗には表示されません。その店舗で販売するには、Polylangで翻訳を追加してください。

## 必要な環境 {#requirements}

<RequirementsList>
  <RequirementItem label="WooCommerce">WooCommerceがインストールされ、有効になっていること</RequirementItem>
  <RequirementItem label="Polylang">Polylangが有効で、少なくともひとつの言語が設定されていること</RequirementItem>
  <RequirementItem label="WCPOS">無料版プラグインで動作します。店舗ごとの言語設定にはWCPOS Proが必要です</RequirementItem>
</RequirementsList>

## 設定方法 {#installation}

手順1から3はWP Adminで行います。手順4は各レジで行います。

1. **Polylang を設定します。** [Polylang](https://wordpress.org/plugins/polylang/) をインストールして有効化し、使用する言語を追加してデフォルトの言語を選びます。WordPress 6.5 以降では、Polylang が有効になるまで WCPOS Polylang を有効化できません。
2. **WCPOS Polylangをインストールします。**

   **WCPOS Proの場合：** **POS → 設定 → 拡張機能** を開き、**WCPOS Polylang** を探して、**インストール**、**有効化** の順に選択します。[拡張機能のインストール](./index.mdx#installing-an-extension)をご覧ください。

   **WCPOS Proがない場合：** [最新リリース](https://github.com/wcpos/wcpos-polylang/releases/latest)から `wcpos-polylang.zip` をダウンロードし、**プラグイン → 新規プラグインを追加 → プラグインのアップロード** でアップロードします。**今すぐインストール** をクリックし、次に **プラグインを有効化** をクリックします。

3. Polylangのデフォルト言語を使わない店舗がある場合は、**WCPOS Proで店舗ごとの言語を選択します**。[店舗ごとの言語を選ぶ](#per-store-language-pro)をご覧ください。
4. **各レジで商品を再ダウンロードします。** [商品を再ダウンロードする](#redownload)をご覧ください。

## 店舗ごとの言語を選ぶ {#per-store-language-pro}

:::info WCPOS Proの場合
店舗ごとにPolylangの言語を設定できます。Proなしでは、すべてのレジがPolylangのデフォルト言語を使用します。店舗ごとに言語を設定するには、[WCPOS Pro](../getting-started/pro-license.mdx)にアップグレードしてください。
:::

1. WP Adminで **POS → 店舗** を開き、店舗をクリックします。
2. 店舗のメニューで、**拡張機能** の下にある **言語** をクリックします。
3. **店舗の言語** で言語を選択します。Polylangでは、`en` や `fr` などのコードで言語が表示されます。最初の選択肢である **デフォルト言語** は、横にデフォルト言語のコードが表示され、Polylangのデフォルト設定に従います。

変更はその都度保存されます。その後、以下の手順に従って、その店舗のレジで[商品を再ダウンロード](#redownload)してください。

**言語** ページが表示されるのは、WCPOS Pro、少なくともひとつの言語を設定したPolylang、WCPOS Polylangのすべてが有効な場合のみです。

### 「言語」という名前の2つの設定 {#two-languages}

店舗には **言語** の設定が2つあり、それぞれ異なる言語を指定できます。

| 店舗メニューの項目 | 変更される内容 |
| --- | --- |
| **拡張機能 → 言語** | 店舗のレジが取得する商品。Polylangのひとつの言語に絞られます。 |
| **通貨と言語 → 言語** | POS画面とレシートの言語。[店舗の各ページを設定する](../stores/setup.mdx#store-pages)をご覧ください。 |

## 商品を再ダウンロードする {#redownload}

各レジにひとつの言語の商品だけを保存するため、商品を再取得します。各レジをオンラインにして、次の操作を行ってください。

1. ナビゲーションドロワーを開き、**店舗の状態**（心拍のアイコン）をタップします。**データベース** タブが開きます。
2. **商品** の行で **その他の操作** メニューを開き、**消去して再ダウンロード…** を選択して確認します。バリエーションも消去されます。
3. 店舗の言語への翻訳がある商品を検索します。その言語の商品名で、ひとつだけ表示されます。そうならない場合は、[問題が発生した場合](#compatibility-notes)をご覧ください。

<JourneyShot manifest={manifest} device="tablet" step={1} alt="店舗の状態のデータベースタブ。商品の行でその他の操作メニューが開かれ、消去して再ダウンロードが表示されています">

1. **商品** — サイトの商品総数のうち、このレジに保存されている商品の数です。下の **バリエーション** の行も一緒に消去されます。
2. **その他の操作** — その行の操作メニューです。
3. **消去して再ダウンロード…** — このレジに保存されたデータを削除し、ひとつの言語で再取得します。[店舗の状態](../support/store-health.mdx#clear-and-redownload)をご覧ください。

</JourneyShot>

サーバー上のデータは変わりません。最初の商品はすぐに再取得され、残りは閲覧、検索、販売に合わせて取得されます。**商品** の行で、再取得済みの商品数を確認できます。[ダウンロードの進捗を確認する](../products/sync.mdx#progress)をご覧ください。

## 問題が発生した場合 {#compatibility-notes}

**すべての商品が複数表示される。** **プラグイン** で、PolylangとWCPOS Polylangが両方とも有効になっているか確認してください。Polylangが無効な場合、WCPOS Polylangは何も行わず、POSはすべての言語を取得します。確認後、各レジで[商品を再ダウンロード](#redownload)してください。

**店舗で意図しない言語の商品が表示される。** 店舗の **拡張機能 → 言語** ページが **デフォルト言語** または別の言語に設定されています。店舗の言語を選択してから、その店舗のレジで[商品を再ダウンロード](#redownload)してください。

**ある店舗に商品が表示されない。** その店舗の言語への翻訳があるか確認し、なければPolylangで追加してください。翻訳がある場合は、[商品が見つからない場合](../pos/product-panel/index.mdx#goes-wrong)をご覧ください。

**拡張機能の下に言語ページがない。** WCPOS Pro、少なくともひとつの言語を設定したPolylang、WCPOS Polylangのすべてを有効にする必要があります。

## 開発者向け {#developer-hooks}

<details>
<summary>絞り込みの仕組みとフィルター</summary>

- WCPOS Polylangは、WCPOSが行う商品とバリエーションのRESTクエリに、Polylangの `lang` クエリを追加します。対象は `/wcpos/v…/` ルートと、無料版プラグインの `wcpos_request()` によってWCPOSのリクエストと識別されたものの両方です。
- WCPOSの商品とバリエーションのIDのみの一覧（`/wcpos/v1/products` とそのバリエーション用ルートで、`posts_per_page=-1` と `fields=id` または `fields=id,date_modified_gmt` を指定）には、この拡張機能が言語で絞り込んで直接応答します。POS専用商品がオンの場合は、**オンラインのみ** のIDを除外します。
- WCPOS Proでは、ユーザーが利用できる店舗の `store_id` を含むリクエストには、その店舗の言語が使われます。店舗の言語は投稿メタの `_wcpos_polylang_language` に保存され、`/wcpos/v1/stores` から `language` として返されます。

| フィルター | 用途 |
| --- | --- |
| `wcpos_polylang_resolved_language` | リクエストの言語を変更します。言語のスラッグと `WP_REST_Request` を受け取ります。 |
| `wcpos_polylang_default_language` | 店舗に言語が設定されていない場合に使用する言語を変更します。 |
| `wcpos_polylang_is_supported` | Polylangの検出結果にかかわらず、連携を有効または無効にします。 |
| `wcpos_polylang_minimum_version` | Polylangの最低バージョンを指定します。デフォルトは空で、バージョンの確認は行いません。 |

ソース：[github.com/wcpos/wcpos-polylang](https://github.com/wcpos/wcpos-polylang)。

</details>
