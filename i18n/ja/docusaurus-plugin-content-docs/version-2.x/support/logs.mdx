各レジは、販売、同期、設定変更、エラーなど、行った処理をログに記録します。問題が発生すると、何が起きたか、販売にどのような影響があるか、次にどうすればよいかをログで確認できます。WordPress側の問題については、店舗のサーバーにも別のログが記録され、WP Adminで確認できます。

今エラーが出ていますか。[ログ項目を開いて](#open)内容を確認するか、[ログをサポートに送って](#for-support)ください。

## レジで新しいエラーが発生したとき {#unread-badge}

メニュー下部の**店舗の状態**に表示される赤い数字は、最後に**ログ**を開いてから記録されたエラーの件数です。99件を超えると**99+** と表示されます。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[44, 10]]} maxWidth={316} alt="メニュー下部：設定の上にある店舗の状態アイコンに、新しいエラーを示す赤い33が表示されています">

1. **店舗の状態** — 赤い数字はエラーのみの件数で、警告は含みません。スマートフォンでは、メニューを開くと確認できます。

</JourneyShot>

**店舗の状態**を開き、**ログ**を選ぶと数字が消えます。**データベース**や**パフォーマンス**を開いても消えません。件数は、そのレジでログイン中の店舗とレジ係ごとに各レジで保持され、アプリを閉じてもリセットされません。

## ログを読む {#read}

各項目はレジが行った一つの処理を表し、新しい順に並びます。項目は最大30日間保存されます。

このログはレジの動作記録であり、販売の記録ではありません。支払いについて確認する場合は、まず**WooCommerce → 注文**で注文を開いてください。各支払いの簡単な履歴が残っています。ログでは、その前後にこのレジで何が起きたかを確認できます。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[44, 0], [52, 0], [0, -26], [46, 0], [44, 22], [53, 0], [-36, 0], [41, 0], [-36, 0]]} alt="店舗の状態のログタブ：今日の数値、デバッグ情報をコピー、検索欄、フィルターボタンと、時刻、レベル、イベント、所要時間、ステータスが並ぶログ項目の一覧">

1. **店舗の状態** — ログを確認できる場所です。
2. **ログ** — 三番目のタブです。一覧の上にある数値については、[店舗の状態](store-health.mdx#logs)をご覧ください。
3. **エラー** — エラーのみを表示します。[ログ項目を探す](#find)をご覧ください。
4. **時刻** — 今日の項目は時刻、それ以前の項目は日時を表示します。
5. **レベル** — **エラー**、**警告**、**アクション**（人が行った操作）、**同期**、**情報**、**デバッグ**（**詳細診断**がオンの間のみ）のいずれかです。
6. **イベント** — 発生した内容を表示し、その下にアプリの該当箇所と、あればレコード名を表示します。**×2**は、一分ほどの間に同じことが二回起きたことを意味します。
7. **所要時間** — 処理にかかった時間です。
8. **ステータス** — エラーや警告の場合はエラーコード、操作が成功した場合は **✓ 正常**、それ以外は **—** が表示されます。
9. **ステータス行** — **変更を監視中** と、このレジが前回店舗を確認した時刻および次回の確認時刻が表示されます。最初の確認が完了するまでは **初回の確認待ち…** と表示されます。

</JourneyShot>

隣り合う項目が同じ処理に属する場合、左端に同じ色の線が付きます。ほとんどの項目は、記録時の言語に関係なく、レジで現在使用している言語で表示されます。

## ログ項目を探す {#find}

- **ログを検索** — **SYNC131**などのエラーコードや、エラーに含まれる語句を入力します。
- **すべて**、**アクション**、**エラー**、**同期** — **アクション**は人が行った操作、**同期**はレジと店舗との通信です。
- **今日のイベント**、**今日のエラー**、**処理が滞っているレコード** — **今日のイベント**をタップすると**すべて**、**今日のエラー**をタップすると**エラー**、**処理が滞っているレコード**をタップすると**同期**が選択されます。
- **レベル** — 項目の**エラー**などをタップすると、そのレベルだけが表示されます。もう一度タップするか、追加されたボタンの×印を押すと、すべてのレベルを表示します。

一覧の下部にある **…件中…件を表示**は、条件に一致する項目のうち、読み込み済みの件数を示します。下へスクロールすると、さらに読み込まれます。

## ログ項目を開く {#open}

**店舗の状態 → ログ**を開き、**エラー**を押します。問題が発生した時刻の項目を探すか、**ログを検索**にエラーコードを入力してください。項目をタップすると行の下に内容が表示され、もう一度タップすると閉じます。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[50, 0], [64, -10], [-54, -97], [131, 0], [101, 0], [-33, 0]]} alt="エラーフィルターを有効にし、AUTH201の項目を行の下に開いた状態：サーバーの応答、対処方法、レコードを開く、ヘルプリンク、コピー付きのイベントコード、レコード、操作、リクエスト">

1. **エラー** — 有効になっているフィルターです。
2. **ログ項目** — **ステータス**の**AUTH201**がエラーコードです。
3. **発生した内容と対処方法** — 店舗からの応答があればその内容を表示し、その後に対処方法を一行で示します。必要な場合は、**支払いは受領済みです — 再度請求しないでください。** や **この端末のデータを消去しないでください**などの警告が先に表示されます。
4. **ヘルプ — AUTH201** — このドキュメントの該当コードのページを開きます。[エラーコード](../error-codes/index.mdx)をご覧ください。
5. **レコードを開く** — 項目に関連する注文、商品、顧客を開きます。このレジに該当データがあり、店舗でWCPOS Proを使用していて、編集権限がある場合に利用できます。
6. **コピー** — サポートに送るために項目全体をコピーします。隣にある**イベントコード**はレジが行っていた処理を示し、どの言語でも同じです。

</JourneyShot>

処理が滞っている変更や拒否された変更には、**店舗の状態 → データベースへ移動**が表示されます。移動先で対応を選んでください。[対応が必要なとき](store-health.mdx#needs-attention)をご覧ください。**サイト管理者にサーバーログの確認を依頼してください**は、店舗側のログに理由が記録されていることを意味します。[WP Adminで店舗のログを確認する](#wp-admin-logs)をご覧ください。

<details>
<summary>ログ項目の詳細情報</summary>

その下の**レコード**、**操作**、**リクエスト**、**詳細**に、項目の内容が示されます。項目によっては**フィールド**、**試行回数**、**店舗側の理由**が表示されることもあります。追加情報がない項目には、**この項目にこれ以上の詳細はありません。** と表示されます。

</details>

:::warning 消去する前に警告を読んでください
**この端末のデータを消去しないでください**は、店舗にまだ届いていない売上や変更がレジに残っていることを意味します。レジのデータを消去すると、それらは失われます。[すべてのローカルデータの消去](troubleshooting/clear-local-data.mdx)をご覧ください。
:::

## ログをサポートに送る {#for-support}

1. **店舗の状態 → ログ**を開き、**エラー**を押します。
2. 問題が発生したときの項目を開きます。**イベントコード**がある場合は、隣の**コピー**（スマートフォンとタブレットのアプリでは**共有**）を押して、メッセージに貼り付けてください。ない場合は、エラーコードと時刻を送ってください。
3. **デバッグ情報をコピー**（スマートフォンとタブレットのアプリでは**デバッグ情報を共有**）を押し、こちらも貼り付けてください。

   <details>
   <summary>レポートに含まれる情報</summary>

   アプリ、WordPress、WooCommerce、WCPOSのバージョン、店舗名、接続状況、今日の数値、処理が滞っているレコード最大十件、直近のエラー十件です。

   </details>

4. 貼り付けた内容を確認してください。項目の**コピー**には、レジ係の名前が記録されていればその名前が含まれ、エラーメッセージにはレコード名が含まれることもあります。確認したら、両方を[Discord](https://wcpos.com/discord)のサポート、またはメールでsupport@wcpos.comに送ってください。[サポート](index.mdx#where-to-ask)をご覧ください。

:::warning 顧客に再度請求しないでください
サポートのために問題を再現する目的だけで、支払いをもう一度受け付けることは絶対にしないでください。
:::

5. サポートから問題の再現を依頼された場合は、まず**詳細診断**をオンにし、問題を再現して、新しいレポートを送ってください。

<JourneyShot manifest={manifest} device="phone" step={4} offsets={[[-28, 0], [107, 0], [15, -22], [164, 0], [115, -20], [-32, 0]]} maxWidth={390} alt="スマートフォンのログタブでエラーフィルターを有効にした状態：今日の数値、デバッグ情報をコピー、検索欄、フィルターボタン、詳細診断、開いたAUTH201の項目と、そのイベントコードの隣にあるコピー">

1. **デバッグ情報をコピー** — サポート向けの、このレジのレポートです。スマートフォンとタブレットのアプリでは**デバッグ情報を共有**と表示されます。
2. **ログを検索** — 確認を依頼された項目を探します。
3. **エラー** — 有効になっているため、エラーだけが表示されます。
4. **詳細診断：オフ** — タップすると、より詳しい情報を記録します。24時間後に自動でオフになります。
5. **ログ項目** — スマートフォンでは、一番上に時刻とレベル、その次にイベント、その下に該当箇所とレコードまたは所要時間が表示されます。タップすると開きます。
6. **コピー** — サポートへのメッセージ用に項目全体をコピーします。

</JourneyShot>

どちらのレポートも、レジで使用する言語に関係なく英語で出力されます。

## WP Adminで店舗のログを確認する {#wp-admin-logs}

プラグインは、POSのリクエスト、同期、支払い、印刷、レジに関する独自のログをサーバーに保存します。WP AdminでPOS設定を開ける人なら誰でも閲覧できます。**POS → 設定**に移動し、**ツール**の**ログ**を選んでください。

以下は**警告**を有効にした状態です。

<JourneyShot manifest={manifest} device="desktop" step={5} offsets={[[70, 0], [33, 36], [60, 0], [650, 0], [690, 0], [200, 0]]} alt="WP AdminのPOS設定にあるログ画面：メニューのログの隣に赤い1と黄褐色の426が表示され、致命的なエラーを検出したという通知、警告が選択されたすべて・エラー・警告のフィルター、ソース一覧、今日と昨日の下に並ぶ警告があります">

1. **ログ** — **ツール**の下にあります。赤い数字は新しいエラー、黄褐色の数字は新しい警告の件数です。
2. **警告** — 有効になっているレベルフィルターです。隣に**すべて**と**エラー**があります。
3. **ソース** — 拡張機能が独自のログを記録する場合に、どの部分が項目を記録したかを示します。
4. **今日** — 項目は日ごとにまとめられています。
5. **ログ項目** — クリックすると開きます。
6. **WooCommerceのログで表示** — WooCommerce自身のログを開きます。WordPressに致命的なPHPエラーが記録されると、この通知が表示されます。

</JourneyShot>

<details>
<summary>サイト管理者向け：WP Adminのログ</summary>

- 設定メニューの**ログ**にある**赤と黄褐色の数字**は、最後にログを開いてからのエラーと警告の件数です。件数はユーザーごとに保持され、**ログ**を開くと0に戻ります。
- **すべて**、**エラー**、**警告** — レベルで絞り込みます。拡張機能が独自のログを記録すると、**ソース**一覧が表示されます。
- **日ごとの項目** — **今日**、**昨日**、または日付の下に、一ページにつき50件表示されます。**前へ**と**次へ**で移動できます。
- **ログ項目をクリック**すると開き、レベル、ソース、正確な日時、メッセージ、関連情報、**コピー**ボタンが表示されます。

ログはWooCommerce自身のログと一緒に保存されるため、保存期間はWooCommerceによって決まります。このページからログを消去したり、ダウンロードしたりすることはできません。

WordPressに致命的なPHPエラーが記録されると、上部に**致命的なエラーを検出しました — WooCommerceのログで表示**と表示されます。リンクを押すと、新しいタブで**WooCommerce → ステータス → ログ**が開きます。このようなクラッシュによりPOSが店舗に接続できなくなる場合があります。ウェブサイトの管理担当者に見せてください。

</details>

## 問題が発生した場合 {#goes-wrong}

**赤い数字が再び表示される。** 最後に確認した後に、新しいエラーが記録されています。**ログ**を開き、**エラー**を押して最新の項目を読んでください。

**「ログが見つかりません」。** 検索やフィルターに一致する項目がありません。**すべて**を押して、検索欄を空にしてください。

**「前回の確認が完了しませんでした — 再試行中」。** 前回の確認時に、レジが店舗に接続できませんでした。自動で再試行されます。変更がたまっていく場合は、[店舗の状態](store-health.mdx#waiting-to-send)をご覧ください。

**処理が滞っているレコードの件数が、ここに表示されるものとデータベースで異なる。** **店舗の状態 → データベース**を開き、対応が必要なものを確認してください。ここの**処理が滞っているレコード**は、ログで検出した件数です。データベースには、店舗が拒否した変更や保留した変更も表示されます。[対応が必要なとき](store-health.mdx#needs-attention)をご覧ください。

**レジの動作が遅い。** **所要時間**は、各処理にかかった時間を示します。過去24時間全体については、[パフォーマンス](store-health.mdx#performance)と[サーバーのパフォーマンス](performance/server.mdx)をご覧ください。
