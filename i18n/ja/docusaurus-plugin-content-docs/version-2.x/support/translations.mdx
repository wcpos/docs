**設定についての説明ではありません：** POS、プラグイン、このドキュメントの翻訳を修正・追加する方法を紹介します。

WCPOS の翻訳は AI が作成し、公開前に毎回人が確認しています。普段から自分の言語で WCPOS を使っている方なら、機械が見落とした点に気づけます。POS、プラグイン、このドキュメントに不自然な表現があれば、GitHub で該当する行を変更してプルリクエストを送ることで修正できます。開発者である必要はありません。

項目へ移動：[POS・プラグインの修正](#apps-and-plugin) · [ドキュメントの修正](#docs) · [言語の追加](#add-a-language)

## 自分の言語で表示を確認する {#see-it}

修正する前に、その表現が実際に使われている画面を確認してください。POS は、WordPress の「サイトの言語」で設定された店舗の言語で開きます。1 台の端末で別の言語を試すには、メニューから **設定** を開き、**一般** を選択します。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[40, 0], [120, 0], [110, 0]]} alt="設定の一般画面：ローカライズ内の言語選択リストを開き、検索欄に Deutsch と入力した状態">

1. **設定** — メニューの下部にあります。
2. **一般** — 設定の最初のページです。
3. **言語** — この端末の POS で表示する言語です。タップするとリストが開きます。[言語](../settings/store/general.mdx#language)を参照してください。

</JourneyShot>

リストの検索欄に入力して言語を探し、タップします。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[110, 0], [150, 0], [292, 0]]} maxWidth={700} alt="開いた言語リスト：検索欄に Deutsch と入力され、その下にドイツ語（Deutsch）とドイツ語（スイス）（Deutsch (Schweiz)）が表示されている状態">

1. **検索** — 言語名を英語またはその言語で入力します。**Deutsch** と入力するとドイツ語が見つかります。
2. **ドイツ語（Deutsch）** — 言語をタップすると切り替わります。各言語は英語名の後にその言語での名前が表示されます。
3. **ドイツ語（スイス）** — 地域別の言語は基本の言語の隣に表示されます。店舗で使用するものを選んでください。

</JourneyShot>

変更はこの端末だけに適用されます。店舗や他の端末の言語は変わりません。店舗の言語に戻すには、同じページの下部にある **サーバー設定を復元** を押します。店舗から送られてくる通貨と数値形式も元に戻ります。一方、プラグインの WP Admin 画面は、WordPress で設定した自分の言語に従います。

## POS・プラグインの表現を修正する {#apps-and-plugin}

アプリとプラグインの翻訳はすべて [wcpos/translations](https://github.com/wcpos/translations) にあります。

1. 対象の言語と、修正したい WCPOS の部分に対応する **ファイルを探します**。ドイツ語の場合、POS のテキストは [ドイツ語の POS：`core.json`](https://github.com/wcpos/translations/blob/main/translations/js/de_DE/monorepo/core.json)、プラグインの PHP テキストは [ドイツ語のプラグイン：`woocommerce-pos-de_DE.po`](https://github.com/wcpos/translations/blob/main/translations/php/de_DE/woocommerce-pos-de_DE.po) にあります。下の **各ファイルの内容** にすべてのフォルダーを掲載しています。
2. **該当する表現を探します。** Ctrl+F（Mac では ⌘F）を押し、画面で見た表現をファイル内で検索します。JSON ファイルではキーの後に翻訳があります。PO ファイルでは英語の `msgid` の下にある `msgstr` 行が翻訳です。キーや英語の内容が、画面で見た箇所に対応していることを確認してください。
3. **翻訳文だけを変更します。** キーと `msgid` 、また、次のようなプレースホルダー： `{name}`、 `%s`、 `%d` 、 `<strong>` はすべてそのままにしてください。

   JSON ファイルの各項目は、キー、コロン、翻訳の順に並びます。この例の英語は `Delete {name}` ですが、ドイツ語では動詞を最後に置きます。

   ```json title="Before"
   "coupons.delete":
     "Löschen {name}",
   ```

   ```json title="After"
   "coupons.delete":
     "{name} löschen",
   ```

   変更したのはドイツ語の部分だけです。キーの `"coupons.delete"` と `{name}` はそのままです。

   PO ファイルでは、`msgid` が英語、`msgstr` が対象言語の翻訳です。

   ```text
   msgid "Copy of %s"
   msgstr "Kopie von %s"
   ```

   `msgstr` 行の文言だけを変更してください。`msgid` 行と `%s` はそのままにします。

4. **プルリクエストとして送信します。** [GitHub で修正を送信する](#send)を参照してください。

<details>
<summary>各ファイルの内容</summary>

| フォルダー | 内容 |
|---|---|
| `source/` | 自動収集された英語のテキストです。編集しないでください。 |
| `translations/js/<locale>/monorepo/` | レジ係が使う POS のボタン、カート、チェックアウト、ダイアログ、エラー。 |
| `translations/js/<locale>/electron/` | Windows・macOS 向けデスクトップアプリ固有のウィンドウとメニュー。 |
| `translations/js/<locale>/woocommerce-pos/` | 無料プラグインの WP Admin 画面（設定、テンプレートなど）。画面ごとに 1 ファイルあります。 |
| `translations/js/<locale>/woocommerce-pos-pro/` | Pro プラグインの WP Admin 画面（店舗編集、Pro 設定など）。 |
| `translations/php/<locale>/` | プラグインの PHP テキスト。編集するのは `.po` ファイルだけです。同じ場所にある `.mo` と `.l10n.php` の各ファイルは、リポジトリのスクリプトがそのファイルから再生成するため、プルリクエストのチェックで `.mo` が古いと表示される場合があります。プルリクエストには、変更したのは `.po` だけであると記載してください。 |

多くの言語には、`de` のような基本フォルダーと、`de_DE`、`de_AT` のような地域別フォルダーがあります。POS は言語に対応する地域別フォルダーを読み込みます。ドイツ語（Deutsch）なら `de_DE` です。基本フォルダーの `de`、`en`、`es`、`fr`、`nl`、`pt`、`zh` は、リリースごとに主要な地域別フォルダーからコピーされます（`de` は `de_DE` から）。そのため、修正は地域別フォルダーで行ってください。基本フォルダーだけに加えた変更は上書きされます。

</details>

対象の言語がない場合は、[言語の追加](#add-a-language)を参照してください。

## このドキュメントのページを修正する {#docs}

[wcpos/docs](https://github.com/wcpos/docs) には、各ページの言語別のコピーがあります。

1. **ファイルを探します。** ページ下部の **このページを編集** を押すと、GitHub で英語のファイルが開きます。そのパスにある `versioned_docs/` を、次のパスに置き換えます： `i18n/<locale>/docusaurus-plugin-content-docs/`。ここで、対象言語の [言語コード](#locale-codes) を指定する箇所は `<locale>`です。 `de` はドイツ語を表します。パスの残りの部分は変えません。例として、 [このページのドイツ語 1.x 版](https://github.com/wcpos/docs/blob/main/i18n/de/docusaurus-plugin-content-docs/version-1.x/support/translations.mdx)を参照してください。

   <details>
   <summary>別のページや言語を探す</summary>

   このドキュメントは Docusaurus を使用しています。英語のページは `versioned_docs/`内のバージョン別フォルダーにあります。各言語のコピーは `i18n/<locale>/docusaurus-plugin-content-docs/`内の同じバージョンのフォルダーに、英語のページと同じパスで配置されています。コードの一覧は [言語コード](#locale-codes)を参照してください。

   フランス語の場合、英語のファイル `versioned_docs/version-2.x/support/translations.mdx` に対応するのは `i18n/fr/docusaurus-plugin-content-docs/version-2.x/support/translations.mdx` です。[フランス語のフォルダー](https://github.com/wcpos/docs/tree/main/i18n/fr/docusaurus-plugin-content-docs)で内容を確認できます。

   </details>

2. **文言を変更します。** Markdown と MDX の構文、リンク、コード、フロントマターのキーはそのままにしてください。本文、見出し、読者に表示されるラベルを翻訳します。
3. **プルリクエストとして送信します。** 変更するのは次の場所にあるファイルだけです： `i18n/<locale>/`。英語のページは変更しないでください。手順は [GitHub で修正を送信する](#send)を参照してください。

セクション全体の修正や新しい言語の追加など、より大きな変更は、まず issue を作成してください。一緒に進め方を検討します。

## GitHub で修正を送信する {#send}

無料の GitHub アカウントが必要です。すべてブラウザーで操作できるため、インストールは不要です。

1. **GitHub にサインイン** し、修正したいファイルを開きます。
2. ファイル右上の **鉛筆アイコン**（**このファイルを編集**）を押します。初回は GitHub にリポジトリのフォークを求められるので、**このリポジトリをフォーク** を押してください。自分で変更できるコピーが作成されます。
3. エディターで **変更を加えます**。
4. エディター上部の **「変更をコミット…」を押します**。入力ボックスが開きます。
5. ボックスのメッセージ欄に **修正内容を 1 行で記入** し、**変更を提案** を押します。
6. 次のページで **「プルリクエストを作成」を押し**、もう一度 **プルリクエストを作成** を押して送信します。

レビュー担当者が変更を確認してマージするか、プルリクエスト上で質問します。

## 修正が利用者に届くまで {#how-it-works}

すべての変更は公開前に人がレビューします。このドキュメントの修正は、マージ後にサイトに公開されます。POS、デスクトップアプリ、プラグインの修正は、それぞれの次回アップデートで利用者に届きます。

<details>
<summary>全体の流れ</summary>

1. **英語のテキストを収集します。** アプリやプラグインが変更されると、その英語の文字列が [wcpos/translations](https://github.com/wcpos/translations) リポジトリに送られます。このドキュメントの英語は [wcpos/docs](https://github.com/wcpos/docs) に保存されています。
2. すべての言語で **AI が未翻訳部分を補います**。言語ごとのルールと用語集に従います。プレースホルダーやマークアップを壊す翻訳、旧来の長い製品名を使った翻訳は却下され、後で再試行されます。
3. **人が翻訳のバッチをレビュー** し、プルリクエストとしてマージします。
4. **修正を公開します。** このドキュメントでは、マージしたページからサイトを再ビルドして公開します。アプリとプラグインでは、マージすると新しい翻訳リリースが作成されます。POS、デスクトップアプリ、プラグインはそれぞれ特定のリリースを使用するため、修正が反映されるのは次回アップデートです。`.po` ファイルの修正では、先に `.l10n.php` ファイルの再生成も必要なため、さらに時間がかかる場合があります。

アプリとプラグインについては、毎日のチェックで未翻訳部分が残っている場合、[wcpos/translations](https://github.com/wcpos/translations/issues) に issue も作成されます。

</details>

そのため、作業は空のファイルから始めることはほとんどありません。すでにある翻訳の不自然な表現を修正するのが中心です。堅苦しい言い回し、その言語の WooCommerce の用語と合わない言葉、ボタンに収まらないラベルなどが対象になります。

:::note translate.wordpress.org は使用しません
WCPOS は現在、translate.wordpress.org で翻訳を受け付けていません。同サイトでは機械翻訳が認められておらず、ほとんどの言語の翻訳が未完成のままでした。プラグインは wcpos/translations から独自の翻訳をダウンロードします。以前同サイトで WCPOS の翻訳に協力してくださった方には感謝しています。今後の修正は、このページで紹介する場所へお寄せください。
:::

## 言語の追加 {#add-a-language}

アプリとプラグインは、地域別の言語を含めて 50 以上の言語に対応しています。一覧は [`locales.json`](https://github.com/wcpos/translations/blob/main/locales.json) にあります。このドキュメントの対応言語はそれより少なく、以下に掲載しています。必要な言語がない場合は、該当するリポジトリで issue を作成してください。言語を追加します。新しい言語の翻訳は AI がすばやく作成し、その後、その言語を話す方が読みやすく整えます。

### 言語コード {#locale-codes}

<details>
<summary>自分の言語コードを探す</summary>

このドキュメントは次の言語で公開されています。

| コード | 言語 |
|---|---|
| `ar` | アラビア語 *（右から左）* |
| `de` | ドイツ語 |
| `es` | スペイン語 |
| `fr` | フランス語 |
| `hi-IN` | ヒンディー語（インド） |
| `it` | イタリア語 |
| `ja` | 日本語 |
| `ko` | 韓国語 |
| `nl` | オランダ語 |
| `pt-BR` | ポルトガル語（ブラジル） |
| `zh-CN` | 中国語（簡体字） |

2 つのリポジトリではコードの表記が異なります。wcpos/translations は `de_DE`、`pt_BR`、`zh_CN` のようにアンダースコアを使い、基本言語（`de`、`fr`、`es`）と地域別言語（`de_AT`、`fr_CA`、`es_MX`）の両方があります。このドキュメントでは `pt-BR`、`hi-IN`、`zh-CN` のようにハイフンを使います。編集するリポジトリの形式に合わせてください。

</details>

## レビューで確認すること {#translator-tips}

以下は AI が従うルールです。レビュー担当者も同じルールに沿って変更を確認します。

- **プレースホルダーはそのままにします。** `{name}`、 `%s`、 `%d` や、次のようなタグ： `<strong>` は WCPOS が値を埋め込んだり表示したりします。それらの周囲の文言を翻訳してください。
- **製品名は英語のままにします。** `WCPOS`、`WCPOS Pro`、`WooCommerce`、`WordPress` は翻訳しません。Stripe、PayPal、Square、Android、iOS、macOS、Windows など、他のブランド名やプラットフォーム名も同様です。読者向けの本文では **WCPOS** と記載してください。旧来の長い名前を残すのは、スラッグ、ファイル名、Web アドレスだけです。
- **WooCommerce の用語を優先します。** 店舗の運営者は WCPOS と WooCommerce を併用するため、クーポン、払い戻し、税、支払い方法など、WooCommerce にもある用語は、その言語の WooCommerce の翻訳に合わせます。レジ係、レジ、キャッシュドロワーなど、WooCommerce にない用語は、`scripts/translation-glossary.json` にある言語別の用語集に従ってください。
- **英語と同程度の長さにします。** 1 語のボタン名は 1～2 語に収めます。POS 画面のスペースは限られています。
- **文体は言語別の注意事項に従います。** 一部の言語には、wcpos/translations の `scripts/locale-context/` に文体、小数点の区切り文字、よくある注意点を記したファイルがあります。たとえばドイツ語では **Sie** を使います。
- **コードはそのままにします。** クーポンコード、決済ゲートウェイ ID、言語コード、ファイルパス、ショートコードは翻訳しません。判断に迷う場合は英語のままにしてください。ただし、このドキュメントでは例外があります。`WP Admin > WooCommerce > 設定 > 支払い` のようにコード形式で記載したメニューパスには、WordPress と WooCommerce が対象言語で表示するメニュー名を使います。`>` 記号と WP Admin、WooCommerce、WCPOS はそのままにしてください。
- **画面で確認します。** ある画面に収まる表現でも、別の画面では折り返されることがあります。[自分の言語で表示を確認する](#see-it)を参照してください。

アラビア語、ヘブライ語、ペルシャ語、ウルドゥー語など、右から左に書く言語では、レシートにも右から左向けのテンプレートが必要です。ギャラリーから選べます。[レシートのカスタマイズ](../receipts/customise.mdx#the-bundled-templates)と[非ラテン文字のレシート](../hardware/printers/non-latin-receipts.mdx)を参照してください。
