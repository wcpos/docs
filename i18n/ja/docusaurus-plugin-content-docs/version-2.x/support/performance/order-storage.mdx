**症状：** WCPOS の会計に数秒かかり、時間の経過とともに遅くなっています。

:::note この操作はレジではなく WordPress 管理画面で行います
WordPress 管理画面で一度だけ行う操作です。WooCommerce の設定へのアクセス権が必要です。権限がない場合は、ウェブサイトの管理担当者にこの手順を実施するよう依頼してください。会計が遅いことを伝え、このページを送ってください。
:::

よくある原因の1つが、WooCommerce の注文保存方式です。店舗が使用しているストレージの種類を確認し、古い方式であれば WooCommerce 標準のツールで高性能注文ストレージ（HPOS）に移行してください。

## 店舗が使用しているストレージを確認する {#check-which-storage-your-store-uses}

1. WordPress 管理画面で、**WooCommerce → 設定 → 高度な設定 → 機能**に移動します。
2. **注文データストレージ**を探します。
   - **高性能注文ストレージ（推奨）** が選択されている場合：すでに HPOS を使用しているため、これが原因ではありません。[会計が遅くなるその他の原因](#other-causes-of-slow-checkout)をご覧ください。
   - **WordPress 投稿ストレージ（従来）** が選択されている場合：以下の手順で HPOS に切り替えてください。会計のたびに時間がかかっている処理を高速化できます（[理由](#why-legacy-order-storage-slows-checkout)）。店舗の規模が大きいほど効果があります。

この店舗ではすでに HPOS を使用しています。

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[77, 0], [80, 0], [186, 18]]} alt="WooCommerce 設定の高度な設定タブ内の機能ページ：注文データストレージで高性能注文ストレージが選択され、互換モードを有効化は未選択。その下に他の機能が表示されています">

1. **高度な設定** — **WooCommerce → 設定**の最後のタブです。
2. **機能** — タブの下にある最後のリンクです。
3. **注文データストレージ** — 選択されている項目が、店舗で使用しているストレージです。ここでは**高性能注文ストレージ（推奨）** です。HPOS を使用している店舗では、**互換モードを有効化**の下にある同期されていないというメッセージは無視してかまいません。[元に戻す](#switch-back)場合にのみ関係します。

</JourneyShot>

2023年以降に新しく作成された WooCommerce の店舗は HPOS を使用しているため、従来のストレージが残っている可能性が高いのは古い店舗です。

:::tip WCPOS でも確認できます
従来のストレージを使用している店舗では、**POS → 設定 → [レジ](../../settings/wp-admin/checkout.mdx)** の上部に警告が表示されます。警告内の **WooCommerce の注文ストレージ設定を開く** リンクから機能ページに直接移動でき、**切り替え方法** からこのページに戻れます。
:::

## HPOS に切り替える {#switch-to-hpos}

注文の移行は WooCommerce が行います。まず移行先にコピー（同期）し、その後で切り替えます。コピーが完了するまで、WooCommerce は切り替えを許可しません。

:::warning 最初にバックアップしてください
開始前にサイトとデータベースの完全なバックアップを作成し、復元できることを確認してください。[ステージングサイト](../troubleshooting/plugin-conflicts.mdx#before-you-start-use-a-staging-site)がある場合は、まずそこで切り替えを試してください。
:::

1. **WooCommerce → 設定 → 高度な設定 → 機能**に移動します。このページの警告に HPOS と互換性のないプラグイン名が表示される場合は、先にそちらに対処してください。[高性能注文ストレージだけがグレー表示になる](#goes-wrong)をご覧ください。
2. **互換モードを有効化**にチェックを入れ、**変更を保存**をクリックします。WooCommerce がバックグラウンドで注文のコピーを開始します。大規模な店舗では時間がかかる場合があります。チェックボックスの下に**現在注文を同期中...** と未処理の件数が表示され、進捗を確認できます。
3. **互換モードを有効化**の下のメッセージがなくなるまで、時々ページを再読み込みします。メッセージがなくなればコピーは完了です。代わりに**現在、同期されていない注文があります。** と表示される場合は、**今すぐ注文を同期**をクリックしてください。選択肢がグレー表示のままの場合は、[問題が発生した場合](#goes-wrong)をご覧ください。
4. **高性能注文ストレージ（推奨）** を選択し、**変更を保存**をクリックします。
5. **互換モードを有効化**にチェックを入れたまま、すべてが引き続き動作することを確認します。
   - WCPOS でテスト販売を行い、完了することを確認します。
   - **WooCommerce → 注文**で、その販売を探します。
   - 会計、配送、メールなど、注文を扱うプラグインが新しい注文を引き続き認識することを確認します。

   互換モードが有効な間は、両方の注文データが同期されるため、コピーが最新の状態になれば[元に戻す](#switch-back)ことができます。
6. これらの確認が済んだら、**互換モードを有効化**のチェックを外し、**変更を保存**をクリックします。以降、元に戻すには、先に注文をコピーし直す必要があります。[従来のストレージに戻す](#switch-back)をご覧ください。

詳しくは、WooCommerce のガイド[高性能注文ストレージ](https://woocommerce.com/document/high-performance-order-storage/#how-to-enable-high-performance-order-storage)をご覧ください。

## 従来のストレージに戻す {#switch-back}

切り替え後に動作しなくなったものがある場合は、従来のストレージに戻し、問題が起きたプラグインを特定してから再度お試しください。

1. **WooCommerce → 設定 → 高度な設定 → 機能**に移動します。
2. **互換モードを有効化**にチェックが入っていない場合は、チェックを入れて**変更を保存**をクリックします。WooCommerce が注文を従来のストレージにコピーします。
3. **互換モードを有効化**の下のメッセージがなくなるまで待ちます。時々ページを再読み込みし、**今すぐ注文を同期**が表示されたらクリックしてください。それまでは両方の選択肢がグレー表示になります。
4. **WordPress 投稿ストレージ（従来）** を選択し、**変更を保存**をクリックします。

切り替え後に受け付けた注文も引き継がれます。互換モードでは、それらも従来のストレージにコピーされます。

## 問題が発生した場合 {#goes-wrong}

**切り替えようとすると、両方のストレージの選択肢がグレー表示になる。**
WooCommerce でストレージを切り替えられるのは、どちらの方向でも、両方の注文データが同期している場合だけです。まだコピーが完了していません。**互換モードを有効化**の下を確認してください。
- **現在注文を同期中...** と件数が表示されている場合：コピーが進行中です。待ちながら、時々ページを再読み込みしてください。
- **現在、同期されていない注文があります。** と**今すぐ注文を同期**リンクが表示されている場合：コピーは実行されていません。**今すぐ注文を同期**をクリックし、コピーが完了してから切り替えてください。

すでに HPOS を使用し、互換モードを無効にしている店舗では、切り替える予定がなければ、この画面は正常です。ここでは両方の選択肢がグレー表示で、コピーは実行されていません。

<JourneyShot manifest={manifest} device="desktop" step={2} offsets={[[262, 0], [362, 0], [-46, 0], [-44, 0]]} alt="注文データストレージの拡大図：高性能注文ストレージが選択され、両方の選択肢がグレー表示。互換モードを有効化は未選択で、その下に現在、同期されていない注文がありますというメッセージと今すぐ注文を同期リンクがあります">

1. **WordPress 投稿ストレージ（従来）** — コピーが完了するまでグレー表示になります。
2. **高性能注文ストレージ（推奨）** — 選択されていますが、こちらもグレー表示です。
3. **互換モードを有効化** — その下のメッセージで、コピーが実行中かどうかがわかります。
4. **今すぐ注文を同期** — コピーを開始します。

</JourneyShot>

**高性能注文ストレージだけがグレー表示になる。**
有効なプラグインが HPOS と互換性なしとされている間は、WooCommerce は切り替えを許可しません。機能ページの警告に、該当するプラグイン名と**表示と管理**リンクが表示されます。切り替える前に、プラグインを更新するか、開発者に HPOS 対応について確認してください。

**切り替え後に動作しなくなったものがある。**
[従来のストレージに戻し](#switch-back)、問題が起きたプラグインを特定してから再度お試しください。

**切り替え後も会計が遅い。**
注文ストレージだけが原因ではありませんでした。以下の[会計が遅くなるその他の原因](#other-causes-of-slow-checkout)をご覧ください。

## 従来のストレージで会計が遅くなる理由 {#why-legacy-order-storage-slows-checkout}

従来のストレージでは、店舗の規模が大きくなるほど WCPOS での販売の保存に時間がかかります。HPOS では、その遅延の原因となる注文の検索がほぼ瞬時に完了します。ホスティング環境や他のプラグインによって会計が遅くなる場合もあります。[会計が遅くなるその他の原因](#other-causes-of-slow-checkout)をご覧ください。

<details>
<summary>どれくらい速くなるのか、その理由</summary>

WCPOS は注文を保存するたびに、まず WCPOS が割り当てた ID で注文を検索します。従来のストレージでは、WooCommerce は注文を WordPress の投稿と同じテーブルに保存します。このテーブルには、その ID で注文をすばやく見つける仕組みがないため、店舗のレコードを1件ずつ検索します。HPOS は注文を専用のテーブルに保存するため、同じ検索がほぼ瞬時に完了します。

測定したある店舗（商品とバリエーションが約30,000件、従来のストレージを使用）では、1回の検索に約0.46秒かかり、1回の会計で約2回検索していました。HPOS では、同じ検索が約1ミリ秒で完了しました。結果は店舗によって異なりますが、規模が大きいほど効果があります。

</details>

## WCPOS の対応状況 {#what-wcpos-supports}

- **HPOS に完全対応しており、使用を推奨しています。**
- **従来のストレージも引き続き使用できます。** 機能が使えなくなることはありません。大規模な店舗で会計が遅くなるだけです。

## 会計が遅くなるその他の原因 {#other-causes-of-slow-checkout}

会計が遅くなる原因は、注文ストレージだけではありません。すでに HPOS を使用している場合や、切り替え後も会計が遅い場合は、次の点を確認してください。

- **ホスティング環境。** サーバーが高負荷であったり、性能が不足していたりすると、すべての処理が遅くなります。[サーバーのパフォーマンス](./server.mdx)をご覧ください。
- 会計、メールマーケティング、在庫管理など、**注文の保存時に動作する他のプラグイン**。[プラグインの競合](../troubleshooting/plugin-conflicts.mdx)と[会計のパフォーマンス](./checkout.mdx#2-plugin-interference-during-order-creation)をご覧ください。
