Cloudflare を経由する店舗サイトでは、訪問者にセキュリティチェックを求めることがあります。WCPOS アプリはこのチェックを通過できない場合があり、その場合は店舗に接続したり同期したりできません。解決するには、店舗オーナーまたはサイトの Cloudflare アカウント管理者が Cloudflare の設定を変更する必要があります。このページでは、変更する設定とその手順を説明します。

- **レジ係：** [レジでの対応](#at-the-till)をご覧ください。
- **店舗オーナー：** [ブロックの原因となっている Cloudflare の機能を特定する](#which-feature)に進んでください。

## レジでの対応 {#at-the-till}

- **デスクトップアプリにセキュリティチェックのウィンドウが表示された場合：** 2 分以内にチェックボックスをオンにしてください。アプリの処理が続行されます。Cloudflare は 30 分後、または店舗オーナーが設定した時間の経過後に、再びチェックを求めます。
- **iPad、iPhone、Android アプリに HOST121 が表示された場合：** これらのアプリは Cloudflare のチェックを通過できません。店舗オーナーが以下の変更を行うまで、ブロックされたままになります。
- **どちらの場合も、** このページを店舗オーナーに送ってください。デスクトップアプリでは、チェックを通過すると一時的に接続できますが、後で再びチェックが表示されます。

**店舗オーナー：** [ブロックの原因となっている Cloudflare の機能を特定する](#which-feature)から始めてください。

## Cloudflare がアプリをブロックしている兆候 {#how-to-recognise-it}

- 接続画面に **「この店舗のホスティング設定がアプリをブロックしています」** と、エラーコード [HOST121](../../error-codes/HOST121.mdx) が表示されます。
- デスクトップアプリで接続中または同期中に、**your-store.com のセキュリティチェック** という小さなウィンドウが開きます。

<details>
<summary>店舗オーナーが気づく可能性のあるその他の兆候</summary>

- **WP Admin > POS > 設定 > 一般** の上部に **「この店舗は Cloudflare を経由しています」** と表示されます。このプラグインは、Cloudflare を経由するすべてのサイトで、問題が起きる前からこのメッセージを表示します。
- クラウド印刷が停止し、**WP Admin > POS > 設定 > クラウド印刷** のプリンターカードに **「セキュリティサービス（Cloudflare やファイアウォールプラグインなど）が WCPOS Cloud Print をブロックしています」** と表示されます。[リレー](../../receipts/cloud-printing.mdx#relay)はアプリと同じ方法で店舗にアクセスするため、以下の対処で印刷も復旧します。
- 古いバージョンのアプリでは、ブラウザーで正常に開ける店舗でも **「このサイトは WordPress サイトではないようです」** または **「サイトの応答に時間がかかりすぎました」** と表示されていました。

</details>

## ブロックの原因となっている Cloudflare の機能を特定する {#which-feature}

ここからは店舗オーナー向けの説明です。Cloudflare ダッシュボードでサイトを開き、次の手順に進んでください。

1. **セキュリティ > 分析** に移動し、**イベント** タブを選択します。アプリがブロックされた時刻の `/wp-json/` へのリクエストを探してください。**サービス** フィールドには、**ボットファイトモード** や **マネージドルール** など、リクエストを阻止した機能名が表示されます。
2. 以下から該当する機能の項目を開いてください。設定の場所と対処方法が記載されています。
3. 該当するイベントが見つからない場合、無料プランではリクエストの一部しかログに記録されないため、アプリのリクエストが含まれていない可能性があります。代わりに、以下の 4 つの機能のうち、どれがオンになっているか確認してください。

まず Cloudflare が原因かどうか確かめたい場合は、任意で[ターミナルでの確認](#check)を行ってください。

<details>
<summary>ボットファイトモード（無料プラン）：オフにする</summary>

- 場所：**セキュリティ > 設定** で、**ボットトラフィック** で絞り込みます。
- 対処：オフにします。スキップルールではアプリをこの機能の対象から除外できません（[理由](#bot-fight-mode)）。

</details>

<details>
<summary>スーパーボットファイトモード（Pro プラン以上）：スキップルールを追加する</summary>

- 場所：**セキュリティ > 設定** で、**ボットトラフィック** で絞り込みます。
- 対処：[スキップルールを追加します](#add-a-skip-rule)。

</details>

<details>
<summary>訪問者にチャレンジを要求するカスタムルールまたはマネージドルール：スキップルールを追加する</summary>

- 場所：**セキュリティルール**。
- 対処：[スキップルールを追加します](#add-a-skip-rule)。

</details>

<Anchor id="under-attack" />

<details>
<summary>攻撃を受けているモード：オフにするか、設定ルールを追加する</summary>

- 場所：サイトの概要にある **クイックアクション**、または **セキュリティ > 設定** にある **セキュリティレベル** 設定。
- 対処：攻撃が収まったらオフにします。サイトの他の部分ではオンのままにするには、[スキップルールの式](#add-a-skip-rule)を使って **設定ルール**（**ルール > 概要 > ルールを作成 > 設定ルール**）を追加し、**攻撃を受けています** をオフにします。

</details>

WordPress 用の Cloudflare プラグインでは、このページのルールを追加できません。Cloudflare ダッシュボードで変更してください。

## REST API 用のスキップルールを追加する {#add-a-skip-rule}

スキップルールを使うと、店舗の REST API へのリクエストは、以下でチェックを入れた Cloudflare のチェックだけをスキップします。それ以外のチェックは引き続き適用されます。WordPress によるログインと権限の確認も引き続き行われます。

:::note
無料プランのボットファイトモードには、このルールは適用されません。アプリをブロックしている機能がボットファイトモードの場合は、代わりに[オフにしてください](#bot-fight-mode)。
:::

1. Cloudflare ダッシュボードでサイトを開き、**セキュリティルール** に移動して **ルールを作成 > カスタムルール** を選択します。
2. **ルール名** に `WCPOS REST API` と入力します。
3. **受信リクエストが一致する場合** で **式を編集** を選択し、次を貼り付けます。

   ```text
   (starts_with(http.request.uri.path, "/wp-json/")) or (http.request.uri.path eq "/" and (starts_with(http.request.uri.query, "rest_route=") or http.request.uri.query contains "&rest_route="))
   ```

   WordPress が `https://example.com/shop` などのサブフォルダーにある場合は、`/wp-json/` と `/` の代わりに、それぞれ `/shop/wp-json/` と `/shop/` を使用します。

   <details>
   <summary>この式が一致する対象</summary>

   前半は API の通常のアドレス `/wp-json/` に一致します。後半は代替アドレス `/?rest_route=/` に一致しますが、対象はサイトのホームアドレスに限られます。そのため、リンクにたまたま `rest_route=` が含まれているページは引き続き保護されます。

   </details>

4. **実行するアクション** で **スキップ** を選択します。
5. ルールでスキップする対象を選びます。次の項目には必ずチェックを入れてください。
   - **残りのすべてのカスタムルール**：他のカスタムルールがアプリにチャレンジを要求したり、アプリをブロックしたりしないようにします。
   - **セキュリティレベル**。攻撃を受けているモードがオンの場合は、その[設定ルール](#under-attack)も追加します。

   次の項目は、該当する場合のみチェックを入れてください。
   - **すべてのスーパーボットファイトモードルール**：スーパーボットファイトモードがオンの場合。
   - **すべてのマネージドルール**：イベントログで、アプリのリクエストの **サービス** フィールドに **マネージドルール** と表示されている場合。該当するイベントが見つからない場合はチェックを入れず、[まだブロックされる場合](#still-blocked)をご覧ください。

   **（旧バージョン）** と記載されている項目にはチェックを入れないでください。
6. **デプロイ** を選択します。他のカスタムルールが訪問者にチャレンジを要求したり、訪問者をブロックしたりする場合は、**セキュリティルール** の一覧でこのルールをそれらより上にドラッグしてください。マネージドルールは常にカスタムルールの後に実行されるため、その順序は関係ありません。

アプリで接続または同期を行い、通信できることを確認します。コンピューターから確認する場合は、[ターミナルでの確認](#check)を実行してください。応答は `200` で、`content-type: application/json` があり、`cf-mitigated` の行がない状態になるはずです。

### ボットファイトモードがオンの場合 {#bot-fight-mode}

無料プランのボットファイトモードでは、スキップルールと許可ルールは無視されます。Cloudflare の公式ドキュメントでも、カスタムルールやページルールでは回避できないと説明されています。**ボットファイトモード** がオンで、スキップルールを追加してもアプリがブロックされる場合は、**セキュリティ > 設定** で **ボットトラフィック** に絞り込み、ボットファイトモードをオフにしてください。その後、アプリを試すか、もう一度[確認](#check)を行います。ボット対策を維持するには、Pro プランに移行して **スーパーボットファイトモード** を使用してください。この機能なら、上記のスキップルールで対象から除外できます。ボットファイトモードがすでにオフの場合は、[まだブロックされる場合](#still-blocked)をご覧ください。

## コンピューターから確認する {#check}

この確認は任意です。対処の前後に、ご自身のコンピューターから、店舗に代わって Cloudflare が応答しているかどうかを確認できます。

<details>
<summary>ターミナルで確認する</summary>

ターミナル（Mac ではターミナル、Windows では PowerShell）を開き、`your-store.com` を店舗のアドレスに置き換えて、次を実行します。Windows では、`curl` の代わりに `curl.exe` と入力してください。

```bash
curl -sI https://your-store.com/wp-json/
```

応答の最初の数行を確認します。

- **`403` と `cf-mitigated: challenge`：** Cloudflare がアプリをブロックしています。原因となっている[機能を特定してください](#which-feature)。
- **`200` と `content-type: application/json`：** このコンピューターからは通信できました。アプリで接続または同期を試してください。アプリがまだブロックされる場合、Cloudflare がアプリとコンピューターを異なる方法で処理している可能性があります。上記の機能を確認し、その後[プラグインの競合](./plugin-conflicts.mdx)をご覧ください。
- **`404`：** このアドレスに REST API はありません。基本形式以外のパーマリンクを使用していないサイトでは、別のアドレスを使います。`'https://your-store.com/?rest_route=/'` で再度確認してください（引用符は残してください）。

WordPress がサブフォルダーにある場合は、そのフォルダーも含めます：`https://example.com/shop/wp-json/`。

</details>

<details>
<summary>デスクトップアプリがチェックを通過する仕組み</summary>

アプリは店舗の REST API と通信します。REST API は、アプリにデータを返す WordPress の機能です。Web ブラウザーは利用者が気づかないうちに Cloudflare のチェックを通過しますが、通常、アプリは通過できません。Cloudflare がデータの代わりにチェックを返すと、デスクトップアプリは非表示のブラウザーウィンドウを開き、自動で通過を試みます。Cloudflare がチェックボックスの操作を求める場合は、ウィンドウを表示して 2 分間待ちます。その後、Cloudflare は **チャレンジ通過** に設定された時間（既定では 30 分間）、アプリの通信を許可します。その時間が過ぎると再びチェックが表示されます。iPad、iPhone、Android アプリには、このウィンドウはありません。

</details>

## Cloudflare による API のキャッシュを停止する {#caching}

Cloudflare は REST API の応答をキャッシュすることもあります。その場合、アプリには古い商品、価格、注文が表示されます。スキップルールが無効にするのはセキュリティチェックだけであり、キャッシュには影響しません。HTML ページをキャッシュしている場合や Automatic Platform Optimization（APO）を使用している場合は、同じ式で **キャッシュルール** を追加し、**キャッシュをバイパス** に設定してください。

## まだブロックされる場合 {#still-blocked}

- スキップルールを開き、下書きとして保存（**下書きとして保存**）されているのではなく、デプロイされていることを確認してください。
- **IP アクセスルール** が店舗のインターネット接続をブロックしたり、チャレンジを要求したりしていないか確認してください。
- **イベント** ログにアプリのイベントがない場合は、マネージドルールをスキップする前に、[ターミナルでの確認](#check)の結果を添えて、下記のサポートにお問い合わせください。
- サイトへのアクセスを中継する他のサービスも、同じようにアプリをブロックすることがあります。セキュリティプラグインとファイアウォールについては[プラグインの競合](./plugin-conflicts.mdx#server-level-conflicts)を、GoDaddy、WP Engine などのホスティングサービスについては[ホスティングサービス別の注意事項](../performance/server.mdx#hosting-specific-notes)をご覧ください。
