レスポンスエラーは、店舗のウェブサイトがPOSに何も返さなかったか、データ以外のもの（エラーページ、PHPの警告、セキュリティチェックなど）を返したことを意味します。問題はレジではなくウェブサイト側にあります。

## レジでの対処 {#at-the-till}

:::warning 二重に請求しないでください
**CHECKOUT201** が発生した場合、お客様はすでに支払いを済ませている可能性があります。再度支払いを受け付ける前に、注文を開いてステータスを確認してください。手順は [CHECKOUT201](../../error-codes/CHECKOUT201.mdx#troubleshoot) のページにあります。
:::

1. **操作が完了したか確認してください。** 保存しようとしていた商品や顧客を探します。見つかれば、そのまま作業を続けてください。販売の場合は、次のように確認します。
   - 注文を探します。WCPOS Proでは **注文** を開きます（CHECKOUT201のページの手順に従って、先に更新してください）。Proをお使いでない場合は、担当者がWP Adminで **WooCommerce → 注文** を開きます。
   - **処理中** または **完了**：販売は正常に処理されています。再度請求しないでください。
   - 未払い、または注文が見つからない場合：カード決済サービスの画面またはキャッシュドロアーを確認してください。
2. **もう一度試してください。** 一時的な不具合は、再試行で解消することがよくあります。**CHECKOUT201** の後は、注文が未払いで、支払いも受け取っていない場合に限り再試行してください。判断できない場合は、[サポートに相談してください](#get-help)。
3. **まだ失敗しますか？** **店舗の状態 → ログ** を開き、**デバッグ情報をコピー**（スマートフォン・タブレット用アプリでは **デバッグ情報を共有**）を押します。場所は以下の[エラーを確認する](#find-the-error)で説明しています。エラーコードと一緒に、ウェブサイトの管理担当者またはWCPOSサポートに送ってください。

エラーを消すために、この端末のデータを削除しないでください。店舗サイトにまだ反映されていない変更が残っている可能性があります。[ローカルデータの削除](./clear-local-data.mdx)を参照してください。

## エラーを確認する {#find-the-error}

**店舗の状態** を開き、**ログ** に移動します。**エラー** をタップすると問題だけが表示されます。行をタップして開いてください。**SYNC151** と、POSがまだ再試行している変更での **SYNC131** は警告なので、**すべて** から探してください。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[12, -36], [170, 0], [31, 32], [-40, 0], [133, 6], [-40, 0], [-30, 0]]} alt="店舗の状態のログタブでエラーに絞り込み、エラーの行を開いた画面。店舗サイトからの応答、対処方法、エラーコードのヘルプリンク、ログ項目のコピーボタン、上部のデバッグ情報をコピーが表示されています">

1. **店舗の状態** — サイドバーの心拍アイコンです。赤いバッジに未読エラーの件数が表示されます。スマートフォンでは左上のメニュー内にあります。
2. **ログ** — この端末で行ったすべての操作と発生したすべての問題を、最大30日間保存します。[ログ](../logs.mdx)を参照してください。
3. **エラー** — 対処が必要な行だけを表示します。各行の末尾にあるコードで、問題の種類がわかります。
4. **開いた行** — 店舗サイトからの応答、次に行うこと、そして **リクエスト** の下に店舗サイトが返したステータスが表示されます。この例は変更が拒否された場合(`403`)です。レスポンスエラーでは末尾が **SYNC131**、**SYNC151**、**CHECKOUT201** のいずれかになり、多くの場合 `500` が表示されます。
5. **ヘルプ** — そのエラーコードのページを開きます。
6. **コピー** — このログ項目だけをコピーし、サポートへのメッセージに貼り付けられるようにします。
7. **デバッグ情報をコピー** — この端末と最近のエラーに関するレポートをコピーします。スマートフォン・タブレット用アプリでは **デバッグ情報を共有** と表示されます。

</JourneyShot>

## コードの意味 {#codes}

以前のバージョンのWCPOSでは、レスポンスエラーが `Cannot read properties of undefined (reading 'data')` と表示されていました。現在は、ログの行の末尾に次のいずれかのコードが表示されます。

- **[SYNC131](../../error-codes/SYNC131.mdx)：店舗サイトでエラーが発生し、このリクエストを完了できませんでした。** ウェブサイトがリクエストの処理中に失敗したか、データの代わりにページを返しました。
- **[SYNC151](../../error-codes/SYNC151.mdx)：店舗サイトの応答に不要なテキストが含まれていたため、WCPOSが除去を試みました。** プラグインやテーマがデータの前にテキストを出力しました。多くの場合はPHPの警告です。POSはそのテキストを除去しましたが、操作が完了したか確認してください。
- **[CHECKOUT201](../../error-codes/CHECKOUT201.mdx)：WCPOSはチェックアウトが完了したか確認できませんでした。** 販売データは送信されましたが、応答が返ってきませんでした。注文が作成され、支払いも済んでいる可能性があります。
- **[HOST121](../../error-codes/HOST121.mdx)：店舗サイトのAPIの代わりに、ボット対策ページが応答しています。** ファイアウォールやセキュリティサービスが店舗サイトに代わって応答しました。POSは店舗への接続時にこれを確認します。それ以降は、同じページが返されるとSYNC131として表示されます。[Cloudflare](./cloudflare.mdx)を参照してください。

**問題が発生しました：** の後に技術的なテキストが続く赤いバーは、別の問題を示しています。画面の一部を描画できなかったという意味です。**X** で閉じてください。[CLIENT151](../../error-codes/CLIENT151.mdx)を参照してください。

## ウェブサイト側の原因を調べる {#find-the-cause}

以下は、WordPressサイトの管理担当者向けの手順です。

<details>
<summary>サイト管理者向け：エラーログ、応答、その内容からわかること</summary>

### 店舗サイトのエラーログを読む {#error-log}

1. WP Adminで **WooCommerce → ステータス → ログ** に移動します。
2. エラーが発生した時刻付近の、最新の `fatal-errors` ログを開きます。PHPがクラッシュすると、プラグイン名やファイル名を示す行が記録されます。

POSプラグイン独自のログである **POS → 設定 → ログ** には、致命的なエラーがあると **致命的なエラーを検出しました — WooCommerceのログで確認してください** と表示されます。[致命的なエラー](./critical-error.mdx)を参照してください。

### 応答そのものを読む {#read-the-reply}

1. パソコンのブラウザーで `yourdomain.com/pos` を開き、POSにアクセスします。デスクトップアプリでは、代わりに **詳細設定 → 開発者ツールの切り替え** を使います。
2. 開発者ツールを開きます。ページを右クリックして **検証** を選択するか、`Ctrl + Shift + I`（Macでは `Cmd + Option + I`）を押します。
3. **ネットワーク** タブに移動し、失敗した操作を繰り返します。結果がわからない支払いは、絶対に繰り返さないでください。[二重に請求しないでください](#at-the-till)の説明に従って、まず注文を確認します。
4. 赤色または `5xx` ステータスで表示されている失敗したリクエストをクリックし、**レスポンス** を読みます。

### 応答からわかること {#what-the-reply-tells-you}

- **`{` の前に `Warning:`、`Notice:`、`Deprecated:` のテキストがある。** プラグインやテーマが、すべての応答にPHPのメッセージを出力しています。PHPメッセージの画面表示をオフにして（`WP_DEBUG_DISPLAY` を `false` に設定）、プラグインを修正または置き換えてください。[プラグインの競合](./plugin-conflicts.mdx)を参照してください。
- **「このサイトで重大なエラーが発生しました」。** PHPがクラッシュしました。上記のfatal-errorsログを確認してください。[致命的なエラー](./critical-error.mdx)を参照してください。
- **セキュリティチェックや「人間であることを確認してください」というページ。** ファイアウォールやボット対策が店舗サイトに代わって応答しています。店舗サイトのREST APIへの通信を許可してください。[Cloudflare](./cloudflare.mdx)を参照してください。
- **内容が空で、ステータスが `500`、`502`、`503`、`504` のいずれか。** サーバーがメモリ不足になったか、処理時間の上限に達しました。ホスティング事業者にPHPのエラーログと制限値を問い合わせてください。[サーバーのパフォーマンス](../performance/server.mdx#503-errors)を参照してください。
- **どれにも当てはまらない、または更新後に発生し始めた。** WordPress、WooCommerce、PHPが[最小要件](../../getting-started/installation.mdx#server-requirements)を満たしているか確認してください。

まだ解決しない場合は、応答からわかったこととエラーコードをWCPOSサポートに送ってください（[サポートに相談する](#get-help)）。

</details>
