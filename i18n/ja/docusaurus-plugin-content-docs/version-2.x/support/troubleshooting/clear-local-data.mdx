POS はすばやく販売できるよう、またオフラインでも販売を続けられるよう、各端末に店舗データのコピーを保存しています。**すべてのローカルデータを消去** は、このコピーを削除して店舗から再ダウンロードします。ほかの部分的な対処では直せない端末のデータ不具合を解消するための操作です。最初ではなく、最後の手段として試してください。

:::warning 店舗に届いていない売上は失われます
この端末がまだ送信していないデータも一緒に削除され、復元できません。現金をすでにドロワーに受け取っている、完了済みの売上も含まれる可能性があります。[先に確認してください](#check-unsent)。
:::

## 先に試す対処法 {#try-first}

以下の方法はそれぞれ特定の問題だけを解消し、端末上のほかのデータには影響しません。

- **特定の種類のレコードがおかしい場合**（商品、顧客、注文）：[店舗の状態 → データベース](../store-health.mdx#clear-and-redownload)で該当する行の **消去して再ダウンロード…** を選びます。端末上のほかのデータは変わらず、サインインしたまま操作できます。**注文** を消去する前に、未完了の注文をすべて完了するか同期してください。一度も同期していない注文は、この端末にしか存在しません。
- **WooCommerce の変更が届いていない場合：** 同じ行のメニューから **今すぐ変更を確認** を選びます。[ダウンロードと同期](../../products/sync.mdx)を参照してください。
- **この端末の言語、通貨、数値形式が正しくない場合：** **設定 → 一般** の下部にある **サーバー設定を復元** を押すと、WooCommerce 店舗の値に戻ります。[一般設定](../../settings/store/general.mdx#restore-server-settings)を参照してください。
- **画面に赤い「問題が発生しました」パネルが表示される場合：** 閉じるか、再読み込みしてください。[CLIENT151](../../error-codes/CLIENT151.mdx)を参照してください。

## 送信待ちのデータがないことを確認する {#check-unsent}

店舗の状態に表示される件数は、現在サインイン中の店舗とレジ係のものだけです。端末上では店舗ごと、レジ係ごとに売上が分けて保存されていますが、消去するとすべて削除されます。そのため、この端末を使うすべてのレジ係について、利用するすべての店舗で確認してください。

1. **店舗の状態** を開き、**データベース** タブの **送信待ちの変更** を確認します。件数が **0** で、数値の下に **… 件の変更がサーバーに届いていません** や **… 件の変更が保留されています** のパネルがないことを確認してください。パネルがあれば先に対処します。[対応が必要なとき](../store-health.mdx#needs-attention)を参照してください。
2. カートの下にある未完了の注文を確認します。支払いも同期もしていない注文はこの端末にしか存在せず、上記の件数には含まれません。注文を完了するか、**注文の詳細** で **注文を同期** を押してください。[注文を店舗に保存する](../../pos/cart/open-orders.mdx#sync-order)を参照してください。この一覧に表示されるのは一度に 1 台のレジの注文だけです。このレジ係が同じ店舗でほかのレジも使う場合は、レジ係パネルの **レジを切り替え** で各レジを選んで確認します。
3. アバターをタップしてレジ係パネルを開き、次のレジ係を選びます。別の店舗を確認するには、同じパネルで **店舗を切り替え** を選びます。[店舗とレジの選択](../../stores/registers-and-devices.mdx#choosing-a-store-and-a-register)を参照してください。
4. すべてのレジ係の確認が済むまで繰り返します。全員分を確認できない場合は、消去せずに[サポートにお問い合わせください](../index.mdx)。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[40, 0], [150, 0], [160, 0], [100, -369]]} alt="店舗の状態のデータベースタブ：上部に送信待ちの変更が 0 件と表示され、その下にこの端末のレコード一覧がある状態">

1. **店舗の状態** — メニュー下部の脈拍アイコンです。
2. **データベース** — この端末のデータと送信待ちのデータを表示します。
3. **送信待ちの変更** — 店舗への送信を待つ売上、顧客、編集内容です。カートに残る未完了の注文や、判断待ちの変更はこの件数に含まれません。
4. **一覧表** — この端末と店舗にある各種レコードです。**⋮** メニューには、[先に試す対処法](#try-first)で紹介した部分的な修正操作があります。

</JourneyShot>

- **0 件で、パネルがなく、未同期の未完了注文もない場合：** このレジ係がこの店舗で行った作業は店舗に届いています。次のレジ係を確認してください。
- **0 件より多い場合：** まだ消去しないでください。端末をオンラインにし、件数が 0 になるまで待ちます。減らない場合は、[「送信待ちの変更」が減らない](../store-health.mdx#waiting-to-send)を参照してください。

## 消去されるもの {#what-gets-cleared}

対象はこの端末だけです。店舗やほかの端末には影響しません。未送信の売上は失われ、プリンター、スキャナー、レジの選択を再設定する必要があります。デスクトップアプリとモバイルアプリでは店舗情報とサインイン情報も消去されるため、後で店舗に再接続します。

<Accordion>
<AccordionItem question="この端末から消去されるもの">

- 端末に保存された商品、顧客、注文、クーポン、税
- 未送信の売上と変更
- この端末で設定したプリンターとバーコードスキャナー
- 選択したレジ
- この端末の **設定 → 一般** で行った変更
- 店舗の状態にあるこの端末のアクティビティログ
- デスクトップアプリとモバイルアプリの店舗情報とサインイン情報

</AccordionItem>
<AccordionItem question="店舗に残るもの">

- この端末からすでに送信した売上、顧客、編集内容のすべて
- WooCommerce の商品、顧客、注文
- WP Admin で行った設定
- レジと送信済みの締め処理

</AccordionItem>
</Accordion>

消去後は、[印刷](../../hardware/printers/index.mdx)でプリンターを、[バーコードスキャン](../../settings/store/barcode.mdx)でスキャナーを再設定してください。

## すべてのローカルデータを消去する {#clear}

1. メニュー下部の歯車アイコンから **設定** を開き、一覧の先頭にある **一般** を選びます。
2. 一番下までスクロールし、**すべてのローカルデータを消去** を押します。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[40, 0], [-72, 0], [-100, 0]]} alt="設定 → 一般の最下部：メニューの設定の歯車アイコン、設定一覧の先頭の一般、サーバー設定を復元、その下にすべてのローカルデータを消去が表示されている状態">

1. **設定** — メニュー下部の歯車アイコンです。**一般** は設定一覧の最初のページです。
2. **サーバー設定を復元** — [先に試す対処法](#try-first)で紹介した部分的な修正です。データは削除されません。
3. **すべてのローカルデータを消去** — ページの最後のボタンです。削除前に確認が表示されます。

</JourneyShot>

3. 確認メッセージを読みます。最初の行に応じて、次のように操作してください。
   - **変更の件数が表示される場合は、キャンセルを押してください。** *この端末の N 件の変更はサーバーに届いておらず、完全に失われます。* [先に送信してください](#check-unsent)。
   - **アプリで確認できなかったと表示される場合は、すべての店舗のすべてのレジ係が[確認](#check-unsent)を済ませ、送信待ちが 0 件、パネルなし、未同期の未完了注文なしという条件を満たす場合だけ続行してください。** そうでなければ **キャンセル** を押し、[サポートにお問い合わせください](../index.mdx)。この店舗に送信待ちがない場合、アプリは常に *送信待ちの変更を確認できませんでした…* と表示します。端末上のほかのレジ係や店舗を確認できないためです。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[-24, 0], [0, 32]]} alt="設定の上に表示された「すべてのローカルデータを消去しますか？」の確認画面。サーバーに届いていない売上についての警告と、キャンセル、すべてのローカルデータを消去の各ボタンがある">

1. **キャンセル** — 確認画面を閉じます。データは削除されません。
2. **すべてのローカルデータを消去** — この端末に保存されたすべてのデータを削除します。元に戻せません。

</JourneyShot>

4. **すべてのローカルデータを消去** を押します。デスクトップアプリでは、もう一度 **よろしいですか？** と確認されるので、**はい** を押します。POS が再起動します。iOS・Android アプリでは、代わりに **再起動が必要です** と表示されます。アプリを完全に閉じてから、もう一度開いてください。

## 消去後の動作 {#what-happens-next}

**ブラウザーでは**、ページが再読み込みされます。WordPress にサインインしているため、サインイン状態は維持されます。**デスクトップアプリでは**、初回起動時の状態で再起動するので、店舗に接続して再度サインインします。**iOS・Android アプリでは**、案内が表示されたらアプリを閉じて開き直し、店舗に接続して再度サインインします。[店舗への接続](../../getting-started/connect.mdx)を参照してください。

その後、初回と同じように POS が商品、顧客、最近の注文をダウンロードします。[ダウンロードと同期](../../products/sync.mdx)を参照してください。店舗に複数のレジがある場合は、この端末で使うレジの選択を求められます。[店舗とレジの選択](../../stores/registers-and-devices.mdx#choosing-a-store-and-a-register)を参照してください。

## アプリが開かない場合 {#app-wont-open}

アプリ全体が **問題が発生しました** の画面で止まり、**再試行しても、この端末のデータはすべて保持されます** と表示される場合、2 つのボタンがあります。まず **再試行** を押してください。

:::warning リセット前に確認してください
この画面や、以下で紹介するデスクトップアプリのメニューからリセットすると、この端末の未送信の売上がすべて削除されます。[すべての店舗の各レジ係](#check-unsent)について、送信待ちの変更が **0** 件、パネルなし、未同期の未完了注文なしと確認できてからリセットしてください。確認できる画面までアプリを開けない場合は、リセットする前に[サポートにお問い合わせください](../index.mdx)。
:::

- **再試行** — データには一切手を加えず、アプリをもう一度開こうとします。必ず最初に試してください。
- **アプリデータをリセットして再起動** — この画面からすべてのローカルデータを消去します。**アプリデータをリセットして再起動しますか？** と確認され、設定画面の確認と同様に、失われる変更の件数が表示されます。**リセットして再起動** または **キャンセル** を押してください。

アプリが送信待ちのデータの有無を判断できない場合があります。その場合は、サーバーに届いていない完了済みの売上もリセットの対象に **含まれる可能性がある** と警告されます。オフラインで行った販売が WooCommerce に表示されない場合は、リセットせずにサポートへお問い合わせください。

デスクトップアプリでは、メニューバーの **ウィンドウ → 詳細設定 → アプリデータを消去** を選び、**はい** を押すことでも消去できます。設定画面までアプリを開けない場合に使います。

## 問題が発生した場合 {#goes-wrong}

**「再起動が必要です」。** アプリは自動で再起動できません。完全に閉じてから、もう一度開いてください。起動時にデータが消去されます。

**「リセットが完了しませんでした」。** 消去が途中で止まっており、完了するまで新しいデータは保存できません。**再読み込みして再試行** を押してください。ボタンがない場合は、アプリを完全に閉じてから、もう一度開きます。

**「ローカルデータを消去できませんでした」。** アプリを完全に閉じて開き直し、もう一度試してください。

**最初のダウンロードが遅い場合。** データの多い店舗では時間がかかります。[店舗の状態 → データベース](../store-health.mdx#database)で進行状況を確認できます。過去の注文など、必要に応じてダウンロードされるレコードは、開くと再取得されます。

**消去後に問題が再発した場合。** 再度消去しないでください。表示されている内容を記録し、[サポートにお問い合わせください](../index.mdx)。
