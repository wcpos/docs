## プラグインの競合が疑われる症状 {#signs-of-plugin-conflicts}

プラグインの追加や更新後に次のような症状が出た場合、プラグインの競合が考えられます。

- **ログインウィンドウにエラーまたは空白のページが表示される。**
- **アプリに「このサイトの WordPress REST API には認証が必要です」と表示される**、またはログイン済みのユーザーだけが REST API を利用できるという他のプラグインのメッセージが表示される。
- POS または WP Admin で、**「このサイトで重大なエラーが発生しました」と表示される**。
- **商品、注文、顧客のダウンロードが止まる**、または売上を店舗に保存できない。
- **レガシータブにある決済ゲートウェイの支払いページの表示が崩れる**、またはボタンを押しても反応しない。
- **全体的に動作が遅い**、またはリクエストがタイムアウトする。会計処理の遅さについては、専用ページの[会計のパフォーマンス](../performance/checkout.mdx)を参照してください。

プラグインの更新後に WP Admin から **POS** メニューが消えた場合は、[プラグインの更新後に POS が消えた](../../getting-started/upgrading-to-2.mdx#pos-gone)を参照してください。

## 始める前に：ステージングサイトを使う {#before-you-start-use-a-staging-site}

:::warning 本番サイトでトラブルシューティングを行わないでください
レジが使用しているサイトでプラグインを無効化すると、販売ができなくなったり、オンラインストアに変更が生じたりすることがあります。ステージングサイトで行ってください。
:::

### ステージングサイトとは？ {#what-is-a-staging-site}

ステージングサイトは、お客様やレジに影響を与えずに変更をテストできる、サイトのコピーです。多くのホスティング会社では、管理画面から数回のクリックで作成できます。

### ホスティング会社がステージング機能を提供していない場合 {#if-your-host-doesnt-offer-staging}

サイトのコピー方法をホスティング会社に問い合わせてください。コピーする方法がない場合は、対応しているホスティング会社への移行を検討してください。ステージングは今回だけでなく、プラグイン、テーマ、WordPress、WooCommerce を更新するたびに必要になります。WP Engine、SiteGround、Kinsta、Cloudways はいずれもステージング機能を提供しています。

## ステップ 1：致命的なエラーを探す {#step-1-check-for-fatal-errors}

クラッシュ時には、通常、原因となったプラグイン名が記録されます。まず次の場所を確認してください。

1. **POS のログ。** ドロワーメニューから **店舗の健全性** を開き、**ログ**、**エラー** の順に選択します。[ログ](../logs.mdx)を参照してください。
2. **WooCommerce の致命的なエラーログ。** [重大なエラー](./critical-error.mdx)の手順に従って、WP Admin で確認してください。
3. **ファイルパスを確認します。** たとえば、 `wp-content/plugins/<plugin-name>/…` のような行からプラグイン名がわかります。

エラーに WooCommerce や WCPOS 以外のプラグイン名が出ている場合は、ステージングサイトでそのプラグインを無効化し、もう一度試してください。プラグイン名が見つからない場合は、ステップ 2 に進んでください。

## ステップ 2：プラグインを無効化し、一つずつ有効化する {#step-2-the-plugin-elimination-method}

致命的なエラーがない場合や、動作が遅い場合に、この方法を使います。

### 2.1 問題の内容を記録する {#21-create-a-baseline}

1. **ステージングサイトの POS を開きます。** ブラウザーでは、ステージングサイトのアドレスの `/pos` にアクセスします。アプリでは、ステージングサイトのアドレスを別の店舗として接続し（[接続](../../getting-started/connect.mdx)を参照）、先に進む前に **サイト一覧** でアドレスを確認してください。
2. **問題が起きる操作を実行し**、メッセージ、画面、かかった時間など、実際に起きたことを正確に記録します。
3. **動作が遅い場合は**、後で比較できるように[ログ](../logs.mdx)にある処理時間を記録します。

### 2.2 POS 以外をすべて無効化する {#22-disable-all-plugins-except-essential-ones}

**次のプラグインは有効のままにします：**
- WooCommerce
- WCPOS
- WCPOS Pro（使用している場合）
- 決済ゲートウェイ（その支払いページで問題が起きている場合）

**それ以外をすべて無効化します：**
1. `WP Admin > プラグイン` に移動します。
2. 他のすべてのプラグインにチェックを入れます。
3. **一括操作** から **無効化** を選択します。
4. **適用** をクリックします。

以下は、無料プラグインを使用している店舗の **プラグイン** 一覧の下部です。まだ何もチェックしていない状態です。

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[59, 52], [59, 52], [59, 52], [105, 0], [78, 0]]} alt="WP Admin のプラグイン一覧の下部：チェックボックス付きの WCPOS Pro、WCPOS、WooCommerce の各行、WooCommerce の新しいバージョンが利用可能という通知、一覧の下にある一括操作と適用">

1. **WCPOS Pro** — チェックを入れないでください。この店舗ではインストール済みですが、有効化されていません。
2. **WCPOS** — チェックを入れないでください。
3. **WooCommerce** — WCPOS が必要としている間はチェックボックスがグレー表示になるため、有効なままです。
4. **一括操作** — 他のすべてのプラグインにチェックを入れたら、**無効化** を選択します。
5. **適用** — チェックを入れたプラグインを無効化します。

</JourneyShot>

### 2.3 もう一度試す {#23-test-the-issue}

1. **すべてのキャッシュを削除します**：ホスティング会社、CDN、キャッシュプラグインのキャッシュが対象です。
2. **問題が起きた操作を実行します。** 今度は正常に動作しますか？
3. **動作が遅い場合は**、処理時間を記録した時間と比較します。

**正常に動作する場合：** 無効化したプラグインのいずれかが原因と考えられます。[プラグインを一つずつ有効化する](#24-enable-plugins-one-by-one)に進み、どれを有効化すると問題が再発するか調べてください。

**まだ問題が起きる場合：** このテストでは原因を特定できていません。プラグインを一つずつ有効化する手順には進まず、[ステップ 3](#step-3-check-for-theme-conflicts)でテーマを確認してください。テーマも原因でない場合は、次を確認します。
- サーバーのリソースとファイアウォール：[サーバーのパフォーマンス](../performance/server.mdx)を参照してください。
- [Cloudflare](./cloudflare.mdx) など、サイトへのアクセスを中継するサービス
- WordPress、WooCommerce、WCPOS 自体の場合：[問題の内容を記録する](#21-create-a-baseline)で記録した内容を添えて、[サポートにお問い合わせください](#getting-help)

### 2.4 プラグインを一つずつ有効化する {#24-enable-plugins-one-by-one}

<details>
<summary>最初に試すプラグイン</summary>

原因を早く見つけるため、競合しやすい種類のプラグインから始めます。
1. **セキュリティとログインのプラグイン**：Wordfence、Sucuri、Solid Security など
2. **キャッシュと最適化のプラグイン**
3. **決済ゲートウェイ**
4. **その他の WooCommerce 拡張機能**
5. **SEO プラグイン**
6. **その他すべて**

</details>

**各プラグインをテストします：**

1. **プラグインを一つ有効化します。**
2. **もう一度試します。**
3. **引き続き正常に動作する場合：** 次のプラグインを有効化し、もう一度試します。
4. **問題が再発した場合：** 直前に有効化したプラグインを記録します。そのプラグインが競合の原因と考えられます。

**そのプラグインが原因か確認します：**

1. WooCommerce、WCPOS、WCPOS Pro、および最初から有効のままにしていた決済ゲートウェイを残し、**再び有効化したプラグインを無効化します**。
2. **記録したプラグインだけを有効化し**、もう一度試します。
3. **問題が再発する場合：** そのプラグインが競合の原因です。
4. **再発しない場合：** 別のプラグインも関係している可能性があります。他のプラグインを一つずつ有効化し、問題が再発する組み合わせを記録します。

### 2.5 調べた結果を記録する {#25-document-your-findings}

1. **プラグインの名前とバージョン。**
2. **どのような不具合が起きるか**。2.1 で記録した内容をそのまま使います。
3. **新しいバージョンが公開されているかどうか。**

これらの情報は、[ステップ 4](#step-4-resolving-plugin-conflicts)や[サポートへのお問い合わせ](#getting-help)で必要になります。

## ステップ 3：テーマを確認する {#step-3-check-for-theme-conflicts}

POS の画面にはサイトのテーマを使用しないため、テーマがレジの不具合を引き起こすことはまれです。ただし、WordPress から POS に送られる次のものには影響する場合があります。

- 会計画面の **レガシー** タブにある決済ゲートウェイの支払いページ、および [Web Checkout](../../payment/gateways/web-checkout.mdx) ゲートウェイがお客様を誘導するオンラインストアの購入手続き画面
- POS 設定を含む WP Admin の画面
- POS が行う REST API リクエスト。これらのリクエストでも WordPress はテーマのコードを実行するためです。

### デフォルトのテーマでテストする {#test-with-a-default-theme}

1. **ステージングサイトで**、Twenty Twenty-Five や Twenty Twenty-Four など、WordPress のデフォルトテーマに切り替えます。
2. **もう一度試します。**
3. **正常に動作する場合：** テーマが原因です。どのような不具合が起きるか、テーマの開発者に伝えてください。

## ステップ 4：競合を解消する {#step-4-resolving-plugin-conflicts}

原因のプラグインがわかったら、次の方法を順番に試してください。

### 方法 1：プラグインを更新する {#option-1-update-the-plugin}

1. **更新があるか確認します。** 競合がすでに修正されている可能性があります。
2. **まずステージングサイトで更新し**、もう一度試します。
3. **それで問題が解消し**、POS とオンラインストアの購入手続きがどちらも正常に動作することを確認できたら、本番サイトを更新します。

### 方法 2：POS を処理対象から除外する {#option-2-exclude-the-pos}

多くの競合は、相手のプラグインを無効化せずに、その設定で解消できます。[除外する対象](#what-to-exclude)と、[既知のプラグイン競合](#known-plugin-conflicts)にある該当プラグインの対処法を参照してください。

### 方法 3：代替プラグインを探す {#option-2-find-an-alternative}

1. 同じ機能を持つ**別のプラグインを探します**。
2. **ステージングサイトで試します。**
3. 切り替える前に、**設定を移行します**。

### 方法 4：プラグインの開発者に連絡する {#option-3-contact-plugin-developer}

次の情報を送ってください。
- プラグインのバージョン、および WordPress、WooCommerce、WCPOS のバージョン
- 不具合の内容と、表示された正確なメッセージ
- 問題を再現する手順

### 方法 5：開発者に回避策を依頼する {#option-4-custom-solution}

外せないプラグインの場合、WordPress の開発者がそのプラグインのフックを使って、競合する処理を POS のリクエストやページでは実行しないようにできることがあります。

## 除外する対象 {#what-to-exclude}

以下の対処法の多くは、相手のプラグインを無効化するのではなく、POS を処理対象から除外するものです。[既知のプラグイン競合](#known-plugin-conflicts)に該当プラグインがある場合は、その項目に変更箇所が記載されています。一覧にない場合は、以下の詳細をサイト管理者またはプラグインのサポート担当者に渡してください。

<details>
<summary>サイト管理者向けのアドレスと設定</summary>

POS は WordPress サイトの REST API を通じて、店舗のデータを読み書きします。このリクエストをブロック、キャッシュ、書き換えするプラグインは、不具合を引き起こす可能性があります。プラグインが一覧にない場合は、次のように設定します。

- **ファイアウォールと REST API の設定：** `/wp-json/` 自体と、`/wp-json/wcpos/` 以下のすべてへのアクセスを許可します。それ以外のアドレスでは保護を有効のままにしてください。
- **キャッシュとスクリプト最適化の設定：** `/pos` と `/wcpos-checkout/` を除外します。
- **設定が見つからない場合：** この表をプラグインのサポート担当者に送り、これらのアドレスをどこに追加すればよいか問い合わせてください。

| アドレス | POS での用途 |
| --- | --- |
| `/wp-json/wcpos/` | POS が読み書きするすべてのデータ |
| `/wp-json/` | アプリの接続時に店舗を検出します。アプリが読み取るのはこのアドレス自体で、その配下のアドレスではありません |
| `/pos` | ブラウザーで開く POS です。これはデフォルト値です。サイトによっては `WP Admin > 設定 > Permalinks` の **POS ベース** に別の値を設定している場合があります |
| `/wcpos-auth/` | アプリのログインウィンドウ |
| `/wcpos-checkout/` | **レガシー** タブにある決済ゲートウェイの支払いページとレシート |


:::note アプリのログインウィンドウは WordPress のログインページを使いません
デスクトップアプリとモバイルアプリでは、別ウィンドウで `/wcpos-auth/` にある WCPOS 独自のフォームからログインします。ログインアドレスの変更、二要素認証コード、CAPTCHA、メールアドレスのみでのログインなど、WordPress のログインページを変更するプラグインは、このフォームには適用されません。ブラウザーで POS を開く場合は、先に通常の WordPress ログインページに移動するため、これらのプラグインが適用されます。
:::

</details>

## 競合しやすいプラグインの種類 {#common-conflicting-plugin-types}

<details>
<summary>どのようなプラグインが影響するのでしょうか？</summary>

**特に競合しやすいもの：**

- **セキュリティとファイアウォールのプラグイン** は、REST API リクエストをブロックしたり、大量のリクエストの後にレジからのアクセスを遮断したり、ログインを妨げたりすることがあります。
- **キャッシュと最適化のプラグイン** は、POS に古い応答を返したり、WordPress が POS 用に生成するページのスクリプトを壊したりすることがあります。
- **ログイン、会員管理、アクセス制御のプラグイン** は、未ログインのユーザーが REST API を利用できないようにしたり、ログイン方法を変更したりすることがあります。
- **ページビルダーとフロントエンドに要素を挿入するプラグイン** は、決済ゲートウェイの支払いページに独自のスクリプトやオーバーレイを読み込むことがあります。
- **注文や商品の保存時に実行される処理** は、毎回の販売を遅くしたり、売上を保存できなくしたりすることがあります。

**問題が起きることが少ないもの：** お問い合わせフォーム、ソーシャルメディア、アクセス解析、コンテンツ関連のプラグインが POS に影響することはまれです。[WooCommerce Tax](../../integrations/woocommerce-tax.mdx) は POS で動作し、POS の売上にもオンライン注文と同じ税率が自動で適用されます。

</details>

### セキュリティとログインのプラグイン {#security-and-login-plugins}

最もよくある原因です。POS のリクエストがブロックされ、アプリで接続、ログイン、店舗データのダウンロードができなくなります。

<details>
<summary>Wordfence：POS で接続やダウンロードができない</summary>

**症状：** ファイアウォールが POS の REST API リクエストをブロックします。

**対処法：** ファイアウォールで `/wp-json/wcpos/` を許可します。REST API 全体ではなく、このアドレスだけを許可してください。

</details>

<details>
<summary>Really Simple Security：REST API がブロックまたはリダイレクトされる</summary>

**症状：** REST API へのアクセスがブロックされるか、強制的にリダイレクトされます。

**対処法：** プラグインの **詳細** 設定で REST API の制限を無効にします。

</details>

<details>
<summary>Solid Security (iThemes Security)：REST API がブロックされる、またはレジからのアクセスが遮断される</summary>

**症状：** REST API がブロックされるか、ブルートフォース攻撃とみなされてレジからのアクセスが遮断されます。

**対処法：** POS のアドレス `/wp-json/` と `/wp-json/wcpos/`、およびサーバー自身の IP アドレスを許可します。サイト全体で IP アドレスを許可しないでください。

</details>

<details>
<summary>Sucuri：POS で接続やダウンロードができない</summary>

**症状：** ファイアウォールが REST API リクエストをブロックします。

**対処法：** Sucuri のダッシュボードで `/wp-json/wcpos/` を許可します。

</details>

<details>
<summary>Force Login など REST API を制限するプラグイン：「認証が必要です」</summary>

**症状：** アプリに _「このサイトの WordPress REST API には認証が必要です」_ と表示されるか、ログイン済みのユーザーだけが REST API を利用できるというプラグイン独自のメッセージが表示されます。

**対処法：** 未ログインの訪問者が REST API にアクセスできるようにするか、少なくとも `/wp-json/` と `/wp-json/wcpos/` へのアクセスを許可します。

</details>

<details>
<summary>Security Optimizer：ブラウザーの POS でカスタムログイン URL を求められる</summary>

**症状：** ブラウザーで POS を開くと、カスタムログイン URL を使うよう求めるメッセージが表示され、先に進めません。

**対処法：** 先にカスタムログイン URL から WP Admin にログインし、その後 `/pos` に移動します。

</details>

<details>
<summary>Jetpack CRM Client Portal：ユーザーがログインできない</summary>

**症状：** ユーザーが POS にログインできません。

**対処法：** Jetpack CRM 全体ではなく、Client Portal 拡張機能だけを無効化します。

</details>

### パフォーマンス、キャッシュ、最適化のプラグイン {#performance-caching-optimisation-plugins}

<details>
<summary>WP Rocket、Autoptimize、Hummingbird、Smush：レガシーの支払いページが正常に動作しない</summary>

**症状：** JavaScript の遅延読み込みや圧縮により、**レガシー** タブにある決済ゲートウェイの支払いページが正常に動作しなくなります。

**対処法：** `/wcpos-checkout/` と `/pos` を JavaScript の最適化対象から除外します。

</details>

<details>
<summary>LiteSpeed Cache：会計時にデスクトップアプリが再読み込みされる</summary>

**症状：** 会計時にデスクトップアプリが何度も再読み込みされます。

**対処法：** WCPOS と LiteSpeed Cache を更新し、キャッシュを削除して、`/wcpos-checkout/` と `/pos` をキャッシュ対象から除外します。

</details>

### ページビルダーとフロントエンドに要素を挿入するプラグイン {#page-builders-front-end-injectors}

これらのプラグインは、**レガシー** タブの決済ゲートウェイが POS 内に開く支払いページに、独自のスクリプトやオーバーレイを読み込みます。そのページには、スクリプトやスタイルを取り除く **チェックアウト設定** ボタンがあります。[決済ゲートウェイの支払いページの表示がおかしい](../../pos/checkout/troubleshooting.mdx#checkout-settings-troubleshooting)を参照してください。

<details>
<summary>Elementor：支払い方法が開かない</summary>

**症状：** `elementor-frontend.js` によって支払いページが正常に動作しなくなり、支払い方法を開けません。

**対処法：** **チェックアウト設定** の **選択したスクリプトを無効化** で Elementor のフロントエンドスクリプトを取り除くか、`/wcpos-checkout/` で Elementor がそのスクリプトを読み込まないようにします。

</details>

<details>
<summary>Omnisend などのマーケティングプラグイン：支払いページのレイアウトが崩れる</summary>

**症状：** スクリプトによって支払いページのレイアウトが崩れ、決済が正常に動作しなくなります。

**対処法：** **チェックアウト設定** の **選択したスクリプトを無効化** で、該当するスクリプトを取り除きます。

</details>

<details>
<summary>MyStickyElements、Complianz：ボタンやバナーが支払いページを覆う</summary>

**症状：** 追従ボタンや Cookie バナーが支払いページを覆ってしまいます。

**対処法：** `/wcpos-checkout/` を除外するよう設定するか、**チェックアウト設定** で該当するスクリプトを取り除きます。

</details>

### WooCommerce 拡張機能とその他のプラグイン {#woocommerce-extensions-other-plugins}

<details>
<summary>Stripe Tax：POS の注文で動作しない</summary>

**症状：** REST API 経由で作成された注文では動作しません。POS はすべての注文を REST API 経由で保存します。

**対処法：** 回避策はありません。POS で使える税金の自動計算機能は [WooCommerce Tax](../../integrations/woocommerce-tax.mdx) です。

</details>

<details>
<summary>WP Activity Log：データベースが肥大化し、店舗の動作が遅くなる</summary>

**症状：** POS によるすべての変更が記録されるため、データベースが肥大化し、店舗の動作が遅くなります。

**対処法：** プラグインを無効化するか、POS の商品と注文をログの記録対象から除外します。

</details>

<details>
<summary>MailerLite：売上の保存時にサーバーエラー (500) が発生する</summary>

**症状：** MailerLite Signup Forms と MailerLite の WooCommerce 連携機能を両方とも有効にしていると、POS で注文を保存する際にサーバーのメモリが不足し、サーバーエラー (500) が返されます。

**対処法：** 両方を無効化して原因を確認し、MailerLite に問い合わせてください。

</details>

<details>
<summary>The Courier Guy Shipping：注文を保存できない</summary>

**症状：** サーバーエラーにより、POS で注文を保存できません。

**対処法：** プラグインを以前のバージョンに戻すか、開発者に問い合わせてください。

</details>

<details>
<summary>Mollie：銀行振込が表示されない</summary>

**症状：** POS の会計画面で銀行振込が非表示になります。

**対処法：** Mollie を更新します。

</details>

<details>
<summary>CTX Feed：POS 設定ページで 403 エラーが発生する</summary>

**症状：** POS 設定ページで時々 403 エラーが発生します。

**対処法：** プラグインを無効化して原因を確認します。解決できる設定は現在確認されていません。

</details>

<details>
<summary>バーコードスキャナープラグイン：注文を保存または表示できない</summary>

**症状：** REST API が送信する注文データが壊れ、注文を保存または表示できなくなります。

**対処法：** 該当プラグインを無効化します。POS 自体にバーコードを読み取る機能があります。[バーコードスキャン](../../pos/product-panel/barcode-scanning.mdx)を参照してください。

</details>

<details>
<summary>PixelYourSite、PixelMySite：重大なエラー</summary>

**症状：** _bool に対するメンバー関数 `is_type()` の呼び出し_ という重大なエラーが発生します。

**対処法：** プラグインを無効化します。

</details>

<details>
<summary>Google Listings & Ads：WCPOS のクラスが見つからないという重大なエラー</summary>

**症状：** WCPOS のクラスが _見つからない_ という重大なエラーが発生します。

**対処法：** WCPOS のプラグインをすべて削除してから、最新の WCPOS Pro だけをインストールします。

</details>

<details>
<summary>WooCommerce Subscriptions：1.7 以前からの Pro のアップグレードが妨げられる</summary>

**症状：** WCPOS Pro のアップグレード処理が妨げられます。

**対処法：** Subscriptions を無効化し、WCPOS Pro を有効化してアップグレードの完了を待ち、その後 Subscriptions を再び有効化します。

</details>

:::warning Stripe Terminal：WooCommerce の決済設定では無効のままにしてください
Stripe Terminal は `WP Admin > POS > 設定 > 支払い` で、POS 用としてのみ有効にしてください。`WP Admin > WooCommerce > 設定 > 支払い` で有効にする必要はありません。そこで有効にするとオンラインストアの購入手続き画面に表示され、オンラインのお客様が購入手続きを行えなくなる事例がありました。[Stripe Terminal](../../payment/gateways/stripe-terminal.mdx) を参照してください。
:::

### サーバーレベルの競合 {#server-level-conflicts}

<details>
<summary>Web サーバーが設定するセキュリティヘッダー：POS がロゴ画面から進まない、またはページが空白になる</summary>

`.htaccess`、Nginx、ホスティング会社の管理画面に設定された `Content-Security-Policy` または `X-Frame-Options` の行が原因です。

**症状：** POS がロゴ画面から進まない、またはレガシータブの支払いページやレシートが空白になります。

**対処法：** `/pos`、`/wcpos-auth/`、`/wcpos-checkout/` をそのヘッダーの適用対象から除外します。POS のページはインラインスクリプトから起動し、`cdn.wcpos.com` と `cdn.jsdelivr.net` からファイルを取得するため、CDN のアドレスを許可するだけでは不十分です。WordPress やプラグインが追加したこれらのヘッダーは WCPOS が自身のページから取り除きますが、Web サーバーが追加したヘッダーは取り除けません。

</details>

<details>
<summary>GoDaddy Website Firewall：「'undefined' を受信しました」</summary>

**症状：** `/wp-json/` がブロックされ、_「'undefined' を受信しました」_ と表示されます。

**対処法：** ファイアウォールで `/wp-json/` のパスを許可します。[サーバーのパフォーマンス](../performance/server.mdx#hosting-specific-notes)を参照してください。

</details>

### WCPOS が自動で対処する競合 {#handled-by-wcpos}

<details>
<summary>以前は競合していたものの、現在は対処が不要なプラグイン</summary>

WCPOS を最新の状態にしておけば、以下の設定は不要です。

- **プラグインが追加するセキュリティヘッダー。** Wordfence、LiteSpeed Cache などのプラグインは、POS の読み込みを妨げる `Content-Security-Policy` を追加することがあります。WCPOS は自身のページから `Content-Security-Policy` と `X-Frame-Options` を取り除きます。これらのページにポリシーが必要な場合、開発者は `wcpos_content_security_policy` フィルターで設定できます。
- **JWT 認証プラグイン。** 以前は POS のログイントークンを拒否していたため、ログイン後のすべてのリクエストが 403 で失敗していました。現在は WCPOS 自体がリクエストを認証した場合に、これらのプラグインのエラーを解除します。他のプラグインのエラーは引き続き返されます。
- **Image Prioritizer。** アプリが WordPress サイトを検出するために使う `Link` ヘッダーを埋めてしまいます。そのヘッダーにサイトの REST API が示されていない場合、アプリは代わりに `/wp-json/` で探します。それでもアプリに _「このサイトは WordPress サイトではないようです」_ と表示される場合は、プラグインを無効化してください。
- **商品の保存時に動作するプラグイン**（Jetpack、Astra、Xero など）。古いバージョンの WCPOS では、リクエストのたびにこれらのプラグインが重複する行を追加していました。この問題は 1.8.12 で修正され、アップグレード時に重複が削除されました。
- **WooCommerce Stripe 11.1.0。** カード決済用スクリプトが、**レガシー** タブの支払いページで他のすべての支払い方法による決済を妨げていました。Stripe プラグインが 11.1.1 より古い場合、WCPOS はそのページから Stripe のカード決済用スクリプトとスタイルを取り除きます。これにより他の支払い方法は使えますが、Stripe のカード入力フォームは表示されません。Stripe は 11.1.1 でこの競合を修正しました。Stripe を更新すると、以前に **チェックアウト設定** で無効にして保存していた場合でも、WCPOS は再びカード入力フォームをページに表示するようになります。
- **MyParcel。** [その他の商品](../../pos/cart/index.mdx#miscellaneous-products)が入ったカートでは、注文の保存時に MyParcel で重大なエラーが発生し、会計を完了できませんでした。現在は WooCommerce と同様に、その明細に対応するカタログ商品がないことを WCPOS が MyParcel に伝えるため、販売を完了できます。

</details>

## 競合を防ぐためのヒント {#prevention-tips}

### 定期的なメンテナンス {#regular-maintenance}

1. **プラグインを最新の状態に保ちます。**
2. 無効化したまま残すのではなく、**使わないプラグインは削除します**。
3. 本番サイトに適用する前に、**すべての更新をステージングサイトでテストします**。
4. [サーバーのパフォーマンス](../performance/server.mdx)を参考に、**サーバーの速度を確認します**。

### プラグインの選び方 {#plugin-selection-best-practices}

1. 評価が高く、**継続的に更新されているプラグインを選びます**。
2. **同じ機能を持つプラグインを二つ同時に使わないでください。**
3. **使用中の WooCommerce バージョンでテスト済みと記載されているか確認します。**
4. **プラグインは一つずつ追加し**、その都度レジの動作を確認します。

## サポートを受ける {#getting-help}

### 送っていただきたい情報 {#when-contacting-support}

1. **有効化しているプラグイン**とそのバージョン。`WP Admin > Tools > Site Health > Info` に一覧があり、**サイト情報をクリップボードにコピー** ボタンでコピーできます。
2. **WordPress、WooCommerce、WCPOS のバージョン。**
3. **問題の内容**。記録した内容をそのままお送りください。
4. **すでに試した対処法。**
5. [ログ](../logs.mdx)の**エラーメッセージ**。ログタブの **デバッグ情報をコピー**（iOS と Android アプリでは **デバッグ情報を共有**）で、必要な情報をまとめられます。
6. 動作が遅い場合は、**サーバーの応答時間**。
