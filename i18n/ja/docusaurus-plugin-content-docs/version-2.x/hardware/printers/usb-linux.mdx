Linuxでは、アクセスを許可するまでデスクトップアプリからUSBレシートプリンターを使用できません。ルールファイルに一行追加する作業を一度行えば、許可できます。

このページは、Linuxのデスクトップアプリで**テストページを印刷**を押すと、**何も印刷されませんでした**と表示され、**アプリによるプリンターへのアクセスが許可されていません。システム設定で許可してから、もう一度お試しください。** というメッセージが出る場合に役立ちます。Linuxにはこの設定画面がないため、以下のルールで設定します。

<details id="other-signs">
<summary>この問題のその他の兆候</summary>

- メッセージの下にある**サポート詳細**に`LIBUSB_ERROR_ACCESS`と表示されます。
- 検索結果のプリンターカードに、プリンター本来の名前ではなく、**USBプリンター**と数字の列が表示されます。通常、これはアプリがプリンターにアクセスして名前を読み取れなかったことを意味します。

</details>

:::note 始める前に
以下の行を端末にコピーできるよう、レジ端末でこのページを開き、その端末で作業してください。**端末**アプリを開きます（UbuntuとLinux Mintでは**Ctrl+Alt+T**を押します）。レジ端末の管理者パスワードも必要です。わからない場合は、レジ端末を設定した担当者にこのページを送ってください。
:::

## アプリにプリンターへのアクセスを許可する {#do-this}

以下の各コマンドは灰色の枠内に表示されています。実行するには、枠にポインターを合わせ、右上のコピーボタンを押します。次に端末内をクリックし、**Ctrl+Shift+V**で貼り付けて**Enter**を押します。

コマンドでパスワードを求められたら、入力してEnterを押します。入力中は画面に何も表示されないか、星印だけが表示されますが、正常な動作です。

### プリンターのIDを確認する {#find-ids}

1. プリンターを接続し、電源を入れます。
2. プリンターの二つのIDを確認します。端末で次を実行してください。

   ```bash
   lsusb
   ```

   `command not found`と表示された場合は、先に[lsusbをインストール](#command-not-found)してください。各行は一台のUSBデバイスを表します。`Bus 001 Device 007: ID 04b8:0e28 Seiko Epson Corp.`のような、お使いのプリンターの行を探してください。

   その行の見方は次のとおりです。

   - メーカーID：`04b8`。`ID`の直後にあるコードです。
   - 機種ID：`0e28`。コロンの後にあるコードです。
   - メーカー名：末尾の`Seiko Epson Corp.`です。該当する行を見つける手がかりになります。

   どの行がプリンターかわからない場合は、プリンターを抜いて`lsusb`をもう一度実行し、消えた行を確認してください。

### ルールを作成して読み込む {#create-rule}

3. nanoテキストエディターで、新しいルールファイルを開きます。

   ```bash
   sudo nano /etc/udev/rules.d/99-receipt-printer.rules
   ```

   端末内でnanoが開き、空のページと、下部にキー操作の一覧が表示されます。`command not found`と表示された場合は、先に[nanoをインストール](#command-not-found)してください。

4. ファイルにルールを入力します。このルールにより、このレジ端末のすべてのアカウントで、この二つのIDに一致するプリンターを使用できます。先ほどと同じように、枠のコピーボタンでこの行をコピーしてください。行は枠より長いため、全体を読むには枠にポインターを合わせ（スマートフォンではタップ）、コピーボタンの左にある折り返しボタンを押します。

   ```text
   SUBSYSTEM=="usb", ATTRS{idVendor}=="04b8", ATTRS{idProduct}=="0e28", MODE="0666"
   ```

   次に、nanoで以下の操作を行います。
   1. **Ctrl+Shift+V**で**ルールを貼り付けます**。
   2. **二つのIDを置き換えます。** 矢印キーで`04b8`と`0e28`に移動します。この二つのコードだけを、お使いのプリンターのIDに置き換えてください。`lsusb`の表示どおりに正確に入力し、前後の引用符は残してください。
   3. 保存する前に**行を確認します**。`SUBSYSTEM=="usb",`で始まり、`MODE="0666"`で終わる一行になっていて、`04b8`と`0e28`があった位置に、お使いの二つのIDが引用符で囲まれていることを確認してください。
   4. **Ctrl+O**、続いて**Enter**を押して**保存**します。
   5. **Ctrl+X**で**nanoを終了**します。端末のプロンプトに戻ります。

   <details id="rule-parts">
   <summary>ルールの各部分の意味</summary>

   ルールは四つの部分で構成され、最後の部分以外はカンマで終わります。

   - `SUBSYSTEM=="usb",`：USBデバイス用のルールであることを示します。
   - `ATTRS{idVendor}=="04b8",`：メーカーIDです。
   - `ATTRS{idProduct}=="0e28",`：機種IDです。
   - `MODE="0666"`：このパソコンのすべてのアカウントにプリンターの使用を許可します。レジ端末に必要な設定です。

   </details>

5. ルールを読み込みます。

   ```bash
   sudo udevadm control --reload-rules && sudo udevadm trigger
   ```

   パスワードを求められたら、もう一度入力してください。成功すると何も表示されず、プロンプトに戻ります。エラーが表示された場合は、ここで作業を止め、[解決しない場合](#still-stuck)を参照してください。

6. プリンターを抜き、接続し直します。

### プリンターを追加してテストする {#add-and-test}

7. 以前に**テストせずに保存**でこのプリンターを保存した場合は、先に削除してください。**設定 → 印刷**で、そのプリンターの行の **⋮** メニューを開き、**削除**を選択します。
8. デスクトップアプリで**設定 → 印刷**を開き、**プリンターを追加**を押します。USBプリンターの検索が自動的に始まります。**USB**と表示された、お使いのプリンターのカードを選択してください。アプリがプリンターにアクセスできるようになったため、カードにはプリンターから取得した名前が表示されます。
9. **テストページを印刷**を押します。パネルに**テストページは印刷されましたか？** と表示されるので、回答してください。
   - **はい、正しく印刷されました**：プリンターが保存され、パネルにプリンター名と**の設定が完了しました**と表示されます。**完了**を押してください。これでプリンターを使用できます。
   - **印刷されましたが、目盛りがずれています**：プリンターに入っている用紙を選択すると、テストページが再度印刷されます。[印刷されましたが、目盛りがずれています](./setup-wizard.mdx#test-page-ruler)を参照してください。
   - **何も出てきませんでした**：パネルに**何も印刷されませんでした**と表示されます。引き続きプリンターへのアクセスが許可されていないと表示される場合は、[ルールを追加しても許可されない](#still-not-allowed)を参照してください。別のメッセージが表示される場合は、[何も出てきませんでした](./setup-wizard.mdx#test-page-nothing)を参照してください。

:::tip 自分のアカウントでアプリを起動する
デスクトップアプリは通常の方法で起動し、`sudo`は使用しないでください。このルールにより、アプリは自分のアカウントでプリンターを使用できるようになります。
:::

## 問題が発生した場合 {#goes-wrong}

該当する症状を探してください。

- [ルールを追加しても許可されない](#still-not-allowed)
- [`lsusb`または`nano`：コマンドが見つからない](#command-not-found)
- [カードの名前が`ttyUSB0`、`ttyACM0`、または`rfcomm0`](#serial-port)
- [プリンターが見つかりません](#no-printer-found)
- [テストページは印刷できるが、その後レシートを印刷できない](#prints-then-stops)

### ルールを追加しても許可されない {#still-not-allowed}

順番に確認してください。

- ルール内の二つのIDが、小文字も含めて`lsusb`の表示と完全に一致していること。
- ルールファイルに入力した行が保存されていること。`cat /etc/udev/rules.d/99-receipt-printer.rules`で表示できます。
- 手順5の後にプリンターを抜き、接続し直していること。

三つとも正しい場合は、[解決しない場合](#still-stuck)を参照してください。Linuxがルールを適用したかどうかを自分で確認するには、先に以下の確認手順を開いてください。

<details id="device-file">
<summary>Linuxがルールを適用したか確認する</summary>

1. プリンターを接続するたびに`Device`番号が変わるため、`lsusb`をもう一度実行します。プリンターの行にある`Bus`と`Device`の番号（例：`Bus 001`と`Device 007`）を控えてください。
2. それらの番号をバス番号から順に次のコマンドに入れ、実行します。

   ```bash
   ls -l /dev/bus/usb/001/007
   ```

3. 表示された行の先頭を確認してください。
   - `crw-rw-rw-`：ルールは適用されています。**テストページを印刷**をもう一度押してください。引き続きプリンターへのアクセスが許可されていないと表示される場合は、[解決しない場合](#still-stuck)を参照してください。
   - `crw-rw-r--`または`crw-------`：ルールは適用されていません。上の確認事項をもう一度見直し、設定手順5の読み込みコマンドを再実行してください。その後、プリンターを抜いて接続し直し、ここの手順1から3を繰り返します。行の先頭が変わらない場合は、[解決しない場合](#still-stuck)を参照してください。

</details>

<details id="command-not-found">
<summary>`lsusb` または `nano`：コマンドが見つからない</summary>

不足しているプログラムをインストールしてから、その手順をやり直してください。

- `lsusb`：UbuntuまたはDebianでは`sudo apt install usbutils`、Fedoraでは`sudo dnf install usbutils`。
- `nano`：UbuntuまたはDebianでは`sudo apt install nano`、Fedoraでは`sudo dnf install nano`。

</details>

<details id="serial-port">
<summary>カードに表示される名前： `ttyUSB0`, `ttyACM0` または `rfcomm0`</summary>

このプリンターはUSBプリンターとしてではなく、シリアルポート経由で接続されています。Linuxではシリアルポートへのアクセスを`dialout`グループに許可しています。自分をこのグループに追加し、ログアウトしてから再度ログインしてください。

```bash
sudo usermod -aG dialout $USER
```

Arch Linuxでは、グループは`uucp`です。

</details>

<details id="no-printer-found">
<summary>プリンターが見つかりません</summary>

アプリに表示されるのは、自身をプリンターとして識別するUSBデバイスのみです。ケーブルとプリンターの電源を確認してから、**再スキャン**を押してください。[プリンターが見つかりません](./setup-wizard.mdx#not-found)を参照してください。

</details>

<details id="prints-then-stops">
<summary>テストページは印刷できるが、その後レシートを印刷できない</summary>

これは権限の問題ではありません。[まだ印刷できない場合](./setup-wizard.mdx#troubleshoot)から確認してください。

</details>

## 解決しない場合 {#still-stuck}

**何も印刷されませんでした**パネル、または**設定 → 印刷**のプリンター行にある **⋮** メニューで、**セットアップレポートをコピー**を押します。プリンターの`lsusb`の行と、[確認手順](#device-file)を実行した場合はその`ls -l`の行も添えて、メッセージに貼り付けてください。

## この設定が必要な理由 {#why-it-happens}

多くのプログラムは、Linuxの印刷システムを通じて印刷します。レシートプリンターには、用紙のカットやドロアーの開放などのコマンドを直接送る必要があるため、デスクトップアプリはプリンターに直接アクセスします。

Linuxでは、別のルールがない限り、USBデバイスを使用できるのは管理者アカウント(`root`)のみです。アプリは`root`ではなく自分のアカウントで動作するため、ルールがなければプリンターへのアクセスが許可されません。追加したルールは、このプリンターの機種だけを例外として許可します。

LinuxにはUSBプリンター用のドライバーもあり、プリンターを接続するとそのドライバーが制御を取得します。アプリは印刷のたびに自動でドライバーからプリンターを解放するため、ドライバーを削除したり無効化したりする必要はありません。ただし、解放にも印刷と同じ権限が必要です。そのため、一つのルールで両方の問題を解決できます。
