ほとんどのバーコードスキャナーは設定不要です。ケーブルを接続するか、キーボードと同じようにペアリングすればスキャンできます。以下のウィザードでは、いくつかの質問を通じて、その後の手順やスキャンが届かない場合の解決方法をご案内します。

ほとんどの問題は、**設定 → バーコードスキャン**画面で解決できます。ウィザードの下には、[画面の内容](#barcode-scanning-screen)、[テストパネルの見方](#test-panel)、[スキャナーのステータスの意味](#scanner-status)をまとめています。

  <WizardStep id="kb-first-d" title="キーボードモードで始める — 設定は不要です">

ほぼすべてのスキャナーは、初期状態で**キーボード**として動作し、バーコードの文字を入力します。WCPOS は高速なキー入力をスキャンとして認識します。設定は不要です。

1. **USB スキャナー：** ケーブルを接続するだけです。
2. **Bluetooth スキャナー：** ペアリングモードにして、通常のキーボードと同じように**システムの Bluetooth 設定**でペアリングします。ペアリングモードへの切り替え方はマニュアルをご確認ください。通常はトリガーの長押しなどで切り替え、ビープ音で確認できます。
3. WCPOS を開き、商品のバーコードをスキャンします。商品が表示され、販売に追加されれば正常です。

  <WizardFix id="fix-nothing" title="スキャンしても何も起きない場合">

1. **スキャナーは反応しますか？** トリガーを引いてください。音も光も出ない場合は、WCPOS ではなく電源やバッテリーの問題です。
2. **接続されていますか？** Bluetooth 設定で、単に「ペアリング済み」ではなく**接続済み**と表示されている必要があります。不明な場合は、ペアリングし直してください。
3. **文字が入力されるか確認します：** メモアプリや空のテキスト欄を開いてスキャンしてください。文字が表示されればスキャナーは正常で、POS が入力をスキャンとして認識していないだけです。
4. 文字は入力されるのに WCPOS が反応しない場合は、 <kbd>設定</kbd> → <kbd>バーコードスキャン</kbd> を開き、**バーコードスキャンテスト**パネルでスキャンしてください。各入力がタイピングとして扱われた理由が表示されます。スキャナーが少し遅いだけの場合は、しきい値を上げる修正案と**適用**ボタンが表示されます。詳しくは、 [テストパネルでスキャンを確認する](#test-panel)をタップします。

      <WizardChoice value="yes" label="はい、解決しました" goTo="success-kb" />
      <WizardChoice value="no" label="いいえ、まだ何も起きません" goTo="support" />
    </WizardGate>
  </WizardFix>

  <WizardFix id="fix-garbled-d" title="スキャンが文字化けする場合">

キーボードモードのスキャナーは、**キーボード配列**に従って文字を入力します。スキャナーとデバイスの配列が一致しないと（QWERTY と AZERTY の違いや記号の位置など）、別の文字が入力されます。

1. **バーコードスキャンテスト**パネルでスキャンしてください（<kbd>設定</kbd> → <kbd>バーコードスキャン</kbd>）。スキャナーが Shift を独立したキー入力として送信している場合、その状態を検出して表示します。詳しくは、 [テストパネルでスキャンを確認する](#test-panel)をタップします。
2. スキャナーのマニュアルで **「キーボード言語」** または **「キーボード配列」** の設定用バーコードを探し、デバイスに合わせて設定してください。通常は US 配列が無難です。
3. 最も確実な解決方法は**直接接続**です。直接接続したスキャナーはバーコードをデータとして送信するため、キーボード配列が関係せず、文字化けも起こりません。

      <WizardChoice value="direct" label="直接接続を設定する" goTo="conn" />
      <WizardChoice value="help" label="まだ文字化けするのでサポートを受けたい" goTo="support" />
    </WizardGate>
  </WizardFix>

  <WizardFix id="fix-chooser" title="スキャナーが選択画面に表示されない場合">

1. **まだキーボードモードのままである可能性が高いです**。これが最も多い原因です。モード設定用バーコードが反映されていない可能性があるため、もう一度スキャンし、スキャナーの電源を入れ直してください。簡単に確認するには、テキスト欄をクリックしてトリガーを引きます。文字が表示される場合は、まだキーボードモードです。Eyoyo では、Bluetooth 名が `ScannerSPP` になっていることを確認してください。
2. **古いペアリング情報が妨げになっている場合**（Bluetooth）：システムの Bluetooth 設定でスキャナーのペアリングを解除または削除し、モードを切り替えた*後で*再度ペアリングしてください。選択画面には、正しくペアリングされたシリアルデバイスだけが表示されます。
3. **表示されるのに接続できない場合：** ポートを使用している可能性のあるメーカーの設定ツールを閉じ、スキャナーを近づけて再度お試しください。
4. **まだ表示されませんか？** 一部のスキャナーは、選択画面が初期状態では受け付けないメーカー固有の**サービス UUID** でシリアル接続を識別します。マニュアルの Bluetooth の章で、`8-4-4-4-12` 形式の長いコードを探してください。通常は SPP セクションの近くにあります。同じ**スキャナーを直接接続（詳細設定）** パネルの**スキャナーが一覧にありません**に入力し、**追加**を押してください。その後、もう一度接続を試します。[直接接続パネル](#direct-connection-sheet)をご覧ください。
5. **マニュアルにも UUID がありませんか？** スキャナーのメーカーと機種を添えて、サポートにお問い合わせください。

    <WizardGate id="g-fix-chooser" question="もう一度接続を試してください。表示され、接続できましたか？">

**確認と微調整：** 同じ画面の**バーコードスキャンテスト**パネルには各スキャンがグラフで表示され、先頭の記号をプレフィックスとして除去するなど、ワンタップで適用できる修正案が表示されます。[テストパネルでスキャンを確認する](#test-panel)をご覧ください。

## バーコードスキャン画面 {#barcode-scanning-screen}

メニューを開き、 <kbd>設定</kbd> → <kbd>バーコードスキャン</kbd>を選択します。変更はその都度保存されるため、保存ボタンはありません。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[60, 0], [60, 0], [270, 0], [160, 0], [-30, 0], [20, 0]]} alt="バーコードスキャン画面：入力間隔のしきい値と最小文字数、設定ガイドへのリンクと直接接続の行があるスキャナーセクション、バーコードスキャンテストパネル">

1. **バーコードの平均入力時間のしきい値 (ms)** — スキャンと判定するキー入力の速さです。初期値は 24 です。スキャナーの入力が遅い場合は値を上げてください。[テストパネル](#test-panel)で適切な値を確認できます。
2. **バーコードの最小文字数** — これより短いスキャンはレジで無視され、カートに追加されません。初期値は 8 です。
3. **ほとんどのスキャナーは設定不要です** — スキャナーを登録または接続するまで表示されます。キーボードモードのスキャナーは、ここに行がなくても動作します。
4. **スキャナー設定ガイド** — このページを開きます。
5. **スキャナーを直接接続（詳細設定）** — [直接接続パネル](#direct-connection-sheet)を開きます。Android では、この行は**スキャナーを登録**と表示されます。[ウィザード](#wizard)をご覧ください。
6. **バーコードスキャンテスト** — このパネルでスキャンすると、WCPOS がどのように判定したかを確認できます。[テストパネルでスキャンを確認する](#test-panel)をご覧ください。

</JourneyShot>

その間にある**バーコードスキャナーのプレフィックス**と**バーコードスキャナーのサフィックス**には、スキャナーが各コードの前後に付ける文字をそれぞれ一文字指定します。WCPOS は検索前にこれらを除去します。**スキャン時に音を鳴らす**では、スキャン音のオンとオフを切り替えます。各設定の詳細は、[バーコード設定](../../settings/store/barcode.mdx#settings)をご覧ください。

## テストパネルでスキャンを確認する {#test-panel}

バーコードスキャン画面を開いた状態で、任意のバーコードをスキャンしてください。パネルには、スキャナーが送信したキーと WCPOS の読み取り結果が表示されます。「最近の試行」で最新の入力が**スキャン**と表示され、**検出されたバーコード**が商品に印刷されたコードと一致していれば、[レジで最終確認する](#finish-at-the-till)に進んでください。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[200, 0], [200, 0], [420, 0], [340, -25], [300, 0]]} alt="正常なスキャン後のテストパネル：受信したキー、検出されたバーコード、すべての棒が破線のしきい値を下回る入力間隔グラフ、判定、最近の試行一覧">

1. **キー入力イベント** — スキャナーが送信したすべてのキーです。 <kbd>↵</kbd> は Enter、 <kbd>⇧</kbd> は Shift です。
2. **検出されたバーコード** — WCPOS が検索に使うコードです。
3. **入力間隔グラフ** — 各キーに対応する棒で、直前のキーからの間隔をミリ秒単位で示します。破線はしきい値を示し、それを超える棒は黄色になります。
4. **判定** — スキャンかタイピングかを、キー間の平均間隔とともに表示します。
5. **最近の試行** — 直近の五件が新しい順に表示されます。それぞれに**スキャン**、**短すぎます**、または**タイピング**という判定と、平均間隔が表示されます。

</JourneyShot>

各試行は、次の五つのいずれかに分類されます：

- **スキャンとして検出され、「スキャン」と表示される。** キー入力が十分に速く、コードの文字数が最小文字数以上です。[レジで最終確認する](#finish-at-the-till)に進んでください。
- **スキャンとして検出され、「短すぎます」と表示される。** キー入力は十分に速いものの、コードが**バーコードの最小文字数**より短いため、レジでは無視されます。**最小文字数を下げる**の**適用**をタップしてください。
- **タイピングとして扱われ、黄色で「しきい値を超えています」と表示される。** あと少しでスキャンと判定される状態です。キー入力は速いものの、設定されたしきい値を満たしていません。[スキャンが遅すぎる場合](#too-slow)をご覧ください。
- **タイピングとして扱われ、適切に無視される。** 通常のタイピング速度でキーが入力されています。修正は不要です。
- **タイピングとして扱われる — 入力されたキーが一つだけ。** キーが一つだけでは間隔を測れません。バーコード全体をスキャンしてください。

一秒を超える間が空くと、一覧では新しい試行として扱われます。

### スキャンが遅すぎる場合 {#too-slow}

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[420, 0], [460, 12], [300, -14]]} alt="遅いスキャン後のテストパネル：破線のしきい値を超える黄色の棒、あと少しでスキャンと判定されることを示す判定としきい値を上げる提案、タイピングと判定された試行">

1. **黄色の棒** — しきい値より長かった入力間隔です。
2. **あと少し** — 平均間隔と、それを少し上回る値にしきい値を上げる提案が表示されます。**適用**を押すと、新しいしきい値がすぐに保存されます。
3. **最近の試行** — 遅いスキャンは**タイピング**と表示されます。

</JourneyShot>

### 余分な文字が表示される場合 {#extra-characters}

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[0, -32], [330, -16], [300, -39]]} alt="Shift を独立したキー入力として送信し、コードの先頭に記号を付けるスキャナーでスキャンした後のテストパネル：Shift に関する警告と、記号をプレフィックスに設定する提案">

1. **入力間隔グラフ** — <kbd>⇧</kbd> の棒は、スキャナーが単独で送信した Shift キーです。
2. **提案** — 先頭の記号をプレフィックスに設定して除去する提案と、スキャナーが Shift を独立したキー入力として送信しているという警告が表示されます。
3. **最近の試行** — この場合もスキャンとして扱われます。

</JourneyShot>

各提案には、変更をすぐに保存する**適用**ボタンが付いています：

- **しきい値を … ms に上げる** — スキャナーの入力が、しきい値より少し遅くなっています。
- **最小文字数を … に下げる** — コードが最小文字数より短くなっています。
- **先頭の「…」を除去 — プレフィックスに設定** — スキャンが記号で始まっており、プレフィックスが未設定です。

ボタンが付かない通知も二つあります。**スキャナーが Shift を独立したキー入力として送信しています**と表示された場合は、マニュアルの設定用バーコードを使い、スキャナーを US キーボード配列で修飾キーを送信しないモードに設定してください。**末尾の Enter を検出して無視しました — サフィックスは不要です**と表示された場合は、スキャン末尾の Enter がすでに処理されているため、サフィックスは空欄のままにしてください。

**適用するたびに**、同じバーコードをもう一度スキャンしてください。

### レジで最終確認する {#finish-at-the-till}

「最近の試行」で最新の入力が**短すぎます**や**タイピング**ではなく**スキャン**と表示され、**検出されたバーコード**が商品に印刷されたコードと一致していれば、レジを開き、確認しやすい既知のシンプル商品をスキャンしてください。商品がそのままカートに入ります。ブラウザーやデスクトップアプリでは、先に画面の空白部分をクリックしてください。検索欄を含むテキスト欄にカーソルがある間は、WCPOS はキー入力をその欄へのタイピングとして扱います。

スキャンがレジに届いても商品が追加されない場合（例：**バーコードが見つかりません**）、各メッセージの意味は[バーコードをスキャンする](../../pos/product-panel/index.mdx#scan)をご覧ください。

## スキャナーのステータスを確認する {#scanner-status}

**スキャナー**セクションに専用の行が表示されるのは、Android で登録したスキャナーか、直接接続したスキャナーだけです。未登録のキーボードモードのスキャナーには行がなく、必要もないため、この部分は読み飛ばせます。

<details>
<summary>スキャナーの行、五つのステータス、削除方法</summary>

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[0, 0], [110, 4], [-30, 0], [260, 14], [-30, 0]]} alt="スキャナーが一台保存されているスキャナーセクション：スキャナーの行とステータス、メニューボタン、スキャンの取り込みに関する説明、別のスキャナーを接続するボタン">

1. **スキャナーの行** — 名前が表示されます。名前がない場合は接続の種類が表示されます。
2. **ステータス** — 以下の表をご覧ください。
3. **<kbd>⋮</kbd> メニュー** — **削除**で行を削除します。
4. **取り込まれるスキャン** — これらのスキャナーからのスキャンは WCPOS に直接届きます。キーボードモードのスキャナーも引き続き併用できます。
5. **別のスキャナーを接続（詳細設定）** — 直接接続パネルを再度開きます。

</JourneyShot>

| ステータス | スキャナーの種類 | 意味 |
|---|---|---|
| **接続済み** | すべての直接接続 | 現在接続されています。 |
| **登録済み** | Android で登録したキーボードモード | 保存済みです。スキャンはデバイスごとに識別されます。 |
| **通信範囲外** | Bluetooth | 保存済みですが、現在は接続されていません。 |
| **ケーブル未接続** | USB シリアル | 保存済みですが、現在は接続されていません。 |
| **未接続** | USB HID POS | 保存済みですが、現在は接続されていません。 |

WCPOS を開くと、保存済みのスキャナーは自動的に再接続されます。Bluetooth シリアルまたは USB シリアルのスキャナーは、許可したデバイスのうち一致するものが一台だけの場合に限り自動再接続されます。同じスキャナーが二台ある場合は、パネルで使いたいほうを選んでください。

</details>

### 直接接続パネル {#direct-connection-sheet}

**スキャナーを直接接続（詳細設定）** を押すと、このパネルが開きます。スキャナーをキーボードモード以外に切り替えてから使ってください。[ウィザード](#wizard)で切り替え手順をご案内します。

<details>
<summary>USB または Bluetooth シリアルで接続する、または Bluetooth サービス UUID を追加する</summary>

<JourneyShot manifest={manifest} device="tablet" step={6} offsets={[[-26, 0], [211, 0], [-26, 0], [380, 0], [0, 34], [240, 0]]} alt="直接接続パネル：USB で接続、Bluetooth シリアルで接続、キーボードモードのスキャナーに関する注意、スキャナーの Bluetooth サービス UUID を追加する欄">

1. **USB で接続** — USB HID POS モードのスキャナー用です。接続中は、ボタンが **USB スキャナーを切断**に変わります。
2. **Bluetooth シリアルで接続** — SPP モードのスキャナー、または USB COM モードでケーブル接続したスキャナー用です。選択画面には USB シリアルポートも表示されます。接続中は、ボタンが **Bluetooth シリアルスキャナーを切断**に変わります。
3. **キーボードモードに関する注意** — キーボードモードのスキャナーはここでは接続できません。これは WCPOS ではなく、OS の制約です。
4. **スキャナーが一覧にありません** — スキャナーの Bluetooth サービス UUID を入力します。`8-4-4-4-12` 形式の長いコードです。
5. **追加** — 選択画面でスキャナーを検出できるように UUID を保存します。
6. **スキャナーのサービス UUID を探す** — このページを開きます。マニュアルのどこに UUID が記載されているかは、[ウィザード](#wizard)の「スキャナーが選択画面に表示されない場合」で確認できます。

</JourneyShot>

WCPOS デスクトップアプリでは選択画面がアプリ内に開き、Chrome ではブラウザーのポップアップとして開きます。

</details>
