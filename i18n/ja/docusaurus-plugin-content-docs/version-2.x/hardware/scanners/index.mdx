ほぼすべてのバーコードスキャナーは、接続またはペアリングするだけでPOSで使えます。このページでは、新しいスキャナーを開封してから最初のスキャンまでの手順と、スキャンが届かない場合の確認先を紹介します。

## スキャンの方法 {#ways-to-scan}

- **キーボードモード** — ほぼすべてのスキャナーの初期設定です。スキャナーがバーコードをキー入力し、POSが入力速度でスキャンと手入力を区別します。設定は不要です。
- **カメラ** — スキャナーは不要です。商品検索の横にあるスキャンボタンを押して、カメラをバーコードに向けます。[カメラでスキャンする](../../pos/product-panel/barcode-scanning.mdx#camera-scanning)を参照してください。
- **直接接続** — POSが入力速度でスキャンを判定する代わりに、スキャナー自体を識別します。キーボードモードでは対応できない場合は、[スキャナーを直接接続する](#direct)を参照してください。

## スキャナーを接続する {#connect}

1. スキャナーを端末に接続します。
   - **USBスキャナー：** 端末に差し込みます。
   - **Bluetoothスキャナー：** ペアリングモードにし（方法は取扱説明書を参照）、キーボードと同じように端末のBluetooth設定でペアリングします。
2. POSを開きます。店舗で **レジの開閉** を使用している場合は、先に[レジを開いて](../../pos/register/index.mdx#open)ください。
3. 商品のバーコードをスキャンします。
   - **ブラウザーまたはデスクトップアプリ：** テキスト入力欄の外をクリックしてからスキャンします。POSのどの画面からでも、商品が直接カートに追加されます。テキスト入力欄へのスキャンは手入力として扱われます。
   - **iPhone、iPad、Androidアプリ：** 商品検索をタップしてからスキャンします。アプリがキーボードモードのスキャナーから入力を受け取れるのは、この欄だけです。[Androidで登録した](#direct)スキャナーなら、タップせずに使えます。

商品が表示されれば完了です。表示されない場合は、[スキャンをテスト](#test)してPOSが受け取った内容を確認してください。

## スキャンをテストする {#test}

**設定** を開き、**バーコードスキャン** を選択します。iPhone、iPad、Androidアプリでは、**キー入力イベント** の下の欄をタップします。続いて、任意のバーコードをスキャンします。画面下部の **バーコードスキャンテスト** には、受信したキー、POSがそこから読み取ったコード、スキャンと判定されたかどうかが表示されます。この例ではスキャナーの入力が遅いため、手入力として扱われています。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[150, 0], [150, 0], [420, 0], [520, -45], [300, -14], [175, 0]]} alt="遅いスキャン後のバーコードスキャンテスト。スキャナーが送信したキー、検出したバーコード、しきい値を超えた黄色の棒があるキー入力間隔のグラフ、手入力として処理の判定、しきい値を上げる提案と適用ボタン、最近の試行、トラブルシューティングガイドへのリンクが表示されています">

1. **キー入力イベント** — 末尾のEnterを含む、スキャナーが送信したすべてのキーです。
2. **検出したバーコード** — プレフィックスとサフィックスを削除した後、POSが検索するコードです。
3. **入力間隔のグラフ** — キーごとに棒が表示され、しきい値の破線と比較できます。線を超えた棒は、入力が遅すぎたキーを示します。
4. **判定** — **スキャンとして検出**、または手入力として扱われた理由と修正方法の提案です。**適用** で保存します。
5. **最近の試行** — 直近の数回の結果です。それぞれに **スキャン**、**手入力**、**短すぎる** のラベルと、キー入力の平均間隔が表示されます。
6. **トラブルシューティングガイド** — 症状別の解決方法を調べるための[スキャナー設定ウィザード](./setup-wizard.mdx)を開きます。

</JourneyShot>

下の拡大図では、POSがこのスキャンの平均入力間隔を35msと読み取り、しきい値の24ms（破線）を超えているため、43msを提案しています。**適用** を押して保存し、もう一度スキャンして確認してください。

<JourneyShot manifest={manifest} device="tablet" step={4} maxWidth={710} offsets={[[392, -25], [350, 0], [-30, 0]]} alt="テスト結果の拡大図。24msの破線を超える黄色の棒、平均入力間隔35msがしきい値24msを超えているため手入力として処理という判定、スキャナーの平均が35msのためしきい値を43msに上げる提案と適用ボタンが表示されています">

1. **入力間隔の棒** — キーごとに棒が表示され、その下に入力間隔がms単位で表示されます。黄色の棒は、入力がしきい値より遅かったことを示します。
2. **破線** — 設定したしきい値です。この例では24msです。
3. **適用** — 提案されたしきい値を保存します。もう一度スキャンして確認してください。

</JourneyShot>

判定に、スキャナーが **Shiftを個別のキーとして送信している** と表示される場合は、取扱説明書のバーコードでスキャナーをUSキーボード配列に設定するか、[直接接続](#direct)してください。

## スキャナー設定 {#settings}

**バーコードスキャン** のほかの項目には、テストの判定に使う設定と、スキャナーを直接接続するための項目があります。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[50, 0], [50, 0], [50, 0], [50, 0], [45, 0], [260, 0], [151, 0], [341, 0], [175, 0]]} alt="設定のバーコードスキャン画面。しきい値、最小文字数、プレフィックスとサフィックスの欄、スキャン時に音を鳴らすスイッチ、ほとんどのスキャナーは設定不要、スキャナー設定ガイド、直接接続があるスキャナー欄、バーコードスキャンテストの見出しが表示されています">

1. **バーコード平均入力間隔のしきい値 (ms)** — スキャンと判定するキー入力の速さです。POSの初期値は24です。遅いスキャナーでは値を上げ、速い手入力がスキャンと判定される場合は下げてください。
2. **バーコードの最小文字数** — スキャンと判定するコードの最小文字数です。POSの初期値はEAN-8の文字数に合わせた8です。
3. **バーコードスキャナーのプレフィックス** — スキャナーが各コードの先頭に付ける一文字です。POSはコードを検索する前にこの文字を削除します。スキャナーが文字を追加する設定でなければ、空欄のままにしてください。
4. **バーコードスキャナーのサフィックス** — スキャナーが各コードの末尾に付ける一文字です。プレフィックスと同様に削除されます。末尾のEnterはPOSが無視するため、サフィックスの設定は不要です。
5. **スキャン時に音を鳴らす** — 初期状態ではオフです。オンにしてから、**サウンドテーマ** と **音量** を選び、**成功音** と **失敗音** のオン・オフを設定します。iPhone、iPad、Androidアプリには **失敗時に振動** もあります。
6. **ほとんどのスキャナーは設定不要** — スキャナーが直接接続されていない間、この欄に表示されるメッセージです。キーボードモードのスキャナーはここには表示されません。
7. **スキャナー設定ガイド** — [スキャナー設定ウィザード](./setup-wizard.mdx)を開きます。いくつかの質問に答えると、設定や問題の解決方法が順を追って案内されます。
8. **直接接続** — スキャナーを直接接続するまでは **なし** と表示されます。[スキャナーを直接接続する](#direct)を参照してください。
9. **バーコードスキャンテスト** — このページでスキャンすると、スキャナーが送信する内容を確認できます。[スキャンをテストする](#test)を参照してください。

</JourneyShot>

これらの設定はこの端末だけに適用されるため、スキャナーを使うレジごとに設定してください。

## 問題が発生した場合 {#goes-wrong}

**スキャンしても何も起こらない。** スキャナーの音やランプが反応するか、端末のBluetooth設定がペアリング済みだけでなく **接続済み** になっているかを確認してください。iPhone、iPad、Androidアプリでは、スキャン前に商品検索をタップします。次にメモアプリでスキャンしてください。そこにコードが表示されるならスキャナーは動作しており、POSが手入力と判定した理由を[テスト](#test)で確認できます。

**判定に「手入力として処理」と表示される。** スキャナーの入力が、設定したしきい値より遅くなっています。提案の **適用** を押すか、**バーコード平均入力間隔のしきい値 (ms)** を上げてください。

**商品検索での手入力がスキャンと判定される。** iPhone、iPad、Androidアプリでは、POSが検索の手入力も速度で判定するため、この現象が起こります。しきい値を下げるか、**バーコードの最小文字数** を増やしてください。ブラウザーやデスクトップアプリでは、入力欄への手入力がスキャンと判定されることはありません。

**スキャン結果が文字化けする。** スキャナーのキーボード配列が端末の配列と一致していません。取扱説明書のバーコードでUS配列に設定するか、[直接接続](#direct)してください。

**直接接続しようとしてもスキャナーが一覧に表示されない。** デスクトップアプリ、ブラウザー、iPhone、iPadでは、スキャナーがまだキーボードモードになっている可能性が高いです。取扱説明書のモード切り替え用バーコードをスキャンし、[端末に応じた手順](#direct)をもう一度行ってください。それでも表示されないBluetoothシリアルスキャナーは、独自のサービスUUIDを使用している可能性があります。**スキャナーを直接接続する** の[**デスクトップアプリ、Chrome、Edge**](#direct-desktop)を開き、**BluetoothサービスクラスUUID** を確認してください。Androidには一覧がないため、[スキャナーを登録](#direct)してください。

**直接接続したスキャナーの行に「範囲外」「接続されていません」「未接続」と表示される。** 現在、POSがスキャナーと通信できません。スキャナーの電源を入れる、端末に近づける、ケーブルを接続し直すなどしてください。[接続後の状態](#connected)を参照してください。

**POSにはスキャンが届くのに商品が表示されない。** POSに理由が表示されます。**バーコードが見つかりません**、**複数の一致があります**、**バリエーションを選択** などです。[バーコードをスキャンする](../../pos/product-panel/index.mdx#scan)を参照してください。バーコードを格納する商品フィールドは、[バーコードフィールド](../../settings/wp-admin/general.mdx#barcode-field)で設定します。

プラットフォームや症状に応じた解決手順は、[スキャナー設定ウィザード](./setup-wizard.mdx)で確認してください。

## スキャナーを直接接続する {#direct}

ほとんどの店舗ではキーボードモードで十分です。スキャン結果が文字化けする、別の入力欄に入る、入力欄を選択していないと届かない場合は、直接接続してください。

POSを使用している端末の項目を開いてください。それぞれにすべての手順を順番に記載しています。

<details id="direct-desktop">
<summary>デスクトップアプリ、Chrome、Edge</summary>

1. 取扱説明書の設定用バーコードを使い、スキャナーをキーボードモードから *SPPモード*、*シリアルモード*、*HID POSモード* などに切り替えます。
2. Bluetoothスキャナーの場合は、端末のBluetooth設定から削除し、新しいモードでもう一度ペアリングします。
3. **バーコードスキャン** を開き、**スキャナーを直接接続（詳細設定）** を押して、スキャナーの接続方法を選びます。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[-24, 0], [222, 0], [455, 12], [300, 0], [240, 0]]} alt="ブラウザーのスキャナーを直接接続するパネル。USBで接続、Bluetoothシリアルで接続、キーボードモードのスキャナーについての注意事項、スキャナーが一覧にない場合の項目とBluetoothサービスクラスUUID欄、追加ボタンが表示されています">

1. **USBで接続** — HID POSモードのUSBスキャナー用です。開いた一覧からスキャナーを選びます。
2. **Bluetoothシリアルで接続** — シリアル（SPP）モードのスキャナー用です。シリアルモードのUSBスキャナーも同じ一覧に表示されます。
3. **キーボードモードについての注意事項** — キーボードモードのままのスキャナーは、これらの一覧には表示されません。端末は、アプリがキーボードを専有することを許可しないためです。
4. **BluetoothサービスクラスUUID** — キーボードモードを解除しても一覧に表示されないBluetoothシリアルスキャナー用です。取扱説明書に記載されたUUIDを入力し、**追加** を押してから、もう一度接続してください。
5. **スキャナーのサービスUUIDを調べる** — UUIDの確認先を案内する[スキャナー設定ウィザード](./setup-wizard.mdx)を開きます。

</JourneyShot>

</details>

<details>
<summary>iPhoneまたはiPad</summary>

1. 取扱説明書の設定用バーコードを使い、スキャナーをキーボードモードから別のモードに切り替えます。
2. 端末のBluetooth設定ではまだキーボードとして認識されているため、そこから削除します。再度ペアリングしないでください。
3. **バーコードスキャン** で **スキャナーを直接接続（詳細設定）** を押し、続いて **Bluetoothスキャナーを接続** を押します。POSは最初に見つかったBluetooth LEスキャナーに接続するため、ほかのスキャナーの電源は切っておいてください。

</details>

<details>
<summary>Android</summary>

1. スキャナーはキーボードモードでペアリングしたままにします。
2. **バーコードスキャン** で **スキャナーを登録** を押し、続いて **スキャナーを登録** を押します。
3. そのスキャナーで一度スキャンし、名前を付けて **スキャナーを保存** を押します。以降、POSは入力速度ではなく機器自体でそのスキャナーのスキャンを識別します。

</details>

<details>
<summary>SafariまたはFirefox</summary>

直接接続は利用できず、**スキャナー** 欄もありません。キーボードモードやカメラを使うか、デスクトップアプリまたはChromeに切り替えてください。

</details>

### 接続後の状態 {#connected}

接続したスキャナーは **スキャナー** 欄に表示され、状態を確認できます。通信できている間は **接続済み**、通信できない間は **範囲外**、**接続されていません**、**未接続** のいずれか、Androidでは **登録済み** と表示されます。**⋮** メニューには **削除** があります。キーボードモードのスキャナーも引き続き併用できます。
