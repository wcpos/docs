:::info Pro機能
注文ページには [WCPOS Pro](../getting-started/pro-license.mdx) が必要です。Proがない場合はリストのぼかしたプレビューが表示され、注文はWP Adminの **WooCommerce → 注文** で管理します。
:::

メニューの **注文** には、ショップで行われた販売が一覧表示されます。お客様が再来店した際に、販売の検索、レシートの再印刷、払い戻し、カートに戻しての変更ができます。これらの操作のためにWP Adminへ切り替える必要はありません。

目的の操作へ移動：

- [販売を検索する](#find-an-order)
- [レシートを再印刷する](#receipt-reprinting)
- [商品や数量を変更する](#reopening-orders)
- [ステータス、顧客、住所を変更する](#editing-orders)
- [販売を払い戻す](#refunds)

## 注文を検索する {#find-an-order}

リストを開くと、**この店舗で自分が担当した販売** が新しい順に表示されます。販売を検索するには、次の操作を行います。

1. 上部の **注文を検索** に、注文番号、お客様の名前、電話番号、メールアドレス、または商品を入力します。
2. 販売が表示されない場合は、別のレジ係が担当した可能性があります。**レジ係** フィルターの **×** を押して、全員の販売を検索してください。別の店舗やオンラインでの販売の場合は、**店舗** フィルターを変更します。
3. 販売をタップして開きます。[注文を開く](#order-details)を参照してください。

注文ページを開いた状態で、手入力の代わりに、印刷されたレシートの注文番号バーコードをスキャンできます。読み取った値が **注文を検索** に入力され、その販売が表示されます。[バーコードスキャナー](../hardware/scanners/index.mdx)を参照してください。

<details>
<summary>検索の対象</summary>

注文番号、お客様の名前、会社名、電話番号（請求先または配送先）、請求先のメールアドレス、注文内の商品名やSKUが対象です。[検索の対象](../reference/search.mdx#orders)を参照してください。

</details>

ページを開くと、**レジ係** フィルターには自分が、**店舗** フィルターにはサインイン中の店舗が設定されます（サイトに店舗が1つしかない場合は **POS**）。店舗のタイムゾーンに従った日付の見出しごとに、新しい販売から順に表示されます。

1. **注文を検索**：注文番号、名前、電話番号、または商品を入力します。
2. **フィルター**：リストを絞り込みます。[リストを絞り込む](#filters)を参照してください。
3. **レジ係**：ページを開くと自分が設定されます。**×** を押すと、すべてのレジ係の販売が表示されます。
4. **店舗**：サインイン中の店舗が設定されます。
5. **表示設定**：表示する列を選択します。[表示設定](#display-settings)を参照してください。
6. **日付の見出し**：1日分の販売を、新しい日付から順に表示します。
7. **列見出し**：クリックすると並べ替えます。[列の並べ替えと幅の変更](#sort-and-resize)を参照してください。
8. **ステータスバッジ**：押すと、そのステータスの注文だけが表示されます。
9. **開く**：注文を開きます。[注文を開く](#order-details)を参照してください。
10. **M件中N件を表示** と同期ボタン：表示中の注文数を示し、新規注文や変更された注文を取得します。

## 注文を開く {#order-details}

注文の行をタップすると開きます。マウスの場合は、行の末尾にある矢印（<Icon name="chevron-right" />）をクリックするか、矢印キーで行を選択して **Enter** を押します。右側のパネルに注文が開き、**表示** タブが表示されます。

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[350, 0], [24, -29], [26, -29], [19, -29], [28, -29], [31, -29]]} alt="注文ページから開いた注文の表示タブ：日付、店舗、レジ係の行、商品、合計、現金での支払いと、フッターの「削除」「払い戻し」「同期」「閉じる」「レシート」「再開」ボタン">

1. **注文の詳細**：注文日時、店舗、担当レジ係、注文元を示します。
2. **削除**：保存済みの注文をショップのゴミ箱へ移動します。[注文を削除する](#delete)を参照してください。
3. **払い戻し**：払い戻しフォームを開きます。[販売を払い戻す](#refunds)を参照してください。
4. **同期**：この注文の最新データをショップから取得します。[注文を個別に同期する](#sync)を参照してください。
5. **レシート**：注文のレシートを表示し、再印刷やメールでの再送信ができます。[レシートを再印刷する](#receipt-reprinting)を参照してください。
6. **再開**：注文をカートに戻して変更します。[商品や数量を変更する](#reopening-orders)を参照してください。

</JourneyShot>

表示されるボタンは注文によって異なります。[注文の操作](#order-actions)を参照してください。この端末に注文がない場合は、パネルに **注文が見つかりません** と表示されます。

<details>
<summary>表示、編集、JSONの各タブ</summary>

- **表示**：お客様が購入したときの注文内容を表示します。[表示タブの内容](#view-tab)を参照してください。
- **編集**：フォームで注文の詳細を変更します。[ステータス、顧客、住所を変更する](#editing-orders)を参照してください。
- **JSON**：サポートやトラブルシューティングに使う、注文の生データです。商品、顧客、クーポンを開いたときにも、同じ **JSON** タブがあります。

</details>

### 表示タブの内容 {#view-tab}

表示タブでは、スクロールして注文全体を確認できます。ステータス、商品、合計、支払い、払い戻し、顧客が表示されます。

<details>
<summary>表示タブの各項目（上から順に）</summary>

- **ステータス**：注文のステータスバッジです。一部払い戻し済みの注文には **一部払い戻し済み**、未完了の注文には **POS 未完了** または **POS 一部支払い済み** と表示されます。
- **注文の詳細**：日時、店舗（注文に設定されている場合）、レジ係、注文元を示すアイコンです。
- **商品**：各明細の数量、商品、価格、合計と、手数料が表示されます。明細のない注文には **明細がありません。** と表示されます。
- **合計**：小計、割引、送料、手数料、税金が表示され、税金は税率ごとに1行ずつ表示されます。払い戻し後は、払い戻し額が赤で表示され、最後の行は **差引支払額** になります。それ以外の場合は **合計** です。
- **支払い**：支払い方法と金額を表示します。支払い済みの注文には **売上確定済み** と支払日、取引ID（存在する場合）が表示されます。複数回に分けて支払った注文では、**支払い一覧** に各支払いが表示されます。メール送信した請求書では、送信先と送信日時を確認できます。
- **払い戻し**：この注文に対して行った払い戻しがあれば、それぞれ表示します。
- **顧客**：名前、メールアドレス、電話番号、顧客メモ、請求先住所、請求先と異なる場合の配送先住所、税務IDを表示します。

</details>

## 注文の操作 {#order-actions}

<details>
<summary>注文に表示されるボタン</summary>

| ボタン | 操作内容 | 表示される条件 |
|--------|--------------|-----------------|
| **再開** | 注文をカートに戻し、変更して再度支払いを受け付けます。 | Proでは常に表示されます。 |
| **レシート** | レシートを表示し、印刷やメール送信ができます。 | 注文がショップに保存された後。 |
| **再送信** | 請求書の支払い方法が選択された状態で注文のチェックアウト画面を再び開き、新しい請求書を送信できます。 | メール送信した請求書の支払いを待っている注文。 |
| **同期** | この注文をショップから再取得します。 | 注文がショップに保存された後。 |
| **削除** | 注文を削除します。 | Proでは常に表示されます。 |
| **払い戻し** | 払い戻しフォームを開きます。 | 注文がショップに保存され、完了、処理中、保留中のいずれかである場合。 |
| **請求書をキャンセル** | メール送信した請求書を取り消します。接続が必要です。 | メール送信した請求書の支払いを待っている注文。 |

</details>

### レシートを再印刷する {#receipt-reprinting}

レシートを再印刷、またはメールで再送信するには、次の操作を行います。

1. 注文を開き、下部の **レシート** を押します。
2. 印刷するか、お客様にメールで送信します。[レシートを再印刷する](../receipts/index.mdx#reprint)を参照してください。

リストからワンクリックで再印刷するには、[表示設定](#display-settings)で **レシート** 列を有効にします。保存済みの各注文の行にレシートボタンが表示されます。ショップにまだ届いていない注文には、レシートボタンはありません。

### ステータス、顧客、住所を変更する {#editing-orders}

注文の **編集** タブを開きます。商品明細はここでは変更できません。変更するには注文を再開してください。

- **ステータス**：新しいステータスを選択し、**ステータスを更新** を押します。ショップに反映されると **ステータスを更新しました** と表示されます。
- **顧客、顧客メモ、住所**：項目を変更します。保存ボタンはありません。各項目は変更のたびに保存され、保存が完了すると **保存済み** と表示されます。**未保存** は保存できなかったことを示します。その項目をもう一度変更してください。

<details>
<summary>変更できるその他の詳細</summary>

支払い方法、通貨、取引ID、税務ID、メタデータも変更できます。上記の項目と同様に、変更するたびに保存されます。

</details>

### 商品や数量を変更する {#reopening-orders}

:::note 編集すると在庫が変動します
すでに在庫を減らした販売では、明細を変更するたびに在庫がすぐに変動します。
:::

:::warning 合計が減っても差額は払い戻されません
変更後の金額が支払い済みの金額を下回っても、POSは余分な金額を返金しません。お客様と差額を精算してください。[販売を払い戻す](#refunds)を参照してください。
:::

1. 注文の下部にある **再開** を押します。その注文のカートがPOSで開き（スマートフォンでは **カート** タブ）、注文は **POS - 未完了** に変わります。

2. カートを変更します。
   - **数量を変更**：数量をタップして新しい数を入力し、**完了**（チェックマーク）をタップするか **Enter** を押します。iOSアプリとAndroidアプリにはテンキーがなく、入力欄に直接入力します。[数量を変更する](../pos/cart/line-items.mdx#quantity)を参照してください。
   - **明細を削除**：その明細の合計をタップし、**削除** をタップします。
   - **商品を追加**：新しい販売と同様に、商品グリッドで商品をタップするかスキャンします。スキャンするたびに1点追加されます。
   - **価格や顧客を変更**：[商品明細](../pos/cart/line-items.mdx)と[顧客を選択する](../pos/cart/index.mdx#customer-selector)を参照してください。
   - **メモやカスタムフィールドを変更**：**チェックアウト** の横にある **⋮** をタップして **注文の詳細** を開きます。[お客様へのメモを追加する](../pos/cart/order-actions.mdx#order-note)と[追加情報を入力する](../pos/cart/order-actions.mdx#order-meta)を参照してください。

3. 再度チェックアウトを行い、変更後の注文を完了します。受領済みの支払いは注文に残ります。チェックアウトにはその支払いが一覧表示され、未払い分だけが **残額** として請求されます。カートに変更がなく払い戻しもなければ請求はなく、商品を追加した場合は差額が請求されます。[チェックアウト](../pos/checkout/index.mdx)を参照してください。

<details>
<summary>再開した販売の在庫と支払い</summary>

すでに在庫を減らした販売（再開前に支払いを受け付けていた販売）では、カートの明細を変更するたびに在庫がすぐに変動します。明細の追加や数量の増加で商品の在庫が減り、明細の削除や数量の減少で在庫が戻ります。販売を再度完了しても、在庫が二重に減ることはありません。

商品を取り除き、変更後の金額が支払い済みの金額を下回った場合、チェックアウトでの請求はありませんが、POSが余分な金額を自動で返金することもありません。払い戻しなどの方法でお客様と差額を精算してください。[販売を払い戻す](#refunds)を参照してください。

</details>

カード決済が進行中の販売は再開できません。メッセージに進行中の支払いが示されるので、まずその支払いをキャンセルしてください。[支払いをキャンセルする](../pos/checkout/cancelling-a-payment.mdx)を参照してください。

### 販売を払い戻す {#refunds}

POSから全額または一部を払い戻せます。元の支払い方法への払い戻し（決済ゲートウェイが対応している場合）、またはレジからの現金での払い戻しが可能です。注文を開き、下部の **払い戻し** を押してください。

レジでの払い戻しの手順は、[レジでの払い戻し](../pos/refunds.mdx)を参照してください。払い戻し先、一部払い戻し、レシート上の表示については、[払い戻し](./refunds.mdx)を参照してください。

### 注文を個別に同期する {#sync}

WP Adminで誰かが注文を変更した場合などは、**同期** を押すと、この注文の最新データをショップから取得できます。ショップに接続できない場合は、「この注文を更新できませんでした。この端末のデータは変更されていません」と表示されます。接続を確認して、もう一度試してください。

### 注文を削除する {#delete}

**削除** を押し、確認します。保存済みの注文はショップの **ゴミ箱** に移動し、管理者がWP Adminから復元できます。ショップに一度も届いていない注文は完全に削除され、確認画面にもその旨が表示されます。

レジ係の権限グループでは、**サーバー上の注文を削除する権限がありません** と表示され、注文は残ります。ショップマネージャーまたは管理者に削除を依頼してください。

<details>
<summary>管理者向けの権限情報</summary>

削除にはWordPressの `delete_shop_orders` 権限が必要です。別のレジ係の注文やオンライン注文には `delete_others_shop_orders` も必要です。レジ係の権限グループには、どちらも付与されていません。

</details>

## リストの操作 {#the-list}

スクロールすると、さらに注文が読み込まれます。フッターには表示中の件数（**240件中10件を表示**）と同期ボタン（<Icon name="arrow-rotate-right" />）があります。押すと新規注文や変更された注文を取得します。長押しで表示される **消去して更新** は、検索を消去し、フィルターをこの店舗で自分が担当した販売に戻して、注文を再ダウンロードします。

### リストを絞り込む {#filters}

検索バーの下にあるフィルターでリストを絞り込めます。絞り込みはサーバーで行われるため、端末にある注文だけでなく、すべての注文が対象です。

<details>
<summary>すべての注文フィルター</summary>

| フィルター | 絞り込みの対象 |
|------|--------------------|
| **ステータス** | 完了や処理中などの注文ステータス。 |
| **支払い方法** | 注文の支払いに使われた方法。 |
| **顧客を選択** | 特定の顧客。 |
| **レジ係を選択** | 販売を担当した人。解除すると、すべてのレジ係の販売が表示されます。 |
| **店舗** | 特定の店舗、または注文元（**POS**、**オンラインショップ**、**WP Admin**）。店舗が選択されていない場合は **作成元** と表示されます。 |
| **レジを選択** | 販売が行われたレジ。 |
| **日付範囲** | 日付の範囲。カレンダーには **今日**、**昨日**、**今週**、**先週**、**今月**、**先月** をすばやく選べる項目があります。**完了** を押すと適用されます。 |

</details>

設定済みの各フィルターには、解除用の **×** があります。2つ以上のフィルターを変更すると、行の末尾に **すべてクリア** が表示され、フィルターをこの店舗で自分が担当した販売に戻せます。

行からも絞り込めます。ステータスバッジを押すとそのステータスの注文だけが、顧客名やレジ係の名前を押すとその人の注文だけが表示されます。

### 列の並べ替えと幅の変更 {#sort-and-resize}

列見出しをクリックすると、その列で並べ替えます。もう一度クリックすると、昇順と降順が切り替わります。**ステータス**、**注文番号**、**顧客**、**作成日**、**支払い方法**、**合計** で並べ替えができます。日付の見出しは、**作成日** で並べ替えているときだけ表示されます。並び順は次回も保持されます。

列の幅を広げたり狭めたりするには、見出しの右端をドラッグします。最後の列と **アクション** 列の幅は変更できません。ページを離れると、列幅は元に戻ります。

### リストが空の場合 {#empty-list}

**注文はまだありません** は、この店舗で自分が担当した販売がまだないことを意味します。販売を行うと、ここに表示されます。

**このフィルターに一致する注文はありません** は、検索条件やフィルターによってすべての注文が非表示になっていることを意味します。**フィルターをクリア** を押すと検索が消去され、フィルターがこの店舗で自分が担当した販売に戻ります。

<details>
<summary>例：フィルターで販売が非表示になっている場合</summary>

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[0, -28], [0, -28], [0, -28], [0, -28], [0, -28], [0, -28], [300, -3]]} alt="検索条件と「完了」ステータスのフィルターに一致する注文がない注文ページ：「このフィルターに一致する注文はありません」というメッセージと、その下に「フィルターをクリア」リンクが表示されています">

3. **顧客を選択**：未設定です。
4. **レジ係を選択**：**×** を押して解除した後のレジ係フィルターです。すべてのレジ係の販売が検索されます。
5. **店舗**：この店舗に設定されたままです。
6. **レジを選択**：未設定です。
7. **このフィルターに一致する注文はありません** と表示され、その下に **フィルターをクリア** があります。

</details>

## 対応が必要な販売 {#needs-attention}

レジで支払いを受け付けても、その後ショップ側で拒否されることがあります。たとえば、注文がすでにオンラインで支払い済みだった場合や、ショップが支払いの一部しか受け付けられなかった場合です。この場合、検索バーの下に赤い帯が表示され、**1件の販売に対応が必要です**（または **3件の販売に対応が必要です**）と示されます。

各項目には、注文、金額、支払い方法と、「その支払いを払い戻す」「差額を払い戻す」などの対応内容が表示されます。帯には最新の3件が表示され、それ以降は「ほかN件」と表示されます。

1. **注文を開く** を押して販売を確認します。
2. 支払い額や差額を払い戻すか、残額を受け取って、お客様と精算します。
3. **対応済み** を押して項目を消去します。

この帯が、拒否された支払いを自動で再試行することはありません。表示されるのは自分が担当した販売だけです。同じ端末で別のレジ係がサインインしても、自分の項目は表示されません。

## 表示設定 {#display-settings}

検索バーの末尾にあるスライダーアイコン（<Icon name="sliders" />）をクリックすると、**注文設定** が開きます。パネルでは次の操作ができます。

- 列名の横にあるスイッチで、**列の表示をオンまたはオフに切り替え** ます。
- **列の下に行を追加**：**顧客** の下で字下げされた **請求先住所** と **配送先住所** は、顧客名の下に住所を表示します。**合計** の下で字下げされたスイッチは、支払い方法を表示します。さらに下にある **請求先住所** と **配送先住所** は、それぞれ独立した列です。
- **列を移動**：左側のハンドルをつかんでドラッグします。
- **最初の状態に戻す**：**初期設定に戻す** で、すべての列を元に戻します。

## 注文ステータス {#order-statuses}

POSの注文はレジで支払いを受け付けるため、ほとんどがすぐに **完了** になります。カートで未完了のまま保持し、**注文を同期**（**チェックアウト** の横にある **⋮**）でショップに保存した注文は、**POS - 未完了** になります。後で再開して販売を完了できます。[未完了の注文](../pos/cart/open-orders.mdx)を参照してください。

POSの注文では、WooCommerce標準の注文ステータスに加えて、WCPOS独自の2つのステータスを使用します。

<details>
<summary>すべての注文ステータス</summary>

| ステータス | 説明 |
|--------|-------------|
| **POS - 未完了** | POSから保存された、まだ支払いのない注文（一時保存または取り置き中の注文）。 |
| **POS - 一部支払い済み** | 合計金額の一部が支払い済みで、残額が未払いの注文。 |
| **支払い待ち** | 支払いを待っている状態。 |
| **保留中** | 支払いの確認など、対応を待っている状態。 |
| **処理中** | 支払いを受領し、注文を処理している状態。 |
| **完了** | 注文の処理が完了した状態。 |
| **失敗** | 支払いに失敗した状態。 |
| **キャンセル** | 注文がキャンセルされた状態。 |
| **払い戻し済み** | 注文が全額払い戻された状態。 |

</details>

## 問題が発生した場合 {#goes-wrong}

**目的の販売が表示されません。** リストは最初、この店舗で自分が担当した販売を表示します。**レジ係** フィルターを解除して全員の販売を表示するか、**店舗** フィルターを変更してください。

**「このフィルターに一致する注文はありません」。** **フィルターをクリア** を押してから、もう一度検索してください。

**別のレジで行われた新しい販売がありません。** フッターの同期ボタンを押してください。それでも表示されない場合は、長押しして **消去して更新** を選択してください。

**「この注文を更新できませんでした」。** ショップに接続できませんでした。端末内のデータはそのまま残ります。接続できるようになったら、もう一度試してください。

**「サーバー上の注文を削除する権限がありません」。** 自分のWordPressの権限グループでは注文を削除できません。マネージャーに依頼してください。

**支払いが「進行中」のため再開できません。** まずその支払いをキャンセルしてから、再開してください。[支払いをキャンセルする](../pos/checkout/cancelling-a-payment.mdx)を参照してください。
