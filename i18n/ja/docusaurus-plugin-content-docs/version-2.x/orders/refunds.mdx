:::info Pro機能
WCPOSから払い戻しを行うには、[WCPOS Pro](../getting-started/pro-license.mdx)が必要です。Proがない場合、**注文**ページはプレビューのみです。WP Adminの **WooCommerce → 注文**から払い戻してください。
:::

このページでは、払い戻しフォームの各項目、返金先、各エラーメッセージの意味、払い戻し後の注文の表示について詳しく説明します。注文を開いてから払い戻しを確定するまでの手順は、[レジでの払い戻し](../pos/refunds.mdx)をご覧ください。

## 払い戻しを開始する {#starting-a-refund}

インターネット接続が必要です。また、注文が店舗に送信済みで、**完了**、**処理中**、**保留中**のいずれかになっている必要があります（[払い戻し操作が表示される条件](#when-the-refund-action-appears)）。「*(金額)*の払い戻しが処理されました」と表示されるまで、現金を渡さないでください。別のメッセージが表示された場合は、[払い戻しに失敗した場合](#if-a-refund-fails)をご覧ください。

注文を開いた画面：

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[347, 0], [42, -11], [28, -26], [28, -26], [28, -26], [28, -26], [28, -26]]} alt="現金払いの注文を開いた画面：日付、店舗とレジ係の行、商品、合計、現金での支払い、フッターの削除、払い戻し、同期、閉じる、レシート、再度開く">

1. **注文の詳細** — 支払い日時、店舗、担当したレジ係、注文の作成元です。
2. **支払い** — お客様が使用した支払い方法です。払い戻し先はこれによって決まります。[現金と元の支払い方法の使い分け](#when-to-use-cash-vs-original-method)をご覧ください。
3. **削除** — 注文を削除します。払い戻しは行いません。
4. **払い戻し** — **注文 #*(番号)* の払い戻し**フォームを開きます。
5. **同期** — 店舗から注文を再取得します。
6. **レシート** — 注文の現在の内容を反映したレシートです。
7. **再度開く** — 注文をカートに戻して変更できるようにします。

</JourneyShot>

### 払い戻し操作が表示される条件 {#when-the-refund-action-appears}

**払い戻し**は、店舗に送信済みで、**完了**、**処理中**、**保留中**のいずれかの注文にのみ表示されます。

<details>
<summary>払い戻しボタンが見当たらない場合</summary>

**支払い待ち**、**キャンセル**、**失敗**、全額**払い戻し済み**の注文、POSでまだ開いている販売（**POS未完了**または **POS一部支払い済み**）、同期を待っている注文には表示されません。これらの注文を払い戻すには、WP Adminの **WooCommerce → 注文**を使用してください。WP Adminで注文のステータスが変更された場合は、**同期**を押して再度開いてください。WCPOSのローカルデータベースが利用できないと表示された場合は、アプリを再読み込みするまで払い戻しはできません。

</details>

## 払い戻しフォーム {#the-refund-form}

フォームを開くと注文のすべての明細が表示され、払い戻す項目は何も選択されていません。以下は、同じ注文の二回目の払い戻しを入力した例です。前回$45.00を払い戻しており、今回は腕時計を一点払い戻します。

<JourneyShot manifest={manifest} device="tablet" step={4} alt="以前に一度払い戻した注文の払い戻しフォームが、注文画面の上にパネルとして開いている様子" />

フォームの各項目：

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[52, 0], [150, 0], [332, 43], [345, 97], [461, -124], [118, -39], [60, 48], [-12, -30]]} maxWidth={560} alt="以前に一度払い戻した注文の払い戻しフォーム：合計と払い戻し済み金額、最後の腕時計を払い戻すように設定した明細表、任意の金額、理由の「サイズ違い」、払い戻し合計$45.00、払い戻しを処理">

1. **合計** — 注文の合計金額です。
2. **払い戻し済み金額** — これまでの払い戻しで返金した金額です。初回の払い戻し後にのみ表示されます。
3. **数量** — 明細のうち、まだ払い戻し可能な数量です。購入数量から払い戻し済みの数量を差し引いた値です。オフライン時など、WCPOSが店舗の払い戻し履歴を読み込めない場合は、購入数量の全数が表示されます。ただし、払い戻し金額は引き続き払い戻し可能な残額が上限となります。
4. **払い戻し数量** — この明細で今回払い戻す数量です。
5. **払い戻し金額** — この明細で払い戻す税込金額です。
6. **任意の金額** — 明細に紐付かない追加の金額です。明細の金額に加算されます。
7. **理由** — 任意項目です。払い戻しとともに保存され、[払い戻し](#refunds-section)セクションのカードに表示されます。
8. **払い戻しを処理** — 確認を求めます。**払い戻し合計**がゼロを超え、払い戻し可能な残額以下になるまで、グレー表示で無効になります。

</JourneyShot>

<details>
<summary>表の列と表示順</summary>

| 列 | 表示内容 |
|---|---|
| **商品** | 明細の名前 |
| **価格** | 店舗のカート内価格の表示設定に応じた、税込または税抜の単価 |
| **数量** | まだ払い戻し可能な数量 |
| **払い戻し数量** | 今回払い戻す数量 |
| **払い戻し金額** | 払い戻し数量 × 明細の価格に、その数量分の税額を加えた金額 |

</details>

下部の**払い戻し合計**は、各明細の金額と**任意の金額**を合算し、入力に応じて更新されます。

### 全数量と一部数量の払い戻し {#refunding-whole-vs-partial-quantities}

全額払い戻し専用のボタンはありません。注文全体を払い戻すには、すべての明細の**払い戻し数量**を**数量**の全数に設定し、送料や手数料を**任意の金額**に入力します。表には注文の商品だけが表示され、送料や手数料の行はありません。一部を払い戻す場合は、返品される明細と数量だけを設定します。

任意の金額は、税額を分けずに一括で払い戻されます。

在庫管理が有効な商品は、払い戻すと在庫に戻ります。

## 現金と元の支払い方法の使い分け {#when-to-use-cash-vs-original-method}

- WCPOSから払い戻しできるリーダーまたは支払い方法で**カード払いをした場合**：***(支払い方法)*への払い戻し**を選択します。
- **カード払いのお客様に現金で返金する場合**、店舗で許可されていれば、**現金で払い戻し**を選択し、ドロワーから現金を渡します。
- **現金で支払った場合**：払い戻しは現金で行われ、フォームでの選択は不要です。

:::warning
カード端末で返金する場合は、**現金で払い戻し**を選択しないでください。現金払い戻しを行うと、レジが想定するドロワー内の現金残高が減ります。実際には現金が出ていないため、締め時に現金が過剰になります。
:::

<details>
<summary>別のカード端末で支払った場合</summary>

WCPOSに接続していない独立したカード端末で支払った場合は、その端末または決済事業者のダッシュボードでカードに返金し、WP Adminで注文に払い戻しを記録してください。

</details>

<details>
<summary>元の支払い方法が利用できない場合</summary>

その支払い方法でWCPOSから払い戻しできない場合、***(支払い方法)*への払い戻し**がグレー表示になり、フォームに「この注文では元の支払い方法への払い戻しを利用できません。」と表示されます。

WCPOSが支払い方法を確認できない場合、フォームに「元の支払い方法への払い戻しを確認できませんでした。現金での払い戻しは引き続き利用できます。」と表示され、**現金で払い戻し**が選択されます。現金を渡す場合にのみ選択してください。

</details>

## 払い戻しに失敗した場合 {#if-a-refund-fails}

再試行する前にメッセージを確認してください。ほとんどの失敗では払い戻しは行われていませんが、WCPOSで結果を確認できないことを示すメッセージが一つあります。

:::warning 再試行する前に確認してください
**「WCPOSはこの払い戻しが完了したかどうかを確認できませんでした。」** は、払い戻しを送信したものの、WCPOSが明確な応答を受け取れなかったことを示します。払い戻しが完了している可能性があります。再試行する前に注文を開き、[払い戻し](#refunds-section)を確認してください。試行するたびに新たな払い戻しとなるため、**払い戻しを処理**をもう一度押すと、二重に返金してしまう可能性があります。注文が更新されていない場合は、WP Adminで確認してください。[PAYMENT311](../error-codes/PAYMENT311.mdx)をご覧ください。
:::

それ以外のメッセージは、払い戻しが行われなかったことを示します。たとえば、オフラインの場合は次のように表示されます。

<JourneyShot manifest={manifest} device="tablet" step={7} alt="オフラインの注文画面で払い戻しフォームを開き、画面上部に警告が表示されている様子。払い戻し履歴を読み込めないため、腕時計の数量が再び2と表示されています" />

<JourneyShot manifest={manifest} device="tablet" step={6} maxWidth={640} alt="オフライン通知の拡大表示：オフラインのため払い戻しは行われませんでした。インターネットに再接続してから、もう一度お試しください。ヘルプボタン付き" />

<details>
<summary>それ以外のメッセージ：払い戻しは行われていません</summary>

メッセージに示された問題を解消してから、**払い戻しを処理**をもう一度押してください。

- **「オフラインのため払い戻しは行われませんでした。」** インターネットに再接続してから、もう一度お試しください。
- **「WCPOSがバックグラウンドにあったため、払い戻しは行われませんでした。」** 払い戻しの送信前にアプリがバックグラウンドに移りました。もう一度お試しください。
- **「払い戻しは行われませんでした。ログインしてから、もう一度お試しください。」** ログインの有効期限が切れています。ログインしてから、もう一度お試しください。
- **店舗独自のメッセージ、または「払い戻しの処理に失敗しました」。** 店舗または支払い方法が払い戻しを拒否しました。アカウントに払い戻し権限がない、入力値が許可されていないなどの理由が考えられます。メッセージを読んで問題を解消するか、現金を渡す場合は**現金で払い戻し**を選択してください。

</details>

## 払い戻し後 {#after-the-refund}

店舗から注文情報が更新されると、払い戻しが表示されます。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[52, 409], [97, -102], [67, -50]]} alt="$45.00の一部払い戻し後の注文：合計の下に赤色の払い戻し行として-$45.00と、正味支払額$83.00が表示され、その下に元の現金支払い$128.00が表示されています">

1. **払い戻し** — これまでに払い戻した金額です。合計から差し引かれます。
2. **正味支払額** — **合計**に代わって表示されます。注文で受け取った金額から払い戻しを差し引いた金額です。
3. **支払い** — 元の支払いはそのまま残ります。その下の**払い戻し**行に返金額が表示されます。

</JourneyShot>

注文上部のステータスバッジには**一部払い戻し済み**と表示されます。注文自体のステータスは変わりません。たとえば、注文一覧では引き続き**完了**と表示されます。全額を払い戻すと、WooCommerceが注文を**払い戻し済み**に変更し、**払い戻し**は表示されなくなります。

### 払い戻しセクション {#refunds-section}

注文を下にスクロールして**払い戻し**を表示します。見出しには払い戻しの件数と合計額が表示されます。払い戻しごとにカードがあります。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[-391, -137], [-51, -85], [16, -28], [-24, 0]]} alt="支払いの下にある払い戻し行と、カードが一枚表示された払い戻しセクション：払い戻し #229730、一分未満前、-$45.00、実行者2、理由「ベルトが小さすぎる」、払い戻した腕時計の数量、税額、合計">

1. **払い戻し** — **支払い**の下に表示される返金額です。
2. **件数と合計** — 注文の払い戻し件数と、その合計金額です。
3. **実行者** — 払い戻した人です。名前ではなくWordPressユーザーID（この例では2）で表示されます。
4. **レシート** — この払い戻しのレシートを開きます。

</JourneyShot>

各カードの先頭には、払い戻し固有の番号である**払い戻し #*(id)*** と、実行日時が表示されます。金額は右側に表示されます。その下に引用符付きの理由、続いて払い戻し対象の明細が並びます。商品とSKU、数量、税額、合計が表示され、数値はマイナスで示されます。

WCPOSが払い戻しの詳細を取得できない場合、このセクションに「払い戻しの詳細を読み込めませんでした。」と**再試行**が表示されます。その下の**ローカルの払い戻し概要：** には、端末に保存されている各払い戻しの番号、理由（または「理由の記載なし」）、金額が表示されます。端末に情報がない場合は、「ローカルの払い戻し概要はありません。」と表示されます。接続が戻ったら**再試行**を押してください。

### 払い戻しレシート {#refund-receipts}

払い戻しカードの**レシート**を押すと、その払い戻し専用の**払い戻しレシート**が開き、印刷やPDF保存ができます。メール送信ボタンはありません。払い戻した明細と税額が記載され、**払い戻し先**という見出しの支払いセクションに返金先が表示されます。テンプレートとプリンターを選択し、**レシートを印刷**または **PDFをダウンロード**を押してください。

注文フッターの**レシート**を押すと、注文の現在の内容を反映したレシートが開きます。詳細なレシートには**払い戻し済み**と**正味合計**の行が表示されます。[レシートを再度開く](../receipts/at-checkout.mdx#reprinting-receipts)をご覧ください。

### 現金払い戻しとドロワー {#cash-refunds-and-the-drawer}

レジを開いている間に現金で払い戻すと、レジが想定するドロワー内の現金残高が減り、レジパネルの**現金払い戻し**に表示されます。[現金払い戻しとドロワー](../pos/refunds.mdx#drawer)をご覧ください。

### 払い戻しの実行者 {#who-made-the-refund}

WCPOSから行う払い戻しには、レジ係、店舗、返金先（現金または支払い方法）が記録されます。レジのセッションが開いている場合は、払い戻しがそのレジとセッションにも紐付き、そのドロワーの残高に反映されます。[精算](../reports/reconciliation.mdx)をご覧ください。

## 知っておくこと {#things-to-know}

- **返品は払い戻しとして処理します。** 返品を受け付ける場合は、新しい販売を作成せず、お客様が支払った元の注文を払い戻してください。
- **クーポンはそのまま残ります。** 払い戻しではフォームの金額を返金し、注文のクーポンは変更しません。
- **払い戻しには接続が必要です。** 店舗に接続できる必要があります。元の支払い方法に返金する場合は、決済事業者にも接続できる必要があります。
- **全額払い戻し済みの注文には、払い戻し可能な残額がありません。** ステータスは**払い戻し済み**となり、**払い戻し**は表示されなくなります。
