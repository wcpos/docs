**WP 管理画面：** テンプレートは `WP Admin → POS → Templates` で編集します。このページでは、テンプレートで印刷できるフィールドを紹介します。

レシートの印刷やメール送信については[レシートと支払い完了画面](./at-checkout.mdx)、テンプレートの選択や AI による変更については[レシートのカスタマイズ](./customise.mdx)をご覧ください。

このページは、テンプレートのコードを手動で編集する方向けです。HTML 用も感熱紙用も、すべてのテンプレートは店舗、注文、商品、合計、支払いという共通のレシートデータを使って印刷します。フィールドの印刷方法、よく使う例を三つ、そしてすべてのフィールドを紹介します。

**移動先：** [フィールドを探す](#field-reference) · [よく使う例](#common-recipes) · [問題が発生した場合](#if-something-goes-wrong)

## フィールドを印刷する {#print-a-field}

1. **WP Admin → POS → テンプレート** でテンプレートを開きます（詳しくは[手動で編集する](./customise.mdx#option-3--edit-it-by-hand)をご覧ください）。
2. フィールドを印刷する位置に、`{{store.name}}`、`{{order.number}}`、`{{totals.total_display}}` のようにパスを二重の波括弧で囲んで入力するか、コードの横にあるフィールド一覧から挿入します。
3. コードの下にあるプレビューを確認し、**更新**をクリックして保存します。

商品などのリストは、行をセクションで囲むと、項目ごとにその行が繰り返されます。

```mustache
{{#lines}}
  {{name}} x {{qty}} —
  {{line_total_display}}
{{/lines}}
```

フィールドが空、ゼロ、または偽の場合もセクションの内容は省略されるため、`{{#customer.id}}…{{/customer.id}}` は名前のある顧客の場合にのみ印刷されます。金額の印刷には、末尾が `_display` のフィールドを使ってください。[通貨フィールド](#currency-fields)をご覧ください。

レシートはオフラインでも印刷できます。アプリが端末上の注文からレシートデータのコピーを作成します。

<Accordion>
  <AccordionItem question="レシートの内容が異なる理由">

### データの取得元 {#where-the-data-comes-from}

店舗のサーバーが注文ごとのレシートデータを作成し、アプリは端末上の注文から簡略版のコピーを作成します。このコピーには `cashier`、店舗の営業時間、メモ、ポリシー、`totals.paid_total`、`totals.change_total` は含まれません。HTML 用または感熱紙用のテンプレートは、まず端末のコピーですぐに開き、サーバーのデータが届くと切り替わります。オフラインでは端末のコピーで印刷するため、これらのフィールドは空になります。WCPOS Pro では端末のコピーにも店舗のロゴが含まれます。Pro がない場合、ロゴはサーバーのコピーとともに届きます。従来の PHP テンプレートは常にサーバーで描画されます。このため、テンプレートでは以下のフィールドを使用し、PHP の注文メソッドは使用しません。一部のフィールドは、PDF のダウンロード時など、サーバーがテンプレートを描画する場合にのみ印刷されます。該当するフィールドは[問題が発生した場合](#if-something-goes-wrong)に記載しています。

  </AccordionItem>
</Accordion>

## レシートとデータの対応 {#receipt-map}

## よく使う編集例 {#common-recipes}

手動での編集は、主に以下の二つの例に当てはまります。HTML テンプレートでの例を示し、その下の三つ目の例では古い注文の再印刷を扱います。各カードには、レシートに追加される行、そのコード、テンプレート内の追加位置の順に示しています。商品名、金額、合計はテンプレートの他の部分から出力されます。

<Accordion>

## フィールドリファレンス {#field-reference}

セクションを展開するとフィールドが表示されます。最初の項目には、すべてのセクションとその型を記載しています。

<Accordion>
  <AccordionItem question="すべてのセクションとその型">

### 最上位のセクション {#top-level-sections}

| セクション | 内容 |
|---------|---------------|
| `order`（オブジェクト） | 注文の識別情報、ステータス、日付、メモ、支払い URL の情報 |
| `store`（オブジェクト） | 店舗の識別情報、住所、連絡先、納税者 ID、ロゴ、営業時間、フッターのテキスト |
| `cashier`（オブジェクト） | 注文を処理したユーザー |
| `customer`（オブジェクト） | 顧客の表示名、住所、納税者 ID |
| `lines`（配列） | 商品の明細行 |
| `fees`（配列） | 手数料の行 |
| `shipping`（配列） | 配送料の行 |
| `discounts`（配列） | クーポン・割引の行 |
| `totals`（オブジェクト） | 注文合計、支払合計、払い戻しの概要、商品数 |
| `tax`（オブジェクト） | セクションの表示条件に使う税表示モードのフラグ |
| `tax_summary`（配列） | 税率別の税額集計行 |
| `has_tax_summary`（真偽値） | `tax_summary` の表示条件に使えるフラグ |
| `payments`（配列） | 支払いの行 |
| `refunds`（配列） | 注文に適用された払い戻しの記録 |
| `fiscal`（オブジェクト） | 税務連携で設定される税務用スナップショットのフィールド |
| `register`（オブジェクト） | 売上を記録したレジの `id` と `name`。不明な場合は空文字列 |
| `software`（オブジェクト） | レシートを発行したソフトウェア：`name`(`WCPOS`)、`plugin_version`、`app_version`、`app_build`、`platform` |
| `presentation_hints`（オブジェクト） | 書式と描画処理のヒント |
| `i18n`（オブジェクト） | 標準テンプレートとカスタムテンプレート用の翻訳済みラベル |

  </AccordionItem>

### order {#order}

| フィールド | 型 | 例 / 説明 |
|-------|------|-----------------------|
| `order.id` | number | `1042` |
| `order.number` | string | 表示用の注文番号（例：`"1042"`） |
| `order.currency` | string | ISO 通貨コード（例：`"USD"`） |
| `order.customer_note` | string | 顧客・注文のメモ |
| `order.wc_status` | string | WooCommerce のステータスの元のスラッグ（例：`"processing"`） |
| `order.status_label` | string | カスタムステータスも含めた翻訳済みのステータスラベル |
| `order.created_via` | string | 注文元・チャネル（例：`"woocommerce-pos"`） |
| `order.needs_payment` | boolean | 支払いセクションを表示するかどうか |
| `order.payment_url` | string | 利用可能な場合の注文の支払い URL |
| `order.created` | 日付オブジェクト | 注文の作成日 |
| `order.paid` | 日付オブジェクト | 支払い日。未払いの場合は空文字列 |
| `order.completed` | 日付オブジェクト | 完了日。未完了の場合は空文字列 |
| `order.printed` | 日付オブジェクト | 描画時点の印刷・再印刷のタイムスタンプ |

  </AccordionItem>

### store {#store}

| フィールド | 型 | 例 / 説明 |
|-------|------|-----------------------|
| `store.id` | number | 店舗 ID。削除された店舗の場合は過去の ID |
| `store.name` | string | 店舗の表示名 |
| `store.address.address_1` | string | 住所の 1 行目 |
| `store.address.address_2` | string | 建物名・部屋番号の行 |
| `store.address.city` | string | 市区町村 |
| `store.address.state` | string | 都道府県・地域 |
| `store.address.postcode` | string | 郵便番号 |
| `store.address.country` | string | ISO 国コード |
| `store.address_lines` | array | 書式設定済みの住所行。ほとんどのテンプレートで推奨 |
| `store.tax_ids` | array | 構造化された事業者の納税者 ID。単一の納税者 ID を使う代わりに、これをループで処理します |
| `store.phone` | string | 店舗の電話番号 |
| `store.email` | string | 店舗のメールアドレス |
| `store.logo` | string/null | 店舗ロゴの URL またはデータ URI。店舗独自のロゴがなければ、店舗側で無効にしていない限り WordPress サイトのロゴを使用します。どちらもない場合は `null` |
| `store.opening_hours` | string/null | 簡潔な営業時間のテキスト |
| `store.opening_hours_vertical` | string/null | 複数行の営業時間ブロック |
| `store.opening_hours_inline` | string/null | カンマ区切りの営業時間のテキスト |
| `store.opening_hours_notes` | string/null | 営業時間に関する自由記述のメモ |
| `store.personal_notes` | string/null | レシートのフッター・任意のメモ |
| `store.policies_and_conditions` | string/null | 払い戻し、返品、利用規約のテキスト |
| `store.footer_imprint` | string/null | フッターの法定表記 |

### 納税者 ID オブジェクト {#tax-id-objects}

`store.tax_ids` と `customer.tax_ids` には、同じ構造のオブジェクトが含まれます。

| フィールド | 型 | 説明 |
|-------|------|-------------|
| `type` | string | `eu_vat`、`de_steuernummer`、`au_abn`、`br_cpf`、`us_ein`、`other` などの識別子 |
| `value` | string | 印刷する納税者 ID の値 |
| `country` | string/null | ISO 国コード。`eu_vat` と `other` では null |
| `label` | string | 描画前に確定される翻訳済みの表示ラベル |

例：

```mustache
{{#store.tax_ids}}
  {{label}}: {{value}}
{{/store.tax_ids}}
```

### customer {#customer}

| フィールド | 型 | 例 / 説明 |
|-------|------|-----------------------|
| `customer.id` | number/null | 顧客 ID。ゲストの場合は `null` |
| `customer.name` | string | 顧客の表示名、またはゲストのラベル |
| `customer.first_name` | string | 請求先の名。「Nia 様、ありがとうございます」などの挨拶に使用します。名のないゲストの場合は空 |

| `customer.shipping_address.*` | object | WooCommerce の配送先住所フィールド |

よく使う住所キーには、`first_name`、`last_name`、`company`、`address_1`、`address_2`、`city`、`state`、`postcode`、`country`、`email`、`phone` があります。

### 通常価格と値引き額の表示 {#displaying-regular-price-and-savings}

単価を表示するレイアウトでは、記録された通常価格、販売価格、値引き額を次のように表示します。

```mustache
{{#lines}}
  {{#unit_savings}}
    <span style="text-decoration: line-through;">{{regular_price_display}}</span>
    <span>{{selling_price_display}}</span>
    <span>{{i18n.savings}}: -{{unit_savings_display}}</span>
  {{/unit_savings}}
{{/lines}}
```

数量を反映する場合は、明細行の合計フィールドを使用します。

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    <span>{{i18n.savings}}: -{{line_savings_display}}</span>
  {{/line_savings}}
{{/lines}}
```

`selling_price` はクーポン適用前の価格です。WooCommerce の割引適用後の最終金額には `unit_price` または `line_total` を使用します。

:::note v1.9.0 より前に作成された注文の再印刷
古い WCPOS の注文では、通常価格から販売価格への値引きがすでに `discounts` に含まれている場合があります。カスタムテンプレートで明細行の値引き額と割引額の両方を印刷する場合は、`savings_in_discounts` を使って同じ値引きが二重に表示されるのを防いでください。

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    {{^savings_in_discounts}}
      <span>{{i18n.savings}}: -{{line_savings_display}}</span>
    {{/savings_in_discounts}}
  {{/line_savings}}
  {{#discounts}}
    <span>{{i18n.discount}}: -{{discounts_display}}</span>
  {{/discounts}}
{{/lines}}
```

テンプレートで明細行ごとの `discounts` 行を印刷しない場合は、`savings_in_discounts` が真でも `line_savings` を表示してください。標準テンプレートでは、この違いを自動的に処理します。
:::

### presentation_hints {#presentation_hints}

これらのフィールドは主に、レシートの書式設定を行うアプリとサーバー向けです。サーバーで描画するテンプレートではすべて印刷できますが、POS アプリで描画するテンプレートで利用できるのは `display_tax`、`prices_entered_with_tax`、`rounding_mode`、`locale`、`order_barcode_type` だけです。

| フィールド | 型 | 説明 |
|-------|------|-------------|
| `presentation_hints.display_tax` | string | `incl` または `excl`。アプリが設定し、サーバーでは省略されます |
| `presentation_hints.hour12` | boolean/null | 店舗の時刻形式が 12 時間制の場合は真 |
| `presentation_hints.hour_token` | string/null | 店舗の時刻形式で使う時間のパターン：`h`、`hh`、`H`、`HH` |
| `presentation_hints.prices_entered_with_tax` | boolean | カタログ価格が税込かどうか |
| `presentation_hints.rounding_mode` | string | WooCommerce の税額の端数処理設定 |
| `presentation_hints.locale` | string | 書式設定に使用するロケール |
| `presentation_hints.timezone` | string | レシートのタイムゾーン |
| `presentation_hints.currency_position` | string | 通貨記号の位置 |
| `presentation_hints.currency_symbol` | string | 通貨記号 |
| `presentation_hints.price_thousand_separator` | string | 桁区切り記号 |
| `presentation_hints.price_decimal_separator` | string | 小数点記号 |
| `presentation_hints.price_num_decimals` | number | 小数点以下の桁数 |
| `presentation_hints.price_display_suffix` | string | WooCommerce の価格表示の接尾辞 |
| `presentation_hints.order_barcode_type` | string | このフィールドを読み取るテンプレート用のバーコード種別：`code128`（既定値）、`qrcode`、`ean13`、`ean8`、`upca`。アプリが設定し、サーバーでは省略されます。ギャラリーのテンプレートでは、バーコード種別をテンプレート内で設定します |

書式設定済みの金額フィールド（`totals.total_display` などの `*_display` 値）は、上記の位置と区切り記号を使い、注文の通貨の**通貨記号**を付けて金額を表示します。したがって、レシートには `USD 12.00` ではなく `$12.00` と表示されます。元の `order.currency` フィールドは ISO コードのままなので、テンプレート内の処理に利用できます。

  </AccordionItem>

  <AccordionItem question="レシートの文言 — i18n">

### i18n {#i18n}

可能な限りテキストを直接書き込まず、`i18n` ラベルを使用してください。

```mustache
{{i18n.order}} #{{order.number}}
{{i18n.cashier}}: {{cashier.name}}
{{i18n.total}}: {{totals.total_display}}
```

よく使うキーには `order`、`date`、`cashier`、`customer`、`item`、`sku`、`qty`、`unit_price`、`regular_price`、`selling_price`、`savings`、`discount`、`subtotal`、`total_saved`、`total`、`tax`、`paid`、`tendered`、`change`、`tax_summary`、`refunded`、`net_total`、`customer_note`、`thank_you_purchase`、`opening_hours` があります。税務用ラベルには `copy`（控えと印刷）、`reprint`、`register`、`sale_time`、`software`、`document_refund`、`document_void`、`document_cancellation` があり、納税者 ID のラベルキーには `store_tax_id_label_eu_vat` や `customer_tax_id_label_other` などがあります。拡張機能によってキーが追加される場合もあります。

  </AccordionItem>
</Accordion>

## 各価格の関係 {#price-model}

レシートの一つの商品には複数の価格があり、実際の金額を見るとそれぞれの名前を理解しやすくなります。これはサンプル注文のエスプレッソの行です。$17.00 の商品がセールで $14.50 になり、さらに 10% のクーポンが適用されています。

<PriceFlow
  caption="エスプレッソ豆 — 一つあたり（注文には二つ含まれます）"
  scaleLabel="通常価格 17.00"
  segments={[
    { kind: 'paid', amount: 13.05, label: "支払額 13.05" },
    { kind: 'coupon', amount: 1.45, label: "1.45" },
    { kind: 'savings', amount: 2.5, label: "2.50" },
  ]}
  summary={[
    { label: "注文全体のセールによる値引き額", value: '`totals.sale_savings_total` = 5.00' },
    { label: "注文全体のクーポンによる割引額", value: '`totals.discount_total` = 5.28' },
    { label: "値引き額 + 割引額（旧バージョンでの重複を除く）", value: '`totals.total_saved` = 10.28' },
  ]}
/>

セールによる値引き額は、通常価格と販売価格の差です。割引額は、WooCommerce が計算したクーポンによる減額分です。WooCommerce の注文合計とレポートには割引額だけが記録されるため、`total_saved` は両者を合算し、顧客向けの一つの数値にまとめます。

### 日付オブジェクト {#date-objects}

各日付は複数の形式に書式設定された状態で提供されるため、テンプレート側で日付の書式設定を行う必要はありません。

| フィールド | 説明 |
|-------|-------------|
| `datetime`、`date`、`time` | 既定の日付・時刻文字列 |
| `datetime_short`、`datetime_long`、`datetime_full` | ロケールに応じた日付と時刻の組み合わせ形式 |

## レシートデータの拡張 {#extending}

プラグインは `wcpos_receipt_data` フィルターを使って、レシートデータに独自のフィールドを追加できます。

<Accordion>
  <AccordionItem question="フィルターの引数、六つのモード、使用例">

WCPOS は、上記のフィールドに特定のプラグイン固有のデータを含めません。WooCommerce で扱われない情報をレシートに持たせる必要がある場合、プラグイン自身が `wcpos_receipt_data` フィルターを使って追加します。プラグインが WooCommerce 自体の注文合計にフィルターを適用するのと同じ仕組みです。このフィルターは、ライブレシート、支払い時点の税務用スナップショット、PDF ダウンロード、従来の PHP テンプレートなど、サーバーが作成するすべてのレシートで実行されます。WCPOS 2.0 より前は、このフィルターの名前は `woocommerce_pos_receipt_data` でした。旧名は引き続き動作しますが、2.0 以降は非推奨で、早ければ 2.2 で削除されます（[フックの命名](../extensions/index.mdx#hook-naming)を参照）。

第三引数の `$mode` は、作成する書類の種類を示します。`live`、`fiscal`、`refund`、`preview`（テンプレートエディターとギャラリーのサンプルレシート）、`closure`、`xreport`（レジ締めと X レポートの書類）です。`preview`、`closure`、`xreport` では、注文は未保存で ID は `0` です。保存済みの注文を必要とするプラグインは、`$order->get_id()` が `0` の場合、`$data` を変更せずに返すようにしてください。

```php
add_filter( 'wcpos_receipt_data', function ( array $data, WC_Abstract_Order $order, string $mode ) {
    foreach ( $data['discounts'] as &$row ) {
        if ( 'smart_coupon' === $row['discount_type'] ) {
            $row['gift_card'] = true;
        }
    }
    return $data;
}, 10, 3 );
```

テンプレートでは、他のセクションと同様に、新しいキーを表示条件にできます。

```
{{#discounts}}
  {{#gift_card}}Gift Card{{/gift_card}}{{^gift_card}}{{i18n.discount}}{{/gift_card}}{{#label}}: {{label}}{{/label}}
{{/discounts}}
```

スキーマで定義されたキーは、ドキュメントに記載された型を維持してください。追加したキーはスキーマに含まれないため、テンプレートエディターのフィールド選択には表示されません。また、税務用スナップショットに含まれるのは、注文の支払い時点でフィルターが追加した内容だけです。このフィルターは WCPOS 1.10.8 から利用できます。

  </AccordionItem>

  <AccordionItem question="追加したキーを印刷できるレシート">

追加したキーはすべて、サーバー自身が描画するレシート、つまり PDF ダウンロードと従来の PHP テンプレートに渡されます。POS アプリで描画する HTML 用と感熱紙用のテンプレートでは、まずデータを再構築します。`order`、`store`、`cashier`、`customer` 内に追加したキーは引き継がれますが、上記の割引行など、それ以外に追加したキーは省略されます。{/* pending: monorepo#3363 */} 税務用スナップショットを持つライブレシートでは、フィルター実行後に税務識別情報、`register`、`software` がスナップショットからコピーされるため、このフィルターで変更しても反映されません。代わりにスナップショットの内容を拡充してください。

  </AccordionItem>
</Accordion>

## 問題が発生した場合 {#if-something-goes-wrong}

**あるレシートでは行に `$0.00` と印刷され、別のレシートでは何も印刷されません。** `totals.change_total_display`、`totals.refund_total_display`、`payments[].tendered_display` など、一部の `_display` フィールドは、値がゼロの場合、サーバーで描画すると空になり、アプリで描画すると `$0.00` になります。代わりに数値を条件とするセクション内に行を入れると、どちらでも省略されます：`{{#totals.change_total}}…{{/totals.change_total}}`。

**お得になった合計額の行が表示されません。** `totals.total_saved_complete` が偽になっています。少なくとも一つの商品で通常価格が記録されていないため、値引き額を計算できません。通常は WCPOS 1.9.0 より前に会計処理した注文で発生します。

**合計が顧客の支払額より少なくなっています。** 店舗が税抜価格を表示しているため、`totals.total` は税抜合計です。請求額を表示するには `totals.total_incl_display` を印刷してください。WCPOS に付属する従来の PHP レシートでは、この金額を印刷します。

**PDF ダウンロードでは印刷されるフィールドが、POS では印刷されません。** アプリで描画するテンプレートは、最初にデータを再構築する際、一部のフィールドを省略します。これらは PDF ダウンロードと従来の PHP テンプレートでのみ印刷されます。以下のフィールドはそれらでのみ印刷するか、セクションを表示条件として使い、POS レシートでは省略されるようにしてください。{/* pending: monorepo#3363 */}

<Accordion>
  <AccordionItem question="PDF と POS のレシートで異なるフィールド">

- `lines[].attributes`、`lines[].total_refunded_display`、`lines[].unit_subtotal_display`（その `_incl` 版と `_excl` 版も含む）
- `software.platform`
- `display_tax`、`prices_entered_with_tax`、`rounding_mode`、`locale`、`order_barcode_type` 以外の `presentation_hints`
- ドイツ、オランダ、フランス、英国企業、スイスの各種別の顧客納税者 ID
- プラグインが `order`、`store`、`cashier`、`customer` の外に追加したキー。[レシートデータの拡張](#extending)をご覧ください。

</AccordionItem>
</Accordion>

## バージョン {#versions}

レシートデータには、プラグインとは別の独自のバージョン番号があります。フィールドの追加前に取得した税務用スナップショットなど、古いレシートには新しいフィールドが存在しないため、セクションを表示条件にしてください。

| バージョン | 追加内容 |
|---------|-------|
| 1.1 | 各商品の通常価格、販売価格、値引き額と、**お得になった合計額**を含む注文全体の値引き・割引の合計。いずれも注文合計や WooCommerce のレポートには影響しません |
| 1.2 | `discounts[].discount_type` |
| 1.3 | `customer.first_name` と `i18n` 内の顧客表示用ラベル |
| 1.4 | `register`、`software`、税務書類のフィールド（`fiscal.document_type`、`is_…` フラグ、`sale_time`、`received_at`、`sale_tz`、`sale_counter`、`corrects`）と、それらの `i18n` ラベル |
