WCPOS 会将您的产品和客户数据存储在每台设备的本地数据库中。这意味着 POS 的部分功能无需互联网连接即可使用，而其他功能则需要网络连接。

## 哪些功能可离线使用 {#what-works-offline}

- **浏览产品** — 从本地数据中搜索、筛选并查看产品详情
- **浏览客户** — 查找客户姓名、电子邮件和地址
- **建立购物车** — 添加商品、更改数量、编辑价格并应用 POS 折扣
- **应用优惠券**（Pro）— 优惠码会根据已同步的优惠券数据在本地验证；待排队订单到达服务器后，服务器会重新验证
- **使用支持离线的付款方式完成销售** — 现金和外部处理的刷卡销售会保存在本地，并排队等待发送到 WooCommerce
- **扫描条码** — 扫描条码以在本地数据库中查找产品
- **查看报表** — 默认（离线）报表类型会根据本地存储的订单生成报表

## 哪些功能需要连接 {#what-requires-a-connection}

- **依赖服务器的结账操作** — 网页结账、集成的在线网关或终端网关，以及 **保存到服务器**，都需要各自的服务可以访问
- **同步数据** — 从 WooCommerce 拉取新产品、更新后的价格或新客户
- **登录** — 初始身份验证需要连接到您的 WordPress 站点
- **许可证激活** — Pro 许可证检查需要访问 WCPOS 许可证服务器
- **处理退款** — 退款不能离线排队；网关和您的店铺都需要可访问（请参阅[退款](/orders/refunds)）

## 本地数据库的工作方式 {#how-the-local-database-works}

首次打开 WCPOS 时，它会在后台预填充您的产品目录，并在您使用过程中拉取其他数据——只要首批产品已存入设备，您就可以开始销售。此后，后台的变更检查（默认每 60 秒一次，可在[商店健康](/support/store-health)中调整）只会获取服务器上发生变化的内容。

本地数据库：

- **跨会话保留** — 浏览器重启和设备重启后数据仍会保留
- **按设备（并按收银员）存储** — 每台设备都会维护自己的本地副本；收银员之间不共享本地数据
- **保持同步** — 后台变更检查会拉取更新；您所做的更改会在本地排队并推送到服务器

您可以在 **商店健康 → 数据库** 中确切了解设备上有哪些数据，以及哪些仍在等待发送。如需更多技术细节，请参阅[同步引擎的工作原理](/reference/sync-engine)。

## 您离线所做的更改会排队 {#offline-writes}

您在 POS 中所做的每一项更改——一笔销售、一次产品编辑、一次客户更新——都会先保存到设备上，然后排队等待发送。在您离线期间，队列只是等待；即使在班次中途断网，也不会丢失任何内容。

连接恢复后，队列会自动排空。如果您的服务器直接拒绝某项更改（这种情况很少见——例如服务器认为某条记录无效），POS 不会无声地永远重试：该更改会被搁置在 **商店健康 → 数据库** 中的*“从未到达您服务器的更改”*下，并附上服务器给出的原因以及明确的 **重新发送** / **放弃** 操作。参见[商店健康](/support/store-health#refused-changes)。

## 连接状态指示器 {#connectivity-indicator}

POS 页眉会显示一个彩色圆点，用于指示连接状态：

- **绿色** — 已连接到服务器，所有功能均可用
- **黄色** — 连接不稳定，部分操作可能较慢
- **红色** — 离线，仅限于本地数据

## 连接中断时会发生什么 {#what-happens-during-connectivity-loss}

如果在使用 POS 时失去互联网连接：

1. **仍可从本地数据浏览产品和客户**。
2. **可以继续创建购物车**并编辑商品——每项更改都会在本地排队。
3. **可以使用支持离线的付款方式完成结账** — 该笔销售会加入待发送队列。依赖服务器的支付网关在其服务可访问之前仍然不可用。
4. **未完成的订单会保留**在本地数据库中，直到连接恢复。

## 连接恢复时 {#when-connection-restores}

连接恢复后：

- 连接状态指示器会变为绿色。
- **排队的更改会自动发送到您的服务器** — 离线期间完成的销售和编辑无需任何手动操作即可推送。
- 依赖服务器的支付网关和 **保存到服务器** 会再次可用。
- 后台同步会恢复，并拉取您离线期间发生的任何产品或客户变更。

## 网络连接不稳定时的提示 {#tips-for-unreliable-connections}

- **对重要订单使用“保存到服务器”** — 这会立即将订单推送到 WooCommerce，因此即使设备的本地数据库被清除，订单也不会丢失。
- **中断后检查商店健康** — **商店健康 → 数据库** 中的*待发送的更改*卡片可以确认所有内容是否都已到达您的服务器。
- **在有信号时同步** — 如果您知道网络连接会时断时续，请在连接良好时让产品目录完成预填充。
