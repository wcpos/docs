:::note 仅限桌面端和移动端
此界面仅在桌面端和移动端应用中显示。网页端用户可通过 `yourdomain.com/pos` 直接访问 POS，并使用 WordPress 凭据登录。
:::

## 连接界面概览 {#connect-screen-overview}

打开 WCPOS 桌面端或移动端应用后，您会看到连接界面。您可以在此管理店铺连接和用户登录。

{/* Screenshot: connect-screen.png */}

## 添加新店铺 {#adding-a-new-store}

1. 在文本框中输入 WooCommerce 店铺 URL（例如 `https://mystore.com`）
2. 点击 **连接**
3. 系统会跳转到登录页面，请使用 WordPress 凭据登录
4. 登录成功后，您将返回应用

## 多个店铺 {#multiple-stores}

您可以根据需要连接任意数量的 WooCommerce 店铺。连接界面上的每个店铺都显示为一张独立卡片，其中包含：

- **店铺名称**和网站图标
- **店铺 URL**
- 该店铺的**已登录用户**

如果您管理多个地点或业务，此功能会很实用。

## 每个店铺可登录多个用户 {#multiple-users-per-store}

每个店铺都可让多个用户同时登录。适用于以下场景：

- **交接班** - 新收银员可以在上一位收银员退出前登录
- **多收银台设置** - 不同收银员在不同设备上操作
- **快速切换** - 轻松切换用户账户

### 添加用户 {#adding-a-user}

点击 <Icon name="plus" /> “已登录用户”旁边的按钮，即可为该店铺添加另一位用户。

### 切换用户 {#switching-users}

点击用户徽章（例如“Brenda”），即可用该用户身份打开 POS。

### 移除用户 {#removing-a-user}

点击用户徽章上的 **×**，即可将该用户从店铺注销。

## 移除店铺 {#removing-a-store}

点击店铺卡片上的红色 **×** 按钮，即可将店铺从列表中移除。此操作会注销所有用户，并从应用中移除该店铺连接。

## 演示店铺 {#demo-store}

您可能会在屏幕底部看到“进入演示店铺”链接。点击后可连接到演示用 WooCommerce 店铺，试用 WCPOS 功能而不影响自己的店铺数据。

## 故障排除 {#troubleshooting}

:::tip 首先检查：`X-Frame-Options`
桌面端和移动端应用使用 **iframe** 进行登录、支付和收据显示。**任何**发送 `X-Frame-Options: DENY` 或 `SAMEORIGIN` 的服务器响应头或插件都会导致登录失败。这是应用登录失败最常见的原因——请先检查登录页面的响应头（使用浏览器开发者工具，或运行 `curl -I https://yourstore.com/wp-login.php`），再进行其他排查。
:::

<Accordion>
  <AccordionItem question="无法连接到我的店铺？">

  - 确保 WCPOS 插件已在您的 WordPress 网站上安装并启用
  - 确认使用的 URL 正确（包括 `https://`——WooCommerce REST API 需要 SSL）
  - 先在网页浏览器中打开 `yourdomain.com/pos`，确认插件正常工作
  - 确认 WooCommerce REST API 可以访问
  - 确认您的用户账户具有 POS 访问权限

  </AccordionItem>

  <AccordionItem question="桌面端或移动端应用登录失败">

  大多数应用登录失败都是安全或缓存插件阻止了登录 iframe 所致：

  - **`X-Frame-Options` 响应头**（由安全插件或服务器设置）会阻止登录 iframe——请参阅上方说明。暂时停用安全插件，登录后再重新启用（您的会话可持续约一周）。
  - **安全插件**——Wordfence、Really Simple Security、WPS Hide Login、iThemes/Solid Security 和 Defender Pro 都是常见原因。完整列表和解决方法请参阅[插件冲突](/support/troubleshooting/plugin-conflicts#security-and-login-plugins)。
  - **Wordfence 2FA**——登录 iframe 中不会显示 2FA 代码字段。目前请为 POS 用户停用 2FA。
  - **自定义登录 URL**（例如 WPS Hide Login）——应用无法找到登录页面。请使用标准的 `/wp-admin/` URL。
  - **缓存插件**可能会在您停用有问题的插件后继续提供被阻止的登录表单——请清除缓存，或清除应用缓存／重新安装桌面应用。

  </AccordionItem>

  <AccordionItem question='连接界面显示“REST API 需要身份验证”或安全插件错误'>

  某个插件（例如 Force Login 或 JWT 身份验证插件）要求所有 REST API 请求都进行身份验证，因此应用无法读取网站的公开信息。现在，应用会显示服务器返回的实际消息（例如 _“只有经过身份验证的用户才能访问 REST API”_），而不会错误判断网站类型。

  **解决方法：** 将安全插件配置为允许未认证访问 `/wp-json/wcpos/` 和 `/wp-json/wc/v3/`，或者仅在完成首次连接期间暂时停用该插件。

  </AccordionItem>

  <AccordionItem question='“这似乎不是 WordPress 网站”（桌面应用）'>

  桌面应用通过 HTTP `Link` 标头发现 REST API。如果某个插件（通常是 **Image Prioritizer** 或其他性能插件）导致该标头内容过多或被截断，发现过程就会失败。**解决方法：** 停用图像优化插件和会修改标头的性能插件，然后重试。

  </AccordionItem>

  <AccordionItem question="应用提示需要更新／更新后崩溃">

  请检查应用与服务器插件的版本是否不匹配——应用商店可能已推送应用更新，但 WCPOS 插件仍需更新（反之亦然）。对于 v1.10，应用和 WCPOS 插件都必须使用 **v1.10 发布系列**，因为应用使用该插件的 v2 同步 API。如果只更新了其中一方，且请求因 `rest_no_route` 失败，请更新另一方。

  </AccordionItem>

  <AccordionItem question='“无法创建快速店铺数据库”错误'>

  这是首次登录时发生的竞争条件。**完全关闭应用后重试**——通常第二次就能成功。

  </AccordionItem>

  <AccordionItem question="卡在用户选择界面（桌面应用）">

  登录后，您会看到自己的用户名，但不知道如何继续。**点击您的用户名／姓名**即可进入 POS——姓名本身就是按钮。

  </AccordionItem>

  <AccordionItem question="连接持续失败？">

  - 先在网页浏览器中访问 `yourdomain.com/pos`，确认插件正常工作
  - 检查网站的错误日志，查看是否存在问题
  - 确认主机没有阻止 REST API——请参阅[主机特定说明](/support/performance/server#hosting-specific-notes)
  - 确保服务器符合[最低要求](/support/performance/server#minimum-server-requirements)

  </AccordionItem>
</Accordion>
