## 这意味着什么 {#what-this-means}

支付终端未能完成与 WCPOS 的配对。

请检查终端设置后重试配对，并在联系支付服务商时附上追踪 ID。

## 该怎么做 {#what-to-do}

需要先更改设置，此功能才能正常工作。请在完成上述更改后再重试；不做更改就重试同样会失败。

## 您的数据 {#your-data}

订单和产品数据不受影响。如果问题持续存在，请联系您的支付服务商。

## 故障排查 {#troubleshoot}

1. 从终端设置中重新开始配对，并让终端保持唤醒状态且与收银机处于同一网络。
2. 先检查基础事项：终端已充电、已连接到正确的网络或蓝牙，且未仍与另一台收银机配对。
3. 日志条目中带有一个追踪 ID——如果配对仍无法完成，请在联系支付服务商时一并提供。

## 在哪里查看 {#where-to-look}

当 WCPOS 能够保存此错误时，它会被记录在触发该错误的设备上。打开 **商店健康 → 日志**（导航抽屉底部的心跳图标），找到标有此代码的条目并展开：展开后的行会显示通俗易懂的原因，以及故障发生时捕获的上下文。对于商店请求，该上下文可能包含服务器自身的错误代码（`serverCode`）、HTTP `status` 或 `endpoint`；具体显示哪些字段取决于故障发生的位置。上报问题时，请使用日志页面顶部的 **复制调试信息**（在手机和平板上为 **分享调试信息**），而不要使用截图：它会打包应用版本、连接状态和最近的错误。日志最多保留 30 天，因此请趁问题还新鲜时收集。此外，也请复制在 POS 能够写入自身日志条目之前出现的任何浏览器控制台错误。

除应用内日志外，此故障还可能在以下位置留下线索：

- **支付服务商后台**：终端服务商自己的记录（例如 Stripe Dashboard → Payments，或 Square Dashboard）才是判断扣款是否成功的权威依据——在重试任何付款之前请先查看。
