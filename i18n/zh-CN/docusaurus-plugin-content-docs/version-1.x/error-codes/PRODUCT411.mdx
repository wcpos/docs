## 这意味着什么 {#what-this-means}

条形码扫描设置无法加载，因此扫描可能匹配不到产品。

POS 会持续在后台尝试加载这些设置。如果扫描一直不可靠，请重新加载应用一次。

## 该怎么做 {#what-to-do}

请再次尝试该操作。WCPOS 会自动重试。

## 您的数据 {#your-data}

订单和产品数据不受影响。

## 故障排查 {#troubleshoot}

1. 继续工作——POS 会在后台重试加载条形码设置。
2. 如果扫描始终匹配不到任何内容，请重新加载应用一次。
3. 如果重新加载后问题依旧，说明设置请求本身正在失败：请检查与商店的连接，并在商店健康 → 日志中查找相应的错误。

## 在哪里查看 {#where-to-look}

当 WCPOS 能够保存此错误时，它会被记录在触发该错误的设备上。打开 **商店健康 → 日志**（导航抽屉底部的心跳图标），找到标有此代码的条目并展开：展开后的行会显示通俗易懂的原因，以及故障发生时捕获的上下文。对于商店请求，该上下文可能包含服务器自身的错误代码（`serverCode`）、HTTP `status` 或 `endpoint`；具体显示哪些字段取决于故障发生的位置。上报问题时，请使用日志页面顶部的 **复制调试信息**（在手机和平板上为 **分享调试信息**），而不要使用截图：它会打包应用版本、连接状态和最近的错误。日志最多保留 30 天，因此请趁问题还新鲜时收集。此外，也请复制在 POS 能够写入自身日志条目之前出现的任何浏览器控制台错误。

除应用内日志外，此故障还可能在以下位置留下线索：

- **网络检查器**（网页版和桌面版）：打开开发者工具——在浏览器中按 F12，或在桌面应用的菜单中选择 **高级 → 切换开发者工具**——然后选择 **网络** 选项卡。请先遵循本页的重试指引；只有当这些步骤说明可以安全操作时，才重现该操作。失败的请求会显示 HTTP 状态码和原始响应正文，其中包括那些从未传到 POS 日志的错误页面。
