## 这意味着什么 {#what-this-means}

您的店铺拒绝了此更改，因此该更改尚未到达店铺。

查看店铺给出的原因。如果 **店铺健康 → 数据库** 中列出了此更改，请修复相应记录，然后点按 **重新发送**，或点按 **放弃**。如果没有列出，则店铺版本已恢复——如果仍需要此更改，请重新进行（请参阅 [SYNC202](/error-codes/SYNC202)）。被拒绝的更改不会自动重试。

## 您的数据 {#your-data}

不要清除此设备上的数据——其中可能包含店铺尚未收到的更改。列在 **店铺健康 → 数据库** 中的被拒更改会一直保留，直到您重新发送或丢弃它。对现有商品、变体、客户或优惠券的编辑通常会自动撤销，并改为记录为 [SYNC202](/error-codes/SYNC202)。如果它显示为此代码，且更改列在 **店铺健康 → 数据库** 中，则表示自动撤销未能完成——请像处理下方列出的其他更改一样处理。如果这种情况持续发生，请在 **日志** 选项卡中使用 **复制调试信息**，并联系 WCPOS 支持。

## 故障排查 {#troubleshoot}

1. 请查看店铺给出的原因——该原因会显示在日志条目中，也会显示在 **店铺健康 → 数据库** 中该更改所在的行。
2. 打开 **店铺健康 → 数据库**。如果更改未列在其中，说明店铺中的版本已恢复到此设备，无需发送——请参阅 [SYNC202](/error-codes/SYNC202)。根据原因修正问题；如果仍需要此更改，请重新进行更改。
3. 如果更改仍在列表中——例如订单、在此设备上创建的记录，或自动撤销未能完成的目录编辑——被拒的更改会显示在 **"… 个更改未能到达您的服务器"** 下，其所在行会注明店铺给出的原因。请直接修正记录中原因所指的问题，例如订单中的某个字段，同时让该更改继续保留在列表中。
4. 返回 **店铺健康 → 数据库**，点击该行上的 **重新发送**。系统会根据此设备上的当前内容重新构建更改并发送。
5. 如果不再需要此更改，请改为点击 **丢弃**：店铺中的版本会保留。请先阅读确认信息——如果店铺从未保存过该记录，丢弃操作会将其从此设备删除。
6. **站点管理员：** 如果原因指出用户无权进行此更改，则其角色缺少相应权限——请参阅 [AUTH201](/error-codes/AUTH201)。如果原因提到 POS 中未显示的字段，请在 WP Admin 中打开同一条记录——其他插件可能添加了 POS 无法查看的验证规则。如果仍被拒绝，请在 **日志** 选项卡中使用 **复制调试信息**，并联系支持团队。
