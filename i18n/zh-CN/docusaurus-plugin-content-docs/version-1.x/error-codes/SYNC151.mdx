## 这意味着什么 {#what-this-means}

您的商店发送了格式错误的响应，WCPOS 必须先修复才能读取。

这通常意味着某个插件或 PHP 通知正在向商店响应中输出多余内容。WCPOS 已修复这一次，但修复并不总能成功——请让网站管理员检查网站的错误日志。

## 该怎么做 {#what-to-do}

您可以继续工作——WCPOS 会自动处理。WCPOS 会自动重试。

## 您的数据 {#your-data}

订单和产品数据不受影响。如果问题持续存在，请咨询管理您 WordPress 网站的人员。

## 故障排查 {#troubleshoot}

1. 检查相关请求最终是否成功。如果成功，说明 WCPOS 已修复本次问题；如果失败，请改为按该请求的错误和重试指引处理。
2. 原因出在网站上：某个插件或主题正在向 REST 响应中输出警告或多余内容。请让网站管理员检查网站日志中故障时段的 PHP 通知。
3. 网络检查器会显示原始响应正文——多余的输出就出现在 JSON 之前或之后。
4. 修复只是尽力而为：如果这类警告变得频繁，请修复有问题的插件，而不要依赖修复机制。

## 在哪里查看 {#where-to-look}

当 WCPOS 能够保存此错误时，它会被记录在触发该错误的设备上。打开 **商店健康 → 日志**（导航抽屉底部的心跳图标），找到标有此代码的条目并展开：展开后的行会显示通俗易懂的原因，以及故障发生时捕获的上下文。对于商店请求，该上下文可能包含服务器自身的错误代码（`serverCode`）、HTTP `status` 或 `endpoint`；具体显示哪些字段取决于故障发生的位置。上报问题时，请使用日志页面顶部的 **复制调试信息**（在手机和平板上为 **分享调试信息**），而不要使用截图：它会打包应用版本、连接状态和最近的错误。日志最多保留 30 天，因此请趁问题还新鲜时收集。此外，也请复制在 POS 能够写入自身日志条目之前出现的任何浏览器控制台错误。

除应用内日志外，此故障还可能在以下位置留下线索：

- **网络检查器**（网页版和桌面版）：打开开发者工具——在浏览器中按 F12，或在桌面应用的菜单中选择 **高级 → 切换开发者工具**——然后选择 **网络** 选项卡。请先遵循本页的重试指引；只有当这些步骤说明可以安全操作时，才重现该操作。失败的请求会显示 HTTP 状态码和原始响应正文，其中包括那些从未传到 POS 日志的错误页面。
- **WooCommerce → 状态 → 日志**：在 WordPress 网站上，查看最新的 `fatal-errors-*.log` 是否有 PHP 崩溃记录，以及以故障相关插件命名的任何日志来源。商店返回的 500 类错误几乎总会在这里留下原因。
- **网站的 PHP 错误日志**：如果 WooCommerce 的日志页面在故障时段没有任何记录，请向主机服务商索取 PHP 错误日志——有些致命错误只在服务器层面被捕获。
