## 这意味着什么 {#what-this-means}

店铺拒绝了此更改，因此此设备已还原为店铺中的版本。

更改未保存。请查看店铺给出的原因，修正相关问题，然后重新进行更改。

这种情况会发生在编辑现有商品、商品变体、优惠券和客户时。如果店铺永久拒绝某项更改（例如值无效，或已登录用户无权进行此更改），WCPOS 不会让被拒绝的编辑继续等待，而是将店铺中的版本恢复到此设备上，确保收银台销售时使用与店铺相同的信息。日志条目会标明记录，并附上店铺给出的原因。

## 您的数据 {#your-data}

其他内容均未更改。店铺仍保留其原有版本，此设备也重新显示该版本。如果店铺已删除该记录，此设备上也会将其移除。只有被拒绝的编辑会丢失，因此修正原因后请重新进行编辑。销售和订单不受影响；您在被拒绝的那次编辑之后对同一记录所做的编辑仍会保留并继续发送。

## 故障排查 {#troubleshoot}

1. 展开日志条目并查看店铺给出的原因：其中会说明店铺拒绝了什么，以及该内容属于哪条记录。
2. 根据原因修正问题。如果涉及某个值（例如价格、SKU、电子邮件地址，或未填写的必填字段），请确定正确的值。如果原因指出用户无权进行此更改，则该账户的角色缺少相应权限：请参阅 [AUTH201](/error-codes/AUTH201)。
3. 打开该记录（如果店铺已将其删除，则无需更改），使用修正后的值重新进行更改并保存。同步完成后，检查记录是否显示了您的更改。
4. 如果店铺拒绝了此设备上新建的记录，该记录不会还原——因为没有可还原的店铺版本。它会继续列在 **Store health → Database** 的 **"… changes never reached your server"** 下；请参阅 [SYNC201](/error-codes/SYNC201)。
5. **站点管理员：** 如果原因提到 POS 中不可见的字段，请在 WP Admin 中打开同一条记录——其他插件可能添加了 POS 无法看到的验证规则。如果店铺持续拒绝此更改，请在 **Logs** 标签页使用 **Copy debug info** 并联系支持团队。
