## 这意味着什么 {#what-this-means}

您的店铺发生错误，未能完成此请求。

已连接到店铺，但其服务器未能处理此请求——问题出在网站，而不是 POS。请重试此操作。如果问题持续，请让您的站点管理员检查 **WooCommerce → 状态 → 日志**。此设备上的数据没有丢失。

## 您的数据 {#your-data}

请勿清除此设备的数据——其中可能包含店铺尚未收到的更改。正在发送的更改可能尚未到达店铺。如果问题持续出现，请在 **日志** 标签页中使用 **复制调试信息**，并联系 WCPOS 支持人员。

## 故障排查 {#troubleshoot}

**在 POS 上（收银员）：**展开日志条目，并记下 status、endpoint 和 serverCode——这些信息可以说明请求失败时服务器正在执行什么操作。

**在网站上（网站管理员／主机服务商）：**

1. 在网站上打开 WooCommerce → 状态 → 日志，查看故障时段前后最新的 fatal-errors 日志；500 类响应几乎总会在那里留下 PHP 错误。
2. 如果故障是在网站的插件、主题或 PHP 更新之后开始出现的，请首先怀疑该变更，并将其回滚或停用。
3. 如果 WooCommerce 的日志中什么都没有，请向主机服务商索取同一时间段的服务器 PHP 错误日志。

**然后，返回 POS：**重试此操作。
