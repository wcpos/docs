# API02008: 刷新令牌无效 {#api02008-refresh-token-invalid}

## 这意味着什么 {#what-this-means}

POS存储的刷新令牌未被服务器识别。刷新令牌用于在不需要您重新登录的情况下获取新的访问令牌。

## 常见原因 {#common-causes}

- **令牌已撤销** — 管理员使您的会话失效
- **服务器密钥已更改** — WordPress安全密钥已更新
- **数据损坏** — 令牌在存储中被损坏
- **多次登录** — 在其他地方登录可能使此令牌失效

## 如何修复 {#how-to-fix}

### 1. 再次登录 {#1-log-in-again}

由于刷新令牌无效，您需要再次进行身份验证：
1. 从POS注销
2. 输入您的用户名和密码
3. 这将生成新的有效令牌

### 2. 检查是否有已撤销的会话 {#2-check-for-revoked-sessions}

如果管理员撤销了会话：
- 这是正常的安全做法
- 只需再次登录
- 您的新会话将正常工作

### 3. 检查服务器更改 {#3-check-server-changes}

如果这影响所有用户：
- WordPress盐值/密钥可能已更改
- JWT插件设置可能已被修改
- 联系您的服务器管理员

### 4. 清除存储的数据 {#4-clear-stored-data}

如果问题仍然存在，请先完成下方检查：

:::warning 请先检查是否有未保存的工作
清除本地数据或重新安装应用会删除此设备上尚未同步到店铺的所有内容，包括离线期间的销售记录、未完成的购物车以及未保存的编辑。清除任何内容前，请打开 **店铺健康 → 数据库**，确认没有记录显示为暂存或从未到达服务器；然后打开 **店铺健康 → 日志**，确认有 **0 条卡住的记录**和 **0 项等待发送的更改**；接着完成或记录每个未完成的购物车。如果 WCPOS 中没有“店铺健康”页面，请先更新 WCPOS，然后再检查。如果有任何记录列出或正在等待，或者无法检查，请勿清除数据——请咨询店铺所有者或联系支持人员。
:::

- 清除POS应用程序数据
- 删除缓存的凭据
- 从干净的登录开始
