## 这意味着什么 {#what-this-means}

店铺拒绝了发送给它的值。

店铺给出的原因会指出有问题的值。请在输入该值的位置进行修正，然后重新保存。该值通常属于某条记录——商品、客户或订单——但此代码也可能由店铺拒绝的设置请求或登录请求引起；这种情况下，请在相应界面中修正该值。

## 您的数据 {#your-data}

不要清除此设备上的数据——其中可能包含店铺尚未收到的更改。对现有商品、变体、客户或优惠券的编辑通常会自动撤销，并改为记录为 [SYNC202](/error-codes/SYNC202)。如果它显示为此代码，且更改列在 **店铺健康 → 数据库** 中，则表示自动撤销未能完成——请像处理其他列出的更改一样处理。设置请求或登录请求不会留下待保存的内容。

## 故障排查 {#troubleshoot}

1. 展开日志条目，查看店铺给出的原因和端点：原因会指出有问题的值，端点则会显示请求来自某条记录，还是来自设置请求或登录请求。
2. 请在输入该值的位置修正它——常见原因包括值超出范围、格式不被接受，或必填选项留空——然后重新保存。如果更改未列在 **店铺健康 → 数据库** 中，说明店铺中的版本已恢复，请使用修正后的值重新进行更改。如果修正后它仍列在 **店铺健康 → 数据库** 的 **"… 个更改未能到达您的服务器"** 下，请点击该行上的 **重新发送**。
3. 如果该记录改为列在 **"… 个更改已暂存"** 下，并标注 *"您的店铺要求使用当前版本"*，则没有值出错——请按照 [SYNC221](/error-codes/SYNC221) 中的说明，在 **重新发送** 和 **丢弃设备上的更改** 之间作出选择。
4. 如果这是设置请求或登录请求，请在输入该值的界面中修正并重新保存。**站点管理员：**如果 POS 日志中没有相关详情，可在浏览器的开发者工具（Network 选项卡）中查看店铺的响应；桌面应用中则可使用 **高级 → 切换开发者工具**。
5. **站点管理员：**如果 POS 中显示的某个值看起来正确，请在 WP Admin 中对照同一条记录——店铺上的插件可能添加了验证规则，从而拒绝 POS 认为有效的值。
