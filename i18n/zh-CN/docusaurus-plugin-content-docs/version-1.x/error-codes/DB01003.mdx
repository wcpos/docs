# DB01003: 交易失败 {#db01003-transaction-failed}

## 这意味着什么 {#what-this-means}

一个数据库事务未能完成。事务将多个操作组合在一起 — 如果任何部分失败，所有操作将回滚以维护数据完整性。

## 常见原因 {#common-causes}

- **并发访问** — 多个操作尝试修改相同数据
- **存储已满** — 没有空间写入新数据
- **数据库被锁定** — 另一个进程正在锁定数据库
- **电源中断** — 操作意外中断

## 如何修复 {#how-to-fix}

### 1. 重试该操作 {#1-retry-the-operation}

问题可能是暂时的：
- 等待片刻
- 再次尝试该操作
- 避免快速重复尝试

### 2. 检查冲突 {#2-check-for-conflicts}

如果多个设备或标签页打开：
- 一次使用一个实例
- 关闭重复的浏览器标签页
- 协调多设备使用

### 3. 检查存储空间 {#3-check-storage-space}

确保有数据存储空间：
- 检查可用磁盘空间
- 如有需要释放空间
- 在网页版中清除浏览器缓存（取消勾选“Cookie 和其他网站数据”——其中保存着 POS 的数据，包括尚未发送的内容）

### 4. 重启应用程序 {#4-restart-the-application}

重置数据库状态：
1. 完全关闭POS
2. 等待几秒钟
3. 重新打开应用程序

### 5. 清除并重新同步 {#5-clear-and-re-sync}

:::warning 请先检查是否有未保存的工作
清除本地数据或重新安装应用会删除此设备上尚未同步到店铺的所有内容，包括离线期间的销售记录、未完成的购物车以及未保存的编辑。清除任何内容前，请打开 **店铺健康 → 数据库**，确认没有记录显示为暂存或从未到达服务器；然后打开 **店铺健康 → 日志**，确认有 **0 条卡住的记录**和 **0 项等待发送的更改**；接着完成或记录每个未完成的购物车。如果 WCPOS 中没有“店铺健康”页面，请先更新 WCPOS，然后再检查。如果有任何记录列出或正在等待，或者无法检查，请勿清除数据——请咨询店铺所有者或联系支持人员。
:::

只有在本页其他步骤均无效、交易持续失败，且完成上述检查后，才执行以下操作：
1. 清除本地数据
2. 再次登录
3. 从服务器重新同步

## 交易安全 {#transaction-safety}

WCPOS 使用事务来确保：
- 数据一致性
- 完整操作（全部或无）
- 防止部分更新

当交易失败时，您的数据仍然保持一致。
