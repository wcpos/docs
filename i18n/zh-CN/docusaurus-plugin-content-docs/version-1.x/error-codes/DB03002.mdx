# DB03002: 无效的数据类型 {#db03002-invalid-data-type}

## 这意味着 {#what-this-means}

数据类型与数据库期望的类型不匹配。例如，在应填入数字的地方填入了文本。

## 常见原因 {#common-causes}

- **用户输入错误** — 在数字字段中输入文本
- **导入问题** — 导入的数据格式错误
- **数据损坏** — 在传输过程中值被损坏
- **插件冲突** — 其他插件修改了数据类型

## 如何修复 {#how-to-fix}

### 1. 检查输入 {#1-check-your-input}

审核您输入的数据：
- **价格** — 应为数字（例如，`19.99`）
- **数量** — 应为整数（例如，`5`）
- **ID** — 应为数字

### 2. 清除并重新输入 {#2-clear-and-re-enter}

如果数据被损坏：
- 清除字段
- 手动重新输入值
- 避免从外部来源复制粘贴

### 3. 检查源数据 {#3-check-source-data}

如果从 WooCommerce 同步：
- 检查 WordPress 管理中的数据
- 查找格式不正确的字段
- 在源头修复数据

### 4. 重新同步数据 {#4-re-sync-data}

:::warning 请先检查是否有未保存的工作
清除本地数据或重新安装应用会删除此设备上尚未同步到店铺的所有内容，包括离线期间完成的销售、未结购物车以及未保存的编辑。清除前，请打开 **店铺健康 → 数据库**，确认没有项目被列为暂存或从未同步到服务器；然后打开 **店铺健康 → 日志**，确认有 **0 条卡住的记录**和 **0 项等待发送的更改**；再完成或记录所有未结购物车。如果 WCPOS 中没有“店铺健康”页面，请先更新 WCPOS，然后再检查。如果有任何项目被列出或正在等待，或者您无法检查，请勿清除数据；请联系店铺所有者或支持团队。
:::

只有在本页其他步骤无效且完成上述检查后，才从服务器获取最新数据：
- 清除本地缓存
- 再次同步数据
- 检查问题是否解决

### 5. 检查插件冲突 {#5-check-for-plugin-conflicts}

如果使用其他 WooCommerce 插件：
- 它们可能以意想不到的方式修改数据
- 暂时禁用以进行测试
- 报告不兼容性

## 常见示例 {#common-examples}

| 字段 | 预期 | 无效 |
|-------|----------|---------|
| 价格 | `19.99` | `$19.99` |
| 数量 | `5` | `five` |
| SKU | `ABC123` | — （任何格式均可） |
| 产品 ID | `42` | `product-42` |
