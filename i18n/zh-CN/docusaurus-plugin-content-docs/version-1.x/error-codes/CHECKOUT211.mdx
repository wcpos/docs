## 这意味着什么 {#what-this-means}

商店没有返回结账结果，因此订单状态未知。

重试前请打开订单并检查其状态。如果订单已付款或已完成，请勿再次收费。响应为空通常表示订单已创建，但确认信息未能送达。

## 您的数据 {#your-data}

无法确认结果——重试前请先检查。如果问题持续出现，请在 **Logs** 标签页中使用 **Copy debug info**，并联系 WCPOS 支持团队。

## 故障排查 {#troubleshoot}

**在收银台：**

1. 在确认订单状态之前，请勿再次按 **Process Payment**，也不要再次向顾客收费。
2. 打开订单并检查其状态。使用 WCPOS Pro 时，请先刷新收银台的订单——打开 **Store health → Database**，点按 **Orders** 行中的 **⋮** 菜单，再选择 **Check for changes now**——然后在 **Orders** 中打开订单。没有 Pro 时，请让他人前往 WP Admin 中的 **WooCommerce → Orders** 打开订单，并按总金额和最近几分钟的时间范围搜索。
3. 找到订单还不够——订单可能已创建但尚未付款。如果订单状态为 **Processing** 或 **Completed**，说明销售已完成：请勿再次收费。
4. 如果订单仍未付款，或找不到订单，请检查顾客是否已付款——银行卡付款请查看支付服务提供商的界面、收据或控制面板；现金付款请检查钱箱和收取的金额。如果顾客已付款，请勿再次收费。如果已找到订单，请重新加载应用并再次检查订单状态（启动时，收银台会完成其已记录付款的销售）；如果找不到订单或仍未付款，请继续执行最后一步。
5. 如果订单尚未付款且支付服务提供商显示未扣款，请重试结账一次。
6. 如果仍无法确定，请在再次尝试前使用 **Logs** 标签页中的 **Copy debug info**，并联系支持团队。

**在店铺端** — 网站管理员：

1. 在 WooCommerce → 状态 → 日志中查看结账过程中的致命错误——订单创建之后发生的 PHP 崩溃正会导致这种情况。
2. 如果 WooCommerce 日志中没有记录，请向托管服务提供商索取服务器的 PHP 错误日志 — 有些致命错误只会记录在那里。

**开发人员：**在浏览器开发者工具中 — 或在桌面应用中选择**高级 → 切换开发者工具** — 如果网络选项卡中的结账请求状态成功，但响应正文为空或被截断，则可能是插件或服务器缓冲区截断了响应。
