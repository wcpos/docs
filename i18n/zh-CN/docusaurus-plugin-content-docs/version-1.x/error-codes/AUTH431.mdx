## 这意味着什么 {#what-this-means}

店铺的 REST API 未在此应用可使用的任何地址形式上响应。

此应用尝试通过店铺的常规地址（/wp-json/...）以及 WordPress 的内置备用地址（/?rest_route=...）访问 REST API，但两者均未响应。店铺网站本身可能仍可正常访问——此问题特指 REST API 无法访问，通常是安全插件将其隐藏，或防火墙规则将其阻止。

## 处理方法 {#what-to-do}

导出诊断信息并联系支持团队。完成上述更改后重试；未进行更改直接重试仍会以相同方式失败。

## 数据影响 {#your-data}

不会影响任何订单或产品数据。

## 故障排除 {#troubleshoot}

1. 如果安全插件隐藏或重命名了 /wp-json/（例如 WP Hide），也请允许使用 WordPress 内置的 /?rest_route= 形式——应用会自动回退到该形式。
2. 检查防火墙（WAF）规则中是否有匹配 wp-json 或 rest_route 的规则，并允许店铺自身的 REST API 通过。
3. 在浏览器中测试：https://your-store.com/?rest_route=/ 应返回 JSON，而不是 403 页面或网站主页。
4. 如果服务器受到维护页面或机器人验证机制保护，REST 请求可能会收到 HTML 页面——请为 REST API 禁用该验证机制。

## 查看位置 {#where-to-look}

当 WCPOS 能够保存此错误时，错误会记录在触发该错误的设备上。打开 **店铺运行状况 → 日志**（导航抽屉底部的心率图标），找到标有此代码的条目并将其展开：展开后的行会显示通俗易懂的原因，以及故障发生时捕获的上下文。对于店铺请求，该上下文可能包含服务器自身的错误代码 (`serverCode`)、HTTP `status` 或 `endpoint`；显示哪些字段取决于故障发生的位置。报告问题时，请使用“日志”页面顶部的 **复制调试信息**（手机和平板电脑上为 **分享调试信息**），而非截图：该信息会打包应用版本、连接状态和最近的错误。日志最多保留 30 天，因此请在问题刚出现时收集。还请复制 POS 能够写入自身日志条目前在浏览器控制台中出现的任何错误。
