## 这意味着什么 {#what-this-means}

您的 WCPOS Pro 许可证未在此商店或此设备上激活。

请检查本地、许可证服务器和更新程序的状态，然后为指定的商店激活许可证。

## 该怎么做 {#what-to-do}

需要先更改设置，此功能才能正常工作。请在完成上述更改后再重试；不做更改就重试同样会失败。

## 您的数据 {#your-data}

订单和产品数据不受影响。如果问题持续存在，请导出诊断信息并联系 WCPOS 支持团队。

## 故障排查 {#troubleshoot}

1. 在 WP Admin 的 POS 设置中查看许可证状态——它应显示对本商店的确切 URL 处于激活状态。
2. 网站 URL 的变更（http 改为 https、添加或去掉 www、域名迁移、暂存副本）会使许可证对新地址失效——请为当前地址重新激活。
3. 如果许可证显示为已激活但 POS 不认可，请停用后再重新激活一次，然后重新加载收银机。
4. 仍然处于锁定状态？请导出调试信息，并携带您的许可证编号联系支持团队。

## 在哪里查看 {#where-to-look}

当 WCPOS 能够保存此错误时，它会被记录在触发该错误的设备上。打开 **商店健康 → 日志**（导航抽屉底部的心跳图标），找到标有此代码的条目并展开：展开后的行会显示通俗易懂的原因，以及故障发生时捕获的上下文。对于商店请求，该上下文可能包含服务器自身的错误代码（`serverCode`）、HTTP `status` 或 `endpoint`；具体显示哪些字段取决于故障发生的位置。上报问题时，请使用日志页面顶部的 **复制调试信息**（在手机和平板上为 **分享调试信息**），而不要使用截图：它会打包应用版本、连接状态和最近的错误。日志最多保留 30 天，因此请趁问题还新鲜时收集。此外，也请复制在 POS 能够写入自身日志条目之前出现的任何浏览器控制台错误。

除应用内日志外，此故障还可能在以下位置留下线索：

- **服务器端 POS 日志**：在 WP Admin 中打开 **POS → 设置 → 工具 → 日志**。此页面记录在服务器端产生的 POS 相关警告和错误，这些内容可能永远不会出现在应用内。菜单上的红色标记表示有未读的服务器端错误。
