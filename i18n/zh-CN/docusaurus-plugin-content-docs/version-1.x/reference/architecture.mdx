本页面向开发人员和高级用户介绍 WCPOS 的技术架构。

## 双部分系统 {#two-part-system}

WCPOS 的系统设计由两部分组成：

1. **PHP 插件：** 托管在您的服务器上，是一个体积较小的插件，为 [WooCommerce REST API](/1.x/reference/wc-rest-api) 添加 POS 专用端点。

2. **JavaScript 客户端：** 在您的浏览器、桌面应用或 iOS/Android 应用中本地运行。

您可以将其视为两个独立的世界：

- _PHP 世界_使用 WordPress 和 WooCommerce 进行数据管理。
- _JavaScript 世界_保存收银机所需店铺数据的本地副本，支持离线使用，并针对快速搜索和即时响应进行优化。

## 数据同步 {#data-synchronization}

:::info v1.10.0 中的变更
v1.10.0 以专用的**同步引擎**取代了之前的复制层。下文是简要概述，完整说明请参阅[同步引擎的工作原理](/1.x/reference/sync-engine)。
:::

客户端采用本地优先设计：每个界面都读写设备的本地数据库，后台同步引擎则让该数据库与 WooCommerce 的数据逐步保持一致。引擎**不会**盲目镜像整个店铺，而是根据界面的实际需求工作：

- **变更检测：** POS 使用条件请求轮询轻量的变更日志；空闲店铺只需返回一个无响应体的 `304`。
- **声明式需求：** 界面声明正在展示的内容，引擎据此判断是否需要发起请求，或本地数据是否已能满足需求。
- **预填充与通道：** 有限范围的产品目录预填充、近期订单窗口及空闲时段维护通道，会按计划填充并校验本地数据；您可为每台设备调整这些计划。
- **持久化写入：** 销售和编辑操作先在本地排队，再逐步发送到 WooCommerce；服务器拒绝的操作会显示出来，并提供恢复方式。

同步内容包括：产品和变体、类别/标签/品牌、客户、税率、优惠券（Pro）和订单。支付网关在结账时获取。

## 架构优缺点 {#architecture-pros-and-cons}

| 优点 😊 | 缺点 😟 |
| ------------------------------------------------------------------ | -------------------------------------------------------- |
| 搜索本地数据可即时完成 | 保持数据同步具有挑战性 |
| 缓存数据可离线使用 | 受限于 WooCommerce REST API |
| 能够为桌面、iOS 和 Android 创建更好的原生应用 | WordPress 主题和钩子无法自定义 POS 应用 |

## 本地数据库 {#local-database}

客户端将数据存储在每台设备的本地数据库中。网页应用和桌面应用使用**在 worker 中运行的 OPFS（源私有文件系统）存储**，移动应用则通过文件系统引擎使用相同的磁盘格式。所有平台共用同一种存储格式和恢复工具，从而提供：

- **持久性：** 浏览器重启和设备重启后数据仍然保留
- **性能：** 查询快速且无网络延迟；筛选、排序和分页在存储层内部执行，因此只有当前可见页的数据行会传递到界面
- **离线浏览：** 无需联网即可继续访问缓存数据

每个站点 + 店铺 + 收银员组合都有独立的本地数据库，因此同一设备上的不同收银员和店铺不会共享本地数据。升级时不会就地迁移本地数据库，而是由应用从服务器重新下载；服务器上的副本始终是权威数据源。

## 结账架构 {#checkout-architecture}

结账过程使用 iframe/webview 加载 WooCommerce 订单支付页面。这种方式：

- **利用现有支付网关：** 任何 WooCommerce 支付网关都可在 POS 中使用
- **保持安全性：** 支付处理通过 WooCommerce 的安全基础设施进行
- **降低复杂性：** 无需重新实现支付网关集成

## API 扩展 {#api-extensions}

PHP 插件为 WooCommerce REST API 添加 POS 专用功能端点，并将其注册在专用的 `wcpos/v1` 和 `wcpos/v2` 命名空间下。`wcpos/v2` 承载 v1.10.0 的同步接口，因此应用与插件版本需要同步发布。入门介绍请参阅 [WooCommerce REST API](/1.x/reference/wc-rest-api)。

### `wcpos/v2` 命名空间 {#wcpos-v2-namespace}

v1.10 引入了 `wcpos/v2` REST 命名空间。同步功能位于此处，之前由 `wcpos/v1` 提供的共享 POS 服务现在也由 `wcpos/v2` 提供（`wcpos/v1` 服务路由会直接转交给对应的 v2 实现）。为保持向后兼容，`wcpos/v1` 路由仍会注册，但已**冻结**，当前客户端不再调用这些路由。

如果您要与这些端点集成，请注意以下几点：

- **v2 路由始终注册。** 旧的 `woocommerce_pos_sync_api_enabled` 选项已移除，不再提供启用或禁用此 API 的开关。
- **公开端点。** `wcpos/v2/site`、`wcpos/v2/ping` 和 `wcpos/v2/echo` 均为公开端点，用于功能和连通性探测，包括针对受限主机的[传输回退](/1.x/error-codes)。
- **订单以 UUID 为主键。** 传输时使用 UUID 标识订单；旧的 `wooOrderId` 字段已从订单拉取数据封装中移除。订单元数据通过统一的规范化器转换为带类型的传输数据。
- **商品行定价的存储方式已有文档说明**，以支持第三方同步兼容。请参阅 [POS 价格覆盖的存储方式](/1.x/reference/pos-discounts#how-pos-price-overrides-are-stored)。
- POS 中的**默认产品排序**现为**按名称升序**（之前为 `menu_order, id`）。
- **已移除旧版方法。** 多个旧版 `API\Settings` 控制器方法（例如 `get_general_settings()`、`update_access_settings()`、`get_general_endpoint_args()`、`remove_license_transient()`）已移除；类的别名仍保留，但这些方法已不存在。

:::note Pro 也遵循此拆分
WCPOS Pro 遵循相同的 V1/V2 拆分：共享服务升级到 `wcpos/v2`，而订单数据仍冻结在 v1。店铺范围内的产品定价通过 v2 通道处理，写入订单时会同时带上收银机所属的店铺范围，以便多店铺订单按正确的店铺定价和计税。请参阅 [Pro](/1.x/getting-started/free-vs-pro)。
:::
