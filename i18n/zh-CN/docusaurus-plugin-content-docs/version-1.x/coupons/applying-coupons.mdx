:::info 专业版功能
在收银台应用优惠券需要 [WCPOS Pro](/1.x/getting-started/pro-license)。免费用户可以看到[优惠券](/1.x/coupons)界面的模糊预览，但购物车中的 **添加优惠券** 操作已禁用。
:::

本页介绍收银台工作流程——查找优惠券、应用优惠券、叠加多张优惠券以及处理错误。有关优惠券类型、设置和验证规则，请参阅[优惠券](/1.x/coupons)；有关收银员临时创建的折扣，请参阅[购物车折扣](/1.x/pos/cart/discounts)。

## 添加优惠券流程 {#the-add-coupon-flow}

购物车商品列表下方有一个 **添加优惠券** 按钮。点击后会打开一个小型输入框，可以输入优惠码或进行搜索。

1. 在购物车中点击 **添加优惠券**
2. 开始输入——输入框同时支持搜索所有已同步的优惠券（包括优惠码和描述）
3. 从建议列表中选择优惠券，或输入完整优惠码后按 **Enter**

优惠券会根据本地同步的数据即时验证，无需向服务器发送请求，折扣随即体现在购物车总额中。如果之后更改购物车内容（添加商品、修改数量、更换客户），折扣会自动重新计算。

{/* Screenshot: cart-add-coupon-search.png */}

:::tip 输入优惠码与搜索
知道优惠码（例如“SUMMER10”）的收银员可以直接输入并按 Enter，这是最快的方式。搜索功能适用于顾客递交打印的优惠券而员工不记得确切优惠码的情况，也适用于按客户姓名查找会员折扣。
:::

## 购物车中的优惠券标签 {#coupon-pills-in-the-cart}

每张已应用的优惠券都会在购物车中显示为一个小 **标签**，位于总额上方。标签会显示优惠券的描述（未设置描述时显示优惠码）以及折扣金额。点击标签上的 **×** 即可移除该优惠券，购物车总额会立即重新计算。

{/* Screenshot: cart-coupon-pills.png */}

应用多张优惠券时，标签会垂直堆叠。显示顺序即添加顺序——而该顺序对[顺序折扣](#sequential-discounts)很重要。

:::note 收据标签
标签文字也会打印在收据上。如果您希望使用比原始优惠码更清晰的标签（例如 *“忠诚折扣”* 而非 *“LOYAL10”*），请在 `WP Admin → Marketing → Coupons` 中设置该优惠券的 **描述** 字段。只要设置了描述，WCPOS 就会将其用作折扣标签。
:::

## 顺序折扣 {#sequential-discounts}

可以对一个订单应用多张优惠券。WooCommerce 会 **按顺序** 计算——每张优惠券都基于前一张优惠券折扣后的剩余小计计算折扣，而非原始购物车总额。

### 计算示例 {#worked-example}

购物车小计：**$100.00**

| 步骤 | 优惠券 | 计算方式 | 累计总额 |
|---|---|---|---|
| 1 | `LOYAL10`（优惠 10%） | $100 × 0.90 | **$90.00** |
| 2 | `WELCOME5`（购物车减 $5） | $90 − $5 | **$85.00** |
| 3 | `EXTRA20`（优惠 20%） | $85 × 0.80 | **$68.00** |

优惠券的应用顺序会影响最终金额。两张 10% 优惠券叠加后，相对于原价的优惠幅度是 19%（而不是 20%），因为第二张 10% 优惠券是按已折扣的总额计算的。

### 优惠券无法叠加的情况 {#when-coupons-cant-stack}

在 WooCommerce 中设置为 **仅限单独使用** 的优惠券不能与任何其他优惠券同时使用。如果 `SUMMER25` 仅限单独使用：

- 先应用 `SUMMER25` → 添加任何其他优惠券时将显示 *“此优惠券不能与其他优惠券同时使用。”*
- 先应用其他优惠券 → 添加 `SUMMER25` 时将显示相同的提示信息。

移除冲突的优惠券后即可应用另一张。

### 固定商品优惠券 {#fixed-product-coupons}

**固定商品折扣** 优惠券（例如 *每件 T 恤减 $2*）仅对匹配的行项目打折，不会减少其他优惠券所依据的小计金额。将其与百分比购物车优惠券叠加使用是安全且可预测的。

## 移除优惠券 {#removing-a-coupon}

- 点击优惠券标签上的 **×** 即可移除该张优惠券。
- 清空购物车（**更多** 菜单 → *清空购物车*）会移除所有已应用的优惠券。
- 移除某个行项目时，如果它是某张限定商品优惠券 *唯一* 符合条件的商品，系统会自动移除该优惠券，并显示简短提示：“优惠券已移除：没有符合条件的商品”。

## 验证错误及解决方法 {#validation-errors-and-how-to-resolve-them}

POS 与 WooCommerce 使用相同的验证规则，完整列表请参阅[验证机制](/1.x/coupons#how-validation-works)。当优惠券被拒绝时，收银员会看到具体的提示信息：

| 提示信息 | 含义 | 解决方法 |
|---|---|---|
| *“优惠券不存在”* | 在已同步的数据中未找到该优惠码。 | 检查拼写。如果优惠券刚在 WP Admin 中创建，请在[优惠券](/1.x/coupons)界面执行同步（长按同步图标选择 **清除并刷新**）。 |
| *“此优惠券已过期”* | 今天的日期已超过优惠券的到期日。 | 在 WP Admin 中延长到期日，或使用其他优惠码。 |
| *“使用次数已达上限”* | 该优惠券的总使用次数已用尽。 | 在 WP Admin 中提高使用上限，或使用其他优惠码。 |
| *“该客户已使用过此优惠券”* | 所选客户已超过每用户使用次数限制。 | 更换客户，或提高每用户使用次数限制。 |
| *“未达到最低消费金额”* | 购物车小计低于优惠券的最低消费要求。 | 添加更多商品或使用其他优惠码。 |
| *“超出最高消费金额”* | 购物车小计高于优惠券的最高消费限制。 | 拆分为多个订单或使用其他优惠码。 |
| *“此优惠券不能与其他优惠券同时使用”* | 新优惠券或已应用的优惠券被设置为 **仅限单独使用**。 | 移除冲突的优惠券，然后应用所需的优惠券。 |
| *“优惠券不适用于购物车中的商品”* | 购物车中没有商品符合优惠券的商品或分类限制。 | 添加符合条件的商品，或选择其他优惠券。 |
| *“优惠券不适用于此客户”* | 所选客户的电子邮件地址与优惠券的 **允许的邮箱** 规则不匹配。 | 更换为邮箱匹配的客户，或移除邮箱限制。 |

如果优惠券在本地验证通过，但订单在结账时被拒绝，说明服务器使用更新的数据重新执行了验证。通常是因为同一班次内的另一笔交易使使用次数达到了上限。请重新应用或选择其他优惠券。

## 常见工作流程 {#common-workflows}

<Accordion>
  <AccordionItem question="经理折扣——使用可追踪优惠码的临时 10% 折扣">

在 `WP Admin → Marketing → Coupons` 中创建一张优惠券，例如命名为 `MGR10`：
- **折扣类型：** 百分比折扣
- **优惠券金额：** 10
- **每张优惠券的使用次数限制：** *（留空——无限制）*
- **仅限单独使用：** 关闭（以便与会员或促销优惠码叠加使用）
- **描述：** *“经理折扣”*（此内容会打印在收据上）

仅与经理共享此优惠码。该优惠券会在 WooCommerce 报表中显示为可追踪的折扣，而 [POS 价格覆盖](/1.x/pos/cart/discounts)目前仅降低行项目价格。

  </AccordionItem>

  <AccordionItem question="忠诚奖励——回头客减 $5">

创建 `LOYAL5`：
- **折扣类型：** 固定购物车折扣
- **优惠券金额：** 5
- **最低消费：** 25 *（或您设定的其他门槛金额）*
- **每位用户的使用次数限制：** 1 *（如果奖励仅限一次）*
- **描述：** *“忠诚奖励”*

在收银台搜索“忠诚”即可找到该优惠券，无需记住优惠码。

  </AccordionItem>

  <AccordionItem question="一次性促销——传单或印刷品推广活动">

为每个活动创建一张优惠券。如果是单次兑换传单，请设置 **每张优惠券的使用次数限制：1**；如果是可多次使用的促销活动，则设为更高数值。将 **到期日期** 设在较近的日期，以免之后误用该优惠码。

对于每位客户只能兑换一次的多次使用促销活动，需同时设置 **每张优惠券的使用次数限制** *以及* **每位用户的使用次数限制：1**。

  </AccordionItem>

  <AccordionItem question="在顾客自带的优惠码基础上叠加经理折扣">

先应用顾客的优惠码，再应用经理优惠码。WooCommerce 会按顺序处理，经理折扣基于已折扣的总额计算，这通常符合顾客的预期。

如果顾客的优惠券设置为 **仅限单独使用**，经理优惠码会被拒绝。可以先移除顾客的优惠券（需要时再重新应用），或在 WP Admin 中修改顾客的优惠券，允许叠加使用。

  </AccordionItem>

  <AccordionItem question="顾客想退回订单中的部分商品，并用其他优惠券重新结算">

先对原订单进行退款（参见[退款](/1.x/orders/refunds)），然后使用新优惠券开始一笔新的销售。优惠券在销售时与订单绑定，无法在 POS 中为已完成的订单更换优惠券。退款会恢复该优惠券的可用次数，以便在新订单中再次使用。

  </AccordionItem>
</Accordion>

## 与 POS 价格调整的交互 {#interaction-with-pos-price-changes}

如果收银员在收银台降低了某个行项目的价格（即 [POS 价格覆盖](/1.x/pos/cart/discounts)），然后应用优惠券，优惠券会基于 **降低后的价格** 计算，而非原价。POS 中降价的行项目会被视为“特价商品”，因此启用了 **排除特价商品** 的优惠券会跳过这些商品。

这是有意设计的，可防止收银员折扣和优惠券都基于原价计算，让顾客获得双重折扣。完整机制请参阅 [POS 价格调整与优惠券的交互方式](/1.x/pos/cart/discounts#how-pos-price-changes-interact-with-coupons)。

## 离线行为 {#offline-behaviour}

- **应用优惠券支持离线使用**——验证基于本地同步的优惠券数据进行。
- 使用支持离线的付款方式，**也可以离线完成销售**。订单会在本地排队；待订单到达 WooCommerce 后，服务器会重新验证优惠券并更新其使用次数。
- **刚在 WP Admin 中创建的优惠券** 在下次同步之前无法在收银台使用。在 [优惠券](/1.x/coupons) 页面底部，点击同步图标（<Icon name="arrow-rotate-right" />）——长按可选择**清除并刷新**以获取最新数据。
