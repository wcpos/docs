POS 提供两个日志界面：**应用内活动日志**（位于 POS 应用内）和 **WP Admin 日志页面**（位于 WordPress 内）。结合两者，您可以全面了解 POS 活动，以便调试和审计。

## POS 应用程序日志 {#pos-application-logs}

:::info v1.10.0 中的变更
从 v1.10.0 起，应用内日志位于 **商店健康 → 日志**（导航抽屉中的心跳图标），原先独立的日志页面已移除。本节介绍 v1.10.0 的日志；如需全面了解该区域，请参阅[商店健康](/1.x/support/store-health#logs)。
:::

### 访问日志 {#accessing-logs}

从左侧导航抽屉打开 **商店健康**（心跳图标），然后选择 **日志** 选项卡。

### 界面概述 {#interface-overview}

日志记录此设备上的活动，保留 30 天。每行显示以下信息：

| 列 | 描述 |
|--------|-------------|
| **时间** | 事件发生的时间 |
| **级别** | 严重程度：错误、警告、操作、同步或信息 |
| **事件** | 便于理解的描述（在显示时翻译） |
| **耗时** | 操作所花费的时间 |
| **状态** | 操作结果 |

日志列表上方的状态行显示同步心跳，即上次检查变更的时间和下次预定检查时间。统计栏则显示今天的事件数、错误数、卡住的记录数以及待发送的更改数。其中大多数项目都可点击，用作筛选条件。

#### 筛选 {#filtering}

预设标签可用于筛选日志：**全部**、**操作**（人为执行的操作，如销售、编辑和设置更改）、**错误** 和 **同步**。另有一个 **详细诊断** 开关，可在 24 小时内记录更多详细信息，之后会自动关闭。

### 行详情与错误代码 {#row-details}

点击错误或警告行即可展开。详情视图提供以下信息：

- **发生了什么**，用通俗语言说明
- **您的数据** — 明确的数据安全说明，例如更改是否已安全保存在服务器上，还是仅存在于此设备上
- **该怎么做** — 建议的下一步操作
- **一个帮助链接** — 错误附有代码（例如 `SYNC121`、`AUTH311`），链接到[错误代码](/1.x/error-codes)文档
- **一个可复制的事件代码** — 行标题会在显示时翻译，而事件代码是固定不变的标识符。联系支持时请提供该代码。

## WP Admin 日志页面 {#wp-admin-logs-page}

POS 插件还在 WordPress 管理后台提供服务器端日志页面。该页面显示服务器上记录的 POS 相关警告和错误，有助于诊断 POS 应用本身可能未显示的问题。

### 访问 WP Admin 日志页面 {#accessing-the-wp-admin-logs-page}

前往 **WP Admin > POS > 设置**，然后选择 **工具** 选项卡并点击 **日志**。

### 未读徽章 {#unread-badge}

日志菜单项会显示徽章，提示有未读日志条目：

- **红色徽章** - 有未读的错误级别条目
- **琥珀色徽章** - 有未读的警告级别条目，但没有错误

访问日志页面会重置未读计数。计数按用户分别记录，因此每位管理员看到的都是自己的未读状态。

### 筛选条目 {#filtering-entries}

使用级别筛选器缩小日志条目的范围：

- **全部** - 显示所有日志条目
- **错误** - 仅显示错误级别条目
- **警告** - 仅显示警告级别条目

### 可展开条目 {#expandable-entries}

较长的日志消息会在约 100 个字符处截断。点击条目即可展开，查看完整消息及附加的上下文数据。

### 分页 {#pagination}

日志条目在服务器端分页。使用分页控件浏览较早的条目。

### 致命错误横幅 {#fatal-errors-banner}

如果服务器上存在 `fatal-errors-*.log` 文件，日志页面顶部会显示警告横幅。该横幅链接到 **WooCommerce > 状态 > 日志**，您可以在那里查看完整的致命错误日志。致命错误通常是导致 POS API 无法响应的 PHP 级崩溃。

## 使用日志请求支持 {#using-logs-for-support}

请求支持时：

1. **重现问题** - 执行导致问题的操作
2. **检查日志** - 在 **商店健康 → 日志** 中查找错误或警告
3. **展开该行** - 阅读数据安全说明及建议的下一步操作
4. **复制事件代码** - 将其附在支持请求中；它是标识所发生事件的固定代码
5. 如果支持人员需要更多详细信息，请 **开启详细诊断**，它会在 24 小时内记录额外信息

## 性能监控 {#performance-monitoring}

汇总性能数据位于 **商店健康 → 性能**，包括过去 24 小时内的请求数、数据传输量（当响应未包含大小信息时，该值为下限）和典型响应时间，以及按小时显示的正常运行状态条。如果响应时间偏高，请参阅[服务器性能](/1.x/support/performance/server)。
