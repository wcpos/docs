插件冲突是 WCPOS 出现问题的最常见原因之一。当其他 WordPress 插件干扰 WooCommerce 或 WCPOS 的功能时，您可能会遇到崩溃、性能问题或意外行为。

## 插件冲突的迹象 {#signs-of-plugin-conflicts}

如果您遇到以下情况，可能存在插件冲突：

- **致命错误** - “该网站出现了严重错误”
- **性能问题** - 加载缓慢、超时或服务器负载过高
- **功能问题** - 功能未按预期工作
- **数据同步问题** - 产品、订单或客户无法正常同步
- **支付网关问题** - 结账失败或支付处理错误

## 开始之前：使用暂存网站 {#before-you-start-use-a-staging-site}

:::warning 重要
**切勿在生产网站上排查插件冲突。** 请始终使用暂存环境，以免影响业务运营。
:::

### 什么是暂存网站？ {#what-is-a-staging-site}

暂存网站是生产网站的完整副本，您可以在其中安全地测试更改，而不影响客户。如今，大多数主机服务商都将暂存环境作为标准功能提供。

### 如果您的主机服务商不提供暂存环境 {#if-your-host-doesnt-offer-staging}

如果您的主机服务商不提供暂存网站，**请考虑更换为提供此功能的服务商**。如今这已是一项标准功能，对以下工作至关重要：

- 安全地测试插件/主题
- 更新 WordPress
- 排查问题
- 开发工作

**推荐的提供暂存功能的主机服务商：**
- WP Engine
- SiteGround  
- Kinsta
- Cloudways
- 以及许多其他服务商

## 第 1 步：检查致命错误 {#step-1-check-for-fatal-errors}

如果您遇到崩溃或严重错误，请先检查错误日志：

1. **检查 WCPOS 日志** - 在 WCPOS 中打开[**店铺健康 → 日志**](/1.x/support/logs)，查找错误消息
2. **检查致命错误日志** - 按照[致命错误故障排除指南](/1.x/support/troubleshooting/critical-error)查找详细的错误消息
3. **记录错误详情** - 查找错误中提到的插件名称或文件路径

如果致命错误中提到了某个插件，它很可能就是问题的根源。您可以禁用该插件，然后测试问题是否已解决。

## 第 2 步：插件排除法 {#step-2-the-plugin-elimination-method}

如果日志中没有致命错误，或者您想查找影响性能的插件冲突，请按以下步骤逐一排查：

### 2.1 创建基线 {#21-create-a-baseline}

1. **访问您的暂存网站**
2. **测试有问题的功能** - 准确记录哪些功能无法工作或运行缓慢
3. **记录性能指标** - 如果是性能问题，请记录[日志](/1.x/support/logs)中的执行时间

### 2.2 禁用所有插件（必要插件除外） {#22-disable-all-plugins-except-essential-ones}

**保持以下插件处于启用状态：**
- WooCommerce
- WCPOS
- WCPOS Pro（如果您已安装）

**禁用其他所有插件：**
1. 转到 `WP Admin > 插件`
2. 选择所有其他插件
3. 在批量操作下拉菜单中选择“停用”
4. 点击“应用”

### 2.3 测试问题是否仍然存在 {#23-test-the-issue}

1. **清除缓存** - 如果您使用了缓存插件，请清除所有缓存
2. **测试有问题的功能** - 现在能正常工作了吗？
3. **检查性能** - 执行时间是否缩短？

**如果问题已解决：** 说明存在插件冲突。请继续第 2.4 步。

**如果问题仍然存在：** 问题可能并非由插件冲突引起。请考虑以下原因：
- 服务器资源问题（请参阅[服务器性能](/1.x/support/performance/server)）
- 主题冲突（参见第 3 步）
- WordPress/WooCommerce 核心问题

### 2.4 逐个启用插件 {#24-enable-plugins-one-by-one}

接下来需要确定是哪个插件导致了冲突：

1. **启用一个插件** - 从最重要的插件开始
2. **测试功能** - 检查问题是否重现
3. **如果没有问题** - 启用下一个插件并再次测试
4. **如果问题重现** - 您已找到发生冲突的插件！

**插件优先顺序（请按此顺序启用）：**
1. **安全插件** - Wordfence、Sucuri 等
2. **SEO 插件** - Yoast、RankMath 等  
3. **性能插件** - 缓存、优化类插件
4. **支付网关** - Stripe、PayPal 等
5. **其他 WooCommerce 扩展**
6. **常规 WordPress 插件**

### 2.5 记录排查结果 {#25-document-your-findings}

找到发生冲突的插件后：

1. **记录插件名称和版本**
2. **记录它引起的具体问题**
3. **检查是否有可用的更新版本**
4. **寻找提供类似功能的替代插件**

## 第 3 步：检查主题冲突 {#step-3-check-for-theme-conflicts}

主题很少影响 WCPOS，因为 WCPOS 使用自己的界面，但主题有时仍会影响以下方面：

- 结账流程（使用网页结账网关时）
- 后台功能
- API 响应

### 使用默认主题进行测试 {#test-with-a-default-theme}

1. **在您的暂存网站上**，切换到默认的 WordPress 主题：
   - Twenty Twenty-Four
   - Twenty Twenty-Three
   - Twenty Twenty-Two
2. **测试有问题的功能**
3. **如果问题已解决** - 说明您的主题存在冲突

:::info 主题的影响
与插件相比，主题导致 WCPOS 问题的可能性要小得多。POS 界面独立于主题运行。不过，主题仍可能影响以下方面：
- WooCommerce 结账页面
- WordPress 后台功能
- REST API 响应
:::

## 第 4 步：解决插件冲突 {#step-4-resolving-plugin-conflicts}

确定发生冲突的插件后，您可以选择以下几种解决方式：

### 选项 1：更新插件 {#option-1-update-the-plugin}

1. **检查更新** - 新版本可能已修复该冲突
2. 先在暂存网站上**更新插件**
3. 在生产网站上更新之前，先**进行彻底测试**

### 选项 2：寻找替代插件 {#option-2-find-an-alternative}

1. **研究替代插件**，寻找提供相同功能的插件
2. 在暂存网站上**测试替代插件**
3. 如果更换插件，请**迁移设置**

### 选项 3：联系插件开发者 {#option-3-contact-plugin-developer}

1. 向插件开发者**报告冲突**
2. **提供详细信息：**
   - 涉及的插件版本
   - WordPress 和 WooCommerce 版本
   - 准确的错误消息或具体异常表现
   - 重现问题的步骤

### 选项 4：定制解决方案 {#option-4-custom-solution}

对于无法替代的必要插件：

1. **联系 WordPress 开发者**，制定专门的修复方案
2. **考虑使用该插件的专用钩子**，禁用发生冲突的功能
3. **使用条件逻辑**，在 POS 相关页面上禁用该插件

## 常见的冲突插件类型 {#common-conflicting-plugin-types}

### 高风险插件类别 {#high-risk-plugin-categories}

**安全插件：**
- 可能阻止 API 请求
- 可能干扰身份验证
- 通常具有过于严格的防火墙规则

**缓存插件：**
- 可能不恰当地缓存 API 响应
- 可能干扰实时数据
- 可能导致数据过期问题

**SEO 插件：**
- 资源占用较高的插件可能拖慢后台速度
- 可能增加不必要的数据库查询
- 可能干扰 REST API 响应

**页面构建器：**
- 通常会在后台加载资源占用较高的脚本
- 可能与 WooCommerce 后台页面冲突
- 可能干扰结账流程

**会员/访问限制插件：**
- 可能阻止 API 访问
- 可能干扰用户身份验证
- 可能限制对必要资源的访问

### 低风险插件类别 {#lower-risk-plugin-categories}

**联系表单：** 通常不会干扰 WCPOS
**社交媒体插件：** 很少引起冲突
**分析插件：** 通常不会引起问题，除非资源占用非常高
**基本内容插件：** 通常兼容
**WooCommerce Tax（通过 TaxJar 自动计算税费）：** 受支持。保存未结 POS 订单时，WCPOS 会向其请求税率，因此 POS 订单与在线订单使用相同的自动税率。请参阅 [WooCommerce Tax](/1.x/integrations/woocommerce-tax)。

## 已知插件冲突 {#known-plugin-conflicts}

以下插件已知会干扰 WCPOS。许多问题已在近期的 WCPOS 版本中自动修复，**更新到最新版本**即可解决这些问题，无需任何配置。

:::tip 大多数修复方法都是“排除 POS”
这些问题有一个共同点：WCPOS 依赖 WooCommerce REST API，并在 iframe 中显示部分流程（登录、支付、收据）。通常的修复方法是在其他插件中**排除 POS 端点/URL**（`/wp-json/wcpos/`、`/wp-json/wc/v3/` 和 `/pos/` 路径），而非完全禁用该插件。
:::

### 安全与登录插件 {#security-and-login-plugins}

这类插件是**最常见**的冲突来源，尤其容易影响桌面/移动应用登录。

| 插件 | 症状 | 修复方法 |
| --- | --- | --- |
| **Wordfence** | 防火墙阻止 REST API；登录 iframe 中无法显示 2FA 验证码字段；严格的 CSP 可能阻止加载 POS 资源 | 在防火墙中将 `/wp-json/wcpos/` 和 `/wp-json/wc/v3/` 加入白名单。对于 2FA，请暂时为 POS 用户禁用此功能。v1.9.0+ 会自动移除 CSP |
| **Really Simple Security** | 阻止 API 访问 / 强制重定向 | 在插件的 **高级** 设置中禁用所有 REST API 限制 |
| **WPS Hide Login** | 自定义登录 URL 导致应用的登录 iframe 无法正常工作 | 使用标准的 `/wp-admin/` 登录 URL 访问 POS |
| **iThemes / Solid Security** | 阻止 REST API，或因 POS 调用而触发防暴力破解锁定 | 仅将 POS 端点和服务器自身的 IP 加入白名单，避免设置过于宽泛的 IP 规则 |
| **Sucuri** | WAF 阻止 API 请求 | 在 Sucuri 仪表板中将 REST API 端点加入白名单 |
| **Security Optimizer** | 阻止管理员登录 POS（_“使用自定义登录 URL”_） | 先通过自定义 URL 登录 WP Admin，再前往 `/pos` |
| **Force Login**（及类似的 REST 身份验证插件） | `/wp-json/` 返回 401/403；旧版应用会报告 _“该网站似乎不是 WordPress 网站”_ | 允许未经身份验证访问 POS 端点，或在初次连接时禁用该插件。v1.x 应用现已显示实际的错误消息 |
| **LoginPress** | 强制使用电子邮件登录，导致 POS 多用户登录无法正常工作 | 允许使用用户名登录，或在访问 POS 时禁用该插件 |
| **JWT Authentication 插件** | 启用后，所有 POS API 请求均返回 403（登录可能成功，但其他操作均失败） | v1.8.x+ 已自动修复。对于旧版本，请停用 JWT 插件或排除 POS 端点 |
| **Captcha / reCAPTCHA** | 桌面应用反复要求登录（验证码无法在 iframe 中显示） | 对 POS 登录 URL 禁用验证码 |
| **Defender Pro** | `X-Frame-Options` 标头阻止所有 POS iframe（登录、支付、收据） | 为 `/pos/` 添加 POS 专用例外，而非在整个网站上禁用 `X-Frame-Options` |
| **Jetpack CRM Client Portal** | 导致 POS 完全无法登录 | 仅禁用 Client Portal 扩展 |

### 性能、缓存与优化插件 {#performance-caching-optimisation-plugins}

| 插件 | 症状 | 修复方法 |
| --- | --- | --- |
| **WP Rocket、Autoptimize、Hummingbird、Smush** | 延迟加载/压缩 JS 导致结账和 Stripe Terminal 无法正常工作 | 在 JS 优化中排除 `/pos/` URL |
| **LiteSpeed Cache** | 桌面应用在结账时不断重新加载；CSP 限制过严 | 更新 WCPOS，清除缓存，并在缓存中排除 POS 页面。v1.9.0+ 会自动移除 CSP |
| **Image Prioritizer** | 向 HTTP `Link` 标头添加大量内容，导致 REST API 发现机制失效；桌面应用显示 _“似乎不是 WordPress 网站”_ | 停用该插件 |

### 页面构建器与前端注入插件 {#page-builders-front-end-injectors}

| 插件 | 症状 | 修复方法 |
| --- | --- | --- |
| **Elementor** | `elementor-frontend.js` 导致 POS iframe 内的结账折叠面板失效，支付方式无法展开 | 在 POS 页面上排除 Elementor 脚本加载 |
| **Omnisend / 营销插件** | 向结账 iframe 注入脚本，破坏布局并影响支付 | 使用 POS 的**收银台设置**禁用非必要脚本 |
| **MyStickyElements / Complianz** | 向结账 iframe 注入覆盖层（悬浮按钮、Cookie 横幅） | 配置这些插件，排除 `/pos/` URL |

### WooCommerce 扩展与其他插件 {#woocommerce-extensions-other-plugins}

| 插件 | 症状 | 修复方法 |
| --- | --- | --- |
| **WooCommerce Subscriptions** | 从 v1.7→v1.8 升级时出现迁移脚本冲突 | 停用 Subscriptions，启用 WCPOS Pro（让迁移完成），然后重新启用 Subscriptions |
| **WP Activity Log** | 记录每个 POS 操作 → postmeta 膨胀 → _“只有 10 个产品”_ | 禁用该插件，或在日志记录中排除 POS 文章类型 |
| **Jetpack / Astra / Xero**（所有挂接 `save_post` 的插件） | 每次 POS API 调用都产生重复的元数据行（某个店铺的单个产品曾达到 36,867 行） | v1.8.12+（免费版）/ v1.8.14+（Pro）已通过清理迁移自动修复，只需更新即可 |
| **Stripe Tax** | 不兼容通过 REST API 创建的订单（POS 正是以此方式创建订单） | 不兼容，且无变通方案。[WooCommerce Tax](/1.x/integrations/woocommerce-tax) 是受支持的自动税费计算方案 |
| **Mollie** | 可能在 POS 结账时隐藏 BACS（银行转账）支付方式 | 将 Mollie 更新到最新版本 |
| **CTX Feed** | POS 设置页面间歇性出现 403 错误 | 停用以确认原因；目前没有已知的变通方案 |
| **第三方条码扫描插件** | 破坏订单 API 的 JSON，导致订单无法创建/显示 | 禁用这些插件，使用 POS 内置的条码扫描功能 |
| **MailerLite**（Signup Forms + WooCommerce） | 创建 POS 订单时出现 500 错误（内存耗尽） | 停用以确认原因，然后联系 MailerLite |
| **The Courier Guy Shipping** | 创建 POS 订单时因服务器错误而失败 | 回退到先前版本，或联系开发者 |
| **PixelYourSite / PixelMySite** | 致命错误：_在布尔值上调用成员函数 `is_type()`_ | 暂时禁用 |
| **Google Listings & Ads** | 自动加载器冲突 → _“找不到类 WCPOS\…\Stores”_ 严重错误 | 删除所有 POS 插件，仅重新安装最新的 Pro 独立版 |

:::warning Stripe Terminal：请勿全局启用
**Stripe Terminal** 网关应**仅**在 POS 设置中启用，切勿在 `WooCommerce > 设置 > 支付` 中启用。全局启用后，它会出现在面向顾客的店铺结账页面上，并导致在线结账流程崩溃。
:::

### 服务器级冲突 {#server-level-conflicts}

| 来源 | 症状 | 修复方法 |
| --- | --- | --- |
| **自定义 CSP 标头**（`.htaccess`、Nginx 或安全插件） | POS 卡在标志画面；JS/CSS 被阻止加载 | v1.9.0+ 会自动移除 POS 页面上的 CSP。对于服务器级 CSP，请在 `script-src`/`style-src` 中允许 `cdn.jsdelivr.net`，或添加 `/pos/` 例外 |
| **GoDaddy Website Firewall** | 阻止 `/wp-json/`（_“收到 'undefined'”_） | 在防火墙中允许 `/wp-json/` URL 路径，请参阅[服务器性能](/1.x/support/performance/server#hosting-specific-notes) |

## 预防建议 {#prevention-tips}

### 定期维护 {#regular-maintenance}

1. **保持插件更新** - 始终使用最新版本
2. **移除未使用的插件** - 不要只停用，还应将其删除
3. **在暂存网站上测试更新**，再应用到生产网站
4. 使用[服务器性能](/1.x/support/performance/server)指标定期**监控性能**

### 插件选择最佳实践 {#plugin-selection-best-practices}

1. **选择信誉良好的开发者** - 查看评价和更新频率
2. **避免功能重复** - 不要安装多个具有相同功能的插件
3. **阅读兼容性信息** - 检查插件是否经过 WooCommerce 兼容性测试
4. **从最少的插件开始** - 根据需要逐步添加功能
