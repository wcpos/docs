POS 会在某笔销售上显示一条通知，内容为 **"你的商店更改了此订单的总计金额"**，并列出两者之间存在差异的金额。

## 该通知的含义 {#what-the-notice-means}

WooCommerce 会自行计算每个订单的总计金额。POS 在本地重现该计算，使收银机能够即时结算一笔销售并收款 —— 并且在断网时仍能继续工作。

两者本应完全一致。当 POS 保存一笔销售、而你的商店返回了不同的金额时，说明这次重现出了错，于是通知会**在货物离开柜台之前**告知收银员。

:::info 以你商店的金额为准
销售不会被阻止，也不会丢失任何内容。你商店的数字才是被记录下来的，也是出现在 WooCommerce 报表和客户订单上的数字。此通知的存在是为了让收银员在交付任何货物之前先核对总计金额。
:::

:::warning 在问题解决之前，请勿进行离线销售
POS 在本地计算的金额，与它在无连接时所使用的金额是相同的 —— 而在离线状态下，没有服务器来纠正它们。因此，只要一笔销售因**任何**原因出现偏差，此商店上的离线销售就可能出错，且在你重新连接之前都无法被发现。

这适用于下面列出的每一种原因，而不仅仅是插件那一种情况。
:::

## 首先，重新同步 POS {#first-resync-the-pos}

POS 会保留一份你商店税务配置的副本，且在你更改 WooCommerce 时它不会自动更新。副本过时是两者不一致最常见的原因，而且它有一个一键式的修复方法。

在 POS 中打开 **Tax Settings（税务设置）**，使用 **Restore Server Settings（恢复服务器设置）**从你的商店拉取当前配置，然后进行一笔全新的测试销售。

如果这样就解决了，那就完成了 —— 记得在每次更改 **WooCommerce → Settings → Tax** 下的任何内容后都执行一次。请参阅[税务设置](/settings/store/tax)了解各字段的含义，以及那一种不宜执行恢复的特殊情况。

如果在 POS 刚刚同步后通知仍然出现，那么就要查看下面列出的原因。

## 是什么导致的 {#what-causes-it}

有三种可能，而通知在这三种情况下看起来都一样。

### POS 解读方式不同的某项税务或舍入设置 {#a-tax-or-rounding-setting}

这是目前最常见的原因。请在 **WooCommerce → Settings → Tax** 下检查：

- **含税录入价格** —— 你的商品目录价格是否已含税
- **舍入** —— “按小计层级对税额进行舍入”会改变多行销售的结果
- **税率** —— 某个税率的*优先级*或*复合*设置与你的预期不同
- **小数位数** —— 在 **General（常规）**下，设为 3 位及以上小数的商店与设为 2 位的商店舍入方式不同

最近更改过上述任一项的商店，或按邮编或城市设置税率的商店，是首先要排查的对象。

### 会重写订单总计的插件 {#a-plugin-that-rewrites-totals}

附加费、手续费、货币换算、忠诚度以及“基于角色的定价”类插件，通常会在 POS 完成自己的运算之后，在服务器上重新计算总计。POS 无法看到这些规则，因此对于它们涉及的每一笔销售都会出现不一致。

如果这是有意为之且你接受它，那么并没有出问题 —— 这些销售会被你的商店正确记录。但通知会出现在每一笔受影响的销售上，而这是唯一一种不会自行消失的原因：这些规则存在于服务器上、POS 无法重现，因此以这种方式计算总计的商店**完全无法正确地进行离线销售**，而不仅仅是在问题修复之前无法销售。

请参阅[插件冲突](/support/troubleshooting/plugin-conflicts)了解如何确定是哪个插件造成的。

### POS 中的一个缺陷 {#a-bug-in-the-pos}

如果你的商店是标准的 WooCommerce 安装、没有任何会更改总计的插件，而金额仍然不一致，那就是我们的缺陷，我们希望了解此事。

## 当它出现在多笔销售上时 {#when-it-happens-on-several-sales}

单笔出现偏差的销售值得检查。当**多笔不同的销售**都出现不一致后，POS 会升级该通知，因为到那时它就不再是单个订单的特性 —— 而是整个安装的特性，并且会一直发生，直到找到原因为止。

## 需要发给我们的内容 {#what-to-send-us}

通知会列出每一项存在差异的金额，并同时显示两个数字。这些内容，加上以下信息，通常足以在无需屏幕共享的情况下确定原因：

1. 显示金额的通知截图。
2. 确认你已在 POS 中运行过 **Restore Server Settings（恢复服务器设置）**且通知仍然存在。
3. 你的税务设置：**WooCommerce → Settings → Tax**（所有字段），以及 **General → 小数位数**。
4. 是否启用了“按小计层级对税额进行舍入”。
5. **税率表本身**，而不仅仅是设置页面 —— 每个税率类别下的各行，包括*国家/州/邮编/城市*、*税率 %*、*优先级*、*复合*和*运费*。上述大多数原因都藏在这些行里，而不是在其上方的设置中，缺少它们我们就得回来再问一次。
6. 涉及价格、税费、手续费或货币的已启用插件列表。
7. 一笔受影响销售的订单编号。
