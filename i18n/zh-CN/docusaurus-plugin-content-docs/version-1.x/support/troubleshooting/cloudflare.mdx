Cloudflare 会要求访客通过安全检查，以保护您的网站。浏览器可以在后台通过该检查。WCPOS 应用不是浏览器：它通过 REST API 与店铺通信；如果 Cloudflare 返回安全检查页面而非数据，应用便无法连接。

本文介绍如何识别此问题，以及如何设置 Cloudflare 以允许应用通过。以下所有步骤均由店铺所有者或管理网站 Cloudflare 账户的人员执行。

## 如何识别此问题 {#how-to-recognise-it}

- 连接屏幕显示 **“此店铺的托管配置正在阻止应用”**，并带有错误代码 [HOST121](/error-codes/HOST121)。
- 连接或同步时，桌面应用会打开一个小窗口，显示 **“your-store.com 的安全检查”**。
- 旧版本会在明显在线的网站上报告 **“该网站似乎不是 WordPress 网站”** 或 **“网站响应时间过长”**。
- 云打印停止工作，并显示“安全服务正在阻止 WCPOS Cloud Print”消息。

如需确认，请打开终端并运行：

```bash
curl -sI https://your-store.com/wp-json/
```

被拦截的店铺会返回 `403` 状态和 `cf-mitigated: challenge` 标头。正常的店铺会返回 `200` 和 `content-type: application/json`。如果返回 `404`，说明网站未使用美观固定链接；请改为对 `'https://your-store.com/?rest_route=/'` 运行相同检查。如果 WordPress 安装在子文件夹中，请将其包含在内：`https://example.com/shop/wp-json/`。

:::note 桌面应用可以通过一次性检查
在条件允许时，较新版本的桌面应用会在小窗口中完成 Cloudflare 检查，让您继续营业；但 Cloudflare 发放的通行凭证会过期（默认 30 分钟），之后检查会再次出现。请将该窗口视为临时措施，并应用下方的修复方法。
:::

## 是哪项 Cloudflare 功能导致了问题 {#which-feature}

具体修复方法取决于触发应用安全检查的功能。请在网站的 Cloudflare 控制面板中检查以下项目。Cloudflare 一直在调整菜单位置；括号内为旧版位置。

| 功能 | 位置 | 能否豁免 API？ |
| --- | --- | --- |
| **机器人防护模式**（免费计划） | 安全性 → 设置 → 机器人流量（旧版控制面板：安全性 → 机器人） | **不可以。** Cloudflare 不允许使用 Skip 或 Allow 规则绕过此模式。请将其关闭，或升级到 Pro 并使用 Super Bot Fight Mode，后者可通过下方的 Skip 规则豁免。 |
| **攻击模式** | 网站概览中的“攻击模式”开关，或安全性 → 设置 | 可以。下方的跳过规则会跳过安全级别，而攻击模式会提高该级别。也可以在攻击结束后关闭攻击模式。 |
| **超级机器人防护模式**（Pro 及更高套餐） | 安全性 → 设置 → 机器人流量（旧版控制面板：安全性 → 机器人） | 可以，使用下方的跳过规则。 |
| **WAF 自定义规则或托管规则**设置为_托管质询_ | 安全性 → 安全规则（旧版控制面板：安全性 → WAF） | 可以，使用下方的跳过规则，并将其放在任何会触发质询的自定义规则之前。托管规则始终在自定义规则之后运行，因此对托管规则无需考虑顺序。 |

官方 Cloudflare WordPress 插件可以切换攻击模式并启用 WAF，但无法创建跳过规则。跳过规则需要在 Cloudflare 控制面板中设置。

## 为 REST API 添加跳过规则 {#add-a-skip-rule}

除 Bot Fight Mode 外，此修复适用于所有情况。它会告知 Cloudflare 不要对发往店铺 REST API 的请求发起质询。WordPress 自身的登录和权限检查仍会保护这些端点。

1. 在 Cloudflare 控制面板中打开您的网站，然后选择 **安全性 → 安全规则**（旧版控制面板：**安全性 → WAF → 自定义规则**），再选择 **创建规则 → 自定义规则**。
2. 将规则命名为 `WCPOS REST API`。
3. 在 **匹配传入请求时**下，选择 **编辑表达式**并粘贴：

   ```text
   (starts_with(http.request.uri.path, "/wp-json/")) or (http.request.uri.path eq "/" and (starts_with(http.request.uri.query, "rest_route=") or http.request.uri.query contains "&rest_route="))
   ```

   后半部分匹配 WordPress 的备用地址 `/?rest_route=/...`，且仅限网站根目录，因此其他页面查询参数中的 `rest_route=` 字符串不会关闭该页面的保护。如果 WordPress 安装在子文件夹中，例如 `https://example.com/shop`，请将 `/shop/wp-json/` 和 `/shop/` 分别替换为 `/wp-json/` 和 `/`。

4. 在 **然后执行操作**下，选择 **跳过**。
5. 勾选 **所有其余自定义规则**。在要跳过的组件列表中，勾选 **所有超级机器人防护模式规则**和**安全级别**。只有在托管规则导致质询时才勾选**所有托管规则**；不要更改标记为“（旧版本）”的条目。
6. 部署规则。如果还有其他会发起质询或拦截请求的自定义规则，请确保此规则排在它们之前。

再次运行 `curl` 检查。`cf-mitigated` 标头应已消失，响应内容应为 JSON。

:::tip 免费套餐与 Bot Fight Mode
如果应用跳过规则后，`curl` 检查仍显示质询，且**Bot Fight Mode**已开启，原因就是 Bot Fight Mode。免费套餐唯一的修复方法是在“安全性 → 设置 → 机器人流量”下将其关闭。Cloudflare 官方文档确认，任何规则都无法绕过此功能。如果 Bot Fight Mode 已关闭，请参阅[仍被拦截？](#still-blocked)。
:::

## 缓存 {#caching}

Cloudflare 也可能缓存 REST API 响应，导致应用显示过期的商品和订单。上述跳过规则不会更改缓存设置。如果您使用 Cloudflare 缓存 HTML 页面或自动平台优化，请添加一条**缓存规则**，针对相同表达式设置**绕过缓存**。

## 仍被拦截？ {#still-blocked}

请确认跳过规则已部署，而不是仅保存为草稿，并确认没有 IP 访问规则拦截收银台所在的网络。网站前端的其他服务也可能像 Cloudflare 一样造成问题：有关安全插件，请参阅[插件冲突](/support/troubleshooting/plugin-conflicts)；有关 GoDaddy、WP Engine 等服务，请参阅[托管说明](/support/performance/server#hosting-specific-notes)。
