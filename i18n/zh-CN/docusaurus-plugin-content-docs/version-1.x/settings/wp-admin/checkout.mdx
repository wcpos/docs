收银台设置页面(`WP Admin > POS > 设置 > 结账`)用于控制 POS 中显示哪些支付网关、如何处理订单，以及 POS 销售会触发哪些通知邮件。

## 电子邮件通知 {#email-notifications}

页面顶部有三组电子邮件开关：**管理员电子邮件**、**客户电子邮件** 和 **收银员电子邮件**。它们控制 POS 订单会发送哪些 WooCommerce 通知电子邮件，独立于站点级的 WooCommerce 电子邮件设置。

完整参考请参见 **[电子邮件通知](/1.x/settings/wp-admin/email-notifications)**，其中包括各类电子邮件开关的默认值、收银员收件人的确定方式、常见场景以及开发者钩子。

## 支付网关 {#payment-gateways}

此部分列出了站点上安装的所有 WooCommerce 支付网关。每个网关都可以针对 POS 独立启用或禁用。

| 列 | 描述 |
|--------|-------------|
| **默认** | 选择收银员打开结账界面时预先选中的网关 |
| **网关** | 支付网关名称 |
| **网关 ID** | WooCommerce 网关标识符（对开发者有用） |
| **已启用** | 为 POS 结账启用或禁用该网关 |
| **订单状态** | 使用该网关付款时 POS 订单被设置成的状态（参见下方的[订单状态](#order-status)） |

每一行还有一个菜单（⋮），其中 **POS 设置** 可更改该网关仅用于 POS 的 **标题** 和 **描述**，**WooCommerce 设置** 则会直接跳转到该网关在 WooCommerce 中的完整设置。

### 启用网关 {#enabling-a-gateway}

1. 在列表中找到该网关
2. 打开 **已启用** 开关
3. 该网关将在下次页面加载时出现在 POS 结账中

:::note 免费版与 Pro 版
在免费版中，只有内置的 **现金** 和 **卡** 网关可以编辑。要为 POS 启用其他已安装的 WooCommerce 网关，需要 [WCPOS Pro](/1.x/getting-started/pro-license)。
:::

### 重新排序网关 {#reordering-gateways}

拖动网关可更改它们在 POS 结账中的显示顺序。使用 **默认** 列选择收银员打开结账弹窗时预先选中的网关。

### POS 与在线商店 {#pos-vs-online-store}

此处的网关设置 **独立于** WooCommerce 支付设置。一个网关可以：

- **为 POS 启用，在线禁用**——适用于现金等不适合在线订单的支付方式
- **在线启用，为 POS 禁用**——适用于 PayPal 等不便于面对面销售的网关
- **两者都启用**——该网关在两处都可使用

:::note
网关必须先在 `WP Admin > WooCommerce > 设置 > 支付` 中安装并启用，才会出现在 POS 收银台设置列表中。如果某个网关未显示，请检查插件是否已安装，以及该网关是否已在 WooCommerce 中启用。
:::

## 订单状态 {#order-status}

订单状态 **按网关** 设置，可在网关表格的 **订单状态** 列中配置，因此一笔销售的最终状态会因付款方式而异：

- **现金** 和 **卡** 默认为 **已完成**，因为款项已在销售点收取。
- 资金稍后才到账的网关，例如 **BACS**（银行直接转账）或 **支票**，默认为 **暂时保留**。

您可以为每个网关选择任意 WooCommerce 订单状态。（旧版本使用单一的全局默认值；升级时，该值已迁移到各个网关。）

### 收银设备如何处理订单状态 {#order-status-at-the-till}

订单达到您为网关选择的状态后，POS 会结束销售并返回购物车。WooCommerce 仅将 **处理中** 和 **已完成** 视为已付款。**暂时保留** 和 **等待付款** 不属于已付款状态。

对于在柜台收到的款项，请选择 **处理中** 或 **已完成**。若客户将自行转账且不使用付款链接，请选择 **暂时保留**；这是 BACS 和支票的默认设置。

如果希望客户稍后通过订单付款链接付款，请选择 **等待付款**，例如使用 **BACS** 的“按发票付款”流程。WooCommerce 会让待付款订单保持可付款状态：订单不会标记为已付款，库存不会扣减，且只要订单保持等待付款状态，付款链接就有效。POS 不会发送此链接。订单需要填写客户电子邮件地址；您可以在 WooCommerce 订单页面发送发票邮件，或通过其他方式分享链接。

:::caution v1.10.25 及更早版本中的等待付款状态
在 WCPOS v1.10.25 及更早版本中，将网关设为等待付款后，收银员确认时，收银设备上的付款窗口仍会保持打开，订单也会留在购物车中；重新加载 POS 可将其清除。当插件页面提供高于 v1.10.25 的版本后，请先更新插件，再更新每台收银设备上的 POS 应用；两项更新缺一不可。在此之前，请将网关保持为 **暂时保留**，这会结束销售，但不会向客户提供付款链接，请通过其他方式发送发票。
:::

## 防止超卖 {#prevent-overselling}

**防止超卖** 开关会阻止 POS 销售库存不足的商品。该开关 **默认关闭**，启用之前，结账行为与以往完全相同。

WooCommerce 的 REST API 在创建订单时不会校验库存，因此繁忙的收银台（或过时的产品列表）可能导致售出数量超过实际库存。打开开关后，WCPOS 会在两处检查库存：

1. **在收银台**——收银员无法将商品加入购物车或增加其数量至超过可用库存。POS 会显示 *实际* 可用的数量，例如 *“连帽衫 – 蓝色，M 仅剩 3 件”*。
2. **结账时，在您的服务器上**——在付款完成前校验订单。即使收银台的本地数据已过时，会造成超卖的订单也会被拒绝，并向收银员明确显示哪些商品库存不足以及各自的可用数量。随后，POS 会刷新这些商品的库存，以便根据准确数量调整购物车。

未结账购物车的同步不会被阻止，校验只在结账时运行。

### 库存如何判定 {#prevent-overselling-stock-rules}

| 产品设置 | 开关打开时的行为 |
|---|---|
| **管理库存**（跟踪数量） | 销售数量受库存数量限制。购物车中同一产品的多个行项目共用同一限额。 |
| **变体跟踪自己的库存** | 限额按变体分别计算。 |
| **变体使用父产品的库存** | 该产品的所有变体共用父产品的库存数量。 |
| **不管理库存** | 由产品的库存状态决定：*缺货* 无法出售；*有库存* 和 *延期交货* 可以出售。 |

:::note 库存数量插件
WCPOS 将库存扣减交由 WooCommerce 处理。与在线订单一样，当 POS 订单进入会扣减库存的状态（处理中、已完成或暂时保留）时，WooCommerce 会扣减库存；删除 POS 订单时则会恢复库存（参见[删除订单时恢复库存](/1.x/settings/wp-admin/general#restore-stock-on-order-delete)）。因此，只要插件作用于 WooCommerce 的库存扣减流程，改变每笔销售所消耗库存数量的插件（例如为整包或整箱商品设置库存数量倍数的插件）也适用于 POS 订单。只修改在线商店购物车的插件则不会影响 POS 销售，因为 POS 不使用该购物车。

防止超卖功能比较的是购物车行项目中的数量与产品库存，而不是乘以倍数后的数量。使用倍数时，一笔销售可能通过此检查，但实际消耗的库存仍可能超过剩余库存。请先进行一笔测试销售，然后检查产品库存。
:::

### 延期交货设置仍然优先 {#prevent-overselling-backorders}

每个产品的 **延期交货设置优先级更高**，因此在开关打开的情况下，仍可允许特定产品超卖：

- **不允许**——库存售罄后停止销售（这正是开关所执行的限制）。
- **允许**——该产品始终可以出售，即使库存低于零。
- **允许，但通知客户**——该产品始终可以出售；当销售数量超过可用库存时，收银员会看到 *“将转为延期交货”* 的提示。

### 防止超卖与“显示缺货产品” {#prevent-overselling-vs-display}

这两项设置提供不同的库存保护，但都可能阻止添加缺货商品：

- **防止超卖**（本页）在添加或更新商品时检查可用数量，并在结账时再次校验库存。
- **显示缺货产品**（POS 产品面板中的显示设置）控制缺货产品与变体的选择方式。启用时，缺货产品仍然可见，但无法加入购物车。禁用时，它们会被隐藏；缺货的变体选项也会变灰，匹配这些商品的条形码扫描会被拒绝。

关闭防止超卖并不会覆盖产品面板的这些规则。您可以让缺货商品保持可见，同时用防止超卖功能增加数量与结账方面的保护：收银员会看到商品带有 *缺货* 标记，且加入购物车按钮处于禁用状态。

:::note
开关的更改会在收银员下次登录或应用重新校验时应用于已打开的 POS 会话，服务器端检查则立即生效。
:::
