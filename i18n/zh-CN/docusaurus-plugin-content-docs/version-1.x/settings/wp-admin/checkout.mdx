结账设置页面（`WP Admin > POS > Settings > Checkout`）控制哪些支付网关显示在 POS 中、订单如何处理，以及 POS 销售会触发哪些通知电子邮件。

## 电子邮件通知 {#email-notifications}

页面顶部有三组电子邮件开关——**管理员电子邮件**、**客户电子邮件** 和 **收银员电子邮件**——它们控制 POS 订单会发送哪些 WooCommerce 通知电子邮件，独立于您的站点级 WooCommerce 电子邮件设置。

完整参考请参见 **[电子邮件通知](/settings/wp-admin/email-notifications)**，其中包括每封电子邮件的开关默认值、收银员收件人模型、常见场景以及开发者钩子。

## 支付网关 {#payment-gateways}

此部分列出了安装在您站点上的所有 WooCommerce 支付网关。每个网关都可以针对 POS 独立启用或禁用。

| 列 | 描述 |
|--------|-------------|
| **默认** | 选择收银员打开结账时预先选中的网关 |
| **网关** | 支付网关名称 |
| **网关 ID** | WooCommerce 网关标识符（对开发者有用） |
| **已启用** | 为 POS 结账打开或关闭该网关 |
| **订单状态** | 使用该网关付款时 POS 订单被设置成的状态（参见下方的[订单状态](#order-status)） |

每一行还有一个菜单（⋮），其中 **POS 设置** 可更改该网关仅用于 POS 的 **标题** 和 **描述**，**WooCommerce 设置** 则会直接跳转到该网关在 WooCommerce 中的完整设置。

### 启用网关 {#enabling-a-gateway}

1. 在列表中找到该网关
2. 打开 **已启用** 开关
3. 该网关将在下次页面加载时出现在 POS 结账中

:::note 免费版与 Pro 版
在免费版中，只有内置的 **现金** 和 **卡** 网关可以编辑。要为 POS 启用其他已安装的 WooCommerce 网关，需要 [WCPOS Pro](/getting-started/pro-license)。
:::

### 重新排序网关 {#reordering-gateways}

拖动网关以更改它们在 POS 结账中的显示顺序。使用 **默认** 列选择收银员打开结账弹窗时预先选中的网关。

### POS 与在线商店 {#pos-vs-online-store}

此处的网关设置 **独立于** 您的 WooCommerce 支付设置。一个网关可以是：

- **为 POS 启用，在线禁用**——适用于不适合网店订单的现金支付
- **在线启用，为 POS 禁用**——适用于像 PayPal 这样不便于面对面销售的网关
- **两者都启用**——该网关在任何地方都可用

:::note
网关必须先在 `WP Admin > WooCommerce > Settings > Payments` 中安装并激活，然后才会出现在 POS 结账设置列表中。如果某个网关缺失，请检查该插件是否已安装且该网关已在 WooCommerce 中启用。
:::

## 订单状态 {#order-status}

订单状态**按网关**设置，可在网关表格的 **订单状态** 列中配置——因此一笔销售的最终状态会因付款方式而异：

- **现金** 和 **卡** 默认为 **已完成**，因为付款已在销售点收取。
- 资金稍后才到账的网关——例如 **BACS**（银行直接转账）或 **支票**——默认为 **暂时保留**。

您可以为每个网关选择任意 WooCommerce 订单状态。（旧版本使用单一的全局默认值；升级时该值已迁移到每个网关上。）

## 防止超卖 {#prevent-overselling}

**防止超卖** 开关会阻止 POS 销售库存不足的商品。该开关**默认关闭**——在启用之前，结账行为与以往完全相同。

WooCommerce 的 REST API 在创建订单时不会校验库存，因此繁忙的收银台（或过时的产品列表）可能卖出超过实际持有的数量。开关打开后，WCPOS 会在两处检查库存：

1. **在收银台** — 收银员无法将商品加入购物车（或将其数量提高）到超过可用库存。POS 会显示*实际*可用的数量，例如 *“Hoodie – Blue, M 仅剩 3 件”*。
2. **结账时，在您的服务器上** — 在付款完成前会对订单本身进行校验。即使收银台的本地数据已过时，会造成超卖的订单也会被拒绝，并向收银员准确显示哪些商品不足以及各自还有多少可用。随后 POS 会刷新这些商品的库存，以便按准确数量修正购物车。

已打开的购物车永远不会被阻止同步——校验只在结账那一刻运行。

### 库存如何判定 {#prevent-overselling-stock-rules}

| 产品设置 | 开关打开时的行为 |
|---|---|
| **管理库存**（跟踪数量） | 销售数量受库存数量限制。购物车中同一产品的多行会计入同一限额。 |
| **变体跟踪自己的库存** | 限额按变体分别应用。 |
| **变体使用父产品的库存** | 该产品的所有变体共用父产品的数量。 |
| **不管理库存** | 由产品的库存状态决定：*缺货* 无法出售；*有库存* 和 *延期交货* 可以出售。 |

### 延期交货设置优先 {#prevent-overselling-backorders}

**单个产品的延期交货设置优先级更高**——在开关打开的情况下，这就是为特定产品放行超卖的方式：

- **不允许** — 库存售罄后停止销售（这正是开关所强制执行的）。
- **允许** — 该产品始终可以出售，即使库存低于零。
- **允许，但通知客户** — 该产品始终可以出售；当某笔销售低于可用库存时，收银员会看到 *“将转为延期交货”* 的提示。

### 防止超卖与“显示缺货产品”的区别 {#prevent-overselling-vs-display}

这两项设置涵盖不同的库存保护，但都可能阻止缺货商品被加入购物车：

- **防止超卖**（本页）在添加或更新商品时检查可用数量，并在结账时再次校验库存。
- **显示缺货产品**（POS 产品面板中的一项显示设置）控制缺货产品与变体的可选方式。启用时，缺货产品仍然可见，但无法加入购物车。禁用时，它们会被隐藏；缺货的变体选项也会变灰，匹配的条码扫描会被拒绝。

关闭防止超卖并不会覆盖产品面板的这些规则。您可以在保持缺货商品可见的同时，用防止超卖增加数量与结账方面的保护——收银员会看到该商品带有 *缺货* 标记，且加入购物车按钮为禁用状态。

:::note
开关的更改会在收银员下次登录或应用重新校验时到达已打开的 POS 会话——服务器端检查会立即生效。
:::
