本页引导收银员（或经理）完成日终关账流程。如需了解报表界面本身的筛选条件、列和汇总面板内容，请参阅[报表](/1.x/reports)。

:::info 专业版功能
报表界面需要 [WCPOS Pro](/1.x/getting-started/pro-license)。没有 Pro 时，日终对账必须通过 **WP Admin → WooCommerce → 分析** 完成。
:::

:::note 手动现金清点
WCPOS 没有内置的开班备用金或“开钱箱／关钱箱”功能：没有可打卡签到或签退的班次会话，没有应用内钱箱清点，也没有自动差异计算。报表界面显示钱箱**应有**的收款金额；收银员需手动清点钱箱并核对。本页介绍的就是这套操作流程。
:::

## 首次关账前的准备 {#before-your-first-close}

先确定以下事项，再让各班次始终遵循：

- **开班备用金金额。** 零售收银台通常每天准备 $100–$200 的小面额现金用于找零。选定一个金额并保持一致，可以简化每日对账计算。
- **备用金记录方式。** WCPOS 不会记录备用金；您需要使用放在收银台的便签、纸质记录表或电子表格。无论选择哪种方式，*开班备用金*和*预期钱箱总额*都应记录在同一份记录中，以便日后审计。
- **清点与签字人员。** 最佳做法是由两人完成（收银员清点，经理核实）。仅有一名员工的店铺可由收银员兼任这两项工作，请将此做法写入操作规定。

## 开班 {#opening-the-till}

班次开始时：

1. 从保险柜中取出备用金，放入钱箱。
2. 在对账单上填写备用金金额和开班时间。
3. 登录 WCPOS 并选择正确的店铺（多店铺站点）。如果不确定该选哪家，请参阅[多店铺设置](/1.x/stores)。

这样就完成了。WCPOS 现在会将本班次的销售记录关联到您的用户账户和所选店铺。

## 班次期间 {#during-the-shift}

注意以下几点，可以让关账更轻松：

- **统一使用优惠券或商品行折扣的方式。** 两者都可用于临时调整，但优惠券会作为可跟踪的折扣显示在报表中，商品行价格更改则不会。有关两者的取舍，请参阅[折扣](/1.x/pos/cart/discounts)。
- **暂存订单，不要直接放弃。** “POS - 待处理”订单（通过**保存到服务器**保存）会清晰地显示在订单和报表中；放弃的购物车则不会留下记录。客户返回时，可继续处理暂存订单。
- **钱箱现金过多时，在班次中途取出多余现金。** 每次取出现金都要记录金额和时间，以便关账时核对。WCPOS 不会记录这些取款，请将其记在对账单上。

## 关账流程 {#the-close-procedure}

<Steps>
  <StepCard number="1" title="停止收银">

锁好前门（或暂停排队），避免清点过程中产生新交易。如果关账时有客户到来，请在为其收银**之前**完成清点和报表；在报表时段结束后增加销售会导致总额不准确。

  </StepCard>
  <StepCard number="2" title="清点钱箱">

将钱箱带到后台办公室或安静的柜台，逐一清点每种面额的现金。记下总额，这就是您的**实点现金**。

如果班次期间曾取出现金或支付现金（退款、从钱箱支付供应商款项），也请准备好这些金额。

  </StepCard>
  <StepCard number="3" title="打开报表界面">

在 POS 中打开**报表**，设置筛选条件，使报表恰好覆盖您的班次：

- **日期范围：** *今天*（如果是事后对账，则选择具体日期）
- **收银员：** 如果多位收银员使用过收银台，而您只想查看自己的销售额，请选择自己的用户账户
- **店铺：** 自动设为当前店铺
- **状态：** 保留默认值（通常为*已完成* + *处理中*）

右侧的销售汇总面板会随筛选条件变化而更新。记下*付款方式*下的**现金**金额，这就是您的**预期现金销售额**。

  </StepCard>
  <StepCard number="4" title="现金对账">

按以下公式计算：

> **预期钱箱总额 = 开班备用金 + 现金销售额 − 现金退款 − 现金取出／支出**

与**实点现金**进行比较，两者应一致。

- **完全相符：** 在对账单上签字并填写日期，存放好现金，现金部分就完成了。
- **不符：** 签名前，请先参阅下方的 [差异处理](#variance-handling)。

</StepCard>
  <StepCard number="5" title="银行卡对账">

接下来核对银行卡付款。记下销售汇总中的**银行卡**金额，以及各集成网关的金额，如 Stripe Terminal、SumUp、Vipps/MobilePay。

在刷卡终端上运行**批次汇总**（具体菜单因终端而异，通常位于设备的*报表*或*日结*中）。比较以下金额：

- 同一时段的**终端批次汇总**与**WCPOS 刷卡总额**应一致。
- 如果使用需要手动结批的终端，请在下班前**立即结批**。Stripe Terminal 等集成网关会自动结批。有关通过网页结账配置 Square 的说明，请参阅[网页结账](/1.x/payment/gateways/web-checkout)。

</StepCard>
  <StepCard number="6" title="打印报表">

在报表界面的汇总面板中点击**打印**。通常会使用已配置的打印路由（请参阅[打印路由](/1.x/hardware/printers#print-routing)），将报表发送到收据打印机或文档打印机，生成纸质记录。

打印的报表包含店铺信息、时段、各行总额、付款方式明细，以及逐单详情（如果您在订单表中选择了订单）。

  </StepCard>
  <StepCard number="7" title="存放现金并签字确认" isLast>

- 将**明天的开班备用金**放回钱箱。
- 将已签字的对账单和打印报表装订在一起，与剩余现金一同放入保险柜投款袋。
- 更新您使用的外部系统（电子表格、会计软件）。
- 关闭 WCPOS 应用并锁好门店。

</StepCard>
</Steps>

## 差异处理 {#variance-handling}

如果实点现金与预期不符，请在签字确认前按以下顺序排查：

1. **重新清点钱箱。** 清点难免出错，请再数一遍，尤其是硬币。
2. **检查是否漏记现金交易。** 是否有人在其他设备或浏览器标签页处理了销售，却未计入本期？请重新检查报表中的日期范围和收银员筛选条件。
3. **检查暂存／未结订单。** 将订单筛选为 *POS - 待处理* 状态，已录入但未付款的销售会显示在此处。现在完成订单，否则就应预期会出现相应差异。
4. **退款和支出。** 确认今天的每笔现金退款和现金支出均已记录在对账单上，并注明金额。
5. **优惠券和折扣。** 确认总额已计入所有应用的折扣：报表的*总折扣*行显示可跟踪的优惠券折扣，商品行价格覆盖则直接减少*净销售额*（请参阅[折扣](/1.x/pos/cart/discounts#why-tracked-differently)）。
6. **找零错误。** 这是最常见的差异来源。小额差异（低于 $5）通常由此造成；较大差异需要调查。

无论是否找到原因，都应在对账单上记录差异。有记录可查的小额差异，总好过没有记录的账目不符。

## 多收银员或多店铺场景 {#multi-cashier-or-multi-store-scenarios}

<Accordion>
  <AccordionItem question="今天有多位收银员使用同一个收银台">

有两种方式：

- **每位收银员单独关账**（最准确）：每位收银员在关账前，先在报表中按自己的用户账户筛选，各自清点经手的金额并核对自己的账目。钱箱可在班次之间进行实物交接，每次交接相当于一次小型关账。
- **全天统一关账**：将收银员筛选条件保持为*全部*，在日终统一核对钱箱。这样更快，但较难确定差异由谁造成。

报表界面上的收银员筛选条件也用于筛选明细，没有独立的按收银员查看面板。

  </AccordionItem>

  <AccordionItem question="今天一位收银员在多家店铺工作">

退出一家店铺，再登录另一家店铺；每次会话都会通过 `_pos_store` 订单元数据关联到正确的店铺。关账时，切换报表界面上的**店铺**筛选条件，按店铺分别对账。

如果要在日终对整个站点关账，还应将店铺筛选条件设为*全部*，进行一次整体关账，便于交叉核对各店铺的关账结果。

  </AccordionItem>

  <AccordionItem question="每家店铺由不同的人负责关账">

这是常规做法。各店铺的关账负责人登录自己的店铺，按该店铺和当天日期范围生成报表，再核对该店的钱箱。站点所有者可在第二天早上通过 **WP Admin → WooCommerce → 分析** 查看所有结果，该页面会汇总各店铺的数据。

  </AccordionItem>

  <AccordionItem question="开始关账后又完成了一笔销售">

不要直接将其计入本次关账。请选择以下一种做法：

- **延长报表时段**以包含该笔销售（同时调整实点现金，将新增销售金额计入），或者
- **留到明天的报表中处理**，在明天的开班记录表中，将这笔较晚销售的现金标记为结转款。

选定一种规则并始终遵循，来回切换做法会增加账目审计的难度。

  </AccordionItem>
</Accordion>

## 最佳实践 {#best-practices}

- **每天关账。** 跳过一天就意味着要核查两天的差异，难度会大得多。
- **打印并归档报表**，即使当天交易很少也应如此。纸质记录是您在审计或争议中的保障。
- **不要共用用户账户。** 每位收银员使用各自的 WordPress 用户账户，收银员筛选条件才能准确生成个人报表。
- **每周与 WooCommerce 分析数据交叉核对**(`WP Admin → WooCommerce → Analytics`)，两者使用相同数据，只是呈现方式不同。如果总额不一致，通常是因为暂存订单较晚才完成，或退款是在 WP Admin 而非 POS 中处理的。
- **保持备用金金额固定。** 经常更改开班备用金容易导致计算错误。
