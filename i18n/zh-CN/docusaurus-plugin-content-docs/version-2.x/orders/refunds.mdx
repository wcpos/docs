:::info Pro 功能
在 WCPOS 中退款需要 [WCPOS Pro](../getting-started/pro-license.mdx)。没有 Pro 时，**订单**页面仅供预览：请在 WP Admin 的 **WooCommerce → 订单**中办理退款。
:::

本页详细介绍退款：退款表单的各个部分、退款去向、各类失败提示的含义，以及退款后订单的显示内容。有关从打开订单到确认退款的操作步骤，请参阅[收银时退款](../pos/refunds.mdx)。

## 发起退款 {#starting-a-refund}

退款需要网络连接，且订单必须已传送到店铺，状态为**已完成**、**处理中**或**保留**（参阅[何时显示退款操作](#when-the-refund-action-appears)）。请等到出现“已处理金额为 *(金额)* 的退款”后再交付现金。如果出现其他提示，请参阅[退款失败时](#if-a-refund-fails)。

打开的订单：

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[347, 0], [42, -11], [28, -26], [28, -26], [28, -26], [28, -26], [28, -26]]} alt="打开的现金订单：日期、店铺和收银员信息、商品、总计和现金付款，以及底部的删除、退款、同步、关闭、收据和重新打开">

1. **订单详情** — 付款时间、所在店铺、经手收银员以及创建位置。
2. **付款** — 客户的付款方式。这决定了退款可以退到哪里；请参阅[何时使用现金或原付款方式退款](#when-to-use-cash-vs-original-method)。
3. **删除** — 删除订单，不会退款。
4. **退款** — 打开退款表单，标题为**退款订单 #*(编号)***。
5. **同步** — 从店铺重新获取订单。
6. **收据** — 订单当前的收据。
7. **重新打开** — 将订单放回购物车以进行修改。

</JourneyShot>

### 何时显示退款操作 {#when-the-refund-action-appears}

只有已传送到店铺，且状态为**已完成**、**处理中**或**保留**的订单才会显示**退款**。

<details>
<summary>找不到退款按钮？</summary>

**待付款**、**已取消**、**失败**或已全额**退款**的订单、仍在 POS 中未结清的销售（**POS 未结清**或 **POS 部分付款**），以及仍在等待同步的订单都不会显示此按钮。如需为这些订单退款，请前往 WP Admin 的 **WooCommerce → 订单**。如果订单状态已在 WP Admin 中更改，请点击**同步**，然后重新打开订单。如果 WCPOS 提示本地数据库不可用，则必须重新加载应用才能退款。

</details>

## 退款表单 {#the-refund-form}

打开表单时会列出订单的所有商品行，但尚未选择任何退款项目。下图填写了同一订单的第二次退款：退回一只手表，此前已退款 $45.00。

<JourneyShot manifest={manifest} device="tablet" step={4} alt="一个此前已退款一次的订单，其退款表单以面板形式显示在订单界面上方" />

表单的各个部分：

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[52, 0], [150, 0], [332, 43], [345, 97], [461, -124], [118, -39], [60, 48], [-12, -30]]} maxWidth={560} alt="此前已退款一次的订单的退款表单：总计和此前已退款、将最后一只手表设为退款的商品表格、自定义金额、原因“尺寸不合适”、退款总额 $45.00 和处理退款">

1. **总计** — 订单总额。
2. **此前已退款** — 之前已退回的金额。仅在首次退款后显示。
3. **数量** — 该行仍可退款的数量，即购买数量减去此前已退款的数量。如果 WCPOS 无法加载店铺的退款记录（例如处于离线状态），则显示全部购买数量；退款金额仍以剩余可退金额为上限。
4. **退款数量** — 本次要退回的该行商品数量。
5. **退款金额** — 该行的退款金额，包含税费。
6. **自定义金额** — 不关联任何商品行的额外金额，将加到各行退款金额之上。
7. **原因** — 可选。随退款保存，并显示在[退款](#refunds-section)部分的对应卡片中。
8. **处理退款** — 请求确认。只有**退款总额**大于零且不超过剩余可退金额时，此按钮才可用。

</JourneyShot>

<details>
<summary>表格各列，按显示顺序排列</summary>

| 列 | 显示内容 |
|---|---|
| **商品** | 该行的名称 |
| **价格** | 单价，是否含税取决于店铺在购物车中显示价格的方式 |
| **数量** | 仍可退款的数量 |
| **退款数量** | 本次要退回的数量 |
| **退款金额** | 退款数量 × 该行单价，再加上该行按比例分摊的税费 |

</details>

底部的**退款总额**为各行金额与**自定义金额**之和，会随输入实时更新。

### 全部数量与部分数量退款 {#refunding-whole-vs-partial-quantities}

没有单独的全额退款按钮。如需退回整个订单，请将每行的**退款数量**设为该行完整的**数量**，并在**自定义金额**中输入运费和其他费用：表格仅列出订单商品，运费和其他费用没有单独的行。如需部分退款，只需设置要退回的商品行和数量。

自定义金额作为一笔总额退回，不单独拆分税费。

如果商品启用了库存管理，退款商品的数量会加回库存。

## 何时使用现金或原付款方式退款 {#when-to-use-cash-vs-original-method}

- 通过支持从 WCPOS 退款的读卡器或付款方式**刷卡付款**：选择**退回至 *(付款方式)***。
- 如果店铺允许，**刷卡客户改为收取现金退款**：选择**现金退款**，并从钱箱取出现金交给客户。
- **现金付款**：退款方式为现金，表单不会询问。

:::warning
如果通过刷卡终端退款，请勿选择**现金退款**。现金退款会减少收银机记录的钱箱预期现金，但实际上没有现金支出，因此结班清点时会出现现金盈余。
:::

<details>
<summary>通过独立刷卡终端付款？</summary>

如果客户通过未与 WCPOS 连接的独立刷卡终端付款，请在该终端或服务商控制面板中将款项退回银行卡，然后在 WP Admin 的订单中记录这笔退款。

</details>

<details>
<summary>原付款方式不可用？</summary>

如果付款方式不支持从 WCPOS 退款，**退回至 *(付款方式)*** 会变灰，表单会提示“此订单无法通过原付款方式退款。”

如果 WCPOS 无法检查付款方式，表单会提示“无法验证是否可通过原付款方式退款。仍可使用现金退款。”，并选中**现金退款**。只有在实际交付现金时才选择此项。

</details>

## 退款失败时 {#if-a-refund-fails}

重试前请先阅读提示。大多数失败提示表示未发生退款，但有一种提示表示 WCPOS 无法确定结果。

:::warning 重试前请先检查
**“WCPOS 无法确认这笔退款是否成功。”** 表示退款请求已发送，但 WCPOS 未收到明确答复，因此退款可能已经成功。重试前，请打开订单并查看[退款](#refunds-section)部分。每次尝试都会发起一笔新退款，因此再次点击**处理退款**可能会给客户重复退款。如果订单尚未更新，请在 WP Admin 中检查。参阅 [PAYMENT311](../error-codes/PAYMENT311.mdx)。
:::

其他所有提示都表示未发生退款，例如离线时：

<JourneyShot manifest={manifest} device="tablet" step={7} alt="离线状态下的订单界面，退款表单已打开，屏幕顶部显示警告提示。由于无法加载退款记录，手表的数量再次显示为 2" />

<JourneyShot manifest={manifest} device="tablet" step={6} maxWidth={640} alt="离线提示特写：您处于离线状态，因此未进行退款。请重新连接互联网后重试，旁边有帮助按钮" />

<details>
<summary>其他提示：未发生退款</summary>

解决提示指出的问题后，再次点击**处理退款**：

- **“您处于离线状态，因此未进行退款。”** 请重新连接互联网后重试。
- **“WCPOS 当时在后台运行，因此未进行退款。”** 退款请求发送前，应用已被切换到后台。请现在重试。
- **“未进行退款，请登录后重试。”** 登录已过期。请登录后重试。
- **店铺自身的提示，或“处理退款失败”。** 店铺或付款方式拒绝了退款，例如账户可能没有退款权限，或某个值不被允许。请阅读提示并解决其中指出的问题；如果实际交付现金，也可以选择**现金退款**。

</details>

## 退款后 {#after-the-refund}

订单从店铺刷新后，就会显示退款。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[52, 409], [97, -102], [67, -50]]} alt="部分退款 $45.00 后的订单：总计下方显示红色退款行 -$45.00 和净付款 $83.00，再下方是 $128.00 的现金付款">

1. **退款** — 截至目前已退回的金额，从总计中扣除。
2. **净付款** — 替代**总计**，为订单实收金额减去退款。
3. **付款** — 原始付款保持不变。下方的**退款**行显示已退回的金额。

</JourneyShot>

订单顶部的状态标记显示**部分退款**。订单本身的状态不变，例如订单列表中仍显示为**已完成**。全部退款后，WooCommerce 会将订单设为**已退款**，订单上不再显示**退款**操作。

### 退款部分 {#refunds-section}

向下滚动订单至**退款**部分。标题中显示退款次数和总金额，每笔退款各有一张卡片。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[-391, -137], [-51, -85], [16, -28], [-24, 0]]} alt="付款下方的退款行，以及包含一张卡片的退款部分：退款 #229730、不到一分钟前、-$45.00、操作人 2、原因“表带太小”，以及退款手表的数量、税费和总计">

1. **退款** — 位于**付款**下方，显示已退回的金额。
2. **次数和总额** — 订单的退款次数及其金额之和。
3. **操作人** — 办理退款的人，显示其 WordPress 用户 ID（此处为 2），而非姓名。
4. **收据** — 打开这笔退款的退款收据。

</JourneyShot>

每张卡片开头显示**退款 #*(id)***，即该笔退款自身的编号，以及退款时间。金额显示在右侧。下方依次显示带引号的原因和退款涵盖的商品行：商品和 SKU，以及以负数显示的数量、税费和总计。

如果 WCPOS 无法获取退款详情，此部分会显示“无法加载退款详情。”以及**重试**按钮。下方的**本地退款摘要：** 列出设备已保存的每笔退款的信息：编号、原因（或“未提供原因”）和金额。如果设备未保存任何信息，则显示“没有可用的本地退款摘要。”恢复连接后，请点击**重试**。

### 退款收据 {#refund-receipts}

退款卡片上的**收据**会打开仅对应这笔退款的**退款收据**，可供打印或保存为 PDF。退款收据没有电子邮件按钮。它列出退款商品行及其税费，并在标题为**退款至**的付款部分说明款项去向。选择模板和打印机后，点击**打印收据**或**下载 PDF**。

订单底部的**收据**会打开订单当前的收据。详细收据中会显示**已退款**和**净总额**行。请参阅[重新打开收据](../receipts/at-checkout.mdx#reprinting-receipts)。

### 现金退款与钱箱 {#cash-refunds-and-the-drawer}

收银机开班期间办理的现金退款会减少钱箱的预期现金，并在收银机面板的**现金退款**下列出。请参阅[现金退款与钱箱](../pos/refunds.mdx#drawer)。

### 退款经手人 {#who-made-the-refund}

从 WCPOS 发起的每笔退款都会记录收银员、店铺和退款去向（现金或付款方式）。如果收银机有正在进行的班次，退款也会关联到该收银机和班次，计入对应钱箱的账目。请参阅[对账](../reports/reconciliation.mdx)。

## 须知 {#things-to-know}

- **退货通过退款处理。** 接收退货时，请为客户付款时的原订单退款，不要新建销售。
- **优惠券保持不变。** 退款会退回表单上的金额，不会更改订单的优惠券。
- **退款需要网络连接。** 必须能够连接到店铺；如果退回原付款方式，还必须能够连接到支付服务商。
- **全额退款的订单没有剩余可退金额。** 其状态为**已退款**，不再显示**退款**操作。
