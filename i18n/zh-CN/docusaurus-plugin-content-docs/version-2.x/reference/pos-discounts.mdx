要为一笔销售减价，可选择以下三种方式之一。[购物车折扣](../pos/cart/discounts.mdx)是收银员了解这三种方式的主要页面。开发者和报表使用者可直接查看[各类折扣的记录位置](#where-recorded)。

## 收银时减价 {#at-the-till}

- **降低单件商品的价格** — [修改其价格](#change-price)。
- **降低整个订单的金额** — 使用**添加折扣**为[整个订单减价](#add-discount)。
- **顾客持有优惠券** — [应用店铺优惠券](#apply-coupon)。

这些方式能否在同一订单中叠加，取决于[优惠券的规则](../coupons/applying-coupons.mdx#more-than-one)。**添加折扣**不能与标记为**仅限单独使用**的优惠券叠加。

### 修改单件商品的价格 {#change-price}

1. 点击商品行上的价格，即可打开数字键盘。
2. 按下百分比按键（−5%、−10%、−15%），或输入新价格。
3. 按下勾号（**✓**）完成操作；在手机上则按下**完成**。行总额会变为数量 × 新价格。

<JourneyShot manifest={cartManifest} device="tablet" step={1} offsets={[[-68, 0], [56, 21], [-88, -24], [65, 0], [-24, 0]]} alt="在价格为 $45.00 的商品行上打开价格数字键盘，并按下 −10%：新价格为 $40.50，上方显示 $45.00 −10%，另有三个百分比按键、数字按键、删除键和完成键">

1. **新价格** — 商品的新售价，以及根据原价格计算新价格的过程。
2. **百分比按键** — 每个按键会按对应百分比降低该行的价格。亮起的按键（此处为 −10%）表示当前使用的比例；再次按下即可恢复原价格。可在**购物车设置**中的[**快捷折扣**](../pos/cart/index.mdx#quick-discounts)下配置这些按键。
3. **数字** — 也可以直接输入新价格。
4. **删除** — 删除最后一位数字。
5. **✓** — 确定新价格。

</JourneyShot>

如果操作有误：

- **按错百分比按键** — 在按下 **✓** 之前按另一个按键，即可替换先前的选择。
- **想恢复原价格** — 在按下 **✓** 之前，再次按下亮起的按键。按下 **✓** 之后，则需再次点击价格并输入所需价格。
- **关闭数字键盘** — 点击键盘外部会保留已输入的价格。按下实体键盘上的 **Escape** 则会保留原价格。

其他解决方法：[出现问题时](#if-something-goes-wrong)。更多信息：[为单件商品减价](../pos/cart/discounts.mdx#quick-discounts)。

### 为整个订单减价 {#add-discount}

1. 按下购物车顶部的 **+**，然后选择**添加折扣**。
2. 在**快捷折扣**选项卡中输入金额，并选择 **$** 或 **%**。
3. 按下**添加折扣**。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[0, 0], [0, 0], [0, 0], [12, 46], [50, -52]]} alt="购物车中有一块售价为 $45.00 的 Aim Analog Watch，上方打开了添加折扣对话框的快捷折扣选项卡：其中有快捷折扣和优惠券选项卡、数值 10、已设为百分比的美元与百分比切换控件，以及添加折扣按钮">

1. **快捷折扣** — 按固定金额或百分比为整个订单减价，而非仅针对某一行。
2. **优惠券** — 也可以使用店铺中的优惠券。请参阅[应用优惠券](#apply-coupon)。
3. **金额** — 点击后用数字键盘输入。
4. **$ 或 %** — 减去固定金额，或按订单金额的百分比减价。
5. **添加折扣** — 将折扣应用到订单。

</JourneyShot>

折扣会显示在金额汇总区域：

<JourneyShot manifest={cartManifest} device="tablet" step={5} offsets={[[12, 46], [100, 0], [50, 0], [0, 0]]} alt="售价为 $45.00 的手表应用 10% 折扣后的购物车：行总额 $45.00 带有删除线，下方显示 $40.50，小计为 $45.00，折扣（10%）行减去 $4.50 并带有移除按钮，结账显示 $40.50">

1. **行总额** — 带删除线的折扣前价格，以及顾客现在需支付的金额。
2. **小计** — 折扣前的订单金额。
3. **折扣（10%）** — 折扣及其减免金额。仅显示**折扣**时表示固定金额折扣。按下 **✕** 即可移除。
4. **结账** — 新的总额。

</JourneyShot>

要撤销折扣，请按下该行上的 **✕**。各行总额会恢复，已修改的商品行价格则保持不变。其他解决方法：[出现问题时](#if-something-goes-wrong)。更多信息：[为整个订单减价](../pos/cart/discounts.mdx#order-level-discounts)。

### 应用优惠券 {#apply-coupon}

1. 按下购物车顶部的 **+**，然后选择**添加折扣**（优惠券也在其中）。
2. 切换到**优惠券**，按下**选择优惠券**，然后输入部分优惠码进行查找。
3. 点击优惠券，然后按下**应用**。

<JourneyShot manifest={couponManifest} device="tablet" step={1} offsets={[[0, 0], [0, 0], [-24, 0], [-30, 0], [-30, 0], [0, -34], [0, -44]]} alt="添加折扣对话框的优惠券选项卡，优惠券列表已展开：其中有快捷折扣和优惠券选项卡、选择优惠券字段、搜索框、显示类型和金额的优惠券、新建优惠券按钮以及应用按钮">

1. **快捷折扣** — 无需优惠券，按固定金额或百分比为订单减价。请参阅[为整个订单减价](#add-discount)。
2. **优惠券** — 店铺中的优惠券。
3. **选择优惠券** — 打开列表。选中优惠券后，其优惠码会显示在此处。
4. **搜索优惠券** — 输入优惠码或描述的任意部分。
5. **优惠券** — 显示其优惠码、描述或类型，以及减免金额。
6. **新建优惠券**（WCPOS Pro）— 立即创建优惠券并应用于本次销售。
7. **应用** — 检查此订单是否符合优惠券规则，然后应用优惠券。

</JourneyShot>

优惠券会显示在金额汇总区域；如果无法使用，POS 会说明原因：

<JourneyShot manifest={couponManifest} device="tablet" step={3} offsets={[[-28, 0], [100, 0], [40, 0], [40, 0], [0, 0]]} alt="应用两张优惠券后的购物车：添加菜单、小计、每张优惠券各占一行并显示优惠码、移除按钮及减免金额，商品总额中的原金额带有删除线，以及结账按钮">

1. **+** — 再次打开**添加折扣**，添加另一张优惠券。
2. **小计** — 应用优惠券前的订单金额。优惠券行位于其下方。
3. **优惠券** — 显示优惠码、用于移除的 **✕** 和减免金额。
4. **下一张优惠券** — 每张优惠券各占一行，按应用顺序排列。
5. **结账** — 为订单收款。请参阅[结账](../pos/checkout/index.mdx)。

</JourneyShot>

选错了优惠券？按下该行上的 **✕**，即可恢复其减免的金额。优惠券被拒绝？请参阅[优惠券被拒绝时](#coupon-refused)。更多信息：[应用优惠券](../pos/cart/discounts.mdx#coupon)和[使用优惠券](../coupons/applying-coupons.mdx)。

## 出现问题时 {#if-something-goes-wrong}

- **商品行价格有误** — 再次点击价格并输入正确值。在按下 **✓** 之前，再次按下亮起的百分比按键即可恢复原价格。
- **误关数字键盘** — 点击键盘外部会保留已输入的价格；按下 **Escape** 则会保留原价格。
- **订单折扣有误** — 按下金额汇总区域中对应行上的 **✕**。各行总额会恢复，已修改的商品行价格则保持不变。
- **优惠券有误** — 按下该行上的 **✕**，即可恢复其减免的金额。
- **优惠券被拒绝** — 请参阅[优惠券被拒绝时](#coupon-refused)。

### 优惠券被拒绝时 {#coupon-refused}

对话框会保持打开，并以红色文字说明原因。其中两种原因与订单上的其他折扣有关：

- **…不能与其他优惠券叠加使用**或 **…已应用于订单，且不能与其他优惠券叠加使用** — 标记为**仅限单独使用**的优惠券必须单独使用。请移除与之冲突的优惠券，或者保留原优惠券，不添加新的优惠券。
- **排除促销商品** — 收银时降价的商品会被视为促销商品。优惠券会跳过该商品；对于整单固定金额优惠券，只要购物车中有该商品，就完全无法使用。请移除该商品，或选择其他优惠券。原因说明：[哪些商品被视为促销商品](#exclude_sale_items-behaviour)。

其他所有提示及相应处理方法：[收银时优惠券被拒绝](../coupons/applying-coupons.mdx#refused)。

## 各类折扣的记录位置 {#where-recorded}

:::note 面向开发者和报表使用者
收银操作无需了解以下内容。这些内容面向开发者，以及通过报表、导出文件或其他插件查看 WCPOS 订单的人员。
:::

每种方式在订单中的记录位置各不相同：

- **修改后的价格**就是该行的价格，记录在 `_woocommerce_pos_data` 元数据和该行的 `subtotal` 中。它**不计入** `discount_total`，也不受任何优惠券规则约束。
- **添加折扣**生成的是优惠券行，其代码为 `pos-discount`，并带有 `_wcpos_quick_discount` 元数据。它**计入** `discount_total`。它适用于所有商品行，包括促销商品，但不能与标记为**仅限单独使用**的优惠券叠加。
- **店铺优惠券**记录为带有该优惠码的优惠券行。它**计入** `discount_total`，并遵循优惠券自身的规则。

此例中，一块售价为 $45.00 的手表在收银时被改价为 $40.00，随后又通过**添加折扣**为订单应用了 10% 折扣：

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[0, 46], [0, 46], [0, -40], [20, 0], [0, 0]]} alt="购物车中有一块 Aim Analog Watch：收银时价格从 $45.00 降至 $40.00，行总额 $40.00 带有删除线，下方显示 $36.00，小计为 $40.00，折扣（10%）行减去 $4.00，结账显示 $36.00">

1. **价格** — 收银时修改后的价格。以单价形式存储在该行的 `_woocommerce_pos_data` 元数据中；该行的 `subtotal` 为此价格 × 数量。请参阅[POS 改价的存储方式](#how-pos-price-overrides-are-stored)。
2. **行总额** — 该行的 `total`，即 `subtotal` 减去分摊到该行的优惠券或**添加折扣**减免额。
3. **小计** — 各行小计之和。它已经按收银时的价格计算，因此订单不会另存一个数值来记录这部分改价。
4. **折扣（10%）** — 通过**添加折扣**生成的条目，即代码为 `pos-discount` 且带有 `_wcpos_quick_discount` 元数据的优惠券行。它计入订单的 `discount_total`。请参阅[添加折扣条目](#add-discount-lines)。
5. **结账** — 订单的 `total`。

</JourneyShot>

此截图中的价格含税：金额汇总下方的 **US** 和 **US AL** 行显示其中所含的税额。购物车显示含税金额，而各行的 `subtotal`、`total` 以及订单的 `discount_total` 存储的都是扣除税额后的金额。订单的 `total` 为含税总额。

## POS 改价的存储方式 {#how-pos-price-overrides-are-stored}

POS 创建的每个商品行都会在 `_woocommerce_pos_data` 行项目元数据中存储单价：

```json
{
  "price": "40.00",
  "regular_price": "45.00",
  "tax_status": "taxable"
}
```

- `price` 是该行的实际销售单价，已包含收银时的任何改价。
- `regular_price` 是商品添加时的常规价格。收银时改价不会改变此值，因此收银时若提高价格，售价就会高于此值。
- [杂项商品](../pos/cart/index.mdx#miscellaneous-products)还会包含 `virtual`、`downloadable` 和 `categories`，以便优惠券规则检查这些属性。

此元数据是单价的权威依据。该行的 `subtotal` 由 `price` × 数量计算得出，再扣除税额并进行舍入；应用优惠券或**添加折扣**后，`total` 会低于它。若需要精确的单价，请从元数据中读取 `price` 和 `regular_price`。

该元数据在 WooCommerce 订单页面中是隐藏的。

<details>
<summary>通过代码读取元数据</summary>

**使用能处理两种格式的解码器。** 旧版应用生成的行以 JSON 字符串形式存储元数据。2.0 应用将其写为对象，因此 WordPress 会存储序列化数组，其中的值可能是数字而非字符串。直接使用 `json_decode()` 无法处理该数组。

新的 POS 订单还包含私有订单元数据 `_woocommerce_pos_version`，用于记录保存订单的 WCPOS 插件版本。收据仍以已存储的行数据格式为准，因为离线创建的订单可能会由比创建它的应用更新的插件处理。

</details>

## 行总额与折扣总额 {#subtotal-model-v190}

WCPOS 记录收银价格的方式，与 WooCommerce 记录促销价格的方式相同：

- `line_item.subtotal` = `price` × 数量，其中 `price` 是收银时的价格。
- `line_item.total` = `subtotal` − 分摊到该行的优惠券和**添加折扣**减免额。
- `order.discount_total` = 仅包含优惠券和**添加折扣**条目的减免额。收银时的改价不会计入其中。

<details>
<summary>计算示例：$45.00 → 收银时改为 $40.00 → $36.00</summary>

不考虑税费：一块常规价格为 $45.00 的手表，收银时输入价格 $40.00，随后通过**添加折扣**应用 10% 折扣。$40.00 − $4.00 = **$36.00**。订单中的存储结果如下：

- `_woocommerce_pos_data.regular_price`：**45.00**
- `_woocommerce_pos_data.price`：**40.00**，即收银时的价格
- `line_items[0].subtotal`：**40.00**，即 40.00 × 1
- `line_items[0].total`：**36.00**，已减去**添加折扣**的减免额
- `discount_total`：**4.00**，仅包含**添加折扣**的减免额
- `total`：**36.00**

收银时改价减去的 $5.00，只有比较 `regular_price` 与 `price` 才能得出。收据会为您完成这一比较；请参阅[收据数据](#receipt-data-exposure)。

</details>

<details>
<summary>v1.9.0 之前的订单</summary>

在 v1.9.0 之前，应用发送的 `subtotal` = `regular_price` × 数量。随后 WooCommerce 会计算 `discount_total` = `subtotal` − `total`，因此收银时改价也会计入折扣。这会导致优惠券计算出错：`recalculate_coupons()` 基于 `subtotal` 计算，因此优惠券按原价格计算。服务器端曾通过 `woocommerce_order_item_get_subtotal` 过滤器，在执行 `recalculate_coupons()` 时绕过此问题。

v1.9.0 改用上述促销价格模型，并移除了该过滤器。在此之前保存的订单仍保留原有数值，因此报表中旧订单的 `discount_total` 可能包含收银时的改价减免额。收据已考虑这种情况：请参阅[收据数据](#receipt-data-exposure)。

</details>

## 添加折扣条目 {#add-discount-lines}

**添加折扣**按固定金额或百分比为整个订单减价。它是一个优惠券行，而不是店铺中的优惠券：

- **代码** — 订单上的第一个条目使用 `pos-discount`，后续依次使用 `pos-discount-2`、`pos-discount-3`，以此类推。
- **元数据** — 优惠券行上的 `_wcpos_quick_discount`：`{ "discount_type": "percent", "amount": "10" }`。`discount_type` 为 `percent`（最高为 100）或 `fixed_cart`；`amount` 是表示正数金额或比例的十进制数字字符串。
- **规则** — 适用于促销商品，包括收银时降价的商品。不能与标记为**仅限单独使用**的优惠券叠加。
- **重新计算** — WCPOS 将优惠券详情存储在该行上，因此在 WooCommerce 订单页面中使用**重新计算**会保留该折扣。

虚拟优惠券仅在 WCPOS 保存 POS 订单时存在：网店前台无法使用 `pos-discount`。如果请求使用的代码已被某张店铺优惠券占用，保存将被拒绝，并提示**快捷折扣代码“…”属于店铺优惠券。请使用其他代码。**

2.0 应用不再通过负数费用减价，而是请求**添加折扣**。插件仍接受旧版应用和其他客户端发送的负数费用行。

## 与优惠券的交互行为 {#coupon-interaction-behaviour}

免费插件支持在收银时应用店铺优惠券；要在收银时创建优惠券，则需要 [WCPOS Pro](../getting-started/pro-license.mdx)。将优惠券应用到包含收银改价的订单时：

1. 优惠券按**收银时的价格**(`_woocommerce_pos_data.price`)计算，而不是按 `regular_price` 计算。
2. 移除优惠券后，该行会恢复为收银时设定的价格。

应用在设备上计算优惠券，因此可在离线时应用优惠券；插件保存订单时，会使用相同的商品上下文重新计算。

如果价格含税，且某行同时应用了多个优惠券或**添加折扣**，应用会先合计该行的折扣，再一次性扣除税额，与 WooCommerce 的做法一致。这样，收银端的行总额与已保存订单的金额会精确到最后一位小数。

### `exclude_sale_items` 的行为 {#exclude_sale_items-behaviour}

如果某行的 `_woocommerce_pos_data.price` 低于其 `regular_price`，该行就被视为促销商品，与 WooCommerce 促销价格的处理方式相同。收银价格等于或高于 `regular_price` 时则不属于促销。因此，启用**排除促销商品**的优惠券：

- 会跳过收银价格低于其 `regular_price` 的商品行；
- 如果是购物车固定金额优惠券，只要购物车中有此类商品，就完全无法使用。这是 WooCommerce 本身对购物车固定金额优惠券的规则。

要更改促销商品的判定方式，请使用下方的 `wcpos_item_is_on_sale` 过滤器。

## 可用过滤器 {#available-filters}

### `wcpos_item_is_on_sale` {#wcpos_item_is_on_sale}

覆盖插件验证优惠券时，对带有 POS 价格数据的商品行是否属于“促销商品”的判定。在 WCPOS 2.0 之前，此过滤器名为 `woocommerce_pos_item_is_on_sale`；该名称仍可使用，但自 2.0 起已弃用，最早将在 2.2 中移除（请参阅[钩子命名](../extensions/index.mdx#hook-naming)）。

<details>
<summary>示例与参数</summary>

```php
add_filter( 'wcpos_item_is_on_sale', function ( $is_on_sale, $product, $item, $pos_data ) {
    // Let coupons with exclude_sale_items apply to lines lowered at the till.
    return false;
}, 10, 4 );
```

- `$is_on_sale`(`bool`)— 该行是否被视为促销商品。默认值：`price < regular_price`。
- `$product`(`WC_Product`)— 商品对象。
- `$item`(`WC_Order_Item_Product`)— 订单行项目。
- `$pos_data`(`array`)— 解码后的 `_woocommerce_pos_data`。

</details>

该过滤器在服务器上运行。收银员仍在向购物车添加商品时，应用自身的促销判定始终使用 `price < regular_price`；保存订单时才会采用服务器的判定结果。

## REST API 端点 {#rest-api-endpoint}

优惠券端点包含在**免费插件**中，因此即使没有 WCPOS Pro，应用请求优惠券时也不会收到 404。

2.0 应用通过 `GET /wp-json/wcpos/v2/coupons` 同步优惠券，该端点使用 POS 读取权限，将请求转发到 WooCommerce 的 `wc/v3/coupons`。收银时创建的优惠券（Pro）会保存为普通 WooCommerce 优惠券，收银员需要具备创建优惠券的权限。

<details>
<summary>适用于 2.0 之前应用版本的 v1 端点</summary>

2.0 之前的应用使用 `/wp-json/wcpos/v1/coupons`。其控制器继承 `WC_REST_Coupons_Controller`，并增加了用于离线同步的 UUID、向所有具备 `access_woocommerce_pos` 权限的用户开放的读取访问，以及在请求包含 `posts_per_page=-1` 和 `fields=id`（或 `fields=id,date_modified_gmt`）时使用的仅获取 ID 的快速处理路径。

</details>

有关哪些角色可以访问哪些端点，请参阅[角色与端点访问权限](./role-endpoint-access.mdx)。

## 收据提供的数据 {#receipt-data-exposure}

收据模板无需自行读取 `_woocommerce_pos_data` 即可获取优惠金额：包括每行的节省金额、每张优惠券或每项**添加折扣**对应的一行记录，以及这两类金额在订单层面的合计。

<details>
<summary>用于折扣和节省金额的收据字段</summary>

- **每个商品行** — `regular_price`、`unit_savings` 和 `line_savings` 提供收银时改价或促销价格带来的节省金额。`discounts` 等于该行的 `subtotal` − `total`，即分摊到该行的优惠券和**添加折扣**减免额，不包含收银时改价。v1.9.0 之前的订单例外，其中可能已包含改价的节省金额：此时 `savings_in_discounts` 为 true。
- **`discounts[]`** — 每个优惠券行对应一条记录，包括**添加折扣**，包含 `label`、`code`、`discount_type` 和 `total`。**添加折扣**的行标签为**折扣（10%）**；固定金额折扣则显示**折扣**，其 `code` 为 `pos-discount`，`discount_type` 为 `percent` 或 `fixed_cart`。
- **合计** — `discount_total`（优惠券和**添加折扣**的减免额，来自 `WC_Order::get_discount_total()`）、`sale_savings_total`（常规价格与实际售价之间的差额，包括收银时改价），以及汇总两者的 `total_saved`。`total_saved` 会消除 v1.9.0 之前订单中重复计算的部分。
- **`total_saved_complete`** — 当某行缺少用于可靠计算合计的价格数据时为 false；此时节省金额合计为 `null`。

各字段均有 `_incl` 和 `_excl` 变体。`Receipt_Data_Builder::get_item_meta_pairs()` 会从 `lines[].meta` 中排除所有以下划线开头的元数据键，包括 `_woocommerce_pos_data`。

</details>

模板示例请参阅[显示常规价格和节省金额](../receipts/receipt-data.mdx#displaying-regular-price-and-savings)及[合计](../receipts/receipt-data.mdx#totals)。
