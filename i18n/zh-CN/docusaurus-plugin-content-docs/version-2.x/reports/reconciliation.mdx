本页面向负责每日对账的人员；有关盘点操作的逐屏说明，请参阅[收银机关班](../pos/reconciliation.mdx)。

- 在报告中[查看交班记录](#closures)，并[阅读记录详情](#closure-detail)。
- 盘点有误时，[复点交班记录](#recount)。
- 将[交班记录导出](#export)为 CSV 文件。
- 先[设置交班规则](#before-your-first-close)，然后[开始当日收银](#opening-the-till)，最后[盘点并关班](#the-close-procedure)。
- 钱箱出现短款或长款时，[查明差额原因](#variance-handling)。

:::note 本页功能需要启用收银机
在[收银机](../settings/wp-admin/registers.mdx#one-register)设置中启用**收银机开班与关班**。关闭此选项时，POS 销售不使用收银班次，因此无需盘点或关班。
:::

收银机开班、盘点、关班以及 WP Admin 中的**导出交班记录**均可免费使用。报告中的**交班记录**视图包含往日记录、复点和**导出 CSV** 功能，需要 [WCPOS Pro](../getting-started/free-vs-pro.mdx#at-a-glance)。

## 查看交班记录 {#closures}

1. 打开**报告**。顶部收银状态栏显示此设备的收银机。收银机[关班](#the-close-procedure)后，状态栏显示**已关班**，然后显示**上次交班**及其编号和**钱箱盘点结果**。
2. 打开交班记录：
   - **免费插件：** 点按**上次交班**，打开该交班记录。
   - **使用 Pro：** 点按状态栏末尾的箭头，打开**交班记录**，查看您有权访问的所有收银班次和交班记录。

要重新打印上次交班记录，请按状态栏上的**打印交班记录**。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[0, -30], [0, -30], [0, -30], [120, -21], [120, -21], [120, -21], [120, -21], [120, -21], [250, 0], [250, 0], [-30, 0]]} alt="报告中的交班记录视图：店铺和收银机、今天和所有收银员、导出 CSV、五张统计卡片、全部、进行中和已关班选项卡、带有打印 X 报告按钮的进行中班次，以及显示实点现金和盘点结果的带编号交班记录列表">

1. **全部** — 所选时段内的所有班次，包括进行中和已关班的班次。
2. **进行中** — 仍在进行的收银班次。
3. **已关班** — 仅显示带编号的交班记录。
4. **班次** — 班次数量，包括进行中和已关班的班次。
5. **开班现金** — 备用金。
6. **现金变动** — 现金销售额减去现金退款，再加上存入现金、减去取出现金。
7. **关班现金** — 实点金额及盘点次数。
8. **差额** — 所选时段内的差额合计，以及**短款**、**长款**和**相符**的盘点次数。
9. **进行中班次** — 仍未关班的收银机、开班时间、开班人员和销售笔数，以及**应有**现金。**打印 X 报告**可打印当前状态。
10. **交班记录** — **交班 N** 及其收银机、开班 → 关班时间和关班人员、实点现金，以及**相符**、短款或长款的结果。点按可[阅读交班记录](#closure-detail)。
11. **导出 CSV** — 保存列表中的交班记录。请参阅[导出交班记录](#export)。

</JourneyShot>

- 在手机上，每条交班记录的下方用一行显示数据：**应有 … · 实点 … · 差额 …**，状态标记显示在其下方。
- 每天都有一个标题，显示当天的实点现金和盘点结果。列表每次加载 50 条；末尾的**加载更多**可加载接下来的 50 条。
- 与[报告](./index.mdx#scope)页面一样，顶部的时段、店铺和收银机以及**所有收银员**可用于筛选列表。交班记录可追溯至过去 92 天。
- 交班记录的状态标记说明盘点后发生的变化：**已更正**（已复点，或有延迟到达的销售或现金变动）、**未同步**（尚未传至店铺）或**已转至**另一家店铺。
- 交班记录需要联网。离线时，视图显示**离线时不可用**，且无法打开此设备从未打开过的交班记录。

## 阅读交班记录 {#closure-detail}

点按一条交班记录。在平板电脑上，记录会在列表旁打开，按 **×** 或**关闭**可返回列表。下面的示例与上面的盘点不同：这是交班 30，一笔延迟到达的销售在关班后改变了其结果。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[112, -26], [112, -26], [112, -26], [370, 0], [200, -188], [195, 0]]} alt="列表旁打开的交班 30：店铺、收银机、时间和关班人员，实点、应有及短款 27.50 美元的结果，收银员备注，原记录为短款 2.50 美元的提示，从备用金到 25 美元的延迟更正再到钱箱应有金额的明细，以及复点、关闭和打印交班记录">

1. **实点** — 关班时盘点的现金。
2. **应有** — 收银机计算的应有金额。
3. **差额** — 实点金额减去应有金额的结果：**相符**、短款或长款。
4. **备注** — 收银员盘点时填写的备注。
5. **钱箱** — 从**备用金**（收银机的开班时间和开班人员）开始，列出现金销售、现金退款、存入现金、取出现金及所有**延迟更正**，直至**钱箱应有金额**和**实点**金额的各项明细。
6. **复点…**、**关闭**和**打印交班记录** — [重新盘点](#recount)钱箱、关闭面板或重新打印交班记录。

</JourneyShot>

如果交班记录在关班后发生变化，钱箱明细上方会显示说明。此处显示**原记录 $3,162.50 · −$2.50 短款**：一笔 $25.00 的销售在盘点后才传至店铺，因此**延迟更正**将**应有**金额提高至 $3,190.00，交班记录现在显示短款 $27.50。原交班记录不会被改写：更正会单独列在旁边。

交班记录下方还包括：

- **其他付款方式** — 各种其他付款方式的总额，例如**银行卡**。
- **班次** — **收银员**、**销售额**、**售出商品数**、**折扣**、**平均每笔销售额**和**开箱次数**。
- **纸质交班记录** — **已打印一次**、**已打印 N 次**或**尚未打印**。
- **更正** — 每次**复点**、**延迟销售**和**延迟现金变动**：操作人员、经理审批时的**审批人**及经理姓名、原因和时间。上方一行显示最初记录的金额和最终金额，例如 **1 次复点后的最终金额为 …**。

## 复点交班记录 {#recount}

盘点有误时（例如第二天早上发现一袋硬币，或有纸币卡在钱箱中），应复点交班记录，而不是修改下次开班的备用金。在交班记录上按**复点…**。下面的示例不是交班 30，而是交班 31，实点金额为 $4,047.50。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[170, 0], [170, 0], [0, 0], [0, 0], [60, -38]]} alt="交班记录上方的复点面板：实点现金和实点银行卡金额输入框、按纸币和硬币盘点、复点原因、需输入 WordPress 用户名和密码的经理审批，以及表单填完前呈灰色的记录盘点按钮">

1. **实点现金** — 此次盘点的现金。
2. **实点银行卡金额** — 交班记录上的每种其他付款方式都有一个类似的输入框。
3. **按纸币和硬币盘点** — 与关班时相同的盘点工具。
4. **复点原因** — 必填，最多 500 个字符。
5. **记录盘点** — 保存复点结果。所有输入框都填入金额并填写原因后，此按钮才会启用；如果显示**经理审批**，还需输入经理的用户名和密码。

</JourneyShot>

原因下方的**经理审批**要求输入经理的 WordPress 用户名和密码。拥有**审批交班**权限的用户不会看到此项（参阅[访问权限](../settings/wp-admin/access.mdx#till-permissions)）。

原始数据与新数据会一并保留，交班记录显示**已更正**。复点需要联网，且交班记录必须已保存到店铺。离线时，**复点…**呈灰色，面板显示**联网后可复点**。如果交班记录仍仅保存在此设备上，则显示**同步此交班记录后可复点**。

## 导出交班记录 {#export}

- **从 POS 导出（Pro）：** 在交班记录视图中，按**导出 CSV**，即可保存列表中的交班记录。
- **从 WP Admin 导出（免费版和 Pro）：** 前往 `WP Admin > POS > 设置`，在**工具**下选择**导出交班记录**，然后按**下载 CSV**。这会保存所有交班记录。

<Accordion>
  <AccordionItem question="POS 导出包含哪些内容">

导出所选时段、店铺、收银机和收银员对应的列表中的交班记录，文件名为 `closures-<from>-<to>.csv`。在浏览器中会下载文件；在应用中会打开分享面板。每行包含营业日期、交班编号、收银机、店铺、开班和关班时间及关班人员，然后是每种付款方式的应有金额、实点金额和差额，以及**未同步**或**已更正**状态。选择**进行中**选项卡时无法导出：进行中的班次还不是交班记录。

  </AccordionItem>

  <AccordionItem question="WP Admin 导出包含哪些内容">

导出您有权访问的店铺的所有交班记录，不限日期范围，内容完全按关班时的记录保留：编号、收银机、营业日期、备用金、实点和应有总额、差额、各付款方式和税率，以及累计总额。需要具有管理 POS 和查看报告权限的用户才能导出。

  </AccordionItem>
</Accordion>

## 首次关班前 {#before-your-first-close}

在 `WP Admin > POS > 设置 > General` 的**收银机**下完成以下一次性设置（参阅[收银机](../settings/wp-admin/registers.mdx#one-register)）。使用 Pro 时，这些是站点默认设置：店铺可在其**收银机**页面的**钱箱规则**下更改规则，每台收银机也有各自的备用金（参阅[店铺的收银机页面](../settings/wp-admin/registers.mdx#store-registers)）。

<Accordion>
  <AccordionItem question="三项关班设置">

- **开班备用金**会在收银员开班时自动填入金额。通常收银机会准备 $100–$200 的小额纸币和硬币。开班卡片还提供**上次盘点金额**，即上次关班时的实点金额。
- **盘点差额超过 … 时请经理审批**：差额超过此值时，收银机需经经理审批才能关班。关闭此选项后，无论差额多少，都无需审批即可关班。
- **在 … 提醒收银员关班**：超过此时间后，收银机显示**已超时**，面板按钮显示**收银机关班 · 已超过**指定时间。

</AccordionItem>

  <AccordionItem question="谁来盘点，谁来审批">

具有*查看报告*权限的收银员可在盘点时看到应有现金金额。没有此权限的收银员则进行**盲盘**：看不到应有金额、差额和交班详情。审批需使用经理账号，且不能是正在关班或为该收银机开班的收银员账号。请参阅[访问权限](../settings/wp-admin/access.mdx)。

  </AccordionItem>

  <AccordionItem question="一个钱箱对应一台收银机">

同一收银柜台上的所有设备共用一台收银机及其班次，因此钱箱只需盘点一次。第二个钱箱对应第二台收银机（Pro）。请参阅[店铺、收银机和设备](../stores/registers-and-devices.mdx)。

  </AccordionItem>
</Accordion>

## 收银机开班 {#opening-the-till}

将备用金放入钱箱。购物车显示**收银机开班**，并已填入**钱箱现金**金额。清点备用金，如金额不符则更正，然后按**收银机开班**。未开班时，POS 只能查询价格；卡片上的**上次交班**一行可打开收银机面板，查看上次交班记录。操作步骤请参阅[收银机开班](../pos/register/index.mdx#open)。

如果收银机已在其他设备上开班，则不会要求输入备用金：此设备会加入该班次（[REGISTER221](../error-codes/REGISTER221.mdx)）。

## 班次期间 {#during-the-shift}

点按栏中的头像，再点按**钱箱内**，即可打开**收银机面板**。这是唯一的入口：栏中没有收银机按钮。面板显示**钱箱内**的现金、**本班销售额**、**存入现金**、**取出现金**和**无销售开箱**，接着是**钱箱应有金额**，点按可展开从备用金开始的计算明细。如有相关数据，还会在**打印 X 报告**和**收银机关班**之前列出**其他付款方式**（银行卡及所有非现金方式）和**上次交班**。带标注的面板请参阅[存入和取出现金](../pos/register/index.mdx#cash-movements)。

<Accordion>
  <AccordionItem question="不涉及销售的现金变动">

现金放入钱箱时使用**存入现金**，现金从钱箱取出时使用**取出现金**（如转存保险柜或从钱箱付款给供应商）。每笔都需填写金额和原因。如误录了现金变动，可在收银机仍处于开班状态时，按该行的**作废**。

  </AccordionItem>

  <AccordionItem question="打开钱箱兑换零钱">

按**无销售开箱**。面板会询问**为什么打开钱箱？**：选择**兑换零钱**、**操作失误**或**检查钱箱**，也可选择**其他…**并输入原因，然后按**打开钱箱**。此操作不产生资金变动，但会记录开箱次数：交班记录列有**无销售开箱**和**开箱次数**。

  </AccordionItem>

  <AccordionItem question="班次中途检查钱箱">

**打印 X 报告**可打印班次的当前情况，不会关班。**报告**顶部的收银状态栏显示同样的计算：**开班备用金 + 现金销售额 − 现金退款 = 钱箱应有金额**；如果班次中有现金存取，还会包含**存入现金**和**取出现金**（参阅[收银状态栏](./index.mdx#closures)）。

  </AccordionItem>

  <AccordionItem question="将订单挂单，不要直接放弃">

挂单会出现在[订单](../orders/index.mdx)中；放弃的购物车则不留记录。每次都以相同方式使用优惠券或商品行[折扣](../pos/cart/discounts.mdx)，以确保交班记录口径一致。

  </AccordionItem>

  <AccordionItem question="不关班直接交接">

点按头像，然后在**交接给**下选择下一位收银员，或选择**其他账号…** 登录其他账号。每个姓名旁会显示其未结购物车数量。钱箱保持开班状态，POS 会以该收银员身份重新加载。请参阅[收银员面板](../pos/register/index.mdx#cashier-sheet)。

  </AccordionItem>
</Accordion>

## 盘点并关班 {#the-close-procedure}

1. 完成最后一笔销售后，在收银机面板中按**收银机关班**。盘点期间，商品区域显示**正在盘点钱箱。盘点后可添加商品。**
2. 清点钱箱内的所有现金，包括备用金，然后在**实点现金（含备用金）**中输入金额，或使用**按纸币和硬币盘点**逐项点按录入。
3. 在**其他付款方式**下输入刷卡终端的批次总额，以及其他各付款方式的总额。
4. 如果**应有**金额显示钱箱有短款或长款，请重新盘点，并按照[差额处理](#variance-handling)逐项检查。在**备注**中说明发现的情况。
5. 按**关班并打印**。如果按钮显示**审批并关班**，则需由经理在此设备上审批；审批需要联网。
<Accordion>
  <AccordionItem question="谁可以审批？">

盘点差额超过限额时，按钮显示**审批并关班**。经理需在此设备上输入自己的 WordPress 用户名和密码。店铺不会接受正在关班或为该收银机开班的收银员审批。盲盘也不例外：收银员虽然看不到差额，但店铺会检查差额并要求审批。如果在经理审批后修改盘点金额，则需经理重新审批。如审批被拒绝，请参阅 [REGISTER301](../error-codes/REGISTER301.mdx)。

  </AccordionItem>
</Accordion>

如果有顾客前来，可按顶部的 **‹** 返回销售；关班前需重新盘点。逐屏说明请参阅[收银机关班](../pos/reconciliation.mdx#count)。

<JourneyShot manifest={eodManifest} device="tablet" step={2} offsets={[[-29, 0], [-55, 0], [-35, 0], [-29, -23], [-30, 0], [-30, 0], [-29, 0], [-29, 0], [61, -38]]} alt="盘点钱箱：正在盘点钱箱提示后方的商品变暗，大框中的实点现金，同一区块中的应有金额和差额，备注，按纸币和硬币盘点，其他付款方式，以及关班并打印">

1. **‹ 返回销售** — 退出盘点，继续销售。
2. **实点现金（含备用金）** — 钱箱内的现金金额。
3. **点按金额以编辑** — 重新显示数字键盘。
4. **应有** — 收银机计算的应有金额。进行盲盘的收银员看不到此金额或差额。
5. **相符** — 盘点差额：显示带勾的**相符**，或**短款**或**长款**金额。
6. **备注** — **说明差额原因**。备注会保存在交班记录中。
7. **按纸币和硬币盘点** — 每清点一张纸币或一枚硬币，就点按相应面额一次。金额会变为其合计值；按**清除**可重新开始。
8. **其他付款方式** — 本班次使用的每种其他付款方式都有一个输入框，例如**实点银行卡金额**，用于填写终端或签购单上的总额。
9. **关班并打印** — 写入交班记录。差额超过您设定的限额时，按钮显示**审批并关班**。

</JourneyShot>

系统会自动计算应有现金：

> **应有现金 = 开班备用金 + 现金销售额 − 现金退款 + 存入现金 − 取出现金**

关班后：

1. **交班记录。** 面板显示**交班 N 已写入**，并对照显示实点金额和应有金额。按**打印交班记录**可打印交班报告（Z 报告）；打印后，面板显示**打印于**及打印时间。按**完成**。请参阅[归档交班记录](../pos/reconciliation.mdx#closure)。
2. **结算银行卡批次。** 交班记录中**其他付款方式**下的**银行卡**金额应与您输入的终端批次总额一致。如果终端不会自动结算批次，请现在结算。对于 Square 等托管结账方式，请参阅[网页结账](../payment/gateways/web-checkout.mdx)。
3. **转存现金。** 将明天的备用金放回钱箱，其余现金与打印的交班记录一起装袋，存入保险柜。

## 差额处理 {#variance-handling}

如果实点现金与应有金额不符，请在关班前依次检查以下各项：

1. **重新盘点钱箱。** 重新清点，尤其注意硬币，并输入新金额。关班后，经理仍可在报告中[复点交班记录](#recount)；原始数据会与更正后的数据一并保留。
2. **检查所有设备是否已同步。** 尚未传至店铺的销售不会计入应有金额。盘点时会提示 **N 笔销售尚未传至服务器 — 交班记录将记下这些销售**：您仍可关班，这些销售到达后会以**延迟更正**的形式附在交班记录旁。在加入班次的设备上，**数据将在下次同步时传入**提示会使**收银机关班**保持禁用，直到数据到达。盘点前，请让所有设备联网。
3. **检查挂单。** 将[订单](../orders/index.mdx)筛选为 *POS - 未结*：已录入但未付款的销售会显示在此处。检查仍标记为 **POS - 未结**的订单是否已收款；如已收款，请完成该订单。
4. **存入和取出现金。** 确认每次现金转存和支出都已记录在收银机面板中。店铺拒绝的现金变动会列在面板顶部，并提供**重试**按钮（参阅 [REGISTER101](../error-codes/REGISTER101.mdx)）。
5. **退款。** 在 WP Admin 中而非 POS 中发放的现金退款不会计入钱箱总额。请参阅[退款](../orders/refunds.mdx)。
6. **找零有误。** 检查是否找错零钱。如果无法解释差额，请在**备注**中如实说明。

无论是否找到原因，差额都会记入交班记录。小额差额有据可查，总比不留记录更好。

## 多位收银员或多家店铺 {#multi-cashier-or-multi-store-scenarios}

<Accordion>
  <AccordionItem question="今天有多位收银员使用同一台收银机">

无论有多少位收银员在同一台收银机上销售，都只有一个班次，因此钱箱只需盘点和关班一次。班次会记录开班人员，交班记录会记录关班人员。每位收银员可在自己的收银员面板上，通过**您今日的销售额**查看个人数据，交班记录的**班次**区块则列出**收银员**。

要交接收银工作，请使用收银员面板上的**交接给**：钱箱保持开班状态，未结购物车保留给各自的收银员继续处理。如果需要每位收银员单独盘点，请在交接时关班，再由下一位收银员填入备用金重新开班。每次关班都会生成独立编号的交班记录。

  </AccordionItem>

  <AccordionItem question="一位收银员今天在多家店铺工作">

每家店铺都有自己的收银机，因此需要分别开班和关班。使用收银员面板上**店铺**旁的**切换**可在店铺间切换，并在一天结束时为每家店铺的收银机关班。

使用 Pro 时，报告顶部的店铺和收银机菜单可在不同收银机及店铺之间切换，让您在同一台设备上查看各店铺的交班记录。

  </AccordionItem>

  <AccordionItem question="每家店铺由不同人员关班">

这是正常的工作方式。每位关班人员盘点并关闭自己店铺的收银班次。使用 Pro 时，经理可在第二天早上通过**交班记录**视图，查看其有权访问的所有店铺中每台收银机的交班记录。

  </AccordionItem>

  <AccordionItem question="关班后又有一笔销售入账">

交班记录写入后才传至店铺的销售或退款，会作为该交班记录的延迟更正保存。交班记录本身不会被改写：更正会单独列在旁边，交班记录显示**已更正**，因此既能查看关班时的报告，也能查看最终金额。

  </AccordionItem>
</Accordion>

## 最佳实践 {#best-practices}

- **每天关班。** 跳过一天意味着需要跨两天追查差额，难度会大得多。
- **保留打印的交班报告**，即使当天生意清淡也应如此。交班记录也会保存在 WCPOS 中，并可导出为 CSV。
- **不要共用用户账号。** 每位收银员使用自己的 WordPress 用户账号，可确保交班记录中的人员姓名准确。
- **每周与 WooCommerce 分析交叉核对**(`WP Admin > WooCommerce > Analytics`)：同一批订单，不同的查看方式。如果总额不一致，通常是挂单较晚才完成，或退款是在 WP Admin 中而非 POS 中发放的。
- **保持备用金一致。** 设置**开班备用金**，使每次开班都从相同金额开始。

## 出现问题时 {#goes-wrong}

**交班记录显示“离线时不可用”。** 交班记录视图和复点需要连接店铺。请检查网络连接；此设备之前打开过的交班记录仍可阅读。

**复点…呈灰色。** **联网后可复点**表示设备处于离线状态。**同步此交班记录后可复点**表示交班记录仍仅保存在此设备上：请保持联网，直到交班记录保存到店铺。

**“不允许访问报告”。** 您的用户无权查看收银数据，因此无法访问报告和交班记录。请参阅[访问权限](../settings/wp-admin/access.mdx#till-permissions)。

**“启用盲盘时限制查看交班详情”。** 进行盲盘的收银员无法打开交班记录，需由经理查看。

**“此交班记录超出可用历史范围”。** POS 中的交班记录可追溯至过去 92 天。更早的记录可从 WP Admin 导出。

**“导出失败。请重试。”** 请重试。在 WP Admin 中，**您的会话已过期**表示需要重新加载页面并再次登录；**请检查您是否有查看报告的权限**表示您的用户无法导出交班记录。请参阅[访问权限](../settings/wp-admin/access.mdx)。

:::info 免费版和 Pro
免费插件包含收银机开班、盘点、关班、带编号的交班记录，以及 WP Admin 中的**导出交班记录**。使用免费插件时，报告显示此设备收银机的当日数据及上次交班记录。Pro 支持每家店铺添加更多收银机，并提供**交班记录**视图：可在 POS 中查看往日、所有收银机和所有店铺的记录，进行复点，以及**导出 CSV**。请参阅[使用 Pro 添加更多收银机](../settings/wp-admin/registers.mdx#more-registers-with-pro)。
:::
