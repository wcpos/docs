扩展是专为 WCPOS 构建的 WordPress 插件，可提供刷卡终端、多语言商品目录、店铺储值、分地点库存等功能。在 WordPress 的 **WP Admin > POS > 设置 > 扩展** 中，即可在同一个目录中找到所有扩展。

只需点击一个按钮即可从目录安装扩展，但需要 **WCPOS Pro** 和 WordPress 管理员权限。没有 Pro，也可以手动安装 [Polylang](./polylang.mdx)、[WPML](./wpml.mdx) 和 [WP Multilang](./wp-multilang.mdx)。

跳转至：[安装扩展](#installing-an-extension) · [没有 Pro 时安装](#install-by-hand) · [故障排查](#troubleshooting)

## 安装扩展 {#installing-an-extension}

:::note 开始之前
从目录安装扩展需要 **WCPOS Pro** 和 WordPress 管理员权限：店铺管理员无法安装插件（参阅[访问权限](../settings/wp-admin/access.mdx)）。如果使用免费版，请参阅[没有 Pro 时](#install-by-hand)。
:::

1. 在 WordPress 中，前往 **WP Admin > POS > 设置**，然后选择 **扩展**。
2. 查找扩展。在 **搜索扩展…** 中输入内容（可匹配名称、描述和标签），或选择一个选项卡：**全部**、**商品目录**、**优惠券**、**库存**、**支付**。
3. 点击扩展卡片上的 **安装**。WCPOS 会一次完成下载、安装和启用，并开启 **自动更新**。卡片随后显示 **已启用**。
4. 配置扩展。如果卡片的 **⋮**（**更多操作**）菜单中有 **设置**，请选择它。上方对应扩展的介绍页会说明需要填写的内容。

<details>
<summary>菜单中没有设置，或需要其他入口</summary>

- 只有目录中列出了该扩展的设置页面时，菜单中才会出现 **设置**。如果没有，请按照扩展介绍页的说明操作。
- 使用 WCPOS Pro 时，**WP Admin > 插件** 中的扩展名称下方也有同样的 **设置** 链接。
- 对于支付扩展，**设置** 会打开 WooCommerce 支付设置中对应的页面。

</details>

1. **扩展** — 位于 WCPOS 设置菜单中。旁边的数字表示有可用更新的扩展数量。
2. **搜索扩展…** — 匹配名称、描述和标签。
3. **刷新** — 立即检查目录中是否有新版本。
4. **类别选项卡** — 选择 **全部** 或某个类别。

### 没有 Pro 时 {#install-by-hand}

免费版会列出所有扩展，但 **安装** 按钮呈灰色，并显示 **需要 Pro 才能安装**。Polylang、WPML 和 WP Multilang 这三个多语言扩展无需 Pro 即可运行，因此可以手动安装：

1. 在扩展卡片上打开 **⋮**（**更多操作**），然后选择 **在 GitHub 上查看**。
2. 下载最新发布版本附带的 `.zip` 文件。
3. 在 **WP Admin > 插件 > 安装插件** 中，点击 **上传插件**，选择 zip 文件并启用插件。

之后，目录会将其显示为 **已启用**，有新版本发布时则显示 **有可用更新**。没有 Pro 时不会显示 **更新** 按钮：按相同方法上传新版本的 zip 文件，WordPress 会提示替换已安装的版本。

## 更新、停用或启用 {#activating-and-deactivating}

没有 Pro 时，请手动更新扩展：参阅[没有 Pro 时](#install-by-hand)。

使用 WCPOS Pro 时，已安装扩展卡片上的按钮功能如下：

- **更新** — 安装新版本。原本正在运行的扩展会继续运行。
- **停用** — 停止扩展，但不移除它。设置和文件会保留，点击 **启用** 即可恢复运行。**启用** 也会重新开启 **自动更新**。

### 更新 {#updating-extensions}

有新版本发布时，卡片上的版本会显示为 **v0.5.9 → v0.5.10**，正在运行的扩展状态会变为 **有可用更新**（已停用的扩展仍显示 **未启用**）。使用 WCPOS Pro 时，还会显示 **更新** 按钮，WordPress 的 **插件** 界面也会列出同一更新，因此可以从任一位置更新。使用免费版时，请手动更新：参阅[没有 Pro 时](#install-by-hand)。

目录每小时检查一次新版本。点击搜索框旁的 **刷新** 可立即检查。

### 自动更新 {#auto-updates}

从目录安装或启用的每个扩展都会开启 **自动更新**。开启后，WordPress 会在后台安装新版本，与其他已开启自动更新的插件相同。如果希望手动更新，例如先测试新版本，可以在卡片上关闭此功能。

如果新版本要求的 WCPOS 版本高于您网站当前运行的版本，卡片和自动更新都不会提供该版本。先更新 WCPOS Pro，扩展更新才会出现。

### 移除扩展 {#removing-an-extension}

要彻底移除扩展，请像处理其他插件一样，在 **WP Admin > 插件** 中停用并删除它。使用 WCPOS Pro 时，可以先在扩展卡片上停用它。

## 故障排查 {#troubleshooting}

**安装按钮呈灰色，并显示“需要 Pro 才能安装”。** 您正在使用免费版：从目录安装需要 [WCPOS Pro](../getting-started/pro-license.mdx)。多语言扩展可以[手动安装](#install-by-hand)。

**“您没有管理插件的权限。”** 您的 WordPress 用户无法安装插件。请联系管理员。

**“…需要 WCPOS 2.1 或更高版本；此网站运行的是 WCPOS 2.0。请先更新 WCPOS Pro。”** 提供的版本超出了当前 WCPOS 的支持范围。请更新 WCPOS Pro 后重试。

**未输入搜索内容，却显示“无法刷新扩展。请重试。”或“未找到扩展。”** 您的网站未能获取扩展列表。列表来自 GitHub，而部分主机服务商会阻止网站向外连接。请稍后重试，或联系主机服务商允许连接 GitHub。

**安装失败，卡片上显示错误。** WordPress 无法下载或解压插件，卡片上的信息会说明原因。请联系主机服务商，检查 WordPress 是否能在插件文件夹(`wp-content/plugins`)中保存文件，以及是否能连接 GitHub。

**安装后卡片显示未启用。** WordPress 已安装扩展，但无法启用它；启用前扩展不会运行。点击 **启用**：如果失败，卡片上的信息会说明原因。

**新版本未显示。** 目录会将列表缓存一小时。请点击 **刷新**。

:::info 使用 WCPOS Pro
免费版会显示完整目录，但 **安装**、**启用**、**更新**、**停用** 和 **自动更新** 控件需要 Pro。请参阅[免费版与 Pro 版对比](../getting-started/free-vs-pro.mdx)。
:::

## 开发者指南 {#for-developers}

本节介绍如何开发扩展或上架自己的扩展。运营店铺无需了解以下内容。

### 钩子命名 {#hook-naming}

从 WCPOS 2.0 起，WCPOS 触发的所有钩子均以 `wcpos_*` 命名。旧的 `woocommerce_pos_*` 名称已弃用：目前仍可使用，最早会在 2.2 中移除。

<details>
<summary>Pro 钩子、弃用通知，以及保留原名的项目</summary>

WCPOS Pro 的钩子以 `wcpos_pro_*` 命名。旧名称作为别名仍会触发；若有回调挂载到旧名称，在开启 `WP_DEBUG` 时会记录弃用通知。只有钩子名称会改变，选项、元数据键和权限名称保持不变。

</details>

<details>
<summary>您的代码触发的钩子，以及何时切换</summary>

有四个钩子由您的代码触发、由 WCPOS 监听：`woocommerce_pos_invalidate`（扩展）、`woocommerce_pos_receipt_head`（已保存的 PHP 收据模板），以及 `woocommerce_pos_head` / `woocommerce_pos_footer`（主题中的 `pos.php` 覆盖文件）。WCPOS 会继续监听这些名称，直到 2.2；请切换为 `wcpos_invalidate`、`wcpos_receipt_head`、`wcpos_head` 和 `wcpos_footer`。

扩展开发者：请在 2.0 之后的首个发布版本中切换为 `wcpos_` 名称，并要求 WCPOS 2.0 或更高版本。切勿同时挂载到新旧两个名称；否则在 2.0 和 2.1 中，回调会执行两次。请参阅 [ADR 0041](https://github.com/wcpos/woocommerce-pos/blob/main/docs/adr/0041-wcpos-is-the-hook-prefix.md)。

</details>

<details>
<summary>开发扩展并将其上架到目录</summary>

<h3 id="creating-a-pos-extension">创建 POS 扩展</h3>

WCPOS 扩展是使用 WCPOS 钩子和 API 的普通 WordPress 插件。如果要开发支付扩展，请从[网关模板](../reference/gateway-template.mdx)开始。

<h3 id="pos-screens">向 POS 界面添加内容</h3>

目前，插件无法在 POS 界面中添加自己的面板或按钮。购物车、商品和客户界面只显示应用自带的内容。结账界面例外：支付网关可在[传统选项卡](../pos/checkout/legacy-tab.mdx)中显示自己的付款页面，也可以通过两个过滤器，在 **支付** 选项卡中添加自己的卡片和字段。请参阅[为收款面板声明字段](../reference/declaring-pos-fields.mdx)。

<details>
<summary>让目录能够识别已安装的插件</summary>

- **文件夹名称** — 插件文件夹名称必须与目录中的 `slug` 一致，例如 `my-extension/my-extension.php`。目录根据此文件夹识别已安装的扩展，也会将扩展安装到此文件夹。
- **文本域或插件 URI** — 其中一个必须与 `slug` 或 GitHub 仓库名称匹配。如果不匹配，自动更新和 WordPress 的 **插件** 界面都不会提供您的发布版本。此检查可防止复用了您文件夹名称的分支插件收到这些版本。

</details>

<h3 id="submitting-to-the-directory">提交到目录</h3>

目录读取 GitHub 上 [`wcpos/extensions`](https://github.com/wcpos/extensions) 仓库中的 `catalog.json`。要上架扩展，请在该仓库发起拉取请求，在 `catalog.json` 中添加条目；如果有图标，也请添加到 `icons/` 下。合并后，WCPOS 网站会在大约一小时内看到该扩展。

<details>
<summary>目录条目中的所有字段</summary>

| 字段 | 内容 |
|---|---|
| `slug` | 插件的文件夹名称。 |
| `name`, `description`, `author` | 卡片显示的内容。 |
| `category` | 所属选项卡：`payments`、`catalog`、`coupons`、`inventory`，或一个新类别。 |
| `tags` | 供搜索匹配的额外词语。 |
| `homepage` | GitHub 仓库，`https://github.com/owner/repo`。发布版本从这里读取。 |
| `icon` | 方形图标的 URL，通常指向您添加到 `icons/` 下的文件。如果未提供，卡片会显示拼图块图标。 |
| `requires_wp`, `requires_wc`, `requires_wcpos` | 运行所需的最低 WordPress、WooCommerce 和 WCPOS 版本。低于 `requires_wcpos` 要求的网站不会收到此发布版本。 |
| `requires_pro` | 是否需要 WCPOS Pro 才能运行。 |
| `settings_url` | 设置页面相对于 `wp-admin/` 的路径，例如 `admin.php?page=wc-settings&tab=checkout&section=my_gateway`。用于卡片菜单中的 **设置** 链接。 |

将 `version`、`latest_version`、`download_url` 和 `released_at` 留给目录处理：这些字段会根据您的发布版本自动填充。

</details>

<h3 id="github-release-conventions">GitHub 发布约定</h3>

创建正式的 GitHub 发布版本，以版本号作为标签，并附上插件 zip 文件。目录每小时读取各已上架仓库的最新发布版本，并更新相应条目。

<details>
<summary>发布版本推送到 WCPOS 网站的要求</summary>

- **使用版本号打标签**，例如 `v1.2.3`。版本号会去掉开头的 `v`，且必须与插件头部的 `Version` 一致。
- **附上插件 zip 文件**，并以 slug 命名，例如 `my-extension.zip`。如果没有此名称的文件，则使用发布版本中的第一个 `.zip` 文件。无论 zip 内的文件夹叫什么，WCPOS 都会将其安装到 `slug` 文件夹。
- **作为正式版本发布。** 草稿和预发布版本会被跳过，因此可以安全地通过预发布版本分享测试构建。
- 当发布版本需要更高版本的 WCPOS 时，请在 `catalog.json` 中 **提高 `requires_wcpos`**，以免向旧网站推送无法启动的版本。

</details>

网站刷新列表后即可看到新版本：通常在一小时内，也可点击 **刷新** 立即获取。开启 **自动更新** 的网站会在后台安装。

要在提交前测试自己的目录，可通过 `wcpos_extensions_catalog_url` 过滤器让网站使用该目录。

</details>
