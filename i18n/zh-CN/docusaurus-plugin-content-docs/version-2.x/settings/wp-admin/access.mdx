## 更改角色可执行的操作 {#change-a-role}

:::warning 关闭“使用 POS”或“管理订单”会导致用户无法登录
如果没有 **使用 POS** 权限，或被移除了 **管理订单** 权限，POS 会拒绝登录，并指出缺少的权限。请参阅[遇到问题时](#goes-wrong)。
:::

**谁能打开访问权限页面：** WP Admin 中的整个 **POS** 菜单都需要 **管理 POS 设置** 权限，管理员和店铺管理员拥有此权限，收银员则没有。如果无法打开访问权限页面，或无法保存更改，请联系站点管理员。

1. 前往 **WP Admin > POS > 设置**，在侧边栏中选择 **访问权限**。这不是 POS 内部的 **设置** 页面：后者仅包含[此设备的偏好设置](../index.mdx)，所有 POS 用户都能打开。
2. 在左侧角色列表中选择角色。默认先选中管理员。带有琥珀色圆点的角色表示其权限已不同于 WCPOS 默认设置。
3. 在 **收银员可执行的操作** 下（标题会显示所选角色的名称），勾选任务以授予权限，取消勾选则移除权限。
4. 这里没有保存按钮：每次勾选或取消勾选都会立即保存。页面会先显示 **正在保存**，然后显示 **已保存**。如果店铺拒绝更改，复选框会恢复原状，并显示原因提示。
5. 请让所有以该角色登录的用户退出 POS 后重新登录，以便 POS 获取新权限。店铺端会立即应用这些权限。

<details>
<summary>保存更改所需的权限</summary>

除了 **管理 POS 设置**，保存还需要 WordPress 的 `edit_users` 和 `promote_users` 权限。在 WordPress 单站点中，管理员同时拥有这两项权限。

</details>

### 任务与收银员默认权限 {#tasks}

以下按全新安装时收银员角色的默认权限分组，说明每项任务允许角色执行哪些操作。

**收银员默认可以：**

- **使用 POS**：登录 POS 并进行销售。
- **创建和编辑商品**：添加商品，更改名称、价格、库存、条形码和成本，包括商品变体。
- **创建和编辑优惠券**：添加优惠券，更改代码、金额、到期时间和描述（WCPOS Pro）。
- **管理订单**：保存、重新打开和更改订单，包括其他收银员处理的订单以及网店订单。
- **管理客户**：查找客户、添加新客户并更改客户详情。
- **管理分类和标签**：添加和更改商品分类及标签。

**收银员默认不能：**

- **管理 POS 设置**：打开 WP Admin 中的 **POS** 菜单，包括当前页面、收据模板和店铺日志。
- **删除商品**：删除商品及其变体。
- **删除优惠券**：删除优惠券（WCPOS Pro）。

管理员和店铺管理员最初拥有全部 POS 权限。其商品、订单和客户任务反映了 WooCommerce 和 WordPress 为这些角色授予的权限；WCPOS 不会更改这些权限。

## 默认角色权限一览 {#what-each-default-role-can-do-at-a-glance}

- **管理员**：可在 POS 和 WP Admin 中执行所有操作。
- **店铺管理员**：可使用 WP Admin 中的 **POS** 菜单，拥有收银机权限，并可执行 WooCommerce 允许店铺管理员对商品、订单和客户执行的操作。不包括安装 POS 扩展，因为这需要安装插件的权限。
- **收银员**：可进行销售，创建和编辑商品、优惠券、订单及客户，以及开启、盘点和关闭收银机。不能删除内容、管理 POS 设置，也不能审批有差额的盘点。

各角色可向店铺发起哪些请求，请参阅[角色端点访问权限](../../reference/role-endpoint-access.mdx)。

## 收银员看到“您没有权限”时 {#no-permission-hint}

使用 WCPOS Pro 时，商品、优惠券和客户页面，以及购物车中的 **新建优惠券** 和 **添加新客户** 按钮，均受收银员角色权限控制。角色无权使用的控件会显示为灰色，其提示会告诉收银员谁能解决这个问题：

> 您没有创建优惠券的权限。管理员可在 WP Admin > POS > 设置 > 访问权限中授予此权限。

每条提示都会指出应为收银员角色勾选哪项任务：

- “……**创建优惠券**”或“……**编辑优惠券**”：勾选 **创建和编辑优惠券**。
- “……**编辑商品**”或“……**编辑变体**”：勾选 **创建和编辑商品**。
- “……**创建客户**”或“……**编辑客户**”：勾选 **管理客户**。

未使用 Pro 时，这些控件会显示 **升级到 Pro**。无论页面显示什么，店铺都会再次检查每项更改。店铺拒绝的商品、优惠券或客户更改会在设备上撤销，并在 **店铺健康状况 > 日志** 中记录为 **已撤销店铺拒绝的更改**。

在购物车中，**新建优惠券** 就是 **添加折扣** 对话框中 **优惠券** 字段旁的 **+** 按钮。只有这个按钮受角色权限限制；选择并应用现有优惠券只需 **使用 POS** 权限。

## 收银机权限 {#till-permissions}

收银机有四项独立权限，不属于任务。打开访问权限页面底部的 **高级** 即可更改。要了解它们在该处的名称，请展开下方的 **高级中的权限名称**。各项权限默认授予哪些角色，以斜体标明。

- **操作收银机**：开启收银机，记录现金存入、现金支出和无销售开钱箱，以及盘点和关闭收银机。*收银员、店铺管理员、管理员。*
- **查看收银机数据**：查看预期现金、X 报表、打印的结班报告及报表。没有此权限时，收银员需进行 **盲盘**：屏幕不显示预期现金或差额，也无法打印结班报告。*收银员、店铺管理员、管理员。*
- **审批结班**：审批差额超出限额的盘点，以及重新盘点结班记录。审批人不能是开启收银机的收银员，也不能是执行关闭操作的收银员。*店铺管理员、管理员。*
- **重新分配销售记录**：此权限预留用于在销售完成后更改该笔销售的收银员。POS 尚未提供此功能，因此更改此权限目前没有效果。*店铺管理员、管理员。*

<details>
<summary>高级中的权限名称</summary>

**高级** 在 **WCPOS** 下按权限名称列出这四项：

- 操作收银机：`manage_woocommerce_pos_cash`
- 查看收银机数据：`view_woocommerce_pos_reports`
- 审批结班：`manage_woocommerce_pos_closures`
- 重新分配销售记录：`reassign_woocommerce_pos_sales`

</details>

限额对应[收银机](./registers.mdx#one-register)中的 **盘点差额超过以下金额时请经理审批** 设置。盘点操作本身请参阅[开启收银机](../../pos/register/index.mdx#close)。

## 部分授权的任务与恢复默认设置 {#restore-defaults}

**复选框显示横线，并带有“3 / 7”等标记：** 该角色仅拥有此任务的部分权限。勾选复选框可授予整个任务的权限，取消勾选则将其全部移除。

**要将角色恢复为全新安装时的状态：** 选择角色，点击其标题下方的 **恢复默认设置**，查看对话框中的更改列表，然后再次点击 **恢复默认设置**。角色仍与默认设置一致时，此按钮显示为灰色。

:::warning 恢复默认设置可能会移除其他插件授予的权限
恢复操作只会写入 WCPOS 设置的权限：对于收银员，是访问权限页面列出的全部权限；对于其他角色，则仅限 **高级** 中 **WCPOS** 下的六项权限。角色的其他权限不会改变，但上述范围内的权限即使由其他插件授予，也会恢复为 WCPOS 默认值。
:::

<details>
<summary>部分授权的任务如何运作</summary>

每项任务代表一组权限。当角色仅拥有其中一部分时，复选框会显示横线，任务旁会出现 **3 / 7** 等标记。将指针移到标记上可查看其含义，或点击 **查看** 打开 **高级**，查看缺少哪些权限。勾选带横线的复选框会授予该组剩余权限；取消勾选则移除整组权限。

</details>

<details>
<summary>恢复默认设置会如何更改各角色</summary>

角色标题下方的 **使用 WCPOS 默认设置** 或 **已更改 WCPOS 默认设置** 会说明该角色是否仍与全新安装时一致。写入任何更改之前，标题为 **恢复收银员的默认权限？** 的对话框会在 **将进行的更改** 下列出各项任务将被 **授予**、**移除** 还是 **保留**，然后列出 **高级** 中将更改的权限。点击 **恢复默认设置** 确认，或点击 **取消**。

- **收银员**：WCPOS 安装时授予的全部权限，即上方列出的任务和收银机权限。
- **管理员** 和 **店铺管理员**：仅 POS 权限。WCPOS 不管理这些角色的 WooCommerce 或 WordPress 权限。
- **其他任何角色**：无 POS 访问权限。对话框标题会改为 **移除……的 POS 权限？**。

</details>

<details>
<summary>重新启用或更新插件对权限的影响</summary>

停用并重新启用 WCPOS 插件，会为管理员、店铺管理员和收银员重新添加全部默认权限，但不会移除您另行添加的权限，例如 **删除商品**。插件更新只授予该版本新增的权限，因此已关闭的任务仍保持关闭。例外是首次从 1.10.17 或更早版本更新：它会像重新启用插件一样，重新添加一次全部默认权限。

</details>

<details>
<summary>访问权限页面中的全部权限</summary>

**高级** 将各项权限分别列在 **WCPOS**、**WooCommerce** 或 **WordPress** 下。只有任务无法满足需求时，才需要逐项更改权限。

| 权限 | 任务 | 在 POS 中的作用 |
| --- | --- | --- |
| `access_woocommerce_pos` | 使用 POS | 登录并使用 POS。缺少此权限时，POS 会拒绝登录。 |
| `manage_woocommerce_pos` | 管理 POS 设置 | 访问 WP Admin 中的 **POS** 菜单及其设置。管理员始终保留此权限。 |
| `manage_woocommerce_pos_cash`, `view_woocommerce_pos_reports`, `manage_woocommerce_pos_closures`, `reassign_woocommerce_pos_sales` | 无 | 请参阅[收银机权限](#till-permissions)。 |
| `edit_products`, `edit_others_products`, `edit_published_products` | 创建和编辑商品 | 更改商品。 |
| `edit_product` | 创建和编辑商品 | 更改变体。 |
| `publish_products`, `edit_private_products` | 创建和编辑商品 | 添加商品；更改私密商品。 |
| `read_private_products` | 创建和编辑商品 | 加载商品列表。缺少此权限时，所有商品都无法加载，而不只是私密商品。 |
| `delete_product`, `delete_products`, `delete_others_products`, `delete_private_products`, `delete_published_products` | 删除商品 | 删除商品及其变体。 |

| `delete_shop_coupons`, `delete_others_shop_coupons`, `delete_private_shop_coupons`, `delete_published_shop_coupons` | 删除优惠券 | 删除优惠券。 |

| `edit_shop_orders` | 管理订单 | 更改订单。 |
| `edit_others_shop_orders` | 管理订单 | 更改其他收银员处理的订单以及网店订单。 |

## 客户列表中的员工账户 {#staff-accounts}

POS 客户列表显示所有 WordPress 用户，包括员工，因为任何账户都可以作为订单的客户。更改账户的权限比查找账户更严格：无论 **管理客户** 如何设置，只有管理员可以在 POS 中编辑或删除员工账户。其他用户会看到 **只有管理员可以在 POS 中编辑或删除员工账户。** 每个人仍可编辑自己的账户。

员工包括管理员、店铺管理员、收银员，以及编辑、作者和贡献者。

<details>
<summary>如何识别员工账户</summary>

账户只要拥有 `manage_options`、`manage_woocommerce`、`edit_users` 或 `edit_posts` 中的任一权限，就视为员工账户。拥有其中任一权限的自定义角色也属于员工。

</details>

## 拥有多个角色的用户 {#more-than-one-role}

**症状：** 用户拥有两个角色（例如管理员和客户），却无法使用其中一个角色已授予的权限。

**解决方法：** 从账户中移除额外角色（打开 **用户 > 所有用户**，然后编辑账户），或在角色编辑器中打开该角色并清除 *拒绝* 标记。然后让用户重新登录。

<details>
<summary>为什么第二个角色可能导致权限丢失</summary>

一个账户可以拥有多个角色，通常通过 Members 等角色编辑插件设置。WordPress 会合并各角色授予的权限，因此第二个角色本身很少会导致权限减少。但角色编辑器中的 *拒绝* 不同：某个角色拒绝的权限可能覆盖另一个角色的授权，而 Members 会优先应用拒绝设置。同时拥有客户角色的管理员，可能会失去客户角色所拒绝的任何权限。

访问权限页面显示各角色自身的勾选状态。*拒绝* 在该页面中仅表现为对应角色上未勾选的复选框，与“未授予”看起来一样。勾选该复选框会以授权覆盖拒绝设置。

</details>

## 遇到问题时 {#goes-wrong}

**“此账户无法使用 POS。缺少权限：……”** 该角色缺少 **使用 POS** 或 **管理订单** 权限，因此 POS 拒绝登录。请为用户的角色勾选对应任务。如果用户拥有两个或更多角色，请参阅[拥有多个角色的用户](#more-than-one-role)。

<details>
<summary>单角色与多角色情况下的完整提示</summary>

提示会列出缺少的权限，例如 **管理订单** 所需的 `publish_shop_orders`。只有一个角色时，提示会要求在 WCPOS 设置的访问权限页面中授予相应权限，或分配拥有这些权限的角色。如果账户拥有两个或更多角色，提示示例如下：

> 此账户无法使用 POS。缺少权限：publish_shop_orders、read_private_products、read_private_shop_orders、list_users。该账户拥有客户、管理员角色。某个角色拒绝的权限可能覆盖另一个角色的授权，Members 等角色编辑插件会优先应用拒绝设置。请移除额外角色，或在角色编辑器中清除拒绝设置。

</details>

**收银员能够登录，但商品、客户或订单均未加载。** 请为收银员角色重新勾选 **创建和编辑商品**、**管理客户** 或 **管理订单**，或检查第二个角色是否设置了 *拒绝*。

<details>
<summary>为什么页面显示为空</summary>

该角色缺少 `read_private_products`、`list_users` 或 `read_private_shop_orders` 权限。这些权限缺失不会阻止登录，但会导致相应页面为空。**店铺健康状况 > 日志** 中的收银机日志会将每个被拒绝的请求记录为 [AUTH201](../../error-codes/AUTH201.mdx)。

</details>

**已关闭的收银员权限又恢复了。** 有人停用并重新启用了插件，或店铺从 1.10.17 或更早版本进行了更新；这两种操作都会重新添加默认权限。请再次取消勾选相关任务。

**无法取消管理员的勾选。** 管理员始终保留 **管理 POS 设置** 和 `read` 权限，以免任何人将自己锁在此页面之外。

:::info 使用 WCPOS Pro
Pro 增加了店铺功能。店铺的 **员工** 列表包含所有拥有 **使用 POS** 权限的用户，无论权限来自角色还是单独授予；编辑店铺则需要 **管理 POS 设置** 权限。请参阅[设置店铺](../../stores/setup.mdx#staff)。只有使用 Pro 才能在商品、优惠券和客户页面更改记录。
:::
