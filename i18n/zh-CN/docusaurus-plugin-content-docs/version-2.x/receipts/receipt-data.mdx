**WP 后台：** 模板在 `WP Admin → POS → Templates` 中编辑；本页列出了模板可打印的字段。

要打印收据或通过电子邮件发送收据，请参阅[收据与已付款界面](./at-checkout.mdx)；要选择模板或让 AI 帮您修改模板，请参阅[自定义收据](./customise.mdx)。

本页适用于手动编辑模板代码。无论是 HTML 模板还是热敏模板，打印时都使用同一套收据数据：店铺、订单、商品、总计和付款。本页介绍如何打印字段，提供三个常见示例，并列出所有字段。

**跳转至：** [查找字段](#field-reference) · [常见示例](#common-recipes) · [问题排查](#if-something-goes-wrong)

## 打印字段 {#print-a-field}

1. 在 **WP Admin → 收银台 → 模板** 中打开模板（详见[手动编辑](./customise.mdx#option-3--edit-it-by-hand)）。
2. 在需要打印字段的位置，将字段路径放在双花括号内，例如 `{{store.name}}`、`{{order.number}}` 或 `{{totals.total_display}}`，也可以从代码旁的字段列表中插入。
3. 检查代码下方的预览，然后点击 **更新** 保存。

对于商品等列表，将行包裹在区块中，即可为每个条目重复输出一次：

```mustache
{{#lines}}
  {{name}} x {{qty}} —
  {{line_total_display}}
{{/lines}}
```

字段为空、零或假时，区块也会省略其内容，因此 `{{#customer.id}}…{{/customer.id}}` 仅在有具名客户时打印。打印金额时，请使用以 `_display` 结尾的字段；参阅[货币字段](#currency-fields)。

离线时也能打印收据：应用会根据设备上的订单构建一份收据数据。

<Accordion>
  <AccordionItem question="为什么收据可能不同">

### 数据来源 {#where-the-data-comes-from}

店铺服务器会为每笔订单构建收据数据，应用则根据设备上的订单构建一份精简副本：其中没有 `cashier`，没有店铺营业时间、备注或政策，也没有 `totals.paid_total` 或 `totals.change_total`。HTML 或热敏模板会立即使用设备副本打开，收到服务器副本后再切换过去；离线时打印的是设备副本，因此这些字段会显示为空。使用 WCPOS Pro 时，设备副本也包含店铺标志；未使用 Pro 时，标志随服务器副本一起到达。旧版 PHP 模板始终由服务器渲染。因此，模板使用下列字段，而不使用 PHP 订单方法。少数字段仅在服务器渲染模板时才会打印，例如下载 PDF 时；[问题排查](#if-something-goes-wrong)中列出了这些字段。

  </AccordionItem>
</Accordion>

## 字段参考 {#field-reference}

展开分区即可查看其字段。第一项列出了所有分区及其类型。

### 顶层分区 {#top-level-sections}

| 分区 | 包含的内容 |
|---------|---------------|
| `order`（对象） | 订单标识、状态、日期、备注和付款 URL 信息 |
| `store`（对象） | 店铺标识、地址、联系方式、税号、标志、营业时间和页脚文本 |
| `cashier`（对象） | 处理订单的用户 |
| `customer`（对象） | 客户显示名称、地址和税号 |
| `lines`（数组） | 商品行项目 |
| `fees`（数组） | 费用行 |
| `shipping`（数组） | 运费行 |
| `discounts`（数组） | 优惠券/折扣行 |
| `totals`（对象） | 订单总计、付款总计、退款汇总和商品数量 |
| `tax`（对象） | 用于区块条件判断的税费显示模式标志 |
| `tax_summary`（数组） | 按税率汇总的税费行 |
| `has_tax_summary`（布尔值） | 用于判断 `tax_summary` 是否有内容的便捷条件 |
| `payments`（数组） | 付款行 |
| `refunds`（数组） | 应用于订单的退款记录 |
| `fiscal`（对象） | 由税务集成填充的税务快照字段 |
| `register`（对象） | 完成这笔销售的收银机：`id` 和 `name`。未知时为空字符串 |
| `software`（对象） | 开具收据的软件：`name`(`WCPOS`)、`plugin_version`、`app_version`、`app_build`、`platform` |
| `presentation_hints`（对象） | 格式设置和渲染器提示 |
| `i18n`（对象） | 内置模板和自定义模板使用的翻译标签 |

  </AccordionItem>

| `order.payment_url` | 字符串 | 订单付款 URL（如有） |
| `order.created` | 日期对象 | 订单创建日期 |

### store {#store}

| 字段 | 类型 | 示例 / 说明 |
|-------|------|-----------------------|
| `store.id` | 数字 | 店铺 ID，或已删除店铺的历史 ID |
| `store.name` | 字符串 | 店铺显示名称 |
| `store.address.address_1` | 字符串 | 街道地址第 1 行 |
| `store.address.address_2` | 字符串 | 房间/单元地址行 |
| `store.address.city` | 字符串 | 城市/地方 |
| `store.address.state` | 字符串 | 州/地区 |
| `store.address.postcode` | 字符串 | 邮政编码 |
| `store.address.country` | 字符串 | ISO 国家代码 |
| `store.address_lines` | 数组 | 已格式化的地址行；推荐大多数模板使用 |
| `store.tax_ids` | 数组 | 结构化的企业税号；应循环遍历此字段，而非使用单个税号 |
| `store.phone` | 字符串 | 店铺电话 |
| `store.email` | 字符串 | 店铺电子邮箱 |
| `store.logo` | 字符串/null | 店铺标志 URL 或数据 URI：优先使用店铺自己的标志，否则使用 WordPress 站点标志，除非店铺关闭了此选项。两者均无时为 `null` |
| `store.opening_hours` | 字符串/null | 简短的营业时间文本 |
| `store.opening_hours_vertical` | 字符串/null | 多行营业时间文本块 |
| `store.opening_hours_inline` | 字符串/null | 以逗号分隔的营业时间文本 |
| `store.opening_hours_notes` | 字符串/null | 自由填写的营业时间备注 |
| `store.personal_notes` | 字符串/null | 收据页脚/个性化备注 |
| `store.policies_and_conditions` | 字符串/null | 退款、退货或条款文本 |
| `store.footer_imprint` | 字符串/null | 页脚法律声明 |

### 税号对象 {#tax-id-objects}

`store.tax_ids` 和 `customer.tax_ids` 包含结构相同的对象：

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `type` | 字符串 | 标识符，例如 `eu_vat`、`de_steuernummer`、`au_abn`、`br_cpf`、`us_ein` 或 `other` |
| `value` | 字符串 | 要打印的税号值 |
| `country` | 字符串/null | ISO 国家代码；`eu_vat` 和 `other` 为 null |
| `label` | 字符串 | 本地化的显示标签，在渲染前解析确定 |

示例：

```mustache
{{#store.tax_ids}}
  {{label}}: {{value}}
{{/store.tax_ids}}
```

### 显示原价和节省金额 {#displaying-regular-price-and-savings}

采用单价布局时，可按以下方式显示记录的原价、售价和节省金额：

```mustache
{{#lines}}
  {{#unit_savings}}
    <span style="text-decoration: line-through;">{{regular_price_display}}</span>
    <span>{{selling_price_display}}</span>
    <span>{{i18n.savings}}: -{{unit_savings_display}}</span>
  {{/unit_savings}}
{{/lines}}
```

需要考虑数量时，使用行总计字段：

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    <span>{{i18n.savings}}: -{{line_savings_display}}</span>
  {{/line_savings}}
{{/lines}}
```

`selling_price` 是使用优惠券前的价格。要显示应用 WooCommerce 折扣后的最终金额，请使用 `unit_price` 或 `line_total`。

:::note 重印 v1.9.0 之前创建的订单
较早的 WCPOS 订单可能已经将原价到售价的降价金额计入 `discounts`。如果自定义模板同时打印行节省金额和行折扣，请使用 `savings_in_discounts`，避免重复显示同一笔减免：

```mustache
{{#lines}}
  {{#line_savings}}
    <span style="text-decoration: line-through;">{{line_regular_total_display}}</span>
    {{^savings_in_discounts}}
      <span>{{i18n.savings}}: -{{line_savings_display}}</span>
    {{/savings_in_discounts}}
  {{/line_savings}}
  {{#discounts}}
    <span>{{i18n.discount}}: -{{discounts_display}}</span>
  {{/discounts}}
{{/lines}}
```

如果模板不打印行级 `discounts` 行，即使 `savings_in_discounts` 为真，也应继续显示 `line_savings`。内置模板会自动处理这种区别。
:::

| `presentation_hints.price_display_suffix` | 字符串 | WooCommerce 价格显示后缀 |
| `presentation_hints.order_barcode_type` | 字符串 | 供读取此字段的模板使用的条形码类型：`code128`（默认）、`qrcode`、`ean13`、`ean8` 或 `upca`。由应用填充；服务器不提供此字段，模板库中的模板在模板内设置条形码类型 |

预先格式化的金额字段（如 `totals.total_display` 等 `*_display` 值）会按订单货币显示金额及其 **货币符号**，并使用上方的位置和分隔符设置，因此收据显示 `$12.00`，而非 `USD 12.00`。原始 `order.currency` 字段仍为 ISO 代码，可用于模板中的逻辑判断。

  </AccordionItem>

  <AccordionItem question="收据用语 — i18n">

## 各项价格之间的关系 {#price-model}

收据上的一件商品会有多种价格，结合具体金额最容易理解这些名称。以下是示例订单中的浓缩咖啡豆行：一件原价 $17.00 的商品，促销价为 $14.50，再叠加 10% 优惠券：

<PriceFlow
  caption="浓缩咖啡豆 — 一件（订单中有两件）"
  scaleLabel="原价 17.00"
  segments={[
    { kind: 'paid', amount: 13.05, label: "实付 13.05" },
    { kind: 'coupon', amount: 1.45, label: "1.45" },
    { kind: 'savings', amount: 2.5, label: "2.50" },
  ]}
  summary={[
    { label: "整笔订单的促销节省金额", value: '`totals.sale_savings_total` = 5.00' },
    { label: "整笔订单的全部优惠券折扣", value: '`totals.discount_total` = 5.28' },
    { label: "节省金额 + 折扣，已扣除旧版重复部分", value: '`totals.total_saved` = 10.28' },
  ]}
/>

促销节省金额是原价与售价之差。折扣是 WooCommerce 计算出的优惠券减免金额。WooCommerce 的订单总计和报表仅包含折扣，因此 `total_saved` 将两者合为一个数值供客户查看。

## 扩展收据数据 {#extending}

插件可以通过 `wcpos_receipt_data` 过滤器向收据数据添加自己的字段。

<Accordion>
  <AccordionItem question="过滤器：参数、六种模式和示例">

WCPOS 不会在上述字段中加入任何特定插件的数据。当插件需要向收据提供 WooCommerce 数据模型之外的信息时，应自行通过 `wcpos_receipt_data` 过滤器添加，方式与插件过滤 WooCommerce 自身订单总计时相同。服务器每次构建收据时都会运行该过滤器，包括实时收据、付款时的税务快照、PDF 下载和旧版 PHP 模板。在 WCPOS 2.0 之前，此过滤器名为 `woocommerce_pos_receipt_data`；该名称仍可使用，但从 2.0 起已弃用，最早将在 2.2 移除（参阅[钩子命名](../extensions/index.mdx#hook-naming)）。

第三个参数 `$mode` 表示正在构建的单据类型：`live`、`fiscal`、`refund`、`preview`（模板编辑器和模板库中的示例收据）、`closure` 或 `xreport`（收银机结算单和 X 报表）。在 `preview`、`closure` 和 `xreport` 模式下，订单尚未保存，ID 为 `0`；需要已保存订单的插件，应在 `$order->get_id()` 为 `0` 时原样返回 `$data`。

```php
add_filter( 'wcpos_receipt_data', function ( array $data, WC_Abstract_Order $order, string $mode ) {
    foreach ( $data['discounts'] as &$row ) {
        if ( 'smart_coupon' === $row['discount_type'] ) {
            $row['gift_card'] = true;
        }
    }
    return $data;
}, 10, 3 );
```

随后，模板就可以像使用其他区块一样，以新键作为显示条件：

```
{{#discounts}}
  {{#gift_card}}Gift Card{{/gift_card}}{{^gift_card}}{{i18n.discount}}{{/gift_card}}{{#label}}: {{label}}{{/label}}
{{/discounts}}
```

数据结构定义中的键应保持文档规定的类型。新增键不属于该定义，因此不会出现在模板编辑器的字段选择器中；税务快照也仅包含订单付款时过滤器添加的内容。此过滤器从 WCPOS 1.10.8 起可用。

  </AccordionItem>

  <AccordionItem question="哪些收据会打印新增键">

服务器自行渲染的收据会收到所有新增键，包括 PDF 下载和旧版 PHP 模板。在 POS 应用中渲染的 HTML 和热敏模板会先重新构建数据：添加到 `order`、`store`、`cashier` 或 `customer` 内的键会保留，但添加到其他位置的键（如上方折扣行中的键）会被省略。{/* pending: monorepo#3363 */} 对于带有税务快照的实时收据，税务标识、`register` 和 `software` 会在过滤器运行后从快照中复制，因此在此过滤器中修改它们不会生效；请改为扩充快照。

  </AccordionItem>
</Accordion>

## 问题排查 {#if-something-goes-wrong}

**某行在一张收据上打印 `$0.00`，在另一张收据上却为空。** 某些 `_display` 字段，例如 `totals.change_total_display`、`totals.refund_total_display` 和 `payments[].tendered_display`，值为零时，在服务器渲染的收据中为空，在应用渲染的收据中则为 `$0.00`。改为将该行放入以数字字段为条件的区块中，即可在两种情况下都省略它：`{{#totals.change_total}}…{{/totals.change_total}}`。

**缺少“共节省”行。** `totals.total_saved_complete` 为假：至少有一件商品没有记录原价，因此无法计算节省金额。通常出现在 WCPOS 1.9.0 之前收银生成的订单中。

**总计小于客户实付金额。** 店铺显示的是不含税价格，因此 `totals.total` 为税前总额。要打印实际收取的金额，请使用 `totals.total_incl_display`。WCPOS 附带的旧版 PHP 收据打印的就是该金额。

**某字段在下载的 PDF 中打印，却不在 POS 中打印。** 应用中渲染的模板会先重新构建数据，并省略少数字段；这些字段仅在 PDF 下载和旧版 PHP 模板中打印。下列字段请仅在这两类收据中打印，或用区块控制显示，让 POS 收据将其省略。{/* pending: monorepo#3363 */}

<Accordion>
  <AccordionItem question="PDF 与 POS 收据中存在差异的字段">

- `lines[].attributes`、`lines[].total_refunded_display` 和 `lines[].unit_subtotal_display`（及其 `_incl` 和 `_excl` 版本）
- `software.platform`
- `presentation_hints` 中除 `display_tax`、`prices_entered_with_tax`、`rounding_mode`、`locale` 和 `order_barcode_type` 以外的字段
- 德国、荷兰、法国、英国公司及瑞士类型的客户税号
- 插件在 `order`、`store`、`cashier` 和 `customer` 之外添加的键；参阅[扩展收据数据](#extending)

</AccordionItem>
</Accordion>

## 版本 {#versions}

收据数据有独立于插件的版本号。旧收据中没有较新的字段，例如在字段加入前生成的税务快照，因此请用区块控制这些字段的显示。

| 版本 | 新增内容 |
|---------|-------|
| 1.1 | 每件商品的原价、售价和节省金额，以及订单的节省总额，包括 **共节省**。这些字段都不会改变订单总计或 WooCommerce 报表 |
| 1.2 | `discounts[].discount_type` |
| 1.3 | `customer.first_name` 和 `i18n` 中的客户显示标签 |
| 1.4 | `register`、`software`、税务单据字段（`fiscal.document_type`、`is_…` 标志、`sale_time`、`received_at`、`sale_tz`、`sale_counter`、`corrects`）及其 `i18n` 标签 |
