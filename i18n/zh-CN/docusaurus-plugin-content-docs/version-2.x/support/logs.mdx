每台收银机都会记录自己的活动，包括销售、同步、设置变更和错误。出现问题时，日志会说明发生了什么、对销售有何影响，以及接下来该怎么做。店铺还会在服务器上保留另一份日志，可在 WP Admin 中查看，用于记录 WordPress 端的问题。

现在遇到了错误？[打开日志条目](#open)查看详情，或[将日志发送给支持团队](#for-support)。

## 收银机出现新错误时 {#unread-badge}

菜单底部的 **店铺健康状况** 上会显示一个红色数字，表示自上次打开 **日志** 以来记录的错误数量。超过 99 时显示 **99+**。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[44, 10]]} maxWidth={316} alt="菜单底部：设置上方的店铺健康状况图标，带有表示新错误数量的红色数字 33">

1. **店铺健康状况** — 红色数字仅统计错误，不包括警告。在手机上，打开菜单即可看到。

</JourneyShot>

打开 **店铺健康状况**，再打开 **日志**，数字就会清除。打开 **数据库** 或 **性能** 不会清除数字。每台收银机分别为当前登录的店铺和收银员保留计数，关闭应用也不会重置。

## 阅读日志 {#read}

每个条目记录收银机的一项活动，最新的排在最前面。条目最多保留 30 天。

日志记录的是这台收银机的运行情况，而非销售记录。如果对某笔付款有疑问，请先在 **WooCommerce → 订单** 中查看订单，其中每笔付款都有自己的简要历史记录。日志则展示这台收银机在该付款前后发生的活动。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[44, 0], [52, 0], [0, -26], [46, 0], [44, 22], [53, 0], [-36, 0], [41, 0], [-36, 0]]} alt="店铺健康状况的日志选项卡：今日统计数据、复制调试信息、搜索框、筛选按钮，以及包含时间、级别、事件、耗时和状态的条目列表">

1. **店铺健康状况** — 日志所在的位置。
2. **日志** — 第三个选项卡。列表上方统计数据的说明见[店铺健康状况](store-health.mdx#logs)。
3. **错误** — 仅显示错误。参见[查找条目](#find)。
4. **时间** — 今天的条目显示时间，之前的条目显示日期和时间。
5. **级别** — **错误**、**警告**、**操作**（用户执行的操作）、**同步**、**信息** 或 **调试**（仅在开启 **详细诊断** 时记录）。
6. **事件** — 发生的活动，下方显示所属的应用模块；如有相关记录，还会显示记录名称。**×2** 表示同一活动在大约一分钟内发生了两次。
7. **耗时** — 任务执行所用的时间。
8. **状态** — 错误或警告显示错误代码；操作成功时显示 **✓ 正常**；其他情况显示 **—**。
9. **状态行** — 显示 **正在监测变更**，以及这台收银机上次检查店铺的时间和下次检查的时间。首次检查完成前显示 **等待首次检查…**。

</JourneyShot>

相邻且属于同一任务的条目，左侧会显示相同颜色的边线。大多数条目会以收银机当前使用的语言显示，不受记录时所用语言的影响。

## 查找条目 {#find}

- **搜索日志** — 输入错误代码，例如 **SYNC131**，或错误信息中的关键词。
- **全部**、**操作**、**错误**、**同步** — **操作** 指用户执行的操作，**同步** 指收银机与店铺之间的通信。
- **今日事件**、**今日错误**、**受阻记录** — 点击 **今日事件** 可切换到 **全部**，点击 **今日错误** 可切换到 **错误**，点击 **受阻记录** 可切换到 **同步**。
- **级别** — 点击条目上的级别，例如 **错误**，即可仅显示该级别的条目。再次点击，或点击新增筛选按钮上的叉号，即可显示所有级别。

列表底部的 **已显示 …，共 …** 表示在匹配的条目中已加载了多少条。向下滚动可加载更多。

## 打开条目 {#open}

打开 **店铺健康状况 → 日志**，点击 **错误**。找到时间与问题发生时间相符的条目，或在 **搜索日志** 中输入错误代码。点击条目即可在该行下方阅读详情，再次点击可收起。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[50, 0], [64, -10], [-54, -97], [131, 0], [101, 0], [-33, 0]]} alt="已启用错误筛选，并在行下方展开了 AUTH201 条目：服务器返回的信息、处理方法、打开记录、帮助链接、带有复制按钮的事件代码，以及记录、操作和请求">

1. **错误** — 当前启用的筛选条件。
2. **条目** — **状态** 中的 **AUTH201** 是该条目的错误代码。
3. **发生了什么以及如何处理** — 如果店铺返回了信息，会先显示该信息，然后用一行文字说明处理方法。必要时会先显示警告，例如 **已收取款项，请勿再次收费。** 或 **请勿清除此设备的数据**。
4. **帮助 — AUTH201** — 打开本文档中该代码对应的页面。参见[错误代码](../error-codes/index.mdx)。
5. **打开记录** — 打开条目涉及的订单、商品或客户，前提是这台收银机上有该记录、店铺已启用 WCPOS Pro，且你有权编辑该记录。
6. **复制** — 复制整个条目，以便发送给支持团队。旁边的 **事件代码** 表示收银机当时正在执行的任务，在所有语言中都相同。

</JourneyShot>

受阻或被拒绝的变更会显示 **前往店铺健康状况 → 数据库**，你需要在那里选择处理方式。参见[需要你处理的情况](store-health.mdx#needs-attention)。**请网站管理员检查服务器日志** 表示原因记录在店铺自身的日志中：参见[WP Admin 中的店铺日志](#wp-admin-logs)。

<details>
<summary>条目中的更多详情</summary>

下方的 **记录**、**操作**、**请求** 和 **详情** 会说明该条目涉及的内容。其他条目可能包含 **字段**、**尝试次数** 或 **店铺返回的原因**。没有更多信息时会显示 **此条目没有更多详情。**

</details>

:::warning 清除任何内容前，请先阅读警告
**请勿清除此设备的数据** 表示收银机上保存着尚未传到店铺的销售记录或变更。清除收银机数据会导致这些内容丢失。参见[清除所有本地数据](troubleshooting/clear-local-data.mdx)。
:::

## 将日志发送给支持团队 {#for-support}

1. 打开 **店铺健康状况 → 日志**，点击 **错误**。
2. 打开问题发生时的条目。如果有 **事件代码**，点击旁边的 **复制**（手机和平板应用中为 **分享**），并粘贴到消息中。如果没有，请提供错误代码和时间。
3. 点击 **复制调试信息**（手机和平板应用中为 **分享调试信息**），也将其粘贴进去。

   <details>
   <summary>报告包含的内容</summary>

   应用、WordPress、WooCommerce 和 WCPOS 的版本，店铺名称、连接情况、今日统计数据，最多十条受阻记录，以及最近十条错误。

   </details>

4. 检查粘贴的内容：条目的 **复制** 内容会包含收银员姓名（如果条目中有），错误信息也可能包含记录名称。然后通过 [Discord](https://wcpos.com/discord) 或发送邮件至 support@wcpos.com，将两份内容发送给支持团队。参见[支持](index.mdx#where-to-ask)。

:::warning 请勿向客户重复收费
切勿为了向支持团队复现问题而再次收款。
:::

5. 如果支持团队要求你复现问题，请先开启 **详细诊断**，再重复操作，并发送新的报告。

<JourneyShot manifest={manifest} device="phone" step={4} offsets={[[-28, 0], [107, 0], [15, -22], [164, 0], [115, -20], [-32, 0]]} maxWidth={390} alt="手机上的日志选项卡，已启用错误筛选：今日统计数据、复制调试信息、搜索框、筛选按钮、详细诊断，以及展开的 AUTH201 条目，其事件代码旁有复制按钮">

1. **复制调试信息** — 生成供支持团队查看的本机报告。在手机和平板应用中为 **分享调试信息**。
2. **搜索日志** — 查找支持团队询问的条目。
3. **错误** — 已启用，因此只显示错误。
4. **详细诊断：关闭** — 点击可记录更多详情。24 小时后会自动关闭。
5. **条目** — 在手机上，顶部显示时间和级别，接着是事件，下方显示所属模块及记录或耗时。点击可展开。
6. **复制** — 复制整个条目，以便粘贴到发送给支持团队的消息中。

</JourneyShot>

无论收银机使用哪种语言，两份报告都为英文。

## WP Admin 中的店铺日志 {#wp-admin-logs}

插件会在服务器上保留自己的日志，记录 POS 的请求、同步、付款、打印和收银台相关活动。任何能在 WP Admin 中打开 POS 设置的人都可以查看：前往 **POS → 设置**，在 **工具** 下选择 **日志**。

以下是启用 **警告** 筛选后的界面：

<JourneyShot manifest={manifest} device="desktop" step={5} offsets={[[70, 0], [33, 36], [60, 0], [650, 0], [690, 0], [200, 0]]} alt="WP Admin 中 POS 设置的日志页面：菜单中日志旁有红色数字 1 和琥珀色数字 426，页面显示检测到致命错误的提示，全部、错误和警告筛选中已选中警告，还有来源列表，以及今天和昨天分组下的警告">

1. **日志** — 位于 **工具** 下。红色数字统计新增错误，琥珀色数字统计新增警告。
2. **警告** — 当前启用的级别筛选条件。旁边还有 **全部** 和 **错误**。
3. **来源** — 扩展写入自身日志时，显示条目由哪个部分记录。
4. **今天** — 按天分组的条目。
5. **条目** — 点击可展开。
6. **在 WooCommerce 日志中查看** — 打开 WooCommerce 自身的日志。WordPress 记录了 PHP 致命错误时会显示此提示。

</JourneyShot>

<details>
<summary>供网站管理员参考：WP Admin 中的日志</summary>

- 设置菜单中 **日志** 上的 **红色和琥珀色数字**，统计自上次打开以来的错误和警告。每个用户都有独立的计数，打开 **日志** 后会重置为 0。
- **全部**、**错误**、**警告** — 按级别筛选。扩展写入自身日志时会出现 **来源** 列表。
- **按天分组的条目** — 显示在 **今天**、**昨天** 或某个日期下，每页 50 条，可通过 **上一页** 和 **下一页** 翻页。
- **点击条目** 可展开查看级别、来源、完整时间、消息及相关上下文，并显示 **复制** 按钮。

这些日志与 WooCommerce 自身的日志存储在一起，因此条目的保留时间由 WooCommerce 决定。此页面无法清除或下载日志。

WordPress 记录了 PHP 致命错误时，顶部会显示 **检测到致命错误 — 在 WooCommerce 日志中查看**。该链接会在新选项卡中打开 **WooCommerce → 状态 → 日志**。这类崩溃可能导致 POS 无法连接店铺，请将其提供给网站负责人。

</details>

## 出现问题时 {#goes-wrong}

**红色数字再次出现。** 上次查看后又记录了新错误。打开 **日志**，点击 **错误**，查看最新条目。

**“未找到日志”。** 没有条目符合搜索或筛选条件。点击 **全部** 并清空搜索内容。

**“上次检查未完成，正在重试”。** 收银机在上次检查时未能连接店铺，会自动重试。如果变更不断积压，请参见[店铺健康状况](store-health.mdx#waiting-to-send)。

**此处的受阻记录数与数据库中的不同。** 打开 **店铺健康状况 → 数据库**，查看需要你处理的内容。此处的 **受阻记录** 统计的是日志中记录的情况；数据库还会列出店铺拒绝或暂缓处理的变更。参见[需要你处理的情况](store-health.mdx#needs-attention)。

**收银机运行缓慢。** **耗时** 显示每项任务所用的时间。要了解过去 24 小时的整体情况，请参见[性能](store-health.mdx#performance)和[服务器性能](performance/server.mdx)。
