POS 在收银端计算各项总额，然后将订单保存到店铺。店铺会重新计算总额。两者不一致时，购物车和结账界面会显示警告：**店铺更改了此订单的总额**。

## 提示的含义 {#what-the-notice-means}

交付任何商品前，请先与顾客核对总额。销售不会被阻止，也不会丢失任何内容：订单保留店铺计算的金额，WooCommerce 报表和顾客订单显示的也是这些金额。然后[开始执行三项检查](#first-resync-the-pos)，让 POS 与店铺重新保持一致。

:::warning 问题修复前，请勿在此店铺进行离线销售
离线时，POS 使用相同的计算方式，但无法由店铺纠正计算结果。在找到原因之前，此店铺的离线销售可能产生错误总额，而您只有在恢复连接后才会发现。
:::

提示位于购物车明细下方、总额上方，并列出发生变化的项目：

- **金额以店铺为准。交付商品前请核对总额。** — 标题下方的文字。
- 每项发生变化的金额各占一行：**总计**、**税费**、**商品税额**、**折扣**、**折扣税额**、**运费** 或 **运费税额**，均按收银端金额 → 店铺金额的格式显示。
- **另有 N 条明细的金额不一致** — 当单条明细的金额也发生变化时显示。只显示条数，不逐一列出。
- **总额为何不一致** — 打开本页面。

此提示无法关闭。在订单离开购物车或切换店铺之前，它会一直显示在该订单上。关闭 WCPOS（浏览器中为重新加载页面）也会清除提示，但不会消除其原因。

## 首先，确保 POS 已获取店铺的设置 {#first-resync-the-pos}

POS 会在本地保留店铺设置和税率的副本。如果您在 WooCommerce 中进行了更改，而本地副本尚未更新，两者就会不一致。请按顺序完成以下步骤，然后[进行一次测试销售](#test-sale)。对照 WooCommerce 检查设置需要 `WP Admin` 访问权限；如果您没有权限，请将此页面交给店铺管理人员。

1. [检查在 WooCommerce 中设置的税费选项](#check-set-in-woocommerce)
2. [恢复服务器设置](#restore-server-settings)
3. [重新获取税率](#refresh-tax-rates)

### 1. 检查在 WooCommerce 中设置的税费选项 {#check-set-in-woocommerce}

打开菜单底部的 **设置**，然后进入 **税费**。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[245,0],[245,0],[245,0],[245,0],[0,-28]]} alt="设置中的税费页面：计税依据，下方依次为启用税费、输入的价格含税、运费税类和按小计舍入税额，每项均标有在 WooCommerce 中设置，并提供打开链接">

1. **启用税费** — 关闭时，所有销售均不计税。
2. **输入的价格含税** — 指定输入的价格是否已含税。
3. **运费税类** — 用于运费的税类。
4. **按小计舍入税额** — 开启时，对整笔订单的税额统一舍入一次；关闭时，逐条明细舍入。在包含多条明细的订单中，两种方式会使总额相差一两分。
5. **打开** — 在浏览器中打开 WooCommerce 的税费设置。这四项设置旁均有此链接。

</JourneyShot>

这四项[在 WooCommerce 中设置](../../settings/store/tax.mdx#set-in-woocommerce)，无法在 POS 中更改。请检查它们是否与 `WP Admin > WooCommerce > 设置 > Tax` 中的设置一致。POS 每次加载店铺时都会重新读取这些设置，因此在 WooCommerce 中更改任一设置后，请关闭 WCPOS 并重新打开（浏览器中则重新加载页面）。上方的 **计税依据** 用于选择决定税率的地址，请参阅[计税依据](../../settings/store/tax.mdx#calculate-tax-based-on)。

### 2. 恢复服务器设置 {#restore-server-settings}

部分设置仅复制一次，因此在此设备上更改的值会保留。这包括 POS 用于计算店内销售税费的店铺地址。如果 WooCommerce 中的店铺地址已更改，POS 会继续使用旧地址，直到您恢复服务器设置。

打开 **设置**，进入 **常规**，然后滚动到底部。点击 **恢复服务器设置**，再在对话框中点击一次 **恢复服务器设置**。按钮旁会出现 **已恢复**。有关此操作会更改哪些内容，请参阅[恢复服务器设置](../../settings/store/general.mdx#restore-server-settings)。

### 3. 重新获取税率 {#refresh-tax-rates}

点击菜单底部的脉搏图标打开 **店铺健康**，然后进入 **数据库**。在 **税率** 一行点击 **⋮**。

<JourneyShot manifest={manifest} device="tablet" step={2} alt="店铺健康的数据库页面：税率一行的菜单已展开，包含立即检查更改以及清除并重新下载">

1. **立即检查更改** — 立即向店铺请求新增或已更改的税率，无需等到下次检查。
2. **清除并重新下载…** — 移除此设备上的税率副本并重新下载。店铺中的税率仍会保留。当 **立即检查更改** 无法解决问题时，请使用此选项。

</JourneyShot>

请参阅[立即检查，或清除并重新下载](../store-health.mdx#clear-and-redownload)。

### 进行一次测试销售 {#test-sale}

无需实际收款。

1. 新建订单，使用与触发提示的销售订单相同的商品、顾客或计税地址。
2. 点击 **结账** 旁的 **⋮**，然后点击 **同步订单**。这会将订单发送到店铺，由店铺重新计算总额。请参阅[同步订单](../../pos/cart/order-actions.mdx#sync-order)。
3. 等待出现 **订单 #… 已同步**。在此之前，店铺尚未响应，因此没有提示并不能说明问题已解决。如果同步失败，请修复连接后重新同步。
4. 查看购物车明细下方。如果总额一致且没有出现提示，则测试销售通过。
5. [作废](../../pos/cart/order-actions.mdx#void)测试订单。该订单会移至 WooCommerce 的回收站。

每次更改 `WP Admin > WooCommerce > 设置 > Tax` 中的任何设置后，都请重新执行这三项检查。

<details>
<summary>正在使用 WooCommerce Tax？新地点的首笔销售可能出现差异</summary>

启用 [WooCommerce Tax](../../integrations/woocommerce-tax.mdx#what-to-expect) 自动计税后，在店铺从未计税的地点进行首笔销售时，通常会出现一次提示；如果当地税收辖区更改税率，还会再出现一次。相应税率记录是在该笔销售时创建的，因此 POS 当时尚未获取它。POS 会在下次检查时下载该税率，通常不超过一分钟，该地点的下一笔销售金额便会一致。在 **税率** 一行点击 **立即检查更改** 可立即获取税率。按顾客地址计税时，每个新邮政编码都可能出现一次这种情况。

</details>

如果测试销售仍出现提示，请查看下方原因。

## 原因有哪些 {#what-causes-it}

原因有三种，显示的提示均相同。如果都不符合，请[将详细信息发送给我们](#what-to-send-us)。

### POS 对某项税费设置或税率的处理存在差异 {#a-tax-or-rounding-setting}

这是最常见的原因。请在 WooCommerce 中检查以下项目：

- **输入的价格含税** — 位于 `WP Admin > WooCommerce > 设置 > Tax`。
- **按小计舍入税额** — 位于同一页面。POS 使用店铺的设置值；此项在 **设置 > 税费** 中显示为灰色，无法更改。
- **税率** — 某项税率的 **优先级** 或 **复合税** 设置不符合预期，或税率按邮政编码或城市设置。
- **小数位数** — 位于 `WP Admin > WooCommerce > 设置 > General`。POS 按店铺设置的小数位数舍入。在 POS 中更改 **小数位数** 只会改变金额的显示方式。

如果店铺最近更改过其中任何一项，请优先检查该项。

### 插件更改了订单总额 {#a-plugin-that-rewrites-totals}

附加费、费用、货币、会员奖励和按角色定价等插件，往往会在 POS 计算完成后，在店铺端重新计算总额。POS 无法获知这些规则，因此所有受其影响的销售都会出现总额不一致。

如果这正是您期望的行为，就没有发生故障：店铺会正确记录销售。但每笔受影响的销售都会出现提示，而且提示不会消失，因为 POS 无法复制店铺端的规则。同样，此店铺的离线销售金额也会与店铺原本应收取的金额不一致。

要找出具体是哪个插件，请参阅[插件冲突](plugin-conflicts.mdx)。

### POS 中的缺陷 {#a-bug-in-the-pos}

如果完成[上述三项检查](#first-resync-the-pos)后总额仍不一致，且没有插件更改总额，请[将下列详细信息发送给我们](#what-to-send-us)，以便调查。

## 多笔销售出现此问题时 {#when-it-happens-on-several-sales}

出现一次提示，表示有一笔销售需要检查。自 WCPOS 打开此店铺以来，如果已有三笔不同的销售出现总额不一致，提示会新增两行：

- **已有 N 笔销售出现此问题**
- **店铺与 POS 的总额计算方式不同。请将此信息交给店铺管理人员。**

这里统计的是销售笔数，而非保存次数：再次保存同一订单不会增加计数。

对于使用 [WooCommerce Tax](../../integrations/woocommerce-tax.mdx#what-to-expect) 的店铺，计数达到三次也可能是正常情况：每个新邮政编码的首笔销售都可能出现一次不一致（请参阅[进行一次测试销售](#test-sale)中的 **正在使用 WooCommerce Tax？**）。如果这些邮政编码各自的下一笔销售金额均一致，就没有问题。如果同一地点的后续销售仍不一致，请让店铺管理人员逐一排查[上述原因](#what-causes-it)。

<details>
<summary>另一种提示：收款前请检查此订单的金额</summary>

同一提示框还可能显示另一条消息，单独出现或位于 **店铺更改了此订单的总额** 下方。它表示 POS 无法读取计算订单总额所需的某些信息。此消息不含 **总额为何不一致** 链接。

- **无法读取某条明细已保存的价格详情** — 移除该明细后重新添加。
- **此订单使用的某项税率已不在店铺中** — 添加该明细后，此税率已在 WooCommerce 中被删除。收款前请检查订单税额。

</details>

## 需要提供的信息 {#what-to-send-us}

提示会同时显示每项发生变化的金额在两端的数值。结合以下信息，通常无需共享屏幕就能找到原因：

1. 包含金额的提示截图。
2. 说明您已完成[上述三项检查](#first-resync-the-pos)，但提示再次出现。
3. 税费设置：`WP Admin > WooCommerce > 设置 > Tax` 中的所有字段，包括是否启用自动计税，以及 **常规** 下的 **小数位数**。
4. 是否启用了 **按小计舍入税额**。
5. **税率表本身**，而不只是设置页面：每个税类下的所有记录，包括 **国家**、**州/省**、**邮政编码**、**城市**、**税率 %**、**优先级**、**复合税** 和 **运费**。多数问题的原因就在这些记录中；如果缺少这些信息，我们还需要再次询问。
6. 已启用且会影响价格、税费、费用或货币的插件。
7. 出现过提示的销售订单号。
8. **店铺健康 → 日志** 中的 **店铺总额与收银端不一致** 记录，以及对应的事件代码。请参阅[日志](../logs.mdx#for-support)。
