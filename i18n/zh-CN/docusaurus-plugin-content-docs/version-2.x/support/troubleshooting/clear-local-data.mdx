POS 会在每台设备上保存一份店铺数据副本，以便快速销售，并在离线时继续销售。**清除所有本地数据** 会删除这份副本，然后从店铺重新下载。当设备数据出现问题，其他局部修复方法都无效时，可以使用此功能。请将它作为最后的处理手段，而不是首选方法。

:::warning 尚未发送到店铺的销售记录将丢失
此设备尚未发送的所有内容都会一并删除，且无法恢复。其中可能包括已经完成、钱款已放入钱箱的销售记录。[请先检查](#check-unsent)。
:::

## 先尝试这些方法 {#try-first}

以下方法各自只修复一类问题，不会影响设备上的其他内容。

- **某类记录看起来不对**（产品、客户、订单）：在[店铺健康状况 → 数据库](../store-health.mdx#clear-and-redownload)中，点击对应行的 **清除并重新下载…**。设备上的其他内容不会改变，您也会保持登录。清除 **订单** 前，请完成或同步所有未结订单：从未同步过的订单只存在于此设备上。
- **WooCommerce 中的更改尚未同步过来：** 点击同一行菜单中的 **立即检查更改**。参见[下载与同步](../../products/sync.mdx)。
- **此设备上的语言、货币或数字格式不正确：** 点击 **设置 → 常规** 底部的 **恢复服务器设置**，即可恢复 WooCommerce 店铺的设置值。参见[常规设置](../../settings/store/general.mdx#restore-server-settings)。
- **界面出现红色的“出了点问题”面板：** 关闭该面板，或重新加载。参见 [CLIENT151](../../error-codes/CLIENT151.mdx)。

## 确认没有等待发送的内容 {#check-unsent}

店铺健康状况只统计当前登录的店铺和收银员。设备上每个店铺中各收银员的销售记录分别存储，而清除操作会将其全部删除。因此，请检查使用此设备的每位收银员，以及他们使用的每个店铺：

1. 打开 **店铺健康状况**，查看 **数据库** 选项卡上的 **等待发送的更改**。数量必须为 **0**，且统计数字下方不能出现 **… 项更改从未发送到服务器** 或 **… 项更改已暂缓** 面板。如果出现面板，请先处理其中的问题，参见[需要您处理时](../store-health.mdx#needs-attention)。
2. 查看购物车下方的未结订单。尚未付款或同步的订单只存在于此设备上，不计入上述数量。请完成订单，或在 **订单详情** 中点击 **同步订单**。参见[将订单保存到店铺](../../pos/cart/open-orders.mdx#sync-order)。订单栏每次只显示一台收银机的订单：如果此收银员还使用该店铺的其他收银机，请在收银员面板中选择 **切换收银机**，逐一检查。
3. 点击头像打开收银员面板，选择下一位收银员。要检查其他店铺，请在同一面板中选择 **切换店铺**。参见[选择店铺和收银机](../../stores/registers-and-devices.mdx#choosing-a-store-and-a-register)。
4. 重复以上步骤，直到每位收银员都通过检查。如果无法检查所有人，请勿清除数据，应[联系支持](../index.mdx)。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[40, 0], [150, 0], [160, 0], [100, -369]]} alt="店铺健康状况的数据库选项卡：顶部显示 0 项等待发送的更改，下方是此设备上的记录表格">

1. **店铺健康状况** — 菜单底部的脉搏图标。
2. **数据库** — 显示此设备上的内容以及等待发送的内容。
3. **等待发送的更改** — 正在发送到店铺的销售记录、客户和编辑内容。仍在购物车中的未结订单，以及等待您决定如何处理的更改，不计入此处。
4. **表格** — 显示此设备和店铺中的各类记录。表格的 **⋮** 菜单中包含[先尝试这些方法](#try-first)一节介绍的局部修复操作。

</JourneyShot>

- **数量为 0、没有提示面板，且没有未同步的未结订单：** 此收银员在该店铺中的工作已全部发送到店铺。请检查下一位。
- **大于 0：** 暂时不要清除。让设备联网，等待数量降至 0。如果数量一直不减少，请参见[“等待发送的更改”数量不减少](../store-health.mdx#waiting-to-send)。

## 会清除哪些内容 {#what-gets-cleared}

清除仅影响此设备，店铺和其他所有设备均不受影响。尚未发送的销售记录会丢失，打印机、扫描器和收银机选择需要重新设置。桌面和移动应用还会清除店铺及登录信息，因此之后需要重新连接店铺。

<Accordion>
<AccordionItem question="将从此设备清除的内容">

- 保存在此设备上的产品、客户、订单、优惠券和税费
- 尚未发送的销售记录和更改
- 此设备上配置的打印机和条形码扫描器
- 此设备的收银机选择
- 在此设备的 **设置 → 常规** 中所做的更改
- 店铺健康状况中此设备的活动日志
- 桌面和移动应用中的店铺及登录信息

</AccordionItem>
<AccordionItem question="店铺中会保留的内容">

- 此设备已发送的所有内容：销售记录、客户和编辑内容
- WooCommerce 中的产品、客户和订单
- 在 WP Admin 中所做的设置
- 收银机及已发送的关账记录

</AccordionItem>
</Accordion>

清除后，请参照[打印](../../hardware/printers/index.mdx)重新设置打印机，并参照[条形码扫描](../../settings/store/barcode.mdx)重新设置扫描器。

## 清除所有本地数据 {#clear}

1. 从菜单底部的齿轮图标打开 **设置**，然后选择设置列表顶部的 **常规**。
2. 滚动到底部，点击 **清除所有本地数据**。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[40, 0], [-72, 0], [-100, 0]]} alt="设置 → 常规页面已滚动到底部：菜单中的设置齿轮、设置列表顶部的常规、恢复服务器设置，以及下方的清除所有本地数据">

1. **设置** — 菜单底部的齿轮图标。**常规** 是设置列表中的第一个页面。
2. **恢复服务器设置** — [先尝试这些方法](#try-first)中介绍的局部修复操作。它不会删除任何内容。
3. **清除所有本地数据** — 页面上的最后一个按钮。删除任何内容前都会要求确认。

</JourneyShot>

3. 阅读确认提示，根据第一行决定下一步操作：
   - **如果提示具体有多少项更改，请点击取消。** *此设备上有 N 项更改从未发送到服务器，将永久丢失。* [请先发送这些更改](#check-unsent)。
   - **如果提示应用无法检查，只有在每个店铺的每位收银员都通过[检查](#check-unsent)后才能继续：0 项等待发送的更改、没有提示面板，且没有未同步的未结订单。** 否则，请点击 **取消** 并[联系支持](../index.mdx)。只要当前店铺没有等待发送的内容，应用就会显示 *应用无法检查等待发送的更改…*，因为它无法检查此设备上的其他收银员和店铺。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[-24, 0], [0, 32]]} alt="设置页面上的“清除所有本地数据？”确认对话框，显示尚未发送到服务器的销售记录警告，以及取消和清除所有本地数据按钮">

1. **取消** — 关闭确认对话框，不删除任何内容。
2. **清除所有本地数据** — 删除此设备上存储的全部内容。此操作无法撤销。

</JourneyShot>

4. 点击 **清除所有本地数据**。桌面应用会再次询问 **您确定吗？** 请点击 **是**，POS 随即重启。iOS 和 Android 应用则会显示 **需要重启**：请彻底关闭应用，然后重新打开。

## 接下来会发生什么 {#what-happens-next}

**在浏览器中**，页面会重新加载，由于您仍登录着 WordPress，因此会保持登录状态。**在桌面应用中**，应用会像首次使用时一样重新启动，您需要重新连接店铺并登录。**在 iOS 和 Android 应用中**，请按提示关闭并重新打开应用，然后重新连接店铺并登录。参见[连接店铺](../../getting-started/connect.mdx)。

随后，POS 会像首次使用时一样下载产品、客户和近期订单。参见[下载与同步](../../products/sync.mdx)。如果店铺有多台收银机，POS 会询问此设备对应哪一台。参见[选择店铺和收银机](../../stores/registers-and-devices.mdx#choosing-a-store-and-a-register)。

## 应用无法打开时 {#app-wont-open}

如果整个应用停留在 **出了点问题** 界面，并显示 **重试会保留此设备上的所有内容**，界面上会提供两个按钮。请先点击 **重试**。

:::warning 重置前请先检查
从此界面或下文介绍的桌面应用菜单重置，都会删除此设备尚未发送的所有销售记录。只有在[每个店铺的每位收银员](#check-unsent)都通过检查后才能重置：**0** 项等待发送的更改、没有提示面板，且没有未同步的未结订单。如果应用无法打开到可供检查的界面，请在重置前[联系支持](../index.mdx)。
:::

- **重试** — 尝试重新打开应用，不会更改任何数据。请始终先尝试此操作。
- **重置应用数据并重启** — 从此界面清除所有本地数据。它会询问 **重置应用数据并重启？** 并像设置中的确认提示一样，说明将丢失多少项更改。点击 **重置并重启** 或 **取消**。

应用可能无法确定是否有内容等待发送。此时，警告会说明重置所删除的内容 **可能** 包括已完成但从未发送到服务器的销售记录。如果您曾离线销售，而在 WooCommerce 中看不到这些销售记录，请勿重置，应联系支持。

桌面应用还可以通过菜单栏清除数据：选择 **窗口 → 高级 → 清除应用数据**，然后点击 **是**。当应用无法打开到设置页面时，可使用此方法。

## 出现问题时 {#goes-wrong}

**“需要重启”。** 应用无法自行重启。请彻底关闭并重新打开应用：它会在启动时清除数据。

**“重置未完成”。** 清除操作中途停止，在完成前无法保存任何新内容。请点击 **重新加载并重试**。如果没有此按钮，请彻底关闭应用，然后重新打开。

**“无法清除本地数据”。** 请彻底关闭应用，重新打开后再试一次。

**首次下载较慢。** 数据量大的店铺需要一些时间。您可以在[店铺健康状况 → 数据库](../store-health.mdx#database)中查看进度。旧订单等按需下载的记录，会在您打开时重新下载。

**清除后问题再次出现。** 请勿再次清除。记录您看到的情况并[联系支持](../index.mdx)。
