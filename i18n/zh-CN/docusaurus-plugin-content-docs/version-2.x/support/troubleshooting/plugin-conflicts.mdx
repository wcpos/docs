## 插件冲突的迹象 {#signs-of-plugin-conflicts}

添加或更新插件后，如果出现以下情况，可能存在插件冲突：

- **登录窗口显示错误或空白页。**
- **应用提示“此站点上的 WordPress REST API 需要身份验证”**，或显示其他插件的提示，说明只有已登录用户才能使用 REST API。
- **网站显示“此站点遇到了致命错误”**，出现在 POS 或 WP Admin 中。
- **商品、订单或客户数据停止下载**，或销售记录无法保存到店铺。
- **传统选项卡中支付网关的付款页面显示异常**，或页面上的按钮没有反应。
- **所有操作都很慢**，或请求超时。结账缓慢的问题有专门的页面：[结账性能](../performance/checkout.mdx)。

如果更新插件后 WP Admin 中的 **销售点** 菜单消失了，请参阅[更新插件后 POS 消失](../../getting-started/upgrading-to-2.mdx#pos-gone)。

## 开始之前：使用预发布站点 {#before-you-start-use-a-staging-site}

:::warning 不要在正式站点上排查问题
在收银系统使用的站点上停用插件，可能导致销售中断，并影响网店。请在预发布站点上操作。
:::

### 什么是预发布站点？ {#what-is-a-staging-site}

预发布站点是网站的副本，您可以在其中测试更改，而不会影响客户或收银系统。大多数托管服务商都支持在托管控制面板中点击几下即可创建。

### 如果托管服务商不提供预发布站点 {#if-your-host-doesnt-offer-staging}

请向托管服务商咨询如何复制站点。如果他们没有办法，建议迁移到支持此功能的服务商：不仅是这次排查，每次更新插件、主题、WordPress 和 WooCommerce 时，您都会用到预发布站点。WP Engine、SiteGround、Kinsta 和 Cloudways 都提供此功能。

## 步骤 1：查找致命错误 {#step-1-check-for-fatal-errors}

崩溃信息通常会指出导致问题的插件。请先检查以下内容：

1. **POS 日志。** 从侧边菜单打开 **店铺健康**，选择 **日志**，再选择 **错误**。请参阅[日志](../logs.mdx)。
2. **WooCommerce 致命错误日志。** 按照[致命错误](./critical-error.mdx)中的说明，在 WP Admin 中找到该日志。
3. **查看文件路径。** 例如，路径 `wp-content/plugins/<plugin-name>/…` 会指出插件名称。

如果错误指出了 WooCommerce 或 WCPOS 以外的插件，请在预发布站点上停用该插件，然后重试。如果没有任何信息指出插件，请继续执行步骤 2。

## 步骤 2：停用插件，再逐个重新启用 {#step-2-the-plugin-elimination-method}

没有致命错误，或问题是运行缓慢时，请使用此方法。

### 2.1 记录问题现象 {#21-create-a-baseline}

1. **打开预发布站点上的 POS。** 在浏览器中，访问预发布站点地址下的 `/pos`。在应用中，将预发布站点地址作为另一个店铺连接（参阅[连接](../../getting-started/connect.mdx)），并在继续之前检查 **您的站点** 下的地址。
2. **执行会失败的操作**，准确记录看到的情况：提示信息、所在界面以及耗时。
3. **如果运行缓慢**，请记录[日志](../logs.mdx)中的耗时，方便稍后比较。

### 2.2 停用 POS 以外的所有插件 {#22-disable-all-plugins-except-essential-ones}

**保持以下插件启用：**
- WooCommerce
- WCPOS
- WCPOS Pro（如果已安装）
- 支付网关（如果问题出在其付款页面）

**停用其他所有插件：**
1. 前往 `WP Admin > 插件`。
2. 勾选其他所有插件。
3. 在 **批量操作** 中选择 **停用**。
4. 点击 **应用**。

以下是使用免费版插件的店铺中，尚未勾选任何项目时 **插件** 列表底部的画面：

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[59, 52], [59, 52], [59, 52], [105, 0], [78, 0]]} alt="WP Admin 中插件列表的底部：WCPOS Pro、WCPOS 和 WooCommerce 各行及其复选框、WooCommerce 有新版本可用的通知，以及列表下方的批量操作和应用">

1. **WCPOS Pro** — 不要勾选。此店铺已安装该插件，但尚未启用。
2. **WCPOS** — 不要勾选。
3. **WooCommerce** — WCPOS 依赖它，因此其复选框呈灰色，会保持启用状态。
4. **批量操作** — 勾选其他所有插件后，选择 **停用**。
5. **应用** — 停用已勾选的插件。

</JourneyShot>

### 2.3 重试 {#23-test-the-issue}

1. **清除所有缓存**：托管服务商、CDN 以及所有缓存插件的缓存。
2. **执行之前失败的操作。** 现在能正常运行了吗？
3. **如果运行缓慢**，将当前耗时与之前记录的耗时进行比较。

**现在可以正常运行：** 原因很可能是刚才停用的某个插件。前往[逐个重新启用插件](#24-enable-plugins-one-by-one)，找出哪个插件会让问题再次出现。

**仍然失败：** 此次测试尚未找到原因。不要逐个重新启用插件。请按[步骤 3](#step-3-check-for-theme-conflicts)检查主题。如果也不是主题导致的，请检查：
- 服务器资源和防火墙：参阅[服务器性能](../performance/server.mdx)
- 位于网站前端的服务，例如 [Cloudflare](./cloudflare.mdx)
- WordPress、WooCommerce 或 WCPOS 本身：请[联系支持](#getting-help)，并提供您在[记录问题现象](#21-create-a-baseline)中记下的内容

### 2.4 逐个重新启用插件 {#24-enable-plugins-one-by-one}

<details>
<summary>先测试哪些插件</summary>

从最容易产生冲突的插件类型开始，以便更快找到原因：
1. **安全和登录插件**：Wordfence、Sucuri、Solid Security 等
2. **缓存和优化插件**
3. **支付网关**
4. **其他 WooCommerce 扩展**
5. **SEO 插件**
6. **其他所有插件**

</details>

**逐个测试插件：**

1. **启用一个插件。**
2. **重试。**
3. **仍然正常：** 启用下一个插件，然后重试。
4. **再次失败：** 记下刚启用的插件。它很可能就是冲突来源。

**确认是否确实是该插件：**

1. **停用刚才重新启用的插件**，仅保留 WooCommerce、WCPOS、WCPOS Pro 和之前一直启用的支付网关。
2. **只启用您记下的那个插件**，然后重试。
3. **问题再次出现：** 该插件就是冲突来源。
4. **问题没有再次出现：** 可能还有其他插件参与其中。逐个启用其他插件，并记下哪两个插件同时启用时会导致问题再次出现。

### 2.5 记录排查结果 {#25-document-your-findings}

1. **插件名称和版本。**
2. **它导致的问题**，使用您在 2.1 中记录的描述。
3. **是否有更新版本。**

执行[步骤 4](#step-4-resolving-plugin-conflicts)和[联系支持](#getting-help)时，您会用到这些信息。

## 步骤 3：检查主题 {#step-3-check-for-theme-conflicts}

POS 界面不使用您的主题，因此主题很少会导致收银系统异常。但它仍可能影响 WordPress 发送给 POS 的内容：

- 结账界面 **传统** 选项卡中支付网关的付款页面，以及[网页结账](../../payment/gateways/web-checkout.mdx)网关将客户引导至的网店结账页面
- WP Admin 界面，包括 POS 设置
- POS 发出的 REST API 请求，因为 WordPress 也会在处理这些请求时运行主题代码

### 使用默认主题测试 {#test-with-a-default-theme}

1. **在预发布站点上**，切换到 WordPress 默认主题，例如 Twenty Twenty-Five 或 Twenty Twenty-Four。
2. **重试。**
3. **现在可以正常运行：** 原因在于主题。请将具体问题告知主题开发者。

## 步骤 4：解决冲突 {#step-4-resolving-plugin-conflicts}

确定问题插件后，请依次尝试以下方法。

### 方法 1：更新插件 {#option-1-update-the-plugin}

1. **检查是否有更新。** 冲突可能已经修复。
2. **先在预发布站点上更新**，然后重试。
3. **如果问题已解决**，并且 POS 和网店结账都仍能正常运行，再更新正式站点。

### 方法 2：将 POS 排除在插件的处理范围之外 {#option-2-exclude-the-pos}

大多数冲突可以通过调整其他插件的设置解决，无需停用插件。请参阅[需要排除的内容](#what-to-exclude)，以及[已知插件冲突](#known-plugin-conflicts)中对应插件的解决方法。

### 方法 3：寻找替代插件 {#option-2-find-an-alternative}

1. **寻找另一个插件**，实现相同功能。
2. **在预发布站点上试用。**
3. 切换之前，**迁移原有设置**。

### 方法 4：告知插件开发者 {#option-3-contact-plugin-developer}

向他们提供：
- 插件版本，以及 WordPress、WooCommerce 和 WCPOS 的版本
- 具体问题和完整的提示信息
- 复现问题的步骤

### 方法 5：请开发者提供临时解决方案 {#option-4-custom-solution}

如果某个插件不可或缺，WordPress 开发者通常可以利用该插件自身的钩子，阻止产生冲突的部分在 POS 请求和 POS 页面中运行。

## 需要排除的内容 {#what-to-exclude}

下文的大多数解决方法，是让其他插件不再干扰 POS，而非停用插件。如果[已知插件冲突](#known-plugin-conflicts)中列出了您的插件，对应条目会说明需要修改的设置。如果没有，请将以下详细信息交给网站管理人员或插件支持团队。

<details>
<summary>供网站管理人员参考的地址和设置</summary>

POS 通过 WordPress 站点的 REST API 读取和保存店铺数据。如果插件拦截、缓存或重写这些请求，就可能导致 POS 异常。如果列表中没有该插件：

- **防火墙和 REST API 设置：** 放行 `/wp-json/` 本身以及 `/wp-json/wcpos/` 下的所有地址。其他地址仍应保持防护。
- **缓存和脚本优化设置：** 排除 `/pos` 和 `/wcpos-checkout/`。
- **找不到设置：** 将此表发送给插件支持团队，询问应在哪里添加这些地址。

| 地址 | POS 的用途 |
| --- | --- |
| `/wp-json/wcpos/` | POS 读取和保存的所有数据 |
| `/wp-json/` | 应用连接时查找店铺。应用读取的是此地址本身，而不是它下面的地址 |
| `/pos` | 浏览器中的 POS。这是默认地址；您的站点可能在 `WP Admin > 设置 > Permalinks` 中使用了其他 **销售点前缀** |
| `/wcpos-auth/` | 应用的登录窗口 |
| `/wcpos-checkout/` | **传统** 选项卡中支付网关的付款页面，以及收据 |


:::note 应用的登录窗口不使用 WordPress 登录页面
桌面和移动应用在独立窗口中，通过 `/wcpos-auth/` 上 WCPOS 自身的表单登录。修改 WordPress 登录页面的插件，例如自定义登录地址、双重验证代码、验证码或仅允许电子邮箱登录的插件，不适用于此表单。但在浏览器中打开 POS 时，这些插件会生效，因为浏览器会先将您引导至常规 WordPress 登录页面。
:::

</details>

## 常见的冲突插件类型 {#common-conflicting-plugin-types}

<details>
<summary>哪些类型的插件可能产生干扰？</summary>

**最容易产生冲突：**

- **安全和防火墙插件** 可能拦截 REST API 请求，在大量请求后封禁收银系统，或阻止登录。
- **缓存和优化插件** 可能向 POS 返回过时的响应，或破坏 WordPress 为 POS 生成的页面上的脚本。
- **登录、会员和访问控制插件** 可能禁止未登录用户访问 REST API，或改变用户的登录方式。
- **页面构建器和前端注入插件** 可能将自身的脚本和覆盖层加载到支付网关的付款页面中。
- **保存订单或商品时运行的任何插件** 都可能拖慢每笔销售，或导致销售记录无法保存。

**很少产生问题：** 联系表单、社交媒体、分析和内容插件很少影响 POS。[WooCommerce Tax](../../integrations/woocommerce-tax.mdx) 与 POS 兼容：POS 销售会使用与线上订单相同的自动税率。

</details>

## 已知插件冲突 {#known-plugin-conflicts}

以下插件已被报告与 WCPOS 存在冲突。展开您使用的插件，查看问题现象和解决方法，然后先在预发布站点上修复。

跳转至：[安全和登录](#security-and-login-plugins) · [缓存和优化](#performance-caching-optimisation-plugins) · [页面构建器](#page-builders-front-end-injectors) · [WooCommerce 扩展及其他插件](#woocommerce-extensions-other-plugins) · [服务器层面的冲突](#server-level-conflicts) · [WCPOS 已处理](#handled-by-wcpos)

### 安全和登录插件 {#security-and-login-plugins}

这些是最常见的冲突来源。它们会拦截 POS 发出的请求，导致应用无法连接、登录或下载店铺数据。

<details>
<summary>Wordfence：POS 无法连接或下载</summary>

**问题现象：** 其防火墙拦截了 POS 的 REST API 请求。

**解决方法：** 在防火墙中放行 `/wp-json/wcpos/`。仅放行该地址，不要放行整个 REST API。

</details>

<details>
<summary>Really Simple Security：REST API 被拦截或重定向</summary>

**问题现象：** 它会阻止 REST API 访问，或强制重定向。

**解决方法：** 在插件的 **高级** 设置中关闭 REST API 限制。

</details>

<details>
<summary>Solid Security (iThemes Security)：REST API 被拦截或收银系统被封禁</summary>

**问题现象：** 它会拦截 REST API，或将收银系统的请求视为暴力破解攻击并予以封禁。

**解决方法：** 放行 POS 的地址 `/wp-json/` 和 `/wp-json/wcpos/`，以及服务器自身的 IP 地址。不要对 IP 地址设置全站放行。

</details>

<details>
<summary>Sucuri：POS 无法连接或下载</summary>

**问题现象：** 其防火墙拦截了 REST API 请求。

**解决方法：** 在 Sucuri 控制面板中放行 `/wp-json/wcpos/`。

</details>

<details>
<summary>Force Login 及其他关闭 REST API 访问的插件：“需要身份验证”</summary>

**问题现象：** 应用提示 _“此站点上的 WordPress REST API 需要身份验证”_，或显示插件自身的提示，说明只有已登录用户才能使用 REST API。

**解决方法：** 允许未登录访客访问 REST API，或至少允许访问 `/wp-json/` 和 `/wp-json/wcpos/`。

</details>

<details>
<summary>Security Optimizer：浏览器中的 POS 要求使用自定义登录 URL</summary>

**问题现象：** 在浏览器中打开 POS 时，停留在要求使用自定义登录 URL 的提示页面。

**解决方法：** 先通过自定义登录 URL 登录 WP Admin，再前往 `/pos`。

</details>

<details>
<summary>Jetpack CRM Client Portal：用户无法登录</summary>

**问题现象：** 用户无法登录 POS。

**解决方法：** 仅停用 Client Portal 扩展，不要停用整个 Jetpack CRM。

</details>

### 性能、缓存和优化插件 {#performance-caching-optimisation-plugins}

<details>
<summary>WP Rocket、Autoptimize、Hummingbird、Smush：传统付款页面异常</summary>

**问题现象：** 延迟加载或压缩 JavaScript 会导致 **传统** 选项卡中的网关付款页面异常。

**解决方法：** 将 `/wcpos-checkout/` 和 `/pos` 排除在 JavaScript 优化范围之外。

</details>

<details>
<summary>LiteSpeed Cache：桌面应用在结账时重新加载</summary>

**问题现象：** 桌面应用在结账时反复重新加载。

**解决方法：** 更新 WCPOS 和 LiteSpeed Cache，清除缓存，并将 `/wcpos-checkout/` 和 `/pos` 排除在缓存范围之外。

</details>

### 页面构建器和前端注入插件 {#page-builders-front-end-injectors}

这些插件会将自身的脚本和覆盖层加载到 **传统** 选项卡中的网关在 POS 内打开的付款页面上。该页面有一个 **结账设置** 按钮，可用于移除页面中的脚本和样式：请参阅[支付网关的付款页面显示异常](../../pos/checkout/troubleshooting.mdx#checkout-settings-troubleshooting)。

<details>
<summary>Elementor：无法展开付款方式</summary>

**问题现象：** `elementor-frontend.js` 导致付款页面异常，无法展开付款方式。

**解决方法：** 在 **结账设置** 的 **禁用所选脚本** 下移除 Elementor 的前端脚本，或阻止 Elementor 在 `/wcpos-checkout/` 上加载该脚本。

</details>

<details>
<summary>Omnisend 及其他营销插件：付款页面布局异常</summary>

**问题现象：** 它们的脚本导致付款页面布局和支付功能异常。

**解决方法：** 在 **结账设置** 的 **禁用所选脚本** 下移除它们的脚本。

</details>

<details>
<summary>MyStickyElements、Complianz：按钮或横幅遮挡付款页面</summary>

**问题现象：** 悬浮按钮或 Cookie 横幅遮挡了付款页面。

**解决方法：** 在这些插件中设置排除 `/wcpos-checkout/`，或在 **结账设置** 中移除它们的脚本。

</details>

### WooCommerce 扩展及其他插件 {#woocommerce-extensions-other-plugins}

<details>
<summary>Stripe Tax：不支持 POS 订单</summary>

**问题现象：** 它不支持通过 REST API 创建的订单，而 POS 的每个订单都是通过 REST API 保存的。

**解决方法：** 没有临时解决办法。[WooCommerce Tax](../../integrations/woocommerce-tax.mdx) 是支持 POS 的自动税费计算方案。

</details>

<details>
<summary>WP Activity Log：数据库被填满，店铺变慢</summary>

**问题现象：** 它会记录 POS 的每次更改，导致数据库被填满，店铺运行变慢。

**解决方法：** 停用该插件，或在其日志记录中排除 POS 商品和订单。

</details>

<details>
<summary>MailerLite：保存销售记录时出现服务器错误（500）</summary>

**问题现象：** 同时启用 MailerLite Signup Forms 和 MailerLite WooCommerce 集成时，POS 保存订单会导致服务器内存耗尽，并返回服务器错误（500）。

**解决方法：** 同时停用两者以确认原因，然后联系 MailerLite。

</details>

<details>
<summary>The Courier Guy Shipping：订单无法保存</summary>

**问题现象：** POS 因服务器错误而无法保存订单。

**解决方法：** 恢复到该插件的上一个版本，或联系插件开发者。

</details>

<details>
<summary>Mollie：直接银行转账选项消失</summary>

**问题现象：** 它会隐藏 POS 结账中的直接银行转账选项。

**解决方法：** 更新 Mollie。

</details>

<details>
<summary>CTX Feed：POS 设置页面出现 403 错误</summary>

**问题现象：** POS 设置页面偶尔出现 403 错误。

**解决方法：** 停用插件以确认原因。目前没有已知的设置可以解决此问题。

</details>

<details>
<summary>条码扫描插件：订单无法保存或显示</summary>

**问题现象：** 它们会破坏 REST API 发送的订单数据，导致订单无法保存或显示。

**解决方法：** 停用这些插件。POS 自身即可读取条码：请参阅[条码扫描](../../pos/product-panel/barcode-scanning.mdx)。

</details>

<details>
<summary>PixelYourSite、PixelMySite：致命错误</summary>

**问题现象：** 出现致命错误：_在布尔值上调用成员函数 `is_type()`_。

**解决方法：** 停用该插件。

</details>

<details>
<summary>Google Listings & Ads：致命错误，找不到 WCPOS 类</summary>

**问题现象：** 出现致命错误，提示 _找不到_ 某个 WCPOS 类。

**解决方法：** 删除所有 WCPOS 插件，然后只安装最新版 WCPOS Pro。

</details>

<details>
<summary>WooCommerce Subscriptions：阻止从 1.7 或更早版本升级 Pro</summary>

**问题现象：** 它会阻止 WCPOS Pro 的升级步骤。

**解决方法：** 停用 Subscriptions，启用 WCPOS Pro 并等待升级完成，然后重新启用 Subscriptions。

</details>

:::warning Stripe Terminal：请在 WooCommerce 付款设置中保持关闭
仅在 `WP Admin > POS > 设置 > 结账` 中为 POS 启用 Stripe Terminal。无需在 `WP Admin > WooCommerce > 设置 > 支付` 中启用它。在后者启用后，它会出现在网店结账页面中，并曾导致线上客户无法结账。请参阅 [Stripe Terminal](../../payment/gateways/stripe-terminal.mdx)。
:::

### 服务器层面的冲突 {#server-level-conflicts}

<details>
<summary>Web 服务器设置的安全响应头：POS 停留在标志画面，或页面空白</summary>

在 `.htaccess`、Nginx 或托管控制面板中设置的 `Content-Security-Policy` 或 `X-Frame-Options` 配置行。

**问题现象：** POS 停留在标志画面，或传统选项卡中的付款页面或收据显示为空白。

**解决方法：** 让该响应头不应用于 `/pos`、`/wcpos-auth/` 和 `/wcpos-checkout/`。仅放行 CDN 地址还不够，因为 POS 页面通过内联脚本启动，并从 `cdn.wcpos.com` 和 `cdn.jsdelivr.net` 获取文件。如果这些响应头由 WordPress 或插件添加，WCPOS 会从自身页面中移除它们，但无法移除 Web 服务器添加的响应头。

</details>

<details>
<summary>GoDaddy Website Firewall：“收到 'undefined'”</summary>

**问题现象：** 它会拦截 `/wp-json/`，并提示 _“收到 'undefined'”_。

**解决方法：** 在防火墙中放行 `/wp-json/` 路径：请参阅[服务器性能](../performance/server.mdx#hosting-specific-notes)。

</details>

### WCPOS 自行处理的冲突 {#handled-by-wcpos}

<details>
<summary>过去存在冲突、现在无需您处理的插件</summary>

保持 WCPOS 为最新版本，以下情况就无需额外设置：

- **插件添加的安全响应头。** Wordfence、LiteSpeed Cache 和其他插件可能添加 `Content-Security-Policy`，导致 POS 无法加载。WCPOS 会从自身页面中移除 `Content-Security-Policy` 和 `X-Frame-Options`。如需在这些页面上设置策略，开发者可使用 `wcpos_content_security_policy` 过滤器。
- **JWT 身份验证插件。** 过去这些插件会拒绝 POS 的登录令牌，导致登录后的每个请求都因 403 错误而失败。现在，WCPOS 在自行完成请求的身份验证后，会清除这些插件的错误；其他插件的错误仍会正常返回。
- **Image Prioritizer。** 它会填充应用用于查找 WordPress 站点的 `Link` 响应头。如果该响应头未指明站点的 REST API，应用会改为在 `/wp-json/` 查找。如果应用仍提示 _“该站点似乎不是 WordPress 站点”_，请停用该插件。
- **保存商品时运行的插件**（Jetpack、Astra、Xero 等）。旧版 WCPOS 会导致它们在每次请求时添加重复数据行。此问题已在 1.8.12 中修复，升级时也已移除重复数据。
- **WooCommerce Stripe 11.1.0。** 其银行卡脚本会导致 **传统** 选项卡付款页面上的其他所有付款方式都无法支付。如果 Stripe 插件版本低于 11.1.1，WCPOS 会从该页面移除 Stripe 的银行卡脚本和样式。这样其他付款方式便可正常使用，但 Stripe 的银行卡表单不会显示。Stripe 已在 11.1.1 中修复此冲突。更新 Stripe 后，WCPOS 会再次保留页面上的银行卡表单，即使之前保存 **结账设置** 时曾将其禁用。
- **MyParcel。** 包含[杂项商品](../../pos/cart/index.mdx#miscellaneous-products)的购物车过去无法结账，因为保存订单时 MyParcel 会出现致命错误。现在 WCPOS 会像 WooCommerce 一样，告知 MyParcel 该行项目没有对应的商品目录条目，从而使销售顺利完成。

</details>

## 预防建议 {#prevention-tips}

### 定期维护 {#regular-maintenance}

1. **保持插件为最新版本。**
2. **删除不使用的插件**，不要只是停用。
3. 在更新正式站点之前，**先在预发布站点上测试每次更新**。
4. 参考[服务器性能](../performance/server.mdx)，**关注服务器速度**。

### 选择插件 {#plugin-selection-best-practices}

1. **选择持续更新的插件**，并参考用户好评。
2. **不要同时运行两个功能相同的插件。**
3. **确认插件说明中已注明通过您所用 WooCommerce 版本的测试。**
4. **每次只添加一个插件**，每次添加后都检查收银系统。
