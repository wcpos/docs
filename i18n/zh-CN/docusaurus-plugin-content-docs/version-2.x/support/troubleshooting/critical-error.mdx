“此站点遇到了致命错误。”是网站崩溃时 WordPress 自身显示的提示：PHP 错误使网站在响应 POS 之前就停止了运行。故障出在网站，而非收银设备。收银设备上可能存有尚未同步到店铺的更改，因此在修复网站期间请勿清除其数据。

## 收银端操作 {#at-the-till}

:::warning 请勿清除此收银设备的数据
日志中的错误记录也会提示：“请勿清除此设备的数据，其中可能包含尚未同步到店铺的更改。”清除数据会导致这些更改丢失。如果按下述方法再试一次后仍然失败，请等待网站修复。
:::

**正在收款？** 暂时不要再次扣款。请按照提示中结账错误代码对应页面的说明操作：

- [CHECKOUT101](../../error-codes/CHECKOUT101.mdx)：可以安全地重试此购物车的结账操作。
- [CHECKOUT201](../../error-codes/CHECKOUT201.mdx)：交易可能已经完成。

对于其他操作：

1. 再尝试执行一次该操作。崩溃可能只是偶发情况。
2. 如果再次失败，请通过菜单底部的脉搏图标打开 **店铺健康状况**，然后打开 **日志**，再按 **错误**。
3. 点按 **SYNC131** 记录将其打开，查看数据是否安全。**帮助 — SYNC131** 可打开该代码的说明页面。
4. 按 **复制调试信息**，将其连同出错时间发送给网站维护人员。

## 错误会显示在哪里 {#where-you-see-it}

- **收银设备上**，操作失败后会显示提示和错误代码 [SYNC131](../../error-codes/SYNC131.mdx)：店铺发生错误，未能完成请求。
- **店铺返回的原因中**，例如结账时或店铺拒绝某项更改时，POS 可能会显示这一原因。原因可能是 WordPress 的提示语；如果网站显示错误详情，也可能是 PHP 错误本身，例如 *wp-includes/class-wpdb.php:2324 中允许的 134217728 字节内存已耗尽*。
- **结账时**，提示会使用结账错误代码，说明付款的处理情况：可以安全重试购物车结账时显示 [CHECKOUT101](../../error-codes/CHECKOUT101.mdx)；POS 无法确定交易是否完成时显示 [CHECKOUT201](../../error-codes/CHECKOUT201.mdx)。再次扣款前，请先按照相应页面的说明操作。
- **浏览器中**，如果网站在加载 POS 页面时崩溃，WordPress 会显示自身的错误页面，而非 POS。
- **店铺健康状况 → 日志中**，显示为 **状态**列带有 **SYNC131** 的错误记录。

## 在网站上查找原因 {#find-the-cause}

此部分需要由能够登录 WP Admin 的人员操作。

1. 前往 **WooCommerce → 状态 → 日志**，打开故障发生时间附近最新的 **fatal-errors** 日志。崩溃几乎都会在此留下 PHP 错误记录。
2. 阅读错误的第一行及其中指明的文件。`wp-content/plugins/` 下的文件路径会指出所属插件；`wp-content/themes/` 下的文件路径则会指出所属主题。
3. 如果崩溃是在更新插件或主题后开始的，请撤销该更新，或停用相应插件或主题。如果崩溃是在升级 PHP 后开始的，请让托管服务商检查此次更改。[插件冲突](./plugin-conflicts.mdx)介绍了如何找出有问题的插件。
4. WooCommerce 日志中没有记录？WooCommerce 的[查找 PHP 错误日志](https://woocommerce.com/document/finding-php-error-logs/)指南介绍了其他查找位置，您也可以向托管服务商索取同一时段的服务器 PHP 错误日志。
5. 修复后，返回收银设备。如果涉及付款，请先查看结账错误代码对应的页面，再决定是否再次扣款。对于其他操作，请重试。

只要 WooCommerce 写入了 fatal-errors 日志文件，**WP Admin > POS > 设置**中 **工具**下的 **日志**就会显示 **检测到致命错误 — 在 WooCommerce 日志中查看**。该链接会打开 WooCommerce 日志，并筛选出致命错误。

:::tip WordPress 发来的邮件
当插件或主题导致崩溃时，WordPress 会向网站管理员邮箱发送邮件：**您的站点遇到了技术问题**。登录后，邮件中的链接会以恢复模式打开 WP Admin。即使 WP Admin 无法正常打开，您也能在恢复模式中停用有问题的插件。
:::

### 可能遇到的错误 {#common-errors}

**允许的 … 字节内存已耗尽。** PHP 内存不足。请让托管服务商提高 PHP 的内存限制。

**其他插件的文件中出现错误。** 某些插件已知会与 POS 冲突。请在[已知插件冲突](./plugin-conflicts.mdx#known-plugin-conflicts)中查找该插件及其解决方法。

**移除免费插件并上传 Pro 后，出现致命错误或 *无法修改标头信息*。** Pro 不依赖免费插件：它已包含免费插件的代码，可以独立运行，因此无需重新安装免费插件。请按上文说明阅读错误的第一行及其中指明的文件。如果 WP Admin 显示 **WCPOS Pro 加载失败。请运行 composer install。** 则说明 zip 文件缺少 Pro 的部分内容：请从[下载](https://wcpos.com/account/downloads)页面重新下载并上传。请参阅[安装 Pro 插件](../../getting-started/pro-license.mdx#installation)。
