**这不是一项设置：** 本页介绍如何修正或添加 POS、插件或本文档的翻译。

WCPOS 使用 AI 翻译，每批译文发布前都会经过人工审核。使用母语操作 WCPOS 的用户能发现机器遗漏的问题。如果 POS、插件或本文档中的某个词翻译不当，您可以自行修正：只需在 GitHub 上修改一行文本并提交拉取请求，无需具备开发经验。

跳转至：[修正 POS 或插件翻译](#apps-and-plugin) · [修正本文档翻译](#docs) · [添加语言](#add-a-language)

## 查看您所用语言的界面 {#see-it}

修改前，请先在实际使用该词的界面上找到它。POS 默认使用店铺的语言，即 WordPress 中设置的站点语言。要在某台设备上试用其他语言，请从菜单打开 **设置**，然后选择 **常规**。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[40, 0], [120, 0], [110, 0]]} alt="设置中的常规页面：本地化区域的语言选择器已展开，搜索框中输入了 Deutsch">

1. **设置** — 位于菜单靠近底部的位置。
2. **常规** — 设置中的第一个页面。
3. **语言** — 此设备上 POS 的显示语言。点击可打开列表。参见[语言](../settings/store/general.mdx#language)。

</JourneyShot>

在列表的搜索框中输入名称，找到您的语言后点击它：

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[110, 0], [150, 0], [292, 0]]} maxWidth={700} alt="展开的语言列表：搜索框中输入了 Deutsch，下方显示德语（Deutsch）和德语（瑞士）（Deutsch (Schweiz)）">

1. **搜索** — 输入语言的英文名称或该语言自己的名称：输入 **Deutsch** 即可找到德语。
2. **德语（Deutsch）** — 点击一种语言即可切换。每种语言的英文名称后都附有该语言自己的名称。
3. **德语（瑞士）** — 地区变体会列在主要版本旁边。请选择店铺使用的版本。

</JourneyShot>

此更改仅保存在当前设备上。店铺和其他设备仍使用各自的语言。要恢复为店铺的语言，请点击同一页面底部的 **恢复服务器设置**：这也会恢复店铺提供的货币和数字格式。插件的 WP Admin 页面则使用您在 WordPress 中设置的语言。

## 修正 POS 或插件中的用词 {#apps-and-plugin}

所有应用和插件的翻译都保存在 [wcpos/translations](https://github.com/wcpos/translations)。

1. **找到文件**，确认它对应您的语言和要修正的 WCPOS 部分。以德语为例，POS 文本位于[德语 POS：`core.json`](https://github.com/wcpos/translations/blob/main/translations/js/de_DE/monorepo/core.json)，插件的 PHP 文本位于[德语插件：`woocommerce-pos-de_DE.po`](https://github.com/wcpos/translations/blob/main/translations/php/de_DE/woocommerce-pos-de_DE.po)。下方的 **各文件存放的内容** 列出了所有文件夹。
2. **找到对应文本。** 在文件中搜索您在界面上看到的文字：按 Ctrl+F，Mac 上按 ⌘F。JSON 文件中的译文紧跟在键之后；PO 文件中的译文则位于英文 `msgid` 下方的 `msgstr` 行。请确认键或英文原文与您看到它的位置相符。
3. **只修改译文。** 请将键、 `msgid` 以及所有占位符（例如 `{name}`、 `%s`、 `%d` 或 `<strong>` ）保持原样。

   JSON 文件中的每个条目依次包含键、冒号和译文。这里的英文是 `Delete {name}`，而德语把动词放在最后：

   ```json title="Before"
   "coupons.delete":
     "Löschen {name}",
   ```

   ```json title="After"
   "coupons.delete":
     "{name} löschen",
   ```

   只有德语文字发生了变化。键 `"coupons.delete"` 和 `{name}` 均保持原样。

   PO 文件中的 `msgid` 是英文，`msgstr` 是您的语言：

   ```text
   msgid "Copy of %s"
   msgstr "Kopie von %s"
   ```

   只修改 `msgstr` 行中的文字。请保留 `msgid` 行和 `%s` 不变。

4. **通过拉取请求提交。** 参见[在 GitHub 上提交修正](#send)。

<details>
<summary>各文件存放的内容</summary>

| 文件夹 | 存放的内容 |
|---|---|
| `source/` | 自动收集的英文文本。请勿编辑。 |
| `translations/js/<locale>/monorepo/` | 收银员使用的 POS：按钮、购物车、结账、对话框和错误提示。 |
| `translations/js/<locale>/electron/` | Windows 和 macOS 桌面应用自身的窗口和菜单。 |
| `translations/js/<locale>/woocommerce-pos/` | 免费插件的 WP Admin 页面，例如设置和模板，每个页面对应一个文件。 |
| `translations/js/<locale>/woocommerce-pos-pro/` | Pro 插件的 WP Admin 页面，例如店铺编辑器和 Pro 设置。 |
| `translations/php/<locale>/` | 插件的 PHP 文本。只编辑 `.po` 文件。旁边的 `.mo` 和 `.l10n.php` 文件由仓库脚本根据它重新生成，因此拉取请求的检查可能会提示 `.mo` 已过期。请在拉取请求中说明，您修改的只有 `.po` 文件。 |

许多语言既有基础文件夹，也有地区文件夹，例如 `de` 以及 `de_DE`、`de_AT`。POS 会读取其语言指向的地区文件夹：德语（Deutsch）读取的是 `de_DE`。每次发布时，基础文件夹 `de`、`en`、`es`、`fr`、`nl`、`pt` 和 `zh` 都会从各自的主要地区文件夹复制内容（例如 `de` 从 `de_DE` 复制），因此请在地区文件夹中修正：仅对基础文件夹所做的更改会被覆盖。

</details>

如果没有您的语言，请参见[添加语言](#add-a-language)。

## 修正本文档中的页面 {#docs}

在 [wcpos/docs](https://github.com/wcpos/docs) 中，每种语言都有各页面的独立副本。

1. **找到文件。** 页面底部的 **编辑此页** 会打开 GitHub 上的英文文件。请将路径中的 `versioned_docs/` 替换为 `i18n/<locale>/docusaurus-plugin-content-docs/`，并用您的 [语言代码](#locale-codes) 替换 `<locale>`： `de` 表示德语。路径的其余部分保持不变，例如 [本页的 1.x 德语版本](https://github.com/wcpos/docs/blob/main/i18n/de/docusaurus-plugin-content-docs/version-1.x/support/translations.mdx)。

   <details>
   <summary>查找其他页面或语言</summary>

   本文档使用 Docusaurus。英文页面位于 `versioned_docs/`中，每个版本各有一个文件夹。每种语言的副本都位于 `i18n/<locale>/docusaurus-plugin-content-docs/`下对应版本的文件夹中，路径与英文页面相同。语言代码列在 [语言代码](#locale-codes)。

   以法语为例，英文文件 `versioned_docs/version-2.x/support/translations.mdx` 对应 `i18n/fr/docusaurus-plugin-content-docs/version-2.x/support/translations.mdx`。浏览[法语文件夹](https://github.com/wcpos/docs/tree/main/i18n/fr/docusaurus-plugin-content-docs)即可查看其中的内容。

   </details>

2. **修改文字。** 保留 Markdown 和 MDX 语法、链接、代码以及前置元数据的键不变。翻译读者看到的正文、标题和标签。
3. **通过拉取请求提交。** 只修改以下目录中的文件： `i18n/<locale>/`，不要修改英文页面。参见 [在 GitHub 上提交修正](#send)。

如果改动范围较大，例如整个章节或添加新语言，请先提交议题，以便我们共同规划。

## 在 GitHub 上提交修正 {#send}

您需要一个免费的 GitHub 账号。无需安装任何软件，所有操作都在浏览器中完成。

1. **登录 GitHub**，打开您想修正的文件。
2. **点击铅笔图标**，即文件右上角的 **编辑此文件**。首次操作时，GitHub 会要求您派生仓库：点击 **派生此仓库**，即可获得供您修改的独立副本。
3. 在编辑器中 **进行修改**。
4. **点击提交更改…**，该按钮位于编辑器上方，点击后会打开一个对话框。
5. 在对话框的消息字段中用一行文字 **说明您修正的内容**，然后点击 **提议更改**。
6. 在下一页 **点击创建拉取请求**，然后再次点击 **创建拉取请求** 进行提交。

审核者会检查并合并您的更改，或在拉取请求中向您提问。

## 修正如何送达用户 {#how-it-works}

每项更改发布前都会经过人工审核。本文档的修正合并后会随网站一起发布。POS、桌面应用或插件的修正则会在它们下次更新时提供给用户。

<details>
<summary>完整流程详解</summary>

1. **收集英文文本。** 应用或插件发生变化时，其英文字符串会被收集到 [wcpos/translations](https://github.com/wcpos/translations) 仓库。本文档的英文文本则保存在 [wcpos/docs](https://github.com/wcpos/docs)。
2. **AI 补全缺失的翻译**，覆盖所有语言。它会遵循各语言的规则和词汇表。破坏占位符或标记，或使用旧版产品全称的译文会被拒绝，稍后重新尝试翻译。
3. **人工审核整批译文**，以拉取请求的形式审阅并合并。
4. **发布修正。** 对于本文档，网站会根据合并后的页面重新构建并发布。对于应用和插件，合并会生成新的翻译版本。POS、桌面应用和插件各自使用固定的翻译版本，因此修正会在它们下次更新时生效。修正 `.po` 文件后，还需要先重新生成对应的 `.l10n.php` 文件，因此可能需要更长时间。

对于应用和插件，每日检查如果发现仍有缺失内容，还会在 [wcpos/translations](https://github.com/wcpos/translations/issues) 上创建议题。

</details>

因此，您通常不需要从空白文件开始，而是修正已有译文中不自然的地方：生硬的措辞、与 WooCommerce 同语言界面不一致的术语，或按钮放不下的标签。

:::note 不再通过 translate.wordpress.org 翻译
WCPOS 不再通过 translate.wordpress.org 接收翻译。该平台不允许机器翻译，因此大多数语言的翻译始终未能完成。插件现在从 wcpos/translations 下载自己的译文。如果您曾在那里翻译过 WCPOS，感谢您的贡献：现在请通过本页列出的位置提交修正。
:::

## 添加语言 {#add-a-language}

应用和插件支持超过 50 种语言及地区变体，完整列表见 [`locales.json`](https://github.com/wcpos/translations/blob/main/locales.json)。本文档支持的语言较少，列在下方。如果缺少您的语言，请在相应仓库提交议题，我们会添加。AI 能快速补全新语言的翻译，之后由使用该语言的人将译文润色得自然流畅。

### 语言代码 {#locale-codes}

<details>
<summary>查找您的语言代码</summary>

本文档提供以下语言版本：

| 代码 | 语言 |
|---|---|
| `ar` | 阿拉伯语 *（从右到左）* |
| `de` | 德语 |
| `es` | 西班牙语 |
| `fr` | 法语 |
| `hi-IN` | 印地语（印度） |
| `it` | 意大利语 |
| `ja` | 日语 |
| `ko` | 韩语 |
| `nl` | 荷兰语 |
| `pt-BR` | 葡萄牙语（巴西） |
| `zh-CN` | 简体中文 |

两个仓库使用不同的代码格式。wcpos/translations 使用下划线，例如 `de_DE`、`pt_BR`、`zh_CN`，并同时包含基础语言（`de`、`fr`、`es`）和地区变体（`de_AT`、`fr_CA`、`es_MX`）。本文档使用连字符，例如 `pt-BR`、`hi-IN`、`zh-CN`。请使用您正在编辑的仓库所采用的格式。

</details>

## 审核者关注的内容 {#translator-tips}

以下是 AI 遵循的规则，审核者也会据此检查您的更改。

- **占位符必须保持原样。** `{name}`、 `%s`、 `%d` 以及以下标签（例如 `<strong>` ）均由 WCPOS 填充或渲染。只需翻译它们周围的文字。
- **产品名称保留英文。** `WCPOS`、`WCPOS Pro`、`WooCommerce` 和 `WordPress` 不翻译，Stripe、PayPal、Square、Android、iOS、macOS 和 Windows 等其他品牌及平台名称也不翻译。在面向读者的文本中，请使用 **WCPOS**。旧版产品全称只应出现在路径标识、文件名和网址中。
- **优先使用 WooCommerce 的术语。** 店主会同时使用 WCPOS 和 WooCommerce，因此对于优惠券、退款、税费或付款方式等 WooCommerce 也使用的术语，应与 WooCommerce 在该语言中的译法一致。对于 WooCommerce 中没有的术语，例如收银员、收银机或钱箱，请使用该语言词汇表 `scripts/translation-glossary.json` 中的译法。
- **长度尽量接近英文。** 只有一个词的按钮标签应保持在一到两个词的长度。POS 界面空间有限。
- **正式或非正式语气遵循该语言的说明。** 某些语言在 wcpos/translations 的 `scripts/locale-context/` 中有专门说明，涵盖语体、小数分隔符和常见易错点。例如，德语使用 **Sie**。
- **代码保持原样。** 优惠券代码、网关 ID、语言代码、文件路径和短代码都不翻译。如果不确定，请保留英文。本文档中有一个例外：以代码样式显示的菜单路径，例如 `WP Admin > WooCommerce > 设置 > 支付`，应使用 WordPress 和 WooCommerce 在该语言中显示的菜单名称。请保留 `>` 符号以及 WP Admin、WooCommerce 和 WCPOS 这些名称。
- **在界面上检查。** 一段文字在某个界面上能放下，在另一个界面上却可能换行。参见[查看您所用语言的界面](#see-it)。

阿拉伯语、希伯来语、波斯语或乌尔都语等从右到左书写的语言，也需要使用从右到左的收据模板。模板库中提供了这些模板，参见[自定义收据](../receipts/customise.mdx#the-bundled-templates)和[非拉丁文字收据](../hardware/printers/non-latin-receipts.mdx)。

- **Discord** — 在 [wcpos.com/discord](https://wcpos.com/discord) 与我们及其他译者讨论翻译。
