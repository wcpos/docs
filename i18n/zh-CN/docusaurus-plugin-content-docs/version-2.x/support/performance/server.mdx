每台收银机全天都在与 WordPress 网站通信：检查变更、发送销售记录，以及获取收银员查询的信息。服务器的响应速度决定了 POS 使用起来是否流畅。当服务器不堪重负时，每台收银机会自行降低检查频率，并自动恢复。本页介绍在哪里查看这些情况、它们意味着什么，以及应如何调整托管配置。

是看到以下情况才来到这里的吗？

- **服务器历史状况**下显示[**正在降低频率**或**暂停至 …**](#pace)。您可以继续销售：只有后台检查会减慢，因此其他收银机的变更可能需要更长时间才会显示。如果大多数日子都出现这种情况，请先[选择负担更轻的预设](#fix)。
- 出现 [**503**、**429** 或 **414** 错误](#503-errors)。每个错误码都先提供简短说明，供网站维护人员参考的详细信息折叠在下方。
- [所有收银机的搜索和销售操作都很慢](#fix)。降低检查频率不会减慢这些操作，因此请先检查服务器，而非收银机：将[应提供给托管服务商的信息](#when-to-seek-help)交给网站维护人员。

## 查看服务器的运行状况 {#store-health}

通过菜单底部的脉搏图标打开**店铺健康**，然后选择**性能**。这些数据仅反映当前收银机的情况。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[50, 0], [160, 0], [370, 0], [480, 26], [180, 0], [470, 0]]} alt="店铺健康的性能选项卡：状态行显示过去 24 小时的请求数、数据量和典型响应时间，下方是按小时显示的引擎运行状态条，以及节能、均衡和实时预设">

1. **店铺健康** — 菜单底部的脉搏图标。
2. **性能** — 当前收银机检查店铺的频率，以及服务器的运行状况。
3. **过去 24 小时** — **正常**表示当前收银机此刻在线且正在同步。随后显示请求数、数据量和以毫秒为单位的**典型响应时间**：此处的 2347 约为 2.3 秒。如果大多数日子都持续超过 2000，请将其纳入[提供给托管服务商的信息](#when-to-seek-help)。
4. **引擎运行状态** — 每个单元格代表一小时。琥珀色表示该小时内至少有一次请求失败。将鼠标悬停在单元格上或轻点单元格即可查看计数。
5. **节能** — 三种预设中负担最轻的一种，旁边是**均衡**和**实时**。对于不需要快速查看其他收银机销售记录的收银机，请选择此预设。除非网站维护人员建议，否则不要选择**实时**。请参阅[同步预设](../store-health.mdx#sync-presets)。
6. **当前** — 下次检查的时间。每小时请求数表示按您的设置应执行的常规检查次数；收银机降低频率后，实际检查次数会减少，因此这里距离下次检查还有约 2 分钟。

</JourneyShot>

## 解读“服务器历史状况” {#server-load}

在同一选项卡中向下滚动。**服务器历史状况**会说明收银机当前的检查频率，并以图表展示过去 24 小时的情况。

<JourneyShot manifest={manifest} device="tablet" step={2} maxWidth={710} offsets={[[400, -204], [430, 0], [110, -84], [120, -84]]} alt="正在降低频率的收银机上的服务器历史状况：琥珀色的频率状态行显示，由于服务器报告高负载，正在降低频率，检查间隔增至 2×；服务器负载图在凌晨 3:00 升至 59.1，而 POS 请求数图则在下降">

1. **服务器历史状况** — 服务器负载涵盖服务器上运行的所有任务，而不仅是 POS：网站、备份，以及同一主机上的其他网站。
2. **频率** — 此处以琥珀色显示**正在降低频率 — 检查间隔增至 2×：服务器报告高负载**。当前收银机改为每 2 分钟检查一次，而非每分钟一次，服务器恢复后会自行恢复原来的频率。请参阅[频率状态行的含义](#pace)。
3. **服务器负载** — 服务器每小时报告的最高负载。标题旁的数值是最近一小时的数据。您无需自行判断数值：服务器认为负载偏高或过高时，频率状态行会给出提示。
4. **POS 请求数** — 当前收银机每小时向店铺发送的所有请求：常规检查，以及下载变更、发送销售记录和搜索请求。因此，它可能远高于您的设置所要求的每小时请求数。

</JourneyShot>

请结合两张图表来看。如果负载随 POS 请求数一起升降，收银机可能是原因之一。如果负载单独上升，则说明服务器上有其他任务正忙：网站、备份，或同一主机上的另一个网站。这张截图中，两条曲线在午夜后同时下降；凌晨 2:00 后，负载升至 59.1，而当前收银机的请求数继续下降，说明有其他任务正忙，收银机已降低检查频率以减轻服务器负担。

无论是哪种情况，托管服务商都需要看到这两张图表的截图。如果**典型响应时间**很长，而负载一直很低，则服务器并非算力不足：请先检查订单存储和插件（[服务器持续不堪重负时](#fix)的步骤 2 和 3）。

### 频率状态行的含义 {#pace}

该行会显示以下状态之一。它与选项卡顶部的**正常**状态相互独立；收银机降低检查频率时，顶部仍可能显示正常。

- **正常频率** — 收银机按您设置的频率检查。
- **正常频率 — 服务器报告负载偏高**（或**负载过高**）— 服务器表示当前繁忙，但收银机仍按您设置的频率检查：一次繁忙响应不会使其降低频率。持续高负载也会让收银机降低频率：当最近十次响应中大多数都报告高负载时，即使这些响应返回得很快，该行也会变为**正在降低频率**（请参阅[各项原因的含义](#reasons)）。除非大多数日子都出现这种情况，否则无需处理。
- **正在降低频率 — 检查间隔增至 N×：…** — 收银机降低了检查频率，并在冒号后说明原因。请参阅下方的[各项原因的含义](#reasons)。
- **暂停至 …** — 服务器指定了再次请求的时间，收银机会等到该时间。等待期间您仍可继续销售。

收银机降低频率或暂停时，该行会变色。服务器恢复后，两种状态都会自行解除。如果大多数日子都出现这些情况，请参阅[服务器持续不堪重负时](#fix)。

:::note 只有后台检查会减慢
只有收银机定期检查变更的操作和后台检查会减慢。搜索、条码查询或销售请求仍会立即发送到服务器。频率降低期间，当前收银机需要更长时间才能看到其他收银机和 WooCommerce 中发生的变更。
:::

<Accordion>
<AccordionItem question="各项原因的含义、收银机降低频率的幅度，以及恢复方式">

<Anchor id="reasons" />

- **服务器要求 POS 降低频率** — 服务器或其前端的防火墙返回过一次“请求过多”（**429**）。
- **服务器返回错误**或**向服务器发送的请求超时** — 一分钟内出现三次服务器错误（**5xx**）或超时。显示的原因以三次中的最后一次为准。
- **服务器响应缓慢** — 最近十次响应的典型响应时间（中位数）超过两秒。
- **服务器报告高负载** — 收银机处于正常频率时，最近十次响应中大多数表示服务器负载过高；或者在负载达到 1 或以上时，连续两次负载读数至少为服务器通常负载的两倍。

每次触发时，检查频率都会降至之前的一半。检查间隔最长为 5 分钟，或您设置间隔的两倍（取较长者）：**节能**模式下为每 10 分钟一次。如果服务器指定了暂停时长（通过 **Retry-After** 响应头），则会按其要求暂停，最长 15 分钟。

恢复过程刻意放缓：收到十次正常响应，且距离上次降低频率至少已过一分钟后，等待间隔才会减半。负载突增是例外：收银机将检查频率降至一半，不会进一步降低，直到连续两次负载读数与服务器通常负载的差距均回到四分之一以内。收银机重启后会恢复为您设置的频率。

WCPOS 本身也会要求短暂暂停：网站更新插件时暂停 5 秒，安装同步表时暂停 30 秒。届时您可能会短暂看到**暂停至 …**。

有关背后的引擎规则，请参阅[同步性能](../../reference/sync-performance.mdx#server-pressure)。

</AccordionItem>
<AccordionItem question="负载数据的来源">

服务器会在每次同步响应中报告平均负载，即过去一分钟内正在运行或等待处理器的进程数量的平均值。请将其与服务器的处理器核心数比较。对于 4 核服务器，负载为 4 意味着满负荷运行；对于 16 核服务器，这一负载则很轻。

**偏高**和**过高**这些提示已为您完成判断。WCPOS 将负载除以核心数：每核低于 0.9 为低负载，最高 1.8 为偏高，超过该值则为过高。在共享主机上，此数值统计的是整台机器上的所有网站，而不仅是您的网站。

当 PHP 无法读取平均负载时，图表位置会显示**服务器未报告负载。本页其他功能仍可正常使用。** 在 Windows 服务器以及禁用了该函数的主机上，这是正常现象。即使没有负载数据，频率状态行仍可工作，因为收银机也会监测错误和响应时间。

</AccordionItem>
</Accordion>

## 服务器持续不堪重负时 {#fix}

请按顺序执行以下步骤，越靠前的步骤成本越低。任何使用收银机的人都可以完成步骤 1。步骤 2 至 4 由网站维护人员处理，例如店主、开发人员或托管服务商。

1. **选择负担更轻的预设。** 对于不需要在几秒内看到其他收银机销售记录的收银机，请打开**店铺健康 › 性能**并选择**节能**。除非网站维护人员建议，否则不要选择**实时**。预设按收银机分别保存。请参阅[同步预设](../store-health.mdx#sync-presets)。
2. 如果 WooCommerce 仍使用旧版订单存储，请**将 WooCommerce 切换至 HPOS**。对于订单量大的店铺，这是单项收益最大的改进。店铺使用旧版存储时，WP Admin 中 **POS → 设置 → 收银台**页面顶部会显示警告，并提供 WooCommerce 设置的链接。请参阅[订单存储（HPOS）](./order-storage.mdx#switch-to-hpos)。
3. **找出拖慢所有请求的插件。** 在预发布网站上仅启用 WooCommerce 和 WCPOS 进行测试，然后逐一重新启用其他插件。请参阅[插件冲突](../troubleshooting/plugin-conflicts.mdx#step-2-the-plugin-elimination-method)。
4. **联系托管服务商**，申请启用对象缓存（Redis 或 Memcached）、增加 PHP 工作进程和内存，或迁出共享主机。请参阅[应提供给托管服务商的信息](#when-to-seek-help)。

## 应提供给托管服务商的信息 {#when-to-seek-help}

如果大多数日子都显示**正在降低频率**或**暂停至 …**、典型响应时间持续超过 2 秒，或托管服务商的日志中出现内存错误，请联系托管服务商或 WordPress 开发人员。

从收银机获取并发送：

- **店铺健康 → 性能**页面的截图，需滚动到**服务器历史状况**区域。
- 通过**店铺健康 → 日志 → 复制调试信息**获取的调试报告（手机和平板应用中为**分享调试信息**）。报告已包含 WordPress、WooCommerce 和 WCPOS 的版本信息。请参阅[日志](../store-health.mdx#logs)。

请网站维护人员补充：

- WP Admin 中**插件**页面上的已启用插件列表。
- 托管账户中列出的服务器配置：核心数、内存和存储类型。

本页其余内容供网站维护人员参考。如果您是因 **503**、**429** 或 **414** 错误码来到这里，[服务器返回的错误](#503-errors)会先为每种错误提供简短说明。

## 服务器返回的错误 {#503-errors}

### 503 服务不可用 {#503}

服务器或其前端的某个组件无法处理请求。收银机的后台检查会自动延长间隔并重试。网站正在更新 WCPOS 或安装其数据表时，短暂出现 503 属于正常现象：收银机会等待 5 至 30 秒后继续。如果持续发生，请将[应提供给托管服务商的信息](#when-to-seek-help)交给网站维护人员。

<Accordion>
<AccordionItem question="供网站维护人员参考：出现 503 时要检查什么">

检查服务器负载和可用内存、PHP 工作进程是否已耗尽，以及 PHP 内存限制是否至少为 **256 MB**。托管服务商的错误日志中有 POS 无法显示的信息。

</AccordionItem>
</Accordion>

### 429 请求过多 {#429}

托管服务商或防火墙限制了单个地址调用网站的频率。收银机会立即降低频率，稍后重试。同一店铺路由器后的多台收银机共用一个地址，因此对于不需要快速查看其他收银机销售记录的收银机，请选择**节能**。如果持续发生，请将[应提供给托管服务商的信息](#when-to-seek-help)交给网站维护人员。

<Accordion>
<AccordionItem question="供网站维护人员参考：允许 POS 发送更多请求">

请托管服务商调整限制，或在防火墙设置中允许店铺地址向 `/wp-json/` 发送更多请求。POS 调用的就是此路径。

</AccordionItem>
</Accordion>

### 414 URI 过长 {#http-414-uri-too-long}

此错误会出现在结账界面**旧版**选项卡下的支付页面上。该页面打开时，地址中包含登录信息，而服务器允许的地址长度上限太低。请网站维护人员或托管服务商提高上限。

<Accordion>
<AccordionItem question="供网站维护人员参考：提高地址长度上限">

- **Apache：** 在 `httpd.conf` 中设置 `LimitRequestLine 65536`
- **Nginx：** 在 `nginx.conf` 中设置 `large_client_header_buffers 4 65536;`

</AccordionItem>
</Accordion>

## 安全更新 WooCommerce {#woocommerce-version-compatibility}

WooCommerce 更新偶尔会导致 POS 无法正常工作。请先在[预发布网站](../troubleshooting/plugin-conflicts.mdx#before-you-start-use-a-staging-site)上更新 WooCommerce，并保持 WCPOS 为最新版本，以获得最新的兼容性修复。WCPOS 2.0 需要 WooCommerce 9.0 或更高版本。

如果更新后 POS 无法正常工作，请在 [Discord](https://wcpos.com/discord) 上告知我们，并向网站维护人员咨询回退事宜。更新可能会修改店铺数据库，因此维护人员应先核查这一点，并确保有更新前的备份。

<Accordion>
<AccordionItem question="供网站维护人员参考：回退至较早版本的 WooCommerce">

WooCommerce 的 WordPress.org 页面上的**高级视图**链接列出了历史版本。如果更新修改了数据库，请从更新前的备份恢复；否则，安装之前使用的版本即可。请先在预发布环境中尝试。

</AccordionItem>
</Accordion>

## 订单存储（HPOS） {#woocommerce-high-performance-order-storage-hpos}

WooCommerce 的**高性能订单存储**将订单保存在独立的数据表中，而不是与文章混存。对于订单量大的店铺，使用它能显著加快销售记录的保存速度。请检查店铺当前的存储方式，并使用 WooCommerce 自带的工具切换：[订单存储（HPOS）](./order-storage.mdx)。WooCommerce 的指南见[高性能订单存储](https://woocommerce.com/document/high-performance-order-storage/)。

<Accordion>
<AccordionItem question="可向托管服务商咨询的 PHP 和 WordPress 设置">

这些只是起始建议，并非硬性规定。托管服务商了解其服务器允许哪些配置。

```ini
memory_limit = 512M
max_execution_time = 300
max_input_vars = 3000
```

在 `wp-config.php` 中减少保留的文章修订版本数量，可以缩小数据库：

```php
define('WP_POST_REVISIONS', 3);
```

经常拖慢所有请求的插件包括：在保存商品时运行的重型 SEO 插件、复杂的库存系统、实时分析和跟踪插件，以及挂接到 WooCommerce 的自定义代码。请按[插件冲突](../troubleshooting/plugin-conflicts.mdx)中的方法查找。

## 特定托管服务的注意事项 {#hosting-specific-notes}

部分托管服务商和 CDN 需要调整配置后，POS 才能访问网站的 REST API。请展开您使用的服务：

<Accordion>
<AccordionItem question="GoDaddy">

网站防火墙会阻止 `/wp-json/`，并出现 _“收到 'undefined'”_ 等错误。请在**网站安全 › 防火墙 › 设置 › 访问控制 › 允许 URL 路径**中添加 `/wp-json/`。

</AccordionItem>
<AccordionItem question="WP Engine">

必须启用 REST API。请将其开启，并在需要时在 WP Engine 防火墙中放行相关路径。

</AccordionItem>
<AccordionItem question="Cloudflare">

机器人对抗模式、受攻击模式或 WAF 质询会阻止 REST 请求，缓存也可能返回过时的响应。请按照 [Cloudflare 指南](../troubleshooting/cloudflare.mdx)，为 `/wp-json/` 添加 WAF **跳过**规则和**绕过缓存**规则。

</AccordionItem>
<AccordionItem question="WordPress.com">

商品可能无法完整加载，例如大型商品目录只显示 9 或 10 个商品。请使用自托管 WordPress。

</AccordionItem>
<AccordionItem question="共享主机">

PHP 工作进程和内存不足以支持多台收银机。请迁移至 VPS 或托管式 WordPress 主机。

</AccordionItem>
</Accordion>

Wordfence 等安全插件也可能以同样的方式阻止 REST API。请参阅[插件冲突](../troubleshooting/plugin-conflicts.mdx)。
