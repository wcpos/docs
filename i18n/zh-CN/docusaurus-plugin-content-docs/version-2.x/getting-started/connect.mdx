在浏览器中无需连接：POS 就在您自己的网站上。桌面和移动应用启动后会显示 **连接** 界面，您只需添加一次店铺，使用 WordPress 账户登录，即可打开 POS。

## 在浏览器中打开 POS {#web}

访问 `yourdomain.com/pos`，使用 WordPress 用户名和密码登录，POS 随即打开。

默认地址为 `pos`。如需更改，管理员可在 WP Admin 中打开 **设置 › 固定链接**，填写 **可选** 下的 **POS 前缀**。留空即可保留 `pos`。

在浏览器中，点击 **退出登录** 也会退出 WordPress。

## 在应用中连接店铺 {#adding-a-new-store}

1. 在 **您的店铺地址** 下输入店铺地址，例如 `mystore.com`，然后点击 **连接**。应用会依次显示各项检查的进度：**正在查找您的店铺…**、**正在检查 WordPress…**，然后是插件检查和 **正在保存…**。
2. 点击店铺卡片上的 **使用 WordPress 登录**，店铺的登录窗口随即打开。使用 WordPress 用户名和密码登录。
3. 您将返回连接界面。您的姓名会显示在 **WordPress 用户** 下，旁边标有 **已登录**。
4. 在 **店铺** 下，您的店铺已被选中。如果使用 WCPOS Pro 且有多家店铺，标题会显示为 **选择店铺**：请选择您要销售商品的店铺。
5. 点击 **打开 POS**。

如果无法访问该地址，原因会以红色显示在 **连接** 下方，通常还会附有 **了解更多** 链接，指向相应的错误代码页面。请参阅[遇到问题时](#troubleshooting)。

## 在一台设备上使用多家店铺 {#multiple-stores}

点击店铺下方的 **连接另一家店铺** 可继续添加店铺。有两家或更多店铺时，它们会列在 **您的站点** 下，每次只能展开一家。每家店铺都显示名称、地址和已登录人数，例如 **2 位用户**。点击店铺即可展开。

如需从此设备移除店铺，请打开其卡片上的 **操作** 菜单，选择 **移除站点**，然后点击 **移除** 以确认。应用会询问 **是否移除店铺及关联用户？** 此设备上登录该店铺的所有用户都会退出登录。店铺本身不会发生任何变化。

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[-35, 0], [305, 0], [63, 0], [142, 0], [-35, 0], [115, 0]]} alt="您的站点中有两家店铺：第一张卡片已折叠，显示名称、地址和 1 位用户，其操作菜单已打开并显示移除站点；第二张卡片已展开，显示用户、店铺和打开 POS；下方是连接另一家店铺">

1. **已折叠的店铺** — 点击可展开，当前展开的店铺会随之折叠。
2. **1 位用户** — 此设备上登录该店铺的人数。
3. **操作** — 该店铺的菜单。
4. **移除站点** — 确认后从此设备移除店铺。
5. **已展开的店铺** — 显示其用户、店铺和 **打开 POS**。
6. **连接另一家店铺** — 再添加一家店铺。

</JourneyShot>

## 同一家店铺使用多个收银员账户 {#multiple-users-per-store}

每位销售人员都使用自己的 WordPress 账户登录。

- **添加收银员。** 点击 **WordPress 用户** 下的 **添加其他用户**，让该收银员登录。登录后，该用户会加入列表。
- **选择由谁进行销售。** 点击姓名，店铺和 **打开 POS** 会随所选用户切换。
- **重新登录。** 姓名旁显示 **重新登录** 表示该用户已被店铺退出登录：可能是登录已过期，也可能是管理员在[会话](../settings/wp-admin/sessions.mdx#signing-devices-out)中结束了登录。点击该行的 **重新验证**，以该用户身份登录。
- **移除收银员。** 点击该用户所在行的 **×**，然后点击 **移除** 以确认。这只会将该用户从此设备移除，服务器上的信息不会改变。

:::note 请以该行对应的用户身份登录
如果 **重新验证** 后登录的是其他用户，应用会提示：**已使用其他用户身份登录**。新登录的用户会加入列表，但您原先选择的用户仍未登录。请再次点击 **重新验证**，使用原用户的账户登录。
:::

## 将收银工作交接给另一位收银员 {#switching-users}

POS 打开后，可在收银员面板中交接。点击收银机栏末尾的头像即可。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[182, -19], [0, 0], [-75, 0], [0, -30], [0, -30], [90, 0]]} alt="POS 中的收银员面板：交接给及其下方的其他账户、店铺及切换按钮、WordPress 后台和桌面应用链接，以及退出登录">

1. **交接给** — 显示此设备上已登录的其他收银员，以及各自未结购物车的数量。选择一位收银员并点击 **交接给 …**：POS 会以其身份重新加载，已开班的收银机保持开班状态。您自己的未结购物车和未发送的销售记录会保留在此，等待您回来处理。此处尚无其他人登录。
2. **其他账户…** — 在此设备上登录新用户。该用户会加入上方列表和连接界面。
3. **切换** — 有多家店铺时，可切换到另一家店铺（WCPOS Pro）。请参阅[选择店铺和收银机](../stores/registers-and-devices.mdx#choosing-a-store-and-a-register)。
4. **WordPress 后台** — 打开您网站的 WP Admin，仅在浏览器中可用。
5. **桌面应用** — 打开桌面应用下载页面，仅在浏览器中可用。
6. **退出登录** — 在应用中返回连接界面；在浏览器中则退出 WordPress。未结班的收银机会保持开班状态，供下一位收银员使用，POS 会询问是否先结班。请参阅[收银员面板](../pos/register/index.mdx#cashier-sheet)。

</JourneyShot>

付款正在进行时（**请先完成付款**），或正在清点钱箱时（**请先完成或放弃清点**），无法交接。

## 试用演示店铺 {#demo-store}

连接界面底部的 **试用演示店铺** 会将应用连接到 WCPOS 演示店铺，并打开其登录页面。您可以在其中体验功能，而不会影响自己的店铺。

## 遇到问题时 {#troubleshooting}

请根据提示出现的阶段查找对应说明。

### 连接或登录时 {#while-connecting}

<Accordion>
  <AccordionItem question="登录未完成。">

  登录结果未能返回应用。数据不会丢失：尚未发送的内容会在您登录后发送。请再次点击 **使用 WordPress 登录** 或 **重新验证**。

  </AccordionItem>

  <AccordionItem question="登录窗口显示错误或空白页面">

  通常是网站上的安全、防火墙或登录插件阻止了登录。请参阅[插件冲突](../support/troubleshooting/plugin-conflicts.mdx#security-and-login-plugins)。

  </AccordionItem>

  <AccordionItem question="此网站的 WordPress REST API 需要身份验证">

  请让网站管理员检查此设置。应用也可能显示拦截请求的插件自身的提示，例如仅允许已登录用户使用 REST API。

  给网站管理员的说明：Force Login 等插件禁止未登录用户访问 REST API，导致应用无法读取店铺信息。请在该插件中允许未登录的访客访问 REST API。请参阅[插件冲突](../support/troubleshooting/plugin-conflicts.mdx#security-and-login-plugins)。

  </AccordionItem>

  <AccordionItem question="此网站似乎不是 WordPress 网站">

  应用未能在该地址找到 WordPress。请确认在浏览器中访问该地址能打开店铺，且 `yourdomain.com/pos` 也能正常访问。如果提示网站响应超时，请检查服务器后重试。

  </AccordionItem>

  <AccordionItem question="无法连接到本地或测试网站">

  应用通过网站首页发送的 `Link` 响应头查找店铺，该响应头指向网站的 REST API。如果无法读取此响应头，应用会尝试访问 `yourdomain.com/wp-json/`。如果两种方式都无效，就会显示 **此网站似乎不是 WordPress 网站**。

- 请使用此设备可以访问的地址。`localhost` 始终指设备自身，因此手机或平板电脑无法通过这个名称访问您电脑上的店铺。
- 在同一设备的浏览器中打开 `yourdomain.com/wp-json/`，应显示网站的 REST API 数据，而不是错误或登录页面。
- 请确认网站已启用 WCPOS。它会发送必要的响应头，让应用能够读取 `Link` 响应头。
- 有关 CORS 或 `Link` 响应头的提示意味着网站的跨域（CORS）响应头有问题，通常是服务器或代理上的另一层 CORS 配置造成的。请参阅 [HOST111](../error-codes/HOST111.mdx)。

</AccordionItem>

  <AccordionItem question="此用户没有可用的店铺">

  应用未找到此账户可用的 POS 店铺。请让管理员设置店铺，然后重新登录。请参阅[设置店铺](../stores/setup.mdx)。

  </AccordionItem>
</Accordion>

### 需要更新时 {#update-needed}

<Accordion>
  <AccordionItem question="请更新此设备上的 POS 应用。">

  网站上的 WCPOS 插件比此应用更新。在浏览器中，请点击 **重新加载**。在桌面或移动应用中，请安装应用更新后重新打开；未发送的销售记录会保留在设备上。此处也提供 **退出登录**。连接界面的店铺会显示相同提示，并提供 **重试**，供更新后使用。请参阅 [SYNC341](../error-codes/SYNC341.mdx)。

  </AccordionItem>

  <AccordionItem question="请更新 WordPress 网站上的 WCPOS 插件。">

  应用比店铺上的插件更新。请让管理员在 WP Admin 中打开 **插件** 并更新 WCPOS，然后重新登录。在更新之前，只能通过 **退出登录** 离开此界面。连接界面的店铺卡片也会显示要求更新插件的通知，并附有 **了解更多**。请参阅 [AUTH331](../error-codes/AUTH331.mdx)。

  </AccordionItem>
</Accordion>

### 点击打开 POS 后 {#after-open-pos}

<Accordion>
  <AccordionItem question="此店铺没有收银机">

  店铺使用收银机，但尚未添加。请让管理员在 **WooCommerce › POS › 店铺** 中添加；管理员会看到可直接前往该页面的 **打开店铺** 按钮，收银员则会看到 **收银机指南**。添加后点击 **重试**。请参阅[收银机](../settings/wp-admin/registers.mdx)。

  </AccordionItem>

  <AccordionItem question="无法访问此店铺的收银机">

  POS 无法读取店铺的收银机信息。请检查连接，然后点击 **重试**。

  </AccordionItem>
</Accordion>

### 仍未解决 {#still-stuck}

请确认店铺符合[服务器要求](../support/performance/server.mdx#minimum-server-requirements)，且主机未阻止 REST API 访问。
