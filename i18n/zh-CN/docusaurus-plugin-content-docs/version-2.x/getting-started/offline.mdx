POS 会将商品、客户和未结订单保存在设备上。当网络断开或店铺停止响应时，您仍可继续销售：只要销售记录在断线前已送达店铺，就可收取现金、通过自备终端收取银行卡付款，以及记录其他收银台付款。每笔销售记录都会保留在设备上，待店铺恢复连接后自动发送。本页以一笔离线收款的销售为例，介绍从连接中断到恢复的完整过程。

## 识别离线状态 {#offline-signs}

连接中断时，您无需采取任何操作。POS 会提示您，您可以继续工作。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[60, 14], [-16, 0], [150, 0], [0, 0], [10, 0]]} alt="离线状态的 POS，购物车中有一件商品：收银机状态栏中店铺名称旁的离线标记、设备已离线提示、搜索框、结账按钮和健康状况按钮">

1. **离线** — 显示在收银机状态栏的店铺名称旁。即使设备有网络，只要店铺没有响应，也会显示 **离线**。其他界面（订单、商品、客户）的页面栏中也会显示同样的 **离线** 标记。
2. **设备已离线** — 连接中断几秒后出现。**帮助** 会打开该提示的说明。如果是店铺停止响应，则会显示 **无法访问网站**。
3. **搜索商品** — 搜索设备上已有的商品，因此您仍可查找和销售已下载的所有商品。
4. **结账** — 创建销售的操作照常可用。离线时发起的销售必须等店铺恢复连接后才能收款，在此之前会保留在未结订单中。店铺已收到的销售能否收款，取决于付款方式：参见[离线收款](#take-payment-offline)。
5. **健康状况** — 打开[店铺健康状况](../support/store-health.mdx)，查看设备上已有的数据及仍在等待发送的内容。

</JourneyShot>

## 仍可使用的功能 {#what-works-offline}

- **查找商品和客户** — 根据设备上已有的数据进行搜索、筛选和扫码。
- **编辑购物车** — 添加商品、更改数量和价格、添加折扣和费用、应用设备上已有的优惠码，以及在[未结订单](../pos/cart/open-orders.mdx)之间切换。
- **收款** — **现金**、通过自备终端收款后记录的 **银行卡** 付款，以及您在收银台记录的其他付款方式，例如货到付款、银行转账或支票。这些方式都适用于店铺已收到的销售：参见[离线收款](#take-payment-offline)。
- **收据** — 已付款界面、通过连接到收银台的打印机打印，以及排队等待发送的电子邮件。
- **收银机** — 销售款项照常计入钱箱。您也可以将收银台交接给其他收银员，或切换收银机。
- **保存更改** — 新增客户、编辑订单、发送收据邮件。每项更改都会保留在设备上，稍后发送。

## 离线收款 {#take-payment-offline}

:::warning 仅限店铺已收到的销售
只有在断线前已送达店铺的销售才能离线收款：结账界面的商品上方会显示其订单号。离线时发起的销售尚无订单号。按 **结账** 后，您会看到 **无连接**，而非付款方式：销售会保存在未结订单中，其选项卡显示 **结账中 · 离线**。按 **返回收银机**，继续服务下一位客户，待店铺恢复连接后再收款。参见[无连接](../pos/checkout/troubleshooting.mdx#no-connection)。
:::

1. 按 **结账**，检查商品上方是否有订单号，例如 **#224371**。
2. 点按 **现金**、用于记录自备终端收款的 **银行卡**，或其他在收银台记录的付款方式。
3. 输入客户支付的金额，或点按恰好付清的金额。
4. 按 **收款**，然后确认。

离线时，收款面板会在金额旁显示 **离线**，每种付款方式都会注明当前是否可用。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[60, 14], [0, -32], [0, -32], [-18, 4], [-18, 4], [440, 0]]} alt="离线收款面板：应付金额旁显示离线，现金和银行卡选项均标有稍后发送及店铺可能拒绝，并显示收取 $45.00 现金按钮">

1. **离线** — 收银机状态栏会持续显示此提示。
2. **现金** — 在收银台收取，因此离线时也可使用。
3. **银行卡** — 通过自备终端收款并在收银台记录的银行卡付款，离线时也可使用。与收银台配对的读卡器或在线支付网关则会列在 **… 当前不可用** 下，并显示 **需要连接**。
4. **稍后发送 · 店铺可能拒绝** — 立即记录付款，待店铺恢复连接后发送。届时店铺会对其进行检查。
5. **稍后发送 · 店铺可能拒绝** — 银行卡付款也同样如此。
6. **收取 $45.00 现金** — 与平时一样，注明金额和付款方式。

</JourneyShot>


按 **收款** 时，POS 会要求您确认，因为店铺尚未收到这笔付款记录。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[80, -60], [-24, 0], [0, -26], [0, -26]]} alt="变暗的收款面板上方出现确认提示：离线时收取 $45.00 现金？下方有取消和收取 $45.00 现金按钮">

1. **提示后方** — 收款面板变暗并等待操作。在您作出选择前，不会记录收款。
2. **离线时收取…？** — 销售记录会保留在此设备上，待店铺恢复连接后发送。如果店铺拒绝该记录，它会显示在[订单](../orders/index.mdx)的 **需要处理** 中。
3. **取消** — 返回收款面板，不记录收款。
4. **收取 $45.00 现金** — 记录付款。照常找零即可。

</JourneyShot>

## 店铺确认前的收据 {#awaiting-store}

这笔销售已付款。在店铺收到记录之前，已付款界面和收据都会注明这一状态。

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[62, 0], [-30, 0], [80, 16], [0, -28], [0, -28], [0, -28], [0, -28]]} alt="离线时的已付款界面：以时钟代替勾号，显示等待店铺确认 · 现金，收银机状态栏显示离线 · 1 笔销售待发送，以及电子邮件收据、下载 PDF、打印收据和新销售按钮">

1. **时钟** — 已付款，尚未经店铺确认。店铺收到销售记录后，会变为通常的勾号。
2. **等待店铺确认** — 显示在所用付款方式之前。未结订单的选项卡显示 **已付款 · 等待店铺确认**，购物车中的付款记录显示 **离线记录**。
3. **离线 · 1 笔销售待发送** — 此设备上有多少笔销售记录正在等待发送给店铺。
4. **打印收据** — 使用连接到收银台的打印机打印。收据上会注明 **等待店铺确认 · 尚未确认**。打印店铺端收据的打印机则需要等待：它会提示您在店铺确认销售后重新打印。参见[打印收据](../receipts/at-checkout.mdx#print-receipt)。
5. **电子邮件收据** — 仍可使用，邮件会等待发送。详见下文。
6. **下载 PDF** — 需要连接店铺，因此呈灰色不可用状态。
7. **新销售** — 为下一位客户打开一个空购物车。

</JourneyShot>

预览中可能显示 **此模板无法预览此订单**。这是因为店铺端模板需要等待连接店铺，并不影响打印收据。

您仍可按 **电子邮件收据**，安排向客户发送收据。

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[-18, 0], [0, -28]]} alt="离线时的电子邮件收据表单：提示连接恢复后会通过邮件发送收据，并显示上线后发送按钮">

1. **此设备目前无法连接到您的店铺** — 连接恢复后，会自动通过邮件发送收据。
2. **上线后发送** — 替代 **发送** 按钮。按下后会看到 **收据邮件已加入队列**。参见[电子邮件收据](../receipts/at-checkout.mdx#email-receipt)。

</JourneyShot>

## 等待发送的销售记录 {#offline-writes}

离线时的所有操作都会保留在此设备上，即使销售过程中断线或关闭应用也不会丢失。只要您已登录且店铺可以访问，这些数据就会自动发送，无需按任何按钮。点按收银机状态栏末端的头像，可查看等待发送的内容。

<JourneyShot manifest={manifest} device="tablet" step={6} offsets={[[0, 0], [-30, 0]]} alt="离线时的收银员面板：等待店铺确认 · 1 笔销售提示条、在线登录后发送提示，以及显示需要连接店铺才能切换的店铺行">

1. **等待店铺确认 · 1 笔销售** — 此设备已完成收款，但店铺尚未收到的销售记录。**在线登录后发送**：无需按任何按钮。
2. **切换** — 呈灰色不可用状态，并显示 **需要连接店铺才能切换**。更换店铺需要等待连接恢复。交接收银台、切换收银机和退出登录仍可操作。

</JourneyShot>

收银机状态栏中的提示：

- **离线** — 没有连接，也没有等待发送的销售记录。
- **离线 · 1 笔销售待发送** — 没有连接，有销售记录等待发送。
- **1 笔销售等待店铺确认** — 连接已恢复，但店铺尚未对这些销售记录作出响应。

您还可能看到：

- **1 笔销售等待同步** — 店铺要求您重新登录时，会显示在横幅上。参见[登录和钱箱](#goes-wrong-sign-in)。
- **在此为您保留** — 交接收银台时若仍有销售记录等待发送，会显示此提示及尚未发送的销售笔数。这些记录会保留在此设备上，待您登录并恢复在线后发送。
- **等待发送的更改** — 位于[店铺健康状况 → 数据库](../support/store-health.mdx#database)，列出仍保存在此设备上的所有更改，包括客户、编辑内容和收据邮件。

:::warning 有更改等待发送时，请勿清除本地数据
[清除本地数据](../support/troubleshooting/clear-local-data.mdx)会丢弃所有尚未送达店铺的更改。离线完成收款的销售，其款项已经进入您的钱箱。
:::

## 连接恢复后 {#back-online}

等待中的销售记录会自动发送，通常只需几秒钟。

屏幕顶部会出现 **连接已恢复** 提示，收银机状态栏会显示 **1 笔销售等待店铺确认**，直到店铺收到所有销售记录后才会消失。读卡器、在线支付网关以及[哪些功能需要连接](#what-requires-a-connection)中列出的所有功能都会恢复正常。

您离线期间店铺中更改过的商品、价格和客户，会在恢复在线后不久自动下载。要确认所有销售记录均已送达，请打开[店铺健康状况 → 数据库](../support/store-health.mdx#database)：**等待发送的更改** 应显示为 0，表格上方也不应有要求您作出决定的面板。参见[需要您处理的情况](../support/store-health.mdx#needs-attention)。

## 哪些功能需要连接 {#what-requires-a-connection}

- **与收银台配对的读卡器和在线支付网关** — 选项上会显示 **需要连接**。如果销售已有订单号，可收取现金或记录通过自备终端收取的银行卡付款。否则，请保留订单，待店铺恢复连接后再收款。通过读卡器离线收款的功能已列入[路线图](roadmap.mdx)。
- **为离线时发起的销售收款** — 销售会保留在未结订单中，待店铺恢复连接后再收款。参见[上方说明](#take-payment-offline)。
- **旧版选项卡** — 在网关自己的付款页面上收款。参见[旧版选项卡](../pos/checkout/legacy-tab.mdx)。
- **退款** — 离线时无法退款。参见[退款](../orders/refunds.mdx)。
- **创建新优惠券**（WCPOS Pro）— 按钮会显示 **连接店铺后才能创建优惠券**。
- 收据的 **下载 PDF** 功能。
- **切换店铺**，以及向设备 **添加收银员**。将收银台交接给设备上已有的收银员可在离线时进行。
- 将 **钱箱随身转移** 到其他店铺。仍在等待发送的销售记录必须先发出：在发送完成前，此选项会显示例如 **请先发送 2 笔销售**。
- 交班时 **批准有差额的盘点结果**。参见[开启收银机](../pos/register/index.mdx#goes-wrong)。
- 店铺中的 **新商品、新价格和新客户**。连接恢复前，您只能使用设备上已有的数据进行销售。

:::tip 网络不佳时，上班前的准备
在信号良好时打开 POS，让商品目录下载完成。[店铺健康状况 → 数据库](../support/store-health.mdx#database)会显示设备上已下载了多少内容。
:::

## 出现问题时 {#goes-wrong}

根据提示出现的销售环节，在下方查找收银台显示的消息。

### 扫码 {#goes-wrong-scanning}

**“无法扫码” — 此设备上没有该商品，离线时无法搜索店铺。** 该商品尚未下载到此设备。请按名称搜索，或恢复在线后再销售。**查看状态** 会打开[店铺健康状况](../support/store-health.mdx#database)。参见[条码扫描](../pos/product-panel/barcode-scanning.mdx)。

**“查找失败” — 店铺未响应。** 设备有网络，但店铺未响应扫码请求。请检查连接后重新扫描。

### 结账和订单 {#goes-wrong-checkout}

**“订单未保存 — 店铺已拒绝”。** 店铺拒绝了该订单，原因显示在标题下方。销售会返回购物车，其选项卡显示 **保存被拒绝**。解决店铺指出的问题（例如某件商品缺货）后，再次按 **结账**。**店铺健康状况** 会打开被拒绝的更改，提供 **重新发送** 和 **丢弃** 操作。参见[未能送达服务器的更改](../support/store-health.mdx#refused-changes)。

**“此订单仍在发送至您的店铺”。** 稍等片刻，再次按 **结账**。尚未扣款，而且店铺能识别该订单，因此不会重复创建订单。

**“…未保存到店铺”。** 您离线时添加的客户被店铺拒绝了。销售会保留其地址，但仍作为访客销售处理。从[店铺健康状况](../support/store-health.mdx#refused-changes)重新发送该客户后，销售就会关联到该客户。

**订单中“需要处理”下的销售。** 店铺拒绝了一笔离线收取的付款。请打开订单，与客户处理这笔款项。参见[订单](../orders/index.mdx)。

### 登录和钱箱 {#goes-wrong-sign-in}

**“会话已过期”或“1 笔销售等待同步”。** 店铺要求您重新登录，才会继续接收此设备发送的数据。请按 **登录**。数据不会丢失：尚未发送的销售记录会在登录后发送。如果看到 **会话已自动续期**，表示 POS 已自动为您重新登录，无需操作。

**“钱箱已转移。此设备将在下次同步时记录。”** 您已将钱箱转移到其他店铺，店铺端也已记录，无需操作。如果显示的是 **钱箱转移未完成**，请检查两个收银机后再重试。

### 收据 {#goes-wrong-receipts}

**“您的服务器未发送邮件。”** 店铺已收到收据邮件请求，但未发送邮件。仍在等待或已停止尝试发送的收据邮件，会列在[店铺健康状况 → 数据库](../support/store-health.mdx#database)的 **等待发出的收据邮件** 下，每封邮件都提供 **重新发送** 和 **移除** 操作。

收据上显示 **“未保存到店铺 · 无订单号”**。店铺从未收到这笔销售记录，因此它没有订单号，也暂时无法通过邮件发送收据。请按 **同步订单** 将其发送。

:::info 使用 WCPOS Pro
有多个店铺时，切换店铺需要连接：在连接恢复之前，店铺行会显示 **需要连接店铺才能切换**。
:::
