# Windcave Terminal 网关 {#windcave-terminal-gateway}

Windcave Terminal 会将销售请求从收银机发送到 Windcave 终端。顾客在终端上付款，Windcave 确认后，收银机便会记录这笔付款。

本页从收银机操作开始。店铺管理员可参阅[设置 Windcave Terminal](#setup)，了解凭据、WP Admin 设置以及如何确认设置成功。

:::info Pro 功能
Windcave Terminal 需要 2.0 或更高版本的 [WCPOS Pro](../../getting-started/pro-license.mdx)，以及 1.0 或更高版本的扩展。
:::

:::warning 尚未通过 Windcave 认证
**仅用于测试付款：目前请勿使用 Windcave 收取真实顾客的银行卡付款。** Windcave 要求所有 POS 集成通过审批后才能收取真实付款，而此集成尚未获批。

<details>
<summary>尚未测试的内容</summary>

此扩展尚未在实体 Windcave 终端上运行过。我们根据 Windcave 文档构建了 HIT 服务模拟环境，并在其中测试了付款和退款。正式使用前，请先在 UAT 环境进行一笔小额销售并退款。

</details>
:::

## 收取银行卡付款 {#take-payment}

:::note 请先开启收银机
启用 **开启和关闭收银机** 后，收银机关闭时无法记录付款；如果已经收取银行卡款项，则必须退款。有关此设置，请参阅[收银机](../../settings/wp-admin/registers.mdx#one-register)。
:::

1. 在购物车中按 **结账**，然后点按 **付款** 选项卡中的 **Windcave Terminal** 磁贴。如果终端会询问签名，请改用 **传统** 选项卡：参阅[终端询问问题时](#terminal-questions)。
2. 查看键盘上方。如果看到 **选择终端**，请点按柜台所用终端的 **Station ID**：这是 Windcave 为每台终端指定的名称，例如 `DOCS-STATION-1`。如果看到 **终端：** 和一个 ID，则表示此收银机正在使用该终端；按 **更改** 可选择其他终端。收银机会记住您的选择。
3. 如需用银行卡支付部分余额，请输入金额。剩余金额仍需通过另一笔付款结清。
4. 按 **发送 … 到 Windcave Terminal**。收银机将显示 **终端处理中** 和四个步骤：**已发送**、**终端处理中**、**已批准** 和 **已扣款**，表示款项已收取。
5. 顾客在终端上感应、插入或刷卡。付款扣款完成且没有剩余应付金额时，系统会打开收据。如果还有余额，请使用另一种付款磁贴收取。

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[105, 0], [-40, 0], [190, 0], [-45, 0], [0, 0], [85, 0]]} maxWidth={720} alt="在付款选项卡中为 $45.00 销售进行结账：已选中 Windcave Terminal 磁贴，选择终端下方列出两个 Station ID，其下方显示全额余额；未选择终端前，发送 $45.00 到 Windcave Terminal 按钮呈灰色不可用">

1. **Windcave Terminal** — 点按后会以边框突出显示的磁贴。
2. **选择终端** 下方的 **Station ID** — 点按柜台所用终端对应的 ID。此收银机选定终端后，此行会显示 **终端：** 及其 ID，并提供 **更改**。
3. **待支付** — 此次付款的金额。输入较小金额即可用银行卡支付部分余额。
4. **全额余额** — 将所有剩余应付金额填回 **待支付**。
5. **发送 … 到 Windcave Terminal** — 在终端上开始付款。选择终端前，此按钮呈灰色不可用。

</JourneyShot>

四个步骤下方的 **详情** 会打开付款日志，其中包含付款所用的 Station。终端不支持小费、附加费或刷卡取现。

### 终端询问问题时 {#terminal-questions}

终端可能会暂停并提出问题，例如询问顾客的签名是否相符。此版本的 **付款** 选项卡不会显示这些问题，**传统** 选项卡则会显示：

1. 打开 **传统** 选项卡并选择 **Windcave Terminal**。请参阅[传统选项卡](../../pos/checkout/legacy-tab.mdx)。
2. 在该选项卡中开始付款。整个订单会通过一笔付款结清。
3. 终端提问时，付款页面会显示问题以及终端自带的按钮，例如 **YES** 和 **NO**。请按下相应答案。

### 取消付款 {#cancel}

请在顾客付款前按 **在终端上取消**。只有终端本身提供 **CANCEL** 时，此操作才有效。否则，收银机会显示 *终端当前未提供取消选项。请在终端上取消。*

取消操作只是发送请求。如果已经读取银行卡，付款仍可能成功：收银机会显示 **正在取消 — 等待终端确认**，继续查询并显示结果。请等待结果后再改用其他方式收款。

如果收银机无法获取结果，会提供 **释放此笔付款**。释放不代表已取消：只有经理检查 Windcave 门户并确认该订单没有已批准的付款后，才能按此按钮。之后可以改用其他方式支付订单，而店铺仍会继续查询终端。

## 故障排查 {#goes-wrong}

### 顾客可能已付款时 {#may-have-paid}

:::warning 请勿再次收款
在以下两种情况下，银行卡可能已扣款。经理应先检查 Windcave 门户，销售记录会列在订单编号下。
:::

**无法确认终端结果。再次收款前，请先检查 Windcave。** 收银机重新查询了已发送的付款，但 Windcave 的答复不明确。只有经理在门户中查找销售记录并确认不存在后，才能再次收款。

**付款失败：终端确认的金额不同。** 终端批准的金额与收银机发送的金额不同，因此收银机没有记录这笔付款，但银行卡可能已扣款。请勿再次收款：让经理在门户中按订单编号查找销售记录，并比较终端收取的金额与订单金额。

## 退还 Windcave 付款 {#refunds}

退款会经由 Windcave 返回到收取该笔销售款项的 Station，可退还全额或部分金额。

1. 在 POS 中打开订单的退款界面。请参阅[退款](../../pos/refunds.mdx)。
2. 选择 **退还到 Windcave Terminal**，然后按 **处理退款**。
3. 店铺最多等待 Windcave 回复 20 秒，然后将结果添加到订单备注中。

在 WP Admin 中使用 WooCommerce 的 **通过 Windcave Terminal 退款 …** 按钮办理退款，操作方式相同。

如果退款仍处于 **待处理** 状态，请先在 Windcave 门户中检查，再次退款前确认结果。

<Accordion>
  <AccordionItem question="退款一直处于待处理状态">

  Windcave 未在 20 秒内回复，或批准的金额与请求金额不同。店铺不会重试。请在 Windcave 门户中查找退款：如果退款已成功，顾客已收到款项；如果没有成功，请再次退款。

  </AccordionItem>
  <AccordionItem question="使用 0.1 版本收取的销售款无法退款">

  退款会因 *请先在 POS 设置中配置默认 Station，然后再退还此笔销售。* 而停止。扩展 0.1 版本没有记录收取销售款的 Station，因此 1.0 版本会使用店铺级默认 Station 退款。现在每台收银机都会在 **设置 > 刷卡器** 下选择自己的 Station，而 WCPOS 2.0 目前没有店铺级默认值。请在 Windcave 门户或终端上退还该笔销售，然后在 WooCommerce 中选择 **手动退款 …** 记录退款。

  </AccordionItem>
</Accordion>

## 设置 Windcave Terminal {#setup}

管理员只需在 WP Admin 中为每个店铺设置一次，然后在每台收银机上选择一个 Station。店铺通过互联网经由 Windcave 连接各终端，因此无需配对，任何收银机都可以使用任意终端。

### 要求 {#requirements}

您需要 HIT 凭据、**HIT 用户名**、**HIT 密钥**，以及每台终端对应的 **Station ID**。这些信息均由 Windcave 提供；WP Admin 无法查询或创建。请联系 Windcave，申请 **UAT** HIT 凭据和每台终端的 Station ID；也可以使用 Windcave 的[集成要求表](https://www.windcave.com/merchant-attended-developer-hit)申请开发账户。UAT 和生产环境各自使用独立的用户名和密钥；Windcave 认证通过后会提供 **Vendor ID**。

<RequirementsList>
  <RequirementItem label="Windcave 账户">HIT 凭据，以及每台终端对应的一个 Station ID。Windcave 完成集成认证前请使用 UAT 凭据</RequirementItem>
  <RequirementItem label="终端">支持 HIT 付款的 Windcave 终端</RequirementItem>
  <RequirementItem label="WCPOS">WCPOS Pro 2.0 或更高版本，以及 1.0 或更高版本的扩展</RequirementItem>
  <RequirementItem label="服务器">WooCommerce，以及 PHP 7.4 或更高版本并安装 DOM 扩展（php-xml）</RequirementItem>
</RequirementsList>

### 安装扩展 {#install}

打开 `WP Admin > POS > 设置 > 扩展`，找到 **Windcave Terminal for WooCommerce**，安装并启用。需要 1.0 或更高版本；0.1 版本适用于 WCPOS 2.0 之前的版本。请参阅[扩展](../../extensions/index.mdx#installing-an-extension)。

您也可以从 [GitHub 发布页面](https://github.com/wcpos/windcave-terminal-for-woocommerce/releases)下载**插件 zip**（不是源代码 zip），然后通过 `插件 > Add Plugin > 上传插件` 上传。

如果没有 WCPOS Pro 2.0，WP Admin 会显示 *Windcave Terminal 需要 WooCommerce POS Pro 2.0 或更高版本。*，并且不会添加此网关。PHP 低于 7.4 或未安装 DOM 扩展时，系统会拒绝启用：请联系主机服务商启用 **php-xml**。

### 输入 HIT 凭据 {#credentials}

前往 `WP Admin > WooCommerce > 设置 > 支付`，打开 **Windcave Terminal**。

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[410, 0], [410, 0], [410, 0], [850, 0], [410, 0], [410, 0]]} maxWidth={720} alt="WP Admin 中的 Windcave Terminal 设置：环境为 UAT（测试），HIT 用户名、HIT 密钥、Station ID 和 Vendor ID 均为空，POS 名称为 WCPOS">

1. **环境** — 保持默认的 **UAT（测试）**。Windcave 完成集成认证并提供生产凭据后，才能使用 **生产环境**。
2. **HIT 用户名** — 由 Windcave 针对所选环境提供。
3. **HIT 密钥** — 由 Windcave 提供。保存后，此字段会保持空白：留空即可保留已保存的密钥。
4. **Station ID** — 每台终端填写一个，每行一个。由 Windcave 提供，不会自动查找。
5. **Vendor ID** — Windcave 提供前请留空。
6. **POS 名称** — POS 在 Windcave 中使用的名称。默认为 `WCPOS`。

</JourneyShot>

下方的 **结果通知（FPRN）** 为可选项。勾选后，Windcave 也会在结果就绪时通知店铺，作为收银机自行查询的备用方式。要使用此功能，您的网站必须能从互联网访问。

点击 **保存更改**。

### 在 WCPOS 中启用 {#enable}

前往 `WP Admin > POS > 设置 > 结账`，在 **网关** 表格中找到 **Windcave Terminal**，然后打开 **已启用** 开关。此页面会自动保存更改，无需点击保存按钮。

请在 WooCommerce 设置页面中关闭 **启用/禁用**。无论该选项是否勾选，只要此处的 **已启用** 已打开，POS 就会使用此网关。请参阅[结账设置](../../settings/wp-admin/checkout.mdx#enabling-a-gateway)。

<JourneyShot manifest={manifest} device="desktop" step={2} offsets={[[172, 0], [-26, 0]]} maxWidth={720} alt="WP Admin 中的 POS 设置、结账页面：网关表格有两行，Vipps MobilePay 已开启，Windcave Terminal 已关闭">

1. **Windcave Terminal** — 扩展在 **网关** 表格中的一行。
2. **已启用** — 网关 ID 旁边的开关；请将其打开。收银机重新加载后会显示 **Windcave Terminal** 磁贴。

</JourneyShot>

### 为每台收银机选择 Station {#till-terminal}

在每台收银机上打开 **设置 > 刷卡器**。您输入的每个 Station ID 都会列在 **智能刷卡器** 下方，并标记为 **在线**：扩展不会向 Windcave 查询终端是否已开机。按柜台所用 Station 对应的 **使用此读卡器**，其所在行会显示 **已选中**。收银员仍可在结账时按 **更改**。

只有一个 Station 时无需选择：每台收银机上都已将其标记为 **已选中**。请参阅[选择智能刷卡器](../../hardware/card-readers/index.mdx#smart-readers)。

### 确认设置成功 {#check}

1. 返回 Windcave Terminal 设置页面，设置下方会显示 `uat: HIT credentials configured (not verified).`。这表示用户名和密钥已保存，并不代表 Windcave 已接受它们。`HIT credentials missing.` 表示其中一项为空。
2. 在收银机上重新加载 POS 并按 **结账**。可用付款方式中会出现 **Windcave Terminal** 磁贴。点按后，键盘上方会显示 Station ID，位置在 **选择终端** 下方，或显示为 **终端：** 及此收银机正在使用的终端。
3. 在 UAT 终端上进行一笔小额销售，然后退款。此扩展没有测试连接按钮：首次销售用于检查凭据和 Station ID。

### 从 0.1 版本升级 {#upgrade}

- 先将 WCPOS、WCPOS Pro 和应用更新到 2.0，然后再更新扩展。
- 升级期间正在处理的付款会继续保留，不会重复扣款。
- 如果订单仍未付款，0.1 版本暂存的付款会继续保留。否则，订单会收到备注：*Windcave TxnRef … 在 1.0.0 升级前已暂存，不再自动跟踪。* 请在 Windcave 门户中检查该笔付款：如果已获批准，请在那里退款，或手动在订单中记录。
- 以下 0.1 版本设置已移除：**默认 Station ID**、**锁定终端选择**、**结账日志** 和 **日志级别**。现在每台收银机都会在 **设置 > 刷卡器** 下选择自己的 Station。
- 暂存功能也已移除，终端收据文本不再作为私密备注添加到订单中。
- 退还使用 0.1 版本收取的销售款：请参阅[退还 Windcave 付款](#refunds)。

## 设置参考 {#settings}

前往 `WP Admin > WooCommerce > 设置 > 支付 > Windcave Terminal`：

| 设置 | 作用 |
|---|---|
| **启用/禁用** | 在网店结账页面提供此网关。请保持关闭；POS 在 `POS > 设置 > 结账` 下有自己的开关 |
| **标题** | 收银机上磁贴的名称。默认为 `Windcave Terminal` |
| **描述** | 默认为 `Pay in person on the Windcave terminal.` |
| **环境** | **UAT（测试）**（默认）或 **生产环境**。每种环境都有独立的 HIT 凭据；生产环境需要 Windcave 认证。在某个环境中发起的付款始终会在该环境中查询 |
| **HIT 用户名** | 由 Windcave 提供，适用于所选环境 |
| **HIT 密钥** | 由 Windcave 提供。保存后不会再显示；留空即可保留该密钥 |
| **Station ID** | 每台终端填写一个，每行一个。重复项会被删除 |
| **Vendor ID** | 在认证期间与 Windcave 确认。在此之前请留空 |
| **POS 名称** | 您的 POS 在 Windcave 中使用的名称。默认为 `WCPOS` |
| **结果通知（FPRN）** | 结果就绪时，Windcave 也会通知店铺，作为收银机查询的补充。默认关闭 |

## 日志和支持包 {#logs-and-support-bundle}

设置页面底部有支持包、凭据状态行和日志链接。

<JourneyShot manifest={manifest} device="desktop" step={3} offsets={[[200, 0], [80, 0], [-20, 0]]} maxWidth={720} alt="尚未完成设置的店铺中，WP Admin 的 Windcave Terminal 设置页面底部：支持包及其下载支持包按钮、uat: HIT credentials missing 状态行和查看日志">

1. **凭据状态行** — 此店铺尚未完成设置，因此显示 `HIT credentials missing.`。您的状态应显示 `HIT credentials configured (not verified).`。
2. **查看日志** — 打开 `WooCommerce > Status > 日志`，日志来源为 `windcave-terminal`。
3. **下载支持包** — 提供给 WCPOS 支持人员的文件。

</JourneyShot>

日志会记录发往 Windcave 的每个请求及其回复，并遮蔽 HIT 密钥和银行卡号。

付款出现问题时，点击 **下载支持包**，并将文件连同 **订单编号** 一起发送给 WCPOS 支持人员。WCPOS Pro 会添加此按钮：支持包涵盖网站上的所有 POS 付款提供商，并会移除机密信息和银行卡号。

## 不支持的功能 {#scope-and-limitations}

- Windcave 完成集成认证前不支持真实付款。
- 不支持小费、附加费、刷卡取现，也不支持先授权后扣款。
- 无法在 **付款** 选项卡中回答终端的问题。请使用 **传统** 选项卡。
- 自动发现终端：需要手动输入每个站点 ID。
- 首次付款前无法检查 HIT 凭据。

<details>
<summary>开发者说明：工作原理</summary>

此网关通过 HTTPS 使用 Windcave **HIT（主机发起交易）**：UAT 使用 `uat.windcave.com`，生产环境使用 `sec.windcave.com`。每台终端通过其 **Station ID** 寻址。

付款请求会发送一笔金额与收银机显示金额相同的 Purchase，并以 `Order #` 和订单编号作为商户参考，然后 WCPOS Pro 会持续查询状态直至完成。如果收银机再次发起查询，扩展会先查询同一交易参考，而不是再发起一笔 Purchase。Windcave 在 30 秒内未登记的 Purchase 会被视为未发送。

启用 **结果通知（FPRN）** 后，每笔 Purchase 都会要求 Windcave 调用店铺的 WCPOS 付款 webhook：`wp-json/wcpos/v2/payments/webhook`，并附带 `provider=windcave` 和交易参考。此调用仅作提示：随后店铺会自行向 Windcave 查询结果。

退款是针对原 Windcave 交易发起的 HIT 匹配退款，金额为您输入的金额。店铺最多每隔 2 秒查询一次状态，持续 20 秒。

</details>
