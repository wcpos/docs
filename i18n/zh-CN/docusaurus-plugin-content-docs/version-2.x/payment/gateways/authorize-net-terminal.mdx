# Authorize.net Tap to Pay {#authorizenet-tap-to-pay}

顾客在您的手机上使用 Authorize.net 自有应用贴卡付款。您需要在该应用中手动输入金额：收银台不会发送金额。随后，收银台会在 Authorize.net 中查找这笔付款，并将其记录到订单中。

这与 [WCPOS 应用自带的 Tap to Pay](../../hardware/card-readers/index.mdx#tap-to-pay) 是两项不同的功能，后者使用 Stripe Terminal。店铺管理员可参阅[设置 Authorize.net Tap to Pay](#setup)，了解凭据、手机设置以及如何确认功能正常。

:::info Pro 功能
Authorize.net Tap to Pay 需要 [WCPOS Pro](../../getting-started/pro-license.mdx) 2.0 或更高版本。
:::

:::warning 测试版：请先进行测试付款
**0.1.0 版本仍处于测试阶段，尚未尝试在 Authorize.net 应用中实际贴卡付款。** 在收取顾客的银行卡款项前，请先用自己的卡进行一笔小额付款并退款。

<details>
<summary>已测试和未测试的内容</summary>

我们使用 Authorize.net 沙盒测试了 0.1.0 版本，并通过 Authorize.net API 模拟现场刷卡销售，以代替实际贴卡操作；测试了销售、匹配、撤销以及结算后的退款。尚未测试：在应用中实际贴卡付款、实际贴卡后 Legacy 标签页中的匹配付款列表，以及与 Authorize.net 应用配对的读卡器。如需报告问题，请提供订单号、销售时间和屏幕截图。

</details>
:::

## 收取付款 {#take-payment}

:::note 请先打开收银台
启用 **打开和关闭收银台** 后，收银台关闭时系统不会记录付款；如果您已经收取了银行卡款项，就必须退款。有关此设置，请参阅[收银台](../../settings/wp-admin/registers.mdx#one-register)。
:::

1. 在购物车中按 **结账**。
2. 在 **付款方式** 标签页中，点按 **Authorize.net Tap to Pay** 磁贴（您的店铺可能已为其改名）。数字键盘上方会显示 **终端：** 和手机名称；除非经理更改过名称，否则会显示 **Authorize.net 应用**。
3. 按 **发送 … 至 Authorize.net Tap to Pay**，例如 **发送 $10.00 至 Authorize.net Tap to Pay**。收银台会显示 **正在等待顾客在终端上付款**。
4. 在手机上的 Authorize.net 应用中输入 **完全相同的金额**。请勿在应用中添加小费；请参阅[小费](../../pos/checkout/tips.mdx)。
5. 顾客在手机上贴卡付款。
6. 等待收银台处理。找到这笔付款后，收银台会将其记录下来；待付金额为零时，会打开收据。

请在按下发送后 5 分钟内完成贴卡付款。5 分钟后，收银台会取消付款，显示 **已超时 — 付款已取消**，并停止查找这笔付款。

<details>
<summary>收银台如何查找付款</summary>

收银台等待期间，WCPOS 会持续在 Authorize.net 中查找金额相符的付款。如果自您按下 **发送** 前 30 秒起，恰好有一笔此金额的付款到账，并且已启用 **自动匹配**，系统就会自动记录这笔付款。记录前，WCPOS 会向 Authorize.net 核对付款信息，包括金额和币种。一笔付款最多只会记录到一个订单中。

付款处理过程中，收银台会依次亮起 **已发送**、**终端已收到**、**已批准** 和 **已捕获**。

</details>

### 取消付款 {#cancel}

按 **在终端上取消**。在 WCPOS 中取消不会停止 Authorize.net 应用中的操作，因此请告知顾客不要贴卡。

收银台会最后一次检查 Authorize.net。如果恰好有一笔此金额的新付款到账，系统就会记录该付款并完成销售；否则会取消付款。

## 遇到问题时 {#goes-wrong}

### 顾客可能已付款的情况 {#may-have-paid}

:::warning 请勿再次收取银行卡款项
在这些情况下，款项可能已经进入您的 Authorize.net 账户，但订单仍显示未付款。请按下方 Legacy 标签页中的步骤操作，或联系经理。
:::

**顾客贴卡后，收银台仍在等待。** 只有在确定哪笔付款属于当前订单时，收银台才会自动记录付款。否则会继续等待，并在 5 分钟后超时。以下情况可能导致此问题：

- 应用中的金额与收银台中的金额不同，例如在应用中添加了小费；
- 其他收银台或您的网上商店同时收到了一笔相同金额的付款；
- 经理已在网关设置中关闭 **自动匹配**。

**付款方式** 标签页无法询问您哪笔付款属于当前订单。订单的 [**Legacy**](../../pos/checkout/legacy-tab.mdx) 标签页可以列出最近 15 分钟内的付款，由收银员或经理执行以下操作：

1. 在结账时保持同一个订单，选择 **Legacy** 标签页，然后选择 **Authorize.net Tap to Pay**。
2. 按 **发送 10.00 USD 至 Authorize.net 应用**（此标签页上的按钮显示手机名称，而非磁贴名称）。请勿再次收取银行卡款项。
3. 收银台会显示一个列表，标题示例：**有 2 笔 10.00 USD 的 Authorize.net 付款可能是这笔交易。请选择刚才收取的那一笔。**
4. 每一行都会显示卡类型、末 4 位数字、时间和 Authorize.net 交易编号。请选择与顾客银行卡及贴卡时间相符的一笔。订单随即标记为已付款。

如果没有显示列表，请勿再次收取银行卡款项：经理应在您的 Authorize.net 账户中找到这笔付款并[在那里退款](#refunds)。

**顾客在您取消后才贴卡。** 取消操作不会停止应用。请按上述步骤从 Legacy 标签页记录付款，或由经理在您的 Authorize.net 账户中退款。

**付款失败：终端确认的金额不同。** 这与上述小费情况不同：只有 Authorize.net 本身报告所选付款的金额或币种不同才会出现此提示，例如店铺使用的币种不在账户支持范围内。收银台不会记录这笔付款，并会添加订单备注。请勿使用 Legacy 标签页；请联系经理，由经理在您的 Authorize.net 账户中找到这笔付款并退款。

如果付款因其他原因卡在收银台，请参阅[读卡器付款卡住时的处理方法](../index.mdx#card-reader-problems)。

## 退还 Authorize.net 付款 {#refunds}

1. 在 POS 中打开订单的退款操作。请参阅[退款](../../pos/refunds.mdx)。
2. 选择 **退款至 Authorize.net Tap to Pay**，然后按 **处理退款**。

Authorize.net 结算付款前（通常在夜间结算），只能全额退款，且这会撤销付款。结算后，可以将全部或部分款项退回银行卡。在 WP Admin 中从订单发起退款，处理方式相同。

<details>
<summary>退款消息</summary>

- **Authorize.net 会在夜间结算这笔付款。现在全额退款可撤销付款；结算后可退还部分款项。** — 可全额退款，或等到明天再办理部分退款。
- **过去 8 小时内已发送相同的退款。再次尝试前，请先检查 Authorize.net 商户界面。**
- **这笔 Authorize.net 付款已撤销。** — 整笔付款已在结算前撤销。
- **Authorize.net 未确认退款。再次尝试前，请先检查 Authorize.net 商户界面。**
- **Authorize.net 目前无法退还这笔付款。请检查 Authorize.net 商户界面。**
- **这笔付款是在另一个 Authorize.net 环境中收取的。** — 请切回原来的 **环境**，或在商户界面中退款。
- **这笔付款没有可供退款的 Authorize.net 交易。**
- **退款金额必须大于零。**

</details>

## 设置 Authorize.net Tap to Pay {#setup}

经理只需在 WP Admin 中设置一次网关，然后在手机上的 Authorize.net 应用中登录。

### 要求 {#requirements}

<RequirementsList>
  <RequirementItem label="处理商">您的 Authorize.net 商户账户必须使用 TSYS 处理商，并由 Authorize.net 启用 Tap to Pay。购买手机前，请向 Authorize.net 确认。</RequirementItem>
  <RequirementItem label="Authorize.net 账户">美国商户账户、该账户的 API Login ID 和 Transaction Key，以及已启用的 Transaction Details API</RequirementItem>
  <RequirementItem label="手机">根据 Authorize.net 的说明：iPhone 上的 Tap to Pay 需要 iPhone XS 或更新机型，并运行 iOS 18 或更高版本；Android 上的 Tap to Pay 需要运行 Android 15 且支持 Tap to Pay Ready 的手机。请使用同一 Authorize.net 账户下的用户登录 Authorize.net 2.0 应用。</RequirementItem>
  <RequirementItem label="币种">USD：Authorize.net 2.0 应用仅支持 USD</RequirementItem>
  <RequirementItem label="WCPOS">WCPOS Pro 2.0 或更高版本，以及收银台的网络连接</RequirementItem>
  <RequirementItem label="服务器">WooCommerce 7.0+、PHP 7.4+，以及误差在 30 秒以内的服务器时钟</RequirementItem>
</RequirementsList>

### 安装扩展程序 {#install}

在 `WP Admin > POS > 设置 > 扩展` 中找到 **Authorize.net Tap to Pay for WooCommerce (beta)**，然后点击 **安装**。WCPOS 会安装并启用该扩展程序，同时开启 **自动更新**，以便自动安装新的测试版。请参阅[扩展程序](../../extensions/index.mdx#installing-an-extension)和[自动更新](../../extensions/index.mdx#auto-updates)。

<details>
<summary>也可以从已下载的 zip 文件安装</summary>

从 [GitHub 发布页面](https://github.com/wcpos/authorize-net-terminal-for-woocommerce/releases)下载 `authorize-net-terminal-for-woocommerce.zip`，然后通过 `插件 > Add Plugin` 上传，再点击 **上传插件**。GitHub 上的“Source code”zip 文件无法用于安装。

</details>

### 获取 API 凭据 {#credentials}

在 Authorize.net 商户界面中：

1. 打开 **账户 → 设置 → API 凭据和密钥**，并复制 **API Login ID**。Authorize.net 只会在创建 **Transaction Key** 时显示一次：如果您没有保存该密钥，请重新创建并立即复制。新密钥会替换旧密钥，因此如果您的网上商店已使用此账户，请继续使用原密钥，或同时更新商店中的密钥。**生产环境** 请使用正式账户的凭据；沙盒账户的凭据只能用于 **沙盒**。
2. 打开 **账户 → 设置 → Transaction Details API** 并启用该选项。未启用时，您的店铺无法读取付款，收银台也不会记录付款。

### 输入凭据 {#enter-credentials}

打开 `WP Admin > WooCommerce > 设置 > 支付`，然后点击 **Authorize.net Tap to Pay**。

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[410, 0], [410, 0], [410, 0], [410, 0], [-30, 0], [410, 0]]} maxWidth={720} alt="WP Admin 中尚未设置的店铺的 Authorize.net Tap to Pay 设置：标题为 Authorize.net Tap to Pay，环境为沙盒，API Login ID 和 Transaction Key 字段为空并显示“未保存值”，自动匹配已勾选，读卡器名称为 Authorize.net 应用">

1. **标题** — 收银台上磁贴的名称。
2. **环境** — 选择 **生产环境**。仅在不使用手机、只测试店铺端功能时，才保留默认值 **沙盒**。请参阅[沙盒和生产环境](#environments)。
3. **API Login ID** — 在此处粘贴。
4. **Transaction Key** — 在此处粘贴。保存后，这两个字段会保持空白，且只显示末 4 位字符；若要保留已保存的值，请将字段留空。保存操作不会测试凭据；请通过[确认功能正常](#check)进行检查。
5. **自动匹配** — 保持勾选。若未启用，收银台就不会自动记录付款。
6. **读卡器名称** — 收银台在数字键盘上方显示的名称。

</JourneyShot>

点击 **保存更改**。

### 设置手机 {#phone}

在手机上安装 Authorize.net 应用，并使用您所输入凭据所属 Authorize.net 账户的用户登录：使用 **生产环境** 时，请登录正式账户。

### 在 WCPOS 中启用 {#enable}

网关设置页面中没有 **启用** 复选框。请打开 `WP Admin > POS > 设置 > 结账`。

<JourneyShot manifest={manifest} device="desktop" step={2} offsets={[[-22, 0], [50, 0]]} maxWidth={720} alt="WP Admin 中的 POS 设置和结账页面：网关表格有三行，银行卡已启用，Authorize.net Tap to Pay 和直接银行转账已停用">

1. **Authorize.net Tap to Pay** — 扩展程序在 **网关** 表格中的对应行。
2. **已启用** — 将其切换为开启。收银台重新加载后会显示该磁贴。

</JourneyShot>

该网关不会出现在网上商店的结账页面中。请参阅[结账设置](../../settings/wp-admin/checkout.mdx#enabling-a-gateway)。

### 确认功能正常 {#check}

1. 在收银台重新加载 POS 并按 **结账**。在可用付款方式中应能看到 **Authorize.net Tap to Pay** 磁贴。
2. 点按该磁贴：数字键盘上方会显示 **终端：** 和您的 **读卡器名称**。
3. 确认 **环境** 为 **生产环境**，然后用自己的银行卡进行一笔小额销售。
4. 请在当天全额退款：结算前全额退款会撤销付款。

如果收银台自动记录了付款并打开收据，且订单的付款信息中显示 Authorize.net 交易 ID，即表示功能正常。

如果收银台显示 **连接不稳定，仍在尝试** 并持续等待，请检查凭据、**环境** 和 Transaction Details API。

## 沙盒和生产环境 {#environments}

**沙盒** 是默认环境，使用 `apitest.authorize.net`。**生产环境** 使用 `api.authorize.net`，会处理真实款项。凭据仅适用于对应环境：请输入所选环境的凭据。店铺端功能可在沙盒中运行；测试版已通过 Authorize.net API 在沙盒中进行销售测试。Authorize.net 未说明其应用是否可以登录沙盒账户，因此请在生产环境中尝试实际贴卡付款。

只有在没有收银台正在处理 Authorize.net 付款时，才能切换 **环境**：等待中的付款会失败。切换环境后，无法再通过收银台退款给在另一个环境中收取的款项。

## 设置参考 {#settings}

在 `WP Admin > WooCommerce > 设置 > 支付 > Authorize.net Tap to Pay` 中：

| 设置 | 功能 |
|---|---|
| **标题** | 收银台上磁贴的名称。默认值为 **Authorize.net Tap to Pay** |
| **环境** | **沙盒**（默认）或 **生产环境** |
| **API Login ID** | 在商户界面中获取：**账户 → 设置 → API 凭据和密钥**。保存后只显示末 4 位字符；留空可保留已保存的值 |
| **Transaction Key** | 仅存储在服务器上，之后不会再次显示。保存和显示方式与 API Login ID 相同 |
| **自动匹配** | 恰好有一笔 Authorize.net 付款符合条件时自动记录。默认开启 |
| **读卡器名称** | 收银台在数字键盘上方显示的名称。默认值为 **Authorize.net 应用** |

粘贴的凭据中如果包含隐藏字符，系统会拒绝并显示 **Authorize.net 凭据不能包含控制字符。** 请重新粘贴。

**请先输入 Authorize.net API Login ID 和 Transaction Key。** 表示缺少凭据：请输入两项凭据，然后点击 **保存更改**。

</JourneyShot>

日志位于 `WooCommerce > Status > 日志`，来源为 `authorize-net-terminal-for-woocommerce`；其中的凭据和银行卡号已移除。发生付款问题时，请连同支持信息包一起提供 **订单号** 和 **销售时间**。

如果扩展程序显示 **Authorize.net Tap to Pay for WooCommerce POS needs WooCommerce POS Pro 2.0.0 or newer.**，请安装或更新 WCPOS Pro：没有它，该扩展程序不会为 POS 添加任何功能。

## 此功能不支持的操作 {#scope-and-limitations}

- 将金额发送到手机：您需要在应用中输入金额。
- 在应用中添加小费：金额必须完全一致。
- 在 **付款方式** 标签页中显示可能的付款列表：请在 [Legacy 标签页](#may-have-paid)中从列表选择。
- 实体银行卡终端。与 Authorize.net 应用配对的读卡器尚未经过测试。
- 手动捕获，或 Authorize.net 暂扣待审核的付款：收银台会继续等待。
- 不支持美国以外的账户或 USD 以外的币种。
- 交易量很大的账户：0.1.0 版本只会检查 Authorize.net 尚未结算的最新 50 笔付款。如果收银台找到该笔付款前，账户中的其他付款（包括任何收银台和网上商店的付款）在贴卡后又到账 50 笔或更多，收银台就会漏掉该笔付款。
- 无法区分两台收银台：两台收银台在同一时刻收取相同金额时，都可能记录对方的付款。
