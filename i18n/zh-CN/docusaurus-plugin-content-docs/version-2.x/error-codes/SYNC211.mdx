## 含义 {#what-this-means}

店铺拒绝了发送给它的某个值。

店铺给出的原因会指明该值。请在输入该值的位置修正，然后重新保存。该值通常属于某条记录，例如商品、客户或订单；但此代码也可能来自店铺拒绝的设置或登录请求，这时请在相应页面上修正。

## 您的数据 {#your-data}

不要清除此设备的数据，其中可能存有店铺尚未收到的更改。对现有商品、变体、客户或优惠券的编辑被拒绝时，通常会自动撤销，并改为记录为 [SYNC202](/error-codes/SYNC202)。如果显示的是此代码，且更改列在 **店铺健康状况 → 数据库** 中，说明未能自动撤销，请按处理其他已列出更改的方法处理。设置或登录请求不会留下需要保存的内容。

## 故障排查 {#troubleshoot}

1. 展开日志条目，查看店铺给出的原因和端点。原因会指明该值，端点则说明它来自记录，还是设置或登录请求。
2. 在输入该值的位置修正，然后重新保存。常见原因包括值超出范围、格式不被接受或必填选项留空。如果 **店铺健康状况 → 数据库** 中未列出该更改，说明已恢复店铺版本，请使用正确的值重新修改。如果修正后，它仍列在 **店铺健康状况 → 数据库** 的 **“… 项更改未能传送到您的服务器”** 下，请点击该行的 **重新发送**。
3. 如果记录列在 **“… 项更改已暂缓”** 下，并显示 *“您的店铺要求使用最新版本”*，则并非值有误。请按照 [SYNC221](/error-codes/SYNC221) 的说明，在 **重新发送** 和 **丢弃设备更改** 之间作出选择。
4. 如果是设置或登录请求，请在输入该值的页面上修正并重新保存。**站点管理员：** 如果 POS 日志中没有详细信息，可通过浏览器的开发者工具（网络选项卡），或桌面应用中的 **高级 → 切换开发者工具**，查看店铺的响应。
5. **站点管理员：** 如果指出的值在 POS 中看起来正确，请与 WP Admin 中的同一条记录进行比较。店铺上由插件添加的验证规则，可能会拒绝 POS 认为有效的值。
