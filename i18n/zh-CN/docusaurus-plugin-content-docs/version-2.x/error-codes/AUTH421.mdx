## 含义 {#what-this-means}

店铺服务器阻止了应用通过所有可用通道传送登录令牌。

应用已确认店铺可以访问，但服务器（或其前面的防火墙、代理或安全插件）移除了 Authorization 请求头，同时也阻止了通过 URL 参数发送的令牌。由于没有第三种方式传送登录令牌，必须在服务器端解决此问题。

## 您的数据 {#your-data}

订单和商品数据均不受影响。

## 故障排查 {#troubleshoot}

**主机／服务器端操作** — 在服务器允许令牌通过之前，登录令牌没有可用的传送通道：

1. 允许 Authorization 请求头传递到 WordPress。在 Apache 上，通常只需一行配置：`SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1`。
2. 如果网站使用 `.htaccess` 重写，请保留 WordPress 生成的、用于传递 `HTTP_AUTHORIZATION` 的 RewriteRule 行，安全插件有时会将其移除。
3. 如果使用了代理或 CDN，请检查其请求头允许列表：必须将 Authorization 请求头转发至源站。
4. 如果 Web 应用防火墙（WAF）正在过滤 URL 参数，请允许 `/wcpos/` REST 路由上的 authorization 参数。
