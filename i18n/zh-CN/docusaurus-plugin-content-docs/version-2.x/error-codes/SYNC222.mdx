## 这意味着什么 {#what-this-means}

此设备保存了自己的版本，覆盖了店铺端较新的修改。

在 WP Admin 中检查日志条目列出的字段。如果店铺端的修改才是正确的，请在那里重新修改。

此问题发生在订单上。此设备上次下载订单后，有人在 WP Admin 中修改了该订单，或插件、付款通知自动修改了它。随后，此设备保存自己对订单的修改时，店铺报告了冲突。为避免耽误收银端的销售，WCPOS 再次发送此设备的版本以覆盖店铺端的版本，店铺接受了该版本。日志条目列出了此设备的值替换了店铺端不同值的所有字段。其中一些可能是此设备自身的修改，例如在收银端添加的订单行或设置的状态，而非店铺端的修改。

如果同一冲突连续发生两次，WCPOS 会暂缓发送该更改，并请您选择如何处理，参见 [SYNC221](/error-codes/SYNC221)。

## 您的数据 {#your-data}

订单已按此设备的版本保存在店铺中，收银端没有丢失任何内容。可能需要重新操作的是店铺端对所列字段作出的较新修改。日志列出的是被替换的字段，而非字段原来的值。如果条目说明仅显示了部分字段，则实际被替换的字段比列出的更多，请检查整个订单。

## 故障排除 {#troubleshoot}

1. 展开日志条目：其中注明了订单，并列出了此设备的值替换了店铺端值的字段。
2. 在 WP Admin 的 **WooCommerce → 订单** 中打开该订单，检查这些字段。订单备注可能会显示店铺端的修改由谁或什么程序作出。
3. 如果字段当前的值正确，例如这些值就是收银端作出的修改，则无需操作。
4. 如果店铺端的修改才是正确的，请在 WP Admin 中重新修改。收银端会在下次同步时获取该更改。
5. 如果此问题持续发生，说明有两处正在同时修改相同的订单，例如销售在收银端尚未完成时，有人在 WP Admin 中设置了订单状态，或有插件在订单创建后更新订单。请约定各类订单修改应在哪一端进行；网站管理员可以检查是哪个插件在修改订单。
