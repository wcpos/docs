## 含义 {#what-this-means}

店铺拒绝了此项更改，因此更改未能传送到店铺。

查看店铺给出的原因。如果 **店铺健康状况 → 数据库** 中列出了该更改，请修正记录并点击 **重新发送**，或将其 **丢弃**。如果未列出，说明已恢复店铺版本；如仍需要此更改，请重新修改（参见 [SYNC202](/error-codes/SYNC202)）。被拒绝的更改不会自动重试。

## 您的数据 {#your-data}

不要清除此设备的数据，其中可能存有店铺尚未收到的更改。列在 **店铺健康状况 → 数据库** 中的被拒更改会一直保留，直到您重新发送或丢弃。对现有商品、变体、客户或优惠券的编辑被拒绝时，通常会自动撤销，并改为记录为 [SYNC202](/error-codes/SYNC202)。如果显示的是此代码，且更改列在 **店铺健康状况 → 数据库** 中，说明未能自动撤销，请按下文处理其他已列出更改的方法处理。如果问题持续出现，请使用 **日志** 选项卡中的 **复制调试信息**，并联系 WCPOS 支持团队。

## 故障排查 {#troubleshoot}

1. 查看店铺给出的原因。日志条目中以及 **店铺健康状况 → 数据库** 中该更改所在的行都会显示原因。
2. 打开 **店铺健康状况 → 数据库**。如果其中未列出该更改，说明此设备已恢复店铺版本，没有内容需要发送，参见 [SYNC202](/error-codes/SYNC202)。解决原因中指出的问题后，如仍需要此更改，请重新修改。
3. 如果其中列出了该更改，无论是订单、在此设备上创建的记录，还是未能自动撤销的商品目录编辑，被拒绝的更改都会显示在 **“… 项更改未能传送到您的服务器”** 下，其所在行会显示店铺给出的原因。保留列表中的更改，直接在记录本身上修正原因中指出的问题，例如订单中的某个字段。
4. 返回 **店铺健康状况 → 数据库**，点击该行的 **重新发送**。此操作会根据设备上的当前内容重新构建更改并发送。
5. 如果不再需要此更改，请点击 **丢弃**，这样会保留店铺版本。请先阅读确认提示：对于店铺从未保存过的记录，丢弃会将其从此设备上删除。
6. **站点管理员：** 如果原因提示用户无权进行此更改，说明其角色没有执行该操作的权限，参见 [AUTH201](/error-codes/AUTH201)。如果原因提到了 POS 未显示的字段，请在 WP Admin 中打开同一条记录，其他插件可能添加了 POS 无法看到的验证规则。如果仍被拒绝，请使用 **日志** 选项卡中的 **复制调试信息**，并联系支持团队。
