## 含义 {#what-this-means}

店铺拒绝了此项更改，因此此设备已恢复为店铺版本。

更改未保存。请查看店铺给出的原因，解决其中指出的问题，然后重新修改。

编辑现有商品、变体、优惠券和客户时会出现这种情况。当店铺明确拒绝某项编辑，例如值无效或已登录用户无权进行该更改时，WCPOS 不会让被拒绝的编辑一直等待，而是会在此设备上恢复店铺版本，使收银终端使用与店铺一致的信息进行销售。日志条目会指明相关记录，并附上店铺给出的原因。

## 您的数据 {#your-data}

其他内容均未改变。店铺仍保留原有版本，未作更改，此设备也重新显示该版本。如果店铺已删除该记录，此设备也会将其移除。只有被拒绝的编辑已被撤销，请在解决问题后重新修改。销售和订单不受影响，而且您在被拒绝的编辑之后对同一记录所做的编辑会保留，并继续发送。

## 故障排查 {#troubleshoot}

1. 展开日志条目，查看店铺给出的原因，其中会说明店铺拒绝了什么内容以及它属于哪条记录。
2. 解决原因中指出的问题。如果涉及某个值，例如价格、SKU、电子邮箱地址，或留空的必填字段，请确定正确的值。如果原因提示用户无权进行此更改，说明该账号的角色没有执行该操作的权限，参见 [AUTH201](/error-codes/AUTH201)。
3. 打开记录（如果店铺已删除它，就没有可修改的内容），使用正确的值重新修改并保存。同步完成后，检查记录是否显示了您的更改。
4. 在此设备上新建但被店铺拒绝的记录不会还原，因为没有店铺版本可供恢复。它会一直列在 **店铺健康状况 → 数据库** 的 **“… 项更改未能传送到您的服务器”** 下，参见 [SYNC201](/error-codes/SYNC201)。
5. **站点管理员：** 如果原因提到了 POS 未显示的字段，请在 WP Admin 中打开同一条记录，其他插件可能添加了 POS 无法看到的验证规则。如果店铺持续拒绝此更改，请使用 **日志** 选项卡中的 **复制调试信息**，并联系支持团队。
