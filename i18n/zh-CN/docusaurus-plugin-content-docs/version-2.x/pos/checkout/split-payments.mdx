一个订单可以分多笔付款：部分用现金、余款刷卡，或由朋友分摊。整个过程始终是同一个订单，每笔付款都会列在订单上，直到全部付清。本页从收款面板开始介绍；[结账](./index.mdx)一页介绍了完整的销售流程。

- **先付一部分，余款用其他方式** — [收取部分款项](#part-payment)。
- **平均分摊，或先付指定金额** — [拆分订单付款](#split)。
- **每位顾客支付自己的商品** — [按商品付款](#by-item)。
- **某笔付款有误** — [取消单笔付款](#cancel-one)。

## 收取部分款项 {#part-payment}

如果顾客先付一部分、余款用其他方式支付，请点击本次使用的付款方式卡片，输入本次支付的金额，然后按 **收款**。无需事先设置：金额下方会显示 **部分付款 · 本次付款后还剩 …**。按 **收款** 后，金额会变为余款，准备收取下一笔：选择下一个付款方式卡片，收取余款即可。

<JourneyShot manifest={manifest} device="tablet" step={12} offsets={[[-42, 0], [-40, 0], [70, 0], [-4, 0], [0, 0], [-40, 0]]} alt="未开启拆分时的部分付款：在现金方式下输入 $50.00，显示部分付款、本次付款后还剩 $144.00，收款按钮标明余款，账单显示剩余 $194.00">

1. **$50.00** — 顾客本次支付的部分金额。
2. **部分付款 · 本次付款后还剩 $144.00** — 收取本笔款项后仍需支付的金额。
3. **拆分** — 收取部分款项时保持关闭。
4. **现金** — 顾客本次使用的付款方式卡片。
5. **收取现金 $50.00 · 还剩 $144.00** — 收取这部分款项。
6. **剩余** — 收取这部分款项前的订单未付金额。

</JourneyShot>

使用独立终端刷卡时，操作与整单付款相同：先在终端上收款，再在此处记录。已配对的读卡器会从收银设备接收金额；请参阅[使用读卡器](./taking-a-payment.mdx#card-reader)。读卡器仍在收款时，按 **✕** 会退出结账，但读卡器会继续处理，不会取消任何付款。

:::warning
收取一笔款项后，按 **✕** 不会暂存这笔销售，而会询问 **取消此笔付款？** 因为已收款项必须退还给顾客。按 **继续收款** 可留在当前页面。请参阅[顾客未付清余款就离开](#customer-leaves)。
:::

## 拆分订单付款 {#split}

按金额旁的 **拆分**。收款面板会显示一排余款拆分方式，旁边的账单则变为可选择商品的列表。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[70, 0], [56, -46], [90, -46], [56, -46], [40, -18], [0, 0]]} alt="开启拆分后的结账界面：拆分按钮、一排百分比及分为 2 笔至分为 6 笔的卡片（各自显示每笔金额）、账单上可选的商品，以及收款按钮">

1. **拆分** — 开启拆分付款。再次按下可关闭并取消拆分方案。
2. **分为 2 笔** — 分为两笔等额付款。每张卡片都标明每笔付款的金额。
3. **分为 3 笔** — 依此类推，最多 **分为 6 笔**。如果卡片无法全部显示，可横向滚动这一排。
4. **百分比** — 收取余款的一定比例。请参阅[按余款的百分比付款](#percent)。
5. **账单上的商品** — 点击即可为该商品付款。请参阅[按商品付款](#by-item)。
6. **收款** — 标明金额、付款方式和本笔付款的内容。

</JourneyShot>

每笔付款都可以使用不同的付款方式。如果订单金额无法均分，各份金额会四舍五入，最后一笔收取剩余金额，因此其中一笔可能与其他笔相差一分。收取整单款项的支付网关无法收取部分款项；请参阅[支付网关不可用](#greyed-gateway)。

点击一张卡片，然后[逐笔收款](#take-each)。

### 先付指定金额 {#amount}

选择卡片前，先在数字键盘上输入首笔付款金额。这一排随后会显示 **本次付款后 · …**，每张卡片按本次付款后的余款进行分摊。点击其中一张：先收取输入的金额，再将余款分为所选笔数的等额付款。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[-30, 0], [154, -50], [0, 0]]} alt="开启拆分并输入 $50.00 后的局部视图：金额、标题变为本次付款后并显示余款的拆分方式行，以及标明后续每笔金额的分为 2 笔卡片">

1. **金额** — 首笔付款的金额。
2. **本次付款后 · …** — 收取本笔款项后待分摊的余款。
3. **分为 2 笔** — 首笔付款后，将余款分为两笔等额付款。

</JourneyShot>

如果只想收取输入的金额、不设拆分方案，请按 **收款**，而不要点击卡片。若选择了卡片，则依次[逐笔收款](#take-each)。

### 按余款的百分比付款 {#percent}

点击 **百分比**，再点击 **10 %**、**20 %**、**25 %** 或 **50 %**，也可点击 **输入** 自行输入比例。金额会变为余款中该比例对应的数额。将其作为一笔收取后，再拆分或收取余款。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[18, 30], [70, 0], [-30, 0], [-32, 0]]} alt="按余款百分比付款的局部视图：10、20、25 和 50 百分比按钮及输入按钮，已选择 25 %，并显示计算出的金额">

1. **25 %** — 余款的四分之一。
2. **输入** — 在数字键盘上输入其他比例。
3. **金额** — 为您计算出的本次应付金额。
4. **比例** — 百分比及其计算基数。

</JourneyShot>

按 **收款** 后，点击卡片拆分余款并[逐笔收款](#take-each)，或一次收取全部余款。

## 逐笔收款 {#take-each}

选择拆分方式后，收款面板会引导您逐笔收款，并自动填入下一笔金额。每笔付款都选择顾客使用的付款方式卡片，再按 **收款**。使用读卡器时，按钮显示 **发送 … 至 …**，读卡器会收取该部分款项。

此处第一位顾客已为自己的手表支付 $45.00（请参阅[按商品付款](#by-item)），余款分为三笔。

<JourneyShot manifest={manifest} device="tablet" step={6} offsets={[[-36, 0], [-26, 0], [33, -32], [33, -32], [33, -32], [110, 0], [0, 0]]} alt="首笔付款后将余款分为三笔：第 2 笔／共 4 笔及余款、已收款项、带边框的当前付款和两笔灰显的后续付款、更改拆分按钮，以及标明付款序号的收款按钮">

1. **第 2 笔／共 4 笔 · 还剩 …** — 当前是第几笔付款，以及仍需支付的金额。首笔付款也计入总笔数，因此之后再分三笔，总共就是四笔。
2. **现金 $45.00**，带勾选标记 — 已收取的款项。
3. **当前付款**，带边框 — 金额已自动填入。
4. **下一笔付款**，灰显。
5. **最后一笔付款**，灰显 — 此处少一分，因为余款无法均分。
6. **更改拆分** — 返回拆分方式行，重新拆分余款。
7. **收款** — 标明金额、付款方式，以及当前是第几笔付款。

</JourneyShot>

### 顾客交付的现金多于应付份额时 {#cash-over}

使用现金的顾客可以交付超过自己应付份额的金额。接下来的两张图中，同一个 $194.00 订单从一开始就分为三笔，第一位顾客为 $64.67 的份额交付了 $100.00。在数字键盘上输入实收现金：找零会以大号数字显示，而 **收款** 仅记录该顾客应付的份额。

<JourneyShot manifest={manifest} device="tablet" step={7} offsets={[[-46, 0], [-40, 0], [0, 0]]} alt="拆分付款中收到 $100.00 现金：顶部突出显示应找零金额，下方显示实收金额，以及收取本次份额的收款按钮">

1. **找零** — 应找给顾客的金额。
2. **实收** — 顾客交付的金额。
3. **收款** — 记录计划中的应付份额，而非实际交付的现金金额。

</JourneyShot>

最后一笔付款的按钮与其他付款一样，显示 **第 … 笔／共 … 笔**，此处为 **第 3 笔／共 3 笔**。收取后，销售完成，收据也已就绪，与其他销售相同。请参阅[查看付款完成界面](./index.mdx#paid)。

:::warning
付款完成界面显示的找零已在对应付款时交给顾客。请勿重复找零。
:::

<JourneyShot manifest={manifest} device="tablet" step={11} offsets={[[-22, 0], [-32, 0]]} alt="三笔现金付款后的付款完成界面局部视图：顶部突出显示找零 $35.33，下方显示已付 $194.00、实收现金 $229.33、3 笔付款">

1. **找零 $35.33** — 再次显示第一位顾客交付 $100.00 时产生的找零。如果整笔销售无需找零，此处会显示 **已付** 和订单总额。
2. **已付 … · 实收现金 … · 3 笔付款** — 订单总额、全部实收现金和付款笔数。使用多种方式付款时，每种方式只列出一次，例如 **现金 + 银行卡**。

</JourneyShot>

按 **新销售**，为下一位顾客打开空购物车。

## 按商品付款 {#by-item}

每位顾客各自支付所购商品时，可直接在账单上选择。开启 **拆分** 后，点击商品名称，即可为该商品所有未付款数量付款。使用 **−** 和 **+** 调整该行本次付款的数量，例如两杯咖啡中的一杯。然后选择付款方式并按 **收款**。

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[40, -18], [-40, 34], [42, 40], [33, -32], [43, -32], [0, 0]]} alt="按商品付款：在账单上的两块 Aim Analog Watch 中选中一块，带数量调节按钮的本次付款列、数字键盘上方的已选商品名称、分摊、+ 金额和收款按钮">

1. **商品** — 点击名称，为该商品所有剩余未付款数量付款。
2. **1／共 2 件** — 本笔付款涵盖该行的商品数量。使用 **−** 和 **+** 可调整。
3. **1 Aim Analog Watch** — 本笔付款涵盖的商品。点击其上的 **✕** 可移除该商品。
4. **分摊** — 将所选商品分为两笔、三笔或四笔等额付款，例如分摊一瓶饮品。
5. **+ 金额** — 在所选商品金额之外，加上手动输入的金额。
6. **收款** — 标明商品总额、付款方式和本次付款后的余款。

</JourneyShot>

手机屏幕无法在数字键盘旁显示账单。按 **选择商品** 显示列表，选好商品后按 **返回数字键盘**。

按 **收款** 后，以同样方式选择下一位顾客的商品，或拆分余款并[逐笔收款](#take-each)。

### 已付款的商品 {#paid-items}

某笔付款支付了商品后，账单会标明该商品已付款的数量和付款方式。已付款的商品数量不能再次选择，因此下一位顾客只能看到剩余数量。这些标记会保存在订单上，即使稍后或在另一台收银设备上重新打开订单，标记仍然保留。

<JourneyShot manifest={manifest} device="tablet" step={13} offsets={[[45, 0], [7, -31], [47, 0]]} alt="两块手表中的一块用现金支付后的账单局部视图：手表行标记为已付 1／共 2 件、现金，数量调节器显示 0／共 1 件">

1. **已付 1／共 2 件 · 现金** — 已付款的数量及付款方式。
2. **0／共 1 件** — 该商品剩余可选的数量；已付款的手表无法再次选择。
3. **Aim Analog Watch** — 点击名称，选择该商品剩余未付款的数量。

</JourneyShot>

收款面板会进入下一笔付款：

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[0, 0], [-36, 0], [-36, 0], [166, 0], [90, -42], [-34, 0]]} alt="首笔付款后：账单上两块手表中的一块标记为已用现金支付，数字键盘上方显示已收款项、第 2 笔及余款，旧版选项卡标记为仅限整单">

1. **已付 1／共 2 件 · 现金** — 该商品已付款的数量及付款方式。
2. **现金 $45.00**，带勾选标记 — 已收取的款项。点击可查看或取消。请参阅[取消单笔付款](#cancel-one)。
3. **第 2 笔 · 还剩 …** — 当前是第几笔付款，以及仍需支付的金额。
4. **仅限整单** — 旧版选项卡（WCPOS Pro）无法收取部分款项。请参阅[旧版选项卡](./legacy-tab.mdx)。
5. **分为 3 笔** — 与之前一样，拆分余款。
6. **部分已付 · 待付 …** — 尚未付清时，未结订单中的订单选项卡会显示此标记。请参阅[未结订单](../cart/open-orders.mdx)。

</JourneyShot>

## 取消单笔付款 {#cancel-one}

如果某笔付款有误，例如付款方式或金额不对，可只取消这一笔并保留其他付款。点击数字键盘上方带勾选标记的付款，即可列出所有已收款项及每笔付款支付的商品。

<JourneyShot manifest={manifest} device="tablet" step={8} offsets={[[-6, 0], [-6, 0], [-38, 0], [-28, 0], [-36, 0]]} alt="订单的已收款项列表：每笔列出付款方式、金额和商品，各有一个取消付款按钮，另有隐藏按钮">

1. **首笔付款** — 付款方式、金额及其支付的商品。
2. **最后一笔付款** — 每笔付款各占一行。
3. 行内的 **取消付款** — 仅取消该笔付款。
4. **隐藏** — 关闭列表。
5. 顶部的 **取消付款** — 取消所有已收款项，而非仅一笔。请参阅[取消付款](./cancelling-a-payment.mdx)。

</JourneyShot>

在有误的付款所在行按 **取消付款**。POS 会先询问：

<JourneyShot manifest={manifest} device="tablet" step={9} offsets={[[70, 44], [40, 44]]} alt="取消此笔付款？对话框要求向顾客退还 $49.67 现金，并提供取消和取消付款按钮">

1. **取消付款** — 取消该笔付款。如果是现金，请将钱退还给顾客。
2. **取消** — 保留该笔付款。

</JourneyShot>

现金付款的对话框会显示 **向顾客退还 … 现金**。其他付款方式请参阅“取消付款”一页中的[取消单笔付款](./cancelling-a-payment.mdx#cancel-one)。取消后，订单会将该笔付款列为 **已取消**，清除其商品的已付款标记，并将余款重新分摊到后续付款中。

如果要取消所有已收款项，让销售恢复为未付款状态，请按结账页面顶部的 **取消付款**。系统会列出需要退还给顾客的款项，然后由您按 **取消并作废** 确认。请参阅[取消付款](./cancelling-a-payment.mdx)。

## 遇到问题时 {#goes-wrong}

### 少于计划金额 {#less-than-planned}

如果顾客交付的金额少于计划付款金额，金额下方会显示 **少于计划金额 · … 转入下一笔付款**，或提示转入后续多笔付款。收取后，不足的金额会由尚未收取的付款分摊。

### 顾客想更改拆分方式 {#split-differently}

按 **更改拆分**，为余款选择新的拆分方式。已收款项保持不变。要取消拆分方案，按 **拆分** 将其关闭。

### 顾客未付清余款就离开 {#customer-leaves}

已收款项会保留在订单上。如果需要先服务下一位顾客，请按未结订单末尾的 **+**：系统会开始一笔新销售，原订单的选项卡仍然保留，并标记为 **部分已付 · 待付 …**。顾客回来后，点击该选项卡，结账界面会再次打开并显示余款，已付款商品的标记仍然保留。请参阅[未结订单](../cart/open-orders.mdx)。

### 支付网关不可用 {#greyed-gateway}

收取整单款项的支付网关（例如[邮件发票](../../payment/gateways/email-invoice.mdx)）无法收取部分款项。收取一笔付款后，该方式会从卡片中移除，列在 **… 当前不可用** 下。展开这一行可查看原因：**仅收取整单款项，已有付款后无法使用**。[旧版选项卡](./legacy-tab.mdx)（WCPOS Pro）也会因同样的原因显示 **仅限整单**。请使用其他卡片收取余款，或[取消已收款项](./cancelling-a-payment.mdx)后再使用这些方式。
