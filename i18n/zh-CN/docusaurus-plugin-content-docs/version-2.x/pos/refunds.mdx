:::info Pro 功能
从 POS 退款需要 [WCPOS Pro](../getting-started/pro-license.mdx)。没有 Pro 时，**订单** 页面仅供预览：请在 WP Admin 的 **WooCommerce → 订单** 中为订单退款。
:::

顾客带着商品前来退货。本页演示一次收银台退款操作：从一笔以现金购买两块手表和一个背包的订单中，退回一块手表。退款针对顾客付款时的订单进行，因此应从 **订单** 开始，而不是从购物车开始。

## 打开订单 {#open-order}

从菜单中打开 **订单**，搜索订单号或顾客。点击订单所在行即可打开；使用鼠标时，点击该行末尾的箭头。

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[347, 0], [30, -26], [28, -26]]} alt="从订单页面打开的订单：日期、店铺和收银员信息行、商品、总额和现金付款，以及底部的收据和退款按钮">

1. **订单详情** — 付款时间、所在店铺及经手的收银员。
2. **收据** — 原始收据，可用来核对购买的商品。请参阅[收据](../receipts/index.mdx)。
3. **退款** — 打开退款表单。

</JourneyShot>

开始前，请检查 **商品** 和 **付款**：它们显示顾客购买了什么以及如何付款。现金销售以现金退款；请参阅[选择退款去向](#destination)。

只有订单状态为 **已完成**、**处理中** 或 **保留**，且已传到店铺时，才会显示 **退款**。仍在等待同步的订单暂时没有 **退款** 按钮。

## 选择退款项目 {#choose}

点击 **退款**。退款表单会列出订单的所有项目。点击某一行的 **退款数量**，输入退回数量，然后点击 **完成**。该行的退款金额包含税费。

本次退货中，将手表的 **退款数量** 设为 **1**，背包保持为 **0**，并检查 **退款总额** 是否显示 **$45.00**。要退整笔订单，请将每一行都设为该行的全部数量。

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[350, 98], [497, 97], [0, 0], [497, 87], [57, -40]]} alt="退款表单，其中两块手表中的一块被设为退款：订单总额、退款数量、该行退款金额、自定义金额、原因以及处理退款">

1. **退款数量** — 该行退回的数量。旁边的 **数量** 表示仍可退款的数量，之前已退款的商品已从中扣除。
2. **退款金额** — 该行的含税退款金额。
3. **自定义金额** — 不对应具体项目的退款金额，例如价格调整。此金额会加到各行退款金额之上。
4. **原因** — 可选。它会随退款一起保存，并显示在订单上。
5. **处理退款** — 底部的 **退款总额** 大于零后才会启用；超过剩余可退金额时也会变灰。

</JourneyShot>

如果订单之前已有退款，**总计** 下方的 **此前已退款** 行会显示已退金额。

## 选择退款去向 {#destination}

现金销售无需选择：退款会记录为从钱箱退还的现金，如本指南的示例所示。

<details>
<summary>为其他付款方式的销售退款</summary>

如果订单通过其他方式付款，表单会在 **原因** 和 **退款总额** 之间增加 **退款去向**：

- **退回至 *（付款方式）*** — 通过顾客原先使用的付款方式退回款项。如果该付款方式支持从 WCPOS 退款，这就是默认选项。若不支持，此选项会变灰，并显示“此订单不支持原付款方式退款。”
- **通过现金退款** — 您从钱箱取出现金退还给顾客，WCPOS 仅记录退款，不会联系原付款方式。

</details>

## 确认退款 {#confirm}

退款需要网络连接，不能像销售一样离线等待。点击 **处理退款**。WCPOS 会要求您确认金额和订单号。

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[132, 0]]} alt="确认退款对话框，询问是否为该订单退还相应金额，并提供处理退款按钮">

1. **处理退款** — 将退款请求发送至店铺。

</JourneyShot>

店铺接受退款后，会显示“*（金额）* 的退款已处理”，随后返回订单。如果是现金退款，现在请将相应金额交还顾客。

:::warning 不确定退款是否成功？
如果 WCPOS 提示“WCPOS 无法确认此次退款是否成功”，请勿立即再次点击 **退款**。先检查订单上的 **退款记录**：再次尝试可能会向顾客重复退款。如果订单尚未更新，请先在 WP Admin 中检查，再重试。请参阅 [PAYMENT311](../error-codes/PAYMENT311.mdx)。
:::

## 在订单上检查退款 {#check}

WCPOS 从店铺刷新订单后，就会显示已退款的内容。部分退款会将其标记为 **部分退款**，**付款** 中会增加一行 **退款**，显示扣除的金额。全部退款后，WooCommerce 会将订单状态设为 **已退款**。

向下滚动到 **退款记录**。每笔退款都有独立卡片，显示金额、操作人员和时间、原因以及退款涵盖的项目。卡片上的 **收据** 可打开该笔退款的退款收据，以便打印或发送。

## 现金退款与钱箱 {#drawer}

如果现金退款时收银机已开班，钱箱的应有金额会相应减少。[收银员面板](./register/index.mdx#cashier-sheet)上的 **钱箱金额** 会扣减该金额，收银机面板中会将其列为 **现金退款**。当您[盘点并结班](./register/index.mdx#close)时，退还的现金已计算在内。请参阅[对账](../reports/reconciliation.mdx)。

退款不要求收银机必须已开班。如果收银机已结班，退款不会减少其应有现金。如果您要从钱箱取出现金退款，请先[为收银机开班](./register/index.mdx#open)。

## 遇到问题时 {#goes-wrong}

<details>
<summary>没有退款按钮</summary>

订单状态不是 **已完成**、**处理中** 或 **保留**，或者订单尚未传到店铺。如果订单状态已在 WP Admin 中更改，请点击订单上的 **同步**，然后重新打开订单。尚未传到店铺的订单在发送完成前不会显示 **同步** 或 **退款** 按钮：请检查网络连接，再重新打开订单。

</details>

<details>
<summary>“……未进行退款”</summary>

没有发生退款。请解决提示中指出的问题，然后重试：

- **“您处于离线状态，因此未进行退款。”** 请先重新连接网络。
- **“未进行退款 — 请登录后重试。”** 您的登录已过期。请先登录。
- **“WCPOS 处于后台，因此未进行退款。”** 退款完成前，应用被切换到了后台。现在请重试。

</details>

<details>
<summary>店铺拒绝了退款</summary>

您会看到店铺返回的提示，或“处理退款失败”。没有发生退款。请阅读提示，解决其中指出的问题，然后重试。

</details>

<details>
<summary>不确定退款是否成功</summary>

“WCPOS 无法确认此次退款是否成功”表示退款请求已发送，但未收到响应。重试前请打开订单并检查 **退款记录**：再次尝试可能会向顾客重复退款。请参阅 [PAYMENT311](../error-codes/PAYMENT311.mdx)。

</details>

<details>
<summary>订单仍未显示退款</summary>

{/* pending: docs#670 */}
如果出现过“*（金额）* 的退款已处理”，说明店铺已向 POS 返回响应，通常意味着退款已完成，只是 POS 上的订单尚未更新。在 WP Admin 中检查订单之前，请勿再次退款：再次尝试可能会向顾客重复退款。

</details>

<details>
<summary>无法退回原付款方式</summary>

- **退回至 *（付款方式）* 已变灰。** 该付款方式不支持从 WCPOS 退款。请通过现金退款，或在 WP Admin 或支付服务商自己的管理后台中为订单退款。
- **“无法验证原付款方式退款功能。仍可通过现金退款。”** WCPOS 无法检查该付款方式是否支持退款。请通过现金退款，或稍后再退。

</details>
