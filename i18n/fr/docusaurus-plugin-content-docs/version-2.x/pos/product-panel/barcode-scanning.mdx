Scannez un code-barres et le produit est ajouté directement au panier. Presque tous les scanners fonctionnent sans configuration, car ils saisissent le code comme un clavier très rapide : WCPOS distingue une lecture d’une saisie grâce à cette vitesse. Vous n’avez pas de scanner ? Utilisez la [caméra](#camera-scanning).

## Scanner un produit {#scan}

Vous utilisez la caméra ? Ouvrez la caisse si votre boutique en utilise une, puis suivez [Scanner avec la caméra](#camera-scanning). Avec un scanner :

1. Appairez ou branchez votre scanner ([Connecter un scanner](#connection-modes)).
2. Si votre boutique utilise des caisses, [ouvrez d’abord la caisse](../register/index.mdx#open) : tant qu’elle est fermée, aucun produit ne peut être ajouté au panier.
3. Placez le curseur à l’endroit requis par votre appareil :
   - **Navigateur web ou application de bureau :** cliquez ou appuyez en dehors de tout champ de texte.
   - **Application WCPOS sur iPad, iPhone ou Android :** appuyez sur **Rechercher des produits**. {/* pending: monorepo#3368 */}
4. Scannez.

<Accordion>
  <AccordionItem question="Pourquoi la position du curseur compte">

Un scanner en mode clavier saisit le code comme le ferait un clavier.

Dans un navigateur web ou l’application de bureau, une zone vide de l’écran convient, quel que soit l’appareil. Tant que le curseur se trouve dans un champ de texte, y compris le champ de recherche, WCPOS y laisse les caractères comme une saisie normale.

Dans l’application WCPOS, les caractères du scanner arrivent dans **Rechercher des produits**. Un scanner que vous avez [enregistré sur Android](#android) fonctionne quelle que soit la position du curseur.

  </AccordionItem>
</Accordion>

[Rien ne se passe ou le code apparaît comme du texte saisi ?](#goes-wrong)

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[0, 0], [165, 0], [205, 0]]} alt="Une lecture a ajouté une veste au panier : le message Ajouté au panier, un champ de recherche vide et la nouvelle ligne dans le panier">

1. **Ajouté au panier** — s’affiche brièvement avec le nom du produit ajouté, pour vous éviter de regarder le panier. Pour une variation, le nom correspond à ses options, ici **XS, Gris**.
2. **Rechercher** — de nouveau vide après la lecture, sur tous les appareils, prêt pour la suivante.
3. **La nouvelle ligne** — la taille et la couleur scannées. Scannez à nouveau le même code pour ajouter un autre exemplaire.

</JourneyShot>

Dans un navigateur ou l’application de bureau, vous pouvez scanner partout dans le PDV, y compris dans le panier et sur l’écran de paiement.

Un code plus court que la **Longueur minimale du code-barres** (8 par défaut) ne peut pas être ajouté ; voir [Paramètres de détection](#configuring-barcode-scanning).

:::note
Pendant le [comptage du tiroir-caisse](../register/index.mdx#close), les lectures sont refusées jusqu’à la fin du comptage.
:::

Sur les écrans **Produits** et **Commandes**, le code scanné est placé dans le champ de recherche de l’écran : vous pouvez ainsi scanner un produit pour le retrouver ou retrouver ses commandes.

### Ce que WCPOS recherche {#what-matches}

WCPOS recherche d’abord sur cet appareil un produit ou une variation dont le code-barres correspond. S’il n’en trouve aucun, il interroge votre boutique (**Recherche dans la boutique…**). Lorsque votre boutique trouve le produit, WCPOS l’ajoute au panier. Le champ utilisé comme code-barres se définit dans [Champ du code-barres](../../settings/wp-admin/general.mdx#barcode-field).

<Accordion>
  <AccordionItem question="Codes SKU, GTIN, UPC, EAN et ISBN">

Outre le [Champ du code-barres](../../settings/wp-admin/general.mdx#barcode-field), le SKU d’un produit et son champ GTIN, UPC, EAN ou ISBN fonctionnent toujours aussi, sur cet appareil comme dans votre boutique.

  </AccordionItem>
  <AccordionItem question="Codes-barres à 12 et 13 chiffres">

Un code UPC-A à 12 chiffres correspond à sa forme EAN à 13 chiffres, et inversement. Un emballage portant 12 chiffres permet donc de retrouver un produit enregistré avec le zéro initial.

  </AccordionItem>
  <AccordionItem question="Un produit trouvé dans votre boutique">

Un produit trouvé dans votre boutique est téléchargé sur cet appareil avant d’être ajouté : la lecture suivante n’a donc plus besoin d’interroger la boutique. Un nouvel appareil récupère le reste de votre catalogue automatiquement ; voir [Synchronisation des produits](../../products/sync.mdx).

  </AccordionItem>
</Accordion>

## Les messages à l’écran {#messages}

Lorsqu’une lecture ne permet pas d’ajouter exactement un produit, un message en haut de l’écran vous en indique la raison et reste affiché pendant six secondes.

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[0, 0], [0, 0]]} alt="Lecture d’un code inconnu : le message Code-barres introuvable, le code conservé dans le champ de recherche et une liste de produits vide">

1. **Code-barres introuvable** — accompagné du code lu : absent de cette boutique, en local comme en ligne.
2. **Le code** — conservé dans le champ de recherche pour que vous puissiez vérifier ce que le scanner a lu. La liste reste vide tant que vous ne l’effacez pas avec la croix à droite du champ.

</JourneyShot>

Si le code reste dans **Rechercher des produits**, effacez-le avec la croix à droite du champ pour revoir vos produits. Pour savoir quoi faire, ouvrez la rubrique ci-dessous qui correspond au message affiché :

<Accordion>
  <AccordionItem question="Code-barres introuvable">

Aucun produit sur cet appareil ou dans votre boutique ne porte ce code. Comparez le code du champ de recherche avec celui du produit. S’il est correct, ajoutez le code-barres au produit dans WooCommerce.

  </AccordionItem>
  <AccordionItem question="Plusieurs correspondances">

Plusieurs produits portent ce code, qui reste dans le champ de recherche. Sélectionnez le bon produit parmi les résultats, puis attribuez un code-barres distinct à chaque produit.

  </AccordionItem>
  <AccordionItem question="Choisir une variation">

Le code appartient à un produit variable et non à l’une de ses options ; il reste dans le champ de recherche. Sélectionnez l’option dans les résultats. Attribuez un code-barres distinct à chaque variation pour l’ajouter directement en la scannant.

  </AccordionItem>
  <AccordionItem question="… en rupture de stock">

Le produit a été trouvé, mais il n’est plus en stock. Il est refusé tant que **Afficher les produits en rupture de stock** est désactivé ; voir [Paramètres d’affichage](display-settings.mdx#show-out-of-stock-products).

  </AccordionItem>
  <AccordionItem question="Lecture indisponible">

*Absent de cet appareil, et la recherche dans la boutique est impossible hors ligne* : la boutique est injoignable et le code reste dans le champ de recherche. Appuyez sur **Voir l’état** pour consulter [État de la boutique](../../support/store-health.mdx#database), puis scannez à nouveau une fois la connexion rétablie.

*Base de données locale indisponible* : le PDV ne peut pas lire sa propre base de données. Rechargez l’application avant d’effectuer d’autres ventes.

  </AccordionItem>
  <AccordionItem question="Échec de la recherche">

Votre boutique n’a pas répondu dans les dix secondes ou a renvoyé une erreur. Le code reste dans le champ de recherche. Vérifiez votre connexion, puis scannez à nouveau.

  </AccordionItem>
  <AccordionItem question="Impossible d’ajouter au panier">

Le produit a été trouvé, mais son ajout a échoué. Scannez à nouveau ou appuyez sur le produit.

  </AccordionItem>
</Accordion>

## Scanner avec la caméra {#camera-scanning}

Si votre appareil possède une caméra, vous pouvez l’utiliser pour scanner, sans scanner séparé. Appuyez sur le bouton de lecture à côté du champ de recherche. La caméra s’ouvre dans un panneau sous les filtres, pour que la liste des produits reste visible.

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[0, 0], [0, 0]]} alt="Le panneau de la caméra sous la barre de filtres, demandant l’accès à la caméra avec un bouton Autoriser la caméra">

1. **Scanner** — ouvre le panneau de la caméra. Appuyez à nouveau pour le fermer.
2. **Autoriser la caméra** — la première fois, WCPOS demande l’accès à la caméra. Appuyez sur ce bouton, puis autorisez l’accès dans la fenêtre qui suit.

</JourneyShot>

Présentez un code-barres devant la caméra. Lorsqu’il est lu, le bord du panneau clignote en vert et la lecture est traitée exactement comme celle d’un scanner, avec les mêmes [messages](#messages). Le produit n’est ajouté qu’une fois, quelle que soit la durée pendant laquelle vous maintenez le code devant la caméra. Pour en ajouter un autre, retirez-le du champ un instant, puis présentez-le à nouveau.

Si la caméra ne peut pas démarrer, la ligne d’état du panneau en indique la raison. Ici, aucune caméra utilisable n’a été trouvée :

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[454, 0], [234, 0], [0, 0]]} maxWidth={589} alt="Gros plan du panneau de la caméra, avec le message Caméra indisponible — vérifiez qu’aucune autre application ne l’utilise">

1. **État** — ce que fait la caméra, en bas de la vue de la caméra. Une fois la caméra démarrée, la zone noire au-dessus affiche son image.
2. **Redimensionner** — faites glisser pour augmenter ou réduire la hauteur de la vue de la caméra. WCPOS mémorise la hauteur sur cet appareil.
3. **Fermer** — ferme le panneau.

</JourneyShot>

Pour savoir quoi faire, ouvrez la rubrique ci-dessous qui correspond à l’état affiché dans le panneau :

<Accordion>
  <AccordionItem question="Démarrage de la caméra…">

Patientez un instant.

  </AccordionItem>
  <AccordionItem question="WCPOS a besoin d’accéder à la caméra pour scanner les codes-barres.">

Appuyez sur **Autoriser la caméra**. Si vous avez déjà refusé, la demande peut ne plus apparaître : autorisez la caméra pour WCPOS dans les paramètres du site de votre navigateur ou dans les paramètres de votre appareil, puis rouvrez le panneau.

  </AccordionItem>
  <AccordionItem question="Caméra indisponible — vérifiez qu’aucune autre application ne l’utilise.">

Fermez l’autre application ou l’onglet qui utilise la caméra, ou vérifiez qu’une caméra est connectée.

  </AccordionItem>
  <AccordionItem question="Le décodage des codes-barres échoue — fermez le scanner et réessayez.">

Fermez le panneau avec **Fermer**, puis rouvrez-le avec le bouton de lecture.

  </AccordionItem>
</Accordion>

Une note sous l’état vous avertit lorsqu’une lecture risque de ne pas tout trouver :

- **Hors ligne — seuls les produits déjà présents sur cet appareil peuvent être scannés.** Les autres produits pourront être scannés une fois la connexion rétablie.
- **La synchronisation est encore en cours de démarrage — certains produits peuvent être introuvables pour le moment.** Patientez un instant, puis scannez à nouveau. Si la note reste affichée, consultez [État de la boutique](../../support/store-health.mdx#database).
- **Base de données locale indisponible — rechargez l’application pour rétablir la lecture.** Rechargez l’application, puis scannez à nouveau.

## Sons de lecture {#sounds}

Un son à chaque lecture vous permet de garder les yeux sur le client. Activez **Émettre un son à la lecture** dans **Paramètres** → **Lecture des codes-barres**, sous **Son**. Cette option est désactivée par défaut et enregistrée uniquement sur cet appareil : chaque caisse peut donc avoir son propre réglage.

<Accordion>
  <AccordionItem question="Choisir et tester les sons de lecture">

<JourneyShot manifest={manifest} device="tablet" step={6} offsets={[[0, 0], [0, 0], [0, 0]]} maxWidth={726} alt="La section Son des paramètres de lecture des codes-barres avec Émettre un son à la lecture activé : trois thèmes sonores avec des boutons d’écoute, Volume, Son de réussite et Son d’échec">

1. **▶** — joue le son de réussite d’un thème.
2. **▶✕** — joue son son d’échec.
3. **Volume ▶** — joue le son de réussite au volume que vous avez réglé.

</JourneyShot>

- **Émettre un son à la lecture** — l’interrupteur en haut. Il active les sons et affiche les options en dessous.
- **Thème sonore** — **Classique** (bip clair ascendant / bourdonnement grave), **Caisse** (bip uniforme de supermarché / double tonalité grave) ou **Doux** (carillon léger / coup feutré, pour les boutiques calmes).
- **Volume** — faites glisser le curseur.
- **Son de réussite** — se joue lorsqu’un produit est ajouté au panier.
- **Son d’échec** — se joue pour tous les autres messages de la section [Les messages à l’écran](#messages). **Recherche dans la boutique…** reste silencieux.
- **Vibration en cas d’échec** — uniquement sur iPhone, iPad et Android. L’appareil vibre en cas d’échec, avec le son d’échec ou seul si **Son d’échec** est désactivé. L’option **Émettre un son à la lecture** doit être activée.

</AccordionItem>
</Accordion>

## Paramètres de détection {#configuring-barcode-scanning}

La section **Lecture** du même écran détermine ce qui est considéré comme une lecture de code-barres. La plupart des boutiques ne la modifient jamais. Si les lectures apparaissent comme du texte saisi ou si les codes courts sont refusés, lancez le **Test de lecture des codes-barres** à cet endroit : il mesure la vitesse de votre scanner et suggère des valeurs. Voir [Paramètres des codes-barres](../../settings/store/barcode.mdx).

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[195, 0], [195, 0], [194, 0], [194, 0]]} alt="Paramètres, Lecture des codes-barres : la section Lecture avec le seuil à 24, la longueur minimale à 8 et le préfixe et le suffixe vides, au-dessus des sections Son, Scanner et Test de lecture des codes-barres">

1. **Seuil de temps moyen de saisie du code-barres (ms)** — la vitesse à laquelle les caractères doivent arriver pour être considérés comme une lecture.
2. **Longueur minimale du code-barres** — les codes plus courts ne sont jamais ajoutés.
3. **Préfixe du scanner de codes-barres** — un caractère unique que votre scanner ajoute avant le code, retiré avant la recherche. Laissez ce champ vide, sauf si votre scanner est configuré pour en ajouter un.
4. **Suffixe du scanner de codes-barres** — la même chose pour un caractère unique ajouté après le code.

</JourneyShot>

<Accordion>
  <AccordionItem question="Rôle de chaque paramètre de détection">

| Paramètre | Fonction | Valeur par défaut |
|---|---|---|
| **Seuil de temps moyen de saisie du code-barres (ms)** | Lorsque l’intervalle moyen entre les caractères est inférieur à ce seuil, les caractères sont considérés comme une lecture. Les caractères plus lents sont traités comme de la saisie. | 24 |
| **Longueur minimale du code-barres** | Les codes plus courts ne sont jamais ajoutés. Réglez-la sur la longueur de votre code-barres le plus court. | 8 |
| **Préfixe du scanner de codes-barres** | Un caractère que votre scanner ajoute avant le code, retiré avant la recherche. | Vide |
| **Suffixe du scanner de codes-barres** | Un caractère que votre scanner ajoute après le code, retiré avant la recherche. | Vide |

**Un code plus court que la Longueur minimale du code-barres :** s’il ressemble à une lecture, uniquement composé de chiffres ou se terminant par Entrée, WCPOS affiche **Code-barres scanné** avec **Le code-barres doit comporter au moins 8 caractères**, au maximum une fois toutes les 30 secondes. Une courte séquence de lettres est considérée comme une saisie rapide et n’est pas interceptée.

  </AccordionItem>
</Accordion>

## Connecter un scanner {#connection-modes}

Presque tous les scanners sont livrés en mode clavier et, dans ce mode, aucune configuration n’est nécessaire : appairez ou branchez le scanner, puis scannez. Cela convient à la plupart des boutiques. Pour être guidé dans la configuration ou le dépannage, utilisez l’[Assistant de configuration du scanner](../../hardware/scanners/setup-wizard.mdx).

Une connexion directe peut être utile si les lectures contiennent des caractères erronés, par exemple des majuscules et des symboles confondus à cause d’une disposition de clavier, ou si vous devez scanner alors que le curseur se trouve dans un champ de texte.

<Accordion>
  <AccordionItem question="Connecter un scanner directement (avancé)">

Un scanner connecté directement est reconnu par son identité matérielle, et non par la vitesse de saisie, la disposition du clavier ou le champ actif. Chaque scanner de codes-barres est livré dans l’un des quelques modes disponibles, et ce mode détermine comment WCPOS reçoit ses lectures :

| Mode | Réception des données | Configuration |
|---|---|---|
| **Clavier (HID)**, le mode d’usine de presque tous les scanners | Le scanner saisit le code ; WCPOS reconnaît la saisie rapide | Aucune : appairez ou branchez le scanner, puis scannez |
| **HID-POS** | Une connexion USB directe | Changez le mode du scanner, puis **Connecter par USB** |
| **Série (SPP / USB-COM)** | Une connexion série directe par Bluetooth ou USB | Changez le mode du scanner, puis **Connecter par liaison série Bluetooth**. Un scanner Bluetooth absent de la liste peut utiliser son propre UUID de service : ajoutez-le sous **Mon scanner n’est pas dans la liste**. |
| **Bluetooth LE** | Une connexion Bluetooth Low Energy directe, dans l’application iPhone et iPad | Supprimez le scanner des paramètres Bluetooth de votre appareil sans l’appairer à nouveau, puis appuyez sur **Connecter un scanner Bluetooth**. L’application se connecte au premier scanner Bluetooth LE trouvé : laissez donc les autres éteints. |

Les boutons de connexion se trouvent dans **Paramètres** → **Lecture des codes-barres** → **Scanner** → **Connecter un scanner directement (avancé)**.

:::info Un scanner en mode clavier ne peut pas être connecté directement
Votre appareil traite un scanner en mode clavier exactement comme un clavier, et aucune application n’est autorisée à prendre le contrôle d’un clavier. Si votre scanner n’apparaît pas dans la liste après avoir appuyé sur un bouton de connexion, il est presque certainement encore en mode clavier.
:::

**Pour changer de mode**, trouvez le code-barres de configuration dans le manuel de votre scanner (cherchez *« mode SPP »*, *« mode série »* ou *« mode HID-POS »*) et scannez-le. Le scanner se reconfigure automatiquement. Pour un scanner Bluetooth, oubliez l’ancien appairage dans les paramètres Bluetooth de votre appareil et appairez-le à nouveau après le changement. Scanner le code-barres *« HID »* ou *« clavier »* du manuel permet de revenir au mode précédent à tout moment.

Les connexions USB et série Bluetooth fonctionnent dans l’application de bureau et les navigateurs basés sur Chrome. L’application de bureau affiche un sélecteur d’appareil dans l’application ; Chrome affiche le sien. L’application iPhone et iPad se connecte directement à un scanner Bluetooth LE. Safari et Firefox ne proposent pas de connexion directe : utilisez le mode clavier ou la caméra.

  </AccordionItem>
</Accordion>

### Enregistrer un scanner sur Android {#android}

Sur Android, enregistrez un scanner en mode clavier pour pouvoir scanner quelle que soit la position du curseur, y compris dans un champ de texte. La **Longueur minimale du code-barres** s’applique toujours.

1. Appairez ou branchez le scanner.
2. Dans **Paramètres** → **Lecture des codes-barres**, dans la section **Scanner**, appuyez sur **Enregistrer un scanner**, puis sur **Enregistrer le scanner**.
3. Scannez n’importe quel code-barres avec ce scanner. WCPOS affiche **« … » détecté — nommez-le et enregistrez**.
4. Donnez-lui un nom et appuyez sur **Enregistrer le scanner**.

Le scanner dispose de sa propre ligne portant la mention **Enregistré**. Les autres scanners en mode clavier continuent de fonctionner sans être enregistrés. Voir [Enregistrer votre scanner sur Android](../../hardware/scanners/setup-wizard.mdx).

<Accordion>
  <AccordionItem question="Fonctionnement de l’enregistrement d’un scanner sur Android">

Android ne peut pas se connecter directement à un scanner, mais reconnaît un scanner enregistré grâce à l’appareil dont proviennent les données. Ses lectures sont interceptées avant d’atteindre un champ de texte, sans déduction fondée sur la vitesse de saisie.

  </AccordionItem>
</Accordion>

## En cas de problème {#goes-wrong}

- **Rien ne se passe lorsque vous scannez** — dans un navigateur web ou l’application de bureau, cliquez sur une zone vide de l’écran et scannez à nouveau. Dans l’application WCPOS pour iPad, iPhone ou Android, appuyez d’abord dans le champ de recherche. Vérifiez ensuite le scanner avec le **Test de lecture des codes-barres** ; voir [Paramètres des codes-barres](../../settings/store/barcode.mdx).
- **Le code apparaît dans le champ de recherche comme du texte saisi** — dans un navigateur web ou l’application de bureau, le curseur se trouvait dans le champ : cliquez sur une zone vide de l’écran et scannez à nouveau. Dans l’application WCPOS pour iPad, iPhone ou Android, gardez le curseur dans le champ de recherche. Dans les deux cas, le scanner peut être plus lent que le **Seuil de temps moyen de saisie du code-barres (ms)** : lancez le test et appuyez sur **Appliquer** pour accepter la valeur suggérée.
- **Code-barres introuvable pour un produit que vous connaissez** — vérifiez le paramètre [Champ du code-barres](../../settings/wp-admin/general.mdx#barcode-field) et le code-barres du produit dans WooCommerce. Un produit réservé à la vente en ligne n’apparaît jamais dans le PDV. Sur un nouvel appareil, attendez la fin de la première synchronisation : **État de la boutique → Base de données** en affiche la progression.
- **Lecture indisponible** — vous êtes hors ligne et le produit n’est pas encore sur cet appareil. Consultez [État de la boutique](../../support/store-health.mdx#database).
- **La caméra ne démarre pas** — voir [les messages de la caméra](#camera-scanning).

## F.A.Q. {#faq}

<Accordion>
  <AccordionItem question="Pourquoi un produit que je viens d’ajouter à ma boutique ne peut-il pas être scanné ?">

WCPOS interroge votre boutique pour tout code absent de cet appareil : un nouveau produit peut donc être scanné tant que vous êtes en ligne. Si **Code-barres introuvable** s’affiche, la boutique ne possède pas non plus ce code : vérifiez le champ du code-barres du produit dans WooCommerce. Si **Lecture indisponible** s’affiche, vous êtes hors ligne ; scannez à nouveau une fois la connexion rétablie.

  </AccordionItem>

  <AccordionItem question="Le PDV génère-t-il et imprime-t-il des codes-barres ?">

Non, pas pour le moment. WCPOS scanne et lit les codes-barres existants, mais ne les crée ni ne les imprime.
Pour générer des codes-barres pour vos produits, utilisez une extension WooCommerce spécialisée dans la création et l’impression de codes-barres, par exemple :

- [EAN for WooCommerce](https://wordpress.org/plugins/ean-for-woocommerce/)
- [A4 Barcode Generator](https://wordpress.org/plugins/a4-barcode-generator/)

Ajoutez ensuite chaque code au champ du code-barres du produit pour pouvoir le scanner en caisse.

  </AccordionItem>
</Accordion>
