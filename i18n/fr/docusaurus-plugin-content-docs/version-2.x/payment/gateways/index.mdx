**Administration WordPress :** chaque passerelle de paiement est une extension à installer dans WordPress et à activer dans `WP Admin → POS → Settings → Checkout`.

Une passerelle de paiement ajoute une façon de payer en caisse : un terminal de paiement sur le comptoir, un paiement depuis le téléphone du client ou une facture qu’il réglera plus tard. Chacune est une extension WordPress de WCPOS que vous ajoutez à votre boutique. Pour accéder directement à la vôtre, consultez [Choisir une passerelle de paiement](#gateways).

Pour un client qui souhaite utiliser un moyen de paiement proposé par votre boutique en ligne, consultez [Web Checkout](./web-checkout.mdx) ; pour les espèces, la carte et les autres façons d’encaisser en caisse, consultez [Moyens de paiement](../index.mdx).

:::info Fonctionnalité Pro
Les passerelles de paiement nécessitent [WCPOS Pro](../../getting-started/pro-license.mdx). Sans cette version, la caisse accepte uniquement **Espèces** et **Carte**.
:::

## Où apparaît une passerelle lors du paiement {#at-the-till}

Appuyez sur **Paiement** : le panneau d’encaissement s’ouvre sur **Paiements**. Une passerelle indiquée comme **Paiements** dans la [liste ci-dessous](#gateways) y dispose de sa propre tuile, à côté d’**Espèces** et de **Carte**.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[28, 42], [0, 0], [0, 0], [29, 42]]} alt="Le panneau d’encaissement dans l’onglet Paiements : les onglets Paiements et Ancien, les tuiles Espèces et Carte, le montant à payer et le bouton Encaisser">

1. **Paiements** — le panneau d’encaissement. Tous les moyens de paiement disposant d’une tuile s’y trouvent. Consultez [Le panneau d’encaissement](../../pos/checkout/payment-methods.mdx).
2. **Espèces** — calcule la monnaie à rendre pour vous. Disponible dans toutes les boutiques.
3. **Carte** — pour un terminal de paiement qui n’est pas connecté au PDV : encaissez sur le terminal, puis enregistrez le paiement ici. Disponible dans toutes les boutiques.
4. **Ancien** — les passerelles qui utilisent leur propre page de paiement. Consultez [L’onglet Ancien](../../pos/checkout/legacy-tab.mdx).

</JourneyShot>

Les tuiles des passerelles suivent l’ordre défini dans les [réglages de la caisse](../../settings/wp-admin/checkout.mdx#reordering-gateways). Une tuile que la caisse ne peut pas utiliser pour le moment se replie dans une ligne sous les tuiles : **Stripe Terminal n’est pas disponible pour le moment**, ou **2 indisponibles pour le moment** s’il y en a plusieurs. Appuyez sur la ligne pour en connaître la raison.

Les passerelles WooCommerce de paiement à la livraison, de virement bancaire et de chèque disposent aussi d’une tuile : vous enregistrez ces paiements en caisse, comme avec **Carte**. Consultez [Moyens de paiement en caisse](../../pos/checkout/payment-methods.mdx). Toute autre passerelle se trouve dans l’onglet **Ancien**, qui ouvre la page de paiement de la commande de votre boutique à l’intérieur du PDV. Une passerelle de cet onglet encaisse la totalité de la commande ; elle ne peut donc pas constituer une partie d’un [paiement fractionné](../../pos/checkout/split-payments.mdx).

<details>
<summary>Encaisser un paiement dans l’onglet Ancien</summary>

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[29, 42], [0, -272], [-30, 0]]} alt="L’onglet Ancien : la page de paiement de la passerelle répertoriant les passerelles activées pour le PDV, et le bouton Traiter le paiement">

1. **Ancien** — cet onglet est toujours présent. S’il n’a aucune passerelle à proposer, il l’indique.
2. **Page de paiement** — la page de paiement de votre boutique pour cette commande. Choisissez la passerelle et renseignez les informations demandées.
3. **Traiter le paiement** — transmet le paiement à la passerelle.

</details>

## Choisir une passerelle de paiement {#gateways}

### Terminaux de paiement {#hardware-terminal-gateways}

Le client approche, insère ou fait glisser sa carte sur un terminal de votre prestataire de paiement. La caisse transmet le montant au terminal et enregistre le paiement lorsque le prestataire le confirme.

| Passerelle de paiement | Lors du paiement |
|---|---|
| [Stripe Terminal](./stripe-terminal.mdx) | Paiements, 2.0+ |
| [SumUp Terminal](./sumup-terminal.mdx) | Paiements, 2.0+ |
| [Mollie Terminal](./mollie-terminal.mdx) | Paiements, 2.0+ |
| [Square Terminal](./square-terminal.mdx) | Paiements, 1.0+ |
| [Mercado Pago Terminal](./mercadopago-terminal.mdx) (Point Smart) | Paiements, 1.0+ |
| [Windcave Terminal](./windcave-terminal.mdx) | Paiements, 1.0+ |
| [PayArc Terminal](./payarc-terminal.mdx) (PAX) | Paiements, 1.0+ |
| [PayPal Reader (Zettle)](./paypal-reader.mdx) | Ancien, toutes les versions |

Le numéro indique la plus ancienne version de l’extension de passerelle disposant d’une tuile. Une version antérieure apparaît dans l’onglet **Ancien**. Pour savoir quels lecteurs fonctionnent avec quels appareils, consultez [Compatibilité des lecteurs de cartes](../../hardware/index.mdx#card-reader-compatibility).

### Paiements par téléphone {#mobile-payment-gateways}

- **[Vipps MobilePay](./vipps-mobilepay.mdx)** — le client scanne un code QR à l’écran ou confirme une demande sur son téléphone, dans l’application Vipps ou MobilePay. Dans l’onglet **Ancien**.

### Payer plus tard {#digital-payment-gateways}

La commande est enregistrée sans paiement et le client la règle ensuite en ligne.

- **[Email Invoice](./email-invoice.mdx)** — le client reçoit un e-mail avec un lien pour régler la commande. Dans l’onglet **Paiements** à partir de la version 0.1.0 ; les versions antérieures se trouvent dans **Ancien**.
- **[Web Checkout](./web-checkout.mdx)** — le client paie sur la page de paiement de votre boutique en ligne. Dans l’onglet **Ancien**.

## Ajouter une passerelle de paiement à votre boutique {#install}

En tant que propriétaire de la boutique, vous effectuez cette opération une seule fois dans WordPress : installez la passerelle, connectez votre compte, activez-la pour le PDV, puis rechargez le PDV. La page de chaque passerelle détaille ses propres réglages.

<details>
<summary>Propriétaire de la boutique : installer, activer ou débloquer une passerelle grisée</summary>

1. **Installez-la.** Dans `WP Admin > POS > Réglages > Extensions`, recherchez la passerelle, appuyez sur **Installer**, puis sur **Activer**. Vous pouvez aussi télécharger le zip de l’extension depuis la page des versions de la passerelle sur GitHub, puis le téléverser dans `Extensions > Add Plugin`, puis **Téléverser une extension**. Web Checkout ne figure pas dans la liste des extensions ; son installation se fait donc toujours par zip. Consultez [Extensions](../../extensions/index.mdx#installing-an-extension).
2. **Connectez votre compte.** Ouvrez la passerelle dans `WP Admin > WooCommerce > Réglages > Paiements` et saisissez les clés de votre prestataire de paiement. Si la passerelle propose un mode test, effectuez un paiement de test avant la mise en service.
3. **Activez-la pour le PDV.** Dans `WP Admin > POS > Réglages > Validation de la commande`, activez l’option **Activée** de la passerelle et faites-la glisser à l’endroit souhaité pour sa tuile. Il n’est pas nécessaire de l’activer pour votre boutique en ligne. Consultez [Réglages de la caisse](../../settings/wp-admin/checkout.mdx#enabling-a-gateway).
4. **Rechargez le PDV.** La caisse charge vos moyens de paiement à chaque démarrage.

**Installer est grisé et affiche Pro requis pour l’installation.** L’installation depuis **Extensions** nécessite WCPOS Pro.

**L’interrupteur Activée est grisé.** Toutes les passerelles, sauf Espèces et Carte, nécessitent WCPOS Pro, activé avec votre clé de licence. Consultez [Licence Pro](../../getting-started/pro-license.mdx).

</details>

## En cas de problème {#goes-wrong}

**La passerelle n’apparaît pas lors du paiement.** Regardez d’abord dans l’onglet **Ancien**. Si elle n’y figure pas non plus, vérifiez que l’option **Activée** est cochée dans les réglages de la caisse, puis rechargez le PDV. Si l’interrupteur est grisé, ouvrez **Propriétaire de la boutique : installer, activer ou débloquer une passerelle grisée** sous [Ajouter une passerelle de paiement à votre boutique](#install).

**Elle apparaît dans l’onglet Ancien, sans tuile.** PayPal Reader, Vipps MobilePay et Web Checkout s’y trouvent toujours. Pour un terminal [répertorié ci-dessus](#hardware-terminal-gateways) avec un numéro de version, comparez la version installée à celle du tableau. Si elle est plus ancienne, mettez-la à jour : sa fiche dans **Extensions** affiche **Mise à jour disponible** lorsqu’une nouvelle version existe.

**La tuile se trouve sous « indisponible pour le moment ».** Appuyez sur la ligne : chaque passerelle en indique la raison, par exemple **Connexion nécessaire** lorsque vous êtes hors ligne. En attendant, terminez la vente avec un autre moyen de paiement.

**Un paiement échoue.** Si la caisse indique **PAYMENT301**, la boutique a refusé la passerelle : elle n’est pas activée pour le PDV ou n’est plus présente. Consultez [PAYMENT301](../../error-codes/PAYMENT301.mdx). Les échecs sur le terminal ou chez le prestataire sont décrits sur la page de la passerelle, avec les messages d’erreur et les solutions. Pour signaler un problème, consultez [Assistance](../../support/index.mdx).

### Créer votre propre passerelle de paiement {#creating-your-own-gateway}

Pour les développeurs : toute extension de paiement WooCommerce peut être adaptée au PDV. Partez du [modèle de passerelle de paiement](../../reference/gateway-template.mdx).
