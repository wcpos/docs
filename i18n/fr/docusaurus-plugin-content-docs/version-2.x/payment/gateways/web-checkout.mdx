# Passerelle de paiement Web Checkout {#web-checkout-gateway}

:::info Fonctionnalité Pro
Vous avez besoin de [WCPOS Pro](../../getting-started/free-vs-pro.mdx) pour encaisser des paiements avec Web Checkout.
:::

Web Checkout permet au client de régler une commande du PDV sur la page de paiement de votre boutique en ligne, avec les moyens de paiement qu’elle propose, comme un formulaire de paiement par carte ou un portefeuille électronique. Utilisez cette option lorsque le client souhaite payer avec un moyen que la caisse n’accepte pas.

Accès direct : [Encaisser un paiement](#take-payment) · [Configurer](#set-up) · [En cas de problème](#goes-wrong)

## Encaisser un paiement {#take-payment}

Web Checkout se trouve dans l’onglet **Ancien** de l’écran de paiement. Une connexion est nécessaire et le paiement porte sur la totalité de la commande : si un paiement a déjà été encaissé, consultez d’abord [Une partie de la commande est déjà payée](#split).

:::warning Restez sur l’écran de paiement jusqu’à ce que vous appuyiez sur Traiter le paiement
La caisse ne surveille pas l’autre onglet. Elle termine la vente uniquement lorsque vous appuyez sur **Traiter le paiement** pour une commande que le client a réglée. Gardez donc l’écran de paiement ouvert pendant qu’il paie.
:::

1. Enregistrez la vente comme d’habitude et appuyez sur **Paiement**.
2. Ouvrez l’onglet **Ancien**. La page de paiement de votre boutique se charge dans le PDV.
3. Choisissez **Web Checkout**. Sa note et un lien **Payer cette commande** apparaissent en dessous.
4. Appuyez sur **Payer cette commande**. La page de paiement de cette commande sur votre boutique en ligne s’ouvre dans un nouvel onglet du navigateur ; dans l’application de bureau, elle s’ouvre dans le navigateur web de votre ordinateur.
5. Présentez l’écran au client. Il choisit un moyen de paiement et règle la commande, comme il le ferait sur votre site web.
6. Une fois le paiement effectué, l’onglet du client affiche la confirmation de commande de votre boutique. Laissez cet onglet ouvert et revenez au PDV.
7. Appuyez sur **Traiter le paiement**. Si la commande est payée, la caisse affiche l’écran de confirmation du paiement et le reçu, comme pour toute vente. Sinon, elle reste sur cette page : consultez [En cas de problème](#goes-wrong).
8. Fermez l’onglet du client une fois que la caisse affiche le reçu.

### Une partie de la commande est déjà payée {#split}

Une passerelle de paiement de l’onglet Ancien facture la totalité de la commande. Dès qu’un paiement a été encaissé, cet onglet affiche donc **Une passerelle de paiement de l’ancien système ne peut pas être utilisée après l’encaissement d’un paiement**. Vous avez deux possibilités :

- **Encaisser le reste avec une tuile**, comme Espèces ou Carte, dans l’onglet Paiements. Consultez [Paiements fractionnés](../../pos/checkout/split-payments.mdx).
- **Annuler les paiements déjà encaissés**, puis utiliser Web Checkout pour la totalité de la commande. Avant toute annulation, la caisse indique ce qu’il adviendra de chaque paiement : les espèces sont rendues au client, les autres paiements sont annulés auprès du moyen de paiement utilisé et ceux qui ne peuvent pas être annulés sont remboursés depuis la commande. Consultez [Annuler un paiement](../../pos/checkout/cancelling-a-payment.mdx).

:::tip Le client souhaite payer plus tard, sur son propre téléphone
Web Checkout ouvre la page de paiement sur l’appareil qui exécute le PDV. Pour envoyer au client un lien lui permettant de payer plus tard, utilisez [Facture par e-mail](./email-invoice.mdx).
:::

## Configurer {#set-up}

Une personne qui gère votre boutique dans WP Admin effectue cette configuration une seule fois, avant la première vente avec Web Checkout. Web Checkout est une extension gratuite, mais le PDV ne la propose qu’avec WCPOS Pro ; sans Pro, la caisse accepte les espèces et les cartes. Elle utilise les moyens de paiement dont votre boutique en ligne dispose déjà. Aucun compte ni aucune clé ne sont nécessaires.

<details>
<summary>Responsable de boutique : installer et activer</summary>

1. **Installez l’extension.** Web Checkout ne figure pas dans `WP Admin > POS > Réglages > Extensions`. Téléchargez **woocommerce-pos-web-checkout-gateway.zip** (et non l’archive zip du code source) depuis la [page des versions sur GitHub](https://github.com/wcpos/web-checkout-gateway/releases), téléversez-la dans `WP Admin > Extensions > Add Plugin`, puis **Téléverser une extension**, et activez-la.
2. **Activez-la pour le PDV.** Dans `WP Admin > POS > Réglages > Validation de la commande`, activez **Web Checkout** et enregistrez. Consultez [Réglages de la caisse](../../settings/wp-admin/checkout.mdx#enabling-a-gateway). Elle n’apparaît jamais sur votre écran de paiement en ligne : les clients y accèdent uniquement par le PDV.
3. **Vérifiez vos moyens de paiement en ligne.** Le client paie avec les moyens activés pour le web dans `WP Admin > WooCommerce > Réglages > Paiements`. Au moins un doit être prêt à encaisser des paiements.

</details>

<details>
<summary>Modifier le nom ou le message</summary>

Le nom et la note affichés sur la page de paiement correspondent aux champs **Titre** et **Description** de la passerelle, dans `WP Admin > WooCommerce > Réglages > Paiements > Web Checkout Gateway`. La note par défaut indique « Accédez à la page de paiement pour régler la commande. Après le paiement, cliquez sur le bouton Traiter le paiement pour accéder au reçu. » Pour la renommer uniquement dans le PDV, modifiez son **Titre** sous **Réglages du PDV**, dans le menu **⋮** de la passerelle, dans [Réglages de la caisse](../../settings/wp-admin/checkout.mdx#payment-gateways) ; la note provient toujours de WooCommerce.

</details>

<details>
<summary>Pour les développeurs : fonctionnement</summary>

L’extension ajoute une passerelle WooCommerce dont l’ID est `wcpos_web_checkout`. Le code la désactive pour le paiement en ligne : seul le PDV peut donc la proposer. Ses champs de paiement affichent la description et un lien vers l’URL de paiement propre à la commande (`$order->get_checkout_payment_url()`), qui s’ouvre dans une nouvelle fenêtre.

La passerelle n’encaisse elle-même aucun paiement. Lorsque **Traiter le paiement** soumet une commande déjà payée, créée par le PDV et pour laquelle `wcpos_web_checkout` est sélectionné, l’extension redirige la page de paiement vers la page de confirmation de commande, à partir de laquelle le PDV termine la vente. Une commande non payée ne passe pas à l’étape suivante. Le code source se trouve dans le [dépôt web-checkout-gateway](https://github.com/wcpos/web-checkout-gateway).

</details>

## En cas de problème {#goes-wrong}

**Web Checkout ne figure pas dans la liste de l’onglet Ancien.** L’extension n’est pas active, ou Web Checkout n’est pas activé dans [Réglages de la caisse](../../settings/wp-admin/checkout.mdx#enabling-a-gateway). Sans WCPOS Pro, le PDV propose uniquement Espèces et Carte.

**« Aucune passerelle de paiement de l’ancien système n’est activée pour le PDV. »** Aucune passerelle sans tuile n’est activée. Activez Web Checkout dans Réglages de la caisse.

**Traiter le paiement ne permet pas d’accéder au reçu.** La boutique ne considère pas la commande comme payée. Avant de demander au client de payer à nouveau, regardez son onglet : s’il affiche encore la page de paiement, le client n’a pas terminé. S’il affiche la confirmation de commande, appuyez à nouveau sur **Traiter le paiement** et, si la caisse ne passe toujours pas à l’étape suivante, vérifiez la commande dans `WP Admin > WooCommerce > Orders`.

**Aucun moyen de paiement utilisable par le client n’apparaît sur la page de paiement.** Aucun des moyens activés sur votre boutique en ligne ne lui convient. Activez-en un pour le web dans `WP Admin > WooCommerce > Réglages > Paiements`.

**La page de paiement s’affiche mal dans le PDV.** Un thème ou une extension peut perturber son affichage. Consultez [La page de paiement d’une passerelle s’affiche mal](../../pos/checkout/troubleshooting.mdx#checkout-settings-troubleshooting).
