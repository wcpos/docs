# Passerelle de paiement SumUp Terminal {#sumup-terminal-gateway}

SumUp Terminal vous permet d’utiliser un lecteur de cartes SumUp en caisse. La caisse envoie le montant au lecteur, le client y règle son achat et la vente se termine lorsque SumUp approuve le paiement. Cette page vous guide dans la configuration initiale de la passerelle de paiement, l’association ou la connexion du lecteur, puis l’encaissement du premier paiement.

La configuration est déjà faite ? [Associez un Solo](#pairing), [connectez un lecteur Bluetooth](#card-readers) ou [encaissez un paiement](#processing-payments).

:::info Fonctionnalité Pro
SumUp Terminal 2.0 nécessite [WCPOS Pro](../../getting-started/pro-license.mdx) 2.0.0 ou une version ultérieure. Sans cela, l’extension n’a aucun effet en caisse.
:::

## Solo via le cloud ou Bluetooth {#hardware-compatibility}

Le réglage **Connexion au PDV** de la passerelle de paiement détermine comment le PDV communique avec le lecteur. Ce choix s’applique à toute la boutique.

- **Solo via le cloud** (par défaut) : votre boutique se connecte à un **SumUp Solo** par Internet. Cette option fonctionne depuis toutes les caisses : navigateur, application de bureau, iPhone, iPad et Android. Vous associez le Solo une seule fois, sur la page de la passerelle de paiement.
- **Lecteur Bluetooth** : l’application WCPOS pour iOS ou Android se connecte à un **Solo Lite**, un **Solo** ou un **Air** par Bluetooth. Chaque caisse connecte son propre lecteur dans l’application. Cette option n’apparaît que si la version de WCPOS Pro de la boutique prend en charge les lecteurs auxquels l’application se connecte.

Un navigateur ou l’application de bureau ne peut pas communiquer avec un lecteur Bluetooth. Si **Lecteur Bluetooth** est sélectionné, la tuile SumUp de ces caisses figure sous **… indisponible pour le moment**. Choisissez donc **Solo via le cloud** si une caisse utilise un navigateur ou l’application de bureau. Le message de la tuile est expliqué dans [Seuls les lecteurs de l’application sont autorisés](#only-app-readers).

## Configurer la passerelle de paiement {#setup}

Un administrateur effectue cette opération une seule fois par boutique, dans WP Admin.

1. **Installez l’extension.** Dans `WP Admin > POS > Réglages > Extensions`, recherchez **SumUp Terminal for WooCommerce**, cliquez sur **Installer**, puis sur **Activer**, et vérifiez qu’il s’agit de la version 2.0.0 ou d’une version ultérieure : le répertoire peut encore proposer une ancienne version. Consultez [Extensions](../../extensions/index.mdx#installing-an-extension).

   <details>
   <summary>Installer à partir d’un fichier zip téléchargé</summary>

   Téléchargez `sumup-terminal-for-woocommerce.zip` parmi les fichiers de la version sur [GitHub](https://github.com/wcpos/sumup-terminal-for-woocommerce/releases), puis téléversez-le depuis `Extensions > Add Plugin`, puis **Téléverser une extension**. Le fichier zip « Source code » de GitHub ne peut pas être installé.

   </details>

2. **Ajoutez votre clé API.** Votre **Clé API SumUp** se trouve dans le [portail développeur SumUp](https://developer.sumup.com/), dans le compte auquel appartiennent vos lecteurs. Allez dans `WP Admin > WooCommerce > Réglages > Paiements`, ouvrez **SumUp Terminal** et collez-la dans **Clé API SumUp**.
3. **Choisissez la connexion au PDV** : **Solo via le cloud** ou **Lecteur Bluetooth**. Pour **Lecteur Bluetooth**, saisissez également la **Clé d’affiliation** provenant de [SumUp Affiliate Keys](https://developer.sumup.com/tools/authorization/affiliate-keys/).
4. **Enregistrez les réglages.**
5. **Activez la passerelle pour le PDV.** Allez dans `WP Admin > POS > Réglages > Validation de la commande`, activez **SumUp Terminal** et enregistrez. Il n’est pas nécessaire de l’activer dans la liste des paiements de WooCommerce ; consultez [Réglages de la caisse](../../settings/wp-admin/checkout.mdx).
6. **Associez ou connectez le lecteur** : un Solo via le cloud s’[associe sur cette page](#pairing) ; un lecteur Bluetooth se [connecte dans l’application](#card-readers).

SumUp Terminal est réservé au PDV. Il n’est pas proposé lors du paiement sur votre boutique en ligne.

<details>
<summary>Tous les réglages de la page de la passerelle de paiement</summary>

| Réglage | Fonction |
|---|---|
| **Titre** et **Description** | Le nom et la ligne de texte affichés pour la passerelle de paiement. La caisse affiche le titre sur la tuile. |
| **Clé API SumUp** | Fournie par votre compte SumUp. |
| **ID de l’application affiliée** et **Clé d’affiliation** | Fournis par [SumUp Affiliate Keys](https://developer.sumup.com/tools/authorization/affiliate-keys/). La clé est nécessaire pour **Lecteur Bluetooth** : l’application l’utilise pour lancer le logiciel de lecteur SumUp. Elle est facultative pour **Solo via le cloud**. |
| **Connexion au PDV** | *Solo via le cloud (la boutique pilote le lecteur)* ou *Lecteur Bluetooth (l’application PDV pilote le lecteur : Solo Lite, Solo, Air)*. |
| **Paiements par carte hors ligne** | Sans effet dans la version 2.0 ; consultez [Paiements hors ligne](#offline-payments). |
| **Terminal par défaut** | Le Solo associé qu’une caisse utilise pour encaisser tant qu’elle n’en choisit pas un autre. |
| **Terminaux activés** | Limite les caisses aux Solo que vous sélectionnez. Laissez ce champ vide pour tous les autoriser. |
| **Verrouiller la sélection du terminal** | *Les caissiers ne peuvent pas changer de terminal lors du paiement.* Nécessite un **Terminal par défaut**. |
| **Journaux de débogage du paiement** | Affiche les journaux détaillés des paiements SumUp lors du paiement. L’activité des paiements est toujours consignée dans `WooCommerce > Status > Journaux`. |

Sous les champs, la page affiche l’état de la connexion, les informations de votre compte marchand SumUp et les lecteurs associés. Aucun webhook n’est à configurer : la boutique indique à SumUp où envoyer chaque résultat.

</details>

## Associer un Solo via le cloud {#pairing}

Le code d’association provient du Solo lui-même, et non de l’application SumUp. Vous le saisissez sur la page de la passerelle de paiement dans WP Admin.

1. Allumez le Solo. Ne vous connectez pas à SumUp sur cet appareil.
2. Sur le Solo, ouvrez le menu, puis **Connexions → API Cloud**. Il s’agit du dernier élément de la liste. Appuyez sur **Connecter** : le Solo affiche un code d’association.
3. Dans WP Admin, ouvrez la page de la passerelle de paiement (`WooCommerce > Réglages > Paiements > SumUp Terminal`). Sous **Associer un nouveau lecteur**, saisissez le code dans **Saisir le code d’association** et appuyez sur **Associer le lecteur**.
4. La page affiche *Lecteur associé avec succès !* et se recharge. Votre Solo figure sous **Lecteurs configurés**, avec son modèle et son numéro de série.

**Pas d’API Cloud sur le Solo ?** Déconnectez-vous de votre compte SumUp sur le lecteur, puis ouvrez à nouveau le menu.

Pour associer un second Solo, utilisez **Associer un lecteur supplémentaire**. L’option **Dissocier le lecteur** à côté d’un lecteur le supprime de la boutique.

## Connecter un lecteur Bluetooth dans l’application {#card-readers}

Lorsque **Connexion au PDV** est réglé sur **Lecteur Bluetooth**, chaque téléphone ou tablette connecte son propre lecteur dans l’application WCPOS pour iOS ou Android. Appuyez sur **Réglages** en bas du menu latéral, puis sur **Lecteurs de cartes** : une fois la passerelle de paiement configurée, la page contient une section **Lecteurs Bluetooth** avec un bouton **Connecter un lecteur**. Si elle affiche uniquement **Aucun lecteur de cartes n’est configuré pour cette boutique**, consultez [Aucun lecteur de cartes](#no-card-readers).

1. Allumez le lecteur et gardez-le à proximité du téléphone ou de la tablette.
2. Appuyez sur **Connecter un lecteur**. Si **Connecter un lecteur avec** apparaît, choisissez **SumUp Terminal**.
3. L’écran de SumUp s’ouvre : connectez-vous à votre compte SumUp et choisissez le lecteur.

Une fois un lecteur enregistré, **Lecteurs de cartes** affiche une ligne **SumUp Terminal**. La prochaine fois, utilisez son bouton **Ouvrir les réglages du lecteur SumUp Terminal**. Le bouton reprend le **Titre** de la passerelle de paiement ; son libellé change donc si vous l’avez renommée.

De retour dans **Lecteurs de cartes**, la ligne affiche **Connecté**, ou **Enregistré dans l’application SumUp Terminal** lorsque le lecteur est mémorisé mais déconnecté. Le message **Connectez-vous à SumUp Terminal pour utiliser son lecteur.** signifie que l’application n’est pas encore connectée à SumUp : appuyez à nouveau sur le bouton.

## Tester avant la mise en service {#testing}

Pour **Solo via le cloud**, vous pouvez effectuer une vente sans lecteur ni argent réel : le [Virtual Solo](https://virtual-solo.sumup.com) de SumUp simule un Solo pour un compte de test SumUp.

<details>
<summary>Tester avec un Virtual Solo</summary>

1. Sur la page de la passerelle de paiement, collez la clé API du compte de test dans **Clé API SumUp** et enregistrez.
2. Associez le Virtual Solo avec son code d’association, comme pour [un Solo](#pairing). Il figure sous **Lecteurs configurés**.
3. Effectuez une vente en suivant les étapes d’[Encaisser un paiement](#processing-payments). La tuile affiche **Terminal : …** avec le Virtual Solo.

Lorsque vous avez terminé, remettez votre clé API de production, enregistrez et associez votre véritable Solo avant d’encaisser un paiement réel.

</details>

## Encaisser un paiement {#processing-payments}

:::note Ouvrez d’abord la caisse
Lorsque **Ouvrir et fermer la caisse** est activé, la caisse n’enregistre aucun paiement tant qu’elle est fermée, et un paiement par carte déjà encaissé devrait être remboursé. Consultez [Ouvrir la caisse](../../pos/register/index.mdx).
:::

1. Remplissez le panier et appuyez sur **Paiement**.
2. Appuyez sur la tuile **SumUp Terminal** parmi les moyens de paiement et vérifiez la ligne du lecteur :
   - **Solo via le cloud** : **Terminal : …**, avec **Changer** pour choisir un autre Solo lorsque la boutique l’autorise.
   - **Lecteur Bluetooth** : **Connecté** avec le niveau de batterie du lecteur. **Aucun lecteur connecté** signifie qu’il n’est pas connecté : appuyez sur **Connecter dans Réglages → Lecteurs de cartes**.
3. Appuyez sur **Envoyer … à SumUp Terminal** et laissez le client payer sur le lecteur :
   - **Solo via le cloud** : la caisse affiche **En attente du client sur le terminal**. Pour interrompre le paiement, appuyez sur **Annuler sur le terminal**.
   - **Lecteur Bluetooth** : la caisse affiche **Présentez la carte sur le lecteur**. Pour interrompre le paiement, annulez sur le lecteur lui-même. Si vous appuyez sur **Annuler sur le terminal** sur la caisse, elle affiche **Annulez sur le lecteur**. Le lecteur peut proposer au client de laisser un pourboire ; consultez [Pourboires](../../pos/checkout/tips.mdx).

   La caisse coche les étapes **Envoyé**, **Sur le terminal**, **Approuvé** et **Capturé**.
4. Lorsqu’il ne reste rien à payer, l’écran du reçu s’ouvre : imprimez le reçu ou envoyez-le par e-mail, puis appuyez sur **Nouvelle vente**. Consultez [Vérifier que la vente est payée](../../pos/checkout/index.mdx#paid). S’il reste une partie du total à régler, encaissez le reste avec un autre moyen de paiement ; consultez [Paiements fractionnés](../../pos/checkout/split-payments.mdx).

Un paiement par carte refusé ou annulé affiche **Échec du paiement : …**, avec **Réessayer** et **Choisir un autre moyen**. Consultez [Sur un lecteur de cartes](../../pos/checkout/taking-a-payment.mdx#card-reader).

Dans l’onglet [**Ancien système**](../../pos/checkout/legacy-tab.mdx) de l’écran de paiement, SumUp Terminal affiche un sélecteur **Terminal** avec **Envoyer au terminal**, **Annuler** et **Réessayer**. Le paiement est enregistré comme un paiement effectué depuis le panneau des moyens de paiement.

<details>
<summary>Une ancienne version de SumUp Terminal, antérieure à 2.0</summary>

Les versions antérieures à 2.0 n’ont pas de tuile dans le panneau des moyens de paiement. La passerelle de paiement se trouve dans l’onglet **Ancien système**, sur sa propre page de paiement avec **Démarrer un nouveau paiement**, **Annuler le paiement** et **État du paiement**, et fonctionne uniquement avec un Solo via le cloud. Passez à la version 2.0 pour bénéficier de la tuile et des lecteurs Bluetooth.

</details>

## Paiements hors ligne {#offline-payments}

WCPOS 2.0 n’accepte pas les paiements par carte SumUp lorsque la caisse est hors ligne, quel que soit le lecteur ou le réglage **Paiements par carte hors ligne** de la passerelle de paiement.{/* pending: monorepo#3387 */} Sans connexion, la tuile SumUp figure sous **… indisponible pour le moment**, avec **Connexion requise**. Encaissez la vente en espèces ou attendez le rétablissement de la connexion ; consultez [Mode hors ligne](../../getting-started/offline.mdx#take-payment-offline).

Les paiements par carte hors ligne figurent sur la [feuille de route](../../getting-started/roadmap.mdx).

<Anchor id="solo-wont-pair" />

**Le Solo ne s’associe pas.** Utilisez un SumUp Solo : c’est le seul lecteur qui s’associe via le cloud ; un lecteur Bluetooth se connecte depuis l’application WCPOS. Vérifiez que le Solo est en ligne, déconnecté du compte SumUp et qu’il affiche le code de **Connexions → API Cloud**. Saisissez le code exactement comme il apparaît.

<Anchor id="only-app-readers" />

**« Seuls les lecteurs de l’application sont autorisés pour ce moyen de paiement. »** La caisse utilise un navigateur ou l’application de bureau, et **Connexion au PDV** est réglé sur **Lecteur Bluetooth**. Encaissez le paiement dans l’application iOS ou Android, ou demandez à un administrateur de régler **Connexion au PDV** sur **Solo via le cloud** et d’[associer un Solo](#pairing). Le lien **Vous rencontrez un problème ?** de cette ligne ouvre la page [Lecteurs de cartes](../../hardware/card-readers/index.mdx).

<Anchor id="needs-a-connection" />

**La tuile SumUp n’est pas disponible hors ligne.** Les lecteurs de cartes attendent la connexion ; consultez [Paiements hors ligne](#offline-payments).

<Anchor id="no-card-readers" />

**« Aucun lecteur de cartes n’est configuré pour cette boutique ».** La passerelle de paiement n’est pas encore [configurée](#setup), donc **Lecteurs de cartes** affiche uniquement ce message :

<JourneyShot manifest={manifest} device="tablet" step={1} maxWidth={720} alt="Réglages avec Lecteurs de cartes sélectionné, sur une caisse dont la boutique n’a pas encore de lecteur de cartes configuré">

1. **Aucun lecteur de cartes n’est configuré pour cette boutique** — terminez la [configuration de la passerelle de paiement](#setup), puis [connectez le lecteur](#card-readers).

</JourneyShot>

Avec **Solo via le cloud**, vos Solo associés figurent sous **Lecteurs intelligents** dans **Lecteurs de cartes**, et non sur une ligne SumUp.

<Anchor id="no-terminals" />

**« Aucun terminal n’est configuré pour SumUp Terminal ».** Aucun Solo n’est associé, ou le réglage **Terminaux activés** n’en autorise aucun pour cette caisse. Consultez [Associer un Solo via le cloud](#pairing).

<Anchor id="payment-wont-start" />

**Le paiement ne démarre pas.** Ouvrez la page de la passerelle de paiement dans WP Admin. Elle doit afficher **Connecté à SumUp**. **Échec de la connexion** signifie que la **Clé API SumUp** est incorrecte ou n’est plus active. Vérifiez que le Solo est allumé, chargé, en ligne et répertorié sous **Lecteurs configurés**.

<Anchor id="affiliate-key" />

**« Un administrateur de la boutique doit saisir une clé d’affiliation SumUp… ».** La passerelle de paiement n’a pas de **Clé d’affiliation**, indispensable à un lecteur Bluetooth. Consultez [Configurer la passerelle de paiement](#setup), étape 3.

<Anchor id="card-declined" />

**La carte est refusée.** Demandez une autre carte ou un autre moyen de paiement.

**Toujours bloqué ?** Cochez **Journaux de débogage du paiement** et consultez l’activité des paiements dans `WooCommerce > Status > Journaux`, signalez un bug sur [GitHub](https://github.com/wcpos/sumup-terminal-for-woocommerce/issues) ou contactez l’assistance SumUp au sujet de votre compte ou de votre lecteur.
