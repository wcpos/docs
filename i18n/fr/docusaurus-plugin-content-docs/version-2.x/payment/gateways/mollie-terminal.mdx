:::info Fonctionnalité Pro
Mollie Terminal nécessite [WCPOS Pro](../../getting-started/pro-license.mdx) 2.0.0 ou une version ultérieure.
:::

Mollie Terminal envoie la vente depuis la caisse vers un terminal de paiement par carte [Mollie](https://www.mollie.com/products/point-of-sale). Le client paie sur le terminal et la vente se termine automatiquement sur la caisse. Il accepte uniquement l’**euro** et fonctionne uniquement dans le PDV : il n’est jamais proposé au moment du paiement sur votre boutique en ligne.

## Encaisser un paiement {#take-payment}

Un responsable [effectue la configuration](#setup) une seule fois, avec le terminal associé au compte Mollie de production de votre boutique. [Ouvrez la caisse](../../pos/register/index.mdx#open) avant de commencer.

:::warning
Lorsque l’option **Ouvrir et fermer la caisse** est activée, une caisse fermée ne peut pas enregistrer le paiement, et un paiement par carte déjà débité devrait être remboursé.
:::

1. Appuyez sur **Paiement**, puis sur la tuile **Mollie Terminal** dans le panneau des moyens de paiement.
2. Vérifiez le terminal dans le panneau des moyens de paiement : **Terminal :** suivi de son nom. Pour en utiliser un autre, appuyez sur **Modifier** et sélectionnez-le. **Modifier** n’apparaît pas si la boutique n’a qu’un seul terminal activé ou si elle verrouille le choix.
3. Appuyez sur **Envoyer … à Mollie Terminal**. Le montant est envoyé au terminal.
4. Le client présente, insère ou fait glisser sa carte sur le terminal. La caisse affiche **Sur le terminal** avec les étapes **Envoyé**, **Sur le terminal**, **Approuvé** et **Capturé**.
5. Lorsque Mollie confirme le paiement, la vente est réglée et le reçu est prêt, comme pour tout [paiement](../../pos/checkout/index.mdx#paid).

Chaque caisse mémorise le dernier terminal utilisé. Consultez [Sur un lecteur de carte](../../pos/checkout/taking-a-payment.mdx#card-reader).

Un pourboire ajouté par le client sur le terminal est enregistré sur la commande sous la forme d’une ligne **Pourboire**. Consultez [Pourboires](../../pos/checkout/tips.mdx).

### Annuler un paiement sur le terminal {#cancel}

Pendant que la caisse attend, appuyez sur **Annuler sur le terminal**. La caisse affiche **Annulation — en attente de confirmation du terminal**.

#### Paiement annulé ou refusé {#cancelled}

Après **Paiement annulé**, un refus ou **Délai dépassé — paiement annulé**, le paiement n’a pas abouti : appuyez sur **Réessayer** pour l’envoyer à nouveau, ou sur **Choisir un autre moyen** pour payer autrement.

#### Le terminal n’a pas confirmé {#not-confirmed}

Une fois que le client a commencé à payer, Mollie peut ne plus autoriser l’annulation depuis la caisse. Annulez sur le terminal lui-même.

Si la caisse n’obtient toujours pas de réponse, elle propose **Libérer ce paiement**.

:::warning Avant d’encaisser à nouveau
Regardez le terminal. S’il indique que le paiement est approuvé, **n’encaissez pas à nouveau** : la boutique poursuit les vérifications auprès de Mollie. En cas de doute, demandez à un responsable de vérifier le paiement dans le tableau de bord Mollie avant d’encaisser un autre paiement.
:::

**Libérer ce paiement** permet de payer la commande avec un autre moyen, et la caisse affiche **Paiement libéré**. Cela ne signifie pas que le paiement a été annulé : la boutique continue de vérifier le terminal.

### Dans l’onglet Ancien {#legacy-tab}

Vous pouvez aussi encaisser le paiement dans l’[onglet Ancien](../../pos/checkout/legacy-tab.mdx) de l’écran de paiement, qui affiche la page de paiement de la commande. Ouvrez l’onglet **Ancien** et choisissez **Mollie Terminal**. Le panneau affiché dépend de l’activation des **Paiements par code QR** par un responsable.

**Si le panneau affiche Terminal et Code QR**, restez sur **Terminal** et appuyez sur **Démarrer le paiement sur le terminal**. Appuyez sur **Annuler le paiement sur le terminal** pour arrêter. Pour afficher un code à la place, consultez [Payer par code QR](#qr-code).

**Sinon :**

1. Sélectionnez le terminal si le panneau le demande.
2. Appuyez sur **Envoyer … à** suivi du nom du terminal. Le panneau affiche les mêmes étapes que la tuile.
3. Pour arrêter, appuyez sur **Annuler sur le terminal**, comme dans [Annuler un paiement](#cancel). Après l’arrêt, **Réessayer** l’envoie à nouveau. Le PDV enregistre ce paiement comme depuis la tuile.

## Payer par code QR {#qr-code}

Aux Pays-Bas et en Belgique, le client peut payer en scannant un code QR iDEAL ou Bancontact avec son application bancaire au lieu d’utiliser le terminal. Un responsable doit d’abord activer ces moyens de paiement sous **Paiements par code QR** dans [les réglages](#settings).

1. Au moment du paiement, ouvrez l’[onglet Ancien](../../pos/checkout/legacy-tab.mdx) et choisissez **Mollie Terminal**.
2. Dans le panneau de paiement, passez de **Terminal** à **Code QR**.
3. Choisissez **iDEAL** ou **Bancontact** si les deux sont activés, puis appuyez sur **Afficher le code QR**.
4. Le client le scanne et paie sur son téléphone. La vente se termine comme avec le terminal.

Bancontact accepte au maximum €1,500.00 par paiement QR ; utilisez le terminal pour les montants supérieurs.

## Remboursements {#refunds}

Remboursez une vente Mollie Terminal depuis le PDV en choisissant **Rembourser via Mollie Terminal**, ou depuis l’écran de commande WooCommerce. L’argent est remboursé via Mollie, en totalité ou en partie. Consultez [Remboursements](../../pos/refunds.mdx#destination).

Un remboursement Mollie est d’abord En attente de paiement. WCPOS Pro le vérifie auprès de Mollie toutes les dix minutes, puis le marque comme remboursée ou échouée et ajoute une note à la commande.

## En cas de problème {#goes-wrong}

### Le client a déjà payé : n’encaissez pas à nouveau {#already-paid}

**Le client a payé, mais la caisse attend toujours.** **N’encaissez pas à nouveau.** Restez sur cet écran : la vente se termine lorsque Mollie confirme le paiement. Sinon, demandez à un responsable de vérifier le paiement dans le tableau de bord Mollie.

**« Un paiement Mollie antérieur pour cette vente a été réglé ».** Un paiement pour cette vente a déjà abouti chez Mollie, mais ne figure pas encore sur la commande. **N’encaissez pas à nouveau.** Attendez quelques minutes et rechargez. Si le message indique que le paiement ne correspond pas à la commande, un responsable doit d’abord le vérifier dans le tableau de bord Mollie.

### Autres problèmes {#other-problems}

**« Aucun terminal configuré pour Mollie Terminal ».** La boutique n’a aucun terminal actif à proposer. Un responsable vérifie que **Mode** est sur **Production**, avec une clé de production, et que le terminal est actif sur ce compte Mollie.

**« Utilisé par la commande #… ».** Ce terminal est occupé par une autre vente. Choisissez un autre terminal ou terminez ou annulez d’abord l’autre vente.

**« Connexion nécessaire ».** La caisse est hors ligne. Mollie Terminal fonctionne uniquement en ligne : encaissez le paiement autrement ou attendez le rétablissement de la connexion.

**« Délai dépassé — paiement annulé ».** Personne n’a payé à temps, le paiement a donc été annulé. Vérifiez que le terminal est allumé et connecté, puis appuyez sur **Réessayer** ou **Choisir un autre moyen**.

**Une vente dans une autre devise est refusée.** Mollie Terminal accepte uniquement l’euro.

**Toujours bloqué ?** Signalez un problème avec l’extension sur [GitHub](https://github.com/wcpos/mollie-terminal-for-woocommerce/issues). Pour votre compte Mollie ou le terminal lui-même, contactez l’assistance Mollie ou consultez le [guide de configuration des terminaux](https://docs.mollie.com/docs/setting-up-terminal) de Mollie.

<details>
<summary>Comment la caisse et la boutique suivent les paiements auprès de Mollie</summary>

- Pendant l’attente d’un paiement, la page de paiement interroge Mollie toutes les deux secondes, et le message envoyé par Mollie à votre boutique le confirme généralement plus tôt. Vous n’avez rien à configurer pour ce message.
- Chaque mise à jour est vérifiée auprès de Mollie avant toute modification de la commande, afin que celle-ci reflète les informations de Mollie.
- Si une requête de remboursement reste sans réponse, l’extension recherche le remboursement déjà effectué par Mollie avant d’en créer un autre.
- Dans l’onglet Ancien, lorsque les **Paiements par code QR** sont activés, le panneau de l’extension gère le paiement. Il annule un paiement resté ouvert chez Mollie si personne ne paie dans les cinq minutes, si la commande est payée autrement ou annulée dans WooCommerce, ou si la page de paiement est fermée pendant le paiement. Une vérification toutes les dix minutes annule tout paiement encore ouvert après dix minutes sur une commande impayée.
- Un paiement déjà reçu par le terminal ne peut pas être annulé depuis la boutique : annulez-le sur le terminal.
- Pour le dépannage, chaque paiement est journalisé dans `WooCommerce > Status > Journaux`. Un responsable y recherche les messages de Mollie lorsqu’une vente ne se termine pas.

</details>

## Configuration {#setup}

Un responsable effectue cette opération une seule fois, dans WP Admin. Vous avez besoin de WCPOS Pro 2.0.0 ou d’une version ultérieure, d’un compte Mollie de production avec le moyen de paiement **Point de vente** activé, et de l’euro comme devise de la boutique.

<details>
<summary>Configuration par le responsable : installation, clé, terminaux, activation</summary>

L’extension nécessite WCPOS Pro 2.0.0 ou une version ultérieure : sans cela, elle ne fonctionne pas et affiche un avis dans WP Admin.

:::note Avant de commencer
Dans l’application web Mollie, activez le moyen de paiement **Point de vente** pour votre profil et achetez-y vos terminaux. Mollie vend des terminaux aux Pays-Bas, en Belgique, en Allemagne, en France et au Royaume-Uni, et peut demander une vérification préalable de votre compte. Les terminaux n’existent que sur un compte de **production** : vous avez donc besoin de votre clé API de production.
:::

1. **Installez l’extension.** Ouvrez `POS Settings > Extensions` et installez **Mollie Terminal**, ou téléversez le zip de la version disponible sur [GitHub](https://github.com/wcpos/mollie-terminal-for-woocommerce/releases) dans `Extensions > Add Plugin`, puis **Téléverser une extension**. Utilisez le zip joint à la version, et non l’archive du code source. Consultez [Extensions](../../extensions/index.mdx#installing-an-extension).
2. **Ajoutez votre clé.** Accédez à `WooCommerce > Réglages > Paiements > Mollie Terminal`. Réglez **Mode** sur **Production**, puis collez votre clé de production dans **Clé API Mollie** ou réglez **Source de la clé API** pour réutiliser la clé de l’extension Mollie Payments for WooCommerce. Enregistrez.
3. **Choisissez vos terminaux.** Une fois la clé enregistrée, les terminaux de votre compte Mollie s’affichent. Sélectionnez un **Terminal par défaut**. Si certains terminaux ne doivent pas être utilisés en caisse, indiquez ceux qui doivent l’être dans **Terminaux activés**. Enregistrez.
4. **Activez la passerelle pour le PDV.** Accédez à `POS > Réglages > Validation de la commande` et activez **Mollie Terminal**. C’est le seul interrupteur d’activation. Consultez [Activer une passerelle](../../settings/wp-admin/checkout.mdx#enabling-a-gateway).

Aucun webhook n’est à configurer dans le tableau de bord Mollie et aucun ID de profil n’est à coller : l’extension envoie l’adresse de son webhook avec chaque paiement et répertorie les terminaux de l’ensemble de votre compte.

Si la liste **Terminal par défaut** reste vide, vérifiez que **Mode** est sur **Production** avec votre clé de production (les terminaux n’existent pas sur un compte de test), que le terminal est actif dans Mollie et que votre site peut joindre Mollie.

</details>

### Les réglages {#settings}

<details>
<summary>Tous les réglages de l’écran Mollie Terminal</summary>

Tous ces réglages se trouvent dans `WooCommerce > Réglages > Paiements > Mollie Terminal`.

| Réglage | Fonction |
|---|---|
| **Titre** | Le nom affiché sur la tuile en caisse. Par défaut : « Mollie Terminal ». |
| **Description** | Texte affiché avec le moyen de paiement sur la page de paiement de la commande. |
| **Mode** | **Test** ou **Production**. Réglé par défaut sur **Test**, qui affiche un avertissement : la clé de test ne peut pas piloter un terminal. Utilisez **Production** pour encaisser des paiements. |
| **Source de la clé API** | **Utiliser la clé saisie ci-dessous** ou **Réutiliser la clé de l’extension officielle Mollie** (la clé de test ou de production correspondant au **Mode**). Si aucune clé n’est définie dans l’extension Mollie, la clé ci-dessous est utilisée. |
| **Clé API Mollie** | Votre clé pour le mode sélectionné. Ignorée si la source de la clé réutilise celle de l’extension Mollie. |
| **Terminal par défaut** | Le terminal utilisé initialement par une caisse. La liste est récupérée directement depuis votre compte Mollie ; les terminaux inactifs sont masqués, car Mollie ne peut pas les réactiver. |
| **Terminaux activés** | Seuls ces terminaux peuvent être choisis en caisse. Un champ vide autorise tous les terminaux actifs. Le terminal par défaut est toujours proposé : changez-le aussi lorsque vous retirez un terminal du service. Ce réglage est masqué si la liste des terminaux ne peut pas être chargée ; votre choix enregistré est conservé. |
| **Paiements par code QR** | **iDEAL** et **Bancontact** : permettent au caissier d’afficher un code QR à l’écran à la place. Chacun doit être actif sur votre profil Mollie. iDEAL QR fonctionne aussi en mode **Test**, ce qui permet de l’essayer sans terminal ; Bancontact QR nécessite le mode **Production**. Consultez [Payer par code QR](#qr-code). |
| **Verrouiller la sélection du terminal** | La caisse utilise toujours le terminal par défaut et le caissier ne peut pas le changer. Nécessite un **Terminal par défaut**. |
| **Journaux de débogage du paiement** | Affiche **Afficher les journaux**, **Copier** et **Effacer** sur le panneau de paiement. Laissez cette option désactivée sauf si l’assistance vous le demande : les paiements sont toujours journalisés dans `WooCommerce > Status > Journaux`. |

</details>
