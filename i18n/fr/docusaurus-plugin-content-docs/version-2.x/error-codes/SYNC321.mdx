## Signification {#what-this-means}

Certaines données n’ont pas été synchronisées cette fois-ci.

Ce code apparaît sous deux formes — le titre de la ligne du journal indique laquelle vous concerne :

- **« Synchronisation partielle »** (titres des enregistrements) : certains enregistrements ont été synchronisés, mais pas ceux qui sont nommés. Vous n’avez rien à faire si la prochaine synchronisation résout le problème. Si **État de la boutique → Base de données** répertorie des modifications nécessitant votre attention, traitez-les à cet endroit.
- **« Abandon d’une requête de données bloquée »** : le traitement des requêtes de données du moteur de synchronisation n’avançait plus sur une requête. Après une longue attente, l’application a donc abandonné cette requête pour éviter qu’elle ne bloque toutes les suivantes dans la file. Vous n’avez rien à relancer manuellement — le moteur de synchronisation émet à nouveau la requête automatiquement. Cela fait souvent suite à un appel bloqué à la base de données locale, consigné séparément sous le code [SYNC181](/error-codes/SYNC181).

## Vos données {#your-data}

N’effacez pas les données de cet appareil — il peut contenir des modifications que votre boutique n’a pas encore reçues. Dans le cas d’une requête de données abandonnée, rien n’a été modifié — la requête abandonnée est émise à nouveau automatiquement. Si cela se reproduit régulièrement, utilisez **Copier les informations de débogage** dans l’onglet **Journaux** et contactez l’assistance WCPOS.

## Dépannage {#troubleshoot}

1. Pour une entrée **« Abandon d’une requête de données bloquée »**, aucune action n’est nécessaire, sauf si un écran reste bloqué. Dans ce cas, rechargez l’application — rechargez l’onglet du navigateur sur le web, ou fermez puis rouvrez l’application sur ordinateur et mobile.
2. Pour une synchronisation partielle, vous n’avez rien à faire si la prochaine synchronisation résout le problème. Sinon, ouvrez **État de la boutique → Base de données** : les enregistrements qui n’ont toujours pas été synchronisés apparaissent en haut. L’encadré **« … enregistrements nécessitent votre attention »** indique le premier et la raison du problème (corrigez-le pour afficher le suivant). Les panneaux **« … modifications ne sont jamais parvenues à votre serveur »** et **« … modifications ont été retenues »** répertorient les enregistrements correspondants. Ceux qui ont été synchronisés ne nécessitent aucune intervention.
3. Traitez chaque enregistrement répertorié selon la raison indiquée. Dans l’encadré, **Corriger l’enregistrement** (lorsque ce bouton est affiché) ouvre l’enregistrement pour le modifier ; une modification refusée se corrige directement dans l’enregistrement ([SYNC201](/error-codes/SYNC201)) ; pour une modification retenue, choisissez la version à conserver ([SYNC221](/error-codes/SYNC221)).
4. Renvoyez-les ensuite : utilisez **Réessayer** dans l’encadré (cela lance une synchronisation), ou **Envoyer à nouveau** sur la ligne de l’enregistrement dans les panneaux. Un enregistrement que l’encadré indique comme *impossible à télécharger depuis votre boutique* ne dispose pas du bouton **Réessayer** — voir [SYNC331](/error-codes/SYNC331).
5. Si un enregistrement ne se synchronise toujours pas, utilisez **Copier les informations de débogage** dans l’onglet **Journaux** et contactez l’assistance.
