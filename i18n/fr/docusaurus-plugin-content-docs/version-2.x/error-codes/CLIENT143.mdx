## Ce que cela signifie {#what-this-means}

La recherche n’a pas trouvé un produit qu’elle aurait dû trouver.

Vous n’avez rien à faire, sauf si un produit visible reste introuvable dans la recherche ; dans ce cas, rechargez WCPOS.

Un contrôle automatique périodique a interrogé l’index de recherche local avec les mots d’un enregistrement, mais l’index ne l’a pas renvoyé. Les recherches ont donc pu afficher moins de résultats que l’appareil n’en contient réellement. L’application peut reconstruire l’index d’elle-même, mais une seule fois par liste et par session : cette reconstruction n’est donc pas garantie.

## Vos données {#your-data}

Aucune donnée de la boutique n’a été modifiée. Seul l’index de recherche local est concerné ; il est créé à partir des données déjà présentes sur cet appareil. Sa reconstruction n’entraîne aucune perte.

## Dépannage {#troubleshoot}

1. Vous n’avez rien à faire, sauf si un produit visible reste introuvable dans la recherche ; les ventes peuvent continuer normalement. L’application peut reconstruire l’index d’elle-même, mais une seule fois par liste et par session. Si ce code se répète, passez donc à l’étape suivante.
2. Si la recherche ne trouve toujours pas des enregistrements visibles dans l’application — dans une liste de produits, de clients, de commandes ou autre — rechargez l’application : sur le web, rechargez l’onglet du navigateur ; sur ordinateur et mobile, fermez puis rouvrez l’application. Elle pourra ainsi tenter une nouvelle reconstruction lors de la prochaine détection du problème.
3. Si le code réapparaît après un rechargement, utilisez **Copier les informations de débogage** dans l’onglet **Journaux** et contactez l’assistance. L’entrée du journal contient les détails dont l’assistance a besoin pour identifier la liste concernée et l’enregistrement manquant dans l’index.
