## Signification {#what-this-means}

L’adresse de la boutique est manquante ou n’est pas une URL valide.

Soit le champ d’adresse était vide, soit votre boutique a répondu mais son adresse de connexion WCPOS n’est pas valide. Dans ce dernier cas, le problème doit être corrigé sur la boutique, pas sur la caisse.

## Vos données {#your-data}

Aucune donnée de commande ou de produit n’est affectée.

## Dépannage {#troubleshoot}

1. Saisissez l’adresse de la boutique dans **Saisissez l’URL de votre boutique WooCommerce** — par exemple `shop.example.com` — puis appuyez sur **Connecter**. Un champ ne contenant que des espaces est considéré comme vide.
2. Si l’adresse est renseignée et que le message indique **« L’URL de connexion WCPOS n’est pas valide. Veuillez vérifier que l’extension WCPOS est correctement configurée »**, le problème se situe sur la boutique. **Administrateur du site :** mettez WCPOS à jour vers la dernière version dans **WP Admin → Extensions**, puis appuyez à nouveau sur **Connecter**. Ne désactivez pas l’extension pour la réactiver ensuite dans le but de résoudre ce problème : la réactivation rétablit les autorisations PDV par défaut de tous les rôles.
3. **Administrateur du site :** si cela ne résout pas le problème, ouvrez dans un navigateur l’adresse complète de la boutique suivie de `/wp-json/` — par exemple `https://your-store.com/wp-json/`, ou `https://example.com/shop/wp-json/` si WordPress se trouve dans `/shop`. Si cela renvoie une erreur 404 (par exemple avec des permaliens simples), utilisez plutôt la même adresse suivie de `/?rest_route=/`. Sous `authentication` → `wcpos` → `endpoints`, `authorization` doit être une simple adresse Web. S’il s’agit d’une liste, d’un objet ou d’un nombre, une extension de sécurité, de mise en cache ou de personnalisation REST modifie cette réponse : désactivez ces extensions une par une sur une copie de préproduction pour trouver celle qui est en cause.
