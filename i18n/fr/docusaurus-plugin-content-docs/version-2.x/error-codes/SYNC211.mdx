## Signification {#what-this-means}

Votre boutique a refusé une valeur qui lui a été envoyée.

Le motif fourni par la boutique indique la valeur concernée. Corrigez-la là où vous l’avez saisie, puis enregistrez à nouveau. Cette valeur appartient généralement à un enregistrement — produit, client ou commande —, mais ce code peut aussi provenir d’une requête de réglages ou de connexion refusée par la boutique ; corrigez alors la valeur sur cet écran.

## Vos données {#your-data}

N’effacez pas les données de cet appareil : il peut contenir des modifications que votre boutique n’a pas encore reçues. Une modification refusée portant sur un produit, une variation, un client ou un coupon existant est généralement annulée automatiquement et consignée sous le code [SYNC202](/error-codes/SYNC202). Si elle apparaît sous ce code-ci et figure dans **État de santé de la boutique → Base de données**, l’annulation automatique n’a pas eu lieu : traitez-la comme toute autre modification répertoriée. Une requête de réglages ou de connexion ne laisse rien à sauvegarder.

## Dépannage {#troubleshoot}

1. Développez l’entrée du journal et lisez le motif fourni par la boutique ainsi que le point de terminaison : le motif indique la valeur, et le point de terminaison permet de savoir si elle provient d’un enregistrement ou d’une requête de réglages ou de connexion.
2. Corrigez la valeur là où vous l’avez saisie — les causes courantes sont une valeur hors limites, un format rejeté ou une option obligatoire laissée vide —, puis enregistrez à nouveau. Si la modification ne figure pas dans **État de santé de la boutique → Base de données**, la version de la boutique a été restaurée : effectuez donc à nouveau la modification avec la valeur corrigée. Si elle figure encore sous **« … modifications ne sont jamais parvenues à votre serveur »** dans **État de santé de la boutique → Base de données** après la correction, appuyez sur **Renvoyer** sur sa ligne.
3. Si l’enregistrement figure plutôt sous **« … modifications ont été mises en attente »** avec le message *« Votre boutique exigeait une version à jour »*, aucune valeur n’est en cause : choisissez entre **Renvoyer** et **Abandonner la modification de l’appareil**, comme décrit dans [SYNC221](/error-codes/SYNC221).
4. S’il s’agissait d’une requête de réglages ou de connexion, corrigez la valeur sur l’écran où vous l’avez saisie et enregistrez à nouveau. **Administrateur du site :** les outils de développement du navigateur (onglet Réseau), ou **Avancé → Afficher/masquer les outils de développement** dans l’application de bureau, affichent la réponse de la boutique lorsque les détails ne figurent pas dans le journal du PDV.
5. **Administrateur du site :** si une valeur indiquée semble correcte dans le PDV, comparez-la avec le même enregistrement dans WP Admin : une validation ajoutée par une extension sur la boutique peut rejeter des valeurs que le PDV considère comme valides.
