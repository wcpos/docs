## Ce que cela signifie {#what-this-means}

Le serveur bloque la vérification d’autorisation du navigateur (requête préliminaire CORS) ; l’application web ne peut donc pas le joindre.

Les navigateurs envoient une requête OPTIONS avant tout appel d’API interorigine comportant des en-têtes personnalisés. Un élément placé devant cette boutique — généralement une règle de pare-feu — bloque OPTIONS ; le navigateur n’envoie donc jamais la véritable requête. Les applications natives ne sont pas affectées ; la correction doit être effectuée côté serveur.

## Vos données {#your-data}

Aucune donnée de commande ou de produit n’est affectée.

## Dépannage {#troubleshoot}

1. Recherchez dans le pare-feu (WAF) une règle bloquant la méthode OPTIONS et autorisez-la sur les routes REST /wcpos/.
2. Certaines extensions de sécurité proposent une option « bloquer les méthodes de requête inhabituelles » ; OPTIONS doit rester autorisée.
3. Test : une requête OPTIONS vers l’API REST de la boutique ne doit pas renvoyer 403.
4. Les applications pour ordinateur et mobile n’utilisent pas CORS et continueront de fonctionner pendant la résolution du problème.
