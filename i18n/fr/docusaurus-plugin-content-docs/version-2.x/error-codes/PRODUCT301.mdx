## Ce que cela signifie {#what-this-means}

Un scan ou une recherche saisie n'a trouvé aucun produit correspondant.

Les causes habituelles sont un filtre actif, un code-barres manquant ou enregistré dans un autre champ, ou une première synchronisation qui n'est pas terminée.

## Vos données {#your-data}

Aucune donnée de commande ou de produit n'est affectée.

## Dépannage {#troubleshoot}

**À la caisse :**

1. Effacez d'abord les filtres : un filtre de catégorie ou de stock restreint chaque recherche sans avertissement (un code scanné est saisi dans le même champ de recherche).
2. Recherchez le produit par son nom. S'il apparaît alors que le scan ne l'a pas trouvé, son code-barres dans la boutique ne correspond pas à la valeur scannée. Si vous avez saisi la recherche, vérifiez l'orthographe et les espaces superflus.
3. Si le produit vient d'être créé, l'index local est peut-être encore en cours de synchronisation : laissez la première synchronisation se terminer, puis réessayez.

**Côté boutique :**

- Si le code-barres est manquant, ajoutez la valeur scannée dans WP Admin, dans le champ indiqué par **Champ du code-barres** (ci-dessous). Pour un article avec des variations (tailles, couleurs), renseignez-la sur la variation elle-même — modifiez le produit et développez la variation — et non sur le produit parent.
- Si aucun scan ne trouve de produit, la boutique cherche peut-être dans le mauvais champ. Vérifiez **WP Admin > PDV > Réglages > Général > Champ du code-barres** : ce réglage doit désigner le champ dans lequel vos produits stockent réellement leurs codes-barres (par exemple `_global_unique_id` pour le GTIN, `_sku` ou `_barcode`).
