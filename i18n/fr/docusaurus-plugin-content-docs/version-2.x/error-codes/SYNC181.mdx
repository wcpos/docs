## Signification {#what-this-means}

L’enregistrement ou le chargement sur cet appareil est très lent, et son résultat n’est pas encore connu.

Vous n’avez rien à faire si WCPOS fonctionne. Si un écran reste bloqué, rechargez WCPOS, puis vérifiez que votre dernière modification a été enregistrée.

Une seule opération de lecture ou d’écriture dans la base de données locale de cet appareil est restée sans réponse bien plus longtemps que la normale, alors que la base continue de répondre à toutes les autres opérations. Ce mécanisme de signalement se contente de consigner le blocage : il n’annule pas l’opération et ne la relance pas. L’appel initial peut donc encore aboutir ou échouer plus tard ; cette entrée permet qu’un écran ou un indicateur de chargement bloqué laisse une trace indiquant précisément l’opération concernée. Les opérations de synchronisation bloquées disposent d’un délai d’expiration et d’un mécanisme de nouvelle tentative distincts, consignés sous la forme d’une entrée « Abandon d’une requête de données bloquée » avec le code [SYNC321](/error-codes/SYNC321). Un appel bloqué provenant d’un écran reste en attente jusqu’à ce qu’il se termine ou que l’application soit rechargée.

## Vos données {#your-data}

Le résultat n’a pas pu être confirmé : vérifiez-le avant de réessayer. L’opération bloquée est généralement une recherche, qui ne modifie rien. Si une modification était en cours d’enregistrement à ce moment-là, ouvrez l’enregistrement concerné et vérifiez qu’elle a été sauvegardée ; il se peut qu’aucun symptôme n’ait été visible. Le contexte de l’entrée indique l’opération et la collection de données concernées.

## Dépannage {#troubleshoot}

1. Si WCPOS fonctionne, vous n’avez rien à faire : l’appel a très probablement abouti, simplement avec du retard. Si l’opération indiquée dans l’entrée était une sauvegarde, ouvrez l’enregistrement et vérifiez qu’elle a bien été effectuée.
2. Si un écran ou un indicateur de chargement reste bloqué, rechargez l’application : sur le web, rechargez l’onglet du navigateur ; sur ordinateur et mobile, fermez puis rouvrez l’application. Cela abandonne l’opération bloquée ; l’écran se recharge et interroge à nouveau la base de données. Une sauvegarde en cours n’est pas renvoyée : ouvrez l’enregistrement et vérifiez qu’elle a bien été effectuée.
3. Si ce code revient régulièrement sur le même appareil, utilisez **Copier les informations de débogage** dans l’onglet **Journaux** et contactez l’assistance : le contexte de l’entrée indique l’opération et la collection, la durée exacte de l’attente et le niveau d’activité de la base de données pendant ce temps.
