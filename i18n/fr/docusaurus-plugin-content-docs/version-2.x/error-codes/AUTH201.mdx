## Ce que cela signifie {#what-this-means}

Votre compte n’a pas l’autorisation d’effectuer cette action.

Rien n’a été perdu. Demandez à l’administrateur de votre boutique d’autoriser cette action pour votre rôle utilisateur, puis réessayez.

## Vos données {#your-data}

Rien n’a été perdu : aucune donnée de commande ou de produit n’est affectée.

## Dépannage {#troubleshoot}

1. **À la caisse :** notez ce que vous faisiez lors du refus (modification d’un produit, d’un client ou d’une commande) et le compte connecté. Si le refus est apparu de lui-même pendant la synchronisation, transmettez simplement l’entrée correspondante dans **État de la boutique → Journaux** : elle consigne la requête refusée. Communiquez ces informations à votre administrateur ; vous pouvez continuer à vendre en attendant si l’action refusée ne faisait pas partie de la vente.
2. **Administrateur du site :** déterminez d’abord si ce compte doit être autorisé à effectuer cette action. Si ce n’est pas le cas, le refus est normal : ne modifiez pas le rôle et faites effectuer l’action avec un compte autorisé. Si le compte doit y être autorisé, ouvrez **WP Admin > PDV > Réglages > Accès** et sélectionnez le rôle du compte. Sous **Ce qu’un Caissier peut faire** (le titre indique le rôle), cochez la tâche correspondant à l’action refusée : **Utiliser le PDV**, **Créer et modifier des produits**, **Gérer les commandes**, **Gérer les clients**, etc. Un tiret accompagné d’un indicateur tel que **3 sur 7** signifie que la tâche n’est que partiellement autorisée ; la cocher accorde les autorisations restantes. **Rétablir les valeurs par défaut** rétablit les autorisations qu’une nouvelle installation accorde au rôle. Pour un rôle personnalisé, WCPOS n’accorde aucun accès au PDV par défaut ; cette option lui retire donc l’accès au PDV.
3. **Administrateur du site :** si le compte peut se connecter mais que toutes les requêtes concernant les produits, les clients ou les commandes sont refusées, vérifiez s’il possède **plusieurs rôles**. Les extensions de gestion des rôles telles que Members appliquent un *Refuser* défini sur l’un des rôles à l’ensemble du compte : un Administrateur également Client perd donc toutes les autorisations refusées au rôle Client. Supprimez le rôle supplémentaire ou retirez les marques *Refuser* ; consultez [Un utilisateur avec plusieurs rôles](/manage-store/staff-permissions#more-than-one-role).
4. **De retour à la caisse :** déconnectez-vous, puis reconnectez-vous pour appliquer les nouvelles autorisations, et réessayez l’action refusée.
