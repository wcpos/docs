## Signification {#what-this-means}

Le serveur de la boutique bloque le jeton de connexion sur tous les canaux que cette application peut utiliser.

L’application a confirmé que la boutique est joignable, mais le serveur (ou un pare-feu, un proxy ou une extension de sécurité placé en amont) supprime l’en-tête Authorization et bloque aussi le jeton lorsqu’il est envoyé comme paramètre d’URL. Il n’existe pas de troisième moyen de transmettre un jeton de connexion : le problème doit donc être corrigé sur le serveur.

## Vos données {#your-data}

Aucune donnée de commande ou de produit n’est affectée.

## Dépannage {#troubleshoot}

**Pour votre hébergeur / serveur** — le jeton de connexion ne peut être transmis par aucun canal tant que le serveur ne le laisse pas passer :

1. Autorisez la transmission de l’en-tête Authorization à WordPress ; sur Apache, une seule ligne suffit généralement : `SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1`.
2. Si le site utilise des réécritures dans `.htaccess`, conservez la ligne RewriteRule générée par WordPress qui transmet `HTTP_AUTHORIZATION` : les extensions de sécurité la suppriment parfois.
3. Si le serveur est derrière un proxy ou un CDN, vérifiez sa liste d’en-têtes autorisés : l’en-tête de requête Authorization doit être transmis au serveur d’origine.
4. Si un pare-feu d’application Web (WAF) filtre les paramètres d’URL, autorisez le paramètre authorization sur les routes REST `/wcpos/`.
