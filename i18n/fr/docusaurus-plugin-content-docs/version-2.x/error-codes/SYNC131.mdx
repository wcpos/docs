## Signification {#what-this-means}

Votre boutique a rencontré une erreur et n’a pas terminé cette requête.

La boutique a été jointe, mais son serveur n’a pas pu traiter la requête : le problème concerne le site web plutôt que le PDV. Réessayez l’action. Si le problème persiste, demandez à l’administrateur du site de consulter **WooCommerce → État → Journaux**. Rien n’a été perdu sur cet appareil.

## Vos données {#your-data}

N’effacez pas les données de cet appareil : il peut contenir des modifications que votre boutique n’a pas encore reçues. Une modification en cours d’envoi n’est peut-être pas parvenue à votre boutique. Si le problème persiste, utilisez **Copier les informations de débogage** dans l’onglet **Journaux** et contactez l’assistance WCPOS.

## Dépannage {#troubleshoot}

**Sur le PDV (caissier) :** développez l’entrée du journal et notez le statut, le point de terminaison et serverCode : ils indiquent ce que faisait le serveur au moment de l’échec.

**Sur le site web (administrateur du site / hébergeur) :**

1. Ouvrez WooCommerce → État → Journaux sur le site et consultez le journal fatal-errors le plus récent autour de l’heure de l’échec ; une réponse de la classe 500 y laisse presque toujours une erreur PHP.
2. Si le problème est apparu après la mise à jour d’une extension, d’un thème ou de PHP sur le site, examinez d’abord ce changement et revenez à la version précédente ou désactivez l’élément concerné.
3. Si les journaux de WooCommerce ne montrent rien, demandez à l’hébergeur le journal des erreurs PHP du serveur pour la même période.

**Puis, de retour sur le PDV :** réessayez l’action.
