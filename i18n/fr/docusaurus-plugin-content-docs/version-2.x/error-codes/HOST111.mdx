## Ce que cela signifie {#what-this-means}

La configuration interorigine (CORS) du serveur est incorrecte ; le navigateur refuse donc ses réponses.

La boutique répond, mais ses en-têtes de réponse CORS sont incorrects : ils sont dupliqués, définissent une mauvaise origine ou sont absents des réponses d’erreur. Le navigateur masque alors la véritable réponse à l’application web, ce qui dissimule aussi toutes les autres erreurs derrière une erreur réseau générique. La correction doit être effectuée côté serveur : exactement un en-tête Access-Control-Allow-Origin, présent pour chaque code d’état.

## Vos données {#your-data}

Aucune donnée de commande ou de produit n’est affectée.

## Dépannage {#troubleshoot}

1. Recherchez une seconde couche CORS (une extension ET la configuration du serveur qui ajoutent toutes deux des en-têtes) et supprimez-en une : un en-tête Access-Control-Allow-Origin dupliqué provoque une erreur bloquante dans le navigateur.
2. Sur nginx, les lignes add_header ne s’appliquent pas aux réponses d’erreur sauf si elles se terminent par 'always' ; les en-têtes CORS doivent aussi être présents sur les réponses 4xx/5xx.
3. Si un CDN ou un proxy ajoute des en-têtes CORS, assurez-vous qu’ils n’entrent pas en conflit avec ceux de WordPress.
4. Les applications pour ordinateur et mobile n’utilisent pas CORS et continueront de fonctionner pendant la résolution du problème.
