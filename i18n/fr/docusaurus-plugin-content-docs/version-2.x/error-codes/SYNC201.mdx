## Signification {#what-this-means}

Votre boutique a refusé cette modification ; elle ne lui est donc pas parvenue.

Lisez le motif fourni par la boutique. Si la modification figure dans **État de santé de la boutique → Base de données**, corrigez l’enregistrement et appuyez sur **Renvoyer**, ou abandonnez-la avec **Abandonner**. Sinon, la version de la boutique a été restaurée : effectuez à nouveau la modification si elle est toujours nécessaire (voir [SYNC202](/error-codes/SYNC202)). Une modification refusée n’est jamais renvoyée automatiquement.

## Vos données {#your-data}

N’effacez pas les données de cet appareil : il peut contenir des modifications que votre boutique n’a pas encore reçues. Une modification refusée figurant dans **État de santé de la boutique → Base de données** y reste jusqu’à ce que vous la renvoyiez ou l’abandonniez. Une modification refusée portant sur un produit, une variation, un client ou un coupon existant est généralement annulée automatiquement et consignée sous le code [SYNC202](/error-codes/SYNC202). Si elle apparaît sous ce code-ci et figure dans **État de santé de la boutique → Base de données**, l’annulation automatique n’a pas eu lieu : traitez-la comme toute autre modification répertoriée ci-dessous. Si le problème persiste, utilisez **Copier les informations de débogage** dans l’onglet **Journaux** et contactez l’assistance WCPOS.

## Dépannage {#troubleshoot}

1. Lisez le motif fourni par la boutique : il figure dans l’entrée du journal et sur la ligne de la modification dans **État de santé de la boutique → Base de données**.
2. Ouvrez **État de santé de la boutique → Base de données**. Si la modification n’y figure pas, la version de la boutique a déjà été restaurée sur cet appareil et il n’y a rien à envoyer ; consultez [SYNC202](/error-codes/SYNC202). Corrigez le problème indiqué dans le motif, puis effectuez à nouveau la modification si elle est toujours nécessaire.
3. Si elle figure dans la liste — une commande, un enregistrement créé sur cet appareil ou une modification du catalogue dont l’annulation automatique n’a pas eu lieu —, la modification refusée se trouve sous **« … modifications ne sont jamais parvenues à votre serveur »**, avec le motif fourni par votre boutique sur sa ligne. Corrigez le problème indiqué directement dans l’enregistrement, par exemple un champ de la commande, tandis que la modification reste dans la liste.
4. Revenez dans **État de santé de la boutique → Base de données** et appuyez sur **Renvoyer** sur cette ligne. La modification est reconstituée à partir des données actuellement présentes sur cet appareil, puis envoyée.
5. Si vous ne souhaitez plus conserver la modification, appuyez plutôt sur **Abandonner** : la version de la boutique est conservée. Lisez d’abord la confirmation : si la boutique n’a jamais sauvegardé cet enregistrement, l’abandon le supprime de cet appareil.
6. **Administrateur du site :** si le motif indique que l’utilisateur n’est pas autorisé à effectuer la modification, son rôle ne lui accorde pas cette permission ; consultez [AUTH201](/error-codes/AUTH201). Si le motif mentionne un champ que le PDV n’affiche pas, ouvrez le même enregistrement dans WP Admin : une autre extension peut ajouter une validation invisible pour le PDV. Si la modification est toujours refusée, utilisez **Copier les informations de débogage** dans l’onglet **Journaux** et contactez l’assistance.
