**WP Admin :** activez le bouton **Reçu** pour les commandes en ligne dans `WP Admin → POS → Settings → General`.

:::note Cette page s’adresse à la personne qui gère le site web
Avec [WCPOS Pro](../getting-started/pro-license.mdx), vous pouvez imprimer ou envoyer par e-mail un reçu à la caisse pour n’importe quelle commande, y compris les commandes en ligne : consultez [Réimprimer un reçu](../orders/index.mdx#receipt-reprinting) sur la page **Commandes**.
:::

:::tip Si un client demande le reçu de sa commande en ligne
Une fois cette fonction configurée sur le site, le client peut utiliser le bouton **Reçu** dans **Mon compte → Commandes**, ou un lien vers le reçu sur sa page de confirmation de commande, si la boutique en a ajouté un.
:::

Vos modèles de reçus WCPOS fonctionnent aussi sur votre site web. Un client ayant acheté en ligne peut télécharger son reçu au format PDF depuis **Mon compte**, ou depuis un lien que vous ajoutez à la page de confirmation de commande.

## Activer le bouton Reçu {#my-account}

:::warning Activez d’abord un modèle de reçu
Activez-en un dans **PDV → Modèles** avant de commencer. Sans modèle actif, les clients ne verront pas le bouton **Reçu**, même si le réglage est activé. Consultez [Personnaliser votre reçu](./customise.mdx#option-1--pick-a-different-template).
:::

Le bouton reste désactivé tant que vous ne l’activez pas. Le PDF est généré à partir de votre modèle de reçu.

1. Dans WP Admin, accédez à **PDV → Réglages → Général**.

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[95, 0], [105, 0]]} alt="WP Admin avec PDV, Réglages sélectionné dans le menu et Général ouvert dans le menu des réglages, affichant Boutiques, Caisse et le début de Produits">

1. **PDV → Réglages** — l’entrée du menu WP Admin qui ouvre les réglages du PDV.
2. **Général** — le premier écran des réglages, déjà ouvert à votre arrivée.

</JourneyShot>

2. Faites défiler jusqu’à la section **Clients** et activez **Autoriser les clients à télécharger les reçus**. Le réglage est enregistré dès que vous le modifiez.

<JourneyShot manifest={manifest} device="desktop" step={2} maxWidth={880} offsets={[[100, 0], [310, 0]]} alt="La section Clients de Général : Générer automatiquement un identifiant à partir de l’e-mail du client, Client PDV par défaut défini sur Invité, et Autoriser les clients à télécharger les reçus, encore désactivé ici">

1. **Clients** — la section qui contient le réglage des reçus.
2. **Autoriser les clients à télécharger les reçus** — désactivé tant que vous ne l’activez pas.

</JourneyShot>

3. **Modèle de reçu pour les clients** apparaît en dessous. Conservez **Utiliser le modèle de reçu actif**, ou choisissez un modèle. Consultez [Choisir le modèle destiné aux clients](#template-choice).

Un client connecté voit désormais un bouton **Reçu** à côté de ses commandes dans **Mon compte → Commandes**. Ce bouton télécharge un PDF nommé d’après la commande, par exemple `receipt-1234.pdf`.

Le bouton apparaît uniquement pour les commandes qui ont été payées :

| État de la commande | Bouton Reçu |
|---|---|
| **En cours** | Oui |
| **Terminée** | Oui |
| **Remboursée** | Oui |
| Tout autre état, comme **En attente de paiement**, **Suspendue**, **Annulée** ou **Échouée** | Non |

Un développeur peut [modifier les états pour lesquels le bouton apparaît](#developers).

## Choisir le modèle destiné aux clients {#template-choice}

**Modèle de reçu pour les clients** définit le modèle utilisé pour le téléchargement.

- **Utiliser le modèle de reçu actif** (par défaut) : les clients obtiennent le modèle de reçu actif dans **PDV → Modèles**. Si vous le modifiez à cet endroit, leurs téléchargements reflètent ce changement.
- **Un modèle précis** : les clients obtiennent toujours ce modèle, quel que soit celui choisi par le caissier à la caisse. Utilisez cette option lorsque plusieurs modèles de reçus sont actifs, ou pour donner une présentation spécifique aux commandes en ligne.

Un modèle étroit de type reçu thermique produit un PDF étroit. Pour les commandes en ligne, une page entière est généralement plus lisible : le modèle **Facture** de la galerie est conçu pour le papier A4 et Letter. Consultez [Personnaliser votre reçu](./customise.mdx#option-1--pick-a-different-template) pour l’ajouter.

Le PDF est rempli à partir des mêmes [données de reçu](./receipt-data.mdx) que le reçu de caisse : votre logo, les coordonnées de la boutique et vos réglages de taxes sont donc repris.

Si un modèle choisi est ensuite supprimé ou dépublié, la liste déroulante affiche **Modèle indisponible** et les clients obtiennent votre modèle de reçu actif à la place. Choisissez-en un autre.

## Ajouter un lien vers le reçu à la page de confirmation de commande {#shortcode}

Proposez aux clients un lien **Télécharger le reçu (PDF)** sur la page de remerciement qui s’affiche après le paiement. Les invités ayant commandé sans compte peuvent ainsi obtenir leur reçu.

Si votre WP Admin propose **Apparence → Éditeur → Modèles → Confirmation de commande**, ajoutez vous-même le lien à la page de remerciement :

1. Dans WP Admin, accédez à **Apparence → Éditeur → Modèles** et ouvrez **Confirmation de commande**.
2. Ajoutez un bloc **Code court** à l’endroit où vous souhaitez placer le lien et saisissez-y `[wcpos_receipt]`.
3. Appuyez sur **Enregistrer**.

Si vous ne disposez pas de ce modèle, ou si vous souhaitez placer le lien sur la page d’une commande dans **Mon compte**, demandez à un développeur d’[ajouter le lien vers le reçu par du code](#developers).

Le code court fonctionne que l’option **Autoriser les clients à télécharger les reçus** soit activée ou non : ce réglage contrôle uniquement le bouton dans **Mon compte → Commandes**.

<details>
<summary>Options et exemples du code court</summary>

`[wcpos_receipt]` fonctionne sur la page de confirmation de commande et sur la page d’une commande dans **Mon compte**. Il y trouve automatiquement la commande : vous n’avez donc pas à saisir de numéro de commande. Sur toute autre page, il n’affiche rien à moins que vous lui fournissiez un `order_id`.

| Option | Valeur par défaut | Fonction |
|---|---|---|
| `order_id` | *(trouvé sur la page)* | Lien vers une commande, sur n’importe quelle page. Visible uniquement par le client connecté auquel appartient cette commande. |
| `link_text` | `Download receipt (PDF)` | Le texte du lien. |
| `format` | `pdf` | `pdf` télécharge un PDF. `html` ouvre le reçu dans le navigateur, prêt à être imprimé. |
| `template` | *(votre modèle de reçu actif)* | Utilise ce modèle à la place. |
| `class` | `wcpos-receipt-link` | Classe CSS du lien. |
| `id` | *(aucun)* | `id` HTML du lien. |

L’option `template` du code court ignore **Modèle de reçu pour les clients** : si vous l’omettez, le lien utilise votre modèle de reçu actif.

Un lien de téléchargement avec votre propre texte :

```text
[wcpos_receipt link_text="Download your invoice"]
```

Ouvrir le reçu dans le navigateur au lieu de télécharger un PDF :

```text
[wcpos_receipt format="html" link_text="View your receipt"]
```

Utiliser un modèle précis, par exemple une facture A4 à la place de votre reçu de caisse 80mm :

```text
[wcpos_receipt template="123" link_text="Download invoice (PDF)"]
```

Le numéro du modèle figure dans la barre d’adresse lorsque vous modifiez le modèle dans **PDV → Modèles** (`post=123`). Un modèle non publié est ignoré et le lien utilise votre modèle de reçu actif.

</details>

## Qui peut ouvrir un reçu {#security}

- **Les clients ayant un compte** se connectent et utilisent le bouton **Reçu** dans **Mon compte → Commandes**.
- **Les invités** ayant commandé sans compte utilisent le lien vers le reçu sur leur page de confirmation de commande, une fois que vous [en avez ajouté un](#shortcode).

:::warning Ne partagez les liens vers les reçus qu’avec le client concerné
Toute personne disposant d’un lien vers un reçu peut l’ouvrir sans se connecter. Traitez ce lien avec la même confidentialité que la commande elle-même.
:::

<details>
<summary>Comment les liens vers les reçus sont protégés</summary>

Chaque lien vers un reçu contient la clé privée de la commande, celle que WooCommerce utilise sur sa page de confirmation de commande. Sans la bonne clé, le reçu ne s’ouvre pas. Un code court avec l’option `order_id` n’affiche son lien qu’au client connecté auquel appartient cette commande.

</details>

## En cas de problème {#goes-wrong}

La plupart des corrections ci-dessous se font dans WP Admin. Si vous êtes caissier, transmettez le message affiché au client à la personne qui gère le site web. En attendant, avec [WCPOS Pro](../getting-started/pro-license.mdx), vous pouvez imprimer ou envoyer son reçu par e-mail à la caisse : consultez [Réimprimer un reçu](../orders/index.mdx#receipt-reprinting) sur la page **Commandes**.

**Le client ne voit pas de bouton Reçu.** Vérifiez que **Autoriser les clients à télécharger les reçus** est activé, que la commande est **En cours**, **Terminée** ou **Remboursée**, et qu’au moins un modèle de reçu est actif dans **PDV → Modèles**. Le bouton n’apparaît que dans **Mon compte → Commandes**, pour un client connecté.

**« Aucun modèle de reçu n’est configuré. »** Aucun modèle n’est disponible pour générer le PDF. Activez un modèle de reçu dans **PDV → Modèles**.

**« Vous n’avez pas l’autorisation de consulter ce reçu. »** Le lien est incomplet ou a été mal copié : chaque lien contient une clé privée propre à sa commande. Renvoyez au client le lien de sa page de confirmation ou de **Mon compte**.

**« Impossible de générer le reçu PDF. »** Le PDF n’a pas pu être généré à partir du modèle. Ouvrez celui-ci dans **PDV → Modèles** et prévisualisez-le. Consultez [Personnaliser votre reçu](./customise.mdx).

**Le lien affiche une erreur « Page introuvable ».** Dans WP Admin, accédez à **Réglages → Permaliens** et choisissez une option autre que **Simple**. Les liens vers les reçus ne fonctionnent pas avec **Simple**.

## Pour les développeurs {#developers}

<details>
<summary>Ajouter le lien vers le reçu par du code</summary>

Avec un thème classique, affichez le lien à partir des deux actions WooCommerce qui génèrent ces pages :

```php
// The order confirmation ("thank you") page.
add_action( 'woocommerce_thankyou', function () {
	echo do_shortcode( '[wcpos_receipt]' );
} );

// An order's page in My Account.
add_action( 'woocommerce_view_order', function () {
	echo do_shortcode( '[wcpos_receipt]' );
} );
```

Le code court trouve la commande sur les deux pages : il n’a donc pas besoin de `order_id`.

</details>

<details>
<summary>Filtres du bouton Reçu et du modèle PDF</summary>

Trois filtres complètent les réglages ci-dessus pour définir des règles qu’ils ne permettent pas d’exprimer, par exemple par commande ou par client :

```php
// Force the My Account Receipt button on or off, overriding the setting.
// Its default value is the "Let customers download receipts" setting,
// so you only need it to override that, e.g. show the button for one user role.
add_filter( 'wcpos_storefront_receipt_my_account_button', '__return_true' );

// Change which order statuses show the button (default: processing, completed, refunded).
add_filter( 'wcpos_storefront_receipt_order_statuses', function ( $statuses, $order ) {
	$statuses[] = 'on-hold';
	return $statuses;
}, 10, 2 );

// Use a different template for storefront PDF downloads, overriding the template
// chosen by the setting or the shortcode. Receives and returns the full template array
// (null when none is configured).
add_filter( 'wcpos_storefront_receipt_template', function ( $template, $order ) {
	return \WCPOS\WooCommercePOS\Templates::get_template( 123 );
}, 10, 2 );
```

Avant WCPOS 2.0, ces filtres portaient le nom `woocommerce_pos_storefront_receipt_*`. Ces noms fonctionnent encore, mais sont obsolètes depuis la version 2.0 et seront supprimés au plus tôt dans la version 2.2. Consultez [Nommage des hooks](../extensions/index.mdx#hook-naming).

L’adresse du PDF est `/wcpos-checkout/wcpos-receipt/{order_id}` avec `?key={order_key}&format=pdf` : c’est la même adresse de reçu protégée par une clé que celle utilisée par le PDV, avec `format=pdf` pour renvoyer un PDF au lieu de la page.

</details>
