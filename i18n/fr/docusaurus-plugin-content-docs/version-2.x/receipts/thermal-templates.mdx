**Administration WP :** les modèles thermiques se modifient dans `WP Admin → POS → Templates`.

Un modèle thermique est un court fichier texte écrit en XML qui définit la mise en page d’un reçu pour une imprimante de reçus. Ce même fichier produit l’aperçu à l’écran et indique à l’imprimante quoi imprimer, quel que soit le **Langage de l’imprimante** utilisé : **ESC/POS**, **StarPRNT** ou **Star Line Mode**. Il insère les données de la commande à l’aide des mêmes `{{placeholders}}` que les [modèles HTML](./html-templates.mdx). Toutes les variables sont répertoriées dans [Données des reçus](./receipt-data.mdx).

Utilisez un modèle thermique pour toute imprimante de reçus configurée selon les instructions de [Configuration des imprimantes](../hardware/printers/index.mdx).

## Créer un modèle thermique {#make-a-thermal-template}

Partez d’un modèle de la galerie et modifiez-le. Vous n’avez pas besoin d’en créer un de toutes pièces.

1. **Ouvrez la galerie.** Dans WP Admin, accédez à **PDV → Modèles**. Dans la **Galerie de modèles**, filtrez le format sur **ESC/POS (imprimante thermique)**.
2. **Copiez un modèle.** Cliquez sur **Utiliser le modèle** sur une fiche, par exemple **Reçu thermique simple (80mm)**. Votre copie apparaît dans **Vos modèles**. Activez son interrupteur **Actif**.
3. **Modifiez-le.** Ouvrez votre copie. Modifiez le XML à gauche ; l’aperçu à droite se met à jour pendant la saisie. Cliquez sur **Mettre à jour** pour enregistrer. L’éditeur n’enregistre pas automatiquement.
4. **Envoyez-le à l’imprimante de reçus.** Dans le PDV, accédez à **Paramètres → Impression**. Sous **Modèles de reçus**, sélectionnez votre imprimante de reçus à côté du modèle, ou laissez **Auto**.
5. **Imprimez un reçu.** Dans la fenêtre du reçu, choisissez votre modèle sous **Modèle**, puis appuyez sur **Imprimer le reçu**.

### Exemple : modifier la ligne de remerciement {#example-change-the-thank-you-line}

Vérifiez d’abord la note de pied de page des reçus de la boutique. Si une note est définie, elle s’imprime à la place de la ligne de remerciement : modifiez donc cette note en suivant [Personnaliser un reçu](./customise.mdx#common-customisations). Si aucune note n’est définie, poursuivez ici.

Dans **Reçu thermique simple (80mm)**, recherchez `{{i18n.thank_you_purchase}}` vers le bas de l’éditeur. Remplacez uniquement cette variable par votre propre texte.

Avant :

```xml
{{i18n.thank_you_purchase}}
```

Après :

```xml
See you again soon!
```

Laissez tout ce qui précède et suit cette variable sur la même ligne tel quel.

<details>
<summary>La ligne de remerciement complète, avant et après</summary>

```xml
{{^store.personal_notes}}<text>{{i18n.thank_you_purchase}}</text>{{/store.personal_notes}}
```

```xml
{{^store.personal_notes}}<text>See you again soon!</text>{{/store.personal_notes}}
```

</details>

Cliquez sur **Mettre à jour**. L’aperçu affiche la nouvelle ligne en bas du reçu.

## Le modèle et l’imprimante {#the-template-and-the-printer}

Certains réglages se font sur l’imprimante, et non dans le modèle. Dans le PDV, accédez à **Paramètres → Impression**, puis appuyez sur **Modifier** sur la ligne de l’imprimante.

1. **Langage de l’imprimante** — **ESC/POS** ici. Le même modèle fonctionne avec les trois langages.
2. **Largeur du papier** — **48** ici. Sur papier, ce réglage remplace le `paper-width` du modèle.
3. **Langue du reçu** — le jeu de lettres et de symboles utilisé par l’imprimante. ESC/POS uniquement.
4. **Imprimer les reçus sous forme d’image** — imprime l’intégralité du reçu sous forme d’image.

</JourneyShot>

Lorsque **Ouverture automatique du tiroir-caisse** est activé, **Connecteur du tiroir-caisse** apparaît en dessous :

<JourneyShot manifest={manifest} device="tablet" step={6} offsets={[[680, 0], [680, 0], [47, -30], [36, -30]]} maxWidth={799} alt="Le bas de Modifier l’imprimante : Ouverture automatique du tiroir-caisse activé, Connecteur du tiroir-caisse réglé sur Broche 2 / Tiroir 1, Définir par défaut, et les boutons Ouvrir le tiroir, Test d’impression et Fermer">

1. **Ouverture automatique du tiroir-caisse** — ouvre le tiroir après le reçu, sauf si le modèle possède sa propre balise `<drawer />`.
2. **Connecteur du tiroir-caisse** — **Broche 2 / Tiroir 1** ici. `<drawer />` l’utilise lorsque la balise ne précise aucun connecteur.
3. **Ouvrir le tiroir** — ouvre le tiroir une fois, sans imprimer.
4. **Test d’impression** — imprime la page de test de l’application, *Diagnostic de l’imprimante*, et non votre modèle. Si **Ouverture automatique du tiroir-caisse** est activé, comme ici, le tiroir s’ouvre également.

</JourneyShot>

Surveillez surtout **Largeur du papier**. Le `paper-width` du modèle définit uniquement la largeur de l’**aperçu**. Sur papier, c’est **Largeur du papier** de l’imprimante qui prévaut. Une colonne `width="*"` occupe l’espace restant après les autres colonnes ([Colonnes extensibles](#star-width-columns)). Vérifiez le résultat pour chaque largeur de papier utilisée ([Largeur du reçu](../hardware/printers/receipt-width.mdx)).

<details>
<summary>Paramètres de l’imprimante qui influencent votre reçu</summary>

| Paramètre de l’imprimante | Effet sur un modèle thermique |
|---|---|
| **Largeur du papier** (32, 42, 48 ou 64) | Le nombre de caractères par ligne sur papier. Ce réglage **remplace** le `paper-width` du modèle à l’impression. Consultez [Largeur du reçu](../hardware/printers/receipt-width.mdx). |
| **Langage de l’imprimante** | **ESC/POS**, **StarPRNT** ou **Star Line Mode**. Le même modèle s’imprime avec les trois. |
| **Langue du reçu** (ESC/POS uniquement) | Le jeu de lettres et de symboles utilisé par l’imprimante. |
| **Ouverture automatique du tiroir-caisse** | Ouvre le tiroir après le reçu, sauf si le modèle possède sa propre balise `<drawer />`. |
| **Connecteur du tiroir-caisse** | **Broche 2 / Tiroir 1** ou **Broche 5 / Tiroir 2**. Affiché lorsque **Ouverture automatique du tiroir-caisse** est activé. Utilisé par `<drawer />` si la balise ne précise aucun connecteur. |
| **Imprimer les reçus sous forme d’image** | Imprime l’intégralité du reçu sous forme d’image. Pour les écritures que l’imprimante ne peut pas imprimer sous forme de texte, comme l’arabe, l’hébreu et le thaï. Plus lent que le texte. |

</details>

## Balises disponibles {#xml-elements}

Chaque balise dispose de sa propre section ci-dessous, avec un exemple. Les paramètres à l’intérieur d’une balise, comme `width="2"`, sont facultatifs sauf indication contraire.

<details>
<summary>Tous les éléments et attributs dans un tableau</summary>

| Balise | Ce qu’elle imprime et ses paramètres (valeur utilisée en cas d’omission) |
|---|---|
| `<receipt>` | Obligatoire. Encadre l’intégralité du modèle.<br />`paper-width` (`48`) |
| `<text>` | Une ligne de texte. |
| `<bold>`, `<underline>`, `<invert>` | Texte mis en forme. `<invert>` affiche du blanc sur fond noir. |
| `<size>` | Texte agrandi de 1–8 fois.<br />`width` (`1`), `height` (identique à `width`) |
| `<align>` | Aligne son contenu.<br />`mode`: `left`, `center`, `right` (`left`) |
| `<row>` + `<col>` | Colonnes côte à côte.<br />`width`: un nombre ou `*` (`12`); `align`: `left`, `right` (`left`) |
| `<line />` | Un trait sur toute la largeur du papier.<br />`style`: `single`, `double`, `dashed`, `dotted` (`single`) |
| `<feed />` | Lignes vides.<br />`lines` (`1`) |
| `<barcode>` | Un code-barres représentant le texte contenu.<br />`type` (`code128`), `height` (`40`) |
| `<qrcode>` | Un code QR représentant le texte contenu.<br />`size` (`4`) |
| `<image />` | Un logo ou une image.<br />`src` (obligatoire), `width` en points d’impression (`200`) |
| `<cut />` | Coupe le papier.<br />`type`: `full`, `partial` (`partial`) |
| `<drawer />` | Ouvre le tiroir-caisse.<br />`connector`: `pin2`, `pin5` (réglage de l’imprimante) |

</details>

Les nombres doivent être entiers et supérieurs à zéro. Toute autre valeur, comme `width="1.5"` ou `lines="0"`, est ignorée et la balise utilise sa valeur habituelle. Une balise absente de ce tableau est ignorée, mais le texte qu’elle contient est tout de même imprimé.

### La balise `<receipt>` {#root-element}

Chaque modèle thermique commence et se termine par `<receipt>`:

```xml
<receipt paper-width="48">
  <!-- 48 characters = 80 mm paper on most Epson and Star printers -->
  <!-- 32 characters = 58 mm paper -->
</receipt>
```

`paper-width` définit la largeur de l’aperçu, en caractères. Sur papier, **Largeur du papier** de l’imprimante la remplace ([Le modèle et l’imprimante](#the-template-and-the-printer)).

### Texte en gras, souligné et inversé {#text-and-formatting}

```xml
<text>Plain text</text>
<bold><text>Bold text</text></bold>
<underline><text>Underlined text</text></underline>
<invert><text>Inverted (white on black)</text></invert>
```

Une balise de mise en forme seule ne termine pas la ligne : placez donc une balise `<text>` à l’intérieur. Une balise `<text>` termine la ligne après son texte ([Encadrer les titres mis en forme](#wrap-styled-headings-in-text-for-a-line-break)). À l’intérieur d’une balise `<align>` centrée ou alignée à droite, il existe une exception ([Titres mis en forme centrés](#centred-styled-headings-inside-align-blocks)).

### À gauche, au centre et à droite {#alignment}

```xml
<align mode="left"><text>Left aligned</text></align>
<align mode="center"><text>Centered</text></align>
<align mode="right"><text>Right aligned</text></align>
```

Toute autre valeur de `mode` imprime à gauche.

### Texte agrandi {#text-size}

Augmentez la largeur du texte, sa hauteur, ou les deux :

```xml
<size width="2" height="2"><text>Double-size text</text></size>
<size width="2" height="1"><text>Wide text</text></size>
<size width="1" height="2"><text>Tall text</text></size>
```

Si vous omettez `height`, sa valeur sera celle de `width`. Les imprimantes ESC/POS vont jusqu’à 8 fois la taille normale ; les imprimantes Star s’arrêtent à 6.

### Colonnes {#tabular-layout}

Utilisez `<row>` et `<col>` pour disposer du texte côte à côte en colonnes :

```xml
<row>
  <col width="16">Item name</col>
  <col width="4" align="right">Qty</col>
  <col width="12" align="right">Price</col>
</row>
```

Ces largeurs totalisent 32, soit le papier le plus étroit : la ligne convient donc à toutes les imprimantes. Sur un papier plus large, le reste de la ligne reste vide.

La largeur des colonnes se compte en caractères. Attribuez `width="*"` à une colonne pour qu’elle occupe l’espace restant et que la ligne s’adapte au papier :

```xml
<row>
  <col width="*">{{name}}</col>
  <col width="12" align="right">{{line_total_display}}</col>
</row>
```

- Une balise `<col>` s’aligne selon `left` ou `right`. Une colonne ne peut pas être centrée.
- Une balise `<col>` située hors d’une balise `<row>` est ignorée.
- Une colonne imprime **uniquement son texte**. La mise en forme à l’intérieur d’une balise `<col>` (`<bold>`, `<size>` et les autres) apparaît dans l’aperçu, mais pas sur papier, sauf si **Imprimer les reçus sous forme d’image** est activé. Les modèles de la galerie mettent le TOTAL en gras de cette manière (dans **Reçu thermique simple (80mm)**, par exemple), si bien que leur TOTAL s’imprime sans gras. Pour imprimer une ligne entière en gras, placez la balise `<bold>` autour de la balise `<row>`.

<details>
<summary>Exemple : une ligne TOTAL qui s’imprime en gras</summary>

```xml
<!-- Prints bold on paper -->
<bold>
  <row>
    <col width="*">{{i18n.total}}</col>
    <col width="16" align="right">{{totals.total_display}}</col>
  </row>
</bold>
```

</details>

### Traits et espaces vides {#separators-and-spacing}

```xml
<line />                       <!-- Single line -->
<line style="double" />        <!-- Double line -->
<line style="dashed" />        <!-- Dashed line -->
<line style="dotted" />        <!-- Dotted line -->
<feed lines="2" />             <!-- Two blank lines -->
```

L’aperçu représente chaque style différemment. Sur papier, `single` et `dashed` ont le même aspect.

<details>
<summary>Rendu de chaque style de trait sur papier</summary>

- `single` et `dashed` impriment tous deux une rangée de caractères `-` sur toute la largeur du papier.
- `dotted` imprime `. . . .` sur toute la largeur du papier. Sur une imprimante Epson à laquelle l’application accède via ePOS, la connexion réseau propre à Epson (une imprimante réseau Epson depuis le navigateur, ou depuis l’application de bureau si l’imprimante répond sur son port ePOS), ce style imprime `-` comme `single`.
- `double` imprime une rangée de caractères à double trait. Via ePOS et l’impression cloud, ce style imprime une rangée de `=`.

</details>

### Couper le papier et ouvrir le tiroir {#printer-commands}

```xml
<cut />                <!-- Partial cut (leaves a small tab) -->
<cut type="full" />    <!-- Full cut -->
<drawer />             <!-- Open the cash drawer -->
<drawer connector="pin5" /> <!-- Open the drawer on pin 5 -->
```

- `<cut />` fait d’abord avancer le papier jusqu’au massicot. L’aperçu représente la coupe par une ligne en tirets avec ✂. Sur une imprimante Epson à laquelle l’application accède via ePOS, `<cut />` et `<cut type="full" />` produisent la même coupe.
- `<drawer />` ouvre le tiroir quel que soit le réglage **Ouverture automatique du tiroir-caisse**. Lorsque le modèle possède sa propre balise `<drawer />`, l’application n’ouvre pas le tiroir une seconde fois. L’aperçu ne représente pas cette action. Consultez [Tiroir-caisse](../hardware/printers/cash-drawer.mdx).

### Codes-barres et codes QR {#barcodes-and-qr-codes}

```xml
<barcode type="code128" height="40">{{order.number}}</barcode>
<qrcode size="4">{{fiscal.qr_payload}}</qrcode>
```

- `height` est la hauteur du code-barres en points d’impression.
- `size` est la taille de chaque carré du code QR : plus le nombre est élevé, plus le code est grand.

<details>
<summary>Un code QR créé avec `<barcode>`</summary>

`<barcode type="qrcode">` (ou `type="qr"`) crée également un code QR. Sa taille est déterminée par `height`: `height` ÷ 10, avec une valeur comprise entre 2 et 10.

</details>

L’aperçu représente les codes-barres et les codes QR sous forme d’images. L’imprimante reçoit ses propres commandes de code-barres, ou une image à imprimer lorsque l’application en a créé une.

## Exemple : reçu simple de 80mm {#example-simple-80mm-receipt}

Un reçu complet, de haut en bas : le nom et l’adresse de la boutique, le numéro de commande, la date et le caissier, les articles sur trois colonnes, les totaux avec une ligne **TOTAL** en gras, chaque paiement avec le montant remis et la monnaie rendue, une ligne de remerciement et une coupe.

<details>
<summary>Afficher le modèle complet (environ 80 lignes)</summary>

```xml
<receipt paper-width="48">
  <align mode="center">
    <bold><size height="2"><text>{{store.name}}</text></size></bold>
    {{#store.address_lines}}<text>{{.}}</text>{{/store.address_lines}}
    {{#store.phone}}<text>{{store.phone}}</text>{{/store.phone}}
  </align>
  <line />

  <text>Order: #{{order.number}}</text>
  <text>Date: {{order.created.datetime}}</text>
  {{#cashier.name}}<text>Cashier: {{cashier.name}}</text>{{/cashier.name}}
  <line />

  <!-- Column headers, bold on paper -->
  <bold>
    <row>
      <col width="*">Item</col>
      <col width="4" align="right">Qty</col>
      <col width="12" align="right">Total</col>
    </row>
  </bold>
  <line />

  <!-- Line items -->
  {{#lines}}
  <row>
    <col width="*">{{name}}</col>
    <col width="4" align="right">{{qty}}</col>
    <col width="12" align="right">{{line_total_display}}</col>
  </row>
  {{/lines}}

  <line />

  <!-- Totals -->
  <row>
    <col width="*">Subtotal</col>
    <col width="16" align="right">{{totals.subtotal_display}}</col>
  </row>
  {{#totals.tax_total}}
  <row>
    <col width="*">Tax</col>
    <col width="16" align="right">{{totals.tax_total_display}}</col>
  </row>
  {{/totals.tax_total}}
  <bold>
    <row>
      <col width="*">TOTAL</col>
      <col width="16" align="right">{{totals.total_display}}</col>
    </row>
  </bold>

  <line />

  {{#payments}}
  <row>
    <col width="*">{{method_title}}</col>
    <col width="16" align="right">{{amount_display}}</col>
  </row>
  {{#tendered}}
  <row>
    <col width="*">Tendered</col>
    <col width="16" align="right">{{tendered_display}}</col>
  </row>
  <row>
    <col width="*">Change</col>
    <col width="16" align="right">{{change_display}}</col>
  </row>
  {{/tendered}}
  {{/payments}}

  <feed lines="2" />
  <align mode="center">
    <text>Thank you for your purchase!</text>
  </align>
  <feed lines="3" />
  <cut />
</receipt>
```

</details>

Les libellés de cet exemple sont en anglais. Les modèles de la galerie utilisent à la place des libellés `{{i18n.*}}`, pour que le reçu suive la langue de la boutique ([Champs i18n](./receipt-data.mdx#i18n)).

## Colonnes extensibles {#star-width-columns}

Une colonne `width="*"` s’adapte à la largeur du papier. Au lieu de fixer chaque colonne pour un seul format de papier, attribuez `*` à la colonne qui doit s’étendre :

```xml
<!-- Works on 58 mm (32 characters) AND 80 mm (48 characters) printers -->
<row>
  <col width="*">{{name}}</col>
  <col width="10" align="right">{{line_total_display}}</col>
</row>
```

Sur une imprimante de 48 caractères, le nom de l’article dispose de 38 caractères. Sur une imprimante de 32 caractères, il en dispose de 22. Les colonnes fixes gardent la même taille sur les deux.

<details>
<summary>Plusieurs colonnes `*` extensibles</summary>

L’espace restant est réparti à parts égales. La dernière colonne `*` reçoit le caractère restant si le partage tombe sur un nombre impair. Une colonne `*` fait toujours au moins 1 caractère de large.

</details>

## Aperçu du modèle {#template-preview}

L’éditeur de modèles dans WP Admin affiche un **aperçu thermique en direct** pendant la saisie. Il se met à jour 300 ms après l’arrêt de la saisie. La fenêtre du reçu dans le PDV affiche le même type d’aperçu avant l’impression. Tous deux représentent votre modèle avec des caractères de largeur fixe, sur une largeur de `paper-width`.

Le même modèle sert à l’aperçu et à l’impression. Il n’existe pas de modèle d’impression distinct. L’aperçu est proche du résultat sur papier, sans être exact : imprimez donc un reçu de test sur chaque largeur de papier utilisée avant de vous y fier.

<details>
<summary>Différences entre l’aperçu et le papier</summary>

| Dans l’aperçu | Sur papier |
|---|---|
| La largeur est `paper-width` | La largeur est **Largeur du papier** de l’imprimante |
| `<bold>`, `<size>` à l’intérieur d’une balise `<col>` s’affichent | La colonne imprime du texte sans mise en forme, sauf si **Imprimer les reçus sous forme d’image** est activé |
| `<size>` s’agrandit uniquement selon `width` , donc un agrandissement en hauteur seule paraît normal | La largeur et la hauteur s’appliquent toutes deux |
| Les traits simples et en tirets ont un aspect différent | Tous deux impriment des caractères `-` |
| `<cut />` est une ligne en tirets avec ✂ ; `<drawer />` n’affiche rien | Le papier est coupé ; le tiroir s’ouvre |
| Toutes les écritures s’affichent | Seules les lettres disponibles dans l’imprimante s’impriment, sauf si **Imprimer les reçus sous forme d’image** est activé |

</details>

## Conseils pour créer des modèles {#authoring-tips-and-pitfalls}

L’impression thermique présente quelques pièges qui n’existent pas en HTML. Les voici, avec une solution pour chacun.

### Encadrer les titres mis en forme avec `<text>` pour un saut de ligne {#wrap-styled-headings-in-text-for-a-line-break}

Les balises de mise en forme — `<bold>`, `<size>`, `<underline>`, `<invert>`, `<align>` — **ne terminent pas la ligne à elles seules**. Une balise `<text>` termine la ligne après son texte, tout comme les balises qui occupent une ligne entière, telles que `<line />`, `<row>` et `<feed />`. Une exception : un titre mis en forme placé directement dans une balise `<align>` centrée ou alignée à droite termine sa propre ligne lorsqu’une autre ligne suit ([Titres mis en forme centrés](#centred-styled-headings-inside-align-blocks)).

```xml
<!-- ❌ Wrong: the heading runs into whatever follows -->
<bold>{{i18n.bill_to}}</bold>
{{customer.name}}

<!-- ✅ Right: put the words inside <text> -->
<bold><text>{{i18n.bill_to}}</text></bold>
<text>{{customer.name}}</text>
```

Les modèles de 80 mm de la galerie procèdent ainsi pour chaque titre.

### Éviter `<size width="2">` dans les lignes étroites {#avoid-size-width2-inside-narrow-rows}

Un texte de largeur double **occupe deux fois plus d’espace par lettre**. Un titre qui tient sur une imprimante de 48 caractères peut déborder sur une imprimante de 42 caractères, et sur du papier de 58 mm, il ne reste que 16 caractères.

La taille définie à l’intérieur d’une balise `<col>` ne s’applique de toute façon pas à l’impression. Pour afficher une valeur en grand (un total, un numéro de commande en cuisine), imprimez-la plutôt sur sa propre ligne avec `<size>` à cet effet.

<details>
<summary>Exemple : un nom de boutique plus haut et un total en grand</summary>

```xml
<!-- For store names, prefer normal-width, double-height -->
<bold><size height="2"><text>{{store.name}}</text></size></bold>

<!-- For a big total, put it on its own line above the row -->
<align mode="right">
  <bold><size height="2"><text>{{totals.total_display}}</text></size></bold>
</align>
```

</details>

### Utiliser `width="*"` pour adapter les lignes à tous les papiers {#use-width-for-paper-width-agnostic-layouts}

Une colonne `width="*"` occupe la largeur restante après les colonnes fixes. Les lignes construites ainsi conviennent aux imprimantes de 32, 42, 48 et 64 caractères ([Colonnes extensibles](#star-width-columns)). Les colonnes fixes et le texte de largeur double occupent toujours tout leur espace : vérifiez donc le résultat pour chaque largeur de papier utilisée.

Si vous utilisez des largeurs fixes, **veillez à ce que leur somme ne dépasse pas la Largeur du papier de l’imprimante** : 32 sur du papier de 58 mm. Sur du papier de 80 mm, utilisez 42, et non 48 : de nombreuses imprimantes de 80 mm impriment 42 caractères par ligne, et une ligne totalisant 48 passe sur deux lignes. Vérifiez le nombre de caractères de votre imprimante dans [Largeur du reçu](../hardware/printers/receipt-width.mdx).

### Titres mis en forme centrés dans les blocs `<align>` {#centred-styled-headings-inside-align-blocks}

Dans `<align mode="center">` (ou `right`), un titre mis en forme placé directement dans la balise `<align>` — `<bold>`, `<size>`, `<underline>` ou `<invert>` — termine sa propre ligne lorsqu’une autre ligne suit. Un nom de boutique centré et agrandi au-dessus d’une adresse centrée s’imprime correctement même sans balise `<text>` pour encadrer le texte.

En dehors d’un bloc `<align>` , conservez la balise `<text>` pour encadrer le texte.

### Tirets et guillemets typographiques {#escpos-punctuation-normalisation}

Sur les imprimantes **ESC/POS**, les tirets et les guillemets typographiques s’impriment sous leur forme simple : vous pouvez donc les saisir librement. Sur les imprimantes Star, utilisez uniquement les lettres et symboles disponibles dans l’imprimante.

<details>
<summary>Ce qui change exactement, et sur quelles imprimantes</summary>

Lorsque **Langage de l’imprimante** est réglé sur **ESC/POS**, la ponctuation typographique est convertie en caractères simples du clavier avant l’impression :

- Traits d’union et tirets de toutes longueurs (demi-cadratin, cadratin, tiret numérique, signe moins) → `-`
- Guillemets typographiques → guillemets droits

Ainsi, `Mon–Sat 9:00–18:00` et `“open”` s’impriment correctement même sur les imprimantes qui ne disposent pas de ces caractères. Les imprimantes Star (**StarPRNT** et **Star Line Mode**) conservent les tirets et guillemets d’origine lorsque l’application leur envoie une impression : utilisez donc uniquement les caractères disponibles dans l’imprimante. Avec l’impression cloud, les reçus Star bénéficient de la même conversion en caractères simples.

Sur toutes les imprimantes, les espaces spéciales (insécables, étroites et fines) s’impriment comme une espace ordinaire.

</details>

### Écritures non latines et de droite à gauche {#non-latin-and-rtl-scripts}

Une imprimante thermique imprime du texte avec ses propres caractères intégrés. L’arabe, l’hébreu, le persan, l’ourdou, le thaï et les autres écritures non latines ne s’impriment correctement que si l’imprimante dispose de cette écriture. Sinon, vous obtenez des blancs ou des lettres incorrectes.

La solution fiable consiste à activer **Imprimer les reçus sous forme d’image** sur l’imprimante. Cette option dessine l’intégralité du reçu sous forme d’image, qui s’imprime donc comme prévu quels que soient les caractères disponibles dans l’imprimante. Une commande de coupe, d’avance du papier ou `<drawer />` à la fin du modèle fonctionne toujours ; une commande placée au milieu du modèle est ignorée. Pour les autres solutions, consultez [Reçus en écritures non latines](../hardware/printers/non-latin-receipts.mdx).

:::note Une imprimante thermique nécessite un modèle thermique
Une imprimante thermique ne peut pas imprimer un modèle **HTML** pleine page. Le contenu doit être converti en commandes d’imprimante (ESC/POS ou Star), et une page HTML ne peut pas être écrite sous cette forme. Utilisez un modèle thermique pour une imprimante thermique. Pour du HTML pleine page au format A4/Letter, imprimez avec une imprimante système ou PDF, ou via [PrintNode](./cloud-printing.mdx#setup-printnode).
:::

### Logos et images {#logos-and-images}

Utilisez `<image />` pour ajouter un logo. Le logo de la boutique se trouve dans `{{store.logo}}`:

```xml
<align mode="center">
  <image src="{{store.logo}}" width="200" />
</align>
```

L’application transforme l’image en points d’impression sur l’appareil : elle remplit les zones transparentes de blanc, réduit l’image pour l’adapter au papier et la convertit en noir et blanc (sous forme de trame de points, pour préserver les nuances du logo). Elle l’envoie ensuite à l’imprimante sous forme d’image. Utilisez un PNG à fort contraste ; le SVG ne s’imprime pas encore.

<details>
<summary>Largeur de l’image, sources et formats acceptés</summary>

- **Largeur** : `width` s’exprime en points d’impression (200 si vous l’omettez). L’image ne s’imprime jamais plus large que le papier : 384 points sur du papier de 58 mm (32 caractères ou moins), 576 points sur du 80 mm.
- **Sources acceptées** : les URL de données `data:image/png` et `data:image/jpeg`, les adresses `http(s)` et les chemins de votre propre site commençant par `/`. Les adresses commençant par `//` et les chemins contenant des barres obliques inverses ou `..` sont refusés.
- **Format recommandé** : un PNG à fort contraste sur fond transparent ou blanc. Le JPEG fonctionne, mais son flou peut produire des points parasites à l’impression.
- **Le SVG n’est pas encore pris en charge** sur les imprimantes thermiques.

</details>

### Conseils {#tips}

- **Partez d’un modèle de la galerie.** Les modèles thermiques de la galerie utilisent toutes les techniques ci-dessus. Vous y trouverez des reçus de 58 mm, de 80 mm et de droite à gauche, un ticket de cuisine, ainsi que des versions pour la clôture de caisse, le bordereau de comptage et les rapports.
- **Testez chaque largeur de papier utilisée**, même avec des colonnes `width="*"`. Les colonnes fixes et le texte de largeur double peuvent toujours provoquer un retour à la ligne.
- **Utilisez les champs `_display`** pour les montants. Ils sont déjà formatés selon la devise de la boutique ([Champs monétaires](./receipt-data.mdx#currency-fields)).
- **Restez simple.** Une imprimante thermique offre moins de possibilités de mise en forme du texte qu’une page web. Construisez le reçu à partir de `<text>`, `<row>` et `<col width="*">`.

## En cas de problème {#if-something-goes-wrong}

**L’aperçu de l’éditeur indique « Erreur de rendu du modèle thermique. Vérifiez votre syntaxe XML. »**
Le modèle ne peut pas être lu. Deux causes possibles :

- Une balise n’est pas fermée, ou un caractère `&` ou `<` non échappé figure dans le texte. Fermez chaque balise (`<line />`, et non `<line>`) et écrivez `&amp;` pour représenter un `&`.
- La balise la plus externe n’est pas `<receipt>`. Encadrez l’intégralité du modèle avec `<receipt>…</receipt>`.

**Un titre se poursuit sur la ligne suivante.**
Une balise de mise en forme seule ne termine pas la ligne : le texte suivant reste donc sur la même ligne. Placez une balise `<text>` à l’intérieur ([Encadrer les titres mis en forme](#wrap-styled-headings-in-text-for-a-line-break)). Un titre mis en forme placé directement dans une balise `<align>` centrée ou alignée à droite fait exception ([Titres mis en forme centrés](#centred-styled-headings-inside-align-blocks)).

**Une ligne s’étale sur deux lignes sur papier.**
La somme des largeurs fixes dépasse la **Largeur du papier** de l’imprimante. Attribuez `width="*"` à une colonne, ou réduisez la somme des largeurs fixes pour qu’elle ne dépasse pas la **Largeur du papier** : 32 sur du papier de 58 mm, 42 sur de nombreuses imprimantes de 80 mm ([Utiliser `width="*"`](#use-width-for-paper-width-agnostic-layouts)).

**Le total est en gras dans l’aperçu, mais pas sur papier.**
La mise en forme à l’intérieur d’une balise `<col>` ne s’imprime pas, et les modèles de la galerie mettent le TOTAL en gras de cette manière. Placez la balise `<bold>` autour de toute la balise `<row>` ([Colonnes](#tabular-layout)), ou activez **Imprimer les reçus sous forme d’image**.

**L’aperçu est plus étroit ou plus large que le papier.**
Le résultat sur papier suit la **Largeur du papier** de l’imprimante, et non `paper-width`. Réglez `paper-width` sur le même nombre pour prévisualiser ce qui sera imprimé.

**La coupe laisse une attache.**
`<cut />` effectue une coupe partielle. Utilisez `<cut type="full" />` pour une coupe complète. Sur une imprimante Epson accessible via ePOS, les deux produisent la même coupe : `type` n’a donc aucun effet dans ce cas.

**Le logo ne s’imprime pas.**
Vérifiez que `src` correspond à l’une des [sources acceptées](#logos-and-images) et qu’il ne s’agit pas d’un SVG. Dans le navigateur, consultez [Logo absent dans le navigateur](../hardware/printers/logo-missing-browser.mdx).

**Des points d’interrogation, des blancs ou des lettres incorrectes apparaissent.**
L’imprimante ne dispose pas de cette écriture. Activez **Imprimer les reçus sous forme d’image** ([Écritures non latines](#non-latin-and-rtl-scripts)).

**Le tiroir-caisse s’ouvre à chaque reçu.**
Soit **Ouverture automatique du tiroir-caisse** est activé, soit le modèle contient une balise `<drawer />`, qui ouvre le tiroir quel que soit le réglage. Pour empêcher cette ouverture, désactivez le réglage et retirez `<drawer />` du modèle.

**Le tiroir-caisse ne s’ouvre pas.**
Si la balise `<drawer />` du modèle possède un attribut `connector`, il prévaut sur le réglage de l’imprimante. Retirez l’attribut `connector` pour que le paramètre **Connecteur du tiroir-caisse** de l’imprimante s’applique, puis essayez l’autre broche dans ce réglage (il s’affiche lorsque **Ouverture automatique du tiroir-caisse** est activé). Vérifiez aussi que **Langage de l’imprimante** correspond à l’imprimante, car la commande du tiroir en dépend.

**Un modèle conçu pour l’ancienne mise en page fixe StarPRNT n’imprime rien d’exploitable.**
Cette mise en page a été supprimée dans la version 1.10. Reconstruisez-la avec `<row>`, `<col>` et `width="*"`, ou repartez d’un modèle de la galerie.
