**Administration WP :** les modèles HTML se modifient dans `WP Admin → POS → Templates`.

Modifiez le texte ou la mise en page d’un reçu en éditant un modèle HTML : un reçu présenté comme une page web, avec des `{{placeholders}}` à l’emplacement des détails de la commande. Pour choisir plutôt un autre reçu prêt à l’emploi, consultez [Personnaliser votre reçu](./customise.mdx).

<details>
<summary>HTML ou thermique ?</summary>

Utilisez HTML pour l’impression depuis le navigateur, les PDF, les factures A4 et les imprimantes capables d’imprimer des pages web. Pour une imprimante de reçus qui accepte les commandes ESC/POS, utilisez plutôt un [modèle thermique](./thermal-templates.mdx). HTML est le moteur que nous recommandons pour la plupart des boutiques. Le PDV remplit le modèle HTML directement sur l’appareil : vous pouvez donc le prévisualiser et l’imprimer même si la connexion à votre boutique est interrompue.

</details>

Accès direct : [Créer un modèle](#write) · [Syntaxe](#syntax) · [Exemples courants](#common-patterns) · [En cas de problème](#goes-wrong)

## Créer un modèle {#write}

Ne partez pas d’une page blanche : copiez un modèle de la galerie, puis modifiez la copie.

1. Dans la **Galerie de modèles**, appuyez sur **Utiliser le modèle** sur la fiche la plus proche de ce que vous recherchez. Vous obtenez votre propre copie sous **Vos modèles** ; l’original de la galerie reste inchangé.
2. Ouvrez votre copie. **Champs** répertorie toutes les variables : recherchez celle qui vous intéresse, puis cliquez sur **Insérer**, sans avoir à mémoriser les noms. **Aperçu** remplit le modèle avec des **Données d’exemple** ou l’une de vos commandes PDV au fil de la saisie.
3. Effectuez les modifications souhaitées. Par exemple, pour ajouter une ligne sur les retours à votre copie du **Reçu standard**, recherchez `{{i18n.thank_you_purchase}}` vers la fin. La balise suivante `</div>` ferme le pied de page. Copiez ces lignes après cette balise `</div>` :

   ```html
   <div style="text-align: center;">
     Returns within 30 days
     with this receipt.
   </div>
   ```

   Le texte saisi s’imprime exactement tel quel, dans une seule langue. Appliquez les styles à chaque élément (`style="…"`), comme ici, et non dans un bloc `<style>`  : consultez [Les styles peuvent disparaître à l’impression](#styling).

4. Appuyez sur **Mettre à jour**. Chaque reçu imprimé avec votre copie affiche désormais votre modification, par exemple la ligne sur les retours sous le message de pied de page.
5. Dans **Vos modèles**, activez **Actif** pour que le PDV propose le modèle en caisse.

   <details>
   <summary>Placer ce modèle en premier en caisse</summary>

   La caisse répertorie les modèles actifs dans l’ordre de **Vos modèles** et commence chaque vente avec le premier. Remontez le vôtre en faisant glisser la poignée **≡** de sa ligne, ou à l’aide des boutons **↑** et **↓** de sa colonne **Actions**. Une boutique disposant de sa propre liste de modèles conserve son propre ordre. Consultez [Ce que les caissiers voient en caisse](./customise.mdx#at-the-till).

   </details>

6. Vérifiez-le dans le PDV avant de l’utiliser en caisse : consultez [Vérifier le modèle dans le PDV](#check).

### Vérifier le modèle dans le PDV {#check}

L’aperçu de l’éditeur tolère des erreurs que le PDV ne tolère pas : un modèle n’est donc prêt que lorsque son rendu est correct en caisse.

**Pour examiner rapidement la mise en page**, inutile d’effectuer une vente : ajoutez un article au panier, appuyez sur **⋮** à côté de **Paiement**, puis sur **Imprimer**. Le sélecteur Modèle et l’aperçu s’ouvrent pour la commande du panier. Un modèle HTML peut y être prévisualisé avant même que la commande ne parvienne à la boutique ; le **Modèle PHP historique** vous demande de synchroniser d’abord la commande.

**Avant de l’utiliser en caisse**, vérifiez chaque montant sur une vente réelle :

1. Saisissez une commande à l’image de vos commandes les plus chargées : une ligne avec remise, un produit soumis à une taxe et un paiement en espèces avec monnaie à rendre.
2. Sur l’écran de confirmation du paiement, sélectionnez votre modèle sous **Modèle**.
3. Examinez l’aperçu : noms, prix, remise, lignes de taxes, montant remis et monnaie à rendre.
4. Imprimez-le comme vous le ferez en caisse, avec **Imprimer le reçu** ou **Télécharger le PDF**, puis vérifiez aussi le papier ou le fichier. [Les styles peuvent disparaître à l’impression](#styling).

L’écran de confirmation du paiement, avec le **Reçu standard** de la galerie sélectionné :

:::tip Conserver l’original
Chaque clic sur **Utiliser le modèle** crée une nouvelle copie. Pour vos essais, créez deux copies (*Reçu v1*, *Reçu v2*) et passez de l’une à l’autre en caisse.
:::

## Syntaxe {#syntax}

Les variables utilisent [Mustache](https://mustache.github.io/mustache.5.html), un petit langage de modèles. Il ne possède pas de logique propre. Il remplit trois fonctions : insérer une valeur, répéter un bloc pour chaque élément d’une liste, et afficher ou masquer un bloc.

### Variables {#variables}

Placez le nom d’un champ entre doubles accolades :

```html
<h1>{{store.name}}</h1>
<p>Order #{{order.number}}</p>
<p>Total: {{totals.total_display}}</p>
```

Un champ se terminant par `_display` contient le montant déjà mis en forme pour votre boutique (`$12.50` plutôt que `12.5`). La [Référence des données de reçu](./receipt-data.mdx) répertorie tous les champs.

### Échappement {#escaping}

`{{field}}` imprime la valeur en texte brut : un `<` dans un nom de produit apparaît comme `<`, jamais comme du HTML. Trois accolades, `{{{field}}}`, l’impriment en HTML. Ce HTML est tout de même nettoyé avant l’impression (voir [Mise en forme](#styling)) : un champ ne peut donc jamais ajouter de script.

### Sections (boucles et conditions) {#sections-loops-and-conditionals}

`{{#section}}...{{/section}}` répète le bloc pour chaque élément d’une liste, ou l’affiche une fois lorsque la valeur est présente.

<details>
<summary>Exemple : une ligne par article</summary>

```html
{{#lines}}
<div class="line-item">
  <span>{{name}} × {{qty}}</span>
  <span>{{line_total_display}}</span>
</div>
{{/lines}}
```

</details>

Dans une section, un nom est d’abord recherché dans l’élément courant, puis à l’extérieur. C’est pourquoi `{{i18n.tendered}}` fonctionne dans `{{#payments}}`. `{{.}}` désigne l’élément courant lui-même, pour une liste de texte brut comme `store.address_lines`.

### Sections inversées {#inverted-sections}

`{{^section}}...{{/section}}` affiche le bloc lorsque la valeur est absente, vide, `false` ou `0`.

<details>
<summary>Exemple : nom du client ou « Commande en tant qu’invité »</summary>

```html
{{#customer.id}}
  <p>Customer: {{customer.name}}</p>
{{/customer.id}}
{{^customer.id}}
  <p>Guest checkout</p>
{{/customer.id}}
```

</details>

### Libellés traduits {#localised-labels}

`{{i18n.key}}` imprime un libellé dans la langue de votre boutique, afin qu’un même modèle fonctionne dans toutes les boutiques.

<details>
<summary>Exemple : un libellé Sous-total traduit</summary>

```html
<th>{{i18n.subtotal}}</th>
<td>{{totals.subtotal_display}}</td>
```

</details>

Les libellés suivent la langue WordPress de la boutique, et non celle choisie par le caissier dans l’application. Toutes les clés figurent dans la [référence i18n](./receipt-data.mdx#i18n).

<details>
<summary>Ce que le PDV ne prend pas en charge</summary>

- Les **modèles partiels** (`{{> name}}`) n’impriment rien dans le PDV. Placez tout dans un seul modèle.
- Les **lambdas** (fonctions à la place des valeurs) ne sont pas possibles : les données de reçu ne contiennent que des valeurs simples.
- Les **commentaires** (`{{! a note }}`) et les délimiteurs modifiés (`{{=<% %>=}}`) fonctionnent comme dans toute implémentation de Mustache.

</details>

## Exemples courants {#common-patterns}

### En-tête de la boutique {#store-header}

`store.address_lines` contient l’adresse déjà répartie sur plusieurs lignes. Parcourez-la dans une boucle plutôt que d’assembler vous-même les champs de l’adresse.

<details>
<summary>Exemple : logo, nom, adresse, téléphone et identifiants fiscaux</summary>

```html
<div style="text-align: center;">
  {{#store.logo}}<img src="{{store.logo}}" alt="{{store.name}}" style="max-width: 200px;" />{{/store.logo}}
  <h1 style="margin: 8px 0;">{{store.name}}</h1>
  {{#store.address_lines}}<div>{{.}}</div>{{/store.address_lines}}
  {{#store.phone}}<div>{{store.phone}}</div>{{/store.phone}}
  {{#store.tax_ids}}<div>{{label}}: {{value}}</div>{{/store.tax_ids}}
</div>
```

</details>

Le logo provient des réglages de la boutique, et non du modèle. Consultez [Personnaliser votre reçu](./customise.mdx).

### Lignes d’articles avec remises {#line-items-with-discounts}

Le champ `discounts` d’une ligne contient la remise sous forme de nombre positif, ou `0` s’il n’y en a pas. Mustache considère `0` comme une valeur vide : `{{#discounts}}...{{/discounts}}` n’affiche donc le bloc que sur une ligne avec remise.

<details>
<summary>Exemple : chaque ligne avec sa remise</summary>

```html
{{#lines}}
<div class="line-item" style="display: flex; justify-content: space-between;">
  <div>
    <div>{{name}} × {{qty}}</div>
    {{#discounts}}
      <div style="font-size: 0.9em;">
        <s>{{line_subtotal_display}}</s> −{{discounts_display}}
      </div>
    {{/discounts}}
  </div>
  <div>{{line_total_display}}</div>
</div>
{{/lines}}
```

</details>

`line_subtotal_display` correspond au montant de la ligne avant remises, et `line_total_display` au montant après remises. Pour les prix promotionnels et les économies, consultez [Afficher le prix normal et les économies](./receipt-data.mdx#displaying-regular-price-and-savings).

### Récapitulatif des taxes {#tax-summary}

`tax_summary` contient une ligne par taux de taxe. `rate` est un pourcentage, comme `10`. Il peut être vide (taux de 0 % ou reçu imprimé hors ligne) : la condition `{{#rate}}` évite donc qu’un simple `(%)` apparaisse sur le reçu.

<details>
<summary>Exemple : une ligne par taux de taxe</summary>

```html
{{#tax_summary}}
<div class="tax-line" style="display: flex; justify-content: space-between;">
  <span>{{label}}{{#rate}} ({{rate}}%){{/rate}}</span>
  <span>{{tax_amount_display}}</span>
</div>
{{/tax_summary}}
```

</details>


### Détails du paiement {#payment-details}

Le reçu a été imprimé avant que la commande ne parvienne à votre boutique, hors ligne par exemple ? Il n’indique pas les espèces reçues ni la monnaie à rendre. Réimprimez-le une fois la commande synchronisée. L’écran de confirmation du paiement affiche la monnaie à rendre dans tous les cas.

<details>
<summary>Explication et exemple avec le montant remis et la monnaie à rendre</summary>

Le montant **Monnaie à rendre** de l’écran de confirmation du paiement est calculé par le PDV lui-même. Les champs `tendered` et `change` du reçu proviennent de votre boutique : tant que la commande n’est pas synchronisée, ils sont vides et le bloc `{{#tendered}}` est ignoré.

```html
{{#payments}}
<div class="payment" style="display: flex; justify-content: space-between;">
  <span>{{method_title}}</span>
  <span>{{amount_display}}</span>
</div>
{{#tendered}}
  <div style="display: flex; justify-content: space-between;">
    <span>{{i18n.tendered}}</span><span>{{tendered_display}}</span>
  </div>
  <div style="display: flex; justify-content: space-between;">
    <span>{{i18n.change}}</span><span>{{change_display}}</span>
  </div>
{{/tendered}}
{{/payments}}
```

</details>


### Codes-barres et codes QR {#barcodes-and-qr-codes}

Utilisez les mêmes éléments que pour les [modèles thermiques](./thermal-templates.mdx). La valeur se place à l’intérieur de l’élément, et le PDV dessine le code à sa place.

<details>
<summary>Exemple : Code 128, EAN-13 et un code QR</summary>

```html
<!-- Code 128 barcode of the order number -->
<barcode type="code128" height="40">{{order.number}}</barcode>

<!-- EAN-13 of each product, when your SKUs are EAN numbers -->
{{#lines}}<barcode type="ean13" height="30">{{sku}}</barcode>{{/lines}}

<!-- QR code: size sets how big, 4 by default -->
{{#order.payment_url}}<qrcode size="4">{{order.payment_url}}</qrcode>{{/order.payment_url}}
```

</details>

- **Définissez toujours `type`.** Sinon, le PDV dessine un Code 128 et le PDF de la boutique un code QR.
- **Pour les numéros de commande, utilisez Code 128.** N’utilisez EAN-13 que si le SKU est un code produit EAN valide.

<details>
<summary>Types de codes-barres, tailles des codes QR et types définis par une variable</summary>

- **Choisissez parmi ces types :** `code128`, `code39`, `code93`, `ean13`, `ean8`, `upca`, `upce`, `codabar`, `itf` et `qrcode`. Le PDV peut dessiner d’autres [types bwip-js](https://github.com/metafloor/bwip-js/wiki/Supported-Barcode-Types), comme `pdf417`, mais l’aperçu de l’éditeur et le PDF les dessinent sous forme de Code 128.
- **Utilisez `<qrcode size="…">` pour les codes QR.** `<barcode type="qrcode">` (ou `qr`) en dessine également un, mais le PDV calcule sa taille à partir de `height` et le PDF à partir de `size` : les deux ne correspondent donc pas.
- **`type` peut être une variable**, car les variables sont remplacées avant que les codes ne soient dessinés :

  ```html
  <barcode type="{{presentation_hints.order_barcode_type}}">{{order.number}}</barcode>
  ```

</details>

Si la valeur ne correspond pas au type, le PDV affiche un bloc **Erreur de code-barres** ou **Erreur de code QR** contenant la valeur. Corrigez la valeur ou choisissez un type qui l’accepte. Le PDF imprime à la place la valeur seule.

## Mise en forme {#styling}

Appliquez les styles à chaque élément **en ligne**, avec un attribut `style="…"`, comme le font les modèles de la galerie :

```html
<div style="font-family: monospace; font-size: 12px; max-width: 300px; margin: 0 auto;">
  <div style="text-align: center; margin-bottom: 16px;">
    <strong style="font-size: 16px;">{{store.name}}</strong>
  </div>
  <div style="display: flex; justify-content: space-between; font-weight: 700; border-top: 1px solid black; padding-top: 8px;">
    <span>{{i18n.total}}</span>
    <span>{{totals.total_display}}</span>
  </div>
</div>
```

:::warning Les styles peuvent disparaître à l’impression
Un bloc `<style>` s’affiche correctement dans l’aperçu de l’éditeur de modèles, car celui-ci affiche votre HTML tel qu’il est écrit. Le PDF de la boutique et les applications mobiles suppriment les blocs `<style>` avant l’impression : le même reçu y est donc imprimé sans mise en forme. Appliquez tous les styles en ligne.
:::

<details>
<summary>Quels éléments HTML sont supprimés ?</summary>

Le reçu est nettoyé avant l’impression : un modèle ne peut donc jamais exécuter de code. Les scripts, les balises `<link>` et `<meta>` ainsi que les attributs `on…` sont supprimés quel que soit le mode d’impression. Le PDF de la boutique supprime les blocs `<style>` , `<head>` et les autres balises au niveau du document ; les applications mobiles suppriment aussi les blocs `<style>` .

</details>

:::tip Une conception adaptée au noir et blanc
Les reçus sont généralement imprimés sur des imprimantes thermiques ou laser en noir et blanc. Utilisez **la graisse, les espaces, la taille des caractères et les traits horizontaux** pour hiérarchiser le contenu plutôt que des aplats de couleur. Les fonds colorés et le texte gris disparaissent ou s’impriment sous forme de trames peu lisibles.
:::

:::tip Vous souhaitez l’aspect du papier thermique sans imprimante thermique ?
Appuyez sur **Utiliser le modèle** sur la fiche **Reçu étroit** de la galerie. Sa mise en page à chasse fixe de 72 mm de large s’imprime proprement depuis le navigateur, sur les imprimantes capables d’imprimer des pages web (appareils Sunmi et iMin) et sur du papier standard. Pour une imprimante utilisant directement ESC/POS, utilisez plutôt un **Reçu thermique simple** (58mm ou 80mm).
:::

## Bonnes pratiques {#best-practices}

- **Utilisez les champs `_display`** pour les montants : ils respectent le format monétaire de votre boutique.
- **Utilisez les libellés `{{i18n.*}}`** plutôt que du texte saisi, afin que le modèle fonctionne dans la langue de chaque boutique.
- **Placez les champs facultatifs dans des sections**, `{{#field}}...{{/field}}`, pour que rien ne s’imprime lorsqu’ils sont vides.
- **Partez d’un modèle de la galerie** plutôt que d’une page blanche.
- **Vérifiez le modèle dans le PDV** sur une commande réelle, avec une remise, une ligne de taxe et un paiement en espèces, avant de l’utiliser en caisse.

## En cas de problème {#goes-wrong}

**Les styles apparaissent dans l’éditeur, mais pas sur le reçu.** Appliquez-les en ligne. Consultez [Les styles peuvent disparaître à l’impression](#styling).

**Un champ n’imprime rien.** Vérifiez son nom dans la [Référence des données de reçu](./receipt-data.mdx) ; un champ mal orthographié ou inconnu reste vide, sans erreur. Dans une section, le nom est d’abord recherché dans l’élément courant.

**Le reçu affiche un bloc Erreur de code-barres.** La valeur ne correspond pas au type de code-barres. Consultez [Codes-barres et codes QR](#barcodes-and-qr-codes).

**Le montant remis et la monnaie à rendre n’apparaissent pas sur le reçu.** Il a été imprimé hors ligne, avant que la commande ne parvienne à votre boutique ; l’écran de confirmation du paiement affichait tout de même la monnaie à rendre. Réimprimez-le une fois la commande synchronisée. Consultez [Mode hors ligne](../getting-started/offline.mdx).

**Le modèle n’apparaît pas dans la liste Modèle de la caisse.** Il n’est pas **Actif**, ou une boutique dispose de sa propre liste de modèles. Consultez [Personnaliser votre reçu](./customise.mdx#per-store-assignments).

**L’aperçu de l’éditeur indique « Erreur de rendu du modèle ».** Une section n’est pas fermée, ou une balise de fermeture ne correspond pas à sa balise d’ouverture. Chaque `{{#x}}` et `{{^x}}` doit avoir son propre `{{/x}}`.
