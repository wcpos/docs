« Il y a eu une erreur critique sur ce site. » est le message affiché par WordPress lorsque votre site plante : une erreur PHP l’a arrêté avant qu’il puisse répondre au PDV. Le problème vient du site, pas de la caisse. Celle-ci peut contenir des modifications qui n’ont pas encore été transmises à votre boutique : n’effacez donc pas ses données pendant la réparation du site.

## À la caisse {#at-the-till}

:::warning N’effacez pas les données de cette caisse
L’entrée de l’erreur dans les Journaux le précise aussi : « N’effacez pas les données de cet appareil : il peut contenir des modifications qui n’ont pas encore été transmises à votre boutique. » Les effacer ferait perdre ces modifications. Si la nouvelle tentative décrite ci-dessous échoue aussi, attendez que le site soit réparé.
:::

**Vous encaissez un paiement ?** Ne débitez pas à nouveau le client pour le moment. Suivez les instructions de la page correspondant au code de paiement dans le message :

- [CHECKOUT101](../../error-codes/CHECKOUT101.mdx) : vous pouvez réessayer de valider le panier sans risque.
- [CHECKOUT201](../../error-codes/CHECKOUT201.mdx) : la vente a peut-être été enregistrée.

Dans les autres cas :

1. Réessayez l’action une fois. Le plantage peut être ponctuel.
2. Si elle échoue à nouveau, ouvrez **État de la boutique** depuis l’icône de pouls en bas du menu, puis **Journaux**, et appuyez sur **Erreurs**.
3. Appuyez sur l’entrée **SYNC131** pour l’ouvrir. Elle indique si vos données sont en sécurité, et **Aide — SYNC131** ouvre la page du code.
4. Appuyez sur **Copier les informations de débogage** et envoyez-les à la personne qui s’occupe de votre site, en précisant l’heure du problème.

## Où l’erreur apparaît {#where-you-see-it}

- **Sur la caisse**, sous forme de message après l’action qui a échoué, avec le code [SYNC131](../../error-codes/SYNC131.mdx) : votre boutique a rencontré une erreur et n’a pas terminé la requête.
- **Dans le motif renvoyé par la boutique**, lorsque le PDV en affiche un, par exemple lors du paiement ou d’une modification refusée par votre boutique. Ce motif est le message de WordPress, ou l’erreur PHP elle-même lorsque votre site affiche les détails des erreurs, comme *Allowed memory size of 134217728 bytes exhausted in wp-includes/class-wpdb.php:2324*.
- **Lors du paiement**, le message contient à la place un code de paiement qui indique ce qu’il est advenu du paiement : [CHECKOUT101](../../error-codes/CHECKOUT101.mdx) lorsque vous pouvez réessayer de valider le panier sans risque, [CHECKOUT201](../../error-codes/CHECKOUT201.mdx) lorsque le PDV ne peut pas déterminer si la vente a été enregistrée. Suivez les instructions de cette page avant de débiter à nouveau le client.
- **Dans un navigateur**, lorsque le site plante pendant le chargement de la page du PDV elle-même. WordPress affiche sa propre page d’erreur à la place du PDV.
- **Dans État de la boutique → Journaux**, sous forme d’entrée d’erreur avec **SYNC131** dans la colonne **Statut**.

## Trouver la cause sur votre site {#find-the-cause}

Cette partie nécessite l’intervention d’une personne pouvant se connecter à WP Admin.

1. Accédez à **WooCommerce → État → Journaux** et ouvrez le journal **fatal-errors** le plus récent correspondant à l’heure de l’incident. Un plantage y laisse presque toujours une trace de l’erreur PHP.
2. Lisez la première ligne de l’erreur et le fichier qu’elle mentionne. Un fichier sous `wp-content/plugins/` permet d’identifier l’extension à laquelle il appartient ; un fichier sous `wp-content/themes/` permet d’identifier le thème.
3. Si les plantages ont commencé après la mise à jour d’une extension ou d’un thème, annulez cette mise à jour ou désactivez l’extension ou le thème. S’ils ont commencé après une mise à niveau de PHP, demandez à votre hébergeur de vérifier ce changement. La page [Conflits d’extensions](./plugin-conflicts.mdx) explique comment identifier l’extension en cause.
4. Rien dans les journaux de WooCommerce ? Le guide WooCommerce [Trouver les journaux d’erreurs PHP](https://woocommerce.com/document/finding-php-error-logs/) indique où chercher ailleurs. Vous pouvez aussi demander à votre hébergeur le journal d’erreurs PHP du serveur pour la même heure.
5. Une fois le problème résolu, retournez à la caisse. Pour un paiement, consultez la page du code de paiement avant de débiter à nouveau le client. Dans les autres cas, réessayez l’action.

Dans **WP Admin > PDV > Réglages**, la section **Journaux** sous **Outils** affiche **Erreurs fatales détectées — consulter les journaux WooCommerce** dès que WooCommerce a écrit un fichier journal fatal-errors. Le lien ouvre les journaux WooCommerce filtrés sur les erreurs fatales.

:::tip L’e-mail de WordPress
Lorsqu’une extension ou un thème provoque le plantage, WordPress envoie un e-mail à l’adresse d’administration du site : **Votre site rencontre un problème technique**. Son lien ouvre WP Admin en mode de récupération après votre connexion. Vous pouvez alors y désactiver l’extension en cause, même si WP Admin ne s’ouvre pas normalement.
:::

### Erreurs que vous pouvez rencontrer {#common-errors}

**Allowed memory size of … bytes exhausted.** PHP a manqué de mémoire. Demandez à votre hébergeur d’augmenter la limite de mémoire de PHP.

**Une erreur dans le fichier d’une autre extension.** Certaines extensions sont connues pour entrer en conflit avec le PDV. Recherchez l’extension et sa solution dans [Conflits d’extensions connus](./plugin-conflicts.mdx#known-plugin-conflicts).

**Une erreur fatale ou *Cannot modify header information* après la suppression de l’extension gratuite et le téléversement de Pro.** Pro n’a pas besoin de l’extension gratuite : elle intègre son code et fonctionne seule. Vous n’avez donc pas besoin de réinstaller l’extension gratuite. Lisez la première ligne de l’erreur et le fichier qu’elle mentionne, comme indiqué ci-dessus. Si WP Admin affiche **Échec du chargement de WCPOS Pro. Veuillez exécuter composer install.**, il manque une partie de Pro dans le fichier zip : téléchargez-le à nouveau depuis vos [Téléchargements](https://wcpos.com/account/downloads), puis téléversez ce fichier. Consultez [Installer l’extension Pro](../../getting-started/pro-license.mdx#installation).
