## Signes d’un conflit entre extensions {#signs-of-plugin-conflicts}

Il peut s’agir d’un conflit entre extensions si, après l’ajout ou la mise à jour d’une extension :

- **La fenêtre de connexion affiche une erreur ou une page blanche.**
- **L’application indique « L’API REST WordPress de ce site nécessite une authentification »**, ou affiche un message d’une autre extension indiquant que seuls les utilisateurs connectés peuvent utiliser l’API REST.
- **Le site affiche « Une erreur critique est survenue sur ce site »**, dans le PDV ou dans WP Admin.
- **Les produits, les commandes ou les clients ne se téléchargent plus**, ou une vente ne s’enregistre pas dans la boutique.
- **La page de paiement d’une passerelle dans l’onglet Hérité semble défectueuse**, ou ses boutons ne réagissent pas.
- **Tout est lent**, ou les requêtes dépassent le délai d’attente. Une page est consacrée aux lenteurs à l’encaissement : [Performances de l’encaissement](../performance/checkout.mdx).

Si le menu **PDV** a disparu de WP Admin après la mise à jour d’une extension, consultez [Le PDV a disparu après la mise à jour d’une extension](../../getting-started/upgrading-to-2.mdx#pos-gone).

## Avant de commencer : utilisez un site de préproduction {#before-you-start-use-a-staging-site}

:::warning N’effectuez pas le diagnostic sur votre site en production
Désactiver des extensions sur le site utilisé par votre caisse peut interrompre les ventes et modifier votre boutique en ligne. Faites-le sur un site de préproduction.
:::

### Qu’est-ce qu’un site de préproduction ? {#what-is-a-staging-site}

Un site de préproduction est une copie de votre site web sur laquelle vous pouvez tester des modifications sans qu’elles soient visibles par vos clients ni par votre caisse. La plupart des hébergeurs permettent d’en créer un en quelques clics depuis le tableau de bord de l’hébergement.

### Si votre hébergeur ne propose pas de préproduction {#if-your-host-doesnt-offer-staging}

Demandez à votre hébergeur comment copier le site. S’il ne propose aucune solution, envisagez de passer chez un hébergeur qui le permet : la préproduction vous sera utile pour chaque mise à jour d’extension, de thème, de WordPress et de WooCommerce, pas seulement pour ce diagnostic. WP Engine, SiteGround, Kinsta et Cloudways proposent tous cette fonctionnalité.

## Étape 1 : recherchez une erreur fatale {#step-1-check-for-fatal-errors}

Un plantage indique généralement l’extension qui l’a provoqué. Commencez par là :

1. **Le journal du PDV.** Ouvrez **Santé de la boutique** depuis le menu latéral, choisissez **Journaux**, puis **Erreurs**. Consultez [Journaux](../logs.mdx).
2. **Le journal des erreurs fatales de WooCommerce.** Suivez les instructions de [Erreur critique](./critical-error.mdx) pour le trouver dans WP Admin.
3. **Lisez le chemin du fichier.** Une ligne telle que `wp-content/plugins/<plugin-name>/…` indique le nom de l’extension.

Si l’erreur désigne une extension autre que WooCommerce ou WCPOS, désactivez-la sur votre site de préproduction et réessayez. Si aucune extension n’est mentionnée, passez à l’étape 2.

## Étape 2 : désactivez les extensions, puis réactivez-les une par une {#step-2-the-plugin-elimination-method}

Utilisez cette méthode en l’absence d’erreur fatale ou si le problème est une lenteur.

### 2.1 Notez le problème rencontré {#21-create-a-baseline}

1. **Ouvrez le PDV sur votre site de préproduction.** Dans un navigateur web, accédez à `/pos` à l’adresse du site de préproduction. Dans l’application, ajoutez cette adresse comme une autre boutique (voir [Connexion](../../getting-started/connect.mdx)) et vérifiez l’adresse sous **Vos sites** avant de continuer.
2. **Effectuez l’action qui échoue** et notez exactement ce que vous observez : le message, l’écran, le temps nécessaire.
3. **En cas de lenteur**, relevez les durées dans les [Journaux](../logs.mdx) pour pouvoir les comparer plus tard.

### 2.2 Désactivez tout sauf le PDV {#22-disable-all-plugins-except-essential-ones}

**Laissez ces extensions actives :**
- WooCommerce
- WCPOS
- WCPOS Pro, si vous l’avez
- la passerelle de paiement, si le problème concerne sa page de paiement

**Désactivez toutes les autres extensions :**
1. Accédez à `WP Admin > Extensions`.
2. Cochez toutes les autres extensions.
3. Choisissez **Désactiver** dans **Actions groupées**.
4. Cliquez sur **Appliquer**.

Voici le bas de la liste des **Extensions** sur une boutique équipée de l’extension gratuite, avant de cocher quoi que ce soit :

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[59, 52], [59, 52], [59, 52], [105, 0], [78, 0]]} alt="Le bas de la liste des extensions dans WP Admin : les lignes WCPOS Pro, WCPOS et WooCommerce avec leurs cases à cocher, un avis indiquant qu’une nouvelle version de WooCommerce est disponible, puis Actions groupées et Appliquer sous la liste">

1. **WCPOS Pro** — laissez la case décochée. Sur cette boutique, l’extension est installée mais inactive.
2. **WCPOS** — laissez la case décochée.
3. **WooCommerce** — sa case est grisée tant que WCPOS en a besoin ; l’extension reste donc active.
4. **Actions groupées** — choisissez **Désactiver** une fois toutes les autres extensions cochées.
5. **Appliquer** — désactive les extensions cochées.

</JourneyShot>

### 2.3 Réessayez {#23-test-the-issue}

1. **Videz tous les caches** : celui de votre hébergeur, celui de votre CDN et ceux des extensions de cache.
2. **Effectuez l’action qui échouait.** Fonctionne-t-elle maintenant ?
3. **En cas de lenteur**, comparez les durées avec celles que vous aviez notées.

**Cela fonctionne maintenant :** l’une des extensions désactivées est probablement en cause. Passez à [Réactivez les extensions une par une](#24-enable-plugins-one-by-one) pour trouver celle qui fait réapparaître le problème.

**Le problème persiste :** ce test n’a pas permis d’en trouver la cause. Ne réactivez pas les extensions une par une. Vérifiez votre thème à l’[étape 3](#step-3-check-for-theme-conflicts). Si le thème n’est pas non plus en cause, vérifiez :
- les ressources et le pare-feu de votre serveur : consultez [Performances du serveur](../performance/server.mdx)
- un service placé devant votre site, tel que [Cloudflare](./cloudflare.mdx)
- WordPress, WooCommerce ou WCPOS lui-même : [contactez l’assistance](#getting-help) avec les informations relevées dans [Notez le problème rencontré](#21-create-a-baseline)

### 2.4 Réactivez les extensions une par une {#24-enable-plugins-one-by-one}

<details>
<summary>Quelles extensions tester en premier</summary>

Commencez par les types d’extensions les plus susceptibles de provoquer un conflit pour le trouver plus vite :
1. **Extensions de sécurité et de connexion** : Wordfence, Sucuri, Solid Security et autres extensions similaires
2. **Extensions de cache et d’optimisation**
3. **Passerelles de paiement**
4. **Autres extensions WooCommerce**
5. **Extensions de référencement**
6. **Toutes les autres**

</details>

**Testez chaque extension :**

1. **Activez une extension.**
2. **Réessayez.**
3. **Cela fonctionne toujours :** activez la suivante et réessayez.
4. **Le problème réapparaît :** notez l’extension que vous venez d’activer. Elle est probablement à l’origine du conflit.

**Vérifiez qu’il s’agit bien de cette extension :**

1. **Désactivez les extensions que vous avez réactivées**, en laissant actifs WooCommerce, WCPOS, WCPOS Pro et toute passerelle de paiement que vous aviez gardée active.
2. **Activez uniquement l’extension que vous avez notée** et réessayez.
3. **Le problème réapparaît :** cette extension est à l’origine du conflit.
4. **Le problème ne réapparaît pas :** une autre extension peut également être impliquée. Activez les autres une par une et notez la paire qui fait réapparaître le problème.

### 2.5 Notez vos constatations {#25-document-your-findings}

1. **Le nom et la version de l’extension.**
2. **Ce qu’elle perturbe**, avec les termes notés en 2.1.
3. **Si une version plus récente est disponible.**

Vous aurez besoin de ces informations à l’[étape 4](#step-4-resolving-plugin-conflicts) et si vous [contactez l’assistance](#getting-help).

## Étape 3 : vérifiez votre thème {#step-3-check-for-theme-conflicts}

Les écrans du PDV n’utilisent pas votre thème ; un thème perturbe donc rarement la caisse. Il peut toutefois perturber ce que WordPress envoie au PDV :

- la page de paiement d’une passerelle dans l’onglet **Hérité** de l’encaissement, ainsi que la page de paiement de la boutique en ligne vers laquelle la passerelle [Paiement web](../../payment/gateways/web-checkout.mdx) dirige les clients
- les écrans de WP Admin, y compris les réglages du PDV
- les requêtes de l’API REST effectuées par le PDV, car WordPress exécute aussi le code de votre thème pour ces requêtes

### Testez avec un thème par défaut {#test-with-a-default-theme}

1. **Sur votre site de préproduction**, passez à un thème WordPress par défaut, tel que Twenty Twenty-Five ou Twenty Twenty-Four.
2. **Réessayez.**
3. **Cela fonctionne maintenant :** votre thème est en cause. Indiquez à son développeur ce qui ne fonctionne pas.

## Étape 4 : résolvez le conflit {#step-4-resolving-plugin-conflicts}

Une fois l’extension identifiée, essayez ces solutions dans l’ordre.

### Option 1 : mettez-la à jour {#option-1-update-the-plugin}

1. **Recherchez une mise à jour.** Le conflit a peut-être déjà été corrigé.
2. **Effectuez d’abord la mise à jour en préproduction**, puis réessayez.
3. **Si cela résout le problème**, et que le PDV et le paiement de votre boutique en ligne fonctionnent toujours, mettez à jour votre site en production.

### Option 2 : excluez le PDV de son périmètre {#option-2-exclude-the-pos}

La plupart des conflits se résolvent dans les réglages de l’autre extension, sans la désactiver. Consultez [Éléments à exclure](#what-to-exclude) ainsi que la solution pour votre extension dans [Conflits connus entre extensions](#known-plugin-conflicts).

### Option 3 : trouvez une alternative {#option-2-find-an-alternative}

1. **Recherchez une autre extension** qui remplit la même fonction.
2. **Testez-la en préproduction.**
3. **Transférez les réglages** avant de changer d’extension.

### Option 4 : informez le développeur de l’extension {#option-3-contact-plugin-developer}

Envoyez-lui :
- la version de l’extension, ainsi que vos versions de WordPress, WooCommerce et WCPOS
- le problème rencontré, avec le message exact
- les étapes permettant de le reproduire

### Option 5 : faites appel à un développeur pour contourner le problème {#option-4-custom-solution}

Si vous ne pouvez pas vous passer d’une extension, un développeur WordPress peut souvent empêcher la partie qui provoque le conflit de s’exécuter sur les requêtes et les pages du PDV, à l’aide des hooks de l’extension.

## Éléments à exclure {#what-to-exclude}

La plupart des solutions ci-dessous consistent à demander à l’autre extension de ne pas intervenir sur le PDV, plutôt qu’à la désactiver. Si votre extension figure dans [Conflits connus entre extensions](#known-plugin-conflicts), sa rubrique indique quoi modifier. Sinon, transmettez les informations ci-dessous à la personne qui gère votre site web ou à l’assistance de l’extension.

<details>
<summary>Adresses et réglages pour la personne qui gère votre site web</summary>

Le PDV lit et enregistre les données de votre boutique via l’API REST de votre site WordPress. Une extension qui bloque, met en cache ou réécrit ces requêtes peut en perturber le fonctionnement. Si l’extension ne figure pas dans la liste :

- **Réglages du pare-feu et de l’API REST :** autorisez l’accès à `/wp-json/` lui-même et à tout ce qui se trouve sous `/wp-json/wcpos/`. Maintenez la protection pour toutes les autres adresses.
- **Réglages du cache et de l’optimisation des scripts :** excluez `/pos` et `/wcpos-checkout/`.
- **Vous ne trouvez pas le réglage :** envoyez ce tableau à l’assistance de l’extension et demandez où ajouter ces adresses.

| Adresse | Utilisation par le PDV |
| --- | --- |
| `/wp-json/wcpos/` | Toutes les données que le PDV lit et enregistre |
| `/wp-json/` | Recherche de votre boutique lors de la connexion de l’application. L’application lit cette adresse elle-même, pas celles qui se trouvent en dessous |
| `/pos` | Le PDV dans un navigateur web. Il s’agit de la valeur par défaut ; votre site peut utiliser une autre **Base du PDV** dans `WP Admin > Réglages > Permalinks` |
| `/wcpos-auth/` | La fenêtre de connexion de l’application |
| `/wcpos-checkout/` | La page de paiement d’une passerelle dans l’onglet **Hérité**, ainsi que les reçus |


:::note La fenêtre de connexion de l’application n’utilise pas la page de connexion WordPress
Les applications de bureau et mobiles se connectent via le formulaire propre à WCPOS à l’adresse `/wcpos-auth/`, dans une fenêtre distincte. Les extensions qui modifient la page de connexion WordPress, par exemple avec une adresse de connexion personnalisée, des codes d’authentification à deux facteurs, un captcha ou une connexion par e-mail uniquement, ne s’y appliquent pas. Elles s’appliquent en revanche lorsque vous ouvrez le PDV dans un navigateur web, qui vous dirige d’abord vers votre page de connexion WordPress habituelle.
:::

</details>

## Types d’extensions fréquemment en conflit {#common-conflicting-plugin-types}

<details>
<summary>Quels types d’extensions peuvent interférer ?</summary>

**Les plus susceptibles de provoquer un conflit :**

- **Les extensions de sécurité et de pare-feu** peuvent bloquer les requêtes de l’API REST, verrouiller l’accès de la caisse après de nombreuses requêtes ou empêcher la connexion.
- **Les extensions de cache et d’optimisation** peuvent fournir des réponses obsolètes au PDV ou perturber les scripts des pages que WordPress génère pour lui.
- **Les extensions de connexion, d’adhésion et de contrôle d’accès** peuvent fermer l’API REST aux utilisateurs non connectés ou modifier la façon dont les utilisateurs se connectent.
- **Les constructeurs de pages et les extensions qui injectent du contenu côté interface** peuvent charger leurs scripts et leurs éléments superposés dans la page de paiement d’une passerelle.
- **Tout ce qui s’exécute lors de l’enregistrement d’une commande ou d’un produit** peut ralentir chaque vente ou empêcher son enregistrement.

**Rarement en cause :** les extensions de formulaires de contact, de réseaux sociaux, d’analyse et de contenu interviennent rarement sur le PDV. [WooCommerce Tax](../../integrations/woocommerce-tax.mdx) fonctionne avec lui : les ventes du PDV bénéficient des mêmes taux calculés automatiquement que vos commandes en ligne.

</details>

## Conflits connus entre extensions {#known-plugin-conflicts}

Des conflits avec WCPOS ont été signalés pour ces extensions. Ouvrez la rubrique de la vôtre pour consulter le problème et sa solution, puis appliquez d’abord la correction sur votre site de préproduction.

Accès direct : [Sécurité et connexion](#security-and-login-plugins) · [Cache et optimisation](#performance-caching-optimisation-plugins) · [Constructeurs de pages](#page-builders-front-end-injectors) · [Extensions WooCommerce et autres extensions](#woocommerce-extensions-other-plugins) · [Au niveau du serveur](#server-level-conflicts) · [Gérés par WCPOS](#handled-by-wcpos)

### Extensions de sécurité et de connexion {#security-and-login-plugins}

Elles sont la cause la plus fréquente. Elles bloquent les requêtes du PDV, ce qui empêche l’application de se connecter au site, de s’authentifier ou de télécharger les données de votre boutique.

<details>
<summary>Wordfence : le PDV ne peut pas se connecter ni télécharger les données</summary>

**Problème :** son pare-feu bloque les requêtes de l’API REST du PDV.

**Solution :** autorisez `/wp-json/wcpos/` dans le pare-feu. Autorisez uniquement cette adresse, pas l’ensemble de l’API REST.

</details>

<details>
<summary>Really Simple Security : API REST bloquée ou redirigée</summary>

**Problème :** l’extension bloque l’accès à l’API REST ou impose des redirections.

**Solution :** désactivez les restrictions de l’API REST dans les réglages **Avancés** de l’extension.

</details>

<details>
<summary>Solid Security (iThemes Security) : API REST bloquée ou accès de la caisse verrouillé</summary>

**Problème :** l’extension bloque l’API REST ou verrouille l’accès de la caisse en considérant son activité comme une attaque par force brute.

**Solution :** autorisez les adresses du PDV, `/wp-json/` et `/wp-json/wcpos/`, ainsi que l’adresse IP de votre propre serveur. N’autorisez pas les adresses IP sur l’ensemble du site.

</details>

<details>
<summary>Sucuri : le PDV ne peut pas se connecter ni télécharger les données</summary>

**Problème :** son pare-feu bloque les requêtes de l’API REST.

**Solution :** autorisez `/wp-json/wcpos/` dans le tableau de bord de Sucuri.

</details>

<details>
<summary>Force Login et autres extensions qui ferment l’API REST : « nécessite une authentification »</summary>

**Problème :** l’application indique _« L’API REST WordPress de ce site nécessite une authentification »_, ou affiche le message de l’extension indiquant que seuls les utilisateurs connectés peuvent utiliser l’API REST.

**Solution :** autorisez les visiteurs non connectés à accéder à l’API REST, ou au moins à `/wp-json/` et à `/wp-json/wcpos/`.

</details>

<details>
<summary>Security Optimizer : le PDV dans le navigateur demande l’URL de connexion personnalisée</summary>

**Problème :** l’ouverture du PDV dans un navigateur web s’arrête sur un message demandant d’utiliser l’URL de connexion personnalisée.

**Solution :** connectez-vous d’abord à WP Admin via votre URL de connexion personnalisée, puis accédez à `/pos`.

</details>

<details>
<summary>Jetpack CRM Client Portal : les utilisateurs ne peuvent pas se connecter</summary>

**Problème :** les utilisateurs ne peuvent pas se connecter au PDV.

**Solution :** désactivez uniquement l’extension Client Portal, pas l’ensemble de Jetpack CRM.

</details>

### Extensions de performance, de cache et d’optimisation {#performance-caching-optimisation-plugins}

<details>
<summary>WP Rocket, Autoptimize, Hummingbird, Smush : les pages de paiement de l’onglet Hérité ne fonctionnent plus</summary>

**Problème :** le chargement différé ou la minification du JavaScript perturbe les pages de paiement des passerelles dans l’onglet **Hérité**.

**Solution :** excluez `/wcpos-checkout/` et `/pos` de l’optimisation JavaScript.

</details>

<details>
<summary>LiteSpeed Cache : l’application de bureau se recharge à l’encaissement</summary>

**Problème :** l’application de bureau se recharge en boucle à l’encaissement.

**Solution :** mettez à jour WCPOS et LiteSpeed Cache, videz le cache et excluez `/wcpos-checkout/` et `/pos` de la mise en cache.

</details>

### Constructeurs de pages et extensions qui injectent du contenu côté interface {#page-builders-front-end-injectors}

Ces extensions chargent leurs scripts et leurs éléments superposés dans la page de paiement qu’une passerelle de l’onglet **Hérité** ouvre dans le PDV. Cette page comporte un bouton **Réglages de la caisse** qui permet d’en retirer les scripts et les styles : consultez [La page de paiement d’une passerelle s’affiche mal](../../pos/checkout/troubleshooting.mdx#checkout-settings-troubleshooting).

<details>
<summary>Elementor : les moyens de paiement ne s’ouvrent pas</summary>

**Problème :** `elementor-frontend.js` perturbe la page de paiement : les moyens de paiement ne s’ouvrent pas.

**Solution :** dans **Réglages de la caisse**, retirez le script d’interface d’Elementor sous **Désactiver les scripts sélectionnés**, ou empêchez Elementor de le charger sur `/wcpos-checkout/`.

</details>

<details>
<summary>Omnisend et autres extensions marketing : la mise en page du paiement est perturbée</summary>

**Problème :** leurs scripts perturbent la mise en page de la page de paiement et les paiements.

**Solution :** dans **Réglages de la caisse**, retirez leurs scripts sous **Désactiver les scripts sélectionnés**.

</details>

<details>
<summary>MyStickyElements, Complianz : des boutons ou une bannière recouvrent la page de paiement</summary>

**Problème :** des boutons fixes ou une bannière de cookies recouvrent la page de paiement.

**Solution :** configurez ces extensions pour exclure `/wcpos-checkout/`, ou retirez leurs scripts dans **Réglages de la caisse**.

</details>

### Extensions WooCommerce et autres extensions {#woocommerce-extensions-other-plugins}

<details>
<summary>Stripe Tax : ne fonctionne pas avec les commandes du PDV</summary>

**Problème :** l’extension ne fonctionne pas avec les commandes créées via l’API REST, que le PDV utilise pour enregistrer chaque commande.

**Solution :** il n’existe aucune solution de contournement. [WooCommerce Tax](../../integrations/woocommerce-tax.mdx) est la solution de calcul automatique des taxes qui fonctionne avec le PDV.

</details>

<details>
<summary>WP Activity Log : la base de données se remplit et la boutique ralentit</summary>

**Problème :** l’extension journalise chaque modification effectuée par le PDV ; la base de données se remplit et la boutique ralentit.

**Solution :** désactivez-la ou excluez les produits et les commandes du PDV de sa journalisation.

</details>

<details>
<summary>MailerLite : erreur serveur (500) lors de l’enregistrement d’une vente</summary>

**Problème :** lorsque MailerLite Signup Forms et l’intégration MailerLite pour WooCommerce sont toutes deux actives, le serveur manque de mémoire et renvoie une erreur serveur (500) lorsque le PDV enregistre une commande.

**Solution :** désactivez les deux pour confirmer, puis contactez MailerLite.

</details>

<details>
<summary>The Courier Guy Shipping : les commandes ne s’enregistrent pas</summary>

**Problème :** le PDV ne peut pas enregistrer les commandes en raison d’une erreur serveur.

**Solution :** revenez à la version précédente de l’extension ou contactez son développeur.

</details>

<details>
<summary>Mollie : le virement bancaire est absent</summary>

**Problème :** l’extension masque le virement bancaire lors de l’encaissement dans le PDV.

**Solution :** mettez à jour Mollie.

</details>

<details>
<summary>CTX Feed : erreurs 403 sur la page des réglages du PDV</summary>

**Problème :** des erreurs 403 surviennent de temps à autre sur la page des réglages du PDV.

**Solution :** désactivez l’extension pour confirmer. Aucun réglage connu ne permet de résoudre ce problème.

</details>

<details>
<summary>Extensions de lecture de codes-barres : les commandes ne s’enregistrent pas ou ne s’affichent pas</summary>

**Problème :** elles altèrent les données des commandes envoyées par l’API REST, ce qui empêche leur enregistrement ou leur affichage.

**Solution :** désactivez-les. Le PDV lit lui-même les codes-barres : consultez [Lecture des codes-barres](../../pos/product-panel/barcode-scanning.mdx).

</details>

<details>
<summary>PixelYourSite, PixelMySite : erreur critique</summary>

**Problème :** une erreur critique : _appel à une fonction membre `is_type()` sur un booléen_.

**Solution :** désactivez l’extension.

</details>

<details>
<summary>Google Listings & Ads : erreur critique, classe WCPOS introuvable</summary>

**Problème :** une erreur critique indique qu’une classe WCPOS est _introuvable_.

**Solution :** supprimez toutes les extensions WCPOS, puis installez uniquement la dernière version de WCPOS Pro.

</details>

<details>
<summary>WooCommerce Subscriptions : bloque la mise à niveau de Pro depuis la version 1.7 ou une version antérieure</summary>

**Problème :** l’extension bloque l’étape de mise à niveau de WCPOS Pro.

**Solution :** désactivez Subscriptions, activez WCPOS Pro et laissez la mise à niveau se terminer, puis réactivez Subscriptions.

</details>

:::warning Stripe Terminal : laissez-le désactivé dans les paiements WooCommerce
Activez Stripe Terminal uniquement pour le PDV, dans `WP Admin > POS > Réglages > Validation de la commande`. Il n’a pas besoin d’être activé dans `WP Admin > WooCommerce > Réglages > Paiements`. Lorsqu’il y est activé, il apparaît sur la page de paiement de votre boutique en ligne, où il a déjà empêché les clients en ligne de payer. Consultez [Stripe Terminal](../../payment/gateways/stripe-terminal.mdx).
:::

### Conflits au niveau du serveur {#server-level-conflicts}

<details>
<summary>En-têtes de sécurité définis par votre serveur web : PDV bloqué sur son logo ou pages blanches</summary>

Une ligne `Content-Security-Policy` ou `X-Frame-Options` dans `.htaccess`, Nginx ou le panneau de votre hébergeur.

**Problème :** le PDV reste bloqué sur son logo, ou une page de paiement de l’onglet Hérité ou un reçu s’affiche en blanc.

**Solution :** excluez `/pos`, `/wcpos-auth/` et `/wcpos-checkout/` de cet en-tête. Autoriser les adresses des CDN ne suffit pas, car la page du PDV démarre à partir d’un script intégré et récupère ses fichiers depuis `cdn.wcpos.com` et `cdn.jsdelivr.net`. WCPOS retire ces en-têtes de ses propres pages lorsque WordPress ou une extension les ajoute, mais il ne peut pas retirer un en-tête ajouté par votre serveur web.

</details>

<details>
<summary>GoDaddy Website Firewall : « Valeur reçue : 'undefined' »</summary>

**Problème :** il bloque `/wp-json/` avec le message _« Valeur reçue : 'undefined' »_.

**Solution :** autorisez le chemin `/wp-json/` dans le pare-feu : consultez [Performances du serveur](../performance/server.mdx#hosting-specific-notes).

</details>

### Conflits gérés directement par WCPOS {#handled-by-wcpos}

<details>
<summary>Extensions qui provoquaient des conflits et ne nécessitent désormais aucune intervention</summary>

Gardez WCPOS à jour et aucun réglage n’est nécessaire pour ces extensions :

- **En-têtes de sécurité des extensions.** Wordfence, LiteSpeed Cache et d’autres extensions peuvent ajouter un en-tête `Content-Security-Policy` qui empêche le chargement du PDV. WCPOS retire `Content-Security-Policy` et `X-Frame-Options` de ses propres pages. Un développeur qui a besoin d’une politique à cet endroit peut en définir une avec le filtre `wcpos_content_security_policy`.
- **Extensions d’authentification JWT.** Elles rejetaient le jeton de connexion du PDV, ce qui faisait échouer chaque requête après la connexion avec une erreur 403. WCPOS efface désormais leur erreur lorsqu’il a lui-même authentifié la requête ; les erreurs des autres extensions continuent d’être transmises.
- **Image Prioritizer.** Cette extension remplit l’en-tête `Link` que les applications utilisent pour trouver un site WordPress. Lorsque cet en-tête n’indique pas l’API REST de votre site, l’application la cherche à l’adresse `/wp-json/`. Si l’application indique toujours _« Le site ne semble pas être un site WordPress »_, désactivez l’extension.
- **Extensions qui s’exécutent à l’enregistrement d’un produit** (Jetpack, Astra, Xero et autres). Les anciennes versions de WCPOS leur faisaient ajouter des lignes en double à chaque requête. Ce problème a été corrigé dans la version 1.8.12, et la mise à niveau a supprimé les doublons.
- **WooCommerce Stripe 11.1.0.** Son script de paiement par carte empêchait tous les autres moyens de paiement de fonctionner sur une page de paiement de l’onglet **Hérité**. Tant que votre extension Stripe est antérieure à la version 11.1.1, WCPOS retire le script et les styles de paiement par carte de Stripe de cette page. Les autres moyens de paiement fonctionnent alors, mais le formulaire de paiement par carte de Stripe n’y apparaît pas. Stripe a corrigé le conflit dans la version 11.1.1. Mettez Stripe à jour et WCPOS laissera de nouveau son formulaire de paiement par carte sur la page, même si un enregistrement antérieur dans **Réglages de la caisse** l’avait désactivé.
- **MyParcel.** Un panier contenant un [produit divers](../../pos/cart/index.mdx#miscellaneous-products) ne pouvait pas passer à l’encaissement, car MyParcel rencontrait une erreur critique lors de l’enregistrement de la commande. WCPOS indique désormais à MyParcel que la ligne ne correspond à aucun produit du catalogue, comme le fait WooCommerce, ce qui permet à la vente d’aboutir.

</details>

## Conseils de prévention {#prevention-tips}

### Maintenance régulière {#regular-maintenance}

1. **Gardez les extensions à jour.**
2. **Supprimez les extensions que vous n’utilisez pas**, plutôt que de les laisser désactivées.
3. **Testez chaque mise à jour en préproduction** avant de l’appliquer à votre site en production.
4. **Surveillez la vitesse de votre serveur** avec [Performances du serveur](../performance/server.mdx).

### Choix des extensions {#plugin-selection-best-practices}

1. **Choisissez des extensions régulièrement mises à jour**, avec de bons avis.
2. **N’utilisez pas deux extensions qui remplissent la même fonction.**
3. **Vérifiez que l’extension indique avoir été testée avec votre version de WooCommerce.**
4. **Ajoutez les extensions une par une** et vérifiez la caisse après chaque ajout.
