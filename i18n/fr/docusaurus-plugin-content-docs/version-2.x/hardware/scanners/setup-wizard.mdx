La plupart des lecteurs de codes-barres ne nécessitent aucune configuration : branchez le lecteur ou associez-le comme un clavier, puis scannez. L’assistant ci-dessous vous pose quelques questions et vous guide pour la suite, ou pour résoudre un problème de lecture.

La plupart des problèmes se règlent sur un même écran, **Paramètres → Lecture de codes-barres**. Sous l’assistant : [le contenu de cet écran](#barcode-scanning-screen), [comment lire le panneau de test](#test-panel) et [la signification de l’état de votre lecteur](#scanner-status).

WCPOS peut lire les codes-barres avec la caméra de votre appareil : appuyez sur l’**icône de caméra** dans la barre de recherche du PDV et pointez-la vers le code-barres.

Cela fonctionne sur les téléphones, les tablettes et les ordinateurs portables équipés d’une webcam. C’est une bonne solution pour débuter ou pour scanner occasionnellement. Pour une caisse très fréquentée, un lecteur dédié est plus rapide — lorsque vous en aurez un, revenez suivre cet assistant.

  <WizardStep id="kb-first-d" title="Commencez en mode clavier — aucune configuration nécessaire">

Par défaut, presque tous les lecteurs se comportent comme un **clavier** : ils « saisissent » chaque code-barres. WCPOS reconnaît ces frappes rapides comme une lecture. Il n’y a rien à configurer.

1. **Lecteur USB :** branchez-le, c’est tout.
2. **Lecteur Bluetooth :** activez son mode d’association (consultez le manuel — généralement en maintenant la gâchette enfoncée ou en suivant une séquence de bips), puis associez-le dans les **paramètres Bluetooth de votre système**, comme un clavier.
3. Ouvrez WCPOS et scannez le code-barres d’un produit. Le produit doit apparaître et être ajouté à la vente.

Le mode clavier convient à la plupart des boutiques : aucune configuration, et il fonctionne partout.

**Affinez les réglages :** ouvrez <kbd>Paramètres</kbd> → <kbd>Lecture de codes-barres</kbd> et scannez dans le panneau **Test de lecture de codes-barres**.   <WizardFix id="fix-nothing" title="Quand rien ne se passe à la lecture">

1. **Le lecteur réagit-il ?** Appuyez sur la gâchette — l’absence de bip ou de voyant indique un problème d’alimentation ou de batterie, pas de WCPOS.
2. **Est-il connecté ?** Les paramètres Bluetooth doivent indiquer **Connecté**, et pas seulement « associé ». En cas de doute, associez-le à nouveau.
3. **Vérifiez qu’il saisit du texte :** ouvrez une application de notes ou un champ de texte vide et scannez. Si des caractères y apparaissent, le lecteur fonctionne — le PDV ne reconnaît simplement pas la saisie comme une lecture.
4. S’il saisit du texte mais que WCPOS l’ignore : ouvrez <kbd>Paramètres</kbd> → <kbd>Lecture de codes-barres</kbd> et scannez dans le panneau **Test de lecture de codes-barres**. Il indique pourquoi chaque tentative a été traitée comme une saisie au clavier et, si le lecteur est juste un peu lent, propose d’augmenter le seuil avec un bouton **Appliquer**. Consultez [Vérifier une lecture dans le panneau de test](#test-panel).

  <WizardFix id="fix-garbled-d" title="Quand les codes lus sont illisibles">

Un lecteur en mode clavier « saisit » selon une **disposition de clavier**. Si celle du lecteur ne correspond pas à celle de votre appareil (QWERTY ou AZERTY, position des symboles), des caractères sont intervertis.

1. Scannez dans le panneau **Test de lecture de codes-barres** (<kbd>Paramètres</kbd> → <kbd>Lecture de codes-barres</kbd>). Il repère les lecteurs qui envoient Maj sous forme de frappes séparées et indique ce qu’il détecte. Consultez [Vérifier une lecture dans le panneau de test](#test-panel).
2. Dans le manuel du lecteur, cherchez les codes-barres de configuration **« langue du clavier »** ou **« disposition du clavier »** et choisissez celle de votre appareil (la disposition US est généralement un choix sûr).
3. La solution la plus fiable : une **connexion directe**. Un lecteur connecté directement transmet le code-barres sous forme de données — aucune disposition de clavier n’intervient, donc aucun caractère ne peut être altéré.

  <WizardFix id="fix-focus-d" title="Lectures au mauvais endroit ou perdues sans champ actif">

C’est une limite inhérente au mode clavier : le lecteur saisit dans **l’élément actif**. Si le curseur se trouve dans un champ de quantité, le code-barres y arrive ; si une autre fenêtre est active, elle reçoit la lecture.

Sur cette plateforme, la solution est une **connexion directe** : chaque lecture est transmise directement à WCPOS, quel que soit le champ actif.

  <WizardFix id="fix-osk-a" title="Faire réapparaître le clavier à l’écran">

Les téléphones et les tablettes masquent le clavier à l’écran lorsqu’un clavier physique est connecté — et un lecteur en mode clavier *est* un clavier physique. Ce comportement dépend du système d’exploitation, pas d’un réglage de WCPOS.

1. **La plupart des lecteurs ont un raccourci pour le faire réapparaître** — généralement en maintenant la gâchette ou un petit bouton de fonction enfoncé quelques secondes (Inateck : maintenez le bouton de lecture ~3&nbsp;s). Cherchez *« clavier iOS »* ou *« clavier virtuel »* dans le manuel du lecteur.
2. Vous pouvez aussi déconnecter le lecteur dans les paramètres Bluetooth lorsque vous devez saisir beaucoup de texte.

  <WizardStep id="android-register" title="Enregistrez votre lecteur — aucun changement de mode nécessaire">

Sur Android, WCPOS reconnaît votre lecteur grâce à son **identité d’appareil** : vous pouvez donc conserver son mode clavier d’usine. Aucun code-barres de configuration ni nouvelle association nécessaires.

1. Associez le lecteur dans les paramètres Bluetooth d’Android (ou branchez-le en USB), en conservant sa configuration d’usine.
2. Dans WCPOS, ouvrez <kbd>Paramètres</kbd> → <kbd>Lecture de codes-barres</kbd>. Dans la section **Lecteur**, appuyez sur **Enregistrer un lecteur**, puis sur <kbd>Enregistrer le lecteur</kbd>.
3. Scannez **n’importe quel code-barres**. WCPOS détecte l’appareil qui l’a envoyé — « *NETUM Bluetooth* détecté — nommez-le et enregistrez-le ».
4. Donnez-lui un nom (par ex. « Comptoir d’accueil ») et appuyez sur <kbd>Enregistrer le lecteur</kbd>.

Désormais, chaque lecture de ce lecteur arrive directement dans WCPOS — sans estimation basée sur la vitesse de frappe et sans perte lorsqu’aucun champ n’est actif.

## L’écran Lecture de codes-barres {#barcode-scanning-screen}

Ouvrez le menu, puis <kbd>Paramètres</kbd> → <kbd>Lecture de codes-barres</kbd>. Les modifications sont enregistrées au fur et à mesure ; il n’y a pas de bouton Enregistrer.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[60, 0], [60, 0], [270, 0], [160, 0], [-30, 0], [20, 0]]} alt="L’écran Lecture de codes-barres : le seuil de délai et la longueur minimale, la section Lecteur avec son lien vers le guide de configuration et sa ligne de connexion directe, et le panneau Test de lecture de codes-barres">

1. **Seuil du délai moyen de saisie des codes-barres (ms)** — la vitesse à laquelle les frappes doivent arriver pour être reconnues comme une lecture. La valeur par défaut est 24. Augmentez-la pour un lecteur plus lent ; le [panneau de test](#test-panel) indique de combien.
2. **Longueur minimale du code-barres** — une lecture plus courte est ignorée à la caisse et jamais ajoutée au panier. La valeur par défaut est 8.
3. **Aucune configuration nécessaire pour la plupart des lecteurs** — s’affiche tant que vous n’avez pas enregistré ou connecté de lecteur. Un lecteur en mode clavier fonctionne sans avoir de ligne ici.
4. **Guide de configuration du lecteur** — ouvre cette page.
5. **Connecter un lecteur directement (avancé)** — ouvre le [panneau de connexion directe](#direct-connection-sheet). Sur Android, cette ligne s’intitule **Enregistrer un lecteur** ; consultez [l’assistant](#wizard).
6. **Test de lecture de codes-barres** — scannez dans ce panneau pour voir comment WCPOS interprète la lecture. Consultez [Vérifier une lecture dans le panneau de test](#test-panel).

</JourneyShot>

Les champs **Préfixe du lecteur de codes-barres** et **Suffixe du lecteur de codes-barres** acceptent chacun un caractère ajouté par le lecteur avant ou après chaque code, afin que WCPOS le supprime avant la recherche. **Émettre un son à la lecture** active ou désactive le son de lecture. Pour le détail de chaque réglage, consultez [Paramètres des codes-barres](../../settings/store/barcode.mdx#settings).

## Vérifier une lecture dans le panneau de test {#test-panel}

Scannez un code-barres lorsque l’écran Lecture de codes-barres est ouvert. Le panneau affiche les frappes envoyées par le lecteur et leur interprétation par WCPOS. Si votre dernière tentative porte la mention **lecture** dans Tentatives récentes et que le **Code-barres détecté** correspond au code imprimé sur le produit, passez directement à [Terminer à la caisse](#finish-at-the-till).

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[200, 0], [200, 0], [420, 0], [340, -25], [300, 0]]} alt="Le panneau de test après une lecture correcte : les frappes reçues, le code-barres détecté, un graphique des délais dont toutes les barres restent sous la ligne pointillée du seuil, le verdict et la liste des tentatives récentes">

1. **Événement de frappe** — chaque touche envoyée par le lecteur. <kbd>↵</kbd> correspond à Entrée et <kbd>⇧</kbd> à Maj.
2. **Code-barres détecté** — le code que WCPOS rechercherait.
3. **Graphique des délais** — une barre par touche, indiquant le délai qui la précède en millisecondes. La ligne pointillée représente votre seuil ; une barre qui le dépasse devient orange.
4. **Verdict** — lecture ou saisie au clavier, avec le délai moyen entre les frappes.
5. **Tentatives récentes** — vos cinq dernières tentatives, de la plus récente à la plus ancienne, chacune portant la mention **lecture**, **trop court** ou **saisie au clavier**, avec son délai moyen.

</JourneyShot>

Chaque tentative aboutit à l’un de ces cinq résultats :

- **Détecté comme une lecture, marqué lecture.** Les frappes sont arrivées assez vite et le code atteint la longueur minimale. Passez à [Terminer à la caisse](#finish-at-the-till).
- **Détecté comme une lecture, marqué trop court.** Les frappes sont arrivées assez vite, mais le code est plus court que la **Longueur minimale du code-barres** : la caisse l’ignore donc. Appuyez sur **Appliquer** pour **Réduire la longueur minimale**.
- **Traité comme une saisie au clavier, en orange, « au-dessus de votre seuil ».** Presque une lecture : les frappes sont arrivées vite, mais pas assez pour votre seuil. Consultez [Si la lecture est trop lente](#too-slow).
- **Traité comme une saisie au clavier… ignoré à juste titre.** Les frappes sont arrivées à la vitesse d’une saisie manuelle. Rien à corriger.
- **Traité comme une saisie au clavier — une seule touche enfoncée.** Une seule touche ne donne aucun intervalle à mesurer. Scannez un code-barres complet.

Une pause de plus d’une seconde commence une nouvelle tentative dans la liste.

### Si la lecture est trop lente {#too-slow}

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[420, 0], [460, 12], [300, -14]]} alt="Le panneau de test après une lecture lente : des barres orange au-dessus de la ligne pointillée du seuil, le verdict indiquant une lecture presque reconnue avec une proposition d’augmentation du seuil, et la tentative marquée comme saisie au clavier">

1. **Barres orange** — les délais qui dépassaient votre seuil.
2. **Presque une lecture** — le délai moyen et une proposition pour placer le seuil juste au-dessus. **Appliquer** enregistre immédiatement le nouveau seuil.
3. **Tentatives récentes** — la lecture lente porte la mention **saisie au clavier**.

</JourneyShot>

### Si des caractères supplémentaires apparaissent {#extra-characters}

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[0, -32], [330, -16], [300, -39]]} alt="Le panneau de test après une lecture provenant d’un lecteur qui envoie Maj sous forme de frappes séparées et ajoute un symbole avant le code : l’avertissement concernant Maj et une proposition de définir le symbole comme préfixe">

1. **Graphique des délais** — les barres <kbd>⇧</kbd> correspondent aux touches Maj envoyées séparément par le lecteur.
2. **Suggestions** — supprimer le symbole initial en le définissant comme préfixe, et un avertissement indiquant que le lecteur envoie Maj sous forme de frappes séparées.
3. **Tentatives récentes** — cette tentative compte quand même comme une lecture.

</JourneyShot>

Chaque suggestion s’accompagne d’un bouton **Appliquer** qui enregistre immédiatement la modification :

- **Augmenter le seuil à … ms** — votre lecteur est un peu plus lent que le seuil.
- **Réduire la longueur minimale à …** — le code est plus court que votre longueur minimale.
- **Supprimer le « … » initial — le définir comme préfixe** — la lecture commence par un symbole et aucun préfixe n’est défini.

Deux remarques n’ont pas de bouton. **Le lecteur envoie Maj sous forme de frappes séparées** signifie que vous devez configurer le lecteur avec une disposition de clavier US, en mode sans modificateur, à l’aide des codes-barres de configuration de son manuel. **Entrée finale détectée et ignorée — aucun suffixe nécessaire** signifie que la touche Entrée à la fin d’une lecture est déjà prise en charge : laissez donc le suffixe vide.

**Après chaque appui sur Appliquer**, scannez à nouveau le même code-barres.

### Terminer à la caisse {#finish-at-the-till}

Lorsque votre dernière tentative porte la mention **lecture** dans Tentatives récentes, et non **trop court** ou **saisie au clavier**, et que le **Code-barres détecté** correspond au code imprimé sur le produit, ouvrez la caisse et scannez un produit simple que vous connaissez. Il est ajouté directement au panier. Dans le navigateur ou l’application de bureau, cliquez d’abord sur une zone vide de l’écran : tant que le curseur se trouve dans un champ de texte, y compris le champ de recherche, WCPOS y laisse les frappes comme une saisie au clavier.

Si la lecture arrive à la caisse mais que rien n’est ajouté, par exemple avec le message **Code-barres introuvable**, consultez [Scanner un code-barres](../../pos/product-panel/index.mdx#scan) pour connaître la signification de chaque message.

## Comprendre l’état de votre lecteur {#scanner-status}

Seul un lecteur enregistré sur Android ou connecté directement dispose de sa propre ligne dans la section **Lecteur**. Un lecteur en mode clavier non enregistré n’a pas de ligne et n’en a pas besoin : vous pouvez donc passer cette partie.

<details>
<summary>La ligne du lecteur, ses cinq états et comment la supprimer</summary>

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[0, 0], [110, 4], [-30, 0], [260, 14], [-30, 0]]} alt="La section Lecteur avec un lecteur enregistré : sa ligne et son état, son bouton de menu, la remarque sur les lectures interceptées et le bouton pour connecter un autre lecteur">

1. **Ligne du lecteur** — son nom, ou le type de connexion s’il n’a pas de nom.
2. **État** — consultez le tableau ci-dessous.
3. **<kbd>⋮</kbd> menu** — **Supprimer** supprime la ligne.
4. **Lectures interceptées** — les lectures de ces appareils arrivent directement dans WCPOS. Les lecteurs en mode clavier continuent de fonctionner en parallèle.
5. **Connecter un autre lecteur (avancé)** — ouvre à nouveau le panneau de connexion directe.

</JourneyShot>

| État | Type de lecteur | Signification |
|---|---|---|
| **Connecté** | Toute connexion directe | Actuellement connecté. |
| **Enregistré** | Mode clavier, enregistré sur Android | Enregistré. Ses lectures sont reconnues selon l’appareil. |
| **Hors de portée** | Bluetooth | Enregistré, mais pas connecté actuellement. |
| **Non branché** | USB série | Enregistré, mais pas connecté actuellement. |
| **Non connecté** | USB HID POS | Enregistré, mais pas connecté actuellement. |

À l’ouverture de WCPOS, un lecteur enregistré se reconnecte automatiquement. Un lecteur Bluetooth série ou USB série ne le fait que si un seul appareil autorisé lui correspond ; avec deux lecteurs identiques, choisissez celui souhaité dans le panneau.

### Le panneau de connexion directe {#direct-connection-sheet}

**Connecter un lecteur directement (avancé)** ouvre ce panneau. Utilisez-le uniquement après avoir quitté le mode clavier du lecteur ; [l’assistant](#wizard) vous guide dans cette opération.

<details>
<summary>Se connecter via USB ou Bluetooth série, ou ajouter un UUID de service Bluetooth</summary>

<JourneyShot manifest={manifest} device="tablet" step={6} offsets={[[-26, 0], [211, 0], [-26, 0], [380, 0], [0, 34], [240, 0]]} alt="Le panneau de connexion directe : Connecter via USB, Connecter via Bluetooth série, la remarque sur les lecteurs en mode clavier et le champ pour ajouter l’UUID de service Bluetooth d’un lecteur">

1. **Connecter via USB** — pour un lecteur en mode USB HID POS. Tant qu’il est connecté, le bouton indique **Déconnecter le lecteur USB**.
2. **Connecter via Bluetooth série** — pour un lecteur en mode SPP ou en mode USB COM avec un câble : le sélecteur affiche aussi les ports série USB. Tant qu’il est connecté, le bouton indique **Déconnecter le lecteur Bluetooth série**.
3. **Remarque sur le mode clavier** — un lecteur en mode clavier ne peut pas être connecté ici. C’est une règle du système d’exploitation, pas de WCPOS.
4. **Mon lecteur n’est pas dans la liste** — l’UUID de service Bluetooth du lecteur, un long code au format `8-4-4-4-12`.
5. **Ajouter** — enregistre l’UUID pour que le sélecteur puisse trouver le lecteur.
6. **Trouver l’UUID de service de votre lecteur** — ouvre cette page. Pour savoir où trouver l’UUID dans un manuel, consultez [l’assistant](#wizard), dans la solution pour un lecteur absent du sélecteur.
