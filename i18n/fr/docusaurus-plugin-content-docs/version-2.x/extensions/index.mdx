Une extension est un module WordPress conçu pour WCPOS : terminal de paiement, catalogue multilingue, avoirs, stock par emplacement. Vous les trouverez toutes dans un même répertoire dans WordPress, sous **WP Admin > PDV > Réglages > Extensions**.

L’installation depuis le répertoire se fait en un clic et nécessite **WCPOS Pro** ainsi qu’un compte administrateur WordPress. Sans Pro, [Polylang](./polylang.mdx), [WPML](./wpml.mdx) et [WP Multilang](./wp-multilang.mdx) peuvent être installés manuellement.

Accès rapide : [Installer une extension](#installing-an-extension) · [Installer sans Pro](#install-by-hand) · [En cas de problème](#troubleshooting)

## Installer une extension {#installing-an-extension}

:::note Avant de commencer
L’installation depuis le répertoire nécessite **WCPOS Pro** et un compte administrateur WordPress : les gestionnaires de boutique ne peuvent pas installer d’extensions (consultez [Accès](../settings/wp-admin/access.mdx)). Avec la version gratuite, consultez [Sans Pro](#install-by-hand).
:::

1. Dans WordPress, allez dans **WP Admin > PDV > Réglages** et choisissez **Extensions**.
2. Recherchez l’extension. Saisissez votre recherche dans **Rechercher des extensions...** (la recherche porte sur le nom, la description et les étiquettes), ou choisissez un onglet : **Toutes**, **Catalogue**, **Codes promo**, **Stock**, **Paiements**.
3. Appuyez sur **Installer** sur sa fiche. WCPOS la télécharge, l’installe et l’active en une seule opération, et active la **Mise à jour automatique**. La fiche indique désormais **Active**.
4. Configurez-la. Si le menu **⋮** (**Plus d’actions**) de la fiche propose **Réglages**, choisissez cette option. La page de l’extension, accessible ci-dessus, précise les champs à remplir.

<details>
<summary>Pas de Réglages dans le menu, ou un autre chemin d’accès</summary>

- **Réglages** n’apparaît dans le menu que si le répertoire indique une page de réglages pour cette extension. Sinon, suivez les instructions de la page de l’extension.
- Avec WCPOS Pro, le même lien **Réglages** apparaît sous le nom de l’extension dans **WP Admin > Extensions**.
- Pour une extension de paiement, **Réglages** ouvre sa page dans les réglages de paiement de WooCommerce.

</details>

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[190, 0], [200, 0], [-36, 0], [-28, 0]]} alt="L’écran Extensions dans WordPress avec WCPOS Pro : le menu des réglages WCPOS avec Extensions sélectionné, un champ de recherche et un bouton Actualiser, les onglets de catégorie Toutes, Catalogue, Codes promo, Stock et Paiements, et une grille de fiches d’extensions.">

1. **Extensions** — dans le menu des réglages WCPOS. Le nombre à côté indique combien d’extensions ont une mise à jour en attente.
2. **Rechercher des extensions...** — recherche dans le nom, la description et les étiquettes.
3. **Actualiser** — vérifie immédiatement si de nouvelles versions sont disponibles dans le répertoire.
4. **Onglets de catégorie** — **Toutes**, ou une catégorie.

</JourneyShot>

### Le contenu d’une fiche {#browsing-extensions}

Chaque extension possède une fiche avec son icône, son nom et sa description. Une pièce de puzzle remplace l’icône si l’extension n’en a pas. La fiche d’une extension installée :

<JourneyShot manifest={manifest} device="desktop" step={2} maxWidth={432} offsets={[[-28, 0], [115, 0], [-30, 0], [0, -30], [-34, 0]]} alt="La fiche de PayPal Reader for WooCommerce, installé mais Inactif : version 0.1.0 dans Paiements, Mise à jour automatique activée et bouton Activer.">

1. **Statut** — **Active**, **Inactive** (comme ici) ou **Mise à jour disponible**.
2. **Version** — la version installée. Lorsqu’une mise à jour est en attente, elle indique **v0.5.9 → v0.5.10**. C’est un lien vers la version publiée sur GitHub. La catégorie qui suit correspond à l’onglet où figure l’extension.
3. **⋮ Plus d’actions** — **Voir sur GitHub**, et **Réglages** si l’extension possède une page de réglages.
4. **Mise à jour automatique** — activée ou désactivée pour cette extension.
5. **Activer** — le bouton indique l’action suivante : **Activer**, **Mettre à jour**, ou les deux lorsqu’une extension désactivée dispose d’une mise à jour. **Désactiver** apparaît à côté lorsque l’extension fonctionne.

</JourneyShot>

Une extension qui n’est pas installée :

### Sans Pro {#install-by-hand}

La version gratuite affiche toutes les extensions, mais **Installer** est grisé avec la mention **Pro requis pour l’installation**. Les trois extensions multilingues, Polylang, WPML et WP Multilang, fonctionnent sans Pro : vous pouvez donc les installer manuellement :

1. Sur la fiche de l’extension, ouvrez **⋮** (**Plus d’actions**) et choisissez **Voir sur GitHub**.
2. Téléchargez le fichier `.zip` joint à la dernière version publiée.
3. Dans **WP Admin > Extensions > Ajouter une extension**, appuyez sur **Téléverser une extension**, choisissez le fichier zip et activez l’extension.

Le répertoire l’affiche alors comme **Active**, puis indique **Mise à jour disponible** lorsqu’une nouvelle version est publiée. Sans Pro, il n’y a pas de bouton **Mettre à jour** : téléversez le fichier zip de la nouvelle version de la même manière, et WordPress vous proposera de remplacer la version installée.

## Mettre à jour, désactiver ou activer {#activating-and-deactivating}

Sans Pro, mettez à jour les extensions manuellement : consultez [Sans Pro](#install-by-hand).

Avec WCPOS Pro, les boutons de la fiche d’une extension installée permettent les actions suivantes :

- **Mettre à jour** — installe la nouvelle version. Une extension qui était active le reste.
- **Désactiver** — arrête l’extension sans la supprimer. Ses réglages et ses fichiers sont conservés, et **Activer** la remet en service. **Activer** réactive également la **Mise à jour automatique**.

### Mises à jour {#updating-extensions}

Lorsqu’une nouvelle version est publiée, la fiche indique **v0.5.9 → v0.5.10**, et le statut d’une extension active devient **Mise à jour disponible** (une extension désactivée reste **Inactive**). Avec WCPOS Pro, le bouton **Mettre à jour** apparaît également, et WordPress affiche la même mise à jour sur son écran **Extensions** : vous pouvez donc la lancer depuis l’un ou l’autre. Avec la version gratuite, procédez manuellement : consultez [Sans Pro](#install-by-hand).

Le répertoire recherche de nouvelles versions une fois par heure. Appuyez sur **Actualiser** à côté du champ de recherche pour vérifier immédiatement.

### Mises à jour automatiques {#auto-updates}

La **Mise à jour automatique** est activée pour chaque extension que vous installez ou activez depuis le répertoire. WordPress installe alors les nouvelles versions en arrière-plan, comme pour toute extension dont les mises à jour automatiques sont activées. Désactivez cette option sur la fiche si vous préférez procéder manuellement, par exemple pour tester d’abord une nouvelle version.

Une nouvelle version qui nécessite une version de WCPOS plus récente que celle de votre site n’est proposée ni sur la fiche ni par la mise à jour automatique. Mettez d’abord WCPOS Pro à jour : la mise à jour de l’extension apparaîtra ensuite.

### Supprimer une extension {#removing-an-extension}

Pour supprimer définitivement une extension, désactivez-la puis supprimez-la dans **WP Admin > Extensions**, comme toute autre extension. Avec WCPOS Pro, vous pouvez d’abord la désactiver sur sa fiche.

## En cas de problème {#troubleshooting}

**Installer est grisé et indique « Pro requis pour l’installation ».** Vous utilisez la version gratuite : l’installation depuis le répertoire nécessite [WCPOS Pro](../getting-started/pro-license.mdx). Les extensions multilingues peuvent être [installées manuellement](#install-by-hand).

**« Vous n’avez pas l’autorisation de gérer les extensions. »** Votre compte WordPress ne peut pas installer d’extensions. Adressez-vous à un administrateur.

**« … nécessite WCPOS 2.1 ou une version ultérieure ; ce site utilise WCPOS 2.0. Mettez d’abord WCPOS Pro à jour. »** La version proposée est trop récente pour votre version de WCPOS. Mettez WCPOS Pro à jour, puis réessayez.

**« Impossible d’actualiser les extensions. Veuillez réessayer. » ou « Aucune extension trouvée. » sans recherche saisie.** Votre site n’a pas pu récupérer la liste des extensions. Cette liste provient de GitHub, et certains hébergeurs bloquent les connexions sortantes des sites web. Réessayez plus tard ou demandez à votre hébergeur d’autoriser les connexions à GitHub.

**L’installation échoue avec une erreur sur la fiche.** WordPress n’a pas pu télécharger ou décompresser l’extension, et le message sur la fiche en indique la cause. Demandez à votre hébergeur de vérifier que WordPress peut enregistrer des fichiers dans son dossier d’extensions (`wp-content/plugins`) et se connecter à GitHub.

**La fiche indique Inactive après l’installation.** WordPress a installé l’extension mais n’a pas pu l’activer ; elle ne fonctionnera pas tant qu’elle ne sera pas active. Appuyez sur **Activer** : en cas d’échec, le message sur la fiche en indique la cause.

**Une nouvelle version n’apparaît pas.** Le répertoire conserve sa liste pendant une heure. Appuyez sur **Actualiser**.

:::info Avec WCPOS Pro
La version gratuite affiche l’ensemble du répertoire, mais les commandes **Installer**, **Activer**, **Mettre à jour**, **Désactiver** et **Mise à jour automatique** sont réservées à Pro. Consultez [Version gratuite ou Pro](../getting-started/free-vs-pro.mdx).
:::

## Pour les développeurs {#for-developers}

Pour créer une extension ou référencer la vôtre. Les informations ci-dessous ne sont pas nécessaires pour gérer une boutique.

### Nommage des hooks {#hook-naming}

Depuis WCPOS 2.0, tous les hooks déclenchés par WCPOS portent un nom de la forme `wcpos_*`. Les anciens noms `woocommerce_pos_*` sont obsolètes : ils fonctionnent toujours et ne seront supprimés qu’en 2.2 au plus tôt.

<details>
<summary>Hooks Pro, avis d’obsolescence et noms conservés</summary>

Les hooks de WCPOS Pro portent un nom de la forme `wcpos_pro_*`. Les anciens noms sont des alias : ils sont toujours déclenchés et génèrent un avis d’obsolescence avec `WP_DEBUG` lorsqu’une fonction y est rattachée. Seuls les hooks changent : les options, les clés de métadonnées et les capacités conservent leurs noms.

</details>

<details>
<summary>Les hooks déclenchés par votre code et quand changer de noms</summary>

Quatre hooks sont déclenchés par votre code et écoutés par WCPOS : `woocommerce_pos_invalidate` (extensions), `woocommerce_pos_receipt_head` (modèles de reçus PHP enregistrés) et `woocommerce_pos_head` / `woocommerce_pos_footer` (surcharge de `pos.php` par un thème). WCPOS continue d’écouter ces noms jusqu’à la version 2.2 ; passez à `wcpos_invalidate`, `wcpos_receipt_head`, `wcpos_head` et `wcpos_footer`.

Extensions : passez aux noms `wcpos_` dès votre première version publiée après la 2.0 et exigez WCPOS 2.0 ou une version ultérieure. Ne rattachez jamais votre fonction aux deux noms ; en 2.0 et 2.1, elle s’exécuterait deux fois. Consultez [ADR 0041](https://github.com/wcpos/woocommerce-pos/blob/main/docs/adr/0041-wcpos-is-the-hook-prefix.md).

</details>

<summary>Créer une extension et la référencer dans le répertoire</summary>

<h3 id="creating-a-pos-extension">Créer une extension pour le PDV</h3>

Une extension WCPOS est une extension WordPress ordinaire qui utilise les hooks et les API de WCPOS. Pour une extension de paiement, partez du [Modèle de passerelle de paiement](../reference/gateway-template.mdx).

<h3 id="pos-screens">Ajouter des éléments aux écrans du PDV</h3>

À ce jour, une extension ne peut pas ajouter son propre panneau ou bouton aux écrans du PDV. Les écrans du panier, des produits et des clients n’affichent que les éléments fournis avec l’application. Le paiement fait exception : une passerelle de paiement affiche sa propre page dans l’[onglet Classique](../pos/checkout/legacy-tab.mdx) ou, grâce à deux filtres, dispose de sa propre tuile et de ses champs dans l’onglet **Paiements**. Consultez [Déclarer des champs pour le panneau d’encaissement](../reference/declaring-pos-fields.mdx).

<details>
<summary>Pour que le répertoire reconnaisse votre extension une fois installée</summary>

- **Nom du dossier** — le dossier de l’extension doit correspondre au `slug` du catalogue, par ex. `my-extension/my-extension.php`. Le répertoire repère les extensions installées grâce à ce dossier et les y installe.
- **Domaine de traduction ou URI de l’extension** — l’un des deux doit correspondre au `slug` ou au nom du dépôt GitHub. Sans correspondance, ni les mises à jour automatiques ni l’écran **Extensions** de WordPress ne proposent vos versions. Cette vérification empêche un fork qui réutilise le nom de votre dossier de les recevoir.

</details>

<h3 id="submitting-to-the-directory">Soumettre une extension au répertoire</h3>

Le répertoire lit `catalog.json` dans le dépôt [`wcpos/extensions`](https://github.com/wcpos/extensions) sur GitHub. Pour référencer votre extension, ouvrez-y une pull request qui ajoute une entrée dans `catalog.json` et une icône sous `icons/` si vous en avez une. Une fois la pull request fusionnée, les sites WCPOS la voient dans un délai d’environ une heure.

<details>
<summary>Tous les champs d’une entrée du catalogue</summary>

| Champ | Contenu |
|---|---|
| `slug` | Le nom du dossier de l’extension. |
| `name`, `description`, `author` | Ce qu’affiche la fiche. |
| `category` | L’onglet où elle figure : `payments`, `catalog`, `coupons`, `inventory`, ou un nouvel onglet. |
| `tags` | Des mots supplémentaires pris en compte par la recherche. |
| `homepage` | Le dépôt GitHub, `https://github.com/owner/repo`. Les versions publiées sont récupérées ici. |
| `icon` | L’URL d’une icône carrée, généralement le fichier ajouté sous `icons/`. Sans icône, la fiche affiche une pièce de puzzle. |
| `requires_wp`, `requires_wc`, `requires_wcpos` | Les versions minimales de WordPress, WooCommerce et WCPOS nécessaires à son fonctionnement. La version n’est jamais proposée aux sites dont la version est inférieure à `requires_wcpos`. |
| `requires_pro` | Indique si WCPOS Pro est nécessaire à son fonctionnement. |
| `settings_url` | Sa page de réglages, relative à `wp-admin/`, par ex. `admin.php?page=wc-settings&tab=checkout&section=my_gateway`. Définit la cible de **Réglages** dans le menu de la fiche. |

Laissez le catalogue renseigner `version`, `latest_version`, `download_url` et `released_at` : ces champs sont remplis à partir de vos versions publiées.

</details>

<h3 id="github-release-conventions">Conventions de publication sur GitHub</h3>

Publiez une version finale sur GitHub, avec le numéro de version comme tag et le fichier zip de l’extension en pièce jointe. Chaque heure, le catalogue consulte la dernière version de chaque dépôt référencé et met à jour son entrée.

<details>
<summary>Ce qu’une version doit contenir pour parvenir aux sites WCPOS</summary>

- **Ajoutez un tag** avec le numéro de version, `v1.2.3`. Le `v` initial est retiré pour obtenir le numéro de version, qui doit correspondre au champ `Version` de l’en-tête de l’extension.
- **Joignez le fichier zip de l’extension** nommé d’après le slug, `my-extension.zip`. En l’absence de ce nom, le premier fichier `.zip` de la version est utilisé. WCPOS l’installe dans le dossier `slug`, quel que soit le nom du dossier contenu dans le zip.
- **Publiez-la comme version finale.** Les brouillons et les préversions sont ignorés : une préversion permet donc de partager une version de test sans la distribuer aux sites.
- **Augmentez `requires_wcpos`** dans `catalog.json` lorsqu’une version nécessite un WCPOS plus récent, afin de ne pas envoyer aux sites plus anciens une version qui ne démarrera pas.

</details>

Les sites voient la nouvelle version dès que leur liste est actualisée : dans l’heure, ou immédiatement avec **Actualiser**. Les sites où la **Mise à jour automatique** est activée l’installent en arrière-plan.

Pour tester votre propre catalogue avant de le soumettre, faites pointer un site vers ce catalogue à l’aide du filtre `wcpos_extensions_catalog_url`.

</details>
