L’extension **WCPOS StoreApps Smart Coupons** permet d’utiliser un code d’avoir de [Smart Coupons](https://woocommerce.com/products/smart-coupons/) par StoreApps, comme une carte cadeau, pour régler tout ou partie d’une vente au PDV. Avec WCPOS Pro, vous acceptez la carte sur la page de paiement à l’encaissement, le montant exact en est déduit et le reçu affiche le solde restant.

:::warning Ajouter une remise ne permet pas d’utiliser un avoir
Saisir une carte cadeau dans **Ajouter une remise** du panier affiche **Code promo introuvable**. Utilisez plutôt l’onglet **Classique** de l’écran de paiement : consultez [Accepter une carte cadeau en caisse](#at-the-till).
:::

## Accepter une carte cadeau en caisse {#at-the-till}

Avant de commencer, l’administrateur doit avoir [installé cette extension](#install) et activé Smart Coupons par StoreApps. Il vous faut également un moyen de paiement dans l’[onglet Classique](../pos/checkout/legacy-tab.mdx) de l’écran de paiement : cet onglet ouvre la page de paiement de la boutique, qui contient un champ de code promo.

1. Remplissez le panier, appuyez sur **Paiement** et ouvrez l’onglet **Classique**. La page de paiement de la boutique s’ouvre dans l’écran de paiement.
2. Saisissez le code de la carte cadeau dans **Code promo** et appuyez sur **Appliquer le code promo**. Le total de la commande diminue du montant couvert par la carte.
3. Choisissez le moyen de paiement utilisé par le client pour régler le reste, encaissez le paiement sur cette page, puis appuyez sur **Traiter le paiement**.
4. Sur le reçu, vérifiez que la ligne de remise du code promo indique **Solde de l’avoir**, comme dans [Ce qu’affiche le reçu](#receipt). Si cette mention est absente, consultez [En cas de problème](#goes-wrong).

Si l’onglet **Classique** ne propose aucun moyen de paiement, aucune page de paiement ne permet d’accepter la carte. Encaissez comme d’habitude et demandez au client de conserver sa carte cadeau pour un prochain achat : aucun montant n’en a été déduit.

## Ce qu’affiche le reçu {#receipt}

La ligne de remise du code promo se termine par le solde de la carte au moment où le reçu est généré. Sur le **Reçu standard**, un code d’avoir dont la description est **Carte cadeau** affiche :

> Remise · Carte cadeau — Solde de l’avoir : $61.50

Sur le reçu à l’encaissement, il s’agit du solde juste après la vente. Aucune modification de votre modèle de reçu n’est nécessaire. Si le code promo n’a pas de description, la ligne se termine quand même par **Solde de l’avoir**. Pour afficher **Carte cadeau** à la place de **Remise** sur cette ligne, consultez [Pour les développeurs](#developers).

## Ce que fait l’extension {#what-it-does}

StoreApps tient à jour le solde des cartes cadeaux pour les commandes en ligne, mais ne prend pas en compte, à lui seul, les commandes payées au PDV. Lorsqu’une commande du PDV contient un code d’avoir, l’extension :

- **Déduit le montant dépensé, et rien de plus.** Elle enregistre le montant de la carte utilisé pour la commande, afin que StoreApps le déduise et laisse le reste sur la carte.
- **Réduit le solde lorsque la commande est payée.** Jamais à l’ajout du code promo, et jamais deux fois.
- **Ignore un code promo que vous avez retiré.** Si le code promo est retiré avant le paiement, aucun montant n’est déduit pour celui-ci.
- **Ajoute une note à la commande.** Consultez [La note sur la commande](#order-note).
- **Imprime le solde sur le reçu.** Consultez [Ce qu’affiche le reçu](#receipt).

Lorsque StoreApps Smart Coupons est désactivé, l’extension ne fait rien.

## Installer l’extension {#install}

Un administrateur l’installe une seule fois dans **WP Admin** : depuis **PDV → Réglages → Extensions** avec WCPOS Pro, ou en téléversant sa version publiée avec l’extension gratuite.

<details>
<summary>Étapes d’installation, avec WCPOS Pro ou l’extension gratuite</summary>

:::note Avant de commencer
Vous devez disposer d’un accès administrateur à **WP Admin**, et Smart Coupons par StoreApps (vendu sur WooCommerce.com) doit être actif sur le site. L’extension fonctionne uniquement avec ce module, pas avec les autres extensions dont le nom contient « Smart Coupons ».
:::

### Avec WCPOS Pro {#install-pro}

1. Dans **WP Admin**, allez dans **PDV → Réglages → Extensions**.
2. Recherchez **WCPOS StoreApps Smart Coupons** et appuyez sur **Installer**.
3. Appuyez sur **Activer**.

Consultez [Installer une extension](./index.mdx#installing-an-extension) pour les mises à jour manuelles et automatiques.

### Avec l’extension gratuite {#install-free}

L’écran Extensions affiche l’extension, mais ses boutons nécessitent Pro. Procédez plutôt ainsi :

1. Téléchargez `wcpos-storeapps-smart-coupons.zip` depuis la [dernière version publiée](https://github.com/wcpos/wcpos-storeapps-smart-coupons/releases/latest) de l’extension.
2. Dans **WP Admin**, allez dans **Extensions → Ajouter une extension** et appuyez sur **Téléverser une extension**.
3. Choisissez le fichier téléchargé et appuyez sur **Installer maintenant**.
4. Appuyez sur **Activer l’extension**.

</details>

Il n’y a ensuite rien à configurer. Créez vos codes d’avoir ou cartes cadeaux dans WooCommerce comme d’habitude.

## La note sur la commande {#order-note}

Lorsque la commande est payée, l’extension y ajoute une note privée. Le personnel peut la consulter sur la commande dans **WP Admin → WooCommerce → Commandes** :

> Avoir StoreApps Smart Coupons enregistré pour WCPOS : le code promo store100 a utilisé $38.50. Solde actuel : $61.50.

Utilisez cette note pour vérifier quelle carte a servi au paiement, le montant couvert et le solde restant. La note est ajoutée une seule fois par commande.

## Remboursements et annulations {#refunds}

L’extension ne recrédite pas les avoirs. Lorsque vous remboursez ou annulez une commande réglée en partie avec un avoir, StoreApps détermine ce qu’il advient du solde. Vérifiez ensuite le montant du code promo dans **WP Admin → Marketing → Codes promo**. S’il ne correspond pas au montant dû au client, adressez-vous à l’administrateur de votre boutique : il peut y modifier le montant du code promo.

## En cas de problème {#goes-wrong}

**Code promo introuvable** lorsque vous appliquez une carte cadeau depuis **Ajouter une remise**. Dans WCPOS 2.0, Ajouter une remise accepte uniquement les codes promo de type pourcentage, remise fixe sur le panier ou remise fixe sur un produit. Un code d’avoir y affiche donc **Code promo introuvable**, avec ou sans cette extension. Utilisez plutôt [la page de paiement de l’onglet Classique](#at-the-till).

**Le solde n’a pas diminué après la vente.** Vérifiez que **Smart Coupons** et **WCPOS StoreApps Smart Coupons** sont tous deux actifs dans **Extensions**. La déduction intervient lorsque la commande est payée, pas à l’ajout du code promo. Une commande sans note relative à l’avoir n’a donné lieu à aucune déduction par l’extension.

**Le reçu n’affiche pas de solde.** Un reçu imprimé lorsque la caisse est hors ligne n’affiche aucun solde. Imprimez-le à nouveau une fois la caisse reconnectée. Si le solde est toujours absent, votre modèle de reçu n’imprime pas le libellé de la ligne de remise ; consultez [Données du reçu](../receipts/receipt-data.mdx#discounts).

<details>
<summary>Pour les développeurs : données enregistrées et hooks</summary>

<Anchor id="developers" />

L’extension n’ajoute aucun champ de code promo WCPOS. Elle s’appuie sur les métadonnées des commandes WooCommerce et sur la logique de gestion du solde de StoreApps. Elle s’applique uniquement aux commandes du PDV (`wcpos_is_pos_order()` : `created_via` vaut `woocommerce-pos`) et aux codes promo de type `smart_coupon`.

- **Utilisation.** Sur `woocommerce_order_after_calculate_totals`, elle écrit les métadonnées de commande StoreApps `smart_coupons_contribution` (code promo → montant utilisé) et `wc_sc_environment` lorsque StoreApps ne l’a pas fait. Elle supprime les entrées des codes promo qui ne figurent plus sur la commande impayée.
- **Champ de code promo de la page de paiement.** Ce formulaire effectue une simple requête POST depuis l’interface publique vers `WC_Order::apply_coupon()`, que StoreApps ne considère pas comme un contexte de commande. Lorsqu’une commande impayée du PDV contenant une ligne `smart_coupon` est recalculée en dehors d’une requête REST, l’extension signale un contexte REST afin que la logique de remise sur commande de StoreApps s’exécute.
- **Déduction.** Une commande du PDV est payée depuis le statut `pos-open` ou `pos-partial`, et StoreApps ne déduit le montant que lors d’une transition depuis `pending` ou `failed`. Sur `woocommerce_order_status_changed`, lors du passage de tout autre statut à un statut payé ou à `on-hold`, l’extension appelle `WC_SC_Coupon_Process::update_smart_coupon_balance()` de StoreApps, qui marque chaque ligne de code promo afin de ne jamais déduire deux fois le montant.
- **Note de commande.** Ajoutée lors du passage à `processing`, `completed` ou `on-hold`, une seule fois par commande (`_wcpos_storeapps_smart_coupons_audit_note_added`).
- **Reçu.** L’extension filtre `woocommerce_coupon_get_description` pendant le rendu d’un reçu WCPOS et, via le filtre des données du reçu, ajoute `gift_card: true` à la ligne d’avoir dans `discounts` et ajoute le solde à la fin de son `label`. Un modèle peut alors imprimer :

```text
{{#discounts}}{{#gift_card}}Gift Card{{/gift_card}}{{^gift_card}}{{i18n.discount}}{{/gift_card}} · {{label}}{{/discounts}}
```

- **Noms des hooks.** La version 0.2.3 utilise encore les noms antérieurs à la 2.0 : `woocommerce_pos_receipt_data`, `woocommerce_pos_before_template_render` et `woocommerce_pos_after_template_render`. WCPOS 2.0 les déclenche toujours après leurs équivalents `wcpos_`, et WordPress journalise un avis d’obsolescence pour chacun lorsque `WP_DEBUG` est activé. Consultez [Nommage des hooks](./index.mdx#hook-naming).

Source : [github.com/wcpos/wcpos-storeapps-smart-coupons](https://github.com/wcpos/wcpos-storeapps-smart-coupons).

</details>
