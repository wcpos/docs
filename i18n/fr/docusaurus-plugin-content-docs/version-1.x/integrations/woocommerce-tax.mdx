# WooCommerce Tax {#woocommerce-tax}

[WooCommerce Tax](https://woocommerce.com/document/woocommerce-tax/) est l’extension WooCommerce qui recherche automatiquement les taxes de vente via TaxJar, au lieu de maintenir manuellement un tableau de taux. WCPOS fonctionne avec cette extension : les ventes POS utilisent les mêmes taux de juridiction que vos commandes en ligne, et rien ne doit être activé dans WCPOS.

## Fonctionnement {#how-it-works}

WooCommerce Tax ne demande des taux à TaxJar que lorsqu’une commande passe par le paiement en ligne ou est modifiée dans l’écran des commandes WooCommerce. Les commandes PDV ne suivent aucune de ces voies ; WCPOS effectue donc la requête pour elles :

1. Lorsque le PDV enregistre une commande ouverte, WCPOS demande à WooCommerce Tax les taux correspondant au lieu d’imposition de la commande. Ce lieu dépend du réglage **Calculer la taxe selon** du PDV : l’adresse de base de la boutique, ou l’adresse de facturation ou de livraison du client.
2. WooCommerce Tax inscrit ces taux dans le tableau habituel des taux de taxe de votre boutique, à raison d’une ligne par juridiction, exactement comme pour une commande en ligne. Ils apparaissent sous `WP Admin > WooCommerce > Réglages > Tax > Standard rates`, classés par code postal et ville.
3. WooCommerce applique les lignes à la commande. Celle-ci comporte une ligne de taxe par juridiction, avec les noms utilisés par WooCommerce Tax (par exemple *CA STATE TAX*, *CA COUNTY TAX*).
4. Le PDV télécharge les nouvelles lignes lors de sa prochaine vérification des modifications, généralement en moins d’une minute. Ses totaux locaux correspondent alors à ceux de votre boutique. Pour les récupérer immédiatement, utilisez **Effacer et télécharger à nouveau** sur la ligne **Taux de taxe** sous [État de la boutique → Base de données](/1.x/support/store-health#clear-and-redownload).

L’ajout ou la suppression de lignes dans une commande PDV ouverte entraîne le recalcul de sa taxe à partir des lignes actuelles. Une fois la commande payée, WCPOS ne la modifie plus et WooCommerce Tax se comporte comme pour toute autre commande.

Lorsque les taxes automatisées sont désactivées, WCPOS n’applique aucun traitement particulier et le PDV utilise comme d’habitude le tableau des taux de taxe de votre boutique.

## Configuration {#setup}

<Steps>
  <StepCard number="1" title="Connecter WooCommerce Tax">

Installez et activez WooCommerce Tax, puis connectez-le à WordPress.com. `WP Admin > WooCommerce > Status > WooCommerce Tax` doit indiquer **Connecté à WordPress.com**.

  </StepCard>
  <StepCard number="2" title="Activer les taxes automatisées">

Dans `WP Admin > WooCommerce > Réglages > Tax`, définissez **Taxes automatisées** sur **Activer les taxes automatisées**. Votre boutique doit se trouver dans un pays pris en charge par WooCommerce Tax.

L’activation de cette option sauvegarde les taux saisis manuellement dans un fichier CSV et les supprime du tableau. Téléchargez la sauvegarde depuis `WP Admin > WooCommerce > Status > WooCommerce Tax` si vous risquez d’en avoir de nouveau besoin.

  </StepCard>
  <StepCard number="3" title="Reproduire les réglages dans le PDV">

Dans le PDV, ouvrez les [Paramètres de taxe](/1.x/settings/store/tax) et cliquez sur **Restaurer les réglages du serveur**. Lorsque les taxes automatisées sont activées, WooCommerce Tax impose à WooCommerce de calculer la taxe à partir de l’adresse de livraison du client, avec des prix saisis et affichés *hors* taxe. Le PDV doit reproduire ces réglages.

Si vous conservez volontairement l’adresse de base de la boutique dans le PDV pour les ventes aux clients de passage, WCPOS utilise également cette base pour les commandes PDV de votre boutique, afin que les deux concordent.

  </StepCard>
  <StepCard number="4" title="Effectuer une vente test" isLast>

Ajoutez à la vente un produit taxable de la classe de taxe **Standard** et laissez la commande s’enregistrer. Vérifiez-la dans WP Admin : elle doit comporter des lignes de taxe portant le nom des juridictions, et les lignes correspondantes doivent être apparues sous **Taux standard**. Pour les produits d’une autre classe de taxe, les lignes apparaissent sous cette classe lors de la première vente qui en inclut un.

  </StepCard>
</Steps>

## À quoi s’attendre {#what-to-expect}

- **La première vente dans un nouvel emplacement peut présenter un écart ponctuel.** Le PDV calcule le total d’une vente à partir des lignes de taux qu’il a déjà téléchargées. Si votre boutique n’a encore jamais appliqué de taxe à une adresse, aucune ligne n’existe pour celle-ci ; le PDV peut donc afficher l’[avis sur les totaux](/1.x/support/troubleshooting/totals-disagree) pour cette vente. Ce sont les chiffres de votre boutique qui sont enregistrés. Une fois la ligne reçue par le PDV, généralement en moins d’une minute, les ventes suivantes à cet emplacement concordent. Avec une taxe basée sur l’adresse du client, cela peut se produire une fois par nouveau code postal ; avec l’adresse de base de la boutique, normalement uniquement lors de la toute première vente. Un changement de taux dans une juridiction peut provoquer un nouvel écart.
- **N’ajoutez pas de lignes de taux manuellement.** Les lignes d’un emplacement apparaissent lors de la première vente à cet emplacement. Si **Voir tous les taux de taxe** dans le PDV ne présente aucune ligne pour un emplacement, aucune vente n’y a encore été effectuée.
- **Les frais ne sont pas envoyés à TaxJar.** Les frais taxables sont taxés au taux déjà présent dans votre tableau pour leur classe de taxe. C’est également ainsi que WooCommerce Tax traite les frais sur son propre écran de commande.
- **L’échec d’une recherche ne bloque jamais une vente.** Si TaxJar est inaccessible ou si WooCommerce Tax refuse de rechercher les taux de la commande (absence de code postal dans l’adresse, client exonéré de taxe, emplacement où votre boutique n’a pas de lien fiscal), la commande est tout de même enregistrée avec les taux déjà présents dans votre tableau. Les journaux du PDV sur votre serveur indiquent le cas rencontré : *WooCommerce Tax rate priming failed* en cas d’indisponibilité, *WooCommerce Tax returned no rates for the POS order* en cas de refus. Consultez les [journaux](/1.x/support/logs).
- **Stripe Tax est différent.** Stripe Tax ne fonctionne pas du tout avec les commandes PDV. Consultez les [conflits entre extensions](/1.x/support/troubleshooting/plugin-conflicts).
