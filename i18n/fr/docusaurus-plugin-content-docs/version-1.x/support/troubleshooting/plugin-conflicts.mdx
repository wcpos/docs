Les conflits entre extensions sont l’une des causes les plus courantes de problèmes avec WCPOS. Lorsque d’autres extensions WordPress interfèrent avec les fonctionnalités de WooCommerce ou de WCPOS, vous pouvez rencontrer des plantages, des problèmes de performance ou des comportements inattendus.

## Signes de conflits entre extensions {#signs-of-plugin-conflicts}

Un conflit entre extensions peut être en cause si vous rencontrez les problèmes suivants :

- **Erreurs fatales** - « Une erreur critique est survenue sur ce site web »
- **Problèmes de performance** - Chargement lent, délais d’attente dépassés ou charge élevée du serveur
- **Problèmes de fonctionnement** - Fonctionnalités qui ne fonctionnent pas comme prévu
- **Problèmes de synchronisation des données** - Produits, commandes ou clients qui ne se synchronisent pas correctement
- **Problèmes de passerelle de paiement** - Échecs lors du passage en caisse ou erreurs de traitement des paiements

## Avant de commencer : utilisez un site de préproduction {#before-you-start-use-a-staging-site}

:::warning Important
**Ne recherchez jamais la cause d’un conflit entre extensions sur votre site en production.** Utilisez toujours un environnement de préproduction pour éviter de perturber votre activité.
:::

### Qu’est-ce qu’un site de préproduction ? {#what-is-a-staging-site}

Un site de préproduction est une copie exacte de votre site en production, sur laquelle vous pouvez tester des modifications en toute sécurité sans affecter vos clients. La plupart des hébergeurs modernes proposent des environnements de préproduction en standard.

### Si votre hébergeur ne propose pas de préproduction {#if-your-host-doesnt-offer-staging}

Si votre hébergeur ne propose pas de sites de préproduction, **envisagez de passer à un hébergeur qui en propose**. Cette fonctionnalité est aujourd’hui standard et essentielle pour :

- Tester les extensions et les thèmes en toute sécurité
- Mettre à jour WordPress
- Résoudre les problèmes
- Effectuer des travaux de développement

**Hébergeurs recommandés proposant la préproduction :**
- WP Engine
- SiteGround  
- Kinsta
- Cloudways
- Et bien d’autres

## Étape 1 : recherchez les erreurs fatales {#step-1-check-for-fatal-errors}

Si vous rencontrez des plantages ou des erreurs critiques, commencez par consulter les journaux d’erreurs :

1. **Consultez les journaux WCPOS** - Ouvrez [**État de la boutique → Journaux**](/1.x/support/logs) dans WCPOS pour rechercher des messages d’erreur
2. **Consultez les journaux d’erreurs fatales** - Suivez le [guide de dépannage des erreurs critiques](/1.x/support/troubleshooting/critical-error) pour trouver des messages d’erreur détaillés
3. **Notez les détails de l’erreur** - Recherchez les noms d’extensions ou les chemins de fichiers mentionnés dans l’erreur

Si vous trouvez une erreur fatale qui mentionne une extension précise, celle-ci est probablement en cause. Vous pouvez la désactiver, puis vérifier si le problème est résolu.

## Étape 2 : la méthode d’élimination des extensions {#step-2-the-plugin-elimination-method}

Si les journaux ne contiennent aucune erreur fatale, ou si vous souhaitez identifier des conflits liés aux performances, procédez de manière systématique :

### 2.1 Établissez une référence {#21-create-a-baseline}

1. **Accédez à votre site de préproduction**
2. **Testez la fonctionnalité problématique** - Notez précisément ce qui ne fonctionne pas ou ce qui est lent
3. **Relevez les métriques de performance** - S’il s’agit d’un problème de performance, notez les temps d’exécution indiqués dans les [Journaux](/1.x/support/logs)

### 2.2 Désactivez toutes les extensions (sauf les indispensables) {#22-disable-all-plugins-except-essential-ones}

**Gardez ces extensions actives :**
- WooCommerce
- WCPOS
- WCPOS Pro (si vous en disposez)

**Désactivez toutes les autres :**
1. Accédez à `WP Admin > Extensions`
2. Sélectionnez toutes les autres extensions
3. Choisissez « Désactiver » dans le menu déroulant des actions groupées
4. Cliquez sur « Appliquer »

### 2.3 Vérifiez si le problème persiste {#23-test-the-issue}

1. **Videz tous les caches** - Si vous utilisez des extensions de mise en cache, videz tous les caches
2. **Testez la fonctionnalité problématique** - Fonctionne-t-elle maintenant ?
3. **Vérifiez les performances** - Les temps d’exécution se sont-ils améliorés ?

**Si le problème est résolu :** il s’agit d’un conflit entre extensions. Passez à l’étape 2.4.

**Si le problème persiste :** il ne s’agit probablement pas d’un conflit entre extensions. Examinez les pistes suivantes :
- Problèmes de ressources du serveur (voir [Performance du serveur](/1.x/support/performance/server))
- Conflits avec le thème (voir l’étape 3)
- Problèmes liés au cœur de WordPress ou de WooCommerce

### 2.4 Activez les extensions une par une {#24-enable-plugins-one-by-one}

Vous devez maintenant identifier l’extension à l’origine du conflit :

1. **Activez une extension** - Commencez par les plus indispensables
2. **Testez la fonctionnalité** - Vérifiez si le problème réapparaît
3. **Si aucun problème ne survient** - Activez l’extension suivante et testez à nouveau
4. **Si le problème réapparaît** - Vous avez trouvé l’extension à l’origine du conflit !

**Ordre de priorité des extensions (activez-les dans cet ordre) :**
1. **Extensions de sécurité** - Wordfence, Sucuri, etc.
2. **Extensions SEO** - Yoast, RankMath, etc.  
3. **Extensions de performance** - Mise en cache, optimisation
4. **Passerelles de paiement** - Stripe, PayPal, etc.
5. **Autres extensions WooCommerce**
6. **Extensions WordPress générales**

### 2.5 Consignez vos observations {#25-document-your-findings}

Lorsque vous identifiez l’extension à l’origine du conflit :

1. **Notez le nom et la version de l’extension**
2. **Décrivez précisément le problème qu’elle provoque**
3. **Vérifiez si une version plus récente est disponible**
4. **Recherchez d’autres extensions offrant des fonctionnalités similaires**

## Étape 3 : recherchez les conflits avec le thème {#step-3-check-for-theme-conflicts}

Bien que les thèmes affectent rarement WCPOS (qui utilise sa propre interface), ils peuvent parfois provoquer des problèmes avec :

- Les processus de paiement (si vous utilisez la passerelle de paiement web)
- Les fonctionnalités de l’espace d’administration
- Les réponses de l’API

### Testez avec un thème par défaut {#test-with-a-default-theme}

1. **Sur votre site de préproduction**, passez à un thème WordPress par défaut :
   - Twenty Twenty-Four
   - Twenty Twenty-Three
   - Twenty Twenty-Two
2. **Testez la fonctionnalité problématique**
3. **Si le problème est résolu** - Votre thème provoque un conflit

:::info Impact du thème
Les thèmes sont beaucoup moins susceptibles de provoquer des problèmes avec WCPOS que les extensions. L’interface du PDV fonctionne indépendamment de votre thème. Toutefois, les thèmes peuvent affecter :
- Les pages de paiement de WooCommerce
- Les fonctionnalités de l’administration WordPress
- Les réponses de l’API REST
:::

## Étape 4 : résolvez les conflits entre extensions {#step-4-resolving-plugin-conflicts}

Une fois l’extension à l’origine du conflit identifiée, plusieurs options s’offrent à vous :

### Option 1 : mettre à jour l’extension {#option-1-update-the-plugin}

1. **Recherchez les mises à jour** - Le conflit a peut-être été corrigé dans une version plus récente
2. **Mettez à jour l’extension** sur votre site de préproduction en premier
3. **Effectuez des tests approfondis** avant de mettre à jour le site en production

### Option 2 : trouver une alternative {#option-2-find-an-alternative}

1. **Recherchez d’autres extensions** offrant les mêmes fonctionnalités
2. **Testez les alternatives** sur votre site de préproduction
3. **Migrez les réglages** si vous changez d’extension

### Option 3 : contacter le développeur de l’extension {#option-3-contact-plugin-developer}

1. **Signalez le conflit** au développeur de l’extension
2. **Fournissez des informations détaillées :**
   - Versions des extensions concernées
   - Versions de WordPress et de WooCommerce
   - Messages d’erreur exacts ou comportement précis
   - Étapes permettant de reproduire le problème

### Option 4 : solution personnalisée {#option-4-custom-solution}

Pour les extensions indispensables qui ne peuvent pas être remplacées :

1. **Contactez un développeur WordPress** pour créer un correctif personnalisé
2. **Envisagez d’utiliser des hooks propres à l’extension** pour désactiver la fonctionnalité à l’origine du conflit
3. **Utilisez une logique conditionnelle** pour désactiver l’extension sur les pages liées au PDV

## Types d’extensions fréquemment à l’origine de conflits {#common-conflicting-plugin-types}

### Catégories d’extensions à risque élevé {#high-risk-plugin-categories}

**Extensions de sécurité :**
- Peuvent bloquer les requêtes API
- Peuvent perturber l’authentification
- Appliquent souvent des règles de pare-feu strictes

**Extensions de mise en cache :**
- Peuvent mettre en cache les réponses de l’API de manière inappropriée
- Peuvent perturber les données en temps réel
- Peuvent provoquer des problèmes de données obsolètes

**Extensions SEO :**
- Les extensions lourdes peuvent ralentir l’espace d’administration
- Peuvent ajouter des requêtes inutiles à la base de données
- Peuvent perturber les réponses de l’API REST

**Constructeurs de pages :**
- Chargent souvent des scripts lourds dans l’espace d’administration
- Peuvent entrer en conflit avec les pages d’administration de WooCommerce
- Peuvent perturber les processus de paiement

**Extensions d’adhésion ou de restriction d’accès :**
- Peuvent bloquer l’accès à l’API
- Peuvent perturber l’authentification des utilisateurs
- Peuvent restreindre l’accès aux ressources nécessaires

### Catégories d’extensions à risque plus faible {#lower-risk-plugin-categories}

**Formulaires de contact :** n’interfèrent généralement pas avec WCPOS
**Extensions de réseaux sociaux :** provoquent rarement des conflits
**Extensions d’analyse :** généralement sans risque, sauf si elles sont très lourdes
**Extensions de contenu basiques :** généralement compatibles
**WooCommerce Tax (taxes automatisées via TaxJar) :** pris en charge. WCPOS lui demande les taux lorsqu’une commande PDV ouverte est enregistrée ; les commandes du PDV bénéficient donc des mêmes taux automatisés que les commandes en ligne. Consultez [WooCommerce Tax](/1.x/integrations/woocommerce-tax).

## Conflits connus avec des extensions {#known-plugin-conflicts}

Les extensions ci-dessous sont connues pour interférer avec WCPOS. De nombreux problèmes ont déjà été corrigés automatiquement dans les versions récentes de WCPOS — **la mise à jour vers la dernière version** les résout sans aucune configuration.

:::tip La plupart des corrections consistent à « exclure le PDV »
Le point commun : WCPOS s’appuie sur l’API REST de WooCommerce et affiche certains parcours (connexion, paiement, reçus) dans des iframes. La correction habituelle consiste à **exclure les points de terminaison et les URL du PDV** (`/wp-json/wcpos/`, `/wp-json/wc/v3/` et le chemin `/pos/`) du traitement de l’autre extension — et non à la désactiver entièrement.
:::

### Extensions de sécurité et de connexion {#security-and-login-plugins}

Ce sont les sources de conflits **les plus courantes**, en particulier pour la connexion depuis l’application de bureau ou mobile.

| Extension | Symptôme | Correction |
| --- | --- | --- |
| **Wordfence** | Le pare-feu bloque l’API REST ; le champ du code 2FA ne s’affiche pas dans l’iframe de connexion ; une CSP restrictive peut bloquer les ressources du PDV | Autorisez `/wp-json/wcpos/` et `/wp-json/wc/v3/` dans le pare-feu. Pour la 2FA : désactivez-la temporairement pour les utilisateurs du PDV. La CSP est supprimée automatiquement en v1.9.0+ |
| **Really Simple Security** | Bloque l’accès à l’API ou impose des redirections | Désactivez toutes les restrictions de l’API REST dans les réglages **Avancés** de l’extension |
| **WPS Hide Login** | L’URL de connexion personnalisée empêche le bon fonctionnement de l’iframe de connexion de l’application | Utilisez l’URL de connexion standard `/wp-admin/` pour accéder au PDV |
| **iThemes / Solid Security** | Bloque l’API REST ou déclenche des blocages contre les attaques par force brute à cause des appels du PDV | Autorisez uniquement les points de terminaison du PDV et l’IP du serveur lui-même — évitez les règles générales sur les IP |
| **Sucuri** | Le WAF bloque les requêtes API | Autorisez les points de terminaison de l’API REST dans le tableau de bord Sucuri |
| **Security Optimizer** | Bloque la connexion administrateur au PDV (_« utilisez l’URL de connexion personnalisée »_) | Connectez-vous d’abord à WP Admin via l’URL personnalisée, puis accédez à `/pos` |
| **Force Login** (et extensions similaires d’authentification REST) | `/wp-json/` renvoie 401/403 ; les anciennes applications signalaient _« Le site ne semble pas être un site WordPress »_ | Autorisez l’accès non authentifié aux points de terminaison du PDV, ou désactivez l’extension pendant la connexion initiale. Les applications v1.x affichent désormais le véritable message d’erreur |
| **LoginPress** | Impose la connexion par e-mail ; empêche la connexion multi-utilisateur au PDV | Autorisez la connexion par nom d’utilisateur, ou désactivez l’extension pour l’accès au PDV |
| **Extensions d’authentification JWT** | Erreur 403 sur toutes les requêtes API du PDV après activation (la connexion peut réussir, mais tout le reste échoue) | Corrigé automatiquement en v1.8.x+. Sur les versions antérieures, désactivez l’extension JWT ou excluez les points de terminaison du PDV |
| **Captcha / reCAPTCHA** | Boucle de connexion dans l’application de bureau (le captcha ne peut pas s’afficher dans l’iframe) | Désactivez le captcha pour l’URL de connexion du PDV |
| **Defender Pro** | L’en-tête `X-Frame-Options` bloque toutes les iframes du PDV (connexion, paiement, reçus) | Ajoutez une exception propre au PDV pour `/pos/` plutôt que de désactiver `X-Frame-Options` sur l’ensemble du site |
| **Jetpack CRM Client Portal** | Empêche totalement la connexion au PDV | Désactivez uniquement l’extension Client Portal |

### Extensions de performance, de mise en cache et d’optimisation {#performance-caching-optimisation-plugins}

| Extension | Symptôme | Correction |
| --- | --- | --- |
| **WP Rocket, Autoptimize, Hummingbird, Smush** | Le chargement différé ou la minification du JS perturbe le paiement et Stripe Terminal | Excluez les URL `/pos/` de l’optimisation du JS |
| **LiteSpeed Cache** | Boucle de rechargement permanente au paiement dans l’application de bureau ; CSP restrictive | Mettez WCPOS à jour, purgez le cache et excluez les pages du PDV de la mise en cache. La CSP est supprimée automatiquement en v1.9.0+ |
| **Image Prioritizer** | Sature l’en-tête HTTP `Link`, empêchant la découverte de l’API REST ; l’application de bureau affiche _« ne semble pas être un site WordPress »_ | Désactivez l’extension |

### Constructeurs de pages et extensions injectant du contenu dans l’interface {#page-builders-front-end-injectors}

| Extension | Symptôme | Correction |
| --- | --- | --- |
| **Elementor** | `elementor-frontend.js` perturbe l’accordéon de paiement dans l’iframe du PDV — les moyens de paiement ne se déploient pas | Excluez les pages du PDV du chargement des scripts Elementor |
| **Omnisend / extensions marketing** | Injectent des scripts dans l’iframe de paiement, perturbant la mise en page et les paiements | Utilisez les **Paramètres de paiement** du PDV pour désactiver les scripts non indispensables |
| **MyStickyElements / Complianz** | Injectent des éléments superposés (boutons fixes, bannières de cookies) dans l’iframe de paiement | Configurez-les pour exclure les URL `/pos/` |

### Extensions WooCommerce et autres extensions {#woocommerce-extensions-other-plugins}

| Extension | Symptôme | Correction |
| --- | --- | --- |
| **WooCommerce Subscriptions** | Conflit du script de migration lors de la mise à niveau v1.7→v1.8 | Désactivez Subscriptions, activez WCPOS Pro (laissez la migration s’exécuter), puis réactivez Subscriptions |
| **WP Activity Log** | Journalise chaque action du PDV → accumulation de métadonnées postmeta → _« seulement 10 produits »_ | Désactivez l’extension, ou excluez les types de publication du PDV de la journalisation |
| **Jetpack / Astra / Xero** (tout ce qui utilise le hook `save_post`) | Lignes de métadonnées en double à chaque appel de l’API du PDV (une boutique a atteint 36,867 lignes pour un seul produit) | Corrigé automatiquement en v1.8.12+ (gratuit) / v1.8.14+ (Pro) avec une migration de nettoyage — il suffit de mettre à jour |
| **Stripe Tax** | Incompatible avec les commandes créées via l’API REST (méthode utilisée par le PDV pour créer les commandes) | Aucune solution de contournement — incompatible. [WooCommerce Tax](/1.x/integrations/woocommerce-tax) est la solution de taxes automatisées prise en charge |
| **Mollie** | Peut masquer le moyen de paiement BACS (virement bancaire) lors du paiement dans le PDV | Mettez Mollie à jour vers la dernière version |
| **CTX Feed** | Erreurs 403 intermittentes sur la page des paramètres du PDV | Désactivez l’extension pour confirmer ; aucune solution de contournement connue |
| **Extensions tierces de lecture de codes-barres** | Corrompent le JSON de l’API des commandes, empêchant la création ou l’affichage des commandes | Désactivez-les ; utilisez la lecture de codes-barres intégrée au PDV |
| **MailerLite** (Signup Forms + WooCommerce) | Erreur 500 lors de la création d’une commande dans le PDV (mémoire épuisée) | Désactivez l’extension pour confirmer, puis contactez MailerLite |
| **The Courier Guy Shipping** | La création de commandes dans le PDV échoue avec une erreur serveur | Revenez à une version précédente ou contactez le développeur |
| **PixelYourSite / PixelMySite** | Erreur fatale : _appel de la fonction membre `is_type()` sur une valeur booléenne_ | Désactivez temporairement l’extension |
| **Google Listings & Ads** | Conflit de chargement automatique → erreur critique _« Classe WCPOS\…\Stores introuvable »_ | Supprimez toutes les extensions du PDV et réinstallez uniquement la dernière version Pro autonome |

:::warning Stripe Terminal : ne l’activez pas globalement
La passerelle **Stripe Terminal** doit être activée **uniquement** dans les paramètres du PDV, jamais dans `WooCommerce > Réglages > Paiements`. L’activer globalement la fait apparaître sur la page de paiement publique de votre boutique et fait planter le parcours de paiement en ligne.
:::

### Conflits au niveau du serveur {#server-level-conflicts}

| Source | Symptôme | Correction |
| --- | --- | --- |
| **En-têtes CSP personnalisés** (`.htaccess`, Nginx ou une extension de sécurité) | PDV bloqué sur le logo ; JS/CSS bloqués | Supprimés automatiquement sur les pages du PDV en v1.9.0+. Pour une CSP au niveau du serveur, autorisez `cdn.jsdelivr.net` dans `script-src`/`style-src`, ou ajoutez une exception pour `/pos/` |
| **GoDaddy Website Firewall** | Bloque `/wp-json/` (_« Valeur reçue : 'undefined' »_) | Autorisez le chemin d’URL `/wp-json/` dans le pare-feu — voir [Performance du serveur](/1.x/support/performance/server#hosting-specific-notes) |

## Conseils de prévention {#prevention-tips}

### Maintenance régulière {#regular-maintenance}

1. **Gardez les extensions à jour** - Utilisez toujours les dernières versions
2. **Supprimez les extensions inutilisées** - Ne vous contentez pas de les désactiver, supprimez-les
3. **Testez les mises à jour en préproduction** avant de les appliquer au site en production
4. **Surveillez régulièrement les performances** à l’aide des métriques de [Performance du serveur](/1.x/support/performance/server)

### Bonnes pratiques pour choisir les extensions {#plugin-selection-best-practices}

1. **Choisissez des développeurs réputés** - Consultez les avis et la fréquence des mises à jour
2. **Évitez les fonctionnalités redondantes** - N’installez pas plusieurs extensions qui font la même chose
3. **Lisez les informations de compatibilité** - Vérifiez si les extensions sont testées avec WooCommerce
4. **Commencez avec un minimum d’extensions** - Ajoutez progressivement des fonctionnalités selon vos besoins
