WCPOS est traduit par IA, selon un ensemble de règles soigneusement élaboré, et amélioré grâce à des personnes comme vous. La machine produit rapidement une première version complète et cohérente dans chaque langue prise en charge après la modification d’une chaîne ; les personnes repèrent les nuances, le contexte et les usages locaux qui échappent à la machine. Vous n’avez pas à traduire toute une application, ni à être développeur pour aider. Cette page explique le fonctionnement du processus et où suggérer des changements.

## Fonctionnement actuel des traductions de WCPOS {#how-wcpos-translations-work-now}

Toutes les chaînes traduisibles — l’application destinée aux caissiers, l’application de bureau, les écrans d’administration WordPress, les chaînes PHP de l’extension et cette documentation — passent par un pipeline automatisé unique :

1. **Les chaînes sources sont extraites automatiquement** des applications, de l’extension et de la documentation vers le dépôt central [`wcpos/translations`](https://github.com/wcpos/translations) (et, pour la documentation, vers ce dépôt [`wcpos/docs`](https://github.com/wcpos/docs)).
2. **L’IA les traduit dans toutes les locales prises en charge**, selon un ensemble strict de règles qui préserve les espaces réservés, le code, les noms de marque et les chemins de menu tout en localisant le texte visible.
3. **Un contrôle quotidien de l’exhaustivité** recherche les chaînes manquantes ou obsolètes et les met automatiquement en file d’attente pour traduction, afin que les chaînes nouvelles ou modifiées ne restent pas sans traduction.
4. **Chaque lot fait l’objet d’une pull request soumise à une révision humaine** avant sa publication. Les traductions approuvées sont ensuite publiées et distribuées automatiquement — aux applications par CDN et à l’extension via son outil intégré de mise à jour des traductions.

Comme tout le processus est automatisé, votre rôle de contributeur consiste rarement à traduire à partir d’un fichier vierge : il s’agit plutôt d’**améliorer une traduction déjà présente**. Vous avez repéré une tournure maladroite, un terme qui devrait correspondre à celui utilisé par WooCommerce dans votre langue, ou un libellé inadapté au contexte ? Proposez une correction : elle sera publiée pour tout le monde.

:::note Nous n’utilisons plus translate.wordpress.org
WCPOS utilisait auparavant le site de traduction de WordPress (GlotPress) pour les chaînes de l’extension. **Nous l’avons complètement abandonné.** Ce processus est lent et obsolète et, surtout, il n’autorise pas la traduction automatique : la plupart des langues n’étaient donc jamais terminées. Un pipeline d’IA optimisé couvre bien plus de langues, reste automatiquement à jour et donne de meilleurs résultats en pratique. Si vous avez déjà traduit WCPOS sur ce site, merci — mais les contributions ne s’y font plus.
:::

## Améliorer les traductions de l’application et de l’extension {#improving-app-and-plugin-translations}

Toutes les traductions de l’application et de l’extension se trouvent dans le dépôt [`wcpos/translations`](https://github.com/wcpos/translations). Vous y trouverez :

- **`source/`** — les chaînes anglaises extraites. **Ne les modifiez pas** : elles sont générées automatiquement à partir des applications et de l’extension.
- **`translations/js/<locale>/<project>/<namespace>.json`** — les chaînes de l’interface traduites. Modifiez-les pour corriger les applications et les écrans d’administration.
- **`translations/php/<locale>/`** — les chaînes traduites de l’extension. Modifiez le fichier **`.po`** fichier ; les fichiers `.mo` et `.l10n.php` qui se trouvent à côté sont générés : ne les modifiez pas.

Les chaînes JavaScript sont réparties dans quatre `<project>` dossiers :

| Projet | Contenu |
|---|---|
| `monorepo` | L’application PDV utilisée par le caissier — boutons, panier, caisse, boîtes de dialogue et erreurs. |
| `electron` | L’enveloppe de l’application de bureau (Windows/macOS). |
| `woocommerce-pos` | Les écrans React de WP Admin de l’extension gratuite — réglages, modèles, journaux, etc. |
| `woocommerce-pos-pro` | Les écrans React de WP Admin de l’extension Pro — éditeur de boutiques et réglages Pro. |

**Pour suggérer une correction :**

1. **Trouvez la chaîne** dans le fichier correspondant à votre locale et à votre projet — par exemple `translations/js/de_DE/monorepo/core.json` pour une chaîne de l’application en allemand, ou `translations/php/de_DE/woocommerce-pos-de_DE.po` pour une chaîne de l’extension en allemand.
2. **Modifiez la valeur traduite.** Laissez les clés JSON, le code PHP `msgid`, ainsi que tous les `{{interpolation}}`, `%s`, `%d`, ou des balises `<tag>` espaces réservés exactement tels quels.
3. **Ouvrez une pull request.** Pour une correction d’une ligne, vous pouvez utiliser l’icône en forme de crayon sur GitHub, qui ouvrira une PR. Les réviseurs vérifient la modification et la fusionnent.

Si votre langue n’est pas encore disponible, consultez [Ajouter une nouvelle langue](#adding-a-new-language).

## Améliorer cette documentation {#improving-these-docs}

Le site de documentation utilise la configuration i18n standard de Docusaurus. Les sources anglaises se trouvent dans `versioned_docs/`, et les copies traduites par IA dans [`wcpos/docs`](https://github.com/wcpos/docs), sous `i18n/<locale>/docusaurus-plugin-content-docs/`. Chaque page anglaise a un équivalent dans chaque locale active.

**Pour suggérer une correction :**

1. **Ouvrez la page** dans votre langue et cliquez sur **Modifier cette page** en bas de page : vous accéderez directement au fichier MDX traduit sur GitHub.
2. **Modifiez la traduction.** Conservez la syntaxe Markdown/MDX, les liens, les segments de code et les clés du frontmatter ; traduisez le texte, les titres et les libellés visibles.
3. **Ouvrez une pull request.** Ne modifiez pas la source anglaise dans `versioned_docs/` pour « corriger » une traduction : modifiez uniquement le fichier dans `i18n/<locale>/`.

Pour une contribution plus importante — une section entière ou la création d’une nouvelle locale — ouvrez d’abord un ticket afin que nous puissions nous coordonner.

## Ajouter une nouvelle langue {#adding-a-new-language}

Les applications et l’extension proposent déjà des traductions pour **plus de 50 locales** (consultez [`locales.json`](https://github.com/wcpos/translations/blob/main/locales.json) pour la liste complète). La documentation en propose moins ; elles sont répertoriées ci-dessous. Si votre langue manque ou n’est que partiellement couverte, ouvrez un ticket dans le dépôt concerné et nous configurerons la locale. Le pipeline d’IA peut rapidement traduire une nouvelle langue ; la communauté pourra ensuite peaufiner le résultat.

## Codes de locale {#locale-codes}

Cette documentation est actuellement publiée dans les langues suivantes :

| Code | Langue |
|---|---|
| `ar` | Arabe *(écriture de droite à gauche)* |
| `de` | Allemand |
| `es` | Espagnol |
| `fr` | Français |
| `hi-IN` | Hindi (Inde) |
| `it` | Italien |
| `ja` | Japonais |
| `ko` | Coréen |
| `nl` | Néerlandais |
| `pt-BR` | Portugais (Brésil) |
| `zh-CN` | Chinois (simplifié) |

À propos du format des codes de locale : les applications et l’extension (`wcpos/translations`) utilisent la forme avec **underscore** pour les dossiers et les noms de fichiers — `de_DE`, `pt_BR`, `zh_CN` — et incluent les langues de base (`de`, `fr`, `es`) ainsi que les variantes régionales (`de_AT`, `fr_CA`, `es_MX`). La documentation et les balises de langue web utilisent la forme avec **tiret** — `pt-BR`, `hi-IN`, `zh-CN`. Utilisez la forme correspondant au dépôt que vous modifiez.

## Conseils aux traducteurs {#translator-tips}

Ces conseils reprennent les règles suivies par le pipeline d’IA : ce sont donc les mêmes éléments qu’un réviseur vérifiera :

- **Conservez les espaces réservés.** Les chaînes contiennent souvent `{{variable}}`, `%s`, `%d`, ou des balises `<strong>` — traduisez le texte qui les entoure, mais laissez les espaces réservés exactement tels quels. WCPOS y insère les valeurs réelles à l’exécution.
- **Conservez les noms de marque et de produit à l’identique.** `WCPOS`, `WCPOS Pro`, `WooCommerce`, `WordPress`, `Stripe`, `Stripe Terminal` et `SumUp` restent inchangés. Utilisez **WCPOS** dans les textes destinés aux clients ; les anciens noms de produits ne doivent figurer que dans les identifiants techniques tels que les slugs et les URL.
- **Localisez les libellés visibles de l’interface.** Les libellés de menu, de réglage et de bouton doivent être naturels dans votre langue ; reprenez ceux déjà utilisés par WordPress et WooCommerce dans votre locale (par exemple, un fil d’Ariane `WP Admin > Réglages > Paiements` doit utiliser les noms de menu WordPress de votre locale).
- **Respectez le ton existant.** La documentation et l’interface de WCPOS sont volontairement pratiques et directes, dans un registre neutre et formel. Si l’anglais indique *« Add Coupon »*, utilisez la forme verbale employée par votre langue pour des boutons similaires, et non un nom traduit littéralement.
- **Ne traduisez pas le code, les URL ni les identifiants techniques.** Les codes de coupon, les identifiants de passerelle, les codes de locale, les chemins de fichiers et les shortcodes restent en anglais. En cas de doute, laissez-les tels quels : c’est plus sûr que de modifier un élément dont dépend le système.
- **Testez en contexte si possible.** Réglez votre site ou votre application sur votre locale et vérifiez le texte sur l’écran concerné. Une expression adaptée à un écran peut manquer de place sur un autre.
- **Langues écrites de droite à gauche (RTL)** — arabe, hébreu, persan, ourdou — les modèles de reçu doivent également être marqués comme RTL. WCPOS inclut des modèles de reçu RTL ; consultez [Personnaliser votre reçu](/receipts/customise) pour la galerie.
