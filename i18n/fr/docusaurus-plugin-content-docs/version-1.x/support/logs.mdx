Le PDV dispose de deux interfaces de journalisation : le **journal d'activité intégré à l'application** (dans l'application PDV) et la **page Journaux de WP Admin** (dans WordPress). Ensemble, elles donnent une vue complète de l'activité du PDV à des fins de débogage et d'audit.

## Journaux de l'application PDV {#pos-application-logs}

:::info Modifié dans la v1.10.0
À partir de la v1.10.0, le journal intégré se trouve dans **État de la boutique → Journaux** (l'icône de battement de cœur dans le tiroir de navigation — l'écran Journaux autonome qu'il remplace a été supprimé). Cette section décrit le journal de la v1.10.0 ; consultez [État de la boutique](/support/store-health#logs) pour une visite complète de cette zone.
:::

### Accéder aux journaux {#accessing-logs}

Ouvrez **État de la boutique** depuis le tiroir de navigation de gauche (l'icône de battement de cœur) et sélectionnez l'onglet **Journaux**.

### Aperçu de l'interface {#interface-overview}

Le journal est un registre de l'activité sur cet appareil, conservé pendant 30 jours. Chaque ligne affiche :

| Colonne | Description |
|--------|-------------|
| **Heure** | Moment où l'événement s'est produit |
| **Niveau** | Gravité — erreur, avertissement, action, synchronisation ou info |
| **Événement** | Description lisible (traduite au moment de l'affichage) |
| **Durée** | Temps qu'a pris l'opération |
| **Statut** | Le résultat |

Au-dessus du registre, une ligne d'état affiche la pulsation de synchronisation — quand le dernier contrôle des changements a eu lieu et quand le prochain est prévu — et un en-tête de statistiques compte les événements et erreurs du jour, les enregistrements bloqués et les modifications en attente d'envoi. La plupart de ces éléments sont des filtres sur lesquels on peut appuyer.

#### Filtrage {#filtering}

Des pastilles prédéfinies filtrent le registre : **Tout**, **Actions** (ce qu'une personne a fait — ventes, modifications, changements de réglages), **Erreurs** et **Synchronisation**. Un commutateur distinct **Diagnostics détaillés** capture des informations supplémentaires pendant 24 heures, puis se désactive automatiquement.

### Détails d'une ligne et codes d'erreur {#row-details}

Appuyez sur une ligne d'erreur ou d'avertissement pour la développer. La vue détaillée vous donne :

- **Ce qui s'est passé**, en langage clair
- **Vos données** — une indication explicite sur la sécurité des données (par exemple, si la modification est bien enregistrée sur le serveur ou n'existe que sur cet appareil)
- **Ce qu'il faut faire** — l'étape suivante recommandée
- **Un lien d'aide** — les erreurs portent un code (par ex. `SYNC121`, `AUTH311`) renvoyant à la documentation [Codes d'erreur](/error-codes)
- **Un code d'événement copiable** — les titres des lignes étant traduits au moment de l'affichage, le code d'événement est l'identifiant stable. Mentionnez-le lorsque vous contactez le support.

## Page Journaux de WP Admin {#wp-admin-logs-page}

L'extension PDV fournit également une page Journaux côté serveur dans l'administration WordPress. Cette page affiche les avertissements et erreurs spécifiques au PDV consignés sur le serveur, ce qui peut aider à diagnostiquer des problèmes qui n'apparaissent pas dans l'application PDV elle-même.

### Accéder à la page Journaux de WP Admin {#accessing-the-wp-admin-logs-page}

Rendez-vous dans **WP Admin > POS > Réglages**, puis sélectionnez l'onglet **Outils** et cliquez sur **Journaux**.

### Badge des entrées non lues {#unread-badge}

L'élément de menu Journaux affiche un badge indiquant les entrées de journal non lues :

- **Badge rouge** - Il existe des entrées non lues de niveau erreur
- **Badge orange** - Il existe des entrées non lues de niveau avertissement (mais aucune erreur)

Consulter la page Journaux remet les compteurs de non-lus à zéro. Les compteurs sont suivis par utilisateur : chaque administrateur voit son propre état de lecture.

### Filtrer les entrées {#filtering-entries}

Utilisez le filtre de niveau pour restreindre les entrées de journal :

- **Tout** - Afficher toutes les entrées de journal
- **Erreurs** - Afficher uniquement les entrées de niveau erreur
- **Avertissements** - Afficher uniquement les entrées de niveau avertissement

### Entrées extensibles {#expandable-entries}

Les messages de journal longs sont tronqués aux alentours de 100 caractères. Cliquez sur une entrée pour la développer et voir le message complet ainsi que les éventuelles données de contexte supplémentaires.

### Pagination {#pagination}

Les entrées de journal sont paginées côté serveur. Utilisez les commandes de pagination pour parcourir les entrées plus anciennes.

### Bannière d'erreurs fatales {#fatal-errors-banner}

Si le serveur possède des fichiers `fatal-errors-*.log`, la page Journaux affiche une bannière d'avertissement en haut. Cette bannière renvoie vers **WooCommerce > État > Journaux**, où vous pouvez consulter l'intégralité des journaux d'erreurs fatales. Les erreurs fatales sont généralement des plantages au niveau de PHP qui empêchent l'API du PDV de répondre.

## Utiliser les journaux pour le support {#using-logs-for-support}

Lorsque vous demandez de l'aide :

1. **Reproduisez le problème** - Effectuez l'action qui provoque le problème
2. **Consultez les journaux** - Recherchez les erreurs ou avertissements dans **État de la boutique → Journaux**
3. **Développez la ligne** - Lisez l'indication sur la sécurité des données et l'étape suivante suggérée
4. **Copiez le code d'événement** - Incluez-le dans votre demande de support ; c'est l'identifiant stable de ce qui s'est produit
5. **Activez les Diagnostics détaillés** si le support demande plus de détails — ils capturent des informations supplémentaires pendant 24 heures

## Suivi des performances {#performance-monitoring}

Les performances agrégées se trouvent dans **État de la boutique → Performances** : requêtes, données transférées (une valeur plancher lorsque les réponses n'indiquent pas leur taille) et temps de réponse typique sur les dernières 24 heures, ainsi qu'une bande de disponibilité horaire. Si les temps de réponse semblent élevés, consultez [Performances du serveur](/support/performance/server).
