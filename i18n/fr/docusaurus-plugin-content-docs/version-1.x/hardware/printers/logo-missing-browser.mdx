**Symptôme :** les reçus imprimés depuis un onglet de navigateur sortent complets, sauf le logo de la boutique. Le même reçu imprimé depuis l'application de bureau ou mobile contient le logo normalement.

## Pourquoi cela arrive {#why-it-happens}

Le logo est stocké dans votre médiathèque WordPress, et le navigateur va l'y chercher. Avant qu'une page web puisse lire les pixels d'une image chargée depuis une autre adresse, le serveur qui l'héberge doit l'autoriser via un en-tête appelé `Access-Control-Allow-Origin`. WordPress n'envoie pas cet en-tête sur les fichiers téléversés par défaut : le navigateur fournit donc l'image pour l'affichage, mais pas pour l'impression.

L'application ne peut pas contourner cela — elle imprime le reçu sans le logo plutôt que de faire échouer la vente. Les applications de bureau et mobiles récupèrent le fichier elles-mêmes et ne sont pas soumises à cette règle.

## Ce qu'il faut faire {#do-this}

Choisissez ce qui convient le mieux à la boutique :

- **Imprimez depuis l'application de bureau.** Rien à configurer, et c'est la solution la plus rapide si la caisse l'a déjà installée.
- **Autorisez l'en-tête sur votre site.** La personne qui gère le site ajoute `Access-Control-Allow-Origin` pour le répertoire des fichiers téléversés, dans la configuration du serveur web ou via une extension qui définit les en-têtes CORS. Rechargez ensuite le POS et relancez l'impression.

## Si le logo s'imprime en bruit {#if-the-logo-prints-as-noise}

Une bande de points aléatoires à la place du logo est un autre problème : certaines imprimantes anciennes ou bon marché ne savent pas décoder le format d'image utilisé. Retirez le logo du modèle de reçu de cette imprimante.

## Toujours bloqué ? {#still-stuck}

Utilisez **Copier le rapport de configuration** sur l'écran de dépannage et collez-le dans votre message, avec l'adresse de l'image du logo.
