## Signification {#what-this-means}

L’index de recherche n’a pas répondu à temps. WCPOS a donc effectué la recherche directement dans le catalogue.

L’index de recherche local était encore en cours de création ou n’a pas pu répondre. Sur le web, cela se produit généralement parce que l’onglet POS est resté en arrière-plan, ou parce qu’un autre onglet contrôle la base de données ; sur ordinateur et mobile, cela se produit généralement juste après une synchronisation importante, ou dans les instants qui suivent le redémarrage de l’application pendant le rechargement de l’index enregistré. Les recherches continuent de répondre grâce à une analyse directe des données de cet appareil, puis repassent automatiquement à l’index dès qu’il répond.

## Vos données {#your-data}

Aucune donnée de boutique n’a été modifiée et la recherche a tout de même abouti : une analyse directe des données de cet appareil a répondu à la place de l’index. Les recherches peuvent simplement être un peu plus lentes jusqu’à ce que l’index prenne de nouveau le relais.

## Dépannage {#troubleshoot}

1. En général, aucune action n’est nécessaire : les résultats de recherche continuent de fonctionner et l’index reprend automatiquement le relais dès qu’il répond.
2. Sur le web, si WCPOS est ouvert dans plusieurs onglets de navigateur, fermez les onglets supplémentaires — un seul onglet peut contrôler la base de données locale — et gardez le POS dans sa propre fenêtre plutôt que dans un onglet en arrière-plan.
3. Si les recherches restent lentes ou si ce code continue d’apparaître, rechargez l’application une fois — sur le web, rechargez l’onglet du navigateur ; sur ordinateur et mobile, fermez puis rouvrez l’application.
4. Si le code s’affiche toujours après cela, exportez les informations de débogage et contactez l’assistance.
