## Ce que cela signifie {#what-this-means}

Votre boutique a renvoyé une erreur ; cette action ne s’est donc pas terminée.

La boutique a été jointe, mais son serveur n’a pas réussi à traiter la requête. Le problème vient du site web plutôt que du POS ; réessayer seul peut donc ne rien changer : consultez le journal d’erreurs du site ou demandez à l’hébergeur de le faire, puis réessayez. Rien n’a été perdu sur cet appareil.

## Vos données {#your-data}

La modification est enregistrée sur cet appareil mais n’est pas parvenue à votre boutique. Si le problème persiste, exportez les diagnostics et contactez l’assistance WCPOS.

## Dépannage {#troubleshoot}

**Dans le PDV (caissier) :** développez l’entrée du journal et notez le statut, le point de terminaison et le serverCode ; ils indiquent ce que faisait le serveur au moment de l’échec.

**Sur le site Web (administrateur du site / hébergeur) :**

1. Ouvrez WooCommerce → État → Journaux sur le site et consultez le journal fatal-errors le plus récent autour de l’heure de l’échec ; une réponse de classe 500 y laisse presque toujours une erreur PHP.
2. Si l’échec a commencé après la mise à jour d’une extension, d’un thème ou de PHP sur le site, suspectez d’abord ce changement et annulez-le ou désactivez-le.
3. Si les journaux de WooCommerce n’affichent rien, demandez à l’hébergeur le journal d’erreurs PHP du serveur pour la même plage horaire.

**Puis, de retour dans le PDV :** une fois la cause côté serveur corrigée, réessayez — la modification est toujours enregistrée sur cet appareil.
