## Ce que cela signifie {#what-this-means}

Une erreur s'est produite dans votre boutique, qui n'a pas terminé cette requête.

La boutique a été jointe, mais son serveur n'a pas pu traiter la requête : le problème vient du site Web, et non du PDV. Réessayez l'action. Si le problème persiste, demandez à l'administrateur de votre site de vérifier **WooCommerce → État → Journaux**. Aucune donnée n'a été perdue sur cet appareil.

## Vos données {#your-data}

N'effacez pas les données de cet appareil : elles peuvent contenir des modifications qui ne sont pas encore arrivées dans votre boutique. Une modification en cours d'envoi n'a peut-être pas atteint votre boutique. Si le problème persiste, utilisez **Copier les infos de débogage** dans l'onglet **Journaux** et contactez l'assistance WCPOS.

## Dépannage {#troubleshoot}

**Dans le PDV (caissier) :** développez l’entrée du journal et notez le statut, le point de terminaison et le serverCode ; ils indiquent ce que faisait le serveur au moment de l’échec.

**Sur le site Web (administrateur du site / hébergeur) :**

1. Ouvrez WooCommerce → État → Journaux sur le site et consultez le journal fatal-errors le plus récent autour de l’heure de l’échec ; une réponse de classe 500 y laisse presque toujours une erreur PHP.
2. Si l’échec a commencé après la mise à jour d’une extension, d’un thème ou de PHP sur le site, suspectez d’abord ce changement et annulez-le ou désactivez-le.
3. Si les journaux de WooCommerce n’affichent rien, demandez à l’hébergeur le journal d’erreurs PHP du serveur pour la même plage horaire.

**Ensuite, de retour dans le PDV :** réessayez l'action.
