## Signification {#what-this-means}

Le compte de boutique connecté ne correspond pas au caissier de cette caisse.

Chaque caissier conserve les données de sa propre caisse ; travailler sous un autre compte peut donc entraîner le mauvais classement des commandes. Déconnectez-vous, puis connectez-vous avec le compte du caissier concerné.

## Que faire {#what-to-do}

Une modification des réglages est nécessaire avant que cela fonctionne. WCPOS ne réessaie pas automatiquement ; réessayez lorsque vous êtes prêt.

## Vos données {#your-data}

Aucune donnée de commande ou de produit n’est affectée.

## Résolution des problèmes {#troubleshoot}

1. Le POS déconnecte automatiquement la session afin de protéger les données de chaque caissier — aucune donnée de commande n’est mélangée entre les comptes.
2. Reconnectez-vous avec le compte du caissier concerné ; travailler sous un autre compte peut entraîner un mauvais classement des commandes.
3. Si les caisses sont partagées entre plusieurs caissiers, intégrez le changement de compte à la routine de passation.

## Où chercher {#where-to-look}

Chaque occurrence de ce code est enregistrée sur l’appareil qui l’a générée. Ouvrez **État de la boutique → Journaux** (l’icône de pulsation cardiaque au bas du panneau de navigation), recherchez l’entrée marquée avec ce code et développez-la : la ligne développée affiche la raison en langage clair et le contexte capturé au moment de l’échec — pour tout ce qui implique une requête vers votre boutique, cela inclut le code d’erreur propre au serveur (`serverCode`), le `status` HTTP et le `endpoint`. Pour signaler un problème, utilisez **Copier les informations de débogage** en haut de l’écran Journaux (**Partager les informations de débogage** sur les téléphones et tablettes) plutôt que des captures d’écran : cette option regroupe la version de l’application, l’état de la connexion et les erreurs les plus récentes. Les journaux sont conservés pendant 30 jours au maximum ; collectez-les tant que le problème est récent.
