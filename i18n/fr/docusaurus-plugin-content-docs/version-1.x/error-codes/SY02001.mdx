# SY02001 : Configuration invalide {#sy02001-invalid-configuration}

## Ce que cela signifie {#what-this-means}

La configuration du système est invalide ou corrompue. L'application POS a trouvé des paramètres de configuration qui n'ont pas de sens ou qui sont incomplets.

## Causes courantes {#common-causes}

- **Paramètres corrompus** — Le fichier de configuration est devenu corrompu
- **Configuration incomplète** — Le processus de configuration n'a pas été terminé
- **Erreur d'édition manuelle** — Les fichiers de configuration ont été modifiés incorrectement
- **Problème de mise à niveau de version** — L'ancienne configuration n'est pas compatible avec la nouvelle version

## Comment résoudre le problème {#how-to-fix}

### 1. Réinitialiser les paramètres par défaut {#1-reset-to-default-settings}

Si disponible dans l'application :
- Recherchez "Réinitialiser les paramètres" ou "Restaurer les valeurs par défaut"
- Cette opération efface les réglages personnalisés, mais corrige la corruption. Si la réinitialisation propose de supprimer votre boutique ou ses données, arrêtez-vous et effectuez d’abord la vérification indiquée dans l’avertissement de l’étape 3

### 2. Compléter la configuration {#2-complete-the-setup}

Si la configuration n'était pas terminée :
1. Relancez le processus de configuration
2. Complétez toutes les étapes requises
3. Vérifiez la configuration avant de terminer

### 3. Effacer les données de l'application {#3-clear-application-data}

:::warning Vérifiez d’abord qu’aucun travail n’est en attente d’enregistrement
La suppression des données locales ou la réinstallation de l’application efface tout ce qui se trouve sur cet appareil sans avoir été transmis à votre boutique — notamment les ventes effectuées hors ligne, les paniers ouverts et les modifications non enregistrées. Avant toute suppression, ouvrez **Store health → Database** et vérifiez qu’aucun élément n’est indiqué comme retenu ou comme n’ayant jamais atteint votre serveur, puis vérifiez dans **Store health → Logs** qu’il y a **0 enregistrement bloqué** et **0 modification en attente d’envoi** ; terminez ou notez ensuite chaque panier ouvert. Si votre WCPOS ne comporte pas de page Store health, mettez d’abord WCPOS à jour, puis vérifiez. Si un élément est répertorié ou en attente, ou si vous ne pouvez pas vérifier, ne supprimez rien — demandez conseil au propriétaire de votre boutique ou contactez l’assistance.
:::

Uniquement si les autres étapes de cette page n’ont pas résolu le problème, et seulement après avoir effectué la vérification ci-dessus, supprimez la configuration corrompue :
- **Bureau :** Supprimez le dossier de données de l'application, redémarrez l'application
- **Navigateur :** Effacez les données du site, rechargez

### 4. Réinstaller l'application {#4-reinstall-the-application}

:::warning Vérifiez d’abord qu’aucun travail n’est en attente d’enregistrement
La suppression des données locales ou la réinstallation de l’application efface tout ce qui se trouve sur cet appareil sans avoir été transmis à votre boutique — notamment les ventes effectuées hors ligne, les paniers ouverts et les modifications non enregistrées. Avant toute suppression, ouvrez **Store health → Database** et vérifiez qu’aucun élément n’est indiqué comme retenu ou comme n’ayant jamais atteint votre serveur, puis vérifiez dans **Store health → Logs** qu’il y a **0 enregistrement bloqué** et **0 modification en attente d’envoi** ; terminez ou notez ensuite chaque panier ouvert. Si votre WCPOS ne comporte pas de page Store health, mettez d’abord WCPOS à jour, puis vérifiez. Si un élément est répertorié ou en attente, ou si vous ne pouvez pas vérifier, ne supprimez rien — demandez conseil au propriétaire de votre boutique ou contactez l’assistance.
:::

Uniquement en cas de problèmes persistants, et seulement après avoir effectué la vérification ci-dessus :
1. Désinstallez complètement
2. Supprimez tous les dossiers de données restants
3. Réinstallez à neuf
4. Complétez la configuration depuis le début

### 5. Vérifier les mises à jour {#5-check-for-updates}

Les formats de configuration peuvent changer :
- Mettez à jour l'application POS
- Mettez à jour le plugin WCPOS
- Reconfigurez après la mise à jour

## Ce qui est réinitialisé {#what-gets-reset}

Lors de la réinitialisation de la configuration :
- Vous devrez vous reconnecter
- Les paramètres personnalisés seront perdus
- Les données devront être resynchronisées
- Vos données WooCommerce sont en sécurité sur le serveur, mais tout ce qui se trouve sur cet appareil sans avoir jamais été transmis à votre boutique — par exemple un panier ouvert — est perdu
