## Signification {#what-this-means}

WCPOS a mis trop de requêtes en file d’attente simultanément et en a abandonné certaines.

Il s’agit généralement d’un défaut de l’application plutôt que d’un problème lié à la boutique. Redémarrez WCPOS ; si le code réapparaît, exportez les diagnostics et contactez le support.

## Que faire {#what-to-do}

Exportez les diagnostics et contactez le support. WCPOS ne réessaie pas automatiquement ; réessayez lorsque vous êtes prêt.

## Vos données {#your-data}

Aucune donnée de commande ou de produit n’est affectée. Si le problème persiste, exportez les diagnostics et contactez le support WCPOS.

## Résolution des problèmes {#troubleshoot}

1. Patientez quelques secondes — la file d’attente se vide d’elle-même et les requêtes obsolètes sont automatiquement supprimées — puis réessayez l’action.
2. Si cela se reproduit au cours de la même session, redémarrez WCPOS ; la file d’attente est vidée au redémarrage.
3. Il s’agit généralement d’un défaut de l’application plutôt que d’un problème de boutique : si le problème persiste, exportez les informations de débogage et contactez l’assistance — le contexte de l’entrée indique aux développeurs quelles requêtes ont saturé la file d’attente.

## Où chercher {#where-to-look}

Chaque occurrence de ce code est enregistrée sur l’appareil qui l’a générée. Ouvrez **État de la boutique → Journaux** (l’icône de pouls cardiaque en bas du panneau de navigation), recherchez l’entrée marquée de ce code et développez-la : la ligne développée affiche la raison en langage clair et le contexte capturé au moment de l’échec — pour tout élément impliquant une requête vers votre boutique, cela comprend le propre code d’erreur du serveur (`serverCode`), le `status` HTTP et l’`endpoint`. Pour signaler un problème, utilisez **Copier les informations de débogage** en haut de l’écran Journaux (**Partager les informations de débogage** sur les téléphones et tablettes) plutôt que des captures d’écran : cela regroupe la version de l’application, l’état de la connexion et les erreurs les plus récentes. Les journaux sont conservés pendant 30 jours au maximum ; collectez-les donc tant que le problème est récent.

En plus du journal intégré à l’application, cet échec peut laisser des traces dans :

- **Console** (web et ordinateur) : l’onglet **Console** des mêmes outils de développement enregistre les erreurs côté client, y compris celles qui surviennent avant que le POS puisse écrire sa propre entrée de journal.
