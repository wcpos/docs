## Ce que cela signifie {#what-this-means}

Ce navigateur autorise un seul onglet à envoyer des modifications à la fois.

Tous les onglets peuvent continuer à être utilisés : ils partagent les mêmes données locales. Un onglet gère discrètement la synchronisation pour tous les autres.

## Que faire {#what-to-do}

Le travail peut se poursuivre : WCPOS gère cette situation automatiquement. Ne réessayez pas : le résultat ne changera pas.

## Vos données {#your-data}

Aucune donnée de commande ou de produit n’est affectée.

## Résolution des problèmes {#troubleshoot}

1. Continuez à utiliser normalement tous les onglets — ils partagent les mêmes données locales, et l’un des onglets effectue discrètement la synchronisation pour les autres.
2. Ce navigateur (ou une fenêtre privée) ne dispose pas de la fonctionnalité de coordination entre onglets privilégiée par le POS ; il revient donc à un seul onglet de synchronisation. Aucune correction n’est nécessaire.

## Où chercher {#where-to-look}

Chaque occurrence de ce code est enregistrée sur l’appareil qui l’a générée. Ouvrez **Santé de la boutique → Journaux** (l’icône de pouls en forme de cœur en bas du panneau de navigation), recherchez l’entrée marquée de ce code et développez-la : la ligne développée affiche la raison en langage clair et le contexte capturé au moment de l’échec — pour tout ce qui impliquait une requête vers votre boutique, cela inclut le code d’erreur propre au serveur (`serverCode`), le `status` HTTP et l’`endpoint`. Lorsque vous signalez un problème, utilisez **Copier les informations de débogage** en haut de l’écran Journaux (**Partager les informations de débogage** sur les téléphones et tablettes) plutôt que des captures d’écran : cette option regroupe la version de l’application, l’état de la connexion et les erreurs les plus récentes. Les journaux sont conservés pendant 30 jours au maximum ; collectez-les tant que le problème est récent.
