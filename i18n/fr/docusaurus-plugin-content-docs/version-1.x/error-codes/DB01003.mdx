# DB01003 : Transaction Échouée {#db01003-transaction-failed}

## Ce que Cela Signifie {#what-this-means}

Une transaction de base de données n'a pas pu être complétée. Les transactions regroupent plusieurs opérations ensemble — si une partie échoue, tout est réinitialisé pour maintenir l'intégrité des données.

## Causes Courantes {#common-causes}

- **Accès concurrent** — Plusieurs opérations essayant de modifier les mêmes données
- **Stockage plein** — Pas d'espace pour écrire de nouvelles données
- **Base de données verrouillée** — Un autre processus verrouille la base de données
- **Interruption de courant** — Opération interrompue de manière inattendue

## Comment Résoudre {#how-to-fix}

### 1. Réessayer l'Opération {#1-retry-the-operation}

Le problème peut être temporaire :
- Attendre un moment
- Réessayer l'opération
- Éviter les tentatives répétées rapides

### 2. Vérifier les Conflits {#2-check-for-conflicts}

Si plusieurs appareils ou onglets sont ouverts :
- Utiliser une instance à la fois
- Fermer les onglets de navigateur en double
- Coordonner l'utilisation sur plusieurs appareils

### 3. Vérifier l'Espace de Stockage {#3-check-storage-space}

Assurez-vous qu'il y a de l'espace pour les données :
- Vérifier l'espace disque disponible
- Libérer de l'espace si nécessaire
- Videz le cache du navigateur dans la version Web (décochez « Cookies et autres données de sites » — cette option contient les données enregistrées du PDV, y compris celles qui n’ont pas encore été envoyées)

### 4. Redémarrer l'Application {#4-restart-the-application}

Réinitialiser l'état de la base de données :
1. Fermez complètement le POS
2. Attendez quelques secondes
3. Rouvrez l'application

### 5. Effacer et Resynchroniser {#5-clear-and-re-sync}

:::warning Vérifiez d’abord qu’aucun travail n’est en attente d’enregistrement
La suppression des données locales ou la réinstallation de l’application efface tout ce qui se trouve sur cet appareil sans avoir été transmis à votre boutique — notamment les ventes effectuées hors ligne, les paniers ouverts et les modifications non enregistrées. Avant toute suppression, ouvrez **Store health → Database** et vérifiez qu’aucun élément n’est indiqué comme retenu ou comme n’ayant jamais atteint votre serveur, puis vérifiez dans **Store health → Logs** qu’il y a **0 enregistrement bloqué** et **0 modification en attente d’envoi** ; terminez ou notez ensuite chaque panier ouvert. Si votre WCPOS ne comporte pas de page Store health, mettez d’abord WCPOS à jour, puis vérifiez. Si un élément est répertorié ou en attente, ou si vous ne pouvez pas vérifier, ne supprimez rien — demandez conseil au propriétaire de votre boutique ou contactez l’assistance.
:::

Uniquement si les transactions échouent systématiquement après toutes les autres étapes de cette page, et seulement après avoir effectué la vérification ci-dessus :
1. Effacer les données locales
2. Se reconnecter
3. Resynchroniser à partir du serveur

## Sécurité des Transactions {#transaction-safety}

WCPOS utilise des transactions pour garantir :
- Cohérence des données
- Opérations complètes (tout ou rien)
- Protection contre les mises à jour partielles

Lorsqu'une transaction échoue, vos données restent cohérentes.
