## Ce que cela signifie {#what-this-means}

La validation de commande ne s’est pas terminée, et le panier peut être réessayé sans risque.

Vérifiez le panier et relancez la validation de commande ; le contenu actuel du panier a été conservé.

## Vos données {#your-data}

La commande elle-même est intacte et inchangée.

## Dépannage {#troubleshoot}

**À la caisse** — pour le caissier :

1. Vérifiez le panier — il est inchangé — et relancez la validation de commande.
2. Si l’échec se reproduit, dépliez l’entrée dans État de la boutique → Journaux : les champs serverCode et status indiquent si la boutique a refusé la commande et pourquoi.
3. Si la raison désigne une ligne d’article précise, retirez-la, finalisez la vente, et examinez ce produit ensuite.

**Sur la boutique** — pour l’administrateur du site : un échec répété accompagné d’un code de statut de classe 500 signale un problème sur le site. Vérifiez si WooCommerce → État → Journaux contient une erreur PHP à l’heure de l’échec.
