# API02008 : Jeton de rafraîchissement invalide {#api02008-refresh-token-invalid}

## Ce que cela signifie {#what-this-means}

Le jeton de rafraîchissement stocké par le POS n'est pas reconnu par le serveur. Les jetons de rafraîchissement sont utilisés pour obtenir de nouveaux jetons d'accès sans vous obliger à vous reconnecter.

## Causes courantes {#common-causes}

- **Jeton révoqué** — Un administrateur a invalidé votre session
- **Secrets du serveur modifiés** — Les clés de sécurité WordPress ont été mises à jour
- **Corruption des données** — Le jeton a été corrompu dans le stockage
- **Connexions multiples** — Se connecter ailleurs peut avoir invalidé ce jeton

## Comment résoudre {#how-to-fix}

### 1. Reconnectez-vous {#1-log-in-again}

Puisque le jeton de rafraîchissement est invalide, vous devrez vous authentifier à nouveau :
1. Déconnectez-vous du POS
2. Entrez votre nom d'utilisateur et votre mot de passe
3. Cela génère de nouveaux jetons valides

### 2. Vérifiez les sessions révoquées {#2-check-for-revoked-sessions}

Si un admin a révoqué des sessions :
- C'est une pratique de sécurité normale
- Il suffit de se reconnecter
- Votre nouvelle session fonctionnera normalement

### 3. Vérifiez les modifications du serveur {#3-check-server-changes}

Si cela affecte tous les utilisateurs :
- Les sels/clés WordPress peuvent avoir changé
- Les paramètres du plugin JWT ont pu être modifiés
- Contactez votre administrateur de serveur

### 4. Effacez les données stockées {#4-clear-stored-data}

Si le problème persiste, et seulement après la vérification ci-dessous :

:::warning Vérifiez d’abord les travaux non enregistrés
Effacer les données locales ou réinstaller l’application supprime tout ce qui se trouve sur cet appareil sans être arrivé dans votre boutique, notamment les ventes effectuées hors ligne, les paniers ouverts et les modifications non enregistrées. Avant tout effacement, ouvrez **État de la boutique → Base de données** et vérifiez qu’aucun élément n’est indiqué comme retenu ou comme n’ayant jamais atteint votre serveur, puis consultez **État de la boutique → Journaux** pour vérifier qu’il y a **0 enregistrement bloqué** et **0 modification en attente d’envoi** ; terminez ou notez ensuite chaque panier ouvert. Si votre WCPOS ne comporte pas de page État de la boutique, mettez d’abord WCPOS à jour, puis vérifiez. Si un élément est répertorié ou en attente, ou si vous ne pouvez pas vérifier, n’effacez rien : demandez au propriétaire de la boutique ou contactez le support.
:::

- Effacez les données de l'application POS
- Supprimez les identifiants mis en cache
- Commencez avec une connexion propre
