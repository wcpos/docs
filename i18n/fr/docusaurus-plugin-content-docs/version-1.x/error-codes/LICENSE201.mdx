## Signification {#what-this-means}

WCPOS Pro est désactivé car sa version ne correspond pas à celle de WCPOS.

Mettez à jour le composant WCPOS ou WCPOS Pro indiqué afin que les deux versions soient compatibles.

## Que faire {#what-to-do}

Une modification des réglages est nécessaire avant que cela fonctionne. Réessayez après avoir effectué la modification ci-dessus ; sans elle, la nouvelle tentative échouera de la même manière.

## Vos données {#your-data}

Aucune donnée de commande ou de produit n’est affectée. Si le problème persiste, contactez la personne qui gère votre site WordPress.

## Résolution des problèmes {#troubleshoot}

1. Vérifiez les versions des deux extensions dans WP Admin → Extensions — l’entrée du journal indique lequel de WCPOS et WCPOS Pro est en retard.
2. Mettez à jour la plus ancienne ; mettre les deux à jour vers les dernières versions résout ce décalage.
3. Si aucune mise à jour de Pro n’est proposée, l’outil de mise à jour n’est peut-être pas autorisé (voir LICENSE301) — corrigez d’abord ce problème, puis effectuez la mise à jour.

## Où chercher {#where-to-look}

Chaque occurrence de ce code est enregistrée sur l’appareil qui l’a générée. Ouvrez **État de santé du point de vente → Journaux** (l’icône en forme de pouls cardiaque en bas du panneau de navigation), recherchez l’entrée marquée de ce code et développez-la : la ligne développée affiche la raison en termes simples et le contexte capturé au moment de l’échec — pour tout ce qui implique une requête adressée à votre boutique, cela inclut le propre code d’erreur du serveur (`serverCode`), le `status` HTTP et l’`endpoint`. Lors du signalement d’un problème, utilisez **Copier les informations de débogage** en haut de l’écran Journaux (**Partager les informations de débogage** sur les téléphones et tablettes) plutôt que des captures d’écran : ces informations regroupent la version de l’application, l’état de la connexion et les erreurs les plus récentes. Les journaux sont conservés pendant 30 jours au maximum ; recueillez-les tant que le problème est récent.

Au-delà du journal intégré à l’application, cet échec peut laisser des traces dans :

- **Journaux POS côté serveur** : dans WP Admin, ouvrez **POS → Réglages → Outils → Journaux**. Cette page enregistre les avertissements et erreurs liés au POS générés sur le serveur lui-même, qui peuvent ne jamais apparaître dans l’application. Un badge rouge dans le menu indique des erreurs côté serveur non lues.
