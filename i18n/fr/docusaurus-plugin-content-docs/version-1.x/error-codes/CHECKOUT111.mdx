## Signification {#what-this-means}

Cette modification n’a pas pu être appliquée au panier, qui reste inchangé.

L’article, les frais, la ligne de livraison ou le code promo n’ont pas été ajoutés et aucun élément n’a été supprimé. Réessayez l’action ; si le problème persiste, exportez les diagnostics et contactez l’assistance.

## Que faire {#what-to-do}

Réessayez l’action. WCPOS ne réessaie pas automatiquement — réessayez lorsque vous êtes prêt.

## Vos données {#your-data}

La commande elle-même est sécurisée et inchangée. Si le problème persiste, exportez les diagnostics et contactez l’assistance WCPOS.

## Résolution des problèmes {#troubleshoot}

1. Essayez d’ajouter à nouveau l’article, les frais, la ligne de livraison ou le code promo — le panier reste inchangé.
2. Si le même article échoue toujours, essayez une fois avec un autre produit : l’échec d’un seul article indique un problème avec cette fiche, tandis que l’échec de tous les articles indique un problème avec l’appareil.
3. Si le problème persiste, redémarrez WCPOS ; exportez les informations de débogage et contactez l’assistance s’il continue.

## Où chercher {#where-to-look}

Chaque occurrence de ce code est enregistrée sur l’appareil qui l’a générée. Ouvrez **Santé de la boutique → Journaux** (l’icône de pulsation cardiaque au bas du tiroir de navigation), recherchez l’entrée marquée avec ce code et développez-la : la ligne développée affiche la raison en termes simples ainsi que le contexte capturé au moment de l’échec — pour tout ce qui implique une requête vers votre boutique, cela comprend le code d’erreur du serveur (`serverCode`), le `status` HTTP et l’`endpoint`. Lors du signalement d’un problème, utilisez **Copier les informations de débogage** en haut de l’écran Journaux (**Partager les informations de débogage** sur les téléphones et tablettes) plutôt que des captures d’écran : cette option regroupe la version de l’application, l’état de la connexion et les erreurs les plus récentes. Les journaux sont conservés pendant 30 jours au maximum ; recueillez-les donc tant que le problème est récent.

En plus du journal intégré à l’application, cet échec peut laisser des traces dans :

- **Console** (web et bureau) : l’onglet **Console** des mêmes outils de développement enregistre les erreurs côté client, y compris celles qui surviennent avant que le POS puisse écrire sa propre entrée de journal.
