## Signification {#what-this-means}

WCPOS n’a pas pu confirmer si le paiement a été finalisé.

Ne réessayez pas aveuglément. Vérifiez d’abord la commande dans la boutique, puis exportez les diagnostics si son résultat reste incertain.

## Que faire {#what-to-do}

Vérifiez les détails ci-dessous avant de réessayer. Ne réessayez pas avant d’avoir confirmé ce qui s’est réellement passé : une nouvelle tentative à l’aveugle peut entraîner un double débit ou une commande en double.

## Vos données {#your-data}

Le résultat n’a pas pu être confirmé : vérifiez-le avant de réessayer. Si le problème persiste, exportez les diagnostics et contactez l’assistance WCPOS.

## Résolution des problèmes {#troubleshoot}

1. Ne réessayez pas encore le paiement et ne débitez pas de nouveau le client.
2. Ouvrez WooCommerce → Commandes dans WP Admin et recherchez la commande — effectuez la recherche par total et sur les dernières minutes.
3. Si la commande existe, la vente a été effectuée — ne la créez pas de nouveau ; synchronisez le POS pour qu’elle apparaisse sur la caisse.
4. Si aucune commande n’existe après une synchronisation, réessayez le paiement une fois.
5. La situation reste incertaine ? Exportez les informations de débogage et contactez l’assistance avant toute nouvelle tentative.

## Où chercher {#where-to-look}

Chaque occurrence de ce code est enregistrée sur l’appareil qui l’a générée. Ouvrez **État du POS → Journaux** (l’icône de pouls cardiaque en bas du tiroir de navigation), recherchez l’entrée marquée de ce code et développez-la : la ligne développée affiche la raison en langage clair et le contexte capturé au moment de l’échec — pour tout ce qui impliquait une requête vers votre boutique, cela inclut le propre code d’erreur du serveur (`serverCode`), le `status` HTTP et l’`endpoint`. Lors du signalement d’un problème, utilisez **Copier les informations de débogage** en haut de l’écran Journaux (**Partager les informations de débogage** sur les téléphones et tablettes) plutôt que des captures d’écran : cette option regroupe la version de l’application, l’état de la connexion et les erreurs les plus récentes. Les journaux sont conservés 30 jours au maximum ; récupérez-les tant que le problème est récent.

Au-delà du journal de l’application, cet échec peut laisser des traces dans :

- **Inspecteur réseau** (web et bureau) : ouvrez les outils de développement — appuyez sur F12 dans le navigateur, ou sélectionnez **Avancé → Basculer les outils de développement** dans le menu de l’application de bureau — puis sélectionnez l’onglet **Réseau** et répétez l’action. La requête ayant échoué affiche le statut HTTP et le corps brut de la réponse, y compris les pages d’erreur qui n’atteignent jamais le journal POS.
- **Journaux POS côté serveur** : dans WP Admin, ouvrez **POS → Réglages → Outils → Journaux**. Cette page enregistre les avertissements et erreurs liés au POS générés sur le serveur lui-même, qui peuvent ne jamais apparaître dans l’application. Un badge rouge sur le menu signale des erreurs côté serveur non lues.
