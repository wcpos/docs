## Ce que cela signifie {#what-this-means}

La synchronisation a rencontré un problème inattendu.

Les ventes déjà enregistrées sur cet appareil sont en sécurité. Consultez d’abord le journal (voir Dépannage) : une nouvelle tentative peut être automatique ou, si une écriture n’a jamais atteint la file d’attente, la vente devra être saisie à nouveau. Si ce code réapparaît, exportez les diagnostics et contactez l’assistance.

## Vos données {#your-data}

Si votre saisie a été capturée, elle est en sécurité sur cet appareil et n’a pas encore atteint votre boutique ; si le journal indique que l’écriture a échoué avant sa mise en file d’attente (voir l’étape 2 du dépannage), saisissez-la à nouveau. Si le problème persiste, exportez les diagnostics et contactez l’assistance WCPOS.

## Dépannage {#troubleshoot}

1. Ne partez pas du principe que ce code sera réessayé. Dépliez d’abord l’entrée de journal : si elle confirme que la modification était déjà en file d’attente, WCPOS réessaie automatiquement ; laissez donc faire et laissez la file se vider.
2. Si l’erreur indique que le résident du moteur est absent ou que l’écriture a échoué avant qu’un identifiant de mutation ne soit renvoyé, rien n’a été mis en file d’attente — revenez à cet enregistrement ou à cette commande et enregistrez-le à nouveau.
3. Dépliez l’entrée de journal et notez le code d’événement ainsi que tout serverCode : un code 999 signifie que la cause précise n’a pas encore de code dédié, et ce contexte est exactement ce dont l’assistance a besoin.
4. Si le code continue d’apparaître, utilisez Copier les infos de débogage et contactez l’assistance — c’est en le signalant qu’un code spécifique finit par être ajouté.
