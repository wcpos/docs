## Signification {#what-this-means}

WCPOS a manqué de mémoire et n'a pas pu terminer l'opération.

Redémarrez WCPOS et réessayez une fois ; exportez les diagnostics si l'appareil manque de nouveau de mémoire.

## Que faire {#what-to-do}

Réessayez l'action. WCPOS ne réessaie pas automatiquement ; réessayez lorsque vous êtes prêt.

## Vos données {#your-data}

La modification est enregistrée sur cet appareil, mais n'a pas encore atteint votre boutique. Si le problème persiste, exportez les diagnostics et contactez l'assistance WCPOS.

## Résolution des problèmes {#troubleshoot}

1. Redémarrez WCPOS, puis réessayez l’action une fois.
2. Fermez les autres applications ou onglets du navigateur : le POS partage la mémoire de l’appareil avec tout ce qui y est exécuté.
3. Si une action spécifique entraîne systématiquement un manque de mémoire, notez laquelle et contactez l’assistance avec les informations de débogage.
4. Si cela se produit chaque jour sur le même appareil, celui-ci est peut-être insuffisant pour le catalogue ; signalez-le afin que l’assistance puisse le confirmer.

## Où chercher {#where-to-look}

Chaque occurrence de ce code est enregistrée sur l’appareil qui l’a générée. Ouvrez **Santé de la boutique → Journaux** (l’icône de pouls en bas du panneau de navigation), recherchez l’entrée marquée de ce code et développez-la : la ligne développée affiche la raison en langage clair et le contexte capturé au moment de l’échec. Pour tout ce qui implique une requête vers votre boutique, cela inclut le propre code d’erreur du serveur (`serverCode`), le `status` HTTP et l’`endpoint`. Lorsque vous signalez un problème, utilisez **Copier les informations de débogage** en haut de l’écran Journaux (**Partager les informations de débogage** sur les téléphones et tablettes) plutôt que des captures d’écran : cette option regroupe la version de l’application, l’état de connexion et les erreurs les plus récentes. Les journaux sont conservés pendant 30 jours au maximum ; recueillez-les donc tant que le problème est récent.

Au-delà du journal intégré à l’application, cet échec peut laisser des traces dans :

- **Console** (web et ordinateur) : l’onglet **Console** des mêmes outils de développement enregistre les erreurs côté client, y compris celles qui surviennent avant que le POS puisse écrire sa propre entrée de journal.
