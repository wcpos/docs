## Signification {#what-this-means}

Un problème inattendu est survenu lors de la connexion ou du maintien de la connexion.

Réessayez l’action une fois. Si le problème se reproduit, déconnectez-vous puis reconnectez-vous, puis exportez les diagnostics et contactez l’assistance.

## Que faire {#what-to-do}

Réessayez l’action. WCPOS ne réessaie pas automatiquement — réessayez lorsque vous êtes prêt.

## Vos données {#your-data}

Aucune donnée de commande ou de produit n’est affectée. Si le problème persiste, exportez les diagnostics et contactez l’assistance WCPOS.

## Dépannage {#troubleshoot}

1. Réessayez l’action une fois ; si elle échoue à nouveau, déconnectez-vous puis reconnectez-vous.
2. Développez l’entrée du journal et notez le code d’événement ainsi que tout serverCode : un code 999 signifie que la cause ne possède pas encore de code dédié, et ce contexte permet de l’identifier.
3. Si le problème se reproduit, utilisez Copier les informations de débogage et contactez l’assistance.

## Où chercher {#where-to-look}

Chaque occurrence de ce code est enregistrée sur l’appareil qui l’a générée. Ouvrez **État de santé du point de vente → Journaux** (l’icône de pouls située au bas du volet de navigation), recherchez l’entrée marquée de ce code et développez-la : la ligne développée affiche la raison en langage clair et le contexte capturé au moment de l’échec — pour tout ce qui impliquait une requête vers votre boutique, cela inclut le propre code d’erreur du serveur (`serverCode`), le `status` HTTP et le `endpoint`. Pour signaler un problème, utilisez **Copier les informations de débogage** en haut de l’écran Journaux (**Partager les informations de débogage** sur les téléphones et tablettes) plutôt que des captures d’écran : cette option regroupe la version de l’application, l’état de la connexion et les erreurs les plus récentes. Les journaux sont conservés pendant 30 jours au maximum ; collectez-les donc tant que le problème est récent.

Au-delà du journal de l’application, cet échec peut laisser des traces dans :

- **Inspecteur réseau** (web et bureau) : ouvrez les outils de développement — appuyez sur F12 dans le navigateur, ou sélectionnez **Avancé → Afficher/Masquer les outils de développement** dans le menu de l’application de bureau —, sélectionnez l’onglet **Réseau** et répétez l’action. La requête en échec affiche le statut HTTP et le corps brut de la réponse, y compris les pages d’erreur qui n’atteignent jamais le journal du POS.

## Détails {#details}

- **Code :** `AUTH999` (`AUTH_UNEXPECTED`)
- **Gravité :** erreur
- **Introduit dans :** WCPOS 1.10.0
