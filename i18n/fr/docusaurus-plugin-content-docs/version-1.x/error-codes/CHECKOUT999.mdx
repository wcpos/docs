## Ce que cela signifie {#what-this-means}

Un problème inattendu est survenu lors du paiement.

Vérifiez la commande dans l’administration de votre boutique avant de facturer à nouveau le client. Exportez les diagnostics et contactez l’assistance si le problème se reproduit.

## Que faire {#what-to-do}

Vérifiez les informations ci-dessous avant de réessayer. WCPOS ne réessaie pas automatiquement ; réessayez lorsque vous êtes prêt.

## Vos données {#your-data}

Le résultat n’a pas pu être confirmé ; vérifiez-le avant de réessayer. Si le problème persiste, exportez les diagnostics et contactez l’assistance WCPOS.

## Résolution des problèmes {#troubleshoot}

1. Vérifiez WooCommerce → Commandes dans WP Admin avant de débiter à nouveau le client.
2. Développez l’entrée du journal et notez le code d’événement ainsi que tout serverCode — ce code générique signifie que la cause ne dispose pas encore d’un code dédié.
3. Si le problème se reproduit, exportez les informations de débogage et contactez l’assistance.

## Où chercher {#where-to-look}

Chaque occurrence de ce code est enregistrée sur l’appareil qui l’a généré. Ouvrez **État de la boutique → Journaux** (l’icône de pouls située en bas du panneau de navigation), recherchez l’entrée marquée de ce code et développez-la : la ligne développée affiche la raison en langage clair et le contexte capturé au moment de l’échec. Pour tout élément impliquant une requête à votre boutique, cela inclut le propre code d’erreur du serveur (`serverCode`), le `status` HTTP et l’`endpoint`. Pour signaler un problème, utilisez **Copier les informations de débogage** en haut de l’écran Journaux (**Partager les informations de débogage** sur les téléphones et tablettes) plutôt que des captures d’écran : cette option regroupe la version de l’application, l’état de la connexion et les erreurs les plus récentes. Les journaux sont conservés au maximum 30 jours ; récupérez-les tant que le problème est récent.

En plus du journal intégré à l’application, cet échec peut laisser des traces dans :

- **Inspecteur réseau** (web et bureau) : ouvrez les outils de développement — appuyez sur F12 dans le navigateur, ou sur **Avancé → Afficher les outils de développement** dans le menu de l’application de bureau — sélectionnez l’onglet **Réseau** et répétez l’action. La requête ayant échoué affiche le statut HTTP et le corps brut de la réponse, y compris les pages d’erreur qui n’atteignent jamais le journal POS.
- **Journaux POS côté serveur** : dans WP Admin, ouvrez **POS → Réglages → Outils → Journaux**. Cette page enregistre les avertissements et erreurs liés au POS générés sur le serveur lui-même, qui peuvent ne jamais apparaître dans l’application. Un badge rouge dans le menu indique des erreurs côté serveur non lues.
