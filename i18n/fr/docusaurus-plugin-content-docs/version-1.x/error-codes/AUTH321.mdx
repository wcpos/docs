## Signification {#what-this-means}

WooCommerce n’est pas actif sur ce site. WCPOS ne peut donc pas se connecter.

WCPOS nécessite l’extension WooCommerce. Demandez à l’administrateur du site d’installer ou de réactiver WooCommerce, puis reconnectez-vous.

## Que faire {#what-to-do}

Une modification des réglages est nécessaire avant que cela fonctionne. Réessayez après avoir effectué la modification ci-dessus ; sans elle, la nouvelle tentative échouera de la même manière.

## Vos données {#your-data}

Aucune donnée de commande ou de produit n’est affectée. Si le problème persiste, contactez la personne qui gère votre site WordPress.

## Dépannage {#troubleshoot}

1. Demandez à l’administrateur du site de vérifier WP Admin → Extensions : WooCommerce doit être installé et actif pour que WCPOS puisse se connecter.
2. Si WooCommerce a été désactivé par une mise à jour ayant échoué, réactivez-le et surveillez l’apparition d’une bannière d’erreur — WooCommerce → État → Journaux indique la raison de l’échec.
3. Une fois WooCommerce à nouveau actif, reconnectez-vous depuis la caisse.

## Où chercher {#where-to-look}

Chaque occurrence de ce code est enregistrée sur l’appareil qui l’a générée. Ouvrez **État de santé de la boutique → Journaux** (l’icône de pulsation cardiaque en bas du volet de navigation), recherchez l’entrée marquée de ce code et développez-la : la ligne développée affiche la raison en langage clair et le contexte capturé au moment de l’échec — pour tout ce qui impliquait une requête vers votre boutique, cela inclut le code d’erreur du serveur (`serverCode`), le `status` HTTP et l’`endpoint`. Lorsque vous signalez un problème, utilisez **Copier les informations de débogage** en haut de l’écran Journaux (**Partager les informations de débogage** sur les téléphones et tablettes) plutôt que des captures d’écran : cette option regroupe la version de l’application, l’état de connexion et les erreurs les plus récentes. Les journaux sont conservés pendant 30 jours maximum ; récupérez-les tant que le problème est récent.

Au-delà du journal intégré à l’application, cet échec peut laisser des traces dans :

- **WooCommerce → État → Journaux** : sur le site WordPress, consultez le fichier `fatal-errors-*.log` le plus récent pour détecter les plantages PHP, ainsi que toute source de journal portant le nom d’une extension impliquée dans l’échec. Une erreur de classe 500 provenant de la boutique laisse presque toujours sa cause ici.
