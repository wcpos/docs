## Signification {#what-this-means}

La boutique n’a pas accepté les identifiants de connexion.

Saisissez à nouveau le nom d’utilisateur et le mot de passe, ou réinitialisez le mot de passe dans WordPress si le problème persiste. Aucune donnée de commande n’est affectée.

## Que faire {#what-to-do}

Corrigez les informations mises en évidence, puis réessayez. WCPOS ne réessaie pas automatiquement : réessayez lorsque vous êtes prêt.

## Vos données {#your-data}

Aucune donnée de commande ou de produit n’est affectée.

## Résolution des problèmes {#troubleshoot}

1. Saisissez à nouveau le nom d’utilisateur et le mot de passe — la boutique a refusé cette combinaison.
2. Vérifiez que le compte fonctionne en vous connectant à WP Admin dans un navigateur avec les mêmes identifiants ; réinitialisez-y le mot de passe si la connexion échoue.
3. Si les identifiants fonctionnent dans WP Admin mais pas dans le POS, une extension de protection de connexion ou de sécurité bloque peut-être la connexion programmatique — vérifiez ses paramètres ou contactez l’administrateur du site.

## Où chercher {#where-to-look}

Chaque occurrence de ce code est enregistrée sur l’appareil qui l’a générée. Ouvrez **État de la boutique → Journaux** (l’icône de pouls cardiaque au bas du panneau de navigation), recherchez l’entrée marquée de ce code et développez-la : la ligne développée affiche la raison en termes simples et le contexte capturé au moment de l’échec — pour tout ce qui implique une requête à votre boutique, cela comprend le propre code d’erreur du serveur (`serverCode`), le `status` HTTP et l’`endpoint`. Lors du signalement d’un problème, utilisez **Copier les informations de débogage** en haut de l’écran Journaux (**Partager les informations de débogage** sur les téléphones et tablettes) plutôt que des captures d’écran : ces informations regroupent la version de l’application, l’état de la connexion et les erreurs les plus récentes. Les journaux sont conservés pendant 30 jours au maximum ; récupérez-les tant que le problème est récent.

Au-delà du journal intégré à l’application, cet échec peut laisser des traces dans :

- **Inspecteur réseau** (web et bureau) : ouvrez les outils de développement — appuyez sur F12 dans le navigateur, ou sur **Avancé → Afficher les outils de développement** dans le menu de l’application de bureau — sélectionnez l’onglet **Réseau** et répétez l’action. La requête en échec affiche le statut HTTP et le corps brut de la réponse, y compris les pages d’erreur qui n’atteignent jamais le journal du POS.
- **Journaux POS côté serveur** : dans WP Admin, ouvrez **POS → Paramètres → Outils → Journaux**. Cette page enregistre les avertissements et les erreurs liés au POS générés sur le serveur lui-même, qui peuvent ne jamais apparaître dans l’application. Un badge rouge dans le menu indique des erreurs côté serveur non lues.
