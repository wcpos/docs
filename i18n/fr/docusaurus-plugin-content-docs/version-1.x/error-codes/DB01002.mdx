# DB01002 : Délai d'Expiration de Requête {#db01002-query-timeout}

## Ce que Cela Signifie {#what-this-means}

Une opération de base de données a pris trop de temps à se compléter. La requête de base de données locale a dépassé le temps maximum autorisé.

## Causes Courantes {#common-causes}

- **Grand ensemble de données** — Nombre très élevé de produits ou d'enregistrements
- **Requête complexe** — Requête impliquant de nombreuses conditions
- **Performance de l'appareil** — L'appareil fonctionne lentement
- **Fragmentation de la base de données** — La base de données a besoin d'optimisation

## Comment Réparer {#how-to-fix}

### 1. Attendre et Réessayer {#1-wait-and-retry}

La requête peut réussir lors d'une nouvelle tentative :
- Fermez et rouvrez le POS
- Essayez à nouveau l'opération
- Évitez d'autres opérations intensives simultanément

### 2. Fermer D'autres Applications {#2-close-other-applications}

Libérez les ressources de l'appareil :
- Fermez les onglets de navigateur inutilisés
- Fermez d'autres applications
- Redémarrez l'appareil si nécessaire

### 3. Réduire la Portée des Données {#3-reduce-data-scope}

Si vous recherchez :
- Utilisez des termes de recherche plus spécifiques
- Appliquez des filtres pour affiner les résultats
- Divisez les grandes opérations en plus petites

### 4. Optimiser la Base de Données {#4-optimise-the-database}

:::warning Vérifiez d'abord qu'aucun travail n'est en attente d'enregistrement
La suppression des données locales ou la réinstallation de l'application efface tout ce qui, sur cet appareil, n'est pas arrivé jusqu'à votre boutique, notamment les ventes effectuées hors ligne, les paniers ouverts et les modifications non enregistrées. Avant toute suppression, ouvrez **Store health → Database** et vérifiez qu'aucun élément n'est indiqué comme bloqué ou comme n'ayant jamais atteint votre serveur, puis consultez **Store health → Logs** pour vérifier qu'il y a **0 stuck records** et **0 changes waiting to send** ; terminez ou notez ensuite chaque panier ouvert. Si votre WCPOS ne comporte pas de page Store health, mettez d'abord WCPOS à jour, puis vérifiez. Si un élément est répertorié ou en attente, ou si vous ne pouvez pas effectuer cette vérification, ne supprimez rien : demandez conseil au responsable de votre boutique ou contactez le support.
:::

Effacez les données et synchronisez-les à nouveau uniquement si les autres étapes de cette page n'ont pas résolu le problème et après avoir effectué la vérification ci-dessus :
1. Effacez les données locales (option de paramètres si disponible)
2. Connectez-vous à nouveau
3. Laissez les données se synchroniser fraîchement

### 5. Vérifier la Performance de l'Appareil {#5-check-device-performance}

Assurez-vous que votre appareil répond aux exigences :
- RAM suffisante
- Vitesse de processeur adéquate
- SSD préféré au HDD

## Grands Catalogues {#large-catalogues}

Si vous avez un très grand catalogue de produits :
- La synchronisation initiale prend plus de temps
- Envisagez d'utiliser des filtres dans le POS
- Certaines opérations prennent naturellement plus de temps
- Contactez le support pour des conseils d'optimisation
