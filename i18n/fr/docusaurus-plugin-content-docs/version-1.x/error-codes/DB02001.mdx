# DB02001 : Enregistrement en Double {#db02001-duplicate-record}

## Ce Que Cela Signifie {#what-this-means}

La base de données a essayé d'insérer un enregistrement avec un ID qui existe déjà. Chaque enregistrement doit avoir un identifiant unique.

## Causes Communes {#common-causes}

- **Conflit de sync** — Même données synchronisées deux fois
- **Condition de course** — Plusieurs opérations créant le même enregistrement
- **Corruption des données** — Les IDs ont été corrompus ou dupliqués
- **Problème d'importation** — Importation de données qui existent déjà

## Comment Réparer {#how-to-fix}

### 1. Rafraîchir les Données {#1-refresh-data}

Re-sync depuis le serveur :
- Tirer les dernières données
- Laisser le processus de sync résoudre les conflits
- Les données les plus récentes devraient prévaloir

### 2. Réessayer l'Opération {#2-retry-the-operation}

Si vous créez de nouveaux enregistrements :
- Le système a peut-être déjà créé celui-ci
- Vérifiez si l'enregistrement existe
- Évitez de cliquer sur soumettre plusieurs fois

### 3. Vider le Cache Local {#3-clear-local-cache}

:::warning Vérifiez d’abord qu’aucun travail n’est en attente d’enregistrement
Vider les données locales ou réinstaller l’application supprime tout ce qui se trouve sur cet appareil et n’a pas atteint votre boutique — y compris les ventes effectuées hors ligne, les paniers ouverts et les modifications non enregistrées. Avant de vider quoi que ce soit, ouvrez **État de la boutique → Base de données** et vérifiez qu’aucun élément n’est indiqué comme mis de côté ou comme n’ayant jamais atteint votre serveur, puis consultez **État de la boutique → Journaux** pour vérifier qu’il y a **0 enregistrements bloqués** et **0 modifications en attente d’envoi** ; terminez ensuite chaque panier ouvert ou prenez-en note. Si votre WCPOS ne comporte pas de page État de la boutique, mettez d’abord WCPOS à jour, puis vérifiez. Si un élément est indiqué ou en attente, ou si vous ne pouvez pas vérifier, ne videz rien — demandez conseil au propriétaire de votre boutique ou contactez l’assistance.
:::

Uniquement si les étapes 1, 2 et 4 n’ont pas aidé, et seulement après avoir effectué la vérification ci-dessus, réinitialisez les données locales :
1. Vider la base de données/cache local
2. Se connecter à nouveau
3. Synchroniser les données fraîches

### 4. Vérifier les Doublons dans WooCommerce {#4-check-for-duplicates-in-woocommerce}

Si le problème persiste :
- Vérifiez WooCommerce pour des entrées dupliquées
- Recherchez des produits/commandes avec les mêmes IDs
- Nettoyez tout doublon dans l'administration

### 5. Signaler les Problèmes Persistants {#5-report-persistent-issues}

Si cela se produit fréquemment :
- Notez quelles actions le causent
- Vérifiez s'il y a des motifs
- Signalez au support avec des détails

## Pourquoi Cela Compte {#why-this-matters}

Des IDs dupliqués causeraient :
- Confusion sur quel enregistrement est correct
- Écrasement de données
- Problèmes de synchronisation

L'erreur empêche la corruption des données.
