## Ce que cela signifie {#what-this-means}

Votre boutique a refusé une valeur qui lui a été envoyée.

Le motif de la boutique indique la valeur concernée. Corrigez-la à l’endroit où vous l’avez saisie, puis enregistrez de nouveau. Il s’agit généralement d’une valeur associée à un enregistrement — produit, client ou commande —, mais ce code peut aussi provenir d’une requête de paramètres ou de connexion refusée par la boutique ; corrigez alors la valeur sur cet écran.

## Vos données {#your-data}

N’effacez pas les données de cet appareil : elles peuvent contenir des modifications que votre boutique n’a pas encore reçues. La modification refusée d’un produit, d’une variation, d’un client ou d’un code promo existant est généralement annulée automatiquement et consignée sous [SYNC202](/error-codes/SYNC202). Si elle apparaît sous ce code et que la modification figure dans **Santé de la boutique → Base de données**, l’annulation automatique n’a pas eu lieu : traitez-la comme toute autre modification listée. Une requête de paramètres ou de connexion ne laisse rien à enregistrer.

## Dépannage {#troubleshoot}

1. Développez l’entrée du journal et lisez le motif de la boutique ainsi que le point de terminaison : le motif indique la valeur concernée, et le point de terminaison précise si la requête provient d’un enregistrement ou des paramètres ou de la connexion.
2. Corrigez la valeur à l’endroit où vous l’avez saisie — les causes fréquentes sont une valeur hors plage, un format refusé ou une option obligatoire laissée vide — puis enregistrez de nouveau. Si la modification ne figure pas dans **Santé de la boutique → Base de données**, la version de la boutique a été restaurée : refaites la modification avec la valeur corrigée. Si elle figure toujours sous **« … modifications jamais parvenues à votre serveur »** dans **Santé de la boutique → Base de données** après correction, touchez **Renvoyer** sur sa ligne.
3. Si l’enregistrement figure plutôt sous **« … modifications mises en attente »** avec *« Votre boutique exigeait une version actuelle »*, aucune valeur n’est en cause : choisissez entre **Renvoyer** et **Ignorer la modification de l’appareil**, comme indiqué dans [SYNC221](/error-codes/SYNC221).
4. S’il s’agissait d’une requête de paramètres ou de connexion, corrigez la valeur sur l’écran où vous l’avez saisie, puis enregistrez de nouveau. **Administrateur du site :** les outils de développement du navigateur (onglet Network) — ou **Avancé → Activer les outils de développement** dans l’application de bureau — affichent la réponse de la boutique si le journal du PDV ne contient pas ces détails.
5. **Administrateur du site :** si une valeur indiquée semble correcte dans le PDV, comparez-la au même enregistrement dans l’interface d’administration de WordPress : une validation ajoutée par une extension sur la boutique peut refuser des valeurs que le PDV juge correctes.
