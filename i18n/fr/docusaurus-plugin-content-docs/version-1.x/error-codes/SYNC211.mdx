## Ce que cela signifie {#what-this-means}

Votre boutique a rejeté un champ d’un enregistrement. Parfois, ce code désigne également une requête de paramètres ou d’authentification refusée par la boutique.

Si un enregistrement est indiqué, corrigez le champ mentionné et réessayez ; la copie locale reste disponible jusqu’à sa synchronisation. Sinon, suivez le message de la boutique pour la requête indiquée.

## Vos données {#your-data}

S’il s’agissait d’une modification d’enregistrement, elle est toujours enregistrée sur cet appareil et n’a pas atteint votre boutique. Une requête de paramètres ou d’authentification ne laisse rien à enregistrer.

## Dépannage {#troubleshoot}

1. Dépliez l’entrée de journal et vérifiez d’abord l’endpoint et la réponse du serveur : ce code peut aussi correspondre à une erreur HTTP 400 provenant d’une requête de réglages, d’authentification ou d’un autre type, sans lien avec un enregistrement.
2. Si le contexte désigne un enregistrement ou un champ, modifiez ce champ dans le POS — les causes courantes sont une valeur hors limites, un format refusé ou une option obligatoire laissée vide — puis réessayez.
3. S’il ne s’agit pas d’une requête d’enregistrement, suivez plutôt le message du serveur pour le point de terminaison indiqué. Les outils de développement du navigateur (onglet Réseau) — ou **Avancé → Afficher/Masquer les outils de développement** dans l’application de bureau — affichent la réponse lorsque les détails ne figurent pas dans le journal du PDV.
4. **Administrateur du site :** si le champ indiqué semble correct dans le PDV, comparez-le au même enregistrement dans WP Admin — une validation ajoutée par une extension sur la boutique peut rejeter des valeurs que le PDV juge correctes.
