## Ce que cela signifie {#what-this-means}

Le stockage de cet appareil ne répond plus ; l'enregistrement est donc suspendu.

Redémarrez WCPOS (sur le Web, rechargez l'onglet), puis vérifiez que votre dernière vente ou modification a été enregistrée : une modification effectuée dans les secondes précédant l'arrêt du stockage n'a peut-être pas été écrite. N'effacez pas les données de cet appareil. Si le problème persiste, contactez le support.

## Vos données {#your-data}

N'effacez pas les données de cet appareil : elles peuvent contenir des ventes qui ne sont pas encore arrivées dans votre boutique. Si le problème persiste, utilisez **Copier les infos de débogage** dans l'onglet **Journaux** et contactez l'assistance WCPOS.

## Dépannage {#troubleshoot}

1. Redémarrez WCPOS : fermez puis rouvrez l'application ; sur le Web, rechargez l'onglet au lieu de le fermer. Cela reconnecte la base de données locale dans presque tous les cas.
2. Après le redémarrage, vérifiez que votre dernière vente ou modification a été enregistrée : une modification effectuée dans les secondes précédant l'échec n'a peut-être pas été écrite. Si elle manque, saisissez-la à nouveau.
3. Sur le Web, n'utilisez pas la caisse dans une fenêtre de navigation privée ou incognito, et évitez les extensions qui nettoient agressivement le stockage : elles peuvent toutes deux interrompre le stockage local en pleine session, et la fermeture d'une fenêtre privée supprime tout ce qu'elle contient, y compris les ventes non envoyées. Si vous en utilisez une actuellement, laissez-la ouverte jusqu'à ce que **État de la boutique → Base de données** affiche 0 **modifications en attente d'envoi**.
4. Si ce problème se reproduit régulièrement sur le même appareil, utilisez **Copier les infos de débogage** dans l'onglet **Journaux** et contactez l'assistance ; précisez ce que faisait l'appareil au moment du problème (veille, changement d'onglet, mémoire insuffisante).
