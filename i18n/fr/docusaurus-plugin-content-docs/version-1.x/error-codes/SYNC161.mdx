## Ce que cela signifie {#what-this-means}

La base de données locale de cet appareil ne répond plus ; les actions qui en dépendent sont donc suspendues.

Redémarrez WCPOS pour reconnecter la base de données locale. Des modifications non enregistrées sur cet appareil peuvent ne pas avoir été écrites ; vérifiez les commandes récentes après le redémarrage. Si cela se reproduit, exportez les diagnostics et contactez l’assistance.

## Que faire {#what-to-do}

Redémarrez WCPOS ; si cela se reproduit, les données locales de cet appareil doivent être réparées. WCPOS ne réessaie pas cette opération de lui-même — relancez-la quand vous êtes prêt.

## Vos données {#your-data}

Les données de cet appareil peuvent être menacées — n’effacez pas les données locales. Si le problème persiste, exportez les diagnostics et contactez l’assistance WCPOS.

## Dépannage {#troubleshoot}

1. Redémarrez WCPOS — fermer puis rouvrir l’application (ou l’onglet du navigateur) reconnecte la base de données locale dans la quasi-totalité des cas.
2. Après le redémarrage, vérifiez les commandes les plus récentes : une modification effectuée dans les secondes précédant l’échec peut ne pas avoir été écrite.
3. Sur le web, évitez les fenêtres de navigation privée et les extensions de nettoyage agressif du stockage — les deux peuvent détruire le stockage local en pleine session.
4. Si cela revient régulièrement sur le même appareil, exportez les infos de débogage et contactez l’assistance en précisant ce que faisait l’appareil (veille, changement d’onglet, mémoire faible) au moment des faits.

## Où chercher {#where-to-look}

Lorsque WCPOS peut enregistrer cette erreur, elle est consignée sur l’appareil qui l’a déclenchée. Ouvrez **État de la boutique → Journaux** (l’icône en forme de cœur avec pouls, en bas du tiroir de navigation), repérez l’entrée portant ce code et dépliez-la : la ligne dépliée indique la raison en langage clair ainsi que le contexte capturé au moment de l’échec. Pour une requête vers la boutique, ce contexte peut inclure le code d’erreur propre au serveur (`serverCode`), le `status` HTTP ou l’`endpoint` ; les champs affichés dépendent de l’endroit où l’échec s’est produit. Pour signaler un problème, utilisez **Copier les infos de débogage** en haut de l’écran Journaux (**Partager les infos de débogage** sur téléphone et tablette) plutôt que des captures d’écran : cela regroupe la version de l’application, l’état de la connexion et les erreurs les plus récentes. Les journaux sont conservés 30 jours au maximum ; collectez-les donc pendant que le problème est récent. Copiez également toute erreur de la console du navigateur apparue avant que le POS n’ait pu écrire sa propre entrée de journal.

Au-delà du journal intégré à l’application, cet échec peut laisser des traces dans :

- **Console** (web et bureau) : l’onglet **Console** des mêmes outils de développement enregistre les erreurs côté client, y compris celles qui surviennent avant que le POS ne puisse écrire sa propre entrée de journal.
