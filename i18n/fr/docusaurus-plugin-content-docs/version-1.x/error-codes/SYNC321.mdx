## Ce que cela signifie {#what-this-means}

Certaines données n’ont pas été synchronisées cette fois-ci.

Ce code apparaît sous deux formes — le titre de la ligne du journal indique laquelle vous concerne :

- **« Synchronisation partielle »** (titres des enregistrements) : certains enregistrements ont été synchronisés, mais pas ceux nommés. Vous n’avez rien à faire si la prochaine synchronisation résout le problème. Si **Santé de la boutique → Base de données** répertorie des modifications nécessitant votre attention, traitez-les à cet endroit.
- **"Abandon d’une requête de données bloquée"** : la voie des requêtes de données du moteur de synchronisation n’avançait plus sur une requête ; après un délai d’attente généreux, l’application l’a abandonnée plutôt que de bloquer toutes les requêtes en attente derrière elle. Aucune relance manuelle n’est nécessaire — le moteur de synchronisation réémet automatiquement la requête — et cela fait souvent suite à un appel bloqué à la base de données locale, consigné séparément sous [SYNC181](/error-codes/SYNC181).

## Vos données {#your-data}

N’effacez pas les données de cet appareil : elles peuvent contenir des modifications que votre boutique n’a pas encore reçues. Pour une requête de données abandonnée, rien n’a été modifié : elle est automatiquement envoyée de nouveau. Si cela se reproduit, utilisez **Copier les informations de débogage** dans l’onglet **Journaux** et contactez l’assistance WCPOS.

## Dépannage {#troubleshoot}

1. Pour une entrée **« Abandon d’une requête de données bloquée »**, aucune intervention n’est nécessaire, sauf si un écran reste bloqué. Dans ce cas, rechargez l’application : actualisez l’onglet du navigateur sur le Web, ou fermez puis rouvrez l’application sur ordinateur et appareil mobile.
2. Pour une synchronisation partielle, vous n’avez rien à faire si la prochaine synchronisation résout le problème. Sinon, ouvrez **Santé de la boutique → Base de données** : les enregistrements toujours non synchronisés apparaissent en haut. L’encart **« … enregistrements nécessitent votre attention »** nomme le premier avec son motif (corrigez-le pour afficher le suivant), et les panneaux **« … modifications jamais parvenues à votre serveur »** et **« … modifications mises en attente »** répertorient les autres. Aucune intervention n’est nécessaire pour les enregistrements synchronisés.
3. Traitez chaque enregistrement listé selon son motif. Dans l’encart, **Corriger l’enregistrement** (si cette option est affichée) ouvre l’enregistrement pour le modifier ; corrigez une modification refusée directement dans l’enregistrement ([SYNC201](/error-codes/SYNC201)) ; pour une modification mise en attente, choisissez la version à conserver ([SYNC221](/error-codes/SYNC221)).
4. Renvoyez-les ensuite : touchez **Réessayer** dans l’encart (cela lance une synchronisation), ou **Renvoyer** sur la ligne de l’enregistrement dans les panneaux. Si l’encart indique qu’un enregistrement *ne peut pas être téléchargé depuis votre boutique*, l’option **Réessayer** n’est pas disponible ; consultez [SYNC331](/error-codes/SYNC331).
5. Si un enregistrement ne se synchronise toujours pas, utilisez **Copier les informations de débogage** dans l’onglet **Journaux** et contactez l’assistance.
