## Ce que cela signifie {#what-this-means}

Votre compte n’a pas l’autorisation d’effectuer cette action.

Demandez à un administrateur de la boutique de vérifier les rôles et les capacités du compte, puis réessayez.

## Vos données {#your-data}

Aucune donnée de commande ou de produit n’est affectée. Si le problème persiste, adressez-vous à l’administrateur de votre boutique.

## Dépannage {#troubleshoot}

**À la caisse** — pour le caissier : notez l’action refusée (elle figure dans l’entrée de journal) et transmettez cette information à votre administrateur.

**Sur la boutique** — pour l’administrateur du site : vérifiez les rôles du compte. Les caissiers du PDV ont besoin des capacités enregistrées par WCPOS, et les extensions de gestion des rôles peuvent les retirer.

Si le compte peut se connecter, mais que chaque requête concernant les produits, les clients ou les commandes est refusée, vérifiez s’il possède **plus d’un rôle**. Les extensions de gestion des rôles comme Members appliquent un *Refus* défini sur n’importe quel rôle à l’ensemble du compte. Un administrateur qui possède aussi le rôle Client perd donc tout ce que le rôle Client refuse. Retirez le rôle supplémentaire ou effacez les marques *Refus* ; consultez [Un utilisateur avec plusieurs rôles](/settings/wp-admin/access#more-than-one-role).

**De retour à la caisse :** une fois le rôle corrigé, déconnectez-vous puis reconnectez-vous si une session PDV est encore ouverte ; sinon, reconnectez-vous. Réessayez ensuite l’action refusée.
