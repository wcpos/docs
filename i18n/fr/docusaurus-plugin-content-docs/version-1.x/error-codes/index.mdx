# Codes d’erreur {#error-codes}

Lorsque WCPOS rencontre un problème, un code d’erreur s’affiche pour vous aider à l’identifier. À partir de **v1.10.0**, les codes suivent le format **domaine + trois chiffres** — par exemple `SYNC131` ou `AUTH311`. Le domaine désigne la zone du PDV concernée ; le nombre identifie la condition précise. Chaque code possède sa propre page qui explique sa signification, la marche à suivre et les conséquences pour vos données.

Dans le PDV, les codes d’erreur apparaissent dans **État de la boutique → Journaux** : développez une ligne et utilisez le lien **Aide** pour accéder directement à la page du code.

## Domaines d’erreur (v1.10.0+) {#error-domains}

| Domaine | Zone | Exemples |
|--------|------|----------|
| `AUTH` | Connexion, sessions et jetons | [AUTH101](./AUTH101.mdx), [AUTH311](./AUTH311.mdx) |
| `CHECKOUT` | Finalisation des commandes en caisse | [CHECKOUT101](./CHECKOUT101.mdx), [CHECKOUT201](./CHECKOUT201.mdx) |
| `CLIENT` | Application PDV et stockage local | [CLIENT101](./CLIENT101.mdx), [CLIENT201](./CLIENT201.mdx) |
| `HOST` | Hébergement et règles de pare-feu qui bloquent le PDV | [HOST101](./HOST101.mdx), [HOST121](./HOST121.mdx) |
| `LICENSE` | Activation et validation de la licence Pro | [LICENSE101](./LICENSE101.mdx) |
| `PAYMENT` | Passerelles de paiement et terminaux | [PAYMENT101](./PAYMENT101.mdx), [PAYMENT301](./PAYMENT301.mdx) |
| `PRINT` | Impression des reçus | [PRINT101](./PRINT101.mdx), [PRINT301](./PRINT301.mdx) |
| `PRODUCT` | Données produit et gestion du catalogue | [PRODUCT101](./PRODUCT101.mdx), [PRODUCT401](./PRODUCT401.mdx) |
| `SYNC` | Synchronisation entre le PDV et votre boutique | [SYNC101](./SYNC101.mdx), [SYNC121](./SYNC121.mdx), [SYNC311](./SYNC311.mdx) |

Utilisez la barre latérale pour parcourir tous les codes d’un domaine, ou recherchez directement le code.

Les codes qui se terminent par `999` sont les codes génériques du domaine pour les conditions qui n’ont pas encore de code spécifique.

## Anciens codes (avant v1.10.0) {#legacy-codes}

Les versions antérieures à v1.10.0 utilisaient un autre format : `[DOMAIN][CATEGORY][SPECIFIC_CODE]`, par ex. `API04001` = API (domaine) + 04 (erreurs de réponse) + 001 (format de réponse invalide). Si vous utilisez une ancienne version ou consultez une ancienne entrée de journal ou un ancien fil de discussion d’assistance, ces pages s’appliquent toujours :

| Domaine | Nombre de codes | Couvre |
|--------|-------------|---------------|
| [API](./api.mdx) | 39 codes | Communication avec le serveur, authentification, problèmes liés aux extensions |
| [DB](./db.mdx) | 9 codes | Stockage et récupération des données locales |
| [PY](./py.mdx) | 6 codes | Traitement des paiements |
| [SY](./sy.mdx) | 5 codes | Ressources et configuration de l’appareil |

Un client v1.10.0+ ne génère jamais ces codes — si vous en voyez un sur un PDV à jour, il provient d’une ancienne entrée de journal conservée ou d’un message côté serveur.
