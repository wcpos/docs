## Ce que cela signifie {#what-this-means}

Votre boutique a refusé cette modification ; elle ne lui est donc pas parvenue.

Lisez le motif indiqué par la boutique. Si **État de la boutique → Base de données** répertorie la modification, corrigez la fiche puis appuyez sur **Renvoyer**, ou sur **Abandonner** pour l'écarter. Sinon, la version de la boutique a été restaurée : effectuez à nouveau la modification si elle est toujours nécessaire (voir [SYNC202](/error-codes/SYNC202)). Une modification refusée n'est jamais réessayée automatiquement.

## Vos données {#your-data}

N'effacez pas les données de cet appareil : elles peuvent contenir des modifications que votre boutique n'a pas encore reçues. Une modification refusée répertoriée dans **État de la boutique → Base de données** y reste jusqu'à ce que vous la renvoyiez ou l'abandonniez. Une modification refusée portant sur un produit, une variation, un client ou un coupon existant est généralement annulée automatiquement et consignée à la place sous le code [SYNC202](/error-codes/SYNC202). Si elle apparaît sous ce code et que la modification figure dans **État de la boutique → Base de données**, l'annulation automatique n'a pas eu lieu : traitez-la comme toute autre modification répertoriée ci-dessous. Si le problème persiste, utilisez **Copier les infos de débogage** dans l'onglet **Journaux** et contactez l'assistance WCPOS.

## Dépannage {#troubleshoot}

1. Lisez le motif indiqué par la boutique : il figure dans l’entrée du journal et sur la ligne de la modification dans **Santé de la boutique → Base de données**.
2. Ouvrez **Santé de la boutique → Base de données**. Si la modification n’y figure pas, la version de la boutique a déjà été restaurée sur cet appareil et rien n’est à envoyer : consultez [SYNC202](/error-codes/SYNC202). Corrigez le problème indiqué par le motif, puis refaites la modification si elle est toujours nécessaire.
3. Si elle y figure — une commande, un enregistrement créé sur cet appareil ou une modification du catalogue dont l’annulation automatique n’a pas eu lieu —, la modification refusée apparaît sous **« … modifications jamais parvenues à votre serveur »**, avec le motif de la boutique sur sa ligne. Corrigez le problème indiqué directement dans l’enregistrement, par exemple un champ de la commande, tant que la modification reste listée.
4. De retour dans **Santé de la boutique → Base de données**, touchez **Renvoyer** sur cette ligne. L’application reconstitue la modification à partir de l’état actuel de cet appareil et l’envoie.
5. Si la modification n’est plus nécessaire, touchez plutôt **Ignorer** : la version de la boutique est conservée. Lisez d’abord la confirmation : s’il s’agit d’un enregistrement jamais enregistré par la boutique, l’ignorer le supprime de cet appareil.
6. **Administrateur du site :** si le motif indique que l’utilisateur n’est pas autorisé à effectuer la modification, son rôle ne lui permet pas cette tâche ; consultez [AUTH201](/error-codes/AUTH201). Si le motif mentionne un champ qui n’apparaît pas dans le PDV, ouvrez le même enregistrement dans l’interface d’administration de WordPress : une autre extension peut ajouter une validation invisible pour le PDV. Si la modification est toujours refusée, utilisez **Copier les informations de débogage** dans l’onglet **Journaux** et contactez l’assistance.
