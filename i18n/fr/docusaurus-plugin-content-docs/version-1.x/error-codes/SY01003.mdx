# SY01003: Permission refusée {#sy01003-permission-denied}

## Ce que cela signifie {#what-this-means}

L'application POS n'a pas la permission d'accéder à une ressource requise. Il peut s'agir d'un fichier, d'un dossier ou d'une fonctionnalité système.

## Causes courantes {#common-causes}

- **Permissions de fichier** — Impossible de lire ou d'écrire dans les fichiers nécessaires
- **Permissions de l'application** — L'application manque des permissions requises
- **Dossier protégé** — Tentative d'accès à un emplacement restreint
- **Logiciel de sécurité** — Antivirus bloquant l'accès

## Comment corriger {#how-to-fix}

### 1. Exécuter en tant qu'administrateur (Windows) {#1-run-as-administrator-windows}

Cliquez avec le bouton droit sur l'application et sélectionnez « Run as administrator » si nécessaire pour la configuration initiale.

### 2. Vérifier les permissions de l'application {#2-check-application-permissions}

**macOS :**
- Système Preferences → Security & Privacy → Privacy
- Vérifiez que l'application dispose des permissions nécessaires

**Windows :**
- Paramètres → Confidentialité
- Passez en revue les permissions de l'application

### 3. Vérifier les permissions du dossier {#3-check-folder-permissions}

Assurez-vous que l'application peut accéder à son dossier de données :
- L'utilisateur doit posséder le répertoire de données de l'application
- Les permissions d'écriture doivent être activées
- Pas de drapeaux en lecture seule sur le dossier

### 4. Examiner les paramètres de l'antivirus {#4-review-antivirus-settings}

Le logiciel de sécurité peut bloquer l'accès :
- Vérifiez les journaux de l'antivirus pour les blocages
- Ajoutez l'application POS à la liste autorisée
- Mettez sur liste blanche le dossier de données de l'application

### 5. Réinstaller l'application {#5-reinstall-the-application}

:::warning Vérifiez d’abord qu’aucun travail n’est en attente d’enregistrement
La suppression des données locales ou la réinstallation de l’application efface tout ce qui se trouve sur cet appareil sans avoir été transmis à votre boutique — notamment les ventes effectuées hors ligne, les paniers ouverts et les modifications non enregistrées. Avant toute suppression, ouvrez **Store health → Database** et vérifiez qu’aucun élément n’est indiqué comme retenu ou comme n’ayant jamais atteint votre serveur, puis vérifiez dans **Store health → Logs** qu’il y a **0 enregistrement bloqué** et **0 modification en attente d’envoi** ; terminez ou notez ensuite chaque panier ouvert. Si votre WCPOS ne comporte pas de page Store health, mettez d’abord WCPOS à jour, puis vérifiez. Si un élément est répertorié ou en attente, ou si vous ne pouvez pas vérifier, ne supprimez rien — demandez conseil au propriétaire de votre boutique ou contactez l’assistance.
:::

Uniquement si les autorisations sont corrompues, et seulement après avoir effectué la vérification ci-dessus :
1. Désinstallez l'application POS
2. Redémarrez votre appareil
3. Réinstallez à un emplacement standard
4. Exécutez avec des permissions normales (non administratives)

## Permissions du navigateur (version Web) {#browser-permissions-web-version}

Si vous utilisez la version web :
- Autorisez le stockage local pour le site
- Activez les cookies pour le site
- N'utilisez pas de paramètres de navigateur trop restrictifs
