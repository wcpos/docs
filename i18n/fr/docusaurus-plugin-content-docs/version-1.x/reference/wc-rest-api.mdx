L’**API REST de WooCommerce** est comparable à un ensemble de « canaux » standardisés qui permettent aux propriétaires de boutiques de connecter leur boutique WooCommerce à d’autres applications et services.

Voici une explication simple de son fonctionnement :

1. Elle sert de passerelle entre votre boutique WooCommerce et les applications externes, qui peuvent ainsi communiquer et échanger des données.

2. L’API fonctionne en envoyant des requêtes à des **points de terminaison** spécifiques — imaginez des « canaux » correspondant à différents types de données de la boutique. Il existe, par exemple, des points de terminaison pour les produits, les commandes et les clients.

3. Les applications externes peuvent utiliser ces points de terminaison pour :

- Obtenir des informations (par exemple, récupérer une liste de produits)
- Ajouter de nouvelles données (par exemple, créer une commande)
- Mettre à jour des informations existantes (par exemple, modifier le prix d’un produit)
- Supprimer des données (par exemple, retirer un produit obsolète)

Au lieu de s’appuyer sur les hooks et filtres PHP (comme le font de nombreuses extensions WordPress traditionnelles), elle fonctionne en envoyant et en recevant des données dans un format structuré et prévisible appelé **JSON**.

## Pourquoi certaines extensions ne fonctionnent-elles pas dans le PDV ? {#why-dont-some-plugins-work-in-the-pos}

WCPOS télécharge les données des produits, des commandes et des clients depuis votre boutique WooCommerce via l’API REST.
WCPOS conserve ensuite une copie locale de ces données afin de continuer à fonctionner même si votre connexion Internet est instable.
Cette approche rend le PDV plus rapide et plus fiable dans un environnement d’encaissement très fréquenté.

Cela signifie toutefois que notre PDV ne « voit » pas en temps réel les modifications dynamiques apportées à votre site. Par exemple :

<table>
  <tr>
    <th style={{ width: "200px" }}>Type d’extension</th>
    <th>Pourquoi cela ne fonctionne pas</th>
  </tr>
  <tr>
    <td>Tarification dynamique</td>
    <td>
      Si une autre extension de votre boutique calcule un prix personnalisé pour chaque
      client connecté, le PDV ne récupère pas automatiquement ce prix
      personnalisé.
    </td>
  </tr>
  <tr>
    <td>Options supplémentaires du produit</td>
    <td>
      Si une autre extension de votre boutique ajoute des données supplémentaires aux produits, le PDV ne les récupère pas
      automatiquement. Le PDV ne reçoit que les données exposées
      via l’API REST.
    </td>
  </tr>
</table>
