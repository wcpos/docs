# Passerelle Mollie Terminal {#mollie-terminal-gateway}

La passerelle Mollie Terminal permet d’encaisser des paiements en personne sur le matériel [Mollie Terminal](https://www.mollie.com/products/point-of-sale) directement depuis WCPOS. Un paiement est initié depuis WooCommerce et finalisé sur le terminal, puis la confirmation de Mollie est enregistrée dans la commande.

## Fonctionnement {#how-it-works}

Mollie Terminal utilise les **paiements `pointofsale` côté serveur** de Mollie. Lorsque vous initiez un paiement, WooCommerce crée un paiement Mollie pour la commande et Mollie l’envoie au terminal sélectionné. Le client paie sur l’appareil, et **Mollie fait autorité** sur l’état du paiement et des remboursements — les métadonnées locales de la commande WooCommerce ne sont qu’un cache.

**Comment un paiement est confirmé.** Pendant que le paiement est en cours, le POS interroge Mollie (toutes les 2 secondes par défaut) et, dès que le terminal confirme, redirige directement vers la page de remerciement. Les webhooks Mollie sont également utilisés pour accélérer les choses — et l’URL du webhook est définie automatiquement à chaque paiement, il n’y a donc **rien à configurer dans le tableau de bord Mollie**.

Le terminal doit être enregistré et actif sur le même compte Mollie que l’extension.

## Installation {#setup}

<Steps>
  <StepCard number="1" title="Installer Mollie Terminal for WooCommerce">

Installez depuis `WP Admin > POS > Réglages > Extensions`, ou téléchargez le dernier **fichier zip de l’extension** (et non le zip du code source GitHub ni l’archive tarball) depuis la [page des versions GitHub](https://github.com/wcpos/mollie-terminal-for-woocommerce/releases) et importez-le via `Extensions > Ajouter > Téléverser une extension`.

  </StepCard>
  <StepCard number="2" title="Configurer vos identifiants Mollie">

1. Accédez à `WP Admin > WooCommerce > Réglages > Paiements` et ouvrez **Mollie Terminal**
2. Réglez le **Mode** sur `Live` — les paiements par terminal nécessitent un compte en production (voir [Portée et limitations](#scope-and-limitations))
3. Réglez la **Source de la clé API** pour réutiliser la clé de l’extension officielle Mollie Payments for WooCommerce, ou utilisez la clé saisie sur cet écran
4. Si vous saisissez la clé ici, collez votre **clé API live** Mollie dans **Mollie API Key**
5. Enregistrez

:::warning Utilisez le mode Live
Les terminaux Mollie n’existent que sur les comptes **live** : la clé API de test ne peut donc pas piloter un terminal. L’écran de réglages vous avertit lorsque le mode Test est sélectionné — passez en `Live` avec votre clé API live pour encaisser des paiements. Voir [Portée et limitations](#scope-and-limitations).
:::

:::note Aucun Profile ID nécessaire
Les paiements `pointofsale` ne nécessitent pas de **Profile ID** Mollie, et les terminaux sont listés pour l’ensemble du compte : il n’y a donc rien d’autre à coller.
:::

  </StepCard>
  <StepCard number="3" title="Choisir vos terminaux">

1. Choisissez un **Terminal par défaut** dans la liste déroulante. La liste est récupérée depuis l’environnement Mollie sélectionné — les terminaux inactifs sont masqués, car Mollie ne peut pas les réactiver.
2. *(Facultatif)* Limitez les **Terminaux activés** aux appareils réellement utilisés. Le terminal par défaut enregistré reste disponible même s’il n’est pas sélectionné ici ; laissez le réglage vide pour autoriser tous les terminaux actifs. Pour retirer un terminal du service, modifiez ou effacez également le **Terminal par défaut**.
3. *(Facultatif)* Activez **Verrouiller la sélection du terminal** afin que les caissiers ne puissent pas changer de terminal lors de l’encaissement — le terminal par défaut est toujours utilisé, et cette règle est également appliquée côté serveur.
4. Enregistrez

  </StepCard>
  <StepCard number="4" title="Activer dans WCPOS" isLast>

1. Accédez à `WP Admin > POS > Réglages > Encaissement`
2. Trouvez la passerelle **Mollie Terminal** et activez-la pour le POS
3. Enregistrez vos réglages

:::note
La case **Activer/Désactiver** de l’écran de réglages WooCommerce contrôle uniquement l’encaissement de la *boutique en ligne*. WCPOS utilise cette passerelle dès qu’elle est configurée, que cette case soit cochée ou non.
:::

  </StepCard>
</Steps>

## Référence des réglages {#settings}

| Réglage | Rôle |
|---|---|
| **Activer/Désactiver** | Active la passerelle pour l’encaissement de la boutique en ligne (non nécessaire pour le POS) |
| **Titre** / **Description** | Libellé et texte affichés au client lors de l’encaissement |
| **Mode** | `Test` ou `Live`. Les paiements par terminal nécessitent le mode **Live** — la clé API de test ne peut pas piloter un terminal |
| **Source de la clé API** | Utilise la clé saisie ci-dessous, ou réutilise la clé test/live correspondante de l’extension officielle Mollie Payments for WooCommerce. Si la clé partagée n’est pas disponible, l’extension bascule sur la clé ci-dessous |
| **Mollie API Key** | La clé API test ou live du mode sélectionné. Utilisée lorsque la **Source de la clé API** est réglée sur la clé saisie ici, et comme solution de repli en cas de clé partagée manquante |
| **Terminal par défaut** | Le terminal utilisé par défaut lors de l’encaissement, choisi dans une liste déroulante des terminaux actifs de l’environnement Mollie sélectionné |
| **Terminaux activés** | Limite la liste proposée à l’encaissement aux terminaux sélectionnés. Vide = tous les terminaux actifs. Le terminal par défaut enregistré est toujours disponible : modifiez-le ou effacez-le également lorsque vous retirez un terminal du service |
| **Verrouiller la sélection du terminal** | Impose le terminal par défaut lors de l’encaissement afin que les caissiers ne puissent pas en changer (nécessite un terminal par défaut) |
| **Journaux de débogage de l’encaissement** | Affiche les outils **Afficher les journaux**, **Copier** et **Effacer** dans le panneau de paiement de l’encaissement. Laissez cette option désactivée sauf pour collecter des journaux destinés à l’assistance ; l’activité de paiement est de toute façon toujours enregistrée sous `WooCommerce > État > Journaux` |

L’URL du webhook est appliquée automatiquement à chaque paiement : il n’y a donc aucun champ de webhook à remplir ni aucune configuration à effectuer dans le tableau de bord Mollie.

## Utilisation {#usage}

### Traitement des paiements {#processing-payments}

1. **Ajouter des articles** : ajoutez des produits au panier dans le POS
2. **Sélectionner la passerelle** : choisissez « Mollie Terminal » comme moyen de paiement
3. **Choisir le terminal** : sélectionnez un terminal dans la liste déroulante (le terminal configuré est proposé par défaut ; la liste est masquée si la sélection du terminal est verrouillée)
4. **Démarrer le paiement** : cliquez sur **Démarrer le paiement sur le terminal** — Mollie envoie le paiement à l’appareil
5. **Paiement du client** : le client approche, insère ou glisse sa carte sur le terminal. Le statut se met à jour en direct — `Envoi au terminal…` → `En attente du terminal…`
6. **Finalisation automatique** : lorsque le terminal confirme, la commande est marquée comme payée et le POS redirige automatiquement vers le reçu

### Commandes de paiement {#payment-controls}

- **Démarrer le paiement sur le terminal** : envoie une nouvelle demande de paiement au terminal sélectionné
- **Annuler le paiement** : annule un paiement encore ouvert. Une fois le paiement parvenu au terminal, Mollie le signale comme non annulable et le caissier l’annule sur l’appareil lui-même

### Gestion des commandes {#order-management}

- **Finalisation vérifiée** : chaque webhook, interrogation, annulation et nouvelle tentative récupère l’état Mollie faisant autorité avant de modifier une commande ; les commandes ne sont donc marquées comme payées que sur un état Mollie confirmé
- **Suivi des paiements** : les tentatives de paiement sont enregistrées dans un historique en ajout seul sur la commande
- **Génération du reçu** : les reçus POS standard sont générés après un paiement réussi

## Remboursements {#refunds}

Les remboursements sont pris en charge. Remboursez une commande depuis l’écran de commande WooCommerce habituel et le remboursement est transmis à Mollie. Mollie faisant autorité, les nouvelles tentatives de remboursement sont rapprochées des identifiants et métadonnées de remboursement Mollie **avant** d’en créer un autre : un remboursement n’est donc jamais émis deux fois par accident.

## Nettoyage des paiements obsolètes {#stale-payment-cleanup}

Un paiement Mollie `pointofsale` peut rester « ouvert » côté Mollie si un encaissement est abandonné. L’extension annule automatiquement ces paiements ouverts lorsque :

- l’interrogation automatique arrive à expiration (5 minutes par défaut) — l’annulation est envoyée au lieu de laisser le paiement en suspens
- la commande est finalisée avec un moyen de paiement **différent** (par exemple, le client paie en espèces), ou la commande est annulée dans WooCommerce
- la page d’encaissement est fermée en plein paiement — une annulation « au mieux » est déclenchée au moment où l’onglet est quitté
- un balayage WP-Cron s’exécute toutes les 10 minutes et annule ou résout les paiements restés ouverts au-delà du seuil d’obsolescence (10 minutes par défaut), y compris lorsque le navigateur est fermé ou que le réseau tombe avant que les autres mécanismes de nettoyage n’aient pu s’exécuter

Si le paiement est déjà parvenu au terminal, Mollie le signale comme non annulable et le caissier l’annule sur l’appareil lui-même — dans ce cas, ces nettoyages sont sans effet et sans risque.

## Portée et limitations {#scope-and-limitations}

:::important Limitation du mode test
Les terminaux Mollie n’existent que sur les comptes **live**. La clé API de **test** Mollie ne peut pas piloter un terminal physique (ni iOS/Android) : les paiements par terminal ne peuvent donc pas être testés de bout en bout en mode test. Il s’agit d’une limitation de la plateforme Mollie, et non d’une restriction de l’extension — l’écran de réglages affiche un avertissement lorsque le mode Test est sélectionné. Utilisez le mode **Live** avec votre clé API live pour encaisser des paiements par terminal.
:::

:::note Devise
Les paiements par terminal au POS sont limités à l’**EUR** tant qu’une prise en charge plus large des devises par Mollie Terminal n’est pas confirmée.
:::

## Dépannage {#troubleshooting}

### Problèmes fréquents {#common-issues}

<Accordion>
  <AccordionItem question="Aucun terminal n’apparaît dans la liste déroulante">

  - Vérifiez que le **Mode** est réglé sur `Live` et que la clé API effective est une clé live — les terminaux n’existent pas sur les comptes de test
  - Vérifiez que le terminal est enregistré et **actif** sur votre compte Mollie ; les terminaux inactifs sont masqués, car Mollie ne peut pas les réactiver
  - Assurez-vous que votre site peut joindre Mollie — la liste est récupérée en direct via l’API

  </AccordionItem>

  <AccordionItem question="Le paiement ne démarre pas">

  - Vérifiez qu’un terminal est sélectionné (ou qu’un **Terminal par défaut** est défini lorsque la sélection est verrouillée)
  - Vérifiez que le terminal est allumé, en ligne et actif sur le même compte Mollie
  - Vérifiez que la devise de la commande est l’**EUR**

  </AccordionItem>

  <AccordionItem question="Le terminal a expiré ou le paiement est resté ouvert">

  - L’extension tente d’annuler automatiquement les paiements ouverts en cas d’expiration (5 minutes par défaut)
  - Si le paiement est déjà parvenu au terminal et ne peut pas être annulé automatiquement, annulez-le sur l’appareil lui-même
  - Vous pouvez ensuite démarrer un nouveau paiement ou encaisser autrement

  </AccordionItem>

  <AccordionItem question="La commande a été payée sur le terminal, mais tarde à se mettre à jour">

  - Le POS interroge Mollie toutes les 2 secondes et redirige dès que le paiement est confirmé ; un webhook le confirme généralement en premier
  - Mollie faisant autorité, la commande est rapprochée de l’état Mollie de référence — elle n’est pas perdue
  - Consultez `WooCommerce > État > Journaux` pour y trouver d’éventuels messages de l’API Mollie

  </AccordionItem>
</Accordion>
