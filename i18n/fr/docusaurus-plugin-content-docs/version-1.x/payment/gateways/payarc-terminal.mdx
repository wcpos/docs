# Passerelle PayArc Terminal {#payarc-terminal-gateway}

La passerelle PayArc Terminal vous permet d’accepter des paiements en personne sur un terminal PayArc PAX depuis WCPOS via PayArc Connect. Le paiement est lancé depuis WooCommerce et effectué sur le terminal ; la commande n’est marquée comme payée qu’après confirmation de PayArc.

## Fonctionnement {#how-it-works}

WordPress appelle **PayArc Connect**, qui communique avec le terminal PAX. Le PDV communique uniquement avec votre site. Chaque paiement porte sur le **montant total de la commande**.

La page de paiement vérifie le résultat toutes les **1.5 secondes** et s’arrête après **5 minutes**. Les rappels de PayArc à l’URL indiquée dans **Webhook URL** accélèrent l’affichage du résultat ; les paiements aboutissent toujours grâce à la vérification périodique, même sans rappel. Gardez la page de paiement ouverte pendant que le client paie sur le terminal.

## Configuration {#setup}

<Steps>
  <StepCard number="1" title="Installer PayArc Terminal for WooCommerce">

Installez l’extension depuis `WP Admin > POS > Réglages > Extensions` ou téléchargez l’archive **payarc-terminal-for-woocommerce.zip** depuis la [page des versions GitHub](https://github.com/wcpos/payarc-terminal-for-woocommerce/releases), puis téléversez-la via `Extensions > Ajouter > Téléverser une extension`. Activez l’extension.

  </StepCard>
  <StepCard number="2" title="Saisir vos identifiants PayArc">

1. Accédez à `WP Admin > WooCommerce > Réglages > Paiements` et ouvrez **PayArc Terminal**
2. Choisissez le **Mode** : `Live` est le mode par défaut. Utilisez `Test` uniquement avec les identifiants du tableau de bord de test PayArc et l’application PayArc Connect Test. Ne mélangez jamais les environnements
3. Renseignez le champ **PayArc login email** avec l’adresse e-mail utilisée pour vous connecter à votre tableau de bord marchand PayArc
4. Saisissez le **PayArc MID** indiqué dans le profil marchand PayArc, et non l’identifiant du terminal
5. Saisissez le **PayArc ClientSecret** indiqué dans la section API du tableau de bord et le **PayArc SecretKey / API bearer token** du tableau de bord PayArc
6. Laissez le champ **Callback bearer token** vide, sauf si l’assistance PayArc vous en a fourni un ; il est facultatif

  </StepCard>
  <StepCard number="3" title="Connexion">

Cliquez sur **Connect using these credentials**. Si la connexion réussit, l’écran vous invite à saisir ou confirmer le numéro de série du terminal et à enregistrer les réglages. Si le message indique que les identifiants semblent appartenir à l’autre environnement, changez le **Mode** et reconnectez-vous.

:::note
Après chaque modification du mode ou des identifiants, cliquez de nouveau sur **Connect using these credentials** et enregistrez. Les paiements sont bloqués tant que le mode et les identifiants ne correspondent pas à la connexion enregistrée. Si vous effectuez une mise à niveau depuis une version antérieure à 0.1.14, cliquez une fois sur Connect.
:::

  </StepCard>
  <StepCard number="4" title="Ajouter votre terminal">

1. Renseignez le champ **Terminal serial number** avec le numéro de série du terminal PAX indiqué sur l’étiquette **S/N** au dos de l’appareil, tel qu’il a été configuré par PayArc pour votre compte
2. Choisissez les réglages **Tender type** et **Print receipt**
3. Vérifiez que l’URL du champ **Webhook URL** utilise HTTPS. Ne la communiquez à PayArc que si l’assistance vous la demande
4. Cliquez sur **Save changes**

Le mode Live nécessite un site HTTPS.

  </StepCard>
  <StepCard number="5" title="Activer dans WCPOS" isLast>

1. Accédez à `WP Admin > POS > Réglages > Validation de la commande`
2. Repérez la passerelle **PayArc Terminal** et activez-la pour le PDV
3. Enregistrez vos réglages

:::note
La case **Enable/Disable** dans les réglages WooCommerce contrôle uniquement le paiement dans la boutique en ligne. WCPOS utilise cette passerelle dès qu’elle est configurée, que cette case soit cochée ou non.

La plupart des boutiques laissent cette case décochée.
:::

  </StepCard>
</Steps>

## Référence des réglages {#settings}

| Réglage | Fonction |
|---|---|
| **Enable/Disable** | Active PayArc Terminal pour le paiement dans la boutique en ligne. Désactivé par défaut ; l’activation pour le PDV se règle dans `POS > Réglages > Validation de la commande` |
| **Title** | Libellé affiché au paiement ; valeur par défaut : `PayArc Terminal` |
| **Description** | Description affichée au paiement ; valeur par défaut : `Pay in person at a PayArc PAX terminal.` |
| **Mode** | `Live` (par défaut) ou `Test`. Le mode Test nécessite les identifiants du tableau de bord de test PayArc et l’application PayArc Connect Test |
| **PayArc login email** | Adresse e-mail de connexion à votre tableau de bord marchand PayArc ; requise avant la connexion |
| **PayArc MID** | MID marchand indiqué dans votre profil marchand PayArc, et non l’identifiant du terminal |
| **PayArc ClientSecret** | Clé secrète de la section API du tableau de bord ; stockée uniquement sur votre serveur |
| **PayArc SecretKey / API bearer token** | Jeton du tableau de bord PayArc, utilisé pour se connecter et récupérer le registre des terminaux |
| **Callback bearer token** | Facultatif. Renseignez-le uniquement si l’assistance PayArc vous en a fourni un |
| **PayArc connection** | Boutons **Connect using these credentials**, **Refresh Terminals** et **Disconnect** |
| **Terminal serial number** | Numéro S/N du terminal PAX attribué à votre compte, requis pour les paiements. Renseigné depuis le registre s’il y figure ; saisissez-le ou confirmez-le avant l’enregistrement |
| **Tender type** | `CREDIT` (par défaut) ou `DEBIT` |
| **Print receipt** | `0` — aucun (par défaut), `1` — commerçant, `2` — client, `3` — les deux |
| **Webhook URL** | Adresse de rappel en lecture seule. Vérifiez qu’elle utilise HTTPS ; ne la communiquez à PayArc que si l’assistance vous la demande |
| **PayArc diagnostics** | Informations de connexion et bouton **Validate Settings** ; les secrets ne sont jamais affichés |

Les champs de secret enregistrés n’affichent que les 4 derniers caractères. Laissez un champ de secret vide pour conserver la valeur enregistrée.

Le tableau **PayArc diagnostics** affiche le mode, les points de terminaison, le MID / ID de locataire / numéro de série masqués, la présence du jeton d’accès Connect, l’URL du webhook, le dernier rappel et la dernière erreur PayArc. Utilisez **Validate Settings** pour vérifier vos réglages.

## Utilisation {#usage}

### Traiter les paiements {#processing-payments}

1. **Sélectionner la passerelle** : choisissez **PayArc Terminal** comme mode de paiement dans le PDV
2. **Lancer le paiement** : cliquez sur **Start Payment** pour envoyer le montant total de la commande au terminal
3. **Paiement du client** : gardez la page ouverte pendant que le client effectue le paiement sur le terminal PAX. Suivez les messages d’état : `Starting terminal payment...` → `Payment sent to terminal.` → `Waiting for the terminal result...` → `Payment approved. Completing the order...`
4. **Finalisation automatique** : lorsque PayArc confirme le paiement, la commande est finalisée automatiquement

### Commandes de paiement {#payment-controls}

- **Cancel Payment** apparaît dès qu’un paiement est lancé. Si PayArc n’a pas encore renvoyé d’identifiant de trace, attendez un instant avant d’annuler
- Après un refus, une annulation ou un délai d’attente dépassé, vous pouvez réessayer. En cas de dépassement du délai, vérifiez le terminal avant de réessayer
- Le journal d’activité des paiements est réduit par défaut. Utilisez **Show activity** pour l’afficher et **Clear** pour effacer l’activité affichée

### Reçus {#receipts}

Le réglage **Print receipt** contrôle l’impression sur le terminal : aucun reçu, le reçu commerçant, le reçu client ou les deux.

## Remboursements {#refunds}

Les remboursements ne sont pas pris en charge par l’extension. Effectuez le remboursement via PayArc, puis enregistrez-le manuellement dans WooCommerce.

## Journaux {#logs}

Retrouvez les journaux dans `WooCommerce > Status > Journaux`, sous la source `payarc-terminal-for-woocommerce`. Ils incluent les tentatives de connexion, les ventes lancées ou échouées, les annulations et les rappels acceptés ou refusés. Les identifiants sont masqués et les secrets supprimés.

Il n’est pas possible de télécharger un dossier d’assistance. Pour demander de l’aide, transmettez le numéro de commande et les lignes de journal pertinentes. Ne communiquez pas les MID complets, les identifiants de terminal, les jetons ni les données de carte.

## Portée et limites {#scope-and-limitations}

- Les remboursements ne sont pas pris en charge par l’extension
- Les paiements portent sur le **montant total de la commande** ; les paiements partiels ou fractionnés ne sont pas pris en charge
- Les pourboires ne sont pas pris en charge
- Un terminal par boutique : un seul réglage de numéro de série, sans sélecteur de caissier
- Les devises sont limitées à **USD, CAD, GBP, EUR et JPY**
- Les paiements sont bloqués tant que le mode et les identifiants ne correspondent pas à la connexion enregistrée

## Dépannage {#troubleshooting}

### Problèmes courants {#common-issues}

<Accordion>
  <AccordionItem question="Les identifiants semblent appartenir à l’autre environnement">

  - Le mode sélectionné et les identifiants proviennent d’environnements différents
  - Changez le **Mode** pour qu’il corresponde aux identifiants, ou remplacez les identifiants par ceux de l’environnement sélectionné
  - Cliquez de nouveau sur **Connect using these credentials** et enregistrez

  </AccordionItem>
  <AccordionItem question="Impossible de se connecter à PayArc">

  - PayArc a refusé les identifiants de connexion. Vérifiez les identifiants saisis et réessayez
  - Consultez `WooCommerce > Status > Journaux`, source `payarc-terminal-for-woocommerce`, pour plus de détails

  </AccordionItem>
  <AccordionItem question="Impossible de traiter la requête de paiement. (HTTP 500)">

  - Ce message destiné au caissier est générique. Recherchez **PayArc payment action failed** dans le journal WooCommerce pour connaître la cause réelle
  - Après avoir modifié le mode ou les identifiants, cliquez de nouveau sur **Connect using these credentials** et enregistrez
  - Vérifiez que le champ **Terminal serial number** est renseigné
  - Si le journal indique que PayArc a refusé à la fois le jeton d’accès Connect et le SecretKey, demandez à l’assistance PayArc de confirmer que **PayArc Connect V3** est activé pour votre compte marchand
  - Vérifiez que la devise de la boutique est **USD, CAD, GBP, EUR ou JPY**

  </AccordionItem>
  <AccordionItem question="Accès refusé. (HTTP 403) lors du lancement du paiement">

  - Effectuez la mise à jour vers la version **0.1.12 ou ultérieure**, qui corrige cette erreur pour les sessions PDV

  </AccordionItem>
  <AccordionItem question="Le registre des terminaux est vide">

  - Un registre vide, ou un terminal affiché sans identifiant de PDV, est normal
  - Les données du registre sont uniquement informatives. Les paiements utilisent le numéro indiqué dans **Terminal serial number**

  </AccordionItem>
  <AccordionItem question="Un paiement prend trop de temps">

  - Vérifiez l’écran du terminal et gardez la page de paiement ouverte
  - Vérifiez les notes de commande et le tableau de bord PayArc avant de réessayer
  - La page vérifie le résultat toutes les **1.5 secondes** et s’arrête après **5 minutes**

  </AccordionItem>
</Accordion>
