# Passerelle Windcave Terminal {#windcave-terminal-gateway}

La passerelle Windcave Terminal vous permet d’accepter des paiements par carte en personne sur un terminal Windcave via Windcave HIT. Les paiements sont lancés depuis WCPOS et effectués sur le terminal, puis leur confirmation est enregistrée dans la commande WooCommerce.

:::warning Nouveau dans la version 0.1.0 — certification Windcave en attente
La version 0.1.0 est la première version. Windcave exige la certification QA d’une intégration avant son utilisation en production, et cette intégration n’est pas encore certifiée. Utilisez-la avec les identifiants Windcave **UAT** (test) jusqu’à la fin de la certification. Windcave délivre l’**ID du fournisseur** pendant la certification.
:::

## Fonctionnement {#how-it-works}

La passerelle utilise Windcave **HIT (Host Initiated Transaction)** sur HTTPS. **Environnement** sélectionne le point de terminaison UAT ou production, et chaque terminal est identifié par l’**ID de station** attribué par Windcave.

Le lancement d’un paiement transmet au terminal le total intégral de la commande et la devise. La page de paiement interroge Windcave toutes les **1.5 secondes**, en reproduisant les invites et les boutons disponibles sur le terminal. Les **notifications de résultat (FPRN)** facultatives permettent à Windcave d’avertir le site en complément de l’interrogation périodique.

## Configuration {#setup}

<Steps>
  <StepCard number="1" title="Installer Windcave Terminal pour WooCommerce">

Téléchargez le **fichier ZIP de l’extension** (et non le ZIP du code source GitHub) depuis la [page des versions GitHub](https://github.com/wcpos/windcave-terminal-for-woocommerce/releases). Téléversez-le via `Extensions > Ajouter > Téléverser une extension`, puis activez-le après avoir installé et activé WooCommerce.

L’activation nécessite **PHP 7.4+** et l’**extension PHP DOM (php-xml)**. Si l’un de ces éléments manque, l’activation est refusée avec un message.

  </StepCard>
  <StepCard number="2" title="Obtenir les identifiants HIT auprès de Windcave">

Demandez à Windcave un **nom d’utilisateur HIT**, une **clé HIT** et un **ID de station** par terminal. Demandez un compte de développement via le [formulaire des exigences d’intégration](https://www.windcave.com/merchant-attended-developer-hit) de Windcave.

Les identifiants UAT et de production sont distincts. Utilisez les identifiants UAT tant que cette intégration est en attente de certification.

  </StepCard>
  <StepCard number="3" title="Configurer la passerelle">

1. Accédez à `WP Admin > WooCommerce > Réglages > Paiements` et ouvrez **Windcave Terminal**
2. Réglez **Environnement** sur `UAT (testing)` (valeur par défaut). `Production` s’utilise après la certification Windcave avec les identifiants de production
3. Saisissez le **nom d’utilisateur HIT** et la **clé HIT** fournis par Windcave
4. Saisissez vos **ID de station**, un par ligne
5. *(Facultatif)* Définissez un **ID de station par défaut**. Activez **Verrouiller la sélection du terminal** pour toujours utiliser cette valeur par défaut et empêcher les caissiers de la modifier
6. Laissez l’**ID du fournisseur** vide jusqu’à ce que Windcave vous en attribue un pendant la certification
7. Enregistrez vos réglages

  </StepCard>
  <StepCard number="4" title="Activer les notifications de résultat (facultatif)">

Activez **Notifications de résultat (FPRN)** et enregistrez pour demander à Windcave d’avertir votre site lorsqu’un résultat de transaction est disponible. Il s’agit d’un complément à l’interrogation périodique.

  </StepCard>
  <StepCard number="5" title="Activer dans WCPOS" isLast>

1. Accédez à `WP Admin > POS > Réglages > Validation de la commande`
2. Repérez la passerelle **Windcave Terminal** et activez-la pour le PDV
3. Enregistrez vos réglages

:::note
La case **Activer/Désactiver** dans les réglages WooCommerce ne contrôle que le paiement de la *boutique en ligne*. WCPOS utilise cette passerelle dès qu’elle est configurée, que cette case soit cochée ou non.
:::

  </StepCard>
</Steps>

## Référence des réglages {#settings}

| Réglage | Fonction |
|---|---|
| **Activer/Désactiver** | Active la passerelle pour le paiement de la boutique en ligne. L’activation pour le PDV se règle sous `POS > Réglages > Validation de la commande` |
| **Titre** | Libellé du paiement ; valeur par défaut : `Windcave Terminal` |
| **Description** | Description du paiement ; valeur par défaut : `Pay in person on the Windcave terminal.` |
| **Environnement** | `UAT (testing)` (par défaut) ou `Production`. Chaque environnement utilise des identifiants HIT distincts ; la production nécessite la certification Windcave |
| **Nom d’utilisateur HIT** | Nom d’utilisateur HIT fourni par Windcave pour l’environnement sélectionné |
| **Clé HIT** | Clé HIT fournie par Windcave pour l’environnement sélectionné |
| **ID de station** | Un ID de station attribué par Windcave par ligne, un pour chaque terminal |
| **ID de station par défaut** | Station présélectionnée, également utilisée lorsqu’aucune station n’est sélectionnée |
| **Verrouiller la sélection du terminal** | Utilise toujours la station par défaut pour empêcher les caissiers de la modifier. Ne prend effet que si une valeur par défaut est définie |
| **ID du fournisseur** | Attribué par Windcave pendant la certification. Laissez ce champ vide tant que Windcave ne vous l’a pas fourni |
| **Nom du PDV** | Nom envoyé à Windcave pour identifier le PDV ; valeur par défaut : `WCPOS` |
| **Notifications de résultat (FPRN)** | Demande à Windcave d’avertir le site lorsqu’un résultat de transaction est disponible, en complément de l’interrogation périodique. Désactivé par défaut |
| **Journaux de paiement** | Affiche les outils de journalisation dans le panneau de paiement. Désactivé par défaut |
| **Niveau de journalisation** | `Off`, `Errors only` ou `Debug`. Par défaut : Debug ; les requêtes et réponses sont consignées avec les clés et les données de carte masquées |
| **Assistance** | Fournit **Télécharger le dossier d’assistance** et un lien pour consulter les journaux dans `WooCommerce > Status > Journaux` |

Il n’y a pas de bouton de test de connexion : les identifiants et les ID de station sont vérifiés lors du premier paiement.

## Utilisation {#usage}

### Traiter les paiements {#processing-payments}

1. **Ajouter des articles** : Ajoutez des produits au panier dans le PDV
2. **Sélectionner une passerelle** : Choisissez **Windcave Terminal** comme mode de paiement
3. **Choisir un terminal** : Sélectionnez une station ou utilisez la valeur par défaut verrouillée. Une sélection est obligatoire s’il y a au moins deux stations et aucune valeur par défaut
4. **Lancer le paiement** : Cliquez sur **Lancer le paiement sur le terminal** pour envoyer le total de la commande au terminal
5. **Suivre les invites** : Les invites et les boutons disponibles sur le terminal s’affichent à l’écran, notamment **YES/NO** pour la vérification de signature et **CANCEL** lorsqu’il est proposé
6. **Finalisation automatique** : Après approbation et vérification, la commande est finalisée et le PDV affiche le reçu

### Commandes de paiement {#payment-controls}

- **Lancer le paiement sur le terminal** : Envoyer une nouvelle requête de paiement à la station sélectionnée
- **Annuler le paiement sur le terminal** : Appuie sur le bouton **CANCEL** du terminal lorsqu’il est proposé. Sinon, annulez sur le terminal ou mettez le paiement de côté lorsque cette option apparaît
- **Mettre le paiement de côté** : Apparaît après le **délai d’attente de 5 minutes**. L’opération reste suivie par une **vérification en arrière-plan de 10 minutes** afin que vous puissiez encaisser autrement ; elle n’annule pas le paiement auprès de Windcave
- **Rechargement de la page** : Reprend un paiement déjà en cours

### Reçus {#receipts}

Le texte du reçu du terminal, lorsque Windcave le renvoie, est enregistré sous forme de **note privée de commande** dans WooCommerce.

## Remboursements {#refunds}

Les remboursements depuis WooCommerce ne sont **pas pris en charge dans la version 0.1.0**. Effectuez le remboursement dans le portail Windcave (**Payline**) ou sur le terminal, puis consignez-le **manuellement** dans WooCommerce.

## Journaux et dossier d’assistance {#logs-and-support-bundle}

Consultez les journaux dans `WooCommerce > Status > Journaux`, sous la source `windcave-terminal`. Le niveau de journalisation par défaut est **Debug** ; les requêtes et réponses Windcave sont consignées avec les clés et les données de carte masquées.

Cliquez sur **Télécharger le dossier d’assistance** dans l’écran des réglages de la passerelle pour télécharger un fichier `.json`, puis envoyez-le avec le **numéro de commande**. Il contient des détails sur l’environnement, les réglages avec la clé et le nom d’utilisateur HIT masqués, les tentatives de paiement de 20 commandes récentes au maximum sans les reçus, ainsi que les 1,000 dernières lignes des deux fichiers journaux les plus récents ; les lignes peuvent inclure le texte des reçus du terminal avec les numéros de carte masqués.

Si WooCommerce utilise le **gestionnaire de journaux de la base de données**, le dossier ne contient aucune ligne de journal. Exportez plutôt les journaux depuis `WooCommerce > Status > Journaux`.

Activez **Journaux de paiement** pour afficher les outils de journalisation dans le panneau de paiement.

## Périmètre et limites {#scope-and-limitations}

:::warning Certification requise
Cette intégration n’est pas encore certifiée par Windcave. Utilisez les identifiants **UAT** jusqu’à la fin de la certification QA de Windcave ; ne l’utilisez pas en production avant sa certification.
:::

- Les remboursements depuis WooCommerce ne sont pas pris en charge dans la version 0.1.0
- Les pourboires, frais supplémentaires et retraits d’espèces ne sont pas pris en charge
- Seules les **devises à deux décimales** sont prises en charge
- Le terminal débite le **montant total de la commande** ; le paiement d’une partie seulement de la commande sur le terminal n’est pas pris en charge
- Les **ID de station** sont saisis manuellement ; les terminaux ne sont pas détectés automatiquement
- La passerelle est conçue pour le PDV. Dans la boutique en ligne, elle fonctionne uniquement sur la **page order-pay**

## Dépannage {#troubleshooting}

### Problèmes fréquents {#common-issues}

<Accordion>
  <AccordionItem question="Activation refusée : extension PHP DOM (php-xml) requise">

  - L’extension PHP DOM est absente du serveur
  - Demandez à votre hébergeur d’activer **php-xml**. L’activation nécessite également **PHP 7.4+**

  </AccordionItem>
  <AccordionItem question="Aucun ID de station configuré">

  - Le réglage **ID de station** est vide
  - Ajoutez les ID de station fournis par Windcave dans les réglages de la passerelle, un par ligne, puis enregistrez

  </AccordionItem>
  <AccordionItem question="Les identifiants Windcave HIT ne sont pas configurés">

  - Le **nom d’utilisateur HIT** ou la **clé HIT** est vide
  - Saisissez les deux dans les réglages de la passerelle, puis enregistrez. Vérifiez que **Environnement** correspond à ces identifiants

  </AccordionItem>
  <AccordionItem question="Le terminal termine encore une transaction précédente">

  - Une transaction précédente est toujours en cours sur cette station
  - Terminez-la ou annulez-la sur le terminal, puis réessayez

  </AccordionItem>
  <AccordionItem question="Windcave ne trouve aucune trace de cette transaction">

  - Windcave ne trouve toujours aucune trace après le délai de grâce initial de 30 secondes
  - Relancez le paiement

  </AccordionItem>
  <AccordionItem question="Windcave a approuvé un paiement, mais il n’a pas pu être appliqué">

  - Le résultat approuvé n’a pas satisfait aux vérifications nécessaires pour finaliser cette commande
  - Vérifiez le **portail Windcave** et les **notes de commande avant de facturer à nouveau**

  </AccordionItem>
  <AccordionItem question="Ce paiement a été lancé dans un autre environnement">

  - **Environnement** a été modifié pendant le traitement du paiement
  - Revenez à l’environnement dans lequel le paiement a été lancé ou consultez le portail Windcave

  </AccordionItem>
</Accordion>
