WCPOS stocke vos données produits et clients dans une base de données locale sur chaque appareil. Certaines parties du PDV fonctionnent donc sans connexion Internet, tandis que d'autres nécessitent une connexion.

## Ce qui fonctionne hors connexion {#what-works-offline}

- **Parcourir les produits** — rechercher, filtrer et consulter les détails des produits à partir des données locales
- **Parcourir les clients** — rechercher des noms de clients, des adresses e-mail et des adresses postales
- **Constituer un panier** — ajouter des articles, modifier les quantités, modifier les prix et appliquer des remises PDV
- **Appliquer des coupons** (Pro) — les codes sont validés localement à partir des données de coupons synchronisées ; le serveur les revalide lorsque la commande en file d'attente lui parvient
- **Finaliser une vente avec un moyen de paiement compatible hors connexion** — les ventes en espèces et les ventes par carte traitées en externe sont enregistrées localement et mises en file d'attente pour WooCommerce
- **Lecture de codes-barres** — scanner des codes-barres pour trouver des produits dans la base de données locale
- **Consulter les rapports** — le type de rapport par défaut (hors connexion) génère les rapports à partir des commandes stockées localement

## Ce qui nécessite une connexion {#what-requires-a-connection}

- **Les actions d'encaissement dépendant du serveur** — le paiement web, les passerelles en ligne ou de terminal intégrées et **Enregistrer sur le serveur** nécessitent que leurs services respectifs soient joignables
- **La synchronisation des données** — récupérer les nouveaux produits, les prix mis à jour ou les nouveaux clients depuis WooCommerce
- **La connexion** — l'authentification initiale nécessite une connexion à votre site WordPress
- **L'activation de licence** — les vérifications de licence Pro doivent joindre le serveur de licences WCPOS
- **Le traitement des remboursements** — les remboursements ne peuvent pas être mis en file d'attente hors connexion ; la passerelle et votre boutique doivent toutes deux être joignables (voir [Remboursements](/orders/refunds))

## Fonctionnement de la base de données locale {#how-the-local-database-works}

Lorsque vous ouvrez WCPOS pour la première fois, il amorce votre catalogue produits en arrière-plan et récupère les autres données au fil de votre utilisation — vous pouvez commencer à vendre dès que les premiers produits sont sur l'appareil. Ensuite, un contrôle des changements en arrière-plan (toutes les 60 secondes par défaut, ajustable dans [État de la boutique](/support/store-health)) ne récupère que ce qui a changé sur le serveur.

La base de données locale :

- **Persiste entre les sessions** — les données survivent aux redémarrages du navigateur et de l'appareil
- **Est propre à chaque appareil (et à chaque caissier)** — chaque appareil conserve sa propre copie locale ; les caissiers ne partagent pas les données locales
- **Reste synchronisée** — les contrôles des changements en arrière-plan récupèrent les mises à jour ; vos modifications sont mises en file d'attente localement puis envoyées au serveur

Vous pouvez voir exactement ce qui se trouve sur l'appareil — et ce qui reste à envoyer — dans **État de la boutique → Base de données**. Pour plus de détails techniques, consultez [Fonctionnement du moteur de synchronisation](/reference/sync-engine).

## Les modifications faites hors connexion sont mises en file d'attente {#offline-writes}

Chaque modification effectuée dans le PDV — une vente, une modification de produit, une mise à jour client — est d'abord enregistrée sur l'appareil, puis mise en file d'attente pour envoi. Tant que vous êtes hors connexion, la file d'attente attend simplement ; rien n'est perdu si la connexion tombe en pleine journée.

Lorsque la connexion revient, la file d'attente se vide automatiquement. Si votre serveur refuse catégoriquement une modification (rare — par exemple, un enregistrement que le serveur juge invalide), le PDV ne la réessaie pas silencieusement indéfiniment : la modification est mise de côté dans **État de la boutique → Base de données**, sous « modifications n'ayant jamais atteint votre serveur », avec le motif indiqué par le serveur et des actions explicites **Renvoyer** / **Ignorer**. Consultez [État de la boutique](/support/store-health#refused-changes).

## Indicateur de connectivité {#connectivity-indicator}

L'en-tête du PDV affiche un point coloré indiquant l'état de la connexion :

- **Vert** — connecté au serveur, toutes les fonctionnalités sont disponibles
- **Jaune** — connexion intermittente, certaines opérations peuvent être lentes
- **Rouge** — hors connexion, limité aux données locales

## Ce qui se passe en cas de perte de connectivité {#what-happens-during-connectivity-loss}

Si vous perdez votre connexion Internet pendant l'utilisation du PDV :

1. **Les produits et les clients restent consultables** à partir des données locales.
2. **Vous pouvez continuer à constituer des paniers** et à modifier des articles — chaque modification est mise en file d'attente localement.
3. **Vous pouvez finaliser un encaissement avec un moyen de paiement compatible hors connexion** — la vente rejoint la file d'attente sortante. Les passerelles de paiement dépendant du serveur restent indisponibles tant que leurs services ne sont pas joignables.
4. **Les commandes ouvertes sont conservées** dans la base de données locale jusqu'au retour de la connectivité.

## Au rétablissement de la connexion {#when-connection-restores}

Une fois votre connexion revenue :

- L'indicateur de connectivité passe au vert.
- **Les modifications en file d'attente sont envoyées automatiquement à votre serveur** — les ventes et les modifications effectuées hors connexion partent sans aucune action manuelle.
- Les passerelles de paiement dépendant du serveur et **Enregistrer sur le serveur** redeviennent disponibles.
- La synchronisation en arrière-plan reprend et récupère les modifications de produits ou de clients survenues pendant votre déconnexion.

## Conseils pour les connexions peu fiables {#tips-for-unreliable-connections}

- **Utilisez « Enregistrer sur le serveur » pour les commandes importantes** — cela envoie la commande immédiatement à WooCommerce, afin qu'elle ne soit pas perdue si la base de données locale de l'appareil est effacée.
- **Vérifiez l'État de la boutique après une coupure** — la tuile *modifications en attente d'envoi* dans **État de la boutique → Base de données** confirme que tout est bien parvenu à votre serveur.
- **Synchronisez tant que vous avez du signal** — si vous savez que la connectivité sera intermittente, laissez l'amorçage du catalogue se terminer pendant que la connexion est bonne.
