WCPOS 2.0 ist ein großes Update: eine neue Kassenoberfläche, ein neuer Zahlungsvorgang und eine Kassenschublade. Diese Seite richtet sich an alle, die auf **Aktualisieren** klicken. Lesen Sie sie vorher bis zum Ende.

:::warning Zuerst alle Kassen synchronisieren
Wenn eine Kasse zum ersten Mal 2.0 öffnet, löscht sie die Daten von 1.11 auf diesem Gerät. Verkäufe, die sie bis dahin nicht an Ihren Shop gesendet hat, gehen verloren. Lassen Sie vor dem Update alle Kassen die Synchronisierung abschließen.

Der Shop ist bereits aktualisiert, aber auf einer Kasse liegen noch nicht gesendete Verkäufe? Siehe [Auf einer Kasse mit 1.11 liegen noch nicht gesendete Verkäufe](#unsent-sales).
:::

## Können Sie das Upgrade heute durchführen? {#can-you-upgrade-today}

Öffnen Sie **WP Admin → Plugins** und prüfen Sie zwei Dinge.

- **WooCommerce ist auf Version 9.0 oder neuer.** 2.0 setzt das voraus. Bei einer Version vor 9.0 lesen Sie [Wenn Ihr Shop noch nicht bereit ist](#if-your-store-isnt-ready-yet) und aktualisieren Sie WCPOS nicht zuerst.
- **Sie haben WCPOS Pro, wenn Sie eine Kartenterminal-Erweiterung verwenden.** Ab 2.0 benötigen Stripe Terminal, SumUp, Mollie Terminal und die anderen Terminal-Erweiterungen Pro. Wenn Sie eine davon ohne Pro verwenden, lesen Sie vor dem Update zuerst [Kostenlos vs. Pro](./free-vs-pro.mdx).

WooCommerce ist auf Version 9.0 oder neuer, und Sie verwenden entweder keine Kartenterminal-Erweiterung oder haben WCPOS Pro: Fahren Sie mit [Bevor Sie auf Aktualisieren klicken](#before-you-click-update) fort.

## Bevor Sie auf Aktualisieren klicken {#before-you-click-update}

1. **Synchronisieren Sie alle Kassen.** Öffnen Sie jede Kasse und dann in ihrem Menü **Shop-Zustand → Datenbank**. Bei **Änderungen zum Senden ausstehend** muss **0** stehen, und es darf kein [Bereich eine Entscheidung anfordern](../support/store-health.mdx#needs-attention). Alles über 0 ist noch nicht in Ihrem Shop angekommen: Lassen Sie die Kasse online und warten Sie. Offene Bestellungen sind in dieser Zahl nicht enthalten: Schließen Sie jede ab oder drücken Sie bei ihr auf **Auf Server speichern** ([Bestellung synchronisieren](../pos/cart/open-orders.mdx#sync-order) in 2.0). Beide Ansichten gelten nur für den aktuell angemeldeten Benutzer: Wiederholen Sie dies für jeden Kassierer, der die Kasse nutzt, in jeder Filiale und an jeder von ihm verwendeten Kasse. Verkäufe, offene Bestellungen oder Änderungen, die eine Kasse noch nicht an Ihren Shop gesendet hat, gehen beim Öffnen von 2.0 verloren.
2. **Sichern Sie die Website** oder bitten Sie Ihren Hosting-Anbieter um einen Wiederherstellungspunkt. Das Update verändert Ihre Bestellungen nicht, aber bei einem großen Update sollte es einen Weg zurück geben.
3. **Wählen Sie eine ruhige Stunde.** Nach dem Plugin-Update muss jede Kasse auf 2.0 umgestellt werden, bevor ihre Verkäufe wieder Ihren Shop erreichen. Ein Verkauf, dessen Zahlungsvorgang in der alten Version bereits begonnen hat, muss erneut erfasst werden.
4. **Wenn Sie WCPOS Pro verwenden, prüfen Sie, ob Ihre Lizenz aktiv ist**, unter **WP Admin → POS → Einstellungen → Lizenz**. Pro-Updates erhalten Sie nur mit einer gültigen Lizenz. Siehe [WCPOS Pro installieren](./pro-license.mdx).
5. **Informieren Sie Ihre Kassierer über Rabatte.** Wenn sie Beträge durch eine *negative Gebühr* abziehen, funktioniert das künftig nicht mehr. In 2.0 gibt es dafür **Rabatt hinzufügen**. Siehe [Was sich am ersten Tag ändert](#what-changes-on-day-one).
6. **Wenn Sie eine Kartenterminal-Erweiterung verwenden, prüfen Sie, ob es eine Version für 2.0 gibt.** Für Stripe Terminal, SumUp und Mollie Terminal gibt es sie. Sie aktualisieren die Erweiterung weiter unten direkt nach WCPOS.

## Plugin und Kassen aktualisieren {#updating}

1. **Aktualisieren Sie das Plugin.** Bei der kostenlosen Version aktualisieren Sie **WCPOS**. Mit Pro aktualisieren Sie nur **WCPOS Pro**: Es enthält das kostenlose Plugin bereits und deaktiviert die separat installierte Kopie. Ein Hinweis informiert Sie darüber; Sie können das kostenlose Plugin dann löschen.
2. **Aktualisieren Sie Ihre Kartenterminal-Erweiterung**, falls Sie eine verwenden, auf ihre Version für 2.0. Eine nicht aktualisierte Erweiterung wird weiterhin auf der Registerkarte **Legacy** im Zahlungsvorgang angezeigt, kann aber kein Lesegerät aus dem Zahlungsbereich heraus steuern.
3. **Stellen Sie alle Kassen auf 2.0 um.** Laden Sie bei einer Browser-Kasse die Seite neu: Sie lädt 2.0 aus Ihrem Shop. Aktualisieren Sie die Desktop- und Mobil-Apps wie gewohnt auf 2.0 und öffnen Sie sie anschließend. Lassen Sie jede Kasse ihre erste Synchronisierung abschließen.
4. **Prüfen Sie, ob jede Kasse auf 2.0 ist.** Tippen Sie unten im Menü auf die Version (**v 2.0.0** oder **Version 2.0.0** auf einem Smartphone). **Über WCPOS** wird geöffnet.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[-40, 0], [-40, -10], [-40, 10], [-40, 0], [162, 0]]} alt="Über WCPOS in einem Shop mit Pro: App-Version 2.0.0 und Plattform Web, darunter die Versionen von WCPOS Pro Plugin, WooCommerce und WordPress unter Server, Status Pro unter Lizenz sowie die Schaltflächen Schließen und Versionshinweise">

1. **App-Version** — der POS auf dieser Kasse. Sie muss mit 2.0 beginnen.
2. **WCPOS Pro Plugin** — das Plugin in Ihrem Shop, bei der kostenlosen Version **WCPOS Plugin**. Auch dieses muss auf 2.0 sein.
3. **WooCommerce** — 9.0 oder neuer.
4. **Status** — **Pro** oder **Kostenlos**. Wenn bei Pro hier **Kostenlos** steht, siehe [WCPOS Pro installieren](./pro-license.mdx).
5. **Versionshinweise** — die Änderungen jeder Version.

</JourneyShot>

App und Plugin müssen beide auf 2.0 sein. Stimmen die Versionen nicht überein, hält die Kasse mit einem entsprechenden Hinweis an:

- **Eine App mit 1.11 an einem Shop mit 2.0** fordert ein App-Update an. Siehe [SYNC341](../error-codes/SYNC341.mdx). Wenn sie noch nicht gesendete Verkäufe enthält, aktualisieren Sie sie noch nicht: siehe [Auf einer Kasse mit 1.11 liegen noch nicht gesendete Verkäufe](#unsent-sales).{/* pending: docs#675 */}
- **Eine App mit 2.0 an einem Shop, der noch auf 1.11 ist**, meldet **AUTH331**. Aktualisieren Sie das Plugin und stellen Sie die Verbindung anschließend erneut her. Siehe [AUTH331](../error-codes/AUTH331.mdx).

## Was sich am ersten Tag ändert {#what-changes-on-day-one}

Ihre Kassierer sehen beim ersten Öffnen des POS eine neue Kassenoberfläche. Das meiste funktioniert wie bisher; die folgenden Änderungen werden ihnen auffallen. Die vollständige Liste finden Sie unter [Neu in 2.0](./whats-new.mdx).

### Rabatte ersetzen negative Gebühren {#discounts}

Eine Gebühr kann nicht mehr negativ sein. Um einen Betrag abzuziehen, drücken Sie im Warenkorb auf **+** und wählen Sie **Rabatt hinzufügen**. Bestellungen, die bereits eine negative Gebühr enthalten, bleiben unverändert.

<details>
<summary>Rabatt hinzufügen und Gutscheine finden</summary>

1. **Kassenleiste** — die Filiale dieser Kasse und, wenn die Filiale mehrere Kassen hat, die Kasse. Siehe [Filialen, Kassen und Geräte](../stores/registers-and-devices.mdx).
2. **+** — das Hinzufügen-Menü des Warenkorbs für alles, was keine Produktkachel ist.
3. **Gebühr hinzufügen** — Gebühren können den Bestellbetrag jetzt nur noch erhöhen.
4. **Rabatt hinzufügen** — ein fester oder prozentualer Abzug vom Bestellbetrag oder ein WooCommerce-Gutscheincode auf der Registerkarte **Gutschein**. Gutscheine an der Kasse benötigen kein Pro mehr. Siehe [Warenkorbrabatte](../pos/cart/discounts.mdx).
5. **Zwischensumme** — die Beträge der Bestellung vor der Zahlung.
6. **Kasse** — öffnet den unten beschriebenen Zahlungsbereich.

### Der Zahlungsvorgang findet im Zahlungsbereich statt {#checkout}

Wenn Sie auf **Kasse** drücken, öffnet sich ein Ziffernblock neben dem Warenkorb statt der Zahlungsseite von WooCommerce. Geben Sie den vom Kunden übergebenen Betrag ein; das Rückgeld wird angezeigt. Ein Verkauf lässt sich auf Bar- und Kartenzahlungen aufteilen.

<details>

1. **Zahlungen** — die Zahlungsarten, die Ihr Shop an der Kasse akzeptiert, und die mit dieser Kasse gekoppelten Kartenlesegeräte. Siehe [Der Zahlungsbereich](../pos/checkout/payment-methods.mdx).
2. **Legacy** — Zahlungsgateways, die weiterhin ihre eigene Zahlungsseite verwenden, einschließlich noch nicht aktualisierter Terminal-Erweiterungen. Siehe [Die Registerkarte Legacy](../pos/checkout/legacy-tab.mdx).

### Ebenfalls neu am ersten Tag {#also-new}

- **Ein neues Erscheinungsbild.** Formulare und Auswahlfelder werden als Bereiche seitlich eingeblendet. Mit **Skalierung** unter **Einstellungen → Design** passen Sie die Größe des POS an Ihr Gerät an. Sie können den Warenkorb links platzieren und eigene Schnellfilter-Schaltflächen hinzufügen. Siehe [Neu: Eine neue Kassenoberfläche](./whats-new.mdx#a-new-register).
- **WooCommerce Analytics zählt eine POS-Bestellung erst, wenn sie bezahlt ist.** An der Kasse noch offene oder nur teilweise bezahlte Bestellungen zählen nicht mehr als Verkäufe. Summen, in denen sie bisher enthalten waren, fallen dadurch niedriger aus.
- **Belege enthalten den Kassennamen und die Softwareversion.** Bei einer Rückerstattung wird ein eigener Beleg mit der Überschrift **Rückerstattung** gedruckt, der den korrigierten Verkauf nennt. Benutzerdefinierte Belegvorlagen funktionieren weiterhin und zeigen die neuen Angaben nur, wenn Sie diese hinzufügen. Siehe [Belege](../receipts/index.mdx).
- **Bei Produkten mit „Nur POS“ wird die Katalogsichtbarkeit auf „Verborgen“ gesetzt**, einmalig beim Plugin-Update, damit sie nicht in Ihrem Onlineshop erscheinen.
- **Magnetstreifen-Kartenlesegeräte werden nicht mehr unterstützt.** Nehmen Sie Kartenzahlungen über ein gekoppeltes Lesegerät (Pro) oder Ihr eigenes Terminal an und erfassen Sie die Zahlung an der Kasse.

### Kassen und Kassenschublade {#registers-and-cash-drawer}

<details>
<summary>Kassen und Kassenschublade: deaktiviert, bis Sie sie einschalten</summary>

2.0 ermöglicht das Öffnen und Schließen der Kasse mit Anfangsbestand und Kassensturz, auch im kostenlosen Plugin. Am ersten Tag ändert sich nichts: Die Funktion bleibt deaktiviert, bis ein Manager unter **WP Admin → POS → Einstellungen → Allgemein** im Abschnitt **Kasse** die Option **Kasse öffnen und schließen** aktiviert. Dort wird auch der **Anfangsbestand** festgelegt. Ist die Funktion aktiv, fragt der POS vor dem ersten Verkauf nach einem Anfangsbestand. Mit **Kasse schließen** wird der Schubladeninhalt gezählt und ein nummerierter Kassenabschluss erstellt, der in der anschließenden Ansicht mit **Kassenabschluss drucken** gedruckt werden kann. Siehe [Tagesabschluss](../pos/reconciliation.mdx).

Das kostenlose Plugin hat eine Kasse, die alle Geräte gemeinsam nutzen. Weitere Kassen gibt es mit Pro. Siehe [Kassen](../settings/wp-admin/registers.mdx#one-register) und [Kasse öffnen](../pos/register/index.mdx).

</details>

## Wenn Ihr Shop noch nicht bereit ist {#if-your-store-isnt-ready-yet}

**Bleiben Sie bei WCPOS 1.11.** Es funktioniert weiterhin und erhält noch sechs Monate nach der Veröffentlichung von 2.0 Fehlerbehebungen.

1. **Deaktivieren Sie automatische Aktualisierungen** für WCPOS und WCPOS Pro. Unter **WP Admin → Plugins** hat jede Plugin-Zeile den Link **Automatische Aktualisierungen aktivieren** / **Automatische Aktualisierungen deaktivieren**. Achten Sie darauf, dass dort **Automatische Aktualisierungen aktivieren** steht: Das bedeutet, dass sie ausgeschaltet sind. So verhindern Sie, dass eine Kasse mitten in einer Schicht automatisch aktualisiert wird.
2. **Aktualisieren Sie WooCommerce auf 9.0 oder neuer**, sobald Sie bereit sind. Informationen dazu finden Sie in den Versionshinweisen von WooCommerce.
3. **Kehren Sie zu [Bevor Sie auf Aktualisieren klicken](#before-you-click-update) zurück.**
4. **Aktivieren Sie automatische Aktualisierungen wieder, sobald Sie auf 2.0 sind**, sofern Sie sie zuvor genutzt haben. Andernfalls werden spätere Fehlerbehebungen nicht automatisch installiert.

### Wenn WCPOS vor WooCommerce aktualisiert wurde {#if-wcpos-updated-first}

{/* pending: docs#675 */}
Der POS lässt sich erst öffnen, wenn WooCommerce auf 9.0 oder neuer ist. Bereits im Shop gespeicherte Bestellungen bleiben erhalten. Nicht gesendete Verkäufe bleiben nur so lange auf einer Kasse, bis sie 2.0 öffnet. Aktualisieren Sie diese Kasse daher nicht und laden Sie sie nicht neu: Befolgen Sie [Auf einer Kasse mit 1.11 liegen noch nicht gesendete Verkäufe](#unsent-sales). Aktualisieren Sie entweder jetzt WooCommerce oder [installieren Sie WCPOS 1.11 erneut](./previous-versions.mdx) und deaktivieren Sie automatische Aktualisierungen wie oben beschrieben.

## Der POS ist nach einem Plugin-Update verschwunden {#pos-gone}

Das Menü **POS** ist aus WP Admin verschwunden, und `yourdomain.com/pos` öffnet den POS nicht mehr. WCPOS 2.0 läuft nur, wenn Ihre Website die [Voraussetzungen](./installation.mdx#server-requirements) erfüllt. Andernfalls bleibt das Plugin installiert, aktiviert aber keine Funktionen. Ihre Bestellungen bleiben in WooCommerce.

1. **Prüfen Sie WooCommerce.** Unter **WP Admin → Plugins** muss WooCommerce aktiv und auf Version 9.0 oder neuer sein. Aktualisieren oder aktivieren Sie es. Wenn Sie es noch nicht aktualisieren können, siehe [Wenn WCPOS vor WooCommerce aktualisiert wurde](#if-wcpos-updated-first).
2. **Prüfen Sie PHP.** 2.0 benötigt PHP 7.4 oder neuer. Fragen Sie Ihren Hosting-Anbieter, welche Version Ihre Website verwendet.
3. **Prüfen Sie bei Pro, ob WCPOS Pro aktiv ist.** Das kostenlose Plugin **WCPOS** ist absichtlich deaktiviert: Es ist in Pro enthalten. Siehe [Plugin und Kassen aktualisieren](#updating).
4. **Achten Sie oben in WP Admin auf „Das WCPOS-Plugin konnte nicht korrekt geladen werden.“** Die Dateien des Plugins wurden nicht geladen, daher startet es nicht. Laden Sie dieselbe Version erneut herunter und laden Sie sie über die vorhandene Installation hoch, wie unter [Über die aktuelle Version hochladen](./previous-versions.mdx#install) beschrieben. Löschen Sie das Plugin nicht vorher.

Wenn auf einer Kasse noch Verkäufe von vor dem Update liegen, lesen Sie vor dem Neuladen [Auf einer Kasse mit 1.11 liegen noch nicht gesendete Verkäufe](#unsent-sales).

## Zur vorherigen Version zurückkehren {#rolling-back}

### Auf einer Kasse mit 1.11 liegen noch nicht gesendete Verkäufe {#unsent-sales}

Die Kasse zeigt einen Aktualisierungshinweis, und ihre Verkäufe sind noch nicht in Ihrem Shop angekommen. Sie bleiben auf diesem Gerät, bis es 2.0 öffnet. So senden Sie sie:

1. **Lassen Sie diese Kasse unverändert.** Aktualisieren Sie die App nicht und laden Sie bei einer Browser-Kasse die Seite nicht neu: Beides öffnet 2.0 und löscht die nicht gesendeten Verkäufe.
2. **[Installieren Sie das Plugin in Version 1.11 erneut](./previous-versions.mdx)** in Ihrem Shop.
3. **Laden Sie bei einer Browser-Kasse die Seite neu oder schließen und öffnen Sie die App erneut.** Da der Shop wieder auf 1.11 ist, verbindet sich die Kasse erneut und sendet ihre Verkäufe. Warten Sie, bis unter **Shop-Zustand → Datenbank** bei **Änderungen zum Senden ausstehend** **0** steht und kein [Bereich eine Entscheidung anfordert](../support/store-health.mdx#needs-attention). Offene Bestellungen sind in dieser Zahl nicht enthalten: Schließen Sie jede ab oder drücken Sie bei ihr auf **Auf Server speichern**. Die Verkäufe der Kasse sind jetzt im Shop.
4. **Aktualisieren Sie erneut auf 2.0**, beginnend mit [Plugin und Kassen aktualisieren](#updating).

### Zurück zu 1.11 {#back-to-1-11}

Wenn 2.0 bei Ihnen nicht funktioniert, melden Sie sich zuerst auf [Discord](https://wcpos.com/discord). Für die meisten Probleme am Tag des Upgrades gibt es eine schnellere Lösung als die Rückkehr zur alten Version.

:::warning Vor der Rückkehr synchronisieren
Bei der Rückkehr zu 1.11 startet jede Kasse mit einer leeren lokalen Datenbank. Zudem kann 1.11 keine Verkäufe senden, die eine Kasse mit 2.0 noch nicht an Ihren Shop gesendet hat. Lassen Sie zuerst jede Kasse mit 2.0 die Synchronisierung abschließen: Unter **Shop-Zustand → Datenbank** muss bei **Änderungen zum Senden ausstehend** **0** stehen. Kein [Bereich darf eine Entscheidung anfordern](../support/store-health.mdx#needs-attention), und alle offenen Bestellungen müssen synchronisiert sein ([Bestellung synchronisieren](../pos/cart/open-orders.mdx#sync-order)).
:::

**Eine Desktop- oder Mobil-App, die bereits auf 2.0 ist, kann sich nicht mit einem Plugin in Version 1.11 verbinden** (sie meldet [AUTH331](../error-codes/AUTH331.mdx)), und die App-Stores bieten keine älteren Versionen an. Nutzen Sie auf dieser Kasse den Browser-POS unter `yourdomain.com/pos`, bis Sie das Upgrade erneut durchführen.

Um zurückzukehren, [installieren Sie das Plugin in Version 1.11 erneut](./previous-versions.mdx). Browser-Kassen und Apps, die noch auf 1.11 sind, funktionieren wie bisher weiter.

Mit 2.0 erstellte Bestellungen sind normale WooCommerce-Bestellungen und bleiben erhalten. In 2.0 erfasste Kassensitzungen und Kassenabschlüsse bleiben in der Datenbank, werden in 1.11 aber nicht angezeigt.
