**WP-Admin:** HTML-Vorlagen werden unter `WP Admin → POS → Templates` bearbeitet.

Ändern Sie den Text oder das Layout eines Belegs, indem Sie eine HTML-Vorlage bearbeiten: einen wie eine Webseite aufgebauten Beleg mit `{{placeholders}}` an den Stellen für die Bestelldaten. Wenn Sie stattdessen zu einem anderen vorgefertigten Beleg wechseln möchten, lesen Sie [Beleg anpassen](./customise.mdx).

<details>
<summary>HTML oder Thermodruck?</summary>

Verwenden Sie HTML für den Browserdruck, PDFs, A4-Rechnungen und Drucker, die Webseiten drucken. Für einen Belegdrucker, der ESC/POS-Befehle verarbeitet, verwenden Sie stattdessen eine [Thermodruckvorlage](./thermal-templates.mdx). HTML ist die Engine, die wir für die meisten Filialen empfehlen. Der POS füllt HTML-Vorlagen direkt auf dem Gerät aus. Vorschau und Druck funktionieren daher auch, wenn die Verbindung zu Ihrem Shop unterbrochen ist.

</details>

## Vorlage erstellen {#write}

Beginnen Sie nicht mit einer leeren Seite: Kopieren Sie eine Vorlage aus der Galerie und bearbeiten Sie anschließend die Kopie.

1. Klicken Sie in der **Vorlagengalerie** auf der Karte, die Ihren Vorstellungen am nächsten kommt, auf **Vorlage verwenden**. Sie erhalten unter **Ihre Vorlagen** eine eigene Kopie; das Original in der Galerie bleibt unverändert.
2. Öffnen Sie Ihre Kopie. Unter **Felder** sind alle Platzhalter aufgelistet: Suchen Sie den gewünschten Platzhalter und klicken Sie auf **Einfügen**, damit Sie sich die Namen nicht merken müssen. Die **Vorschau** füllt die Vorlage während der Eingabe mit **Beispieldaten** oder einer Ihrer POS-Bestellungen aus.
3. Nehmen Sie die gewünschten Änderungen vor. Um beispielsweise Ihrer Kopie von **Standardbeleg** eine Zeile zur Rückgabe hinzuzufügen, suchen Sie `{{i18n.thank_you_purchase}}` nahe dem Ende. Das nächste `</div>` schließt die Fußzeile. Kopieren Sie diese Zeilen hinter dieses `</div>`:

   ```html
   <div style="text-align: center;">
     Returns within 30 days
     with this receipt.
   </div>
   ```

   Eingegebener Text wird genau so gedruckt, wie er eingegeben wurde, in einer Sprache. Hinterlegen Sie Stile wie hier direkt am jeweiligen Element (`style="…"`), nicht in einem `<style>` -Block: siehe [Stile können beim Drucken verloren gehen](#styling).

4. Klicken Sie auf **Aktualisieren**. Jeder mit Ihrer Kopie gedruckte Beleg zeigt nun Ihre Änderung, etwa die Rückgabezeile unter der Fußzeilennachricht.
5. Schalten Sie unter **Ihre Vorlagen** die Option **Aktiv** ein, damit der POS die Vorlage an der Kasse anbietet.

   <details>
   <summary>Diese Vorlage an der Kasse an die erste Stelle setzen</summary>

   Die Kasse listet aktive Vorlagen in der Reihenfolge unter **Ihre Vorlagen** auf und beginnt jeden Verkauf mit der ersten. Verschieben Sie Ihre Vorlage nach oben, indem Sie den Griff **≡** in ihrer Zeile ziehen oder die Schaltflächen **↑** und **↓** in der Spalte **Aktionen** verwenden. Eine Filiale mit eigener Vorlagenliste behält ihre eigene Reihenfolge. Siehe [Was Kassierer an der Kasse sehen](./customise.mdx#at-the-till).

   </details>

6. Prüfen Sie die Vorlage im POS, bevor sie an der Kasse eingesetzt wird: siehe [Im POS prüfen](#check).

### Im POS prüfen {#check}

Die Vorschau im Editor verzeiht Fehler, die der POS nicht verzeiht. Eine Vorlage ist daher erst einsatzbereit, wenn sie an der Kasse richtig aussieht.

**Für einen kurzen Blick auf das Layout** brauchen Sie keinen Verkauf: Legen Sie einen Artikel in den Warenkorb, tippen Sie neben **Kasse** auf **⋮** und dann auf **Drucken**. Die Vorlagenauswahl und die Vorschau öffnen sich für die Bestellung im Warenkorb. Eine HTML-Vorlage wird dort bereits angezeigt, bevor die Bestellung den Shop erreicht; bei der **Legacy-PHP-Vorlage** werden Sie aufgefordert, die Bestellung zuerst zu synchronisieren.

**Bevor die Vorlage an der Kasse eingesetzt wird**, prüfen Sie jeden Betrag anhand eines echten Verkaufs:

1. Erfassen Sie eine Bestellung wie bei Ihren umfangreichsten Verkäufen: mit einer rabattierten Position, einem steuerpflichtigen Produkt und einer Barzahlung mit Wechselgeld.
2. Wählen Sie auf dem Zahlungsabschlussbildschirm unter **Vorlage** Ihre Vorlage aus.
3. Prüfen Sie die Vorschau: Namen, Preise, Rabatt, Steuerzeilen, gegebenen Betrag und Wechselgeld.
4. Drucken Sie den Beleg so, wie es später an der Kasse geschieht, mit **Beleg drucken** oder **PDF herunterladen**, und prüfen Sie auch den Ausdruck oder die Datei. [Stile können beim Drucken verloren gehen](#styling).

Der Zahlungsabschlussbildschirm mit ausgewähltem **Standardbeleg** aus der Galerie:

Jeder Klick auf **Vorlage verwenden** erstellt eine neue Kopie. Erstellen Sie zum Experimentieren zwei Kopien (*Beleg v1*, *Beleg v2*) und wechseln Sie an der Kasse zwischen ihnen.
:::

## Syntax {#syntax}

Die Platzhalter verwenden [Mustache](https://mustache.github.io/mustache.5.html), eine kleine Vorlagensprache ohne eigene Logik. Sie kann drei Dinge: einen Wert einsetzen, einen Block für jeden Eintrag einer Liste wiederholen und einen Block ein- oder ausblenden.

### Variablen {#variables}

Setzen Sie den Namen eines Feldes in doppelte geschweifte Klammern:

```html
<h1>{{store.name}}</h1>
<p>Order #{{order.number}}</p>
<p>Total: {{totals.total_display}}</p>
```

Ein Feld mit der Endung `_display` enthält den bereits für Ihren Shop formatierten Geldbetrag (`$12.50` statt `12.5`). Die [Belegdatenreferenz](./receipt-data.mdx) führt alle Felder auf.

### Maskierung {#escaping}

`{{field}}` gibt den Wert als reinen Text aus: Ein `<` in einem Produktnamen erscheint als `<`, niemals als HTML. Drei Klammern, `{{{field}}}`, geben ihn als HTML aus. Dieses HTML wird vor dem Drucken dennoch bereinigt (siehe [Formatierung](#styling)), sodass ein Feld niemals ein Skript hinzufügen kann.

### Abschnitte (Schleifen und Bedingungen) {#sections-loops-and-conditionals}

`{{#section}}...{{/section}}` wiederholt den Block für jeden Eintrag einer Liste oder zeigt ihn einmal an, wenn der Wert vorhanden ist.

<details>
<summary>Beispiel: eine Zeile pro Position</summary>

```html
{{#lines}}
<div class="line-item">
  <span>{{name}} × {{qty}}</span>
  <span>{{line_total_display}}</span>
</div>
{{/lines}}
```

</details>

Innerhalb eines Abschnitts wird ein Name zuerst beim aktuellen Eintrag gesucht, dann außerhalb davon. Deshalb funktioniert `{{i18n.tendered}}` innerhalb von `{{#payments}}`. Bei einer Liste mit reinem Text wie `store.address_lines` steht `{{.}}` für den aktuellen Eintrag selbst.

### Invertierte Abschnitte {#inverted-sections}

`{{^section}}...{{/section}}` zeigt den Block an, wenn der Wert fehlt, leer, `false` oder `0` ist.

<details>
<summary>Beispiel: Kundenname oder „Gastbestellung“</summary>

```html
{{#customer.id}}
  <p>Customer: {{customer.name}}</p>
{{/customer.id}}
{{^customer.id}}
  <p>Guest checkout</p>
{{/customer.id}}
```

</details>

### Lokalisierte Beschriftungen {#localised-labels}

`{{i18n.key}}` gibt eine Beschriftung in der Sprache Ihres Shops aus, sodass eine Vorlage in jeder Filiale funktioniert.

<details>
<summary>Beispiel: eine übersetzte Beschriftung für die Zwischensumme</summary>

```html
<th>{{i18n.subtotal}}</th>
<td>{{totals.subtotal_display}}</td>
```

</details>

Die Beschriftungen richten sich nach der WordPress-Sprache des Shops, nicht nach der Sprache, die der Kassierer in der App gewählt hat. Alle Schlüssel finden Sie in der [i18n-Referenz](./receipt-data.mdx#i18n).

<details>
<summary>Was der POS nicht unterstützt</summary>

- **Partials** (`{{> name}}`) geben im POS nichts aus. Fassen Sie alles in einer Vorlage zusammen.
- **Lambdas** (Funktionen anstelle von Werten) sind nicht möglich: Die Belegdaten enthalten nur einfache Werte.
- **Kommentare** (`{{! a note }}`) und geänderte Trennzeichen (`{{=<% %>=}}`) funktionieren wie in Mustache üblich.

</details>

## Häufige Anwendungsfälle {#common-patterns}

### Kopfbereich mit Filialdaten {#store-header}

`store.address_lines` enthält die bereits in Zeilen aufgeteilte Adresse. Durchlaufen Sie diese mit einer Schleife, statt die Adressfelder selbst zusammenzufügen.

<details>
<summary>Beispiel: Logo, Name, Adresse, Telefon und Steuer-IDs</summary>

```html
<div style="text-align: center;">
  {{#store.logo}}<img src="{{store.logo}}" alt="{{store.name}}" style="max-width: 200px;" />{{/store.logo}}
  <h1 style="margin: 8px 0;">{{store.name}}</h1>
  {{#store.address_lines}}<div>{{.}}</div>{{/store.address_lines}}
  {{#store.phone}}<div>{{store.phone}}</div>{{/store.phone}}
  {{#store.tax_ids}}<div>{{label}}: {{value}}</div>{{/store.tax_ids}}
</div>
```

</details>

Das Logo stammt aus den Einstellungen der Filiale, nicht aus der Vorlage. Siehe [Beleg anpassen](./customise.mdx).

### Positionen mit Rabatten {#line-items-with-discounts}

`discounts` enthält den Rabatt einer Position als positive Zahl oder `0`, wenn kein Rabatt vorliegt. Mustache behandelt `0` als leer, sodass `{{#discounts}}...{{/discounts}}` den Block nur bei einer rabattierten Position anzeigt.

<details>
<summary>Beispiel: jede Position mit ihrem Rabatt</summary>

```html
{{#lines}}
<div class="line-item" style="display: flex; justify-content: space-between;">
  <div>
    <div>{{name}} × {{qty}}</div>
    {{#discounts}}
      <div style="font-size: 0.9em;">
        <s>{{line_subtotal_display}}</s> −{{discounts_display}}
      </div>
    {{/discounts}}
  </div>
  <div>{{line_total_display}}</div>
</div>
{{/lines}}
```

</details>

`line_subtotal_display` ist der Positionsbetrag vor Rabatten, `line_total_display` der Betrag danach. Zu Angebotspreisen und Ersparnissen siehe [Regulären Preis und Ersparnisse anzeigen](./receipt-data.mdx#displaying-regular-price-and-savings).

### Steuerübersicht {#tax-summary}

`tax_summary` enthält eine Zeile pro Steuersatz. `rate` ist ein Prozentsatz, zum Beispiel `10`. Er kann leer sein (bei einem Satz von 0% oder einem offline gedruckten Beleg). Die Bedingung `{{#rate}}` verhindert daher, dass ein bloßes `(%)` auf dem Beleg erscheint.

<details>
<summary>Beispiel: eine Zeile pro Steuersatz</summary>

```html
{{#tax_summary}}
<div class="tax-line" style="display: flex; justify-content: space-between;">
  <span>{{label}}{{#rate}} ({{rate}}%){{/rate}}</span>
  <span>{{tax_amount_display}}</span>
</div>
{{/tax_summary}}
```

</details>


### Zahlungsdetails {#payment-details}

Wird der Beleg gedruckt, bevor die Bestellung Ihren Shop erreicht, etwa im Offlinebetrieb? Dann fehlen darauf der erhaltene Barbetrag und das Wechselgeld. Drucken Sie ihn erneut, sobald die Bestellung synchronisiert ist. Der Zahlungsabschlussbildschirm zeigt das Wechselgeld in jedem Fall an.

<details>
<summary>Der Grund und ein Beispiel mit gegebenem Betrag und Wechselgeld</summary>

Das **Wechselgeld** auf dem Zahlungsabschlussbildschirm berechnet der POS selbst. Die Belegfelder `tendered` und `change` stammen aus Ihrem Shop. Bis zur Synchronisierung der Bestellung sind sie deshalb leer und der Block `{{#tendered}}` wird übersprungen.

```html
{{#payments}}
<div class="payment" style="display: flex; justify-content: space-between;">
  <span>{{method_title}}</span>
  <span>{{amount_display}}</span>
</div>
{{#tendered}}
  <div style="display: flex; justify-content: space-between;">
    <span>{{i18n.tendered}}</span><span>{{tendered_display}}</span>
  </div>
  <div style="display: flex; justify-content: space-between;">
    <span>{{i18n.change}}</span><span>{{change_display}}</span>
  </div>
{{/tendered}}
{{/payments}}
```

</details>


### Barcodes und QR-Codes {#barcodes-and-qr-codes}

Verwenden Sie dieselben Elemente wie bei [Thermodruckvorlagen](./thermal-templates.mdx). Der Wert steht innerhalb des Elements; der POS zeichnet an dessen Stelle den Code.

<details>
<summary>Beispiel: Code 128, EAN-13 und ein QR-Code</summary>

```html
<!-- Code 128 barcode of the order number -->
<barcode type="code128" height="40">{{order.number}}</barcode>

<!-- EAN-13 of each product, when your SKUs are EAN numbers -->
{{#lines}}<barcode type="ean13" height="30">{{sku}}</barcode>{{/lines}}

<!-- QR code: size sets how big, 4 by default -->
{{#order.payment_url}}<qrcode size="4">{{order.payment_url}}</qrcode>{{/order.payment_url}}
```

</details>

- **Setzen Sie immer `type`.** Ohne diese Angabe zeichnet der POS Code 128 und das PDF des Shops einen QR-Code.
- **Verwenden Sie für Bestellnummern Code 128.** Verwenden Sie EAN-13 nur, wenn die SKU ein gültiger EAN-Produktcode ist.

<details>
<summary>Barcode-Typen, QR-Größen und Platzhalter für Typen</summary>

- **Wählen Sie aus diesen Typen:** `code128`, `code39`, `code93`, `ean13`, `ean8`, `upca`, `upce`, `codabar`, `itf` und `qrcode`. Der POS kann weitere [bwip-js-Typen](https://github.com/metafloor/bwip-js/wiki/Supported-Barcode-Types) wie `pdf417` zeichnen, doch die Editorvorschau und das PDF stellen diese als Code 128 dar.
- **Verwenden Sie `<qrcode size="…">` für QR-Codes.** `<barcode type="qrcode">` (oder `qr`) erzeugt ebenfalls einen QR-Code, doch der POS bestimmt dessen Größe anhand von `height` und das PDF anhand von `size`, sodass die beiden nicht übereinstimmen.
- **`type` kann ein Platzhalter sein**, da die Platzhalter ausgefüllt werden, bevor die Codes gezeichnet werden:

  ```html
  <barcode type="{{presentation_hints.order_barcode_type}}">{{order.number}}</barcode>
  ```

</details>

Wenn der Wert nicht zum Typ passt, zeigt der POS einen Block mit **Barcode-Fehler** oder **QR-Code-Fehler** an, der den Wert enthält. Korrigieren Sie den Wert oder wählen Sie einen passenden Typ. Das PDF druckt stattdessen nur den Wert.

## Formatierung {#styling}

Formatieren Sie jedes Element **inline** mit einem `style="…"`-Attribut, wie in den Galerievorlagen:

```html
<div style="font-family: monospace; font-size: 12px; max-width: 300px; margin: 0 auto;">
  <div style="text-align: center; margin-bottom: 16px;">
    <strong style="font-size: 16px;">{{store.name}}</strong>
  </div>
  <div style="display: flex; justify-content: space-between; font-weight: 700; border-top: 1px solid black; padding-top: 8px;">
    <span>{{i18n.total}}</span>
    <span>{{totals.total_display}}</span>
  </div>
</div>
```

:::warning Stile können beim Drucken verloren gehen
Ein `<style>` -Block sieht in der Vorschau des Vorlageneditors richtig aus, weil der Editor Ihr HTML so anzeigt, wie Sie es geschrieben haben. Das PDF des Shops und die mobilen Apps entfernen `<style>` -Blöcke vor dem Drucken, sodass derselbe Beleg dort ohne Formatierung ausgegeben wird. Hinterlegen Sie alle Stile inline.
:::

<details>
<summary>Welches HTML wird entfernt?</summary>

Der Beleg wird vor dem Drucken bereinigt, sodass eine Vorlage niemals Code ausführen kann. Skripte sowie `<link>` - und `<meta>` -Tags und `on…` -Attribute werden bei jedem Druckverfahren entfernt. Das PDF des Shops entfernt `<style>` -Blöcke, `<head>` und die anderen Tags auf Dokumentebene; die mobilen Apps entfernen ebenfalls `<style>` -Blöcke.

</details>

:::tip Für Schwarz-Weiß-Druck gestalten
Belege werden in der Regel auf Schwarz-Weiß-Thermo- oder Laserdruckern gedruckt. Verwenden Sie **Schriftstärke, Weißraum, Schriftgröße und horizontale Linien** statt farbiger Flächen, um Inhalte zu gliedern. Farbige Hintergründe und grauer Text verschwinden entweder oder werden als unsaubere Halbtöne gedruckt.
:::

:::tip Thermopapier-Optik ohne Thermodrucker?
Klicken Sie in der Galerie auf der Karte **Schmaler Beleg** auf **Vorlage verwenden**. Das Layout verwendet eine nichtproportionale Schrift und ist 72 mm breit. Es wird aus dem Browser, auf Druckern für Webseiten (Sunmi- und iMin-Geräte) und auf Standardpapier sauber gedruckt. Verwenden Sie für einen reinen ESC/POS-Drucker stattdessen einen **Einfachen Thermobeleg** (58mm oder 80mm).
:::

## Bewährte Vorgehensweisen {#best-practices}

- **Verwenden Sie `_display`-Felder** für Geldbeträge: Sie enthalten das Währungsformat Ihres Shops.
- **Verwenden Sie `{{i18n.*}}`-Beschriftungen** statt eingegebenem Text, damit die Vorlage in der Sprache jedes Shops funktioniert.
- **Umschließen Sie optionale Felder mit Abschnitten**, `{{#field}}...{{/field}}`, damit nichts gedruckt wird, wenn sie leer sind.
- **Beginnen Sie mit einer Galerievorlage** statt mit einer leeren Seite.
- **Prüfen Sie die Vorlage im POS** anhand einer echten Bestellung mit Rabatt, Steuerzeile und Barzahlung, bevor sie an der Kasse eingesetzt wird.

## Wenn etwas schiefgeht {#goes-wrong}

**Stile werden im Editor angezeigt, aber nicht auf dem Beleg.** Hinterlegen Sie sie inline. Siehe [Stile können beim Drucken verloren gehen](#styling).

**Ein Feld gibt nichts aus.** Vergleichen Sie seinen Namen mit der [Belegdatenreferenz](./receipt-data.mdx); ein falsch geschriebenes oder unbekanntes Feld bleibt ohne Fehlermeldung leer. Innerhalb eines Abschnitts wird der Name zuerst beim aktuellen Eintrag gesucht.

**Der Beleg zeigt einen Block mit Barcode-Fehler an.** Der Wert passt nicht zum Barcode-Typ. Siehe [Barcodes und QR-Codes](#barcodes-and-qr-codes).

**Gegebener Betrag und Wechselgeld fehlen auf dem Beleg.** Er wurde offline gedruckt, bevor die Bestellung Ihren Shop erreicht hat; der Zahlungsabschlussbildschirm zeigte das Wechselgeld dennoch an. Drucken Sie den Beleg nach der Synchronisierung der Bestellung erneut. Siehe [Offlinemodus](../getting-started/offline.mdx).

**Die Vorlage fehlt in der Vorlagenliste an der Kasse.** Sie ist nicht **Aktiv**, oder eine Filiale hat ihre eigene Vorlagenliste. Siehe [Beleg anpassen](./customise.mdx#per-store-assignments).

**Die Editorvorschau meldet „Fehler beim Rendern der Vorlage“.** Ein Abschnitt ist nicht geschlossen, oder ein schließendes Tag passt nicht zum öffnenden. Jedes `{{#x}}` und `{{^x}}` benötigt ein eigenes `{{/x}}`.
