Sie können den Verkaufspreis an zwei Stellen reduzieren. Tippen Sie auf den Preis eines Artikels, um nur diesen Artikel günstiger anzubieten. Wählen Sie im Hinzufügen-Menü **Rabatt hinzufügen**, um die gesamte Bestellung um einen festen Betrag, einen Prozentsatz oder mithilfe eines Gutscheins zu reduzieren.

## Einen einzelnen Artikel rabattieren {#quick-discounts}

Tippen Sie auf den Preis einer Position. Darunter öffnet sich ein Ziffernfeld mit Ihren Schnellrabatt-Tasten am oberen Rand.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[-120, 0], [-88, 0], [-88, -24], [65, 0], [-24, 0]]} alt="Das geöffnete Preis-Ziffernfeld einer Position für $45.00 mit gedrückter Taste −10%: der neue Preis $40.50 mit $45.00 −10% darüber, die drei Schnellrabatt-Tasten, die Zifferntasten, die Löschen-Taste und die Fertig-Taste">

1. **Neuer Preis** — was der Artikel kosten wird und wie sich dieser Betrag aus dem vorherigen Preis ergibt.
2. **Schnellrabatt-Tasten** — jede zieht ihren Prozentsatz vom Preis der Position ab. Die falsche Taste gedrückt? Drücken Sie vor **Fertig** eine andere; sie ersetzt die erste Auswahl. Die aktive Taste ist hervorgehoben. Sie legen die Tasten selbst fest; siehe [Schnellrabatt-Tasten festlegen](#quick-discount-keys).
3. **Ziffern** — geben Sie stattdessen einen neuen Preis ein.
4. **Löschen** — entfernt die letzte Ziffer.
5. **Fertig** — übernimmt den neuen Preis. Tippen Sie außerhalb des Ziffernfelds, hat dies denselben Effekt.

</JourneyShot>

Wenn Sie **Fertig** drücken, wird die Positionssumme auf Menge × neuer Preis aktualisiert.

Eine Schnellrabatt-Taste geht vom Preis aus, den die Position beim Öffnen des Ziffernfelds hatte. Um weitere 10% abzuziehen, drücken Sie **Fertig**, öffnen das Ziffernfeld erneut und drücken **−10%**.

<details>
<summary>Beispiel: zwei Tasten bei einem Artikel für $45.00</summary>

**−10%** zeigt $40.50 an. Drücken Sie stattdessen **−5%**, werden $42.75 angezeigt. Drücken Sie erneut **−10%** und dann **Fertig**: Der Preis der Position beträgt nun $40.50. Öffnen Sie das Ziffernfeld erneut und drücken Sie **−10%**: Aus $40.50 werden $36.45.

</details>

### Einen neuen Preis eingeben {#line-item-discounts}

Für eine Preisanpassung an ein Konkurrenzangebot, einen Mitarbeiterpreis oder einen anderen Sonderfall geben Sie den Preis ein, den der Kunde bezahlt, und drücken **Fertig**. Mit einer Tastatur geben Sie den Preis ein und drücken **Enter**.

Der Preis wird für jede Position einzeln festgelegt. Um drei verschiedene Artikel um 10% zu reduzieren, ändern Sie jede Position einzeln oder rabattieren Sie die gesamte Bestellung über [Rabatt hinzufügen](#order-level-discounts). Weitere Änderungsmöglichkeiten für Positionen finden Sie unter [Positionen](line-items.mdx#price).

## Die gesamte Bestellung rabattieren {#order-level-discounts}

Drücken Sie oben im Warenkorb auf **+** und wählen Sie **Rabatt hinzufügen**. Der Dialog öffnet sich auf **Schnellrabatt**. Geben Sie den Betrag ein, wählen Sie **$** oder **%** und drücken Sie dann **Rabatt hinzufügen**.

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[0, 0], [0, 0], [0, 0], [12, 46], [50, -52]]} alt="Der Dialog Rabatt hinzufügen auf dem Tab Schnellrabatt: die Tabs Schnellrabatt und Gutschein, der Betrag 10, der auf Prozent eingestellte Dollar-Prozent-Schalter und die Schaltfläche Rabatt hinzufügen, neben einem Warenkorb mit der Aim Analog Watch für $45.00">

1. **Schnellrabatt** — ein fester Betrag oder ein Prozentsatz, der von dieser Bestellung abgezogen wird.
2. **Gutschein** — stattdessen einer der Gutscheine Ihres Shops. Siehe [Einen Gutschein anwenden](#coupon).
3. **Betrag** — tippen Sie darauf und geben Sie den Wert über das Ziffernfeld ein.
4. **$ oder %** — ein fester Rabattbetrag oder ein Prozentsatz der Bestellung.
5. **Rabatt hinzufügen** — wendet den Rabatt auf die Bestellung an.

</JourneyShot>

Der Rabatt erscheint in der Summenübersicht der Bestellung. Die Positionssummen werden entsprechend angepasst.

<JourneyShot manifest={manifest} device="tablet" step={5} offsets={[[12, 46], [100, 0], [50, 0], [0, 0]]} alt="Der Warenkorb nach einem Rabatt von 10% auf eine Uhr für $45.00: die durchgestrichene Positionssumme $45.00 mit $40.50 darunter, die Zwischensumme $45.00, eine Zeile Rabatt (10%) mit einem Abzug von $4.50 und einer Schaltfläche zum Entfernen sowie Kasse $40.50">

1. **Positionssumme** — der durchgestrichene Preis vor dem Rabatt und der Preis, den der Kunde jetzt bezahlt.
2. **Zwischensumme** — der Bestellbetrag vor dem Rabatt.
3. **Rabatt (10%)** — der Rabatt und der abgezogene Betrag. **Rabatt** ohne weitere Angabe steht für einen festen Betrag. Drücken Sie **✕**, um ihn zu entfernen.
4. **Kasse** — der neue Gesamtbetrag.

</JourneyShot>

Ein fester Betrag wird im Verhältnis zu den Preisen auf die Artikel verteilt. Ein prozentualer Rabatt wird von jedem Artikel abgezogen. Sie können einer Bestellung mehrere Rabatte hinzufügen; jeder erscheint in einer eigenen Zeile.

**Rabatt hinzufügen** funktioniert offline. Die Steuer wird auf Grundlage des reduzierten Preises berechnet. Dabei wird kein Gutschein in Ihrem Shop erstellt.

### Einen Rabatt entfernen {#remove-discount}

Drücken Sie in der Summenübersicht auf **✕** in der Rabattzeile. Die Positionssummen werden zurückgesetzt und die Meldung **Rabatt entfernt** erscheint. Preise, die Sie an einzelnen Positionen geändert haben, bleiben erhalten.

## Einen Gutschein anwenden {#coupon}

Wechseln Sie unter **Rabatt hinzufügen** zu **Gutschein**. Dies funktioniert auch mit dem kostenlosen Plugin.

<JourneyShot manifest={manifest} device="tablet" step={6} offsets={[[-40, 0], [10, 46], [24, -52]]} alt="Der Dialog Rabatt hinzufügen auf dem Tab Gutschein: das Feld Gutschein auswählen, die Schaltfläche Neuer Gutschein daneben und die Schaltfläche Anwenden, neben dem Warenkorb mit der Uhr für $40.50 nach Rabatt (10%)">

1. **Gutschein auswählen** — geben Sie einen Teil des Codes ein, um den Gutschein zu finden.
2. **Neuer Gutschein** (WCPOS Pro) — erstellen Sie direkt einen Gutschein. Siehe [Einen Gutschein an der Kasse erstellen](#new-coupon).
3. **Anwenden** — prüft die Gutscheinbedingungen und wendet den Gutschein auf die Bestellung an.

</JourneyShot>

Kann ein Gutschein nicht auf diese Bestellung angewendet werden, wird der Grund angezeigt. Erläuterungen zu den einzelnen Meldungen, zum Entfernen eines Gutscheins und zur Offline-Nutzung finden Sie unter [Gutscheine anwenden](../../coupons/applying-coupons.mdx).

## Einen Gutschein an der Kasse erstellen {#new-coupon}

:::info Pro-Funktion
Zum Erstellen eines Gutscheins an der Kasse benötigen Sie [WCPOS Pro](../../getting-started/pro-license.mdx). Beim kostenlosen Plugin zeigt **Neuer Gutschein** den Hinweis **Upgrade auf Pro** an.
:::

1. Drücken Sie auf dem Tab **Gutschein** auf **Neuer Gutschein**.
2. Geben Sie einen Code ein oder drücken Sie **Generieren**.
3. Wählen Sie die Rabattart und geben Sie die Höhe des Rabatts ein.
4. Legen Sie unter **Läuft ab** das Ablaufdatum sowie alle weiteren erforderlichen Gutscheinbedingungen fest.
5. Drücken Sie **Gutschein hinzufügen**. Der Gutschein wird zuerst in Ihrem Shop gespeichert und anschließend auf diesen Verkauf angewendet. Die Meldung **… gespeichert und auf diesen Verkauf angewendet** erscheint.

<JourneyShot manifest={manifest} device="tablet" step={7} offsets={[[-40, 0], [22, -40], [-40, 0], [100, 0], [-60, 0], [0, 0], [50, -52]]} alt="Das Formular Gutschein hinzufügen mit dem eingegebenen Code SPRING10: der Link Generieren neben dem Code, die Rabattart Prozentual, die Ablaufoptionen, der Schalter Einmalige Verwendung, die Schaltflächen für weitere Gutscheinbedingungen beginnend mit Mindestbestellwert und die Schaltfläche Gutschein hinzufügen, neben demselben Warenkorb">

1. **Code** — der Code, den Kunden verwenden. Dies ist das einzige Pflichtfeld.
2. **Generieren** — erstellt einen Code für Sie.
3. **Rabatt** — ein Prozentsatz, ein fester Rabatt auf die Bestellung oder auf die Produkte sowie die jeweilige Höhe.
4. **Läuft ab** — wie lange der Gutschein gültig ist.
5. **Einmalige Verwendung** — nach einmaliger Nutzung ist der Gutschein nicht mehr gültig.
6. **Weitere Bedingungen** — **Mindestbestellwert**, **Nutzungen insgesamt**, **Nicht kombinierbar** und die übrigen Optionen fügen jeweils eine Gutscheinbedingung von WooCommerce hinzu.
7. **Gutschein hinzufügen** — speichert den Gutschein in Ihrem Shop und wendet ihn anschließend auf diesen Verkauf an.

</JourneyShot>

Es handelt sich um einen echten WooCommerce-Gutschein. Er steht daher beim nächsten Verkauf, unter **WP Admin → Marketing → Gutscheine** und in Berichten zur Verfügung. Wenn Sie Gutscheine stattdessen auf der Gutscheinseite erstellen möchten, siehe [Gutscheine erstellen](../../coupons/index.mdx#creating-coupons).

## Schnellrabatt-Tasten festlegen {#quick-discount-keys}

Die Tasten werden auf jedem Gerät separat festgelegt. Drücken Sie oben im Warenkorb auf die Schaltfläche mit den Schiebereglern, um die **Warenkorb-Einstellungen** zu öffnen. **Schnellrabatte** zeigt die Tasten so an, wie der Kassierer sie auf dem Preis-Ziffernfeld sieht. Auf einem neuen Gerät sind 5%, 10% und 15% voreingestellt.

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[0, 0], [0, 0], [0, 0], [-34, 0]]} alt="Die Warenkorb-Einstellungen mit der Zeile Schnellrabatte: drei Tasten mit 5%, 10% und 15%, dargestellt wie auf dem Preis-Ziffernfeld, sowie unter Spalten der aktivierte Schalter Menge mit deaktiviertem Schalter Aufteilen">

1. **Erste Taste** — tippen Sie darauf und geben Sie einen Prozentsatz bis 100 ein, etwa 5 oder 12.5.
2. **Zweite Taste** — ebenso.
3. **Dritte Taste** — ebenso. Sie können bis zu drei Tasten festlegen.
4. **Aufteilen** — aktivieren Sie diese Option, damit **Aufteilen** unter der Menge einer Position erscheint. Siehe [Unterschiedliche Preise für dasselbe Produkt](#split).

</JourneyShot>

Um eine Taste zu entfernen, geben Sie für sie 0 ein. Die verbleibenden Tasten füllen dann die gesamte Zeile aus. Ohne Schnellrabatt-Tasten zeigt das Preis-Ziffernfeld nur die Ziffern. Es gibt keine Tasten für feste Beträge. Um einen festen Betrag abzuziehen, geben Sie den neuen Preis ein oder verwenden Sie [Rabatt hinzufügen](#order-level-discounts).

## Unterschiedliche Preise für dasselbe Produkt {#split}

Ein Kunde kauft drei Exemplare eines Produkts und erhält eines davon günstiger. Aktivieren Sie in den [Warenkorb-Einstellungen](index.mdx#columns) unter **Spalten → Menge** die Option **Aufteilen**. Bei einer Position mit mehr als einem Artikel erscheint dann **Aufteilen** unter der Menge.

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[0, 36], [-38, 0], [12, 28]]} alt="Eine Warenkorbposition mit drei Aim Analog Watches zu je $45.00, insgesamt $135.00, mit Aufteilen unter der Menge">

1. **Aufteilen** — erstellt aus der Position eine eigene Position pro Artikel.
2. **Preis** — jede neue Position behält diesen Preis, bis Sie ihn ändern.
3. **Positionssumme** — alle drei zusammen. Nach **Aufteilen** zeigt jede neue Position ihre eigene Summe an.

</JourneyShot>

Drücken Sie **Aufteilen**. Aus der Position wird eine eigene Position pro Artikel, jeweils zum selben Preis. Senken Sie den Preis der Positionen, die Sie rabattieren möchten. Eine Menge wie 2.5 wird in zwei Positionen mit der Menge eins und eine Position mit 0.5 aufgeteilt. Siehe [Positionen aufteilen](line-items.mdx#splitting-line-items).

## Wenn etwas schiefgeht {#goes-wrong}

- **Sie haben die Preiseingabe versehentlich geöffnet.** Drücken Sie die hervorgehobene Taste erneut oder so oft **Löschen**, bis das Feld leer ist, und dann **Fertig**: Der Preis bleibt unverändert. Auf einer Tastatur drücken Sie **Escape**.
- **Sie haben für eine Position den falschen Preis festgelegt.** Tippen Sie erneut auf den Preis und geben Sie den richtigen ein. Alternativ entfernen Sie die Position und fügen das Produkt erneut hinzu, um wieder vom Shoppreis auszugehen.
- **Geben Sie einen Betrag größer als null ein** oder **Geben Sie einen Prozentsatz über 0 und bis 100 ein** — der Betrag unter **Rabatt hinzufügen** ist leer oder liegt außerhalb des zulässigen Bereichs.
- **… ist bereits auf die Bestellung angewendet und kann nicht mit anderen Gutscheinen kombiniert werden.** — die Bestellung enthält einen Gutschein mit der Einstellung **Nur einzeln anwendbar**. Entfernen Sie ihn zuerst oder verzichten Sie auf den Rabatt.
- **Neuer Gutschein ist ausgegraut** — der Tooltip nennt den Grund: **Upgrade auf Pro**, fehlende Berechtigung (ein Administrator erteilt sie unter **WP Admin → POS → Einstellungen → Zugriff**) oder **Gutscheine werden erstellt, wenn der Shop erreichbar ist**. Vorhandene Gutscheine Ihrer Filiale können Sie weiterhin anwenden.
- **… gespeichert, aber nicht angewendet** — der Gutschein ist in Ihrem Shop gespeichert, seine Bedingungen passen jedoch nicht zu dieser Bestellung. Prüfen Sie die Bedingungen oder wählen Sie ihn erneut unter **Gutschein auswählen**, sobald die Bestellung die Bedingungen erfüllt.
- **Eine Gebühr kann nicht negativ sein. Verwenden Sie stattdessen Rabatt hinzufügen.** — im POS lässt sich kein Betrag über eine negative Gebühr abziehen. Verwenden Sie [Rabatt hinzufügen](#order-level-discounts). Informationen zu Gebühren, einschließlich **Betrag enthält Steuer**, finden Sie unter [Gebühren](index.mdx#fees).

## POS-Rabatte und WooCommerce-Gutscheine im Vergleich {#pos-discounts-vs-woocommerce-coupons}

**Ein Positionspreis** (per Schnellrabatt-Taste oder Preiseingabe) — gilt für eine Position und wird vom Kassierer festgelegt. Keine Bedingungen. Ideal für die Anpassung an ein Konkurrenzangebot, einen Mitarbeiterpreis oder einen beschädigten Artikel.

**Rabatt hinzufügen** — gilt für die gesamte Bestellung und wird vom Kassierer festgelegt. Hat keine eigenen Bedingungen, kann aber nicht mit einem Gutschein kombiniert werden, bei dem **Nur einzeln anwendbar** aktiviert ist. Ideal für einen einmaligen Rabatt als festen Betrag oder Prozentsatz.

**Ein WooCommerce-Gutschein** — gilt im Rahmen seiner Bedingungen: Nutzungsbeschränkungen, Produkte, Mindestbestellwert, Ablaufdatum, Kunden-E-Mail-Adresse. Er wird in Ihrem Shop eingerichtet (siehe [Gutscheine erstellen](../../coupons/index.mdx#creating-coupons)) oder mit Pro an der Kasse. Ideal für Aktionen, die Sie begrenzen und in Berichten auswerten möchten.

## Bekannte Einschränkungen {#known-limitations}

- **Keine automatischen Rabattregeln.** Der POS setzt Aktionen wie „2 kaufen, 1 gratis erhalten“ nicht selbstständig um. Verwenden Sie WooCommerce-Gutscheine für Aktionen mit festen Bedingungen.
- **Schnellrabatt-Tasten unterstützen nur Prozentsätze.** Um einen festen Betrag abzuziehen, geben Sie den neuen Preis ein oder verwenden Sie **Rabatt hinzufügen** mit **$**.

## Wie Rabatte erfasst werden {#how-discounts-are-recorded}

An Ihrer Arbeit an der Kasse ändert sich dadurch nichts. Dieser Abschnitt erklärt, was Berichte und Belege anzeigen und warum ältere Bestellungen anders aussehen können. Die vollständigen Hintergründe, einschließlich der Speicherung von Preisen, finden Sie in der [Referenz zu POS-Rabatten](../../reference/pos-discounts.mdx).

### Warum Preisänderungen und Gutscheine unterschiedlich erfasst werden {#why-tracked-differently}

Ein Preis, der per Schnellrabatt-Taste oder direkter Eingabe festgelegt wird, wird so erfasst wie ein Angebotspreis in WooCommerce: Der Artikel wird zu dem vom Kassierer festgelegten Preis verkauft. Daher bleibt die Summe unter **Rabatt** bei null, Gutscheine werden auf Grundlage des reduzierten Preises berechnet und Gutscheine mit **Angebotsprodukte ausschließen** überspringen Artikel, deren Preis gesenkt wurde.

**Rabatt hinzufügen** wird als Gutscheinposition erfasst und ein WooCommerce-Gutschein als solcher. Beide fließen daher in die Summe unter **Rabatt** ein.

<details>
<summary>Wie WooCommerce Gutscheine und Angebotspreise erfasst</summary>

WooCommerce kennt von Haus aus genau eine Form des Rabatts: den **Gutschein**. Ein Gutschein gehört zur Bestellung. Er wird in einem eigenen Feld erfasst, in Berichten in der Spalte **Rabatt** gezählt und hat eigene Bedingungen wie Nutzungsbeschränkungen und Ablaufdaten.

Ein **Angebotspreis** ist für WooCommerce kein Rabatt. Er ist schlicht der aktuelle Produktpreis: Wird ein Artikel im Angebot verkauft, erfasst die Bestellung nur den gezahlten Preis. Berichte zählen ihn als gewöhnlichen Umsatz.

Auf Belegen erwarten Kunden eine Angabe ihrer Ersparnis. Deshalb erfasst WCPOS für jede Position neben dem neuen Preis auch den regulären Preis. Ein Beleg kann so Ersparnisse durch Angebotspreise und Gutscheinrabatte getrennt ausweisen, ohne etwas doppelt zu zählen und ohne die Summen oder Berichte von WooCommerce zu verändern.

</details>

### Wie POS-Preisänderungen mit Gutscheinen zusammenwirken {#how-pos-price-changes-interact-with-coupons}

Angenommen, ein Kassierer senkt den Preis eines Artikels von $18 auf $16 und wendet dann einen Gutschein an. Der Gutschein wird auf Grundlage von **$16** berechnet, nicht von $18. So erhält der Kunde nicht zweimal einen Rabatt auf den ursprünglichen Preis.

- Ein Artikel, dessen Preis an der Kasse gesenkt wurde, gilt als im Angebot, genau wie bei einem WooCommerce-Angebotspreis. Ein an der Kasse erhöhter Preis zählt nicht dazu. Ein Gutschein mit **Angebotsprodukte ausschließen** überspringt Angebotsartikel. Ein Gutschein mit festem Warenkorbrabatt und **Angebotsprodukte ausschließen** lässt sich überhaupt nicht anwenden, solange sich ein solcher Artikel im Warenkorb befindet.
- Wenn Sie einen Gutschein entfernen, behält jede Position den an der Kasse festgelegten Preis.

:::note Entwicklerreferenz
Mit **Rabatt hinzufügen** erstellte Positionen sind Gutscheinpositionen mit den Namen `pos-discount`, dann `pos-discount-2` und so weiter. Der Filter `wcpos_item_is_on_sale` ändert, was als Angebot gilt. Informationen zur Speicherung der Kassenpreise und zu weiteren Filtern finden Sie in der [Referenz zu POS-Rabatten](../../reference/pos-discounts.mdx).
:::

### Bestellungen mit einer negativen Gebühr {#discount-fee-tax}

Vor 2.0 konnte ein Kassierer den Bestellbetrag mit einer negativen Gebühr reduzieren. Der POS erlaubt das nicht mehr, ältere Bestellungen können jedoch weiterhin eine solche Gebühr enthalten.

<details>
<summary>Wie WCPOS eine negative Gebühr besteuert und worin sich WooCommerce unterscheidet</summary>

WCPOS besteuert eine negative Gebühr anhand **der Steuereinstellungen der Gebühr selbst**. Ist ihr Steuerstatus auf **Keine** gesetzt, fällt dafür keine Steuer an und der Gebührenbetrag entspricht dem abgezogenen Betrag: Bei einer Gebühr von `-10.00` zahlt der Kunde 10 weniger. Bleibt der Status auf **Steuerpflichtig**, wird die Gebühr nach ihrer eigenen Steuerklasse besteuert, sodass auch diese Steuer abgezogen wird.

WooCommerce allein geht anders vor. Es verteilt die Steuer einer negativen Gebühr auf alle anderen Positionen der Bestellung und ignoriert dabei den Steuerstatus der Gebühr. In einem Shop, in dem **Preise inklusive Steuern eingegeben** auf *Ja* steht, würde es bei einer Gebühr von `-10.00` und einem Steuersatz von 20% außerdem **12.00** abziehen. WCPOS behält den Betrag bei, den der Kassierer eingegeben hat.

Dieses Verhalten ist an die Bestellung gebunden, nicht an die App, in der Sie sie öffnen: Auch bei einer Neuberechnung einer POS-Bestellung unter **WP Admin → Bestellungen** bleibt es erhalten. Für Bestellungen, die nicht aus dem POS stammen, gilt weiterhin das Verhalten von WooCommerce.

:::note Steuer auf eine negative Gebühr
Wenn der Steuerstatus der Gebühr auf **Keine** gesetzt ist, zahlt der Kunde den richtigen Gesamtbetrag, aber die **in der Bestellung erfasste Steuer sinkt nicht**. Sie liegt daher etwas höher, als es dem reduzierten Gesamtbetrag entspricht. Die Abweichung fällt zugunsten der Steuerbehörde aus, niemals umgekehrt. Eine steuerpflichtige negative Gebühr zieht Steuer zum Satz ihrer eigenen Steuerklasse ab. Mit **Rabatt hinzufügen** erstellte Rabatte sind Gutscheinpositionen, daher wird die Steuer auf Grundlage des reduzierten Preises berechnet.
:::

</details>

### Was sich in v1.9.0 geändert hat {#what-changed-in-v190}

Wenn Sie ein Upgrade von v1.8 durchgeführt haben und die Summe unter **Rabatt** auf Belegen und in Berichten jetzt **0** anzeigt, liegt das hieran. Frühere Versionen erfassten eine Preisänderung an der Kasse als WooCommerce-Rabatt. Dadurch wurden Gutscheine falsch berechnet: Ein zusätzlich angewendeter Gutschein ging vom ursprünglichen Preis aus, sodass dem Kunden zu wenig berechnet wurde. Seit v1.9.0 **ist** der an der Kasse festgelegte Preis der Positionspreis, genau wie WooCommerce ein Angebotsprodukt erfasst. Nur Gutscheine zählen als Rabatte. Siehe [Warum Preisänderungen und Gutscheine unterschiedlich erfasst werden](#why-tracked-differently).

#### Was das für Sie bedeutet {#what-this-means-for-you}

<details>
<summary>Belege, Berichte, Gutscheine und gespeicherte Preise seit v1.9.0</summary>

- **Belege** können den regulären Preis, die Ersparnis gegenüber diesem Preis und unter **Insgesamt gespart** die Summe aus diesen Ersparnissen und Gutscheinen anzeigen. Preisersparnisse bleiben vom WooCommerce-Feld **Rabatt** getrennt.
- **Berichte** zeigen `discount_total = 0`, wenn nur Positionspreise geändert wurden. Es zählen nur Gutscheine, und **Rabatt hinzufügen** zählt als Gutschein.
- **Gutscheine** werden für Artikel, deren Preis an der Kasse gesenkt wurde, korrekt berechnet.
- **Der reguläre Preis und der Verkaufspreis werden gespeichert**, und zwar in den POS-Metadaten der Position (`_woocommerce_pos_data`). So kann ein Beleg die Ersparnis anzeigen, ohne die Rabattsummen von WooCommerce zu verändern.

</details>

#### Den ursprünglichen Preis und Ersparnisse auf Belegen anzeigen {#showing-the-original-price-and-saving-on-receipts}

Die mitgelieferten Vorlagen mit Preisanzeige enthalten den regulären Preis und die Ersparnis, wenn ein Produkt im Angebot ist oder sein Preis an der Kasse geändert wurde. Sie zeigen auch **Insgesamt gespart** an, wenn WCPOS einen vollständigen Wert für die Bestellung berechnen kann. Diese Summe kombiniert Ersparnisse gegenüber dem regulären Preis mit Gutscheinrabatten, ohne etwas doppelt zu zählen.

<details>
<summary>Eine vor v1.9.0 erstellte Belegvorlage aktualisieren</summary>

Aus der Galerie kopierte Vorlagen sind Ihre eigenen Kopien und werden bei WCPOS-Updates nicht überschrieben. Wenn Sie Ihren Beleg vor dieser Änderung erstellt haben, können Sie entweder:

1. bei einer aktuellen Kopie der mitgelieferten Vorlage auf **Vorlage verwenden** klicken oder
2. die Felder aus der [Referenz zu Belegdaten](../../receipts/receipt-data.mdx#displaying-regular-price-and-savings) zu Ihrer Vorlage hinzufügen.

Die Felder für Ersparnisse:

| Feld | Bedeutung |
|-------|---------|
| `lines[].regular_price_display` | Erfasster regulärer Stückpreis |
| `lines[].selling_price_display` | Verkaufspreis pro Stück vor Gutscheinen |
| `lines[].unit_savings_display` | Ersparnis pro Artikel |
| `lines[].line_regular_total_display` | Positionssumme zum regulären Preis |
| `lines[].line_savings_display` | Gesamtersparnis für die Position |
| `totals.sale_savings_total_display` | Gesamte Differenz zwischen regulären Preisen und Verkaufspreisen durch Katalogangebote und Preisänderungen an der Kasse |
| `totals.discount_total_display` | WooCommerce-Rabattsumme: Gutscheine einschließlich **Rabatt hinzufügen** |
| `totals.total_saved_display` | Summe aus Ersparnissen gegenüber regulären Preisen und WooCommerce-Rabatten |
| `totals.total_saved_complete` | Ob die kombinierte Summe vollständig ist und bedenkenlos angezeigt werden kann |

Die meisten dieser Felder sind nur vorhanden, wenn die Bestellung die zugrunde liegenden Daten enthält. Benutzerdefinierte Vorlagen sollten jedes Feld vor der Verwendung prüfen und die Zeile **Insgesamt gespart** ausblenden, wenn der Wert unvollständig ist oder keine Ersparnis vorliegt. Ein entsprechendes Muster finden Sie in der [Referenz zu Belegdaten](../../receipts/receipt-data.mdx#totals).

WooCommerce-Berichte bleiben unverändert: Ihre Rabattsummen enthalten Gutscheine, keine Ersparnisse durch Angebots- oder Kassenpreise. Verwenden Sie `totals.total_saved` für Belege. Verwenden Sie einen Gutschein oder **Rabatt hinzufügen**, wenn eine Ersparnis in Berichten auch als WooCommerce-Rabatt erscheinen soll.
