Eine Erweiterung ist ein WordPress-Plugin für WCPOS: für Kartenterminals, mehrsprachige Kataloge, Kundenguthaben oder standortbezogene Bestände. Sie finden alle Erweiterungen in einem Verzeichnis in WordPress unter **WP Admin > POS > Einstellungen > Erweiterungen**.

Die Installation aus dem Verzeichnis erfolgt per Knopfdruck und erfordert **WCPOS Pro** sowie einen WordPress-Administrator. Ohne Pro lassen sich [Polylang](./polylang.mdx), [WPML](./wpml.mdx) und [WP Multilang](./wp-multilang.mdx) manuell installieren.

Direkt zu: [Erweiterung installieren](#installing-an-extension) · [Ohne Pro installieren](#install-by-hand) · [Wenn etwas schiefgeht](#troubleshooting)

## Erweiterung installieren {#installing-an-extension}

:::note Bevor Sie beginnen
Die Installation aus dem Verzeichnis erfordert **WCPOS Pro** und einen WordPress-Administrator: Shop-Manager können keine Plugins installieren (siehe [Zugriff](../settings/wp-admin/access.mdx)). Für die kostenlose Version siehe [Ohne Pro](#install-by-hand).
:::

1. Gehen Sie in WordPress zu **WP Admin > POS > Einstellungen** und wählen Sie **Erweiterungen**.
2. Suchen Sie die Erweiterung. Geben Sie einen Begriff in **Erweiterungen suchen...** ein (die Suche berücksichtigt Name, Beschreibung und Schlagwörter) oder wählen Sie einen Tab: **Alle**, **Katalog**, **Gutscheine**, **Lagerbestand**, **Zahlungen**.
3. Klicken Sie auf der Karte auf **Installieren**. WCPOS lädt die Erweiterung herunter, installiert und aktiviert sie in einem Schritt und schaltet **Automatische Aktualisierung** ein. Auf der Karte steht nun **Aktiv**.
4. Richten Sie die Erweiterung ein. Falls das Menü **⋮** (**Weitere Aktionen**) auf der Karte den Eintrag **Einstellungen** enthält, wählen Sie ihn. Auf der oben verlinkten Seite der Erweiterung erfahren Sie, was Sie ausfüllen müssen.

<details>
<summary>Keine Einstellungen im Menü oder ein anderer Zugangsweg</summary>

- **Einstellungen** erscheint nur dann im Menü, wenn das Verzeichnis eine Einstellungsseite für diese Erweiterung enthält. Andernfalls folgen Sie der Anleitung auf der Seite der Erweiterung.
- Mit WCPOS Pro finden Sie denselben Link **Einstellungen** unter dem Namen der Erweiterung auf **WP Admin > Plugins**.
- Bei einer Zahlungserweiterung öffnet **Einstellungen** deren Seite in den Zahlungseinstellungen von WooCommerce.

</details>

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[190, 0], [200, 0], [-36, 0], [-28, 0]]} alt="Die Ansicht „Erweiterungen“ in WordPress mit WCPOS Pro: das WCPOS-Einstellungsmenü mit ausgewähltem Eintrag „Erweiterungen“, ein Suchfeld und die Schaltfläche „Neu laden“, die Kategorietabs „Alle“, „Katalog“, „Gutscheine“, „Lagerbestand“ und „Zahlungen“ sowie ein Raster mit Erweiterungskarten.">

1. **Erweiterungen** — im WCPOS-Einstellungsmenü. Die Zahl daneben gibt an, für wie viele Erweiterungen eine Aktualisierung bereitsteht.
2. **Erweiterungen suchen...** — durchsucht Name, Beschreibung und Schlagwörter.
3. **Neu laden** — prüft das Verzeichnis sofort auf neue Versionen.
4. **Kategorietabs** — **Alle** oder eine einzelne Kategorie.

</JourneyShot>

### Was eine Karte anzeigt {#browsing-extensions}

Jede Erweiterung hat eine Karte mit Symbol, Name und Beschreibung. Hat sie kein eigenes Symbol, wird ein Puzzleteil angezeigt. Die Karte einer installierten Erweiterung:

<JourneyShot manifest={manifest} device="desktop" step={2} maxWidth={432} offsets={[[-28, 0], [115, 0], [-30, 0], [0, -30], [-34, 0]]} alt="Die Karte für PayPal Reader for WooCommerce, installiert, aber inaktiv: Version 0.1.0 unter „Zahlungen“, automatische Aktualisierung eingeschaltet und eine Schaltfläche „Aktivieren“.">

1. **Status** — **Aktiv**, **Inaktiv** (wie hier) oder **Aktualisierung verfügbar**.
2. **Version** — die installierte Version. Steht eine Aktualisierung bereit, erscheint **v0.5.9 → v0.5.10**. Der Link führt zum Release auf GitHub. Die Kategorie dahinter entspricht dem Tab, unter dem die Erweiterung zu finden ist.
3. **⋮ Weitere Aktionen** — **Auf GitHub ansehen** und **Einstellungen**, sofern die Erweiterung eine Einstellungsseite hat.
4. **Automatische Aktualisierung** — für diese Erweiterung ein- oder ausgeschaltet.
5. **Aktivieren** — die Schaltfläche zeigt den nächsten Schritt: **Aktivieren**, **Aktualisieren** oder beides, wenn für eine deaktivierte Erweiterung eine Aktualisierung vorliegt. Solange die Erweiterung läuft, steht **Deaktivieren** daneben.

</JourneyShot>

### Ohne Pro {#install-by-hand}

Die kostenlose Version listet alle Erweiterungen auf, aber **Installieren** ist ausgegraut und mit **Installation erfordert Pro** versehen. Die drei mehrsprachigen Erweiterungen Polylang, WPML und WP Multilang funktionieren ohne Pro. Sie können diese daher manuell installieren:

1. Öffnen Sie auf der Karte der Erweiterung **⋮** (**Weitere Aktionen**) und wählen Sie **Auf GitHub ansehen**.
2. Laden Sie die dem neuesten Release angehängte `.zip` herunter.
3. Klicken Sie unter **WP Admin > Plugins > Plugin hinzufügen** auf **Plugin hochladen**, wählen Sie die ZIP-Datei und aktivieren Sie das Plugin.

Das Verzeichnis zeigt die Erweiterung anschließend als **Aktiv** an und bei einem neuen Release als **Aktualisierung verfügbar**. Ohne Pro gibt es keine Schaltfläche **Aktualisieren**: Laden Sie die ZIP-Datei des neuen Releases auf dieselbe Weise hoch. WordPress bietet dann an, die installierte Version zu ersetzen.

## Aktualisieren, deaktivieren oder aktivieren {#activating-and-deactivating}

Ohne Pro aktualisieren Sie Erweiterungen manuell: siehe [Ohne Pro](#install-by-hand).

Mit WCPOS Pro haben die Schaltflächen auf der Karte einer installierten Erweiterung folgende Funktionen:

- **Aktualisieren** — installiert die neue Version. Eine bereits aktive Erweiterung bleibt aktiv.
- **Deaktivieren** — stoppt die Erweiterung, ohne sie zu entfernen. Ihre Einstellungen und Dateien bleiben erhalten. Mit **Aktivieren** schalten Sie sie wieder ein. **Aktivieren** schaltet auch **Automatische Aktualisierung** wieder ein.

### Aktualisierungen {#updating-extensions}

Ist eine neue Version verfügbar, zeigt die Karte **v0.5.9 → v0.5.10** an. Der Status einer aktiven Erweiterung wechselt zu **Aktualisierung verfügbar** (eine deaktivierte bleibt **Inaktiv**). Mit WCPOS Pro erscheint außerdem die Schaltfläche **Aktualisieren**, und WordPress zeigt dieselbe Aktualisierung unter **Plugins** an. Sie können die Aktualisierung also an beiden Stellen vornehmen. In der kostenlosen Version aktualisieren Sie manuell: siehe [Ohne Pro](#install-by-hand).

Das Verzeichnis prüft einmal pro Stunde auf neue Versionen. Klicken Sie neben dem Suchfeld auf **Neu laden**, um sofort zu prüfen.

### Automatische Aktualisierungen {#auto-updates}

**Automatische Aktualisierung** ist für jede Erweiterung eingeschaltet, die Sie aus dem Verzeichnis installieren oder aktivieren. WordPress installiert neue Versionen dann im Hintergrund, wie bei jedem Plugin mit eingeschalteten automatischen Aktualisierungen. Schalten Sie die Funktion auf der Karte aus, wenn Sie lieber manuell aktualisieren möchten, etwa um eine neue Version zuerst zu testen.

Eine neue Version, die eine neuere WCPOS-Version als die Ihrer Website benötigt, wird weder auf der Karte noch über die automatische Aktualisierung angeboten. Aktualisieren Sie zuerst WCPOS Pro, dann erscheint die Aktualisierung der Erweiterung.

### Erweiterung entfernen {#removing-an-extension}

Um eine Erweiterung vollständig zu entfernen, deaktivieren und löschen Sie sie unter **WP Admin > Plugins**, wie jedes andere Plugin. Mit WCPOS Pro können Sie sie zuvor auf ihrer Karte deaktivieren.

## Wenn etwas schiefgeht {#troubleshooting}

**Installieren ist ausgegraut und zeigt „Installation erfordert Pro“ an.** Sie verwenden die kostenlose Version: Die Installation aus dem Verzeichnis erfordert [WCPOS Pro](../getting-started/pro-license.mdx). Die mehrsprachigen Erweiterungen lassen sich [manuell installieren](#install-by-hand).

**„Sie haben keine Berechtigung, Plugins zu verwalten.“** Ihr WordPress-Benutzer kann keine Plugins installieren. Wenden Sie sich an einen Administrator.

**„… benötigt WCPOS 2.1 oder neuer; diese Website verwendet WCPOS 2.0. Aktualisieren Sie zuerst WCPOS Pro.“** Die angebotene Version ist neuer, als Ihre WCPOS-Version unterstützt. Aktualisieren Sie WCPOS Pro und versuchen Sie es erneut.

**„Erweiterungen konnten nicht neu geladen werden. Bitte versuchen Sie es erneut.“ oder „Keine Erweiterungen gefunden.“ ohne Suchbegriff.** Ihre Website konnte die Erweiterungsliste nicht abrufen. Die Liste stammt von GitHub, und manche Hosting-Anbieter blockieren ausgehende Verbindungen von Websites. Versuchen Sie es später erneut oder bitten Sie Ihren Hosting-Anbieter, Verbindungen zu GitHub zu erlauben.

**Die Installation schlägt mit einer Fehlermeldung auf der Karte fehl.** WordPress konnte das Plugin nicht herunterladen oder entpacken. Die Meldung auf der Karte nennt die Ursache. Bitten Sie Ihren Hosting-Anbieter zu prüfen, ob WordPress Dateien in seinem Plugin-Ordner (`wp-content/plugins`) speichern und eine Verbindung zu GitHub herstellen kann.

**Nach dem Installieren zeigt die Karte Inaktiv an.** WordPress hat die Erweiterung installiert, konnte sie aber nicht aktivieren. Erst nach der Aktivierung kann sie ausgeführt werden. Klicken Sie auf **Aktivieren**: Schlägt dies fehl, nennt die Meldung auf der Karte die Ursache.

**Eine neue Version wird nicht angezeigt.** Das Verzeichnis speichert seine Liste für eine Stunde. Klicken Sie auf **Neu laden**.

:::info Mit WCPOS Pro
Die kostenlose Version zeigt das gesamte Verzeichnis. Die Bedienelemente **Installieren**, **Aktivieren**, **Aktualisieren**, **Deaktivieren** und **Automatische Aktualisierung** sind jedoch Pro vorbehalten. Siehe [Kostenlos vs. Pro](../getting-started/free-vs-pro.mdx).
:::

## Für Entwickler {#for-developers}

Hinweise zum Entwickeln und Eintragen eigener Erweiterungen. Für den Betrieb einer Filiale benötigen Sie die folgenden Informationen nicht.

### Benennung von Hooks {#hook-naming}

Ab WCPOS 2.0 heißt jeder von WCPOS ausgelöste Hook `wcpos_*`. Die alten Namen mit `woocommerce_pos_*` sind veraltet: Sie funktionieren weiterhin und werden frühestens in 2.2 entfernt.

<details>
<summary>Pro-Hooks, Veraltungshinweise und unveränderte Namen</summary>

Die Hooks von WCPOS Pro heißen `wcpos_pro_*`. Die alten Namen sind Aliasse: Sie werden weiterhin ausgelöst und protokollieren unter `WP_DEBUG` einen Veraltungshinweis, wenn ein Callback daran registriert ist. Nur Hooks ändern sich: Optionen, Metaschlüssel und Berechtigungen behalten ihre Namen.

</details>

<details>
<summary>Von Ihrem Code ausgelöste Hooks und der Zeitpunkt für die Umstellung</summary>

Vier Hooks werden von Ihrem Code ausgelöst und von WCPOS verarbeitet: `woocommerce_pos_invalidate` (Erweiterungen), `woocommerce_pos_receipt_head` (gespeicherte PHP-Belegvorlagen) und `woocommerce_pos_head` / `woocommerce_pos_footer` (eine `pos.php`-Überschreibung im Theme). WCPOS reagiert bis 2.2 weiterhin auf diese Namen. Stellen Sie auf `wcpos_invalidate`, `wcpos_receipt_head`, `wcpos_head` und `wcpos_footer` um.

Erweiterungen: Stellen Sie im ersten Release nach 2.0 auf die Namen mit `wcpos_` um und setzen Sie WCPOS 2.0 oder neuer voraus. Registrieren Sie einen Callback nie unter beiden Namen; unter 2.0 und 2.1 würde er sonst zweimal ausgeführt. Siehe [ADR 0041](https://github.com/wcpos/woocommerce-pos/blob/main/docs/adr/0041-wcpos-is-the-hook-prefix.md).

</details>

<details>
<summary>Eine Erweiterung entwickeln und ins Verzeichnis aufnehmen lassen</summary>

<h3 id="creating-a-pos-extension">Eine POS-Erweiterung erstellen</h3>

Eine WCPOS-Erweiterung ist ein gewöhnliches WordPress-Plugin, das WCPOS-Hooks und APIs nutzt. Für eine Zahlungserweiterung verwenden Sie die [Gateway-Vorlage](../reference/gateway-template.mdx) als Ausgangspunkt.

<h3 id="pos-screens">Die POS-Ansichten ergänzen</h3>

Ein Plugin kann derzeit keine eigenen Bereiche oder Schaltflächen zu den POS-Ansichten hinzufügen. Die Warenkorb-, Produkt- und Kundenansichten zeigen nur die mit der App ausgelieferten Elemente. Eine Ausnahme ist der Checkout: Ein Zahlungsgateway zeigt auf dem [Tab „Legacy“](../pos/checkout/legacy-tab.mdx) seine eigene Zahlungsseite an oder erhält über zwei Filter eine eigene Kachel und Felder auf dem Tab **Zahlungen**. Siehe [Felder für den Zahlungsbereich deklarieren](../reference/declaring-pos-fields.mdx).

<details>
<summary>So erkennt das Verzeichnis Ihr Plugin nach der Installation</summary>

- **Ordnername** — der Ordner des Plugins muss dem `slug` im Katalog entsprechen, z. B. `my-extension/my-extension.php`. Das Verzeichnis erkennt installierte Erweiterungen anhand dieses Ordners und installiert sie darin.
- **Text Domain oder Plugin URI** — einer dieser Werte muss dem `slug` oder dem Namen des GitHub-Repositorys entsprechen. Andernfalls werden Ihre Releases weder über automatische Aktualisierungen noch auf der WordPress-Seite **Plugins** angeboten. Diese Prüfung verhindert, dass ein Fork, der Ihren Ordnernamen wiederverwendet, Ihre Releases erhält.

</details>

<h3 id="submitting-to-the-directory">Einreichen für das Verzeichnis</h3>

Das Verzeichnis liest `catalog.json` aus dem Repository [`wcpos/extensions`](https://github.com/wcpos/extensions) auf GitHub. Um Ihre Erweiterung einzutragen, öffnen Sie dort einen Pull Request, der einen Eintrag in `catalog.json` ergänzt und, falls vorhanden, ein Symbol unter `icons/` hinzufügt. Nach dem Zusammenführen wird sie auf WCPOS-Websites innerhalb von etwa einer Stunde angezeigt.

<details>
<summary>Alle Felder eines Katalogeintrags</summary>

| Feld | Inhalt |
|---|---|
| `slug` | Der Ordnername des Plugins. |
| `name`, `description`, `author` | Die auf der Karte angezeigten Angaben. |
| `category` | Der Tab, unter dem die Erweiterung erscheint: `payments`, `catalog`, `coupons`, `inventory` oder ein neuer. |
| `tags` | Zusätzliche Wörter, die die Suche berücksichtigt. |
| `homepage` | Das GitHub-Repository, `https://github.com/owner/repo`. Von hier werden die Releases abgerufen. |
| `icon` | URL eines quadratischen Symbols, üblicherweise die unter `icons/` hinzugefügte Datei. Ohne Symbol zeigt die Karte ein Puzzleteil. |
| `requires_wp`, `requires_wc`, `requires_wcpos` | Die Mindestversionen von WordPress, WooCommerce und WCPOS, unter denen die Erweiterung läuft. Websites mit einer Version unter `requires_wcpos` wird das Release nie angeboten. |
| `requires_pro` | Ob die Erweiterung WCPOS Pro zum Ausführen benötigt. |
| `settings_url` | Die Einstellungsseite relativ zu `wp-admin/`, z. B. `admin.php?page=wc-settings&tab=checkout&section=my_gateway`. Hinterlegt das Ziel für **Einstellungen** im Kartenmenü. |

Überlassen Sie `version`, `latest_version`, `download_url` und `released_at` dem Katalog: Diese Werte werden aus Ihren Releases übernommen.

</details>

<h3 id="github-release-conventions">Konventionen für GitHub-Releases</h3>

Veröffentlichen Sie ein reguläres GitHub-Release mit der Version als Tag und der ZIP-Datei des Plugins als Anhang. Der Katalog liest stündlich das neueste Release jedes eingetragenen Repositorys und aktualisiert dessen Eintrag.

<details>
<summary>Was ein Release benötigt, um WCPOS-Websites zu erreichen</summary>

- **Versehen Sie es mit einem Tag** für die Version, `v1.2.3`. Das führende `v` wird für die Versionsnummer entfernt. Diese muss mit `Version` im Plugin-Header übereinstimmen.
- **Hängen Sie die ZIP-Datei des Plugins an**, benannt nach dem Slug: `my-extension.zip`. Fehlt dieser Name, wird die erste `.zip` des Releases verwendet. WCPOS installiert sie in den Ordner `slug`, unabhängig vom Namen des Ordners innerhalb der ZIP-Datei.
- **Veröffentlichen Sie es als reguläres Release.** Entwürfe und Vorabversionen werden übersprungen. Eine Vorabversion eignet sich daher, um einen Testbuild sicher bereitzustellen.
- **Erhöhen Sie `requires_wcpos`** in `catalog.json`, wenn ein Release eine neuere WCPOS-Version benötigt. So erhalten ältere Websites keine Version, die nicht startet.

</details>

Websites sehen die neue Version, sobald ihre Liste neu geladen wird: innerhalb einer Stunde oder sofort über **Neu laden**. Websites, auf denen **Automatische Aktualisierung** eingeschaltet ist, installieren sie im Hintergrund.

Um einen eigenen Katalog vor dem Einreichen zu testen, richten Sie eine Website mit dem Filter `wcpos_extensions_catalog_url` auf diesen Katalog aus.

</details>
