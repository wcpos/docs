# PayArc Terminal-Zahlungsgateway {#payarc-terminal-gateway}

PayArc Terminal sendet einen Verkauf von der Kasse an ein PayArc PAX-Terminal. Der Kunde bezahlt am Terminal, und die Kasse erfasst die Zahlung, sobald PayArc sie bestätigt.

Diese Seite beginnt mit der Bedienung an der Kasse. Die Einrichtung des Zahlungsgateways finden Sie unter [PayArc Terminal einrichten](#setup).

:::info Pro-Funktion
PayArc Terminal benötigt [WCPOS Pro](../../getting-started/pro-license.mdx) 2.0 oder neuer.
:::

## Eine Kartenzahlung entgegennehmen {#take-payment}

:::note Öffnen Sie zuerst die Kasse
Wenn **Kasse öffnen und schließen** aktiviert ist, erfasst die Kasse keine Zahlung, solange sie geschlossen ist. Eine bereits entgegengenommene Kartenzahlung müsste dann zurückerstattet werden. Die Einstellung finden Sie unter [Kassen](../../settings/wp-admin/registers.mdx#one-register).
:::

Drücken Sie im Warenkorb auf **Kasse**. PayArc Terminal erscheint auf dem Tab **Zahlungen** als Kachel neben Ihren anderen Zahlungsarten.

1. Tippen Sie auf die Kachel **PayArc Terminal**.
2. Prüfen Sie das über dem Ziffernfeld angegebene Terminal: **Terminal: …**. Wenn mehrere Terminals vorhanden sind, drücken Sie auf **Ändern** und tippen Sie auf das Terminal an Ihrem Kassenplatz. Die Kasse merkt sich Ihre Auswahl für das nächste Mal.
3. Wenn Sie nur einen Teil des offenen Betrags per Karte entgegennehmen möchten, geben Sie den Betrag ein. Der Rest bleibt für eine weitere Zahlung offen.
4. Drücken Sie auf **… an PayArc Terminal senden**. Die Kasse zeigt **Am Terminal** mit vier Schritten an: **Gesendet**, **Am Terminal**, **Genehmigt** und **Eingezogen**.
5. Der Kunde bezahlt am Terminal. Sobald die Zahlung eingezogen wurde und kein Betrag mehr offen ist, öffnet sich der Beleg. Wenn noch ein Betrag offen ist, nehmen Sie diesen über eine andere Kachel entgegen.

**Details** unterhalb der Schritte öffnet ein Zahlungsprotokoll: wann die Zahlung gesendet wurde, wann sie das Terminal erreicht hat und welcher Betrag genehmigt wurde. Bei der Zahlung werden die Kartenmarke, die letzten 4 Ziffern, wie die Karte gelesen wurde und der Autorisierungscode von PayArc gespeichert.

Am Terminal wird kein Trinkgeld abgefragt. Welche Terminals diese Funktion bieten, erfahren Sie unter [Trinkgeld](../../pos/checkout/tips.mdx).

### Eine Zahlung abbrechen {#cancel}

Drücken Sie auf **Am Terminal abbrechen**, bevor der Kunde bezahlt. Die Kasse wartet auf die Bestätigung des Terminals und zeigt dann **Zahlung abgebrochen** an.

Wenn die Karte bereits gelesen wird, kann PayArc den Abbruch ablehnen und die Zahlung abschließen. Die Kasse prüft weiter und zeigt das Ergebnis an. Während sie wartet, zeigt sie **Abbruch läuft — Warten auf Bestätigung des Terminals** an und bietet **Diese Zahlung freigeben** an. Durch die Freigabe kann die Bestellung auf andere Weise bezahlt werden, während Ihr Shop den Terminalstatus weiter prüft.

:::warning
Die Freigabe bricht die Zahlung nicht ab: Das Terminal kann sie weiterhin entgegennehmen. Prüfen Sie das Ergebnis am Terminal, bevor Sie eine weitere Zahlung entgegennehmen.
:::

## Wenn bei einer Zahlung etwas schiefgeht {#goes-wrong}

:::warning
**Das Terminal hat einen anderen Betrag bestätigt?** Nehmen Sie die Zahlung nicht erneut entgegen. Prüfen Sie zuerst das Terminal, die Bestellung und das PayArc-Dashboard.
:::

<Accordion>
  <AccordionItem question="Zahlung fehlgeschlagen: Karte abgelehnt">

  Drücken Sie auf **Erneut versuchen**, um die Zahlung erneut an das Terminal zu senden, oder auf **Andere Zahlungsart wählen**, um über eine andere Kachel zu bezahlen.

  </AccordionItem>
  <AccordionItem question="Zahlung fehlgeschlagen, mit einer Meldung von PayArc">

  PayArc hat den Verkauf abgelehnt, beispielsweise weil das Terminal ausgeschaltet oder nicht online ist. Prüfen Sie das Terminal und drücken Sie dann auf **Erneut versuchen**.

  </AccordionItem>
  <AccordionItem question="Zeitüberschreitung — Zahlung abgebrochen">

  Innerhalb von 5 Minuten wurde nicht bezahlt, oder das Terminal hat auf eine Karte gewartet, die nicht vorgelegt wurde. Prüfen Sie das Terminal und drücken Sie dann auf **Erneut versuchen**.

  </AccordionItem>
  <AccordionItem question="Die Kachel PayArc Terminal ist ausgegraut">

  Unter den Kacheln zeigt die Kasse den Grund an. Alle Gründe finden Sie unter [Wenn eine Kachel nicht verwendet werden kann](../index.mdx#unavailable-tiles).

  - **Keine Terminals für PayArc Terminal eingerichtet** — für dieses Zahlungsgateway ist in der Filiale kein Terminal eingerichtet. Eine Führungskraft fügt eines in Schritt 4 unter [PayArc Terminal einrichten](#setup) hinzu.
  - **Durch Bestellung #… belegt** — das Terminal verarbeitet gerade die Zahlung einer anderen Bestellung. Schließen Sie diese ab oder brechen Sie sie ab. Alternativ drücken Sie auf **Ändern** und wählen ein anderes Terminal.
  - **Verbindung erforderlich** — die Kasse ist offline. Eine Terminalzahlung läuft über Ihren Shop. Nehmen Sie daher eine andere Zahlungsart entgegen oder warten Sie, bis die Verbindung wiederhergestellt ist.

  </AccordionItem>
  <AccordionItem question="Verbindung instabil, weitere Versuche laufen">

  Diese Meldung erscheint im Protokoll unter **Details**. Die Kasse prüft weiter. Lassen Sie die Ansicht geöffnet: Die Zahlung läuft am Terminal weiter.

  </AccordionItem>
  <AccordionItem question="Eine Zahlung hängt fest, oder die Kasse meldet, dass der Anbieter nicht geantwortet hat">

  Siehe [Wenn eine Zahlung am Kartenlesegerät hängen bleibt](../index.mdx#card-reader-problems).

  </AccordionItem>
  <AccordionItem question="Eine Zahlung wartet zu lange">

  - Prüfen Sie die Anzeige am Terminal und lassen Sie die Zahlungsansicht geöffnet
  - Nach **5 Minuten** beendet die Kasse den Vorgang und zeigt **Zeitüberschreitung — Zahlung abgebrochen** an
  - Prüfen Sie das Terminal, die Bestellnotizen und das PayArc-Dashboard, bevor Sie die Zahlung erneut entgegennehmen

  </AccordionItem>
  <AccordionItem question="Eine frühere PayArc Terminal-Zahlung dieser Bestellung kann mit den aktuellen PayArc-Zugangsdaten nicht abgerufen werden">

  - Nehmen Sie die Zahlung auf andere Weise entgegen oder wenden Sie sich an eine Führungskraft. Die Bestellung enthält eine Zahlung aus der Zeit vor einer Änderung des Modus oder der Zugangsdaten
  - Die Führungskraft prüft diese Zahlung im PayArc-Dashboard in dem Modus, in dem sie entgegengenommen wurde
  - Um PayArc für diese Bestellung wieder zu verwenden, stellt die Führungskraft PayArc auf diesen Modus zurück und klickt auf **Mit diesen Zugangsdaten verbinden**. Laden Sie anschließend die Seite neu

  </AccordionItem>
</Accordion>

## Eine PayArc-Zahlung zurückerstatten {#refunds}

Eine Rückerstattung wird an das Terminal gesendet, das den Verkauf abgewickelt hat, und kann den gesamten Betrag oder einen Teil davon umfassen.

1. Öffnen Sie im POS die Rückerstattung der Bestellung. Siehe [Rückerstattungen](../../pos/refunds.mdx).
2. Wählen Sie **Rückerstattung über PayArc Terminal** und drücken Sie auf **Rückerstattung durchführen**.
3. PayArc sendet die Rückerstattung an das Terminal, wo sie genehmigt oder abgelehnt wird. Die Rückerstattung bleibt ausstehend, bis das Terminal antwortet. Das Ergebnis wird den Bestellnotizen hinzugefügt.

Eine Rückerstattung in WP Admin über die WooCommerce-Schaltfläche **… über PayArc Terminal zurückerstatten** funktioniert genauso.

Wenn eine Rückerstattung ausstehend bleibt, prüfen Sie das PayArc-Dashboard, bevor Sie erneut eine Rückerstattung auslösen.

<details>
<summary>Wenn PayArc auf eine Rückerstattung nicht antwortet</summary>

Ihr Shop fragt alle 2 Minuten erneut an, bis zu 5 Mal, und verwendet dabei denselben Anfrageschlüssel. So behandelt PayArc jeden erneuten Versuch als dieselbe Rückerstattung. Wenn weiterhin keine Antwort vorliegt, werden die Mitarbeiter aufgefordert, das PayArc-Dashboard zu prüfen.

</details>

<details>
<summary>Zahlungen aus einer älteren Version</summary>

**Diese PayArc-Zahlung wurde über die eigene Bestellzahlungsansicht des Plugins entgegengenommen.** Die Zahlung wurde mit Version 0.1 der Erweiterung, vor WCPOS 2, entgegengenommen. Daher kann das Zahlungsgateway sie nicht zurückerstatten. Erstatten Sie sie im PayArc-Dashboard oder am Terminal zurück und erfassen Sie die Rückerstattung anschließend in WooCommerce über **… manuell zurückerstatten**.

</details>

## PayArc Terminal einrichten {#setup}

Eine Führungskraft richtet das Zahlungsgateway einmalig in WP Admin ein und wählt anschließend an jeder Kasse ein Terminal aus.

<details>
<summary>Vor der Einrichtung: Was Sie benötigen</summary>

### Voraussetzungen {#requirements}

PayArc stellt Ihnen MID, ClientSecret und SecretKey sowie die Seriennummer eines für Sie eingerichteten Terminals bereit.

Ihr Shop erreicht jedes Terminal über PayArc per Internet. Daher ist keine Kopplung nötig, und jede Kasse kann jedes Ihrer Terminals verwenden. Ohne WCPOS Pro 2.0 oder neuer zeigt die Erweiterung einen Hinweis in WP Admin an und fügt dem POS keine Funktionen hinzu.

<RequirementsList>
  <RequirementItem label="PayArc-Konto">Ein Händlerkonto mit Zugriff auf PayArc Connect V3</RequirementItem>
  <RequirementItem label="Kompatible Hardware">Ein von PayArc unterstütztes PAX-Terminal, das Ihrem Konto zugewiesen ist</RequirementItem>
  <RequirementItem label="Verbindungen">Nur mit Internetverbindung. Der Shop sendet jede Zahlung anhand der Seriennummer an ein PAX-Terminal, sodass jede Kasse es verwenden kann. Die Kasse wählt ihr Terminal beim Bezahlen aus</RequirementItem>
  <RequirementItem label="WCPOS">WCPOS Pro 2.0 oder neuer und Version 1.0 oder neuer der Erweiterung</RequirementItem>
  <RequirementItem label="Server">WooCommerce 7.0+, PHP 7.4+ und HTTPS für den Live-Modus</RequirementItem>
  <RequirementItem label="Währung">USD, CAD, GBP, EUR oder JPY</RequirementItem>
</RequirementsList>

</details>

<details>
<summary>Sechs Schritte: installieren, verbinden, Terminal hinzufügen, aktivieren und das Terminal jeder Kasse auswählen</summary>

<Steps>
  <StepCard number="1" title="PayArc Terminal for WooCommerce installieren">

Laden Sie **payarc-terminal-for-woocommerce.zip**, Version 1.0 oder neuer, von der [GitHub-Releases-Seite](https://github.com/wcpos/payarc-terminal-for-woocommerce/releases) herunter und laden Sie die Datei über `Plugins > Add Plugin` und anschließend **Plugin hochladen** hoch. Aktivieren Sie das Plugin.

Unter `WP Admin > POS > Einstellungen > Erweiterungen` wird möglicherweise noch Version 0.1 aufgeführt, die vor WCPOS 2 entwickelt wurde. Prüfen Sie die Version, bevor Sie von dort installieren.

  </StepCard>
  <StepCard number="2" title="PayArc-Zugangsdaten eingeben">

1. Gehen Sie zu `WP Admin > WooCommerce > Einstellungen > Zahlungen` und öffnen Sie **PayArc Terminal**
2. Wählen Sie den **Modus**: `Live` ist die Standardeinstellung. Verwenden Sie `Test` nur mit Zugangsdaten für das PayArc-Test-Dashboard und der App PayArc Connect Test. Vermischen Sie niemals die Umgebungen
3. Geben Sie unter **PayArc-Anmelde-E-Mail** die E-Mail-Adresse ein, mit der Sie sich bei Ihrem PayArc-Händler-Dashboard anmelden
4. Geben Sie unter **PayArc MID** die MID aus dem PayArc Merchant Profile ein, nicht die Terminal-ID
5. Geben Sie **PayArc ClientSecret** aus dem API-Bereich des Dashboards und **PayArc SecretKey / API-Bearer-Token** aus dem PayArc-Dashboard ein
6. Lassen Sie **Callback-Bearer-Token** leer, es sei denn, der PayArc-Support hat Ihnen eines bereitgestellt

  </StepCard>
  <StepCard number="3" title="Verbinden">

Klicken Sie auf **Mit diesen Zugangsdaten verbinden**. Bei Erfolg zeigt die Ansicht **Mit PayArc verbunden** an und fordert Sie auf, die Seriennummer des Terminals einzugeben oder zu bestätigen und zu speichern. Wenn eine Meldung besagt, dass die Zugangsdaten zur anderen Umgebung zu gehören scheinen, wechseln Sie den **Modus** und verbinden Sie sich erneut.

:::note
Klicken Sie nach jeder Änderung am **Modus** oder an den Zugangsdaten erneut auf **Mit diesen Zugangsdaten verbinden** und speichern Sie anschließend. Sobald PayArc Terminal in WCPOS aktiviert ist (Schritt 5), erscheint beim Speichern ein Fehler, bis Sie dies tun. Während eine Zahlung auf einem Terminal läuft, können Sie den Modus, die Zugangsdaten und die Verbindung nicht ändern.
:::

  </StepCard>
  <StepCard number="4" title="Terminal hinzufügen">

1. Geben Sie unter **Terminal-Seriennummer** die PAX-Seriennummer vom **S/N**-Etikett auf der Rückseite des Geräts ein, die PayArc für Ihr Konto eingerichtet hat
2. Wählen Sie **Zahlungsart** und **Beleg drucken**
3. Prüfen Sie, ob die **Webhook-URL** HTTPS verwendet. Geben Sie sie nur auf Anfrage an PayArc weiter
4. Klicken Sie auf **Änderungen speichern**

Die Kasse bietet dieses Terminal sowie alle Terminals an, die im Terminalverzeichnis von PayArc für Ihr Konto als aktiviert aufgeführt sind. **Verbinden** ruft das Verzeichnis ab, und **Terminals aktualisieren** ruft es erneut ab. Ein von PayArc als deaktiviert markiertes Terminal wird nicht angeboten, auch wenn Sie seine Seriennummer eingegeben haben. Ein Terminal mit einer eingegebenen Seriennummer wird weiterhin angeboten, auch wenn es nicht im Verzeichnis aufgeführt ist. Für den Live-Modus ist eine HTTPS-Website erforderlich.

  </StepCard>
  <StepCard number="5" title="In WCPOS aktivieren">

1. Gehen Sie zu `WP Admin > POS > Einstellungen > Kasse`
2. Suchen Sie **PayArc Terminal** in der Liste und schalten Sie den Schalter **Aktiviert** ein
3. Die Kachel erscheint an der Kasse, sobald die Seite das nächste Mal geladen wird

:::note
Dies ist der einzige maßgebliche Schalter. Der Schalter **Aktiviert** in der Zahlungsliste von WooCommerce hat keine Wirkung, und PayArc Terminal wird beim Bezahlen in Ihrem Onlineshop nie angeboten. Siehe [Checkout-Einstellungen](../../settings/wp-admin/checkout.mdx#enabling-a-gateway).
:::

  </StepCard>
  <StepCard number="6" title="Das Terminal jeder Kasse auswählen" isLast>

Öffnen Sie an jeder Kasse **Einstellungen > Kartenlesegeräte**. Ihre PayArc-Terminals sind unter **Smarte Lesegeräte** mit jeweils einer eigenen Zeile aufgeführt und alle als **Online** gekennzeichnet: PayArc meldet nicht, ob ein Terminal eingeschaltet ist. Drücken Sie beim Terminal an diesem Kassenplatz auf **Dieses Lesegerät verwenden**. In seiner Zeile erscheint **Ausgewählt**. Der Kassierer kann beim Bezahlen weiterhin auf **Ändern** drücken.

Wenn nur ein PayArc-Terminal vorhanden ist, müssen Sie nichts auswählen: Es ist bereits an jeder Kasse als **Ausgewählt** markiert. Eine Zeile mit **Von der Filiale festgelegt** bedeutet, dass die Kassen auf das Standardterminal der Filiale festgelegt sind. Siehe [Ein smartes Lesegerät auswählen](../../hardware/card-readers/index.mdx#smart-readers).

  </StepCard>
</Steps>

</details>

## Einstellungsreferenz {#settings}

Alle Optionen auf der Seite des Zahlungsgateways unter `WP Admin > WooCommerce > Einstellungen > Zahlungen > PayArc Terminal`.

<details>
<summary>Alle Einstellungen von PayArc Terminal</summary>

| Einstellung | Funktion |
|---|---|
| **Titel** | Der Name der Kachel an der Kasse; standardmäßig `PayArc Terminal` |
| **Beschreibung** | Die Beschreibung der Zahlungsart; standardmäßig `Pay in person at a PayArc PAX terminal.` |
| **Modus** | `Live` (Standard) oder `Test`. Der Testmodus benötigt Zugangsdaten für das PayArc-Test-Dashboard und die App PayArc Connect Test |
| **PayArc-Anmelde-E-Mail** | Ihre E-Mail-Adresse für die Anmeldung beim PayArc-Händler-Dashboard; vor dem Verbinden erforderlich |
| **PayArc MID** | Die Händler-MID aus Ihrem PayArc Merchant Profile, nicht die Terminal-ID |
| **PayArc ClientSecret** | Der geheime Schlüssel aus dem API-Bereich des Dashboards; wird nur auf Ihrem Server gespeichert |
| **PayArc SecretKey / API-Bearer-Token** | Das Token aus dem PayArc-Dashboard, das zur Anmeldung und zum Abrufen des Terminalverzeichnisses verwendet wird |
| **Callback-Bearer-Token** | Optional. Nur ausfüllen, wenn der PayArc-Support eines bereitgestellt hat |
| **PayArc-Verbindung** | Die Schaltflächen **Mit diesen Zugangsdaten verbinden**, **Terminals aktualisieren** und **Verbindung trennen** |
| **Terminal-Seriennummer** | Die PAX-S/N, die PayArc für Ihr Konto eingerichtet hat. Für Zahlungen erforderlich |
| **Zahlungsart** | `CREDIT` (Standard) oder `DEBIT` |
| **Beleg drucken** | Belegdruck am Terminal: `0 - No receipt` (Standard), `1 - Merchant receipt`, `2 - Customer receipt` oder `3 - Both receipts` |
| **Webhook-URL** | Schreibgeschützte Callback-Adresse. Prüfen Sie, ob sie HTTPS verwendet; geben Sie sie nur auf Anfrage an PayArc weiter |
| **PayArc-Diagnose** | Verbindungsinformationen und die Schaltfläche **Einstellungen prüfen**; geheime Zugangsdaten werden nie angezeigt |

Bei gespeicherten geheimen Zugangsdaten werden nur die letzten 4 Zeichen angezeigt. Lassen Sie ein solches Feld leer, um den gespeicherten Wert beizubehalten.

Die Tabelle **PayArc-Diagnose** zeigt den Modus, die PayArc-Endpunkte, ob die Anmelde-E-Mail und das Connect-Zugriffstoken hinterlegt sind, eine maskierte MID, Mandanten-ID und Terminal-Seriennummer, die Anzahl der gefundenen Terminals, die Webhook-URL, den Zeitpunkt des letzten Callbacks und den letzten PayArc-Fehler. **Einstellungen prüfen** überprüft die gespeicherten Einstellungen und listet fehlende Angaben auf.

**Verbindung trennen** löscht die gespeicherte PayArc-Verbindung, die Terminalliste und die **Terminal-Seriennummer**. Ihre Zugangsdaten bleiben erhalten, sodass Sie sich schnell erneut verbinden können. Prüfen Sie die Seriennummer vor dem Speichern.

</details>

## Protokolle {#logs}

Wenn Sie um Hilfe bitten, senden Sie die Bestellnummer und die relevanten Protokollzeilen mit.

<details>
<summary>Protokolle für den Support finden</summary>

Sie finden die Protokolle unter `WooCommerce > Status > Protokolle` mit der Quelle `payarc-terminal-for-woocommerce`. Kennungen werden maskiert und geheime Zugangsdaten entfernt.

Es gibt kein Support-Paket zum Herunterladen. Geben Sie keine vollständigen MIDs, Terminal-IDs, Tokens oder Kartendaten weiter.

</details>

## Funktionsumfang und Einschränkungen {#scope-and-limitations}

- Kein Trinkgeld am Terminal
- Ein Terminal verarbeitet jeweils nur eine Zahlung. Während es belegt ist, sehen andere Kassen **Durch Bestellung #… belegt**
- Die unterstützten Währungen sind auf **USD, CAD, GBP, EUR und JPY** beschränkt
- Die Verbindung meldet nicht, ob ein Terminal eingeschaltet ist: Ein Verkauf an ein Terminal, das offline ist, schlägt sofort fehl, ohne dass etwas an das Terminal gesendet wird
- Zahlungen, die mit Version 0.1 der Erweiterung entgegengenommen wurden, werden in PayArc zurückerstattet, nicht über das Zahlungsgateway
- Eine Rückerstattung wird an das Terminal gesendet, das den Verkauf abgewickelt hat

## Wenn bei der Einrichtung etwas schiefgeht {#troubleshooting}

### Häufige Probleme {#common-issues}

<Accordion>
  <AccordionItem question="Diese Zugangsdaten scheinen für die Test- oder Live-Umgebung von PayArc bestimmt zu sein">

  - Der gewählte Modus und die Zugangsdaten stammen aus unterschiedlichen PayArc-Umgebungen
  - Stellen Sie den **Modus** auf den in der Meldung genannten Modus um oder ersetzen Sie die Zugangsdaten durch solche für den gewählten Modus
  - Klicken Sie erneut auf **Mit diesen Zugangsdaten verbinden** und speichern Sie

  </AccordionItem>
  <AccordionItem question="Verbindung mit PayArc nicht möglich">

  - PayArc hat die Anmeldung abgelehnt. Prüfen Sie die eingegebenen Zugangsdaten und versuchen Sie es erneut
  - Weitere Informationen finden Sie unter `WooCommerce > Status > Protokolle` mit der Quelle `payarc-terminal-for-woocommerce`

  </AccordionItem>
  <AccordionItem question="Die Callback-URL muss HTTPS verwenden, bevor der Live-Modus aktiviert wird">

  - Der Live-Modus erfordert HTTPS auf Ihrer Website, damit PayArc die **Webhook-URL** erreichen kann
  - Stellen Sie die Website auf HTTPS um oder verwenden Sie den Modus **Test** auf einer Testwebsite

  </AccordionItem>
  <AccordionItem question="Das Terminalverzeichnis ist leer">

  - Die Kasse bietet dann nur das unter **Terminal-Seriennummer** eingetragene Terminal an. Zahlungen über dieses Terminal funktionieren weiterhin
  - Bitten Sie PayArc, diese Seriennummer für Ihr Konto zu bestätigen und Ihre anderen Terminals aufzuführen, wenn diese an der Kasse zur Auswahl stehen sollen
  - Klicken Sie auf **Terminals aktualisieren**, nachdem PayArc sie hinzugefügt hat

  </AccordionItem>
  <AccordionItem question="PayArc hat sowohl den Connect AccessToken als auch den SecretKey abgelehnt">

  - PayArc hat Ihrem Konto den Zugriff auf seine Transaktions-API verweigert
  - Bitten Sie den PayArc-Support zu bestätigen, dass **PayArc Connect V3** für Ihr Händlerkonto aktiviert ist und welche Zugangsdaten die Transaktionen autorisieren

  </AccordionItem>
</Accordion>
