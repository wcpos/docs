# Windcave Terminal Zahlungsgateway {#windcave-terminal-gateway}

Windcave Terminal sendet einen Verkauf von der Kasse an ein Windcave-Terminal. Der Kunde bezahlt am Terminal, und die Kasse verbucht die Zahlung, sobald Windcave sie bestätigt.

Diese Seite beginnt an der Kasse. Für Filialadministratoren: Unter [Windcave Terminal einrichten](#setup) finden Sie die Zugangsdaten, die WP-Admin-Einstellungen und eine Anleitung zur Überprüfung.

:::info Pro-Funktion
Windcave Terminal benötigt [WCPOS Pro](../../getting-started/pro-license.mdx) ab Version 2.0 und die Erweiterung ab Version 1.0.
:::

:::warning Noch nicht von Windcave zertifiziert
**Nur Testzahlungen: Nehmen Sie über Windcave noch keine echten Kundenzahlungen entgegen.** Windcave genehmigt jede POS-Integration, bevor sie echte Zahlungen entgegennimmt, und hat diese Integration noch nicht genehmigt.

<details>
<summary>Was noch nicht getestet wurde</summary>

Die Erweiterung wurde noch nicht auf einem physischen Windcave-Terminal ausgeführt. Zahlungen und Rückerstattungen wurden mit einem Ersatz für den HIT-Dienst von Windcave getestet, der auf der Dokumentation von Windcave basiert. Führen Sie eine kleine UAT-Zahlung durch und erstatten Sie sie zurück, bevor Sie sich darauf verlassen.

</details>
:::

## Kartenzahlung entgegennehmen {#take-payment}

:::note Öffnen Sie zuerst die Kasse
Wenn **Kasse öffnen und schließen** aktiviert ist, verbucht die Kasse keine Zahlung, solange sie geschlossen ist. Eine bereits entgegengenommene Kartenzahlung müsste dann zurückerstattet werden. Informationen zur Einstellung finden Sie unter [Kassen](../../settings/wp-admin/registers.mdx#one-register).
:::

1. Drücken Sie im Warenkorb auf **Kasse** und tippen Sie auf der Registerkarte **Zahlungen** auf die Kachel **Windcave Terminal**. Wenn Ihre Terminals nach einer Unterschrift fragen, verwenden Sie stattdessen die Registerkarte **Legacy**: siehe [Wenn das Terminal eine Frage stellt](#terminal-questions).
2. Sehen Sie oberhalb des Tastenfelds nach. Wenn **Terminal auswählen** angezeigt wird, tippen Sie auf die **Stations-ID** des Terminals an Ihrer Kasse: den Namen, den Windcave jedem Terminal zuweist, etwa `DOCS-STATION-1`. Wenn **Terminal:** und eine ID angezeigt werden, verwendet diese Kasse dieses Terminal. Drücken Sie auf **Ändern**, um ein anderes auszuwählen. Die Kasse merkt sich Ihre Auswahl.
3. Um einen Teil des offenen Betrags von der Karte abzubuchen, geben Sie den Betrag ein. Der Rest bleibt für eine weitere Zahlung offen.
4. Drücken Sie auf **An Windcave Terminal senden …**. Die Kasse zeigt **Am Terminal** mit vier Schritten an: **Gesendet**, **Am Terminal**, **Genehmigt** und **Eingezogen**. Letzteres bedeutet, dass das Geld eingezogen wurde.
5. Der Kunde hält die Karte an das Terminal, steckt sie ein oder zieht sie durch. Sobald die Zahlung eingezogen wurde und kein Betrag mehr offen ist, wird der Beleg geöffnet. Ist noch ein Betrag offen, nehmen Sie ihn mit einer anderen Kachel entgegen.

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[105, 0], [-40, 0], [190, 0], [-45, 0], [0, 0], [85, 0]]} maxWidth={720} alt="Checkout auf der Registerkarte Zahlungen für einen Verkauf über $45.00: Die Kachel Windcave Terminal ist ausgewählt, darunter stehen unter Terminal auswählen zwei Stations-IDs und der vollständige Betrag, und die Schaltfläche $45.00 an Windcave Terminal senden ist ausgegraut, bis ein Terminal ausgewählt wurde">

1. **Windcave Terminal** — die Kachel, die nach dem Antippen umrandet angezeigt wird.
2. **Stations-IDs** unter **Terminal auswählen** — tippen Sie auf die ID des Terminals an Ihrer Kasse. Sobald diese Kasse ein Terminal zugewiesen hat, zeigt diese Zeile **Terminal:** und dessen ID sowie **Ändern** an.
3. **Zu zahlen** — der Betrag dieser Zahlung. Geben Sie einen kleineren Betrag ein, um einen Teil des offenen Betrags von der Karte abzubuchen.
4. **Gesamter offener Betrag** — setzt den gesamten noch offenen Betrag wieder in **Zu zahlen** ein.
5. **An Windcave Terminal senden …** — startet die Zahlung am Terminal. Die Schaltfläche ist ausgegraut, bis ein Terminal ausgewählt wurde.
6. **Legacy** — die andere Registerkarte für Zahlungen über Gateways mit eigener Zahlungsseite. Verwenden Sie sie, wenn Ihr Terminal nach einer Unterschrift fragt.

</JourneyShot>

Unter den vier Schritten öffnet **Details** ein Protokoll der Zahlung einschließlich der Station, an die sie gesendet wurde. Am Terminal sind Trinkgeld, Aufschlag und Bargeldauszahlung nicht möglich.

### Wenn das Terminal eine Frage stellt {#terminal-questions}

Ein Terminal kann anhalten und eine Frage stellen, etwa ob die Unterschrift des Kunden übereinstimmt. In dieser Version zeigt die Registerkarte **Zahlungen** solche Fragen nicht an. Die Registerkarte **Legacy** zeigt sie an:

1. Öffnen Sie die Registerkarte **Legacy** und wählen Sie **Windcave Terminal**. Siehe [Die Registerkarte Legacy](../../pos/checkout/legacy-tab.mdx).
2. Starten Sie dort die Zahlung. Dabei wird der gesamte Bestellbetrag mit einer Zahlung beglichen.
3. Wenn das Terminal eine Frage stellt, zeigt die Zahlungsseite sie mit den eigenen Schaltflächen des Terminals an, zum Beispiel **JA** und **NEIN**. Drücken Sie auf die passende Antwort.

### Zahlung abbrechen {#cancel}

Drücken Sie auf **Am Terminal abbrechen**, bevor der Kunde bezahlt. Das funktioniert nur, solange das Terminal selbst **ABBRECHEN** anbietet. Andernfalls zeigt die Kasse *Das Terminal bietet momentan keine Abbruchmöglichkeit. Brechen Sie den Vorgang am Terminal ab.* an.

Ein Abbruch ist eine Anfrage. Wurde die Karte bereits eingelesen, kann die Zahlung trotzdem durchgeführt werden: Die Kasse zeigt **Wird abgebrochen — es wird auf die Bestätigung des Terminals gewartet** an, fragt weiter den Status ab und zeigt das Ergebnis. Warten Sie darauf, bevor Sie eine andere Zahlungsart verwenden.

Wenn die Kasse keine Antwort erhält, bietet sie **Diese Zahlung freigeben** an. Freigegeben bedeutet nicht abgebrochen: Drücken Sie erst darauf, nachdem eine Filialleitung das Windcave-Portal geprüft und festgestellt hat, dass für die Bestellung keine Zahlung genehmigt wurde. Danach kann die Bestellung mit einer anderen Zahlungsart bezahlt werden; die Kasse prüft das Terminal weiterhin.

## Wenn etwas schiefgeht {#goes-wrong}

### Wenn der Kunde möglicherweise bezahlt hat {#may-have-paid}

:::warning Nehmen Sie die Zahlung nicht erneut entgegen
In diesen beiden Fällen wurde die Karte möglicherweise bereits belastet. Eine Filialleitung prüft zuerst das Windcave-Portal, in dem der Verkauf unter der Bestellnummer aufgeführt ist.
:::

**Terminalergebnis konnte nicht bestätigt werden. Prüfen Sie Windcave, bevor Sie die Zahlung erneut entgegennehmen.** Die Kasse hat erneut nach einer bereits gesendeten Zahlung gefragt, aber Windcaves Antwort war unklar. Nehmen Sie die Zahlung nur erneut entgegen, nachdem eine Filialleitung im Portal nach dem Verkauf gesucht und keinen Eintrag gefunden hat.

**Zahlung fehlgeschlagen: Das Terminal hat einen anderen Betrag bestätigt.** Das Terminal hat einen anderen Betrag als den von der Kasse gesendeten genehmigt. Daher hat die Kasse ihn nicht verbucht, aber die Karte könnte belastet worden sein. Nehmen Sie keine weitere Zahlung entgegen. Bitten Sie eine Filialleitung, den Verkauf im Portal unter der Bestellnummer zu suchen und den vom Terminal eingezogenen Betrag mit dem Bestellbetrag zu vergleichen.

## Windcave-Zahlung zurückerstatten {#refunds}

Eine Rückerstattung wird über Windcave an die Station zurückgebucht, die den Verkauf abgewickelt hat. Sie kann den gesamten Betrag oder einen Teil davon umfassen.

1. Öffnen Sie im POS die Rückerstattung der Bestellung. Siehe [Rückerstattungen](../../pos/refunds.mdx).
2. Wählen Sie **An Windcave Terminal zurückerstatten** und drücken Sie auf **Rückerstattung verarbeiten**.
3. Ihre Filiale wartet bis zu 20 Sekunden auf die Antwort von Windcave und fügt das Ergebnis anschließend den Bestellnotizen hinzu.

Eine Rückerstattung in WP Admin über die WooCommerce-Schaltfläche **… über Windcave Terminal zurückerstatten** funktioniert genauso.

Bleibt eine Rückerstattung **ausstehend**, prüfen Sie sie im Windcave-Portal, bevor Sie erneut erstatten.

<Accordion>
  <AccordionItem question="Eine Rückerstattung bleibt ausstehend">

  Windcave hat nicht innerhalb von 20 Sekunden geantwortet oder einen anderen als den angefragten Betrag genehmigt. Ihre Filiale versucht es nicht erneut. Suchen Sie die Rückerstattung im Windcave-Portal: Wurde sie ausgeführt, hat der Kunde sein Geld erhalten; andernfalls führen Sie die Rückerstattung erneut durch.

  </AccordionItem>
  <AccordionItem question="Ein Verkauf aus Version 0.1 kann nicht zurückerstattet werden">

  Die Rückerstattung wird mit *Legen Sie in den POS-Einstellungen eine Standardstation fest, bevor Sie diesen Verkauf zurückerstatten.* angehalten. Version 0.1 der Erweiterung hat nicht gespeichert, welche Station den Verkauf abgewickelt hat. Daher erstattet Version 1.0 über eine filialeinheitliche Standardstation zurück. Kassen wählen ihre Station jetzt unter **Einstellungen > Kartenlesegeräte** aus; WCPOS 2.0 hat noch keine filialeinheitliche Standardstation. Erstatten Sie den Verkauf im Windcave-Portal oder am Terminal und erfassen Sie die Rückerstattung anschließend mit **… manuell zurückerstatten** in WooCommerce.

  </AccordionItem>
</Accordion>

## Windcave Terminal einrichten {#setup}

Eine Administratorin oder ein Administrator richtet dies einmal pro Filiale in WP Admin ein und wählt anschließend an jeder Kasse eine Station aus. Ihre Filiale erreicht jedes Terminal über Windcave und das Internet. Eine Kopplung ist daher nicht erforderlich, und jede Kasse kann jedes Ihrer Terminals verwenden.

### Voraussetzungen {#requirements}

Sie benötigen HIT-Zugangsdaten, also einen **HIT-Benutzernamen** und einen **HIT-Schlüssel**, sowie die **Stations-ID** jedes Terminals. Windcave stellt all diese Daten bereit; WP Admin kann sie weder nachschlagen noch erstellen. Kontaktieren Sie Windcave und bitten Sie um **UAT**-Zugangsdaten für HIT sowie die Stations-ID jedes Terminals. Alternativ können Sie für ein Entwicklungskonto Windcaves [Formular für Integrationsanforderungen](https://www.windcave.com/merchant-attended-developer-hit) verwenden. Für UAT und Produktion gibt es jeweils eigene Benutzernamen und Schlüssel. Sobald Windcave die Integration zertifiziert hat, stellt das Unternehmen eine **Vendor-ID** aus.

<RequirementsList>
  <RequirementItem label="Windcave-Konto">HIT-Zugangsdaten und eine Stations-ID pro Terminal. UAT-Zugangsdaten, bis Windcave die Integration zertifiziert hat</RequirementItem>
  <RequirementItem label="Terminal">Ein Windcave-Terminal, das HIT-Zahlungen annimmt</RequirementItem>
  <RequirementItem label="WCPOS">WCPOS Pro ab Version 2.0 und die Erweiterung ab Version 1.0</RequirementItem>
  <RequirementItem label="Server">WooCommerce und PHP 7.4 oder neuer mit der DOM-Erweiterung (php-xml)</RequirementItem>
</RequirementsList>

### Erweiterung installieren {#install}

Öffnen Sie `WP Admin > POS > Einstellungen > Erweiterungen`, suchen Sie **Windcave Terminal for WooCommerce**, installieren und aktivieren Sie die Erweiterung. Sie benötigen Version 1.0 oder neuer; Version 0.1 ist für WCPOS vor Version 2.0 vorgesehen. Siehe [Erweiterungen](../../extensions/index.mdx#installing-an-extension).

Sie können auch die **Plugin-ZIP-Datei** (nicht die ZIP-Datei mit dem Quellcode) von der [GitHub-Releases-Seite](https://github.com/wcpos/windcave-terminal-for-woocommerce/releases) unter `Plugins > Add Plugin > Plugin hochladen` hochladen.

Ohne WCPOS Pro 2.0 zeigt WP Admin *Windcave Terminal erfordert WooCommerce POS Pro 2.0 oder neuer.* an, und das Zahlungsgateway wird nicht hinzugefügt. Die Aktivierung wird bei PHP-Versionen vor 7.4 oder ohne DOM-Erweiterung abgelehnt. Bitten Sie Ihren Hosting-Anbieter, **php-xml** zu aktivieren.

### HIT-Zugangsdaten eingeben {#credentials}

Gehen Sie zu `WP Admin > WooCommerce > Einstellungen > Zahlungen` und öffnen Sie **Windcave Terminal**.

<JourneyShot manifest={manifest} device="desktop" step={1} offsets={[[410, 0], [410, 0], [410, 0], [850, 0], [410, 0], [410, 0]]} maxWidth={720} alt="WP Admin, Windcave-Terminal-Einstellungen: Umgebung UAT (Test), leere Felder für HIT-Benutzername, HIT-Schlüssel, Stations-IDs und Vendor-ID sowie POS-Name WCPOS">

1. **Umgebung** — belassen Sie die Standardeinstellung **UAT (Test)**. **Produktion** ist für die Zeit nach der Zertifizierung der Integration durch Windcave mit Produktionszugangsdaten vorgesehen.
2. **HIT-Benutzername** — von Windcave für die ausgewählte Umgebung.
3. **HIT-Schlüssel** — von Windcave. Nach dem Speichern bleibt das Feld leer. Lassen Sie es leer, um den gespeicherten Schlüssel beizubehalten.
4. **Stations-IDs** — eine pro Zeile und Terminal. Windcave stellt sie bereit; sie werden nicht automatisch gefunden.
5. **Vendor-ID** — lassen Sie das Feld leer, bis Windcave eine ID ausstellt.
6. **POS-Name** — der Name, unter dem Ihr POS bei Windcave geführt wird. Standardmäßig `WCPOS`.

</JourneyShot>

Darunter ist **Ergebnisbenachrichtigungen (FPRN)** optional. Wenn die Option aktiviert ist, informiert Windcave Ihre Filiale zusätzlich, sobald ein Ergebnis vorliegt, als Ergänzung zu den Statusabfragen der Kasse. Damit die Funktion arbeitet, muss Ihre Website aus dem Internet erreichbar sein.

Klicken Sie auf **Änderungen speichern**.

### In WCPOS aktivieren {#enable}

Öffnen Sie `WP Admin > POS > Einstellungen > Kasse`, suchen Sie in der Tabelle **Zahlungsgateways** nach **Windcave Terminal** und aktivieren Sie den Schalter **Aktiviert**. Diese Seite speichert Änderungen automatisch; eine Schaltfläche zum Speichern gibt es nicht.

Lassen Sie **Aktivieren/Deaktivieren** auf der WooCommerce-Einstellungsseite ausgeschaltet. Der POS verwendet das Zahlungsgateway, sobald **Aktiviert** hier eingeschaltet ist, unabhängig davon, ob das andere Kontrollkästchen markiert ist. Siehe [Checkout-Einstellungen](../../settings/wp-admin/checkout.mdx#enabling-a-gateway).

<JourneyShot manifest={manifest} device="desktop" step={2} offsets={[[172, 0], [-26, 0]]} maxWidth={720} alt="WP Admin, POS-Einstellungen, Checkout: zwei Zeilen der Tabelle Zahlungsgateways, Vipps MobilePay aktiviert und Windcave Terminal deaktiviert">

1. **Windcave Terminal** — die Zeile der Erweiterung in der Tabelle **Zahlungsgateways**.
2. **Aktiviert** — der Schalter neben der Gateway-ID. Schalten Sie ihn ein. Nach dem Neuladen zeigt die Kasse die Kachel **Windcave Terminal** an.

</JourneyShot>

### Station für jede Kasse auswählen {#till-terminal}

Öffnen Sie an jeder Kasse **Einstellungen > Kartenlesegeräte**. Jede eingegebene Stations-ID wird unter **Intelligente Lesegeräte** als Kartenlesegerät aufgeführt und als **Online** markiert. Die Erweiterung fragt Windcave nicht ab, ob ein Terminal eingeschaltet ist. Drücken Sie bei der Station an dieser Kasse auf **Dieses Lesegerät verwenden**. In der Zeile wird **Ausgewählt** angezeigt. Der Kassierer kann beim Checkout weiterhin auf **Ändern** drücken.

Wenn es nur eine Station gibt, müssen Sie nichts auswählen: Sie ist an jeder Kasse bereits **Ausgewählt**. Siehe [Intelligentes Lesegerät auswählen](../../hardware/card-readers/index.mdx#smart-readers).

### Überprüfen, ob alles funktioniert {#check}

1. Auf der Einstellungsseite von Windcave Terminal steht unter den Einstellungen `uat: HIT credentials configured (not verified).`. Das bedeutet, dass Benutzername und Schlüssel gespeichert sind, nicht dass Windcave sie akzeptiert hat. `HIT credentials missing.` bedeutet, dass eines der Felder leer ist.
2. Laden Sie den POS an einer Kasse neu und drücken Sie auf **Kasse**. Die Kachel **Windcave Terminal** wird als Zahlungsart angezeigt. Tippen Sie darauf: Oberhalb des Tastenfelds erscheinen Ihre Stations-IDs unter **Terminal auswählen** oder als **Terminal:** mit dem von dieser Kasse verwendeten Terminal.
3. Führen Sie an einem UAT-Terminal einen kleinen Verkauf durch und erstatten Sie ihn anschließend zurück. Es gibt keine Schaltfläche zum Testen der Verbindung: Erst dieser Verkauf überprüft Zugangsdaten und Stations-ID.

### Upgrade von Version 0.1 {#upgrade}

- Aktualisieren Sie zuerst WCPOS, WCPOS Pro und die App auf Version 2.0 und anschließend die Erweiterung.
- Eine während des Upgrades laufende Zahlung wird übernommen. Es wird nichts doppelt berechnet.
- Eine von Version 0.1 zurückgestellte Zahlung wird übernommen, wenn die zugehörige Bestellung noch unbezahlt ist. Andernfalls erhält die Bestellung den Hinweis: *Windcave TxnRef … wurde vor dem Upgrade auf 1.0.0 zurückgestellt und wird nicht mehr automatisch weiterverfolgt.* Prüfen Sie diese Zahlung im Windcave-Portal: Wurde sie genehmigt, erstatten Sie sie dort oder erfassen Sie sie manuell in der Bestellung.
- Diese Einstellungen aus Version 0.1 gibt es nicht mehr: **Standard-Stations-ID**, **Terminalsuswahl sperren**, **Checkout-Protokolle** und **Protokollierungsstufe**. Kassen wählen ihre Station jetzt unter **Einstellungen > Kartenlesegeräte** aus.
- Auch die Funktion zum Zurückstellen gibt es nicht mehr. Terminal-Belegtext wird der Bestellung nicht länger als private Notiz hinzugefügt.
- Rückerstattung eines mit Version 0.1 abgewickelten Verkaufs: siehe [Windcave-Zahlung zurückerstatten](#refunds).

## Einstellungsreferenz {#settings}

Unter `WP Admin > WooCommerce > Einstellungen > Zahlungen > Windcave Terminal`:

| Einstellung | Funktion |
|---|---|
| **Aktivieren/Deaktivieren** | Stellt das Zahlungsgateway im Checkout Ihres Onlineshops bereit. Lassen Sie die Option ausgeschaltet; der POS hat einen eigenen Schalter unter `POS > Einstellungen > Kasse` |
| **Titel** | Der Name der Kachel an der Kasse. Standardmäßig `Windcave Terminal` |
| **Beschreibung** | Standardmäßig `Pay in person on the Windcave terminal.` |
| **Umgebung** | **UAT (Test)** (Standard) oder **Produktion**. Für jede Umgebung gibt es eigene HIT-Zugangsdaten; für die Produktion ist eine Zertifizierung durch Windcave erforderlich. Eine in einer Umgebung gestartete Zahlung wird immer dort überprüft |
| **HIT-Benutzername** | Von Windcave für die ausgewählte Umgebung bereitgestellt |
| **HIT-Schlüssel** | Wird von Windcave ausgestellt. Nach dem Speichern nicht mehr sichtbar; lassen Sie das Feld leer, um den Schlüssel beizubehalten |
| **Stations-IDs** | Eine pro Zeile und Terminal. Duplikate werden entfernt |
| **Vendor-ID** | Wird während der Zertifizierung mit Windcave vereinbart. Bis dahin leer lassen |
| **POS-Name** | Der Name, unter dem Ihr POS bei Windcave geführt wird. Standardwert: `WCPOS` |
| **Ergebnisbenachrichtigungen (FPRN)** | Windcave informiert Ihren Shop zusätzlich, sobald ein Ergebnis vorliegt, als Ergänzung zu den Statusabfragen der Kasse. Standardmäßig ausgeschaltet |

## Protokolle und Support-Paket {#logs-and-support-bundle}

Am Ende der Einstellungsseite finden Sie das Support-Paket, die Zeile mit dem Status der Zugangsdaten und einen Link zu den Protokollen.

<JourneyShot manifest={manifest} device="desktop" step={3} offsets={[[200, 0], [80, 0], [-20, 0]]} maxWidth={720} alt="WP Admin, Ende der Windcave-Terminal-Einstellungen einer noch nicht eingerichteten Filiale: Support-Paket mit Schaltfläche Support-Paket herunterladen, die Zeile uat: HIT credentials missing und Protokolle anzeigen">

1. **Status der Zugangsdaten** — in dieser noch nicht eingerichteten Filiale steht `HIT credentials missing.`. Bei Ihnen sollte `HIT credentials configured (not verified).` stehen.
2. **Protokolle anzeigen** — öffnet `WooCommerce > Status > Protokolle`, Quelle `windcave-terminal`.
3. **Support-Paket herunterladen** — eine Datei für den WCPOS-Support.

</JourneyShot>

Die Protokolle enthalten jede Anfrage an Windcave und die zugehörige Antwort. HIT-Schlüssel und Kartennummern werden maskiert.

Wenn bei einer Zahlung ein Problem auftritt, klicken Sie auf **Support-Paket herunterladen** und senden Sie die Datei zusammen mit der **Bestellnummer** an den WCPOS-Support. Diese Schaltfläche wird von WCPOS Pro hinzugefügt. Das Paket umfasst alle POS-Zahlungsanbieter auf Ihrer Website; Geheimnisse und Kartennummern werden entfernt.

## Was nicht unterstützt wird {#scope-and-limitations}

- Echte Zahlungen, bis Windcave die Integration zertifiziert hat.
- Trinkgelder, Aufschläge, Bargeldauszahlungen oder eine spätere Einziehung nach der Autorisierung.
- Fragen des Terminals auf der Registerkarte **Zahlungen** beantworten. Verwenden Sie die Registerkarte **Legacy**.
- Automatische Terminalsuche: Sie geben jede Stations-ID selbst ein.
- HIT-Zugangsdaten vor der ersten Zahlung überprüfen.

<details>
<summary>Funktionsweise für Entwickler</summary>

Das Zahlungsgateway verwendet Windcave **HIT (Host Initiated Transaction)** über HTTPS: `uat.windcave.com` für UAT und `sec.windcave.com` für die Produktion. Jedes Terminal wird über seine **Stations-ID** angesprochen.

Bei einer Zahlung wird ein Purchase über den an der Kasse angegebenen Betrag gesendet. Als Händlerreferenz dienen `Order #` und die Bestellnummer. Anschließend prüft WCPOS Pro den Status, bis die Zahlung abgeschlossen ist. Fragt die Kasse erneut an, fragt die Erweiterung zuerst dieselbe Transaktionsreferenz ab, statt einen weiteren Purchase zu starten. Ein Purchase, den Windcave nicht innerhalb von 30 Sekunden registriert, gilt als nicht gesendet.

Wenn **Ergebnisbenachrichtigungen (FPRN)** aktiviert sind, fordert jeder Purchase Windcave auf, den WCPOS-Zahlungs-Webhook Ihrer Filiale aufzurufen: `wp-json/wcpos/v2/payments/webhook` mit `provider=windcave` und der Transaktionsreferenz. Dieser Aufruf dient nur als Hinweis: Anschließend fragt die Filiale das Ergebnis direkt bei Windcave ab.

Eine Rückerstattung ist ein HIT-Matched-Refund für die ursprüngliche Windcave-Transaktion über den von Ihnen eingegebenen Betrag. Die Filiale prüft den Status bis zu 20 Sekunden lang alle 2 Sekunden.

</details>
