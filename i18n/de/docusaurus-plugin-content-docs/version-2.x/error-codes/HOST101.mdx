## Was das bedeutet {#what-this-means}

Der Server blockiert die Berechtigungsprüfung des Browsers (CORS-Preflight), sodass die Web-App ihn nicht erreichen kann.

Browser senden vor jedem ursprungsübergreifenden API-Aufruf mit benutzerdefinierten Headern eine OPTIONS-Anfrage. Eine dem Shop vorgeschaltete Komponente — meist eine Firewall-Regel — blockiert OPTIONS, sodass der Browser die eigentliche Anfrage gar nicht sendet. Native Apps sind nicht betroffen; die Behebung muss auf dem Server erfolgen.

## Ihre Daten {#your-data}

Bestell- und Produktdaten sind nicht betroffen.

## Fehlerbehebung {#troubleshoot}

1. Prüfen Sie die Firewall (WAF) auf eine Regel, die die OPTIONS-Methode blockiert, und erlauben Sie diese Methode auf den REST-Routen unter /wcpos/.
2. Einige Sicherheitsplugins haben eine Option zum Blockieren ungewöhnlicher Anfragemethoden. OPTIONS muss weiterhin erlaubt bleiben.
3. Test: Eine OPTIONS-Anfrage an die REST API des Shops sollte nicht 403 zurückgeben.
4. Die Desktop- und Mobil-Apps verwenden kein CORS und funktionieren weiter, während das Problem behoben wird.
