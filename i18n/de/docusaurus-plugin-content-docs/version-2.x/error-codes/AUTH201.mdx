## Was dies bedeutet {#what-this-means}

Ihr Konto hat keine Berechtigung, diese Aktion auszuführen.

Es ist nichts verloren gegangen. Bitten Sie den Administrator Ihrer Filiale, Ihrer Benutzerrolle die Berechtigung für diese Aktion zu erteilen, und versuchen Sie es anschließend erneut.

## Ihre Daten {#your-data}

Es ist nichts verloren gegangen — Bestell- und Produktdaten sind nicht betroffen.

## Fehlerbehebung {#troubleshoot}

1. **An der Kasse:** Notieren Sie, welche Aktion abgelehnt wurde — etwa die Bearbeitung eines Produkts, eines Kunden oder einer Bestellung — und welches Konto angemeldet ist. Wenn der Fehler während der Synchronisierung von selbst auftrat, geben Sie einfach den Eintrag unter **Filialstatus → Protokolle** weiter: Er enthält die abgelehnte Anfrage. Geben Sie beide Angaben an Ihren Administrator weiter. In der Zwischenzeit können Sie weiterverkaufen, sofern die abgelehnte Aktion nicht Teil des Verkaufs war.
2. **Website-Administrator:** Entscheiden Sie zuerst, ob dieses Konto die Aktion ausführen dürfen soll. Falls nicht, funktioniert die Ablehnung wie vorgesehen — lassen Sie die Rolle unverändert und lassen Sie die Aktion von einem berechtigten Konto ausführen. Falls doch, öffnen Sie **WP Admin > POS > Einstellungen > Zugriff** und wählen Sie die Rolle des Kontos aus. Aktivieren Sie unter **Was ein Kassierer tun kann** (die Überschrift nennt die Rolle) die Aufgabe, zu der die abgelehnte Aktion gehört — **Den POS verwenden**, **Produkte erstellen und bearbeiten**, **Bestellungen verwalten**, **Kunden verwalten** usw. Ein Strich mit einer Anzeige wie **3 von 7** bedeutet, dass die Aufgabe nur teilweise erlaubt ist; durch Aktivieren werden auch die restlichen Berechtigungen erteilt. **Standardeinstellungen wiederherstellen** setzt eine Rolle auf die Berechtigungen einer Neuinstallation zurück — einer benutzerdefinierten Rolle gewährt WCPOS standardmäßig keinen POS-Zugriff, sodass dieser dort stattdessen entfernt wird.
3. **Website-Administrator:** Wenn sich das Konto anmelden kann, aber jede Anfrage zu Produkten, Kunden oder Bestellungen abgelehnt wird, prüfen Sie, ob ihm **mehr als eine Rolle** zugewiesen ist. Plugins zur Rollenbearbeitung wie Members wenden eine in einer beliebigen Rolle gesetzte *Verweigerung* auf das gesamte Konto an. Ein Administrator, der zugleich Kunde ist, verliert dadurch alle Berechtigungen, die in der Kundenrolle verweigert werden. Entfernen Sie die zusätzliche Rolle oder heben Sie die *Verweigerungen* auf; siehe [Ein Benutzer mit mehr als einer Rolle](/manage-your-store/staff-access#more-than-one-role).
4. **Zurück an der Kasse:** Melden Sie sich ab und wieder an, damit die neuen Berechtigungen wirksam werden. Versuchen Sie anschließend die abgelehnte Aktion erneut.
