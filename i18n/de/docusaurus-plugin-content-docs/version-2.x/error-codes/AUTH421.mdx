## Was das bedeutet {#what-this-means}

Der Server des Shops blockiert das Anmeldetoken auf allen Übertragungswegen, die diese App nutzen kann.

Die App hat bestätigt, dass der Shop erreichbar ist. Der Server (oder eine vorgeschaltete Firewall, ein Proxy oder ein Sicherheitsplugin) entfernt jedoch den Authorization-Header und blockiert das Token auch dann, wenn es als URL-Parameter gesendet wird. Es gibt keinen dritten Weg, ein Anmeldetoken zu übertragen. Das Problem muss daher auf dem Server behoben werden.

## Ihre Daten {#your-data}

Bestell- und Produktdaten sind nicht betroffen.

## Fehlerbehebung {#troubleshoot}

**Für Ihren Hosting-Anbieter / Server** — das Anmeldetoken hat keinen Übertragungsweg, solange der Server es nicht durchlässt:

1. Lassen Sie den Authorization-Header bis zu WordPress durch. Bei Apache genügt dafür meist eine Zeile: `SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1`.
2. Wenn die Website `.htaccess`-Rewrites verwendet, behalten Sie die von WordPress erzeugte RewriteRule-Zeile bei, die `HTTP_AUTHORIZATION` weitergibt — Sicherheitsplugins entfernen sie manchmal.
3. Wenn ein Proxy oder CDN vorgeschaltet ist, prüfen Sie dessen Liste erlaubter Header: Der Authorization-Anfrageheader muss an den Ursprungsserver weitergeleitet werden.
4. Wenn eine Web Application Firewall (WAF) URL-Parameter filtert, erlauben Sie den Autorisierungsparameter auf den REST-Routen unter `/wcpos/`.
