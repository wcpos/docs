## Was das bedeutet {#what-this-means}

Der Hosting-Anbieter begrenzt die Anfragerate der Kassen dieser Filiale.

Der Server antwortet weiterhin mit 429 (zu viele Anfragen), obwohl die App ihre Anfragen bereits verlangsamt und die Retry-After-Wartezeiten des Servers einhält. Mehrere Kassen an einem Internetanschluss teilen sich eine Adresse, sodass quellbezogene Ratenbegrenzungen sie als einen einzigen, sehr aktiven Client behandeln. Die Synchronisierung läuft automatisch weiter, bleibt aber zurück, bis das Limit erhöht wird.

## Ihre Daten {#your-data}

Bestell- und Produktdaten sind nicht betroffen.

## Fehlerbehebung {#troubleshoot}

1. Bitten Sie den Hosting-Anbieter, das Anfragelimit der REST API für den eigenen Datenverkehr des Shops zu erhöhen oder diesen davon auszunehmen — nennen Sie die statische IP des Shops, sofern vorhanden.
2. Bei Sicherheitsdiensten, die wiederholte Fehlerantworten (429) als Grund für eine Sperre zählen (zum Beispiel Sucuris IDS), muss die API des Shops möglicherweise von dieser Zählung ausgenommen werden.
3. Falls mehrere Kassen einen Anschluss teilen, weisen Sie den Hosting-Anbieter darauf hin: Eine IP steht hier für eine ganze Filiale, nicht für einen einzelnen Benutzer.
