## Was das bedeutet {#what-this-means}

Anstelle der API des Shops antwortet eine Bot-Schutzseite.

Die REST API des Shops gibt eine HTML-Prüfseite zurück (Bot-Schutz, CAPTCHA oder eine DDoS-Zwischenseite), obwohl die App JSON erwartet. Eine Kassen-App kann eine Browserprüfung nicht lösen. Die REST API des Shops muss im Schutzdienst auf die Freigabeliste gesetzt werden.

## Ihre Daten {#your-data}

Bestell- und Produktdaten sind nicht betroffen.

## Fehlerbehebung {#troubleshoot}

1. Ermitteln Sie anhand der Prüfseite den vorgeschalteten Schutzdienst. Cloudflare, Sucuri, Kinsta und andere kennzeichnen ihre Seiten jeweils mit ihrem Namen. Öffnen Sie dessen Einstellungen.
2. Setzen Sie die eigenen REST-API-Pfade des Shops (/wp-json/ und /?rest_route=) für API-Verkehr auf die Freigabeliste.
3. Fügen Sie in Cloudflare für die REST-API-Pfade eine WAF-Regel mit der Aktion **Überspringen** hinzu. Der Bot Fight Mode im kostenlosen Tarif kann durch keine Regel umgangen werden und muss deaktiviert werden. Die [Cloudflare-Anleitung](/troubleshooting/common-problems/cloudflare) enthält die genaue Regel und eine Prüfung mit `curl`.
4. Setzen Sie in den Bot-/Firewall-Einstellungen von Kinsta die REST-API-Pfade auf die Freigabeliste. Vermeiden Sie bei Sucuri für API-Routen den DDoS-Modus mit JavaScript-Prüfung.
