## Was das bedeutet {#what-this-means}

In Ihrem Shop ist ein Fehler aufgetreten, und diese Anfrage wurde nicht abgeschlossen.

Der Shop wurde erreicht, aber sein Server konnte die Anfrage nicht verarbeiten. Das Problem liegt auf der Website, nicht im POS. Versuchen Sie die Aktion erneut. Wenn das Problem weiterhin auftritt, bitten Sie Ihren Website-Administrator, **WooCommerce → Status → Protokolle** zu prüfen. Auf diesem Gerät ist nichts verloren gegangen.

## Ihre Daten {#your-data}

Löschen Sie die Daten dieses Geräts nicht — sie können Änderungen enthalten, die in Ihrem Shop noch nicht vorliegen. Eine gerade gesendete Änderung hat Ihren Shop möglicherweise nicht erreicht. Wenn dies wiederholt auftritt, verwenden Sie **Debug-Informationen kopieren** auf der Registerkarte **Protokolle** und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

**Im POS (Kassierer):** Klappen Sie den Protokolleintrag auf und notieren Sie Status, Endpunkt und serverCode — diese Angaben zeigen, was der Server beim Auftreten des Fehlers getan hat.

**Auf der Website (Website-Administrator / Hosting-Anbieter):**

1. Öffnen Sie WooCommerce → Status → Protokolle auf der Website und prüfen Sie das neueste fatal-errors-Protokoll für den Zeitraum um den Fehler. Eine Antwort der Klasse 500 hinterlässt dort fast immer einen PHP-Fehler.
2. Wenn der Fehler nach einem Plugin-, Theme- oder PHP-Update auf der Website erstmals auftrat, prüfen Sie zuerst diese Änderung als Ursache und machen Sie sie rückgängig oder deaktivieren Sie die betreffende Komponente.
3. Wenn die WooCommerce-Protokolle nichts zeigen, bitten Sie den Hosting-Anbieter um das PHP-Fehlerprotokoll des Servers für denselben Zeitraum.

**Danach wieder im POS:** Versuchen Sie die Aktion erneut.
