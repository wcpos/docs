## Was das bedeutet {#what-this-means}

Ihr Shop hat diese Änderung abgelehnt. Sie ist daher nicht im Shop angekommen.

Lesen Sie die Begründung des Shops. Wenn die Änderung unter **Shop-Zustand → Datenbank** aufgeführt ist, korrigieren Sie den Datensatz und tippen Sie auf **Erneut senden**, oder wählen Sie **Verwerfen**. Andernfalls wurde die Version des Shops wiederhergestellt — nehmen Sie die Änderung erneut vor, falls sie noch benötigt wird (siehe [SYNC202](/error-codes/SYNC202)). Eine abgelehnte Änderung wird nicht von selbst erneut versucht.

## Ihre Daten {#your-data}

Löschen Sie die Daten dieses Geräts nicht — sie können Änderungen enthalten, die in Ihrem Shop noch nicht vorliegen. Eine abgelehnte Änderung, die unter **Shop-Zustand → Datenbank** aufgeführt ist, bleibt dort, bis Sie sie erneut senden oder verwerfen. Eine abgelehnte Bearbeitung eines bestehenden Produkts, einer Variante, eines Kunden oder eines Gutscheins wird normalerweise automatisch rückgängig gemacht und stattdessen als [SYNC202](/error-codes/SYNC202) protokolliert. Wenn dieser Code angezeigt wird und die Änderung unter **Shop-Zustand → Datenbank** aufgeführt ist, wurde sie nicht automatisch rückgängig gemacht. Behandeln Sie sie dann wie jede andere unten beschriebene aufgeführte Änderung. Wenn dies wiederholt auftritt, verwenden Sie **Debug-Informationen kopieren** auf der Registerkarte **Protokolle** und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

1. Lesen Sie die Begründung des Shops — sie steht im Protokolleintrag und in der Zeile der Änderung unter **Shop-Zustand → Datenbank**.
2. Öffnen Sie **Shop-Zustand → Datenbank**. Wenn die Änderung dort nicht aufgeführt ist, wurde die Version des Shops auf diesem Gerät bereits wiederhergestellt, und es gibt nichts zu senden — siehe [SYNC202](/error-codes/SYNC202). Beheben Sie die genannte Ursache und nehmen Sie die Änderung anschließend erneut vor, falls sie noch benötigt wird.
3. Wenn die Änderung aufgeführt ist — eine Bestellung, ein auf diesem Gerät erstellter Datensatz oder eine Katalogänderung, die nicht automatisch rückgängig gemacht wurde — finden Sie sie unter **„… Änderungen haben Ihren Server nie erreicht“**. Die Begründung des Shops steht in ihrer Zeile. Beheben Sie die genannte Ursache direkt am Datensatz, etwa in einem Feld der Bestellung, während die Änderung weiterhin aufgeführt bleibt.
4. Kehren Sie zu **Shop-Zustand → Datenbank** zurück und tippen Sie in dieser Zeile auf **Erneut senden**. Dadurch wird die Änderung anhand der jetzt auf diesem Gerät vorhandenen Daten neu erstellt und gesendet.
5. Wenn die Änderung nicht mehr gewünscht ist, tippen Sie stattdessen auf **Verwerfen**: Die Version des Shops bleibt erhalten. Lesen Sie zuerst die Bestätigung — bei einem Datensatz, den der Shop nie gespeichert hat, löscht das Verwerfen ihn von diesem Gerät.
6. **Website-Administrator:** Wenn die Begründung besagt, dass der Benutzer die Änderung nicht vornehmen darf, fehlt seiner Rolle die entsprechende Berechtigung — siehe [AUTH201](/error-codes/AUTH201). Wenn die Begründung ein Feld nennt, das der POS nicht anzeigt, öffnen Sie denselben Datensatz in WP Admin. Ein anderes Plugin fügt möglicherweise eine Validierung hinzu, die für den POS nicht sichtbar ist. Wenn die Änderung weiterhin abgelehnt wird, verwenden Sie **Debug-Informationen kopieren** auf der Registerkarte **Protokolle** und wenden Sie sich an den Support.
