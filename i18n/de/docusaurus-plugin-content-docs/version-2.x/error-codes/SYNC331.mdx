## Was das bedeutet {#what-this-means}

Die Kopie eines Datensatzes auf diesem Gerät stimmt nicht mit der in Ihrem Shop überein. Ihre Eingaben sind davon nicht betroffen.

Verwenden Sie unter **Shop-Zustand → Datenbank** bei der betreffenden Liste **Löschen und erneut herunterladen**, um die Kopie auf diesem Gerät durch die aus dem Shop zu ersetzen. Bis dahin zeigt der Datensatz möglicherweise einen veralteten Preis oder Lagerbestand an. Prüfen Sie zuerst, dass nichts mehr auf das Senden wartet — siehe Fehlerbehebung.

## Ihre Daten {#your-data}

Verkäufe und noch nicht gesendete Änderungen sind nicht betroffen. Die Kopie des Datensatzes auf diesem Gerät zeigt möglicherweise einen veralteten Preis oder Lagerbestand an, bis sie ersetzt wird. Wenn dies wiederholt passiert, verwenden Sie **Debug-Informationen kopieren** im Tab **Protokolle** und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

1. Sie können weiter verkaufen. Öffnen Sie **Shop-Zustand → Datenbank**: Der Datensatz wird ganz oben genannt — mit **„… kann nicht aus Ihrem Shop heruntergeladen werden“**, wenn seine Kopie abweicht, oder mit **„… muss von diesem Gerät entfernt werden“**, wenn er im Shop gelöscht wurde.
2. Prüfen Sie vor dem Verkauf dieses Artikels seinen Preis und Lagerbestand anhand der Ware im Regal oder gemeinsam mit der für den Shop zuständigen Person (diese kann die Angaben mit WP Admin abgleichen).
3. Prüfen Sie vor dem Löschen unter **Shop-Zustand → Datenbank**, dass **Änderungen, die auf das Senden warten** bei 0 steht und weder der Bereich **„… Änderungen haben Ihren Server nie erreicht“** noch **„… Änderungen wurden zurückgehalten“** angezeigt wird. Diese Änderungen existieren nur auf diesem Gerät und können beim Löschen ihrer Liste verloren gehen. Warten Sie, bis der Zähler 0 erreicht, und klären Sie zuerst alle aufgeführten Änderungen ([SYNC201](/error-codes/SYNC201), [SYNC221](/error-codes/SYNC221)). Bevor Sie **Bestellungen** löschen, speichern Sie außerdem jeden offenen Warenkorb auf diesem Gerät mit **Auf dem Server speichern** (oder schließen Sie ihn ab). Ein Warenkorb, der nie in Ihrem Shop gespeichert wurde, existiert nur auf diesem Gerät und wird bei keiner dieser Prüfungen mitgezählt. Beim Löschen von **Bestellungen** wird er daher gelöscht. Wenn sich ein Warenkorb nicht speichern lässt, überspringen Sie die Zeile **Bestellungen** und wenden Sie sich an den Support. Öffnen Sie anschließend das Menü **⋮** der Liste, zu der der Datensatz gehört (zum Beispiel **Produkte**), und wählen Sie **Löschen und erneut herunterladen…**. Das Gerät verwirft seine Kopie und lädt die des Shops herunter; ein gelöschter Datensatz wird entfernt. Der Eintrag kann bis zur nächsten Hintergrundprüfung weiterhin angezeigt werden. Prüfen Sie deshalb, ob Preis und Lagerbestand jetzt übereinstimmen. Wenn der Hinweis danach einen Datensatz in einer anderen Liste nennt, wiederholen Sie diesen Schritt für diese Liste — einschließlich der vorherigen Prüfungen.
4. **Website-Administrator:** Wenn dieselben Datensätze nach dem erneuten Herunterladen immer wieder auftauchen, liegt das meist an einer Massenänderung, die die Speicher-Hooks von WooCommerce umgangen hat — etwa einem CSV-Import, einem Migrations-Plugin, WP-CLI oder direktem SQL. Nehmen Sie Änderungen möglichst über WooCommerce vor, damit die Prüfungen an der Kasse zuverlässig bleiben. WCPOS baut seine Integritätsdaten selbstständig neu auf, wenn dieselbe Abweichung wiederholt auftritt.
5. Wenn die Kasse nach dem erneuten Herunterladen weiterhin einen falschen Preis oder Lagerbestand anzeigt, verwenden Sie **Debug-Informationen kopieren** im Tab **Protokolle** und wenden Sie sich an den Support.
