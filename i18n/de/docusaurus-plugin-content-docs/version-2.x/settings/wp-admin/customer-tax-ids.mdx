**WP Admin:** `WP Admin → POS → Settings → General → Tax IDs`. Die ID wird anschließend beim Kunden hinzugefügt.

Kauft ein Kunde für ein Unternehmen ein, benötigt er häufig seine Steuer-ID auf dem Beleg: eine USt-IdNr., ABN, CPF oder GSTIN. Hinterlegen Sie sie einmal beim Kunden. Der POS übernimmt sie dann in jede seiner Bestellungen und druckt sie auf den Beleg. Sie können auch [eine Steuer-ID zu einem einzelnen Verkauf hinzufügen](#one-sale), selbst mit dem kostenlosen Plugin.

Für die meisten Filialen ist keine Einrichtung nötig. Der Abschnitt **Steuer-IDs** unter **WP Admin > POS > Einstellungen > Allgemein** legt lediglich fest, in welchem WordPress-Feld die Nummern gespeichert werden, damit ein bereits verwendetes Umsatzsteuer-Plugin weiterhin funktioniert. Siehe [Speicherort für Steuer-IDs wählen](#plugins-and-field-names).

## Eine Steuer-ID beim Kunden hinterlegen {#add}

:::info Mit WCPOS Pro
Um Kunden im POS hinzuzufügen und zu bearbeiten, benötigen Sie Pro. Mit dem kostenlosen Plugin fügen Sie die Steuer-ID stattdessen [zum Verkauf](#one-sale) hinzu.
:::

1. Öffnen Sie das Kundenformular:
   - **Neuer Kunde:** Tippen Sie im Warenkorb auf **+** und wählen Sie **Neuen Kunden hinzufügen**, oder drücken Sie auf der Seite **Kunden** neben der Suche auf **Neuen Kunden hinzufügen**.
   - **Bestehender Kunde:** Drücken Sie unter **Kunden** in der Zeile des Kunden auf den Pfeil zum Öffnen (›).
2. Drücken Sie auf **Steuer-ID**. Eine Zeile wird geöffnet.
3. Wählen Sie den **Typ**, geben Sie die **ID** ein und prüfen Sie das **Land**. Siehe [Die Steuer-ID-Zeile](#row).
4. **Neuer Kunde:** Drücken Sie auf **Kunden hinzufügen**. **Bestehender Kunde:** Hier gibt es keine Schaltfläche; jede Änderung wird sofort gespeichert. Die übrigen Felder des Formulars sind unter [Kunden](../../customers/index.mdx#add-new-customer) beschrieben.

## Eine Steuer-ID zu einem einzelnen Verkauf hinzufügen {#one-sale}

Das funktioniert auch mit dem kostenlosen Plugin.

<JourneyShot manifest={manifest} device="tablet" step={4} offsets={[[50, 0]]} maxWidth={420} alt="Der obere Bereich des Warenkorbs: Kunde, Gast und daneben ein Standort-Pin zum Bearbeiten der Adresse">

1. **Adresse** — der Standort-Pin neben dem Kundennamen. Er ist grau, solange für den Verkauf weder Straße noch Ort oder Postleitzahl hinterlegt sind. Sie können trotzdem darauf tippen.

</JourneyShot>

1. Tippen Sie oben im Warenkorb auf die Adresse neben dem Kundennamen. **Kundenadresse bearbeiten** wird geöffnet.
2. Drücken Sie auf **Steuer-ID**, wählen Sie den **Typ**, geben Sie die **ID** ein und prüfen Sie das **Land**, wie unter [Die Steuer-ID-Zeile](#row) beschrieben.
3. Drücken Sie auf **Schließen**. Die Nummer wurde bereits während der Eingabe in dieser Bestellung gespeichert und wird auf deren Beleg gedruckt.

<JourneyShot manifest={cartManifest} device="tablet" step={7} offsets={[[80, 0], [250, 0], [200, 0], [200, 0], [285, 0], [0, 0], [0, -40]]} alt="Kundenadresse bearbeiten für Linda Smith: Name, E-Mail und Telefon, die Felder der Rechnungsadresse mit Land und Bundesland, die Lieferadresse, die Schaltflächen Firma und Steuer-ID sowie Schließen und Kunden ebenfalls aktualisieren">

1. **Name** — Vor- und Nachname. Darunter befinden sich **E-Mail** und **Telefon**.
2. **Rechnungsadresse** — **Bearbeiten** öffnet die Adressfelder, **Entfernen** leert sie.
3. **Land** — wählen Sie aus der Liste. Bei mehr als zehn Ländern können Sie die Liste durchsuchen.
4. **Bundesland** — eine Liste für Länder, für die eine solche verfügbar ist, ansonsten ein Textfeld.
5. **Lieferadresse** — **Wie Rechnungsadresse**, bis Sie auf **Andere Adresse verwenden** drücken.
6. **Steuer-ID** — fügt dieser Bestellung eine [Steuer-ID-Zeile](#row) hinzu.
7. **Kunden ebenfalls aktualisieren** — speichert diese Angaben auch im Kundenprofil.

</JourneyShot>

Um die Nummer auch im Kundenprofil zu speichern, drücken Sie auf **Kunden ebenfalls aktualisieren**. Diese Schaltfläche erscheint bei Kunden mit einem Konto und nur für Kassierer, die Kunden bearbeiten dürfen. Siehe [Adresse der Bestellung bearbeiten](../../pos/cart/index.mdx#address).

## Die Steuer-ID-Zeile {#row}

Die Zeile ist im Kundenformular und im hier gezeigten Dialog **Kundenadresse bearbeiten** des Warenkorbs identisch.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[0, 0], [40, -38], [24, -38], [64, -39], [-24, 0]]} maxWidth={560} alt="Kundenadresse bearbeiten mit ausgefüllter Steuer-ID-Zeile: Typ EU-USt-IdNr., ID DE123456789, Land DE, daneben Entfernen und darunter die Schaltfläche Steuer-ID">

1. **Steuer-ID** — fügt eine Zeile hinzu. Drücken Sie erneut darauf, um eine zweite Nummer hinzuzufügen, etwa Codice Fiscale und Partita IVA eines italienischen Kunden.
2. **Typ** — die Art der Nummer. In einer neuen Zeile ist zunächst der erste Typ für das Rechnungsland des Kunden ausgewählt. Solange die Rechnungsadresse leer ist, wird das Land Ihrer Filiale verwendet. Passt kein Typ zum Land, wird **Sonstige** ausgewählt. Siehe [Steuer-ID-Typen](#supported-types).
3. **ID** — die Nummer. Das leere Feld zeigt ein Beispiel für das richtige Format des Typs. Lange Nummern lassen sich innerhalb des Feldes scrollen. Beim Speichern werden Leerzeichen entfernt und Buchstaben in Großbuchstaben umgewandelt.
4. **Land** — zwei Buchstaben. Bei der Auswahl eines Typs wird das Feld ausgefüllt: **GB** für **UK-USt-IdNr.**, **BR** für **Brasilien CPF**. Bei **EU-USt-IdNr.** und **Sonstige** wird das Rechnungsland übernommen. Prüfen Sie es daher bei EU-Kunden aus einem anderen Mitgliedstaat.
5. **Entfernen** — entfernt die Zeile.

</JourneyShot>

<JourneyShot manifest={manifest} device="tablet" step={2} offsets={[[-16, 0], [0, 0]]} maxWidth={520} alt="Die geöffnete Typ-Liste in einer neuen Steuer-ID-Zeile für eine Filiale in den USA: oben US EIN mit Häkchen, darunter eine Trennlinie, dann EU-USt-IdNr., UK-USt-IdNr., Australien ABN und die weiteren Typen">

1. **Typen für das Land** — oberhalb der Linie: die Typen, die zum Rechnungsland oder zum Land Ihrer Filiale passen. Hier befindet sich die Filiale in den USA, daher nur **US EIN**.
2. **Alle anderen Typen** — unterhalb der Linie, beginnend mit **EU-USt-IdNr.**.

</JourneyShot>

Eine EU-USt-IdNr. wird mit Länderkennzeichen eingegeben, etwa **DE123456789**. Wenn Sie es weglassen, stellt die Filiale beim Speichern das **Land** voran. Das gilt nur für **EU-USt-IdNr.** und **UK-USt-IdNr.**.

## Was in der Bestellung gespeichert bleibt {#tax-ids-are-copied-onto-orders}

Wenn Sie einen Kunden für einen Verkauf auswählen, übernimmt der POS dessen Steuer-IDs in die Bestellung. Sie erscheinen unter [der Adresse der Bestellung](../../pos/cart/index.mdx#address), wo Sie sie für diesen Verkauf ändern können. Die Bestellung behält die Nummern, die beim Verkauf verwendet wurden:

- Wenn Sie die Steuer-ID eines Kunden später ändern, bleiben dessen frühere Bestellungen unverändert. Ein alter Beleg wird daher beim erneuten Drucken wie ursprünglich ausgegeben.
- Eine Steuer-ID, die Sie im Warenkorb ändern oder hinzufügen, wird für diese Bestellung anstelle der Steuer-ID aus dem Kundenprofil verwendet.
- Wenn Sie die Steuer-IDs einer Bestellung ändern, betrifft das nur diese Bestellung. Sie werden nicht erneut aus dem Kundenprofil übernommen.
- Ein Verkauf an einen Gast hat keine Steuer-ID, sofern Sie dem Verkauf keine hinzufügen.

## Auf dem Beleg {#on-receipts}

Die Vorlagen **Standardbeleg**, **Detaillierter Beleg**, **Rechnung** und **Angebot** sowie die detaillierten Thermobelege drucken die Steuer-IDs zusammen mit den Kundendaten. Jede Nummer hat ihre eigene Bezeichnung, etwa **USt-IdNr.**, **ABN** oder **CPF**: siehe die Tabelle unter [Steuer-ID-Typen](#supported-types). Wie Sie sie in Ihrer eigenen Vorlage drucken, erfahren Sie unter [Steuer-ID-Objekte](../../receipts/receipt-data.mdx#tax-id-objects).

## Kunden anhand der Steuer-ID finden {#finding-customers-by-tax-id}

Geben Sie die Nummer in die Kundensuche im Warenkorb oder auf der Seite **Kunden** ein. Die Suche findet auch Nummern, die ein Umsatzsteuer-Plugin bereits vor Ihrem Einsatz von WCPOS gespeichert hat, sofern es unter [Speicherort für Steuer-IDs wählen](#plugins-and-field-names) aufgeführt ist. Siehe [Kundensuche](../../customers/index.mdx#find).

## Speicherort für Steuer-IDs wählen {#plugins-and-field-names}

WCPOS speichert Steuer-IDs dort, wo Ihr Umsatzsteuer-Plugin sie bereits ablegt. So erscheint eine an der Kasse eingegebene Nummer im Plugin und eine vom Plugin gespeicherte Nummer im POS. Sie benötigen diesen Abschnitt nur, wenn diese Zuordnung nicht stimmt.

Öffnen Sie zur Prüfung **WP Admin > POS > Einstellungen > Allgemein** und scrollen Sie zu **Steuer-IDs**. Der Hinweis zeigt an, ob WCPOS ein Umsatzsteuer-Plugin gefunden hat.

<JourneyShot manifest={manifest} device="desktop" step={5} offsets={[[-60, 0], [-60, 0], [76, 0], [166, 0], [96, 0], [108, 0]]} alt="Der Abschnitt Steuer-IDs unter Kunden auf der Seite Allgemein: der Hinweis Kein Plugin erkannt und der geöffnete Bereich Erweitert: anderen Feldnamen verwenden mit einer Tabelle mit Typ, Verwendeter Feldname, Quelle und Überschreibung; jede Zeile zeigt Integriert und ein leeres Feld für die Überschreibung">

1. **Kein Plugin erkannt** — WCPOS hat kein Umsatzsteuer-Plugin gefunden und verwendet seine integrierten Feldnamen.
2. **Erweitert: anderen Feldnamen verwenden** — öffnet die folgende Tabelle. Siehe [Anderen Feldnamen verwenden](#choosing-the-field-name-yourself).
3. **Typ** — eine Zeile pro Steuer-ID-Typ.
4. **Verwendeter Feldname** — das Feld, in dem WCPOS diesen Typ derzeit speichert.
5. **Quelle** — wie dieser Feldname ausgewählt wurde, hier für jeden Typ **Integriert**.
6. **Überschreibung** — Ihr eigener Feldname; bleibt das Feld leer, wird der Standard verwendet.

</JourneyShot>

<details>
<summary>Wie WCPOS das Feld auswählt und welche Plugins es erkennt</summary>

WordPress speichert die Steuer-ID eines Kunden in einem benannten Feld (einem Metaschlüssel). Umsatzsteuer-Plugins verwenden dafür jeweils eigene Namen. Der Hinweis lautet:

- **Automatisch erkannt** — nennt das gefundene Plugin mit „… ist installiert.“ WCPOS speichert Steuer-IDs im Format einer Umsatzsteuer-ID in dem Feld, das dieses Plugin ausliest. Sie müssen nichts tun.
- **Kein Plugin erkannt** — WCPOS verwendet seine integrierten Feldnamen oder das Feld, das bereits in Ihren jüngsten Bestellungen verwendet wird.

Für jeden Typ verwendet WCPOS den ersten zutreffenden Eintrag aus dieser Liste:

1. Ihren eigenen Feldnamen, falls Sie unter [Anderen Feldnamen verwenden](#choosing-the-field-name-yourself) einen festgelegt haben.
2. Das Feld eines erkannten Plugins.
3. Wenn kein Plugin erkannt wurde, das in Ihren letzten 200 Bestellungen am häufigsten verwendete Feld.
4. Den integrierten Feldnamen.

Folgende Plugins werden erkannt:

- WooCommerce EU VAT Number
- Aelia EU VAT Assistant, einschließlich der Information, ob Aelia die Nummer als gültig eingestuft hat
- WPFactory EU/UK VAT Manager
- WooCommerce Germanized und Germanized Pro
- Brazilian Market on WooCommerce und Extra Checkout Fields for Brazil
- NIF/CIF Spain for WooCommerce

Die integrierten Feldnamen:

| Typ | Feldname |
|---|---|
| EU-USt-IdNr., UK-USt-IdNr., Saudi-Arabien USt-IdNr., Australien ABN, Kanada GST/HST, US EIN, Sonstige | `_billing_vat_number` |
| Brasilien CPF | `_billing_cpf` |
| Brasilien CNPJ | `_billing_cnpj` |
| Indien GSTIN | `_billing_gstin` |
| Italien Codice Fiscale | `_billing_cf` |
| Italien P. IVA | `_billing_piva` |
| Spanien NIF/CIF | `_billing_nif` |
| Argentinien CUIT | `_billing_cuit` |

</details>

### Anderen Feldnamen verwenden {#choosing-the-field-name-yourself}

Tun Sie dies nur, wenn Ihr Plugin Steuer-IDs unter einem Namen speichert, den WCPOS nicht kennt.

<details>
<summary>Den Feldnamen ändern</summary>

Öffnen Sie im Abschnitt **Steuer-IDs** den Bereich **Erweitert: anderen Feldnamen verwenden**. Er zeigt eine Zeile pro Typ:

- **Typ** — die Art der Steuer-ID.
- **Verwendeter Feldname** — das Feld, in dem WCPOS diesen Typ derzeit speichert.
- **Quelle** — **Plugin** (von einem erkannten Plugin), **Integriert** (WCPOS-Standard) oder **Benutzerdefiniert** (Ihre Überschreibung).
- **Überschreibung** — geben Sie den Feldnamen ein, den Ihr Plugin verwendet. Das Feld schlägt Namen vor, die WCPOS von anderen Plugins kennt. Die Eingabe wird gespeichert, sobald Sie einen Vorschlag auswählen oder nach der Eingabe eines eigenen Namens die Eingabetaste drücken oder das Feld verlassen. Es gibt keine Schaltfläche zum Speichern.

Um wieder den automatisch gewählten Namen zu verwenden, leeren Sie das Feld **Überschreibung**. Es zeigt den Hinweis „(leer lassen, um den Standard zu verwenden)“. Die Zeile **Erweitert: anderen Feldnamen verwenden** zeigt, wie viele Überschreibungen aktiv sind.

</details>

:::note
Hier erscheinen nur Steuer-IDs von Kunden. Die Nummern Ihres eigenen Unternehmens, etwa eine USt-IdNr., KVK- oder SIRET-Nummer, legen Sie unter [Steuer-IDs der Filiale](./store-tax-ids.mdx) fest.
:::

## Wenn etwas nicht funktioniert {#goes-wrong}

<JourneyShot manifest={manifest} device="tablet" step={3} offsets={[[-28, 0]]} maxWidth={560} alt="Eine Steuer-ID-Zeile mit Typ EU-USt-IdNr. und ID DE1234 sowie der Warnung unter der ID: Das Format entspricht nicht dem ausgewählten Typ.">

1. **Die Formatwarnung** — erscheint unter der **ID**. Was Sie tun können, steht im ersten Punkt unten.

</JourneyShot>

- **Das Format entspricht nicht dem ausgewählten Typ.** — prüfen Sie zuerst den **Typ** und dann gemeinsam mit dem Kunden, ob in der Nummer eine Ziffer fehlt. Es handelt sich nur um eine Warnung; die Nummer wird trotzdem gespeichert. Die Warnung erscheint auch bei einer EU-USt-IdNr. ohne Länderkennzeichen. Die Filiale stellt beim Speichern das **Land** voran, prüfen Sie daher, ob das **Land** richtig ist. Der POS prüft nur das Format der Nummer, niemals, ob sie von einer Steuerbehörde vergeben wurde.
- **Ein alter Beleg zeigt die alte Nummer** — die Bestellung behält die Nummer, die beim Verkauf verwendet wurde. Ändern Sie die Steuer-ID in dieser Bestellung, nicht im Kundenprofil.
- **Keine Steuer-ID auf dem Beleg** — der Verkauf erfolgte an einen Gast oder der Kunde hatte zum Zeitpunkt des Verkaufs keine Steuer-ID. Fügen Sie vor der Zahlung eine zum Verkauf hinzu und prüfen Sie, ob Ihre Belegvorlage Kundendaten anzeigt.
- **Ihr Umsatzsteuer-Plugin zeigt die an der Kasse eingegebenen Nummern nicht an** — öffnen Sie unter **WP Admin > POS > Einstellungen > Allgemein > Steuer-IDs** den Bereich **Erweitert: anderen Feldnamen verwenden**. Vergleichen Sie **Verwendeter Feldname** mit dem Feld, das Ihr Plugin ausliest. Legen Sie eine **Überschreibung** fest, wenn die Felder voneinander abweichen.
- **Kunden ebenfalls aktualisieren fehlt** — der Verkauf erfolgt an einen Gast oder Ihre WordPress-Rolle darf keine Kunden bearbeiten. Die Steuer-ID wird trotzdem in der Bestellung gespeichert.
- **Neuen Kunden hinzufügen ist ausgegraut** — dafür benötigen Sie Pro und eine Rolle, die Kunden anlegen darf.
