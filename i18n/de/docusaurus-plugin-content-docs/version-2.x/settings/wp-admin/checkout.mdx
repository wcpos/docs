**WP Admin:** `WP Admin → POS → Settings → Checkout`. Kassierer sehen diesen Bereich nicht.

Die Checkout-Einstellungen bestimmen, wie ein Verkauf bezahlt wird und was anschließend mit der Bestellung geschieht.

Hier können Sie Folgendes tun:

- [Eine Zahlungsart an der Kasse anbieten](#enabling-a-gateway)
- [Festlegen, welche Zahlungsart zuerst erscheint](#reordering-gateways)
- [Eine Kachel umbenennen oder Barbeträge runden](#gateway-pos-settings)
- [Den Bestellstatus nach dem Kassiervorgang festlegen](#order-status)
- [Verkäufe über den verfügbaren Bestand hinaus verhindern](#prevent-overselling) (bei einer neuen Filiale deaktiviert)
- [Festlegen, welche E-Mails eine POS-Bestellung versendet](#email-notifications)

Benutzerdefinierte Felder richten Sie nicht hier ein: Fügen Sie ein solches Feld über **+ Benutzerdefiniertes Feld** in den [Bestelldetails](../../pos/cart/order-actions.mdx#order-meta) zu einer Bestellung hinzu oder über das [Kundenformular](../../customers/index.mdx#add-new-customer) zu einem Kundenkonto.

Änderungen auf dieser Seite werden sofort gespeichert: Zunächst erscheint **Wird gespeichert**, dann **Gespeichert**. Eine Schaltfläche zum Speichern gibt es nicht. Die einzige Ausnahme ist der Dialog [POS-Einstellungen](#gateway-pos-settings) eines Zahlungsgateways, in dem Sie **Speichern** drücken.

Die Kassen lesen diese Einstellungen beim Start des POS ein. Laden Sie den POS daher nach jeder Änderung an jeder Kasse neu.

## Die Seite auf einen Blick {#at-a-glance}

Von oben nach unten finden Sie auf der Seite **Überverkäufe verhindern**, die Schalter **Admin-E-Mails**, **Kunden-E-Mails** und **Kassierer-E-Mails** sowie die Tabelle **Zahlungsgateways**. Verwendet Ihre Filiale die ältere Bestellspeicherung von WooCommerce, erscheint oben außerdem eine Warnung; siehe [Bestellspeicherung](#order-storage).

## Zahlungsgateways {#payment-gateways}

Die Tabelle **Zahlungsgateways** listet Ihre Zahlungsarten auf, die WooCommerce als Gateways bezeichnet: alle auf Ihrer Website installierten sowie die POS-eigenen Zahlungsarten **Bargeld** und **Karte**. Jede Zeile steht für eine Zahlungsart und enthält den Schalter **Aktiviert**, um sie an der Kasse anzubieten, ihren **Bestellstatus** und einen Ziehgriff zum Festlegen ihrer Position. Die übrigen Spalten sind im folgenden aufklappbaren Abschnitt beschrieben.

<details>
<summary>Spalten der Zahlungsgateway-Tabelle</summary>

| Spalte | Funktion |
|--------|-------------|
| Ziehgriff | Ziehen Sie die Zeile nach oben oder unten, um die entsprechende Kachel an der Kasse zu verschieben. Siehe [Festlegen, welche Zahlungsart zuerst erscheint](#reordering-gateways). |
| **Standard** | Das auf der eigenen Zahlungsseite Ihrer Filiale vorausgewählte Zahlungsgateway. Diese Seite wird auf dem [Tab „Legacy“](../../pos/checkout/legacy-tab.mdx) angezeigt. Nur ein aktiviertes Zahlungsgateway kann ausgewählt werden. **Bargeld** erscheint auf dieser Seite nie: Barzahlungen werden ausschließlich über die zugehörige Kachel entgegengenommen. Die Kacheln auf dem Tab „Zahlungen“ verwenden diese Einstellung nicht; siehe [Festlegen, welche Zahlungsart zuerst erscheint](#reordering-gateways). |
| **Zahlungsgateway** | Der Name des Zahlungsgateways. |
| **Zahlungsgateway-ID** | Die Kennung in WooCommerce, etwa `pos_cash`. Sie benötigen sie nur, wenn ein Entwickler danach fragt. |
| **Aktiviert** | Legt fest, ob die Zahlungsart an der Kasse angeboten wird. |
| **Bestellstatus** | Der Status, den ein auf diese Weise bezahlter Verkauf erhält. Siehe [Bestellstatus](#order-status). |
| **⋮** | **POS-Einstellungen** und bei allen Zahlungsgateways außer Bargeld und Karte auch **WooCommerce-Einstellungen**. Siehe [Eine Kachel umbenennen oder Barbeträge runden](#gateway-pos-settings). |

</details>

:::note Kostenlose Version und Pro
Ohne [WCPOS Pro](../../getting-started/pro-license.mdx) lassen sich nur **Bargeld** und **Karte** aktivieren. In allen anderen Zeilen sind der Schalter **Aktiviert**, **Bestellstatus** und **⋮** ausgegraut. Ein Hinweis über der Tabelle erklärt dies und enthält den Link **Upgrade auf Pro**.
:::

### Eine Zahlungsart an der Kasse anbieten {#enabling-a-gateway}

**Bevor Sie beginnen:** Eine Zahlungsart aus einem Plugin, etwa für ein Kartenlesegerät, erscheint erst in der Tabelle, wenn dieses Plugin auf Ihrer Website installiert und aktiv ist. Unter [Zahlungsgateways](../../payment/gateways/index.mdx) finden Sie die vom POS unterstützten Zahlungsgateways mit ihren jeweiligen Einrichtungsanleitungen.

1. Suchen Sie die Zahlungsart in der Tabelle **Zahlungsgateways**.
2. Schalten Sie **Aktiviert** ein.
3. Laden Sie den POS neu. Die Kasse liest Ihre Zahlungsarten bei jedem Start ein.

Die Zahlungsart erscheint nun beim Kassieren als Kachel oder, wenn sie eine eigene Zahlungsseite verwendet, als Zahlungsgateway auf dem [Tab „Legacy“](../../pos/checkout/legacy-tab.mdx).

### Festlegen, welche Zahlungsart zuerst erscheint {#reordering-gateways}

Verschieben Sie eine Zeile mit ihrem Ziehgriff. Die Kacheln an der Kasse folgen dieser Reihenfolge. Wenn Sie den Kassiervorgang für einen neuen Verkauf öffnen, ist die erste verwendbare Kachel bereits ausgewählt. Soll für die meisten Verkäufe Bargeld vorausgewählt sein, ziehen Sie Bargeld ganz nach oben. Die Spalte **Standard** hat keinen Einfluss auf die ausgewählte Kachel; nur die Reihenfolge zählt.

Hier sehen Sie Ihre Einstellungen an der Kasse im Zahlungsbereich:

3. **Zu zahlen** — der noch offene Restbetrag. Ist für Bargeld eine **Rundung** eingestellt, fordert die Kasse den gerundeten Betrag an; siehe [Bargeldrundung](../../payment/index.mdx#cash-rounding).
4. **Aufteilen** — teilt die Bestellung in mehrere Zahlungen auf.

Die Bedienung dieser Seite durch Kassierer ist unter [Der Zahlungsbereich](../../pos/checkout/payment-methods.mdx) beschrieben.

### Eine Kachel umbenennen oder Barbeträge runden {#gateway-pos-settings}

**⋮ > POS-Einstellungen** öffnet einen Dialog für diese Zahlungsart. Er beeinflusst die Anzeige an der Kasse, aber nichts auf Ihrer Website:

- **Titel** — der Name auf der Kachel.
- **Beschreibung** — wird mit dem Zahlungsgateway gespeichert. Die Kasse zeigt sie nicht an; auf der Kachel erscheint nur der **Titel**.
- **Rundung** (nur Bargeld) — rundet Barbeträge auf die verfügbaren Münzwerte: **0.05**, **0.10**, **0.25**, **0.50**, **1**, **5** oder **10**. Standardmäßig ist **Keine Rundung** eingestellt. Bei Karten- und Onlinezahlungen bleibt der genaue Betrag erhalten. Siehe [Bargeldrundung](../../payment/index.mdx#cash-rounding).

Drücken Sie **Speichern**, um die Änderung zu übernehmen, oder **Abbrechen**.

**⋮ > WooCommerce-Einstellungen** öffnet die eigenen Einstellungen des Zahlungsgateways in WooCommerce. Dort verbinden Sie das Konto und legen fest, was Ihre Website anzeigt.

### POS und Onlineshop {#pos-vs-online-store}

Der Schalter **Aktiviert** ist hier unabhängig von den Zahlungseinstellungen in WooCommerce. Eine Zahlungsart kann folgendermaßen eingestellt sein:

- **Im POS aktiviert, online deaktiviert** — beispielsweise Bargeld, das eine Website nicht entgegennehmen kann.
- **Online aktiviert, im POS deaktiviert** — eine Zahlungsart, bei der der Kunde am Computer sein muss, etwa PayPal Checkout.
- **Für beide aktiviert.**

:::note
Das Plugin eines Zahlungsgateways muss installiert und aktiv sein, damit es in der Tabelle erscheint. Unter `WP Admin > WooCommerce > Einstellungen > Zahlungen` muss es nicht aktiviert sein: Der POS listet alle Zahlungsgateways auf, die WooCommerce kennt. Fehlt eines, prüfen Sie, ob das zugehörige Plugin aktiv ist.
:::

## Bestellstatus {#order-status}

Jede Zahlungsart hat ihren eigenen **Bestellstatus**: Diesen erhält eine Bestellung, wenn der Kassiervorgang endet. **In Bearbeitung** und **Abgeschlossen** markieren die Bestellung als bezahlt; bei **Wartend** und **Zahlung ausstehend** bleibt sie unbezahlt. Wählen Sie den Status danach, wie das Geld eingeht:

- **Geld wird an der Kasse entgegengenommen:** **In Bearbeitung** oder **Abgeschlossen**.
- **Geld wird vom Kunden selbstständig überwiesen**, ohne Zahlungslink: **Wartend**, die Standardeinstellung für BACS und Scheck.
- **Später über den Zahlungslink der Bestellung bezahlen**, also ein Ablauf für den „Kauf auf Rechnung“, beispielsweise mit BACS: **Zahlung ausstehend**. Die Bestellung bleibt unbezahlt, bis der Kunde über den Link bezahlt.

So ändern Sie den Status:

1. Suchen Sie die Zahlungsart in der Tabelle **Zahlungsgateways**.
2. Wählen Sie den Status in der Spalte **Bestellstatus** aus.

Die Änderung wird sofort gespeichert und gilt für neue Verkäufe, nicht für bereits erfasste Bestellungen.

Ein beendeter Kassiervorgang bedeutet nicht, dass die Bestellung bezahlt ist. Sobald die an der Kasse erfassten Zahlungen den Gesamtbetrag decken, endet der Kassiervorgang und die Bestellung erhält diesen Status. Eine Bestellung mit **Wartend** oder **Zahlung ausstehend** ist damit an der Kasse fertig bearbeitet, aber noch unbezahlt.

<details>
<summary>Einen Zahlungslink senden</summary>

Eine Bestellung mit dem Status „Zahlung ausstehend“ kann in WooCommerce weiterhin bezahlt werden: Sie ist nicht als bezahlt markiert, der Bestand wird nicht verringert und der Zahlungslink funktioniert, solange der Status „Zahlung ausstehend“ bleibt. Der POS versendet den Link nicht. Die Bestellung benötigt eine Kunden-E-Mail-Adresse. Senden Sie die Rechnung per E-Mail aus der Bestellansicht in WooCommerce oder teilen Sie den Link auf anderem Weg.

</details>

**Bargeld**, **Karte** und die meisten Zahlungsgateways sind zunächst auf **Abgeschlossen** eingestellt, weil das Geld an der Kasse entgegengenommen wird. **BACS** (Direkte Banküberweisung) und **Scheck** sind zunächst auf **Wartend** eingestellt, weil das Geld später eingeht. Sie können jeden WooCommerce-Bestellstatus auswählen. Hat eine ältere POS-Version einen gemeinsamen Status für alle Zahlungsgateways festgelegt, beginnt jedes Zahlungsgateway stattdessen mit diesem Status.

### Wie die Kasse den Status behandelt {#order-status-at-the-till}

An der Kasse erfasste Zahlungen sind Zahlungen über Bargeld, Karte, Kartenlesegeräte und Kacheln wie Direkte Banküberweisung. Sobald sie den Gesamtbetrag decken, erhält die Bestellung den für das Zahlungsgateway ausgewählten Status.

<details>
<summary>Aufgeteilte Zahlungen und Zahlungsgateways auf dem Tab „Legacy“</summary>

- **Ein Verkauf mit aufgeteilten Zahlungen** erhält den Status des Zahlungsgateways mit der höchsten Zahlung. Bei gleichen Beträgen zählt die früheste dieser Zahlungen.
- **Ein Zahlungsgateway auf dem [Tab „Legacy“](../../pos/checkout/legacy-tab.mdx)**: Der POS beendet den Verkauf, sobald die Bestellung diesen Status erreicht.

</details>

<details>
<summary>Das Zahlungsgateway Email Invoice und „Zahlung ausstehend“</summary>

Das **Email Invoice Gateway** versendet die Rechnung und setzt selbst **Zahlung ausstehend**. Lassen Sie seinen **Bestellstatus** daher auf einem anderen Wert. Ist er auf **Zahlung ausstehend** gesetzt, zeigt die Kasse keine Ansicht **Rechnung gesendet** an, und bei der Bestellung fehlen **Erneut senden** und **Rechnung stornieren**. Siehe [Email Invoice](../../payment/gateways/email-invoice.mdx#set-up).

</details>

## Überverkäufe verhindern {#prevent-overselling}

**Überverkäufe verhindern** sorgt dafür, dass der POS nicht mehr von einem Produkt verkauft, als vorhanden ist. Bei einer neuen Filiale ist diese Einstellung **deaktiviert**. Solange Sie sie nicht aktivieren, verkauft die Kasse alles, was im Warenkorb liegt. So aktivieren Sie die Einstellung:

1. Öffnen Sie `WP Admin > POS > Einstellungen > Kasse`.
2. Aktivieren Sie **Überverkäufe verhindern** und warten Sie auf **Gespeichert**.
3. Laden Sie den POS an jeder Kasse neu.

Das Deaktivieren funktioniert genauso. Produkte, für die Lieferrückstände erlaubt sind, können weiterhin verkauft werden; siehe [Lieferrückstände haben weiterhin Vorrang](#prevent-overselling-backorders).

Bei aktiviertem Schalter fügt die Kasse nicht mehr von einem Produkt hinzu, als vorhanden ist. Solange bei einer Warenkorbposition Bestand fehlt, ist der Kassiervorgang gesperrt. Außerdem prüft Ihr Shop den Bestand erneut vor jeder Zahlung. Das Speichern eines noch offenen Verkaufs wird nie abgelehnt.

<details>
<summary>Die drei Bestandsprüfungen und was der Kassierer sieht</summary>

1. **Wenn ein Produkt in den Warenkorb gelegt wird.** Der Kassierer kann ein Produkt nicht über den verfügbaren Bestand hinaus hinzufügen oder seine Menge entsprechend erhöhen. Die Kasse meldet **Nur 3 für Hoodie verfügbar** oder **Hoodie nicht vorrätig** und lässt den Warenkorb unverändert. Alle Meldungen finden Sie unter [Nicht vorrätige Produkte](../../pos/product-panel/display-settings.mdx#show-out-of-stock-products).
2. **Während sich der Verkauf im Warenkorb befindet.** Sinkt der Bestand bei einem offenen Verkauf, etwa weil eine andere Kasse das letzte Stück verkauft hat, führt ein Hinweis über den Warenkorbpositionen jede betroffene Position mit **Reduzieren** oder **Entfernen** auf. Die Position zeigt die verfügbare Menge an und **Kasse** ist ausgegraut, bis der Warenkorb korrigiert wurde. Eine Zahlung im Zahlungsbereich wird auf dieselbe Weise abgelehnt. Siehe [Wenn der Kassiervorgang gesperrt ist](../../pos/cart/line-items.mdx#checkout-blocked).
3. **Bei der Zahlungsannahme, in Ihrem Shop.** Bevor Geld fließt und erneut beim Abschluss des Verkaufs prüft Ihr Shop den Bestand für die Bestellung. Waren die Zahlen der Kasse veraltet, lehnt der Shop die Zahlung mit **Bestellung kann nicht abgeschlossen werden: 1 Artikel überschreiten den verfügbaren Bestand.** ab. Der POS zeigt diesen Grund an. Auf dem [Tab „Legacy“](../../pos/checkout/legacy-tab.mdx) erscheint der Grund auf der Zahlungsseite des Shops. Ein später von einer Offline-Kasse übermittelter Verkauf kann ebenso abgelehnt werden; siehe [Bestellung nicht gespeichert — vom Shop abgelehnt](../../support/store-health.mdx#order-refused).

Ihr Shop prüft einen Verkauf nicht, wenn dieser lediglich gespeichert wird. Offene Verkäufe werden daher ungehindert synchronisiert.

</details>

<details>
<summary>Warum Ihr Shop zusätzlich zur Kasse prüft</summary>

WooCommerce prüft den Bestand nicht, wenn eine Bestellung über seine REST API eingeht. Genau darüber sendet der POS Bestellungen. Zwei stark genutzte Kassen oder eine Kasse mit veralteten Bestandszahlen könnten mehr verkaufen, als vorhanden ist. Die Prüfung in Ihrem Shop erkennt, was die Kasse nicht sehen konnte.

</details>

### Wie die Bestandsgrenze bestimmt wird {#prevent-overselling-stock-rules}

Die Grenze hängt davon ab, ob der Bestand für das Produkt oder für jede Variante einzeln verwaltet wird.

<details>
<summary>Bestandsregeln nach Produkteinrichtung</summary>

| Produkteinrichtung | Bei aktiviertem Schalter |
|---|---|
| **Bestandsverwaltung aktiv** (eine Menge wird erfasst) | Verkäufe werden bei Erreichen der Bestandsmenge gestoppt. Mehrere Positionen desselben Produkts zählen zur selben Grenze. |
| **Variante verwaltet eigenen Bestand** | Die Grenze gilt pro Variante. |
| **Variante verwendet den Bestand des übergeordneten Produkts** | Alle Varianten des Produkts teilen sich die Menge des übergeordneten Produkts. |
| **Keine Bestandsverwaltung** | Der Lagerstatus entscheidet: **Nicht vorrätig** kann nicht verkauft werden; **Vorrätig** und **Im Lieferrückstand** können verkauft werden. |

</details>

### Lieferrückstände haben weiterhin Vorrang {#prevent-overselling-backorders}

Die Produkteinstellung **Lieferrückstände erlauben?** in WooCommerce hat Vorrang. Damit können Sie bestimmte Produkte auch bei aktiviertem Schalter über einen Bestand von null hinaus verkaufen:

- **Nicht erlauben** — Verkäufe werden gestoppt, sobald der Bestand aufgebraucht ist.
- **Erlauben** — das Produkt kann immer verkauft werden, auch bei negativem Bestand.
- **Erlauben, aber Kunde benachrichtigen** — das Produkt kann immer verkauft werden. Überschreitet ein Verkauf den Bestand, meldet die Kasse **Hoodie wird nachbestellt**.

Ein Produkt im Lieferrückstand sperrt den Kassiervorgang nie.

### „Überverkäufe verhindern“ und „Nicht vorrätige Produkte anzeigen“ {#prevent-overselling-vs-display}

Diese beiden Einstellungen erfüllen unterschiedliche Aufgaben:

- **Überverkäufe verhindern** (diese Seite) prüft die Mengen beim Hinzufügen von Produkten zum Warenkorb, während der Verkauf offen ist und erneut vor jeder Zahlungsannahme. Die Einstellung gilt für jede Kasse der Filiale.
- **Nicht vorrätige Produkte anzeigen** ist eine Einstellung im Produktbereich auf jedem einzelnen Gerät. Ist sie deaktiviert, werden Produkte ohne Bestand ausgeblendet und ihr Scan wird abgelehnt. Ist sie aktiviert, bleiben sie ausgegraut und mit **Ausverkauft** gekennzeichnet in der Liste. Siehe [Nicht vorrätige Produkte](../../pos/product-panel/display-settings.mdx#show-out-of-stock-products).

Das Deaktivieren von „Überverkäufe verhindern“ ändert nicht, was der Produktbereich anzeigt.

:::note
Die Kassen erhalten die Einstellung „Überverkäufe verhindern“ beim Start des POS zusammen mit den Filialdaten. Die eigene Prüfung Ihres Shops vor jeder Zahlung gilt sofort, auch an einer Kasse, die noch nicht neu geladen wurde.
:::

## E-Mail-Benachrichtigungen {#email-notifications}

Drei Schalter bestimmen unabhängig von den E-Mail-Einstellungen Ihrer Website, welche WooCommerce-E-Mails POS-Bestellungen versenden:

- **Admin-E-Mails** — **Neue Bestellung**, **Stornierte Bestellung** und **Fehlgeschlagene Bestellung** an die in WooCommerce festgelegten Empfänger. Aktiviert.
- **Kunden-E-Mails** — **Bestellung wartend**, **Bestellung in Bearbeitung**, **Bestellung abgeschlossen**, **Bestellung rückerstattet** und **Fehlgeschlagene Bestellung** an den Kunden. Aktiviert.
- **Kassierer-E-Mails** — **Neue Bestellung** an den Kassierer, der den Verkauf durchgeführt hat. Deaktiviert.

Wenn Sie eine Gruppe aktivieren, erscheinen ihre E-Mails als Kontrollkästchen, die zunächst alle ausgewählt sind. Entfernen Sie die Häkchen bei unerwünschten E-Mails. Unter [E-Mail-Benachrichtigungen](./email-notifications.mdx) erfahren Sie, wann welche E-Mail versendet wird, wer sie erhält und welche Einstellungen üblich sind.

## Bestellspeicherung {#order-storage}

Erscheint oben auf der Seite eine Warnung zur Bestellspeicherung, folgen Sie der Anleitung [Bestellspeicherung](../../support/performance/order-storage.mdx), um Ihren Shop auf die Hochleistungs-Bestellspeicherung von WooCommerce umzustellen. Verwendet der Shop diese bereits, erscheint keine Warnung.

<details>
<summary>Die Warnung zur Bestellspeicherung erkennen</summary>

Sie lautet **Der Kassiervorgang in WCPOS wird mit wachsendem Katalog und Bestellverlauf langsamer, weil dieser Shop die veraltete Bestellspeicherung verwendet. Wir empfehlen dringend, auf die Hochleistungs-Bestellspeicherung umzustellen.** Sie kann nicht ausgeblendet werden. Darunter führt **WooCommerce-Einstellung zur Bestellspeicherung öffnen** zur Einstellung, und **So stellen Sie um** öffnet dieselbe Anleitung.

</details>

## Wenn etwas nicht funktioniert {#goes-wrong}

**Eine Zahlungsart fehlt in der Tabelle.** Ihr Plugin ist nicht installiert oder nicht aktiv. Aktivieren Sie es und laden Sie diese Seite anschließend neu.

**Der Schalter „Aktiviert“ ist ausgegraut.** Ihre Filiale nutzt die kostenlose Version, die nur Bargeld und Karte anbietet. Siehe [WCPOS Pro](../../getting-started/pro-license.mdx).

**Eine Zahlungsart ist aktiviert, erscheint aber nicht beim Kassieren.** Laden Sie den POS neu. Sehen Sie dann auf dem [Tab „Legacy“](../../pos/checkout/legacy-tab.mdx) nach: Zahlungsgateways mit eigener Zahlungsseite befinden sich dort und erscheinen nicht als Kacheln.

**Beim Öffnen des Kassiervorgangs ist die falsche Kachel ausgewählt.** Die Kasse wählt in der Reihenfolge der Tabelle die erste verwendbare Kachel aus. Ziehen Sie die gewünschte Zahlungsart ganz nach oben. Die Spalte **Standard** hat darauf keinen Einfluss.

**Per Banküberweisung bezahlte Bestellungen werden als „Wartend“ angezeigt.** Das ist die Standardeinstellung für BACS und Scheck, da das Geld später eingeht. Sobald eine Überweisung eingeht, ändern Sie den Status dieser Bestellung unter `WP Admin > WooCommerce > Orders`. Ändern Sie den **Bestellstatus** des Zahlungsgateways hier nur, wenn das Geld bei jedem künftigen Verkauf mit dieser Zahlungsart bereits eingegangen sein wird: Die Einstellung gilt für neue Verkäufe, nicht für bereits erfasste Bestellungen.

**Die Kasse hat mehr verkauft, als vorhanden war.** **Überverkäufe verhindern** ist deaktiviert oder das Produkt erlaubt Lieferrückstände. Siehe [Lieferrückstände haben weiterhin Vorrang](#prevent-overselling-backorders).
