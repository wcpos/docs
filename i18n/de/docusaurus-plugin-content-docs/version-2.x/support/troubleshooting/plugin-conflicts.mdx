## Anzeichen für einen Plugin-Konflikt {#signs-of-plugin-conflicts}

Ein Plugin-Konflikt kann vorliegen, wenn nach dem Hinzufügen oder Aktualisieren eines Plugins Folgendes auftritt:

- **Das Anmeldefenster zeigt einen Fehler oder eine leere Seite an.**
- **Die App meldet „Die WordPress REST API auf dieser Website erfordert eine Authentifizierung“**, oder sie zeigt die Meldung eines anderen Plugins an, dass nur angemeldete Benutzer die REST API nutzen können.
- **Die Website zeigt „Es gab einen kritischen Fehler auf deiner Website“ an**, im POS oder in WP Admin.
- **Produkte, Bestellungen oder Kunden werden nicht mehr heruntergeladen**, oder ein Verkauf lässt sich nicht im Shop speichern.
- **Die Zahlungsseite eines Zahlungsgateways auf der Registerkarte „Legacy“ wird fehlerhaft dargestellt**, oder ihre Schaltflächen reagieren nicht.
- **Alles ist langsam**, oder Anfragen überschreiten das Zeitlimit. Für einen langsamen Bezahlvorgang gibt es eine eigene Seite: [Checkout-Leistung](../performance/checkout.mdx).

Wenn das Menü **POS** nach einem Plugin-Update aus WP Admin verschwunden ist, lesen Sie [Der POS ist nach einem Plugin-Update verschwunden](../../getting-started/upgrading-to-2.mdx#pos-gone).

## Bevor Sie beginnen: Verwenden Sie eine Staging-Website {#before-you-start-use-a-staging-site}

:::warning Keine Fehlersuche auf Ihrer Live-Website
Wenn Sie Plugins auf der Website deaktivieren, die Ihre Kasse verwendet, können Verkäufe unterbrochen und Ihr Onlineshop verändert werden. Führen Sie dies auf einer Staging-Website durch.
:::

### Was ist eine Staging-Website? {#what-is-a-staging-site}

Eine Staging-Website ist eine Kopie Ihrer Website, auf der Sie Änderungen testen können, ohne dass Ihre Kunden oder Ihre Kasse davon betroffen sind. Bei den meisten Hosting-Anbietern lässt sie sich mit wenigen Klicks im Hosting-Dashboard erstellen.

### Wenn Ihr Hosting-Anbieter kein Staging anbietet {#if-your-host-doesnt-offer-staging}

Fragen Sie Ihren Hosting-Anbieter, wie Sie die Website kopieren können. Bietet er keine Möglichkeit dazu, lohnt sich ein Wechsel zu einem Anbieter, der dies unterstützt: Sie benötigen Staging für jedes Update von Plugins, Themes, WordPress und WooCommerce, nicht nur hierfür. WP Engine, SiteGround, Kinsta und Cloudways bieten diese Funktion alle an.

## Schritt 1: Suchen Sie nach einem schwerwiegenden Fehler {#step-1-check-for-fatal-errors}

Bei einem Absturz wird meist das verantwortliche Plugin genannt. Prüfen Sie zuerst diese Stellen:

1. **Das POS-Protokoll.** Öffnen Sie **Filialzustand** im Seitenmenü, wählen Sie **Protokolle** und dann **Fehler**. Siehe [Protokolle](../logs.mdx).
2. **Das WooCommerce-Protokoll für schwerwiegende Fehler.** Folgen Sie der Anleitung unter [Kritischer Fehler](./critical-error.mdx), um es in WP Admin zu finden.
3. **Lesen Sie den Dateipfad.** Eine Zeile wie `wp-content/plugins/<plugin-name>/…` nennt das Plugin.

Wenn der Fehler ein anderes Plugin als WooCommerce oder WCPOS nennt, deaktivieren Sie dieses auf Ihrer Staging-Website und versuchen Sie es erneut. Wird kein Plugin genannt, fahren Sie mit Schritt 2 fort.

## Schritt 2: Deaktivieren Sie Plugins und aktivieren Sie sie einzeln wieder {#step-2-the-plugin-elimination-method}

Verwenden Sie diese Methode, wenn kein schwerwiegender Fehler vorliegt oder das Problem eine langsame Ausführung ist.

### 2.1 Notieren Sie, was schiefgeht {#21-create-a-baseline}

1. **Öffnen Sie den POS auf Ihrer Staging-Website.** Rufen Sie im Webbrowser `/pos` unter der Staging-Adresse auf. Verbinden Sie in der App die Staging-Adresse als weitere Filiale (siehe [Verbinden](../../getting-started/connect.mdx)), und prüfen Sie die Adresse unter **Ihre Websites**, bevor Sie fortfahren.
2. **Führen Sie die Aktion aus, die fehlschlägt**, und notieren Sie genau, was Sie sehen: die Meldung, den Bildschirm und die benötigte Zeit.
3. **Bei langsamer Ausführung** notieren Sie die Zeiten aus den [Protokollen](../logs.mdx), damit Sie sie später vergleichen können.

### 2.2 Deaktivieren Sie alles außer dem POS {#22-disable-all-plugins-except-essential-ones}

**Lassen Sie Folgendes aktiviert:**
- WooCommerce
- WCPOS
- WCPOS Pro, falls vorhanden
- das Zahlungsgateway, wenn dessen Zahlungsseite das Problem ist

**Deaktivieren Sie alles andere:**
1. Gehen Sie zu `WP Admin > Plugins`.
2. Markieren Sie alle anderen Plugins.
3. Wählen Sie unter **Mehrfachaktionen** die Option **Deaktivieren**.
4. Klicken Sie auf **Übernehmen**.

Dies ist das untere Ende der Liste **Plugins** in einem Shop mit dem kostenlosen Plugin, bevor etwas markiert wurde:

1. **WCPOS Pro** — lassen Sie das Kontrollkästchen leer. In diesem Shop ist es installiert, aber nicht aktiv.
2. **WCPOS** — lassen Sie das Kontrollkästchen leer.
3. **WooCommerce** — das Kontrollkästchen ist ausgegraut, solange WCPOS es benötigt. Es bleibt daher aktiv.
4. **Mehrfachaktionen** — wählen Sie **Deaktivieren**, sobald alle anderen Plugins markiert sind.
5. **Übernehmen** — deaktiviert die markierten Plugins.

</JourneyShot>

### 2.3 Versuchen Sie es erneut {#23-test-the-issue}

1. **Leeren Sie alle Caches**: den Ihres Hosting-Anbieters, den Ihres CDN und die aller Caching-Plugins.
2. **Führen Sie die fehlgeschlagene Aktion erneut aus.** Funktioniert sie jetzt?
3. **Bei langsamer Ausführung** vergleichen Sie die Zeiten mit Ihren Notizen.

**Es funktioniert jetzt:** Eines der deaktivierten Plugins ist wahrscheinlich die Ursache. Fahren Sie mit [Plugins einzeln wieder aktivieren](#24-enable-plugins-one-by-one) fort, um herauszufinden, welches das Problem erneut auslöst.

**Es schlägt weiterhin fehl:** Dieser Test hat die Ursache nicht gefunden. Aktivieren Sie die Plugins nicht einzeln wieder. Prüfen Sie Ihr Theme in [Schritt 3](#step-3-check-for-theme-conflicts). Wenn es auch nicht am Theme liegt, prüfen Sie:
- die Ressourcen und die Firewall Ihres Servers: siehe [Serverleistung](../performance/server.mdx)
- einen Dienst, der Ihrer Website vorgeschaltet ist, etwa [Cloudflare](./cloudflare.mdx)
- WordPress, WooCommerce oder WCPOS selbst: [Kontaktieren Sie den Support](#getting-help) mit Ihren Notizen aus [Notieren Sie, was schiefgeht](#21-create-a-baseline)

### 2.4 Aktivieren Sie Plugins einzeln wieder {#24-enable-plugins-one-by-one}

<details>
<summary>Welche Plugins Sie zuerst testen sollten</summary>

Beginnen Sie mit den Plugin-Arten, die am häufigsten Konflikte verursachen, damit Sie die Ursache schneller finden:
1. **Sicherheits- und Anmelde-Plugins**: Wordfence, Sucuri, Solid Security und ähnliche
2. **Caching- und Optimierungs-Plugins**
3. **Zahlungsgateways**
4. **Andere WooCommerce-Erweiterungen**
5. **SEO-Plugins**
6. **Alles andere**

</details>

**Testen Sie jedes Plugin:**

1. **Aktivieren Sie ein Plugin.**
2. **Versuchen Sie es erneut.**
3. **Es funktioniert weiterhin:** Aktivieren Sie das nächste Plugin und versuchen Sie es erneut.
4. **Es schlägt wieder fehl:** Notieren Sie das gerade aktivierte Plugin. Es verursacht wahrscheinlich den Konflikt.

**Stellen Sie sicher, dass es an diesem Plugin liegt:**

1. **Deaktivieren Sie die wieder aktivierten Plugins**, lassen Sie aber WooCommerce, WCPOS, WCPOS Pro und die zuvor aktiv gelassenen Zahlungsgateways aktiviert.
2. **Aktivieren Sie nur das notierte Plugin**, und versuchen Sie es erneut.
3. **Das Problem tritt wieder auf:** Dieses Plugin verursacht den Konflikt.
4. **Es tritt nicht wieder auf:** Möglicherweise ist ein weiteres Plugin beteiligt. Aktivieren Sie die anderen einzeln und notieren Sie das Paar, bei dem das Problem erneut auftritt.

### 2.5 Halten Sie Ihre Ergebnisse fest {#25-document-your-findings}

1. **Name und Version des Plugins.**
2. **Welche Probleme es verursacht**, so wie Sie es unter 2.1 notiert haben.
3. **Ob eine neuere Version verfügbar ist.**

Diese Angaben benötigen Sie für [Schritt 4](#step-4-resolving-plugin-conflicts) und wenn Sie [den Support kontaktieren](#getting-help).

## Schritt 3: Prüfen Sie Ihr Theme {#step-3-check-for-theme-conflicts}

Die POS-Bildschirme verwenden Ihr Theme nicht, daher beeinträchtigt ein Theme die Kasse nur selten. Es kann aber dennoch beeinflussen, was WordPress an den POS sendet:

- die Zahlungsseite eines Zahlungsgateways auf der Registerkarte **Legacy** beim Bezahlen und die Kassenseite des Onlineshops, zu der das Zahlungsgateway [Web Checkout](../../payment/gateways/web-checkout.mdx) Kunden weiterleitet
- Bildschirme in WP Admin, einschließlich der POS-Einstellungen
- die REST-API-Anfragen des POS, da WordPress auch bei diesen den Code Ihres Themes ausführt

### Mit einem Standard-Theme testen {#test-with-a-default-theme}

1. Wechseln Sie **auf Ihrer Staging-Website** zu einem WordPress-Standard-Theme wie Twenty Twenty-Five oder Twenty Twenty-Four.
2. **Versuchen Sie es erneut.**
3. **Es funktioniert jetzt:** Ihr Theme ist die Ursache. Teilen Sie dem Entwickler des Themes mit, was nicht funktioniert.

## Schritt 4: Beheben Sie den Konflikt {#step-4-resolving-plugin-conflicts}

Sobald Sie das Plugin kennen, versuchen Sie die folgenden Optionen der Reihe nach.

### Option 1: Aktualisieren Sie das Plugin {#option-1-update-the-plugin}

1. **Suchen Sie nach einem Update.** Möglicherweise wurde der Konflikt bereits behoben.
2. **Aktualisieren Sie zuerst auf der Staging-Website**, und versuchen Sie es erneut.
3. **Wenn das Problem dadurch behoben wird** und sowohl der POS als auch die Kasse Ihres Onlineshops weiterhin funktionieren, aktualisieren Sie Ihre Live-Website.

### Option 2: Nehmen Sie den POS aus {#option-2-exclude-the-pos}

Die meisten Konflikte lassen sich in den Einstellungen des anderen Plugins beheben, ohne es zu deaktivieren. Siehe [Was Sie ausnehmen sollten](#what-to-exclude) und die Lösung für Ihr Plugin unter [Bekannte Plugin-Konflikte](#known-plugin-conflicts).

### Option 3: Finden Sie eine Alternative {#option-2-find-an-alternative}

1. **Suchen Sie nach einem anderen Plugin**, das dieselbe Aufgabe erfüllt.
2. **Testen Sie es auf der Staging-Website.**
3. **Übertragen Sie die Einstellungen**, bevor Sie wechseln.

### Option 4: Informieren Sie den Entwickler des Plugins {#option-3-contact-plugin-developer}

Senden Sie ihm:
- die Version des Plugins sowie Ihre Versionen von WordPress, WooCommerce und WCPOS
- eine Beschreibung des Problems mit dem genauen Wortlaut der Meldung
- die Schritte, mit denen es sich reproduzieren lässt

### Option 5: Lassen Sie einen Entwickler eine Umgehungslösung erstellen {#option-4-custom-solution}

Wenn Sie auf ein Plugin nicht verzichten können, kann ein WordPress-Entwickler oft mithilfe der Hooks des Plugins verhindern, dass der konfliktverursachende Teil bei POS-Anfragen und auf POS-Seiten ausgeführt wird.

## Was Sie ausnehmen sollten {#what-to-exclude}

Bei den meisten folgenden Lösungen wird das andere Plugin so eingestellt, dass es den POS nicht beeinflusst, statt es zu deaktivieren. Ist Ihr Plugin unter [Bekannte Plugin-Konflikte](#known-plugin-conflicts) aufgeführt, steht dort, was Sie ändern müssen. Andernfalls geben Sie die folgenden Angaben an die Person weiter, die Ihre Website verwaltet, oder an den Support des Plugins.

<details>
<summary>Adressen und Einstellungen für Ihre Website-Verwaltung</summary>

Der POS liest und speichert die Daten Ihres Shops über die REST API Ihrer WordPress-Website. Ein Plugin, das diese Anfragen blockiert, zwischenspeichert oder umschreibt, kann den POS beeinträchtigen. Wenn das Plugin nicht aufgeführt ist:

- **Firewall- und REST-API-Einstellungen:** Lassen Sie `/wp-json/` selbst und alles unter `/wp-json/wcpos/` zu. Lassen Sie den Schutz für alle anderen Adressen aktiviert.
- **Einstellungen für Caching und Skriptoptimierung:** Nehmen Sie `/pos` und `/wcpos-checkout/` aus.
- **Sie finden die Einstellung nicht:** Senden Sie diese Tabelle an den Support des Plugins und fragen Sie, wo Sie diese Adressen eintragen können.

| Adresse | Wofür der POS sie verwendet |
| --- | --- |
| `/wp-json/wcpos/` | Alle Daten, die der POS liest und speichert |
| `/wp-json/` | Zum Finden Ihres Shops beim Verbinden der App. Die App liest diese Adresse selbst, nicht die darunterliegenden |
| `/pos` | Der POS im Webbrowser. Dies ist der Standard; Ihre Website verwendet möglicherweise eine andere **POS-Basis** unter `WP Admin > Einstellungen > Permalinks` |
| `/wcpos-auth/` | Das Anmeldefenster der App |
| `/wcpos-checkout/` | Die Zahlungsseite eines Zahlungsgateways auf der Registerkarte **Legacy** und Belege |


:::note Das Anmeldefenster der App verwendet nicht die WordPress-Anmeldeseite
Die Desktop- und Mobil-Apps melden sich über ein eigenes WCPOS-Formular unter `/wcpos-auth/` in einem separaten Fenster an. Plugins, die die WordPress-Anmeldeseite ändern, etwa durch eine eigene Anmeldeadresse, Zwei-Faktor-Codes, ein Captcha oder eine Anmeldung nur per E-Mail, wirken sich darauf nicht aus. Sie greifen jedoch, wenn Sie den POS im Webbrowser öffnen, da Sie dabei zuerst zur normalen WordPress-Anmeldung weitergeleitet werden.
:::

</details>

## Häufig konfliktverursachende Plugin-Arten {#common-conflicting-plugin-types}

<details>
<summary>Welche Plugin-Arten können stören?</summary>

**Am häufigsten verursachen folgende Plugins Konflikte:**

- **Sicherheits- und Firewall-Plugins** können REST-API-Anfragen blockieren, die Kasse nach vielen Anfragen sperren oder die Anmeldung verhindern.
- **Caching- und Optimierungs-Plugins** können dem POS veraltete Antworten liefern oder Skripte auf den Seiten beeinträchtigen, die WordPress für ihn erzeugt.
- **Plugins für Anmeldung, Mitgliedschaften und Zugriffskontrolle** können die REST API für nicht angemeldete Benutzer sperren oder den Anmeldevorgang ändern.
- **Page-Builder und Plugins, die Inhalte ins Frontend einfügen**, können ihre Skripte und Overlays in die Zahlungsseite eines Zahlungsgateways laden.
- **Alles, was beim Speichern einer Bestellung oder eines Produkts ausgeführt wird**, kann jeden Verkauf verlangsamen oder verhindern, dass er gespeichert wird.

**Selten ein Problem:** Plugins für Kontaktformulare, soziale Medien, Analysen und Inhalte beeinflussen den POS nur selten. [WooCommerce Tax](../../integrations/woocommerce-tax.mdx) funktioniert mit ihm: Für POS-Verkäufe gelten dieselben automatisch ermittelten Steuersätze wie für Ihre Onlinebestellungen.

</details>

## Bekannte Plugin-Konflikte {#known-plugin-conflicts}

Für diese Plugins wurden Konflikte mit WCPOS gemeldet. Öffnen Sie den Eintrag Ihres Plugins, um das Problem und die Lösung zu sehen. Setzen Sie die Lösung zuerst auf Ihrer Staging-Website um.

Direkt zu: [Sicherheit und Anmeldung](#security-and-login-plugins) · [Caching und Optimierung](#performance-caching-optimisation-plugins) · [Page-Builder](#page-builders-front-end-injectors) · [WooCommerce-Erweiterungen und weitere Plugins](#woocommerce-extensions-other-plugins) · [Serverebene](#server-level-conflicts) · [Von WCPOS behoben](#handled-by-wcpos)

### Sicherheits- und Anmelde-Plugins {#security-and-login-plugins}

Diese sind die häufigste Ursache. Sie blockieren die Anfragen des POS, sodass die App keine Verbindung herstellen, sich nicht anmelden oder Ihre Shopdaten nicht herunterladen kann.

<details>
<summary>Wordfence: Der POS kann keine Verbindung herstellen oder Daten herunterladen</summary>

**Problem:** Die Firewall blockiert die REST-API-Anfragen des POS.

**Lösung:** Lassen Sie `/wp-json/wcpos/` in der Firewall zu. Geben Sie nur diese Adresse frei, nicht die gesamte REST API.

</details>

<details>
<summary>Really Simple Security: REST API blockiert oder umgeleitet</summary>

**Problem:** Das Plugin blockiert den REST-API-Zugriff oder erzwingt Weiterleitungen.

**Lösung:** Deaktivieren Sie die REST-API-Einschränkungen in den Plugin-Einstellungen unter **Erweitert**.

</details>

<details>
<summary>Solid Security (iThemes Security): REST API blockiert oder Kasse gesperrt</summary>

**Problem:** Das Plugin blockiert die REST API oder sperrt die Kasse, weil es deren Anfragen als Brute-Force-Angriff einstuft.

**Lösung:** Lassen Sie die POS-Adressen `/wp-json/` und `/wp-json/wcpos/` sowie die eigene IP-Adresse Ihres Servers zu. Geben Sie IP-Adressen nicht für die gesamte Website frei.

</details>

<details>
<summary>Sucuri: Der POS kann keine Verbindung herstellen oder Daten herunterladen</summary>

**Problem:** Die Firewall blockiert REST-API-Anfragen.

**Lösung:** Lassen Sie `/wp-json/wcpos/` im Sucuri-Dashboard zu.

</details>

<details>
<summary>Force Login und andere Plugins, die die REST API sperren: „Authentifizierung erforderlich“</summary>

**Problem:** Die App meldet _„Die WordPress REST API auf dieser Website erfordert eine Authentifizierung“_, oder sie zeigt eine Meldung des Plugins an, dass nur angemeldete Benutzer die REST API nutzen können.

**Lösung:** Erlauben Sie nicht angemeldeten Besuchern den Zugriff auf die REST API oder zumindest auf `/wp-json/` und `/wp-json/wcpos/`.

</details>

<details>
<summary>Security Optimizer: Der POS im Webbrowser verlangt die benutzerdefinierte Anmelde-URL</summary>

**Problem:** Beim Öffnen des POS im Webbrowser erscheint eine Meldung, dass die benutzerdefinierte Anmelde-URL verwendet werden muss. Danach geht es nicht weiter.

**Lösung:** Melden Sie sich zuerst über Ihre benutzerdefinierte Anmelde-URL bei WP Admin an und rufen Sie dann `/pos` auf.

</details>

<details>
<summary>Jetpack CRM Client Portal: Benutzer können sich nicht anmelden</summary>

**Problem:** Benutzer können sich nicht beim POS anmelden.

**Lösung:** Deaktivieren Sie nur die Erweiterung Client Portal, nicht ganz Jetpack CRM.

</details>

### Plugins für Leistung, Caching und Optimierung {#performance-caching-optimisation-plugins}

<details>
<summary>WP Rocket, Autoptimize, Hummingbird, Smush: Zahlungsseiten unter „Legacy“ funktionieren nicht</summary>

**Problem:** Das verzögerte Laden oder Minifizieren von JavaScript beeinträchtigt die Zahlungsseiten von Zahlungsgateways auf der Registerkarte **Legacy**.

**Lösung:** Nehmen Sie `/wcpos-checkout/` und `/pos` von der JavaScript-Optimierung aus.

</details>

<details>
<summary>LiteSpeed Cache: Die Desktop-App lädt beim Bezahlen neu</summary>

**Problem:** Die Desktop-App lädt beim Bezahlen immer wieder neu.

**Lösung:** Aktualisieren Sie WCPOS und LiteSpeed Cache, leeren Sie den Cache und nehmen Sie `/wcpos-checkout/` und `/pos` vom Caching aus.

</details>

### Page-Builder und Plugins, die Inhalte ins Frontend einfügen {#page-builders-front-end-injectors}

Diese laden ihre Skripte und Overlays in die Zahlungsseite, die ein Zahlungsgateway auf der Registerkarte **Legacy** innerhalb des POS öffnet. Auf dieser Seite gibt es die Schaltfläche **Checkout-Einstellungen**, mit der sich Skripte und Styles entfernen lassen: siehe [Die Zahlungsseite eines Zahlungsgateways wird falsch dargestellt](../../pos/checkout/troubleshooting.mdx#checkout-settings-troubleshooting).

<details>
<summary>Elementor: Zahlungsarten lassen sich nicht öffnen</summary>

**Problem:** `elementor-frontend.js` beeinträchtigt die Zahlungsseite: Zahlungsarten lassen sich nicht öffnen.

**Lösung:** Entfernen Sie in den **Checkout-Einstellungen** unter **Ausgewählte Skripte deaktivieren** das Frontend-Skript von Elementor, oder verhindern Sie, dass Elementor es auf `/wcpos-checkout/` lädt.

</details>

<details>
<summary>Omnisend und andere Marketing-Plugins: Das Layout der Zahlungsseite ist fehlerhaft</summary>

**Problem:** Ihre Skripte beeinträchtigen das Layout der Zahlungsseite und die Zahlungen.

**Lösung:** Entfernen Sie ihre Skripte in den **Checkout-Einstellungen** unter **Ausgewählte Skripte deaktivieren**.

</details>

<details>
<summary>MyStickyElements, Complianz: Schaltflächen oder ein Banner verdecken die Zahlungsseite</summary>

**Problem:** Fixierte Schaltflächen oder ein Cookie-Banner verdecken die Zahlungsseite.

**Lösung:** Konfigurieren Sie die Plugins so, dass sie `/wcpos-checkout/` ausnehmen, oder entfernen Sie ihre Skripte in den **Checkout-Einstellungen**.

</details>

### WooCommerce-Erweiterungen und weitere Plugins {#woocommerce-extensions-other-plugins}

<details>
<summary>Stripe Tax: Funktioniert nicht mit POS-Bestellungen</summary>

**Problem:** Es funktioniert nicht mit Bestellungen, die über die REST API erstellt werden. Der POS speichert jede Bestellung auf diese Weise.

**Lösung:** Es gibt keine Umgehungslösung. [WooCommerce Tax](../../integrations/woocommerce-tax.mdx) ist die automatische Steuerberechnung, die mit dem POS funktioniert.

</details>

<details>
<summary>WP Activity Log: Die Datenbank füllt sich, der Shop wird langsam</summary>

**Problem:** Das Plugin protokolliert jede Änderung des POS. Dadurch füllt sich die Datenbank und der Shop wird langsamer.

**Lösung:** Deaktivieren Sie es oder nehmen Sie POS-Produkte und -Bestellungen von der Protokollierung aus.

</details>

<details>
<summary>MailerLite: Serverfehler (500) beim Speichern eines Verkaufs</summary>

**Problem:** Wenn sowohl MailerLite Signup Forms als auch die WooCommerce-Integration von MailerLite aktiv sind, geht dem Server der Arbeitsspeicher aus. Beim Speichern einer Bestellung durch den POS gibt er dann einen Serverfehler (500) zurück.

**Lösung:** Deaktivieren Sie beide, um die Ursache zu bestätigen, und kontaktieren Sie anschließend MailerLite.

</details>

<details>
<summary>The Courier Guy Shipping: Bestellungen lassen sich nicht speichern</summary>

**Problem:** Der POS kann Bestellungen aufgrund eines Serverfehlers nicht speichern.

**Lösung:** Kehren Sie zur vorherigen Version des Plugins zurück oder kontaktieren Sie dessen Entwickler.

</details>

<details>
<summary>Mollie: Direkte Banküberweisung fehlt</summary>

**Problem:** Das Plugin blendet die direkte Banküberweisung beim Bezahlen im POS aus.

**Lösung:** Aktualisieren Sie Mollie.

</details>

<details>
<summary>CTX Feed: 403-Fehler auf der POS-Einstellungsseite</summary>

**Problem:** Auf der POS-Einstellungsseite treten gelegentlich 403-Fehler auf.

**Lösung:** Deaktivieren Sie das Plugin, um die Ursache zu bestätigen. Es ist keine Einstellung bekannt, die das Problem behebt.

</details>

<details>
<summary>Barcode-Scanner-Plugins: Bestellungen lassen sich nicht speichern oder anzeigen</summary>

**Problem:** Sie beschädigen die von der REST API gesendeten Bestelldaten, sodass Bestellungen nicht gespeichert oder angezeigt werden können.

**Lösung:** Deaktivieren Sie diese Plugins. Der POS liest Barcodes selbst: siehe [Barcode-Scanning](../../pos/product-panel/barcode-scanning.mdx).

</details>

<details>
<summary>PixelYourSite, PixelMySite: Kritischer Fehler</summary>

**Problem:** Ein kritischer Fehler: _Aufruf der Memberfunktion `is_type()` auf einem booleschen Wert_.

**Lösung:** Deaktivieren Sie das Plugin.

</details>

<details>
<summary>Google Listings & Ads: Kritischer Fehler, WCPOS-Klasse nicht gefunden</summary>

**Problem:** Ein kritischer Fehler meldet, dass eine WCPOS-Klasse _nicht gefunden_ wurde.

**Lösung:** Löschen Sie alle WCPOS-Plugins und installieren Sie anschließend nur die neueste Version von WCPOS Pro.

</details>

<details>
<summary>WooCommerce Subscriptions: Blockiert das Pro-Upgrade von 1.7 oder älter</summary>

**Problem:** Das Plugin blockiert den Upgrade-Schritt von WCPOS Pro.

**Lösung:** Deaktivieren Sie Subscriptions, aktivieren Sie WCPOS Pro und lassen Sie das Upgrade abschließen. Aktivieren Sie anschließend Subscriptions wieder.

</details>

:::warning Stripe Terminal: In den WooCommerce-Zahlungen deaktiviert lassen
Aktivieren Sie Stripe Terminal nur für den POS unter `WP Admin > POS > Einstellungen > Kasse`. Unter `WP Admin > WooCommerce > Einstellungen > Zahlungen` muss es nicht aktiviert sein. Wenn es dort aktiviert wird, erscheint es an der Kasse Ihres Onlineshops, wo es bereits den Bezahlvorgang für Onlinekunden beeinträchtigt hat. Siehe [Stripe Terminal](../../payment/gateways/stripe-terminal.mdx).
:::

### Konflikte auf Serverebene {#server-level-conflicts}

<details>
<summary>Vom Webserver gesetzte Sicherheitsheader: Der POS bleibt beim Logo stehen oder zeigt leere Seiten</summary>

Eine Zeile mit `Content-Security-Policy` oder `X-Frame-Options` in `.htaccess`, Nginx oder der Verwaltungsoberfläche Ihres Hosting-Anbieters.

**Problem:** Der POS bleibt beim Logo stehen, oder eine Zahlungsseite auf der Registerkarte „Legacy“ beziehungsweise ein Beleg bleibt leer.

**Lösung:** Nehmen Sie `/pos`, `/wcpos-auth/` und `/wcpos-checkout/` von diesem Header aus. Nur die CDN-Adressen zu erlauben reicht nicht aus, da die POS-Seite über ein Inline-Skript startet und ihre Dateien von `cdn.wcpos.com` und `cdn.jsdelivr.net` abruft. WCPOS entfernt diese Header von seinen eigenen Seiten, wenn WordPress oder ein Plugin sie hinzufügt. Einen vom Webserver hinzugefügten Header kann es jedoch nicht entfernen.

</details>

<details>
<summary>GoDaddy Website Firewall: „'undefined' empfangen“</summary>

**Problem:** Sie blockiert `/wp-json/` mit der Meldung _„'undefined' empfangen“_.

**Lösung:** Lassen Sie den Pfad `/wp-json/` in der Firewall zu: siehe [Serverleistung](../performance/server.mdx#hosting-specific-notes).

</details>

### Konflikte, die WCPOS selbst behebt {#handled-by-wcpos}

<details>
<summary>Plugins, die früher Konflikte verursacht haben und bei denen Sie jetzt nichts mehr tun müssen</summary>

Halten Sie WCPOS aktuell, dann sind hierfür keine Einstellungen nötig:

- **Sicherheitsheader von Plugins.** Wordfence, LiteSpeed Cache und andere Plugins können eine `Content-Security-Policy` hinzufügen, die das Laden des POS verhindert. WCPOS entfernt `Content-Security-Policy` und `X-Frame-Options` von seinen eigenen Seiten. Entwickler, die dort eine Richtlinie benötigen, können sie über den Filter `wcpos_content_security_policy` festlegen.
- **Plugins zur JWT-Authentifizierung.** Früher lehnten sie das Anmeldetoken des POS ab, sodass jede Anfrage nach der Anmeldung mit einem 403-Fehler scheiterte. WCPOS entfernt diesen Fehler jetzt, wenn es die Anfrage selbst authentifiziert hat; Fehler anderer Plugins werden weiterhin durchgereicht.
- **Image Prioritizer.** Es befüllt den `Link`-Header, mit dem Apps eine WordPress-Website finden. Wenn dieser Header die REST API Ihrer Website nicht nennt, sucht die App stattdessen unter `/wp-json/` danach. Wenn die App weiterhin _„Die Website scheint keine WordPress-Website zu sein“_ meldet, deaktivieren Sie das Plugin.
- **Plugins, die beim Speichern eines Produkts ausgeführt werden** (Jetpack, Astra, Xero und andere). Ältere WCPOS-Versionen führten dazu, dass diese bei jeder Anfrage doppelte Zeilen hinzufügten. Dies wurde in 1.8.12 behoben; das Upgrade entfernte die Duplikate.
- **WooCommerce Stripe 11.1.0.** Dessen Kartenskript verhinderte Zahlungen mit allen anderen Zahlungsarten auf einer Zahlungsseite der Registerkarte **Legacy**. Solange Ihr Stripe-Plugin älter als 11.1.1 ist, entfernt WCPOS das Kartenskript und die Styles von Stripe von dieser Seite. Die anderen Zahlungsarten funktionieren dann, aber das Kartenformular von Stripe wird dort nicht angezeigt. Stripe hat den Konflikt in 11.1.1 behoben. Aktualisieren Sie Stripe, dann belässt WCPOS dessen Kartenformular wieder auf der Seite, selbst wenn es zuvor durch Speichern der **Checkout-Einstellungen** deaktiviert worden war.
- **MyParcel.** Ein Warenkorb mit einem [sonstigen Produkt](../../pos/cart/index.mdx#miscellaneous-products) ließ sich nicht bezahlen, weil MyParcel beim Speichern der Bestellung einen kritischen Fehler auslöste. WCPOS teilt MyParcel nun wie WooCommerce mit, dass zu dieser Position kein Katalogprodukt gehört. So kann der Verkauf abgeschlossen werden.

</details>

## Tipps zur Vorbeugung {#prevention-tips}

### Regelmäßige Wartung {#regular-maintenance}

1. **Halten Sie Plugins aktuell.**
2. **Löschen Sie nicht verwendete Plugins**, statt sie deaktiviert zu lassen.
3. **Testen Sie jedes Update auf der Staging-Website**, bevor Sie es auf Ihrer Live-Website installieren.
4. **Überwachen Sie die Geschwindigkeit Ihres Servers** mithilfe von [Serverleistung](../performance/server.mdx).

### Plugins auswählen {#plugin-selection-best-practices}

1. **Wählen Sie Plugins, die regelmäßig aktualisiert werden**, und achten Sie auf gute Bewertungen.
2. **Betreiben Sie nicht zwei Plugins, die dieselbe Aufgabe erfüllen.**
3. **Prüfen Sie, ob das Plugin laut Anbieter mit Ihrer WooCommerce-Version getestet wurde.**
4. **Fügen Sie Plugins einzeln hinzu**, und prüfen Sie die Kasse nach jedem Plugin.

### Welche Angaben Sie senden sollten {#when-contacting-support}

1. **Ihre aktiven Plugins** mit Versionsnummern. Unter `WP Admin > Tools > Site Health > Info` finden Sie die Liste und die Schaltfläche **Website-Bericht in die Zwischenablage kopieren**.
2. **Ihre Versionen von WordPress, WooCommerce und WCPOS.**
3. **Was schiefgeht**, so wie Sie es notiert haben.
4. **Was Sie bereits versucht haben.**
5. **Fehlermeldungen** aus den [Protokollen](../logs.mdx). **Debug-Informationen kopieren** auf der Registerkarte „Protokolle“ (**Debug-Informationen teilen** in den iOS- und Android-Apps) stellt die benötigten Angaben zusammen.
6. **Die Antwortzeiten Ihres Servers**, wenn er langsam ist.
