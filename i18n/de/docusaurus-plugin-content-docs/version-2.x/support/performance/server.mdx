Jede Kasse kommuniziert den ganzen Tag mit Ihrer WordPress-Website: Sie prüft auf Änderungen, übermittelt Verkäufe und ruft ab, wonach ein Kassierer sucht. Die Antwortgeschwindigkeit Ihres Servers bestimmt, wie schnell sich der POS anfühlt. Bei Serverengpässen reduziert jede Kasse ihre eigenen Prüfungen und kehrt selbstständig zum normalen Betrieb zurück. Diese Seite zeigt, wo Sie das beobachten können, was es bedeutet und was Sie an Ihrem Hosting ändern können.

Sind Sie wegen einer bestimmten Anzeige hier?

- [**Verlangsamt** oder **Pausiert bis …**](#pace) unter **Ihr Server im Zeitverlauf**. Sie können weiter verkaufen: Nur Hintergrundprüfungen werden seltener ausgeführt, sodass Änderungen anderer Kassen möglicherweise später erscheinen. Wenn die Anzeige an den meisten Tagen erscheint, [wählen Sie zunächst eine schonendere Voreinstellung](#fix).
- [Ein Fehler **503**, **429** oder **414**](#503-errors). Zu jedem Code finden Sie zuerst eine kurze Antwort; die Details für die Betreuung Ihrer Website sind darunter eingeklappt.
- [Suchvorgänge und Verkäufe sind an jeder Kasse langsam](#fix). Die reduzierte Prüfhäufigkeit verlangsamt diese nie. Prüfen Sie deshalb zuerst Ihren Server und nicht die Kassen: Geben Sie die [Informationen für Ihren Hosting-Anbieter](#when-to-seek-help) an die Person weiter, die Ihre Website betreut.

## Prüfen, wie Ihr Server zurechtkommt {#store-health}

Öffnen Sie über das Pulssymbol unten im Menü **Filialzustand** und anschließend **Leistung**. Die Werte gelten nur für diese Kasse.

<JourneyShot manifest={manifest} device="tablet" step={1} offsets={[[50, 0], [160, 0], [370, 0], [480, 26], [180, 0], [470, 0]]} alt="Filialzustand auf dem Tab Leistung: die Statuszeile mit Anfragen, Daten und typischer Antwortzeit der letzten 24 Stunden, die stündliche Verfügbarkeitsanzeige und die Voreinstellungen Eco, Ausgewogen und Echtzeit">

1. **Filialzustand** — das Pulssymbol unten im Menü.
2. **Leistung** — wie oft diese Kasse Ihren Shop prüft und wie Ihr Server zurechtkommt.
3. **Letzte 24 Stunden** — **Normal** bedeutet, dass diese Kasse gerade online ist und synchronisiert. Danach folgen Anfragen, Daten und die **typische Antwortzeit** in Millisekunden: 2347 entspricht hier etwa 2.3 Sekunden. Liegt sie an den meisten Tagen über 2000, nehmen Sie sie in die [Informationen für Ihren Hosting-Anbieter](#when-to-seek-help) auf.
4. **Engine-Verfügbarkeit** — eine Zelle pro Stunde. Gelb bedeutet, dass in dieser Stunde mindestens eine Anfrage fehlgeschlagen ist. Bewegen Sie den Mauszeiger über eine Zelle oder tippen Sie darauf, um die Anzahl zu sehen.
5. **Eco** — die schonendste der drei Voreinstellungen neben **Ausgewogen** und **Echtzeit**. Wählen Sie sie an Kassen, die Verkäufe anderer Kassen nicht sofort sehen müssen. Wählen Sie **Echtzeit** nur auf Empfehlung der Person, die Ihre Website betreut. Siehe [Synchronisierungsvoreinstellungen](../store-health.mdx#sync-presets).
6. **Jetzt** — wann die nächste Prüfung ansteht. Die Anfragen pro Stunde entsprechen den regelmäßigen Prüfungen gemäß Ihren Einstellungen. Bei reduzierter Prüfhäufigkeit führt die Kasse weniger davon aus. Deshalb steht die nächste Prüfung hier erst in ~2 Minuten an.

</JourneyShot>

## „Ihr Server im Zeitverlauf“ verstehen {#server-load}

Scrollen Sie auf demselben Tab nach unten. **Ihr Server im Zeitverlauf** zeigt das aktuelle Prüftempo der Kasse und stellt die letzten 24 Stunden grafisch dar.

<JourneyShot manifest={manifest} device="tablet" step={2} maxWidth={710} offsets={[[400, -204], [430, 0], [110, -84], [120, -84]]} alt="Ihr Server im Zeitverlauf an einer Kasse mit reduzierter Prüfhäufigkeit: die gelbe Tempozeile mit Verlangsamt, Prüfungen 2× seltener, weil der Server eine hohe Auslastung gemeldet hat; das Diagramm Serverauslastung steigt um 3:00 Uhr morgens auf 59,1, während das Diagramm POS-Anfragen fällt">

1. **Ihr Server im Zeitverlauf** — die Serverauslastung umfasst alles, was auf Ihrem Server läuft, nicht nur den POS: die Website, Backups und andere Websites auf demselben Server.
2. **Tempo** — hier in Gelb: **Verlangsamt — Prüfungen 2× seltener: Ihr Server hat eine hohe Auslastung gemeldet**. Diese Kasse prüft alle 2 Minuten statt jede Minute und kehrt selbstständig zum normalen Tempo zurück, sobald sich Ihr Server erholt. Siehe [Was die Tempozeile bedeutet](#pace).
3. **Serverauslastung** — die höchste Auslastung, die Ihr Server in der jeweiligen Stunde gemeldet hat. Der Wert neben dem Titel stammt aus der letzten Stunde. Sie müssen die Zahl nicht selbst einschätzen: Die Tempozeile zeigt an, wann Ihr Server die Auslastung als erhöht oder hoch einstuft.
4. **POS-Anfragen** — alle Anfragen, die diese Kasse in der jeweiligen Stunde an Ihren Shop gesendet hat: die regelmäßigen Prüfungen sowie das Herunterladen von Änderungen, das Übermitteln von Verkäufen und Suchanfragen. Deshalb kann die Zahl deutlich über den in Ihren Einstellungen vorgesehenen Anfragen pro Stunde liegen.

</JourneyShot>

Betrachten Sie beide Diagramme zusammen. Steigt und fällt die Auslastung zusammen mit den POS-Anfragen, können die Kassen dazu beitragen. Steigt die Auslastung unabhängig davon, ist etwas anderes auf Ihrem Server aktiv: die Website, ein Backup oder eine andere Website auf demselben Server. In dieser Aufnahme fallen beide Linien nach Mitternacht gemeinsam. Nach 2:00 Uhr morgens steigt die Auslastung auf 59,1, während die Anfragen dieser Kasse weiter abnehmen. Es ist also etwas anderes aktiv, und die Kasse hat ihre Prüfhäufigkeit reduziert, um den Server zu entlasten.

In jedem Fall benötigt Ihr Hosting-Anbieter einen Screenshot beider Diagramme. Ist die **typische Antwortzeit** lang, obwohl die Auslastung niedrig bleibt, fehlt es Ihrem Server nicht an Rechenleistung: Prüfen Sie zuerst die Bestellspeicherung und Ihre Plugins (Schritte 2 und 3 unter [Wenn Ihr Server dauerhaft überlastet ist](#fix)).

<AccordionItem question="Wenn die Diagramme leer sind">

Beide Diagramme zeigen **Noch nicht genügend Daten — dieser Verlauf füllt sich im laufenden Kassenbetrieb**, bis der Kasse Messwerte aus zwei verschiedenen Stunden vorliegen. Lassen Sie die Kasse laufen und sehen Sie später erneut nach.

</AccordionItem>

### Was die Tempozeile bedeutet {#pace}

Die Zeile zeigt einen der folgenden Texte. Sie ist unabhängig vom Status **Normal** oben auf dem Tab. Dieser kann auf Normal bleiben, während die Kasse seltener prüft.

- **Normales Tempo** — die Kasse prüft gemäß Ihrer Einstellung.
- **Normales Tempo — Ihr Server meldet eine erhöhte Auslastung** (oder **hohe Auslastung**) — Ihr Server meldet, dass er beschäftigt ist, und die Kasse arbeitet weiterhin gemäß Ihrer Einstellung: Eine einzelne solche Antwort verlangsamt sie nicht. Auch bei anhaltender Auslastung reduziert die Kasse ihre Prüfhäufigkeit: Wenn die meisten der letzten zehn Antworten eine hohe Auslastung melden, wechselt die Zeile zu **Verlangsamt**, selbst wenn diese Antworten schnell ankamen (siehe [Was die einzelnen Gründe bedeuten](#reasons)). Sie müssen nichts unternehmen, solange die Anzeige nicht an den meisten Tagen erscheint.
- **Verlangsamt — Prüfungen N× seltener: …** — die Kasse prüft seltener und nennt den Grund nach dem Doppelpunkt. Siehe unten [Was die einzelnen Gründe bedeuten](#reasons).
- **Pausiert bis …** — Ihr Server hat einen Zeitpunkt für den nächsten Versuch vorgegeben, und die Kasse wartet bis dahin. Sie können währenddessen weiter verkaufen.

Die Zeile ändert ihre Farbe, während die Kasse seltener prüft oder pausiert. Beide Zustände enden automatisch, sobald sich Ihr Server erholt. Wenn sie an den meisten Tagen auftreten, siehe [Wenn Ihr Server dauerhaft überlastet ist](#fix).

:::note Nur Hintergrundprüfungen werden seltener ausgeführt
Nur die regelmäßige Prüfung auf Änderungen und die Hintergrundprüfungen der Kasse werden seltener ausgeführt. Eine Suche, eine Barcode-Abfrage oder ein Verkauf wird sofort an Ihren Server gesendet. Bei reduzierter Prüfhäufigkeit dauert es länger, bis diese Kasse Änderungen von anderen Kassen und aus WooCommerce sieht.
:::

<Accordion>
<AccordionItem question="Was die einzelnen Gründe bedeuten, wie stark die Kasse ihre Prüfungen reduziert und wie sie zum normalen Tempo zurückkehrt">

<Anchor id="reasons" />

- **Ihr Server hat den POS aufgefordert, langsamer anzufragen** — Ihr Server oder eine vorgeschaltete Firewall hat einmal mit „zu viele Anfragen“ (**429**) geantwortet.
- **Ihr Server hat Fehler zurückgegeben** oder **Zeitüberschreitung bei Anfragen an Ihren Server** — drei Serverfehler (**5xx**) oder Zeitüberschreitungen innerhalb einer Minute. Der angezeigte Grund nennt den letzten dieser drei Fälle.
- **Ihr Server hat langsam geantwortet** — die typische Antwortzeit (Median) der letzten zehn Antworten lag über zwei Sekunden.
- **Ihr Server hat eine hohe Auslastung gemeldet** — entweder meldeten die meisten der letzten zehn Antworten eine hohe Serverauslastung, während die Kasse im normalen Tempo prüfte, oder zwei aufeinanderfolgende Auslastungswerte lagen mindestens beim Doppelten der üblichen Serverauslastung, sofern die Auslastung mindestens 1 beträgt.

Jedes Mal prüft die Kasse nur noch halb so oft wie zuvor. Der Abstand beträgt höchstens 5 Minuten oder das Doppelte Ihrer Einstellung, falls das länger ist: bei **Eco** alle 10 Minuten. Gibt ein Server eine eigene Pause vor (über einen **Retry-After**-Header), wird sie bis zu einer Dauer von 15 Minuten eingehalten.

Die Rückkehr zum normalen Tempo erfolgt absichtlich langsamer: Nach zehn erfolgreichen Antworten und frühestens eine Minute nach der letzten Verlangsamung wird die Wartezeit wieder halbiert. Ein sprunghafter Anstieg der Auslastung ist die Ausnahme: Die Kasse prüft halb so oft, aber nicht noch seltener, bis zwei aufeinanderfolgende Auslastungswerte wieder höchstens um ein Viertel von der üblichen Serverauslastung abweichen. Nach einem Neustart arbeitet die Kasse wieder gemäß Ihrer Einstellung.

WCPOS selbst fordert kurze Pausen an: 5 Sekunden während der Aktualisierung des Plugins auf Ihrer Website und 30 Sekunden während der Installation seiner Synchronisierungstabellen. Dabei kann kurz **Pausiert bis …** erscheinen.

Die zugrunde liegenden Regeln der Engine finden Sie unter [Synchronisierungsleistung](../../reference/sync-performance.mdx#server-pressure).

</AccordionItem>
<AccordionItem question="Woher die Auslastungswerte stammen">

Ihr Server meldet mit jeder Synchronisierungsantwort seine durchschnittliche Auslastung: wie viele Prozesse in der letzten Minute im Durchschnitt liefen oder auf einen Prozessor warteten. Vergleichen Sie diesen Wert mit der Anzahl der Prozessorkerne Ihres Servers. Eine Auslastung von 4 bedeutet bei einem Server mit 4 Kernen volle Auslastung; bei einem Server mit 16 Kernen ist sie gering.

Die Bezeichnungen **erhöht** und **hoch** übernehmen diese Einordnung für Sie. WCPOS teilt die Auslastung durch die Anzahl der Kerne: unter 0,9 pro Kern ist sie niedrig, bis 1,8 erhöht und darüber hoch. Bei Shared Hosting umfasst der Wert alle Websites auf dem Server, nicht nur Ihre.

**Ihr Server meldet seine Auslastung nicht. Alles andere auf dieser Seite funktioniert weiterhin.** erscheint anstelle des Diagramms, wenn PHP die durchschnittliche Auslastung nicht auslesen kann. Das ist bei Windows-Servern und bei Hosting-Anbietern, die diese Funktion deaktivieren, normal. Die Tempozeile funktioniert trotzdem, da die Kasse auch Fehler und Antwortzeiten überwacht.

</AccordionItem>
</Accordion>

## Wenn Ihr Server dauerhaft überlastet ist {#fix}

Arbeiten Sie diese Liste der Reihe nach durch. Jeder Schritt ist kostengünstiger als der nächste. Schritt 1 kann jeder an der Kasse ausführen. Die Schritte 2 bis 4 richten sich an die Person, die Ihre Website betreut: den Shopbetreiber, einen Entwickler oder Ihren Hosting-Anbieter.

1. **Wählen Sie eine schonendere Voreinstellung.** Öffnen Sie an Kassen, die Verkäufe anderer Kassen nicht innerhalb weniger Sekunden sehen müssen, **Filialzustand › Leistung** und wählen Sie **Eco**. Wählen Sie **Echtzeit** nur auf Empfehlung der Person, die Ihre Website betreut. Die Voreinstellung wird pro Kasse gespeichert. Siehe [Synchronisierungsvoreinstellungen](../store-health.mdx#sync-presets).
2. **Stellen Sie WooCommerce auf HPOS um**, falls es noch die bisherige Bestellspeicherung verwendet. Bei einem Shop mit vielen Bestellungen bringt dieser einzelne Schritt die größte Verbesserung. Solange der Shop die bisherige Speicherung verwendet, erscheint oben unter **POS → Einstellungen → Kasse** in WP Admin ein entsprechender Warnhinweis mit einem Link zur WooCommerce-Einstellung. Siehe [Bestellspeicherung (HPOS)](./order-storage.mdx#switch-to-hpos).
3. **Suchen Sie nach dem Plugin, das jede Anfrage verlangsamt.** Testen Sie auf einer Staging-Website, auf der nur WooCommerce und WCPOS aktiv sind, und aktivieren Sie dann die Plugins einzeln wieder. Siehe [Plugin-Konflikte](../troubleshooting/plugin-conflicts.mdx#step-2-the-plugin-elimination-method).
4. **Bitten Sie Ihren Hosting-Anbieter** um Objekt-Caching (Redis oder Memcached), mehr PHP-Worker und Arbeitsspeicher oder einen Wechsel weg von Shared Hosting. Siehe [Informationen für Ihren Hosting-Anbieter](#when-to-seek-help).

## Informationen für Ihren Hosting-Anbieter {#when-to-seek-help}

Wenden Sie sich an Ihren Hosting-Anbieter oder einen WordPress-Entwickler, wenn **Verlangsamt** oder **Pausiert bis …** an den meisten Tagen erscheint, die typische Antwortzeit dauerhaft über 2 Sekunden liegt oder die Protokolle Ihres Hosting-Anbieters Speicherfehler zeigen.

Senden Sie von der Kasse aus:

- Einen Screenshot von **Filialzustand → Leistung**, zum Abschnitt **Ihr Server im Zeitverlauf** gescrollt.
- Den Debug-Bericht aus **Filialzustand → Protokolle → Debug-Informationen kopieren** (**Debug-Informationen teilen** in den Smartphone- und Tablet-Apps). Er enthält bereits Ihre WordPress-, WooCommerce- und WCPOS-Versionen. Siehe [Protokolle](../store-health.mdx#logs).

Lassen Sie die Person, die Ihre Website betreut, Folgendes ergänzen:

- Die Liste der aktiven Plugins aus **Plugins** in WP Admin.
- Die technischen Daten Ihres Servers aus Ihrem Hosting-Konto: Prozessorkerne, Arbeitsspeicher und Speichertyp.

Der Rest dieser Seite richtet sich an die Person, die Ihre Website betreut. Wenn Sie wegen eines Codes **503**, **429** oder **414** hier sind, finden Sie unter [Fehlermeldungen Ihres Servers](#503-errors) zunächst eine kurze Antwort zu jedem Code.

Ein Shop mit täglichen Verkäufen benötigt mehr. Die Angaben für Ihren Hosting-Anbieter finden Sie unten.

:::warning Shared Hosting reicht häufig nicht aus

Beim Hosting auf WordPress.com sind Probleme mit der REST API aufgetreten, etwa dass nur 9 oder 10 Produkte aus einem großen Katalog geladen wurden. Mit selbst gehostetem WordPress vermeiden Sie diese Probleme.
:::

## Fehlermeldungen Ihres Servers {#503-errors}

### 503 Dienst nicht verfügbar {#503}

Ihr Server oder eine vorgeschaltete Komponente konnte die Anfrage nicht verarbeiten. Die Hintergrundprüfungen der Kasse werden seltener ausgeführt und automatisch erneut versucht. Ein kurzzeitiger Fehler 503 ist normal, während WCPOS auf Ihrer Website aktualisiert wird oder seine Tabellen installiert: Die Kasse wartet 5 bis 30 Sekunden und fährt dann fort. Tritt der Fehler immer wieder auf, geben Sie die [Informationen für Ihren Hosting-Anbieter](#when-to-seek-help) an die Person weiter, die Ihre Website betreut.

<Accordion>
<AccordionItem question="Für die Betreuung Ihrer Website: Was bei einem Fehler 503 zu prüfen ist">

Prüfen Sie die Serverauslastung und den freien Arbeitsspeicher, ob alle PHP-Worker belegt sind und ob das PHP-Speicherlimit mindestens **256 MB** beträgt. Die Fehlerprotokolle Ihres Hosting-Anbieters zeigen, was der POS nicht erkennen kann.

</AccordionItem>
</Accordion>

### 429 Zu viele Anfragen {#429}

Ihr Hosting-Anbieter oder Ihre Firewall begrenzt, wie oft eine einzelne Adresse Ihre Website aufrufen darf. Die Kasse reduziert sofort ihre Prüfhäufigkeit und versucht es später erneut. Mehrere Kassen hinter demselben Router in einer Filiale teilen sich eine Adresse. Wählen Sie deshalb **Eco** an Kassen, die Verkäufe anderer Kassen nicht sofort sehen müssen. Tritt der Fehler immer wieder auf, geben Sie die [Informationen für Ihren Hosting-Anbieter](#when-to-seek-help) an die Person weiter, die Ihre Website betreut.

<Accordion>
<AccordionItem question="Für die Betreuung Ihrer Website: Mehr Anfragen für den POS zulassen">

Bitten Sie Ihren Hosting-Anbieter, mehr Anfragen von der Adresse Ihrer Filiale an `/wp-json/` zuzulassen, oder passen Sie die Firewall-Einstellungen entsprechend an. Dies ist der Pfad, den der POS aufruft.

</AccordionItem>
</Accordion>

### 414 URI zu lang {#http-414-uri-too-long}

Dieser Fehler erscheint auf einer Zahlungsseite unter dem Tab **Legacy** im Checkout. Beim Öffnen enthält die Adresse dieser Seite Ihre Anmeldedaten, und die auf Ihrem Server zulässige Adresslänge ist zu kurz. Bitten Sie die Person, die Ihre Website betreut, oder Ihren Hosting-Anbieter, das Limit zu erhöhen.

<Accordion>
<AccordionItem question="Für die Betreuung Ihrer Website: Das Limit für die Adresslänge erhöhen">

- **Apache:** `LimitRequestLine 65536` in `httpd.conf`
- **Nginx:** `large_client_header_buffers 4 65536;` in `nginx.conf`

</AccordionItem>
</Accordion>

## WooCommerce sicher aktualisieren {#woocommerce-version-compatibility}

Ein WooCommerce-Update kann gelegentlich die Funktion des POS beeinträchtigen. Aktualisieren Sie WooCommerce zuerst auf einer [Staging-Website](../troubleshooting/plugin-conflicts.mdx#before-you-start-use-a-staging-site) und halten Sie WCPOS aktuell, damit die neuesten Kompatibilitätskorrekturen enthalten sind. WCPOS 2.0 benötigt WooCommerce 9.0 oder neuer.

Wenn der POS nach einem Update nicht mehr funktioniert, informieren Sie uns auf [Discord](https://wcpos.com/discord) und besprechen Sie mit der Person, die Ihre Website betreut, eine Rückkehr zur vorherigen Version. Ein Update kann die Datenbank Ihres Shops verändern. Das sollte diese Person zuerst prüfen und ein Backup von vor dem Update bereithalten.

<Accordion>
<AccordionItem question="Für die Betreuung Ihrer Website: Zu einer älteren WooCommerce-Version zurückkehren">

Der Link **Erweiterte Ansicht** auf der WordPress.org-Seite von WooCommerce führt zu einer Liste früherer Versionen. Wenn das Update die Datenbank verändert hat, stellen Sie das Backup von vor dem Update wieder her. Andernfalls installieren Sie die zuvor verwendete Version. Testen Sie dies zuerst auf einer Staging-Website.

</AccordionItem>
</Accordion>

## Bestellspeicherung (HPOS) {#woocommerce-high-performance-order-storage-hpos}

Die **Hochleistungs-Bestellspeicherung** von WooCommerce speichert Bestellungen in eigenen Tabellen statt zusammen mit Ihren Beiträgen. In einem Shop mit vielen Bestellungen lassen sich Verkäufe damit deutlich schneller speichern. Prüfen Sie, welche Speicherung Ihr Shop verwendet, und stellen Sie sie mit dem WooCommerce-eigenen Werkzeug um: [Bestellspeicherung (HPOS)](./order-storage.mdx). Die Anleitung von WooCommerce finden Sie unter [Hochleistungs-Bestellspeicherung](https://woocommerce.com/document/high-performance-order-storage/).

<Accordion>
<AccordionItem question="PHP- und WordPress-Einstellungen, die Sie mit Ihrem Hosting-Anbieter besprechen können">

Dies sind Ausgangspunkte, keine festen Vorgaben. Ihr Hosting-Anbieter weiß, was seine Server zulassen.

```ini
memory_limit = 512M
max_execution_time = 300
max_input_vars = 3000
```

Wenn Sie in `wp-config.php` die Anzahl gespeicherter Beitragsrevisionen reduzieren, bleibt die Datenbank kleiner:

```php
define('WP_POST_REVISIONS', 3);
```

Häufig verlangsamen folgende Plugins jede Anfrage: aufwendige SEO-Plugins, die beim Speichern von Produkten ausgeführt werden, komplexe Warenwirtschaftssysteme, Echtzeitanalysen und Tracking sowie eigener Code, der in WooCommerce eingreift. Finden Sie die Ursache mithilfe von [Plugin-Konflikte](../troubleshooting/plugin-conflicts.mdx).

</AccordionItem>
</Accordion>

## Hinweise zu einzelnen Hosting-Anbietern {#hosting-specific-notes}

Bei einigen Hosting-Anbietern und CDNs ist eine Anpassung nötig, damit der POS die REST API Ihrer Website erreichen kann. Öffnen Sie den passenden Abschnitt:

<Accordion>
<AccordionItem question="GoDaddy">

Die Website-Firewall blockiert `/wp-json/` mit Fehlermeldungen wie _„'undefined' empfangen“_. Fügen Sie unter **Website-Sicherheit › Firewall › Einstellungen › Zugriffskontrolle › URL-Pfade zulassen** den Pfad `/wp-json/` hinzu.

</AccordionItem>
<AccordionItem question="WP Engine">

Die REST API muss aktiviert sein. Aktivieren Sie sie und geben Sie ihre Pfade bei Bedarf in der Firewall von WP Engine frei.

</AccordionItem>
<AccordionItem question="Cloudflare">

Der Bot-Abwehrmodus, der Modus „Unter Angriff“ oder WAF-Prüfungen blockieren REST-Anfragen, und der Cache kann veraltete Antworten ausliefern. Folgen Sie der [Cloudflare-Anleitung](../troubleshooting/cloudflare.mdx), um eine WAF-Regel mit **Überspringen** und eine Regel mit **Cache umgehen** für `/wp-json/` hinzuzufügen.

</AccordionItem>
<AccordionItem question="WordPress.com">

Produkte werden möglicherweise nicht geladen, etwa wenn aus einem großen Katalog nur 9 oder 10 angezeigt werden. Verwenden Sie selbst gehostetes WordPress.

</AccordionItem>
<AccordionItem question="Shared Hosting">

Zu wenige PHP-Worker und zu wenig Arbeitsspeicher für mehrere Kassen. Wechseln Sie zu einem VPS oder Managed WordPress Hosting.
