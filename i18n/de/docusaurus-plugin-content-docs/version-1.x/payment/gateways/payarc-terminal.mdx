# PayArc Terminal-Gateway {#payarc-terminal-gateway}

Mit dem PayArc-Terminal-Zahlungsgateway können Sie über PayArc Connect mit einem PayArc-PAX-Terminal Vor-Ort-Zahlungen über WCPOS entgegennehmen. Die Zahlung wird in WooCommerce gestartet und am Terminal abgeschlossen. Die Bestellung wird erst dann als bezahlt markiert, wenn PayArc die Zahlung bestätigt.

## Funktionsweise {#how-it-works}

WordPress ruft **PayArc Connect** auf, und PayArc stellt die Verbindung zum PAX-Terminal her. Der POS kommuniziert ausschließlich mit Ihrer Website. Bei jeder Zahlung wird der **gesamte Bestellbetrag** belastet.

Die Zahlungsseite prüft das Ergebnis alle **1.5 Sekunden** und wird nach **5 Minuten** beendet. PayArc-Callbacks an die **Webhook-URL** beschleunigen die Ergebnisübermittlung; Zahlungen werden auch ohne Callbacks durch regelmäßige Abfragen abgeschlossen. Lassen Sie die Zahlungsseite geöffnet, während der Kunde am Terminal bezahlt.

## Einrichtung {#setup}

<Steps>
  <StepCard number="1" title="PayArc Terminal für WooCommerce installieren">

Installieren Sie das Plugin über `WP Admin > POS > Einstellungen > Erweiterungen` oder laden Sie das Asset **payarc-terminal-for-woocommerce.zip** von der [GitHub-Veröffentlichungsseite](https://github.com/wcpos/payarc-terminal-for-woocommerce/releases) herunter und laden Sie es über `Plugins > Neu hinzufügen > Plugin hochladen` hoch. Aktivieren Sie das Plugin.

  </StepCard>
  <StepCard number="2" title="PayArc-Zugangsdaten eingeben">

1. Rufen Sie `WP Admin > WooCommerce > Einstellungen > Zahlungen` auf und öffnen Sie **PayArc Terminal**.
2. Wählen Sie **Modus**: `Live` ist die Standardeinstellung. Verwenden Sie `Test` nur mit PayArc-Test-Dashboard-Zugangsdaten und der PayArc-Connect-Test-App. Mischen Sie niemals Umgebungen.
3. Geben Sie die **PayArc-Anmelde-E-Mail-Adresse** ein, die Sie für die Anmeldung am PayArc-Händler-Dashboard verwenden.
4. Geben Sie die **PayArc MID** aus dem PayArc-Händlerprofil ein, nicht die Terminal-ID.
5. Geben Sie **PayArc ClientSecret** aus dem API-Bereich des Dashboards und **PayArc SecretKey / API-Bearer-Token** aus dem PayArc-Dashboard ein.
6. Lassen Sie **Callback-Bearer-Token** leer, sofern Sie keines vom PayArc-Support erhalten haben; es ist optional.

  </StepCard>
  <StepCard number="3" title="Verbinden">

Klicken Sie auf **Mit diesen Zugangsdaten verbinden**. Bei erfolgreicher Verbindung werden Sie aufgefordert, die Terminal-Seriennummer einzugeben oder zu bestätigen und die Einstellungen zu speichern. Wenn angezeigt wird, dass die Zugangsdaten zur anderen Umgebung gehören, ändern Sie den **Modus** und stellen Sie die Verbindung erneut her.

:::note
Klicken Sie nach jeder Änderung des Modus oder der Zugangsdaten erneut auf **Mit diesen Zugangsdaten verbinden** und speichern Sie die Einstellungen. Zahlungen sind gesperrt, bis Modus und Zugangsdaten mit der gespeicherten Verbindung übereinstimmen. Wenn Sie von einer Version vor 0.1.14 aktualisieren, klicken Sie einmal auf Verbinden.
:::

  </StepCard>
  <StepCard number="4" title="Terminal hinzufügen">

1. Geben Sie die PAX-**Terminal-Seriennummer** vom **S/N**-Etikett auf der Rückseite des Geräts ein, die PayArc für Ihr Konto eingerichtet hat.
2. Wählen Sie **Zahlungsart** und **Beleg drucken**.
3. Prüfen Sie, ob die **Webhook-URL** HTTPS verwendet. Geben Sie sie PayArc nur auf Anfrage.
4. Klicken Sie auf **Änderungen speichern**.

Für den Live-Modus ist eine HTTPS-Website erforderlich.

  </StepCard>
  <StepCard number="5" title="In WCPOS aktivieren" isLast>

1. Rufen Sie `WP Admin > POS > Einstellungen > Kasse` auf.
2. Suchen Sie das Zahlungsgateway **PayArc Terminal** und aktivieren Sie es für den POS.
3. Speichern Sie Ihre Einstellungen.

:::note
Das Kontrollkästchen **Aktivieren/Deaktivieren** auf der WooCommerce-Einstellungsseite steuert nur den Checkout des *Online-Shops*. WCPOS verwendet dieses Zahlungsgateway nach der Einrichtung unabhängig davon, ob das Kästchen aktiviert ist.

Die meisten Shops lassen diese Option deaktiviert.
:::

  </StepCard>
</Steps>

## Einstellungen im Überblick {#settings}

| Einstellung | Funktion |
|---|---|
| **Aktivieren/Deaktivieren** | Aktiviert PayArc Terminal für den Checkout des Online-Shops. Standardmäßig deaktiviert; die Aktivierung für den POS erfolgt unter `POS > Einstellungen > Kasse` |
| **Titel** | Die Checkout-Bezeichnung; Standardwert: `PayArc Terminal` |
| **Beschreibung** | Die Checkout-Beschreibung; Standardwert: `Pay in person at a PayArc PAX terminal.` |
| **Modus** | `Live` (Standard) oder `Test`. Für den Testmodus sind PayArc-Test-Dashboard-Zugangsdaten und die PayArc-Connect-Test-App erforderlich |
| **PayArc-Anmelde-E-Mail-Adresse** | Ihre Anmelde-E-Mail-Adresse für das PayArc-Händler-Dashboard; vor dem Verbinden erforderlich |
| **PayArc MID** | Die Händler-MID aus Ihrem PayArc-Händlerprofil, nicht die Terminal-ID |
| **PayArc ClientSecret** | Das Geheimnis aus dem API-Bereich des Dashboards; wird nur auf Ihrem Server gespeichert |
| **PayArc SecretKey / API-Bearer-Token** | Das Token aus dem PayArc-Dashboard, das zur Anmeldung und zum Abrufen des Terminalregisters verwendet wird |
| **Callback-Bearer-Token** | Optional. Tragen Sie es nur ein, wenn Sie eines vom PayArc-Support erhalten haben |
| **PayArc-Verbindung** | Schaltflächen **Mit diesen Zugangsdaten verbinden**, **Terminals aktualisieren** und **Trennen** |
| **Terminal-Seriennummer** | Die Ihrem Konto zugewiesene PAX-S/N, die für Zahlungen erforderlich ist. Wird eingetragen, wenn sie im Register gefunden wird; geben Sie sie vor dem Speichern ein oder bestätigen Sie sie |
| **Zahlungsart** | `CREDIT` (Standard) oder `DEBIT` |
| **Beleg drucken** | `0` — keiner (Standard), `1` — Händler, `2` — Kunde, `3` — beide |
| **Webhook-URL** | Schreibgeschützte Callback-Adresse. Prüfen Sie, ob sie HTTPS verwendet; geben Sie sie PayArc nur auf Anfrage |
| **PayArc-Diagnose** | Verbindungsinformationen und eine Schaltfläche **Einstellungen überprüfen**; Geheimnisse werden niemals angezeigt |

Bei gespeicherten Geheimnisfeldern werden nur die letzten 4 Zeichen angezeigt. Lassen Sie ein Geheimnisfeld leer, um den gespeicherten Wert beizubehalten.

Die Tabelle **PayArc-Diagnose** zeigt Modus, Endpunkte, maskierte MID / Mandanten-ID / Seriennummer, ob das Connect-Zugriffstoken eingerichtet ist, die Webhook-URL, den letzten Callback und den letzten PayArc-Fehler. Verwenden Sie **Einstellungen überprüfen**, um Ihre Einstellungen zu prüfen.

## Verwendung {#usage}

### Zahlungen verarbeiten {#processing-payments}

1. **Zahlungsgateway auswählen**: Wählen Sie im POS **PayArc Terminal** als Zahlungsmethode.
2. **Zahlung starten**: Klicken Sie auf **Zahlung starten**, um den Gesamtbetrag der Bestellung an das Terminal zu senden.
3. **Kundenzahlung**: Lassen Sie die Seite geöffnet, während der Kunde die Zahlung am PAX-Terminal abschließt. Beachten Sie die Statusmeldungen: `Starting terminal payment...` → `Payment sent to terminal.` → `Waiting for the terminal result...` → `Payment approved. Completing the order...`
4. **Automatischer Abschluss**: Sobald PayArc die Zahlung bestätigt, wird die Bestellung automatisch abgeschlossen.

### Zahlungssteuerung {#payment-controls}

- **Zahlung abbrechen** wird angezeigt, sobald eine Zahlung gestartet wurde. Wenn PayArc noch keine Trace-ID zurückgegeben hat, warten Sie kurz, bevor Sie abbrechen.
- Nach einer Ablehnung, einem Abbruch oder einer Zeitüberschreitung können Sie es erneut versuchen. Prüfen Sie nach einer Zeitüberschreitung vor dem erneuten Versuch das Terminal.
- Das Zahlungsaktivitätsprotokoll ist standardmäßig eingeklappt. Klicken Sie auf **Aktivität anzeigen**, um es einzublenden, und auf **Leeren**, um die angezeigte Aktivität zu löschen.

### Belege {#receipts}

Die Einstellung **Beleg drucken** steuert den Belegdruck am Terminal: keinen, Händlerbeleg, Kundenbeleg oder beide.

## Rückerstattungen {#refunds}

Rückerstattungen werden vom Plugin nicht unterstützt. Führen Sie die Rückerstattung über PayArc durch und erfassen Sie sie anschließend manuell in WooCommerce.

## Protokolle {#logs}

Sie finden die Protokolle unter `WooCommerce > Status > Protokolle` in der Quelle `payarc-terminal-for-woocommerce`. Die Protokolle enthalten Verbindungsversuche, gestartete oder fehlgeschlagene Verkäufe, Abbrüche sowie angenommene oder abgelehnte Callbacks. Kennungen sind maskiert und Geheimnisse unkenntlich gemacht.

Es gibt keinen Download für ein Supportpaket. Wenn Sie Hilfe anfordern, senden Sie die Bestellnummer und die relevanten Protokollzeilen. Geben Sie keine vollständigen MIDs, Terminal-IDs, Token oder Kartendaten weiter.

## Umfang und Einschränkungen {#scope-and-limitations}

- Rückerstattungen werden vom Plugin nicht unterstützt.
- Es wird der **gesamte Bestellbetrag** belastet; Teil- oder geteilte Zahlungen werden nicht unterstützt.
- Trinkgeld wird nicht unterstützt.
- Ein Terminal pro Filiale: eine einzelne Einstellung für die Seriennummer, keine Auswahl durch den Kassierer.
- Die verfügbaren Währungen sind auf **USD, CAD, GBP, EUR und JPY** beschränkt.
- Zahlungen sind gesperrt, bis Modus und Zugangsdaten mit der gespeicherten Verbindung übereinstimmen.

## Fehlerbehebung {#troubleshooting}

### Häufige Probleme {#common-issues}

<Accordion>
  <AccordionItem question="Die Zugangsdaten scheinen zur anderen Umgebung zu gehören">

  - Der ausgewählte Modus und die Zugangsdaten stammen aus unterschiedlichen Umgebungen.
  - Ändern Sie den **Modus**, sodass er zu den Zugangsdaten passt, oder ersetzen Sie die Zugangsdaten durch jene für den ausgewählten Modus.
  - Klicken Sie erneut auf **Mit diesen Zugangsdaten verbinden** und speichern Sie.

  </AccordionItem>
  <AccordionItem question="PayArc-Verbindung nicht möglich">

  - PayArc hat die Anmeldeinformationen abgelehnt. Prüfen Sie die eingegebenen Zugangsdaten und versuchen Sie es erneut.
  - Weitere Informationen finden Sie unter `WooCommerce > Status > Protokolle` in der Quelle `payarc-terminal-for-woocommerce`.

  </AccordionItem>
  <AccordionItem question="Zahlungsanforderung kann nicht verarbeitet werden. (HTTP 500)">

  - Diese Meldung für den Kassierer ist allgemein gehalten. Suchen Sie im WooCommerce-Protokoll nach **PayArc payment action failed**, um die tatsächliche Ursache zu finden.
  - Klicken Sie nach einer Änderung des Modus oder der Zugangsdaten erneut auf **Mit diesen Zugangsdaten verbinden** und speichern Sie.
  - Prüfen Sie, ob die **Terminal-Seriennummer** eingetragen ist.
  - Wenn im Protokoll steht, dass PayArc sowohl das Connect-Zugriffstoken als auch den SecretKey abgelehnt hat, bitten Sie den PayArc-Support zu bestätigen, dass **PayArc Connect V3** für Ihr Händlerkonto aktiviert ist.
  - Prüfen Sie, ob die Shopwährung **USD, CAD, GBP, EUR oder JPY** ist.

  </AccordionItem>
  <AccordionItem question="Zugriff verweigert. (HTTP 403) beim Starten der Zahlung">

  - Aktualisieren Sie auf **0.1.12 oder höher**. Damit wird dieser Fehler bei POS-Sitzungen behoben.

  </AccordionItem>
  <AccordionItem question="Terminalregister ist leer">

  - Ein leeres Register oder ein Terminal ohne POS-Kennung ist normal.
  - Die Registerdaten dienen nur der Information. Für Zahlungen wird die **Terminal-Seriennummer** verwendet.

  </AccordionItem>
  <AccordionItem question="Eine Zahlung dauert zu lange">

  - Prüfen Sie die Anzeige des Terminals und lassen Sie die Zahlungsseite geöffnet.
  - Prüfen Sie vor einem erneuten Versuch die Bestellnotizen und das PayArc-Dashboard.
  - Die Seite prüft alle **1.5 Sekunden** und wird nach **5 Minuten** beendet.

  </AccordionItem>
</Accordion>
