# Windcave-Terminal-Zahlungsgateway {#windcave-terminal-gateway}

Mit dem Windcave-Terminal-Zahlungsgateway können Sie Vor-Ort-Kartenzahlungen über Windcave HIT an einem Windcave-Terminal annehmen. Zahlungen werden in WCPOS gestartet und am Terminal abgeschlossen. Die Bestätigung wird anschließend in den WooCommerce-Auftrag übernommen.

:::warning Neu in 0.1.0 — Windcave-Zertifizierung steht noch aus
0.1.0 ist die erste Version. Windcave verlangt eine QA-Zertifizierung der Integration, bevor sie in der Produktion eingesetzt wird. Diese Integration ist noch nicht zertifiziert. Verwenden Sie bis zum Abschluss der Zertifizierung Windcave-Zugangsdaten für **UAT** (Test). Die **Vendor ID** wird Ihnen während der Zertifizierung von Windcave zugeteilt.
:::

## Funktionsweise {#how-it-works}

Das Zahlungsgateway verwendet Windcave **HIT (Host Initiated Transaction)** über HTTPS. Mit **Environment** wird der UAT- oder Produktionsendpunkt ausgewählt. Jedes Terminal wird über seine von Windcave vergebene **Station ID** angesprochen.

Beim Start einer Zahlung werden die vollständige Auftragssumme und die Währung an das Terminal gesendet. Die Zahlungsseite fragt Windcave alle **1.5 Sekunden** ab und zeigt die Anweisungen und verfügbaren Schaltflächen des Terminals an. Mit optionalen **Result notifications (FPRN)** kann Windcave die Website ergänzend zu den regelmäßigen Abfragen benachrichtigen.

## Einrichtung {#setup}

<Steps>
  <StepCard number="1" title="Windcave Terminal für WooCommerce installieren">

Laden Sie das **ZIP-Installationspaket des Plugins** (nicht das ZIP mit dem GitHub-Quellcode) von der [GitHub-Releases-Seite](https://github.com/wcpos/windcave-terminal-for-woocommerce/releases) herunter. Laden Sie es über `Plugins > Neu hinzufügen > Plugin hochladen` hoch und aktivieren Sie es, wenn WooCommerce installiert und aktiviert ist.

Für die Aktivierung sind **PHP 7.4+** und die **PHP-DOM-Erweiterung (php-xml)** erforderlich. Fehlt eine der beiden Voraussetzungen, wird die Aktivierung mit einer Meldung abgelehnt.

  </StepCard>
  <StepCard number="2" title="HIT-Zugangsdaten von Windcave anfordern">

Fordern Sie bei Windcave einen **HIT-Benutzernamen**, einen **HIT-Schlüssel** und eine **Station ID** pro Terminal an. Beantragen Sie über das [Formular zu den Integrationsanforderungen](https://www.windcave.com/merchant-attended-developer-hit) ein Entwicklungskonto.

UAT- und Produktionszugangsdaten sind getrennt. Verwenden Sie UAT-Zugangsdaten, solange diese Integration noch nicht zertifiziert ist.

  </StepCard>
  <StepCard number="3" title="Zahlungsgateway konfigurieren">

1. Rufen Sie `WP Admin > WooCommerce > Einstellungen > Zahlungen` auf und öffnen Sie **Windcave Terminal**.
2. Stellen Sie **Environment** auf `UAT (testing)` (Standardeinstellung). `Production` ist nach der Windcave-Zertifizierung mit Produktionszugangsdaten zu verwenden.
3. Geben Sie den von Windcave bereitgestellten **HIT-Benutzernamen** und **HIT-Schlüssel** ein.
4. Geben Sie Ihre **Station IDs** jeweils in einer eigenen Zeile ein.
5. *(Optional)* Legen Sie eine **Default Station ID** fest. Aktivieren Sie **Lock terminal selection**, damit immer diese Standardstation verwendet wird und Kassierer sie nicht ändern können.
6. Lassen Sie **Vendor ID** leer, bis Windcave Ihnen während der Zertifizierung eine ID zuteilt.
7. Speichern Sie Ihre Einstellungen.

  </StepCard>
  <StepCard number="4" title="Ergebnisbenachrichtigungen aktivieren (optional)">

Aktivieren Sie **Result notifications (FPRN)** und speichern Sie die Einstellungen, damit Windcave Ihre Website benachrichtigt, sobald ein Transaktionsergebnis vorliegt. Dies dient als Ergänzung zu den regelmäßigen Abfragen.

  </StepCard>
  <StepCard number="5" title="In WCPOS aktivieren" isLast>

1. Rufen Sie `WP Admin > POS > Einstellungen > Kasse` auf.
2. Suchen Sie das Zahlungsgateway **Windcave Terminal** und aktivieren Sie es für den POS.
3. Speichern Sie Ihre Einstellungen.

:::note
Das Kontrollkästchen **Enable/Disable** in den WooCommerce-Einstellungen steuert nur den Checkout im *Onlineshop*. WCPOS verwendet dieses Zahlungsgateway nach der Konfiguration unabhängig davon, ob das Kästchen aktiviert ist.
:::

  </StepCard>
</Steps>

## Referenz der Einstellungen {#settings}

| Einstellung | Funktion |
|---|---|
| **Enable/Disable** | Aktiviert das Zahlungsgateway für den Checkout im Onlineshop. Die Aktivierung für den POS wird unter `POS > Einstellungen > Kasse` gesteuert. |
| **Title** | Die Bezeichnung im Checkout; Standardwert: `Windcave Terminal`. |
| **Description** | Die Beschreibung im Checkout; Standardwert: `Pay in person on the Windcave terminal.` |
| **Environment** | `UAT (testing)` (Standardwert) oder `Production`. Für beide Umgebungen sind separate HIT-Zugangsdaten erforderlich; für die Produktion ist eine Windcave-Zertifizierung nötig. |
| **HIT username** | Der von Windcave für die ausgewählte Umgebung bereitgestellte HIT-Benutzername. |
| **HIT key** | Der von Windcave für die ausgewählte Umgebung bereitgestellte HIT-Schlüssel. |
| **Station IDs** | Eine von Windcave vergebene Station ID pro Zeile, je eine für jedes Terminal. |
| **Default Station ID** | Die vorausgewählte Station, die auch verwendet wird, wenn keine Station ausgewählt ist. |
| **Lock terminal selection** | Verwendet immer die Standardstation, sodass Kassierer sie nicht ändern können. Wird nur wirksam, wenn eine Standardstation festgelegt ist. |
| **Vendor ID** | Wird Ihnen während der Zertifizierung von Windcave zugeteilt. Lassen Sie das Feld leer, bis Windcave Ihnen die ID mitteilt. |
| **POS name** | Der an Windcave gesendete Name zur Identifizierung des POS; Standardwert: `WCPOS`. |
| **Result notifications (FPRN)** | Bittet Windcave, die Website als Ergänzung zu den regelmäßigen Abfragen zu benachrichtigen, sobald ein Transaktionsergebnis vorliegt. Standardmäßig deaktiviert. |
| **Checkout logs** | Zeigt Protokollwerkzeuge im Zahlungsbereich an. Standardmäßig deaktiviert. |
| **Log level** | `Off`, `Errors only` oder `Debug`. Standardwert: Debug. Anfragen und Antworten werden protokolliert; Schlüssel- und Kartendaten werden maskiert. |
| **Support** | Stellt **Download support bundle** und einen Link zum Anzeigen der Protokolle unter `WooCommerce > Status > Protokolle` bereit. |

Es gibt keine Schaltfläche zum Verbindungstest: Zugangsdaten und Station IDs werden bei der ersten Zahlung geprüft.

## Verwendung {#usage}

### Zahlungen verarbeiten {#processing-payments}

1. **Add Items**: Fügen Sie Produkte im POS zum Warenkorb hinzu.
2. **Select Gateway**: Wählen Sie **Windcave Terminal** als Zahlungsmethode aus.
3. **Choose Terminal**: Wählen Sie eine Station aus oder verwenden Sie die gesperrte Standardstation. Wenn mindestens zwei Stationen vorhanden und keine Standardstation festgelegt ist, muss eine Station ausgewählt werden.
4. **Start Payment**: Klicken Sie auf **Start Terminal Payment**, um die Auftragssumme an das Terminal zu senden.
5. **Follow Prompts**: Die Anweisungen und verfügbaren Schaltflächen des Terminals werden auf dem Bildschirm angezeigt, darunter **YES/NO** zur Signaturprüfung und **CANCEL**, sofern verfügbar.
6. **Automatischer Abschluss**: Nach der Genehmigung und Verifizierung wird der Auftrag abgeschlossen und der POS wechselt zum Beleg.

### Zahlungssteuerung {#payment-controls}

- **Start Terminal Payment**: Sendet eine neue Zahlungsanforderung an die ausgewählte Station.
- **Cancel Terminal Payment**: Betätigt die Schaltfläche **CANCEL** am Terminal, sofern diese verfügbar ist. Andernfalls brechen Sie den Vorgang am Terminal ab oder stellen Sie die Zahlung zurück, sobald diese Option erscheint.
- **Zahlung zurückstellen**: Erscheint nach der **5-Minuten-Zeitüberschreitung**. Der Zahlungsversuch wird durch eine **10-minütige Hintergrundprüfung** weiterverfolgt, sodass Sie die Zahlung auf anderem Weg annehmen können. Die Zahlung bei Windcave wird dadurch nicht abgebrochen.
- **Seite neu laden**: Setzt eine bereits laufende Zahlung fort.

### Belege {#receipts}

Von Windcave zurückgegebener Terminal-Belegtext wird als **private Auftragsnotiz** in WooCommerce gespeichert.

## Rückerstattungen {#refunds}

Rückerstattungen über WooCommerce werden in **0.1.0 nicht unterstützt**. Erstatten Sie den Betrag im Windcave-Portal (**Payline**) oder am Terminal und erfassen Sie die Rückerstattung anschließend **manuell** in WooCommerce.

## Protokolle und Support-Paket {#logs-and-support-bundle}

Die Protokolle finden Sie unter `WooCommerce > Status > Protokolle` in der Quelle `windcave-terminal`. Die Standard-Protokollebene ist **Debug**. Windcave-Anfragen und -Antworten werden dabei aufgezeichnet; Schlüssel- und Kartendaten sind maskiert.

Klicken Sie auf dem Bildschirm mit den Einstellungen des Zahlungsgateways auf **Download support bundle**, um eine `.json`-Datei herunterzuladen, und senden Sie diese zusammen mit der **Auftragsnummer**. Sie enthält Umgebungsdetails, Einstellungen mit maskiertem HIT-Schlüssel und Benutzernamen, Zahlungsversuche aus bis zu 20 aktuellen Aufträgen ohne Belege sowie die letzten 1,000 Zeilen der beiden neuesten Protokolldateien. Protokollzeilen können Text von Terminalbelegen enthalten; Kartennummern sind maskiert.

Wenn WooCommerce den **Datenbank-Protokollhandler** verwendet, enthält das Paket keine Protokollzeilen. Exportieren Sie die Protokolle stattdessen unter `WooCommerce > Status > Protokolle`.

Aktivieren Sie **Checkout logs**, um die Protokollwerkzeuge im Zahlungsbereich anzuzeigen.

## Umfang und Einschränkungen {#scope-and-limitations}

:::warning Zertifizierung erforderlich
Diese Integration ist noch nicht von Windcave zertifiziert. Verwenden Sie **UAT**-Zugangsdaten, bis die QA-Zertifizierung durch Windcave abgeschlossen ist. Setzen Sie die Integration vor der Zertifizierung nicht in der Produktion ein.
:::

- Rückerstattungen über WooCommerce werden in 0.1.0 nicht unterstützt.
- Trinkgelder, Zuschläge und Bargeldabhebungen werden nicht unterstützt.
- Es werden nur **Währungen mit zwei Dezimalstellen** unterstützt.
- Dem Terminal wird die **gesamte Auftragssumme** belastet; Teilbeträge eines Auftrags können nicht am Terminal bezahlt werden.
- **Station IDs** werden manuell eingegeben; Terminals werden nicht automatisch erkannt.
- Das Zahlungsgateway ist für den POS vorgesehen. Im Onlineshop funktioniert es nur auf der **order-pay-Seite**.

## Fehlerbehebung {#troubleshooting}

### Häufige Probleme {#common-issues}

<Accordion>
  <AccordionItem question="Aktivierung abgelehnt: PHP-DOM-Erweiterung (php-xml) erforderlich">

  - Auf dem Server fehlt die PHP-DOM-Erweiterung.
  - Bitten Sie Ihren Hoster, **php-xml** zu aktivieren. Für die Aktivierung ist außerdem **PHP 7.4+** erforderlich.

  </AccordionItem>
  <AccordionItem question="Keine Station IDs konfiguriert">

  - Die Einstellung **Station IDs** ist leer.
  - Fügen Sie die von Windcave vergebenen Station IDs in den Einstellungen des Zahlungsgateways jeweils in einer eigenen Zeile hinzu und speichern Sie die Einstellungen.

  </AccordionItem>
  <AccordionItem question="Windcave-HIT-Zugangsdaten nicht konfiguriert">

  - Der **HIT-Benutzername** oder **HIT-Schlüssel** ist nicht eingetragen.
  - Tragen Sie beide Werte in den Einstellungen des Zahlungsgateways ein und speichern Sie sie. Achten Sie darauf, dass **Environment** zu diesen Zugangsdaten passt.

  </AccordionItem>
  <AccordionItem question="Das Terminal schließt noch eine vorherige Transaktion ab">

  - An dieser Station läuft noch eine vorherige Transaktion.
  - Schließen Sie sie am Terminal ab oder brechen Sie sie dort ab und versuchen Sie es dann erneut.

  </AccordionItem>
  <AccordionItem question="Windcave hat keine Aufzeichnung zu dieser Transaktion">

  - Auch nach der anfänglichen Kulanzfrist von 30 Sekunden liegt Windcave keine Aufzeichnung vor.
  - Starten Sie die Zahlung erneut.

  </AccordionItem>
  <AccordionItem question="Windcave hat eine Zahlung genehmigt, sie konnte jedoch nicht verbucht werden">

  - Das genehmigte Ergebnis hat die Prüfungen zum Abschließen dieses Auftrags nicht bestanden.
  - Prüfen Sie das **Windcave-Portal** und die **Auftragsnotizen, bevor Sie den Betrag erneut abbuchen**.

  </AccordionItem>
  <AccordionItem question="Diese Zahlung wurde in einer anderen Umgebung gestartet">

  - **Environment** wurde geändert, während die Zahlung lief.
  - Wechseln Sie zurück zu der Umgebung, in der die Zahlung gestartet wurde, oder prüfen Sie das Windcave-Portal.

  </AccordionItem>
</Accordion>

- Besuchen Sie das [GitHub-Repository](https://github.com/wcpos/windcave-terminal-for-woocommerce), um Probleme zu melden.
- Wenden Sie sich bei Fragen zu Konto, Zugangsdaten oder Hardware an den Windcave-Support.
