## Nur-POS-Produkte aktivieren {#enable-pos-only-products}

Diese Einstellung ergänzt Ihre Produkte um Sichtbarkeitsoptionen. Damit legen Sie fest, ob die Produkte im Onlineshop, im POS oder in beiden erscheinen.

:::warning Auswirkungen auf die Leistung
Aktivieren Sie diese Einstellung nur, wenn Sie Produkte im Onlineshop oder im POS ausblenden müssen. Bei aktivierter Einstellung wird für jede Produktanfrage eine zusätzliche Datenbankabfrage ausgeführt.
:::

Ausführliche Informationen zur Verwendung dieser Funktion, einschließlich der Sichtbarkeitseinstellungen für einzelne Produkte und der Massenbearbeitung, finden Sie unter [Nur-POS-Produkte](/1.x/products/pos-only-products).

## Dezimalmengen aktivieren {#enable-decimal-quantities}

Mit dieser Einstellung können Kunden und Mitarbeiter Dezimalmengen eingeben, wenn sie Produkte zum Warenkorb hinzufügen.

**Beispiele für Dezimalmengen:**
- 0.25 (eine Viertel-Einheit)
- 1.5 (eineinhalb Einheiten)
- 2.75 (zwei und dreiviertel Einheiten)

**Nützlich für:**
- Produkte, die nach Gewicht verkauft werden (z. B. 0.5kg Kaffeebohnen)
- Anteilige Dienstleistungen (z. B. 1.5 Stunden Beratung)
- Lose Ware, die in Teilmengen verkauft werden kann

:::note Nach Gewicht verkaufen
WCPOS stellt keine Verbindung zu einer Waage her und liest keine Gewichte von ihr aus. Wiegen Sie den Artikel und geben Sie das Gewicht anschließend als Menge der Warenkorbzeile ein: Bei einem Produkt mit einem Kilopreis entsprechen 350 g einer Menge von `0.35`. Aktivieren Sie diese Einstellung zuerst, da Ihr Shop Bestellungen mit Bruchteilmengen sonst ablehnt.

WCPOS liest auch keine Gewichts- oder Preisangaben aus den Barcode-Etiketten aus, die manche Waagen drucken.
:::

## Bestand beim Löschen einer Bestellung wiederherstellen {#restore-stock-on-order-delete}

Wenn diese Option aktiviert ist, stellt WCPOS den Produktbestand automatisch wieder her, sobald eine POS-Bestellung in den Papierkorb verschoben oder gelöscht wird. Wenn Sie einen versehentlichen Verkauf rückgängig machen, werden die Artikel so wieder dem Bestand hinzugefügt. Diese Einstellung ist **standardmäßig aktiviert**.

Deaktivieren Sie die Option, wenn Sie den Bestand auf andere Weise abgleichen und nicht möchten, dass gelöschte POS-Bestellungen den Lagerbestand verändern.

## Benutzernamen automatisch aus Kunden-E-Mail generieren {#automatically-generate-username-from-customer-email}

Wenn diese Option aktiviert ist, erstellt WCPOS beim Checkout automatisch Benutzernamen für neue Kunden auf Grundlage ihrer E-Mail-Adressen. Das vereinfacht das Anlegen von Kunden und sorgt für einheitlich formatierte Benutzernamen.

## Standard-POS-Kunde {#default-pos-customer}

Wählen Sie den Standardkunden aus, der neuen POS-Bestellungen zugewiesen wird. Gängige Optionen sind:

- **Gast**: Bestellungen werden keinem Benutzerkonto zugeordnet
- **Kassierer**: Bestellungen werden dem Konto des angemeldeten Kassierers zugeordnet
- **Laufkunde**: Bestellungen werden einem bestimmten Kundenkonto zugeordnet (dieses Konto müssen Sie zuerst erstellen)

## Kassiererkonto verwenden {#use-cashier-account}

Wenn diese Option aktiviert ist, wird das Benutzerkonto des Kassierers anstelle des ausgewählten Standard-POS-Kunden als Standardkunde für POS-Bestellungen verwendet.

## Kunden Belege herunterladen lassen {#storefront-receipts}

Wenn diese Option aktiviert ist, fügt WCPOS unter **Mein Konto → Bestellungen** in Ihrem Onlineshop eine Schaltfläche **Beleg** hinzu. Kunden können damit ihren Bestellbeleg als PDF herunterladen, das mit Ihrer WCPOS-Vorlage erstellt wird. Diese Einstellung ist **standardmäßig deaktiviert**.

Über das Dropdown-Menü **Belegvorlage für Kunden** unter dem Schalter wählen Sie die Vorlage aus, die Kunden erhalten. Standardmäßig ist **Aktive Belegvorlage verwenden** ausgewählt, sodass die Vorlage mit Ihrem POS übereinstimmt. Wählen Sie eine bestimmte Vorlage, wenn Online-Bestellungen ein anderes Erscheinungsbild erhalten sollen (zum Beispiel eine ganzseitige Rechnung).

Die vollständige Anleitung mit den zulässigen Bestellstatus, dem Shortcode `[wcpos_receipt]` und Entwicklerfiltern finden Sie unter [Belege im Onlineshop](/1.x/receipts/storefront).

## Barcodefeld {#barcode-field}

Diese Einstellung legt fest, welches Produktfeld WCPOS beim Scannen von Barcodes oder bei der Barcode-Suche durchsucht.

<a id="default-option"></a>

:::note Standard-Meta-Schlüssel
Verwenden Sie **`_global_unique_id`** — das Feld „Globale eindeutige ID“ von WooCommerce, das mit WooCommerce 9.2 (August 2024) eingeführt wurde. Es dient zum Speichern von GTIN-, UPC-, EAN- oder ISBN-Codes und ist die empfohlene Option für neue Installationen. Wenn Sie das Feld „Globale eindeutige ID“ nicht verwenden, ist **`_sku`** (das Produktfeld SKU / Stock Keeping Unit) eine gute Alternative.
:::

### Gängige Plugins → Meta-Schlüssel {#common-plugins-meta-key}

Wenn Sie ein Plugin zur Barcode-Verwaltung verwenden, müssen Sie möglicherweise stattdessen dessen spezifischen Meta-Schlüssel verwenden:

| Plugin-/Feldtyp | Meta-Schlüssel |
|---|---|
| WooCommerce Globale eindeutige ID *(Standard, empfohlen)* | `_global_unique_id` |
| Produkt-SKU *(Alternative)* | `_sku` |
| EAN-Plugins (Europäische Artikelnummer) | `_ean`, `_ean13`, `_ean8` |
| EAN for WooCommerce (EAN Barcode Generator von WPFactory) | `_alg_ean`, sofern Sie **Meta key** nicht in den erweiterten Einstellungen geändert haben |
| UPC-Plugins (Universal Product Code) | `_upc`, `_upc_code` |
| GTIN-Plugins (Global Trade Item Number) | `_gtin`, `_gtin13`, `_gtin14` |
| Allgemeine Barcode-Felder | `_barcode`, `_product_barcode` |
| WooCommerce Product Barcodes | `_barcode_text` |
| ATUM Inventory | `_atum_barcode` |

<a id="custom-meta-keys"></a>

:::tip Benutzerdefinierte Meta-Schlüssel
Sie können **jeden** benutzerdefinierten Meta-Schlüssel verwenden, in dem Barcode-Daten gespeichert sind. Geben Sie einfach den Namen des Meta-Schlüssels (gegebenenfalls einschließlich des führenden Unterstrichs) in dieses Feld ein.
:::

### Den Meta-Schlüssel Ihres Plugins finden {#finding-your-plugins-meta-key}

Wenn Ihr Plugin oben nicht aufgeführt ist, finden Sie den richtigen Meta-Schlüssel wie folgt:

<Steps>
  <StepCard number="1" title="Einem Produkt einen Barcode hinzufügen">

Bearbeiten Sie ein Produkt in WP Admin und fügen Sie mithilfe Ihres Plugins einen Barcode hinzu.

  </StepCard>
  <StepCard number="2" title="Die Plugin-Dokumentation prüfen">

Suchen Sie in der Plugin-Dokumentation nach dem Namen des verwendeten Meta-Schlüssels.

  </StepCard>
  <StepCard number="3" title="Oder die Datenbank untersuchen" isLast>

Prüfen Sie in der Datenbanktabelle `wp_postmeta`, welcher Meta-Schlüssel für das Produkt angelegt wurde.

  </StepCard>
</Steps>

:::note Beim Ändern dieser Einstellung wird der Barcode-Index neu erstellt
Wenn Sie das Barcode-Feld ändern, erstellt WCPOS den Barcode-Index des lokalen Katalogs neu, damit Scans mit dem neu ausgewählten Feld abgeglichen werden. Sie müssen Ihre Produkte nicht manuell löschen und erneut herunterladen.

Wenn Scans weiterhin keine passenden Treffer liefern, können Sie eine vollständige Aktualisierung erzwingen: Öffnen Sie die Seite „Produkte“, drücken Sie **lange** auf das Synchronisierungssymbol (↻) unten und wählen Sie **„Löschen und aktualisieren“**. Testen Sie anschließend einen Scan, um zu bestätigen, dass das neue Feld verwendet wird.
:::

## Datenschutz {#privacy}

Der Schalter **Anonyme Nutzungsdaten erlauben** steuert, ob WCPOS anonyme Nutzungsdaten zur Verbesserung des Produkts erfasst. Sie können die Erfassung ausdrücklich ein- oder ausschalten — Kundendaten, Preise oder Filialadressen werden niemals erfasst. Über den Link **Mehr erfahren** neben der Einstellung können Sie genau nachlesen, welche Daten erfasst werden und welche nicht.

## Steuer-IDs der Filiale {#store-tax-ids}

Fügen Sie die geschäftlichen Steuerkennungen hinzu — Umsatzsteuer-ID, ABN, GSTIN, EIN oder lokale Handelsregisternummern —, die WCPOS auf POS-Belegen und Rechnungen druckt. WooCommerce bietet dafür kein integriertes Feld, und in vielen Regionen wird mehr als eine Kennung benötigt.

Die vollständige Anleitung finden Sie unter [Steuer-IDs der Filiale](/1.x/settings/wp-admin/store-tax-ids).

## Steuer-IDs von Kunden {#customer-tax-ids}

WCPOS speichert ein Steuer-ID-Feld bei Ihren Kunden und kopiert es beim Checkout in deren Bestellungen. Da verschiedene Plugins dieses Feld unter unterschiedlichen Namen speichern, erkennt WCPOS, welches Plugin installiert ist, und schreibt automatisch in das richtige Feld. Im Abschnitt **Steuer-IDs** können Sie den Feldnamen bei Bedarf auch überschreiben.

Die vollständige Anleitung finden Sie unter [Steuer-IDs von Kunden](/1.x/settings/wp-admin/customer-tax-ids).
