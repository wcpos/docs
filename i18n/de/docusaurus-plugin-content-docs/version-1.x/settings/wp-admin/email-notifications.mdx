Mit WCPOS steuern Sie für jeden E-Mail-Typ einzeln, welche WooCommerce-Benachrichtigungs-E-Mails für POS-Bestellungen versendet werden — unabhängig von Ihren websiteweiten WooCommerce-E-Mail-Einstellungen. Sie können auch den **Kassierer** benachrichtigen, der den Verkauf abgewickelt hat.

Die Einstellungen befinden sich auf der Seite **Kasse** — gehen Sie zu **WP Admin > POS > Einstellungen > Kasse**. Die E-Mail-Einstellungen stehen oberhalb der Abschnitte Bestellstatus und Zahlungsgateways.

:::info Über E-Mails zu POS-Bestellungen
Die standardmäßigen E-Mail-Auslöser von WooCommerce funktionieren bei POS-Bestellungen nicht immer zuverlässig, da der POS eigene Status wie *POS - Offen* und *POS - Teilweise* verwendet, die WooCommerce nicht kennt. WCPOS löst die E-Mail „Neue Bestellung“ manuell erneut aus, wenn eine Bestellung aus einem dieser Status in Abgeschlossen, In Bearbeitung oder Wartend wechselt. So erhalten Sie zuverlässig eine Benachrichtigung, unabhängig davon, welchen Weg die Bestellung durch den Checkout genommen hat.
:::

## Die drei E-Mail-Gruppen {#the-three-email-groups}

Jede Gruppe verfügt oben über einen **Hauptschalter**. Ist er aktiviert, erscheint darunter eine Liste mit Kontrollkästchen, über die Sie jeden einzelnen E-Mail-Typ aktivieren oder deaktivieren können. Ist er deaktiviert, wird keine dieser E-Mails für POS-Bestellungen versendet (unabhängig von den einzelnen Kontrollkästchen).

### Admin-E-Mails {#admin-emails}

*„WooCommerce-Admin-Benachrichtigungs-E-Mails für POS-Bestellungen“* — **standardmäßig aktiviert.**

Sie werden an die Adresse(n) gesendet, die unter **WooCommerce → Einstellungen → E-Mails → (E-Mail-Typ) → Empfänger** konfiguriert sind.

| E-Mail | Standard | Wird gesendet, wenn |
|---|---|---|
| **Neue Bestellung** | ✓ Aktiviert | Eine POS-Bestellung wechselt zu In Bearbeitung / Abgeschlossen / Wartend |
| **Stornierte Bestellung** | ✓ Aktiviert | Eine POS-Bestellung wird storniert |
| **Fehlgeschlagene Bestellung** | ✓ Aktiviert | Eine POS-Bestellung schlägt fehl (Gateway-Fehler usw.) |

### Kunden-E-Mails {#customer-emails}

*„WooCommerce-Kunden-Benachrichtigungs-E-Mails für POS-Bestellungen“* — **standardmäßig aktiviert.**

Sie werden an die Rechnungs-E-Mail-Adresse des Kunden gesendet — nur bei Bestellungen mit zugeordnetem Kunden (Gastverkäufe werden ohne Hinweis übersprungen).

| E-Mail | Standard | Wird gesendet, wenn |
|---|---|---|
| **Bestellung wartend** | ✓ Aktiviert | Eine POS-Bestellung wechselt zu Wartend |
| **Bestellung in Bearbeitung** | ✓ Aktiviert | Eine POS-Bestellung wechselt zu In Bearbeitung |
| **Abgeschlossene Bestellung** | ✓ Aktiviert | Eine POS-Bestellung wird abgeschlossen |
| **Erstattete Bestellung** | ✓ Aktiviert | Eine POS-Bestellung wird vollständig oder teilweise rückerstattet |
| **Fehlgeschlagene Bestellung** | ✓ Aktiviert | Eine POS-Bestellung schlägt fehl |

### Kassierer-E-Mails {#cashier-emails}

*„Benachrichtigung über neue Bestellung an den Kassierer senden, der die POS-Bestellung bearbeitet hat“* — **standardmäßig deaktiviert.**

| E-Mail | Standard | Wird gesendet, wenn |
|---|---|---|
| **Neue Bestellung** | ✓ Aktiviert *(wenn der Hauptschalter aktiviert ist)* | Eine POS-Bestellung wird von diesem Kassierer abgeschlossen |

WCPOS ermittelt den Kassierer anhand des Metafelds `_pos_user` der Bestellung (der an der Kasse angemeldete WP-Benutzer) und liest die E-Mail-Adresse seines Kontos aus. Stimmt die Kassierer-E-Mail-Adresse mit der Admin-E-Mail-Adresse überein — etwa in einer allein geführten Filiale, in der dieselbe Person Admin und Kassierer ist —, **dedupliziert** WCPOS den Empfänger, damit Sie die E-Mail nicht zweimal erhalten.

Die Schalter für Admin und Kassierer arbeiten **unabhängig** voneinander — das Deaktivieren des einen wirkt sich nicht auf den anderen aus.

## Häufige Szenarien {#common-scenarios}

<Accordion>
  <AccordionItem question="Eine E-Mail-Flut an umsatzstarken Tagen verhindern">

Deaktivieren Sie **Admin-E-Mails → Neue Bestellung**, wenn Ihr Geschäft 50+ Verkäufe pro Tag verzeichnet und der Admin nicht über jeden einzelnen benachrichtigt werden muss. Lassen Sie **Stornierte Bestellung** und **Fehlgeschlagene Bestellung** aktiviert — über diese Ereignisse sollten Sie informiert bleiben.

Für die Umsatzverfolgung ist die Seite [Berichte](/1.x/reports) ohnehin besser geeignet, als E-Mails zu neuen Bestellungen zu zählen.

  </AccordionItem>

  <AccordionItem question="Benachrichtigungen nur an den diensthabenden Kassierer senden, nicht an den Admin">

Deaktivieren Sie den Hauptschalter **Admin-E-Mails** und aktivieren Sie den Hauptschalter **Kassierer-E-Mails**. Der Kassierer, der den jeweiligen Verkauf abschließt, erhält die E-Mail „Neue Bestellung“ an die E-Mail-Adresse seines Kontos, und das Admin-Postfach bleibt übersichtlich.

Dies eignet sich gut für Filialen mit mehreren Kassierern, deren Inhaber nicht über jede einzelne Transaktion informiert werden möchte.

  </AccordionItem>

  <AccordionItem question="Kunden-E-Mails für Verkäufe im Geschäft deaktivieren">

Geschäfte mit vielen Touristen, Marktstände und Cafés mit schneller Bedienung möchten Kunden oft keinen Beleg per E-Mail senden — sie haben bereits den gedruckten Beleg. Deaktivieren Sie den Hauptschalter **Kunden-E-Mails**, damit bei POS-Verkäufen keine E-Mails zu In Bearbeitung / Abgeschlossen / Rückerstattet versendet werden.

Die Kunden-E-Mails für Ihre Online-Bestellungen bleiben davon unberührt, da diese über den regulären WooCommerce-Ablauf versendet werden (nicht über den POS-Ablauf).

  </AccordionItem>

  <AccordionItem question="Kunden-E-Mails aktiviert lassen, aber nicht die E-Mail „In Bearbeitung“">

Wenn Ihre POS-Bestellungen sofort abgeschlossen werden (Barzahlung + Kartenzahlung vor Ort), erhält der Kunde innerhalb derselben Sekunde eine E-Mail *In Bearbeitung* *und* eine E-Mail *Abgeschlossen*. Deaktivieren Sie **Bestellung in Bearbeitung** in der Liste der Kunden-E-Mails, um die überflüssige E-Mail zu vermeiden.

  </AccordionItem>

  <AccordionItem question="Ich habe von einer Version vor v1.8.9 aktualisiert und mein bisheriger einzelner Schalter „E-Mails aktivieren“ ist verschwunden">

Der einzelne Ein-/Ausschalter früherer Versionen wurde durch die oben beschriebene Struktur mit drei Gruppen ersetzt. WCPOS übernimmt Ihre bisherige Einstellung automatisch: Waren E-Mails zuvor deaktiviert, sind alle drei Hauptschalter deaktiviert; waren sie aktiviert, sind die Hauptschalter für Admin und Kunden aktiviert und der für Kassierer deaktiviert (die neue Standardeinstellung).

Sie müssen nichts unternehmen; die Migration erfolgt automatisch, wenn Sie nach dem Upgrade die Seite mit den Checkout-Einstellungen öffnen.

  </AccordionItem>
</Accordion>

## Entwickler-Hooks {#developer-hooks}

Für die programmatische Steuerung über die Benutzeroberfläche hinaus stehen die folgenden WordPress-Filter zur Verfügung:

| Filter | Zweck |
|---|---|
| `woocommerce_pos_admin_email_enabled` | Den Hauptschalter für Admin-E-Mails überschreiben |
| `woocommerce_pos_customer_email_enabled` | Den Hauptschalter für Kunden-E-Mails überschreiben |
| `woocommerce_pos_admin_emails` | Die Liste der aktivierten Admin-E-Mails filtern |
| `woocommerce_pos_customer_emails` | Die Liste der aktivierten Kunden-E-Mails filtern |

Kassierer-Benachrichtigungen sind über den bestehenden WooCommerce-Filter `woocommerce_email_recipient_new_order` eingebunden. Empfängerspezifische Anpassungen (z. B. zusätzliche Adressen in CC) funktionieren daher genauso wie bei jeder anderen WooCommerce-E-Mail.
