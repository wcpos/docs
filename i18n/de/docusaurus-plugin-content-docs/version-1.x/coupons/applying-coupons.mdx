:::info Pro-Funktion
Das Einlösen von Gutscheinen an der Kasse erfordert [WCPOS Pro](/1.x/getting-started/pro-license). Nutzer der kostenlosen Version sehen den Bildschirm [Gutscheine](/1.x/coupons) als unscharfe Vorschau, die Aktion **Gutschein hinzufügen** ist im Warenkorb jedoch deaktiviert.
:::

Diese Seite behandelt den Arbeitsablauf an der Kasse — einen Gutschein finden, ihn anwenden, mehrere Gutscheine kombinieren und Fehler beheben. Informationen zu Gutscheinarten, Einrichtung und Validierungsregeln finden Sie unter [Gutscheine](/1.x/coupons); spontane Rabatte, die ein Kassierer direkt erstellt, werden unter [Warenkorbrabatte](/1.x/pos/cart/discounts) beschrieben.

## Der Ablauf zum Hinzufügen von Gutscheinen {#the-add-coupon-flow}

Unterhalb der Warenkorbpositionen befindet sich die Schaltfläche **Gutschein hinzufügen**. Durch Tippen öffnet sich ein kleines Eingabefeld, in dem Sie entweder einen Code eingeben oder suchen können.

1. Tippen Sie im Warenkorb auf **Gutschein hinzufügen**
2. Beginnen Sie mit der Eingabe — das Eingabefeld dient gleichzeitig zur Suche in allen synchronisierten Gutscheinen (Code und Beschreibung)
3. Wählen Sie den Gutschein aus der Vorschlagsliste aus oder geben Sie den Code vollständig ein und drücken Sie **Enter**

Der Gutschein wird sofort anhand Ihrer lokal synchronisierten Daten validiert — ohne Rückfrage an den Server — und der Rabatt erscheint in der Warenkorbsumme. Wenn Sie den Warenkorb nachträglich ändern (einen Artikel hinzufügen, eine Menge ändern oder den Kunden wechseln), wird der Rabatt automatisch neu berechnet.

{/* Screenshot: cart-add-coupon-search.png */}

:::tip Code oder Suche
Kassenpersonal, das den Code kennt (z. B. „SUMMER10“), kann ihn eingeben und mit Enter bestätigen — das ist der schnellste Weg. Die Suche hilft, wenn ein Kunde einen gedruckten Gutschein vorlegt und das Personal den genauen Code nicht kennt, oder wenn ein Treuerabatt über den Kundennamen gesucht wird.
:::

## Gutschein-Chips im Warenkorb {#coupon-pills-in-the-cart}

Jeder angewendete Gutschein erscheint als kleiner **Chip** im Warenkorb, direkt über den Summen. Der Chip zeigt die Beschreibung des Gutscheins (oder den Code, falls keine Beschreibung hinterlegt ist) sowie den gewährten Rabattbetrag an. Tippen Sie auf das **×** eines Chips, um den entsprechenden Gutschein zu entfernen — die Warenkorbsumme wird sofort neu berechnet.

{/* Screenshot: cart-coupon-pills.png */}

Chips werden vertikal gestapelt, wenn mehr als ein Gutschein angewendet wird. Die angezeigte Reihenfolge entspricht der Reihenfolge, in der sie hinzugefügt wurden — und diese Reihenfolge ist relevant für [sequenzielle Rabatte](#sequential-discounts).

:::note Belegbeschriftungen
Der Chip-Text wird auch auf dem Beleg gedruckt. Wenn Sie eine verständlichere Bezeichnung als den reinen Gutscheincode wünschen (z. B. *„Treuerabatt“* statt *„LOYAL10“*), füllen Sie beim Gutschein unter `WP Admin → Marketing → Coupons` das Feld **Beschreibung** aus. WCPOS verwendet die Beschreibung als Rabattbezeichnung, sofern sie hinterlegt ist.
:::

## Sequenzielle Rabatte {#sequential-discounts}

Sie können mehrere Gutscheine auf eine Bestellung anwenden. WooCommerce verarbeitet diese **sequenziell** — jeder Gutschein reduziert die nach dem vorherigen Gutschein verbleibende Zwischensumme, nicht den ursprünglichen Warenkorbgesamtbetrag.

### Rechenbeispiel {#worked-example}

Warenkorb-Zwischensumme: **$100.00**

| Schritt | Gutschein | Berechnung | Laufende Summe |
|---|---|---|---|
| 1 | `LOYAL10` (10% Rabatt) | $100 × 0.90 | **$90.00** |
| 2 | `WELCOME5` ($5 Rabatt auf den Warenkorb) | $90 − $5 | **$85.00** |
| 3 | `EXTRA20` (20% Rabatt) | $85 × 0.80 | **$68.00** |

Die Reihenfolge der Anwendung beeinflusst den Endbetrag. Zwei Gutscheine mit 10% Rabatt ergeben zusammen 19% Rabatt auf den ursprünglichen Betrag (nicht 20%), da die zweiten 10% auf die bereits rabattierte Summe angewendet werden.

### Wenn Gutscheine nicht kombiniert werden können {#when-coupons-cant-stack}

Ein Gutschein, der in WooCommerce mit **Nur einzeln verwendbar** konfiguriert ist, verhindert die gleichzeitige Anwendung anderer Gutscheine. Wenn `SUMMER25` nur einzeln verwendbar ist:

- Wenden Sie zuerst `SUMMER25` an → beim Hinzufügen eines weiteren Gutscheins erscheint *„Dieser Gutschein kann nicht mit anderen Gutscheinen kombiniert werden.“*
- Wenden Sie zuerst andere Gutscheine an → beim Hinzufügen von `SUMMER25` erscheint dieselbe Meldung.

Entfernen Sie den nicht kombinierbaren Gutschein, um den anderen anzuwenden.

### Festbetrag-Produktgutscheine {#fixed-product-coupons}

Ein Gutschein mit **Festbetrag-Produktrabatt** (z. B. *$2 Rabatt pro T-Shirt*) reduziert nur die Positionen, für die er gilt — die laufende Zwischensumme für andere Gutscheine wird dadurch nicht verringert. Die Kombination mit einem prozentualen Warenkorbgutschein ist sicher und vorhersehbar.

## Einen Gutschein entfernen {#removing-a-coupon}

- Tippen Sie auf das **×** am Gutschein-Chip, um diesen einzelnen Gutschein zu entfernen.
- Durch Leeren des Warenkorbs (Menü **Mehr** → *Warenkorb leeren*) werden alle angewendeten Gutscheine entfernt.
- Wird eine Position entfernt, die der *einzige* für einen produktbeschränkten Gutschein zulässige Artikel war, wird der Gutschein automatisch entfernt und eine kurze Meldung angezeigt — „Gutschein entfernt: keine zulässigen Artikel“.

## Validierungsfehler und deren Behebung {#validation-errors-and-how-to-resolve-them}

Das POS verwendet dieselben Validierungsregeln wie WooCommerce — die vollständige Liste finden Sie unter [So funktioniert die Validierung](/1.x/coupons#how-validation-works). Wird ein Gutschein abgelehnt, sieht das Kassenpersonal eine konkrete Meldung:

| Meldung | Bedeutung | Abhilfe |
|---|---|---|
| *„Gutschein existiert nicht“* | Der Code wurde in den synchronisierten Daten nicht gefunden. | Überprüfen Sie die Schreibweise. Wenn der Gutschein gerade erst in WP Admin erstellt wurde, führen Sie über den Bildschirm [Gutscheine](/1.x/coupons) eine Synchronisierung durch (halten Sie das Synchronisierungssymbol für **Löschen und aktualisieren** gedrückt). |
| *„Dieser Gutschein ist abgelaufen“* | Das heutige Datum liegt nach dem Ablaufdatum des Gutscheins. | Verlängern Sie das Ablaufdatum in WP Admin oder verwenden Sie einen anderen Code. |
| *„Nutzungslimit erreicht“* | Das Gesamtnutzungslimit des Gutscheins ist ausgeschöpft. | Erhöhen Sie das Limit in WP Admin oder verwenden Sie einen anderen Code. |
| *„Der Kunde hat diesen Gutschein bereits verwendet“* | Der ausgewählte Kunde hat das Nutzungslimit pro Benutzer überschritten. | Wechseln Sie den Kunden oder erhöhen Sie das Nutzungslimit pro Benutzer. |
| *„Mindestbestellwert nicht erreicht“* | Die Zwischensumme des Warenkorbs liegt unter dem Mindestbetrag des Gutscheins. | Fügen Sie weitere Artikel hinzu oder verwenden Sie einen anderen Code. |
| *„Maximalbestellwert überschritten“* | Die Zwischensumme des Warenkorbs liegt über dem Höchstbetrag des Gutscheins. | Teilen Sie den Warenkorb in mehrere Bestellungen auf oder verwenden Sie einen anderen Code. |
| *„Dieser Gutschein kann nicht mit anderen Gutscheinen kombiniert werden“* | Entweder der neue Gutschein oder ein bereits angewendeter ist auf **Nur einzeln verwendbar** eingestellt. | Entfernen Sie den nicht kombinierbaren Gutschein und wenden Sie dann den gewünschten an. |
| *„Gutschein gilt nicht für die Artikel im Warenkorb“* | Keiner der Artikel im Warenkorb entspricht den Produkt- oder Kategoriebeschränkungen des Gutscheins. | Fügen Sie einen zulässigen Artikel hinzu oder wählen Sie einen anderen Gutschein. |
| *„Gutschein gilt nicht für diesen Kunden“* | Die E-Mail-Adresse des ausgewählten Kunden entspricht nicht der Regel **Erlaubte E-Mail-Adressen** des Gutscheins. | Wechseln Sie zu einem Kunden mit einer passenden E-Mail-Adresse oder entfernen Sie die E-Mail-Beschränkung. |

Wenn ein Gutschein lokal validiert wird, die Bestellung aber beim Checkout abgelehnt wird, hat der Server die Validierung anhand aktuellerer Daten wiederholt — meist wurde das Nutzungslimit durch einen anderen Verkauf während derselben Schicht erreicht. Wenden Sie den Gutschein erneut an oder wählen Sie einen anderen.

## Häufige Arbeitsabläufe {#common-workflows}

<Accordion>
  <AccordionItem question="Manager-Rabatt — spontane 10% mit nachverfolgbarem Code">

Erstellen Sie unter `WP Admin → Marketing → Coupons` einen Gutschein mit einem Namen wie `MGR10`:
- **Rabattart:** Prozentualer Rabatt
- **Gutscheinbetrag:** 10
- **Verwendungsbeschränkung pro Gutschein:** *(leer — unbegrenzt)*
- **Nur einzeln verwendbar:** aus (damit er mit Treue- / Aktionscodes kombiniert werden kann)
- **Beschreibung:** *„Manager-Rabatt“* (dieser Text wird auf dem Beleg gedruckt)

Geben Sie den Code nur an Filialleiter weiter. Der Gutschein erscheint in WooCommerce-Berichten als nachverfolgbarer Rabatt, anders als eine [POS-Preisänderung](/1.x/pos/cart/discounts), die jetzt lediglich den Positionspreis reduziert.

  </AccordionItem>

  <AccordionItem question="Treueprämie — $5 Rabatt für Stammkunden">

Erstellen Sie `LOYAL5`:
- **Rabattart:** Fester Warenkorbrabatt
- **Gutscheinbetrag:** 5
- **Mindestbestellwert:** 25 *(oder der von Ihnen festgelegte Schwellenwert)*
- **Verwendungsbeschränkung pro Benutzer:** 1 *(wenn die Prämie einmalig ist)*
- **Beschreibung:** *„Treueprämie“*

Suchen Sie an der Kasse nach „Treue“, um den Gutschein zu finden, ohne sich den Code merken zu müssen.

  </AccordionItem>

  <AccordionItem question="Einmalige Aktion — Flyer oder Printkampagne">

Erstellen Sie pro Kampagne einen Gutschein mit **Verwendungsbeschränkung pro Gutschein: 1**, wenn der Flyer nur einmal eingelöst werden darf, oder mit einer höheren Anzahl für eine mehrfach nutzbare Aktion. Legen Sie ein zeitnahes **Ablaufdatum** fest, damit der Code später nicht versehentlich erneut verwendet werden kann.

Legen Sie bei mehrfach nutzbaren Aktionen, die jeder Kunde nur einmal einlösen darf, sowohl **Verwendungsbeschränkung pro Gutschein** *als auch* **Verwendungsbeschränkung pro Benutzer: 1** fest.

  </AccordionItem>

  <AccordionItem question="Einen Manager-Rabatt zusätzlich zu einem vom Kunden mitgebrachten Gutscheincode anwenden">

Wenden Sie zuerst den Code des Kunden an, dann den Manager-Code. WooCommerce verarbeitet die Gutscheine nacheinander — der Manager-Rabatt wird auf die bereits rabattierte Gesamtsumme berechnet, was Kunden in der Regel erwarten.

Ist beim Gutschein des Kunden **Nur einzeln verwendbar** aktiviert, wird der Manager-Code abgelehnt. Entfernen Sie entweder zuerst den Gutschein des Kunden (und wenden Sie ihn bei Bedarf später erneut an) oder passen Sie ihn in WP Admin so an, dass Kombinationen zulässig sind.

  </AccordionItem>

  <AccordionItem question="Ein Kunde möchte einen Teil einer Bestellung zurückgeben und mit einem anderen Gutschein neu erfassen lassen">

Erstatten Sie zuerst die ursprüngliche Bestellung (siehe [Rückerstattungen](/1.x/orders/refunds)) und starten Sie dann einen neuen Verkauf mit dem neuen Gutschein. Gutscheine werden zum Zeitpunkt des Verkaufs mit der Bestellung verknüpft — Sie können im POS den Gutschein einer abgeschlossenen Bestellung nicht nachträglich austauschen. Durch die Rückerstattung wird die gezählte Nutzung des Gutscheins wieder freigegeben, sodass er auf die neue Bestellung angewendet werden kann.

  </AccordionItem>
</Accordion>

## Zusammenspiel mit POS-Preisänderungen {#interaction-with-pos-price-changes}

Wenn das Kassenpersonal einen Positionspreis an der Kasse gesenkt hat (eine [POS-Preisänderung](/1.x/pos/cart/discounts)) und dann einen Gutschein anwendet, wird der Gutschein auf den **reduzierten Preis** berechnet, nicht auf den ursprünglichen. Im POS reduzierte Positionen werden als „im Angebot“ behandelt. Gutscheine mit aktivierter Option **Angebotsartikel ausschließen** überspringen sie deshalb.

Dieses Verhalten ist beabsichtigt — es verhindert, dass Kunden durch die Kombination eines Kassenrabatts und eines Gutscheins auf den ursprünglichen Preis doppelt rabattiert werden. Die genaue Funktionsweise finden Sie unter [Zusammenspiel von POS-Preisänderungen und Gutscheinen](/1.x/pos/cart/discounts#how-pos-price-changes-interact-with-coupons).

## Offline-Verhalten {#offline-behaviour}

- **Das Einlösen von Gutscheinen funktioniert offline** — die Validierung erfolgt anhand der lokal synchronisierten Gutscheindaten.
- **Der Abschluss des Verkaufs kann offline erfolgen**, sofern eine offlinefähige Zahlungsmethode verwendet wird. Die Bestellung wird lokal in die Warteschlange gestellt; der Server validiert den Gutschein erneut und aktualisiert dessen Nutzungsanzahl, sobald die Bestellung WooCommerce erreicht.
- **Ein soeben in WP Admin erstellter Gutschein** kann an der Kasse erst nach der nächsten Synchronisierung eingelöst werden. Über die [Gutscheine](/1.x/coupons) -Fußzeile kann das Synchronisierungssymbol (<Icon name="arrow-rotate-right" />) angetippt werden — durch langes Drücken wird **Löschen und neu laden** ausgelöst, um die Daten vollständig neu abzurufen.
