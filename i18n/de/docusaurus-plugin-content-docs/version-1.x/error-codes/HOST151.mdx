## Was dies bedeutet {#what-this-means}

Ein Cache vor dem Shop spielt die API-Antworten einer Person an alle aus.

Eine Cache-Ebene liefert gespeicherte REST-API-Antworten aus, ohne zu prüfen, wer anfragt: Die App hat zwei unterschiedlich authentifizierte Prüfanfragen gesendet und beide Male die Antwort der ersten Prüfanfrage erhalten. In einem aktiven Shop bedeutet dies, dass ein Kassierer die Daten eines anderen sehen könnte, daher wird die Verbindung blockiert, bis der Cache die API des Shops ausschließt. Dies ist ein Problem auf der Hosting-Ebene — WordPress selbst antwortet immer pro Benutzer.

## Ihre Daten {#your-data}

Daten auf diesem Gerät könnten gefährdet sein — löschen Sie keine lokalen Daten. Falls dies weiterhin auftritt, exportieren Sie die Diagnosedaten und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

1. Schließen Sie die REST-API-Pfade des Shops (/wp-json/ und /?rest_route=) vom Seiten-Caching aus — deaktivieren Sie bei LiteSpeed das REST-Caching oder fügen Sie eine No-Cache-Regel hinzu; erweitern Sie bei WP Engine den WooCommerce-Ausschluss auf /wp-json/wcpos; stellen Sie bei Sucuri die Caching-Stufe so ein, dass Cache-Control beachtet wird.
2. Die API des Shops sendet bereits Cache-Control: no-store und Vary: Authorization — die Cache-Ebene ignoriert sie; weisen Sie den Host auf diese Header hin.
3. Nachdem Sie die Cache-Einstellungen geändert haben, leeren Sie den Cache, bevor Sie sich erneut verbinden.
