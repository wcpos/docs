## Was dies bedeutet {#what-this-means}

Ihr Shop hat einen Fehler zurückgegeben, daher wurde diese Aktion nicht abgeschlossen.

Der Shop wurde erreicht, aber sein Server konnte die Anfrage nicht verarbeiten. Dies ist ein Problem der Website und nicht des POS, daher hilft ein bloßer erneuter Versuch möglicherweise nicht: Prüfen Sie das Fehlerprotokoll der Website oder lassen Sie es prüfen und versuchen Sie es dann erneut. Auf diesem Gerät ging nichts verloren.

## Ihre Daten {#your-data}

Die Änderung ist auf diesem Gerät gespeichert, hat Ihren Shop aber nicht erreicht. Wenn dies weiterhin auftritt, exportieren Sie Diagnosedaten und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

**Im POS (Kassierer):** Klappen Sie den Protokolleintrag auf und notieren Sie Status, Endpunkt und serverCode – daran erkennen Sie, was der Server zum Zeitpunkt des Fehlers gerade tat.

**Auf der Website (Website-Administrator / Hosting-Anbieter):**

1. Öffnen Sie WooCommerce → Status → Protokolle auf der Website und prüfen Sie das neueste Protokoll der fatalen Fehler rund um den Fehlerzeitpunkt; eine Antwort der 500er-Klasse hinterlässt dort fast immer einen PHP-Fehler.
2. Wenn der Fehler nach einem Plugin-, Theme- oder PHP-Update auf der Website begonnen hat, verdächtigen Sie zuerst diese Änderung und machen Sie sie rückgängig oder deaktivieren Sie sie.
3. Wenn die Protokolle von WooCommerce nichts zeigen, fragen Sie den Hosting-Anbieter nach dem PHP-Fehlerprotokoll des Servers für denselben Zeitraum.

**Dann zurück im POS:** Sobald die Ursache auf dem Server behoben ist, versuchen Sie es erneut – die Änderung ist weiterhin auf diesem Gerät gespeichert.
