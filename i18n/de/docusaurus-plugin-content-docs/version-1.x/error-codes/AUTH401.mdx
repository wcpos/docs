## Was dies bedeutet {#what-this-means}

Einer sicheren Verbindung zu diesem Shop konnte nicht vertraut werden.

Verwenden Sie die korrekte Shop-Adresse und bitten Sie den Website-Administrator, das Zertifikat zu reparieren, bevor Sie sich erneut verbinden.

## Was zu tun ist {#what-to-do}

Damit dies funktioniert, ist zuerst eine Änderung der Einstellungen erforderlich. Versuchen Sie es erst nach der oben genannten Änderung erneut; ohne sie schlägt der Versuch genauso fehl.

## Ihre Daten {#your-data}

Es sind keine Bestell- oder Produktdaten betroffen. Wenn dies weiterhin auftritt, wenden Sie sich an die Person, die Ihre WordPress-Website betreut.

## Fehlerbehebung {#troubleshoot}

1. Öffnen Sie die Shop-Adresse in einem Browser auf demselben Gerät — das Schloss-Symbol oder die Warnseite des Browsers zeigt genau, was mit dem Zertifikat nicht stimmt (abgelaufen, selbst signiert oder für eine andere Domain ausgestellt).
2. Prüfen Sie die Adresse, die das POS verwendet: https:// und genau die Domain, die das Zertifikat abdeckt — ob mit oder ohne www, macht einen Unterschied.
3. Bitten Sie den Website-Administrator oder das Hosting, das Zertifikat zu erneuern oder zu reparieren; eine stillschweigend fehlgeschlagene automatische Erneuerung ist die häufigste Ursache.
4. Umgehen Sie eine Zertifikatswarnung nicht durch das Abschalten von Sicherheitsfunktionen — reparieren Sie das Zertifikat.

## Wo Sie nachsehen können {#where-to-look}

Wenn WCPOS diesen Fehler speichern kann, wird er auf dem Gerät aufgezeichnet, das ihn ausgelöst hat. Öffnen Sie **Shop-Zustand → Protokolle** (das Herzschlagsymbol unten im Navigationsmenü), suchen Sie den mit diesem Code gekennzeichneten Eintrag und klappen Sie ihn auf: Die aufgeklappte Zeile zeigt die Ursache in verständlicher Sprache sowie den Kontext, der im Moment des Fehlers erfasst wurde. Bei einer Shop-Anfrage kann dieser Kontext den eigenen Fehlercode des Servers (`serverCode`), den HTTP-`status` oder den `endpoint` enthalten; welche Felder angezeigt werden, hängt davon ab, wo der Fehler aufgetreten ist. Verwenden Sie beim Melden eines Problems **Debug-Infos kopieren** oben im Protokollbildschirm (**Debug-Infos teilen** auf Smartphones und Tablets) statt Screenshots: Damit werden App-Version, Verbindungsstatus und die neuesten Fehler zusammengefasst. Protokolle werden höchstens 30 Tage aufbewahrt — sammeln Sie sie daher, solange das Problem frisch ist. Kopieren Sie außerdem jede Fehlermeldung aus der Browser-Konsole, die erschienen ist, bevor das POS seinen eigenen Protokolleintrag schreiben konnte.

Über das Protokoll in der App hinaus kann dieser Fehler an folgenden Stellen Spuren hinterlassen:

- **Konsole** (Web und Desktop): Der Tab **Konsole** derselben Entwicklertools zeichnet clientseitige Fehler auf, auch solche, die auftreten, bevor das POS seinen eigenen Protokolleintrag schreiben kann.
