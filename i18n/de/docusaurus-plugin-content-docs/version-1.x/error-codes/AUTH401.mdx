## Bedeutung {#what-this-means}

Eine sichere Verbindung zu diesem Shop konnte nicht als vertrauenswürdig eingestuft werden.

Verwenden Sie die korrekte Shop-Adresse und bitten Sie die Website-Administration, das Zertifikat zu reparieren, bevor Sie die Verbindung erneut herstellen.

## Vorgehensweise {#what-to-do}

Damit dies funktioniert, ist eine Änderung der Einstellungen erforderlich. Wiederholen Sie den Vorgang nach der oben genannten Änderung; ohne diese Änderung schlägt er erneut auf dieselbe Weise fehl.

## Ihre Daten {#your-data}

Es sind keine Bestell- oder Produktdaten betroffen. Wenn das Problem weiterhin besteht, wenden Sie sich an die Person, die Ihre WordPress-Website verwaltet.

## Fehlerbehebung {#troubleshoot}

1. Öffnen Sie die Shop-Adresse in einem Browser auf demselben Gerät – das Schloss-Symbol oder die Warnseite des Browsers zeigt genau an, was mit dem Zertifikat nicht stimmt (abgelaufen, selbstsigniert oder für eine andere Domain ausgestellt).
2. Prüfen Sie die Adresse, die das POS verwendet: https:// und die genaue Domain, die das Zertifikat abdeckt – ob mit oder ohne www, ist relevant.
3. Bitten Sie die Website-Administration oder den Hosting-Anbieter, das Zertifikat zu erneuern oder zu korrigieren; eine unbemerkt fehlgeschlagene automatische Erneuerung ist die häufigste Ursache.
4. Umgehen Sie eine Zertifikatswarnung nicht durch das Deaktivieren der Sicherheit – korrigieren Sie das Zertifikat.

## Wo Sie nachsehen können {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät aufgezeichnet, auf dem es ausgelöst wurde. Öffnen Sie **Filialstatus → Protokolle** (das Herzschlag-Symbol unten in der Navigationsleiste), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt den verständlich formulierten Grund und den zum Zeitpunkt des Fehlers erfassten Kontext – bei allem, was eine Anfrage an Ihren Shop betraf, umfasst dies den servereigenen Fehlercode (`serverCode`), den HTTP-`status` und den `endpoint`. Verwenden Sie beim Melden eines Problems oben im Bildschirm „Protokolle“ **Debug-Informationen kopieren** (**Debug-Informationen teilen** auf Smartphones und Tablets) anstelle von Screenshots: Dies bündelt die App-Version, den Verbindungsstatus und die neuesten Fehler. Protokolle werden höchstens 30 Tage aufbewahrt; sammeln Sie sie daher, solange das Problem noch aktuell ist.

Neben dem In-App-Protokoll kann dieser Fehler auch hier Spuren hinterlassen:

- **Konsole** (Web und Desktop): Der Tab **Konsole** derselben Entwicklertools zeichnet clientseitige Fehler auf, einschließlich solcher, die auftreten, bevor das POS einen eigenen Protokolleintrag schreiben kann.
