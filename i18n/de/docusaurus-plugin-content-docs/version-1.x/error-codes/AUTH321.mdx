## Bedeutung {#what-this-means}

WooCommerce ist auf dieser Website nicht aktiv, daher kann WCPOS keine Verbindung herstellen.

WCPOS benötigt das WooCommerce-Plugin. Wenden Sie sich an die Website-Administration, damit WooCommerce installiert oder erneut aktiviert wird. Stellen Sie anschließend die Verbindung erneut her.

## Vorgehensweise {#what-to-do}

Damit dies funktioniert, ist eine Einstellungsänderung erforderlich. Wiederholen Sie den Vorgang, nachdem Sie die obige Änderung vorgenommen haben; ohne diese Änderung schlägt der erneute Versuch auf dieselbe Weise fehl.

## Ihre Daten {#your-data}

Es sind keine Bestell- oder Produktdaten betroffen. Wenn das Problem weiterhin besteht, wenden Sie sich an die Person, die Ihre WordPress-Website verwaltet.

## Fehlerbehebung {#troubleshoot}

1. Bitten Sie die Website-Administration, WP Admin → Plugins zu prüfen: WooCommerce muss installiert und aktiv sein, damit WCPOS eine Verbindung herstellen kann.
2. Wenn WooCommerce durch ein fehlgeschlagenes Update deaktiviert wurde, aktivieren Sie es erneut und achten Sie auf eine Fehlermeldung — WooCommerce → Status → Protokolle dokumentiert die Ursache des Fehlers.
3. Sobald WooCommerce wieder aktiv ist, stellen Sie die Verbindung über die Kasse erneut her.

## Wo Sie nachsehen können {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät aufgezeichnet, auf dem er ausgelöst wurde. Öffnen Sie **Filialstatus → Protokolle** (das Herzschlag-Symbol unten in der Navigationsleiste), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt die verständliche Ursache sowie den zum Zeitpunkt des Fehlers erfassten Kontext — bei allem, was eine Anfrage an Ihre Filiale umfasste, gehören dazu der servereigene Fehlercode (`serverCode`), der HTTP-`status` und der `endpoint`. Verwenden Sie beim Melden eines Problems **Debug-Informationen kopieren** oben im Bildschirm „Protokolle“ (**Debug-Informationen teilen** auf Telefonen und Tablets) statt Screenshots: Dabei werden die App-Version, der Verbindungsstatus und die neuesten Fehler gebündelt. Protokolle werden höchstens 30 Tage lang aufbewahrt; sammeln Sie sie daher, solange das Problem aktuell ist.

Neben dem In-App-Protokoll kann dieser Fehler auch an folgenden Stellen Spuren hinterlassen:

- **WooCommerce → Status → Protokolle**: Prüfen Sie auf der WordPress-Website die neueste `fatal-errors-*.log` auf PHP-Abstürze sowie jede Protokollquelle, die nach einem am Fehler beteiligten Plugin benannt ist. Ein Fehler der 500er-Klasse vom Shop hinterlässt seine Ursache fast immer hier.
