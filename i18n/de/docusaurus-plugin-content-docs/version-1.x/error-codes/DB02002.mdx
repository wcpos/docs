# DB02002: Datensatz nicht gefunden {#db02002-record-not-found}

## Was das bedeutet {#what-this-means}

Der angeforderte Datensatz existiert nicht in der lokalen Datenbank. Das POS hat versucht, auf ein Produkt, einen Kunden, eine Bestellung oder einen anderen Datensatz zuzugreifen, der nicht lokal gespeichert ist.

## Häufige Ursachen {#common-causes}

- **Noch nicht synchronisiert** — Daten wurden noch nicht heruntergeladen
- **Auf dem Server gelöscht** — Datensatz wurde in WooCommerce entfernt
- **Sync nicht abgeschlossen** — Die anfängliche Sync läuft noch
- **Filter angewendet** — Datensatz von aktiven Filtern ausgeschlossen

## So beheben Sie das Problem {#how-to-fix}

### 1. Auf die Sync warten {#1-wait-for-sync}

Falls kürzlich gestartet:
- Warten Sie, bis die anfängliche Sync abgeschlossen ist
- Überprüfen Sie den Fortschrittsindikator der Sync
- Der Datensatz sollte nach der Sync erscheinen

### 2. Aktualisieren/Re-sync {#2-refreshre-sync}

Ein Daten-Refresh auslösen:
- Verwenden Sie die refresh/sync Taste (<Icon name="arrow-rotate-right" />) - kurzer Druck für die Sync
- Verwenden Sie hier nicht die durch **langes Drücken** aufrufbare Option Clear and Refresh – sie leert die gesamte Liste auf diesem Gerät, einschließlich nie gespeicherter offener Warenkörbe. Siehe zuerst Schritt 5.
- Ziehen Sie die neuesten Daten vom Server
- Warten Sie, bis die Verarbeitung abgeschlossen ist

### 3. WooCommerce überprüfen {#3-check-woocommerce}

Stellen Sie sicher, dass der Datensatz auf dem Server existiert:
- Melden Sie sich im WordPress-Admin an
- Überprüfen Sie Produkte, Bestellungen oder Kunden
- Bestätigen Sie, dass der Artikel noch existiert

### 4. Filter überprüfen {#4-check-filters}

Der Datensatz könnte herausgefiltert sein:
- Überprüfen Sie die aktiven Filter im POS
- Überprüfen Sie die Kategoriefilter
- Überprüfen Sie die Sichtbarkeitseinstellungen

### 5. Löschen und erneut synchronisieren {#5-clear-and-re-sync}

:::warning Prüfen Sie zuerst, ob nicht gespeicherte Arbeit vorliegt
Wenn Sie lokale Daten löschen oder die App neu installieren, werden alle Daten auf diesem Gerät gelöscht, die Ihre Filiale noch nicht erreicht haben – darunter offline erfasste Verkäufe, offene Warenkörbe und nicht gespeicherte Änderungen. Öffnen Sie vor dem Löschen **Store health → Database** und prüfen Sie, dass nichts als zurückgehalten oder noch nie an Ihren Server übertragen aufgeführt ist. Prüfen Sie anschließend unter **Store health → Logs**, ob **0 festhängende Datensätze** und **0 noch zu sendende Änderungen** angezeigt werden; schließen oder notieren Sie danach alle offenen Warenkörbe. Wenn Ihr WCPOS keine Seite „Store health“ hat, aktualisieren Sie zuerst WCPOS und prüfen Sie es dann. Wenn etwas aufgeführt wird oder noch aussteht oder Sie die Prüfung nicht durchführen können, löschen Sie nichts – wenden Sie sich an den Inhaber Ihrer Filiale oder den Support.
:::

Nur wenn die Synchronisierung weiterhin festhängt und erst nach der obigen Prüfung:
1. Lokale Daten löschen
2. Erneut anmelden
3. Eine frische Sync durchführen

## Häufige Szenarien {#common-scenarios}

- **Produkt wird nicht angezeigt:** Überprüfen, ob es veröffentlicht und sichtbar ist
- **Kunde nicht gefunden:** Könnte noch nicht synchronisiert worden sein
- **Bestellung fehlt:** Könnte außerhalb des Sync-Zeitraums liegen
