## Bedeutung {#what-this-means}

Der Checkout wurde nicht abgeschlossen, und der Warenkorb kann sicher erneut versucht werden.

Überprüfen Sie den Warenkorb und versuchen Sie den Checkout erneut; der aktuelle Warenkorbinhalt wurde beibehalten.

## Vorgehensweise {#what-to-do}

Versuchen Sie die Aktion erneut. WCPOS wiederholt dies nicht automatisch — wiederholen Sie den Vorgang, wenn Sie bereit sind.

## Ihre Daten {#your-data}

Die Bestellung selbst ist sicher und unverändert.

## Fehlerbehebung {#troubleshoot}

1. Überprüfen Sie den Warenkorb — er ist unverändert — und versuchen Sie den Checkout erneut.
2. Falls dies erneut fehlschlägt, erweitern Sie den Protokolleintrag: serverCode und status zeigen, ob der Shop die Bestellung abgelehnt hat und warum.
3. Ein wiederholter Fehler mit einem Status der 500er-Klasse ist ein Websiteproblem — prüfen Sie WooCommerce → Status → Protokolle auf einen PHP-Fehler zum Zeitpunkt des Fehlers.
4. Falls der Grund einen bestimmten Artikel nennt, entfernen Sie ihn, schließen Sie den Verkauf ab und untersuchen Sie das Produkt anschließend.

## Wo Sie nachsehen können {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät aufgezeichnet, das ihn ausgelöst hat. Öffnen Sie **Filialstatus → Protokolle** (das Herzschlag-Symbol unten in der Navigationsleiste), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt den leicht verständlichen Grund und den zum Zeitpunkt des Fehlers erfassten Kontext — bei allem, was eine Anfrage an Ihren Shop umfasste, sind dies der eigene Fehlercode des Servers (`serverCode`), der HTTP-`status` und der `endpoint`. Verwenden Sie beim Melden eines Problems oben im Bildschirm „Protokolle“ **Debug-Informationen kopieren** (**Debug-Informationen teilen** auf Smartphones und Tablets) statt Screenshots: Dadurch werden die App-Version, der Verbindungsstatus und die neuesten Fehler gebündelt. Protokolle werden höchstens 30 Tage aufbewahrt; sammeln Sie sie daher, solange das Problem aktuell ist.

Neben dem In-App-Protokoll kann dieser Fehler auch hier Spuren hinterlassen:

- **Netzwerkinspektor** (Web und Desktop): Öffnen Sie die Entwicklertools — drücken Sie im Browser F12 oder wählen Sie im Menü der Desktop-App **Erweitert → Entwicklertools umschalten** —, wählen Sie den Tab **Netzwerk** und wiederholen Sie die Aktion. Die fehlgeschlagene Anfrage zeigt den HTTP-Status und den unformatierten Antworttext, einschließlich Fehlerseiten, die das POS-Protokoll nie erreichen.
- **Serverseitige POS-Protokolle**: Öffnen Sie in WP Admin **POS → Einstellungen → Werkzeuge → Protokolle**. Auf dieser Seite werden POS-bezogene Warnungen und Fehler aufgezeichnet, die auf dem Server selbst ausgelöst werden und möglicherweise nie in der App erscheinen. Eine rote Markierung im Menü bedeutet, dass ungelesene serverseitige Fehler vorliegen.
- **WooCommerce → Status → Protokolle**: Prüfen Sie auf der WordPress-Website die neueste `fatal-errors-*.log` auf PHP-Abstürze sowie jede Protokollquelle, die nach einem am Fehler beteiligten Plugin benannt ist. Ein Fehler der 500er-Klasse vom Shop hinterlässt seine Ursache fast immer hier.
