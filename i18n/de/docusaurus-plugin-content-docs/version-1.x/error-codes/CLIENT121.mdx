## Bedeutung {#what-this-means}

Dieser Browser lässt jeweils nur einen Tab Änderungen senden.

Sie können weiterhin jeden Tab verwenden — alle nutzen dieselben lokalen Daten. Ein Tab übernimmt im Hintergrund die Synchronisierung für alle Tabs.

## Vorgehensweise {#what-to-do}

Sie können weiterarbeiten — WCPOS übernimmt dies automatisch. Wiederholen Sie den Vorgang nicht — das Ergebnis ändert sich nicht.

## Ihre Daten {#your-data}

Keine Bestell- oder Produktdaten sind betroffen.

## Fehlerbehebung {#troubleshoot}

1. Alle Tabs können weiterhin normal verwendet werden – sie nutzen dieselben lokalen Daten, und ein Tab synchronisiert unauffällig im Namen der übrigen.
2. Dieser Browser (oder ein privates Fenster) unterstützt die vom POS bevorzugte Funktion zur Tab-Koordination nicht. Daher wird auf einen einzelnen synchronisierenden Tab zurückgegriffen. Es ist keine Behebung erforderlich.

## Wo nachsehen {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät erfasst, das ihn ausgelöst hat. Öffnen Sie **Filialstatus → Protokolle** (das Herzschlag-Symbol unten in der Navigationsleiste), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt den verständlich formulierten Grund sowie den zum Zeitpunkt des Fehlers erfassten Kontext. Bei allen Vorgängen, die eine Anfrage an Ihren Shop umfassten, gehören dazu auch der servereigene Fehlercode (`serverCode`), der HTTP-`status` und der `endpoint`. Verwenden Sie beim Melden eines Problems oben im Bildschirm „Protokolle“ **Debug-Informationen kopieren** (**Debug-Informationen teilen** auf Smartphones und Tablets) statt Screenshots: Dadurch werden die App-Version, der Verbindungsstatus und die neuesten Fehler gebündelt. Protokolle werden maximal 30 Tage aufbewahrt; sammeln Sie sie daher, solange das Problem noch aktuell ist.
