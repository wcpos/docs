## Bedeutung {#what-this-means}

Ein anderes Authentifizierungs-Plugin verhindert, dass WCPOS eine Verbindung herstellt.

Bitten Sie die Person, die die Website verwaltet, den genannten Plugin-Konflikt zu beheben, bevor Sie sich erneut anmelden.

## Vorgehensweise {#what-to-do}

Damit dies funktioniert, muss eine Einstellung geändert werden. Versuchen Sie es nach der oben beschriebenen Änderung erneut; ohne diese Änderung schlägt der erneute Versuch ebenfalls fehl.

## Ihre Daten {#your-data}

Keine Bestell- oder Produktdaten sind betroffen. Falls das Problem weiterhin besteht, wenden Sie sich an die Person, die Ihre WordPress-Website verwaltet.

## Fehlerbehebung {#troubleshoot}

1. Erweitern Sie den Protokolleintrag — er nennt das konfliktverursachende Plugin, sofern der Shop dies meldet.
2. Bitten Sie die Website-Administration, die Einstellungen dieses Plugins zu prüfen: Die meisten Authentifizierungs-Plugins können die WCPOS-REST-Routen ausnehmen, anstatt vollständig deaktiviert zu werden.
3. Melden Sie sich nach der Änderung erneut an der Kasse an.
4. Wenn nicht klar ist, welches Plugin den Konflikt verursacht, testen Sie auf einer Staging-Kopie, indem Sie Sicherheits- und Anmelde-Plugins nacheinander deaktivieren.

## Wo Sie nachsehen können {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät protokolliert, auf dem er ausgelöst wurde. Öffnen Sie **Filialstatus → Protokolle** (das Herzschlag-Symbol unten im Navigationsbereich), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt den einfach verständlichen Grund und den zum Zeitpunkt des Fehlers erfassten Kontext — bei allem, was eine Anfrage an Ihren Shop betraf, gehören dazu der servereigene Fehlercode (`serverCode`), der HTTP-`status` und der `endpoint`. Verwenden Sie bei der Fehlermeldung **Debug-Informationen kopieren** oben im Bildschirm „Protokolle“ (**Debug-Informationen teilen** auf Smartphones und Tablets) statt Screenshots: Dadurch werden die App-Version, der Verbindungsstatus und die neuesten Fehler gebündelt. Protokolle werden höchstens 30 Tage aufbewahrt. Sammeln Sie sie daher, solange das Problem noch aktuell ist.

Neben dem In-App-Protokoll kann dieser Fehler auch an folgenden Stellen Spuren hinterlassen:

- **Netzwerkinspektor** (Web und Desktop): Öffnen Sie die Entwicklertools — drücken Sie im Browser F12 oder wählen Sie im Menü der Desktop-App **Erweitert → Entwicklertools umschalten** —, wählen Sie den Tab **Netzwerk** und wiederholen Sie die Aktion. Die fehlgeschlagene Anfrage zeigt den HTTP-Status und den unverarbeiteten Antworttext, einschließlich Fehlerseiten, die nie das POS-Protokoll erreichen.
- **Serverseitige POS-Protokolle**: Öffnen Sie in WP Admin **POS → Einstellungen → Werkzeuge → Protokolle**. Diese Seite protokolliert POS-bezogene Warnungen und Fehler, die auf dem Server selbst ausgelöst werden und möglicherweise nie in der App erscheinen. Eine rote Kennzeichnung im Menü weist auf ungelesene serverseitige Fehler hin.
- **WooCommerce → Status → Protokolle**: Prüfen Sie auf der WordPress-Website die neueste `fatal-errors-*.log` auf PHP-Abstürze sowie jede Protokollquelle, die nach einem am Fehler beteiligten Plugin benannt ist. Ein Fehler der 500er-Klasse vom Shop hinterlässt seine Ursache fast immer hier.

## Details {#details}

- **Code:** `AUTH301` (`AUTH_PLUGIN_CONFLICT`)
- **Schweregrad:** Fehler
- **Eingeführt in:** WCPOS 1.10.0
