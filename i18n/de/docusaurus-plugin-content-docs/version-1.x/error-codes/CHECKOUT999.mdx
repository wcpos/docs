## Was das bedeutet {#what-this-means}

Beim Checkout ist ein unerwartetes Problem aufgetreten.

Überprüfen Sie die Bestellung in der Verwaltung Ihrer Filiale, bevor Sie den Kunden erneut belasten. Exportieren Sie Diagnosedaten und kontaktieren Sie den Support, wenn das Problem erneut auftritt.

## Was zu tun ist {#what-to-do}

## Fehlerbehebung {#troubleshoot}

1. Prüfen Sie WooCommerce → Bestellungen in WP Admin auf die Bestellung, bevor Sie den Kunden erneut belasten.
2. Erweitern Sie den Protokolleintrag und notieren Sie den Ereigniscode sowie gegebenenfalls serverCode — dieser allgemeine Code bedeutet, dass die Ursache noch keinen eigenen Code hat.
3. Wenn der Fehler erneut auftritt, exportieren Sie Debug-Informationen und wenden Sie sich an den Support.

## Wo Sie nachsehen können {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät aufgezeichnet, auf dem es ausgelöst wurde. Öffnen Sie **Filialstatus → Protokolle** (das Herzschlag-Symbol unten im Navigationsbereich), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt den Grund in verständlicher Sprache sowie den zum Zeitpunkt des Fehlers erfassten Kontext — bei allem, was eine Anfrage an Ihre Filiale umfasste, gehören dazu der eigene Fehlercode des Servers (`serverCode`), der HTTP-`status` und der `endpoint`. Verwenden Sie beim Melden eines Problems **Debug-Informationen kopieren** oben im Bildschirm „Protokolle“ (**Debug-Informationen teilen** auf Smartphones und Tablets) statt Screenshots: Dadurch werden die App-Version, der Verbindungsstatus und die neuesten Fehler zusammengefasst. Protokolle werden höchstens 30 Tage aufbewahrt; sammeln Sie sie daher, solange das Problem noch aktuell ist.

Neben dem Protokoll in der App kann dieser Fehler folgende Spuren hinterlassen:

- **Netzwerkinspektor** (Web und Desktop): Öffnen Sie die Entwicklertools — drücken Sie im Browser F12 oder wählen Sie im Menü der Desktop-App **Erweitert → Entwicklertools umschalten** —, wählen Sie den Tab **Netzwerk** und wiederholen Sie die Aktion. Die fehlgeschlagene Anfrage zeigt den HTTP-Status und den unverarbeiteten Antworttext, einschließlich Fehlerseiten, die nie das POS-Protokoll erreichen.
- **Serverseitige POS-Protokolle**: Öffnen Sie in WP Admin **POS → Einstellungen → Werkzeuge → Protokolle**. Diese Seite zeichnet POS-bezogene Warnungen und Fehler auf, die auf dem Server selbst ausgelöst werden und möglicherweise nie in der App erscheinen. Ein rotes Kennzeichen im Menü weist auf ungelesene serverseitige Fehler hin.
