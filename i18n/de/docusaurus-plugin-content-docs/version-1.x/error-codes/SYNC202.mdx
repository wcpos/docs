## Was dies bedeutet {#what-this-means}

Ihre Filiale hat diese Änderung abgelehnt, daher wurde auf diesem Gerät die Version der Filiale wiederhergestellt.

Die Änderung wurde nicht gespeichert. Lesen Sie den Grund der Filiale, beheben Sie das genannte Problem und nehmen Sie die Änderung erneut vor.

Dies geschieht bei Änderungen an vorhandenen Produkten, Varianten, Gutscheinen und Kunden. Wenn Ihre Filiale eine Änderung endgültig ablehnt — etwa weil ein Wert ungültig ist oder der angemeldete Benutzer sie nicht vornehmen darf — hält WCPOS die abgelehnte Änderung nicht zurück. Stattdessen wird die Version der Filiale auf diesem Gerät wiederhergestellt, damit an der Kasse dieselben Angaben wie in der Filiale verwendet werden. Der Protokolleintrag nennt den Datensatz und enthält den Ablehnungsgrund der Filiale.

## Ihre Daten {#your-data}

Sonst wurde nichts geändert. Ihre Filiale enthält weiterhin ihre unveränderte Version und dieses Gerät zeigt diese Version wieder an. Wenn die Filiale den Datensatz gelöscht hat, wird er auch von diesem Gerät entfernt. Nur die abgelehnte Änderung ist verloren; nehmen Sie sie erneut vor, sobald der Grund behoben ist. Verkäufe und Bestellungen sind nicht betroffen. Eine Änderung desselben Datensatzes, die Sie nach der abgelehnten Änderung vorgenommen haben, bleibt erhalten und wird weiterhin gesendet.

## Fehlerbehebung {#troubleshoot}

1. Klappen Sie den Protokolleintrag auf und lesen Sie den Ablehnungsgrund der Filiale: Er nennt die abgelehnte Änderung und den zugehörigen Datensatz.
2. Beheben Sie den genannten Grund. Wenn es sich um einen Wert handelt — etwa einen Preis, eine SKU, eine E-Mail-Adresse oder ein leeres Pflichtfeld — ermitteln Sie den korrekten Wert. Wenn der Grund besagt, dass der Benutzer die Änderung nicht vornehmen darf, fehlen dem Konto die erforderlichen Berechtigungen: siehe [AUTH201](/error-codes/AUTH201).
3. Öffnen Sie den Datensatz (wenn die Filiale ihn gelöscht hat, gibt es nichts zu ändern), nehmen Sie die Änderung mit dem korrigierten Wert erneut vor und speichern Sie sie. Prüfen Sie nach der Synchronisierung, ob der Datensatz Ihre Änderung anzeigt.
4. Ein auf diesem Gerät neu erstellter Datensatz, den die Filiale abgelehnt hat, wird nicht zurückgesetzt — es gibt keine Version der Filiale, zu der zurückgekehrt werden könnte. Er bleibt unter **„… Änderungen haben Ihren Server nie erreicht“** in **Filialstatus → Datenbank** aufgeführt; siehe [SYNC201](/error-codes/SYNC201).
5. **Website-Administrator:** Wenn der Ablehnungsgrund ein Feld betrifft, das der POS nicht anzeigt, öffnen Sie denselben Datensatz in WP Admin — ein anderes Plugin könnte eine Validierung hinzufügen, die der POS nicht kennt. Wenn die Filiale die Änderung weiterhin ablehnt, tippen Sie im Tab **Protokolle** auf **Debug-Infos kopieren** und wenden Sie sich an den Support.
