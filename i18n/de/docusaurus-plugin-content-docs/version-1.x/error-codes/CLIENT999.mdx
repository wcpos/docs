## Bedeutung {#what-this-means}

WCPOS ist auf einen unerwarteten Fehler gestoßen.

Wiederholen Sie die Aktion einmal. Falls sie erneut fehlschlägt, exportieren Sie die Diagnoseinformationen und wenden Sie sich an den Support.

## Vorgehensweise {#what-to-do}

Exportieren Sie die Diagnoseinformationen und wenden Sie sich an den Support. WCPOS wiederholt dies nicht selbstständig — wiederholen Sie den Vorgang, wenn Sie bereit sind.

## Ihre Daten {#your-data}

Das Ergebnis konnte nicht bestätigt werden — überprüfen Sie es vor einem erneuten Versuch. Falls das Problem weiterhin besteht, exportieren Sie die Diagnoseinformationen und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

1. Versuchen Sie die Aktion noch einmal.
2. Erweitern Sie den Protokolleintrag und notieren Sie den Ereigniscode sowie den Kontext — ein 999-Code bedeutet, dass der Fehler noch keinen eigenen Code hat; anhand dieser Informationen lässt er sich identifizieren.
3. Tritt der Fehler erneut auf, exportieren Sie die Debug-Informationen und wenden Sie sich an den Support — durch die Meldung kann der spezifische Code erstellt werden.

## Wo Sie nachsehen können {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät aufgezeichnet, das ihn ausgelöst hat. Öffnen Sie **Filialzustand → Protokolle** (das Herzschlag-Symbol unten im Navigationsbereich), suchen Sie den mit diesem Code gekennzeichneten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt den leicht verständlichen Grund und den zum Zeitpunkt des Fehlers erfassten Kontext — bei allem, was eine Anfrage an Ihre Filiale betraf, umfasst dies den servereigenen Fehlercode (`serverCode`), den HTTP-`status` und den `endpoint`. Verwenden Sie bei der Fehlermeldung oben auf dem Bildschirm „Protokolle“ **Debug-Informationen kopieren** (**Debug-Informationen teilen** auf Smartphones und Tablets) statt Screenshots: Dadurch werden die App-Version, der Verbindungsstatus und die neuesten Fehler gebündelt. Protokolle werden höchstens 30 Tage aufbewahrt; sammeln Sie sie daher, solange das Problem aktuell ist.

Zusätzlich zum In-App-Protokoll kann dieser Fehler Spuren hinterlassen in:

- **Konsole** (Web und Desktop): Der Tab **Konsole** derselben Entwicklertools zeichnet clientseitige Fehler auf, einschließlich solcher, die auftreten, bevor der POS einen eigenen Protokolleintrag schreiben kann.
