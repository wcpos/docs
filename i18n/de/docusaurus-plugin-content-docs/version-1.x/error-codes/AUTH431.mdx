## Bedeutung {#what-this-means}

Die REST API der Filiale hat unter keiner von dieser App verwendbaren Adressform geantwortet.

Die App hat die REST API der Filiale unter ihrer normalen Adresse (/wp-json/...) und unter der integrierten Fallback-Adresse von WordPress (/?rest_route=...) aufgerufen, aber keine der beiden hat geantwortet. Die Website der Filiale selbst ist möglicherweise erreichbar — betroffen ist speziell die nicht erreichbare REST API, in der Regel weil ein Sicherheits-Plugin sie verbirgt oder eine Firewall-Regel sie blockiert.

## Vorgehensweise {#what-to-do}

Diagnosedaten exportieren und den Support kontaktieren. Nach der oben genannten Änderung erneut versuchen; ohne diese Änderung schlägt der Vorgang erneut auf dieselbe Weise fehl.

## Ihre Daten {#your-data}

Keine Bestell- oder Produktdaten sind betroffen.

## Fehlerbehebung {#troubleshoot}

1. Wenn ein Sicherheits-Plugin /wp-json/ ausblendet oder umbenennt (z. B. WP Hide), muss auch die integrierte WordPress-Form /?rest_route= zugelassen werden — die App greift automatisch darauf zurück.
2. Überprüfen Sie die Firewall-Regeln (WAF) auf Übereinstimmungen mit wp-json oder rest_route und lassen Sie die eigene REST API des Shops durch.
3. Testen Sie im Browser: https://your-store.com/?rest_route=/ sollte JSON zurückgeben, nicht eine 403-Seite oder die Startseite der Website.
4. Wenn der Server hinter einer Wartungsseite oder einer Bot-Prüfung steht, können REST-Anfragen mit einer HTML-Seite beantwortet werden — deaktivieren Sie die Prüfung für die REST API.

## Wo Sie nachsehen können {#where-to-look}

Wenn WCPOS diesen Fehler speichern kann, wird er auf dem Gerät aufgezeichnet, auf dem er aufgetreten ist. Öffnen Sie **Filialstatus → Protokolle** (das Herzschlag-Symbol unten im Navigationsmenü), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt die verständlich formulierte Ursache und den zum Zeitpunkt des Fehlers erfassten Kontext. Bei einer Anfrage an den Shop kann dieser Kontext den servereigenen Fehlercode (`serverCode`), den HTTP-`status` oder den `endpoint` enthalten; welche Felder angezeigt werden, hängt davon ab, wo der Fehler aufgetreten ist. Verwenden Sie beim Melden eines Problems oben auf dem Bildschirm „Protokolle“ **Debug-Informationen kopieren** (**Debug-Informationen teilen** auf Smartphones und Tablets) anstelle von Screenshots: Dadurch werden die App-Version, der Verbindungsstatus und die neuesten Fehler zusammengefasst. Protokolle werden höchstens 30 Tage aufbewahrt. Sammeln Sie sie daher, solange das Problem noch aktuell ist. Kopieren Sie außerdem jeden Fehler der Browser-Konsole, der angezeigt wurde, bevor der POS einen eigenen Protokolleintrag schreiben konnte.
