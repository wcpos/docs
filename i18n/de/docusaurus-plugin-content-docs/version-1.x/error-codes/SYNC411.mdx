## Was dies bedeutet {#what-this-means}

Dieses Gerät hat den Shop weit häufiger als üblich nach Daten gefragt.

Es wurde nichts verlangsamt oder blockiert, und es sind keine Bestelldaten betroffen — dies ist ein reiner Erkennungsalarm. Anhaltende Anfragefluten deuten in der Regel auf ein Problem der App hin (ein Bildschirm, der dieselben Daten in einer Schleife erneut anfragt) und nicht auf etwas, das Sie getan haben. Wenn dieser Code weiterhin auftritt, exportieren Sie Diagnosedaten und wenden Sie sich an den Support, damit die Schleife gefunden und behoben werden kann.

## Was zu tun ist {#what-to-do}

Sie können weiterarbeiten — WCPOS erledigt dies automatisch. WCPOS wiederholt dies automatisch.

## Ihre Daten {#your-data}

Es sind keine Bestell- oder Produktdaten betroffen. Wenn dies weiterhin auftritt, exportieren Sie Diagnosedaten und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

1. Arbeiten Sie weiter — dies ist ein reiner Erkennungsalarm. WCPOS verlangsamt, verzögert oder verwirft keine Anfrage, und es sind keine Bestell- oder Produktdaten betroffen.
2. Wenn der Code einmal auftritt und dann aufhört, ist nichts zu tun. Wenn er sich wiederholt, halten Sie fest, welcher Bildschirm geöffnet war und welche Aktion Sie gerade ausgeführt haben, als er auftrat.
3. Verwenden Sie Debug-Infos kopieren, solange das Ereignis noch im 30-Tage-Protokollfenster liegt, und wenden Sie sich an den WCPOS-Support; der Export ermöglicht es dem Support, die Anfrageschleife nachzuverfolgen.

## Wo Sie nachsehen können {#where-to-look}

Wenn WCPOS diesen Fehler speichern kann, wird er auf dem Gerät aufgezeichnet, das ihn ausgelöst hat. Öffnen Sie **Shop-Zustand → Protokolle** (das Herzschlagsymbol unten im Navigationsmenü), suchen Sie den mit diesem Code gekennzeichneten Eintrag und klappen Sie ihn auf: Die aufgeklappte Zeile zeigt die Ursache in verständlicher Sprache sowie den Kontext, der im Moment des Fehlers erfasst wurde. Bei einer Shop-Anfrage kann dieser Kontext den eigenen Fehlercode des Servers (`serverCode`), den HTTP-`status` oder den `endpoint` enthalten; welche Felder angezeigt werden, hängt davon ab, wo der Fehler aufgetreten ist. Verwenden Sie beim Melden eines Problems **Debug-Infos kopieren** oben im Protokollbildschirm (**Debug-Infos teilen** auf Smartphones und Tablets) statt Screenshots: Damit werden App-Version, Verbindungsstatus und die neuesten Fehler zusammengefasst. Protokolle werden höchstens 30 Tage aufbewahrt — sammeln Sie sie daher, solange das Problem frisch ist. Kopieren Sie außerdem jede Fehlermeldung aus der Browser-Konsole, die erschienen ist, bevor das POS seinen eigenen Protokolleintrag schreiben konnte.
