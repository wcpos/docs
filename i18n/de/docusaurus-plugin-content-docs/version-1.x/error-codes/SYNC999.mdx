## Was dies bedeutet {#what-this-means}

Bei der Synchronisierung ist ein unerwartetes Problem aufgetreten.

Auf diesem Gerät bereits erfasste Verkäufe sind sicher. Prüfen Sie zuerst das Protokoll (siehe Fehlerbehebung): Der Vorgang wird möglicherweise automatisch wiederholt oder muss — falls ein Schreibvorgang nie in die Warteschlange gelangt ist — erneut eingegeben werden. Wenn dieser Code weiterhin auftritt, exportieren Sie die Diagnoseinformationen und wenden Sie sich an den Support.

## Ihre Daten {#your-data}

Wenn Ihr Eintrag erfasst wurde, ist er auf diesem Gerät sicher gespeichert und hat Ihre Filiale noch nicht erreicht. Wenn das Protokoll zeigt, dass der Schreibvorgang vor dem Einreihen in die Warteschlange fehlgeschlagen ist (siehe Schritt 2 der Fehlerbehebung), geben Sie ihn erneut ein. Wenn das Problem weiterhin besteht, exportieren Sie die Diagnoseinformationen und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

1. Gehen Sie nicht davon aus, dass dieser Code automatisch wiederholt wird. Klappen Sie zuerst den Protokolleintrag auf: Bestätigt er, dass die Änderung bereits eingereiht war, wiederholt WCPOS sie automatisch — lassen Sie sie also offen und die Warteschlange abarbeiten.
2. Wenn der Fehler besagt, dass der Engine-Resident fehlt oder der Schreibvorgang fehlschlug, bevor eine Mutations-ID zurückgegeben wurde, wurde nichts eingereiht — kehren Sie zu diesem Datensatz oder dieser Bestellung zurück und speichern Sie ihn bzw. sie erneut.
3. Klappen Sie den Protokolleintrag auf und notieren Sie den Ereigniscode sowie einen etwaigen serverCode: Ein 999er-Code bedeutet, dass die konkrete Ursache noch keinen eigenen Code hat, daher ist genau dieser Kontext das, was der Support benötigt.
4. Wenn der Code weiterhin auftritt, verwenden Sie Debug-Infos kopieren und wenden Sie sich an den Support — nur durch solche Meldungen wird ein eigener Code ergänzt.
