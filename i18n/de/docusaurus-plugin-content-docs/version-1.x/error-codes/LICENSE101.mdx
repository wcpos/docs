## Bedeutung {#what-this-means}

Ihre WCPOS Pro-Lizenz ist für diesen Shop oder dieses Gerät nicht aktiv.

Überprüfen Sie den lokalen Status, den Status des Lizenzservers und den Updater-Status und aktivieren Sie anschließend die Lizenz für den angegebenen Shop.

## Vorgehensweise {#what-to-do}

Damit dies funktioniert, ist eine Änderung der Einstellungen erforderlich. Wiederholen Sie den Vorgang nach der oben genannten Änderung; ohne diese Änderung schlägt er erneut auf dieselbe Weise fehl.

## Ihre Daten {#your-data}

Es sind keine Bestell- oder Produktdaten betroffen. Falls das Problem weiterhin besteht, exportieren Sie Diagnosedaten und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

1. Überprüfen Sie den Lizenzstatus in den POS-Einstellungen in WP Admin — für die genaue URL dieses Shops sollte er als aktiv angezeigt werden.
2. Eine Änderung der Website-URL (http zu https, Hinzufügen oder Entfernen von www, ein Domainumzug, eine Staging-Kopie) deaktiviert die Lizenz für die neue Adresse — aktivieren Sie sie für die aktuelle Adresse erneut.
3. Wenn die Lizenz als aktiv angezeigt wird, das POS jedoch etwas anderes anzeigt, deaktivieren und aktivieren Sie sie einmal erneut und laden Sie dann die Kasse neu.
4. Weiterhin gesperrt? Exportieren Sie Debug-Informationen und kontaktieren Sie den Support mit Ihrer Lizenzreferenz.

## Wo Sie nachsehen können {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät protokolliert, das ihn ausgelöst hat. Öffnen Sie **Filialstatus → Protokolle** (das Herzschlag-Symbol unten in der Navigationsleiste), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt die verständlich formulierte Ursache sowie den zum Zeitpunkt des Fehlers erfassten Kontext — bei allem, was eine Anfrage an Ihren Shop betraf, gehören dazu der Fehlercode des Servers (`serverCode`), der HTTP-`status` und der `endpoint`. Verwenden Sie beim Melden eines Problems **Debug-Informationen kopieren** oben im Bildschirm „Protokolle“ (**Debug-Informationen teilen** auf Smartphones und Tablets) statt Screenshots: Dadurch werden die App-Version, der Verbindungsstatus und die neuesten Fehler gebündelt. Protokolle werden höchstens 30 Tage aufbewahrt; sammeln Sie sie daher, solange das Problem aktuell ist.

Neben dem In-App-Protokoll kann dieser Fehler auch Spuren hinterlassen in:

- **Serverseitige POS-Protokolle**: Öffnen Sie in WP Admin **POS → Einstellungen → Werkzeuge → Protokolle**. Auf dieser Seite werden POS-bezogene Warnungen und Fehler protokolliert, die auf dem Server selbst auftreten und möglicherweise nie in der App erscheinen. Eine rote Kennzeichnung im Menü weist auf ungelesene serverseitige Fehler hin.
