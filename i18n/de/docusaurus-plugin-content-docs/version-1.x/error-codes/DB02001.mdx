# DB02001: Duplikatdatensatz {#db02001-duplicate-record}

## Was Das Bedeutet {#what-this-means}

Die Datenbank hat versucht, einen Datensatz mit einer ID einzufügen, die bereits existiert. Jeder Datensatz muss einen eindeutigen Identifikator haben.

## Häufige Ursachen {#common-causes}

- **Sync-Konflikt** — Gleiche Daten wurden zweimal synchronisiert
- **Race Condition** — Mehrere Vorgänge erstellen denselben Datensatz
- **Datenbeschädigung** — IDs wurden beschädigt oder dupliziert
- **Importproblem** — Importieren von Daten, die bereits existieren

## So Beheben Sie Es {#how-to-fix}

### 1. Daten Auffrischen {#1-refresh-data}

Daten vom Server neu synchronisieren:
- Neueste Daten abrufen
- Den Synchronisierungsprozess Konflikte lösen lassen
- Die neueren Daten sollten Vorrang haben

### 2. Vorgang Wiederholen {#2-retry-the-operation}

Beim Erstellen neuer Datensätze:
- Das System hat ihn möglicherweise bereits erstellt
- Überprüfen, ob der Datensatz existiert
- Vermeiden, mehrmals auf "Absenden" zu klicken

### 3. Lokalen Cache Leeren {#3-clear-local-cache}

:::warning Prüfen Sie zuerst, ob ungespeicherte Arbeit vorliegt
Wenn Sie lokale Daten löschen oder die App neu installieren, wird alles auf diesem Gerät gelöscht, was Ihre Filiale noch nicht erreicht hat — darunter Verkäufe im Offlinebetrieb, offene Warenkörbe und nicht gespeicherte Änderungen. Öffnen Sie vor dem Löschen **Shop-Zustand → Datenbank** und prüfen Sie, dass dort weder zurückgehaltene Änderungen noch solche, die Ihren Server nie erreicht haben, aufgeführt sind. Prüfen Sie anschließend unter **Shop-Zustand → Protokolle**, ob **0 feststeckende Datensätze** und **0 Änderungen, die auf den Versand warten** angezeigt werden. Schließen Sie danach jeden offenen Warenkorb ab oder notieren Sie ihn. Wenn Ihr WCPOS keine Seite „Shop-Zustand“ hat, aktualisieren Sie zuerst WCPOS und prüfen Sie es danach erneut. Falls etwas aufgeführt ist oder auf den Versand wartet oder Sie die Prüfung nicht durchführen können, löschen Sie nichts — fragen Sie den Filialinhaber oder wenden Sie sich an den Support.
:::

Setzen Sie lokale Daten nur dann zurück, wenn die Schritte 1, 2 und 4 nicht geholfen haben, und erst nach der obigen Prüfung:
1. Lokale Datenbank/Cache leeren
2. Erneut einloggen
3. Daten neu synchronisieren

### 4. Auf Duplikate in WooCommerce Überprüfen {#4-check-for-duplicates-in-woocommerce}

Falls das Problem weiterhin besteht:
- WooCommerce auf doppelte Einträge überprüfen
- Nach Produkten/Bestellungen mit denselben IDs suchen
- Alle Duplikate im Admin bereinigen

### 5. Anhaltende Probleme Melden {#5-report-persistent-issues}

Wenn dies häufig passiert:
- Notieren, welche Aktionen es verursachen
- Auf Muster überprüfen
- Dem Support mit Details berichten

## Warum Das Wichtig Ist {#why-this-matters}

Duplikate IDs würden verursachen:
- Verwirrung darüber, welcher Datensatz korrekt ist
- Datenüberschreibungen
- Sync-Probleme

Der Fehler verhindert Datenbeschädigungen.
