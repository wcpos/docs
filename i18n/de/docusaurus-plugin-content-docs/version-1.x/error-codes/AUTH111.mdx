## Bedeutung {#what-this-means}

Die Filiale hat die Anmeldedaten nicht akzeptiert.

Geben Sie Benutzernamen und Passwort erneut ein oder setzen Sie das Passwort in WordPress zurück, falls der Fehler weiterhin auftritt. Bestelldaten sind nicht betroffen.

## Vorgehensweise {#what-to-do}

Korrigieren Sie die hervorgehobenen Angaben und versuchen Sie es anschließend erneut. WCPOS wiederholt dies nicht automatisch — wiederholen Sie den Vorgang, wenn Sie bereit sind.

## Ihre Daten {#your-data}

Keine Bestell- oder Produktdaten sind betroffen.

## Fehlerbehebung {#troubleshoot}

1. Benutzernamen und Passwort erneut eingeben — die Filiale hat diese Kombination abgelehnt.
2. Bestätigen, dass das Konto funktioniert, indem Sie sich mit denselben Zugangsdaten in einem Browser bei WP Admin anmelden; setzen Sie das Passwort dort zurück, falls die Anmeldung fehlschlägt.
3. Wenn die Zugangsdaten in WP Admin funktionieren, aber nicht im POS, blockiert möglicherweise ein Plugin für Anmeldeschutz oder Sicherheit die programmgesteuerte Anmeldung — prüfen Sie dessen Einstellungen oder wenden Sie sich an die Website-Administration.

## Wo Sie nachsehen können {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät aufgezeichnet, das ihn ausgelöst hat. Öffnen Sie **Filialstatus → Protokolle** (das Herzschlag-Symbol unten in der Navigationsleiste), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt den leicht verständlichen Grund und den zum Zeitpunkt des Fehlers erfassten Kontext — bei allem, was eine Anfrage an Ihre Filiale beinhaltete, umfasst dies den servereigenen Fehlercode (`serverCode`), den HTTP-`status` und den `endpoint`. Verwenden Sie beim Melden eines Problems **Debug-Informationen kopieren** oben im Bildschirm „Protokolle“ (**Debug-Informationen teilen** auf Smartphones und Tablets) statt Screenshots: Dadurch werden die App-Version, der Verbindungsstatus und die neuesten Fehler gebündelt. Protokolle werden höchstens 30 Tage lang aufbewahrt; sammeln Sie sie daher, solange das Problem noch aktuell ist.

Neben dem In-App-Protokoll kann dieser Fehler auch an folgenden Stellen Spuren hinterlassen:

- **Netzwerkinspektor** (Web und Desktop): Öffnen Sie die Entwicklerwerkzeuge — drücken Sie im Browser F12 oder wählen Sie im Menü der Desktop-App **Erweitert → Entwicklerwerkzeuge ein-/ausblenden** —, wählen Sie den Tab **Netzwerk** und wiederholen Sie die Aktion. Die fehlgeschlagene Anfrage zeigt den HTTP-Status und den Rohtext der Antwort, einschließlich Fehlerseiten, die das POS-Protokoll nie erreichen.
- **Serverseitige POS-Protokolle**: Öffnen Sie in WP Admin **POS → Einstellungen → Werkzeuge → Protokolle**. Auf dieser Seite werden POS-bezogene Warnungen und Fehler aufgezeichnet, die auf dem Server selbst ausgelöst werden und möglicherweise nie in der App erscheinen. Ein rotes Abzeichen im Menü weist auf ungelesene serverseitige Fehler hin.

## Details {#details}

- **Code:** `AUTH111` (`CREDENTIALS_REJECTED`)
- **Schweregrad:** warn
- **Eingeführt in:** WCPOS 1.10.0
