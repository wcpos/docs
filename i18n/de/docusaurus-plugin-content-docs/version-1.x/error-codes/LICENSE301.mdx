## Bedeutung {#what-this-means}

Das Aktualisierungsprogramm ist nicht berechtigt, WCPOS Pro-Updates herunterzuladen.

Autorisieren Sie das Aktualisierungsprogramm für diese Filiale erneut und suchen Sie dann erneut nach Updates.

## Vorgehen {#what-to-do}

Eine Änderung der Einstellungen ist erforderlich, bevor dies funktioniert. Versuchen Sie es nach der oben genannten Änderung erneut; ohne diese Änderung schlägt der erneute Versuch auf dieselbe Weise fehl.

## Ihre Daten {#your-data}

Es sind keine Bestell- oder Produktdaten betroffen. Wenn das Problem weiterhin besteht, wenden Sie sich an die Person, die Ihre WordPress-Website verwaltet.

## Fehlerbehebung {#troubleshoot}

1. Geben Sie den Lizenzschlüssel erneut ein oder aktivieren Sie ihn erneut in den POS-Einstellungen, damit sich der Updater authentifizieren kann.
2. Suchen Sie erneut nach Updates über WP Admin → Dashboard → Aktualisierungen.
3. Falls die Autorisierung weiterhin fehlschlägt, blockiert die Website möglicherweise ausgehende Anfragen an den Update-Server — fragen Sie beim Hosting-Anbieter nach, ob ausgehendes HTTPS eingeschränkt ist.

## Wo Sie nachsehen können {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät protokolliert, auf dem er ausgelöst wurde. Öffnen Sie **Filialzustand → Protokolle** (das Herzschlag-Symbol unten in der Navigationsleiste), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt den verständlich formulierten Grund und den zum Zeitpunkt des Fehlers erfassten Kontext — bei allem, was eine Anfrage an Ihre Filiale betraf, gehören dazu der eigene Fehlercode des Servers (`serverCode`), der HTTP-`status` und der `endpoint`. Verwenden Sie beim Melden eines Problems oben auf dem Bildschirm „Protokolle“ **Debug-Informationen kopieren** (**Debug-Informationen teilen** auf Smartphones und Tablets) statt Screenshots: Dadurch werden die App-Version, der Verbindungsstatus und die neuesten Fehler zusammengefasst. Protokolle werden höchstens 30 Tage aufbewahrt; sammeln Sie sie daher, solange das Problem noch aktuell ist.

Neben dem App-internen Protokoll kann dieser Fehler auch hier Spuren hinterlassen:

- **Serverseitige POS-Protokolle**: Öffnen Sie in WP Admin **POS → Einstellungen → Werkzeuge → Protokolle**. Auf dieser Seite werden POS-bezogene Warnungen und Fehler protokolliert, die auf dem Server selbst auftreten und möglicherweise nie in der App angezeigt werden. Ein rotes Abzeichen im Menü weist auf ungelesene serverseitige Fehler hin.
