## Bedeutung {#what-this-means}

Die Filialadresse fehlt oder ist keine gültige URL.

Prüfen Sie die Adresse auf Tippfehler und geben Sie die vollständige https:// URL der WordPress-Website der Filiale an. Versuchen Sie es anschließend erneut.

## Vorgehensweise {#what-to-do}

Korrigieren Sie die hervorgehobenen Angaben und versuchen Sie es anschließend erneut. WCPOS wiederholt dies nicht automatisch – wiederholen Sie den Vorgang, wenn Sie bereit sind.

## Ihre Daten {#your-data}

Es sind keine Bestell- oder Produktdaten betroffen.

## Fehlerbehebung {#troubleshoot}

1. Überprüfen Sie die Adresse auf Tippfehler und geben Sie die vollständige URL einschließlich https:// ein — zum Beispiel https://shop.example.com.
2. Verwenden Sie die WordPress-Adresse der Website, nicht eine Admin-Seite oder eine Checkout-URL.
3. Wenn sich die Website in einem Unterverzeichnis befindet (z. B. /shop), geben Sie dieses an.

## Wo Sie nachsehen können {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät protokolliert, auf dem er ausgelöst wurde. Öffnen Sie **Filialstatus → Protokolle** (das Herzschlag-Symbol unten in der Navigationsleiste), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt den Grund in einfacher Sprache sowie den zum Zeitpunkt des Fehlers erfassten Kontext — bei allem, was eine Anfrage an Ihre Filiale betraf, umfasst dies den servereigenen Fehlercode (`serverCode`), den HTTP-`status` und den `endpoint`. Verwenden Sie beim Melden eines Problems **Debug-Informationen kopieren** oben im Protokollbildschirm (**Debug-Informationen teilen** auf Smartphones und Tablets) statt Screenshots: Dadurch werden die App-Version, der Verbindungsstatus und die neuesten Fehler gebündelt. Protokolle werden höchstens 30 Tage lang aufbewahrt; sammeln Sie sie daher, solange das Problem noch aktuell ist.
