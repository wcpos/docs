## Was dies bedeutet {#what-this-means}

Diese Änderung konnte nicht in der lokalen Datenbank gespeichert werden und besteht nur auf diesem Gerät.

Löschen Sie keine lokalen Daten und laden Sie sie nicht neu. Notieren Sie zuerst die Änderung, die nicht gespeichert werden konnte, oder geben Sie sie erneut ein – bei einem Neustart kann sie verloren gehen – und überprüfen Sie dann den Speicher des Geräts. Wenn das Speichern weiterhin fehlschlägt, exportieren Sie die Diagnosedaten und wenden Sie sich an den Support.

## Ihre Daten {#your-data}

Daten auf diesem Gerät könnten gefährdet sein — löschen Sie keine lokalen Daten. Wenn dies weiterhin auftritt, exportieren Sie Diagnosedaten und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

1. Wenn der Protokolleintrag einen Datensatz nennt, halten Sie ihn fest — das ist die Änderung, die nicht gespeichert wurde. Bei Schreibvorgängen zu Website und Zugangsdaten werden stattdessen möglicherweise nur der fehlgeschlagene Vorgang und der Fehler genannt; halten Sie diese Angaben fest, bevor Sie fortfahren.
2. Löschen Sie keine Website-Daten, setzen Sie die App nicht zurück und deinstallieren Sie sie nicht: Die nicht gespeicherte Änderung existiert nur auf diesem Gerät, und das Löschen des lokalen Speichers entfernt sie dauerhaft.
3. Prüfen Sie den freien Speicher des Geräts — eine volle Festplatte oder ein ausgeschöpftes Browser-Speicherkontingent ist der häufigste Grund dafür, dass ein lokaler Schreibvorgang fehlschlägt.
4. Starten Sie WCPOS einmal neu und nehmen Sie eine kleine, harmlose Änderung vor, um zu prüfen, ob neue Änderungen gespeichert werden.
5. Wenn Schreibvorgänge weiterhin fehlschlagen, verwenden Sie Debug-Infos kopieren im Protokollbildschirm und wenden Sie sich an den Support, bevor Sie eine Reparatur versuchen.
