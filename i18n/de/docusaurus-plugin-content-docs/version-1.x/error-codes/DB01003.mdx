# DB01003: Transaktion Fehlgeschlagen {#db01003-transaction-failed}

## Was Dies Bedeutet {#what-this-means}

Eine Datenbanktransaktion konnte nicht abgeschlossen werden. Transaktionen gruppieren mehrere Operationen — wenn ein Teil fehlschlägt, wird alles zurückgerollt, um die Datenintegrität aufrechtzuerhalten.

## Häufige Ursachen {#common-causes}

- **Gleichzeitiger Zugriff** — Mehrere Operationen versuchen, dieselben Daten zu ändern
- **Speicherplatz voll** — Kein Platz, um neue Daten zu schreiben
- **Datenbank gesperrt** — Ein anderer Prozess sperrt die Datenbank
- **Stromunterbrechung** — Operation unerwartet unterbrochen

## Wie Man Es Behebt {#how-to-fix}

### 1. Wiederholen Sie Die Operation {#1-retry-the-operation}

Das Problem könnte vorübergehend sein:
- Warten Sie einen Moment
- Versuchen Sie die Operation erneut
- Vermeiden Sie schnelle wiederholte Versuche

### 2. Überprüfen Sie Auf Konflikte {#2-check-for-conflicts}

Wenn mehrere Geräte oder Tabs geöffnet sind:
- Verwenden Sie jeweils nur eine Instanz
- Schließen Sie doppelte Browser-Tabs
- Koordinieren Sie die Nutzung mehrerer Geräte

### 3. Überprüfen Sie Den Speicherplatz {#3-check-storage-space}

Stellen Sie sicher, dass Platz für Daten vorhanden ist:
- Überprüfen Sie den verfügbaren Speicherplatz
- Geben Sie bei Bedarf Speicherplatz frei
- Löschen Sie in der Webversion den Browser-Cache (entfernen Sie das Häkchen bei „Cookies und andere Websitedaten“ – darin sind die gespeicherten POS-Daten enthalten, auch noch nicht gesendete Daten)

### 4. Starten Sie Die Anwendung Neu {#4-restart-the-application}

Setzen Sie den Zustand der Datenbank zurück:
1. Schließen Sie das POS vollständig
2. Warten Sie ein paar Sekunden
3. Öffnen Sie die Anwendung erneut

### 5. Löschen Und Erneute Synchronisierung {#5-clear-and-re-sync}

:::warning Prüfen Sie zuerst, ob nicht gespeicherte Arbeit vorliegt
Wenn Sie lokale Daten löschen oder die App neu installieren, werden alle Daten auf diesem Gerät gelöscht, die Ihre Filiale noch nicht erreicht haben – darunter offline erfasste Verkäufe, offene Warenkörbe und nicht gespeicherte Änderungen. Öffnen Sie vor dem Löschen **Store health → Database** und prüfen Sie, dass nichts als zurückgehalten oder noch nie an Ihren Server übertragen aufgeführt ist. Prüfen Sie anschließend unter **Store health → Logs**, ob **0 festhängende Datensätze** und **0 noch zu sendende Änderungen** angezeigt werden; schließen oder notieren Sie danach alle offenen Warenkörbe. Wenn Ihr WCPOS keine Seite „Store health“ hat, aktualisieren Sie zuerst WCPOS und prüfen Sie es dann. Wenn etwas aufgeführt wird oder noch aussteht oder Sie die Prüfung nicht durchführen können, löschen Sie nichts – wenden Sie sich an den Inhaber Ihrer Filiale oder den Support.
:::

Nur wenn Transaktionen nach allen anderen Schritten auf dieser Seite weiterhin fehlschlagen und erst nach der obigen Prüfung:
1. Lokale Daten löschen
2. Melden Sie sich erneut an
3. Frisch vom Server synchronisieren

## Transaktionssicherheit {#transaction-safety}

WCPOS verwendet Transaktionen, um sicherzustellen:
- Datenkonsistenz
- Vollständige Operationen (alles oder nichts)
- Schutz vor teilweisen Aktualisierungen

Wenn eine Transaktion fehlschlägt, bleibt Ihre Daten konsistent.
