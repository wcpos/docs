## Was dies bedeutet {#what-this-means}

Der Host drosselt die Anfragerate der Kassen dieses Shops.

Der Server antwortet weiterhin mit 429 (zu viele Anfragen), obwohl die App bereits drosselt und die Retry-After-Verzögerungen des Servers einhält. Mehrere Kassen an einer Internetverbindung teilen sich eine Adresse, sodass quellenbasierte Ratengrenzen sie als einen einzigen sehr aktiven Client behandeln. Die Synchronisierung läuft automatisch weiter, wird aber nachhängen, bis das Limit erhöht wird.

## Ihre Daten {#your-data}

Es sind keine Bestell- oder Produktdaten betroffen.

## Fehlerbehebung {#troubleshoot}

1. Bitten Sie den Host, das Ratenlimit der REST API für den eigenen Datenverkehr des Shops zu erhöhen oder auszunehmen — nennen Sie die statische IP des Shops, falls vorhanden.
2. Sicherheitsdienste, die wiederholte Fehlerantworten (429) auf eine Sperre anrechnen (zum Beispiel Sucuris IDS), müssen möglicherweise die API des Shops von diesem Zähler ausnehmen.
3. Wenn sich mehrere Kassen eine Verbindung teilen, weisen Sie den Host darauf hin: Eine IP steht hier für ein ganzes Geschäft, nicht für einen einzelnen Benutzer.
