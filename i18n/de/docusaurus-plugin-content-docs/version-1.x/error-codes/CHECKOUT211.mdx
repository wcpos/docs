## Was dies bedeutet {#what-this-means}

Der Shop hat kein Checkout-Ergebnis zurückgegeben, daher ist der Bestellstatus unbekannt.

Prüfen Sie, ob die Bestellung angelegt wurde, bevor Sie den Checkout erneut versuchen.

## Ihre Daten {#your-data}

Das Ergebnis konnte nicht bestätigt werden — prüfen Sie es, bevor Sie es erneut versuchen. Wenn dies weiterhin auftritt, exportieren Sie Diagnosedaten und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

**Prüfen Sie zuerst, ob die Bestellung vorhanden ist** — eine leere Antwort bedeutet häufig, dass die Bestellung angelegt wurde, die Bestätigung aber nicht eingegangen ist. Synchronisieren Sie bei WCPOS Pro den POS und suchen Sie die Bestellung in der Bestellliste der Kasse. Andernfalls bitten Sie jemanden, WooCommerce → Bestellungen in WP Admin zu prüfen. Wiederholen Sie den Checkout erst, nachdem Sie bestätigt haben, dass keine Bestellung angelegt wurde.

**In der Filiale** — für die Website-Administration:

1. Prüfen Sie WooCommerce → Status → Protokolle auf einen fatalen Fehler während des Checkouts — ein PHP-Absturz nach dem Anlegen der Bestellung erzeugt genau dieses Bild.
2. Wenn das WooCommerce-Protokoll keinen Eintrag enthält, bitten Sie den Hosting-Anbieter um das PHP-Fehlerprotokoll des Servers. Manche schwerwiegenden Fehler werden nur dort erfasst.

**Für Entwickler:** In den Entwicklertools des Browsers oder über **Erweitert → Entwicklertools umschalten** in der Desktop-App deutet eine Checkout-Anfrage im Tab Netzwerk mit Erfolgsstatus, aber leerem oder abgeschnittenem Antworttext darauf hin, dass ein Plugin oder Serverpuffer die Antwort vorzeitig abschneidet.
