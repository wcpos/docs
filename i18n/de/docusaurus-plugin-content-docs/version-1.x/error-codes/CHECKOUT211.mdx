## Bedeutung {#what-this-means}

Der WooCommerce-Shop hat kein Checkout-Ergebnis zurückgegeben, daher ist der Bestellstatus unbekannt.

Prüfen Sie, ob die Bestellung erstellt wurde, bevor Sie den Kassenvorgang erneut versuchen.

## Vorgehensweise {#what-to-do}

Prüfen Sie die folgenden Details, bevor Sie es erneut versuchen. Wiederholen Sie den Vorgang erst, nachdem Sie bestätigt haben, was tatsächlich passiert ist — ein unbedachter Wiederholungsversuch kann zu einer doppelten Belastung oder Bestellung führen.

## Ihre Daten {#your-data}

Das Ergebnis konnte nicht bestätigt werden — überprüfen Sie es vor einem erneuten Versuch. Falls das Problem weiterhin besteht, exportieren Sie Diagnosedaten und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

1. Vor allen weiteren Maßnahmen WooCommerce → Bestellungen im WP Admin prüfen — eine leere Antwort bedeutet oft, dass die Bestellung erstellt wurde, die Bestätigung jedoch nicht eingetroffen ist.
2. Der Netzwerkinspektor zeigt die Checkout-Anfrage: Ein Erfolgsstatus mit einem leeren oder abgeschnittenen Body deutet darauf hin, dass ein Plugin oder Serverpuffer die Antwort vorzeitig abschneidet.
3. WooCommerce → Status → Protokolle auf einen schwerwiegenden Fehler während des Checkouts prüfen — ein PHP-Absturz nach dem Erstellen der Bestellung führt genau zu diesem Problem.
4. Den Checkout erst erneut versuchen, nachdem bestätigt wurde, dass keine Bestellung erstellt wurde.

## Wo nachgesehen werden kann {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät aufgezeichnet, auf dem es ausgelöst wurde. **Filialzustand → Protokolle** öffnen (das Herzschlag-Symbol unten in der Navigationsleiste), den mit diesem Code markierten Eintrag suchen und erweitern: Die erweiterte Zeile zeigt den Grund in einfacher Sprache sowie den zum Zeitpunkt des Fehlers erfassten Kontext — bei allem, was eine Anfrage an Ihren WooCommerce-Shop betraf, umfasst dies den servereigenen Fehlercode (`serverCode`), den HTTP-`status` und den `endpoint`. Beim Melden eines Problems oben im Bildschirm Protokolle **Debug-Informationen kopieren** verwenden (**Debug-Informationen teilen** auf Smartphones und Tablets) statt Screenshots: Dadurch werden App-Version, Verbindungsstatus und die neuesten Fehler gebündelt. Protokolle werden höchstens 30 Tage aufbewahrt; sie sollten daher gesammelt werden, solange das Problem aktuell ist.

Neben dem In-App-Protokoll kann dieser Fehler auch hier Spuren hinterlassen:

- **Netzwerkinspektor** (Web und Desktop): Die Entwicklertools öffnen — im Browser F12 drücken oder im Menü der Desktop-App **Erweitert → Entwicklertools umschalten** wählen — den Tab **Netzwerk** auswählen und die Aktion wiederholen. Die fehlgeschlagene Anfrage zeigt den HTTP-Status und den unverarbeiteten Response-Body, einschließlich Fehlerseiten, die das POS-Protokoll nie erreichen.
- **WooCommerce → Status → Protokolle**: Auf der WordPress-Website die neueste `fatal-errors-*.log` auf PHP-Abstürze prüfen sowie alle Protokollquellen, die nach einem am Fehler beteiligten Plugin benannt sind. Ein Fehler der 500er-Klasse vom WooCommerce-Shop hinterlässt seine Ursache fast immer hier.
- **Das PHP-Fehlerprotokoll der Website**: Wenn die WooCommerce-Protokollseite für den Fehlerzeitpunkt nichts anzeigt, beim Hosting-Anbieter nach dem PHP-Fehlerprotokoll fragen — einige schwerwiegende Fehler werden nur auf Serverebene erfasst.
