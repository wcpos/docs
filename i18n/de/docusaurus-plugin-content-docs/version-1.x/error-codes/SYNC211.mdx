## Was dies bedeutet {#what-this-means}

Ein Feld eines Datensatzes wurde von Ihrer Filiale abgelehnt. Gelegentlich steht dieser Code auch für eine Einstellungs- oder Authentifizierungsanfrage, die von der Filiale abgelehnt wurde.

Wenn ein Datensatz genannt wird, korrigieren Sie das angegebene Feld und versuchen Sie es erneut; die lokale Kopie bleibt verfügbar, bis sie synchronisiert ist. Folgen Sie andernfalls der Meldung der Filiale zur genannten Anfrage.

## Ihre Daten {#your-data}

Handelte es sich um eine Änderung an einem Datensatz, ist sie weiterhin auf diesem Gerät gespeichert und noch nicht in Ihrer Filiale angekommen. Bei einer Einstellungs- oder Authentifizierungsanfrage gibt es nichts zu speichern.

## Fehlerbehebung {#troubleshoot}

1. Klappen Sie den Protokolleintrag auf und prüfen Sie zuerst endpoint und Serverantwort: Dieser Code kann auch für einen HTTP-400 aus einer Einstellungs-, Authentifizierungs- oder anderen Nicht-Datensatz-Anfrage stehen.
2. Wenn der Kontext einen Datensatz oder ein Feld nennt, bearbeiten Sie dieses Feld im POS — häufige Ursachen sind ein Wert außerhalb des zulässigen Bereichs, ein abgelehntes Format oder eine leer gelassene Pflichtoption — und versuchen Sie es dann erneut.
3. Handelt es sich nicht um eine Datensatzanfrage, folgen Sie stattdessen der Servermeldung zum genannten Endpunkt. Die Entwicklertools des Browsers (Tab „Netzwerk“) – oder **Erweitert → Entwicklertools umschalten** in der Desktop-App – zeigen die Antwort, wenn die Details nicht im POS-Protokoll stehen.
4. **Website-Administrator:** Wenn ein genanntes Feld im POS korrekt aussieht, vergleichen Sie es mit demselben Datensatz in WP Admin — eine durch ein Plugin hinzugefügte Validierung in der Filiale kann Werte ablehnen, die das POS für gültig hält.
