## Was dies bedeutet {#what-this-means}

Eine Änderung auf diesem Gerät ist mit einer neueren Bearbeitung in Ihrer Filiale kollidiert. Es geht nichts verloren.

Wenn unter **Filialstatus → Datenbank** eine zurückgehaltene Änderung für diesen Datensatz aufgeführt ist, tippen Sie auf **Erneut senden**, um die Version dieses Geräts beizubehalten, oder auf **Serverversion verwenden**, um die Version der Filiale zu übernehmen. Andernfalls ist nichts zu tun — der Konflikt wurde bereits gelöst.

## Ihre Daten {#your-data}

Es geht nichts verloren. Bei einer zurückgehaltenen Änderung behält Ihre Filiale ihre Version und dieses Gerät seine Änderung, bis Sie auswählen, welche Version beibehalten werden soll. Weitere Bearbeitungen dieses Datensatzes werden auf diesem Gerät bis dahin zurückgehalten. Löschen Sie die Daten dieses Geräts nicht, solange eine Änderung zurückgehalten wird — dadurch wird sie gelöscht.

## Fehlerbehebung {#troubleshoot}

1. Öffnen Sie **Filialstatus → Datenbank**. Eine zurückgehaltene Änderung wird in einem Bereich aufgeführt, der mit **„1 Änderung wurde zurückgehalten“** (oder **„… Änderungen wurden zurückgehalten“**) beginnt, zusammen mit dem zugehörigen Datensatz.
2. Wenn für diesen Datensatz keine Änderung mehr zurückgehalten wird, wurde der Konflikt bereits gelöst — hier oder in einem anderen Tab — und Sie müssen nichts tun. Ein Bestellkonflikt, den WCPOS selbst löst, indem es die Version dieses Geräts erneut sendet, wird stattdessen als [SYNC222](/error-codes/SYNC222) protokolliert.
3. Wenn eine Änderung zurückgehalten wird, tippen Sie auf **Datensatz öffnen** (sofern angezeigt), um die Version dieses Geräts zu sehen, und vergleichen Sie sie mit demselben Datensatz in WP Admin (möglicherweise muss dies ein Website-Administrator übernehmen).
4. Um die Version dieses Geräts beizubehalten, tippen Sie auf **Erneut senden** — die Änderung wird erneut gesendet und ersetzt die Werte der Filiale in den Feldern, die auf diesem Gerät geändert wurden. Um die Version der Filiale beizubehalten, tippen Sie auf **Serverversion verwenden** (in einigen Zeilen **Geräteänderung verwerfen**) und bestätigen Sie — die Änderung dieses Geräts wird verworfen. Weitere Bearbeitungen dieses Datensatzes warten, bis Sie sich entschieden haben.
5. Häufige Konflikte bei denselben Datensätzen bedeuten meist, dass zwei Personen dieselben Daten parallel bearbeiten — zum Beispiel den Lagerbestand an der Kasse und in WP Admin. Legen Sie fest, wo die jeweiligen Änderungen vorgenommen werden.
