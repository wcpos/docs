## Was bedeutet das? {#what-this-means}

Ihre Sitzung ist beendet und Sie müssen sich erneut anmelden.

Melden Sie sich erneut an und wiederholen Sie die Anfrage; lokale Daten gingen nicht verloren.

## Was ist zu tun? {#what-to-do}

Versuchen Sie die Aktion erneut. Wiederholen Sie den Vorgang, nachdem Sie die obige Änderung vorgenommen haben; ohne diese Änderung schlägt der erneute Versuch erneut fehl.

## Ihre Daten {#your-data}

Keine Bestell- oder Produktdaten sind betroffen.

## Fehlerbehebung {#troubleshoot}

1. Melden Sie sich bei Aufforderung erneut an und wiederholen Sie dann die Aktion — auf der Kasse ging nichts verloren.
2. Häufige Ablaufzeiten (mehrmals täglich) gehen in der Regel auf die Website zurück: Ein Sicherheits-Plugin verkürzt die Sitzungsdauer oder löscht Token. Fragen Sie die Website-Administration, welche Sicherheits-Plugins auf der WooCommerce-Website aktiv sind.

## Wo Sie nachsehen können {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät protokolliert, auf dem es ausgelöst wurde. Öffnen Sie **Filialstatus → Protokolle** (das Herzschlag-Symbol unten in der Navigationsleiste), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt den Grund in einfacher Sprache sowie den zum Zeitpunkt des Fehlers erfassten Kontext — bei allem, was eine Anfrage an Ihren WooCommerce-Shop beinhaltete, umfasst dies den servereigenen Fehlercode (`serverCode`), den HTTP-`status` und den `endpoint`. Verwenden Sie beim Melden eines Problems **Debug-Informationen kopieren** oben im Bildschirm „Protokolle“ (**Debug-Informationen teilen** auf Smartphones und Tablets) statt Screenshots: Dadurch werden die App-Version, der Verbindungsstatus und die neuesten Fehler gebündelt. Protokolle werden höchstens 30 Tage aufbewahrt; sammeln Sie sie daher, solange das Problem aktuell ist.

Neben dem In-App-Protokoll kann dieser Fehler auch hier Spuren hinterlassen:

- **Netzwerkinspektor** (Web und Desktop): Öffnen Sie die Entwicklertools — drücken Sie im Browser F12 oder wählen Sie im Menü der Desktop-App **Erweitert → Entwicklertools ein-/ausblenden** —, wählen Sie den Tab **Netzwerk** und wiederholen Sie die Aktion. Die fehlgeschlagene Anfrage zeigt den HTTP-Status und den unverarbeiteten Antworttext, einschließlich Fehlerseiten, die das POS-Protokoll nie erreichen.
