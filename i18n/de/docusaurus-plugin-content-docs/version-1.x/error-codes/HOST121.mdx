## Was dies bedeutet {#what-this-means}

Eine Bot-Schutzseite antwortet anstelle der API des Shops.

Die REST API des Shops gibt eine HTML-Challenge-Seite (Bot-Schutz, CAPTCHA oder DDoS-Zwischenseite) zurück, wo die App JSON erwartet. Eine Kassen-App kann keine Browser-Challenge lösen; die REST API des Shops muss im Schutzdienst auf die Zulassungsliste gesetzt werden.

## Ihre Daten {#your-data}

Es sind keine Bestell- oder Produktdaten betroffen.

## Fehlerbehebung {#troubleshoot}

1. Ermitteln Sie den Schutzdienst anhand der Challenge-Seite (Cloudflare, Sucuri, Kinsta und andere kennzeichnen ihre Seiten jeweils mit ihrem Namen) und öffnen Sie dessen Einstellungen.
2. Setzen Sie die shopeigenen REST-API-Pfade (/wp-json/ und /?rest_route=) für API-Datenverkehr auf die Zulassungsliste.
3. Fügen Sie in Cloudflare eine WAF-Regel vom Typ **Skip** für die REST-API-Pfade hinzu. Bot Fight Mode (kostenloser Tarif) lässt sich durch keine Regel umgehen und muss deaktiviert werden. Die [Cloudflare-Anleitung](/1.x/support/troubleshooting/cloudflare) enthält die genaue Regel und eine `curl`-Prüfung.
4. Setzen Sie in Kinstas Bot-/Firewall-Einstellungen die REST-API-Pfade auf die Zulassungsliste; vermeiden Sie bei Sucuri den DDoS-Modus mit JavaScript-Challenge für API-Routen.
