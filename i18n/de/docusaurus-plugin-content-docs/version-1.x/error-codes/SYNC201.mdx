## Was dies bedeutet {#what-this-means}

Ihre Filiale hat diese Änderung abgelehnt; sie hat die Filiale daher nicht erreicht.

Lesen Sie die Begründung Ihrer Filiale. Wird die Änderung unter **Shop-Zustand → Datenbank** aufgeführt, korrigieren Sie den Datensatz und tippen Sie auf **Erneut senden** oder **Verwerfen**. Andernfalls wurde die Version der Filiale wiederhergestellt – nehmen Sie die Änderung bei Bedarf erneut vor (siehe [SYNC202](/error-codes/SYNC202)). Eine abgelehnte Änderung wird nicht automatisch erneut versucht.

## Ihre Daten {#your-data}

Löschen Sie nicht die Daten dieses Geräts – möglicherweise enthält es Änderungen, die Ihre Filiale noch nicht hat. Eine abgelehnte Änderung, die unter **Shop-Zustand → Datenbank** aufgeführt ist, bleibt dort, bis Sie sie erneut senden oder verwerfen. Eine abgelehnte Bearbeitung eines bestehenden Produkts, einer Variante, eines Kunden oder eines Gutscheins wird üblicherweise automatisch rückgängig gemacht und stattdessen als [SYNC202](/error-codes/SYNC202) protokolliert. Wird sie als dieser Code angezeigt und ist die Änderung unter **Shop-Zustand → Datenbank** aufgeführt, wurde sie nicht automatisch rückgängig gemacht – behandeln Sie sie wie jede andere unten aufgeführte Änderung. Wenn dies weiterhin auftritt, verwenden Sie **Debug-Infos kopieren** auf dem Tab **Protokolle** und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

1. Lesen Sie den Grund Ihrer Filiale – er steht im Protokolleintrag und in der Zeile der Änderung unter **Shop-Zustand → Datenbank**.
2. Öffnen Sie **Shop-Zustand → Datenbank**. Wenn die Änderung dort nicht aufgeführt ist, wurde die Version der Filiale auf diesem Gerät bereits wiederhergestellt und es gibt nichts zu senden – siehe [SYNC202](/error-codes/SYNC202). Beheben Sie die angegebene Ursache und nehmen Sie die Änderung erneut vor, falls sie weiterhin erforderlich ist.
3. Wenn sie aufgeführt ist – eine Bestellung, ein auf diesem Gerät erstellter Datensatz oder eine Katalogbearbeitung, die nicht automatisch rückgängig gemacht wurde –, steht die abgelehnte Änderung unter **„… Änderungen haben Ihren Server nie erreicht“**. In der Zeile wird der Grund Ihrer Filiale angezeigt. Beheben Sie den genannten Grund direkt im Datensatz, zum Beispiel in einem Feld der Bestellung, während die Änderung weiterhin aufgeführt ist.
4. Tippen Sie unter **Shop-Zustand → Datenbank** bei dieser Zeile auf **Erneut senden**. Dadurch wird die Änderung anhand des aktuellen Stands auf diesem Gerät neu erstellt und gesendet.
5. Wenn die Änderung nicht mehr benötigt wird, tippen Sie stattdessen auf **Verwerfen**: Die Version der Filiale bleibt erhalten. Lesen Sie zuerst die Bestätigung – beim Verwerfen eines Datensatzes, den die Filiale nie gespeichert hat, wird dieser von diesem Gerät gelöscht.
6. **Shop-Administrator:** Wenn der Grund besagt, dass der Benutzer die Änderung nicht vornehmen darf, fehlt seiner Rolle die entsprechende Berechtigung – siehe [AUTH201](/error-codes/AUTH201). Wenn der Grund ein Feld betrifft, das im POS nicht angezeigt wird, öffnen Sie denselben Datensatz in WP Admin – möglicherweise fügt ein anderes Plugin eine Validierung hinzu, die der POS nicht kennt. Wird die Änderung weiterhin abgelehnt, verwenden Sie **Debug-Infos kopieren** im Tab **Protokolle** und wenden Sie sich an den Support.
