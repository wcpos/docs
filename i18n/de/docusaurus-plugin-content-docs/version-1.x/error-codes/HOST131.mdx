## Was dies bedeutet {#what-this-means}

Ein Proxy vor dem Shop lehnt die Antworten des Servers ab, weil sie zu viele Header enthalten.

Eine Cache- oder Proxy-Ebene (häufig Varnish) erzwingt eine Begrenzung für Anzahl oder Größe der Antwort-Header. Die schlanken Endpunkte des Shops passen hinein, aber vollständige API-Antworten überschreiten das Limit und kommen als 503 vom Proxy zurück, nicht von WordPress. Das Limit muss auf dieser Ebene erhöht werden.

## Ihre Daten {#your-data}

Es sind keine Bestell- oder Produktdaten betroffen.

## Fehlerbehebung {#troubleshoot}

1. Erhöhen Sie bei Varnish http_max_hdr (Header-Anzahl) und http_resp_hdr_len / http_resp_size (Größen).
2. Fragen Sie den Host, welche Proxy-Ebene das 503 zurückgibt — das WordPress-Fehlerprotokoll zeigt nichts an, weil die Anfrage dort nie fehlschlägt.
3. Eine schnelle Prüfung: /wcpos/v2/ping des Shops antwortet einwandfrei, während Daten-Endpunkte mit 503 antworten.
