# API02003: Token Ungültig {#api02003-token-invalid}

## Was Das Bedeutet {#what-this-means}

Das verwendete Authentifizierungstoken wird vom Server nicht erkannt. Dies unterscheidet sich von einem abgelaufenen Token – dieses Token war niemals gültig oder wurde widerrufen.

## Häufige Ursachen {#common-causes}

- **Token widerrufen** – Ein Administrator hat die Sitzung widerrufen
- **Token beschädigt** – Datenkorruption während der Speicherung oder Übertragung
- **Server zurückgesetzt** – Servergeheimschlüssel wurden geändert, was alle Tokens ungültig macht
- **Falscher Server** – Token von einer anderen WordPress-Installation

## Zuordnung von Serverfehlern {#server-error-mapping}

Dieser Fehlercode wird ausgelöst, wenn der Server zurückgibt:

| Servercode | Quelle |
|-------------|--------|
| `jwt_auth_invalid_token` | JWT-Authentifizierungs-Plugin |

## So Beheben Sie Es {#how-to-fix}

### 1. Erneut Einloggen {#1-log-in-again}

Melden Sie sich ab und authentifizieren Sie sich erneut. Falls auf diesem Gerät Verkäufe gespeichert sein könnten, die Ihre Filiale noch nicht erreicht haben, führen Sie zuerst die Prüfung in der Warnung zu Schritt 2 durch:
1. Komplett ausloggen
2. POS schließen und erneut öffnen
3. Mit Ihren Zugangsdaten einloggen

### 2. Anwendungsdaten Bereinigen {#2-clear-application-data}

:::warning Prüfen Sie zuerst, ob ungespeicherte Arbeit vorliegt
Durch das Löschen lokaler Daten oder die Neuinstallation der App werden alle Daten auf diesem Gerät gelöscht, die Ihre Filiale noch nicht erreicht haben – einschließlich offline erfasster Verkäufe, offener Warenkörbe und nicht gespeicherter Änderungen. Öffnen Sie vor dem Löschen **Shop-Zustand → Datenbank** und prüfen Sie, ob etwas als zurückgehalten oder noch nicht auf Ihrem Server eingegangen aufgeführt ist. Prüfen Sie anschließend unter **Shop-Zustand → Protokolle**, ob **0 festhängende Datensätze** und **0 Änderungen ausstehend** angezeigt werden. Schließen Sie danach alle offenen Warenkörbe ab oder notieren Sie sie. Wenn Ihre WCPOS-Version keine Seite „Shop-Zustand“ hat, aktualisieren Sie WCPOS zuerst und prüfen Sie dann erneut. Wenn etwas aufgeführt ist oder aussteht oder Sie die Prüfung nicht durchführen können, löschen Sie nichts – wenden Sie sich an den Filialinhaber oder den Support.
:::

Setzen Sie nur dann und erst nach der obigen Prüfung fort, wenn das Abmelden nicht funktioniert hat:
- Cache/Daten der POS-App bereinigen
- Im Web: Browser-Cookies und lokalen Speicher der Website bereinigen
- Auf dem Desktop: App-Einstellungen nach einer Option "Daten bereinigen" überprüfen

### 3. Serverkonfiguration Überprüfen {#3-check-server-configuration}

Wenn das Problem alle Benutzer betrifft:
- Überprüfen Sie, ob die WordPress-Salze geändert wurden
- Überprüfen Sie die Einstellungen des JWT- oder Authentifizierungs-Plugins
- Überprüfen Sie kürzliche Serveränderungen

### 4. Überprüfen Sie, Ob Sie Auf Dem Richtigen Server Sind {#4-verify-youre-on-the-correct-server}

Stellen Sie sicher, dass die POS so konfiguriert ist, dass sie sich mit der richtigen WordPress-Website verbindet, insbesondere wenn Sie mehrere Installationen haben.
