## Was dies bedeutet {#what-this-means}

Die Synchronisierung benötigt länger als erwartet, um zu starten.

Dies erledigt sich normalerweise innerhalb einer Minute von selbst. Wenn die App in diesem Zustand bleibt, laden Sie sie zunächst einmal neu.

## Was zu tun ist {#what-to-do}

Sie können weiterarbeiten – WCPOS verarbeitet dies automatisch. WCPOS versucht dies automatisch erneut.

## Ihre Daten {#your-data}

Es sind keine Bestell- oder Produktdaten betroffen.

## Fehlerbehebung {#troubleshoot}

1. Geben Sie ihm eine Minute — die erste Synchronisierung nach einem Update oder bei einem großen Shop dauert berechtigterweise länger.
2. Wenn die App in diesem Zustand bleibt, laden Sie sie einmal neu.
3. Wenn langsame Starts täglich auftreten, prüfen Sie die Verbindungsqualität zum Shop und die Reaktionsfähigkeit des Shops.

## Wo Sie nachsehen können {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät aufgezeichnet, das ihn ausgelöst hat. Öffnen Sie **Filialzustand → Protokolle** (das Herzschlag-Symbol unten in der Navigationsleiste), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt den leicht verständlichen Grund und den zum Zeitpunkt des Fehlers erfassten Kontext — bei allem, was eine Anfrage an Ihren Shop betraf, umfasst dies den servereigenen Fehlercode (`serverCode`), den HTTP-`status` und den `endpoint`. Verwenden Sie beim Melden eines Problems oben im Bildschirm „Protokolle“ **Debug-Informationen kopieren** (**Debug-Informationen teilen** auf Smartphones und Tablets) statt Screenshots: Dadurch werden die App-Version, der Verbindungsstatus und die jüngsten Fehler gebündelt. Protokolle werden höchstens 30 Tage lang aufbewahrt; sammeln Sie sie daher, solange das Problem noch aktuell ist.
