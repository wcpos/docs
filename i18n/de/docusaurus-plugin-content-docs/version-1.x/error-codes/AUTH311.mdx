## Bedeutung {#what-this-means}

Die WCPOS-Filialroute ist nicht verfügbar.

Bitten Sie die Person, die die Website verwaltet, zu prüfen, ob ein Sicherheits- oder Proxy-Plugin WCPOS-Anfrage-Header entfernt.

## Vorgehensweise {#what-to-do}

Damit dies funktioniert, ist eine Änderung der Einstellungen erforderlich. Versuchen Sie es nach der oben genannten Änderung erneut; ohne diese Änderung schlägt der Vorgang erneut auf dieselbe Weise fehl.

## Ihre Daten {#your-data}

Es sind keine Bestell- oder Produktdaten betroffen. Falls das Problem weiterhin besteht, wenden Sie sich an die Person, die Ihre WordPress-Website verwaltet.

## Fehlerbehebung {#troubleshoot}

1. Bestätigen Sie, dass WCPOS auf der Website aktiv ist: WP Admin → Plugins.
2. Testen Sie die Route direkt: Öffnen Sie die Adresse /wp-json/ Ihrer Filiale in einem Browser — eine HTML-Seite oder ein 404 anstelle von JSON bedeutet, dass die REST API selbst blockiert ist.
3. Fragen Sie die Website-Administration, ob ein Sicherheits-Plugin, Proxy oder CDN WCPOS-Anfrage-Header entfernt oder /wp-json/ blockiert — Firewall-Regeln und Härtungsoptionen zum Deaktivieren der REST API sind die üblichen Ursachen.
4. Bei einigen Hostern stellt das erneute Speichern der Permalinks (Einstellungen → Permalinks → Speichern) fehlende REST-Routen wieder her.

## Wo Sie nachsehen können {#where-to-look}

Jedes Auftreten dieses Codes wird auf dem Gerät aufgezeichnet, das ihn ausgelöst hat. Öffnen Sie **Filialstatus → Protokolle** (das Herzschlag-Symbol unten im Navigationsmenü), suchen Sie den mit diesem Code markierten Eintrag und erweitern Sie ihn: Die erweiterte Zeile zeigt den verständlich formulierten Grund sowie den zum Zeitpunkt des Fehlers erfassten Kontext — bei allen Vorgängen, die eine Anfrage an Ihre Filiale betrafen, gehören dazu der servereigene Fehlercode (`serverCode`), der HTTP-`status` und der `endpoint`. Verwenden Sie beim Melden eines Problems **Debug-Informationen kopieren** oben im Bildschirm „Protokolle“ (**Debug-Informationen teilen** auf Smartphones und Tablets) statt Screenshots: Damit werden die App-Version, der Verbindungsstatus und die neuesten Fehler gebündelt. Protokolle werden höchstens 30 Tage aufbewahrt; sammeln Sie sie daher, solange das Problem aktuell ist.

Neben dem In-App-Protokoll kann dieser Fehler auch an folgenden Stellen Spuren hinterlassen:

- **Netzwerk-Inspektor** (Web und Desktop): Öffnen Sie die Entwicklertools — drücken Sie im Browser F12 oder wählen Sie im Menü der Desktop-App **Erweitert → Entwicklertools umschalten** —, wählen Sie den Tab **Netzwerk** und wiederholen Sie die Aktion. Die fehlgeschlagene Anfrage zeigt den HTTP-Status und den unverarbeiteten Antworttext, einschließlich Fehlerseiten, die das POS-Protokoll nie erreichen.
- **WooCommerce → Status → Protokolle**: Prüfen Sie auf der WordPress-Website die neueste `fatal-errors-*.log` auf PHP-Abstürze sowie jede Protokollquelle, die nach einem am Fehler beteiligten Plugin benannt ist. Ein Fehler der 500er-Klasse aus der Filiale hinterlässt seine Ursache fast immer hier.
