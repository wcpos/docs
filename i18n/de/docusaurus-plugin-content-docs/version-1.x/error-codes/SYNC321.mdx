## Was dies bedeutet {#what-this-means}

Einige Daten wurden diesmal nicht synchronisiert.

Dieser Code tritt in zwei Formen auf — der Titel der Protokollzeile zeigt, welche davon vorliegt:

- **„Sync partial“** (Datensatztitel): Einige Datensätze wurden synchronisiert, die genannten jedoch nicht. Wenn der nächste Synchronisierungsvorgang den Hinweis beseitigt, müssen Sie nichts tun. Wenn unter **Shop-Zustand → Datenbank** Änderungen aufgeführt sind, die Aufmerksamkeit erfordern, bearbeiten Sie sie dort.
- **„Gave up on a stuck data request“**: Der Datenanforderungs-Bereich der Synchronisierungs-Engine machte bei einer Anfrage keine Fortschritte. Nach einer großzügig bemessenen Wartezeit hat die App diese Anfrage aufgegeben, anstatt dadurch alle dahinter wartenden Anfragen zu blockieren. Sie müssen nichts manuell wiederholen — die Synchronisierungs-Engine stellt die Anfrage automatisch erneut. Häufig geht dem ein blockierter Aufruf der lokalen Datenbank voraus, der separat als [SYNC181](/error-codes/SYNC181) protokolliert wird.

## Ihre Daten {#your-data}

Löschen Sie nicht die Daten auf diesem Gerät – sie können Änderungen enthalten, die Ihre Filiale noch nicht erhalten hat. Bei einer abgebrochenen Datenanfrage wurde nichts geändert – eine aufgegebene Anfrage wird automatisch erneut gesendet. Wenn dies weiterhin geschieht, verwenden Sie **Copy debug info** auf dem Tab **Logs** und wenden Sie sich an den WCPOS-Support.

## Fehlerbehebung {#troubleshoot}

1. Bei einem Eintrag **„Gave up on a stuck data request“** ist keine Aktion erforderlich, sofern kein Bildschirm hängen bleibt. Laden Sie dann die App neu – im Web laden Sie den Browser-Tab neu; auf dem Desktop und Mobilgerät schließen Sie die App und öffnen sie erneut.
2. Bei einer teilweisen Synchronisierung müssen Sie nichts tun, wenn der nächste Synchronisierungsvorgang den Hinweis beseitigt. Falls nicht, öffnen Sie **Shop-Zustand → Datenbank**: Datensätze, die weiterhin nicht synchronisiert wurden, stehen ganz oben. Der Hinweis **„… records need attention“** nennt den ersten Datensatz samt Begründung (beheben Sie das Problem, damit der nächste angezeigt wird); die Bereiche **„… changes never reached your server“** und **„… changes were held“** listen die entsprechenden Änderungen auf. Für erfolgreich synchronisierte Datensätze ist nichts zu tun.
3. Bearbeiten Sie jeden aufgeführten Datensatz entsprechend dem jeweiligen Grund. Im Hinweis öffnet **Fix record** (falls angezeigt) den Datensatz zur Bearbeitung. Korrigieren Sie eine abgelehnte Änderung direkt im Datensatz ([SYNC201](/error-codes/SYNC201)); bei einer zurückgehaltenen Änderung entscheiden Sie, welche Version beibehalten werden soll ([SYNC221](/error-codes/SYNC221)).
4. Senden Sie sie anschließend erneut: über **Retry** im Hinweis (dadurch wird eine Synchronisierung ausgeführt) oder über **Send again** in der Zeile des Datensatzes in den Bereichen. Bei einem Datensatz, für den der Hinweis *can't download from your store* meldet, gibt es keine Option **Retry** – siehe [SYNC331](/error-codes/SYNC331).
5. Wenn ein Datensatz weiterhin nicht synchronisiert wird, verwenden Sie **Copy debug info** auf dem Tab **Logs** und wenden Sie sich an den Support.
