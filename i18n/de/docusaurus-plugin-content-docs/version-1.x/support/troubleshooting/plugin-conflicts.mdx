Plugin-Konflikte gehören zu den häufigsten Ursachen für Probleme mit WCPOS. Wenn andere WordPress-Plugins die Funktionen von WooCommerce oder WCPOS beeinträchtigen, können Abstürze, Leistungsprobleme oder unerwartetes Verhalten auftreten.

## Anzeichen für Plugin-Konflikte {#signs-of-plugin-conflicts}

Möglicherweise liegt ein Plugin-Konflikt vor, wenn folgende Probleme auftreten:

- **Fatale Fehler** - „Es gab einen kritischen Fehler auf Ihrer Website“
- **Leistungsprobleme** - Langsame Ladezeiten, Zeitüberschreitungen oder hohe Serverlast
- **Funktionsprobleme** - Funktionen arbeiten nicht wie erwartet
- **Probleme bei der Datensynchronisierung** - Produkte, Bestellungen oder Kunden werden nicht korrekt synchronisiert
- **Probleme mit Zahlungsgateways** - Fehler beim Checkout oder bei der Zahlungsabwicklung

## Bevor Sie beginnen: Verwenden Sie eine Staging-Website {#before-you-start-use-a-staging-site}

:::warning Wichtig
**Suchen Sie niemals auf Ihrer Live-Website nach der Ursache von Plugin-Konflikten.** Verwenden Sie immer eine Staging-Umgebung, um Ihre Geschäftsabläufe nicht zu stören.
:::

### Was ist eine Staging-Website? {#what-is-a-staging-site}

Eine Staging-Website ist eine exakte Kopie Ihrer Live-Website, auf der Sie Änderungen sicher testen können, ohne Ihre Kunden zu beeinträchtigen. Die meisten modernen Hosting-Anbieter bieten Staging-Umgebungen als Standardfunktion an.

### Wenn Ihr Hosting-Anbieter kein Staging anbietet {#if-your-host-doesnt-offer-staging}

Wenn Ihr Hosting-Anbieter keine Staging-Websites anbietet, **erwägen Sie den Wechsel zu einem Anbieter, der dies tut**. Dies ist heutzutage eine Standardfunktion und für Folgendes unerlässlich:

- Sicheres Testen von Plugins und Themes
- WordPress-Updates
- Fehlersuche
- Entwicklungsarbeiten

**Empfohlene Hosting-Anbieter mit Staging:**
- WP Engine
- SiteGround  
- Kinsta
- Cloudways
- Viele weitere

## Schritt 1: Auf fatale Fehler prüfen {#step-1-check-for-fatal-errors}

Wenn Abstürze oder kritische Fehler auftreten, prüfen Sie zunächst die Fehlerprotokolle:

1. **Prüfen Sie die WCPOS-Protokolle** - Öffnen Sie [**Shop-Zustand → Protokolle**](/1.x/support/logs) in WCPOS und suchen Sie nach Fehlermeldungen
2. **Prüfen Sie die Protokolle für fatale Fehler** - Folgen Sie dem [Leitfaden zur Fehlerbehebung bei kritischen Fehlern](/1.x/support/troubleshooting/critical-error), um detaillierte Fehlermeldungen zu finden
3. **Notieren Sie die Fehlerdetails** - Achten Sie auf Plugin-Namen oder Dateipfade, die in der Fehlermeldung erwähnt werden

Wenn Sie einen fatalen Fehler finden, der ein bestimmtes Plugin erwähnt, ist dieses wahrscheinlich die Ursache. Deaktivieren Sie das Plugin und testen Sie, ob das Problem damit behoben ist.

## Schritt 2: Plugins nach dem Ausschlussverfahren prüfen {#step-2-the-plugin-elimination-method}

Wenn die Protokolle keine fatalen Fehler enthalten oder Sie leistungsbezogene Konflikte identifizieren möchten, gehen Sie systematisch vor:

### 2.1 Ausgangszustand erfassen {#21-create-a-baseline}

1. **Öffnen Sie Ihre Staging-Website**
2. **Testen Sie die problematische Funktion** - Notieren Sie genau, was nicht funktioniert oder langsam ist
3. **Erfassen Sie Leistungsmetriken** - Notieren Sie bei Leistungsproblemen die Ausführungszeiten aus den [Protokollen](/1.x/support/logs)

### 2.2 Alle Plugins deaktivieren (außer den notwendigen) {#22-disable-all-plugins-except-essential-ones}

**Lassen Sie diese Plugins aktiviert:**
- WooCommerce
- WCPOS
- WCPOS Pro (falls vorhanden)

**Deaktivieren Sie alle anderen Plugins:**
1. Gehen Sie zu `WP Admin > Plugins`
2. Wählen Sie alle anderen Plugins aus
3. Wählen Sie im Dropdown-Menü für Mehrfachaktionen „Deaktivieren“
4. Klicken Sie auf „Übernehmen“

### 2.3 Prüfen, ob das Problem noch auftritt {#23-test-the-issue}

1. **Leeren Sie alle Caches** - Wenn Sie Caching-Plugins verwenden, leeren Sie sämtliche Caches
2. **Testen Sie die problematische Funktion** - Funktioniert sie jetzt?
3. **Prüfen Sie die Leistung** - Haben sich die Ausführungszeiten verbessert?

**Wenn das Problem behoben ist:** Es liegt ein Plugin-Konflikt vor. Fahren Sie mit Schritt 2.4 fort.

**Wenn das Problem weiterhin besteht:** Wahrscheinlich liegt kein Plugin-Konflikt vor. Ziehen Sie folgende Ursachen in Betracht:
- Probleme mit Serverressourcen (siehe [Server-Leistung](/1.x/support/performance/server))
- Theme-Konflikte (siehe Schritt 3)
- Probleme im Kern von WordPress oder WooCommerce

### 2.4 Plugins einzeln aktivieren {#24-enable-plugins-one-by-one}

Nun müssen Sie herausfinden, welches Plugin den Konflikt verursacht:

1. **Aktivieren Sie ein Plugin** - Beginnen Sie mit den wichtigsten Plugins
2. **Testen Sie die Funktion** - Prüfen Sie, ob das Problem erneut auftritt
3. **Wenn kein Problem auftritt** - Aktivieren Sie das nächste Plugin und testen Sie erneut
4. **Wenn das Problem erneut auftritt** - Sie haben das konfliktverursachende Plugin gefunden!

**Priorität der Plugins (in dieser Reihenfolge aktivieren):**
1. **Sicherheitsplugins** - Wordfence, Sucuri usw.
2. **SEO-Plugins** - Yoast, RankMath usw.  
3. **Leistungsplugins** - Caching, Optimierung
4. **Zahlungsgateways** - Stripe, PayPal usw.
5. **Andere WooCommerce-Erweiterungen**
6. **Allgemeine WordPress-Plugins**

### 2.5 Ergebnisse dokumentieren {#25-document-your-findings}

Wenn Sie das konfliktverursachende Plugin gefunden haben:

1. **Notieren Sie den Plugin-Namen und die Version**
2. **Dokumentieren Sie das konkrete Problem, das es verursacht**
3. **Prüfen Sie, ob eine aktualisierte Version verfügbar ist**
4. **Suchen Sie nach alternativen Plugins mit ähnlichen Funktionen**

## Schritt 3: Auf Theme-Konflikte prüfen {#step-3-check-for-theme-conflicts}

Themes wirken sich nur selten auf WCPOS aus, da es eine eigene Benutzeroberfläche verwendet. Dennoch können sie gelegentlich Probleme in folgenden Bereichen verursachen:

- Checkout-Prozesse (bei Verwendung eines Web-Checkout-Gateways)
- Funktionen im Adminbereich
- API-Antworten

### Mit einem Standard-Theme testen {#test-with-a-default-theme}

1. Wechseln Sie **auf Ihrer Staging-Website** zu einem Standard-Theme von WordPress:
   - Twenty Twenty-Four
   - Twenty Twenty-Three
   - Twenty Twenty-Two
2. **Testen Sie die problematische Funktion**
3. **Wenn das Problem behoben ist** - Ihr Theme verursacht einen Konflikt

:::info Auswirkungen von Themes
Themes verursachen deutlich seltener Probleme mit WCPOS als Plugins. Die POS-Oberfläche läuft unabhängig von Ihrem Theme. Themes können jedoch folgende Bereiche beeinflussen:
- WooCommerce-Checkout-Seiten
- WordPress-Adminfunktionen
- REST-API-Antworten
:::

## Schritt 4: Plugin-Konflikte beheben {#step-4-resolving-plugin-conflicts}

Sobald Sie das konfliktverursachende Plugin identifiziert haben, stehen Ihnen mehrere Möglichkeiten zur Verfügung:

### Option 1: Plugin aktualisieren {#option-1-update-the-plugin}

1. **Prüfen Sie auf Updates** - In einer neueren Version könnte der Konflikt bereits behoben sein
2. **Aktualisieren Sie das Plugin** zunächst auf Ihrer Staging-Website
3. **Testen Sie gründlich**, bevor Sie das Update auf Ihrer Live-Website installieren

### Option 2: Eine Alternative finden {#option-2-find-an-alternative}

1. **Suchen Sie nach alternativen Plugins**, die dieselben Funktionen bieten
2. **Testen Sie Alternativen** auf Ihrer Staging-Website
3. **Übertragen Sie die Einstellungen**, wenn Sie das Plugin wechseln

### Option 3: Den Plugin-Entwickler kontaktieren {#option-3-contact-plugin-developer}

1. **Melden Sie den Konflikt** dem Plugin-Entwickler
2. **Geben Sie detaillierte Informationen an:**
   - Versionen der beteiligten Plugins
   - WordPress- und WooCommerce-Versionen
   - Genaue Fehlermeldungen oder Beschreibung des Verhaltens
   - Schritte zum Reproduzieren des Problems

### Option 4: Eine individuelle Lösung {#option-4-custom-solution}

Für unverzichtbare Plugins, die nicht ersetzt werden können:

1. **Kontaktieren Sie einen WordPress-Entwickler**, um eine individuelle Lösung erstellen zu lassen
2. **Ziehen Sie pluginspezifische Hooks in Betracht**, um konfliktverursachende Funktionen zu deaktivieren
3. **Verwenden Sie bedingte Logik**, um das Plugin auf POS-bezogenen Seiten zu deaktivieren

## Plugin-Typen, die häufig Konflikte verursachen {#common-conflicting-plugin-types}

### Plugin-Kategorien mit hohem Risiko {#high-risk-plugin-categories}

**Sicherheitsplugins:**
- Können API-Anfragen blockieren
- Können die Authentifizierung beeinträchtigen
- Verwenden häufig strenge Firewall-Regeln

**Caching-Plugins:**
- Können API-Antworten zwischenspeichern, die nicht zwischengespeichert werden sollten
- Können die Verarbeitung von Echtzeitdaten beeinträchtigen
- Können Probleme durch veraltete Daten verursachen

**SEO-Plugins:**
- Ressourcenintensive Plugins können den Adminbereich verlangsamen
- Können unnötige Datenbankabfragen hinzufügen
- Können REST-API-Antworten beeinträchtigen

**Seiten-Builder:**
- Laden häufig ressourcenintensive Skripte im Adminbereich
- Können Konflikte mit WooCommerce-Adminseiten verursachen
- Können Checkout-Prozesse beeinträchtigen

**Mitgliedschafts-/Zugriffsbeschränkungs-Plugins:**
- Können den API-Zugriff blockieren
- Können die Benutzerauthentifizierung beeinträchtigen
- Können den Zugriff auf erforderliche Ressourcen einschränken

### Plugin-Kategorien mit geringerem Risiko {#lower-risk-plugin-categories}

**Kontaktformulare:** Beeinträchtigen WCPOS normalerweise nicht
**Social-Media-Plugins:** Verursachen selten Konflikte
**Analyse-Plugins:** In der Regel unbedenklich, sofern sie nicht sehr ressourcenintensiv sind
**Einfache Inhaltsplugins:** Normalerweise kompatibel
**WooCommerce Tax (automatisierte Steuern über TaxJar):** Wird unterstützt. WCPOS fragt beim Speichern einer offenen POS-Bestellung die Steuersätze ab. Dadurch erhalten POS-Bestellungen dieselben automatisierten Steuersätze wie Onlinebestellungen. Siehe [WooCommerce Tax](/1.x/integrations/woocommerce-tax).

## Bekannte Plugin-Konflikte {#known-plugin-conflicts}

Die folgenden Plugins verursachen bekanntermaßen Probleme mit WCPOS. Viele davon werden in neueren WCPOS-Versionen bereits automatisch behoben — **ein Update auf die neueste Version** löst diese Probleme ohne zusätzliche Konfiguration.

:::tip Meist hilft es, den POS auszunehmen
Die Gemeinsamkeit: WCPOS nutzt die WooCommerce REST API und stellt einige Abläufe (Anmeldung, Zahlung, Belege) in iframes dar. In der Regel hilft es, **die POS-Endpunkte/URLs auszunehmen** (`/wp-json/wcpos/`, `/wp-json/wc/v3/` und den Pfad `/pos/`) — also im anderen Plugin Ausnahmen einzurichten, statt es vollständig zu deaktivieren.
:::

### Sicherheits- und Anmeldeplugins {#security-and-login-plugins}

Diese sind die **häufigste** Ursache für Konflikte, insbesondere bei der Anmeldung in der Desktop- oder Mobil-App.

| Plugin | Symptom | Lösung |
| --- | --- | --- |
| **Wordfence** | Firewall blockiert die REST API; das 2FA-Codefeld wird im Anmelde-iframe nicht angezeigt; restriktive CSP kann POS-Ressourcen blockieren | Geben Sie `/wp-json/wcpos/` und `/wp-json/wc/v3/` in der Firewall frei. Bei 2FA: Deaktivieren Sie diese vorübergehend für POS-Benutzer. CSP wird in v1.9.0+ automatisch entfernt |
| **Really Simple Security** | Blockiert den API-Zugriff / erzwingt Weiterleitungen | Deaktivieren Sie alle REST-API-Einschränkungen in den Einstellungen unter **Erweitert** im Plugin |
| **WPS Hide Login** | Benutzerdefinierte Anmelde-URL stört den Anmelde-iframe der App | Verwenden Sie für den POS-Zugriff die Standard-Anmelde-URL `/wp-admin/` |
| **iThemes / Solid Security** | Blockiert die REST API oder löst durch POS-Aufrufe Brute-Force-Sperren aus | Geben Sie nur die POS-Endpunkte und die eigene IP des Servers frei — vermeiden Sie pauschale IP-Regeln |
| **Sucuri** | WAF blockiert API-Anfragen | Geben Sie die REST-API-Endpunkte im Sucuri-Dashboard frei |
| **Security Optimizer** | Blockiert die POS-Anmeldung als Administrator (_„Benutzerdefinierte Anmelde-URL verwenden“_) | Melden Sie sich zuerst über die benutzerdefinierte URL bei WP Admin an und öffnen Sie dann `/pos` |
| **Force Login** (und ähnliche Plugins zur REST-Authentifizierung) | `/wp-json/` gibt 401/403 zurück; ältere Apps meldeten _„Die Website scheint keine WordPress-Website zu sein“_ | Erlauben Sie den Zugriff auf die POS-Endpunkte ohne Authentifizierung oder deaktivieren Sie das Plugin beim ersten Verbindungsaufbau. Apps der Version v1.x zeigen nun die tatsächliche Fehlermeldung an |
| **LoginPress** | Erzwingt die Anmeldung per E-Mail; stört die POS-Anmeldung mit mehreren Benutzern | Erlauben Sie die Anmeldung per Benutzername oder deaktivieren Sie das Plugin für den POS-Zugriff |
| **JWT Authentication-Plugins** | 403 bei allen POS-API-Anfragen nach der Aktivierung (Anmeldung kann gelingen, alles Weitere schlägt fehl) | In v1.8.x+ automatisch behoben. Deaktivieren Sie bei älteren Versionen das JWT-Plugin oder nehmen Sie die POS-Endpunkte aus |
| **Captcha / reCAPTCHA** | Anmeldeschleife in der Desktop-App (Captcha kann im iframe nicht angezeigt werden) | Deaktivieren Sie Captcha für die POS-Anmelde-URL |
| **Defender Pro** | Der Header `X-Frame-Options` blockiert alle POS-iframes (Anmeldung, Zahlung, Belege) | Fügen Sie eine POS-spezifische Ausnahme für `/pos/` hinzu, statt `X-Frame-Options` auf der gesamten Website zu deaktivieren |
| **Jetpack CRM Client Portal** | Verhindert die POS-Anmeldung vollständig | Deaktivieren Sie nur die Erweiterung Client Portal |

### Leistungs-, Caching- und Optimierungsplugins {#performance-caching-optimisation-plugins}

| Plugin | Symptom | Lösung |
| --- | --- | --- |
| **WP Rocket, Autoptimize, Hummingbird, Smush** | Verzögertes Laden oder Minifizieren von JS stört den Checkout und Stripe Terminal | Nehmen Sie `/pos/`-URLs von der JS-Optimierung aus |
| **LiteSpeed Cache** | Ständige Neuladeschleife beim Checkout in der Desktop-App; restriktive CSP | Aktualisieren Sie WCPOS, leeren Sie den Cache und nehmen Sie POS-Seiten vom Caching aus. CSP wird in v1.9.0+ automatisch entfernt |
| **Image Prioritizer** | Überfrachtet den HTTP-Header `Link` und stört damit die REST-API-Erkennung; die Desktop-App zeigt _„scheint keine WordPress-Website zu sein“_ | Deaktivieren Sie das Plugin |

### Seiten-Builder und Plugins, die Inhalte ins Frontend einfügen {#page-builders-front-end-injectors}

| Plugin | Symptom | Lösung |
| --- | --- | --- |
| **Elementor** | `elementor-frontend.js` stört das Checkout-Akkordeon im POS-iframe — Zahlungsmethoden lassen sich nicht aufklappen | Nehmen Sie POS-Seiten vom Laden der Elementor-Skripte aus |
| **Omnisend / Marketing-Plugins** | Fügen Skripte in den Checkout-iframe ein und stören dadurch Layout und Zahlungen | Deaktivieren Sie nicht benötigte Skripte über die **Checkout-Einstellungen** des POS |
| **MyStickyElements / Complianz** | Fügen Overlays (schwebende Schaltflächen, Cookie-Banner) in den Checkout-iframe ein | Konfigurieren Sie die Plugins so, dass sie `/pos/`-URLs ausnehmen |

### WooCommerce-Erweiterungen und andere Plugins {#woocommerce-extensions-other-plugins}

| Plugin | Symptom | Lösung |
| --- | --- | --- |
| **WooCommerce Subscriptions** | Konflikt mit dem Migrationsskript beim Upgrade von v1.7→v1.8 | Deaktivieren Sie Subscriptions, aktivieren Sie WCPOS Pro (lassen Sie die Migration durchlaufen) und aktivieren Sie Subscriptions anschließend wieder |
| **WP Activity Log** | Protokolliert jede POS-Aktion → starkes Anwachsen von postmeta → _„nur 10 Produkte“_ | Deaktivieren Sie das Plugin oder nehmen Sie POS-Beitragstypen von der Protokollierung aus |
| **Jetpack / Astra / Xero** (alles, was sich in `save_post` einhängt) | Doppelte Metadatenzeilen bei jedem POS-API-Aufruf (ein Shop erreichte 36,867 Zeilen für ein einziges Produkt) | In v1.8.12+ (kostenlos) / v1.8.14+ (Pro) durch eine Bereinigungsmigration automatisch behoben — einfach aktualisieren |
| **Stripe Tax** | Nicht mit Bestellungen kompatibel, die über die REST API erstellt werden (so erstellt der POS Bestellungen) | Keine Umgehungslösung — inkompatibel. [WooCommerce Tax](/1.x/integrations/woocommerce-tax) ist die unterstützte Option für automatisierte Steuern |
| **Mollie** | Kann die Zahlungsmethode BACS (Banküberweisung) im POS-Checkout ausblenden | Aktualisieren Sie Mollie auf die neueste Version |
| **CTX Feed** | Sporadische 403-Fehler auf der POS-Einstellungsseite | Deaktivieren Sie das Plugin zur Überprüfung; keine bekannte Umgehungslösung |
| **Barcode-Scanner-Plugins von Drittanbietern** | Beschädigen die JSON-Daten der Bestell-API und verhindern dadurch die Erstellung oder Anzeige von Bestellungen | Deaktivieren Sie diese Plugins und verwenden Sie die integrierte Barcode-Scanfunktion des POS |
| **MailerLite** (Signup Forms + WooCommerce) | 500-Fehler beim Erstellen einer POS-Bestellung (Speicher erschöpft) | Deaktivieren Sie das Plugin zur Überprüfung und kontaktieren Sie anschließend MailerLite |
| **The Courier Guy Shipping** | Erstellen einer POS-Bestellung schlägt mit einem Serverfehler fehl | Kehren Sie zu einer früheren Version zurück oder kontaktieren Sie den Entwickler |
| **PixelYourSite / PixelMySite** | Fataler Fehler: _Aufruf der Memberfunktion `is_type()` auf einem bool-Wert_ | Vorübergehend deaktivieren |
| **Google Listings & Ads** | Autoloader-Konflikt → kritischer Fehler _„Klasse WCPOS\…\Stores nicht gefunden“_ | Löschen Sie alle POS-Plugins und installieren Sie nur die neueste eigenständige Pro-Version neu |

:::warning Stripe Terminal: nicht global aktivieren
Das Zahlungsgateway **Stripe Terminal** sollte **nur** in den POS-Einstellungen aktiviert werden, niemals unter `WooCommerce > Einstellungen > Zahlungen`. Bei globaler Aktivierung erscheint es im Checkout Ihres öffentlichen Shops und bringt den Online-Checkout zum Absturz.
:::

### Konflikte auf Serverebene {#server-level-conflicts}

| Quelle | Symptom | Lösung |
| --- | --- | --- |
| **Benutzerdefinierte CSP-Header** (`.htaccess`, Nginx oder ein Sicherheitsplugin) | POS bleibt beim Logo hängen; JS/CSS blockiert | Auf POS-Seiten in v1.9.0+ automatisch entfernt. Erlauben Sie bei CSP auf Serverebene `cdn.jsdelivr.net` in `script-src`/`style-src` oder fügen Sie eine Ausnahme für `/pos/` hinzu |
| **GoDaddy Website Firewall** | Blockiert `/wp-json/` (_„'undefined' erhalten“_) | Geben Sie den URL-Pfad `/wp-json/` in der Firewall frei — siehe [Server-Leistung](/1.x/support/performance/server#hosting-specific-notes) |

## Tipps zur Vorbeugung {#prevention-tips}

### Regelmäßige Wartung {#regular-maintenance}

1. **Halten Sie Plugins aktuell** - Verwenden Sie immer die neuesten Versionen
2. **Entfernen Sie ungenutzte Plugins** - Deaktivieren Sie sie nicht nur, sondern löschen Sie sie
3. **Testen Sie Updates auf der Staging-Website**, bevor Sie sie auf der Live-Website installieren
4. **Überwachen Sie die Leistung** regelmäßig anhand der Metriken zur [Server-Leistung](/1.x/support/performance/server)

### Bewährte Vorgehensweisen bei der Plugin-Auswahl {#plugin-selection-best-practices}

1. **Wählen Sie seriöse Entwickler** - Prüfen Sie Bewertungen und die Häufigkeit von Updates
2. **Vermeiden Sie doppelte Funktionen** - Installieren Sie nicht mehrere Plugins, die dasselbe tun
3. **Lesen Sie die Kompatibilitätsinformationen** - Prüfen Sie, ob die Plugins mit WooCommerce getestet wurden
4. **Beginnen Sie mit möglichst wenigen Plugins** - Ergänzen Sie Funktionen schrittweise nach Bedarf
