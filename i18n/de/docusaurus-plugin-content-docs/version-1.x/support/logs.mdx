Der POS verfügt über zwei Protokolloberflächen: das **In-App-Aktivitätsprotokoll** (innerhalb der POS-Anwendung) und die **WP-Admin-Protokollseite** (innerhalb von WordPress). Zusammen geben sie Ihnen einen vollständigen Überblick über die POS-Aktivitäten zur Fehlersuche und Nachprüfung.

## POS-Anwendungsprotokolle {#pos-application-logs}

:::info Geändert in v1.10.0
Ab v1.10.0 befindet sich das In-App-Protokoll unter **Shop-Zustand → Protokolle** (das Herzschlagsymbol im Navigationsmenü — die bisherige eigenständige Protokollansicht wurde entfernt). Dieser Abschnitt beschreibt das Protokoll in v1.10.0. Einen vollständigen Rundgang durch diesen Bereich finden Sie unter [Shop-Zustand](/1.x/support/store-health#logs).
:::

### Zugriff auf Protokolle {#accessing-logs}

Öffnen Sie **Shop-Zustand** über das linke Navigationsmenü (das Herzschlagsymbol) und wählen Sie den Tab **Protokolle**.

### Übersicht der Benutzeroberfläche {#interface-overview}

Das Protokoll verzeichnet die Aktivitäten auf diesem Gerät und bewahrt sie 30 Tage lang auf. Jede Zeile zeigt:

| Spalte | Beschreibung |
|--------|-------------|
| **Zeit** | Wann das Ereignis aufgetreten ist |
| **Ebene** | Schweregrad — Fehler, Warnung, Aktion, Sync oder Info |
| **Ereignis** | Verständliche Beschreibung (wird bei der Anzeige übersetzt) |
| **Dauer** | Wie lange der Vorgang gedauert hat |
| **Status** | Das Ergebnis |

Über dem Protokoll zeigt eine Statuszeile den Sync-Takt an — wann zuletzt auf Änderungen geprüft wurde und wann die nächste Prüfung ansteht. Eine Kopfzeile mit Kennzahlen zählt die heutigen Ereignisse und Fehler, feststeckende Datensätze sowie Änderungen, die noch gesendet werden müssen. Die meisten dieser Anzeigen lassen sich antippen, um das Protokoll zu filtern.

#### Filtern {#filtering}

Vordefinierte Filterchips filtern das Protokoll: **Alle**, **Aktionen** (von einer Person ausgeführte Vorgänge — Verkäufe, Bearbeitungen, Einstellungsänderungen), **Fehler** und **Sync**. Ein separater Schalter **Ausführliche Diagnose** erfasst 24 Stunden lang zusätzliche Details und schaltet sich danach automatisch ab.

### Zeilendetails und Fehlercodes {#row-details}

Tippen Sie auf eine Fehler- oder Warnungszeile, um sie aufzuklappen. Die Detailansicht bietet Ihnen:

- **Was passiert ist**, in verständlicher Sprache
- **Ihre Daten** — eine ausdrückliche Aussage zur Datensicherheit (zum Beispiel, ob die Änderung sicher auf dem Server gespeichert ist oder nur auf diesem Gerät existiert)
- **Was zu tun ist** — der empfohlene nächste Schritt
- **Ein Hilfelink** — Fehler haben einen Code (z. B. `SYNC121`, `AUTH311`), der zur Dokumentation der [Fehlercodes](/1.x/error-codes) verlinkt
- **Ein kopierbarer Ereigniscode** — Zeilentitel werden bei der Anzeige übersetzt; der Ereigniscode bleibt dagegen als Kennung unverändert. Geben Sie ihn an, wenn Sie sich an den Support wenden.

## WP-Admin-Protokollseite {#wp-admin-logs-page}

Das POS-Plugin bietet außerdem eine serverseitige Protokollseite im WordPress-Admin-Bereich. Sie zeigt POS-spezifische Warnungen und Fehler, die auf dem Server protokolliert wurden. Dies hilft bei der Diagnose von Problemen, die möglicherweise nicht in der POS-Anwendung selbst sichtbar sind.

### Zugriff auf die WP-Admin-Protokollseite {#accessing-the-wp-admin-logs-page}

Gehen Sie zu **WP Admin > POS > Einstellungen**, wählen Sie dann den Tab **Werkzeuge** und klicken Sie auf **Protokolle**.

### Kennzeichnung ungelesener Einträge {#unread-badge}

Der Menüpunkt Protokolle zeigt eine Kennzeichnung für ungelesene Protokolleinträge:

- **Rote Kennzeichnung** - Es gibt ungelesene Fehlereinträge
- **Bernsteinfarbene Kennzeichnung** - Es gibt ungelesene Warnungen (aber keine Fehler)

Beim Öffnen der Protokollseite werden die Zähler für ungelesene Einträge zurückgesetzt. Die Zähler werden pro Benutzer geführt, sodass jeder Administrator seinen eigenen Ungelesen-Status sieht.

### Einträge filtern {#filtering-entries}

Verwenden Sie den Ebenenfilter, um die angezeigten Protokolleinträge einzugrenzen:

- **Alle** - Alle Protokolleinträge anzeigen
- **Fehler** - Nur Fehlereinträge anzeigen
- **Warnungen** - Nur Warnungen anzeigen

### Aufklappbare Einträge {#expandable-entries}

Lange Protokollmeldungen werden nach etwa 100 Zeichen gekürzt. Klicken Sie auf einen Eintrag, um ihn aufzuklappen und die vollständige Meldung zusammen mit zusätzlichen Kontextdaten anzuzeigen.

### Seitennavigation {#pagination}

Protokolleinträge werden serverseitig auf Seiten verteilt. Verwenden Sie die Seitennavigation, um ältere Einträge anzuzeigen.

### Banner für schwerwiegende Fehler {#fatal-errors-banner}

Wenn auf dem Server `fatal-errors-*.log`-Dateien vorhanden sind, zeigt die Protokollseite oben ein Warnbanner an. Dieses Banner verlinkt auf **WooCommerce > Status > Protokolle**, wo Sie die vollständigen Protokolle der schwerwiegenden Fehler einsehen können. Dabei handelt es sich meist um Abstürze auf PHP-Ebene, die verhindern, dass die POS-API antwortet.

## Protokolle für den Support verwenden {#using-logs-for-support}

Bei einer Supportanfrage:

1. **Reproduzieren Sie das Problem** - Führen Sie die Aktion aus, die das Problem verursacht
2. **Überprüfen Sie die Protokolle** - Suchen Sie unter **Shop-Zustand → Protokolle** nach Fehlern oder Warnungen
3. **Klappen Sie die Zeile auf** - Lesen Sie den Hinweis zur Datensicherheit und den vorgeschlagenen nächsten Schritt
4. **Kopieren Sie den Ereigniscode** - Fügen Sie ihn Ihrer Supportanfrage hinzu; er identifiziert das Ereignis eindeutig
5. **Schalten Sie die Ausführliche Diagnose ein**, wenn der Support weitere Details benötigt — sie erfasst 24 Stunden lang zusätzliche Informationen

## Leistungsüberwachung {#performance-monitoring}

Die zusammengefassten Leistungsdaten finden Sie unter **Shop-Zustand → Leistung**: Anfragen, übertragene Datenmenge (ein Mindestwert, wenn Antworten keine Größenangabe enthalten) und typische Antwortzeit der letzten 24 Stunden sowie eine stündliche Verfügbarkeitsanzeige. Wenn die Antwortzeiten hoch erscheinen, lesen Sie [Server-Leistung](/1.x/support/performance/server).
