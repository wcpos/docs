Das POS verfügt über zwei Protokolloberflächen: das **In-App-Aktivitätsprotokoll** (innerhalb der POS-Anwendung) und die **WP-Admin-Protokollseite** (innerhalb von WordPress). Zusammen liefern sie Ihnen ein vollständiges Bild der POS-Aktivität für Debugging und Auditing.

## POS-Anwendungsprotokolle {#pos-application-logs}

:::info Geändert in v1.10.0
Ab v1.10.0 befindet sich das In-App-Protokoll unter **Shop-Zustand → Protokolle** (das Herzschlagsymbol im Navigationsmenü — der eigenständige Protokollbildschirm, den es ersetzt, wurde entfernt). Dieser Abschnitt beschreibt das Protokoll ab v1.10.0; eine vollständige Führung durch diesen Bereich finden Sie unter [Shop-Zustand](/support/store-health#logs).
:::

### Zugriff auf Protokolle {#accessing-logs}

Öffnen Sie **Shop-Zustand** über das linke Navigationsmenü (das Herzschlagsymbol) und wählen Sie den Tab **Protokolle**.

### Übersicht der Benutzeroberfläche {#interface-overview}

Das Protokoll ist ein Verzeichnis der Aktivität auf diesem Gerät und wird 30 Tage lang aufbewahrt. Jede Zeile zeigt:

| Spalte | Beschreibung |
|--------|-------------|
| **Zeit** | Wann das Ereignis aufgetreten ist |
| **Ebene** | Schweregrad — Fehler, Warnung, Aktion, Sync oder Info |
| **Ereignis** | Verständliche Beschreibung (wird bei der Anzeige übersetzt) |
| **Dauer** | Wie lange der Vorgang gedauert hat |
| **Status** | Das Ergebnis |

Über dem Verzeichnis zeigt eine Statuszeile den Sync-Herzschlag — wann die letzte Änderungsprüfung lief und wann die nächste ansteht — und eine Kopfzeile mit Kennzahlen zählt die heutigen Ereignisse und Fehler, feststeckende Datensätze sowie Änderungen, die auf den Versand warten. Die meisten davon sind antippbare Filter.

#### Filtern {#filtering}

Vordefinierte Chips filtern das Verzeichnis: **Alle**, **Aktionen** (was eine Person getan hat — Verkäufe, Bearbeitungen, Einstellungsänderungen), **Fehler** und **Sync**. Ein separater Schalter **Ausführliche Diagnose** erfasst 24 Stunden lang zusätzliche Details und schaltet sich danach automatisch selbst ab.

### Zeilendetails und Fehlercodes {#row-details}

Tippen Sie auf eine Fehler- oder Warnungszeile, um sie aufzuklappen. Die Detailansicht bietet Ihnen:

- **Was passiert ist**, in verständlicher Sprache
- **Ihre Daten** — eine ausdrückliche Aussage zur Datensicherheit (zum Beispiel, ob die Änderung sicher auf dem Server liegt oder nur auf diesem Gerät existiert)
- **Was zu tun ist** — der empfohlene nächste Schritt
- **Ein Hilfelink** — Fehler tragen einen Code (z. B. `SYNC121`, `AUTH311`), der zur Dokumentation der [Fehlercodes](/error-codes) verlinkt
- **Ein kopierbarer Ereigniscode** — Zeilentitel werden bei der Anzeige übersetzt, daher ist der Ereigniscode die stabile Kennung. Nennen Sie ihn, wenn Sie sich an den Support wenden.

## WP-Admin-Protokollseite {#wp-admin-logs-page}

Das POS-Plugin bietet außerdem eine serverseitige Protokollseite im WordPress-Admin-Bereich. Diese Seite zeigt POS-spezifische Warnungen und Fehler, die auf dem Server protokolliert werden, was bei der Diagnose von Problemen helfen kann, die möglicherweise nicht in der POS-Anwendung selbst erscheinen.

### Zugriff auf die WP-Admin-Protokollseite {#accessing-the-wp-admin-logs-page}

Navigieren Sie zu **WP Admin > POS > Settings**, wählen Sie dann den Tab **Tools** und klicken Sie auf **Logs**.

### Ungelesen-Abzeichen {#unread-badge}

Der Protokoll-Menüpunkt zeigt ein Abzeichen, das ungelesene Protokolleinträge anzeigt:

- **Rotes Abzeichen** - Es gibt ungelesene Einträge auf Fehlerebene
- **Bernsteinfarbenes Abzeichen** - Es gibt ungelesene Einträge auf Warnungsebene (aber keine Fehler)

Der Besuch der Protokollseite setzt die Ungelesen-Zähler zurück. Die Zähler werden pro Benutzer verfolgt, sodass jeder Administrator seinen eigenen Ungelesen-Status sieht.

### Einträge filtern {#filtering-entries}

Verwenden Sie den Ebenenfilter, um Protokolleinträge einzugrenzen:

- **Alle** - Alle Protokolleinträge anzeigen
- **Fehler** - Nur Einträge auf Fehlerebene anzeigen
- **Warnungen** - Nur Einträge auf Warnungsebene anzeigen

### Erweiterbare Einträge {#expandable-entries}

Lange Protokollnachrichten werden bei etwa 100 Zeichen abgeschnitten. Klicken Sie auf einen Eintrag, um ihn zu erweitern und die vollständige Nachricht zusammen mit allen zusätzlichen Kontextdaten anzuzeigen.

### Paginierung {#pagination}

Protokolleinträge werden serverseitig paginiert. Verwenden Sie die Paginierungssteuerung, um durch ältere Einträge zu navigieren.

### Banner für fatale Fehler {#fatal-errors-banner}

Wenn der Server `fatal-errors-*.log`-Dateien hat, zeigt die Protokollseite oben ein Warnbanner an. Dieses Banner verlinkt zu **WooCommerce > Status > Logs**, wo Sie die vollständigen Fatale-Fehler-Protokolle einsehen können. Fatale Fehler sind in der Regel Abstürze auf PHP-Ebene, die verhindern, dass die POS-API antwortet.

## Protokolle für den Support verwenden {#using-logs-for-support}

Bei einer Supportanfrage:

1. **Reproduzieren Sie das Problem** - Führen Sie die Aktion aus, die das Problem verursacht
2. **Überprüfen Sie die Protokolle** - Suchen Sie unter **Shop-Zustand → Protokolle** nach Fehlern oder Warnungen
3. **Klappen Sie die Zeile auf** - Lesen Sie die Zeile zur Datensicherheit und den vorgeschlagenen nächsten Schritt
4. **Kopieren Sie den Ereigniscode** - Fügen Sie ihn in Ihre Supportanfrage ein; er ist die stabile Kennung für das Geschehene
5. **Schalten Sie die Ausführliche Diagnose ein**, wenn der Support mehr Details benötigt — sie erfasst 24 Stunden lang zusätzliche Informationen

## Leistungsüberwachung {#performance-monitoring}

Die Gesamtleistung finden Sie unter **Shop-Zustand → Leistung**: Anfragen, übertragene Datenmenge (eine Untergrenze, wenn Antworten ihre Größe nicht angeben) und typische Antwortzeit der letzten 24 Stunden sowie ein stündlicher Verfügbarkeitsstreifen. Wenn die Antwortzeiten hoch erscheinen, lesen Sie [Server-Leistung](/support/performance/server).
