**Symptom:** Der Drucker taucht beim Suchlauf auf, aber das Drucken scheitert mit einem Zugriffs- oder Berechtigungsfehler.

## Warum das passiert {#why-it-happens}

Unter Linux gehört ein USB-Gerät `root`, sofern keine Regel etwas anderes sagt, deshalb kann eine App, die unter Ihrem Benutzer läuft, es nicht öffnen. Möglicherweise hat auch der Druckertreiber des Kernels das Gerät bereits belegt.

## So gehen Sie vor {#do-this}

1. Ermitteln Sie die Hersteller- und Produkt-ID des Druckers:

   ```bash
   lsusb
   ```

   Suchen Sie die Zeile Ihres Druckers — die IDs sind die beiden vierstelligen Werte nach `ID`, zum Beispiel `04b8:0e28`.

2. Legen Sie eine Regeldatei an und ersetzen Sie die IDs durch Ihre:

   ```bash
   sudo tee /etc/udev/rules.d/99-receipt-printer.rules <<'RULE'
   SUBSYSTEM=="usb", ATTRS{idVendor}=="04b8", ATTRS{idProduct}=="0e28", MODE="0666"
   RULE
   ```

3. Laden Sie die Regeln neu und wenden Sie sie erneut an:

   ```bash
   sudo udevadm control --reload-rules && sudo udevadm trigger
   ```

4. Ziehen Sie den Drucker ab, stecken Sie ihn wieder an und starten Sie die App neu. Drucken Sie eine Testseite.

Führen Sie die App als Ihr normaler Benutzer aus, nicht mit `sudo` — eine Regel, die nur für root wirkt, verfehlt ihren Zweck.

## Immer noch nicht gelöst? {#still-stuck}

Nutzen Sie **Einrichtungsbericht kopieren** auf dem Problembildschirm und fügen Sie ihn zusammen mit der `lsusb`-Zeile Ihres Druckers in Ihre Nachricht ein.
