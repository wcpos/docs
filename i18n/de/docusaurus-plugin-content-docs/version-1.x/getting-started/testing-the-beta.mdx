WCPOS 2.0 befindet sich in der öffentlichen Beta, für Browser-Kassen und die Desktop-App. Die Apps für Android und iOS erscheinen, sobald die Beta-Tests abgeschlossen sind; verwenden Sie Smartphones und Tablets daher bis dahin nur mit einem Shop unter 1.11. Die Beta ist zum Testen auf einer Staging-Kopie Ihres Shops gedacht oder in einem Shop, bei dem Sie sich eine Unterbrechung leisten können; sie ist nicht die finale Version, und WordPress.org bietet weiterhin 1.11 an. Auf dieser Seite finden Sie alles, was Sie als Tester benötigen.

## Was Sie benötigen {#what-you-need}

- **WooCommerce 9.0 oder neuer.** Bei älteren Versionen hält 2.0 mit einem Hinweis an.
- **App und Plugin müssen beide auf 2.0 sein.** Eine 2.0-App funktioniert nicht mit einem 1.11-Plugin, und eine 1.11-App fordert ein Update an, sobald sie auf ein 2.0-Plugin trifft. Aktualisieren Sie zuerst das Plugin, dann jede Kasse.
- **Kein Magnetstreifen-Kartenleser.** 2.0 entfernt den experimentellen Leser. Kartenlesegeräte an der Kasse laufen über Stripe Terminal oder SumUp mit WCPOS Pro.
- **Terminal-Erweiterungen benötigen WCPOS Pro 2.0.** Jede Kartenterminal-Erweiterung hat eine Beta-Vorabversion auf GitHub; installieren Sie sie nach Pro manuell: [Stripe Terminal](https://github.com/wcpos/stripe-terminal-for-woocommerce/releases/tag/v2.0.0-beta1), [SumUp](https://github.com/wcpos/sumup-terminal-for-woocommerce/releases/tag/v2.0.0-beta1), [Mollie](https://github.com/wcpos/mollie-terminal-for-woocommerce/releases/tag/v2.0.0-beta1), [Square](https://github.com/wcpos/square-terminal-for-woocommerce/releases/tag/v1.0.0-beta1), [PayArc](https://github.com/wcpos/payarc-terminal-for-woocommerce/releases/tag/v1.0.0-beta1), [Windcave](https://github.com/wcpos/windcave-terminal-for-woocommerce/releases/tag/v1.0.0-beta1) und [Mercado Pago](https://github.com/wcpos/mercadopago-terminal-for-woocommerce/releases/tag/v1.0.0-beta1). Die aktuellen stabilen Versionen dieser Erweiterungen sind für 1.11.

## Vor der Installation {#before-you-install}

1. **Synchronisieren Sie jede Kasse vor dem Upgrade.** 2.0 legt auf jeder Kasse eine neue lokale Datenbank an und übernimmt keine Verkäufe, die eine 1.11-Kasse noch nicht an die Filiale gesendet hat. Öffnen Sie jede Kasse unter 1.11, warten Sie, bis die Synchronisierung abgeschlossen ist, und aktualisieren Sie erst dann das Plugin. Ein Verkauf, der auf einer 1.11-Kasse noch nicht gesendet wurde, geht nach dem Upgrade verloren.
2. **Erstellen Sie eine Sicherung der Website** oder bitten Sie Ihren Hoster um einen Wiederherstellungspunkt.
3. **Wählen Sie eine ruhige Stunde.** Beim ersten Öffnen wird jede Kasse in die neue Kassenoberfläche geladen. Ein Verkauf, der sich unter 1.11 mitten im Bezahlvorgang befindet, muss erneut erfasst werden.
4. Lesen Sie die [Versionshinweise der App](https://github.com/wcpos/monorepo/releases/tag/v2.0.0-beta.2), um zu erfahren, was sich ändert: Kasse, Bezahlvorgang und Kassenschublade sind neu, jeder Bildschirm wurde neu gestaltet und Rabatte über negative Gebühren werden durch „Rabatt hinzufügen“ ersetzt.

## Die Beta erhalten {#get-the-beta}

**Plugin (kostenlos):** Laden Sie `woocommerce-pos.zip` aus dem [Release WCPOS 2.0.0 Beta 2](https://github.com/wcpos/woocommerce-pos/releases/tag/v2.0.0-beta.2) herunter und installieren Sie es über **WP Admin → Plugins → Plugin hinzufügen → Plugin hochladen**, wobei die aktuelle Version ersetzt wird. Browser-Kassen übernehmen 2.0, sobald das Plugin aktiv ist.

**Plugin (Pro):** Melden Sie sich unter [wcpos.com/account/downloads](https://wcpos.com/account/downloads) an, laden Sie `woocommerce-pos-pro.zip` von der Karte **WCPOS Pro 2.0 Beta** herunter (eine aktive Lizenz ist erforderlich) und laden Sie es auf die gleiche Weise hoch. Pro enthält das kostenlose Plugin; Sie installieren nicht beide.

**Desktop-App:** Das [Release WCPOS Desktop 2.0.0 Beta 2](https://github.com/wcpos/electron/releases/tag/v2.0.0-beta.2) enthält die Installationsprogramme für macOS, Windows und Linux. Der Beta-Build aktualisiert sich nicht selbst; spätere Betas müssen von derselben Release-Seite neu heruntergeladen werden.

**iPhone, iPad und Android:** nicht in dieser Beta. Die 2.0-Apps für die App-Stores erscheinen, sobald die Beta-Tests abgeschlossen sind; eine 1.11-App bleibt bei einem Update-Hinweis stehen, wenn sie auf einen Shop unter 2.0 trifft. Verwenden Sie Smartphones und Tablets daher bis dahin nur mit einem Shop unter 1.11.

Die Versionshinweise der App für die Beta finden Sie im [App-Release](https://github.com/wcpos/monorepo/releases/tag/v2.0.0-beta.2); die Änderungen am Plugin stehen in den Versionshinweisen des jeweiligen Plugin-Releases.

## Zurück zu 1.11 wechseln {#rolling-back}

Sagen Sie uns zuerst auf [Discord](https://wcpos.com/discord) Bescheid; für die meisten Probleme am Beta-Tag gibt es eine schnellere Lösung als ein Rollback.

1. **Synchronisieren Sie jede Kasse vor dem Rollback.** Alles, was eine 2.0-Kasse noch nicht gesendet hat, bleibt in der lokalen 2.0-Datenbank, die die 1.11-App nie öffnet.
2. Installieren Sie das 1.11-Plugin erneut: die kostenlose Version von [WordPress.org](https://wordpress.org/plugins/woocommerce-pos/) oder über [Frühere Versionen](/getting-started/previous-versions), Pro von [wcpos.com/account/downloads](https://wcpos.com/account/downloads) (die neueste 1.11-Version in der Liste).
3. Installieren Sie die 1.11-Desktop-App überall dort erneut, wo Sie die Beta installiert haben. Eine 2.0-App kann keine Verbindung zu einem 1.11-Plugin herstellen.
4. Die 1.11-Kasse startet mit einer leeren lokalen Datenbank und synchronisiert sich erneut mit dem Shop. Unter 2.0 erstellte Bestellungen sind normale WooCommerce-Bestellungen und bleiben, wo sie sind; unter 2.0 erfasste Kassensitzungen und Kassenabschlüsse bleiben in der Datenbank, werden von 1.11 aber nicht angezeigt.

## Ihre Beobachtungen melden {#reporting}

Erstellen Sie ein Issue in [wcpos/roadmap](https://github.com/wcpos/roadmap/issues/new) mit dem Label `beta` oder schreiben Sie an den [Support](https://wcpos.com/support). Geben Sie an, welcher Teil betroffen ist (Plugin, Desktop, iOS, Android, Browser), die Version, was Sie getan haben, was Sie erwartet haben und was passiert ist; ein Screenshot oder der Fehlercode vom Bildschirm hilft. Geben Sie bei einem Problem mit einem Verkauf oder einer Zahlung die Bestellnummer an.
