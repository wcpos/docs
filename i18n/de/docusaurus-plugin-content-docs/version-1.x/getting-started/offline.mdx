WCPOS speichert Produkt- und Kundendaten in einer lokalen Datenbank auf jedem Gerät. Das bedeutet, dass Teile des POS auch ohne Internetverbindung funktionieren, während andere eine Verbindung erfordern.

## Was offline funktioniert {#what-works-offline}

- **Produkte durchsuchen** — Produkte aus lokalen Daten suchen, filtern und Produktdetails anzeigen
- **Kunden durchsuchen** — Kundennamen, E-Mail-Adressen und Anschriften nachschlagen
- **Warenkorb zusammenstellen** — Artikel hinzufügen, Mengen ändern, Preise bearbeiten und POS-Rabatte anwenden
- **Gutscheine einlösen** (Pro) — Codes werden lokal anhand der synchronisierten Gutscheindaten validiert; der Server validiert erneut, sobald die in die Warteschlange gestellte Bestellung bei ihm ankommt
- **Bestellung speichern** — halten oder speichern Sie eine Bestellung auf dem Gerät; sie wird in die ausgehende Warteschlange aufgenommen und an WooCommerce übermittelt, sobald die Verbindung wiederhergestellt ist.
- **Barcode-Scannen** — Barcodes scannen, um Produkte in der lokalen Datenbank zu finden
- **Berichte anzeigen** — der Standard-Berichtstyp (offline) erstellt Berichte aus lokal gespeicherten Bestellungen

## Was eine Verbindung erfordert {#what-requires-a-connection}

- **Zahlung entgegennehmen** — beim Abschließen des Checkouts wird eine von Ihrem Server gehostete Zahlungsseite angezeigt. Daher kann der Zahlungsschritt selbst nicht offline abgeschlossen werden. Sie können die Bestellung offline weiterhin erstellen und **speichern** und die Zahlung entgegennehmen, sobald Sie wieder online sind.
- **Serverabhängige Checkout-Aktionen** — Web-Checkout, integrierte Online- oder Terminal-Gateways sowie **Auf Server speichern** benötigen jeweils erreichbare Dienste
- **Daten synchronisieren** — neue Produkte, aktualisierte Preise oder neue Kunden aus WooCommerce abrufen
- **Anmeldung** — die erstmalige Authentifizierung erfordert eine Verbindung zu Ihrer WordPress-Website
- **Lizenzaktivierung** — Pro-Lizenzprüfungen müssen den WCPOS-Lizenzserver erreichen können
- **Rückerstattungen verarbeiten** — Rückerstattungen können nicht offline in die Warteschlange gestellt werden; das Zahlungsgateway und Ihr Shop müssen erreichbar sein (siehe [Rückerstattungen](/orders/refunds))

:::note Für den Abschluss eines Verkaufs ist eine Verbindung erforderlich
Sie können eine Bestellung offline erstellen und **speichern**, aber für den Zahlungsschritt ist eine Verbindung erforderlich. Die Möglichkeit, einen Verkauf offline *abzuschließen* — zunächst mit Bargeld —, steht auf der [Roadmap](/getting-started/roadmap).
:::

## Funktionsweise der lokalen Datenbank {#how-the-local-database-works}

Beim ersten Öffnen von WCPOS wird Ihr Produktkatalog im Hintergrund grundbefüllt; weitere Daten werden im Laufe der Nutzung nachgeholt — Sie können verkaufen, sobald die ersten Produkte auf dem Gerät sind. Danach holt eine Änderungsprüfung im Hintergrund (standardmäßig alle 60 Sekunden, einstellbar unter [Shop-Zustand](/support/store-health)) nur noch das, was sich auf dem Server geändert hat.

Die lokale Datenbank:

- **Bleibt zwischen Sitzungen erhalten** — Daten überdauern Browser-Neustarts und Geräte-Neustarts
- **Ist gerätebezogen (und kassiererbezogen)** — jedes Gerät führt seine eigene lokale Kopie; Kassierer teilen sich keine lokalen Daten
- **Bleibt synchron** — Änderungsprüfungen im Hintergrund holen Aktualisierungen; Ihre eigenen Änderungen werden lokal in die Warteschlange gestellt und an den Server gesendet

Was genau sich auf dem Gerät befindet — und was noch auf den Versand wartet — sehen Sie unter **Shop-Zustand → Datenbank**. Weitere technische Details finden Sie unter [So funktioniert die Sync-Engine](/reference/sync-engine).

## Offline vorgenommene Änderungen werden in die Warteschlange gestellt {#offline-writes}

Jede Änderung, die Sie im POS vornehmen — eine gespeicherte Bestellung, ein neuer oder bearbeiteter Kunde, ein Gutschein, eine Bestands- oder Preisänderung (Pro) oder eine Beleg-E-Mail — wird zuerst auf dem Gerät gespeichert und zum Senden vorgemerkt. Solange Sie offline sind, wartet die Warteschlange; auch wenn die Verbindung mitten in einer Schicht abbricht, geht nichts verloren. Die Warteschlange bleibt auch bei Neustarts und Abstürzen erhalten: Wenn die App einen Fehlerbildschirm anzeigt, wird sie durch Auswahl von **Erneut versuchen** neu geladen, ohne noch nicht übermittelte Verkäufe zu verwerfen.

Sobald die Verbindung zurückkehrt, wird die Warteschlange automatisch abgearbeitet. Lehnt Ihr Server eine Änderung endgültig ab (selten — zum Beispiel bei einem Datensatz, den der Server als ungültig ansieht), wiederholt das POS sie nicht stillschweigend endlos: Die Änderung wird unter **Shop-Zustand → Datenbank** im Bereich *„Änderungen, die Ihren Server nie erreicht haben“* geparkt, mit der Begründung des Servers und den ausdrücklichen Aktionen **Erneut senden** / **Verwerfen**. Siehe [Shop-Zustand](/support/store-health#refused-changes).

## Verbindungsanzeige {#connectivity-indicator}

In der POS-Kopfzeile wird ein farbiger Punkt angezeigt, der den Verbindungsstatus angibt:

- **Grün** — mit dem Server verbunden, alle Funktionen verfügbar
- **Gelb** — instabile Verbindung, einige Vorgänge können langsam sein
- **Rot** — offline, nur lokale Daten verfügbar

## Was bei einem Verbindungsverlust passiert {#what-happens-during-connectivity-loss}

Wenn die Internetverbindung während der Nutzung des POS unterbrochen wird:

1. **Produkte und Kunden bleiben durchsuchbar** — aus lokalen Daten.
2. **Warenkörbe können weiterhin zusammengestellt** und Artikel bearbeitet werden — jede Änderung wird lokal in die Warteschlange gestellt.
3. **Sie können Bestellungen erstellen und speichern, aber keine Zahlung entgegennehmen** — Warenkörbe und Änderungen werden lokal vorgemerkt, und eine Bestellung kann zum späteren Senden gespeichert werden. Die Zahlung kann erst abgeschlossen werden, wenn die Verbindung wiederhergestellt ist, da Ihr Server den Checkout bereitstellt.
4. **Offene Bestellungen werden** in der lokalen Datenbank gespeichert, bis die Verbindung wiederhergestellt ist.

## Wenn die Verbindung wiederhergestellt wird {#when-connection-restores}

Sobald die Verbindung wiederhergestellt ist:

- Die Verbindungsanzeige wird grün.
- **Die Änderungen in der Warteschlange werden automatisch an Ihren Server übertragen** — offline getätigte Verkäufe und Bearbeitungen werden ohne manuelles Zutun gesendet.
- Serverabhängige Zahlungsgateways und **Auf Server speichern** stehen wieder zur Verfügung.
- Die Hintergrundsynchronisation wird fortgesetzt und ruft alle Produkt- oder Kundenänderungen ab, die während der Offline-Zeit vorgenommen wurden.

## Tipps für unzuverlässige Verbindungen {#tips-for-unreliable-connections}

- **„Auf Server speichern" bei wichtigen Bestellungen verwenden** — dadurch wird die Bestellung sofort an WooCommerce übertragen, sodass sie nicht verloren geht, wenn die lokale Datenbank des Geräts gelöscht wird.
- **Nach einer Störung den Shop-Zustand prüfen** — die Kachel *Änderungen, die auf den Versand warten* unter **Shop-Zustand → Datenbank** bestätigt, wann alles Ihren Server erreicht hat.
- **Synchronisieren, solange Sie Empfang haben** — wenn Sie wissen, dass die Verbindung zeitweise ausfallen wird, lassen Sie die Grundbefüllung des Katalogs abschließen, solange eine stabile Verbindung besteht.
