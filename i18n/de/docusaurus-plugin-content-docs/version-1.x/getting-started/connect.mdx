Dieser Bildschirm wird nur in den Desktop- und Mobil-Apps angezeigt. Im Web greifen Sie direkt unter `yourdomain.com/pos` auf das POS zu und melden sich mit Ihren WordPress-Zugangsdaten an.

## Übersicht zum Verbindungsbildschirm {#connect-screen-overview}

Wenn Sie die WCPOS-Desktop- oder Mobil-App öffnen, wird der Verbindungsbildschirm angezeigt. Hier verwalten Sie Ihre Filialverbindungen und Benutzeranmeldungen.

{/* Screenshot: connect-screen.png */}

## Neue Filiale hinzufügen {#adding-a-new-store}

1. Geben Sie die URL Ihrer WooCommerce-Filiale in das Textfeld ein (z. B. `https://mystore.com`).
2. Klicken Sie auf **Verbinden**.
3. Sie werden zur Anmeldung mit Ihren WordPress-Zugangsdaten weitergeleitet.
4. Nach erfolgreicher Anmeldung kehren Sie zur App zurück.

## Mehrere Filialen {#multiple-stores}

Sie können beliebig viele WooCommerce-Filialen verbinden. Jede Filiale wird auf dem Verbindungsbildschirm als eigene Karte angezeigt, mit folgenden Angaben:

- **Filialname** und Favicon
- **Filial-URL**
- **Angemeldete Benutzer** dieser Filiale

Das ist hilfreich, wenn Sie mehrere Standorte oder Unternehmen verwalten.

## Mehrere Benutzer pro Filiale {#multiple-users-per-store}

Bei jeder Filiale können mehrere Benutzer gleichzeitig angemeldet sein. Das ist hilfreich für:

- **Schichtwechsel** – Ein neuer Kassierer kann sich anmelden, bevor sich der vorherige abmeldet.
- **Mehrere Kassen** – Verschiedene Kassierer arbeiten auf unterschiedlichen Geräten.
- **Schnelles Wechseln** – Einfach zwischen Benutzerkonten wechseln.

### Benutzer hinzufügen {#adding-a-user}

Klicken Sie auf die <Icon name="plus" /> Schaltfläche neben „Angemeldete Benutzer“, um dieser Filiale einen weiteren Benutzer hinzuzufügen.

### Benutzer wechseln {#switching-users}

Klicken Sie auf ein Benutzer-Badge (z. B. „Brenda“), um das POS als dieser Benutzer zu öffnen.

### Benutzer entfernen {#removing-a-user}

Klicken Sie auf **×** auf einem Benutzer-Badge, um diesen Benutzer von der Filiale abzumelden.

## Filiale entfernen {#removing-a-store}

Klicken Sie auf die rote Schaltfläche **×** auf der Filialkarte, um sie aus Ihrer Liste zu entfernen. Dadurch werden alle Benutzer abgemeldet und die Filialverbindung aus der App entfernt.

## Demo-Filiale {#demo-store}

Am unteren Bildschirmrand wird möglicherweise der Link „Demo-Filiale betreten“ angezeigt. Damit verbinden Sie sich mit einer WooCommerce-Demo-Filiale und können WCPOS ausprobieren, ohne die Daten Ihrer eigenen Filiale zu verändern.

## Fehlerbehebung {#troubleshooting}

:::tip Prüfen Sie zuerst: `X-Frame-Options`
Die Desktop- und Mobil-Apps verwenden **iframes** für Anmeldung, Zahlung und Belege. **Jeder** Server-Header und jedes Plugin, das `X-Frame-Options: DENY` oder `SAMEORIGIN` sendet, verhindert die Anmeldung. Dies ist die häufigste Ursache für fehlgeschlagene App-Anmeldungen — prüfen Sie zuerst die Antwort-Header der Anmeldeseite (Browser-Entwicklertools oder `curl -I https://yourstore.com/wp-login.php`).
:::

<Accordion>
  <AccordionItem question="Verbindung zur Filiale nicht möglich?">

  - Stellen Sie sicher, dass das WCPOS-Plugin auf Ihrer WordPress-Website installiert und aktiviert ist.
  - Prüfen Sie, ob Sie die richtige URL verwenden (einschließlich `https://` — die WooCommerce REST API erfordert SSL).
  - Rufen Sie zuerst `yourdomain.com/pos` in einem Webbrowser auf, um zu prüfen, ob das Plugin funktioniert.
  - Prüfen Sie, ob die WooCommerce REST API erreichbar ist.
  - Prüfen Sie, ob Ihr Benutzerkonto über POS-Zugriffsberechtigungen verfügt.

  </AccordionItem>

  <AccordionItem question="Anmeldung in der Desktop- oder Mobil-App schlägt fehl">

  Die meisten fehlgeschlagenen App-Anmeldungen werden dadurch verursacht, dass ein Sicherheits- oder Caching-Plugin das Anmelde-iframe blockiert:

  - **`X-Frame-Options`-Header** (von einem Sicherheits-Plugin oder Ihrem Server festgelegt) blockieren das Anmelde-iframe — siehe den Hinweis oben. Deaktivieren Sie das Sicherheits-Plugin vorübergehend, melden Sie sich an und aktivieren Sie es anschließend wieder (Ihre Sitzung bleibt etwa eine Woche bestehen).
  - **Sicherheits-Plugins** — Wordfence, Really Simple Security, WPS Hide Login, iThemes/Solid Security und Defender Pro sind häufig die Ursache. Die vollständige Liste und Lösungen finden Sie unter [Plugin-Konflikte](/support/troubleshooting/plugin-conflicts#security-and-login-plugins).
  - **Wordfence 2FA** — das 2FA-Codefeld wird im Anmelde-iframe nicht angezeigt. Deaktivieren Sie 2FA vorerst für POS-Benutzer.
  - **Benutzerdefinierte Anmelde-URL** (z. B. WPS Hide Login) — die App findet die Anmeldeseite nicht. Verwenden Sie die Standard-URL `/wp-admin/`.
  - **Caching-Plugins** können das blockierte Anmeldeformular weiterhin ausliefern, selbst nachdem Sie das problematische Plugin deaktiviert haben — leeren Sie den Cache oder löschen Sie den App-Cache bzw. installieren Sie die Desktop-App neu.

  </AccordionItem>

  <AccordionItem question='„REST API erfordert Authentifizierung“ oder ein Fehler eines Sicherheits-Plugins auf dem Verbindungsbildschirm'>

  Ein Plugin (z. B. Force Login oder ein JWT-Authentifizierungs-Plugin) verlangt für alle REST-API-Anfragen eine Authentifizierung. Deshalb kann die App die öffentlichen Informationen Ihrer Website nicht lesen. Statt fälschlich den Website-Typ zu melden, zeigt die App jetzt die tatsächliche Meldung des Servers an (z. B. _„Nur authentifizierte Benutzer können auf die REST API zugreifen“_).

  **Lösung:** Konfigurieren Sie das Sicherheits-Plugin so, dass nicht authentifizierter Zugriff auf `/wp-json/wcpos/` und `/wp-json/wc/v3/` erlaubt ist, oder deaktivieren Sie es nur so lange, bis die erste Verbindung hergestellt wurde.

  </AccordionItem>

  <AccordionItem question='„Scheint keine WordPress-Website zu sein“ (Desktop-App)'>

  Die Desktop-App ermittelt die REST API über den HTTP-Header `Link`. Wenn ein Plugin (häufig **Image Prioritizer** oder andere Performance-Plugins) diesen Header überfüllt oder abschneidet, schlägt die Erkennung fehl. **Lösung:** Deaktivieren Sie Plugins zur Bildoptimierung oder solche, die Header ändern, und versuchen Sie es erneut.

  </AccordionItem>

  <AccordionItem question="Die App meldet, dass ein Update erforderlich ist, oder stürzt nach einem Update ab">

  Prüfen Sie, ob die App-Version und das Server-Plugin unterschiedliche Versionen haben — möglicherweise wurde die App über den App-Store aktualisiert, während das WCPOS-Plugin noch aktualisiert werden muss (oder umgekehrt). Für v1.10 müssen sowohl die App als auch das WCPOS-Plugin zur **v1.10-Versionsreihe** gehören, da die App die v2-Synchronisierungs-API des Plugins verwendet. Wenn nur eine Seite aktualisiert wurde und Anfragen mit `rest_no_route` fehlschlagen, aktualisieren Sie auch die andere.

  </AccordionItem>

  <AccordionItem question='Fehler „Cannot create fast store database“'>

  Dies ist eine Race Condition bei der ersten Anmeldung. **Schließen Sie die App vollständig und versuchen Sie es erneut** — beim zweiten Versuch klappt es in der Regel.

  </AccordionItem>

  <AccordionItem question="Auf dem Bildschirm zur Benutzerauswahl festgefahren (Desktop-App)">

  Nach der Anmeldung sehen Sie Ihren Benutzernamen, aber keine offensichtliche Möglichkeit fortzufahren. **Klicken Sie auf Ihren Benutzernamen bzw. Namen** — damit gelangen Sie zum POS; der Name selbst ist die Schaltfläche.

  </AccordionItem>

  <AccordionItem question="Verbindung schlägt weiterhin fehl?">

  - Rufen Sie zuerst `yourdomain.com/pos` in einem Webbrowser auf, um zu prüfen, ob das Plugin funktioniert.
  - Prüfen Sie die Fehlerprotokolle Ihrer Website auf Probleme.
  - Stellen Sie sicher, dass Ihr Hosting-Anbieter die REST API nicht blockiert — siehe [Hosting-spezifische Hinweise](/support/performance/server#hosting-specific-notes).
  - Stellen Sie sicher, dass Ihr Server die [Mindestanforderungen](/support/performance/server#minimum-server-requirements) erfüllt.

  </AccordionItem>
</Accordion>
