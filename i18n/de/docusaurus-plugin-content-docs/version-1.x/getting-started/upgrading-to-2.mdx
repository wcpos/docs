WCPOS 2.0 ist ein umfangreiches Update. Die Kasse, der Checkout und die Kassenschublade sind neu, und das Plugin benötigt jetzt **WooCommerce 9.0 oder höher**. Diese Seite dient als Checkliste vor dem Update für alle, die auf **Aktualisieren** klicken. Lesen Sie sie vorher.

## Können Sie heute aktualisieren? {#can-you-upgrade-today}

Öffnen Sie **WP Admin → Plugins** und ermitteln Sie die WooCommerce-Version.

- **WooCommerce 9.0 oder höher:** Folgen Sie den Anweisungen unter [Wenn Ihre Filiale bereit ist](#if-your-store-is-ready).
- **Älter als 9.0:** Folgen Sie den Anweisungen unter [Wenn Ihre Filiale noch nicht bereit ist](#if-your-store-isnt-ready-yet). Aktualisieren Sie WCPOS nicht zuerst.

## Wenn Ihre Filiale bereit ist {#if-your-store-is-ready}

### Bevor Sie auf Aktualisieren klicken {#before-you-click-update}

1. **Synchronisieren Sie jede Kasse.** 2.0 legt auf jeder Kasse eine neue lokale Datenbank an und übernimmt keine Daten, die eine Kasse mit 1.11 noch nicht an die Filiale gesendet hat. Öffnen Sie jede Kasse, warten Sie, bis die Synchronisierung abgeschlossen ist, und aktualisieren Sie erst dann. Unter **Filialstatus → Datenbank** muss bei **Änderungen, die noch gesendet werden müssen** der Wert **0** stehen, und es darf kein Dialog angezeigt werden, der eine Entscheidung verlangt. Offene Bestellungen sind in diesem Wert nicht enthalten: Schließen Sie jede davon ab oder drücken Sie **Auf dem Server speichern**. Beide Ansichten zeigen nur, wer gerade angemeldet ist: Wiederholen Sie dies für jeden Kassierer, der die Kasse nutzt, in jeder Filiale und an jeder verwendeten Kasse.
2. **Sichern Sie die Website**, oder bitten Sie Ihren Hosting-Anbieter um einen Wiederherstellungspunkt. Das Update selbst verändert Ihre Bestellungen oder Produkte nicht, aber für ein umfangreiches Update sollte eine Möglichkeit zur Wiederherstellung vorhanden sein.
3. **Wählen Sie eine ruhige Stunde.** Jede Kasse wird in die neue Kassenoberfläche geladen. Ein Verkauf, dessen Checkout in der alten Version gerade läuft, muss erneut erfasst werden.
4. **Prüfen Sie, ob Ihre Pro-Lizenz aktiv ist** (WP Admin → POS → Einstellungen → Lizenz; siehe [WCPOS Pro installieren](/getting-started/pro-license)). Pro-Updates werden nur mit einer gültigen Lizenz bereitgestellt.
5. **Beachten Sie Ihre Rabattpraxis.** Wenn Kassierer bisher einen Betrag von einer Bestellung abgezogen haben, indem sie eine *negative Gebühr* hinzugefügt haben, funktioniert das nicht mehr. In 2.0 gibt es an der Kasse stattdessen **Rabatt hinzufügen**. Damit wird der Rabatt korrekt erfasst. Siehe [Warenkorbrabatte](/pos/cart/discounts).
6. **Aktualisieren Sie auch Ihre Terminal-Erweiterungen.** Für Stripe Terminal, SumUp und Mollie Terminal gibt es jeweils eine Version 2.0. Eine ältere Erweiterung funktioniert weiterhin über den Tab **Legacy** im Checkout, kann aber kein Lesegerät über den neuen Zahlungsbereich steuern.

### Aktualisieren {#updating}

1. **Aktualisieren Sie das Plugin.** Aktualisieren Sie bei einer kostenlosen Installation **WCPOS**. Mit Pro aktualisieren Sie nur **WCPOS Pro**: Es enthält bereits das kostenlose Plugin und deaktiviert eine separate Kopie davon.
2. Öffnen Sie den POS auf jedem Gerät und warten Sie, bis die erste Synchronisierung abgeschlossen ist. Browserkassen übernehmen 2.0, sobald das Plugin aktualisiert wurde. Desktop- und Mobil-Apps werden über ihre üblichen Kanäle aktualisiert. Eine App mit Version 1.11, die auf ein Plugin mit Version 2.0 trifft, zeigt einen Update-Hinweis an, bis sie selbst aktualisiert wird: App und Plugin müssen beide Version 2.0 haben.

Wenn eine Kasse nach dem Update **AUTH331** meldet, kommuniziert eine App mit Version 2.0 mit einer Filiale, die noch nicht aktualisiert wurde. Aktualisieren Sie das Plugin und stellen Sie die Verbindung erneut her. Siehe [AUTH331](/error-codes/AUTH331).

### Was sich am ersten Tag ändert {#what-changes-on-day-one}

- **Die Kassenoberfläche sieht anders aus.** Alle Bildschirme verwenden eine einheitliche Gestaltung, mit einer Skalierungseinstellung (kompakt, normal, großzügig), die zur Größe Ihres Geräts passt. Formulare und Auswahlfelder erscheinen als Seitenleisten statt als Dialogfenster. Die Leiste oben zeigt den Namen der Filiale und, wenn es dort mehrere gibt, den Namen der Kasse. Sie können festlegen, auf welcher Seite der Warenkorb angezeigt wird, und in den Kasseneinstellungen eine Reihe von Schnellfilter-Schaltflächen einrichten.
- **Checkout ist der Zahlungsbereich.** Wenn Sie **Kasse** drücken, wird ein Tastenfeld geöffnet. Geben Sie den Betrag ein, den der Kunde übergibt; das Rückgeld wird angezeigt. Teilen Sie einen Verkauf auf Bargeld und Karte oder auf mehrere Karten auf. Kartenlesegeräte, die mit der Kasse verbunden sind, werden über denselben Bildschirm gesteuert (Pro). Zahlungsgateways, die weiterhin ihre eigene Zahlungsseite verwenden, befinden sich im Tab **Legacy**. Siehe [Checkout](/pos/checkout).
- **Jede Kasse hat einen Kassenabschluss.** Wenn ein Kassierer den POS zum ersten Mal öffnet, öffnet er die Kasse mit einem Anfangsbestand. **Kasse schließen** zählt den Inhalt der Kassenschublade und speichert den Zählstand als nummerierten Abschluss; der Abschlussbericht (Z-Bericht) wird anschließend auf dem Abschlussblatt gedruckt. Diese Funktion ist im kostenlosen Plugin enthalten. Das kostenlose Plugin hat eine Kasse, die von allen Geräten gemeinsam genutzt wird; Manager benennen sie und legen ihren Standard-Anfangsbestand unter **WP Admin → POS → Einstellungen → Kassen** fest. Weitere Kassen sind mit Pro verfügbar. Wenn Sie keine Kassenschublade verwenden, können Kassensitzungen in den POS-Einstellungen deaktiviert werden. Siehe [Tagesabschluss und Abgleich](/pos/reconciliation).
- **Gutscheine an der Kasse sind kostenlos.** Kassierer können im kostenlosen Plugin im Warenkorb einen WooCommerce-Gutscheincode anwenden. Das Durchsuchen der Gutscheinansicht im POS bleibt Pro vorbehalten.
- **Negative Gebühren gibt es nicht mehr.** Verwenden Sie **Rabatt hinzufügen**. Bestellungen, die bereits eine negative Gebühr enthalten, bleiben unverändert.
- **WooCommerce Analytics zählt eine POS-Bestellung, sobald sie bezahlt ist.** Bestellungen, die an der Kasse noch offen oder nur teilweise bezahlt sind, werden erst nach ihrem Abschluss als Verkäufe angezeigt. Daher fallen Summen, die solche Bestellungen enthielten, niedriger aus.
- **Belege enthalten mehr Angaben.** Auf jedem Beleg erscheinen der Kassenname, die Softwareversion und ein QR-Code. Bei einer Rückerstattung wird ein eigener Beleg als Gutschrift gedruckt. Benutzerdefinierte Belegvorlagen funktionieren weiterhin.
- **Magnetstreifen-Kartenlesegeräte werden nicht mehr unterstützt.** Kartenzahlungen an der Kasse erfolgen über ein integriertes Lesegerät (Pro) oder werden als externe Kartenzahlung erfasst.

## Wenn Ihre Filiale noch nicht bereit ist {#if-your-store-isnt-ready-yet}

**Bleiben Sie bei WCPOS 1.11.** Es funktioniert weiterhin und erhält sechs Monate nach der Veröffentlichung von 2.0 weiterhin Fehlerbehebungen.

1. **Deaktivieren Sie automatische Updates für WCPOS** und WCPOS Pro. Unter **WP Admin → Plugins** befindet sich in jeder Plugin-Zeile der Link **Automatische Updates aktivieren** / **Automatische Updates deaktivieren**. Achten Sie darauf, dass dort *Aktivieren* steht. So verhindern Sie, dass ein automatisches Update während einer Schicht einen blockierenden Hinweis vor einem Kassierer einblendet.
2. **Aktualisieren Sie WooCommerce auf Version 9.0 oder höher**, sobald Sie bereit sind. Die Versionshinweise von WooCommerce beschreiben dieses Update.
3. **Kehren Sie zu [Wenn Ihre Filiale bereit ist](#if-your-store-is-ready) zurück.**
4. **Sobald Sie Version 2.0 verwenden, aktivieren Sie automatische Updates wieder**, falls Sie sie zuvor genutzt haben. Andernfalls werden spätere Fehlerbehebungen nicht automatisch installiert.

### Wenn WCPOS vor WooCommerce aktualisiert wurde {#if-wcpos-updated-first}

Der POS zeigt einen Hinweis an, dass WooCommerce 9.0 erforderlich ist; es geht nichts verloren. Aktualisieren Sie entweder jetzt WooCommerce oder [installieren Sie WCPOS 1.11 erneut](/getting-started/previous-versions) und deaktivieren Sie wie oben beschrieben automatische Updates.

## Zurückwechseln {#rolling-back}

### Eine Kasse mit Version 1.11 hat noch nicht gesendete Verkäufe {#unsent-sales}

Die Kasse zeigt einen Update-Bildschirm an und ihre Verkäufe sind noch nicht in Ihrer Filiale angekommen. Sie bleiben auf diesem Gerät, bis darauf 2.0 geöffnet wird. So senden Sie sie:

1. **Lassen Sie diese Kasse unverändert.** Aktualisieren Sie die App nicht und laden Sie bei einer Browserkasse die Seite nicht neu: Beides öffnet 2.0, wodurch die noch nicht gesendeten Verkäufe gelöscht werden.
2. **[Installieren Sie das Plugin mit Version 1.11 erneut](/getting-started/previous-versions)** in Ihrer Filiale.
3. **Laden Sie bei einer Browserkasse die Seite neu oder schließen Sie die App und öffnen Sie sie erneut.** Da die Filiale nun wieder Version 1.11 verwendet, stellt die Kasse die Verbindung wieder her und sendet ihre Verkäufe. Warten Sie, bis unter **Filialstatus → Datenbank** bei **Änderungen, die noch gesendet werden müssen** der Wert **0** steht und kein Dialog eine Entscheidung verlangt. Offene Bestellungen sind in diesem Wert nicht enthalten: Schließen Sie jede davon ab oder drücken Sie **Auf dem Server speichern**. Die Verkäufe sind nun in der Filiale angekommen.
4. **Aktualisieren Sie erneut auf 2.0** wie unter [Aktualisieren](#updating) beschrieben.

### Zu 1.11 zurückkehren {#back-to-1-11}

Wenn 2.0 bei Ihnen nicht funktioniert, schreiben Sie uns zuerst auf [Discord](https://wcpos.com/discord). Die meisten Probleme am Tag des Upgrades lassen sich schneller beheben als durch ein Zurücksetzen.

:::warning Vor dem Zurücksetzen synchronisieren
Bei der Rückkehr zu 1.11 wird auf jeder Kasse eine leere lokale Datenbank angelegt. 1.11 kann keine Verkäufe senden, die eine Kasse mit 2.0 noch nicht an Ihre Filiale übermittelt hat. Warten Sie zunächst, bis die Synchronisierung auf jeder Kasse mit 2.0 abgeschlossen ist: Unter **Filialstatus → Datenbank** muss bei **Änderungen, die noch gesendet werden müssen** der Wert **0** stehen. Es darf kein Dialog eine Entscheidung verlangen und keine offene Bestellung mehr unsynchronisiert sein.
:::

**Eine Desktop- oder Mobil-App mit Version 2.0 kann keine Verbindung zu einem Plugin mit Version 1.11 herstellen** (sie meldet [AUTH331](/error-codes/AUTH331)), und die App-Stores bieten keine älteren Versionen an. Verwenden Sie auf dieser Kasse bis zum nächsten Upgrade den Browser-POS unter `yourdomain.com/pos`.

Um zurückzusetzen, [installieren Sie das Plugin mit Version 1.11 erneut](/getting-started/previous-versions). Browserkassen und Apps, auf denen weiterhin 1.11 läuft, funktionieren wie zuvor.

Bestellungen, die mit 2.0 erstellt wurden, sind gewöhnliche WooCommerce-Bestellungen und bleiben erhalten. Kassensitzungen und Abschlüsse, die mit 2.0 erfasst wurden, bleiben in der Datenbank, werden aber in 1.11 nicht angezeigt.
