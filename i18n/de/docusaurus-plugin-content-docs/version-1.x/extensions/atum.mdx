# WCPOS ATUM-Integration {#wcpos-atum-integration}

Integriert [ATUM Multi-Inventory](https://www.stockmanagementlabs.com/addons/atum-multi-inventory/) mit [WCPOS Pro](/1.x/getting-started/pro-license) und ermöglicht standortbezogenen Bestand, Preise und SKUs am Point of Sale.

Mit ATUM Multi-Inventory können Sie den Bestand eines Produkts auf mehrere Lagerstandorte aufteilen — Lagerhäuser, Einzelhandelsgeschäfte und so weiter. Dieses Plugin verknüpft diese ATUM-Standorte mit den [Filialen](/1.x/stores) in WCPOS Pro, sodass jedes POS-Terminal die korrekten Bestandsmengen, Preise und SKUs für seinen physischen Standort anzeigt.

  <FeatureCard icon="box" title="Standortbezogener Bestand">
    Jede Filiale bezieht Bestandsmengen vom zugewiesenen ATUM-Lagerstandort anstelle des gesamten WooCommerce-Bestands.
  </FeatureCard>
  <FeatureCard icon="store" title="Flexible Preisgestaltung">
    Wählen Sie zwischen den WooCommerce-Standardpreisen, den WCPOS Pro-Filialpreisen und den standortspezifischen ATUM-Preisen.
  </FeatureCard>
  <FeatureCard icon="barcode" title="Standort-SKUs">
    Optional können Sie die Haupt-SKU eines Produkts im POS durch eine standortspezifische ATUM-SKU ersetzen.
  </FeatureCard>
  <FeatureCard icon="sync" title="Revisionssichere Bestandsbewegung">
    Bestellungen buchen Bestand am korrekten ATUM-Standort ab und wieder ein, mit vollständigem Audit-Trail in `atum_inventory_orders`.
  </FeatureCard>
  <FeatureCard icon="arrow-right" title="Produktbearbeitung mit Rückschreibung">
    Änderungen an Bestand, Preis und SKU im POS werden in die zugeordnete ATUM-Bestandszeile für den jeweiligen Standort zurückgeschrieben.
  </FeatureCard>
</FeatureGrid>

## Installation {#installation}

<Steps>
  <StepCard number="1" title="ATUM und Multi-Inventory installieren">

Installieren Sie [ATUM Inventory Management](https://wordpress.org/plugins/atum-stock-manager-for-woocommerce/) und das [ATUM Multi-Inventory Add-on](https://www.stockmanagementlabs.com/addons/atum-multi-inventory/). Konfigurieren Sie anschließend Ihre Lagerstandorte in ATUM.

  </StepCard>
  <StepCard number="2" title="WCPOS ATUM-Integration installieren">

Installation über `WP Admin > POS > Einstellungen > Erweiterungen`, oder laden Sie die neueste Version von der [GitHub-Releases-Seite](https://github.com/wcpos/wcpos-atum/releases) herunter und installieren Sie sie über `Plugins > Neu hinzufügen > Plugin hochladen`.

  </StepCard>
  <StepCard number="3" title="Filialen ATUM-Standorten zuordnen" isLast>

Navigieren Sie zu `POS > Geschäfte`, bearbeiten Sie eine Filiale und konfigurieren Sie den Seitenleistenabschnitt **ATUM-Bestandsverwaltung**. Wählen Sie den Lagerstandort aus, den die Filiale verwenden soll, legen Sie eine Preisquelle fest und aktivieren Sie optional die SKU-Überschreibung.

  </StepCard>
</Steps>

## Filialenkonfiguration {#store-configuration}

Das Plugin fügt einen Bereich **ATUM-Bestandsverwaltung** in der Seitenleiste des WCPOS Pro Filialeditors mit drei Einstellungen pro Filiale hinzu:

- **Lagerstandort** — von welchem ATUM-Standort diese Filiale den Bestand bezieht.
- **Preisquelle** — woher die Produktpreise stammen:
  - *Standard* — reguläre WooCommerce-Preise
  - *WCPOS Pro* — filialspezifische Preise, festgelegt in WCPOS Pro
  - *ATUM* — standortspezifische Preise aus dem ATUM-Inventar
- **SKU-Überschreibung** — optional können standortspezifische SKUs aus ATUM anstelle der Haupt-SKU des Produkts verwendet werden.

## POS-Verhalten {#pos-behavior}

Wenn einer Filiale ein ATUM-Standort zugewiesen ist, werden die an das POS übermittelten Produktdaten automatisch angepasst:

- **Lagerbestände** spiegeln den Bestand des jeweiligen Standorts wider, nicht den aggregierten WooCommerce-Bestand.
- **Lagerstatus** wird anhand der Menge am jeweiligen Standort neu berechnet.
- **Preise** stammen aus der konfigurierten Preisquelle.
- **SKUs** werden durch die ATUM-Standort-SKU ersetzt, wenn die Überschreibung aktiviert ist.

Alle Anpassungen erfolgen transparent über die WCPOS REST API — auf der POS-App-Seite sind keine Änderungen erforderlich. Produktänderungen, die über das POS vorgenommen werden, werden ebenfalls in die zugeordnete ATUM-Bestandszeile zurückgeschrieben; siehe [Produktbearbeitungs-Rückschreibung](#product-edit-write-back) weiter unten.

## Bestandsverwaltung {#stock-management}

Bei POS-Bestellungen in Filialen mit einem zugeordneten ATUM-Standort überlässt das Plugin das Schreiben der Bestandsänderung dem nativen Bestandsabzug von ATUM — lenkt diesen jedoch zum korrekten Standort:

1. **REST-Payload-Injektion.** Wenn der POS eine Bestellung erstellt oder aktualisiert, fügt das Plugin jeder Bestellposition einen `mi_inventories`-Eintrag hinzu, damit ATUM weiß, von welchem Standort der Bestand entnommen werden soll. Ohne diesen Eintrag würde ATUM auf den Hauptbestand zurückgreifen.
2. **Standortbezogener Bestandsfilter.** Das Plugin beschränkt die Liste der infrage kommenden ATUM-Bestände auf diejenigen, die mit dem zugeordneten Standortbegriff der Filiale verknüpft sind. So wird sowohl beim Abzug als auch bei der Wiederherstellung der richtige Bestand ausgewählt.

ATUM selbst führt die eigentliche Bestandsänderung bei Bestellung und Rückerstattung durch und schreibt Zeilen mit der tatsächlichen `order_id` in `atum_inventory_orders` — so bleibt der Audit-Trail von ATUM erhalten.

## Produktbearbeitungs-Rückschreibung {#product-edit-write-back}

Wenn ein Kassierer oder Manager ein Produkt oder eine Variante im POS bearbeitet, werden die Änderungen in die zugeordnete ATUM-Bestandszeile für den Standort dieser Filiale zurücksynchronisiert — nicht nur in das WooCommerce-Hauptprodukt. Dadurch bleiben Bestand, Preis und SKU jedes Standorts ohne manuelle Aktualisierungen in `WP Admin` mit ATUM synchron.

Die Rückschreibung wird bei REST-Aktualisierungen von WCPOS-Produkten und -Varianten (`POST`, `PUT`, `PATCH` an `/wcpos/v1/products/...`) ausgelöst, die eine `store_id` enthalten. Das Plugin ermittelt den zugeordneten ATUM-Standort der Filiale und aktualisiert nur die Bestandszeile für diesen Standort — andere Standorte bleiben unberührt.

### Was synchronisiert wird {#what-syncs}

Die Rückschreibung berücksichtigt die Konfiguration jeder Filiale, sodass ATUM-Daten nur geändert werden, wenn die Filiale diese Daten tatsächlich verwaltet:

| Feld | Wann synchronisiert wird |
| --- | --- |
| **Lagerbestand** | Immer — jede Filiale mit einem zugeordneten ATUM-Standort hält ihre Bestandszeile für diesen Standort synchron. |
| **Regulärer Preis / Aktionspreis / Preis** | Nur wenn die **Preisquelle** der Filiale auf *ATUM* gesetzt ist. |
| **SKU** | Nur wenn **SKU-Überschreibung** für die Filiale aktiviert ist. |

Wenn die Filiale die Preisquelle *Standard* oder *WCPOS Pro* verwendet, bleiben die ATUM-Preisfelder unverändert, sodass ATUM weiterhin als Preisreferenz und nicht als maßgebliche Quelle dient. Dasselbe gilt für SKUs, wenn die Überschreibung deaktiviert ist.

### Was kein Zurückschreiben auslöst {#what-doesnt-trigger-write-back}

- Produkterstellung (nur Aktualisierungen werden zurückgeschrieben — neue Produkte durchlaufen den normalen Speicherprozess von WooCommerce).
- Anfragen ohne eine `store_id` — der POS muss dem Plugin mitteilen, für welchen Standort geschrieben werden soll.
- Filialen ohne einen zugeordneten ATUM-Standort.
- Produkte ohne eine vorhandene ATUM-Bestandszeile für den Standort der Filiale — das Plugin erstellt keine neuen Bestandszeilen, sondern aktualisiert nur bestehende.
