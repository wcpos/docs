WCPOS hält auf jedem Gerät eine lokale Kopie Ihrer Produkte vor, damit sich der Katalog sofort durchblättern und durchsuchen lässt und auch offline nutzbar bleibt. Diese Anleitung erläutert, wie Produkte auf das Gerät gelangen und wie sie aktuell bleiben.

:::info Geändert in v1.10.0
Mit v1.10.0 wird eine neue Sync-Engine eingeführt. Wenn Ihr POS älter als v1.10.0 ist, lesen Sie unten [Was sich in v1.10.0 geändert hat](#what-changed-in-v1100).
:::

## Wie Produkte auf das Gerät gelangen {#how-products-arrive}

- **Eine Katalog-Grundbefüllung läuft im Hintergrund.** Ab dem ersten Start lädt das POS Ihren Katalog nach einem Zeitplan in kleinen Stapeln herunter, ohne dass Sie etwas tun müssen. Sie können verkaufen, sobald die ersten Produkte angekommen sind — der Checkout wartet nicht auf einen vollständigen Download.
- **Was Sie gerade ansehen, wird bei Bedarf heruntergeladen.** Beim Suchen, beim Filtern nach Kategorie oder beim Scannen eines Barcodes werden die passenden Produkte direkt geholt, falls sie noch nicht lokal vorliegen. Eine Suche zieht keine unbeteiligten Produkte mehr mit — sie holt genau das, wonach Sie gefragt haben.
- **Aktualisierungen kommen über Änderungsprüfungen.** Sobald ein Produkt lokal vorliegt, lädt das POS es nicht erneut herunter, um zu sehen, ob es sich geändert hat. Es fragt ein schlankes Änderungsprotokoll ab (bei der Standard-Voreinstellung alle 60 Sekunden) und holt nur das, was sich tatsächlich geändert hat — ein Shop ohne Aktivität antwortet mit einer einzigen, nahezu kostenlosen Antwort „nichts geändert“.

## Wie groß sind die Stapel? {#batch-size}

Standardmäßig fordert das POS **50 Produkte auf einmal** an. Das ist keine feste Konstante mehr — es ist einer von zwei Reglern, die über Ihre Sync-Voreinstellung unter **Shop-Zustand → Leistung** gesetzt werden:

| Voreinstellung | Prüfintervall | Datensätze pro Anfrage |
| --- | --- | --- |
| Eco | 5 min | 25 |
| Ausgewogen (Standard) | 60 s | 50 |
| Echtzeit | 10 s | 75 |

Kleine Stapel gibt es zum Schutz Ihres Servers: Große Seiten kosten den Server echte Rechenzeit, und auf Shared Hosting können sie den Onlineshop verlangsamen oder Rate-Limits auslösen. Wählen Sie Eco für bescheidenes Hosting und Echtzeit für Geschäfte mit mehreren Kassen auf leistungsfähigem Hosting. Einzelheiten finden Sie unter [Shop-Zustand](/support/store-health#sync-presets).

## Den Download-Fortschritt prüfen {#checking-progress}

Öffnen Sie **Shop-Zustand → Datenbank**, um pro Sammlung zu sehen, wie viele Datensätze auf diesem Gerät gegenüber Ihrem Server vorliegen — samt Abdeckungsbalken. Die Zahl *auf dem Server* ist ein echter, vom Server gemeldeter Wert; solange das POS ihn noch bestätigt, zeigt die Zeile *wird geprüft …* statt einer Schätzung.

Ein teilweise gefüllter Produktbalken bedeutet lediglich, dass die Grundbefüllung noch nicht abgeschlossen ist; sie läuft im Hintergrund weiter. Wenn ein bestimmtes Produkt zu fehlen scheint, suchen Sie danach — dadurch wird es direkt geholt.

:::tip
Wenn eine Sammlung festzustecken scheint, verwenden Sie **Löschen & neu herunterladen** in ihrer Zeile unter Shop-Zustand → Datenbank, bevor Sie zum vollständigen Reset [alle lokalen Daten zurücksetzen](/support/troubleshooting/clear-local-data) greifen.
:::

## Was sich in v1.10.0 geändert hat {#what-changed-in-v1100}

Frühere Versionen luden den Katalog *nach und nach durch die Nutzung* herunter: Jede Suche und jedes Scrollen zog einen weiteren Stapel Produkte, und alle 5 Minuten lief eine vollständige Abfrage. Dieses Modell ist abgelöst. In v1.10.0 gilt:

- Der Katalog füllt sich über eine geplante Grundbefüllung im Hintergrund — Sie müssen weder suchen noch scrollen, damit Produkte heruntergeladen werden.
- Eine Suche holt die dazu passenden Produkte, nicht einen beliebigen nächsten Stapel.
- Änderungsprüfungen laufen im Intervall Ihrer gewählten Voreinstellung (standardmäßig 60 Sekunden) und nutzen bedingte Anfragen statt einer festen vollständigen Abfrage alle 5 Minuten.
- Der Download-Fortschritt ist pro Sammlung unter **Shop-Zustand → Datenbank** sichtbar.

Entwickler finden die vollständige Mechanik unter [So funktioniert die Sync-Engine](/reference/sync-engine).

## F.A.Q. {#faq}

<Accordion>
  <AccordionItem question="Muss ich etwas tun, damit meine Produkte heruntergeladen werden?">

  Nein. Die Katalog-Grundbefüllung lädt Ihre Produkte automatisch im Hintergrund herunter. Suchen oder Filtern holt bestimmte Produkte sofort, falls sie noch nicht lokal vorliegen, aber nicht das normale Durchblättern schließt den Download ab — das tut die Grundbefüllung im Hintergrund.

  </AccordionItem>

  <AccordionItem question="Wie schnell erreichen Produktänderungen das POS?">

  Bei der Standard-Voreinstellung Ausgewogen prüft das POS alle 60 Sekunden auf Änderungen (die Prüfungen sind leicht zufällig gestreut, damit mehrere Kassen den Server nicht gleichzeitig treffen). Es werden nur geänderte Produkte geholt. Wenn mehrere Kassen die Änderungen der anderen schneller sehen müssen, verwenden Sie die Voreinstellung Echtzeit.

  </AccordionItem>

  <AccordionItem question="Ich sehe nicht alle meine Produkte im POS">

  Dafür gibt es mehrere Möglichkeiten:

  - Die Grundbefüllung im Hintergrund ist möglicherweise schlicht noch nicht abgeschlossen — prüfen Sie die Produktzeile unter **Shop-Zustand → Datenbank**.
  - Das POS blendet nicht vorrätige Artikel standardmäßig aus. Diese Einstellung kann in den Produktanzeigeeinstellungen geändert werden.
  - Die WooCommerce REST API unterstützt nur die Standard-Produkttypen (einfach, variabel, gruppiert, extern). Benutzerdefinierte Produkttypen werden möglicherweise nicht im POS angezeigt.

  </AccordionItem>
</Accordion>
