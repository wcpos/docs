WCPOS bietet einem Kassierer mehrere Möglichkeiten, eine Bestellung spontan zu rabattieren: schnelle Prozent-Schaltflächen, direkte Preisänderungen einzelner Positionen und Rabattgebühren auf Bestellebene. Informationen zu vorkonfigurierten Aktionen mit Nutzungsregeln finden Sie unter [Gutscheine](/coupons) (Pro).

:::info Suchen Sie die Rabatt-Summe?
Ein an der Kasse gesenkter Preis wird als Angebotspreis des Artikels erfasst, nicht als WooCommerce-Rabatt — die native Summe **Rabatt** ist Gutscheinen vorbehalten. [Warum Preisänderungen und Gutscheine unterschiedlich erfasst werden](#why-tracked-differently) erklärt das Modell; wenn sich Ihre Summen nach dem Update auf v1.9.0 geändert haben, siehe [Was sich in v1.9.0 geändert hat](#what-changed-in-v190).
:::

## Schnellrabatte {#quick-discounts}

Mit Schnellrabatt-Schaltflächen können Sie mit einem einzigen Tippen einen prozentualen Rabatt auf die gesamte Bestellung anwenden.

Öffnen Sie zur Konfiguration die [Anzeigeeinstellungen](/pos/cart#display-settings) des Warenkorbs und geben Sie im Feld **Schnellrabatte** eine durch Kommas getrennte Liste von Prozentsätzen ein. Beispielsweise erstellt `5,10,15,20` vier Schnellzugriffsschaltflächen.

Wenn Sie auf eine Schnellrabatt-Schaltfläche tippen, wird der Prozentsatz auf alle Positionen im Warenkorb angewendet.

## Rabatte auf Positionsebene {#line-item-discounts}

Sie können den Preis jeder einzelnen Position direkt im Warenkorb ändern:

1. Klicken Sie auf das Feld **Preis** der Position
2. Geben Sie den neuen Preis ein
3. Drücken Sie zum Bestätigen die **Eingabetaste**

Dies ist nützlich für Preisanpassungen, Mitarbeiterrabatte oder einmalige Änderungen. Der Gesamtbetrag der Position wird automatisch anhand von Menge × neuem Preis aktualisiert.

Weitere Informationen zum Bearbeiten von Warenkorbpositionen finden Sie unter [Positionen](/pos/cart/line-items).

:::tip Positionen aufteilen
Wenn ein Kunde unterschiedliche Rabatte auf Teile desselben Produkts erhalten soll (z. B. 3 zum vollen Preis und 2 reduziert), aktivieren Sie die Option **Aufteilen** in den [Anzeigeeinstellungen](/pos/cart#display-settings) des Warenkorbs, um eine Position in separate Zeilen aufzuteilen.
:::

## Rabatte auf Bestellebene {#order-level-discounts}

Um einen festen Rabatt auf die gesamte Bestellung anzuwenden (statt auf einzelne Positionen), fügen Sie eine **negative Gebühr** hinzu:

1. Klicken Sie unterhalb der Warenkorbpositionen auf **Gebühr hinzufügen**
2. Geben Sie einen Namen ein (z. B. „Mitarbeiterrabatt“)
3. Geben Sie den Rabattbetrag als negative Zahl ein (z. B. `-5.00`)

Die Gebühr wird als separate Position angezeigt und verringert die Bestellsumme. Bei Bedarf können Sie den Steuerstatus und die Steuerklasse der Gebühr über das Drei-Punkte-Menü bearbeiten.

### Wie die Steuer auf eine Rabattgebühr berechnet wird {#discount-fee-tax}

WCPOS besteuert eine negative Gebühr anhand **der eigenen Steuereinstellungen der Gebühr**: Setzen Sie deren Steuerstatus auf **Keine**, wird keine Steuer darauf angewendet; belassen Sie ihn auf **Steuerpflichtig**, wird sie mit ihrer eigenen Steuerklasse besteuert. Der Betrag, den Sie eingeben, ist der Betrag, der abgezogen wird — geben Sie `-10.00` ein, zahlt der Kunde 10 weniger.

WooCommerce-Core macht das anders. Von sich aus behandelt WooCommerce eine negative Gebühr als Rabatt auf den gesamten Warenkorb und verteilt deren Steuer auf die Steuerklassen aller anderen Artikel der Bestellung, wobei der von Ihnen für die Gebühr festgelegte Steuerstatus ignoriert wird. Es berücksichtigt außerdem keine steuerinklusive Preisgestaltung, sodass in einem Shop, in dem **Preise inklusive Steuer eingegeben** auf *Ja* steht, eine Gebühr von `-10.00` bei einem Satz von 20 % **12,00** abziehen würde. WCPOS überschreibt das, sodass die Kasse genau das abzieht, was der Kassierer eingegeben hat.

Diese Behandlung gehört zur Bestellung, nicht zu der App, die Sie gerade verwenden — eine Neuberechnung einer POS-Bestellung aus **WP Admin → Bestellungen** ändert sie nicht. Nicht-POS-Bestellungen behalten das Standardverhalten von WooCommerce bei.

:::note Bekannte Einschränkung bei steuerinklusiven Shops
Wenn Ihre Preise die Steuer enthalten, ergibt eine Rabattgebühr für den Kunden die korrekte Gesamtsumme, lässt aber die **auf der Bestellung erfasste Steuer unverändert** — sodass der Steuerbetrag geringfügig höher ist, als der reduzierte Betrag streng genommen rechtfertigen würde. Er fällt zugunsten der Steuerbehörde aus, niemals umgekehrt. Wenn die erfasste Steuer für Ihre Buchhaltung wichtig ist, verwenden Sie stattdessen einen [Gutschein](/coupons) für den Rabatt: Gutscheine reduzieren den steuerpflichtigen Betrag und berechnen die Steuer darauf korrekt neu. Aus genau diesem Grund verlagern wir Rabatte auf Bestellebene im POS in einem künftigen Release auf Gutscheine.
:::

## POS-Rabatte im Vergleich zu WooCommerce-Gutscheinen {#pos-discounts-vs-woocommerce-coupons}

Die Rabatte auf dieser Seite sind spontane Anpassungen, die Kassierer an der Kasse anwenden; WooCommerce-**Gutscheine** sind vorkonfigurierte Aktionen mit Regeln und Nachverfolgung. Hier ein kurzer Vergleich:

| | POS-Rabatte | WooCommerce-Gutscheine (Pro) |
|---|---|---|
| **Anwendung** | Schnellrabatt, Bearbeitung des Positionspreises oder negative Gebühr | Gutscheincode im Warenkorb eingeben |
| **Konfiguration** | Spontan durch den Kassierer | Vorkonfiguriert unter **WP Admin → Marketing → Gutscheine** |
| **Nachverfolgung** | Als Positionspreis erfasst, wie ein Angebotspreis (siehe [warum](#why-tracked-differently)) | Als Gutscheinrabatt in WooCommerce-Berichten nachverfolgt |
| **Einschränkungen** | Keine — der Kassierer legt jeden beliebigen Preis fest | Nutzungslimits, Produkt-/Kategorieeinschränkungen, Mindestbestellwert, Ablaufdatum, E-Mail-Regeln |
| **Am besten geeignet für** | Spontane Anpassungen, Preisanpassungen | Strukturierte Aktionen, nachverfolgbare Rabatte |

:::tip Was sollte ich verwenden?
Für einmalige Preisanpassungen sind die Rabatte auf dieser Seite einfacher. Wenn Sie die Rabattnutzung in WooCommerce-Berichten nachverfolgen oder Regeln wie Nutzungslimits durchsetzen müssen, verwenden Sie [Gutscheine](/coupons).
:::

## Warum Preisänderungen und Gutscheine unterschiedlich erfasst werden {#why-tracked-differently}

WooCommerce hat genau ein integriertes Konzept für einen Rabatt: den **Gutschein**. Ein Gutschein gehört zur Bestellung — er wird in einem eigenen Feld erfasst, in der Spalte **Rabatt** der Berichte gezählt und trägt eigene Regeln wie Nutzungslimits und Ablaufdaten.

Ein **Angebotspreis** ist für WooCommerce kein Rabatt. Er ist einfach der aktuelle Preis des Produkts: Wenn ein reduzierter Artikel verkauft wird, erfasst die Bestellung den gezahlten Preis und sonst nichts. Der reguläre Preis erscheint nie auf der Bestellung, und Berichte zählen den Verkauf als gewöhnlichen Umsatz — WooCommerce selbst führt keine Aufzeichnung darüber, dass der Kunde etwas gespart hat.

Schnellrabatte und Preisänderungen auf Positionsebene folgen dem Angebotspreis-Modell: Der Artikel wird „im Angebot“ zu dem Preis verkauft, den der Kassierer festlegt. Diese eine Regel erklärt den Rest dieser Seite — die WooCommerce-Summe **Rabatt** bleibt bei null, Gutscheine berechnen sich gegen den gesenkten Preis, und „Angebotsartikel ausschließen“-Gutscheine überspringen an der Kasse gesenkte Artikel. (Eine negative Gebühr auf Bestellebene ist wiederum etwas anderes: Sie wird als Gebührenzeile erfasst, nicht als Preisänderung.)

Belege sind der eine Ort, an dem Kunden erwarten zu sehen, was sie gespart haben, daher erfasst WCPOS den regulären Preis neben dem neuen Preis auf jeder Zeile. Dadurch kann ein Beleg Angebotsersparnisse und Gutscheinrabatte als getrennte Beträge anzeigen, ohne einen davon doppelt zu zählen — und ohne die Bestellsummen oder Berichte von WooCommerce zu ändern.

## Wie POS-Preisänderungen mit Gutscheinen interagieren {#how-pos-price-changes-interact-with-coupons}

Wenn ein Kassierer einen benutzerdefinierten Preis für eine Position festlegt (z. B. $18 auf $16 reduziert) und anschließend ein Gutschein angewendet wird, berechnet sich der Gutschein gegen den **im POS rabattierten Preis** ($16), nicht gegen den ursprünglichen ($18). Dadurch erhalten Kunden nicht durch das Kombinieren eines Kassiererrabatts mit einem Gutschein gegen den ursprünglichen Preis einen zu hohen Rabatt.

- Im POS rabattierte Artikel werden von WooCommerce als „im Angebot“ behandelt. Wenn für einen Gutschein **Angebotsartikel ausschließen** aktiviert ist, überspringt er im POS rabattierte Artikel — genauso wie er reguläre Angebotsartikel überspringt. Entwickler können dies mit dem Filter `woocommerce_pos_item_is_on_sale` überschreiben.
- Beim Entfernen eines Gutscheins bleibt die Position bei ihrem im POS rabattierten Preis.

:::note Entwicklerreferenz
Technische Details dazu, wie POS-Preisüberschreibungen gespeichert werden, sowie die verfügbaren Filter finden Sie in der [POS-Rabattreferenz](/reference/pos-discounts).
:::

## Was sich in v1.9.0 geändert hat {#what-changed-in-v190}

Wenn Sie von v1.8 aktualisiert haben und die Summe **Rabatt** auf Belegen und in Berichten jetzt **0** anzeigt, hat das folgenden Grund: Frühere Versionen erfassten eine Preisänderung an der Kasse als WooCommerce-Rabatt, was die Gutschein-Berechnung zerstörte — ein zusätzlich angewendeter Gutschein berechnete sich gegen den ursprünglichen Preis, gab der Bestellung einen zu hohen Rabatt und belastete den Kunden zu wenig. Ab v1.9.0 **ist** der an der Kasse festgelegte Preis der Positionspreis, genau so, wie WooCommerce ein reduziertes Produkt erfasst, und nur Gutscheine zählen als Rabatte. Siehe [Warum Preisänderungen und Gutscheine unterschiedlich erfasst werden](#why-tracked-differently) oben.

### Was das für Sie bedeutet {#what-this-means-for-you}

- **Belege** können den erfassten regulären Preis, die Ersparnis vom regulären zum Verkaufspreis und einen kombinierten Wert **Gesamtersparnis** für diese Ersparnisse plus Gutscheine anzeigen. Preisersparnisse bleiben vom WooCommerce-Feld **Rabatt** getrennt.
- **Berichte** zeigen `discount_total = 0`, wenn nur POS-Preisänderungen auf Positionsebene verwendet wurden. Nur Gutscheinrabatte werden gezählt.
- **Gutscheine** berechnen sich jetzt korrekt, wenn sie mit im POS rabattierten Artikeln kombiniert werden.
- **Die erfassten regulären Preise und Verkaufspreise werden gespeichert** — in den Metadaten der POS-Positionen (`_woocommerce_pos_data`), sodass der Beleg die Ersparnis ableiten kann, ohne die Rabattsummen von WooCommerce zu ändern.

### Ursprünglichen Preis und Ersparnis auf Belegen anzeigen {#showing-the-original-price-and-saving-on-receipts}

Die aktuellen gebündelten Vorlagen mit Preisangaben zeigen den erfassten regulären Preis und die Ersparnis an, wenn ein Produkt reduziert ist oder sein Preis an der Kasse geändert wird. Sie zeigen außerdem **Gesamtersparnis**, wenn WCPOS einen vollständigen Wert auf Bestellebene berechnen kann. Dieser Gesamtwert kombiniert Ersparnisse zum regulären Preis mit Gutscheinrabatten, ohne einen davon doppelt zu zählen.

Aus der Galerie kopierte Vorlagen sind bearbeitbare Momentaufnahmen und werden durch WCPOS-Updates nicht überschrieben. Wenn Sie Ihren Beleg vor dieser Änderung erstellt haben, gehen Sie wie folgt vor:

1. Klicken Sie bei einer neuen Kopie der gebündelten Vorlage auf **Vorlage verwenden**; oder
2. Aktualisieren Sie Ihre bestehende Vorlage mit den Feldern in der [Belegdatenreferenz](/receipts/receipt-data#displaying-regular-price-and-savings).

Die wichtigsten Belegfelder sind:

| Feld | Bedeutung |
|-------|---------|
| `lines[].regular_price_display` | Erfasster regulärer Stückpreis |
| `lines[].selling_price_display` | Verkaufspreis pro Einheit vor Gutscheinen |
| `lines[].unit_savings_display` | Ersparnis pro Artikel |
| `lines[].line_regular_total_display` | Regulärer Gesamtpreis der Position |
| `lines[].line_savings_display` | Gesamtersparnis der Position |
| `totals.sale_savings_total_display` | Gesamtersparnis vom regulären zum Verkaufspreis aus Katalog-Angeboten und Preisänderungen an der Kasse |
| `totals.discount_total_display` | WooCommerce-Rabattsumme; normalerweise Gutscheine bei aktuellen Bestellungen |
| `totals.total_saved_display` | Kombinierte Ersparnis aus regulärem Preis und WooCommerce-Rabatten |
| `totals.total_saved_complete` | Gibt an, ob die kombinierte Gesamtersparnis vollständig und zur Anzeige sicher ist |

Benutzerdefinierte Vorlagen sollten die Zeile **Gesamtersparnis** absichern, sodass sie ausgeblendet wird, wenn historische Preisdaten unvollständig sind oder nichts gespart wurde — das genaue Muster finden Sie in der [Belegdatenreferenz](/receipts/receipt-data#totals).

WooCommerce-Berichte bleiben unverändert: Die nativen Rabattsummen enthalten weiterhin Gutscheine statt aktueller Ersparnisse durch Angebotspreise oder Kassenpreise. Verwenden Sie `totals.total_saved` für Belege und weiterhin [Gutscheine](/coupons), wenn Ersparnisse in Berichten auch als WooCommerce-Rabatte erfasst werden müssen.

## Bekannte Einschränkungen {#known-limitations}

- **Keine automatischen Rabattregeln** — das POS unterstützt keine automatischen Rabatte im Stil von „Kaufe 2, erhalte 1 gratis“. Verwenden Sie WooCommerce-Gutscheine für strukturierte Aktionen.
- **Schnellrabatte sind nur prozentual** — es gibt keine integrierte Schnellschaltfläche für Rabatte mit festem Betrag. Verwenden Sie stattdessen eine negative Gebühr oder bearbeiten Sie einzelne Preise.
- **Rabattgebühren und steuerinklusive Preisgestaltung** — eine Rabattgebühr auf Bestellebene berechnet die richtige Gesamtsumme, reduziert aber nicht die auf der Bestellung erfasste Steuer. Siehe [Wie die Steuer auf eine Rabattgebühr berechnet wird](#discount-fee-tax).
