## Highest-leverage findings for the page

1. **When the till refuses a coupon: task clarity / structure.** The cashier sees a red message on screen (in the shot it says "This coupon has expired."). But the 14 collapsed headings below are named by cause ("Expired coupon", "Customer has used their share", "Cart changed while checking"). The cashier has to work out which heading matches the words on the screen, and most headings don't use the same words, so they end up opening several. **Smallest fix:** add the exact red message to each heading, for example *Expired coupon: "This coupon has expired."*, so the cashier can match what's on screen in one glance.

2. **When the till refuses a coupon screenshot: visuals.** This shot exists to show the red refusal line, but it has no label. Label 1 points at the coupon box and the caption tells the reader to look "above it". The **Apply it** shot has a similar gap: the struck-through old line total that the text describes has no label. **Smallest fix:** add a label on the red line, captioned "Why it didn't go on: find this message below". Add one more label on the struck-through line total in the Apply it shot.

3. **If something goes wrong → The coupon isn't in the list: consistency / accuracy signals.** The page tells the cashier to go to **Store health → Database → More actions → Check for changes now / Clear & re-download…**. The approved Product Panel page fixes the same kind of problem a different way: press and hold the sync button and choose **Clear and Refresh**. Two routes with two different names look like a guess to the reader. The page also uses words the cashier wouldn't say ("Database", "fetched"). It gives no warning that re-downloading everything could be slow in the middle of a sale. **Smallest fix:** use the same route and button name as the approved page, or link to one shared section. Move the re-download step into a warning callout that says it reloads every coupon.
